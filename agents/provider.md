# Provider

Load when changing Provider selection, model configuration, endpoint profiles, credentials, request/response mapping, structured outcomes, routing, usage, privacy provenance, or provider conformance.

The capability/routing evidence lives in `docs/research/beta-multi-provider-routing-and-adapters.md`; the current ChatGPT-plan decision and its weaker output-bound trade-off live in `docs/research/next-step-decision-register.md` (D-18). Keep this file as the working Provider contract.

## Beta contract

- One explicitly selected ProviderProfile, model, reasoning profile, privacy profile, and outcome encoding is pinned before Workspace input and `RunStarted`; every call in that Run uses the resolution. A Session may change its default only between Runs.
- Pin the Provider-declared concurrency ceiling with the selected profile before Workspace input; `RunStarted` records it. Legacy `RunStarted` payloads without the field replay conservatively with a ceiling of one.
- `Provider` remains the only Engine behavior seam. Engine requests and responses contain Arany semantics, never provider wire objects or a generic parameter bag.
- `Provider::compact` is a separate semantic call, not a synthetic AgentRun. It receives bounded accepted conversation outcomes (including unanswered objectives) and optional prior derived summary, and excludes Workspace instructions/includes. API-key and custom Providers enforce the requested output cap remotely; the consented ChatGPT-plan route records a local-only acceptance cap because its published request rejects a remote cap. The resulting summary is untrusted data, portable across Providers only with its recorded provenance.
- Product rollout is staged: native OpenAI and Anthropic first; exact custom endpoint/model profiles join only after data-free conformance; a built-in constrained OpenRouter profile remains deferred behind its route/privacy gate; Z.AI remains unadmitted until an exact profile passes a documented strict outcome contract. The scripted Provider is test-only.
- Provider switching is deterministic selection, not automatic routing. There is no cross-provider/model fallback or hidden discovery call inside a Run.
- Native effort is model-specific, resolved before Workspace input, sent explicitly on every Run and compaction request, and pinned in `RunStarted`. An omitted next-Run choice resolves to the reviewed native model default; an unreviewed model requires an explicit closed effort, not a synthetic check. Malformed IDs and unsupported reviewed-table combinations fail before credential or Workspace input. `resolve_native_effort` supplies reviewed metadata; `resolve_native_effort_for_run` additionally admits an explicit unknown choice without claiming compatibility and pins its concurrency to one. Custom v1 conformance authorizes only provider-default effort; custom v2 declares an ordered set of selectable efforts, probes each one with synthetic input, and pins the selected choice on Run and compaction calls.

## Strict outcome rule

- Prefer provider-enforced JSON Schema for `Delegate | Finish`, restricted by typed phase and collaboration policy. Read-only native/custom calls and Anthropic coding calls use structured text. Tool-enabled OpenAI/ChatGPT primary calls use strict native function definitions for catalog-available Tool operations and phase-available Finish/Delegate submissions, `tool_choice: required` and disabled parallel calls. Exactly one completed function call translates to the same Engine semantic outcome; reject final text, multiple/unknown/incomplete calls and invalid typed arguments, without encoding fallback. Children reject Tool context before transport. Preserve complete-response/model/usage and credential-reflection checks. Exact custom profiles remain read-only and reject Tool context before HTTP; future support needs exact tool-capable evidence.
- The Responses coding adapter reconstructs ordered paired function-call/result items from current observed semantic actions with request-local correlation labels. These describe actual journaled actions, never pending historical intents, remote stored state or renewed authority. Read-only/child/compaction encoding remains unchanged. Keep native function details inside Provider and pin coding encoding from typed Tool admission before requests; version ChatGPT account admission when that coding request/decoder contract changes.
- A synthetic `submit_agent_outcome` call is an allowed private encoding only when the exact provider/model officially supports strict tool arguments and forced tool selection. It is decoded and validated, never executed.
- JSON mode, prompt-only formatting, unconstrained automatic tool selection, local repair, or schema validation after unconstrained generation cannot satisfy the beta contract.
- Keep instruction text consistent with each phase's schema: forcing synthesis to Finish suppresses allowed primary reads/edits even when Engine continuation works. Pending file data belongs to a Tool proposal and its correlated observation; children remain reasoning-only.
- Restrict generated Tool branches and command/Skill/MCP-server names to bounded catalog availability. Advertising unconfigured MCP invites invalid fallback proposals after an unrelated file failure. This restricts generation only; catalog data never replaces pinned router/Guard authorization.
- Use the shared model-input Tool projection: structured catalog/results and ordered action/disposition/workspace-effect data, without journal enforcement metadata. Preserve complete canonical observations and plain-output fallback. An absent edit receipt after successful inspection is not an observed edit failure; coding guidance must direct the primary to propose the requested mutation.
- Structured-text Responses decoding validates every assistant content block, joins ordered `output_text` parts without repair, and accepts exactly one final structured outcome. Explicit `commentary` is not a final answer; absent/null phase retains legacy single-final-message support. Refusal, unknown phase, malformed text, duplicate final messages, late commentary and non-null error/incomplete markers reject. Shared decoder changes invalidate native, exact-custom and ChatGPT check contracts plus ChatGPT account admission.
- Select the encoding from reviewed capability evidence before `RunStarted`. Refusal, truncation, duplicate/missing call, or schema mismatch fails that Provider call without retrying another encoding.

## Configuration and egress

- Resolve an explicit CLI profile/model over trusted Session or user-config defaults. There is no compiled model default, Workspace-defined profile, or implicit discovery.
- Read only the selected provider's credential. Credentials never enter CLI arguments, Events, output, fixtures, telemetry, or error bodies.
- Native credentials carry their selected Provider, bounded key and optional Anthropic API workspace as one immutable value. Environment-backed Anthropic selections may read `ANTHROPIC_WORKSPACE_ID`; other Providers and key-only protected accounts never inherit it. Validate the bounded `wrkspc_` identifier before requests, send the scope on every catalog/Run/compaction/conformance request, and bind it to exact native evidence. Neither a workspace header nor catalog visibility grants another destination, model capability or consumer-plan permission. Key-only library APIs keep their no-workspace meaning.
- `exec` and explicit native CLI selections use only their named API-key environment variable. Bare new attached mode can instead use one OS-credential-store API account chosen through `/setup` or `--setup`; with no account it remains unconfigured and rejects objectives locally before Workspace input. Saved-account Session defaults pin an account UUID, and Run/catalog admission must match that UUID and Provider before releasing its credential for Provider use. A replaced account never silently becomes the credential for an older Session. Native adapters carry the validated saved-account UUID to the Engine's `RunStarted` provenance; environment-backed and custom adapters carry no saved-account UUID. Native adapters and catalog discovery accept the selected key in-process without changing global environment. Official ChatGPT-plan OAuth is a distinct consented account route: its catalog can be listed without Workspace input, and current selected-account identity and storage-bound consent admit a model/effort Run without mandatory synthetic inference. It never falls back to API-key billing. Never import another harness's tokens or use a private ChatGPT route. Anthropic remains API-key only unless it grants Arany prior approval.
- Native endpoints come from compiled reviewed profiles. A custom profile lives in trusted user configuration outside the Workspace and names a closed protocol family, exact normalized endpoint/base path, exact model, credential reference, outcome encoding, and capability-evidence version. It never accepts arbitrary headers, shell credential commands, redirects, ambient proxies, or cross-profile credential reuse.
- The loader reads only `provider-profiles.json` from the private state root. Document version 1 is a closed `profiles` array (maximum 32) with unique lowercase-hyphen names, `openai-responses`, exact canonical `/responses` endpoint, model, `ARANY_PROVIDER_*` credential-environment reference, `json_schema`, `user_authorized` privacy classification, and a 4,096-token cap. Capability-evidence version 1 forbids an `efforts` field; version 2 requires a nonempty, unique, canonically ordered `efforts` array from `none|low|medium|high|xhigh|max`. Numeric loopback may use HTTP; domain hosts require HTTPS. A loaded profile is still unverified and cannot be selected for a Run until current conformance evidence exists.
- Before a custom profile receives Workspace data, `arany provider check PROFILE` runs a bounded synthetic conformance sequence and records expiring evidence keyed by Arany/adapter/test versions, exact origin, model, encoding, and output cap. A catalog or model list is not evidence. Unverified profiles are usable only by `provider check`.
- The checker uses three data-free strict Responses probes (direct finish, one child, compaction), plus one strict finish per declared v2 effort, a pinned no-proxy/no-redirect/no-retry destination, and a 24-hour SQLite evidence row. The bound effort list changes the v2 fingerprint; changes to either compiled strict contract invalidate old evidence independently of configuration version. After profile admission it clears stale evidence before probes and reads only the selected credential after destination admission. `CustomProvider::admit` re-reads the exact profile, re-resolves every address, compares fresh evidence, and only then reads the selected key; `custom:NAME` Runs use that constructor before Workspace input. A check result alone is not a Run authorization.
- The custom checker and Run adapter share bounded transport and strict Responses decoding. Custom calls require positive labeled usage within the requested output cap; the unproven concurrency ceiling is one.
- Every Provider HTTP client requests identity encoding, disables automatic decompression even if another dependency enables reqwest compression features, rejects any non-identity `Content-Encoding` value before reading the body, and bounds both declared length and accumulated chunks to 1 MiB per response. Compressed Provider replies are deliberately unsupported.
- Require HTTPS outside explicit numeric loopback. Pin destination and reject redirect, route/model drift, changed addresses, metadata/link-local/multicast destinations, and credential reflection. Receipts say `custom verified`; they never relabel a service as native OpenAI/Anthropic.
- Use Reqwest's published platform TLS verifier with certificate-chain and server-name checks intact. Arany's endpoint and payload admission does not control auxiliary certificate/revocation connections made by the operating system during trust evaluation; never treat them as Provider destinations for content, files, or credentials.
- For domain DNS answers, IPv6 admission uses reviewed allocated ranges rather than all `2000::/3`; unallocated and reserved ranges fail closed. Refresh the allowlist against the [IANA global-unicast allocations](https://www.iana.org/assignments/ipv6-unicast-address-assignments) and [special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry) when a new range is needed. Numeric loopback remains a separate explicit exception.
- A future built-in OpenRouter profile treats it as a broker: pin one reviewed upstream endpoint; require parameter support; disable fallback; deny data collection; require ZDR; disable response caching; and record broker plus upstream provenance.
- Similar HTTP mechanics may use private concrete helpers. Each adapter owns authentication, request documents, strict encoding, error mapping, usage, privacy, and response parsing. Do not create a transport trait or a universal OpenAI-compatible adapter.

## Reliability and evidence

- Keep zero automatic retries. Provider calls, tokens, bytes, time, concurrency, and admitted children share one immutable aggregate Run budget sized from the resolved collaboration policy. Each public adapter rejects reported input above the shared ceiling and output above the exact request cap before returning success; Engine admission remains defense in depth, not the adapter's sole bound. Native OpenAI retains optional unknown usage; custom transport retains required positive usage. A lost response may already have consumed tokens; broker fallback is also a retry and stays disabled.
- Each observed Run call commits one bounded `ProviderCallRecorded` fact before its AgentRun terminal Event. Its phase and local disposition are canonical; response ID and provider-reported input/output usage are present only when a bounded response was received. A timed-out or cancelled call reports unknown usage and does not prove absence of remote billing. `RunStarted` remains the selected Provider/model/effort provenance. Accepted wire provenance distinguishes Responses `completed` with a local `store: false` request from Messages `end_turn` with no equivalent request switch; it is not a remote retention or account-level ZDR guarantee. Compaction records carry the same optional provenance.
- API-key adapters reject exact selected-key reflection in bounded raw response bytes and decoded outcome, response-ID, or compaction fields before any result can become a canonical Event. This includes JSON-escaped echoes but is not general secret detection.
- MCP argument strings are a second JSON boundary: Provider Tool admission and credential scanning use the same bounded duplicate-free object decoder as the Guard. Reject malformed/non-object arguments before persistence; a last-key-wins parse or failed parse cannot hide an escaped credential.
- Persist bounded adapter, endpoint profile, requested/resolved model, request ID, broker/upstream identity, finish reason, usage provenance, privacy controls, and capability-evidence version. Never persist raw response bodies or uncontrolled headers.
- The scripted Provider owns Engine tests. Each product adapter owns hand-reviewed offline wire fixtures and ignored, explicitly activated, credential-and-model-gated live Runs. Native API-key adapters test direct and team Runs separately; the ChatGPT-plan gate first performs its account-bound synthetic model/effort check, then one direct Run with exact JSONL/Store replay and local-only bound provenance. No ignored test is release evidence until it actually passes against the selected account.
- The native OpenAI Responses adapter admits the exact `gpt-5.4`, `gpt-5.6-luna`, `gpt-6-astra`, `gpt-6.1-sol`, and `gpt-6-luna` IDs with `OPENAI_API_KEY`. The [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), and [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) pages supply the reviewed effort sets; Arany sends the resolved value as `reasoning.effort`. Arany chooses `medium` as the explicit Astra default; the other defaults match their model pages. Its HTTP client must keep redirects, ambient proxies, cookies, and automatic protocol retries disabled; reqwest retries some protocol failures by default unless explicitly overridden. Offline fixtures do not establish live support.
- The native Anthropic Messages adapter admits the exact `claude-sonnet-5`, `claude-fable-5-1`, `claude-opus-5-5`, and `claude-sonnet-5-5` IDs with `ANTHROPIC_API_KEY`. The [official effort guide](https://platform.claude.com/docs/en/build-with-claude/effort) lists each supported level; Opus 5.5 defaults to `medium`, and the other admitted models default to `high`. Arany sends the resolved value as `output_config.effort`. It uses the compiled `/v1/messages` route, `anthropic-version: 2023-06-01`, schema-constrained `output_config.format`, remote `max_tokens`, and the same no-proxy/no-redirect/no-retry bounds. Thinking blocks are ignored as private data; only one complete text outcome is accepted. Normalize Anthropic input usage as uncached + cache-creation + cache-read tokens with checked arithmetic, because `input_tokens` alone excludes cached tokens. Offline fixtures do not establish live support or an account-level ZDR claim.
- A catalog lists availability, not compatibility. Only reviewed manifests, adapter fixtures, and opt-in live probes support capability claims.
- Native model checks are optional potentially billable diagnostics, not product Run authorization. `provider check PROFILE MODEL --effort LEVEL --accept-cost` uses the named environment source or explicit `--saved-account`, confirms catalog visibility, then makes at most three synthetic direct/delegate/compaction calls with a 1,024-token remote cap per call and one aggregate 180-second deadline, without retries or Workspace data. It clears prior tuple evidence before probes and publishes a 24-hour HMAC bound to exact key, Provider, API workspace, source/account UUID, model, effort, package and checker-contract version only after strict success. The optional checked library constructors still require that exact evidence and pin concurrency one; ordinary constructors and product Runs do not. Preserve source isolation, failure clearing and bounded Store rows; a diagnostic neither proves universal model compatibility nor grants credential authority. HMAC requires high-entropy real keys, and is not encryption of history or process memory.
- Bump the native checker-contract version whenever its prompts, strict request/decoder, effort mapping, remote output cap, or validation semantics change. Package version alone does not invalidate evidence across beta source changes at the same version.
- `arany provider models PROFILE` reads only the selected native Models API credential and no Workspace data. The default source is the Provider's environment key; `--saved-account` selects the current OS-stored API account and rejects a Provider mismatch. It returns the complete account-visible result or fails closed at 1 MiB per page, 16 pages, or 4,096 unique models; the JSON decoder also caps retained rows per page before collecting the result. The catalog requires one `application/json` response media type (optional parameters) before body reading and uses no proxy, redirect, retry, or decompression; model IDs are bounded printable ASCII. Native entries distinguish reviewed effort metadata from availability-only rows; neither label promises live compatibility. Unknown rows are selectable with an explicit effort and no mandatory probe. A custom exact profile lists only its configured model and declared effort choices without reading its credential; current conformance is still checked at Run admission.
- `provider models chatgpt` reads the selected OS-user OAuth account, rotates a near-expiry token under the account lock when needed, and lists every `visibility: "list"` row in the compiled Models API response, preserving order and inert display names. It does not use `OPENAI_API_KEY`, a Session StateRoot, or Workspace content; it accepts neither `--saved-account` nor `--state-dir`. An account replacement after listing may stale the display, so Run admission must revalidate the selected account identity and storage-bound consent for its pinned model/effort. A visible subscription model is not automatically compatible with Arany's strict outcome or an effort choice; the actual bounded Run must still pass strict request/outcome validation. A synthetic compatibility check is optional, not a Run prerequisite.
- `provider check chatgpt MODEL --effort LEVEL --accept-cost` first clears the selected account's old exact-tuple evidence, verifies model visibility with that OAuth token, then runs three synthetic direct/delegate/compaction calls. It accepts neither `--saved-account` nor `--state-dir` and cannot fall back to `OPENAI_API_KEY`. Only completed strict outcomes publish a 24-hour check bound to account UUID, signed registration, exact consent receipt, model, effort, protocol/check version, and the retained ID token. The protected account index holds at most 64 check records; reauthorization clears that account's records, while access-token rotation preserves them. Failed/incomplete probes leave no new evidence; cancellation after completed probes may leave an already-started atomic publication. Bump the check-contract version whenever the probe prompts, strict decoder, effort mapping, or local output acceptance cap changes. The command is explicitly plan-consuming; later Run admission revalidates account identity and consent before Workspace input, independently of these optional diagnostic records.
- The ChatGPT-plan Responses Provider uses the native OpenAI strict Run and compaction decoders but a distinct streaming request: `store: false`, `stream: true`, array `input` containing required local history, no HTTP `previous_response_id`, and no remote `max_output_tokens`, as required by the [official preview contract](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). Its bounded SSE parser accepts LF, CRLF, and CR line endings across chunks. Both operations accept only `response.completed`, with positive labeled final usage no greater than the requested local output cap, under a 120-second and 1-MiB stream-read bound. `response.failed`, `response.incomplete`, malformed/encoded/interrupted streams, missing usage, and local overflow fail without publishing a partial outcome or summary. A failed/error event can retain only a nonempty machine-readable code of at most 128 safe ASCII bytes from its documented JSON location, after full token-reflection rejection; malformed or unsafe codes remain generic. Only recognized temporary usage-unavailable codes map to the Engine's unavailable category, and no stream failure publishes partial output. Its three-call synthetic model/effort probe uses a 1,024-token local cap per call and a 180-second aggregate deadline. A local abort cannot guarantee a remote generation or plan-usage cap. The checked constructor receives only a selected account token, exact model/effort, UUID, opaque admission fingerprint and closed category after protected account admission; it has no API-key fallback or alternate endpoint. The Engine validates the Provider's ChatGPT provenance and local-only output-bound category before Workspace input and persists both for replay. New account-consent admission receipts use a domain-separated HMAC bound to identity, storage consent, model/effort and the compiled protocol contract; they are never recorded as successful probes. Legacy absent-category records retain conformance semantics. Offline proof does not establish a successful live turn.
- Subscription requests negotiate SSE with `Accept: text/event-stream` and always use the bounded SSE parser, regardless of a missing or misleading response media label. Native and catalog media admission is unchanged. SSE requires a bounded JSON `type`; an optional `event:` label must match it. Complete `response.output_item.done` items may supply an empty terminal output only after a matching bounded `response.created` identity and `response.completed` arrive. Retain all items in contiguous output-index order, reject repeated indices/IDs and unfinished messages, and require a populated terminal output to agree with the retained collection. Both received and reconstructed documents stay within the stream byte bound; item count is bounded by the event ceiling. Deltas never supply accepted text. Complete terminal response, model, message phase, usage, strict outcome and token-reflection checks remain required; interruption, failed/incomplete closure and contradictory output publish nothing. Bump both ChatGPT admission and optional check contracts when these acceptance semantics change. There is no JSON/HTML fallback, retry or encoding fallback.
- For that direct route, non-200 retains only a numeric typed status without reading the failure body: 4xx maps to rejected, 5xx to unavailable, others to invalid response. Optional checks display status with compiled advice. Observed Runs preserve only closed reasons: account access, usage limit, temporary usage or service unavailability, stream protocol, selected response contract, structured outcome contract, or local output acceptance. Unknown errors remain generic. Canonical Events contain no raw status/code, upstream text/body or request ID; compiled guidance is shared by chat and agent details, not Provider context or telemetry. A reason does not establish credential invalidity, exact quota, retry time or billing. There is no automatic retry, model/encoding fallback or billing switch. Other adapters earn detail only through typed errors; this is not full [OpenAI error-diagnostic guidance](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).
- Attached native model/effort choices require no synthetic check; each Run still validates the selected credential source/account identity, API workspace, bounded model/effort and strict actual response before publishing an outcome. ChatGPT retains current consent/identity admission, and custom profiles retain exact-destination conformance. Native setup loads only its selected account catalog, saves a low-effort choice and returns to chat without model/effort/cost questions or inference. Prefer visible `gpt-5.6-luna` for OpenAI, or `claude-sonnet-5-5` then `claude-sonnet-5` for Anthropic; otherwise use the first visible row with unknown pricing disclosed. This is an economical reviewed low-effort-capable preference, not a global-cheapest or universal support claim. Attached `/model` selects the model and effort atomically in chat; selecting either is staging, never credential or compatibility authority.
