# Image input

Load with Provider, Session, Store, Security and Terminal rules when changing image attachment admission, context, wire encoding or replay. `src/provider/image.rs` owns the immutable semantic image value; it is not a new Engine behavior seam.

- Admit bytes, never a filename, URL or terminal image escape. PNG structure/CRC/dimension admission is not raster decoding or proof that a remote model supports vision. Reject animated PNG and unknown critical chunks; preserve original admitted bytes, including metadata, without local decompression.
- The constructor and closed deserializer enforce the same canonical value. Private shared Base64 data prevents caller mutation and avoids per-snapshot pixel copies. Debug output contains metadata/digest, not Base64. Human drawing uses metadata only; canonical export is a separate intentional data-bearing surface.
- Aggregate image count/bytes and encoded context bytes need separate bounds. Overflow rejects a whole image or whole historical turn, never a truncated prefix or silent lost attachment. Native adapter admission validates count, aggregate bytes and objective/history origin before body construction or egress.
- Historical origin indexes refer to the selected ordered semantic history, not the entire Session. Children receive only current-objective images, never historical pixels. Labels/content stay in user data, never system instructions or an authority grant.
- A current image-only Message has empty user text, not invented prompt text. Canonical `MessageAccepted` v2 retains inline bytes; text-only v1 stays unchanged. Store bounds the exception by kind/version before decoding and the image-list visitor stops at four values. The existing database/page, replay-event and hot-cache aggregate bounds still apply.
- Context counts encoded bytes plus bounded per-image overhead and admits whole historical turns only. Compaction compiler v2 sends user text, assistant interpretations and immutable image metadata/digests, not pixels; v1 text snapshots remain readable. Covered pixels stay canonical and fork-recoverable but are absent from later summarized context. Reserve compaction headroom for maximal text plus image metadata.
- Composer controls consume only their command text; attachments stay in the draft. Explicit clear discards both, objective submission transfers both once, and Session switching rejects outstanding images. Linear local validation clears the submitted physical text, not its attachments. Current work, selectors and clipboard errors preserve the remaining draft/caret.
- Native Responses, ChatGPT-plan Responses and Messages encode actual image content without file uploads, external URLs, another destination, retries or changed credentials. ChatGPT's streaming conversion accepts the resulting message array directly; do not nest that array inside another message's content.
- Exact custom profiles remain text-only until their separate image contract is admitted. Text-only conformance does not authorize multimodal disclosure. Bump affected native/check/account-admission contracts when native request semantics change, without requiring a new optional check for ordinary native Runs.
- Extend existing public wire/admission, Engine journey, Composer/frame and Store replay owners. Synthetic container fixtures prove structural admission and bytes, not decoded pixels, native clipboard service, real vision or paid compatibility. A compiled clipboard route is not native transport evidence.
