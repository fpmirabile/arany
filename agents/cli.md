# CLI composition

Load when changing `main.rs`, `src/cli.rs`, or `src/cli/` command admission, process channels, or command-specific Engine composition. Read [the terminal spec](../docs/specs/terminal.md) for modes, process channels and interactive behavior, and [terminal rules](./terminal.md) for rendering/lifecycle constraints; Provider and Workspace trust remain in [provider.md](./provider.md) and [security.md](./security.md).

- `main.rs` owns command selection and exit codes. The private CLI files select trusted inputs, call the Engine, and project only committed facts; they never implement Run transitions or provider wire logic. Label attached parser/local-argument, input-capacity/line and caught typed Session/effort-admission rejection once through the existing `Error:` feedback convention at the caller; validators return undecorated diagnostics. No-argument syntax belongs to the compiled parser in every Run state; idle validation owns selection-dependent values. An operation error is not a rollback guarantee or authority to restore/resubmit its consumed command. Successful continuation, loading progress and locked inspection controls remain ordinary notices.
- Idle Provider/model/effort/collaboration mutation and model-browser activation retain typed defaults errors until classification. Only `EngineError::SessionBusy` returns recoverable chat error feedback without saving the attempted selection; State admission, Workspace, append/replay and shutdown failures still propagate. Strict startup, account-setup publication and partially created `/new` operations keep their existing fatal contract. Reuse one private classification; never inspect display strings, restore a consumed command, retry automatically or imply that earlier catalog/check/account work rolled back.
- Initialize opt-in telemetry from `--otlp-endpoint` or the supported OTLP endpoint variables before the Tokio runtime and Workspace admission. Invalid explicit telemetry configuration exits 2 without state creation; Collector outages after admission never change a Run result or JSONL channel. Shut down the bounded worker after the runtime returns.
- Enable development diagnostics only after normal attached Session or `exec` state admission; [diagnostic rules](./diagnostics.md) own its privacy and lossy bounds. Keep help/version, read-only `show`, internal helpers and exact process channels unchanged.
- `exec` requires an explicit native Provider, `chatgpt`, or `custom:NAME` profile and a model. ChatGPT also requires an explicit effort and current selected-account consent/identity; native `--effort` selects a reviewed model-specific level or an explicit closed choice for an unknown model. Validate the objective, collaboration policy, Session ID, basic model ID, and obvious state/Workspace overlap before credential loading or state creation. Reviewed native model/effort combinations resolve before reading their key; an unreviewed model requires explicit effort, not current diagnostic evidence. Unsupported reviewed combinations reject locally; unknown choices use the same strict request/outcome encoding with concurrency one and no hidden probes. The Engine's handle-based Workspace check remains authoritative.
- Select only the chosen Provider credential before Workspace content. Native runs validate model/effort before reading their named environment key, then pass that key by value to the selected adapter; native catalog discovery passes the selected key without mutating process environment. There is no fake-provider product flag, hidden model default, or automatic fallback.
- Attached and `exec` enable coding Tools only through explicit `--tools` and the private configuration owner. The CLI passes the shipped executable identity to Engine admission; it does not parse Skill/MCP metadata or implement Tool policy. `/permissions` reports requested/pinned authority, not an approval action. Missing/invalid grants admit no objective or Provider call; actual dispatch failure preserves the canonical effect facts and safe uncertainty guidance.
- `provider check PROFILE [--state-dir DIR]` retains the custom exact-profile path. `provider check openai|anthropic MODEL --effort LEVEL --accept-cost [--state-dir DIR]` is a separate environment-key path: consent and tuple validation precede state/credential work, then a bounded catalog read and at most three potentially billable synthetic inference calls run without Workspace data. The optional checked library constructor revalidates exact evidence; ordinary product Runs do not require it. Human custom Run receipts label it `Provider: custom verified`; JSONL carries custom provenance in `RunStarted`.
- `provider models PROFILE [--state-dir DIR]` lists every account-visible native model or the one configured exact custom model. It reads no Workspace content or unselected credential; native entries outside the reviewed table disclose availability only and require an explicit effort, not a check, for `exec`. Model discovery does not replace `--model` or authorize an unreviewed model.
- `provider models chatgpt` lists all visible rows for the selected OS-user ChatGPT account using its consent-matched token and, if needed, a serialized token refresh. It accepts neither `--saved-account` nor `--state-dir`, does not read an API-key environment variable or Workspace content, and labels availability without claiming strict compatibility; synthetic checks are optional for Run admission. Names pass through the shared inert terminal-text renderer.
- `provider check chatgpt MODEL --effort LEVEL --accept-cost` is the separate, explicit plan-consuming check for that selected account. Validate the tuple and cost flag before account or State access; reject `--saved-account` and `--state-dir`. It clears prior exact evidence, confirms catalog visibility, probes only synthetic content, and publishes account-bound evidence only after strict completion. The CLI receives only the account UUID and success status; no token enters output. Warn that the 1,024-token per-call cap is local, not a remote generation or billing cap. A successful check records only that exact account/model/effort diagnostic; it is not required for a Run. Run admission independently revalidates selected-account identity and storage-bound consent.
- `provider logout chatgpt` disconnects only the selected OS-user account; reject profile variants and StateRoot flags before account access. Report remote revocation as confirmed only after strict success, otherwise warn about ChatGPT Settings. Treat uncertain keyring deletion as locally blocked but not confirmed cleared. Do not expose the token, switch billing routes, or imply secure erasure or cancellation of in-flight requests.
- Bare idle `/model` and `/models` dispatch to the same bounded catalog selector, keeping terminal ownership and signals live during discovery and paging through only visible rows. Classify catalog-operation failure at its completion boundary as recoverable error feedback with safe diagnostics and retry guidance; missing-Provider guidance and cancellation remain ordinary notices, while terminal-owner failure still propagates. Its inline browser filters cached model IDs locally; linear mode retains numbered pages. The in-chat panel keeps the composer and History anchor; Up/Down focuses a row, Left/Right changes its tentative effort and Enter saves both in one defaults operation. Escape preserves draft/caret/history and defaults. An unreviewed native row starts with low effort, not fabricated compatibility evidence. Actual strict request/response failure is not repaired or retried. `/model ID [EFFORT|default]` keeps its literal tuple-selection path, and active `/model` remains view-only without discovery. Active Runs cannot open the catalog. An exact custom profile lists its configured model without a credential or inference request.
- Model selection is staging, not account authority: validate local native/ChatGPT combinations before consuming a typed command, then reuse one atomic defaults writer for typed and picker activation. Reviewed native rows offer allowed levels plus default; unknown native/ChatGPT rows offer explicit closed levels; custom rows offer only declared levels plus default. Keep each row's tentative effort across local focus/filter changes. Linear input accepts `NUMBER [EFFORT|default]`. No selection loads a token, renews consent or makes inference; Run admission still validates current account/consent and exact custom-destination evidence. Retired `/effort` is not parsed or completed.
- Idle inline `Ctrl+K` selects Models, Agents, Sessions or Setup without taking the composer. Setup reuses the private `/setup` composition and preserves a retained draft; its row is initially focused only with no selected Provider. Sessions rejects a nonempty draft before State access. Opening this selector performs no Provider or credential I/O; selecting Setup explicitly enters the existing consent and credential flow. Linear/screen-reader mode retains slash commands.
- Close the writable Engine and reopen state read-only before `exec` emits a result. Project only the current invocation's committed facts; [the terminal spec](../docs/specs/terminal.md#entry-modes-and-channels) owns their channel and rendering contract.
- `show` validates its Session-or-Run UUID before State access and opens only existing read-only State. An existing Session ID selects that Session's direct Events; otherwise the Store resolves a unique parent for the Run ID. Replay the complete parent before filtering to that Run, close the Store before rendering, and reject missing or conflicting ownership with no stdout. Inspection never reads a Provider credential or starts a Run.
- Enable Tokio's time and I/O drivers in the product runtime; Run deadlines and native HTTP adapters rely on them even when the command has no explicit timer or socket.
- Bare attached mode admits terminal stdin/stderr before creating a Session. A positional prompt requires a selected Provider/model and preflights only that selection after TTY admission but before Session or fork creation. Missing defaults return actionable setup/model guidance, never a panic or empty Session; a fork does not inherit a billing route merely to satisfy that prompt.
- Bare new attached mode with no explicit Provider checks protected record presence before reading either account record. If both native API and ChatGPT records exist, it asks for the billing route on every start; cancellation creates no Session. It then reads the chosen route's protected record, not the other route's, with no fallback if that account is invalid or unavailable. The chosen ChatGPT index may itself contain multiple private-file tokens, but only its selected account is eligible for use. A sole pinned native account or selected ChatGPT account is reused; without either it creates an unconfigured Session and opens the ordinary composer. An objective submitted there is rejected locally with `/setup` guidance before Provider admission or Workspace input. Idle `/setup` opens account choices in the existing Session; `--setup` deliberately opens the same wizard before creating a new Session. Native API-key setup prefers the OS keyring, and offers the private-file fallback only when no keyring backend is pinned and the keyring is unavailable, with explicit pre-save warning and confirmation. Native setup asks for Provider and hidden API key, plus explicit Anthropic API workspace when selected. It reads the account-visible catalog, saves a low-effort choice and returns to chat without a model/effort/cost questionnaire or inference. The economic preference and unknown-pricing fallback belong to [Provider rules](./provider.md); empty catalog or pre-save cancellation leaves the previous account/defaults unchanged. ChatGPT setup saves a verified account after backend-specific explicit Back/Accept consent and callback redemption, then, when plan permission is enabled, reads the visible catalog and returns to chat with low effort and the visible `gpt-5.6-luna` if present, otherwise the first visible model with an unknown-prices notice. It makes no inference and asks no additional model/effort/cost questions. Cancellation or catalog failure after save retains account-only defaults. Cancelling `--setup` before save creates no Session; cancelling `/setup` before save leaves existing defaults unchanged. An interrupted in-progress save may have changed the account. Explicit Provider flags and resume/fork/continue bypass saved-account selection on new entry. `exec` remains noninteractive and uses an explicit environment key only for native/custom, never for ChatGPT.
- ChatGPT setup persists one stable opaque host ID before first sign-in and retains a newly issued client ID before code redemption; a failed `invalid_grant` must restart authorization under that issued registration without retrying the spent code. Keep these account identities separate from Session IDs and from token persistence. The browser launch accepts only the compiled HTTPS authorization URL and no token hint in process arguments.
- With a connected selected ChatGPT account, the attached setup wizard offers `Use saved`, `Reconnect`, or `Connect new` after access-method selection. A disconnected selection offers reconnect or new sign-in, plus another connected saved account when available. If multiple connected accounts exist, `Use saved` lists only short UUID labels with the current one marked when connected; choosing another validates its consented credential and changes the selected OS-user account under the private account lock before catalog use. The changed account becomes account-only Session defaults on later cancellation or catalog failure; successful catalog discovery publishes its low-effort default without a check. Reusing the current account performs no OAuth registration or browser step and reads its catalog and returns to chat with its low-effort default, without inference. Reconnect reads only selected metadata, pins its storage backend, repeats explicit Back/Accept risk consent, and runs returning OAuth without a token hint in browser arguments; only the same signed subject and locked selected UUID/client/backend may replace the token. It pins model/effort defaults only from the matching account catalog; cancellation or catalog failure on current-account reuse leaves prior Session defaults intact, while a newly connected or reconnected account retains account-only defaults and a retry notice for failures. A missing token or invalid consent fails without a new Session in pre-Session `--setup`.
- Save a completed setup account only while holding the Store's default-user-root private nonblocking account-replacement lock through the selected backend write; a busy or unsafe StateRoot fails without saving selected defaults or starting a Run. The keyring path writes only a backend marker to StateRoot and uses the supervised private credential helper; the user-confirmed file path writes the bounded account under private-mode file controls. Read-only account selection still validates the pinned UUID and Provider at use.
- Attached mode selects the terminal presentation before raw acquisition: explicit `--screen-reader`/`ARANY_SCREEN_READER=1`, `TERM=dumb`, and short or unmeasurable terminals use labeled linear output. `--no-color`/`NO_COLOR` disable inline semantic accents before the first frame and across reacquisition without changing facts; linear output stays unstyled. Ineligible pipes still fail before Session creation.
- Exact-ID `--resume` reuses persisted defaults unless explicit flags override them; `--fork` requires a committed Run boundary and starts with unselected defaults. Local resume, fork, and rename need no Provider credential. `/new` and `/clear` use the [current-selection Session contract](./session.md#session-commands), never startup defaults; install their local ID/view only after defaults persistence and canonical reload succeed, without promising rollback of a partially created Session. Idle slash admission mirrors the canonical title's byte bound before consuming `/rename`, allowing inline correction at the same caret without State access; linear rejection clears its physical line. A positional prompt must resolve and preflight its selected Provider before any new Run.
- `--continue` chooses the latest committed Session for the admitted Workspace and uses the same persisted-default and prompt preflight path as exact-ID resume. Discovery itself reads no Provider credential.
- Bare `--resume` opens the Workspace-scoped picker before creating a Session; `/sessions` and idle `/resume` without an ID open the same picker. Preserve unavailable-list and empty-list outcomes separately from terminal-owner errors: inside chat, listing failure gets safe error feedback and an empty list ordinary guidance; before Session entry, both remain unsuccessful. Drawing/input/cleanup errors propagate to restoration and exit. Escape leaves the current Session unchanged. A selected row passes through exact-ID resume before it replaces the current view; listing never loads a Provider credential.
- Idle `/compact` uses only the selected admitted Provider/model and the Engine's Workspace-checked compaction operation. Manual and automatic maintenance share the [terminal's busy-draft contract](../docs/specs/terminal.md#draft-editing-and-submission); pass the same Composer through their private callers and compute retained-byte feedback after maintenance, not before it. Keep Provider admission inside that input-owning future; `compact_selected` already supplies it, so a separate awaited preflight duplicates credential work and stalls editing/interruption. Preserve private operation/interruption outcomes separately from terminal errors: admission/operation failure and a typed committed failure get error feedback; explicit Ctrl+C remains an interruption warning. Drawing/input/restoration errors propagate to exit. Report committed status/usage without model-authored summary text. Dropping the local attempt is not cancellation or rollback: an already queued Event append can still commit, and a remote Provider may still charge. Reload the committed Session view after interruption.
- After a successful attached Run, restore the terminal and emit its confirmed receipt before automatic context maintenance. If its committed config reached the context threshold, print a durable warning, then compact only that Run boundary with its pinned Provider/model/effort and account source through the Engine's duplicate-safe operation. Derive the source from that committed config, never newly loaded next-Run defaults; a pinned `None` remains environment-backed/custom rather than inheriting a saved account. Current credential/identity/evidence admission still applies. Maintenance failure is visible but does not change the completed Run or canonical history. `exec` adds no hidden compaction call.
- After an attached Run, restore terminal ownership and reopen its committed view read-only before emitting an answer or receipt. Keep its signal listeners alive during output and reacquire the selected attached presentation only afterward. Confirmed failed/cancelled Run feedback uses the same pure owner in inline and linear modes; linear mode appends one labeled notice, without rewriting or inventing an answer. Keep retained-draft status separate.
- Attached Run composition subscribes to Engine `RunProgress` before starting the Run and selects over committed updates, terminal input, and completion. Mutate the caller-owned terminal-local `SessionView` for progress; copying the full resolved history at Run start scales with the entire transcript. Retain only the selected Provider/model strings needed across the mutable borrow. Progress redraws never emit an assistant answer; only the read-only confirmed terminal Run may do so.
- Race attached selected-Provider admission against the existing sticky cancellation waiter before constructing the Engine. A typed pre-Run interruption reloads the Session and returns to the same draft/caret with ordinary feedback, not a cancellation receipt, retry or restored original objective. Already delegated account work can finish; no rollback is implied. Restore the linear reader's actual draft byte count after panel cleanup on recoverable failure or interruption. Pre-Session prompt preflight and fatal terminal shutdown keep their separate contracts.
- Inline routine progress draws the committed status projection without a generic notice hiding model/context bytes; linear progress retains its labeled append-only notice. Cancellation and validation notices remain explicit in both modes.
- Run shared pure selection validation before consuming an objective draft, including the explicit effort required by unreviewed native and ChatGPT models. Rejection from that check preserves inline text/caret without credential, State, Workspace or Provider I/O. Ctrl+K Setup or Models keeps that draft. Missing Provider/model also retains the inline draft with setup guidance. Linear mode clears the submitted physical line because it cannot edit it retrospectively. Later credential/evidence/State failures or attempted effects do not imply safe resubmission.
- Idle `/provider chatgpt` validates the selected account before changing defaults. Its typed account-selection failure becomes local error feedback, with `/setup` guidance for no selected account, while Provider/model/effort/account source remain unchanged. Do not restore the consumed command, retry, start sign-in or change billing automatically. State persistence/replay and terminal-owner failures retain their fatal paths.
- Active inspection captures the last committed Session sequence once before starting the submission. Only Run facts accepted after that boundary may supply `/provider`, `/model` or `/status`; before current progress, report selected defaults and admission without prior Run IDs or context. Keep current terminal snapshots inspectable while awaiting the receipt. Active `/status` places recorded context-input used/budget bytes before Session/Run IDs for 40-column inline output, only while that current Run is Active; finished or legacy facts are not current draft usage.
- Active attached input stays in the terminal-local composer. Inline Ctrl+O inserts a bounded newline without submitting; Enter on an objective retains the draft for submission only after the Run ends. Trusted slash commands provide read-only inspection or a locked notice, never a second Run or mid-Run default/Session mutation. Reacquisition restores the linear reader's retained draft-byte count.
- Bare `/agents` opens the local read-only inspector while idle or during a Run. Keep the Run future selected while it is open; the existing argument form alone changes next-Run collaboration defaults, and active arguments stay locked. A completed Run closes the inspector before its confirmed receipt.
- Attached Unix SIGTERM/SIGHUP exits from every input-owning state; an active Run requests Engine cancellation and may emit a receipt only after terminal restoration and confirmed read-only replay. Preserve private setup error categories through the shared slash/quick-action caller: recoverable account/Provider failures become chat feedback, while typed shutdown or terminal-owner failure propagates to exit and restoration before defaults persistence. Classify at the operation boundary, never by matching display text. Shared setup notices must describe facts valid both before Session creation and inside an existing Session; place caller-specific state claims at that caller. A second Ctrl+C during cancellation forces the same bounded exit. An interrupted compaction makes no cancellation claim.
