# CLI composition

Load when changing `main.rs`, `src/cli.rs`, or `src/cli/` command admission, process channels, or command-specific Engine composition. Terminal rendering rules remain in [terminal.md](./terminal.md); Provider and Workspace trust remain in [provider.md](./provider.md) and [security.md](./security.md).

- `main.rs` owns command selection and exit codes. The private CLI files select trusted inputs, call the Engine, and project only committed facts; they never implement Run transitions or provider wire logic.
- Initialize opt-in telemetry from `--otlp-endpoint` or the supported OTLP endpoint variables before the Tokio runtime and Workspace admission. Invalid explicit telemetry configuration exits 2 without state creation; Collector outages after admission never change a Run result or JSONL channel. Shut down the bounded worker after the runtime returns.
- `exec` requires an explicit native Provider or `custom:NAME` profile and a model; `--effort` selects a reviewed native model-specific level or one exact checked native model/effort tuple. Validate the objective, collaboration policy, Session ID, basic model ID, and obvious state/Workspace overlap before credential loading or state creation. Reviewed model/effort combinations resolve before reading their key; an unreviewed tuple requires explicit effort and must compare current evidence against the selected key before Workspace input. The Engine's handle-based Workspace check remains authoritative.
- Select only the chosen Provider credential before Workspace content. Native runs validate model/effort before reading their named environment key, then pass that key by value to the selected adapter; native catalog discovery passes the selected key without mutating process environment. There is no fake-provider product flag, hidden model default, or automatic fallback.
- `provider check PROFILE [--state-dir DIR]` retains the custom exact-profile path. `provider check openai|anthropic MODEL --effort LEVEL --accept-cost [--state-dir DIR]` is a separate environment-key path: consent and tuple validation precede state/credential work, then a bounded catalog read and at most three potentially billable synthetic inference calls run without Workspace data. The checked constructor revalidates exact evidence before an environment-backed `exec` Run. Human custom Run receipts label it `Provider: custom verified`; JSONL carries custom provenance in `RunStarted`.
- `provider models PROFILE [--state-dir DIR]` lists every account-visible native model or the one configured exact custom model. It reads no Workspace content or unselected credential; native entries outside the reviewed table require a separate current check before an `exec` Run. Model discovery does not replace `--model` or authorize an unreviewed model.
- Idle attached `/models` uses the same bounded catalog, keeps terminal ownership and signals live during discovery, and pages through only visible rows. Its inline browser filters cached model IDs locally; linear mode retains numbered pages. Selecting any listed entry updates next-Run defaults and clears effort only when the model changes; an unreviewed native entry still needs exact conformance before `/effort` or a Run. Active Runs cannot open the catalog. An exact custom profile lists its configured model without a credential or inference request.
- Idle inline `Ctrl+K` selects the existing Models, Agents, or Sessions path without taking the composer. The Sessions action rejects a nonempty draft before State access: submit or clear it before switching Sessions. Opening the local selector itself performs no Provider or credential I/O. Linear/screen-reader mode retains only the slash-command path.
- Close the writable Engine and reopen state read-only before `exec` emits a result. Project only the current invocation's committed facts; [terminal.md](./terminal.md) owns their channel and rendering contract.
- Enable Tokio's time and I/O drivers in the product runtime; Run deadlines and native HTTP adapters rely on them even when the command has no explicit timer or socket.
- Bare attached mode admits terminal stdin/stderr before creating a Session. A positional prompt preflights only its selected Provider credential/model after TTY admission but before Session creation; an unavailable selection must not leave an empty Session behind.
- Bare new attached mode with no explicit Provider selection loads one selected native API account from its pinned protected backend, or opens first-run setup before Session creation; `--setup` deliberately replaces that selection. Setup prefers the OS keyring, and offers the private-file fallback only when no keyring backend is pinned and the keyring is unavailable, with explicit pre-save warning and confirmation. Setup asks for access method, native Provider, hidden API key, account-visible model, and model-specific effort. An unreviewed model requires explicit effort and a separate billable-check confirmation; only successful exact saved-account evidence permits saving it. Cancellation or unavailable credentials create no Session, though an interrupted in-progress save may have changed the account. The ChatGPT-plan choice is visible but unavailable until its separately admitted OAuth route exists. Explicit Provider flags and resume/fork/continue bypass automatic setup. `exec` remains noninteractive and uses an explicit environment key.
- Before activating ChatGPT-plan setup, persist one stable opaque host ID before first sign-in and retain a newly issued client ID before code redemption; a failed `invalid_grant` must restart authorization under that issued registration without retrying the spent code. Keep these account identities separate from Session IDs and from token persistence.
- Save a completed setup account only while holding the Store's default-user-root private nonblocking account-replacement lock through the selected backend write; a busy or unsafe StateRoot fails setup without creating a Session. The keyring path writes only a backend marker to StateRoot and uses the supervised private credential helper; the user-confirmed file path writes the bounded account under private-mode file controls. Read-only account selection still validates the pinned UUID and Provider at use.
- Attached mode selects the terminal presentation before raw acquisition: explicit `--screen-reader`/`ARANY_SCREEN_READER=1`, `TERM=dumb`, and short or unmeasurable terminals use labeled linear output. `--no-color`/`NO_COLOR` disable inline semantic accents before the first frame and across reacquisition without changing facts; linear output stays unstyled. Ineligible pipes still fail before Session creation.
- Exact-ID `--resume` reuses persisted defaults unless explicit flags override them; `--fork` requires a committed Run boundary and starts with unselected defaults. Local resume, fork, and rename need no Provider credential. A positional prompt must resolve and preflight its selected Provider before any new Run.
- `--continue` chooses the latest committed Session for the admitted Workspace and uses the same persisted-default and prompt preflight path as exact-ID resume. Discovery itself reads no Provider credential.
- Bare `--resume` opens the Workspace-scoped picker before creating a Session; `/sessions` and idle `/resume` without an ID open the same picker. Escape leaves the current Session unchanged. A selected row passes through exact-ID resume before it replaces the current view; listing never loads a Provider credential.
- Idle `/compact` uses only the selected admitted Provider/model and the Engine's Workspace-checked compaction operation. Report its committed success/failure and usage without displaying model-authored summary text. Ctrl+C drops the local attempt and reports interruption, not cancellation: an already queued Event append can still commit, and a remote Provider may still have charged for the call. Reload the committed Session view after interruption.
- After a successful attached Run, restore the terminal and emit its confirmed receipt before an automatic context-maintenance call. If its committed config reached the context threshold, print a durable warning, then compact only that Run boundary with its pinned Provider/model through the Engine's duplicate-safe automatic operation. Failure is visible but does not change the completed Run or canonical history. `exec` does not add a hidden compaction call or change its output contract.
- After an attached Run, restore terminal ownership and reopen its committed view read-only before emitting an answer or receipt. Keep its signal listeners alive during output and reacquire the selected attached presentation only afterward.
- Attached Run composition subscribes to Engine `RunProgress` before starting the Run and selects over committed updates, terminal input, and completion. Progress redraws never emit an assistant answer; only the read-only confirmed terminal Run may do so.
- Inline routine progress draws the committed status projection without a generic notice hiding model/context bytes; linear progress retains its labeled append-only notice. Cancellation and validation notices remain explicit in both modes.
- Active `/status` places the current Run's recorded context-input used/budget bytes first when available, ahead of Session and Run IDs, so the value survives 40-column inline truncation. It never presents a finished or legacy Run's missing footprint as current draft usage.
- Active attached input stays in the terminal-local composer. Inline Ctrl+O inserts a bounded newline without submitting; Enter on an objective retains the draft for submission only after the Run ends. Trusted slash commands provide read-only inspection or a locked notice, never a second Run or mid-Run default/Session mutation. Reacquisition restores the linear reader's retained draft-byte count.
- Bare `/agents` opens the local read-only inspector while idle or during a Run. Keep the Run future selected while it is open; the existing argument form alone changes next-Run collaboration defaults, and active arguments stay locked. A completed Run closes the inspector before its confirmed receipt.
- Attached Unix SIGTERM/SIGHUP exits from every input-owning state; an active Run requests Engine cancellation and may emit a receipt only after terminal restoration and confirmed read-only replay. A second Ctrl+C during cancellation forces the same bounded exit. An interrupted compaction makes no cancellation claim.
