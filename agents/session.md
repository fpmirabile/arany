# Sessions and collaboration

Load when changing Session lifecycle, resume/fork/rename, compaction, context reconstruction, collaboration policy, agent topology, queued input, or per-Run budgets.

The [decision register](../docs/research/next-step-decision-register.md) and [context research](../docs/research/context-memory-and-compaction.md) retain reasons and alternatives. This file retains the Session lifecycle/context contract and editing constraints; the [Goals spec](../docs/specs/goals.md) owns durable Goal transitions, budgets and plan contracts, while the [execution spec](../docs/specs/execution.md) owns bounded Run coordination and delegation.

## Domain boundaries

- A Session is one durable ordered conversation across process exits. A Run is one bounded execution caused by one accepted user Message. An AgentRun is one primary or child execution inside that Run.
- Every accepted task belongs to a durable Goal; each Run is linked before its accepted Message. Replay rejects missing linkage and projects unfinished Goals as interrupted without retrying prior calls or effects. Starting a Goal seals an unfinished predecessor as interrupted, so at most one Goal is Running; explicit resume targets only the most recent unfinished Goal, and older paused Goals are history. Goal is task lifecycle; Session remains conversation/history identity.
- Resume preserves Session identity. Fork creates a new Session from an exact committed Run boundary and records immutable source Session, Run, sequence, and prefix digest.
- A fork's first Event is `SessionForked`; replay resolves at most eight lineage links and 10,000 total Events, verifies each canonical Event-prefix digest, and includes only inherited committed Runs through the recorded boundary. A missing or changed source fails replay before context compilation.
- Historical agents remain inspectable after resume; no in-memory child is fabricated or restarted. Retrying interrupted work creates a new Run ID.
- A pre-`RunStarted` interrupted objective has no pinned Workspace identity. Later completed Runs may be forked or compacted in their admitted Workspace; compaction carries the old objective as unanswered data, while a fork inherits only committed terminal Runs.
- A new Session's versioned start Event pins its admitted Workspace identity even before the first Run. Every later Run and fork must agree with the pinned identity.
- `--continue` selects the matching Session with the greatest committed Event sequence, then revalidates it under the exact-ID resume path. Discovery reads canonical Events, never directory names or a mutable index; malformed history fails rather than choosing an older Session.
- The `/resume` picker lists only canonical heads bound to the admitted Workspace, newest committed activity first. Its titles and selection are presentation data; choosing a row still runs exact-ID resume and fails without switching if replay or Workspace revalidation fails.
- `SessionView.title` preserves the canonical creation/rename text; `conversation_title()` projects the readable name without a rename Event. Replay retains explicit-title provenance, including deliberate placeholder-looking names. Fork resolution pins a bounded inherited generated title to its verified source prefix before later source activity can affect display.
- Discovery projects the first successfully completed primary summary into a bounded readable title; non-placeholder creation and explicit rename win, with first-objective/empty fallback. Creation and last activity come from canonical Event timestamps, not file mtime or picker focus. Fork metadata is limited to its recorded source prefix. This adds no Provider call or canonical rename.
- Attached resume preserves configured defaults; absent selection recovers the latest Run tuple, then the current/user default. Account-only selection may restore only its same-account tuple. Persist inheritance before switching and preserve Session collaboration policy. Credentials remain user-scoped; replay/preferences never authorize a replaced account or a billing fallback.
- Provider-hosted conversation IDs, prompt-cache keys, and opaque compaction items are accelerators, never canonical Session history.

## Collaboration policy

- Pin exactly one `single`, `auto(max_active_children = N)`, or `team(max_active_children = N)` policy before each Run. `SessionDefaultChanged` records a complete validated next-Run selection only while idle; every Run still re-admits its selected Provider before Workspace input.
- The primary AgentRun owns the final answer and an ordered `0..N` collection of direct read-only children. Children cannot spawn nested teams in beta.
- `N` bounds total direct children, despite the field name `max_active_children`. Admission respects Session policy, process safety and remaining call/token/byte/time budgets. The separately pinned Provider concurrency ceiling limits simultaneous calls; admitted children may wait in the ordered queue.
- Default `auto` to at most three total direct children. `single` admits none. `team` requests team-oriented decomposition but still cannot exceed effective capacity. The [execution spec](../docs/specs/execution.md#collaboration) owns this distinction.
- Every child has a causal assignment, stable identity, isolated context, and persisted terminal disposition. Cancellation reaches every admitted child.

## Session commands

- Bare `arany` opens a local new conversation; attached startup and `/new`/`/clear` create its durable Session only on the first task submission after local selection validation. Local commands, setup, rename, model changes and draft editing keep that conversation unsaved. Exit or resume discards it without Session Events or a resumable ID. Explicit Engine creation and forks remain durable; existing empty Sessions remain readable and are not deleted. `--continue` resumes the latest admitted-Workspace Session; `--resume` resumes an exact Session or opens the picker; `--fork` creates a new Session at a committed boundary.
- Interactive Session commands are `/resume [SESSION_ID]`, `/new` with `/clear` as its familiar alias, `/fork`, `/rename`, and `/compact`. `/new` copies the current next-Run defaults into a fresh unsaved conversation, not startup preferences or prior title/history. It preserves account identity without loading credentials or renewing capability evidence; later Run admission still revalidates the selection. First submission persists its current explicit title and defaults before Run admission. A failed admission after submission may retain a Session; no rollback or guaranteed Message acceptance is implied.
- Do not implicitly resume based only on the current directory. A draft or active Run must be handled explicitly before switching Sessions.
- Provider, model, effort, profile, permission grants, and collaboration defaults may change between Runs, never during one. Attached dispatch approval mode can change between effects, narrowing the same pinned grant without rewriting Session defaults or an outstanding intent. `RunStarted` persists the resolved immutable values with explicit nullable fields; missing fields reject.
- A saved native API account is selected by a UUID in Session defaults, never by replayed credential bytes. The CLI resolves that UUID and exact Provider against the current protected account before Run or catalog access; replacing the account makes an older Session's saved-key selection unavailable rather than silently switching billing identity. `RunStarted` pins the selected saved-account UUID as explicit nullable provenance; replay requires a native Provider and UUIDv7 when it is present. Missing fields and unsupported versions reject under the [current-format contract](../docs/specs/execution.md#admission-persistence-and-recovery).
- ChatGPT Session defaults pin the selected account UUID without a token. Each Run and compaction records its account UUID, opaque admission fingerprint, closed admission category and local-only output bound; strict replay validates the combination but cannot turn history into current account authority. Records require `account_consent`; missing categories, provenance fields or output bounds reject.
- `exec` creates one Run and exits by default. Appending to an existing Session requires an explicit Session ID.

## Context and compaction

- Explicit include data carries an escaped relative path, SHA-256 of the raw file bytes and untrusted snapshot text; count the full envelope in the context budget. Keep the raw file digest pinned separately. Historical Tool context identifies its previous-Run scope; it never denotes a pending current result or forbids a fresh inspection.
- Context compilation is deterministic over committed local Messages, Events, instruction snapshots, exact budgets, and the selected Provider capability snapshot.
- Past Tool attempts/results, including failed and incomplete Runs, enter primary history and compaction only as bounded untrusted facts. An unfinished intent says uncertain; it is never replayed, retried or reused as approval. Active Goal compaction covers only an acknowledged Tool prefix of its exact Run, preserves all canonical observations, and leaves the completed-Run `ContextCompacted` proof unchanged. Tool history consumes the remaining context budget; images still contribute metadata rather than pixels to a summary.
- Compaction never deletes or replaces canonical history. It creates a digest-bound derived snapshot covering an exact Session prefix with author/provider/model/schema provenance.
- Manual Engine compaction summarizes accepted Run outcomes after the latest valid summary, including unanswered failed/cancelled/interrupted objectives as data. Its `ContextCompacted` Event records provider-neutral model-authored text or a typed failure; replay checks source/content digests and version before any later Run can select it. A failed attempt preserves the last good summary.
- Check remaining resolved Event capacity under lineage locks before inference. A manual or automatic compaction attempt has no lifetime attempt quota; Goal compaction is charged to the Goal Provider-call budget instead. A rejection makes no Provider call and appends no attempt.
- `/compact` runs only while idle and exposes its Provider usage. `RunStarted` records explicit selected context-content bytes, compactable Session-history bytes, and the policy-adjusted budget. After a successful attached Run, automatic maintenance triggers on 80% context pressure with at least 10% compactable history, 24 of 32 selectable history Runs, or compactable bytes approaching the independent compaction-input cap. The source-pressure guard reserves two maximal canonical turns because the recorded footprint predates the current reply and the previous unchecked turn can also grow the source. Derive this headroom from the shared Message and image-metadata limits; never raise a cap to make maintenance pass. A visible warning precedes one attempt for that exact committed boundary. Immutable Workspace input alone never triggers a useless call. Unmaintained or failure-heavy prefixes can still exceed the source bound and must reject before Provider egress. Failure is recorded but not automatically retried at the same boundary; manual `/compact` remains available. `exec` makes no hidden post-Run Provider call.
- A snapshot mismatch, fork outside its covered prefix, incompatible Provider item, deleted source, or compiler version other than the current version 3 invalidates the snapshot and fails closed.
- Cross-Session Memory remains a different product. Session history does not silently become durable Memory.
- A step declares its model Tool requests on its `ToolRequested` record. `ToolStarted` needs a declared request not yet started, a continuation needs every declared request observed, and a compaction prefix ends on a whole step, counting model Tools only (integration Tools excluded).

## Persistence and proof

- Every canonical Event carries `session_id`; Run and AgentRun scopes are optional where the Event is Session-only. Session lists may use rebuildable indexes, never a second source of truth.
- The reducer's committed-Event transition is shared with live Run observation. Closed replay labels an unfinished final Run `Interrupted`. A later `MessageAccepted`, idle `SessionRenamed` or `SessionDefaultChanged` also seals that unfinished predecessor as interrupted, preserving observed calls, terminal agents and committed Messages while rejecting later facts for the abandoned Run ID. Lifecycle callers enforce live-operation exclusion with the per-Session lock; stored metadata is not proof of lock ownership. Ordinary in-process Run progress must not apply the end-of-history interruption rule.
- Typed Event envelopes still require payload validation at the reducer boundary, not only SQL decoding. Tool transitions require the pinned policy/Workspace/primary identity, one preceding Tool-requested call, one matched intent/result and aggregate bounds. Missing receipts, widened limits, duplicate results and continued/successful work after uncertain/cancelled effects reject.
- Internal command changeset integration requires the immediately preceding
  attested command observation, its exact intent digest and identical validated
  changeset. It consumes effect capacity without inventing a model Tool request.
  Replay rejects changed/missing sources and duplicate integration; it retains
  both stages as historical facts and never re-executes either.
  Pin each accepted AI review to its pending Tool in the projection; inferring
  ownership from adjacent review calls permits duplicate integration reviews
  when approval modes change between command execution and publication.
- `ProviderCallRecorded` is an AgentRun fact: primary planning precedes children, child work is a sequence of ChildWork calls, each after the child's previous read-only Tool observation, and primary synthesis follows finished children. A child spawn requires an observed Delegated call, and successful Agent completion requires an observed Finished call. It stores bounded observed outcome, response ID, provider-reported token usage, optional accepted wire provenance and optional closed failure reason. A reason must match a rejected or unavailable call; it is not upstream text or current account authority. Absent usage is unknown, not zero. A nullable wire provenance is explicit; omitted fields reject. The closed provenance value reports a local request control and accepted wire completion, never a Provider privacy guarantee. A plan-less Tool request opens a plan wait. While it is open, only the plan record, prelude Tool events, explicit resume, and Failed or Cancelled AgentFinished/RunFinished are accepted; RunFinished clears the wait.
- `GoalSteeringNoteRecorded` is accepted only while the latest Active Run's primary AgentRun holds an open planning or synthesis provider reservation in its Goal (not a Tool review or pending Tool observation); replay rejects it anywhere else, enforces the Run's 8 KiB note total, and never re-delivers it. Its contract lives in the [Goals spec](../docs/specs/goals.md#steering-notes-and-pause).
- Persist Session creation/default/rename/fork/compaction facts plus existing Run and AgentRun lifecycle facts. Do not persist terminal focus, panel state, hover, picker selection, or native scroll position.
- One evidence-dense scenario must prove multiple Runs, process exit, resume, provider change between Runs, bounded `N`, fork prefix identity, compaction failure safety, and deterministic replay. Boundary tables own `single`, `auto`, capacity, cancellation, and invalid snapshot cases.

- `AssistantDisplayRecorded` is a display-only primary/call-scoped Event. Replay enforces sequential byte offsets, legal active call phases and the terminal contract's per-Run bytes/items/chunk bounds, including at most one compiled detail-limit cue. It never supplies `MessageCommitted`, Agent results, Provider context or compaction items. An accepted primary result must match every checkpoint of its final call; delegation/Tool calls cannot accept answer checkpoints. Cancelled/interrupted replay can expose these facts as incomplete; failed validation hides its candidate while explicit journal export retains the qualified facts.
