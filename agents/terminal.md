# Terminal presentation

Load when changing interactive terminal behavior, plain or JSONL output, accessibility, cancellation keys, terminal ownership, presentation dependencies, or the user-visible projection of a Run.

The evidence and rationale live in `docs/research/beta-terminal-interface-and-multi-agent-feedback.md`. This file is the concise working contract.

## Product modes

- Bare `arany [PROMPT]` is the attached-human command. It requires terminal stdin and stderr, creates a durable Session, draws a full-height primary-screen interface on stderr without alternate screen, and writes confirmed assistant results to stdout after restoring terminal ownership.
- A bare new attached start without an explicit Provider shows the ordinary Session composer even when no account is saved; inline welcome/status and linear Session facts name `/setup` immediately, while an unconfigured objective gets the same local guidance and starts no Run. Idle `/setup` opens choices in that Session; `--setup` deliberately opens the wizard before Session creation. Cancelling before account save preserves the Session and its defaults, while cancelling pre-Session `--setup` creates no Session. After a ChatGPT account is saved, cancelling its model/check steps keeps account-only defaults; a successful explicit check pins its model and effort. No unchecked catalog row becomes runnable.
- A ChatGPT account already selected at the OS-user scope adds an inline or named linear `Use saved` / `Reconnect` / `Connect new` step after access-method selection. If multiple accounts are saved, `Use saved` opens the same bounded choice UI with short UUID suffixes and a current-account marker; cancelling there changes neither selection nor Session. Reusing the current account keeps the model browser, effort, and cost-consent flow without browser login; cancelling, declining, or failing its catalog/check before a successful check changes no Session defaults. Switching to another saved account is an explicit OS-user selection, so a later cancellation or catalog/check failure retains account-only Session defaults. Reconnect repeats the backend-specific warning and browser sign-in for the selected account, then clears prior model evidence. A newly connected or reconnected account retains account-only defaults after model-selection cancellation or catalog/check failure, with a retry notice for failures. All labels and focus remain readable at 16 columns without color.
- Without a prompt, bare `arany` opens the Session composer. With a prompt it starts the first Run after validation and remains interactive. `--continue`, `--resume`, and `--fork` own explicit Session entry semantics; never resume implicitly from TTY or directory detection.
- `arany exec --output text|jsonl` is deterministic and noninteractive. It never initializes terminal modes and is the contract for CI, pipes, and captured logs.
- `exec` text stdout contains only a sanitized, indented committed answer; stderr carries the stable Session/Run/status receipt. JSONL stdout contains the new Session fact, if any, and only the current Run's committed Events; successful JSONL leaves stderr empty. A failed Run exits unsuccessfully and never fabricates an answer.
- `arany show --output text|jsonl SESSION_OR_RUN_ID` deterministically replays committed Events and never initializes terminal modes.
- Do not infer product behavior from TTY detection. The command selects the contract. An ineligible bare invocation fails before the Engine starts and directs the caller to `exec`.
- `--screen-reader` or `ARANY_SCREEN_READER=1` uses a labeled append-only presentation with no raw mode, redraw, boxes, cursor focus, or animation.
- `TERM=dumb`, fewer than eight terminal rows, or an unavailable size selects the same linear mode before raw acquisition. The choice remains fixed for that terminal ownership; Linux PTY evidence covers canonical line input, while native macOS behavior is still a release gate.
- `--no-color` and `NO_COLOR` disable inline color, including after terminal reacquisition. Semantic leads, focus, and attention/error notices carry restrained accents; selection markers, bold focus, labels, and wording preserve the same facts without color. Slash placeholders and completion suffixes use ordinary intensity in monochrome mode; textual brackets distinguish untyped hints from editable draft text. Linear and deterministic output stay unstyled. No fact may depend on color, icon, alignment, or cursor position.

## Interactive commands

- The complete beta set is `/help`, `/setup`, `/status`, `/sessions`, `/new`, `/clear`, `/resume`, `/fork`, `/rename`, `/compact`, `/agents`, `/provider`, `/models`, `/model`, `/effort`, `/permissions`, `/quit`, and `/exit`.
- Commands are compiled trusted local controls. Workspace text, instructions, providers, models, Skills, and persisted data cannot register, shadow, or redefine them.
- Only a single `/` at column zero followed by an exact lowercase registered name is command syntax. `//text` submits `/text` as the objective. Unknown leading commands are local errors with suggestions; they are never billed Provider input.
- Inline slash names and argument schemas come only from the compiled registry. Tab completes a unique command name, static Provider/collaboration value, or a selectable model from the last explicit `/models` catalog; effort choices follow the selected reviewed native model or loaded exact custom profile. Changing Provider invalidates cached model choices. Unsupported catalog entries never become completion candidates; ambiguous prefixes leave the draft unchanged. Preview hints and their status appear only when the caret is at the draft end, where Tab may complete a choice; argument placeholders remain until typing starts in that slot, but never enter the draft, a submitted command, or an Event. Do not perform catalog or credential I/O on a keystroke. Linear/screen-reader mode keeps canonical input and announces that arguments are literal and Tab completion is inline-only.
- A unique argument prefix shows the complete Tab result; a complete known choice shows that Enter submits the command instead of continuing to advertise Tab. These are local hints, not a guarantee that an active Run will accept a locked command.
- Inline `/help` opens a terminal-local scrollable panel built from that same closed registry; Up/Down, PageUp/PageDown, Home/End navigate, and Enter/Escape return to the composer and prior history position. It remains usable while a Run progresses, while Ctrl+C still cancels that Run. Linear/screen-reader mode keeps the complete append-only help notice. The panel does no State, credential, catalog, or Provider I/O.
- Validate an idle submitted draft before consuming it. An unknown slash command or locally invalid argument keeps its bounded inline text and caret so Backspace or Tab can correct it; the notice remains local and creates no Event or Provider input. Reject unexpected arguments on no-argument controls before acting. Errors after State access or an attempted effect do not restore a command for automatic resubmission. Linear/screen-reader input cannot edit a submitted physical line, so reject it with a labeled notice and start the next line with an empty draft rather than joining commands.
- While idle, `/provider [id]`, `/model [id]`, and `/effort [value|default]` update Session defaults for the next Run. `/models` opens a bounded page-by-page catalog for the selected Provider, with numbered selection in linear mode. Inline mode keeps a local, at-most-64-character ASCII search over the already loaded model IDs; typing filters, Backspace edits, navigation selects visible rows, and Enter with no matches changes nothing. The search never enters the composer, Session, Provider request, or scrollback. At widths below 80, each inline row puts its textual `reviewed`, `check`, or `exact` classification before the model ID so a long ID cannot displace it; long ASCII IDs retain both ends, while untrusted text uses the terminal sanitizer. `provider models` supplies the full ID when the inline preview is ambiguous. An unreviewed native entry can be staged there or typed into `/model`, but cannot run until `/effort` revalidates exact current conformance evidence. A Provider or model change clears an incompatible effort. During a Run `/models` is locked, while `/provider`, `/model`, and `/effort` are view-only and report `locked for this run`.
- `/agents` opens agent details and configures `single`, `auto`, or `team` plus the bounded maximum active children for the next Run. It does not mutate an active topology.
- The `/agents` inspector selects primary-first AgentRuns across the 16 most recent Runs, newest Run first. It displays identity, role, state, objective, summary, and result as bounded inert previews; `arany show SESSION_ID` remains the complete-history path. Inline Up/Down selects an agent, PageUp/PageDown scrolls details, Home/End jumps, and Escape or Enter closes. Linear mode uses numbered selection, `n`/`p`, and `q`, with labeled append-only output and visible invalid-choice notices.
- If a Run ends while the linear agent inspector is open, discard the terminal's incomplete canonical input before returning to the composer. Otherwise a half-typed picker choice can join the next command and become a new objective.
- Attached automatic compaction prints a plain warning after a confirmed Run receipt and before its separate Provider call. The resulting notice reports committed compaction status and usage without exposing summary text; interruption does not imply rollback of an already queued append.
- Session commands operate only at committed boundaries. `/clear` is the familiar alias of `/new`; it never means deleting history. `/compact` creates derived context and never replaces canonical history.
- During active work, the composer retains bounded draft edits. Enter on an objective retains it for explicit resubmission after the Run ends; it never queues or steers a Provider call. A parser-rejected inline slash command also keeps its text and caret for correction; linear/screen-reader mode clears the rejected submitted line. Valid slash commands provide local read-only inspection or a locked notice without changing Session defaults. `/quit` and `/exit` explain that `Ctrl+C` cancels the active Run before the Session exits.
- `exec` and `show` never interpret `/`, `@`, or `!`. A slash-prefixed `exec` objective is literal.
- `/permissions` reports effective facts: explicit bounded reads, no Workspace writes, no process Tools, only selected Provider requests from Arany, possible auxiliary OS TLS certificate connections, and no sandbox claim. It cannot change authority.
- Reserve `/approve`, editable `/permissions`, approval flags, and sandbox flags until typed effects, Policy, Guard, and attestation exist.

## Ownership and data

- `presentation.rs` is pure. It maps committed `SessionView` and active `RunView` state into bounded semantic rows and append-only transcript lines.
- The `terminal` module owns Ratatui widgets, Crossterm input and resize events, the bounded grapheme-aware composer, primary-screen history/focus state, and one RAII terminal owner. Its private `input.rs`, `composer.rs`, `history.rs`, `linear.rs`, and `view.rs` files separate event decoding, draft editing, lazy committed-history indexing, append-only output, and drawing from lifecycle ownership.
- The Engine exposes reconstructible facts and a cancellation handle. It imports no terminal library or presentation state.
- Interactive Arany, screen-reader mode, `exec`, and `show` expose the same committed facts. Draft text, shelf focus, palette selection, folding, width, hover, and loaded timeline window are presentation-local and never canonical Session state.
- Persist assignment cause, waiting sets, typed state reasons, provider-call attribution, usage provenance, safe progress summaries, handback status, cancellation stage, errors, and durable sequence. Never infer them from UI arrival order.
- Show Engine facts and bounded agent-authored work summaries. Never expose chain-of-thought, raw prompts, provider token streams, reasoning items, tool payloads, or raw error bodies.

## Terminal behavior

- Use a full-height Ratatui viewport on the primary screen. The normal layout is committed Session transcript, conditional agent activity, composer fixed above the bottom status row. Terminal-owned history indexes message row counts without copying the full transcript; it appends newly committed turns at a stable width, materializes only visible message rows, and keeps an older reading anchor stable as content arrives. `PageUp`/`PageDown` navigate, `Ctrl+F` opens a bounded literal find whose Backspace removes one grapheme, and `Ctrl+L` returns to the live tail. The find status keeps the newest query text and Enter/Escape hints visible when space is scarce. Up/Down and Home/End still edit the composer. A resize preserves the source-text position within the selected message. Emulator scrollback/search is no longer the complete Session history; `arany show` remains complete. Do not enter alternate screen or enable focus reporting, title/clipboard OSC, or bracketed paste.
- An empty idle transcript shows a short, width-aware welcome inside the chat area; it disappears when committed history or agent activity appears. When no Provider is selected, that welcome and the bottom status lead with `/setup` rather than inviting a Run that cannot start. The composer has a borderless `Ask Arany` label and `> ` input lead, with one breathing row before the bottom status. These are presentation-only cues; the editable draft, caret, completion hints, and submission behavior retain their existing owners.
- Confirmed `You:` and `Arany:` transcript headings are bold; only `Arany:` takes the semantic accent when color is enabled. Message bodies remain unstyled, and the labels remain distinct in monochrome mode.
- A no-prompt inline start shows the projected idle state and selected model in the status row immediately; the welcome supplies `/help`. Linear/screen-reader starts and positional-prompt progress retain their labeled Session notice, and `/status` still discloses the full Session ID.
- Keep the single-agent case visually primary: no empty team dashboard. Show one primary row during single work; expand to at most three activity rows plus `+N more` only when children exist or attention is required. `/agents` owns the full picker/details.
- Keyboard access is complete. Mouse reporting is disabled during normal transcript/composer use and enabled transiently for visible rows in the open inline Session picker or Agent inspector. Every mouse action has a keyboard equivalent; off-list pointer input is inert, and closing or losing terminal ownership disables mouse reporting before control returns.
- Redraw only for committed updates, resize, or user actions. No spinner, animation, idle refresh, or continuously ticking elapsed clock.
- During a Run, consume the Engine's latest committed `RunView` plus sequence and redraw the active status/activity rows. Coalesced display updates are acceptable because the snapshot contains current ordered agents; canonical Events are never discarded. Linear mode prints labeled append-only facts only when the committed sequence changes.
- After the first committed Run snapshot, draw its sanitized `You:` objective from `SessionView`; linear mode appends its existing bounded labeled preview. After strict replay and terminal restoration, print the committed result and one bounded user preview into ordinary process output, then reacquire and redraw the current Session. Never echo an uncommitted submission or treat a redraw as a second Message.
- Routine inline Run updates show the projected state/model/context row instead of replacing it with a generic progress notice. Actionable retained-draft, cancellation, validation, and error notices may temporarily replace that row. Linear mode keeps its labeled progress notices and does not gain cursor rewriting.
- The canonical-line reader forwards an accepted segment as individual character events before its boundary event. Update the local composer for those characters without printing a linear notice per character; report retained-draft and validation notices at the boundary.
- The sole Crossterm reader runs on a named thread, forwards at most 32 events, backpressures when full, and is closed and joined before raw mode is released. Ignore key repeats/releases and unowned focus or mouse events outside pickers.
- The selected local Crossterm 0.29.0 Mio-source patch returns an input error on terminal EOF or permanent read failure; `WouldBlock` and `Interrupted` must not be treated as loss. The default-feature Linux idle and active lost-PTY regressions own this behavior. `scripts/source-archive.sh` preserves this patched dependency in a separate rebuildable source archive; Cargo's ordinary `.crate` strips the local patch and is not a repaired install path. Native macOS PTY-loss remains a release gate.
- Linear mode uses a separate bounded canonical-line reader without raw mode; Crossterm key events require raw mode. The reader temporarily owns nonblocking stdin flags and restores them after joining its thread, so signal-flushed input cannot strand shutdown in a blocking read. Linux admits at most 4,094 bytes per physical line and macOS currently caps at 1,023; Enter submits, while Ctrl+D after nonempty text continues a logical draft up to 8 KiB across lines. Physical, invalid-UTF-8/control, or aggregate overflow rejects the current segment visibly without submitting a truncated prefix. Ctrl+D on an empty draft exits; on a retained draft it prompts for Enter or Ctrl+C. A registered Unix SIGINT listener supplies Ctrl+C. Put its notice on a new line after the terminal's `^C` echo; print prompts as complete labeled lines to reduce queued-input/notice fusion. Suppress the input prompt during an in-flight Run or compaction, and separate a final receipt from any unfinished prompt.
- During setup and mixed-access startup, keep linear choice names visible and terminal echo enabled until the API-key field; then disable echo, keep the secret out of drawing APIs, bound it to 512 printable ASCII bytes, and restore echo on cancellation, errors, signals, suspend/resume, and terminal release. Never include the secret in a notice, transcript, or Session Event. Inline non-secret choices are centered, borderless, focused rows navigated with Up/Down, Tab, Enter, and Escape; a typed character cannot select a row. Six effort rows fit the 16×8 viewport, while a seventh provider-default row scrolls into view when selected. The ChatGPT file warning and separate plan-cost choice remain textual in narrow monochrome mode; the plan-cost choice starts focused on Back and says the remote token count is not capped. Only the API-key field shows a byte count. ChatGPT consent pages the complete warning before a visibly typed `I ACCEPT`, and linear mode announces the complete warning without cursor rewriting. Linear/screen-reader choices accept their visible names, not numeric codes. Declining the check returns to the same model row; cancelling after account save keeps account-only defaults. The OS credential store may display its own unlock prompt; Arany makes no guarantee about OS-store encryption at rest.
- Canonical terminal echo can still interleave with Arany output when a user types ahead on the next line; complete prompts alone do not remove that race. Cover it in native screen-reader review before release.
- Keep the primary first and all visible child rows in stable spawn order. Every state and wait has a textual label; completed or failed children never disappear while their Run remains active.
- Use semantic layouts for widths `>=80`, `50..79`, and `<50`. At 20–39 columns, compact picker hints keep the edit/navigation cue, Enter action, and Escape exit visible. At 16–19 columns, preserve the selected row's distinguishing suffix and the essential Enter/Escape cues; 16 columns is verified for the idle composer and quick selector on Linux tmux, model, Session, and agent picker journeys in Linux PTYs, and those picker frames in TestBackend, not for every native picker state or smaller widths. If height is below eight rows or terminal capability is unsafe, select the linear attached-terminal presentation before raw mode and do not oscillate on resize.
- The status row prioritizes state and selected model at tested widths of 40 or more; clipped printable-ASCII model IDs retain both ends so similar IDs remain distinguishable. Widths of at least 50 also show Provider, and widths of at least 80 show the current active Run's recorded `input used/budget B` when present. While reading older history at 80 or more columns, a compact history/live-tail cue precedes that same status projection; narrower widths prioritize the navigation cue alone. An actionable notice still takes the whole row. At narrower widths, active `/status` places the recorded footprint before optional IDs so it remains visible; legacy Runs without the footprint retain their existing status notice. Title appears only if space remains. This is a context-content byte estimate, not a Provider context-window percentage; a finished Run's footprint never stands in for the current draft.
- Sanitize untrusted text before width calculation. Truncate by grapheme and terminal-cell width, not bytes or scalar count.
- Session picker labels use the trailing UUID digits, not the time-ordered prefix: adjacent UUIDv7 Sessions commonly share the same leading characters. Exact-ID resume still validates the selected row.
- Inline `Ctrl+O` inserts an explicit newline; Enter still submits or retains the draft. Up/Down move between logical lines at a preserved grapheme column. Keep the cursor on a grapheme boundary; insertion, Backspace, Delete, Left, and Right operate on whole graphemes. Keep at most 8 KiB of draft text, reject overflowing insertion without changing the draft, and show at most four logical lines with horizontal windowing on the cursor line. Grow the viewport upward; when height is scarce, clip activity before the composer and status. Linear mode uses Ctrl+D after text to continue a draft instead.
- Idle inline `Ctrl+K` opens a local, keyboard-only quick selector for Models, Agents, and Sessions without consuming the composer. Up/Down choose, Enter opens the existing panel, and Escape or Ctrl+C returns to the same draft and grapheme caret. A nonempty draft blocks Session switching until the user submits or clears it; the existing `/sessions` command remains available from an empty submitted composer. No catalog or credential I/O occurs merely by opening the selector. During a Run, `Ctrl+K` gives a locked notice; `/agents` remains the detail path. Linear/screen-reader mode keeps slash commands instead of the quick selector.
- While idle, `Ctrl+C` clears a nonempty draft; on an empty draft two bounded presses exit. `Ctrl+D` exits only on an empty draft. During a Run, `Ctrl+C` requests graceful cancellation and a second press during cancellation forces bounded local shutdown after the strongest possible durable terminal state. `Esc` closes the focused picker/detail first; `q`, `Ctrl+D`, and slash commands do not cancel active work.
- On Unix, register SIGTSTP before raw acquisition and route it and inline `Ctrl+Z` through the same terminal owner. Stop and join input, clear the owned viewport, show the cursor, and release raw mode before self-SIGSTOP; after SIGCONT, recheck TTY eligibility, reacquire the selected presentation, and restore the bounded linear draft byte count from the retained composer. Preserve the pinned in-flight Run future; never stop after a failed restoration.
- Register Unix SIGTERM and SIGHUP before raw acquisition and propagate them through idle, picker, compaction, and Run paths. Retain the original listeners while the terminal is restored for committed output and transfer them into reacquired ownership; Tokio's process-wide handlers do not return to defaults when a listener is dropped. On an active Run, request cancellation, restore the terminal, and wait at most three seconds for a durable terminal outcome before reporting one; a second Ctrl+C during cancellation takes the same bounded shutdown path. If the grace period expires, do not claim cancellation or emit an answer: strict replay determines the committed state.
- Restore raw mode, cursor, wrapping, and every enabled mode on success, failure, cancellation, signal, panic, render error, partial acquisition, and suspension. Linux PTYs cover cursor-query timeout (including SIGINT, SIGTERM, and SIGHUP while raw mode is active), a separate stderr write failure during acquisition after raw mode starts, and test-helper panic unwind of the real terminal owner; arbitrary shipped-CLI panic sites remain unverified. Print the final receipt only after restoration.
- If the interactive renderer fails after a durable Run has begun, restore the terminal and fall back only to committed sanitized linear facts or a typed presentation failure; never invent state.

- Linear setup announces a new choice when its title or instruction changes, even if it reuses an internal step number; the step alone is not a screen identity.
- Linear setup and hidden-key input keep rejected typed characters as a correction-only suffix: later characters cannot become choice or key bytes until Backspace consumes that suffix, and Backspace must not erase earlier valid input first.

## Verification gates

- Pure projection and TestBackend cases cover idle Session, single-agent, bounded team/overflow, attention, context, all agent states, causality, partial results, hostile text, monochrome equivalence, and widths 40/50/79/80/120; picker-specific frames also cover 16, 20, and 24 columns.
- Native Linux and macOS PTY tests cover composer/palette/draft behavior, Session and agent pickers, transient mouse capture/restoration, exact command parsing, eligibility, raw-mode acquisition, resize, redraw, cancellation stages, EOF/signals, suspend/resume, panic/error cleanup, broken stderr, tmux, and terminal settings before/after. The Linux Session-picker owner covers SIGTERM, SIGHUP, suspend/resume mouse restoration, and raw-mode restoration after its renderer's stderr fails; a dead stderr sink cannot prove that a mouse-disable sequence reached it. The model-browser owner covers Ctrl+C closure followed by SIGTERM and strict replay without a selection; the slash-completion owner covers Tab, visual-only placeholders, and restoration. The Linux setup owner checks terminal echo off during hidden input, restored while stopped, off again after resume, and restored after cancellation or a TERM/HUP shutdown without a Session. The explicit Linux tmux gates cover an attached client, color, `--no-color`, and `NO_COLOR` rendering, an inline pane at 20/24/40/50/80 columns, both layers' terminal restoration, empty-Session replay, and active activity above a retained multiline draft without submitting that draft. The loopback-only active gate submits one Ctrl+O-delimited objective and verifies its exact newline in Provider input and strict replay. Native macOS remains open. An emitted output marker may be read after raw-mode reacquisition; restored-output signal tests need bounded writer backpressure while checking terminal settings and signaling.
- Exact screen-reader fixtures contain no CSI, OSC, carriage-return rewriting, or unlabeled state; manually verify VoiceOver on macOS and Orca on Linux before release.
- Raw interactive escape bytes are implementation detail, not golden output. Exact-byte goldens remain for `exec` text/JSONL, screen-reader output, final receipts, and `show`.
- The ignored Linux near-cap tmux gate starts from 1,600 completed Runs, keeps an older-history view and draft visible across a committed child delegation, then proves the rest of the draft, cancellation, terminal restoration, and strict replay. It uses the same selected executable for data-free conformance and the pane, with exact-process cleanup. This staged transition does not prove that a keystroke and committed update are processed at the same instant or establish macOS latency.
- The native tmux idle gate covers the composer, quick-selector opening and return, color and monochrome at 16 columns on Linux. Separate no-color Linux PTYs cover model-browser filtering, selection, and draft return; Session keyboard selection with exact-ID replay; agent-inspector navigation and close; and explicit pre-Session setup choice focus, ignored typed digits, hidden-key cancellation, and restoration at 16 columns. An unconfigured 16/40-column inline PTY covers visible draft input, local `/setup` guidance, selector closure, and a Run-free replay. The 16×8 `--setup` PTY proves hidden entry, no State, and terminal restoration. The Session picker proves SIGTERM cleanup after its complete 16×8 frame and raw-mode restoration after a separate 16×8 renderer failure, with unchanged strict Session replay. The model browser now also proves Ctrl+C close and SIGTERM restoration after reopening at 16×8, with unchanged strict Session replay; other narrow picker faults remain unverified. Full native save/reuse remains open. The native tmux active-Run gate checks one committed `You:` block plus `Arany:` answer in the owned viewport, PageUp/find/live-tail navigation at eight rows with a retained draft, focused quick-selector restoration after suspend/resume over older history, exact reading-frame restoration after selector close and separate suspend/resume, and one confirmed stdout answer after terminal restoration. The history unit owner covers arrival/resize anchoring and inert hostile text; the linear cancellation PTY covers append-only labeling. Native macOS and manual Orca/VoiceOver remain unverified.
