# Engine Run coordination

Load for `src/engine.rs` changes to Run admission, Provider calls, budgets, or terminal dispositions. Session transitions and context policy remain in [session.md](./session.md); Workspace and Provider trust rules remain in [security.md](./security.md) and [provider.md](./provider.md).

`src/engine/lifecycle.rs` owns private Session create, resume, discovery, defaults, rename, and fork orchestration; `engine.rs` re-exports its existing interface and retains Run admission.

- Admit the selected Provider profile and bounded request before reading Workspace content. The raw objective and aggregate image caps jointly fit `MessageAccepted`'s kind/version payload bounds even at maximum JSON escaping; preserve that relationship when changing caps or encoding. A Run pins its Workspace identity, instruction and include digests, history selection, policy, model, resolved effort, and output cap before calling the Provider.
- A custom Run's `RunStarted` also pins the exact admitted endpoint and evidence fingerprint. The Engine rejects a `custom:` Provider without that provenance before Workspace input; replay treats it as historical evidence, never fresh authorization.
- A ChatGPT-plan Provider declares an account UUID, opaque admission fingerprint, closed admission category, and local-only output bound together. Engine rejects a missing or mismatched declaration before Workspace input and pins it to the Run; the CLI's protected account owner, not replay, decides whether the selected identity and current storage-bound consent authorize a call. New Runs use `account_consent`; historical records without a category retain `conformance`. Neither category is fresh authority from replay. Native API-key and custom Providers retain their remote-cap category.
- `RunStarted` pins the selected context-content footprint after deterministic compilation. Automatic compaction accepts an expected Run ID, checks it under the Session lock against the latest terminal Run, and skips a boundary that already has a compaction attempt; a stale warning cannot turn into a new Provider call.
- Commit `MessageAccepted`, `RunStarted`, and primary `AgentSpawned` before the first call. Commit a bounded `ProviderCallRecorded` fact after each observed call result and before its terminal AgentRun disposition; this retains known usage in an interrupted prefix. Commit each terminal AgentRun disposition before a final Message and Run disposition. A failed call commits failure without an assistant Message; a failed journal write leaves an interrupted prefix.
- Before Workspace content, Provider usage or Tool dispatch, admit the complete worst-case Event envelope: lifecycle, bounded children and every configured Tool continuation. Store owns both lineage-count admission and the byte allowance above its per-append floor. Hold the Session and every fork ancestor's operation lock until completion because strict replay counts their full journals, including ancestor suffixes outside the inherited boundary. Independent lineages remain concurrent. Event-count admission is stable under those locks; database bytes are a conservative preflight, not a lease against independent writers or protection from disk faults.
- Carry the adapter's typed accepted wire provenance through Run and compaction records. Engine validates its ID/usage consistency before append but never infers a wire finish reason or privacy setting from a Provider name. A rejected or timed-out call has unknown wire provenance.
- Preserve the Provider's closed optional failure reason in the shared Run call recorder before AgentRun terminal commitment, including a call observed before cancellation. Never persist raw error strings, statuses or stream codes, infer a reason from Provider identity, or feed diagnostic metadata into context or telemetry. Compaction retains its existing separate failure contract.
- The Provider returns semantic `Finish`, `Delegate` or an explicitly enabled `Tool`, never direct store writes. Validate content, usage and exact serialized terminal payload bounds before accepting an outcome; JSON escaping can exceed persistence bounds while raw text still fits. Requests carry the pinned collaboration policy, with `Single` and no Tool context for children. `single` cannot delegate; `team` must delegate on its first non-Tool outcome. The private Tool router owns grants/enforcement under [tools.md](./tools.md); primary planning and synthesis share one non-widening observation/iteration budget.
- Pin the Tool grant and native enforcement profile before Workspace content. Reserve escaped result/context space and remaining Run time before committing an intent. Commit the observed Provider Tool request and `ToolStarted` before approval or dispatch, then `ToolFinished` before continuation. Optional `ToolReview` calls use the selected Provider and primary identity with Single policy, no Tools/history/includes/project instructions, a 256-token output cap and a 20-second ceiling. Journal their usage and preserve the aggregate 32-call headroom; uncertainty or failure asks a human, never creates an answer or a broader grant. Missing/uncertain results stop without automatic retry; cancellation keeps earlier effect facts and never implies rollback. A journal failure after dispatch leaves an uncertain interrupted prefix.
- The private child queue owns every spawned call. Admit and persist child identities in ordinal order, run at most the pinned Provider concurrency limit, join all terminal dispositions, and pass results to synthesis in assignment order. A failed child aborts and drains siblings before primary failure; a store failure aborts and drains calls while leaving replay to label the incomplete prefix interrupted.
- Explicit cancellation is a sticky caller signal. Its semantic waiter also lets callers interrupt pre-Engine admission without duplicating cancellation state; dropping a waiter does not undo started work. Before `MessageAccepted` it admits no Run; after primary admission it drops in-flight Provider calls, aborts and drains children, then commits `Cancelled` AgentRun and Run facts without a final Message. Both successful and failed primary transitions recheck cancellation before their first terminal append; once that commitment starts, its transition wins. Preserve earlier observed call records and child dispositions rather than relabeling them cancelled or erasing known usage. A failed store write leaves an interrupted prefix rather than a false cancellation receipt.
- Optional `RunProgress` observes only acknowledged Events through the Session reducer. Its one-slot watch channel coalesces superseded `RunView` snapshots without blocking append or losing canonical Events; the published sequence belongs to the last committed Event. An observer cannot authorize, steer, or cancel a Run, and projection failure leaves the committed prefix for strict replay. A test may receive the terminal snapshot while checking the last child; retain it instead of waiting for another update.
- One Engine Run is active per Engine instance. Session operation locks span each Run, source fork, and compaction; Run/compaction additionally retain ancestor locks as above. Busy operations fail before Workspace content or Provider disclosure. Session replay recognizes incomplete prefixes as interrupted; retry creates a new Run. The Linux product-process gate proves exclusion and lock release after holder death; macOS and orphan-quota gates remain before claiming global release readiness.
