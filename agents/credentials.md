# Credential implementation rules

Load for changes to `src/cli/credentials.rs`, saved-account selection, OS keyring integration or Linux D-Bus transport admission. Read [the saved-credential contract](../docs/specs/credentials.md) for scope, storage, startup authorization, bounds and recovery. [Security](./security.md) owns repository-wide secret and supply-chain rules; [Provider](./provider.md) owns Provider admission; [ChatGPT](./chatgpt.md) owns OAuth and token consent. Native evidence and pending checks remain at the spec's evidence owners.

- Keep credentials inside the private CLI owner. The selected-account loader returns the whole typed credential after UUID/Provider validation; never reconstruct saved workspace scope from the environment. Preserve schema rejection, the outer backend marker and aggregate bounds when changing record admission. Never format a platform error or derive `Debug` for a secret record.
- On Linux and macOS, derive account roots from the effective OS user's passwd home, independently of Session/environment paths. Preserve checked no-follow handles, owner/mode checks and the replacement lock; path selection alone does not establish ACL or Keychain protection. Migration acquires the old-root lock before the stable-root lock and must preserve the spec's durable-copy/conflict behavior.
- OS-store access uses a short-lived same-binary helper with bounded private pipes, fixed service, validated slots, admitted local transport, `env_clear` plus only required OS account/bus variables and working directory `/`. Linux launches the kernel-owned `/proc/self/exe` image: resolving or stripping a deleted pathname after a rebuild can fail or execute a different binary. Keep account replacement locked until the helper completes or is killed/reaped. Secret input writing and bounded output draining run concurrently under the parent deadline; never let a large token pipe block supervision.
- Startup authorization admits only the selected item from validated private account metadata, never Workspace text or arbitrary CLI input. Validate native UUID/Provider inside the status-only helper. Recheck account selection after the wait and reload credentials at actual use; authorization does not grant Run authority. Native discovery discards its bounded credential before chat and must not duplicate the authorization or retain a cache. Keep human-interaction and routine deadlines distinct according to the spec.
- Keep native API slots and verified-client-derived `chatgpt-` slots separate. ChatGPT token write admission validates its versioned consent-bound record; deletion accepts only validated ChatGPT slots. Disconnect/clear model evidence before cleanup after a terminal refresh error; uncertain cleanup cannot reopen account use.
- On Linux, admit only a single bounded `unix:path=` or `unix:abstract=` D-Bus address with an optional exact GUID, or a bounded absolute `XDG_RUNTIME_DIR`, before invoking keyring. With both variables absent, pinned `zbus 5.19.0` connects directly to `/run/user/<effective UID>/bus` without autolaunch. Reject hostile explicit transports and address lists without command execution. Re-check all three paths whenever keyring or D-Bus dependencies change.
- Native credential-owner tests use the production supervisor for reads, writes and ChatGPT deletion, never direct `cfg(test)` keyring calls. Test builds require explicitly supplied absolute `ARANY_TEST_EXE`; shipped binaries use their own image and ignore it. Activate native owners only against an isolated service with synthetic slots. Read back the actual owner save/replacement before an independent write can mask failure. Observation processes need bounded parent wait/output and kill/reap in addition to descendant timeout; filtered children must complete exactly one test. Supply bounded synthetic input through a private file rather than a potentially blocking parent pipe.
- Debug-only `ARANY_TEST_ACCOUNT_ROOT` fixtures require an absolute path; optimized builds reject the override. Isolate both stable and legacy roots under a non-root fixture parent with explicit `HOME`/XDG settings. [Store admission](./store.md) rejects a debug legacy root outside that parent before reading or migrating ambient records. Follow [testing rules](./testing.md) and the [legacy-root incident finding](../docs/security/findings/account-fixture-legacy-root.md); a stable-root override alone is insufficient isolation.
- Synthetic write-timeout evidence establishes helper connection closure, not real OS-service rollback. Read-only availability probes do not establish writability, collection unlock or at-rest protection. Keep the [native stalled-store gate](../docs/security/findings/stalled-credential-store.md) and [cross-root gate](../docs/security/findings/default-account-slot-cross-root.md) open until their production-path evidence exists; never use the user's real wallet or make KDE a prerequisite to bypass a missing isolated service.
