# Terminal history

Load for `src/terminal/history.rs` or its callers. [Terminal presentation](./terminal.md) owns the user-visible modes and keys; this file owns only the private history invariant.

- Derive rows from the caller's already-loaded committed `SessionView`. Never read State, Workspace, credentials, or Providers while indexing, searching, or drawing. A Run objective enters history only after its committed snapshot; an answer enters only after its committed terminal outcome.
- Index message row counts and source-byte positions without retaining a second full transcript. Materialize only messages intersecting the visible window, sanitize before cell measurement, and keep one message's temporary rows bounded by the existing Event size. The find query is at most 64 UTF-8 bytes; rendered row width is capped at 4,096 cells. An unmatched query remains editable and cannot enter the composer or canonical Events.
- Local feedback has its own source identity and remains ordered after the last indexed committed message when recorded. Retain at most 32 notices of 8 KiB each; oversized text keeps a UTF-8 prefix with a visible ellipsis. Coalesce identical consecutive feedback at the same boundary and drop the oldest notice on overflow while preserving surviving anchors. Rebuilds preserve interleaving with committed turns, and find includes feedback. Session switching clears it; terminal reacquisition preserves it. Feedback never enters Events, Provider context, replay, or `show`.
- At the live tail, follow new committed content. While reading older rows, preserve the source-text anchor through appends and width changes; show a textual new-content cue until the user returns to live. Session switching resets the anchor only after the existing empty-draft rule. Selector return and terminal reacquisition preserve it.
- For the same Session and width, append only a newly committed Run objective or terminal answer after confirming the prior last Run identity. Rebuild on Session/width change or a non-append snapshot. This avoids rescanning settled turns on each new Run without assuming an arbitrary mutable prefix is safe.
- On a rebuild of at least 4 MiB with multiple available CPUs, count independent Runs on at most four scoped threads, join them, then construct the ordered index. Borrow the existing message text rather than copying it; smaller rebuilds and incremental appends stay sequential. Count rows without materializing the transcript, including the exact escaped-cell widths of unsafe graphemes.
- Keep input and cancellation authority outside find: Ctrl+C, shutdown signals, suspend, and resize must still reach their established owner. Screen-reader mode never uses this index or cursor rewriting.
- Explicit find may scan the bounded Session synchronously; initial indexing and width-change rebuild still scan it, even when counting uses scoped workers. The ignored file-backed gate can fill three Sessions to a 251.7 MiB SQLite file, then reopen and index a selected 9,601-Event Session with about 65 MiB of transcript; Linux also reports peak process RSS. This proves one near-cap offline workload, not concurrent terminal-input latency, arbitrary Event mixes, or macOS behavior. Keep those release gates open without widening the terminal or Engine interface.
