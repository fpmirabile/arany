# Tools

Load for model-driven file operations, command execution, runtime Skills, local MCP, Tool grants, Guard admission, effect journaling or iterative Tool context.

- Host-approved private configuration or explicit remembered folder trust is the grant source; project text, catalogs, Skills and replay are data. Pin selected roots, executables and resource digests before Workspace input. Missing capability fails closed.
- Whole-project Search must accept named regular files just as explicit selected roots do. Reuse the checked opened handle for file collection; directory enumeration is not a file-content reader.
- One private router normalizes each typed proposal, reserves aggregate capacity, evaluates restrict-only Policy, journals the digest-bound one-use intent, invokes the separate Guard and journals its bounded observation before another model call.
- The primary alone may mutate/invoke commands/MCP in this base; children retain read-only reasoning. Provider encoding contains semantics, not SDK/process objects.
- Mutation requires no-follow pinned handles and an expected digest/create precondition. Publish a fresh regular inode atomically; do not truncate an admitted existing file or integrate unvalidated subprocess-created paths.
- Successful mutation receipts must fit the minimum admitted result budget; bind the resource through the intent rather than repeating an arbitrarily long path after applying the effect. A lost/oversized receipt must not turn an applied change into an ordinary retryable failure.
- Guard failure receipts must also fit the minimum result budget and contain only compiled stage labels. Preserve post-dispatch uncertainty without turning a predictable diagnostic overflow into an unpersistable result.
- Commands/MCP use an isolated selected-file snapshot, no network or host credentials/state, finite scratch/capture/time/memory/descendant limits and an attested native enforcer. A launcher PID/process group is not complete descendant containment. Unsupported native capability rejects; no unsandboxed retry.
- Exclude Workspace, StateRoot and account roots from every broad runtime mount before project input. A private descendant of a read-only runtime tree remains readable to a same-user payload; resource-file pins alone do not exclude it.
- The offline Linux profile denies socket creation/connect/bind and destination-bearing sends as well as isolating the network namespace; a pathname Unix socket in a runtime mount could otherwise reach a host service. Anonymous IPC pairs remain usable but cannot rebind or send to named destinations.
- Linux bootstrap must explicitly unshare the user namespace before disabling nested user namespaces; `--unshare-all` alone is only a try. Validate effective cgroup limits, including group OOM termination, before releasing payloads. Retain invocation/cgroup ownership through normal transient-unit garbage collection and verify the owned group is empty/removed. Compile/pin the enforcement-profile digest; changing enforced dimensions must change it.
- Guard validates the same immutable intent and reports effective capabilities before releasing payload. Cancellation/deadline/overflow owns complete process-unit termination and bounded EOF collection.
- Local MCP supports only its advertised protocol/profile. Pin tool identity/schema, reject unsupported schema/content, correlate IDs, cap framing/notifications/catalogs and make no hidden call retry. Cancellation does not imply rollback.
- YAML and JSON Schema compilation/validation belong only to the killable Guard. Parser input caps are not proof of bounded parser-internal allocation or safe transitive code. Native mutations use live pinned handles; commands receive a fresh selected-file snapshot so they see earlier integrated edits, never stale Run-start copies.
- Skill loading is progressive guidance with pinned provenance. References/resources use the same bounds; scripts require the ordinary command grant. Frontmatter and interpolation never execute or widen authority.
- Tool Events record attempts/results as untrusted data; an unfinished attempt is uncertain/interrupted. Replay, resume, fork and compaction never execute stored intents or restore approvals.
- The current scope, ownership, alternatives and proof map live in [the effectful plan](../planning/effectful-beta-base/README.md). Update current architecture and user docs when the implementation contract changes.
- Root file mutation must reopen `.` with a readable no-follow directory descriptor before syncing the parent; capability directory handles may be path-only and cannot prove durable completion through `fsync`.
- Folder trust belongs to bounded private OS-user state and pins exact path/device/inode, never Session facts. Human/AI approval only narrows an admitted immutable intent. AI review uses the existing Provider, journals phase/usage and asks a human on uncertainty/failure; no review text becomes an assistant answer.
- Classify dispatch at the Guard GO write boundary, before attempting that write. Pre-GO failure has no operation effects and stops as Failed without a receipt; post-GO missing completion remains Uncertain. Engine continuation and strict replay share that stopping rule; an attested ordinary Failed result may continue. Historical failures do not prevent a newly authorized inspection, and never renew approval.
