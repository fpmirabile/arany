# Store

The [execution spec](../docs/specs/execution.md#admission-persistence-and-recovery) owns observable Run/fork/compaction capacity rejection. This file retains persistence and editing invariants.

Load when changing private state admission, the SQLite owner thread, Event schema, migration, append, or replay.

`src/store.rs` owns the journal interface and SQLite thread. `src/store/journal.rs` contains SQLite setup and writes; `src/store/replay.rs` validates and resolves history. `src/store/state.rs` contains filesystem admission; `src/store/state/lock.rs` owns private per-Session operation locks inside that boundary.

- Admit an absolute normalized state path component by component with no-follow directory handles before opening SQLite. New private components use mode `0700`; the database file uses `0600`. Existing objects must pass type, owner, and permission checks. A read-only inspection opens only existing state. The current check covers Unix owner/mode; macOS ACL admission remains a release gate.
- Open state leaves nonblocking before checking their regular-file type, including the database, provider profiles, saved/pending account records, and lock files. A private FIFO must fail admission rather than wait for a peer; no-follow and mode checks alone do not prevent that stall.
- `provider-profiles.json` and opt-in `tools.json` are read only through the admitted state-root handle, with no-follow, regular-file, single-link, owner/private-mode, and 64 KiB limits. Oversized or aliased objects are never parsed as trusted configuration; Tool grants remain owned by [tools.md](./tools.md).
- The fixed saved-account backend/file record is read only through an admitted user account-root handle. On Linux and macOS, `StateRoot::account_path` resolves the effective UID's passwd home plus the platform suffix owned by [credentials](./credentials.md), independent of environment-selected Session roots; the normal `default_path` remains configurable for Sessions. A debug account-root override also confines `default_path` to that fixture root's non-root parent before any legacy migration can open ambient state; optimized overrides still reject. The file and its single pending replacement are at most 1 KiB, no-follow, regular, single-link, current-owner, and mode `0600`; the leaf directory is mode `0700`. The pending file is reused under the account lock after a crash, then file and directory sync precede/confirm atomic rename. `StateRoot` does not parse account JSON; the CLI credential owner validates its version and backend/account combination. A mode check is not an encryption or same-UID isolation claim.
- The same checked, no-follow file-open path exposes only presence for saved native and ChatGPT account records, without reading either record body. The CLI uses these hints to choose a billing route before loading the selected credential; presence alone is never account or Run authority.
- The separate ChatGPT registration record uses the same checked atomic-file boundary at 256 bytes and the user account-root lock. It contains one stable versioned UUIDv4 host ID and an optional issued client ID for an incomplete new-registration retry; a verified account save clears that pending ID, and reopening reconciles a crash after account publication. A returning account does not mutate the pending slot. A validated legacy record migrates to the stable OS-user root before use, with conflict rejection and a version-zero old-root tombstone. It never contains a code, verifier, access token, refresh token, or consent receipt and does not activate subscription access.
- The ChatGPT account index uses a separate checked atomic file, `chatgpt-accounts.json`, with a 384 KiB bound and one pending replacement. The CLI owner validates its at-most-eight entries, selected UUID, stable host ID, backend, signed subject, and durable renewal-pending marker; all entries must share one host ID. Keyring entries store only metadata there; an explicitly accepted private-file entry contains its token pair in the checked plaintext record. The index also holds at most 64 expiring opaque model-check records under the same account lock; no raw token, model name, or synthetic reply is stored in a check record. Structurally valid old consent can be read for reauthorization, but never used to load, renew, list models, or check one with a token until the current warning is accepted. The marker is written before a near-expiry remote refresh and blocks later token loads after a crash or uncertain replacement; a fresh verified sign-in clears it and that account's model checks. StateRoot never parses this JSON or permits unbounded secret reads. This record is distinct from the token-free registration record and SQLite Events. The CLI registration owner migrates the validated legacy index together with its matching registration under both account locks, preserving the current index schema and leaving a version-zero tombstone only after durable copies. StateRoot supplies bounded atomic records and does not validate or merge account identities.
- SQLite Run and compaction Events record only ChatGPT account UUID, opaque admission fingerprint, closed admission category and local-only output bound. Missing fields deserialize as the legacy remote-cap category; malformed combinations fail strict replay. Missing admission category means legacy `conformance`, omitted on re-encoding; new records explicitly use `account_consent`. Unknown categories or fields fail decoding. The protected account owner remains current identity/consent authority, not the Event journal or its optional diagnostic checks.
- Keep admitted directory identities so Workspace admission can reject a Workspace that contains the state root, including alias paths, before any Workspace file is read.
- Open each Session lock by typed ID beneath the admitted state root with no-follow, regular-file, owner, private-mode, zero-length, and single-link checks. A private namespace guard serializes acquisition and removal; at most 65,536 Session lock files may exist, including pre-commit files stranded by process death. Its directory scan stops after that bound plus 32 State files, and quota failure precedes Workspace input or Provider disclosure. Hold each Session's nonblocking exclusive advisory lock through lifecycle mutation, Run, source fork, or compaction; other Sessions proceed independently. Store append validates canonical transitions, not live lock ownership; the [Session reducer contract](./session.md#persistence-and-proof) defines interrupted-prefix recovery. Remove new pre-commit files on ordinary failure; retain committed Sessions' zero-byte files. Native macOS process behavior remains a release gate.
- Explicitly unlock the advisory file lock when its guard drops; rapid parallel lifecycle tests exposed intermittent self-contention when release relied only on descriptor closure.
- Account replacement uses one persistent, zero-byte `account-credentials.lock` beneath the admitted user account root, independent of a Session's `--state-dir`, with the same no-follow, private-owner, single-link checks and a nonblocking exclusive lock. Verify the opened Workspace identity is outside that root before acquiring it. Hold the lock in the same blocking task as the OS credential-store write, so cancellation of the awaiting UI cannot release coordination early. Migration from an environment-selected legacy root holds that root's lock before the stable-root lock and copies only validated records; mismatch fails closed. This fixed file fits the 32-file State overhead allowance. Supervised Linux process tests prove same-root contention, recovery after holder death, and synthetic two-StateRoot replacement against one Secret Service slot; native macOS and the full isolated product setup remain separate gates.
- One named standard-library thread owns the connection. The bounded request channel has capacity 64. An append response follows a committed SQLite transaction; a closed channel is a store failure, never a successful Event.
- Whole-operation admission strictly resolves the lineage inside an immediate transaction and requires its current Event count plus the requested slots to fit the existing replay quota. Database preflight additionally allows each slot's maximum ordinary payload and bounded SQLite page/index overhead, one larger image Message, and the unchanged per-append floor. Checking only that floor can admit Provider usage whose later receipts cannot fit. Engine-held lineage locks stabilize the Event-count admission; the byte check is not a lease against concurrent independent writers or a physical disk reservation. Every append still validates its actual payload and transition.
- Fork creation strictly resolves the resulting lineage after inserting its candidate Event and before committing the same transaction. A valid source alone does not admit the added Event or lineage link; quota failure rolls back the candidate and preserves the original replayable prefix.
- A cold append validates the full persisted Event prefix inside its immediate transaction. The Store thread may reuse one direct-Session projection for ordinary consecutive appends only when the Session ID, SQLite `data_version`, and next global Event sequence still match. The projection is capped at 128 MiB of serialized Event payload, installed only after commit, and discarded after any append failure. Another connection's commit, a Session switch, a fork, or a compaction candidate forces strict replay; fork lineage is not cached. Keep the 10,000-Event limit and commit-before-acknowledgement behavior. This cache is not tamper evidence against direct file modification outside SQLite.
- Keep the `events` table canonical. Sequence is global and ordered; Session reducers consume only fully decoded, version-checked envelopes. Unknown kinds, invalid scopes, gaps, oversized payloads, or illegal transitions fail replay.
- `session_for_run` retains one candidate Session ID through the existing bounded envelope scan and rejects a Run ID attributed to different Sessions. It is a lookup hint, not a replayed Run or authorization; callers must load and strictly validate the parent before disclosing selected Events.
- Schema version 2 adds the 32-row `provider_evidence` table for custom-profile checks. Version 3 adds a separate 256-row `native_provider_evidence` table keyed by an opaque 32-byte fingerprint. Both are derived trust caches, never canonical Events. Writable open migrates versions 1 and 2 transactionally; read-only older versions remain readable without newer evidence. Native rows expire within 24 hours, future-dated rows are unavailable, and malformed rows fail closed. No raw credential belongs in either table.
- Use SQLite no-follow open, defensive mode, `trusted_schema=OFF`, rollback `DELETE`, `synchronous=EXTRA`, a 250 ms busy timeout, and the declared page cap. Read-only `show` never creates a directory, file, migration, or journal.
- Preserve the current Event schema through versioned migrations. A failed migration or append cannot expose an optimistic projection.
- `SessionStarted` v2 atomically records Workspace device/inode with the title; v1 title-only history remains readable. Reject malformed version/payload combinations and later Run identity drift during replay.
- `MessageAccepted` uses v2 only for a nonempty bounded PNG list, including image-only text. Its kind/version-specific 320-KiB payload exception is checked before decoding; all other Events retain 64 KiB. The closed image-list decoder rejects a fifth value before allocating it. Text-only v1 encoding is unchanged; wrong versions/scopes, empty v2 lists, URLs, unknown fields and malformed images fail replay. Original bytes participate in fork/compaction prefix digests and remain canonical after summaries. Human `show` contains metadata only; explicit JSONL export contains the original bytes.
- `ProviderCallRecorded` is a bounded AgentRun-scoped Event. Version 1 has no failure reason; version 2 requires a closed reason consistent with its rejected, unavailable or invalid-response disposition. Stream/response/outcome/local-acceptance reasons belong only to invalid response. Generic calls retain version 1, and unknown reasons or version/payload mismatches fail replay. Its wire provenance and the compaction record's wire provenance are optional for legacy replay. Store/replay reject malformed payloads, inconsistent provenance/usage, non-printable response IDs, and phase/order mismatches; histories written before this Event existed remain valid.
- Session discovery scans the canonical journal and keeps at most 65,536 Session heads. Latest-Session selection fully replays its match; the Workspace-scoped picker lists bounded title/date/selection metadata in committed-activity order and exact-ID resume fully replays a selected row before switching. Fork metadata uses one additional global scan, with selection/prefix snapshots bounded by the same head count, rather than full replay per row. Exceeding the head bound fails with an exact-resume fallback; legacy empty Sessions without a pinned identity are excluded.
