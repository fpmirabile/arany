# Store

Load when changing private state admission, the SQLite owner thread, Event schema, migration, append, or replay.

`src/store.rs` owns the journal interface and SQLite thread. `src/store/journal.rs` contains SQLite setup and writes; `src/store/replay.rs` validates and resolves history. `src/store/state.rs` contains filesystem admission; `src/store/state/lock.rs` owns private per-Session operation locks inside that boundary.

- Admit an absolute normalized state path component by component with no-follow directory handles before opening SQLite. New private components use mode `0700`; the database file uses `0600`. Existing objects must pass type, owner, and permission checks. A read-only inspection opens only existing state. The current check covers Unix owner/mode; macOS ACL admission remains a release gate.
- `provider-profiles.json` is read only through the admitted state-root handle, with no-follow, regular-file, single-link, owner/private-mode, and 64 KiB limits. A file larger than the limit or changed to a link is never parsed as trusted Provider configuration.
- Keep admitted directory identities so Workspace admission can reject a Workspace that contains the state root, including alias paths, before any Workspace file is read.
- Open each Session lock by typed ID beneath the admitted state root with no-follow, regular-file, owner, private-mode, zero-length, and single-link checks. A private namespace guard serializes acquisition and removal; at most 65,536 Session lock files may exist, including pre-commit files stranded by process death. Its directory scan stops after that bound plus 32 State files, and quota failure precedes Workspace input or Provider disclosure. Hold each Session's nonblocking exclusive advisory lock through Run, fork, or compaction; other Sessions proceed independently. Remove new pre-commit files on ordinary failure; retain committed Sessions' zero-byte files. Native macOS process behavior remains a release gate.
- Explicitly unlock the advisory file lock when its guard drops; rapid parallel lifecycle tests exposed intermittent self-contention when release relied only on descriptor closure.
- One named standard-library thread owns the connection. The bounded request channel has capacity 64. An append response follows a committed SQLite transaction; a closed channel is a store failure, never a successful Event.
- Keep the `events` table canonical. Sequence is global and ordered; Session reducers consume only fully decoded, version-checked envelopes. Unknown kinds, invalid scopes, gaps, oversized payloads, or illegal transitions fail replay.
- Schema version 2 adds a bounded `provider_evidence` table for expiring custom-profile check results; it is a derived trust cache, not a canonical Event. Writable open migrates version 1 transactionally; read-only version 1 remains readable and has no evidence. Expired or future-dated evidence is unavailable, and malformed rows fail closed.
- Use SQLite no-follow open, defensive mode, `trusted_schema=OFF`, rollback `DELETE`, `synchronous=EXTRA`, a 250 ms busy timeout, and the declared page cap. Read-only `show` never creates a directory, file, migration, or journal.
- Preserve the current Event schema through versioned migrations. A failed migration or append cannot expose an optimistic projection.
- `SessionStarted` v2 atomically records Workspace device/inode with the title; v1 title-only history remains readable. Reject malformed version/payload combinations and later Run identity drift during replay.
- Session discovery scans the canonical journal once and keeps at most 65,536 Session heads. Latest-Session selection fully replays its match; the Workspace-scoped picker lists bounded head metadata in committed-activity order and exact-ID resume fully replays a selected row before switching. Exceeding the head bound fails with an exact-resume fallback; legacy empty Sessions without a pinned identity are excluded.
