# Serve protocol and schema

## Scope and related contracts

This contract owns the channel Server and `arany serve --stdio`: their JSON-RPC vocabulary, bounded transport, thread and turn projection, and JSON Schema export. The server runs `initialize` / `initialized`, `thread/start|resume|fork|unsubscribe|list`, `turn/start|interrupt|steer`, `thread/settings/update`, `thread/rewind/preview`, `thread/rewind`, `goal/pause|resume`, `events/subscribe` and `receipt/get`, and sends one-use human approval requests, with exact-session scope for eligible primary host commands. Linux and macOS behave the same; native evidence and remaining work are in [NEXT_STEPS](../../NEXT_STEPS.md#pursue-in-order).

[Session](./session.md) owns durable Session identity and replay, [execution](./execution/README.md) committed Runs and Events, [Goals](./goals.md) budgets and recovery, and [Tools](./tools/README.md) authority and approval scopes. [Terminal](./terminal/README.md) owns `exec` and `show` output. Protocol serialization adds no authority or Engine policy.

The attached terminal and headless `exec` use the same Server loop in process. The terminal's admission inputs (saved-account selection, reviewed Workspace grant, Run request and approval mode) are internal to the binary: JSON-RPC, repository content and child agents cannot construct them or gain terminal approval authority, and Provider and Tool admission still fail closed before a Run. `exec` has no human approval channel or provisional display and follows the [headless host policy](./tools/host-commands.md#primary-host-commands); a new Session is created only by ordinary admission, never ahead of a refusal. A lost in-process connection is a fatal presentation boundary, never a fabricated receipt or retry grant. Only provisional display may drop under backpressure; committed Events and control replies are never dropped. Shutdown drains queued notifications within the shared grace. [Server requests](#server-requests) owns channel-specific approval backpressure.

## Framing and envelope

Messages are UTF-8 JSON objects, one per newline-terminated line. Batches, non-objects, malformed JSON, non-integer numeric IDs and ambiguous envelopes are rejected. Outbound envelopes always include `"jsonrpc":"2.0"`; inbound envelopes may omit it but reject any other value, including null. Request IDs are strings or signed 64-bit integers; only error responses can carry a null ID. Server request IDs use a separate integer namespace ([server requests](#server-requests)).

Requests carry `id`, `method` and optional `params`; notifications omit `id`. Responses carry `id` and `result`; error responses carry `id` and `error: {code, message, data?}`, where `data` contains a closed camelCase `reason`. Envelope fields and typed params/results reject unknown fields, except `initialize.capabilities`, whose unknown keys are ignored. Unknown notifications are ignored. Client responses matching no pending approval request (unknown, late, duplicate or null-ID) are dropped silently.

Protocol fields use camelCase. Embedded journal vocabulary (`EventLine`, Event payloads, Tool calls and intents) keeps its snake_case; receipt budgets, usage and reports use camelCase. `EventLine.payload` is an open object: exporting a schema does not redefine the journal format. JSON is data; clients must render untrusted content inertly.

### Error model

| Code | Meaning | `data.reason` |
|---|---|---|
| `-32700` | Malformed message; null ID | Absent |
| `-32600` | Invalid protocol state or oversized message | `notInitialized`, `alreadyInitialized`, `messageTooLarge`, `busy`, `threadNotLoaded`, `threadLimit`, `turnNotActive`, `serverShuttingDown` |
| `-32601` | Unknown method | Absent |
| `-32602` | Invalid parameters or unsupported permission mode | `invalidParams`, `unsupportedPermissionMode`; steering refusals `runFull`, `empty`, `tooLarge`, `unavailable` |
| `-32603` | Internal channel or serialization failure | Absent |
| `-32000` | Engine admission failure | EngineError variant in camelCase; the closed vocabulary is exported as `$defs.Reason` |
| `-32001` | Provider selection or routing failure | `providerUnavailable`, `providerRejected`, `invalidSelection` |

A pending or Uncertain [Provider setup edit](./execution/admission-and-recovery.md#admission-persistence-and-recovery) refuses `turn/start`, `goal/resume` and `thread/resume` with `-32000` and `data.reason:"providerSetupBlocked"`, even for a loaded thread, appending no Events and making no Provider calls; the user inspects the saved setup and starts a new Session.

`goalIncludesUnavailable` reports a continuation or resume whose include list is unknown ([Goals](./goals.md#budget-continuation)). `goalInputTooLarge` reports an objective plus includes too large for Goal admission, before any Event or Provider call.

Engine errors use their compiled message. A failed accepted turn is `turn/completed` with status `failed` and recovery guidance in `error.message`, never a JSON-RPC error; cancellation is `interrupted`. An unknown Tool effect is [Uncertain](./execution/events-and-outcomes.md#effect-outcomes) and projects `uncertain`. If an Engine error leaves an accepted submission without a committed terminal Run, the process exits unsuccessfully with Session-history recovery guidance rather than inventing a completion.

## Methods

| CLI entry | Observable behavior |
|---|---|
| `arany serve --stdio [--state-dir DIR]` | Refuses terminal stdin or stdout before State admission, exit 2 with `error: serve requires piped stdin and stdout`. Omitting `--stdio` exits 2 with `error: unsupported transport; pass --stdio`. Clean EOF cancels any active submission, drains its committed notifications and exits 0. Input failure performs the same shutdown and exits 1. Transport, storage or shutdown failure exits 1 with `error: …` on stderr. |
| `arany generate-schema` | Writes one pretty-printed JSON Schema document plus a final newline to stdout; stderr is empty on success; no State, credentials or Engine are opened. |
| `arany generate-schema --out DIR` | Creates DIR as needed and atomically replaces `DIR/arany-protocol.schema.json`, refusing an existing symlink or non-file target. Success exits 0 with empty stdout and stderr; failure exits 1 with an `error: …` diagnostic on stderr. |

The document is titled `arany-protocol`, carries schema artifact `version: "2"`, uses JSON Schema draft 2020-12 and sorted object keys, and contains `$defs`, `methods`, `notifications` and `serverRequests`. The root validates JSON-RPC envelopes; registry entries reference schemas in `$defs` for method-specific params/results. Output is deterministic for a fixed contract.

| Method | Params and result | Ordering and admission |
|---|---|---|
| `initialize` | `{clientInfo:{name,title?,version},capabilities?:{optOutNotificationMethods?:[string],hostCommandSessionApproval?:bool,provisionalDisplay?:bool}}` → `{userAgent,platformOs,capabilities}` | First request; other requests before it return `notInitialized`; a second initialize returns `alreadyInitialized`. Returns no paths or credentials. `initialized {}` is the following client notification and has no response. |
| `thread/start` | `{cwd,provider,model,effort?,title?,collaboration?,maxActiveChildren?,tools?,permissionMode?,includePaths?}` → `{thread}` | Selects the Provider and configured role chains as `exec` does, and commits the Session before the result and `thread/started`. A thread is a durable Session, even when no turn follows. |
| `thread/resume` | `{threadId,cwd,provider,model,effort?,collaboration?,maxActiveChildren?,tools?,permissionMode?,includePaths?}` → `{thread,turns}` | Admits Workspace and configuration like start, replays history without executing it, and loads the thread. Turns contain historical user, Tool and answer items; an unfinished Run and Goal appear interrupted. |
| `thread/unsubscribe` | `{threadId}` → `{status:"unsubscribed"\|"notLoaded"}` | Unloads the thread and its raw subscription; history remains. An active submission has its approval withdrawn and is cancelled, and its committed completion precedes the response, so `events/subscribe` still works until then; ACP close ordering is defined by [session/close](./acp.md#behavior). A second close while cancellation is pending returns `busy`. An unloaded ID returns `notLoaded` without inspecting State. |
| `thread/list` | `{cwd?,cursor?,limit?}` → `{data:[{id,title,cwd,createdAt,updatedAt}],nextCursor}` | Read-only Session metadata for one admitted Workspace, including unloaded/closed Sessions. Absolute cwd defaults to the launch directory. Newest committed activity first. Pages default to 50 entries, limits 1–100; `nextCursor:null` ends the list. Invalid, oversized, noncanonical, stale-anchor or foreign-Workspace cursors fail `-32602 invalidParams`. No Provider selection, Run or Tool execution, and no loaded slot is consumed. |
| `thread/settings/update` | `{threadId,permissionMode}` → `{permissionMode}` | Requires a loaded thread (`threadNotLoaded` otherwise). Replaces its live approval mode, like terminal Shift+Tab; a pending approval keeps its intent, and only later decisions use the new mode. No Provider selection, Tool grant, Goal budget or child authority changes. |
| `thread/fork` | `{threadId,cwd,title?}` → `{thread}` | Requires a loaded source and capacity for another thread; the Workspace identity must match and the source must be unlocked and end at a committed terminal Run boundary. Inherits the source's execution configuration. The result precedes `thread/started` with `forkedFromId`; empty prefixes, an interrupted objective before `RunStarted` and an open Run fail `forkNotAtRunBoundary`, a busy source fails `sessionBusy`. A reply that cannot fit a line fails `contextTooLarge` before any fork is persisted. |
| `events/subscribe` | `{threadId,since:u64}` → `{events:[EventLine],nextSince:u64\|null}` | Requires a loaded thread. Returns committed Events with `sequence > since`; `since` beyond the head fails `invalidParams`. Follow each non-null `nextSince` to drain the backlog. The final page enables live forwarding; repeating a subscription replaces its cursor. |
| `receipt/get` | `{threadId,goalId}` → `{goal:{id,status,objective,budget,usage,report?,budgetRefusal?}}` | Requires a loaded thread and a Goal in its history; otherwise `threadNotLoaded` or `goalUnavailable`. Returns only journaled receipt facts, with no State paths, Workspace metadata, credentials or runtime configuration. `report` exists only after committed `GoalFinished`. An oversized result fails `contextTooLarge`, without partial data, leaving the connection open. |
| `turn/start` | `{threadId,input:[{type:"text",text}\|{type:"image",mediaType:"image/png",data:base64}],goal?:{autonomous}}` → `{turn}` | Requires a loaded thread and uses its pinned configuration. The result follows `MessageAccepted`, before `turn/started` and user item notifications. The turn ID is the committed Run ID, with a separate Goal ID. One submission may be active per process; another returns `busy`. |
| `turn/interrupt` | `{threadId,turnId}` → `{}` | Cancels the matching active Run. Unknown or finished turns return `turnNotActive`. `turn/completed` reports interruption only after committed `RunFinished`. |
| `turn/steer` | `{threadId,turnId,input:[{type:"text",text}]}` → `{turnId}` | Offers one note to the matching active Run, as the attached composer does. Exactly one text of at most [64 KiB](./limits.md#max_user_message_bytes), no images. Unknown or finished turns return `turnNotActive`; between autonomous Runs the last Run's ID still matches and the note waits for the next Run. An `Empty`, `TooLarge` (over [`8 KiB`](./limits.md#max_steering_note_bytes) with its history label), `RunFull` (the Run's [`8 KiB`](./limits.md#max_steering_note_bytes) note budget) or `Unavailable` refusal is `-32602` with that reason. Success means the note waits; delivery is the committed `GoalSteeringNoteRecorded`, and a note still waiting when the Run ends is discarded. |
| `goal/pause` | `{threadId,goalId}` → `{}` | Pauses the active Goal at its next boundary, as `/goal pause` does, so the turn ends `interrupted` and the Goal stays resumable. Idempotent, and accepted for the whole submission, including between autonomous Runs. No active turn is `turnNotActive`; another `goalId` is `-32000 goalUnavailable`. An in-flight Provider call is never aborted: its answer still commits. |
| `goal/resume` | `{threadId,goalId,input?:[{type:"text",text}]}` → `{turn}` | Starts a submission like `turn/start`, resuming the Goal as `/goal resume` does. Only the thread's most recent resumable Interrupted Goal resumes; any other is `-32000 goalUnavailable` before a Run. Absent input runs the pinned objective. When the Goal has no accepted Run yet, text different from the objective is `goalUnavailable`; otherwise it becomes the Run's user message while the objective stays pinned. No images. Budget, phase and resource settings stay pinned. An exhausted Goal closes Failed and returns `-32000 goalBudgetExhausted` with no Run, `GoalResumed` or `turn/started`. |

One connection owns all loaded threads; a thread is released right after durable completion. Listing covers one Workspace and discloses no other Workspace or State path. List timestamps are UTC ISO 8601 strings (or `Unknown`). Rows return no stored defaults, include paths, Provider configuration, State paths or journal content. Titles are untrusted plain text; clients render every field inertly.

Cursors are opaque, at most 128 UTF-8 bytes, bind a Session and its last committed sequence to the Workspace, and confer no access authority. If the anchor changes, the client restarts without a cursor; newer activity appears on a fresh first page. A page is not a retained snapshot and may hold fewer than `limit` entries once the [Session discovery bound](./execution/persistence.md#persistence-bounds) is reached; only `nextCursor:null` ends the list. Discovery beyond the [discovery head limit](./execution/persistence.md#persistence-bounds) fails `tooManySessions`. Listing never blocks Engine appends and reads one consistent snapshot. Each read waits at most 2 seconds for a committing writer, and writers 250 ms; a still-busy store fails the listing with the retryable `store` error "history is busy with a committing write; retry the listing", never a partial page. A result that cannot fit the line cap fails `contextTooLarge`. Unsupported sorting, filtering and archival options refuse as unknown parameters.

Providers are `openai`, `anthropic`, `chatgpt` or `custom:NAME`; credentials come from the existing selection path. Collaboration defaults to `single`, like `exec`, and accepts `single`, `auto` (three children unless set) and `team`. Permission modes are `default`, `acceptEdits` and `auto`; `plan`, `dontAsk` and bypass spellings are rejected. Tools default to disabled; enabled Tools use the same private grant as `exec`. Absolute `includePaths` must lie under `cwd`. Initialization needs no credentials; a missing one fails Provider selection. Goal and resource settings come from private settings, pinned per loaded thread, with the shared [Goal defaults](./goals.md#lifecycle-budgets-and-recovery); resume keeps the Goal's committed budget. Plain input starts a new Goal; `goal.autonomous:true` starts an autonomous one. `resumeGoalId` is reserved and rejected; use `goal/resume`. Steering and pause add no notification: their effects appear as committed Events and turn completion.

Receipt `usage` contains `runs`, `providerCalls`, `activeMs`, `uncertainActiveMs`, `knownTokens`, `knownCachedTokens` and `tokenUsageUnknown` from committed history, with no wall time or inferred usage. `budget` is the pinned Goal budget. Optional `budgetRefusal` is the committed [Goal refusal record](./goals.md#budget-refusal-feedback), with its snake_case field names. `report` is the exact committed Goal report. Objective and report text remain journal data. Unknown threads on all three methods return `threadNotLoaded`.

## Rewind

`thread_rewind_v2` advertises two idle, loaded-thread methods with the same behavior as the [terminal](./terminal/commands.md#rewind); [Tools](./tools/changesets-and-checkpoints.md#checkpoints-and-rewind) owns guarded publication, drift, limits and uncertainty, and [Session](./session.md#conversation-rewind) owns fork semantics. No Tool approval mode, model response or repository text confirms a rewind.

| Method | Params | Result |
|---|---|---|
| `thread/rewind/preview` | `{threadId,turnId}`; turnId identifies the selected Run, or the UUID of a Before rewind checkpoint | `{checkpoint:{kind:"run"\|"rewind",id,sequence},restore:["both"\|"conversation"\|"code"],files:[{path,state,added,removed}],blockers,nonRewindable:[{sequence,effect}],previewToken}` |
| `thread/rewind` | `{threadId,previewToken,restore:"code"\|"conversation"\|"both",kept?:[path],overwrite?:[path],confirmOverwrite?:bool}` | `{rewind:{id:string\|null,outcome,conflicts,conflictCount},thread?,conversation?:{threadId:string\|null,prompt:string\|null,imagesOmitted},notices:[string]}` |

Preview changes nothing. Restore choices list eligible modes in terminal order; conversation stays available across unknown code outcomes or read-only access. File states are restore, delete, recreate, drifted, historyDrift, unavailable, unsafe, outsideGrant and kept. Added/removed counts follow the [terminal comparison convention](./terminal/commands.md#rewind), or null for binary/unavailable comparisons. Blockers are uncertainPublication, noWriteGrant or guardUnavailable; non-rewindable effects are host, git, unguardedCommand, mcp, cache or directory, where host covers the human-approved Git remote effects of [Tools](./tools/git.md#human-approved-host-git). Paths are untrusted data; no diff content is sent.

Each connection keeps one one-use preview token, replaced by any new preview and bound to the thread, checkpoint, head, plan and observed file states. A new submission, unsubscribe or connection close discards it; stale, foreign, replaced or reused tokens return `previewChanged`, and no token survives restart. Mutation consumes the token, even on a refusal after admission. Kept/overwrite selections follow the [Tools rewind limits](./tools/changesets-and-checkpoints.md#checkpoints-and-rewind); overflow is `invalidParams` before effects. A file edited after preview returns `previewChanged`.

The parent client is the explicit human confirmation channel: a `thread/rewind` request confirms exactly the previewed plan and keep selection. Any overwrite also requires `confirmOverwrite:true`; otherwise it returns `overwriteConfirmationRequired` without consuming the token. The client must show the listed paths, the saved-current-content warning and a separate overwrite decision, with Cancel initially selected, as the terminal does. This is never AI or permission-mode approval; a restricted adapter such as ACP returns humanConfirmationRequired. Blocked publications return `rewindBlocked`.

Code outcomes are restored, conflict, denied, failed, cancelled or uncertain. Conflict returns the bounded conflict list and total; notices include capture/pruning and unknown-outcome guidance. Raw subscriptions carry the rewind Events; turn/item notifications are unchanged. Both mode restores code before forking and keeps its receipt with a `Code restored; conversation unchanged` notice if the fork then fails or is cancelled. Conversation-only restoration has a null rewind ID and creates no Workspace rewind Events. A durable fork appears in thread, loaded with the source configuration, and the response precedes thread/started. Restoring the first prompt returns conversation.threadId null and no thread: the client opens an unsaved conversation with the returned draft and calls thread/start only on submission. The prompt is returned whole up to the [64 KiB](./limits.md#max_user_message_bytes) objective bound; images are omitted and flagged by `imagesOmitted`. Source history and Goal budgets remain intact.

An active submission or another request during publication returns busy; an unknown loaded ID returns threadNotLoaded; an invalid checkpoint is invalidParams. Code refusals use rewindBlocked, previewChanged or rewindTooLarge; lineage overflow uses conversationRewindLimit. No method retries. EOF or shutdown cancels an in-flight publication, keeping only committed outcomes. Responses and previews obey the 1 MiB<!-- unrelated-bound: Serve protocol line cap --> line bound; an oversized request ID is rejected before any effect or fork. Previews stay within the [Tool action, comparison and transfer limits](./tools/changesets-and-checkpoints.md#checkpoints-and-rewind).

## Notifications and items

All live facts come from committed Events; provisional display is a separate opt-in stream, never a source of committed facts. Slow clients never hold Journal appends. Notification opt-outs from initialize are honored. The raw Event catalog includes `ToolPreflightRefused` ([execution contract](./execution/events-and-outcomes.md#accepted-outcomes)); an unstarted refused proposal creates no Tool item.

| Notification | Committed source and payload |
|---|---|
| `thread/started` | Durable Session creation; `{thread}` after the thread/start or thread/fork result. |
| `turn/display` | Only with `initialize.capabilities.provisionalDisplay:true`; `{threadId,turnId,update}` from live Run hints, as described below. |
| `turn/started` | `MessageAccepted`; `{threadId,turn:{id,goalId,status:"inProgress",items:[]}}`. Each Run of an autonomous Goal has a new turn ID and the same Goal ID. |
| `item/started` | `MessageAccepted` or `ToolStarted`; `{threadId,turnId,item,startedAtMs}`. |
| `item/completed` | `MessageAccepted`, `MessageCommitted` or `ToolFinished`; `{threadId,turnId,item,completedAtMs}`. User items start and complete together; final answer items complete without a started notification. |
| `turn/completed` | `RunFinished`, or the end of a settled submission whose last Run has no terminal receipt, plus Goal state; `{threadId,turn:{id,goalId,status,stopReason?,items:[],error?,goal:{status,stopped?,budgetRefusal?}}}`. Status is `completed`, `interrupted` or `failed`. An autonomous submission can complete several turns. |
| `events/committed` | After a thread's final subscription page, `{threadId,event:EventLine}` for each later Event in commit order. |
| `events/resync` | Lost live Events; `{threadId,missed,lastSequence}`. Raw subscriptions get one notice per thread and are disabled until `events/subscribe` is called again; the turn projection may send its own notice, and `missed` may include other threads. Recover by paging `events/subscribe` from `lastSequence`, or with `thread/resume`. Live delivery is best effort and can gap without a notice; paging supplies completeness. |

`turn/display` `update` is either `{type:"preview",preview:{agentRunId,callIndex,answer,commentary,commentaryLimited,tentative}|null}` or `{type:"waiting",intentId:UUID|null}`; null withdraws a preview or wait. Clients render these untrusted values inertly and clear them when the turn settles. They carry no authority, are not journaled or replayed, and never become receipt facts; a full queue or oversized update drops them. Opting in also records [durable display checkpoints](./terminal/conversation.md#terminal-continuity-and-provisional-text) as `AssistantDisplayRecorded` Events, which survive replay but never become an accepted Message, Provider history or compaction input. Unpublished tails follow the [Provider cancellation rule](./provider/encoding-and-streaming.md#streaming-and-provisional-text); streaming deltas are not persisted.

`goal.stopped` is the closed stop derived from committed Goal and Run facts, so a live turn and its `thread/resume` history agree. It is absent while the Run is open and when the Run finished without stopping its Goal. Otherwise it is one of:

- `{reason:"goalExhausted",limit}`, where `limit` is `tokens`, `calls`, `activeTime` or `runs`, following [Goal exhaustion projection](./goals.md#lifecycle-budgets-and-recovery).
- `paused`: the Goal waits at this latest Finished or Cancelled Run for an explicit resume.
- `cancelled` or `stoppedByHook`.
- For a Run with no terminal receipt: `uncertain`, `goalExhausted` or `interrupted`, following [accepted outcomes](./execution/events-and-outcomes.md#accepted-outcomes).
- `{reason:"failed",failure}` with the journal's snake_case `RunFailure`. A failure on the last permitted call is not budget exhaustion.

When an autonomous submission's next Run is refused after a committed Run, that Run's live completion carries `{reason:"notAdmitted",refusal}` with the closed Engine `Reason` and the message in `turn.error`; nothing records the refusal, so history shows `paused`. A settled submission whose last Run has no terminal receipt completes that Run once as `interrupted`.

Optional `turn.goal.budgetRefusal` carries the committed refusal record for the latest accepted Run. Budget stops carry the shared Arany status in `turn.error.message`, even when an answer is preserved, and reopened history shows the same fields. `turn.stopReason` is `tokenBudgetExhausted` for the `tokens` limit and `actionBudgetExhausted` for the others; intermediate autonomous turns omit both.

Raw Events and turn items use separate subscriptions, so `events/committed` may precede or follow the matching `item/*`. Replaying a page executes nothing, and a partial page disables live forwarding until the backlog is drained, so no history is skipped. An Event too large for a live line emits `events/resync` with `missed:1` and disables that subscription; paging refuses it with `contextTooLarge`.

Raw pages and `events/committed` forward journal Events of every kind unchanged, including `SupervisorVerdictRecorded` with its `features` and `evidence` (counts, sequences and closed enums, never paths or content), unlike the reduced [terminal](./terminal/conversation.md#conversation-progress-and-history) and [OTLP](./telemetry.md#spans) projections; its payload is bounded by the [execution format](./execution/persistence.md#persistence-bounds), and it creates no item or approval request.

Times are committed Event timestamps. Item IDs are `<runId>:user`, `<runId>:answer`, or the immutable Tool intent UUID.

| Item tag | Fields and projection |
|---|---|
| `userMessage` | `id,text,images:[{index,mediaType,bytes}]`; metadata only, no pixels. |
| `agentMessage` | `id,text,phase:"final_answer"`; committed final answer only. |
| `commandExecution` | `id,command,args,cwd,status,disposition?,output?,attestation?`; program/argv from the intent, attestation `guard` or `inProcess`. |
| `fileChange` | `id,changes:[{path,kind}],status,disposition?,output?`; Write/Edit/Mkdir/ApplyChangeset; kinds `add`, `update`, `delete`, `mkdir`; no diff bytes. |
| `mcpToolCall` | `id,server,tool?,arguments?,status,disposition?,output?`; MCP call or catalog listing. |
| `toolCall` | `id,call,status,disposition?,output?`; remaining typed Tool calls retain their journal JSON. |

Tool item status maps `succeeded` to `completed`, `denied` to `declined`, `failed|conflict|limit|cancelled` to `failed`, and `uncertain` to `uncertain`; a Tool with `cache_update:uncertain` is uncertain even if it succeeded. Unfinished historical intents are uncertain with no invented observation. Output is the bounded journaled observation.

A recoverable denial or known Tool failure, explicit approval decline or unavailable approval included, completes its item with the mapped status and reaches the model once as the Tool result, without hook or permission-rule prose. The turn may continue; completion status follows the committed Engine outcome.

## Server requests

The server advertises `approvals_v2` and `host_command_session_approval_v1` and sends requests with integer IDs starting at 1 per connection, never reused, only to the client owning the turn.

| Method | Tool family |
|---|---|
| `item/commandExecution/requestApproval` | Command and explicit unguarded command |
| `item/fileChange/requestApproval` | Write, Edit, Mkdir and ApplyChangeset |
| `item/tool/requestApproval` | All remaining calls, including MCP, Skills and reads |

All carry `{threadId,turnId,itemId,startedAtMs,intent,lines}`: `intent` is the exact journaled EffectIntent, `itemId` its UUID, `turnId` its Run and `startedAtMs` its committed `ToolProposed` time; there is no expiry field. `ToolStarted` follows the decision and carries its verdict; a proposal that never starts creates no Tool item and leaves the Session resumable. `lines` uses the terminal's sanitized approval text, including its full unguarded warning. A request that cannot be built or exceeds the message limit records unavailable approval without sending.

The client returns `{decision:"accept"|"decline"|"cancel"}`. Accept resolves only that one pending approval; decline denies; `unavailable` reports a missing approval channel; cancel cancels the turn and resolves the approval as unavailable. A client error or invalid result records unavailable approval. Unknown, withdrawn, cancelled, finished or already resolved request IDs change nothing and get no reply.

A human client opts into host session scope with `initialize.capabilities.hostCommandSessionApproval:true`. For an eligible primary host command, the request then carries `availableDecisions:["accept","acceptForSession","decline","cancel"]`, and `acceptForSession` grants that exact command for the live session; every reuse still gets a fresh intent and a committed verdict referencing the original decision, and Arany journals the scope grant separately. The [Tools scope contract](./tools/host-commands.md#primary-host-commands) owns eligibility, bounds and expiry. Later turns on the same live connection may reuse it; resume, reconnect, restart and fork cannot. Other clients get once/decline/cancel only, and a session reply where no session scope was offered is unavailable approval. Stdio and ACP never offer remembered prefixes; unsolicited scope replies reject without saving or dispatching.

The attached terminal selects its approval channel internally, never through client capabilities or model input; its eligible requests also offer `allowPrefixInFolder` ([attached prefix rules](./tools/host-commands.md#remembered-host-prefixes)), and `allowAutoEdits:true` offers the file-edit shortcut of switching mode through `thread/settings/update`, then accepting once. Only offered scopes are accepted. The Engine validates every decision, journals its verdict before dispatch and owns rule-save failure or uncertainty.

Unanswered primary requests stay pending without a deadline while the connection and Run live; EOF, interruption, pause, completion and output closure withdraw them. Failed delivery is unavailable approval, not a decline. On stdio and ACP a full or closed output queue resolves the request as unavailable at once, without retry; the attached terminal waits for output capacity and never sends a stale request or invents a verdict. A full output queue never holds Journal appends or prevents cancellation, and a slow client alone does not expire a request. Replies to withdrawn requests cannot authorize an effect. At most one approval is outstanding per connection; child-request allowance and withdrawal follow the [Tools approval rules](./tools/trust-and-approvals.md#folder-trust-and-approvals), and stdio and ACP refuse an excess ask while the terminal queues it.

This client is the human approval channel. Hook asks need an explicit human decision, as do primary host commands unless an eligible session or user-owned prefix grant authorizes them under the Tools contract. The transport adds no AI approval; Engine permission composition, revalidation, cancellation, Policy, one-use grants and Guard admission still apply.

## Limits and compatibility

| Bound | Limit and overflow |
|---|---|
| Encoded or decoded line, including newline when present | 1 MiB<!-- unrelated-bound: Serve protocol line cap -->; reader discards overflow through its newline and emits `-32600`, null ID, `messageTooLarge`; malformed input emits `-32700`, null ID; the next valid line remains usable. |
| `initialize.clientInfo` strings | 256 UTF-8 bytes each; invalid params. |
| Notification opt-outs | At most 32; invalid params. |
| Turn input | At least one input item, at most one text of [64 KiB](./limits.md#max_user_message_bytes); base64-encoded images follow the [terminal image contract](./terminal/drafts-and-paste.md#paste-and-attachments), including its image count and aggregate decoded-byte limit; invalid params. Text or images must be nonempty. |
| Pending inbound requests | 64 plus at most 64 deferred messages while output waits; reader buffer 64 KiB<!-- unrelated-bound: protocol reader buffer -->. EOF, interruption, unsubscribe and approval replies are still accepted while output waits. Deferred-input overflow cancels the Run and fails the connection; cancellation or shutdown with output still full settles the Engine and exits with Session-history recovery guidance. |
| Outbound queue | 256; Journal lag is reported through `events/resync`; [`turn/display`](#notifications-and-items) hints may drop. |
| Loaded threads / active submissions / published approval requests | 64 / 1 / 1; `threadLimit` / `busy` / [channel-specific approval backpressure](#server-requests); loaded threads are never evicted. Reloading a known thread consumes no extra slot; unsubscribe frees one after cancellation settles. |
| Session list page / cursor | 1–100 entries (default 50) / 128 UTF-8 bytes; invalid limits/cursors refuse with invalidParams. The whole response must fit 1 MiB<!-- unrelated-bound: Serve protocol response line -->. |
| Resume response | Must fit the outbound line bound; otherwise `-32000 contextTooLarge`, without partial history. |
| Steering and resume input | One text of at most [64 KiB](./limits.md#max_user_message_bytes), bounded further by the [`8 KiB`](./limits.md#max_steering_note_bytes) per-Run note budget for `turn/steer`; invalid params otherwise. |
| Event replay backlog / page | Replay is bounded by the [Session Event cap](./execution/persistence.md#persistence-bounds), inherited history included; exceeding it fails closed with `store`. Each response holds at most 1,000 Events and fits 1 MiB<!-- unrelated-bound: Serve protocol response line -->; overflow shortens the page and continues via `nextSince`. An Event that cannot fit alone fails `contextTooLarge`. |
| Raw live subscriptions / tap backlog | One cursor per loaded thread (64 total); 256 Events of backlog. Overflow emits `events/resync` and disables the cursors until re-subscribe, never blocking commits or silently skipping history. |
| Shutdown grace | 3 seconds total after EOF, input/output failure or a stop signal, covering Run cancellation, Engine closure and output draining; timeout exits 1 with `Run may be interrupted; check Session history`. |

Schema string lengths are character constraints; typed admission also checks UTF-8 byte limits, text/image counts, aggregate image bytes and PNG data. Client paths are absolute; schema validation never replaces Workspace admission, Provider selection or Guard enforcement.

The OS user's parent process is the principal. State path, Guard executable and telemetry configuration are fixed before stdin is consumed. Client text and images, repository content and Tool output are untrusted data. Client configuration can only narrow the Tool grant; repository or model text never grants trust. Credentials, account records and native keys never cross the wire. Goal budgets and per-action and storage bounds apply unchanged; no child gets broader authority. Serve adds no socket listener, authentication, multi-user isolation, encryption, live Provider compatibility or native platform-support claim.

Capability strings provide feature detection, separate from schema artifact versioning: `threads_v1`, `turns_v1`, `items_v1`, `interrupt_receipt_v1`, `approvals_v2`, `host_command_session_approval_v1`, `events_subscribe_v2`, `receipt_get_v1`, `thread_fork_v1`, `turn_steer_v1`, `goal_pause_v1` (also covering `goal/resume`), `thread_settings_update_v1`, `thread_unsubscribe_v1`, `thread_list_v1`, `thread_rewind_v2`, `provisional_display_v1`. Breaking wire changes require a new capability string and at most one release of deprecation compatibility during pre-beta; stored formats follow the [incompatible history contract](./execution/persistence.md#incompatible-history). `events_subscribe_v2` identifies the current raw Event vocabulary of the [committed Event contract](./execution/events-and-outcomes.md#committed-event-stream).
