# Tools: hooks and supervisor adapter

### Hook execution

**Command tools.** `/permissions` → Command tools selects executables from granted user program and shim directories into the private `command-tools.json` record, pinned by path, device/inode and SHA-256 and probed once in the Guard before a role is enabled; repository content, model text, environment variables and hook output never add one. Discovery reads only metadata, sorts the candidates and refuses a scan above [the directory-entry bound](../limits.md#max_command_tool_candidates); the record holds at most [the command-tool bound](../limits.md#max_command_tools). Relative executable links resolve only inside the selected directory or its granted Homebrew root; escaping links are refused, the resolved executable is pinned and retargeting the selected link requires re-pin and probe. Select chooses a Rewrite hook or Prefix wrapper and literal fixed arguments; Probe shows a sample rewrite before confirmation can enable it, Re-pin disables it until another probe, and Remove drops the selection. The page shows pin status and the last probe without enabling a drifted tool. Probes commit their intent and outcome as separate Events; an interrupted probe is reported unknown on the next explicit Probe action without rerunning it.

Configured command tools apply to guarded and host proposals alike. A Rewrite hook runs in record order before Policy for a primary command proposal, in the Guard under the hook grant, with the `PreToolUse` input whose `tool_input.command` is the shell script or the shell-quoted explicit argv; exit 0 with `hookSpecificOutput.updatedInput.command` replaces the proposal with a shell-form intent that records the original digest and the tool identity, so Policy, approval and replay bind the rewritten argv. The rewritten proposal stays shell-form. Any proposal carrying rewrite provenance is ineligible for remembered host prefixes; `permissionDecision` is ignored. A refused pin, non-zero exit, confirmed per-hook limit or malformed output leaves the proposal unchanged with a journaled stage. Goal active-time exhaustion stops continuation: exhaustion before hook admission dispatches nothing, while an admitted hook retains its journaled ceiling and outcome. An unknown outcome is Uncertain and stops the Tool call without retry. Child, hook and non-command Tools are never rewritten. `RunStarted.tool_policy.command_tools_digest` pins the record for the Run; approvals, Tool rows and `/agents` show the resulting command and rewrite stage.

A primary shell-form command applies rewrites before its single enabled Prefix wrapper, which receives literal fixed arguments followed by the whole script as one final argument (`CLAUDE_CODE_SHELL_PREFIX`). The intent binds the final executable/argv, original call and wrapper pin before Policy and approval. Only normalization-time pin refusal continues unwrapped with a journaled stage; dispatch drift refuses with `ChangedInput`, and no dispatched outcome reruns unwrapped. Configured prefix paths, identities and digests exclude host prefix/session reuse; wrapped host commands require fresh human approval. Tool rows name the wrapper.

Import reads only the OS user's own `~/.claude/settings.json`, no-follow, user-owned and without group/world writes, under [the configuration byte bound](../limits.md#max_config_bytes). It proposes Bash `PreToolUse` handlers as disabled Rewrite candidates through selection and probe, resolving literal command words via pinned `PATH` into granted roots; malformed settings, shell computation and unresolvable commands are refused.

Accepted events are exactly `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop` and `PreCompact`. Groups contain a `hooks` array of command handlers, an optional matcher, and nothing else. Handlers accept `type: "command"`, a nonempty `command`, optional `args` and an optional integer `timeout` in seconds. Omitted `args` means shell form; a present array, including `[]`, means exec form. Nothing is interpolated or resolved.

An absent, empty or `*` matcher selects every occurrence. Exact names and `|`/`,` alternatives are supported; other patterns are unanchored regexes in bounded finite-automaton syntax, so lookaround, backreferences and oversized compiled patterns reject. Tool events match through `matches_tool`, so invalid or ambiguous calls cannot evade a hook; other events match their event-specific subject. Tool subjects use the canonical rule Tool names above, including `mcp__<server>__<tool>` calls and `mcp__<server>` catalog subjects; `SubagentStop` matches agent type and `PreCompact` the trigger (`manual`/`auto`). `Stop` accepts only match-all: a filtering matcher rejects. An MCP server name containing `__` produces a blocking Tool-subject error. A present `null` is invalid. Empty handler groups, other events or types, async handlers and extra execution options reject.

**Recorded owner decision:** hook commands run inside the Guard like every process, under pinned interpreter/executable identities, an explicit environment and typed grants. The hook protocol (events, matchers, JSON on stdin, event-specific exit-2 blocking, `permissionDecision` `allow|deny|ask`, timeouts) carries no execution authority: Arany's [Per-effect isolation guarantee](../../../AGENTS.md#non-negotiable-guarantees) requires the Guard. Descendants gain no authority, and repository or hook output cannot select trust.

| Topic | Arany behavior | Reason |
|---|---|---|
| Execution and paths | Guarded, offline, pinned shell/program, explicit environment; stdin `cwd` is `/workspace`; hook changes are discarded. | Per-effect isolation; untrusted output cannot select trust. |
| `allow` | Journal `allow_is_no_op`; never resolve Ask or erase Deny. A hook Ask needs the human even in Auto mode. | Hooks only narrow. |
| `updatedInput` | Only the provable narrowing below, under a new intent, for primary Tools; a delegated `updatedInput` denies. | Immutable intent and pinned authority. |
| Matching hooks | Sequential configuration order, bounded matches, stop at a terminal restriction. | Journal-first ordering, finite Guard capacity, deterministic replay. |
| Errors and timeouts | Other exits add no restriction. Timeout and output overflow fail closed: PreToolUse denies, PostToolUse adds limit feedback, lifecycle hooks block. | A model-steered timeout must not disable a restrictor. |
| PostToolUse output | Bounded feedback only; attested observations and completed effects stay. | Hook text cannot forge effect evidence. |
| `continue: false` | All five events journal `stopped`; in an active Run they take the [terminal outcome](../execution/events-and-outcomes.md#accepted-outcomes) before the pending Tool or compaction. An idle PreCompact stops only that compaction. | Typed honest outcomes. |
| Stop blocks | Bounded user-data continuations under Goal admission, a per-actor cap and the child deadline. | Durable budgets, bounded context. |
| PreCompact instructions | `custom_instructions` is empty; digest-only occurrence subjects. | No fresh authority or host-path disclosure. |
| Matchers | Bounded finite automata; filtering Stop matchers and ambiguous MCP subjects reject. | Resource bounds, fail-closed matching. |
| Handlers and fields | Closed stdin fields and command handlers only; unsupported configuration rejects, unknown output fields are ignored. | Bounded disclosure and authority. |
| Settings reload | Pinned per Run; replay validates recorded results without reading settings or executing hooks. | Journal-first durability, strict replay. |

**Common rules.** Each handler is a journaled `Command` effect with the Guard's offline, private-Workspace-view, explicit-environment grant of a model command. `HookStarted` commits the immutable hook intent, the exact-stdin digest and the pending proposal's digest; `HookFinished` commits the Guard observation (with receipt) and the parsed result. Shell form runs the pinned `sh` as `sh -c <command>`; exec form runs `command` as a pinned program name with `args`. Every recorded result must equal the deterministic parse of its Guard observation for its event, and can only narrow. Exit 0 with empty, non-JSON or non-UTF-8 stdout adds nothing; unknown fields are ignored, and stdout is never instructions. Reasons and feedback are control-stripped and bounded; model and history projections show `hook_denied` and never the reason text, including for older observations and compaction summaries. A hook cannot see host files, and its Workspace changes are discarded. A hook whose observation is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), cancelled or unattested is recorded and blocks continuation and resume like an uncertain Tool. A Guarded Command that is not a hook reads an empty stdin (immediate EOF), like the unguarded executor. Internal Engine preparation calls over snapshot-pinned input, such as agent definition parsing, are never model Tools: no hook sees or narrows them, and they widen nothing.

An ignored hook failure stays `Ignored` with bounded diagnostic feedback. It never creates a host-command offer or an escape-only Stop/PreCompact continuation; the primary may separately request a fresh [host command](./host-commands.md#primary-host-commands), whose result never replaces the recorded hook verdict.

**Delegated Tools.** Researcher and editor Tool calls trigger the same PreToolUse and PostToolUse hooks as primary Tools. Hook intents and Events keep the child's `agent_run_id`; admission reserves their bounded tail, and execution stays within the shared delegation active-time allowance. Denial and feedback apply to that child's Tool. Delegated calls are never rewritten. Completed Workspace publication stays recorded if a post hook stops the Run.

**`PreToolUse`.** After the permission decision and live terminal restriction, and only while the decision is not `Deny`, matched handlers run one at a time in configuration order, then the verdict follows. An unpinned program, a matcher error or more matched handlers than the limit denies the Tool before any hook starts, with reason `hook program is not pinned`, `hook configuration blocks this Tool` or `hook limit`. Handlers after a denial do not run. Stdin is one JSON object with a closed field set: `session_id`, `cwd` (always `/workspace`, never a host path), `permission_mode`, `hook_event_name`, `tool_name` (rule Tool name), `tool_input` (the typed call) and `tool_use_id`. Exit 0 with a JSON object may carry `hookSpecificOutput` (`hookEventName` must be `PreToolUse`) with `permissionDecision` and `permissionDecisionReason`, the legacy top-level `decision: "block"` with `reason`, or `continue: false` with `stopReason`, which stops the Run before dispatch and takes precedence over `decision: "block"`. Exit 2 denies with stderr as the reason; any other exit is a non-blocking failure. Decisions combine `deny > ask > allow`.

The verdict records `hook_restriction` (`null`, `ask` or `deny`) and `hooks` (handlers that ran). The reducer requires every started hook to finish before the verdict, `hooks` to equal the journaled count, `null` only when no hook restricted or stopped, `ask` only for an `Ask` fold, and `deny` only for a `Deny` fold, a stopped hook or a denial before any hook ran. A hook `Deny` has basis and source `hook`; a hook `Ask` over an `Allow` has basis `hook` and is resolved by the human, never AI review (a forged AI review of it rejects on replay).

**Hook limits.** Configuration holds at most 64 groups and 128 handlers across events. Matchers and match subjects are at most 1024 bytes<!-- unrelated-bound: hook matcher subject bytes --> and control-free; subject overflow, controls or an invalid Tool call return an error that blocks the pending action instead of a non-match. Commands are at most 4096 bytes<!-- unrelated-bound: hook command text -->; tab and newline are inert, other controls reject. Exec form has at most 64 arguments of 4096 bytes<!-- unrelated-bound: hook exec argument --> each, without NUL, within the document limit. Timeout is 1–600 seconds<!-- unrelated-bound: hook handler timeout -->, default 600; the finite maximum is an Arany narrowing. Each regex has a 128 KiB<!-- unrelated-bound: hook regex compiled size --> compiled-size ceiling, a 32 KiB<!-- unrelated-bound: regex DFA cache --> DFA cache and 32 nesting levels. Configuration overflow rejects with no truncation, partial config, retry or fallback; errors name the list/index or constraint without echoing command or rule text.

At most 8 matched handlers run per occurrence. Stdin is at most 32 KiB<!-- unrelated-bound: hook input cap -->, including the complete `tool_input`: a matched `PreToolUse` or `PostToolUse` set that cannot receive the whole call, such as a Write, Edit or MultiEdit carrying more than about 32 KiB<!-- unrelated-bound: hook input cap --> of content, denies the Tool before any handler or effect (`hook input exceeds its limit`, zero handlers); `tool_input` is never truncated or hashed and the hook is never bypassed. Every matched handler's Guard task must encode within the Guard task ceiling before any hook starts, else the Tool is denied (`hook input exceeds the Guard task limit`) with no `HookStarted`. A result is at most 32 KiB<!-- unrelated-bound: hook result cap -->, with each stdout/stderr capture capped at 16 KiB<!-- unrelated-bound: hook stream capture cap --> minus 128 bytes; overflow fails closed and cannot turn an exit-2 hook into a non-blocking one. Runtime is at most the handler `timeout` and the remaining Goal active time, never less than 1 s; the Goal ledger refuses a start that does not fit, and the Guard reaps descendants on timeout. Reasons are truncated at a UTF-8 boundary to at most 1 KiB<!-- unrelated-bound: hook reason bytes -->. Tool step admission reserves two Events and one observation per matched handler, and the Tool's authorization lifetime and active-time ceiling grow by the handlers' worst case, clamped to the remaining Goal active time (unbounded Goals keep the full worst case). Hook time is Goal active time.

**`PostToolUse`.** After a primary or delegated Tool commits a `Succeeded` observation, its matched handlers run one at a time with the `PreToolUse` grant, bounds and `HookStarted`/`HookFinished` pair. `HookStarted` requires that observation and the Tool's digest and directly follows the Tool's latest step: a Command's hooks run after its changeset integration commits and see the published tree (a worker command's hook runs after its private seal and sees the host Workspace), and no Provider call, compaction or other Tool may intervene. In a concurrent in-process read step, sibling read and admission Events may intervene: read post-hooks run serially in observation completion order after the step's admissions and reads settle, before any non-read call or Provider reservation, and successful reads still run them after a sibling `Limit`. Each source has one contiguous set of distinct handlers in configuration order, and each deferred hook binds its source digest in the current step. Failed, denied, uncertain, limited and internal calls run no `PostToolUse` hook. The hook cannot undo the effect. Stdin adds `tool_response`, the observation's model-facing projection, replaced by `{"truncated": true, "text": <prefix>}` when it would exceed the stdin limit, with the prefix halved (down to empty) until every matched Guard task fits, so on macOS a hook can receive less than 32 KiB<!-- unrelated-bound: hook input cap -->. Exit 2 (stderr), `decision: "block"` with `reason`, and `hookSpecificOutput` (`hookEventName` must be `PostToolUse`) with `additionalContext` become feedback; other exits are non-blocking failures; a timeout or output overflow becomes the feedback `hook limit reached`. On exit 0, `continue: false` takes precedence over feedback, records `stopped` with optional `stopReason` and skips remaining handlers; [Run outcomes](../execution/events-and-outcomes.md#accepted-outcomes) own the terminal behavior. `updatedToolOutput` and other fields are ignored. An Uncertain, cancelled or unattested hook stops the Run after the effect; the observation stays committed and the next Provider call does not start, while the typed pre-dispatch bootstrap exception stays `Ignored`.

Feedback is stored only in the journaled `HookFinished` result (a `feedback` result with a `lines` list). The model-facing Tool result gains a `hook_feedback` list of `hook feedback: <text>` lines (at most 4 KiB<!-- unrelated-bound: PostToolUse feedback aggregate --> in total, later lines dropped), rebuilt from the journaled results after resume, so prompts are byte-identical. A step matching either Tool hook set reserves twice that room in the context budget, and `PostToolUse` time extends the active-time ceiling but not the authorization lifetime. Because a post hook cannot be refused after the effect, a Tool whose `PostToolUse` handlers are unpinned, over the matched-handler limit, or unable to encode their Guard task or stdin even with an empty truncated response is denied before dispatch with the `PreToolUse` reasons and no `HookStarted`.

**`updatedInput` narrowing.** `updatedInput` must be a complete, valid Tool call of the `tool_input` shape; anything else denies. A replacement narrows only when it is:

- a `read` of the same path whose offset and end lie inside the original window;
- a `glob` with the same normalized pattern whose page lies inside the original window (`offset` through `offset + limit`) for the same path, or whose path lies beneath the original's with both offsets zero and a limit no larger;
- a `list`, `git_status`, `git_diff` or `git_log` whose path equals the original or lies beneath it by whole segments (a root original admits any path), with Git reads keeping every other field;
- a `search` keeping its query, `regex`, `include` and `case_sensitive` after default normalization, whose page lies inside the original row window (`offset` through `offset + limit`) for the same path, or whose path lies beneath the original's with no include, both offsets zero and a limit no larger.

Parent paths, `..`, case or symlink variants, larger windows or glob limits, changed queries, patterns, matching modes, includes or case, and every `command`, MCP, Skill, `write`, `edit`, `multiedit`, `mkdir`, `apply_changeset` or internal call never narrow; the model must propose those as new calls. The replacement must also be at least as restrictive under the pinned rules and within the pinned grant. `HookFinished` journals every valid-shaped update outside an `ask` decision as a `narrowed` result, but only the verdict's `narrowed` flag records acceptance. An update identical to the current call is a no-op, so idempotent clamping hooks work. An update refused by narrowing, rules, grant or the per-step limit denies with the matching reason and a false flag. `ask` with `updatedInput` keeps the ask on the original input. On an accepted narrowing the original Tool is `Denied` with basis `hook`, the flag set and the line `Hook narrowed this Tool to: <tool_name>`; the next Tool of that step must be exactly the replacement (a new `ToolStarted` intent), and `PreToolUse` hooks run again for it. At most one narrowing per step; a second denies (`hook narrowing limit`). The model receives one Tool result built from the replacement's observation, and the original's denial line arrives as a separate `hook_narrowing` data block. Internal Engine calls and delegated research are never narrowed. Step admission reserves the replacement's Events and observations.

**`Stop` and `SubagentStop`.** A primary answer runs `Stop` before `AgentFinished`; a researcher or editor answer runs `SubagentStop`, matched against its definition name (or the role fallback `researcher` / `editor`), before the child's `AgentFinished`. Both receive `stop_hook_active` and `last_assistant_message`, truncated at a UTF-8 boundary to fit the stdin and Guard task ceilings. Exit 2 or `decision: "block"` records `blocked` with a bounded reason. On exit 0, `continue: false` takes precedence over `decision: "block"`, journals `stopped` with optional `stopReason` and skips remaining handlers; [Run outcomes](../execution/events-and-outcomes.md#accepted-outcomes) own settlement. On a block, the accepted assistant turn and a user-data block labelled `stop_hook_feedback` are appended to the next request, which uses ordinary Goal Provider-call admission; exhaustion ends the turn with the budget outcome. A child re-prompt stays inside its delegation deadline and turn ceiling; a stopped editor keeps its landed Workspace effects and releases its lease through the [editor lifecycle](./editors.md#editor-tool-steps). At most eight blocked continuations are admitted per actor in a Run, counting every blocked Stop regardless of intervening Tool calls (which never reset the cap or `stop_hook_active`), so feedback stays within 8 KiB<!-- unrelated-bound: Stop hook feedback aggregate -->; after the cap a valid answer completes without another Stop invocation.

**`PreCompact`.** Before an active-Run compaction reservation or an idle Session compaction, matching handlers receive `trigger` (`manual` or `auto`) and empty `custom_instructions`. Passing hooks are journaled before the reservation. A block skips the compaction without a reservation, and the Run continues while retained context fits; otherwise the context failure applies. `continue: false` stops an active Run before the reservation, or only the compaction when idle. Cancellation during an active-Run hook with a known outcome cancels the Run before any reservation; an unknown outcome leaves the Run interrupted with an uncertain stop under [Run outcome precedence](../execution/events-and-outcomes.md#accepted-outcomes). A manual `/compact` blocked by a hook fails with `CompactionBlockedByHook`, distinct from an empty input. Each trigger/call-index occurrence runs once; a retry at the same call count reuses the recorded outcome and never reruns the hook. Idle compaction re-admits the current private configured or remembered folder grant only if its digest and the permissions digest match the Run's pins; otherwise it fails closed. Between Runs of an open Goal, hook start reserves a durable active-time ceiling and completion settles elapsed time; outside an open Goal the handler keeps its finite timeout and Guard limits.

**Lifecycle hooks** use the same pinned programs, Guard, sequential execution, limits, fail-closed Limit and uncertainty handling as Tool hooks. An invalid program records the offending handler's call as a denied, never-dispatched intent; matched-handler overflow uses the event's first configured handler, and stdin that cannot fit the Guard task uses the first matched handler. That call carries the reason as output and the result is `Blocked`, before any process runs. A SubagentStop shares its delegation, so admission reserves the child's settlement tail; a cut-off or cancelled SubagentStop ends that child (cancelled when the user cancelled, otherwise failed under the child's fatal or local failure policy) without exhausting the Goal budget, and the editor's closed failure cause follows the [worker outcome contract](../execution/events-and-outcomes.md#worker-journal-protocol). An unknown outcome stops the Run as Uncertain. Replay binds Stop subjects to `(agent_run_id, provider call index)` and PreCompact subjects to `(trigger, provider call count)`. A Stop occurrence immediately follows its accepted Finished call; a blocked Stop forbids successful Agent completion until a new call is recorded. Each continuation re-renders the answer turn, which counts toward Tool context and its compaction trigger; a context without room refuses with `ContextTooLarge` before any hook journals. Open or Uncertain hooks block continuation and resume; strict replay consumes recorded facts and rejects forged outcomes, miscounts and unknown payload versions without executing hooks.

### Supervisor adapter

The Engine owns bounded Supervisor evaluation state and calls one pure, deterministic evaluator over committed reducer facts. The RunLoop journals a verdict or continues without one; the reducer only validates recorded verdicts' shape and placement. Tool-enabled Runs pin the required `config.supervisor = {evaluator: 1, window: 32, floors, candidates, digest}` in `RunStarted`; Runs without Tools pin null. The SHA-256 digest binds the domain `arany.supervisor.policy.v1`, evaluator, window and both closed threshold structs. There is no configuration file, model call, clock, I/O, network, Guard task or journal subscriber, and repository text, model output and hooks cannot select thresholds. Shadow mode is always on and never changes permissions, catalogs, approvals, continuation, integration, Run outcomes or model input.

A boundary follows every model `ToolFinished`, including editor Workspace effects and known denials or failures. A primary command with a nonempty validated changeset uses `command_capture`; invalid or deferred Provider results and blocked Stop/SubagentStop use `stall`. Internal definition parsing and changeset integration are excluded. The site vocabulary is closed to `tool_outcome`, `command_capture` and `stall`; other subjects reject.

Each actor (at most nine per Run) has an independent window of its last 32 boundaries; the oldest step is evicted whole on the 33rd, and a new Run starts empty. Feature counts saturate at 65,535; ratios use saturating integer arithmetic, floor division and a denominator of at least one. Keys are SHA-256 over domain `arany.supervisor.call.v1` and canonical typed calls, with Write/Edit content replaced by its SHA-256; intent, actor and Run IDs, expiry and target revision are excluded. Outcome equality binds disposition, closed enforcement cause, exit class (zero/nonzero/unknown) and SHA-256 of the model-facing result without its call or target. No prose is parsed. Policy/plan/grant/lease/permission/hook denials count as refusals; closed `filesystem_denied` counts as a path-admission rejection; ordinary nonzero exits are not probing.

| Signal | Features | Notice floor | Would-narrow candidate |
|---|---|---|---|
| Loop | Identical `(call, outcome)` suffix; same-call non-success suffix; greatest whole suffix cycle repetitions for lengths 2, 3 and 4 (shortest length wins ties); maximum per-path returns to a prior after-digest following a different digest; stall boundaries since the last succeeded observation | identical 3; failing 2; cycle 3; oscillation 1; stalled 2 | identical 4; failing 3; length-2 cycle 3, other cycles 5; oscillation 2; stalled 3 |
| Probing | Refusal suffix; refusals in window; distinct refused call keys; closed path-admission rejections | streak 2 or alias 1 | streak 3, or distinct 3 with window 4, or alias 2 |
| Disproportion | Files, deleted files, ceil(decoded before+after bytes / 1024), declared roots (minimum 1), nullable base KiB (currently null), files/root, deleted/files permille, nullable changed/base permille (currently null) | files 16, or deletion 250 permille with files/root 4 | files/root 8 with files 32; deletion 500 permille with deleted 8; growth 4000 permille with changed 64 KiB<!-- unrelated-bound: change profile growth bytes --> |

Loop and probing are evaluated at all three sites and journaled only when the subject is in the signal's evidence, so one crossing yields one verdict; disproportion is evaluated at every capture. A candidate hit has level `would_narrow`, otherwise a floor hit has level `notice`; both are journaled. Candidate responses are loop `pause`, probing `revoke`, disproportion `require_approval`; notices have null response. These are calibration candidates only. Disproportion uses validated changeset facts and declared lease/plan roots; base/growth features are null without a base. Live editors supply no private capture or handover boundaries. Each signal keeps at most eight increasing subject sequences as evidence. Edit equality keeps only hashed path/after-digest pairs, at most the [capture bound](../limits.md#max_snapshot_files) per step and 589,824 pairs per Run (36 MiB of pair data), never contents; eviction removes a step and its pairs together. Per-boundary work is bounded by the window and those capture bounds and never grows with Session history. The evaluator has no fallible external operation; a panic fails the coordinator through its failure boundary.

The RunLoop commits a nonempty `SupervisorVerdictRecorded` as its own decision immediately after its subject, before hooks, integration, stop facts or other continuation. A failed or unknown append stops continuation; an uncommitted verdict is never treated as recorded. The closed payload carries `subject_sequence`, `site`, `evaluator: 1`, `mode: shadow`, one to three signal entries (`signal`, `level`, nullable `would_response`, fixed feature struct, evidence) and `capped`, and holds only integers, booleans, enums and sequences. [Execution](../execution/persistence.md#persistence-bounds) owns the [2 KiB](../limits.md#max_verdict_bytes) payload and 256-verdict Run cap; evaluation continues after the cap without journaling. No verdict enters compiled context, compaction input, Provider input or diagnostics. [Serve](../serve.md#notifications-and-items) forwards the canonical verdict (counts, sequences and closed enums, never paths or content); [terminal](../terminal/conversation.md#conversation-progress-and-history) and [telemetry](../telemetry.md#spans) own further-reduced projections.

Replay accepts recorded decisions without reevaluating the Supervisor, executing any historical action or reading configuration. It validates the closed payload, supported evaluator, pinned Supervisor, Run and actor scope, adjacent subject and site, evidence shape, cap and cap marker; malformed, duplicate or misplaced verdicts reject. A well-formed, correctly placed forged verdict is accepted even when the evaluator would differ, and replay never infers a missing verdict. An interrupted prefix ending right after a subject stays valid; recovery starts fresh windows in a new Run. A changed feature definition needs a new evaluator version; threshold changes stay pinned data. Replay does not prove evaluator provenance, and the journal is not tamper evidence. No verdict grants authority.

`arany show --output supervisor-corpus SESSION_ID` exports a local calibration corpus after strict read-only replay. It takes the Session lock nonblockingly for the whole read, refuses an active operation or an absent or unsafe lock, and creates no lock files or journal changes. It opens no Workspace, reads no credentials or runtime configuration, and makes no Provider, Tool, hook or Guard call. Fork references and inherited history get the same strict validation; records describe the selected Session's own boundaries. Interrupted closed prefixes are valid; invalid history emits no corpus.

Stdout is JSONL: one header, then one record for every evaluation boundary, including negatives and boundaries after the verdict cap. The header has `format: "arany.supervisor.corpus.v1"`, `evaluator: 1`, `session_ordinal: 1`, `runs` and `goals`. Each Run entry has a one-based `run_ordinal`, closed `outcome` (`completed|failed|cancelled|stopped_by_hook|interrupted`, unfinished prefixes `interrupted`) and nullable `policy` with its pinned evaluator, window, floors and candidates, without the digest. Goal entries have a one-based `goal_ordinal`, `run_ordinals` and `outcome: completed|failed|interrupted|budget_exhausted`.

Each record has `run_ordinal`, the journal's zero-based `actor_ordinal`, closed `role`, `site`, nullable catalog `operation`, nullable `disposition_class` and closed enforcement `cause_class`, `features: {loop, probing, disproportion}`, nullable `journaled_level`, `salted_call_key`, `salted_outcome_key`, one-based `relative_step` and `labels`. Features are recomputed over the same actor window; disproportion is null outside capture sites, and operation, disposition and cause are null outside Tool observations. `relative_step` counts all boundaries of the Run in journal order. `journaled_level` is the greatest level in the matching committed verdict, or null when none was committed. Labels are booleans `pause_or_cancel`, `steering` and `goal_failed`, set when the committed cancellation, steering note or failed Goal follows within three subsequent boundaries of the same Run (including immediately after the subject). The journal cannot distinguish a user pause from Ctrl+C, so the combined label makes no such inference; crash interruption is not a cancellation label.

Corpus privacy is an allowlist: only the fields above are serialized, with no objectives, paths, argv, file content, model text, UUIDs, timestamps, account data, raw hashes or policy digests. Call and outcome keys are HMAC-SHA-256 of the evaluator's normalized keys, with separate corpus domains and a fresh random 32-byte secret salt per export that is never exported or persisted. Keys are equal within one export and unlinkable across exports; ordering, ordinals and feature patterns stay observable, so the corpus is privacy-reduced, not anonymous. Nothing is uploaded; owner labels are added offline to a copy, and threshold sweeps use the feature columns without re-execution.

An export holds at most 10,000 records and 8 MiB<!-- unrelated-bound: repetition corpus export cap -->, including header and newlines, and the [lineage replay cap](../execution/persistence.md#persistence-bounds) applies first. Record or byte overflow refuses the whole export with record and byte counts, never truncating or emitting partial stdout; replay-limit refusal uses the history-limit error. Buffers and label tracking are bounded by those limits, the fixed schema and a four-boundary label window. Random-source failure fails closed. The corpus grants no enforcement authority.

Detection uses ID-free action/observation equality, four identical steps, failure streaks, alternating cycles, hashed calls and short cycles, behind a pre-dispatch inspector seam with a restrict-only adapter shape. Arany journals shadow candidates before any enforcement, uses bounded per-actor windows and excludes LLM judges. Enforcement, durable pause/revoke and human-only overrides need later calibrated owner approval; this adapter applies none.
