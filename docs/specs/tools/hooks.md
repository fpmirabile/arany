# Tools: hooks and supervisor adapter

### Hook execution

**Command tools.** `/permissions` → Command tools selects executables from granted user program and shim directories into the private `command-tools.json` record, pinned by path, device/inode and SHA-256 and probed once in the Guard before a role is enabled; repository content, model text, environment variables and hook output never add one. Discovery reads only metadata and refuses a scan above [the directory-entry bound](../limits.md#max_command_tool_candidates); the record holds at most [the command-tool bound](../limits.md#max_command_tools). Relative executable links resolve only inside the selected directory or its granted Homebrew root, and escaping links are refused; retargeting a selected link requires re-pin and probe. Select chooses a Rewrite hook or Prefix wrapper and literal fixed arguments; Probe shows a sample rewrite before confirmation can enable it, Re-pin disables it until another probe, and Remove drops the selection. The page shows pin status and the last probe and never enables a drifted tool; an interrupted probe is reported unknown, never rerun.

Configured command tools apply to guarded and host proposals alike. Rewrite hooks run in record order before Policy for a primary command proposal, in the Guard under the hook grant, with the `PreToolUse` input whose `tool_input.command` is the shell script or the shell-quoted explicit argv. Exit 0 with `hookSpecificOutput.updatedInput.command` replaces the proposal with a shell-form intent recording the original and the tool identity, so Policy, approval and replay bind the rewritten command; such a proposal is ineligible for remembered host prefixes, and `permissionDecision` is ignored. A refused pin, non-zero exit, confirmed per-hook limit or malformed output leaves the proposal unchanged with a journaled stage. An unknown outcome is Uncertain and stops the Tool call without retry. Child, hook and non-command Tools are never rewritten. `RunStarted.tool_policy.command_tools_digest` pins the record for the Run; approvals, Tool rows and `/agents` show the resulting command and rewrite stage.

A primary shell-form command applies rewrites before its single enabled Prefix wrapper, which receives literal fixed arguments followed by the whole script as one final argument (`CLAUDE_CODE_SHELL_PREFIX`). The intent binds the final command, original call and wrapper pin before Policy and approval. Only a pin refusal before Policy continues unwrapped, with a journaled stage; drift at dispatch refuses with `ChangedInput`, and nothing reruns unwrapped. Wrapped host commands need fresh human approval, never prefix or session reuse. Tool rows name the wrapper.

Import reads only the OS user's own `~/.claude/settings.json`, which must be user-owned, not a link and without group/world writes, under [the configuration byte bound](../limits.md#max_config_bytes). It proposes Bash `PreToolUse` handlers as disabled Rewrite candidates through selection and probe, resolving literal command words via pinned `PATH` into granted roots; malformed settings, shell computation and unresolvable commands are refused.

Accepted events are exactly `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop` and `PreCompact`. Groups contain only a `hooks` array of command handlers and an optional matcher. Handlers accept `type: "command"`, a nonempty `command`, optional `args` and an optional integer `timeout` in seconds. Omitted `args` means shell form (the pinned `sh -c <command>`); a present array, including `[]`, means exec form (`command` as a pinned program with `args`). Nothing is interpolated or resolved.

An absent, empty or `*` matcher selects every occurrence. Exact names and `|`/`,` alternatives are supported; other patterns are unanchored regexes without lookaround or backreferences. Tool events match the canonical [rule Tool names](./permissions.md#permission-rules), including `mcp__<server>__<tool>` calls and `mcp__<server>` catalog subjects, so invalid or ambiguous calls cannot evade a hook; an MCP server name containing `__` produces a blocking error. `SubagentStop` matches agent type and `PreCompact` the trigger (`manual`/`auto`); `Stop` accepts only match-all. A present `null` is invalid. Empty handler groups, other events or types, async handlers and extra execution options reject.

**Recorded owner decision:** hook commands run inside the Guard like every process, as the [Per-effect isolation guarantee](../../../AGENTS.md#non-negotiable-guarantees) requires. The hook protocol (events, matchers, JSON on stdin, event-specific exit-2 blocking, `permissionDecision` `allow|deny|ask`, timeouts) carries no execution authority, and repository or hook output cannot select trust.

| Topic | Arany behavior |
|---|---|
| Execution and paths | Guarded, offline, pinned shell/program, explicit environment; stdin `cwd` is `/workspace`; hook changes are discarded and host files are invisible. |
| `allow` | Journal `allow_is_no_op`; never resolve Ask or erase Deny. A hook Ask needs the human even in Auto mode. |
| `updatedInput` | Only the provable narrowing below, under a new intent, for primary Tools; a delegated `updatedInput` denies. |
| Matching hooks | Sequential configuration order, bounded matches, stop at a terminal restriction. |
| Errors and timeouts | Other exits add no restriction. Timeout and output overflow fail closed: PreToolUse denies, PostToolUse adds limit feedback, lifecycle hooks block. |
| PostToolUse output | Bounded feedback only; attested observations and completed effects stay. |
| `continue: false` | All five events journal `stopped`; in an active Run they take the [terminal outcome](../execution/events-and-outcomes.md#accepted-outcomes) before the pending Tool or compaction. An idle PreCompact stops only that compaction. |
| Stop blocks | Bounded user-data continuations under Goal admission, a per-actor cap and the child deadline. |
| PreCompact instructions | `custom_instructions` is empty. |
| Matchers | Bounded; filtering Stop matchers and ambiguous MCP subjects reject. |
| Handlers and fields | Closed stdin fields and command handlers only; unsupported configuration rejects, unknown output fields are ignored. |
| Settings reload | Pinned per Run; replay validates recorded results without reading settings or executing hooks. |

**Common rules.** Each handler is a journaled `Command` effect with a model command's Guard grant: `HookStarted` commits its intent and the exact stdin digest, and `HookFinished` its Guard observation and parsed result, which must equal the deterministic parse of that observation and can only narrow. Exit 0 with empty, non-JSON or non-UTF-8 stdout adds nothing, and stdout is never instructions. Reasons and feedback are control-stripped and bounded; model and history projections, including compaction summaries, show `hook_denied`, never the reason text. A hook whose observation is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), cancelled or unattested blocks continuation and resume like an uncertain Tool. A guarded command that is not a hook gets empty stdin. Internal Engine preparation, such as agent definition parsing, is never a model Tool, and no hook sees it.

An ignored hook failure stays `Ignored` with bounded diagnostic feedback and never creates a host-command offer or an escape-only Stop/PreCompact continuation; a separately requested [host command](./host-commands.md#primary-host-commands) never replaces the recorded hook verdict.

**Delegated Tools.** Researcher and editor Tool calls trigger the same PreToolUse and PostToolUse hooks, recorded under the child's `agent_run_id` and within the shared delegation active-time allowance. Denial and feedback apply to that child's Tool. Delegated calls are never rewritten or narrowed. Completed Workspace publication stays recorded if a post hook stops the Run.

**`PreToolUse`.** After the permission decision and live terminal restriction, and only while the decision is not `Deny`, matched handlers run one at a time in configuration order, then the verdict follows. An unpinned program, a matcher error or more matched handlers than the limit denies the Tool before any hook starts, with reason `hook program is not pinned`, `hook configuration blocks this Tool` or `hook limit`. Handlers after a denial do not run. Stdin is one JSON object with a closed field set: `session_id`, `cwd` (always `/workspace`, never a host path), `permission_mode`, `hook_event_name`, `tool_name` (rule Tool name), `tool_input` (the typed call) and `tool_use_id`. Exit 0 with a JSON object may carry `hookSpecificOutput` (`hookEventName` must be `PreToolUse`) with `permissionDecision` and `permissionDecisionReason`, the legacy top-level `decision: "block"` with `reason`, or `continue: false` with `stopReason`, which stops the Run before dispatch and takes precedence over `decision: "block"`. Exit 2 denies with stderr as the reason; any other exit is a non-blocking failure. Decisions combine `deny > ask > allow`.

The verdict records `hook_restriction` (`null`, `ask` or `deny`) and `hooks` (handlers that ran); replay rejects a restriction that does not match the recorded hook results. A hook `Deny` has basis and source `hook`; a hook `Ask` over an `Allow` has basis `hook` and is resolved by the human, never AI review.

**Hook limits.** Configuration holds at most 64 groups and 128 handlers across events. Matchers and match subjects are at most 1024 bytes<!-- unrelated-bound: hook matcher subject bytes --> and control-free; subject overflow, controls or an invalid Tool call block the pending action instead of not matching. Commands are at most 4096 bytes<!-- unrelated-bound: hook command text -->; tab and newline are inert, other controls reject. Exec form has at most 64 arguments of 4096 bytes<!-- unrelated-bound: hook exec argument --> each, without NUL. Timeout is 1–600 seconds<!-- unrelated-bound: hook handler timeout -->, default 600. Each regex has a 128 KiB<!-- unrelated-bound: hook regex compiled size --> compiled-size ceiling and 32 nesting levels. Configuration overflow rejects like [permission limits](./permissions.md#permission-limits), naming the list/index or constraint.

At most 8 matched handlers run per occurrence. Stdin is at most 32 KiB<!-- unrelated-bound: hook input cap -->, including the complete `tool_input`, which is never truncated or hashed: a matched `PreToolUse` or `PostToolUse` set that cannot receive the whole call, such as a large Write, Edit or MultiEdit, denies the Tool before any handler or effect (`hook input exceeds its limit`); input too large for the Guard denies it with `hook input exceeds the Guard task limit`. A result is at most 32 KiB<!-- unrelated-bound: hook result cap -->, with each stdout/stderr capture under 16 KiB<!-- unrelated-bound: hook stream capture cap -->; overflow fails closed and cannot turn an exit-2 hook into a non-blocking one. Runtime is at most the handler `timeout` and the remaining Goal active time, never less than 1 s; a start that does not fit the Goal is refused, and timeout kills the hook's descendants. Hook time is Goal active time and extends the Tool's active-time ceiling. Reasons are truncated to at most 1 KiB<!-- unrelated-bound: hook reason bytes -->.

**`PostToolUse`.** After a primary or delegated Tool commits a `Succeeded` observation, its matched handlers run one at a time with the `PreToolUse` grant and bounds, before any Provider call, compaction or other Tool. A Command's hooks run after its changeset integration and see the published tree. Failed, denied, uncertain, limited and internal calls run no `PostToolUse` hook, and a hook cannot undo the effect. Stdin adds `tool_response`, the observation's model-facing projection, replaced by `{"truncated": true, "text": <prefix>}` when it would not fit, so a hook can receive less than 32 KiB<!-- unrelated-bound: hook input cap -->. Exit 2 (stderr), `decision: "block"` with `reason`, and `hookSpecificOutput` (`hookEventName` must be `PostToolUse`) with `additionalContext` become feedback; other exits are non-blocking failures; a timeout or output overflow becomes the feedback `hook limit reached`. On exit 0, `continue: false` takes precedence over feedback, records `stopped` with optional `stopReason` and skips remaining handlers; [Run outcomes](../execution/events-and-outcomes.md#accepted-outcomes) own the terminal behavior. `updatedToolOutput` and other fields are ignored. An Uncertain, cancelled or unattested hook stops the Run after the effect, which stays committed.

Feedback is journaled in `HookFinished` (a `feedback` result with a `lines` list). The model-facing Tool result gains a `hook_feedback` list of `hook feedback: <text>` lines (at most 4 KiB<!-- unrelated-bound: PostToolUse feedback aggregate --> in total, later lines dropped), rebuilt identically after resume. Because a post hook cannot refuse after the effect, a Tool whose `PostToolUse` handlers are unpinned, over the matched-handler limit, or too large even with an empty truncated response is denied before dispatch with the `PreToolUse` reasons.

**`updatedInput` narrowing.** `updatedInput` must be a complete, valid Tool call of the `tool_input` shape; anything else denies. A replacement narrows only when it is:

- a `read` of the same path whose offset and end lie inside the original window;
- a `glob` with the same normalized pattern whose page lies inside the original window (`offset` through `offset + limit`) for the same path, or whose path lies beneath the original's with both offsets zero and a limit no larger;
- a `list`, `git_status`, `git_diff` or `git_log` whose path equals the original or lies beneath it by whole segments (a root original admits any path), with Git reads keeping every other field;
- a `search` keeping its query, `regex`, `include` and `case_sensitive` after default normalization, whose page lies inside the original row window (`offset` through `offset + limit`) for the same path, or whose path lies beneath the original's with no include, both offsets zero and a limit no larger.

Parent paths, `..`, case or symlink variants, larger windows or glob limits, changed queries, patterns, matching modes, includes or case, and every `command`, MCP, Skill, `write`, `edit`, `multiedit`, `mkdir`, `apply_changeset` or internal call never narrow; the model must propose those as new calls. The replacement must also be at least as restrictive under the pinned rules and within the pinned grant. `HookFinished` journals every valid-shaped update outside an `ask` decision as a `narrowed` result; only the verdict's `narrowed` flag records acceptance. An update identical to the current call is a no-op; one refused by narrowing, rules, grant or the per-step limit denies with the matching reason and a false flag. `ask` with `updatedInput` keeps the ask on the original input. On an accepted narrowing the original Tool is `Denied` with basis `hook`, the flag set and the line `Hook narrowed this Tool to: <tool_name>`; the replacement runs next as a new `ToolStarted` intent, and `PreToolUse` hooks run again for it. A second narrowing in a step denies (`hook narrowing limit`). The model receives one Tool result from the replacement, with the original's denial line as a separate `hook_narrowing` data block.

**`Stop` and `SubagentStop`.** A primary answer runs `Stop` before `AgentFinished`; a researcher or editor answer runs `SubagentStop`, matched against its definition name (or the role fallback `researcher` / `editor`), before the child's `AgentFinished`. Both receive `stop_hook_active` and `last_assistant_message`, truncated to fit the stdin limit. Exit 2 or `decision: "block"` records `blocked` with a bounded reason. On exit 0, `continue: false` takes precedence over `decision: "block"`, journals `stopped` with optional `stopReason` and skips remaining handlers; [Run outcomes](../execution/events-and-outcomes.md#accepted-outcomes) own settlement. On a block, the accepted assistant turn and a user-data block labelled `stop_hook_feedback` are appended to the next request under ordinary Goal Provider-call admission; exhaustion ends the turn with the budget outcome, and a context without room refuses with `ContextTooLarge`. A child re-prompt stays inside its delegation deadline and turn ceiling; a stopped editor keeps its landed Workspace effects and releases its lease through the [editor lifecycle](./editors.md#editor-tool-steps). At most eight blocked continuations are admitted per actor in a Run (intervening Tool calls never reset the cap or `stop_hook_active`), so feedback stays within 8 KiB<!-- unrelated-bound: Stop hook feedback aggregate -->; after the cap a valid answer completes without another Stop invocation.

**`PreCompact`.** Before an active-Run or idle Session compaction, matching handlers receive `trigger` (`manual` or `auto`) and empty `custom_instructions`. A block skips the compaction, and the Run continues while retained context fits; otherwise the context failure applies. `continue: false` stops an active Run before compacting, or only the compaction when idle. Cancellation during an active-Run hook with a known outcome cancels the Run; an unknown outcome leaves it interrupted with an uncertain stop under [Run outcome precedence](../execution/events-and-outcomes.md#accepted-outcomes). A manual `/compact` blocked by a hook fails with `CompactionBlockedByHook`, distinct from an empty input. Each occurrence runs once; a retry reuses the recorded outcome. Idle compaction runs hooks only if the current folder grant and permission settings still match the last Run's pins, otherwise it fails closed; its hook time counts against an open Goal's active time.

**Lifecycle hooks** use the same pinned programs, Guard, sequential execution, limits, fail-closed Limit and uncertainty handling as Tool hooks. An unpinned program, matched-handler overflow or oversized input records `Blocked` before any process runs. A cut-off or cancelled SubagentStop ends that child (cancelled when the user cancelled, otherwise failed under the child's failure policy) without exhausting the Goal budget, and the editor's failure cause follows the [worker outcome contract](../execution/events-and-outcomes.md#worker-journal-protocol). An unknown outcome stops the Run as Uncertain. A blocked Stop forbids successful completion until a new answer is recorded. Open or Uncertain hooks block continuation and resume; strict replay rejects forged outcomes and miscounts without executing hooks.

### Supervisor adapter

The Supervisor is a deterministic, shadow-only evaluator over committed facts. Tool-enabled Runs pin the required `config.supervisor = {evaluator: 1, window: 32, floors, candidates, digest}` in `RunStarted`; Runs without Tools pin null. There is no configuration file, model call, clock, I/O or network, and nothing selects thresholds. Shadow mode never changes permissions, catalogs, approvals, continuation, integration, Run outcomes or model input.

A boundary follows every model `ToolFinished`, including editor Workspace effects and known denials or failures. A primary command with a nonempty validated changeset uses site `command_capture`; invalid or deferred Provider results and blocked Stop/SubagentStop use `stall`; other boundaries use `tool_outcome`. Internal definition parsing and changeset integration are excluded.

Each actor has an independent window of its last 32 boundaries, and a new Run starts empty. Calls and outcomes compare by content, never by IDs or prose. Policy, plan, grant, lease, permission and hook denials count as refusals; `filesystem_denied` counts as a path-admission rejection; ordinary nonzero exits are not probing.

| Signal | Features | Notice floor | Would-narrow candidate |
|---|---|---|---|
| Loop | Identical `(call, outcome)` suffix; same-call non-success suffix; greatest whole suffix cycle repetitions for lengths 2, 3 and 4 (shortest length wins ties); maximum per-path returns to a prior after-digest following a different digest; stall boundaries since the last succeeded observation | identical 3; failing 2; cycle 3; oscillation 1; stalled 2 | identical 4; failing 3; length-2 cycle 3, other cycles 5; oscillation 2; stalled 3 |
| Probing | Refusal suffix; refusals in window; distinct refused call keys; closed path-admission rejections | streak 2 or alias 1 | streak 3, or distinct 3 with window 4, or alias 2 |
| Disproportion | Files, deleted files, ceil(decoded before+after bytes / 1024), declared roots (minimum 1), nullable base KiB (currently null), files/root, deleted/files permille, nullable changed/base permille (currently null) | files 16, or deletion 250 permille with files/root 4 | files/root 8 with files 32; deletion 500 permille with deleted 8; growth 4000 permille with changed 64 KiB<!-- unrelated-bound: change profile growth bytes --> |

Loop and probing are journaled once per crossing; disproportion is evaluated at every capture, over validated changeset facts and declared lease/plan roots. A candidate hit is journaled with level `would_narrow`, otherwise a floor hit with level `notice`. Candidate responses, for calibration only, are loop `pause`, probing `revoke`, disproportion `require_approval`; notices have null response. Live editors supply no private capture or handover boundaries. Evaluation memory is bounded by the window and the [capture bound](../limits.md#max_snapshot_files), never by Session history, and never holds file contents.

`SupervisorVerdictRecorded` commits immediately after its subject, before hooks, integration or continuation; a failed or unknown append stops continuation. The closed payload carries `subject_sequence`, `site`, `evaluator: 1`, `mode: shadow`, one to three signal entries (`signal`, `level`, nullable `would_response`, fixed feature struct, evidence) and `capped`, and holds only integers, booleans, enums and sequences. [Execution](../execution/persistence.md#persistence-bounds) owns the [2 KiB](../limits.md#max_verdict_bytes) payload and 256-verdict Run cap; evaluation continues after the cap without journaling. No verdict enters compiled context, compaction input, Provider input or diagnostics. [Serve](../serve.md#notifications-and-items) forwards the canonical verdict (counts, sequences and closed enums, never paths or content); [terminal](../terminal/conversation.md#conversation-progress-and-history) and [telemetry](../telemetry.md#spans) own further-reduced projections.

Replay accepts recorded verdicts without reevaluating, executing or reading configuration; malformed, duplicate or misplaced verdicts reject. A well-formed, correctly placed forged verdict is accepted (replay does not prove evaluator provenance), and a missing verdict is never inferred. An interrupted prefix ending right after a subject stays valid. A changed feature definition needs a new evaluator version; threshold changes stay pinned data. No verdict grants authority.

`arany show --output supervisor-corpus SESSION_ID` exports a local calibration corpus after strict read-only replay. It refuses while the Session is active or its lock is absent or unsafe, changes nothing, opens no Workspace, reads no credentials or runtime configuration, and makes no Provider, Tool, hook or Guard call. Fork references and inherited history get the same strict validation; records describe the selected Session's own boundaries. Interrupted closed prefixes are valid; invalid history emits no corpus.

Stdout is JSONL: one header, then one record for every evaluation boundary, including negatives and boundaries after the verdict cap. The header has `format: "arany.supervisor.corpus.v1"`, `evaluator: 1`, `session_ordinal: 1`, `runs` and `goals`. Each Run entry has a one-based `run_ordinal`, closed `outcome` (`completed|failed|cancelled|stopped_by_hook|interrupted`, unfinished prefixes `interrupted`) and nullable `policy` with its pinned evaluator, window, floors and candidates, without the digest. Goal entries have a one-based `goal_ordinal`, `run_ordinals` and `outcome: completed|failed|interrupted|budget_exhausted`.

Each record has `run_ordinal`, the journal's zero-based `actor_ordinal`, closed `role`, `site`, nullable catalog `operation`, nullable `disposition_class` and closed enforcement `cause_class`, `features: {loop, probing, disproportion}`, nullable `journaled_level`, `salted_call_key`, `salted_outcome_key`, one-based `relative_step` and `labels`. Disproportion is null outside capture sites, and operation, disposition and cause are null outside Tool observations. `relative_step` counts all boundaries of the Run in journal order. `journaled_level` is the greatest level in the matching committed verdict, or null. Labels are booleans `pause_or_cancel`, `steering` and `goal_failed`, set when the committed cancellation, steering note or failed Goal follows within three subsequent boundaries of the same Run; `pause_or_cancel` is combined because the journal cannot tell a user pause from Ctrl+C, and crash interruption sets no label.

Corpus privacy is an allowlist: only the fields above are serialized, with no objectives, paths, argv, file content, model text, UUIDs, timestamps, account data, raw hashes or policy digests. Call and outcome keys are salted with a fresh random 32-byte secret per export that is never exported or persisted, so they are equal within one export and unlinkable across exports; ordering, ordinals and feature patterns stay observable, so the corpus is privacy-reduced, not anonymous. Nothing is uploaded.

An export holds at most 10,000 records and 8 MiB<!-- unrelated-bound: repetition corpus export cap -->, including header and newlines, and the [lineage replay cap](../execution/persistence.md#persistence-bounds) applies first. Overflow refuses the whole export with record and byte counts, never emitting partial stdout; replay-limit refusal uses the history-limit error. Random-source failure fails closed. The corpus grants no enforcement authority.

Enforcement, durable pause/revoke and human-only overrides need later calibrated owner approval; this adapter applies none and uses no LLM judge.
