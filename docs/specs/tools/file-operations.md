# Tools: file operations

## In-process file operations

Exact Read, typed discovery (List, Glob and Search), Skill text reads, Write, Edit, MultiEdit, Mkdir, Delete, Move and primary ApplyChangeset publication run in the Engine process on Linux and macOS; editors use the same path under their child identity and lease. Commands, Skill loading, Skill scripts and MCP stay in the Guard, and [typed Git](./git.md#typed-git-reads) runs natively. In-process operations have the Engine's privileges, bounded only by the handle-relative checks below; they never spawn, use the network or widen disclosure beyond the admitted grant. Discovery parses repository ignore controls as bounded untrusted data under the [ignore-control admission](#typed-read-discovery) and never executes them.

File Tools need a supported OS and a [Guard mode](./host-commands.md#guard-mode-and-extra-reads) that admits work, not a sandbox: without one, `auto` and `off` keep them and `required` offers none. Paths resolve within `workspace_paths` beneath the Workspace opened at admission, never following links or crossing mounts and refusing special files and protected names; a replaced Workspace records Failed at `pinned input` without attestation. A failed discovery never starts an exact read. Missing or unsafe exact paths record attested Failed or Denied observations that permit continuation; content comes only from an admitted regular file.

In a primary or researcher multi-call step, Read, List, Glob, Search and Skill text calls run concurrently under the [file-operation capacity](./limits-and-failures.md#limits-and-failure-behavior), each with its own bounds; full capacity records Limit without reading. [Execution](../execution/events-and-outcomes.md#committed-event-stream) owns step ordering. Read completions commit while a sibling waits for hooks, review or approval. Cancellation, Uncertain, Limit or a hook stop ends dispatch: a pending sibling approval is withdrawn, dispatched reads drain, and each remaining intent gets a `not_dispatched` observation. Started hooks and reviews settle under their bounds; nothing new is admitted or escalated, and a late approval cannot dispatch the withdrawn call.

Results fit the intent's rendered (model-facing serialized) result budget: List and Glob drop trailing rows and set `may_be_truncated`, Search pages as [below](./limits-and-failures.md#limits-and-failure-behavior), and a budget too small for any content is Limit. Read pages by 1-based lines: nullable `offset` defaults to 1 and nullable `limit` defaults to and caps at [`MAX_READ_PAGE_LINES`](../limits.md#max_read_page_lines); lines are cut at [`MAX_READ_LINE_CHARS`](../limits.md#max_read_line_chars) characters with `… [line truncated to <MAX_READ_LINE_CHARS> chars]`. Read streams the file with its whole-file SHA-256 and returns numbered `N\t` lines as `{sha256, total_lines, start_line, end_line, next_line, truncated, text}`. CRLF is one line ending; invalid UTF-8 fails. A page ends at the line limit or the budget; `next_line` is the next unread line or null at EOF, and `truncated` marks more pages or a cut line. An empty file or an offset past EOF returns empty text, `total_lines`, `end_line: start_line - 1` and null `next_line`. Each page is the committed observation; replay never rereads, and repeating a Read of an unchanged file with the same arguments returns the same page. A crash before `ToolFinished` replays the read as Interrupted with its active-time reservation still charged. Timeout is Limit and cancellation Cancelled, neither attested. A read uses no Guard capacity; its runtime is clamped to the remaining Goal active time, and exhausted time refuses it.

`Read { path: "spill:<digest>", offset, limit }` pages a spill file through a separate private-directory capability. The digest must be 64 lowercase hex characters; other `spill:` shapes reject before opening. Only references committed in this Session's own Runs authorize access; guesses, other Sessions and inherited fork history grant nothing. Workspace and plan scopes do not apply, but Read permission rules do. Unknown references record attested `Failed` with `no spill for this Run`. Only private, user-owned, single-link regular files open, and the Guard never receives StateRoot paths or handles.

A valid, in-scope, non-protected missing path (including one under a regular-file ancestor) records attested `Failed` with `File or directory not found; List the parent directory to check the path`, without suggestions. Links, mounts and special files stay `Denied` with `File path is unavailable or outside the admitted regular-file boundary`; protected and out-of-scope paths keep their grant denial.

Each observation carries an `attestation`: `in_process` (policy digest, Workspace device and inode) or `guard` (Guard receipt). Replay rejects Guard receipts or bootstrap causes for in-process calls, and the Guard refuses them. Successful mutations carry `FileReceipt { intent_digest, before, after, executable }` in the attestation, binding intent and result: Move keeps the digest, Delete has no after digest, and Mkdir and batch ApplyChangeset have no single-file digests. Historical Guard mutation intents keep their own enforcement digest and labels and replay unchanged. "Guarded Edit" means this in-process Edit with its FileReceipt and checkpoint; there is no Guard Edit path.

Writes use digest or create preconditions, no-follow handles and a fresh inode with atomic replacement, never in-place truncation. Strict schemas expose `expected_digest` as required nullable on every typed mutation (the source's digest for Move), [filled by the Engine](#engine-filled-preconditions) when null. A create-mode Write (null `expected_digest` and no known digest) creates missing parent directories through Move's checked parent creation, needing no Mkdir; a parent beneath a regular file gets the not-found result. A missing Mkdir parent records attested `Failed` with `Parent directory not found; create it with Mkdir first`, and a missing Edit or MultiEdit target gets the not-found result. Symlinks, hard links, special files and stale preconditions reject. This is no transaction against concurrent host edits, rollback guarantee or protection from a hostile same-user or root process.

ToolStarted commits and a checkpoint is captured before any mutation byte. Cancellation is checked before temporary creation and before publication; once publication begins it completes and records success, then the Run stops Cancelled. A deadline before publication is Limit; after publication begins it is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), as is a failed parent-directory sync. Failed temporary writes or pre-publication renames leave the target unchanged. Death between publication and ToolFinished leaves an Interrupted intent that resume never retries.

### Engine-filled preconditions

A supplied `expected_digest` is used unchanged. The Engine fills a null one from committed facts before the intent is hashed or proposed: the newest SHA-256 of that exact normalized path the same actor observed in the current Run, from an attested `Succeeded` Read page, the actor's own Write, Edit or MultiEdit result, Move destination or command-integration file, or the Run's explicit file include. Another actor's change to the path, a Delete or Move of it, an Uncertain change, a host or unguarded command, `git_switch`, an MCP call or a rewind publication leaves no known digest; a non-Uncertain failed mutation changes nothing. Every omitted digest in one step resolves from observations committed before that step, so a second change to the same file in the step fails stale; MultiEdit combines them.

With no known digest, a primary Edit, MultiEdit, Delete or Move is a [proposal refusal](../execution/events-and-outcomes.md#accepted-outcomes) with cause `digest_unknown` and remediation "Read the file first", before any intent; an editor's such proposal is invalid like its other invalid proposals; a Write stays create-only. A Goal `tool_call_succeeded` criterion must state its digest. `ToolProposed`, `ToolStarted`, hooks, approvals, receipts and checkpoints carry only the concrete digest, and validation rejects a committed mutation intent without one, so strict replay never re-resolves. A filled digest is checked against the file's current bytes exactly like a supplied one, so a wrong fill can only fail stale and carries no more authority than a model-supplied digest.

### Typed read discovery

List, directory Search, Glob and [file suggestions](../terminal/commands.md#interactive-commands-and-completion) apply the shared [ignore-control admission](./changesets-and-checkpoints.md#command-input-selection) before opening payloads. Only admitted root and nested `.gitignore` files supply rules, also outside Git repositories, with the same precedence, escapes, negation and ancestor pruning as command selection; tracked files are not exempt and `.git/info/exclude` is never read. A directory below the Workspace root holding its own `.git` entry (file or directory) is a nested repository or worktree (for example `.claude/worktrees/*`): discovery, suggestions and macOS command selection list it but never descend into it unless it is the requested base or a selected scope root, and command capture discards new outputs beneath it. Walks never follow links or cross mounts. Naming a nested or ignored directory keeps its ancestor rules. Query patterns only narrow candidates. Protected names, generated-directory exclusions, grants and Read restrictions stay dominant, including case variants and descendants. An inaccessible required control rejects generically; confirmed absence is allowed. Unsafe, oversized, malformed or inaccessible controls discard results without raw rule diagnostics.

List and Glob read metadata only. Vanishing descendants and absent scope roots are omitted; an explicitly requested missing base gets the not-found result. A required-control change rejects the whole selection. Directory Search opens only selected regular files, so oversized ignored files cannot fail it. Filtering precedes sorting, pagination and fitting. Exact Read and exact-file Search of an admitted ignored file keep their permission decisions without loading controls; protected names stay refused. Includes, Skills, commands and Git keep their own disclosure contracts. The model cannot override ignores.

Selection uses the shared [in-process file-operation capacity](./limits-and-failures.md#limits-and-failure-behavior), never a Guard slot; full capacity records `Limit / ReadCapacity` before I/O, without retry. The [Terminal contract](../terminal/commands.md#interactive-commands-and-completion) owns composer suggestions. Selection is bounded by 1,048,576 matcher calls, including ancestor checks, and two seconds, shortened by the Tool or Goal deadline: count or expansion exhaustion is `Limit(resource)`, elapsed time `Limit(timeout)`. Walks inspect at most 200,000 directory entries and keep the path, content and result bounds and depth 16, including control filenames. Except for [Search pages](./limits-and-failures.md#limits-and-failure-behavior), failure discards partial results; cancellation records Cancelled at the next entry; neither starts an exact Read or host operation. Strict replay projects committed observations without rereading controls or names.

### Glob file discovery

`glob` takes `{pattern, path, offset, limit}` and returns admitted regular files whose path relative to `path` matches `pattern`, with a 100-file default. `pattern` is 1–512 UTF-8 bytes; `path` is a Workspace-relative directory; `offset` counts matches to skip, at most the 200,000-entry walk bound; `limit` is 1–100. Strict schemas expose `path`, `offset` and `limit` as required nullable fields; null, omitted or empty `path` becomes `.`, a missing offset 0 and a missing limit 100 before hashing, so permissions, hooks and replay see one form. Out-of-range offsets and limits are refused, not clamped.

The grammar is closed and case-sensitive, and the whole relative path must match. `*` matches any run and `?` one character within a component. `**` must be a whole component: `**/` crosses zero or more directories and a terminal `**` matches the rest, so `*.rs` matches only files directly in `path`. One level of `{a,b}` gives literal or wildcard alternatives within a component, at most 16 in total. Bracket classes, backslash escapes, a leading `!`, absolute or `~` prefixes, controls, empty, `.` or `..` components, nested, empty, single or unclosed braces and partial `**` are refused before traversal, never reinterpreted as literals. The translated regular expression is at most 8 KiB<!-- unrelated-bound: glob regex translation bytes -->, compiled with a 128 KiB<!-- unrelated-bound: discovery regex compiled size --> size, a 32 KiB<!-- unrelated-bound: regex DFA cache --> DFA cache and 32 nesting levels; overflow refuses. Permission path patterns have their own semantics.

Glob never opens contents, so it reports sizes beyond the [1 MiB](../limits.md#max_file_bytes) content cap and supplies no SHA-256 or edit precondition. It walks like List: protected components (`.env`, `.env.*`, `.git` and the rest), symbolic links, hard-linked and special files, other mounts and non-UTF-8 names are skipped, and a whole-project grant also skips `target`, `node_modules`, `.venv` and `venv`; other hidden names match normally. A pattern without `**` does not descend past its component count. Exceeding the 200,000-entry, depth 16 or 512-byte<!-- unrelated-bound: Glob discovery path bytes --> path bound is Limit, never partial success. Only the requested page plus one lookahead match is retained, so any number of matches pages.

The result is `{entries: [{path, bytes}], limit, may_be_truncated, next_offset}`: Workspace-relative paths, deduplicated across roots and sorted by UTF-8 bytes (never by mutable timestamps); the first `offset` matches are skipped and the next `limit` kept. `may_be_truncated` is true only when another match exists or trailing entries were dropped to fit, so exactly `limit` matches is complete; `next_offset` is then the offset of the first omitted match, otherwise null, as in [Search pages](./limits-and-failures.md#limits-and-failure-behavior). If nothing fits, Limit. A `path` naming a file records Failed, a missing path not-found, and a link, mount or special file Denied. Editors use the same in-process Glob within their read grant; a missing leased creation root records not-found.

## Typed delete and move

Closed typed operations exist because generic command changes must pass changeset publication. `delete {path, expected_digest}` removes one existing regular file. `move {source, destination, expected_digest}` moves one existing regular file to an absent destination, creating missing destination parents and preserving its bytes and executable status. The digest is the source's lowercase SHA-256, [filled by the Engine](#engine-filled-preconditions) when null. Neither removes directories or overwrites; identical and ASCII case-only moves reject. Missing sources fail; stale digests and occupied destinations conflict. Protected names, unsafe ancestors, links (hard links included), special and set-ID files, mount crossings and filesystem aliases refuse. File-version, argument, result, action and checkpoint bounds apply; overflow publishes nothing.

Both are Edit-family mutations under the write grant, modes, hooks and Goal scope. Move needs both paths within the grant, plan and any editor lease: one allow rule must cover both, while a deny or ask, or a Read denial, on either applies. Hooks see `Edit` with the complete typed call; unsupported rewrites deny. Summaries and approvals name every path inertly. Researchers cannot call them; editors need the `delete` or `move` capability and use the [editor mutation path](./editors.md#editor-tool-steps). Primary effects refuse overlap with an active editor lease on either path.

One call is one journaled intent and result, published [in process](#in-process-file-operations) after revalidating the source, digest, executable status and absent destination. Move publishes the destination before deleting the source; it is not an atomic multi-file transaction. Failure or drift after any publication, lost completion or unconfirmed durability is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), with no rollback claim; cancellation before publication changes nothing. Results keep the removed file's digest, length and executable status. Checkpoints save the source first; rewind restores it and removes the destination. Strict replay validates receipts without touching files.

## Atomic single-file MultiEdit

`multiedit` takes `{file_path, expected_digest, edits: [{old_string, new_string, replace_all}]}` and edits one existing regular UTF-8 file under Edit's path and SHA-256 precondition rules. Unknown fields reject at both levels. `replace_all` defaults to false (strict schemas: required nullable, null meaning false); intents store the effective boolean.

It applies 1–64 literal replacements in order, each to the previous result, so dependent edits (A → B, then B → C) work. False needs exactly one non-overlapping match; true replaces all and needs at least one. Empty searches, identical old and new strings and an unchanged final result reject. Text stays literal: no quote normalization, newline removal or token expansion. Any missing or ambiguous match leaves the file unchanged.

[Limits](./limits-and-failures.md#limits-and-failure-behavior) owns the replacement, input, file-size and argument ceilings. The original, each intermediate result and the final content stay within the file-size ceiling, checked before allocation; overflow refuses the batch. At most 64 passes run, without recursion or retry.

The change publishes once through Edit's fresh-inode replacement with before and after digests, lengths and executable bits, so readers see either version. Stale digests, invalid UTF-8, unsafe paths, match or bound failures and cancellation before publication publish nothing. Interrupted publication or unconfirmed durability is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). One batch is one intent, permission decision, action and outcome; replay uses its receipt without touching the file.

MultiEdit is in the Edit permission family, including `acceptEdits`, path restrictions and read-denial protection. Hooks see `MultiEdit` with the whole batch under the hook-input ceiling; unsupported rewrites deny. Researchers cannot call it; editors need the `multiedit` capability within the parent grant and lease. Model results omit checkpoint metadata. The terminal shows one `MultiEdit(path, N edits)` outcome, and approval shows every replacement in order.

Existing-file scope, ordered intermediate results and the 64-edit limit are owner decisions; there is no implicit creation, fuzzy matching or partial write.
