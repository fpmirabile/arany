# Tools: file operations

## In-process file operations

Exact Read, typed discovery (List, Glob and Search) and Skill text reads run in the Engine process. Discovery parses repository ignore controls as bounded untrusted data under the [ignore-control admission](#typed-read-discovery) and the handle-relative checks below, and never executes them. Write, Edit, MultiEdit, Mkdir, Delete, Move and primary ApplyChangeset publication run in process on Linux and macOS; editors use the same path under their child identity and lease. Typed Git reads, commands, Skill loading, Skill scripts and MCP stay in the Guard. In-process operations run with the Engine's privileges, bounded only by the handle-relative checks below; they never spawn, use the network or widen disclosure beyond the admitted grant.

File Tools need a supported OS and a [Guard mode](./host-commands.md#guard-mode-and-extra-reads) that admits work, not a sandbox: without one, `auto` and `off` keep them and `required` offers none. The Engine opens the Workspace directory handle once at admission and resolves paths beneath it with no-follow, link, mount, special-file and protected-name checks within `workspace_paths`. Dispatch checks the intent, policy digest and directory identity; a replaced Workspace records Failed at `pinned input` without attestation. A failed discovery never starts an exact read. Missing or unsafe exact paths record attested Failed or Denied observations that permit continuation; content comes only from an admitted regular file.

In a primary or researcher multi-call step, Read, List, Glob, Search and Skill text calls run concurrently under the [file-operation capacity](./limits-and-failures.md#limits-and-failure-behavior), each with its own bounds; full capacity records Limit without reading. [Execution](../execution/events-and-outcomes.md#committed-event-stream) owns step ordering. Read completions commit while a sibling waits for hooks, review or approval. Cancellation, Uncertain, Limit or a hook stop ends dispatch: a pending sibling approval is withdrawn, dispatched reads drain, and each remaining intent gets a `not_dispatched` observation. Started hooks and reviews settle under their bounds; nothing new is admitted or escalated, and a late approval cannot dispatch the withdrawn call.

Results fit the intent's rendered (model-facing serialized) result budget: List and Glob drop trailing rows and set `may_be_truncated`, Search pages as [below](./limits-and-failures.md#limits-and-failure-behavior), and a budget too small for any content is Limit. Read uses 1-based line paging: nullable `offset` defaults to 1 and nullable `limit` defaults to and caps at [`MAX_READ_PAGE_LINES`](../limits.md#max_read_page_lines). Lines are cut at [`MAX_READ_LINE_CHARS`](../limits.md#max_read_line_chars) characters with `… [line truncated to <MAX_READ_LINE_CHARS> chars]`. Read streams the file with its whole-file SHA-256 and returns numbered `N\t` lines as `{sha256, total_lines, start_line, end_line, next_line, truncated, text}`. CRLF is one line ending; invalid UTF-8 fails. A page ends at the line limit or the budget; `next_line` is the next unread line or null at EOF, and `truncated` marks more pages or a cut line. An empty file or an offset past EOF returns empty text, `total_lines`, `end_line: start_line - 1` and null `next_line`. Each page is the committed observation; replay never rereads. Repeating a Read of an unchanged file with the same arguments returns the same page. A crash before `ToolFinished` replays the read as Interrupted with its active-time reservation still charged. Timeout is Limit and cancellation Cancelled, neither attested. A read takes no Guard capacity and reserves its Goal action with zero preparation overhead; its runtime is clamped to the remaining active time, and exhausted time refuses it.

`Read { path: "spill:<digest>", offset, limit }` pages a spill file through a separate private-directory capability. The digest must be 64 lowercase hex characters; other `spill:` shapes reject before opening. Only references committed in this Session's own Runs authorize access; guesses, other Sessions and inherited fork history grant nothing. Workspace and plan scopes do not apply, but Read permission rules do. Unknown references record attested `Failed` with `no spill for this Run`. No-follow, owner, private-mode, single-link, regular-file and same-device checks apply. The Guard never receives StateRoot paths or handles.

A valid, in-scope, non-protected missing path (including one under a regular-file ancestor) records attested `Failed` with `File or directory not found; List the parent directory to check the path`, without suggestions. Links, mounts and special files stay `Denied` with `File path is unavailable or outside the admitted regular-file boundary`; protected and out-of-scope paths keep their grant denial.

Each observation carries an `attestation`: `in_process` (policy digest, Workspace device and inode) or `guard` (Guard receipt). Validation and replay reject Guard receipts or bootstrap causes for reads, discovery, Skill text and in-process mutations; live Guard dispatch refuses every in-process call. Successful mutations carry `FileReceipt { intent_digest, before, after, executable }` in the attestation, binding intent and result: Move keeps the digest, Delete has no after digest, and Mkdir and batch ApplyChangeset have no single-file digests. Historical Guard mutation intents keep their own enforcement digest and labels and replay unchanged.

"Guarded Edit" means this in-process Edit with its FileReceipt and checkpoint; there is no Guard Edit path.

Writes use digest or create preconditions, no-follow handles and a fresh inode with atomic replacement, never in-place truncation. Strict schemas expose `expected_digest` as required nullable on every typed mutation (the source's digest for Move); its filling is [below](#engine-filled-preconditions). A create-mode Write (null `expected_digest` and no known digest) creates missing parent directories through Move's checked parent creation, so it needs no Mkdir first; a parent beneath a regular file gets the not-found result. A missing Mkdir parent records attested `Failed` with `Parent directory not found; create it with Mkdir first`, and a missing Edit or MultiEdit target gets the not-found result. Symlinks, hard links, special files and stale preconditions reject. This is not a transaction against concurrent host edits, a rollback guarantee or protection from a hostile same-user or root process.

ToolStarted commits before any mutation byte, and checkpoint capture precedes dispatch. A blocking task keeps its capacity slot until it exits. Cancellation is checked before temporary creation and before publication; once publication begins it completes and records success, then the Run stops Cancelled. A deadline before publication is Limit; after publication begins it is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), as is a failed parent-directory sync. Failed temporary writes or pre-publication renames leave the target unchanged. Death between publication and ToolFinished leaves an Interrupted intent that resume never retries. There is no Guard preparation or pre-GO stage.

### Engine-filled preconditions

A supplied `expected_digest` is used unchanged. A null one is filled by the Engine from committed facts before the intent is hashed or proposed: the newest SHA-256 of that exact normalized path that the same actor observed in the current Run, from an attested `Succeeded` Read page, the actor's own Write, Edit or MultiEdit result, Move destination or command-integration file, or the Run's explicit file include. Another actor's change to the path, a Delete or Move of it, an Uncertain change, a host or unguarded command, `git_switch`, an MCP call or a rewind publication leaves no known digest; a non-Uncertain failed mutation changes nothing. Every omitted digest in one step resolves from observations committed before that step, so a second change to the same file in the step fails stale; MultiEdit combines them.

With no known digest, a primary Edit, MultiEdit, Delete or Move is a [proposal refusal](../execution/events-and-outcomes.md#accepted-outcomes) with cause `digest_unknown` and remediation "Read the file first", before any intent; an editor's such proposal is invalid like its other invalid proposals; a Write stays create-only. A Goal `tool_call_succeeded` criterion must state its digest. `ToolProposed`, `ToolStarted`, hooks, approvals, receipts and checkpoints carry only the concrete digest, and validation rejects a committed mutation intent without one, so strict replay never re-resolves. The reducer does not re-derive a filled digest: the publisher compares it with the file's current bytes exactly as a supplied one, so a wrong fill can only fail stale, never publish over content it does not describe, and it carries no more authority than a model-supplied digest. The harness tracks read state instead of asking the model for hashes, and Arany keeps the exact digest precondition and its journal provenance.

### Typed read discovery

List, directory Search, Glob and [file suggestions](../terminal/commands.md#interactive-commands-and-completion) apply the shared [ignore-control admission](./changesets-and-checkpoints.md#command-input-selection) before opening payloads. Only admitted root and nested `.gitignore` files supply rules, also outside Git repositories, with the same precedence, escapes, negation and ancestor pruning as command selection; tracked files are not exempt. `.git/info/exclude` is never read. A directory below the Workspace root holding its own `.git` entry (file or directory) is a nested repository or worktree (for example `.claude/worktrees/*`): discovery, suggestions and macOS command selection list it but never descend into it, unless it is the requested base or a selected scope root, and command capture discards new outputs beneath it. Like ripgrep's walker, each walk keeps one directory handle per level and resolves every child relative to it without following links or crossing mounts. Naming a nested or ignored directory keeps its ancestor rules. Query patterns only narrow candidates. Protected names, generated-directory exclusions, grants and Read restrictions stay dominant, including case variants and descendants. An inaccessible required control rejects generically; confirmed absence is allowed. Unsafe, oversized, malformed or inaccessible controls discard results without raw rule diagnostics.

List and Glob read metadata only. Vanishing descendants and absent scope roots are omitted; an explicitly requested missing base gets the not-found result. A required-control change rejects the whole selection. Directory Search opens only selected regular files, so oversized ignored files cannot fail it. Filtering precedes sorting, pagination and fitting. Exact Read and exact-file Search of an admitted ignored file keep their permission decisions without loading controls; protected names stay refused. Includes, Skills, commands and Git keep their own disclosure contracts. The model cannot override ignores; consistent omission deliberately narrows incidental disclosure.

Selection runs single-threaded on one blocking thread under the shared [in-process file-operation capacity](./limits-and-failures.md#limits-and-failure-behavior), never in a Guard unit or capacity slot; full capacity records `Limit / ReadCapacity` before I/O, without retry. The [Terminal contract](../terminal/commands.md#interactive-commands-and-completion) owns composer suggestions. Selection is bounded by 1,048,576 matcher calls, including ancestor checks, and two seconds, shortened by the Tool or Goal deadline: count or expansion exhaustion is `Limit(resource)`, elapsed time `Limit(timeout)`. Walks inspect at most 200,000 directory entries and keep the path, content and result bounds and depth 16, including control filenames. A wildcard-free leading directory in a Glob pattern or Search include starts matching beneath it, so the walk skips sibling trees with identical results. Except for [Search pages](./limits-and-failures.md#limits-and-failure-behavior), failure discards partial results; cancellation records Cancelled and the walk stops at its next entry, keeping its capacity slot until then; neither starts an exact Read or host operation. Strict replay projects committed observations without rereading controls or names.

### Glob file discovery

`glob` takes `{pattern, path, offset, limit}` and returns admitted regular files whose path relative to `path` matches `pattern`, with a 100-file default. `pattern` is 1–512 UTF-8 bytes; `path` is a Workspace-relative directory; `offset` counts matches to skip, at most the 200,000-entry walk bound; `limit` is 1–100. Strict schemas expose `path`, `offset` and `limit` as required nullable fields; null, omitted or empty `path` becomes `.`, a missing offset 0 and a missing limit 100 before hashing, so permissions, hooks and replay see one form. Out-of-range offsets and limits are refused, not clamped.

The grammar is closed and case-sensitive. The whole relative path must match. `*` matches any run and `?` one character within a component. `**` must be a whole component: `**/` crosses zero or more directories and a terminal `**` matches the rest, so `*.rs` matches only files directly in `path`. One level of `{a,b}` gives literal or wildcard alternatives within a component, at most 16 in total. Bracket classes, backslash escapes, a leading `!`, absolute or `~` prefixes, controls, empty, `.` or `..` components, nested, empty, single or unclosed braces and partial `**` are refused before traversal, never reinterpreted as literals. The translated regular expression is at most 8 KiB<!-- unrelated-bound: glob regex translation bytes -->, compiled with a 128 KiB<!-- unrelated-bound: discovery regex compiled size --> size, a 32 KiB<!-- unrelated-bound: regex DFA cache --> DFA cache and 32 nesting levels; overflow refuses. Arany refuses bracket classes to keep the grammar closed. Permission path patterns have their own semantics.

Glob never opens contents, so it reports sizes beyond the [1 MiB](../limits.md#max_file_bytes) content cap and supplies no SHA-256 or edit precondition. It walks like List: protected components (`.env`, `.env.*`, `.git` and the rest), symbolic links, hard-linked and special files, other mounts and non-UTF-8 names are skipped, and a whole-project grant also skips `target`, `node_modules`, `.venv` and `venv`. Other hidden names match normally. A pattern without `**` does not descend past its component count. The walk inspects at most 200,000 directory entries, depth 16 and paths of 512 bytes<!-- unrelated-bound: Glob discovery path bytes -->; exceeding any of these is Limit, never partial success. It retains only the requested page plus one lookahead match, so any number of matches pages.

The result is `{entries: [{path, bytes}], limit, may_be_truncated, next_offset}`: Workspace-relative paths, deduplicated across roots and sorted by UTF-8 bytes; the first `offset` matches are skipped and the next `limit` kept. `may_be_truncated` is true only when another match exists or trailing entries were dropped to fit, so exactly `limit` matches is complete; `next_offset` is then the offset of the first omitted match, otherwise null, as in [Search pages](./limits-and-failures.md#limits-and-failure-behavior). If nothing fits, Limit. Arany uses path order so the observation does not depend on mutable timestamps. A `path` naming a file records Failed, a missing path not-found, and a link, mount or special file Denied. Editors use the same in-process Glob within their read grant; a missing leased creation root records not-found.

## Typed delete and move

`delete {path, expected_digest}` removes one existing regular file. `move {source, destination, expected_digest}` moves one existing regular file to an absent destination, creating missing destination parents, and preserves its bytes and executable status. The digest is the source's lowercase SHA-256, [filled by the Engine](#engine-filled-preconditions) when null. Neither removes directories or overwrites; identical and ASCII case-only moves reject. Missing sources fail; stale digests and occupied destinations conflict. Protected names, unsafe ancestors, links (including hard links), special and set-ID files, mount crossings and filesystem aliases refuse. File-version, argument, result, action and checkpoint bounds apply; overflow publishes nothing.

Both are Edit-family mutations under the write grant, modes, hooks and Goal scope. Move needs both paths within the grant, plan and any editor lease: one allow rule must cover both, while a deny or ask, or a Read denial, on either applies. Hooks see `Edit` with the complete typed call; unsupported rewrites deny. Summaries and approvals name every path inertly. Researchers cannot call them; editors need the `delete` or `move` capability and use the [editor mutation path](./editors.md#editor-tool-steps). Primary effects refuse overlap with an active editor lease on either path.

One call is one journaled intent and result, published by the [in-process publisher](#in-process-file-operations) after validating source bytes, digest, executable status, the absent destination and parent identities. Move writes a fresh destination inode, then deletes the source with changeset integration's checked deletion and directory sync; it is not an atomic multi-file transaction. Failure or drift after any publication, lost completion or unconfirmed durability is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), with no rollback claim; cancellation before publication changes nothing. Results keep the removed file's digest, length and executable status. Checkpoints save the source first; rewind restores it and removes the destination. Strict replay validates receipts without touching files.

Arany offers closed typed operations because generic command changes must pass changeset publication.

## Atomic single-file MultiEdit

`multiedit` takes `{file_path, expected_digest, edits: [{old_string, new_string, replace_all}]}` and edits one existing regular UTF-8 file under Edit's path and SHA-256 precondition rules. Unknown fields reject at both levels. `replace_all` defaults to false (strict schemas: required nullable, null meaning false); intents store the effective boolean.

It applies 1–64 literal replacements in order, each to the previous result. False needs exactly one non-overlapping match; true replaces all and needs at least one. Empty searches, identical old and new strings and an unchanged final result reject. Text stays literal: no quote normalization, newline removal or token expansion. Dependent edits (A → B, then B → C) work. Any missing or ambiguous match leaves the file unchanged.

[Limits](./limits-and-failures.md#limits-and-failure-behavior) owns the replacement, input, file-size and argument ceilings. The original, each intermediate result and the final content stay within the file-size ceiling, checked before allocation; overflow refuses the batch. At most 64 passes run, without recursion or retry.

The change publishes once through Edit's fresh-inode replacement with before and after digests, lengths and executable bits, so readers see either version. Stale digests, invalid UTF-8, unsafe paths and match or bound failures publish nothing; so does cancellation before publication. Interrupted publication or unconfirmed durability is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). One batch is one intent, permission decision, action and outcome; replay uses its receipt without touching the file.

MultiEdit is in the Edit permission family, including `acceptEdits`, path restrictions and read-denial protection. Hooks see `MultiEdit` with the whole batch under the hook-input ceiling; unsupported rewrites deny. Researchers cannot call it; editors need the `multiedit` capability within the parent grant and lease. Model results omit checkpoint metadata. The terminal shows one `MultiEdit(path, N edits)` outcome, and approval shows every replacement in order.

Field names, defaults, match checks, no-op rejection and the permission family follow proven harness designs; ordered intermediate results are an owner choice. Existing-file scope and the 64-edit limit are owner decisions; there is no implicit creation, fuzzy matching or partial write.
