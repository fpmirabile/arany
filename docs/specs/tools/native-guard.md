# Tools: native Guard enforcement

## macOS enforcement and compatibility

Primary Workspace mutations and typed discovery allocate no Guard unit. Skill loading and definition parsing use the non-spawning profile, which never grants Workspace writes. Commands and MCP run native binaries with ordinary child launches, including `posix_spawn`; a fork/exec-only profile is insufficient.

Dispatch requires an available Background launchd user domain, a distinct kernel resource coalition, a trusted bounded supervisor and a separate attested Seatbelt worker. The private control directory lies outside the Workspace; overlap rejects. Without the Apple compiler and SDK profiles, a guarded command cannot read or execute the Command Line Tools or an SDK, even where the host baseline allows it. A stale executable pin rejects before any Provider request and keeps the committed history prefix. The supervisor's launchd PID and authenticated peer must be one process. Completion is accepted only after the coalition is empty and the one-use job is removed or reported absent; job retirement is not descendant cleanup. There is no unsandboxed fallback. The launcher runs in its own process group so descendants cannot hang up the supervisor; a PID or process group is not containment, the coalition is.

Before Tools are offered, admission validates the immutable `launchctl` and `env` through no-follow OS-program admission, then coalition observation and the launchd domain with a data-free probe (three-second deadline, one second for kill and reap). Availability is not attestation: unit authentication, coalition ownership, storage preparation and installed enforcement are checked before GO. Deadlines and native-manager failures name their stage without native diagnostics; cleanup failures keep their own stage and block acceptance.

Teardown (supervisor stop, launcher reap, stderr EOF and storage check) shares one ten-second bound; MCP server reap and stderr drain share a second, equal bound in the worker. Member enumeration failing during exit is retried within it. Only observed termination and a unit root with no mount or foreign-device entry beneath it accept.

Failed teardown names a closed stage (process cleanup, launcher reap, output EOF or storage cleanup) as the Guard stage; no worker text reaches the model. The failed storage check (inspection, mount still present) and post-dispatch execution check (worker closed before report, worker panicked, malformed, unattested or unterminated report, cancelled, controller thread failed) go only to the debug development log; the model-facing stage stays execution. Supervisor stdout and stderr go to one owner-only file in the unit root, deleted with it; it holds only panic text, capped at 4 KiB<!-- unrelated-bound: macOS supervisor panic output -->, and fixed fatal-abort lines. On early worker close the controller reads at most the last 4 KiB<!-- unrelated-bound: macOS supervisor diagnostic tail --> to classify a panic, keeping the printable tail for the debug log and test recorder. Privileged OS mutation stays outside the current-user boundary.

Supervision uses kernel process identity, membership from bounded kernel metadata (never arguments or environments) and cumulative CPU across exec. Reaped or replaced members retire after identity revalidation, even if sampling fails during exit; an unobserved live member rejects. Signals target exact incarnations, never a reused PID. Memory is aggregate physical footprint plus thread count; a missing observation fails closed. Cleanup needs an exact-target `bootout` that succeeds or reports absence, then positive emptiness.

Default and Build profiles kill the whole unit when a threshold is exceeded or the observer fails. Thresholds are supervised, not kernel ceilings: delays and work between samples can exceed them, and no swap prohibition or group OOM is claimed. CPU is per process, so tree CPU and instantaneous rate are unbounded; Build's threshold follows its wall timeout, the default keeps 15 seconds per process. Since processes can ignore `SIGXCPU`, `RLIMIT_CPU` alone is insufficient: non-spawning profiles reset and unblock it, install hard CPU expiry and forbid handler, mask, signal-wait and limit changes before Seatbelt locks them, while commands and MCP use external CPU supervision. Wall time, output, the disk reserve, offline isolation and complete descendant termination are always enforced.

Each unit's `workspace`, `scratch` and cache view are owner-only (0700, no ACL) directories in its root on the host volume, never images: Seatbelt confines writes to them by path and refuses hard links from unwritable sources, so an alias of a readable host file cannot be written. Copy and capture caps, the changeset ceiling and the cache candidate cap still bound what is read and published. Disk use is bounded by a [2 GiB](../limits.md#guard_disk_reserve_bytes) free-space reserve on that volume, sampled every supervision interval: a unit is refused before launch below the reserve with `Limit(resource)` naming the free and reserved MiB; a command's worker stops its payload at the reserve and appends a fixed `[arany] Command stopped` line to stderr, keeping its output and publishing nothing; the supervisor kills any unit at half the reserve. Other writers on the volume count too. There is no per-command growth cap: a command may fill free space; Arany keeps only the reserve the journal needs for durability and stops the command there with a message, instead of letting the disk fill. Linux payload writes land in memory-bounded tmpfs uppers, so the reserve concerns only the build cache there. The unit root is `/private/tmp/arany-u-<uuid>`, locked by `unit.lock` created in one exclusive open and released by the kernel when the controller exits. The controller durably records root device, inode and boot identity before launching its job; the supervisor durably records process and coalition identity before any task or payload.

Cleanup empties the coalition before the root is removed, including during preparation unwinds. A storage name that is not a same-device directory, or any mount beneath the root, keeps the root and rejects completion rather than deleting through it. Deletion needs positive ownership and the recorded root identity, never a filename prefix. One debug `development.log` line per unit records controller stage durations (`guard timing call=… connect_ms ready_ms report_ms teardown_ms cache_ms`).

Before creating a unit, admission scans at most 4096 directory entries and recovers at most eight unlocked roots owned by the effective uid within one 30-second<!-- unrelated-bound: macOS native recovery deadline --> deadline, taking an exclusive lock and validating no-follow records and root identity. Within the recorded boot it removes the exact job and empties the coalition by current audit-token identities; after reboot it signals nothing and leaves later-boot jobs alone. Storage cleanup needs no OS tool: root deletion requires no mount or unexpected storage object beneath it. Roots without valid records, including older ones, stay untouched and count toward capacity like live, recovering and pre-lock roots; valid records are tried first. Unreadable or over-limit listings and deadline expiry reject as unavailable protection without removal advice. Cancellation or failure leaves records recoverable and never retries an old intent.

Commands and MCP get a fresh checked Workspace snapshot, including prior typed edits, and a read-only tree of pinned runtime resources. Writable mounts prohibit set-ID. System executables must be immutable, root-owned, non-set-ID and unentitled. Granted `PATH` directories, system link targets, Homebrew prefixes and manager roots are a separate class with read, map-executable and exec permission and without those checks; privileged process, credential and coalition changes stay denied. With commands or MCP enabled, admission checks the bounded executable catalogue once per Run and binds it into each intent and receipt. Workers revalidate each entry through no-follow handles relative to pinned `/bin` and `/usr/bin` (ownership, mode, device, inode, size, timestamps) before Ready; changed or oversized catalogues reject without retry. Signature verdicts are reused only for an identical path and stamp, never persisted; an undetermined one excludes the program for that admission. File and Skill workers carry no catalogue. The runtime excludes account and Session roots, network and Mach services. Root or mismatched real and effective identities reject. Unprivileged `fork`, `exec` and `posix_spawn` stay available.

Seatbelt metadata grants name only required roots and exact ancestors; ancestors such as `/private/tmp` and the unit root grant metadata, never listings, through search-only descriptors, and only the selected final directory opens readably. Admitted runtime directories stay readable; other host paths get no metadata. The command profile also reads `/` itself because the native loader opens it, exposing only top-level names. Commands and MCP may read `/private/etc/ssl` (TLS configuration and CA bundle), because the system LibreSSL behind `/usr/lib/libcurl.4.dylib`, loaded by clients such as rustup proxies, exits when `openssl.cnf` is denied; no other `/private/etc` path is granted. Canonicalized selected roots reject descendant mount targets in `getfsstat` before Seatbelt and Ready/GO, a point-in-time check only.

macOS uses private physical paths, not a mount namespace. The working directory is in the project snapshot. Standalone argv paths under `/workspace`, `/scratch`, `/cache`, `/inputs`, `/skills` or `/programs` map into private storage, and copied-program aliases apply to copied executables. Shell strings are not rewritten; scripts use `ARANY_TOOL_WORKSPACE`, `ARANY_TOOL_INPUTS`, `ARANY_TOOL_SKILLS` or relative paths. On both platforms the pinned `/bin/sh` accepts only argv starting with `-c` followed by a script that does not begin with `-` or `+`; anything else is refused before the shell starts. Arany never starts a login shell or sources profiles, preserving per-effect isolation; a script may source a file it names. The Guard prepends one fixed prefix exporting the quote-escaped page-size helper path, never rewriting options into script text. `HOME` and `TMPDIR` point to scratch. System binaries run at their original paths.

The environment is cleared; `SDKROOT` is set only for the exact Apple SDK profile. The embedded universal (arm64, arm64e, x86_64) page-size dylib is staged privately, read no-follow under a 128 KiB<!-- unrelated-bound: embedded compatibility dylib cap --> cap and compared with the embedded bytes, which the enforcement digest binds. It answers only `sysconf(_SC_PAGESIZE)` and `getpagesize()` from `vm_page_size`; sysctl stays denied without exception. Host CPU discovery stays denied; selected-Rust Build commands get the Goal-pinned jobs default. Because SIP can strip `DYLD_INSERT_LIBRARIES`, the `-c` prefix re-exports it. A configured Prefix wrapper receives that export in its final script argument, omitted from probe previews; compatibility requires evaluating the script through a shell. Further nested SIP-protected shells get no page-size compatibility claim.

The profile denies sysctl, named socket creation, network operations and descriptor-bearing messages, attested before GO so no payload runs under a partial profile. Inherited bootstrap ports are cleared before exec; `NOSUID` does not strip signed entitlements.

Debug builds with an explicit account root and `ARANY_TEST_GUARD_TRACE` may snapshot Guard stages for fixtures: one record per compiled stage, at most 128 bytes each and 8 KiB<!-- unrelated-bound: debug Guard trace aggregate --> total, each `active`, `complete` or `interrupted`. Capture failures never change outcomes, and records never reach Events, context, telemetry or the development log.

## Shared native capacity and settings

Linux and macOS coordinate Guard capacity across processes and Session roots through the effective user's fixed account root. The owner-only file `guard/limits.json` is created on first native admission with:

```json
{"units":8,"queued":32}
```

Edit it to change capacity, keeping mode `0600` and the private directory. The account root is `~/Library/Application Support/dev.Arany.arany` on macOS and `~/.local/state/arany` on Linux, from the effective user's account, not Session storage. `units` accepts 1–64 and `queued` 1–1024; unknown fields, unsafe files and invalid ranges reject. Every admission rereads it. Lowering a limit kills no admitted unit or waiter; no new admission exceeds it.

Every Guard unit, file-only included, reserves one slot before launch; live, recovering and retained units count. macOS unit storage is directories on the host volume, bounded by the [disk reserve](#macos-enforcement-and-compatibility) rather than reserved sizes. Excess roots from an earlier implementation are kept and block admission. A Linux slot owns its host seed until checked deletion. Each seed holds at most [128 MiB](../limits.md#command_snapshot_bytes) of Workspace data and [96 MiB](../limits.md#max_runtime_bytes) of runtime data, so new retained payload is at most `units × 224 MiB` (1.75 GiB by default): a logical bound, not a filesystem quota.

When capacity is full, the approved Tool stays pending; each Run has at most one. Up to `queued` Tools wait in one shared FIFO under the namespace lock; newcomers cannot overtake. Cancellation, the capacity deadline and process death remove a waiter. The deadline starts at post-approval queue entry, is bounded by the pinned runtime allowance and is a capacity refusal, not a human rejection. Native preparation and GO then have their own deadlines, so a short command timeout is not refused because preparation outlasts it; Linux reaches GO within five seconds of preparation and macOS within its worker bound. Overflow rejects before effects. Waiting renews no intent, approval or budget, is not durable, and restart resumes no permission. The [terminal contract](../terminal/conversation.md#conversation-progress-and-history) owns the queued indication. Native recovery's 30-second<!-- unrelated-bound: macOS native recovery deadline --> deadline runs within the capacity window; filesystem bounds are cooperative, not hard real time.

Coordination records are no-follow, owner-, mode- and ACL-checked, single-link and bounded. Coordination writes no database records or Events; wait hints use the existing callback. `Drop` reaping respects the attempt and deadline budget. Preparation without a committed identity may only remove an empty directory. macOS control roots count against capacity independently of reservations, deduplicated by UUID.

### Linux host seed ownership

Every host seed keeps its reservation from creation until checked deletion; normal completion leaves neither. After controller death, the next admission recovers owned storage before releasing capacity, without replaying the effect. Failed deletion, identity uncertainty and ambiguous launch keep the charge. A new boot settles processes, not file deletion. Recovery resets a positively identified failed unit before retiring it; a missing or unloaded unit cannot settle an interrupted launch, so its reservation can hold capacity until native evidence or a later boot allows recovery. A locked lease owns one seed record and at most one publication temporary. The planned location is committed before exclusive creation and the directory identity before copying. Launch-requested precedes the launcher, and positive termination precedes recursive deletion. Deletion rejects links, mounts, foreign ownership, unsafe permissions and replacements; incomplete cleanup keeps the slot and blocks completion. Normal admission never migrates or deletes unsupported records. Unrecorded historical roots need the [one-time maintenance procedure](../../tools.md#historical-linux-seed-maintenance): Arany stopped, positive native inactivity and authorization of exact inventoried objects, with reboot as the fallback for uncertain inactivity. A name prefix never authorizes removal.

## Linux enforcement and compatibility

Primary Workspace mutations, typed discovery and typed Git allocate no Guard unit or Workspace mount. The non-spawning seccomp filter is used only for non-process rewind handover. [Command input selection](./changesets-and-checkpoints.md#command-input-selection) covers overlay and copy views.

The enforcer requires non-set-ID, root-owned `/usr/bin/bwrap`, `/usr/bin/systemd-run`, `/usr/bin/systemctl` and `/usr/bin/env`, unprivileged user namespaces, a systemd user manager and cgroup v2 with effective memory, swap, PID and CPU limits and owned termination. `systemd-run` must support `--expand-environment=no`. A selected toolchain whose host path overlaps a fixed Guard mount target rejects with Configuration before seed creation. Other init systems need their own enforcing adapter; unsupported architectures or missing enforcement fail closed. No desktop environment is required.

The supervisor executable must be a regular file without set-ID or group/other write bits (a group-writable umask build may need `chmod go-w target/debug/arany`); unsafe modes fail as `ChangedInput` even with unchanged bytes. The controller opens it once, pins device, inode and SHA-256 and holds the handle through teardown. The supervisor runs that object via the controller's `/proc/<pid>/fd/<fd>` with fixed argv, root working directory and cleared environment, and checks itself against the pin. After clearing capabilities it passes only `/proc/self/exe` to bwrap's [read-only data import](https://github.com/containers/bubblewrap/blob/v0.9.0/bubblewrap.c), which copies it to a private owner-executable `/arany` and closes the source before payload execution; the helper re-verifies the digest and attests a unique private read-only nosuid/nodev tmpfs. The image's byte ceiling equals the default Tool memory allowance, debug symbols included. Binding `/proc/self/exe` after namespace entry is invalid, since it keeps the original mount. Path replacement cannot select new code; unsupported proc-fd execution, import or identity checks fail closed without repinning or path fallback. The supervisor `unshare(2)`s user and mount namespaces itself, maps only the invoking UID/GID with setgroups denied and makes propagation recursively private; no external launcher exists. The AppArmor prerequisite below stays required, with no wildcard or proc-path profile.

For primary Commands the supervisor first mounts fresh nosuid/nodev tmpfs outside the input tree, bytes bounded by the project allowance and inodes by the scan bound plus finite per-grant overhead, and probes `user.arany_probe` xattr set, read and remove. Missing namespace authorization reports `NamespaceEntry` and failed mounts, topology or xattrs `RuntimeMounts`, each `ProtectionUnavailable` before GO. Tmpfs user xattrs need Linux 6.6 or a backport, verified by operation. Each admitted lower is pinned, cloned non-recursively with `open_tree`/`move_mount`, remounted read-only and overlaid with `userxattr,redirect_dir=nofollow,metacopy=off` on private tmpfs upper and work directories. Only merged trees and masks reach bwrap as binds, exact files via `--ro-bind`, with narrow parents read-only. Probe objects must survive overlay create, edit, unlink and recreate before GO. Any cloning, overlay or topology failure refuses with no copy or host fallback.

A granted root containing any host submount (a tmpfs `target/`, a bind-mounted vendor tree, a nested devcontainer volume) refuses as `ProtectionUnavailable` before setup; narrowing the grant avoids it, and a root that is itself a mount is a different case. The bounded mount inventory must be complete, even where the kernel would clone locked children.

Granted `PATH` directories, system link targets, Homebrew prefixes and manager roots bind read-only and executable at their host paths, parents first; one under a system runtime entry needs no second mount. Only another selected root may be a descendant mount.

Before forking bwrap or parsing output, the supervisor clears all five capability sets, sets no-new-privileges and verifies the six status fields. It binds a pidfd to the exact bwrap child and reaps it before releasing the namespace. The controller owns bounded reports, READY/GO, cgroup teardown and positive descendant absence before capture. Helper or report death after GO is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) and publishes nothing. After bwrap exits, the capability-free supervisor runs the bounded capture phase within the selection envelope and deadline, validating the upper and launch baseline and emitting an intent- and namespace-bound candidate or a known refusal; anything else is Uncertain. The enforcement digest binds overlay, mask, probe, capability and pidfd enforcement separately from copy selection, including both cache classes and handle handoff.

Both namespace owners parse bounded namespace-local `/proc/self/mountinfo`. The supervisor attests the private tmpfs identity, flags, limits and lack of descendant mounts before building views; overlay attestation checks each read-only lower, the layers and every mask before READY and again before GO. Before Ready and after GO the helper rejects ambiguous roots, stacked or missing runtime mounts (`/usr` and each bound system entry included, each of which must also be read-only), propagation metadata and descendant mounts under a runtime mount, and attests the project tmpfs (copy) or every merged bind, read-only file, mask, narrow-grant parent tmpfs and absence of unexpected submounts (overlay). Later host mounts cannot propagate in. Read-only binds import source submounts recursively, so sources are checked accordingly.

Before releasing a one-use intent the Guard verifies isolated mount, network, PID, user, IPC and UTS namespaces, dropped capabilities, no-new-privileges, inherited syscall filters and effective limits. It owns the exact transient unit, invocation and retained cgroup, including double-fork and setsid descendants, and verifies termination before accepting completion. The seccomp deny profile is defense in depth, not an allowlist. The ARM64 profile builds from source; no ARM64 support is claimed.

Snapshot byte and entry bounds do not guarantee a finite response from stalled storage or an uninterruptible kernel call; deadlines bound ordinary payloads, not kernel failures. File preconditions are not a multi-file transaction and do not exclude hostile host mutation.

### Ubuntu namespace-entry diagnosis

Creating a user namespace does not grant permission to map IDs or mount in it. On Ubuntu 24.04 [AppArmor lets unconfined executables create user namespaces but denies capabilities inside them](https://documentation.ubuntu.com/release-notes/24.04/#unprivileged-user-namespace-restrictions), giving `ProtectionUnavailable` even with the kernel facilities present. A denial alone does not identify AppArmor: compare the stage, profile labels and capability sets. Namespace authorization and tmpfs user-xattr support are separate prerequisites.

Ubuntu 24.04 ships `bwrap-userns-restrict` as an [extra profile](https://gitlab.com/apparmor/apparmor/-/raw/master/profiles/apparmor/profiles/extras/bwrap-userns-restrict), enabled by default since [25.04](https://documentation.ubuntu.com/release-notes/25.04/#apparmor-profile-for-bwrap). With that profile, Arany also needs its pinned supervisor authorized. [CI](../../../.github/workflows/ci.yml) disables the restriction for Linux native lanes, so they do not prove stock-policy compatibility.

When the namespace is denied, guarded commands fail closed as `ProtectionUnavailable` before GO with this diagnosis and the remedy below, rendering the admitted supervisor path as an escaped literal, never a model- or repository-supplied path or a wildcard.

**Preferred one-time administrator step.** Add executable-specific `userns` exceptions for `/usr/bin/bwrap` and the exact installed supervisor path; replace the example `/opt/arany/bin/arany` with the resolved admitted path. Never use a symlink, version wildcard, directory or terminal/shell profile. Review local profiles first and do not overwrite policy or create conflicting attachments. If `aa-status` already lists a profile attached to `/usr/bin/bwrap`, omit `arany_bwrap`; that profile's compatibility with Arany's bwrap invocation is not assumed. [AppArmor denies exec when it cannot choose between attachments](https://manpages.ubuntu.com/manpages/noble/man5/apparmor.d.5.html).

The administrator runs these by hand; Arany never makes policy changes or executes privilege tools, even with a host-command approval.

```sh
sudo tee /etc/apparmor.d/arany-userns >/dev/null <<'PROFILE'
abi <abi/4.0>,

profile arany_bwrap /usr/bin/bwrap flags=(unconfined) {
  userns,
}

profile arany_supervisor /opt/arany/bin/arany flags=(unconfined) {
  userns,
}
PROFILE
sudo chmod 0644 /etc/apparmor.d/arany-userns
sudo apparmor_parser -r /etc/apparmor.d/arany-userns
```

Loading applies without a reboot and persists in `/etc/apparmor.d`. Keep `kernel.apparmor_restrict_unprivileged_userns=1`. Restart Arany from the profiled executable, then retry explicitly. Verify the loaded labels and namespace operations; the profile alone does not establish mount, xattr, overlay or full Guard support. These `flags=(unconfined)` profiles only authorize namespaces for the named executables; Arany still enforces zero payload capabilities, no-new-privileges, seccomp and its grants, and they authorize no host command or wider access.

[Attachments](https://manpages.ubuntu.com/manpages/noble/man5/apparmor.d.5.html) match paths, not digests. If `cargo install`, an upgrade or relocation moves the executable, the new path has no exception until the administrator updates it, and namespace entry fails closed meanwhile. A replacement at the same path keeps the exception, so trust what is installed there. Arany's digest pin rejects a changed binary for an already pinned invocation; restart and readmit before retrying. Do not broaden the attachment to future versions.

**Last resort.** If targeted profiles are unavailable or insufficient, an administrator may by hand choose this temporary system-wide change:

```sh
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

It lifts the restriction for every unconfined application, widening their kernel attack surface, supplies no other missing enforcement and is not profile-enabled evidence. Restore it with `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=1`; it normally resets at reboot unless persisted.

To diagnose from the checkout, in a disposable unprivileged account on stock Ubuntu 24.04, run:

```sh
cargo run --locked --offline -p arany --example namespace_entry_probe
```

The [probe](../../../crates/arany/examples/namespace_entry/probe.rs) runs no command payload. It records kernel, package and profile provenance, labels, UID/GID maps, capability sets and positive teardown; on success it also observes a bounded tmpfs mount, write, read and unmount, capability removal and no-new-privileges across exec. A missing entry snapshot is a startup failure. Timed-out children are killed and reaped; cleanup errors or leftover host mountpoints stop the comparison. The probe has its own path and is not covered by the Arany attachment. Neither a probe nor a sysctl-disabled run shows that the profiled supervisor works under the stock restriction or beside an existing `bwrap-userns-restrict` attachment.
