# Tools: private grants and host commands

## Private grants

Put an owner-only `tools.json` beside the admitted Session database, outside the Workspace: a regular, single-link, current-user-owned `0600` file in a private (`0700`) directory. `--state-dir` selects this Session and configuration root, not your saved account. Permissions are not encryption and do not protect against another process of the same user.

A minimal file-only configuration is:

```json
{
  "workspace_paths": ["src", "Cargo.toml", "Cargo.lock"],
  "write": true,
  "commands": [],
  "skills": [],
  "mcp": []
}
```

Use exact, nonoverlapping relative files or directories. The singleton `["."]` selects the whole project under the same exclusions and bounds; mixing `"."` with other roots rejects. List, search and command working directories accept `"."` or an empty path for the root; mutations require a named relative path. Absolute paths, traversal, links, mount crossings and special files are refused. StateRoot and the fixed account root must not overlap the Workspace or configured runtime resources. `.git`, `.env`/`.env.*`, `.aws`, `.ssh`, `.gnupg`, `.npmrc` and `.pypirc` path components are excluded; repository history is reachable only through [typed Git reads](./git.md#typed-git-reads). This is not a secret detector: review the files you select, because Tool observations can reach the selected Provider and the private, unencrypted journal.

The Linux profile keeps its private root and exposes the system runtime read-only at the host paths: `/usr`; `/bin`, `/sbin`, `/lib`, `/lib32`, `/lib64` and `/libx32`; and `/etc/alternatives`, `/etc/ssl`, `/etc/pki`, `/etc/ca-certificates` and `/etc/ld.so.cache`. Merged-`/usr` links such as `/lib -> usr/lib` keep working, and Debian alternatives such as `/usr/bin/cc` resolve when root-owned and not group- or world-writable, while other `/etc` names stay absent. Workspace, StateRoot and account roots must not overlap any of them. No home, unselected cache or other host path is visible.

Without a [network grant](./commands-and-cache.md#network-grants-and-egress-proxy), commands get no network and cannot create, connect to or listen on named Unix sockets. Anonymous pipes and socket pairs stay usable, except that macOS denies writes to socket pairs; passing descriptors with `sendmsg`/`sendmmsg` is unsupported.

The JSON schema is a closed [strict record](../execution/persistence.md#incompatible-records); the six listed top-level fields are required. Optional fields: `network` is the [egress grant](./commands-and-cache.md#network-grants-and-egress-proxy); an `mcp` entry may be a Linux-only [remote server](./skills-and-mcp.md#remote-mcp-and-oauth); `web_search` `{endpoint, key}` declares the [search backend](./commands-and-cache.md#web-fetch-and-web-search); `git` is replaced at admission by the Git each Run resolves from `PATH` ([typed Git reads](./git.md#typed-git-reads)); `child_unguarded` accepts only `denied`; the Run derives the child host grant from its [Guard mode](#guard-mode-and-extra-reads). Unknown and duplicate fields reject. There is no interpolation, automatic installation or hidden executable lookup. Project Skill discovery stays within the selected Workspace roots. Configuration is pinned for a Run; editing it does not cancel an admitted Run, and changed pinned executable or resource contents reject dispatch.

### Guard mode and extra reads

The user-owned, strict `guard.json` record in the fixed account root, shared by every trusted folder and never written by repository content, holds the Guard mode and the user's extra read folders: `{"mode": "auto" | "required" | "off", "reads": [{"path", "device", "inode"}]}`. It is at most 16 KiB<!-- unrelated-bound: guard settings record cap --> with at most [`MAX_SAVED_READ_GRANTS`](../limits.md#max_saved_read_grants) folders. A refused record is [archived](../execution/persistence.md#incompatible-records) with a notice, and the defaults apply until `/settings` saves one. `/settings` → Guard changes the mode and Guard folders lists and removes saved folders, both from the next Run.

**Mode.** Each Run pins the mode and whether the sandbox was available in `RunStarted.tool_policy.guard`, so a Run never switches mid-way and a guarded dispatch that later finds no sandbox refuses.

- `auto` (default) uses the sandbox when available; without one (no Bubblewrap or user namespaces, an unsupported platform), commands run on the host under approval.
- `required` refuses commands without a sandbox while Arany keeps running; the primary's explicit [`command_unguarded`](#primary-host-commands) escalation stays.
- `off` always runs commands on the host under approval.

Without a sandbox in `auto` or `off`, the catalog offers `command_unguarded` instead of guarded commands, Skill scripts, MCP and web Tools, while in-process file Tools and editors stay, and editors run [host commands per call](./editors.md#editor-tool-steps). Every such command needs a human approval at that moment, a remembered host prefix or, in Auto approval, the AI review, and is marked host, non-rewindable and never retried. The status line and every host approval show `sandbox off: commands run on your machine`. Non-interactive surfaces run on the host only what a remembered prefix covers and refuse everything else.

**Extra reads.** A guarded `command` may carry `additional_reads: {paths, justification}`: up to [`MAX_ADDITIONAL_READS_PER_CALL`](../limits.md#max_additional_reads_per_call) absolute, canonical host directories to read and execute, never write, with a reason of at most 512 bytes<!-- unrelated-bound: command justification bytes -->. A directory is refused when it is not a directory, has a protected path component (`.git`, `.env*`, `.aws`, `.ssh`, `.gnupg`, `.npmrc`, `.pypirc`), overlaps the Workspace, the StateRoot or the account root (so `/`, the home directory and their ancestors refuse), or collides with a fixed Linux Guard mount. Other Workspace exclusions do not apply inside an admitted directory, and a Linux directory with a submount refuses.

<a id="protected-names-beneath-read-folders"></a>**Protected names in approved folders.** An approved read folder, saved or once, hides entries whose name is protected (`.git`, `.env`, `.env.*`, `.aws`, `.ssh`, `.gnupg`, `.npmrc`, `.pypirc`, compared case-insensitively), because approving a folder must not disclose the credentials it holds; a link to a hidden path is refused too. On macOS protected names are hidden at any depth. On Linux only the folder's first level is hidden, as read when the command spawns (at most [`MAX_READ_FOLDER_ENTRIES`](../limits.md#max_read_folder_entries) entries): deeper protected names, and protected entries created while the command runs, stay visible. A Linux folder over that bound, or whose first level holds a protected-named link, is withheld from that command and listed in the command result's `hidden_grants`. `PATH` directories, system link targets and manager shims hide nothing; their own path check applies.

A directory the saved list or an earlier human approval in this Run already allows needs no question. A new one always asks a human, whatever the mode or rules, and never AI review. The attached terminal offers `Yes`, `Yes, and always allow these folders in every trusted folder` and `No`; serve and ACP offer once or no. Once lasts for the rest of the Run, and children reuse it and the saved list but cannot ask for new ones. Always also appends the folders to `guard.json` after the human verdict commits; a failed save dispatches nothing, and the list applies from the next Run. Without a human channel a new directory refuses. Each command's directories are pinned by device and inode; replay requires every new directory to have an approving human verdict in its Run and never asks again.

## Enforcement failure causes

`ToolFinished` and `HookFinished` record an optional closed `enforcement_cause`, separate from the disposition and untrusted output:

- `filesystem_denied`: the file boundary or command capture refused a protected path component or set-ID entry, including in ignored outputs; the disposition is `denied`.
- `guard_bootstrap`: the Guard failed to start the sandbox before dispatch; the disposition is `failed`. In-process file effects never carry it.

A `guard_bootstrap` failure is known not to have dispatched, so the next model request may receive it; it grants no authority and retries nothing. After dispatch begins, a missing completion stays [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). Resource limits, cancellation, uncertainty and successes never carry a cause, and unsupported Git layouts, path validation, non-regular or multiply linked files, changeset type conversions and opaque filesystem errors stay unclassified. Classification changes no grant or approval.

The cause carries no path, filename, contents or native diagnostic text. When a cause exists, the model result and Tool summary add one diagnostic: `Guard enforcement: protected path or set-ID entry refused`, or `Guard enforcement: bootstrap failed before dispatch`. Other results keep their projection. JSONL and strict replay keep the typed field under the [current payload versions](../execution/admission-and-recovery.md#admission-persistence-and-recovery).

Only these two are attributed. Sandbox denials a program sees as errno (such as `EPERM`), stderr, exit status, signals, blocked sockets or system sandbox reports never establish Guard causation, because hostile output must never attest enforcement. `null` means no attributable cause, not proof that enforcement was uninvolved; no network or process cause is claimed. This applies to commands, Skill scripts and local MCP servers, whose `isError`, cause fields and text stay program data.

## Primary host commands

`command` stays guarded. The primary may request `command_unguarded` with a bounded justification at any time, including after a Guard failure, and it is the only command Tool when the [Guard mode](#guard-mode-and-extra-reads) has no sandbox. The request keeps approval, journal-first execution and primary-only authority, is never an approval-free fallback from the Guard and is never retried. Host requests stay available when missing protection removes guarded commands from the catalog. Children, workers and hook outputs never receive host authority or inherit host approvals; a failed hook produces no host proposal ([hook execution](./hooks.md#hook-execution)).

Repository content, model text, hooks, Tool output, MCP metadata or output, Skill text, child reports and ACP client policy never authorize host execution; only a human approval, an admitted user-owned rule or, in Auto approval, the AI review does. Approval does not make the process trustworthy or isolated.

**Admission.** Program, explicit argv and Workspace-relative cwd form a fresh immutable intent; absolute targets belong in argv, and cwd must lie beneath the Workspace without links. Programs resolve only through absolute PATH entries outside the Workspace, and an absolute program must be the same executable that lookup finds. The executable, its digest, the Workspace, environment policy and permission snapshot are pinned before approval and rechecked before dispatch. Native executables have the [32 MiB](../limits.md#max_snapshot_bytes) program bound; scripts require an explicitly pinned interpreter. The closed interpreter-name set is `awk`, `gawk`, `mawk`, `nawk`, `sed`, `sh`, `bash`, `dash`, `zsh`, `ksh`, `mksh`, `fish`, `csh`, `tcsh`, `python`, `python2`, `python3`, `pypy`, `pypy3`, `node`, `nodejs`, `deno`, `bun`, `perl`, `ruby`, `php`, `lua`, `luajit`, `tclsh`, `wish`, `pwsh` and `powershell`, plus the BusyBox and ToyBox launchers. A requested or resolved interpreter needs a matching `tools.json` command marked `interpreter: true`; otherwise admission refuses with a distinct interpreter error. Wrapper arguments that name or resolve to an interpreter need their own matching pin. Versioned interpreters are identified only by explicit declarations, never a numeric suffix. Guard-only paths and variables are refused.

**Privilege tools.** The closed first-token policy prohibits `sudo`, `sudoedit`, `doas`, `su`, `pkexec`, `run0`, `runuser`, `chroot`, `systemd-run`, `machinectl`, `pfexec`, `ksu`, `dzdo` and `authopen`, by requested and resolved basename. `osascript` is refused when any argument contains “with administrator privileges” (ASCII case-insensitive). The closed wrapper/launcher set is `env`, `xargs`, `find`, `nice`, `ionice`, `timeout`, `nohup`, `setsid`, `time`, `busybox`, `toybox`, `stdbuf`, `chrt`, `taskset`, `flock`, `command`, `exec`, `strace`, `ltrace`, `nsenter`, `unshare`, `setpriv`, `script`, `watch`, `eatmydata`, `runcon`, `capsh`, `firejail` and `bwrap`. Wrapper argv naming a privilege tool refuses, including nested launchers. `env -S` and `--split-string` refuse outright. Path-like wrapper arguments and option values that resolve to a privilege tool also refuse. Shell, interpreter and wrapper argv, and any executable's inline options (`-c`, `-e`, `-Command`, `--eval`, `--execute` and similar), are split on whitespace, quotes and shell metacharacters (`;`, `&`, `|`, parentheses, backticks, `$`, redirection and `=`), and any privilege-tool token refuses, deliberately including quoted data. This lexical scan is not a security boundary: inline programs beyond it, file scripts, obfuscation and configuration stay uninspected.

Refusal precedes any approval offer and is rechecked before dispatch; no mode, reply, rule, scope or cached grant overrides it. The durable result says “Arany cannot run privilege-escalation commands. Please run this command by hand:” with the exact argv and Workspace-relative cwd as bounded JSON-quoted data. The primary must explicitly ask the user to run it and must never evade refusal through wrappers, shells or children.

**Authority.** Attached human choices are `Yes` (once), `Yes, for this session` (the identical command in this live Session), `Yes, and allow this host prefix in this folder from the next Run` (an eligible proposal) and `No`. Session reuse journals a new verdict referencing the earlier human approval and requires the same executable and digest, argv, cwd and Workspace, environment policy and settings, with no greater limits. At most 128 session grants are reusable per live attachment; `Yes` stays available when full. Rule-based asks, hook restrictions and literal StateRoot/account-root targets offer once only. Resume, restart, reconnect, fork, opening rewind and `/permissions` end reuse. Failed permission readmission denies host authority until a successful explicit readmission; the attached session shows a recoverable notice and keeps an already saved folder-trust change. Replay validates only the recorded settings mode and verdict.

Explicit ask/deny and hooks only narrow. Generic host commands count as mutating and are refused in plan mode; `default` and `dontAsk` may reuse eligible session grants. Remembered host prefixes apply in every mode but `plan`; otherwise `auto` reviews the command and `acceptEdits` and `default` ask a human. Exec and ACP use only [remembered host prefixes](#remembered-host-prefixes). Without a human channel, a generic host command runs only under an eligible remembered rule; any other request refuses immediately with a durable explanation. No human-attestation protocol or bypass mode exists. Serve offers once and negotiated exact-session scope only; unsupported scopes refuse rather than downgrade to once. Typed push and PR create always need a fresh human; typed PR reads keep their own [typed-rule authority](./git.md#human-approved-host-git). An approved generic host command can still perform Git and remote effects; typed-operation guarantees cover only typed operations.

**Legacy rules file.** An inactive `unguarded-commands.json` is archived byte-for-byte to `archive/inactive-host-commands/unguarded-commands.json`, with a bounded notice naming the archive and requiring fresh authority. Private-file admission and size bounds apply even to malformed contents. An unconfirmed archive stays blocked across reopen, without retry or automatic completion, and a recreated source beside an archive is a conflict that is never overwritten or deleted; each has a distinct admission error naming the directory. Recovery is manual: stop Arany, keep source and archive intact, and restore a verified backup or get operator help; never remove a pending marker or overwrite a conflicting copy. No entry becomes authority.

**Review and disclosure.** Review shows the pinned program, every argument, the real cwd and the model justification as escaped data. The prompt says that inline programs are opaque beyond the lexical privilege-tool check, file scripts and obfuscation are uninspected, and children have no controlling terminal for privilege prompts. It warns that the process runs as the user with file and network access, can execute repository configuration, modify Arany permissions, Store and journal, and disclose private data to the Provider. Lexical `.env`/`.env.*`, `.ssh`, `.aws`, `.gnupg`, StateRoot and account-root paths add a warning. Rule-matched or cached non-human dispatch refuses argv that lexically names the StateRoot or account root, including embedded absolute paths and relative tokens normalized against cwd; this check misses computed paths and aliases and is not an isolation boundary.

Live permission settings are compared with the admitted digest before any approval offer and before dispatch. Out-of-band changes refuse with a settings-change explanation until human readmission through `/permissions`; drift during an approval still refuses dispatch. Saving a human-approved typed Git rule advances the settings pin only to the exact bytes written from the expected prior digest and never clears an existing settings-change lockout; later host requests in that Run refuse before offering approval. Pins are admission evidence, not execution isolation: a same-user process can replace an executable, cwd or wrapper target between the check and its use. Host writes are never approvals, but same-user tampering with Arany's state or journal is neither prevented nor reliably detectable.

**Execution.** Intent, verdict, scope and dispatch authority commit before spawn, under the Goal's action-time reservation and the Workspace writer lease. The command gets explicit argv, empty stdin and a cleared allowlisted environment: the pinned command environment record's `PATH` and selected names (a core set by default; names matching `*KEY*`, `*SECRET*` or `*TOKEN*` are never selectable), real HOME and TMPDIR, NO_COLOR, ARANY_TOOL_WORKSPACE and ARANY_UNGUARDED. It has no controlling terminal or terminal-scoped privilege ticket. The finite command timeout, rendered output bound and 1 GiB<!-- unrelated-bound: command output kill ceiling --> per-stream kill ceiling apply. Timeout or output overflow with confirmed teardown is Limit, confirmed cancellation is Cancelled, and a known nonzero exit is Failed. Lost acknowledgement or unconfirmed termination is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). Deliberately detached descendants escape supervision, and nothing confines host filesystem, network, CPU or memory.

**Login-shell capture.** The command environment record comes from the process environment or, on an explicit `/permissions` Capture from login shell or Re-capture action, from the user's login shell. Each capture needs fresh human approval of the pinned executable and home directory. The shell comes from `getpwuid_r`, never `$SHELL`, and must be `zsh`, `bash` or `sh`. It runs once on the host, never in the Guard or from model text, as `-lc 'env -0'` with cwd `$HOME`, the pinned record as initial environment, the [capture runtime bound](../limits.md#login_shell_capture_timeout_ms) and a [capture output cap](../limits.md#login_shell_capture_output_bytes) on combined output. Only selected non-secret names and PATH replace the private record; shell identity and source are shown with values hidden. Captures are journaled as host operations, but captured values never enter Events. Non-zero exit, confirmed timeout or overflow, malformed output and pin drift leave the record unchanged, and a concurrent edit refuses the replacement. An unknown process or save outcome is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes); an interrupted capture is reported unknown after reopen. Re-capture is a new human action, never recovery. Startup reports when the PATH a process capture would pin differs from the record, ignoring entries capture drops, such as relative ones. Login files run with the user's authority.

**Receipts and recovery.** Host commands produce only an UnguardedReceipt, never a Guard receipt, changeset or cache publication, and are excluded from automatic rewind. Approval without a terminal outcome is a possible non-rewindable effect, and recovery never redispatches it. Host dispatch invalidates earlier file-success and worker-verification evidence. Every projection marks host effects, keeps partial output and claims no complete inventory, rollback or rewind. Replay validates committed authority, references and bounds without reading settings or executing anything. [Execution](../execution/admission-and-recovery.md#admission-persistence-and-recovery) owns stored formats and [Session](../session.md#rewind-planning-and-replay) owns rewind.

### Remembered host prefixes

The optional `command_unguarded.prefix_rule` is a literal argv token prefix including the executable spelling. A model proposal needs at least two tokens and must prefix the actual request. Absent or null, the Engine proposes the first two argv tokens, unless the program is a shell, interpreter, wrapper or launcher (the policy below, plus `osascript` and every `python*` spelling), which offers only the exact command. Only attached human approval and idle `/permissions` create rules; serve, ACP, exec, children and hooks cannot. The prompt shows the complete escaped token sequence and warns that every eligible suffix becomes authorized host behavior. Saving approves the pending action once; the rule applies from the next Run.

Private `permissions.hostPrefixes` is separate from `typedPrefixes`. Each closed record binds the literal prefix, an allow/ask/deny decision, the exact relative cwd, Workspace path/device/inode, resolved executable path/device/inode/digest and PATH/environment-policy identity. The list is empty by default and shares the [permission settings bounds](./git.md#typed-prefix-rules). Inserting a rule also caps the compact JSON host-prefix array at 32 KiB<!-- unrelated-bound: host prefix array cap -->; overflow returns Invalid without replacing settings or dispatching the pending command, while larger existing lists stay editable. Malformed or duplicate records and overflow reject the list as a whole. Legacy exact rules are archived, never converted.

Cannot be remembered: every privilege tool, wrapper/launcher and interpreter from the policy above, and generic `git`, `gh` and `rm`, by requested and resolved basename. A declared interpreter or typed Git/gh pin also excludes matching resolved paths, identities or digests, including renamed or versioned copies. Interpreter/script forms, inline program options, heredocs, here-strings and tokens with shell control syntax cannot be remembered. These checks run at creation, settings admission and dispatch. A saved rule that conflicts with a declared pin refuses Tool admission with an error naming its one-based entry and pointing to `/permissions` → Host command rules; the settings stay editable without admitting it. This closed policy is not executable classification or confinement: unknown programs may run other programs.

Matching is exact literal argv-prefix matching, with no globbing, shell splitting, substitution, alias matching or wrapper stripping. Deny/ask rules, hooks, grants, budgets, cancellation and plan still narrow. Prefixes apply before any review: an eligible allow records `host_prefix_rule` and dispatches without a prompt or model call, also from serve, ACP and exec. A rule never applies to a typed Git operation. The approval offers it as `Always allow <prefix> …`. Non-human dispatch refuses lexical StateRoot/account-root targets; a fresh human may approve an otherwise eligible action.

Saving replaces the settings file atomically after full validation, refusing if it changed since it was read; a missing file may be created, with a warning that this activates policy for other Tools too. The human save verdict, including the proposed record, commits before saving. A failed save dispatches nothing; an unconfirmed replacement is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). The new rule gives no current-Run authority, and the Run's own save is not settings drift. Revocation applies from the next Run; cancellation withdraws pending authority at once. Replay requires a used rule to be in the Run's pinned settings with no matching deny/ask record, and never reads current settings.

`/permissions` lists, changes and removes host decisions. It can derive a prefix from a recent eligible command in the conversation after revalidating its executable and Workspace pins. Only this editor may choose a single executable token, with a warning that every eligible argument is covered. There is no user-wide host scope.
