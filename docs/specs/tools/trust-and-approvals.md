# Tools: authority, trust and approvals

## Authority and effect admission

A submission carries `ToolGrant` access: none, the admitted private `tools.json` configuration, or the trusted Workspace grant. Each mutation, process, Skill script and MCP call is admitted as an immutable typed intent (actor, Run, Tool, resources, operations, destinations, descendant behavior, use count and finite action limits) under deterministic restrict-only Policy; approval, journal and Guard bind the same intent. Programs run in the Guard; [in-process file operations](./file-operations.md#in-process-file-operations) publish under the same admitted capability. Names, prefixes, hostnames, remembered approvals and summaries never define authority, and hooks, prompts, command regexes, classifiers and approval UI are not enforcement boundaries. Primary and child effects pass the same Policy. [Provider egress](../provider/routing-and-usage.md#configuration-and-egress) has its own admission; [execution](../execution/collaboration.md#collaboration) owns child grants, and [refusal causes and feedback](../execution/events-and-outcomes.md#accepted-outcomes) for intents that fail validation. Validation before a proposal grants no authority.

Effective capabilities must equal or narrow the authorized set. Unsupported enforcement dimensions, missing capabilities, failed attestation, and authentication, authorization, signature, policy or schema failures reject. Descendants keep or lose authority. There is no approval-free unsandboxed fallback: only [Guard mode](./host-commands.md#guard-mode-and-extra-reads) `auto` without a sandbox or `off` routes commands to approved host execution. Arany never follows or executes a filesystem object created by an agent or sandbox without fresh no-follow validation. A process starts from a pinned executable without PATH search, with validated arguments, a pinned working directory, a cleared allowlisted environment and no inherited descriptors or sockets; scripts need an admitted interpreter. Cancellation and cleanup follow the native profiles and the [failure contract](./limits-and-failures.md#limits-and-failure-behavior).

## Folder trust and approvals

Every attached startup, new, resumed or forked, asks whether to trust the opened folder, even with no account configured, unless that exact folder has remembered trust. Consent precedes saved-account lookup, catalog or credential access and Session discovery or creation. The flow is the same on every OS and independent of Provider flags or `--tools`; `/permissions` revisits it.

The consent screen shows the full folder path and vertical Read only / Trust choices, Read only focused. With explicit `--tools`, the first choice reads Use explicit config and keeps that private configuration when trust is skipped; neither choice expands roots or capabilities. The screen proposes metadata-only runtime and cache selections; toggling one switches to Trust. Discovery runs on initial consent or when `/permissions` opens; a discovery failure shows a notice without aborting startup. Remembered startup revalidates only saved pins. Enter confirms, Escape dismisses without a decision and Ctrl+C exits without saving. `/permissions` first asks whether to manage folder trust or [typed Git rules](./git.md#typed-prefix-rules); folder trust rediscovers candidates, keeps exact pins and permits explicit changes. Checking a toolchain unchecks other selections of its runtime kind; linear `trust` with two of one kind asks again, and `trust N` and `use config` also work. A selection that cannot be saved reports an error and keeps the previous permissions, so startup continues read only. Consent warns that prior versions of files changed by Arany are saved unencrypted in private StateRoot storage.

Read only, explicit configuration without trust, or dismissal remembers nothing. Unavailable, malformed or unsafe trust metadata stops startup before account or Session access with a message naming the record and the failed check. A `workspace-permissions.json` its strict decoder refuses is [archived intact at startup](../execution/persistence.md#incompatible-records), so every folder asks for trust again; a non-private record or state directory offers Retry or Exit and is never archived or modified. Trust is user-owned, shared by conversations, and pinned to the exact absolute path, device and inode in private OS-user state, never in Session facts; a replaced directory needs trust again, and replay never supplies authority. Remembered grants apply only to native Providers on platforms that admit Tools; custom Providers stay read-only. Explicit private `--tools` configuration takes precedence over remembered trust and keeps its narrower roots and capabilities.

The private `workspace-permissions.json` in the fixed OS-user account root holds at most 128 entries and 64 KiB<!-- unrelated-bound: workspace trust record cap --> and is replaced atomically, owner-only. Trust generates a Tool grant for `workspace_paths: ["."]`, typed writes, discovered project Skills and a pinned resolved system `sh`; each Run resolves Git from `PATH` ([typed Git reads](./git.md#typed-git-reads)), and the entry keeps the folder's [Git hooks](./git.md#git-hooks) answer. Optional runtime selections bind exact path, profile kind and directory device/inode to the folder entry. MCP needs explicit private configuration. Standard secret, link and mount exclusions and finite snapshots apply; root discovery and snapshots omit `target`, `node_modules`, `.venv` and `venv`. Commands use the offline Guard, never the host terminal, the whole home directory, package-manager configuration or credentials.

Discovery reads bounded directory entries and executable metadata under `~/.rustup/toolchains`, the per-version Node roots of nvm, fnm, Volta and asdf, and `~/.pyenv/versions`, never executing a candidate, reading manager or project configuration or changing State; invalid or unsafe existing state reports discovery failure. Candidates need a numeric `major.minor.patch` directory label, the manager's directory name rather than a verified binary version; aliases such as `stable` and `nightly` are excluded. Python candidates need a version-specific regular executable, or a `python`/`python3` alias to one in the same `bin`; other symlinks reject. Without an exact saved pin, consent proposes the newest numeric Rust, Node and Python, breaking ties by display order; saved pins, even stale ones, win. A saved toolchain grant for a recreated root is a new candidate.

**PATH directories.** Each Run grants, without a question, every directory of the pinned command environment's `PATH`, read-only and executable, in `PATH` order, wherever it lies (home directory, `/opt`, a Homebrew prefix, a system path), counted once at its first position. Only the first [`MAX_DISCOVERY_PATH_ENTRIES`](../limits.md#max_discovery_path_entries) distinct entries count; startup reports the rest as left out. A `PATH` over 16 KiB<!-- unrelated-bound: user program discovery PATH cap --> refuses. An entry is skipped when it has a protected path component (`.git`, `.env*`, `.aws`, `.ssh`, `.gnupg`, `.npmrc`, `.pypirc`), overlaps the Workspace, the StateRoot or the account root, collides with a fixed Linux Guard mount, cannot be opened as a directory without following links, or on macOS lies under a platform root (`/System`, `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/libexec`, `/Library/Apple`), whose binaries can carry entitlements: there only `/bin` and `/usr/bin` programs run, each through the per-program unentitled [system catalogue](./native-guard.md#macos-enforcement-and-compatibility). Contents are not reviewed: a directory runs whatever it holds, and a user-writable Homebrew prefix is granted whole, with protected names beneath it hidden. For a Homebrew-prefix entry, the whole prefix is readable for its libraries. Only the `PATH` directories are granted, never the home directory.

**System link targets.** A program in a granted `PATH` directory, `/usr/bin` or `/bin` that links to an executable regular file outside every grant and runtime root brings that file's directory along, read-only and executable but not on `PATH`, when the directory is at least two levels deep, it and every ancestor are root-owned and not group- or world-writable, it is outside `$HOME`, `/home`, `/Users`, `/root` and `/private/var/root`, and it passes the checks above; examples are `/usr/local/bin/node -> /opt/node/bin/node` and Debian alternatives into `/opt`. Links resolve once per Run in sorted name order, scanning at most [`MAX_LINK_SCAN_ENTRIES`](../limits.md#max_link_scan_entries) directory entries and granting at most [`MAX_LINK_TARGET_GRANTS`](../limits.md#max_link_target_grants) directories; later targets stay ungranted. Only that directory is granted: a link into a package tree, such as npm's `lib/node_modules/npm/bin`, still lacks its sibling files.

**Manager shims.** Version-manager shim directories come from a closed table with their manager root and home variable. Consent proposes them, metadata only, in environment order; saved selections keep their saved order. For Homebrew's `opt/rustup/bin`, whose bash wrappers lose the [page-size interposer](./native-guard.md#macos-enforcement-and-compatibility), Arany pins rustup's `libexec/bin` instead and sets the `RUSTUP_OVERRIDE_UNIX_FALLBACK_SETTINGS` the wrappers export when `<prefix>/etc/rustup/settings.toml` exists. A manager root is pinned with its shim directory; a replaced or missing root rejects. Several managers may be selected, deduplicated by path and device/inode. A `workspace-permissions.json` that saves `PATH` directories as selections is refused and [archived](../execution/persistence.md#incompatible-records), so the folder asks for trust again.

Selected roots mount read-only. `PATH` is their `bin`, then selected shim directories, then the granted `PATH` directories, then the fixed system path `/usr/bin:/bin`; a selected manager root sets only its manager's home variable. Label, path and device/inode bind each selection, and drift rejects before dispatch. A saved root that no longer verifies stays pinned: commands and MCP reject with `ChangedInput`, while file and Skill Tools keep working. A runtime, user-program or cache grant overlapping the Workspace, the StateRoot or a fixed Guard runtime root rejects. Profile numbers use kind order (Rust, Node, Python, Cargo archive/source/index caches, npm cache, pip HTTP/wheel caches, Apple compiler, Apple SDK), then descending lexicographic version label, then ascending absolute path and token. Saved selections match by token, never by display position.

On macOS, Rust also proposes the Command Line Tools compiler and the newest numeric physical SDK, keeping exact saved pins. The compiler profile is `/Library/Developer/CommandLineTools/usr`; it requires root-owned, non-writable directories, a root-owned `cc` link to `clang`, and root-owned, single-link, non-set-ID, unentitled `clang` and `ld`, and an entitlement that cannot be verified makes the Guard refuse the grant with `ProtectionUnavailable`. Only `cc`, `clang` and `ld` may execute. SDK profiles are exact physical `MacOSX<version>.sdk` directories under `/Library/Developer/CommandLineTools/SDKs` whose version has two or three canonical numeric components, each 0–65535 with a nonzero major, and a total length at most 32 bytes; the SDK must be root-owned and not group/world-writable. Each is pinned like a runtime, deselectable and counts toward the [selected runtime grant ceiling](./limits-and-failures.md#limits-and-failure-behavior).

Optional host caches are separate read-only grants: Cargo's exact `registry/cache`, `registry/src` and `registry/index`; npm's exact `_cacache`; pip's exact `http-v2` or `wheels` under `~/.cache/pip` (Linux) or `~/Library/Caches/pip` (macOS). Existing caches are proposed only with their runtime, only human Trust saves them, and no parent cache mounts. Consent warns that caches may disclose private package names, source, registry metadata or credential URLs, which commands and MCP can emit into journaled output that later Provider requests carry; Arany never auto-loads them. Configuration, credential files, environment values and parent directories stay unavailable. A selected read-only host cache replaces the private cache at that path for the Run; disabling the opt-in restores the private writable view. Cache data supplies no authority.

Shift+Tab cycles **Auto edits → Request approvals → Auto approval → Auto edits**, keeping the draft and caret. The mode shows beside the composer and follows the selected Provider's native capability; selecting a supported native Provider after trusting an unconfigured conversation restores the remembered mode. What each mode asks, and the AI review, follow [Modes and approval decisions](./permissions.md#modes-and-approval-decisions). <a id="auto-approved-workspace-edits"></a>A typed file edit (write, edit, multiedit, delete, move, mkdir) or a command or editor changeset publication inside the Workspace runs with no review and verdict source `mode`, after deny and ask rules, hooks and plan, unless a written path is protected; a protected-path write goes to the review unless a user allow rule approves it. Protected paths are the configuration and instruction paths agents and tools read: the directories `.git`, `.config/git`, `.vscode`, `.idea`, `.husky`, `.cargo`, `.devcontainer`, `.yarn`, `.mvn` and `.claude`, plus the `.agents` directory, at any depth; and the files `.gitconfig`, `.gitmodules`, shell startup files (`.bashrc`, `.bash_profile`, `.bash_login`, `.bash_aliases`, `.bash_logout`, `.zshrc`, `.zprofile`, `.zshenv`, `.zlogin`, `.zlogout`, `.profile`, `.envrc`), package-manager and build configuration (`.npmrc`, `.yarnrc`, `.yarnrc.yml`, `.pnp.cjs`, `.pnp.loader.mjs`, `.pnpmfile.cjs`, `bunfig.toml`, `.bunfig.toml`, `.bazelrc`, `.bazelversion`, `.bazeliskrc`, `gradle-wrapper.properties`, `maven-wrapper.properties`), hook and tool configuration (`.pre-commit-config.yaml`, `lefthook.yml`, `lefthook.yaml`, `.lefthook.yml`, `.lefthook.yaml`, `.devcontainer.json`, `.ripgreprc`, `pyrightconfig.json`, `.mcp.json`, `.claude.json`) and the instruction files `AGENTS.md`, `AGENTS.override.md` and `CLAUDE.md`. 
A human approval shows the exact proposed action, and every page must be reviewed before accepting; [terminal approval](../terminal/commands.md#interactive-commands-and-completion) owns layout, focus, labels and linear replies. Approval is one-use and never expands the grant. Primary ordinary, hook Ask and unguarded prompts have no wall-clock expiry while their human channel and Run are live. Escape and Ctrl+C cancel the Run; explicit No declines the proposal. Pause, cancellation and channel or turn shutdown withdraw pending work. Losing a delegated Ask's approval channel cancels the Run. A missing, invalid or undelivered reply while the Run is live records unavailable approval, never human decline. A late allow still revalidates the target, any explicit file-content precondition, executable bytes, grants and worker revision before dispatch and refreshes no pin. Permission settings stay the Run snapshot: editing the rules file during a wait affects later admission, not the pending decision.

A child Ask stays pending while its human channel and Run are live. Its delegation and Goal active-time allowance pause during an idle human wait but keep running during sibling work; exhaustion withdraws the ask with the delegation or Goal cause, never as human decline, and cancellation and pause win over an accept. The non-dispatched observation stores `approval_cause` as `cancelled`, `paused`, `channel_unavailable`, `declined` or, on older observations only, `child_timeout`; active-time withdrawal uses the typed limit and Run stop causes, and other observations carry `null`. Replay never restores a live request. The shared [denial delivery rules](./permissions.md#permission-modes-rules-and-hooks) apply. Cancellation, pause, hook stop, [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) effects and exhausted or unavailable continuation still stop; completed effects are not rolled back.

AI reviews have a 20-second ceiling, a 256-token output cap, no Tools, project instructions, history or includes, and canonical Provider-call usage. A review sees only the user's own prompts in this Session (accepted messages and steering notes, newest kept within 32 KiB<!-- unrelated-bound: AI review user prompt cap -->, older ones replaced by one marker) and the exact action, without the model's justification or proposed prefix, and decides whether the action is within what the user asked for. It never sees model text, Tool output, repository content, hook output, plans, Goal facts or child reports; children are reviewed against the same prompts, never their model-written objective. Reviews share the primary call budget while preserving final continuation, review text never becomes an assistant answer, and each review belongs to exactly one pending Tool. Headless `--tools` uses its explicit private upfront grant without an interactive approval channel.

Workspace paths resolve beneath the pinned Workspace without following links; symlinks, special files, absolute paths, empty components, `.` and `..` reject.
