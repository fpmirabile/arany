# Tools: agent definitions and editors

## Agent definition parser admission

[Execution](../execution/collaboration.md#agent-definitions) owns discovery, format, precedence and selection. Snapshot capture uses opened directory capabilities, no-follow same-device resolution, current ownership, regular single-link non-set-ID files and bounded reads. Protected names reject before opening, and replacement during capture rejects; later replacement cannot change pinned bytes. Private StateRoot agent files also need private permissions and ACL admission against the held StateRoot identity. No repository Git, shell, configuration script or agent body executes.

YAML parsing runs only in the killable native Guard, after an internal `parse_agent_definition` ToolStarted and the one-use Ready/GO exchange. Its intent names an ordered snapshot index and exact raw digest, not a model path. The task carries only that raw snapshot as canonical base64 within the Guard task bound (1 MiB<!-- unrelated-bound: Guard task frame payload --> plus room for one base64 definition file, so the full pinned config always fits); native admission checks length and digest before Ready. The bounded YAML visitor refuses anchor, alias and tag tokens (quote literal token punctuation in scalar guidance). The normalized-v1 record returns through ordinary bounded ToolFinished and attestation. Model schemas and generic script APIs cannot invoke the parser, and there is no host YAML fallback.

A selected definition's mode can require a verdict even without a parent permission-settings file. `ToolStarted.verdict.mode` names the parent settings mode when present, otherwise the definition mode; replay checks the definition restriction independently. A definition Ask needs a human or recorded AI review and cannot approve itself.

Parsing uses ordinary primary Tool admission, capacity, approval-wait accounting, deadline, cancellation, cleanup and terminal-tail reservation, one pending Tool at a time, and spends no model request. An invalid definition file is a successful parse with a skip diagnostic. Guard failure, malformed normalization, unsupported enforcement, overflow or a missing observation blocks Provider continuation like any primary Tool step; an unknown parse outcome is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), and Store failure stops advancement. Cancellation preserves acknowledged receipts. Strict replay never re-parses or recovers old authority.

## Editor Tool steps

Editors (foreground or disjoint background) work in their own private workspace ([Worker journal protocol](../execution/events-and-outcomes.md#worker-journal-protocol) owns its creation, integration and lifetime) under their own journal identity and leased subset grant. Their catalog is List, Read, Search, Glob, Mkdir, Write, Edit, MultiEdit, Delete, Move and Command, narrowed by parent, plan and definition; Git, Skill, MCP, network and nested delegation are unavailable. Without a sandbox ([Guard mode](./host-commands.md#guard-mode-and-extra-reads) `auto` without one, or `off`), an editor's Command grant becomes `command_unguarded` instead: the Run pins `child_unguarded: human_only`, the editor spawns with `edit_only` and `unguarded: human_only`, and each command runs on the host with its working directory in the editor's own private workspace, never in the Workspace, pinned by that tree's identity. Each call needs its own human approval, a user-owned remembered host prefix matched by the Workspace identity and relative cwd, or, in Auto approval, the AI review; the prompt offers only Yes and No, a parent's session approval never carries over, and no rule is saved. The tree's changes still integrate once through the editor's changeset. Children follow the same order, and every child host approval stays per call. Researchers never run host commands.

Reads and typed mutations run in process on the editor's workspace through ordinary admitted capabilities and bounds, with expected-digest/create preconditions, exact path-case checks, full-batch validation, fresh-inode publication and receipts bound to that workspace's identity. The workspace holds the [selected](./changesets-and-checkpoints.md#disposable-copy-selection) project inputs of any size, so only ignored, dependency and protected Workspace files are absent. Files above [`MAX_FILE_BYTES`](../limits.md#max_file_bytes) are present: reads, commands and typed edits see them exactly as in the Workspace (typed edits refuse with `Limit`), and changing one refuses the integration with `changes_too_large` naming the file. Scope and both lease directions are checked before an intent commits: an editor cannot escape its lease and no other actor can write into it. Hooks and permission modes are evaluated under the child's identity and only narrow authority; hook commands of an editor run in its workspace.

Editor commands run directly in the editor's workspace with no per-command copy, capture or publication: on macOS Seatbelt grants read, write and execute on that tree in place of the unit's project directory; on Linux bubblewrap binds it read-write at `/workspace` (no overlay), and the supervisor attests it as a single mount without submounts. Their changes stay in the workspace beside the typed edits. They take the ordinary exclusive [cache lease](./commands-and-cache.md#persistent-workspace-build-cache); `cache_update` settles independently, as for primary commands.

Nothing an editor does changes the Workspace until its one integration, which publishes the lease-bounded project changes through the in-process publisher with checkpoints, or nothing. An unknown effect, in the workspace or at integration, is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) and stops the entire Run; process death never reschedules it.

Linux and macOS share the in-process publisher, typed discovery, checkpoint Store and pure rewind planner. In a Git repository with a pinned Git the workspace is a linked Git worktree ([Worker journal protocol](../execution/events-and-outcomes.md#worker-journal-protocol)); otherwise it clones with APFS `clonefile` on macOS and `FICLONE` on Linux filesystems that support it, copying otherwise.
