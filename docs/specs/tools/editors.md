# Tools: agent definitions and editors

## Agent definition parser admission

[Execution](../execution/collaboration.md#agent-definitions) owns discovery, format, precedence and selection. Capture admits only bounded, user-owned, regular single-link non-set-ID files on the same device, never following links; protected names and replacement during capture reject, and later replacement cannot change pinned bytes. Private StateRoot agent files must also be private. No repository Git, shell, configuration script or agent body executes.

YAML is parsed only in the native Guard, as a journaled internal `parse_agent_definition` Tool step whose intent names the pinned snapshot and its exact digest, never a model path; there is no host YAML fallback, and model schemas and script APIs cannot invoke it. Anchor, alias and tag tokens refuse (quote literal token punctuation in scalar guidance).

A selected definition's mode can require a verdict even without a parent permission-settings file. `ToolStarted.verdict.mode` names the parent settings mode when present, otherwise the definition mode; replay checks the definition restriction independently. A definition Ask needs a human or recorded AI review and cannot approve itself.

Parsing is an ordinary primary Tool step (admission, capacity, deadline, cancellation, one pending Tool at a time) that spends no model request. An invalid definition file is a successful parse with a skip diagnostic. Guard failure, malformed normalization, unsupported enforcement, overflow or a missing observation blocks Provider continuation like any primary Tool step; an unknown parse outcome is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes), and Store failure stops advancement. Cancellation preserves acknowledged receipts. Strict replay never re-parses or recovers old authority.

## Editor Tool steps

Editors (foreground or disjoint background) work in their own private workspace ([Worker journal protocol](../execution/events-and-outcomes.md#worker-journal-protocol) owns its creation, integration and lifetime) under their own journal identity and leased subset grant. Their catalog is List, Read, Search, Glob, Mkdir, Write, Edit, MultiEdit, Delete, Move and Command, narrowed by parent, plan and definition; Git, Skill, MCP, network and nested delegation are unavailable. Researchers never run host commands.

Without a sandbox ([Guard mode](./host-commands.md#guard-mode-and-extra-reads) `auto` without one, or `off`), an editor's Command grant becomes `command_unguarded`: the Run pins `child_unguarded: human_only`, the editor spawns with `edit_only` and `unguarded: human_only`, and each command runs on the host with its working directory in the editor's private workspace, never the Workspace, pinned by that tree's identity. Each call needs its own human approval, a user-owned remembered host prefix matched by the Workspace identity and relative cwd, or, in Auto approval, the AI review; the prompt offers only Yes and No, a parent's session approval never carries over, and no rule is saved. Other children follow the same order. The tree's changes still integrate once through the editor's changeset.

Reads and typed mutations run [in process](./file-operations.md#in-process-file-operations) on the editor's workspace with the ordinary bounds, preconditions and receipts, bound to that workspace's identity. The workspace holds the [selected](./changesets-and-checkpoints.md#disposable-copy-selection) project inputs of any size, so only ignored, dependency and protected Workspace files are absent. Files above [`MAX_FILE_BYTES`](../limits.md#max_file_bytes) are present: reads, commands and typed edits see them exactly as in the Workspace (typed edits refuse with `Limit`), and changing one refuses the integration with `changes_too_large` naming the file. Scope and both lease directions are checked before an intent commits: an editor cannot escape its lease and no other actor can write into it. Hooks and permission modes are evaluated under the child's identity and only narrow authority; an editor's hook commands run in its workspace.

Editor commands run directly in the editor's workspace, writable at `/workspace` on Linux, with no per-command copy, capture or publication; their changes stay there beside the typed edits. They take the ordinary exclusive [cache lease](./commands-and-cache.md#persistent-workspace-build-cache); `cache_update` settles independently, as for primary commands.

Nothing an editor does changes the Workspace until its one integration, which publishes the lease-bounded project changes through the in-process publisher with checkpoints, or nothing. An unknown effect, in the workspace or at integration, is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) and stops the entire Run; process death never reschedules it.

Linux and macOS share the in-process publisher, typed discovery, checkpoint Store and pure rewind planner; the [Worker journal protocol](../execution/events-and-outcomes.md#worker-journal-protocol) owns how the workspace is made (a linked Git worktree with a pinned Git, else an APFS `clonefile` or `FICLONE` clone or copy).
