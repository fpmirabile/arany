# Tools: commands, build cache and network

## Commands

Native Tool decoding strips leading `./` segments and one trailing `/` from directory arguments (`list`, `search`, `glob` and command `cwd`). File arguments keep a trailing `/` and fail validation. This lexical step precedes validation, permission subjects, intent hashing and Guard pins, with no filesystem lookup, traversal collapse or home expansion; absolute `/` stays absolute. The result must be canonical and Workspace-relative: at most 512 UTF-8 bytes, normal components separated by single `/`, and no absolute path, traversal, `.` component, trailing separator, backslash, control character or excluded private component. Directory arguments also accept `.` or the empty string for the root; a doubled trailing separator stays invalid. Command argv has at most 64 NUL-free strings of at most 4,096 bytes<!-- unrelated-bound: command argv element --> each, within the aggregate [argument ceiling](./limits-and-failures.md#limits-and-failure-behavior). Refusals use [correlated argument feedback](../execution/events-and-outcomes.md#accepted-outcomes), so a spelling error can be corrected within the Goal budget.

`command` accepts optional nullable `resource_class` (`default` or `build`) and integer `timeout_ms` within the advertised schema range, up to [`MAX_COMMAND_TIMEOUT_MS`](../limits.md#max_command_timeout_ms). Each value resolves from the call, then the recorded plan, then the Goal-pinned default. A recorded plan is a ceiling: Build may narrow to default and the timeout may shorten, while widening returns proposal refusal `PlanScopeExcludesCall`; a null plan timeout means the pinned default ceiling. Invalid types, unknown classes, out-of-range timeouts and Build without resolved Goal jobs or CPU cores return `InvalidArguments`, without dispatch. Build-unavailable feedback directs the model to default. The effective runtime still narrows to the remaining Goal active time and any editor deadline. Planless Build uses the same pinned Build limits, jobs, grants and Guard path as a Build plan and grants no additional access. Ask approvals display requested class and timeout and bind the exact intent limits. Hook inputs carry the fields when present; hooks and permission rules cannot widen resources, and a program-prefix allow never implies Build. The model contract reserves Build for compile and test commands; the default class keeps its smaller cache, short timeout and single Cargo job. Resource classes also bound CPU, memory and storage.

Command project copies exclude `.git`, and the command description points to typed Git reads when cataloged. When `git_status`, `git_diff` and `git_log` are available, a nonzero exit whose kept stderr contains `not a git repository` gets a fixed `hint` in the model result. Otherwise a nonzero exit whose kept stderr contains Cargo's `failed to determine the amount of parallelism available` gets a fixed `hint` to set `CARGO_BUILD_JOBS` or use Build. Neither hint is added when it would push the result above the [per-call result ceiling](./limits-and-failures.md#limits-and-failure-behavior).

Each `commands` entry declares a reviewed executable, its SHA-256, whether it is an interpreter and any extra pinned input files:

```json
{
  "name": "bash",
  "executable": "/usr/bin/bash",
  "sha256": "REPLACE_WITH_THE_64_CHARACTER_LOWERCASE_SHA256",
  "interpreter": true,
  "inputs": []
}
```

The placeholder is invalid; compute the real path and digest yourself (`readlink -f`, `sha256sum` or `shasum -a 256`). The executable must be a no-follow, regular, single-link native binary (ELF on Linux, Mach-O on macOS); replace a symlink with its resolved path. The optional `git` pin differs: it must lie under `/usr`, be root-owned, non-set-ID and not group- or world-writable, may have several hard links (distributions hard-link `git-core`), and runs in place from the read-only `/usr` mount because its shared libraries load from `/usr`. Updating an executable requires changing its pin.

Extra inputs use `{"path":"/absolute/reviewed/file","destination":"relative/name","sha256":"<digest>"}` and appear read-only under `/inputs/PROGRAM_ID/relative/name`. Executables are copied to `/programs/PROGRAM_ID`, except checked immutable macOS system programs, which keep their paths. Paths and digests are rechecked for each invocation. Allowing a shell or interpreter authorizes its behavior, including descendants using the admitted runtime, inside the same OS-enforced boundary; the `interpreter` flag proves nothing about arguments or scripts.

## Persistent Workspace build cache

Commands receive an explicit argument array, a relative working directory, a cleared environment, private `HOME`, temporary and Cargo directories, no terminal input and bounded lossy UTF-8 output. The model is told this environment: `PATH` is the selected toolchain `bin` directories followed by `/usr/bin:/bin`, the pinned shell accepts only `-c SCRIPT`, and user-installed tools outside the Guard are reachable only through a primary host command. Locale names from the pinned command environment record are the only host values carried. With the build cache enabled, `CARGO_HOME`, `CARGO_TARGET_DIR`, `npm_config_cache` and `PIP_CACHE_DIR` point into the Workspace's cache (`/cache` on Linux; on macOS a stable per-Workspace path when available); otherwise into private scratch. A selected host cache replaces only its nested cache path. Each snapshot is a fresh writable copy of the selected paths, including prior edits and integrated changes; empty directories, executable bits and modification times survive (so Cargo keeps unchanged inputs fresh), set-ID bits do not.

Selected Rust commands receive `CARGO_ENCODED_RUSTFLAGS=--cfg\x1farany_guard` (separator byte `0x1f`), which replaces lower-precedence Rust flags and enables only inventoried conditional ignores, never `arany_ci`. Every class also receives `CARGO_BUILD_JOBS` from `intent.limits.build_jobs`: one for default, the Goal-pinned value for Build ([Goal admission](../goals.md#lifecycle-budgets-and-recovery) owns its bounds). Build also receives `CARGO_NET_OFFLINE=true`. Jobs cap neither test threads nor CPU. The payload can override these within its limits; they prove no isolation.

An offline registry-backed build needs each archive, source and index subtree selected, plus the compiler and SDK on macOS. Missing inputs and unselected tools are ordinary command failures, with no discovery, installation, extra mount, network retry or host rerun. Repository toolchain files and configuration are computation inputs only. Guarded Cargo output keeps actual passed, failed and ignored counts. IPC-dependent tests use `cfg_attr(arany_guard, ignore = "requires local test IPC")`; forcing them keeps socket denial. A compile-only command can publish a cache but is not executed-test evidence.

Each Workspace has one private cache, shared by primary and editor commands of both classes and keyed by the Workspace's canonical path, device and inode; at most 128 are retained, and admitting a new one past that first evicts the least-recently-used evictable cache. One command or clear holds a Workspace's cache at a time; a competing one returns busy rather than wait ([editor admission](./editors.md#editor-tool-steps)). A command sees a private writable view of the committed cache and publishes changes back only on success, or on a Guard-attested Build timeout with an empty Workspace changeset; other failures, cancellation, resource or output limits and uncertain cleanup keep the prior cache. An abandoned command's cache is recovered before the next use, and unconfirmed teardown keeps the cache busy.

Capture covers the cache roots within the path, depth and capture-time bounds and at most [`COMMAND_PATH_METADATA_BYTES`](../limits.md#command_path_metadata_bytes) of changed names, with no entry count limit. Output outside the cache roots, such as Cargo lock files and npm logs, is validated and discarded; selected read-only host caches never publish. Safe regular-file hard links publish as independent files; links, set-ID, unsupported metadata and special objects refuse the candidate. Published files keep the payload's modification times, which Cargo fingerprints compare. An interrupted apply, failed sync or uncertain publication leaves the cache unavailable until `/cache clear`. A cache in the superseded archive format (`cache-*.arc` and its markers) is never read or converted; it is discarded whole on next use or by eviction and rebuilds from empty. On macOS the view is a copy-on-write clone published at `/private/tmp/arany-c-<device>-<inode>`, so Cargo's absolute-path fingerprints stay valid across commands; if that name is held by another user the command uses a private path, and if cloning fails (for example a StateRoot on another volume) the command runs with an empty view and the update is `rejected`.

**Outcome.** The command result records a typed `cache_update`:

| Value | Meaning |
|---|---|
| `published` | Candidate committed |
| `rejected` | The set size, the disk reserve or a capture bound rejected the candidate and kept the prior cache |
| `failed` | Validation, staging, write, sync, reopen or known publication failure kept the prior cache |
| `uncertain` | Outcome unconfirmed; [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) stops the Run |
| `not_attempted` | Guard error after dispatch, or a failed command that did not publish |
| `not_applicable` | No private cache, including a synthetic Limit without a Guard report |

The cache result is separate from command success: the update keeps the disposition and cause, including `Limit(timeout)`, and a later explicit command may reuse a validated timeout cache. Text receipts surface rejected, failed and uncertain updates; JSONL and replay keep the full observation. Cache data is never executable authority or automatic Provider context; output that discloses it is ordinary bounded observation. Background jobs do not survive a call. This finite profile does not establish support for every large Rust, Node or Python build.

**Size and eviction.** The Build cache size is `unlimited` by default; `/settings` can set a whole-MiB size, and zero disables the cache. The setting is pinned into the Goal and into each command intent (`cache_requested_bytes`), so replay never reads preferences. The intent also records the view limit (`cache_bytes`), the committed cache plus free space above [`GUARD_DISK_RESERVE_BYTES`](../limits.md#guard_disk_reserve_bytes) in whole MiB, and the candidate limit (`cache_candidate_bytes`), that view capped by a set size; no headroom refuses dispatch. A committed cache above a set size still serves the command; its candidate is `rejected` and the command result is unaffected. The free-disk reserve is the only hard bound: when free space on the StateRoot volume falls below [`GUARD_DISK_EVICTION_BYTES`](../limits.md#guard_disk_eviction_bytes), Arany evicts whole Workspace caches least recently used first, never one in use, before the Guard stops a command at the reserve. Publication evicts the same way until its growth fits above the reserve, otherwise it is `rejected`; a build never fails because of the cache. The terminal settings row shows the current total next to the setting.

`/cache clear` removes the current Workspace cache, including unavailable directory data and superseded archive records, and shows `Cleared this Workspace's private build cache`; `/cache clear all` reclaims all committed caches and shows `Cleared all private build caches`. A busy clear shows `Build cache is in use; retry after its command finishes` and keeps the cache. Malformed input shows `Error: Usage: /cache clear [all]`; other failures show `Error: private build cache could not be cleared`.

## Network grants and egress proxy

A reviewed `tools.json` may carry `"network": {"allow": [...]}`. A pattern is an exact lowercase ASCII host with at least two labels, one leading `*.` label matching subdomains only (the apex stays unlisted and at least two labels must follow), or a numeric loopback address. Other IP literals, ports, schemes, uppercase, trailing dots, bare TLDs, unknown or duplicate fields, duplicate patterns and more than [`MAX_NETWORK_PATTERNS`](../limits.md#max_network_patterns) patterns reject. Absent means no grant.

The effective domain set is the grant plus `Network(domain:x)` [allow rules](./permissions.md#permission-rules) in `permissions.json`; deny and ask rules remove matching hosts, because a running command cannot pause for approval. A rule never creates a grant, and each rule list carries at most [`MAX_NETWORK_PATTERNS`](../limits.md#max_network_patterns) domain rules. The effective set joins the pinned configuration digest in `RunStarted`. `/permissions` > Network domains lists these rules, adds one from a host refused earlier in the conversation, and changes or removes them; edits apply from the next Run and rewrite only `Network(domain:…)` strings.

Only a primary guarded Command with a grant, a primary [remote MCP](./skills-and-mcp.md#remote-mcp-and-oauth) call and admitted primary or researcher [`web_fetch` and `web_search`](#web-fetch-and-web-search) carry `limits.network = proxy`. Every other Tool, including child Commands, editors, local MCP, Skill scripts and interactive or background jobs, keeps `none`, and a child intent carrying a grant is rejected.

Such a command still has no direct network: its only route out is a per-command proxy, on Linux at `127.0.0.1:3128` inside the sandbox and on macOS on an ephemeral `127.0.0.1` port. The payload gets `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, their lowercase forms and empty `NO_PROXY`; listening and descriptor passing stay denied. If the proxy cannot start, or (on macOS) the route is not verified closed to everything else, the command refuses before GO. On Linux the payload can kill its proxy relay, costing availability, not authority; on macOS any local process can reach the listener, which grants only the effective set under the same bounds.

The proxy accepts HTTP/1.1 `CONNECT host:port` and absolute-form `GET`/`POST http://…`; other methods and forms refuse. Plain HTTP is admitted only for a listed numeric loopback host and is sent upstream in origin form with `Connection: close`. The host must be in the effective set and the port must be 443, except numeric loopback hosts, which may use any port. Destinations resolve through the [Provider destination policy](../provider/routing-and-usage.md#configuration-and-egress): public addresses for names, loopback only for numeric loopback, a bounded address set per connection and no ambient proxies. TLS is never terminated or inspected. Redirects are new payload requests, checked again. A command may open at most [`MAX_NETWORK_CONNECTIONS`](../limits.md#max_network_connections) connections and move at most [`MAX_NETWORK_BYTES`](../limits.md#max_network_bytes) each way; a connection idle for [`NETWORK_IDLE_MS`](../limits.md#network_idle_ms) without a read or completed write closes, including one stalled on a non-reading peer. Overflow closes the connection with a `limit` row. A connection arriving while twice that many are still open or closing is refused before any header with a `limit` row and empty host.

Refusals are typed rows, never prompts: the command result gains `network_refusals`, omitted when empty, a few `{host, reason, count}` rows with reason `unlisted`, `unsupported` (other method or form, disallowed port, or plain HTTP to a domain), `destination` (resolution or address admission failed), `limit` or `proxy_unavailable`. Only hostname characters survive in `host`, others becoming `?`; rows are untrusted data. The result budget reserves space for them; a result that cannot hold them fails the call rather than dropping rows. A proxy that stops mid-command yields connection failures and a `proxy_unavailable` row; the disposition still follows the exit. The model catalog gains a `network` entry with the domains and one contract sentence only when a grant exists. The effect settles only after the proxy and every connection close. Replay never contacts the network. Allowed hosts remain exfiltration channels, and tools that ignore proxy variables cannot connect (there is no transparent redirection).

### Web fetch and web search

`web_fetch {url}` and `web_search {query}` run in the Guard with `limits.network = proxy`. Linux offers them to the primary; `web_search` only when configured. `child_web: true` in `tools.json` offers them to read-only researchers under the pinned Tool policy: a researcher fetch must match the parent's effective domain set with deny precedence and cannot ask to widen it, and researcher search reaches only the configured backend. Agent definitions can narrow further. Editors and macOS never get them; a configured grant fails closed there. Neither is a Goal success call or plan prelude; a plan contract admits them without a path or command binding. A call cancelled with confirmed teardown is `Cancelled`; any other error after dispatch, or unconfirmed teardown, is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes).

`web_fetch` asks per domain. The URL is at most [`MAX_URL_BYTES`](../limits.md#max_url_bytes), HTTPS on the default port (numeric loopback may use HTTP and any port), with no credentials or fragment. A host in the [effective domain set](#network-grants-and-egress-proxy) runs without a prompt. Any other host asks on every call unless an explicit `WebFetch` allow rule skips the prompt; `dontAsk` denies it, and a deny-listed host refuses in every mode. An approved host joins only that call's proxy grant, with deny precedence. It sends one GET with no redirects (a 3xx is a typed error), no compression and the proxy's address admission, trusting the host CA bundle (`SSL_CERT_FILE`, then the usual distribution paths); a missing bundle fails an HTTPS fetch before any request. The body is read up to [`WEB_DOWNLOAD_BYTES`](../limits.md#web_download_bytes). `text/html` and `application/xhtml+xml` reduce to plain text without head, script, style or comments; nothing executes. Other `text/*` and `application/json` pass as UTF-8 with invalid bytes replaced; other types are errors. Text is cut at [`WEB_FETCH_CHARS`](../limits.md#web_fetch_chars) characters and again to the result budget, each cut ending with `[web_fetch truncated]` and `truncated: true`. The result is `{url, status, content_type, truncated, text}`; an error is `{error}` with `Failed`. A cut result carries `output_total` and, within [Output spill](./limits-and-failures.md#limits-and-failure-behavior) bounds, a spill reference to the full text, readable with `Read` as `spill:<ref>`. The excerpt is the committed observation; replay renders it without network access.

`web_search` needs `web_search: {endpoint, key}`: an HTTPS endpoint (numeric loopback may use HTTP) speaking the Brave Search API, and `key` naming an `ARANY_WEB_SEARCH_*` environment variable. The key never enters an intent, Event, digest or Provider request. A missing or malformed value refuses the call. The search proxy grant is exactly the endpoint host, independent of `network`. A response repeating the key is refused with a generic error. Each call makes one backend request with a query of at most [`MAX_QUERY_BYTES`](../limits.md#max_query_bytes) and returns up to [`WEB_SEARCH_RESULTS`](../limits.md#web_search_results) `{title, url, description}` rows, each field cut at [`MAX_SEARCH_FIELD_CHARS`](../limits.md#max_search_field_chars) characters, dropping rows from the end to fit the budget. At most [`MAX_SESSION_SEARCHES`](../limits.md#max_session_searches) `web_search` proposals commit per Session, counting primary and researcher records across Runs, so the allowance survives resume and is spent before any request; the next is refused as not offered, and replay rejects a record past the limit.

Permission rules name `WebFetch`/`web_fetch` and `WebSearch`/`web_search`. `WebFetch(domain:x)` (exact host or one leading `*.` label) allows, asks or denies fetches by host with deny precedence. Default modes allow them like other Guard reads. Results are untrusted data. An allowed host or the backend receives whatever URL or query the model writes, and TLS content is visible only to the Guard process.

## Local storage inventory

`arany storage` and idle `/storage` show a user-local metadata report. The [terminal contract](../terminal/commands.md#storage-report) owns invocation and channels; [credentials](../credentials.md#metadata-only-storage-inspection) owns account-root admission. It is not a model Tool or a read grant. It creates no Session, Run, Event, directory, database, lock, cache or log, and invokes no Provider, credential helper, recovery, cleanup or telemetry export.

Coverage is the selected Session StateRoot, the default StateRoot and the fixed OS-user account root; `--state-dir` and `ARANY_STATE_DIR` select Session storage only. Each existing root must be private and owned; missing roots are reported absent and never created. Paths appear only for admitted owned locations; individual private file and directory names are suppressed. The Workspace is excluded by opened identity, even inside a root; a root inside the Workspace is unavailable. Nested roots and file identities count once. Build-cache and Output spill totals are separate rows, not added twice; each admitted `spill` subtree has an `Output spill` row covering directories, output files and writer-lock metadata. The report reads no payloads, checks no journal references, takes no writer locks and changes no retention.

It aggregates file and directory counts, logical lengths and allocated bytes from metadata only. Unexpected multi-link files, symlinks, special objects, foreign owners, mount crossings and unreadable metadata are excluded and make coverage partial; links are never followed and permissions never changed. Build-cache records in use, unavailable or superseded mark the category busy or retained and the report partial; the inventory never takes leases or recovers. Complete metadata does not prove inactivity or safe reclamation.

Each category is complete, partial, absent, busy or unavailable. Metadata or root identity changes during collection make it partial. Only attributed observations enter the known subtotal. Allocated bytes do not promise reclaimable space (sparse files, compression, clones, snapshots). The result is point-in-time, not an atomic host total.

One inventory runs at a time, with no queue, retry or refresh. A shared 30-second<!-- unrelated-bound: storage inventory deadline --> cooperative deadline, 16,384 scanned entries, depth 32, 4 KiB<!-- unrelated-bound: storage inventory path --> paths, an 8 MiB<!-- unrelated-bound: storage inventory identity and path index cap --> identity/path index and the [cache-identity limit](#persistent-workspace-build-cache) bound work before allocation. Exhaustion or overflow stops that scan and marks a partial known subtotal, never an exact zero. Cancellation publishes no complete report and cleans nothing; a deadline cannot interrupt a stalled filesystem call. Output is at most 64 KiB<!-- unrelated-bound: local storage inventory output --> with at most 128 detail rows, reserving space for summaries and an overflow marker.

Not covered: Guard backing storage and scratch, worktrees (no owned worktree registry exists, which is not a zero-size claim), unregistered StateRoots, developer checkouts, shared Cargo/npm caches, installed binaries and OS-keyring allocation. No ambient host search or prefix-based attribution occurs.

Cleanup guidance names `/cache clear` (current Workspace) and `/cache clear all` (selected StateRoot), including busy behavior, and the [historical Guard maintenance procedure](../../tools.md#historical-linux-seed-maintenance). It never generates deletion or detach commands or recommends removing history, credentials or live or uncertain Guard storage.
