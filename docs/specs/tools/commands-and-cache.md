# Tools: commands, build cache and network

## Commands

Native Tool decoding strips leading `./` segments and one trailing `/` from directory arguments (`list`, `search`, `glob` and command `cwd`). File arguments keep a trailing `/` and fail validation. This lexical step precedes validation, permission subjects, intent hashing and Guard pins, with no filesystem lookup, traversal collapse or home expansion; absolute `/` stays absolute. The result must be canonical and Workspace-relative: at most 512 UTF-8 bytes, normal components separated by single `/`, and no absolute path, traversal, `.` component, trailing separator, backslash, control character or excluded private component. Directory arguments also accept `.` or the empty string for the root. A doubled trailing separator stays invalid. Command argv has at most 64 NUL-free strings of at most 4,096 bytes<!-- unrelated-bound: command argv element --> each, within the aggregate [argument ceiling](./limits-and-failures.md#limits-and-failure-behavior). Refusals use [correlated argument feedback](../execution/events-and-outcomes.md#accepted-outcomes), so a spelling error grants nothing and can be corrected within the Goal budget.

`command` accepts optional nullable `resource_class` (`default` or `build`) and integer `timeout_ms` within the advertised schema range, up to [`MAX_COMMAND_TIMEOUT_MS`](../limits.md#max_command_timeout_ms). Each value resolves from the call, then the recorded plan, then the Goal-pinned default. A recorded plan is a ceiling: Build may narrow to default and the timeout may shorten; default may not widen to Build, and a null plan timeout means the pinned default ceiling. Widening a plan returns proposal refusal `PlanScopeExcludesCall`. Invalid types, unknown classes, out-of-range timeouts and Build without resolved Goal jobs or CPU cores return `InvalidArguments`, without dispatch. Build-unavailable feedback directs the model to default. The effective runtime still narrows to the remaining Goal active time and any editor deadline. Planless Build uses the same pinned Build limits, jobs, grants and Guard path as a Build plan; it grants no additional access. Ask approvals display requested class and timeout and bind the exact intent limits. Hook inputs carry fields when present; hooks and permission rules cannot widen resources, and a program-prefix allow never implies Build. The model contract reserves Build for compile and test commands; the default class retains its smaller cache, short timeout and single Cargo job. Arany also bounds CPU, memory and storage through its existing resource classes.

Command project copies exclude `.git`, and the command description points to typed Git reads when cataloged. When `git_status`, `git_diff` and `git_log` are available, a nonzero exit whose kept stderr contains `not a git repository` gets a fixed `hint` in the model result. Otherwise a nonzero exit whose kept stderr contains Cargo's `failed to determine the amount of parallelism available` gets a fixed `hint` to set `CARGO_BUILD_JOBS` or use Build. Neither hint is added when it would push the result above the [per-call result ceiling](./limits-and-failures.md#limits-and-failure-behavior).

Each `commands` entry declares a reviewed executable, its SHA-256, whether it is an interpreter and any extra pinned input files:

```json
{
  "name": "bash",
  "executable": "/usr/bin/bash",
  "sha256": "REPLACE_WITH_THE_64_CHARACTER_LOWERCASE_SHA256",
  "interpreter": true,
  "inputs": []
}
```

The placeholder is deliberately invalid; compute the real path and digest yourself (`readlink -f`, `sha256sum` or `shasum -a 256`). The executable must be a no-follow, regular, single-link native binary (ELF on Linux, Mach-O on macOS); replace a symlink with its resolved path. The optional `git` pin differs: it must lie under `/usr`, be root-owned, non-set-ID and not group- or world-writable, may have several hard links (distributions hard-link `git-core`), and runs in place from the read-only `/usr` mount because its shared libraries load from `/usr`. Updating an executable requires changing its pin.

Extra inputs use `{"path":"/absolute/reviewed/file","destination":"relative/name","sha256":"<digest>"}` and appear read-only under `/inputs/PROGRAM_ID/relative/name`. Executables are copied to `/programs/PROGRAM_ID`, except checked immutable macOS system programs, which keep their paths. Paths and digests are rechecked for each invocation. Allowing a shell or interpreter authorizes its behavior, including descendants using the admitted runtime, inside the same OS-enforced boundary; the `interpreter` flag proves nothing about arguments or scripts.

## Persistent Workspace build cache

Commands receive an explicit argument array, a relative working directory, a cleared environment, private `HOME`, temporary and Cargo directories, no terminal input and bounded lossy UTF-8 output. The model-facing contract states this environment: `PATH` is the selected toolchain `bin` directories followed by `/usr/bin:/bin`, the pinned shell accepts only `-c SCRIPT`, and user-installed tools outside the Guard are reachable only through a primary host command. Locale names from the pinned command environment record are the only host values carried. Project selection runs inside the command's own timeout; control-file caps still apply. With the build cache enabled, `CARGO_HOME`, `CARGO_TARGET_DIR`, `npm_config_cache` and `PIP_CACHE_DIR` point into the admitted cache view (`/cache` on Linux; on macOS the cloned cache directory, through its stable per-Workspace alias when one is published); otherwise into private scratch. Toolchain subtrees are executable throughout; selected `bin` paths extend `PATH` in grant order, and a selected host cache replaces only its nested cache path. Each snapshot is a fresh writable copy of the selected paths, including prior edits and integrated changes; empty directories, executable bits and modification times survive (so incremental builds such as Cargo keep unchanged inputs fresh), set-ID bits do not.

Selected Rust commands receive `CARGO_ENCODED_RUSTFLAGS=--cfg\x1farany_guard` (separator byte `0x1f`), which replaces lower-precedence Rust flags and enables only inventoried conditional ignores, never `arany_ci`. Every class also receives `CARGO_BUILD_JOBS` from the digest-bound `intent.limits.build_jobs`: one for default, the Goal-pinned value for Build ([Goal admission](../goals.md#lifecycle-budgets-and-recovery) owns its bounds), so Cargo never needs the CPU-count query the macOS profile denies. Build also receives `CARGO_NET_OFFLINE=true`. Jobs cap neither test threads nor CPU. The payload can override these within its limits; they prove no isolation.

An offline registry-backed build needs each archive, source and index subtree selected, plus the compiler and SDK on macOS. Missing inputs and unselected tools are ordinary command failures, with no discovery, installation, extra mount, network retry or host rerun. Repository toolchain files and configuration are computation inputs only. Guarded Cargo output keeps actual passed, failed and ignored counts. IPC-dependent tests use `cfg_attr(arany_guard, ignore = "requires local test IPC")`; forcing them keeps socket denial. A compile-only command can publish a cache but is not executed-test evidence.

Each Workspace has one cache identity keyed by canonical path, device and inode; at most 128 identities are retained, and admitting a new one past that evicts the least-recently-used evictable cache first (see eviction below). A nonblocking exclusive identity lease covers primary and editor command restore, collection, publication and clear; competing operations return busy rather than wait. No shared-read lease or pinned generation exists; editor command admission follows [Editor Tool steps](./editors.md#editor-tool-steps). Store accepts only allowlisted cache roots and rejects symlinks, special files, set-ID inputs, malformed paths and identity drift. Only success, or a Guard-attested primary or editor Build timeout with an empty Workspace changeset, may publish; other failures, cancellation, resource or output limits and uncertain cleanup keep the prior cache.

**Linux directory cache.** Primary and editor Commands in both `default` and `build` classes use one directory-backed cache overlay under the identity lease. The supervisor receives only the pinned cache-directory identity, clones it read-only and mounts a sized, inode-bounded tmpfs upper at `/cache`; payload Tasks never carry a `StateRoot` path or handle. A durable cache record pins the Guard unit before launch; admission and clear first recover that exact abandoned unit, and unconfirmed teardown keeps the record and refuses lower mutation. A live controller stays busy. Read-only host-cache subtrees mounted in the view are excluded from publication. The upper is sized to the view headroom admitted with the intent; no headroom refuses dispatch, and a committed cache above a set size still mounts, its candidate then being rejected. Application waits for supervisor exit, reap, output EOF and positive unit cleanup; missing handoff or cleanup evidence after GO is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes).

Capture streams the upper against the committed tree in sorted order, reusing the overlay whiteout and `opaque=y` classifier under the cache root, path, depth and capture-time bounds; only one directory listing per level and the changed paths are held, together at most [`COMMAND_PATH_METADATA_BYTES`](../limits.md#command_path_metadata_bytes) of names, so there is no cache entry count limit. Safe output outside the cache roots, such as Cargo lock files and npm logs, is validated and discarded. Safe regular-file hard links copy as independent files; links, set-ID, unsupported private metadata and special objects refuse capture. Size and disk rejection precede lower mutation. Before in-place application, Store durably marks the cache unavailable; only synchronized content, ancestors and directory publication readmit it. An interrupted apply, failed sync or uncertain publication leaves it unavailable until `/cache clear`. Changes apply in place through pinned directory handles, and each published file keeps the payload's access and modification times, which Cargo fingerprints compare. Default and Build commands share the directory and the pinned size. Records of the superseded archive format (`cache-*.arc`, generation stamps, reservations, transaction markers and their staging files) are never read or converted: a cache is regenerable, so such a cache is discarded whole when its Workspace next takes the lease, or by eviction, and rebuilds from empty; the Build cache row's used size shows the change.

**macOS cloned cache.** macOS uses the same Store directory cache, lease, guard record, capture bounds and in-place application as Linux. Before launch the controller clones the pinned directory into the unit root with APFS `fclonefileat` (copy-on-write, so the view costs no space until written) and publishes `/private/tmp/arany-c-<device>-<inode>` as an alias of that view: Cargo fingerprints absolute registry and target paths, so a per-unit path would rebuild every dependency. The alias is replaced only under the identity lease, used only while it resolves to the unit's own view, and gets a metadata-only Seatbelt literal; a name squatted by another user leaves the unit on its private path. A clone that fails (for example a StateRoot on another volume) runs the command with an empty, unpublished view (`rejected`). After positive coalition emptiness the controller diffs the quiescent view against the pinned directory without following links: unchanged files (size, modification time, executable bit) are skipped, links, special and set-ID files refuse the candidate, output outside the cache roots is discarded, and the changes apply through the Linux publication path.

**Outcome.** The controller records a typed `cache_update` beside the observation, command result and Guard receipt:

| Value | Meaning |
|---|---|
| `published` | Candidate committed |
| `rejected` | The set size, the disk reserve or a capture bound rejected the candidate and kept the prior cache |
| `failed` | Validation, staging, write, sync, reopen or known publication failure kept the prior cache |
| `uncertain` | Outcome unconfirmed; [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) stops the Run |
| `not_attempted` | Guard error after dispatch, or a failed command that did not publish |
| `not_applicable` | No private cache, including a synthetic Limit without a Guard report |

Published, rejected and failed require the eligibility above; success cannot commit `not_attempted`. The update keeps the disposition and cause, including `Limit(timeout)`; a later explicit command may reuse a validated timeout cache. Cache data is never executable authority or automatic Provider context; output that discloses it is ordinary bounded observation. Background jobs do not survive a call. This finite profile does not establish support for every large Rust, Node or Python build.

The cache result is separate from command success. Text receipts surface rejected, failed and uncertain updates; JSONL and replay keep the full observation.

**Size and eviction.** The Build cache size is `unlimited` by default; `/settings` can set a whole-MiB size, and zero disables the cache. The setting is pinned into the Goal at admission and into each command intent (`cache_requested_bytes`), so replay never reads preferences. At intent admission the Store measures the committed cache and the free space on the StateRoot volume: the view limit (`cache_bytes`) is the committed cache plus free space above [`GUARD_DISK_RESERVE_BYTES`](../limits.md#guard_disk_reserve_bytes), in whole MiB, and the candidate limit (`cache_candidate_bytes`) is that view capped by a set size. A committed cache above a set size still serves the command; its candidate is `rejected` and the command result is unaffected. The free-disk reserve is the only hard bound: when free space on the StateRoot volume falls below [`GUARD_DISK_EVICTION_BYTES`](../limits.md#guard_disk_eviction_bytes), when a command's cache session starts (off the async runtime; intent admission only measures) and every supervision interval of a macOS unit, retrying after one second when nothing is evictable, the Store evicts whole Workspace caches least recently used first (last use is the latest lease), before the Guard stops a command at the reserve. Eviction never touches a cache held by a lease or one with a Guard record, and a busy namespace skips it for that attempt. Publication evicts the same way until its growth fits above the reserve, otherwise it is `rejected`; a build never fails because of the cache. Arany keeps a private cache per Workspace for isolation, so it bounds that cache by the disk reserve and evicts it instead of capping it. The terminal settings row shows the current total next to the setting.

`/cache clear` removes the current Workspace cache, including unavailable directory data and superseded archive records, and shows `Cleared this Workspace's private build cache`; `/cache clear all` reclaims all committed caches and shows `Cleared all private build caches`. A busy clear shows `Build cache is in use; retry after its command finishes` and keeps the cache. Malformed input shows `Error: Usage: /cache clear [all]`; other failures show `Error: private build cache could not be cleared`.

## Network grants and egress proxy

A reviewed `tools.json` may carry `"network": {"allow": [...]}`. A pattern is an exact lowercase ASCII host with at least two labels, one leading `*.` label matching subdomains only (the apex stays unlisted and at least two labels must follow), or a numeric loopback address. Other IP literals, ports, schemes, uppercase, trailing dots, bare TLDs, unknown or duplicate fields, duplicate patterns and more than [`MAX_NETWORK_PATTERNS`](../limits.md#max_network_patterns) patterns reject. Absent means no grant.

The effective domain set is the grant plus `Network(domain:x)` [allow rules](./permissions.md#permission-rules) in `permissions.json`; deny and ask rules remove matching hosts, because a running command cannot pause for approval. A rule never creates a grant, and each rule list carries at most [`MAX_NETWORK_PATTERNS`](../limits.md#max_network_patterns) domain rules. The effective set joins the pinned configuration digest in `RunStarted`. `/permissions` > Network domains lists these rules, adds one from a host refused earlier in the conversation, and changes or removes them; edits apply from the next Run and rewrite only `Network(domain:…)` strings.

Only a primary guarded Command with a grant, a primary [remote MCP](./skills-and-mcp.md#remote-mcp-and-oauth) call and admitted primary or researcher [`web_fetch` and `web_search`](#web-fetch-and-web-search) carry `limits.network = proxy`. Every other Tool, including child Commands, editors, local MCP, Skill scripts and interactive or background jobs, keeps `none`; the intent validator rejects `proxy` elsewhere, and the reducer rejects a child intent carrying a grant. The enforcement digest binds the proxy contract, its bounds and the routed seccomp program, so the Guard refuses a mismatched profile.

On Linux the parent starts one proxy per command on a `0600` Unix socket in the user's runtime directory, bind-mounted read-only as `/arany-egress.sock`. The payload keeps its empty network namespace. Before seccomp is installed, the Guard helper starts a bridge from the same pinned executable on `127.0.0.1:3128` inside that namespace, relaying to the socket. The payload gets `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, their lowercase forms and empty `NO_PROXY`. The routed filter admits `connect` and only `AF_INET`/`AF_INET6` sockets, with no datagram `socketpair`, so the bridge is the only route out. Failure to start proxy or bridge refuses before GO. The bridge shares the payload's PID namespace and cgroup, is not seccomp-filtered and can be killed by the payload, which costs availability, not authority; socket and bridge use one task and one file slot of the command's limits.

On macOS the controller binds one `127.0.0.1` listener on an ephemeral port per command and passes the port only in the Task, never in a journaled field. The routed Seatbelt profile adds `(allow system-socket (socket-domain AF_INET))` and `(allow network-outbound (remote ip "localhost:PORT"))`; `bind`, `listen` and descriptor delegation stay denied. The payload gets the same proxy variables. The helper attests the route with two connects the profile must refuse (the neighbouring loopback port and a documentation address) and refuses before GO if either succeeds. Any local process can reach the listener, which grants only the effective set under the same bounds. Proxy and connections close after the coalition is empty.

The proxy accepts HTTP/1.1 `CONNECT host:port` and absolute-form `GET`/`POST http://…`; other methods and forms refuse. Plain HTTP is admitted only for a listed numeric loopback host and is sent upstream in origin form with `Connection: close`. The host must be in the effective set and the port must be 443, except numeric loopback hosts, which may use any port. Destinations resolve through the [Provider destination policy](../provider/routing-and-usage.md#configuration-and-egress): public addresses for names, loopback only for numeric loopback, a bounded address set per connection and no ambient proxies. TLS is never terminated or inspected. Redirects are new payload requests, checked again. A command may open at most [`MAX_NETWORK_CONNECTIONS`](../limits.md#max_network_connections) connections and move at most [`MAX_NETWORK_BYTES`](../limits.md#max_network_bytes) each way; a connection idle for [`NETWORK_IDLE_MS`](../limits.md#network_idle_ms) without a read or completed write closes, including one stalled on a non-reading peer. Overflow closes the connection with a `limit` row. Connection tasks are capped at twice the connection limit, including tasks awaiting reaping; an arrival at capacity, or a bridge relay overflow, is refused before any header with a `limit` row and empty host. Refusal replies are bounded.

Refusals are typed rows, never prompts. The command result gains `network_refusals`, omitted when empty: a few `{host, reason, count}` rows with reason `unlisted`, `unsupported` (other method or form, disallowed port, or plain HTTP to a domain), `destination` (resolution or address admission failed), `limit` or `proxy_unavailable`. Only hostname characters survive in `host`, others become `?`; rows are untrusted data. The result budget, including the overlay merge, reserves space for them; a result that cannot hold them fails the call rather than dropping rows. A proxy that stops mid-command yields connection failures and a `proxy_unavailable` row; the disposition still follows the exit. The model catalog gains a `network` entry with the domains and one contract sentence only when a grant exists. The effect settles only after the proxy and every connection close. Replay never contacts the network.

Non-claims: allowed hosts remain exfiltration channels, TLS content is invisible to the proxy, tools that ignore proxy variables cannot connect (no transparent redirection), and Build commands keep Cargo offline.

### Web fetch and web search

`web_fetch {url}` and `web_search {query}` run in the Guard helper with `limits.network = proxy`, an empty network namespace and the routed seccomp program. Linux offers them to the primary; `web_search` only when configured. `child_web: true` in `tools.json` offers them to read-only researchers under the pinned Tool policy: a researcher fetch must match the parent's effective domain set with deny precedence and cannot ask to widen it, and researcher search reaches only the configured backend. Agent definitions can narrow further. Editors and macOS never get them; a configured grant fails closed there. Neither is a Goal success call or plan prelude; a plan contract admits them without a path or command binding. A call cancelled with confirmed teardown is `Cancelled`; any other error after dispatch, or unconfirmed teardown, is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes).

`web_fetch` asks per domain. The URL is at most [`MAX_URL_BYTES`](../limits.md#max_url_bytes), HTTPS on the default port (numeric loopback may use HTTP and any port), with no credentials or fragment. A host in the [effective domain set](#network-grants-and-egress-proxy) runs without a prompt. Any other host asks on every call unless an explicit `WebFetch` allow rule skips the prompt; `dontAsk` denies it, and a deny-listed host refuses in every mode. An approved host joins only that call's proxy grant, with deny precedence. The Guard sends one GET with no redirects (a 3xx is a typed error), no compression and the proxy's address admission. It trusts the host CA bundle (`SSL_CERT_FILE`, then the usual distribution paths) bound read-only as `/arany-ca.pem`; a missing bundle fails an HTTPS fetch before any request. The body is read up to [`WEB_DOWNLOAD_BYTES`](../limits.md#web_download_bytes). `text/html` and `application/xhtml+xml` reduce to text with a bounded extractor that drops head, script, style and comments, breaks lines at block tags, decodes entities and collapses whitespace; nothing executes. Other `text/*` and `application/json` pass as UTF-8 with invalid bytes replaced; other types are errors. Text is cut at [`WEB_FETCH_CHARS`](../limits.md#web_fetch_chars) characters and again to the result budget, each cut ending with `[web_fetch truncated]` and `truncated: true`. The result is `{url, status, content_type, truncated, text}`; an error is `{error}` with `Failed`. A cut result carries `output_total` and, within [Output spill](./limits-and-failures.md#limits-and-failure-behavior) bounds, a spill reference to the full text, readable with `Read` as `spill:<ref>`. The excerpt is the committed observation; replay renders it without network access.

`web_search` needs `web_search: {endpoint, key}`: an HTTPS endpoint (numeric loopback may use HTTP) speaking the Brave Search API, and `key` naming an `ARANY_WEB_SEARCH_*` environment variable. The parent reads it when launching the Guard and passes it only over the private task pipe; it never enters an intent, Event, digest or Provider request. A missing or malformed value refuses the call. The search proxy grant is exactly the endpoint host, independent of `network`. A response repeating the key is refused with a generic error. Each call makes one backend request with a query of at most [`MAX_QUERY_BYTES`](../limits.md#max_query_bytes) and returns up to [`WEB_SEARCH_RESULTS`](../limits.md#web_search_results) `{title, url, description}` rows, each field cut at [`MAX_SEARCH_FIELD_CHARS`](../limits.md#max_search_field_chars) characters, dropping rows from the end to fit the budget. At most [`MAX_SESSION_SEARCHES`](../limits.md#max_session_searches) `web_search` proposals commit per Session, counting primary and researcher records across Runs; the next is refused as not offered and replay rejects a record past the limit, so the allowance survives resume and is spent before any request.

Permission rules name `WebFetch`/`web_fetch` and `WebSearch`/`web_search`. `WebFetch(domain:x)` (exact host or one leading `*.` label) allows, asks or denies fetches by host with deny precedence. Default modes allow them like other Guard reads. Results are untrusted data. Non-claims: an allowed host or the backend receives whatever URL or query the model writes, and TLS content is visible only to the Guard process.

## Local storage inventory

`arany storage` and idle `/storage` show a user-local metadata report. The [terminal contract](../terminal/commands.md#storage-report) owns invocation and channels; [credentials](../credentials.md#metadata-only-storage-inspection) owns account-root admission. It is not a model Tool or a private-file read grant. It creates no Session, Run, Event, directory, database, lock, cache or log, and invokes no Provider, credential helper, recovery, cleanup or telemetry export.

Coverage is the selected Session StateRoot, the default StateRoot and the fixed OS-user account root; `--state-dir` and `ARANY_STATE_DIR` select Session storage only. Each existing root is authenticated by private no-follow component admission, independently of payload validity; missing roots are reported absent and never created. Paths appear only for admitted owned locations; individual private file and directory names are suppressed. The Workspace is excluded by opened identity, even inside a root; a root inside the Workspace is unavailable. Nested roots and file identities count once. Build-cache and Output spill totals are separate rows, not added twice. Each admitted `spill` subtree has an `Output spill` row covering directories, output files and writer-lock metadata. The report reads no payloads, checks no journal references, takes no writer locks, changes no retention and grants no Read authority.

It aggregates file and directory counts, logical lengths and allocated bytes (`blocks × 512`, overflow-checked) through metadata-only descriptors. Private ownership, permissions and ACL admission are required. Unexpected multi-link files, symlinks, special objects, foreign owners and unowned mount crossings are excluded and make coverage partial; linked targets are never followed. Unsupported enforcement fails closed. A denied metadata open (possible for mode-000 records on macOS) excludes that record and marks its category partial, without reading content or changing permissions.

Build-cache inventory reuses the owner's record-name classification. It counts directory caches, Guard and unavailable records, locks and superseded archive records without parsing them, taking leases or recovering. Guard, unavailable and superseded records mark the category busy or retained and the report partial. An unknown or unsafe cache object is excluded as partial. Complete metadata does not prove inactivity or safe reclamation.

Each category is complete, partial, absent, busy or unavailable. Metadata or root identity changes during collection make it partial. Only attributed observations enter the known subtotal. Allocated bytes do not promise reclaimable space (sparse files, compression, clones, snapshots). The result is point-in-time, not an atomic host total.

One inventory runs at a time, with no queue, retry or refresh. A shared 30-second<!-- unrelated-bound: storage inventory deadline --> cooperative deadline, 16,384 scanned entries, depth 32, 4 KiB<!-- unrelated-bound: storage inventory path --> paths, an 8 MiB<!-- unrelated-bound: storage inventory identity and path index cap --> identity/path index and the [cache-identity limit](#persistent-workspace-build-cache) bound work before allocation. Exhaustion or overflow stops that scan and marks a partial known subtotal, never an exact zero. Cancellation publishes no complete report, closes handles and cleans nothing; blocking work stays owned until it stops, and a deadline cannot interrupt a stalled syscall. Output is at most 64 KiB<!-- unrelated-bound: local storage inventory output --> with at most 128 detail rows, reserving space for summaries and an overflow marker.

Not covered: Guard backing storage and scratch, worktrees (no owned worktree registry exists; this is not a zero-size claim), unregistered StateRoots, developer checkouts, shared Cargo/npm caches, installed binaries and OS-keyring allocation. No ambient host search or prefix-based attribution occurs.

Cleanup guidance names `/cache clear` (current Workspace) and `/cache clear all` (selected StateRoot), including busy behavior, and the [historical Guard maintenance procedure](../../tools.md#historical-linux-seed-maintenance). It never generates deletion or detach commands or recommends removing history, credentials or live or uncertain Guard storage.
