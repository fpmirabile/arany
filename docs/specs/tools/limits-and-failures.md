# Tools: limits and failure behavior

## Limits and failure behavior

`ToolObservation.limit_cause` is required and nullable, non-null exactly for `Limit`: `timeout`, `output_ceiling`, `context_full`, `read_capacity`, `requested_time` or `resource`.

|---|---|
| Primary proposal refusals | [Execution](../execution/events-and-outcomes.md#accepted-outcomes) owns the identical-pair refusal cap |
| Private configuration | [`MAX_CONFIG_BYTES`](../limits.md#max_config_bytes); 32 selected roots, 8 commands, [`MAX_SKILLS`](../limits.md#max_skills) Skills, 4 MCP servers |
| Project snapshot outside primary commands | [`MAX_SNAPSHOT_BYTES`](../limits.md#max_snapshot_bytes); [`MAX_SNAPSHOT_FILES`](../limits.md#max_snapshot_files) file/empty-directory entries; 8,192 scanned directory entries; depth 16 |
| Primary command selection | [`COMMAND_SNAPSHOT_BYTES`](../limits.md#command_snapshot_bytes) content; [`COMMAND_SNAPSHOT_FILES`](../limits.md#command_snapshot_files) files/empty directories; [`COMMAND_SCAN_ENTRIES`](../limits.md#command_scan_entries) scanned entries; [`COMMAND_SNAPSHOT_DEPTH`](../limits.md#command_snapshot_depth); [`COMMAND_PATH_METADATA_BYTES`](../limits.md#command_path_metadata_bytes) path and metadata; files at most [`MAX_FILE_BYTES`](../limits.md#max_file_bytes). The same selection, without the size omission and these copy caps, populates editor workspaces within the disk reserve. | Build process profile | Maximum [`MAX_BUILD_MEMORY_BYTES`](../limits.md#max_build_memory_bytes) memory, [`MAX_BUILD_PROCESSES_OR_THREADS`](../limits.md#max_build_processes_or_threads) processes/threads, [`MAX_BUILD_PROJECT_BYTES`](../limits.md#max_build_project_bytes) project storage, a [build cache](./commands-and-cache.md#persistent-workspace-build-cache) `unlimited` by default and [`MAX_COMMAND_TIMEOUT_MS`](../limits.md#max_command_timeout_ms) command time, all lowerable. | Persistent build cache | Size `unlimited` by default or a set whole-MiB size; zero disables. | Command and MCP output | Head and tail around `\n…[N bytes, L lines omitted; T bytes, M lines total]…\n`, fitted to the result budget. Commands carry required `stdout_total` and `stderr_total` `{bytes, lines}` of raw bytes and lines (an unterminated final line counts); cuts keep character boundaries, invalid UTF-8 becomes U+FFFD. Streams share one result budget evenly, a short stream ceding its unused share. Capture drains to EOF; over 1 GiB<!-- unrelated-bound: command output kill ceiling --> per stream kills the command as `Limit` (`output_ceiling`) and publishes nothing |
| Output spill | Excerpted Command (including host command), MCP or `web_fetch` results keep at most [`MAX_SPILL_RESULT_BYTES`](../limits.md#max_spill_result_bytes) each and [`MAX_SPILL_RUN_BYTES`](../limits.md#max_spill_run_bytes) per Run. Before `ToolFinished` the Engine writes raw stdout then stderr, the normalized MCP result or the extracted `web_fetch` text to private `spill/<run-id>/<intent-digest>.txt`; a cut file ends with `[spill truncated]`. Above the Run cap nothing is added. Write failure keeps the excerpt and outcome, omits the reference and logs a development diagnostic; it never makes the effect Uncertain. Persistence waits at most [`SPILL_PERSIST_TIMEOUT_MS`](../limits.md#spill_persist_timeout_ms) or until cancellation, with at most [`MAX_SPILL_WRITERS`](../limits.md#max_spill_writers) active or stalled writers per process and no queue. Late completion never publishes a reference. A spill is readable only after its `ToolFinished` commit is acknowledged |
| Command changeset | [Command changeset limits](./changesets-and-checkpoints.md#command-changesets); overflow rejects the whole record before publication |
| Time | A timed-out command records `Limit(timeout)` with bounded partial output and no changeset; the command is terminated, never backgrounded. Commands default to [`DEFAULT_COMMAND_TIMEOUT_MS`](../limits.md#default_command_timeout_ms); per-call requests are bounded by the saved maximum ([`MAX_COMMAND_TIMEOUT_MS`](../limits.md#max_command_timeout_ms)) and any recorded plan, whose null timeout binds the pinned default ceiling. A request above the saved maximum returns a correlated non-dispatched `Limit(RequestedTime)` with requested and pinned values, pointing to `/settings`; the active Goal keeps its settings. MCP dialogue is [`MCP_TIMEOUT_MS`](../limits.md#mcp_timeout_ms). Goal active time covers transfer, preparation, payload and cleanup, not approval or FIFO waits; GO requires the full runtime to fit the remaining reservation. Preparation, cleanup, Provider and capture deadlines are separate. There is no fixed 300-second Run or 60-second command ceiling. On macOS the timeout runs from GO (a spent budget records `Limit` without spawning); confirmed teardown records the attested `Limit`, otherwise the call is Uncertain |
| Calls per model step | Primary and researcher steps admit 1 through [`MAX_STEP_TOOL_CALLS`](../limits.md#max_step_tool_calls) calls, editors one; [Execution](../execution/events-and-outcomes.md#accepted-outcomes) owns over-cap refusal and [Provider encoding](../provider/encoding-and-streaming.md#structured-outcomes-and-tool-encoding) route availability |

| In-process file operations | At most 16 concurrent Workspace mutations, Reads, Lists, Globs, Searches and Skill calls per process; a full set records Limit before I/O |

| Host Git | Push URL, branch, PR title and PR body at most 2048, 128, 256 and 8192 bytes<!-- unrelated-bound: host PR body bytes -->; writes at most 600 seconds<!-- unrelated-bound: typed host operation deadline -->, reads 20 seconds, narrowed by the action/Goal reservation. | MCP | Oversized admitted results become a head-and-tail preview with `output_total` and the original `is_error`; schema and transport bounds reject whole. List returns at most 64 rows in path order and flags possible truncation; a walk reaching its 8,192 retained entries stops there and returns that truncated page instead of Limit, so narrow `path` or page with Glob. Search pages at most 100 rows. Oversized Command and MCP results and Skill text truncate as above; other oversized requests and results reject whole. Command results fit the changeset first (never cut), then exit status and totals, then excerpts; truncation never changes status, disposition, approval or integration. The excerpt and totals are the committed observation, rendered identically on replay; marker-like program text stays untrusted. Excerpts may carry a private spill reference, with smaller caps and only metadata committed. Spill bytes stay untrusted and never enter changesets, checkpoints, rewind, hook inputs, implicit context or replay. State removal deletes them; a writable Store open removes uncommitted spills of inactive writers within the [list-scan bound](../limits.md#max_list_scan_events) and [sweep deadline](../limits.md#sweep_time_ms); read-only inspection never cleans. Provider requests keep their own limits; ChatGPT's output-acceptance cap is local, not a plan-usage guarantee.

Intents and receipts name `linux_kernel` or `macos_supervised` resource semantics and the `default` or `build` class; their enforcement digest covers every enforced value (timeout and cache-view cap included), and the policy digest the selected grants and pins. Missing or unknown profiles, value mismatches and receipts for another class reject. File and Skill intents carry no runtime grants.

The 128-byte minimum result budget is the smallest admitted result; mutation and failure receipts must fit it, naming resources through the intent, and Guard failure receipts hold only stage labels. A lost completion of an applied mutation stays Uncertain; receipt overflow never makes it retryable.

Search matches single UTF-8 lines of a named file or the files under a directory, in process. The call is `{path, query, regex, include, case_sensitive, offset, limit}`; `path` and `query` are required and the rest are required nullable fields defaulting to `regex: false`, `include: null`, `case_sensitive: true`, `offset: 0` and `limit: 100`, canonicalized before hashing and omitted from stored intents. `query` is 1–512 UTF-8 bytes, literal unless `regex`. Regex mode is Rust syntax without look-around or backreferences; `case_sensitive: false` folds Unicode case. `include` (1–512 bytes<!-- unrelated-bound: Search include glob bytes -->) filters paths relative to a directory, or a file's basename, with the [Glob](./file-operations.md#glob-file-discovery) grammar, so `*.rs` matches only the directory's own files. Query and glob compile once under the Glob regex size, DFA cache, nesting and translation bounds. An invalid or over-limit pattern records attested `Failed` (Workspace and WorkerView alike) with `Search pattern refused: <cause>; nothing was read` (regex syntax, regex size, glob syntax or glob limits) before reading, never falling back to literal matching. A `limit` outside 1–100, an `offset` above 33,554,432 or an empty include rejects at decoding.

Authorization, protected names, ignored directories and scope apply before the filter; excluded files are never read. Rows are `{path, line, text}` with one-based lines and 512-character previews, ordered by path bytes then line, independent of locale. `offset` skips matches; at most `limit` rows plus one lookahead are held. The result is `{entries, limit, may_be_truncated, next_offset}`: `next_offset` is offset plus rows returned when another match exists, else null, and `may_be_truncated` is true exactly when it is non-null. Fitting drops trailing rows and resumes at the first dropped one; if no row fits, Limit; an offset past the end returns empty entries. Each page is a fresh read, not a snapshot; replay uses the committed page. A timed-out scan stops at its next line. Directory Search scans files during the walk and skips files over [1 MiB](../limits.md#max_file_bytes) and non-UTF-8 files, counting them in `skipped_large` and `skipped_binary` (present only when nonzero). Its bounds are 60% of its time budget, the matcher calls, the 200,000 scanned entries and [32 MiB](../limits.md#max_snapshot_bytes) of content: reaching one after at least one row returns the rows so far with `may_be_truncated: true` and `next_offset`; reaching one with no row is Limit (time still runs to the full deadline first). Narrow `path` or `include` to finish sooner. Search supplies no edit precondition; a Read or an `@` include does.

The pinned catalog supplies the host clock in Unix milliseconds (UTC), so current-date tasks need no shell; it grants no authority.

The [execution contract](../execution/events-and-outcomes.md#accepted-outcomes) owns native-function and structured-text selection. Field descriptions explain nullable Read paging and that Edit `old` is non-empty exact text without line-number prefixes; they guide generation and grant nothing.

The primary completes file actions through Tool continuations: a read needed for an edit is a Tool proposal in the same Run, not a request to the user. Researchers inspect read-only; the primary edits and verifies. `@` file references add bounded include snapshots labeled with their escaped path and the SHA-256 of the bytes, counted against context. Trailing-slash directory references say where to look without reading or granting.

Native adapters present the catalog and outputs as structured task data: ordered call, disposition and output observations, not internal intents. Each observation carries a workspace-effect fact: none for inspection and disposable commands, applied for attested successful mutations, uncertain for uncertain or cancelled mutations, otherwise not confirmed. The model-facing result omits `workspace_effect` when it is none and `cache_update` when it is `not_applicable`; journaled observations keep both. Historical Tool context stays untrusted; the full intent, limits and receipt stay canonical. Plain or malformed output stays an untrusted string. No result or catalog becomes instructions or authority, and inspecting a file produces no edit receipt. The primary Tool set never changes within a Run.

A Guard preparation, bootstrap or resource-limit failure before dispatch records Failed or Limit without a receipt and with its typed Guard stage, proving nothing was dispatched; like the typed [`guard_bootstrap` cause](./host-commands.md#enforcement-failure-causes), it is delivered once to the next model decision under the [Run outcomes](../execution/events-and-outcomes.md#accepted-outcomes) and never retried. An unattested Guard failure without that proof stops the Run with no further model call; strict replay rejects any continuation after it. An attested ordinary Failed result may continue. Once the GO write begins, a missing completion is Uncertain, even after a partial write. There is no unconfined fallback. Old failures are previous-Run facts, not pending Tools; a fresh request may propose a newly authorized edit with fresh preconditions, never reusing an old intent or approval.

[Execution](../execution/events-and-outcomes.md#committed-event-stream) owns effect ordering. An interrupted or [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) effect stops the loop; inspect `arany show --output text SESSION_ID`, the private JSONL export and the files before retrying by hand. Replay, resume, fork and compaction carry past Tool facts only as untrusted context and never renew permission. JSONL is a sensitive-data export. [Execution admission](../execution/admission-and-recovery.md#admission-persistence-and-recovery) owns Event headroom, locking and fork quotas; logical headroom reserves no disk and does not remove crash or disk-fault uncertainty.
