# Tools: command inputs, changesets and checkpoints

## Command input selection

Linux primary guarded commands read each admitted directory through a private Workspace overlay; exact file grants are read-only binds. Reads include gitignored files, dependency directories and inputs above [1 MiB](../limits.md#max_file_bytes) within directory grants; ignore rules do not limit Linux overlay reads. Changes, deletions, deduplication and candidate limits follow [Linux overlay publication](#linux-overlay-publication). macOS uses the disposable-copy selection below.

### Linux overlay visibility

The supervisor inventories each read-only lower clone without dependency or ignore pruning and without following links. Protected names present at launch are masked at any depth. A protected name created or renamed into the live lower tree during execution may be visible but is never publishable, because bubblewrap masks paths collected at launch. Masks are empty or inert and read-only. A protected symlink masks its bounded canonical target and enclosing directory; unresolved, cyclic, outside-view or unpinnable targets mask the enclosing directory. Special and set-ID entries are masked. A regular-file hard link to a protected inode found by the walk refuses launch. Ordinary symlinks and hard links stay visible; symlinks resolve only within admitted mounts.

Discovery shares the command entry, path-metadata, depth and preparation-time bounds. Unreadable or over-depth directories are masked whole. Exhausted entry, path or mask-argument space masks the enclosing subtree, up to the root, so no unscanned branch stays visible. A deadline or report/mountinfo bound that prevents installing and attesting masks refuses before GO. Masks reveal names and existence. No coherent snapshot of concurrent external lower mutation is promised. Hard-link aliases outside the grant, or to protected content in an unwalked or masked subtree, are not detected; no alias confidentiality is claimed.

The whole-root `["."]` grant uses one overlay. Narrow grants expose only their directory overlays and single-link read-only file mounts (hard-linked file grants refuse) under empty parents at `/workspace`; no ancestor or sibling tree is mounted. The parent tmpfs is read-only after setup, with a byte ceiling from the [command path-metadata allowance](../limits.md#command_path_metadata_bytes) and an inode ceiling of grant count times [command depth](../limits.md#command_snapshot_depth) plus its root. Both namespace owners attest every grant, mask and parent mount and reject unexpected submounts. Directory uppers share one pinned project tmpfs allowance, and scan, selection and candidate budgets are aggregate across grants. The mask argument envelope ([`MASK_ARGUMENT_BYTES`](../../../crates/arany/src/tools/guard/linux/overlay/masks.rs)) is bounded by grant count and path length. Root identities and no-follow admission are rechecked before GO and capture, so replacement refuses. Only ignore controls inside admitted directory grants apply. For a `src` grant, a root `.gitignore` rule `src/gen/` does not discard `src/gen/` outputs; put `/gen/` in `src/.gitignore` instead. Unlike [disposable-copy selection](#disposable-copy-selection), Linux narrow grants need no ancestor controls.

### Linux overlay publication

The launch inventory records each visible path's device, inode, size, modification and change times, type and executable bits. Complete directories establish absence for unlisted names; masked or incomplete ones never do. Frozen launch controls and fixed dependency rules select publication independently of read visibility. Nested controls in excluded directories are skipped and cannot re-include them. In the selection counts, `ignored_entries` counts inventoried ignored and dependency entries, `pruned_directories` and `oversized_inputs` are zero, and `discarded_outputs` counts safe upper entries discarded by the frozen rules, including changes to existing ignored paths. Masks and identical copy-ups count as neither.

After bwrap exit, pidfd wait and reap, the capability-free supervisor validates the whole upper through no-follow handles before reading content. It may restore owner read/search bits on mode-000 entries, never executable bits. Touched paths and their parents must match launch lower identities or recorded absence; lower metadata is checked around bounded reads, and that lower object supplies the digest-bound `before` bytes. Any mismatch rejects the whole candidate. The in-process publisher rechecks these preconditions before writing.

Safe ignored and dependency creates, edits and deletions are discarded unread, including character-device 0/0 whiteouts and `opaque=y` under ignored directories. Links, other devices, set-ID, protected paths and unsupported metadata reject even under ignored paths. Only bounded kernel `origin`, `impure`, `uuid` and directory `opaque=y` attributes are accepted; redirects, metacopy, unknown private attributes, xattr whiteouts and `opaque=x` refuse (a supported-format limit, not a claim that kernels never produce them). Other attributes, such as SELinux, POSIX ACL and user attributes, are ignored and never published. A 0/0 whiteout over a baseline regular file is a deletion with the same lower identity and digest checks as an edit. Directory whiteouts and `opaque=y` remove hidden baseline regular files and keep recreated upper files as edits or creates; an affected baseline entry that is neither a regular file nor a directory refuses with `Path`, even when ignored. Capture compares every affected baseline entry and complete directory with the current lower before and after building the candidate; new, removed or changed entries, masked descendants and incomplete inventories conflict instead of becoming deletions. Frozen ignored files stay unpublished, and inferred ignored deletions count as discarded. Empty directories produce no change; file/directory type conversions refuse.

Before retained-file, content or changeset caps apply, copy-ups with identical content and executable bit are dropped. Comparison checks lower identity around reads and shares an aggregate allowance of the project upper allowance times [`COMMAND_COMPARE_BYTES_PER_UPPER_BYTE`](../limits.md#command_compare_bytes_per_upper_byte); exceeding it refuses the candidate. Changed files, including executable-only changes and deletions, count toward the candidate caps. Entry and path-metadata budgets charge each upper entry and baseline subtree descendant once, including ignored ones. Opened lower directories must match the baseline; unknown entries, open failure or drift conflict. Subtree deletions share the changeset caps.

Storage exhaustion preserves the command's exit and output. After positive cleanup, bounded valid partial writes may publish even after ENOSPC; unsafe or over-limit candidates, conflicts, timeout and cancellation publish nothing.

During capture, after positive descendant absence, the cgroup memory ceiling is the smaller of the payload allowance and [512 MiB](../limits.md#memory_bytes) plus its verified retained `shmem` charge. Capture cannot grow those tmpfs files; other unit memory stays within [512 MiB](../limits.md#memory_bytes), and CPU and process limits return to the selection envelope. Malformed or out-of-bound accounting fails closed.

### Disposable-copy selection

macOS primary commands select disposable-copy inputs by pattern. Root and nested `.gitignore` files apply in directory order with ordered negation, case-sensitive matching and parent pruning; a descendant rule cannot reopen an excluded parent. Selection is pattern-only, includes tracked-but-ignored files and never reads the Git index. Fixed protected names, dependency-directory exclusions and the command grant dominate; negations never disclose protected names such as environment, Git and credential paths. There is no `.ignore`, `.rgignore`, parent or global ignore, Git configuration or `.git/info/exclude` discovery. An ignored control still supplies rules when its directory is reached, without becoming payload-visible.

Controls are bounded UTF-8 regular single-link files admitted through no-follow, no-mount-crossing directory handles, and must lie inside the command grant and depth. The matcher uses pinned `ignore = "=0.4.33"` (`GitignoreBuilder::new`, `add_line`, `build`, `matched`) and never walks the filesystem or reads global, parent or repository configuration. Missing controls mean no rules. Unsafe, inaccessible, oversized, non-UTF-8 or malformed required controls, replacement and resource exhaustion refuse preparation before copying; invalid data reports `Path` and exceeded bounds report `Limit`. The invocation freezes control bytes and selection; replay never loads controls. Entries are classified through their admitted parent without following links, and exclusions apply before opening. Excluded symlinks, special files and hard links are omitted; unexcluded ones refuse preparation. Output validation stays mandatory for ignored paths. Safe inputs above [1 MiB](../limits.md#max_file_bytes) are omitted unread; exactly [1 MiB](../limits.md#max_file_bytes) is admitted, and growth during a bounded read rejects rather than truncates. An omitted input is never a deletion; a replacement at an omitted path rejects capture, and publication separately checks absent-file preconditions and safe parents.

Parsing and walking run inside the native unit with a [512 MiB](../limits.md#memory_bytes) phase envelope, even for Build. macOS supervises the whole coalition during preparation and capture, keeps control data outside the payload's Seatbelt grants and captures before removing the unit root. Selection limits apply only in the SELECT and capture phases; other phases use the intent limits, and the inner supervisor owns payload resource outcomes. Capture CPU is not charged to the payload: after descendant absence the supervisor's CPU counter is pinned, its 15-second CPU bound counts only later work, a regressed counter is rejected, and no credit transfers to another process.

Selection and payload share one command runtime; the payload gets what remains. macOS starts it when disposable volumes are ready; earlier setup stays inside the action deadlines. Deadlines are monotonic expiries capped by the action deadline; delivery and GO never restart them. Cancellation stops an in-flight compile or match wait and keeps ownership until cleanup. The selection summary records elapsed milliseconds, or null when unavailable. Capture stays inside the completion deadline and maximum command timeout and keeps a one-second report window, shortening its work deadline as needed; insufficient time refuses capture. Capacity waiting, including recovery and the ticket lifetime, is at most 30 seconds<!-- unrelated-bound: native capacity waiting deadline -->. SELECT preserves changed-input, configuration, operation, missing-path and grant-denial errors. Resource, expansion or call overflow is `Limit(resource)`; elapsed selection time is `Limit(timeout)`. There is no unguarded fallback or retry.

Linux overlays keep private bounded writes and launch masks, and macOS keeps disposable copies. Ignore rules select copy inputs only. Host changes still need validated changesets.

## Command changesets

After completion and positive descendant termination, the Guard compares the private view with its input and returns a sorted changeset of created, modified and deleted regular files with digest-bound before and after bytes and executable bits; binary content is canonical base64. A nonzero exit may still return changes. A failed capture, timeout, cancellation or unconfirmed cleanup publishes nothing. Commands publish to the primary Workspace; editor commands publish nothing ([Editor Tool steps](./editors.md#editor-tool-steps)).

The whole output tree, including ignored directories, is structurally validated as it streams against the command's unchanged base (a copy-on-write clone of the selected copy on macOS, the host seed in Linux copy mode), holding only changed files; any refusal rejects the whole changeset before publication. For disposable copies, baseline membership wins over frozen ignore rules; Linux overlays also discard changes to existing ignored paths. Payload edits to controls affect only the next invocation. Ignored outputs are discarded unread. Oversized changed outputs or enlarged baseline files reject capture. The command result has a required `selection` field: `{ignored_entries, pruned_directories, oversized_inputs, discarded_outputs}`, or `null` when counts were not observed, shown as `selection counts unavailable`, never zero. Counts cover observed entries, inferred deletions and pruned roots, never uninventoried descendants, and carry no paths or content. Links (including hard links), special files other than supported Linux whiteouts, set-ID bits, protected, out-of-grant or invalid paths, mount crossings, type conversions and overflow reject the whole changeset. Directories are created only as parents of created files; empty-directory changes are not integrated. The ceiling is 64 files, 32 KiB<!-- unrelated-bound: command changeset decoded content cap --> decoded before and after content and 48 KiB canonical changeset JSON. Engine-generated integration has a [64 KiB](../limits.md#max_command_integration_argument_bytes) argument allowance; model Tool arguments stay at [16 KiB](../limits.md#max_ordinary_tool_argument_bytes). The Build class raises none of these.

The Engine records the observation, then creates a separate one-use integration intent bound to that receipt; models cannot request integration. Goal path scope and the write grant are checked first. An out-of-scope integration is journaled as `Denied` with no receipt or dispatch. In-scope integration goes through the in-process file publisher and never adopts subprocess-created host paths. A later command's snapshot includes integrated creates, modifications, deletions, executable bits and binary content. Approval cannot widen the grant: Auto edits accepts in-grant integration after command approval, Request approvals shows the sanitized changes and asks separately, and Auto approval reviews the integration and asks a human when uncertain. Headless Runs use their upfront grant. Plan revision cannot widen the Tool grant.

The publisher validates the whole batch, Workspace identity, every before digest, executable bit or absence precondition, and parent types through no-follow handles; conflict, denial or overflow changes nothing. It writes fresh regular inodes and syncs directories. A deletion first renames the leaf, no-replace and handle-relative, into an owner-only sibling directory, then rechecks inode, digest, executable bit and parent before unlinking. Drift restored without overwriting is Conflict if no earlier member published. An occupied restore destination is never overwritten; the entry stays under `.arany-remove-<id>/entry` for inspection. The batch is not atomic: unconfirmed restoration, deletion or sync, and failure or drift after a partial publication, are [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). Cancellation during approval changes nothing; during publication it may leave uncertain effects. Only a successful integration receipt proves publication.

Before dispatch, a command reserves Store and Event headroom for its observation, integration and terminal Run and Goal receipts, and context for the full integration argument and rendering; either shortfall prevents dispatch. Integration shares the Goal's active time and needs fresh authorization. The system-executable catalogue travels only through the trusted controller channel, never Workspace or payload input, and is never persisted as authority.

## Checkpoints and rewind

Store captures private pre-images for primary Write, Edit, MultiEdit, Delete, Move and every Workspace ApplyChangeset source, including an editor's one integration, after approval, through the Engine checkpoint gate before publication. Edits inside an editor's private workspace are not Workspace publications and have no checkpoint. A checkpoint is the position before a Run's first effect (prompts, Goal start or resume, autonomous Runs); steering notes create none. A file is saved on its first successful or Uncertain publication in a Run, and again when its before digest differs from its last successful after digest in that Run. Creates and gap-free repeats need no bytes; deletions save their before bytes. A failed publication never advances the chain.

Typed edits read pre-images through the admitted directory handle under the usual file bounds and verify the expected SHA-256; command and rewind integration use their validated before bytes. Capture commits before publication, and the publisher still rechecks the batch. A digest mismatch skips capture and leaves the publisher's conflict check in force. Not covered: Mkdir, MCP, commands themselves (integrated changes are covered), cache publication, scratch, host commands and external effects.

`StateRoot/checkpoints.sqlite` is a Store-owned derived store outside the Workspace and separate from the journal. It holds content-addressed `blobs(digest, bytes, len)` and `refs(session_id, goal_id, run_id, rewind_id, tool_sequence, path, digest, len, captured_at_ms)`. The sequence names the ToolStarted or WorkspaceRewindStarted; exactly one of run_id and rewind_id is set, and rewinds use the Session quota bucket. Blobs are deduplicated and SHA-256-verified on read. Refs never choose a restore destination: plans come from journal facts and look up blobs by journal digest. Strict replay never opens this store, reads the Workspace or re-executes a publication.

Storage uses private-file admission. SQLite runs defensive, with trusted_schema=OFF, synchronous=EXTRA and a page ceiling from the physical quota. Values and rows are capped at 1 MiB<!-- unrelated-bound: checkpoint SQLite value limit --> + 4 KiB<!-- unrelated-bound: checkpoint SQLite row overhead --> and SQL at 64 KiB<!-- unrelated-bound: checkpoint SQL statement limit -->; overflow makes storage unavailable. `user_version` is 1. At startup, a nonempty file at any other version, including a foreign SQLite database, is [archived intact with the journal](../execution/persistence.md#incompatible-history); a file SQLite cannot read stays as malformed storage. A hot `-journal` is recovered by SQLite under both exclusive locks before eligibility is re-read; a sidecar surviving recovery refuses as unsafe with every file untouched. Missing or empty storage initializes lazily. Newer or malformed schemas refuse before mutable pragmas or eviction; busy or unsafe storage is never archived. Capture failures keep storage and do not block the effect. An explicitly confirmed reset removes only a private malformed or unsupported store and its sidecars, under its exclusive lock, refusing if a file changed since the snapshot; busy, non-private or unsafe storage cannot be reset. The [terminal rewind panel](../terminal/commands.md#rewind) offers this recovery; there is no clear command or toggle.

| Bound | Limit | Overflow |
|---|---|---|
| Pre-image | 1 MiB<!-- unrelated-bound: checkpoint preimage cap --> | skip the whole publication with `too_large` |
| Path per owning Session | 32 versions and 32 MiB<!-- unrelated-bound: checkpoint path retention bytes --> logical bytes | evict oldest versions first |
| Goal | 256 MiB logical referenced bytes | evict oldest checkpoint refs, excluding the current Run |
| Session | 100 checkpoints with refs and 512 MiB<!-- unrelated-bound: checkpoint Session retention bytes --> logical bytes | evict the oldest checkpoint's refs, excluding the current Run |
| Store | 2 GiB<!-- unrelated-bound: checkpoint SQLite page ceiling --> SQLite pages including free pages, blobs and refs; 262,144 refs; remaining filesystem headroom | evict the least recently captured Session's oldest refs, excluding this publication; otherwise skip whole with `quota` |
| Retention | 30 days after the Session's latest capture; future-dated Sessions are eligible | sweep on Engine open and before capture |
| Publication capture | typed edit 1 MiB<!-- unrelated-bound: checkpoint typed edit capture -->; [command changeset limits](#command-changesets); an editor integration reads each pre-image from the Workspace under the typed edit bound | skip whole; no partial capture |
| Contention | 2 seconds shared by checkpoint-lock and SQLite contention | skip with `store_unavailable` |

Eviction is transactional: expired Sessions, then per-path, per-Goal, per-Session and total quotas, each in one ordered pass removing whole checkpoints; the physical-size pass targets twice the shortfall. Retention expiry commits separately, so it progresses even when capture is skipped. Unreferenced blobs are removed and pages reclaimed; a failed batch rolls back. The headroom check after eviction keeps 4 MiB free plus the incoming bytes and file growth. The Engine waits at most 3 seconds, and at least 1 second before the publication deadline; a later result is discarded as `skipped` with `store_unavailable`. Orphans from a crash before publication expire with the Session's refs. A removed ref whose digest survives through deduplication emits no notice. The first eviction per Run that loses a blob of this Session names its newest affected checkpoint: `Older checkpoints pruned; code restore unavailable before Run ID`. Other Sessions' prunes are never named here; a startup sweep's prune is reported at the Session's next capture.

[ToolFinished](../execution/admission-and-recovery.md#admission-persistence-and-recovery) has a required nullable `checkpoint`: null for non-publications and known non-dispatch, otherwise `{status: captured|not_needed|skipped, reason: null|quota|too_large|store_unavailable|digest_mismatch, pruned_before_run: null|RunId}`. `captured` requires an overwrite and a successful or Uncertain publication. `not_needed` covers creates, gap-free repeats and dispatched publications that changed nothing (failed, conflicted or denied), which never produce a rewind notice. A skipped capture still permits publication. Summaries and `show` show the reason (quota: `This change cannot be rewound (checkpoint storage full)`); JSONL keeps the field, and Goal reports keep it as a priority unresolved fact. Checkpoint bytes never enter model context, telemetry or diagnostics automatically.

Capture runs no Git and leaves `.git` untouched. Rewind never undoes Git writes or host effects: a preview with any Git write, host Git or unguarded host effect after the checkpoint shows one fixed line, `Git and host command changes are not undone`, instead of listing them, while MCP, cache and directory effects stay listed. Prior file contents are unencrypted private state, like the journal.

**Preview.** Engine::rewind_preview admits an idle Session under the operation slot, Session and ancestor locks and the Workspace writer lock. It checks the Workspace identity and reloads the current write grant or folder consent, never historical permission; current denies also exclude a path, and confirmation supplies any required human approval. It computes live digests and executable bits through the admitted directory capability and verifies needed blobs. Read-only or excluded paths are outside_grant; links, special files, mounts and case aliases are unsafe; missing, pruned or tampered blobs are unavailable. A preview carries no executable text or authority from restored bytes. Comparison data reuses the before/after versions up to 64 MiB<!-- unrelated-bound: rewind comparison decoded content --> of decoded content; beyond that it is marked unavailable without changing admission. Unsafe, outside-grant and unavailable paths disclose no content. Checkpoint-storage errors stay distinct from a missing blob so the terminal can offer recovery.

Live drift, history drift, an unavailable blob, an unsafe path or a grant exclusion refuses the whole batch by default and lists the paths. Two explicit selections produce a new preview: keep listed files and restore the rest, or overwrite drifted paths using their observed digest or absence as the new precondition. Unavailable, unsafe and outside-grant paths can only be kept; a live file above the 1 MiB<!-- unrelated-bound: checkpoint file version cap --> version bound is unsafe. Preview applies the publisher's path admission (ASCII, at most 16 components, whole-batch scan bound), so it never promises a restore the publisher refuses. Kept and overwrite selections are sorted, distinct, disjoint sets of at most 64 paths of at most 512 UTF-8 bytes each. An empty plan cannot restore. Open or Uncertain publications block code restore under the [Session contract](../session.md#rewind-planning-and-replay).

**Restore.** Engine::rewind consumes one opaque, non-cloneable preview as confirmation of that plan. It reacquires the locks and rechecks head and prefix, live state, blobs, grant and enforcement, refusing a changed preview before Started. A live, unchanged preview stays confirmable but cannot be renewed or reused. Before Started the Engine reserves two maximal Session Events; a capacity refusal changes nothing. The plan is capped at 32 MiB<!-- unrelated-bound: rewind restored content cap --> restored and 32 MiB<!-- unrelated-bound: rewind overwritten content cap --> overwritten content; file count, version size and transfer use the [changeset bounds](../execution/events-and-outcomes.md#worker-journal-protocol). Overflow refuses the action. Workspace contention returns WorkspaceBusy; an active Engine returns Busy.

Restoration is an internal Rewind publication source holding the plan digest and transfer length and digest, never a model Tool or ToolStarted source. Bytes are decoded and validated in process under the transfer bounds. After Started, the Engine tries to capture overwritten content under the rewind ID as the Before rewind checkpoint; Finished records the actual status, and a skipped capture still permits ordinary restoration. An explicit drift overwrite refuses before publication if its content could not be saved. Hooks never run. The publisher checks the whole batch before its first write and follows the capacity, deadline and uncertainty rules of [in-process file operations](./file-operations.md#in-process-file-operations), with no Guard unit. Cancellation before Started changes nothing; after Started it records cancelled when non-publication is known. A conflict lists only the paths whose live state, re-read after refusal, differs from the preview. An unconfirmed write or lost completion is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). Finished binds the intent and its in-process attestation digest to plan, Workspace and enforcement; historical Guard receipt digests keep their encoding. A missing Finished leaves an Uncertain prefix, and [Goal recovery](../goals.md#rewind-and-goal-recovery) owns the resume block. Conversation restoration and ordering follow the [Session contract](../session.md#conversation-rewind); the [terminal](../terminal/commands.md#rewind) and [serve](../serve.md#rewind) own controls.

Linux and macOS share one implementation. ASCII case-alias refusal applies on both, and case-insensitive APFS also refuses filesystem aliases. SQLite keeps the macOS durability settings with no F_FULLFSYNC claim. On WSL2, drvfs or /mnt/c executable-bit changes can appear as drift.
