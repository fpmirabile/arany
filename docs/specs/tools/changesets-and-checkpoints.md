# Tools: command inputs, changesets and checkpoints

## Command input selection

On Linux, primary guarded commands see each admitted directory through a private Workspace overlay and exact file grants read-only. They read gitignored files, dependency directories and inputs above [1 MiB](../limits.md#max_file_bytes) within directory grants: on Linux, ignore rules select only what publishes. macOS uses [disposable-copy selection](#disposable-copy-selection). On both, host changes need validated changesets.

### Linux overlay visibility

Protected names present at launch are hidden at any depth; one created or renamed into the Workspace during execution may be visible but never publishes. A protected symlink hides its target and enclosing directory, and an unresolvable one hides the enclosing directory. Special and set-ID entries are hidden, and a regular-file hard link to a protected file refuses launch. Ordinary symlinks and hard links stay visible; symlinks resolve only within admitted mounts.

Visibility discovery shares the command entry, path-metadata, depth and preparation-time bounds. An unreadable or over-depth directory is hidden whole, and exhausted bounds hide the enclosing subtree up to the root, so no unscanned branch stays visible; if the hiding cannot be installed and attested, the command refuses before GO. Hidden entries still reveal their names and existence. No coherent snapshot of concurrent external changes is promised, and hard-link aliases outside the grant, or into a hidden or unscanned subtree, are not detected.

The whole-root `["."]` grant uses one overlay. Narrow grants expose only their directories and single-link read-only files (hard-linked file grants refuse) under empty parents at `/workspace`, with no ancestor or sibling tree; scan, selection and candidate budgets are aggregate across grants. Replacing a granted root before GO or capture refuses. Only ignore controls inside admitted directory grants apply, so narrow grants need no ancestor controls: for a `src` grant, a root `.gitignore` rule `src/gen/` does not discard `src/gen/` outputs; put `/gen/` in `src/.gitignore` instead.

### Linux overlay publication

Ignore controls are frozen at launch and select publication independently of read visibility; nested controls in excluded directories cannot re-include them. Safe ignored and dependency creates, edits and deletions are discarded unread, including changes to existing ignored paths. Links, devices, set-ID entries, protected paths and unsupported metadata reject the candidate even under ignored paths, as do overlay redirects, metacopy and other unsupported overlay formats; SELinux, ACL and user extended attributes are never published.

In the `selection` counts, `ignored_entries` counts inventoried ignored and dependency entries, `pruned_directories` and `oversized_inputs` are zero, and `discarded_outputs` counts safe changes discarded by the frozen rules; hidden entries and unchanged copies count as neither.

A deleted baseline regular file publishes as a deletion under the same checks as an edit; deleting a baseline entry that is neither a regular file nor a directory refuses with `Path`, even when ignored. Every touched path and its parents must still match their launch state, and changed, added or removed entries, hidden descendants and incomplete inventories conflict instead of becoming deletions; any mismatch rejects the whole candidate, and the publisher rechecks before writing. Empty directories produce no change, and file/directory type conversions refuse.

Files rewritten with identical content and executable bit are dropped before the candidate caps, within a comparison allowance of the project upper allowance times [`COMMAND_COMPARE_BYTES_PER_UPPER_BYTE`](../limits.md#command_compare_bytes_per_upper_byte); exceeding it refuses the candidate. Changed files, including executable-only changes and deletions, count toward the candidate caps, and entry and path-metadata budgets charge every changed or deleted entry once, ignored ones included.

Storage exhaustion preserves the command's exit and output. After confirmed cleanup, bounded valid partial writes may publish even after ENOSPC; unsafe or over-limit candidates, conflicts, timeout and cancellation publish nothing. Capture memory stays within [512 MiB](../limits.md#memory_bytes) beyond the payload's retained files.

### Disposable-copy selection

macOS primary commands select disposable-copy inputs by pattern. Root and nested `.gitignore` files apply in directory order with ordered negation, case-sensitive matching and parent pruning; a descendant rule cannot reopen an excluded parent. Selection is pattern-only, includes tracked-but-ignored files and never reads the Git index. Fixed protected names, dependency-directory exclusions and the command grant dominate, so negations never disclose protected names. There is no `.ignore`, `.rgignore`, parent or global ignore, Git configuration or `.git/info/exclude` discovery. An ignored control still supplies rules when its directory is reached, without becoming payload-visible.

Controls must be bounded UTF-8 regular single-link files inside the command grant and depth; missing controls mean no rules. Unsafe, inaccessible, oversized, non-UTF-8 or malformed controls, replacement and resource exhaustion refuse preparation before copying: invalid data reports `Path` and exceeded bounds report `Limit`. The invocation freezes control bytes and selection, and replay never loads controls. Exclusions apply before opening; excluded symlinks, special files and hard links are omitted, and unexcluded ones refuse preparation. Output validation stays mandatory for ignored paths. Safe inputs above [1 MiB](../limits.md#max_file_bytes) are omitted unread, exactly [1 MiB](../limits.md#max_file_bytes) is admitted, and growth during a read rejects rather than truncates. An omitted input is never a deletion; a replacement at an omitted path rejects capture.

Selection and capture run within a [512 MiB](../limits.md#memory_bytes) envelope, even for Build, and their CPU is not charged to the payload. Selection and payload share one command runtime, the payload getting what remains; delivery and GO never restart deadlines, and cancellation stops selection while keeping ownership until cleanup. The selection summary records elapsed milliseconds, or null when unavailable. Capture stays inside the completion deadline and maximum command timeout, keeping a one-second report window; insufficient time refuses capture. Waiting for native capacity, including recovery, is at most 30 seconds<!-- unrelated-bound: native capacity waiting deadline -->. Selection preserves changed-input, configuration, operation, missing-path and grant-denial errors; resource, expansion or call overflow is `Limit(resource)` and elapsed selection time is `Limit(timeout)`. There is no unguarded fallback or retry.

## Command changesets

After completion and confirmed descendant termination, the Guard returns a sorted changeset of created, modified and deleted regular files with digest-bound before and after bytes and executable bits; binary content is canonical base64. A nonzero exit may still return changes. A failed capture, timeout, cancellation or unconfirmed cleanup publishes nothing. Commands publish to the primary Workspace; editor commands publish nothing ([Editor Tool steps](./editors.md#editor-tool-steps)).

The whole output tree, including ignored directories, is validated against the command's unchanged base; any refusal rejects the whole changeset before publication. For disposable copies, baseline membership wins over frozen ignore rules. Payload edits to controls affect only the next invocation. Ignored outputs are discarded unread. Oversized changed outputs or enlarged baseline files reject capture. Links (including hard links), special files, set-ID bits, protected, out-of-grant or invalid paths, mount crossings, type conversions and overflow reject the whole changeset. Directories are created only as parents of created files; empty-directory changes are not integrated. The ceiling is 64 files, 32 KiB<!-- unrelated-bound: command changeset decoded content cap --> decoded before and after content and 48 KiB canonical changeset JSON. Engine-generated integration has a [64 KiB](../limits.md#max_command_integration_argument_bytes) argument allowance; model Tool arguments stay at [16 KiB](../limits.md#max_ordinary_tool_argument_bytes). The Build class raises none of these.

The command result has a required `selection` field: `{ignored_entries, pruned_directories, oversized_inputs, discarded_outputs}`, or `null` when counts were not observed, shown as `selection counts unavailable`, never zero. Counts cover observed entries, inferred deletions and pruned roots, never uninventoried descendants, and carry no paths or content.

The Engine then creates a separate one-use integration intent bound to the command's receipt; models cannot request integration. Goal path scope and the write grant are checked first; an out-of-scope integration is journaled as `Denied` with no receipt or dispatch. Integration goes through the [in-process file publisher](./file-operations.md#in-process-file-operations) and never adopts subprocess-created host paths, and later commands see its result. Approval and plan revision cannot widen the grant. Auto edits accepts in-grant integration after command approval, Request approvals shows the sanitized changes and asks separately, Auto approval follows [auto-approved Workspace edits](./trust-and-approvals.md#auto-approved-workspace-edits), and headless Runs use their upfront grant. Integration shares the Goal's active time, and a command that cannot reserve room for its observation, integration and final receipts does not dispatch.

The publisher validates the whole batch, Workspace identity and every before digest, executable bit or absence precondition first; conflict, denial or overflow changes nothing. A deletion rechecks the file before removing it; drift restored without overwriting is Conflict if no earlier member published, and an occupied restore destination is never overwritten, leaving the entry under `.arany-remove-<id>/entry` for inspection. The batch is not atomic: unconfirmed restoration, deletion or sync, and failure or drift after a partial publication, are [Uncertain](../execution/events-and-outcomes.md#effect-outcomes). Cancellation during approval changes nothing; during publication it may leave uncertain effects. Only a successful integration receipt proves publication.

## Checkpoints and rewind

Arany saves private pre-images for primary Write, Edit, MultiEdit, Delete, Move and every Workspace changeset integration, including an editor's one integration, after approval and before publication. Edits inside an editor's private workspace have no checkpoint. A checkpoint is the position before a Run's first effect (prompts, Goal start or resume, autonomous Runs); steering notes create none. A file is saved on its first successful or Uncertain publication in a Run, and again when its before digest differs from its last successful after digest in that Run. Creates and gap-free repeats need no bytes; deletions save their before bytes. A failed publication never advances the chain. A pre-image whose digest does not match the expected one is not saved, and the publisher's conflict check still applies. Not covered: Mkdir, MCP, commands themselves (integrated changes are covered), cache publication, scratch, host commands and external effects.

`StateRoot/checkpoints.sqlite` is a private derived store outside the Workspace and separate from the journal, with deduplicated, SHA-256-verified content. Restore destinations come only from journal facts, never from this store, and strict replay never opens it, reads the Workspace or re-executes a publication. At startup, a nonempty store of another format, including a foreign SQLite database, is [archived intact with the journal](../execution/persistence.md#incompatible-history); a file SQLite cannot read stays as malformed storage, and a leftover sidecar that recovery cannot clear refuses as unsafe with every file untouched. Missing or empty storage initializes lazily. Newer or malformed schemas refuse; busy or unsafe storage is never archived. Capture failures keep storage and never block the effect. An explicitly confirmed reset removes only a private malformed or unsupported store and its sidecars, refusing if a file changed since the snapshot; busy, non-private or unsafe storage cannot be reset. The [terminal rewind panel](../terminal/commands.md#rewind) offers this recovery; there is no clear command or toggle.

| Bound | Limit | Overflow |
|---|---|---|
| Pre-image | 1 MiB<!-- unrelated-bound: checkpoint preimage cap --> | skip the whole publication with `too_large` |
| Path per owning Session | 32 versions and 32 MiB<!-- unrelated-bound: checkpoint path retention bytes --> logical bytes | evict oldest versions first |
| Goal | 256 MiB logical referenced bytes | evict oldest checkpoint refs, excluding the current Run |
| Session | 100 checkpoints with refs and 512 MiB<!-- unrelated-bound: checkpoint Session retention bytes --> logical bytes | evict the oldest checkpoint's refs, excluding the current Run |
| Store | 2 GiB<!-- unrelated-bound: checkpoint SQLite page ceiling --> SQLite pages including free pages, blobs and refs; 262,144 refs; remaining filesystem headroom | evict the least recently captured Session's oldest refs, excluding this publication; otherwise skip whole with `quota` |
| Retention | 30 days after the Session's latest capture; future-dated Sessions are eligible | sweep on Engine open and before capture |
| Publication capture | typed edit 1 MiB<!-- unrelated-bound: checkpoint typed edit capture -->; [command changeset limits](#command-changesets); an editor integration reads each pre-image from the Workspace under the typed edit bound | skip whole; no partial capture |
| Contention | 2 seconds shared by checkpoint-lock and SQLite contention | skip with `store_unavailable` |

Eviction removes whole checkpoints in order (expired Sessions, then per-path, per-Goal, per-Session and total quotas) and rolls back on failure; retention expiry progresses even when capture is skipped. After eviction, capture keeps 4 MiB free plus the incoming bytes. The Engine waits at most 3 seconds, and at least 1 second before the publication deadline; a later result is discarded as `skipped` with `store_unavailable`. The first eviction per Run that loses content of this Session names its newest affected checkpoint: `Older checkpoints pruned; code restore unavailable before Run ID`. Other Sessions' prunes are never named, and a startup sweep's prune is reported at the Session's next capture.

[ToolFinished](../execution/admission-and-recovery.md#admission-persistence-and-recovery) has a required nullable `checkpoint`: null for non-publications and known non-dispatch, otherwise `{status: captured|not_needed|skipped, reason: null|quota|too_large|store_unavailable|digest_mismatch, pruned_before_run: null|RunId}`. `captured` requires an overwrite and a successful or Uncertain publication. `not_needed` covers creates, gap-free repeats and dispatched publications that changed nothing (failed, conflicted or denied), which never produce a rewind notice. A skipped capture still permits publication. Summaries and `show` show the reason (quota: `This change cannot be rewound (checkpoint storage full)`); JSONL keeps the field, and Goal reports keep it as a priority unresolved fact. Checkpoint bytes never enter model context, telemetry or diagnostics automatically.

Capture runs no Git and leaves `.git` untouched. Rewind never undoes Git writes or host effects: a preview with any Git write, host Git or unguarded host effect after the checkpoint shows one fixed line, `Git and host command changes are not undone`, instead of listing them, while MCP, cache and directory effects stay listed. Prior file contents are unencrypted private state, like the journal.

**Preview.** Preview needs an idle Session and the Workspace writer lock. It checks the Workspace identity and the current write grant or folder consent, never historical permission; current denies also exclude a path, and confirmation supplies any required human approval. Read-only or excluded paths are outside_grant; links, special files, mounts and case aliases are unsafe; missing, pruned or tampered content is unavailable. A preview carries no executable text or authority from restored bytes. Comparison data covers up to 64 MiB<!-- unrelated-bound: rewind comparison decoded content --> of decoded content; beyond that it is marked unavailable without changing admission. Unsafe, outside-grant and unavailable paths disclose no content. Checkpoint-storage errors stay distinct from missing content so the terminal can offer recovery.

Live drift, history drift, unavailable content, an unsafe path or a grant exclusion refuses the whole batch by default and lists the paths. Two explicit selections produce a new preview: keep listed files and restore the rest, or overwrite drifted paths using their observed digest or absence as the new precondition. Unavailable, unsafe and outside-grant paths can only be kept; a live file above the 1 MiB<!-- unrelated-bound: checkpoint file version cap --> version bound is unsafe. Preview applies the publisher's path admission (ASCII, at most 16 components, whole-batch scan bound), so it never promises a restore the publisher refuses. Kept and overwrite selections are sorted, distinct, disjoint sets of at most 64 paths of at most 512 UTF-8 bytes each. An empty plan cannot restore. Open or Uncertain publications block code restore under the [Session contract](../session.md#rewind-planning-and-replay).

**Restore.** Restore consumes one preview as confirmation of that plan, rechecking history, live state, content, grant and enforcement and refusing a changed preview before Started; a preview cannot be renewed or reused. The plan is capped at 32 MiB<!-- unrelated-bound: rewind restored content cap --> restored and 32 MiB<!-- unrelated-bound: rewind overwritten content cap --> overwritten content; file count, version size and transfer use the [changeset bounds](../execution/events-and-outcomes.md#worker-journal-protocol). Overflow refuses the action, and a journal capacity refusal changes nothing. Workspace contention returns WorkspaceBusy; an active Engine returns Busy.

Restoration is an internal publication, never a model Tool, and hooks never run. After Started, the Engine tries to save overwritten content as the Before rewind checkpoint; Finished records the actual status, and a skipped save still permits ordinary restoration, but an explicit drift overwrite refuses before publication if its content could not be saved. Restoration follows the capacity, deadline and uncertainty rules of [in-process file operations](./file-operations.md#in-process-file-operations). Cancellation before Started changes nothing; after Started it records cancelled when non-publication is known. A conflict lists only the paths whose live state, re-read after refusal, differs from the preview. An unconfirmed write or lost completion is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes); a missing Finished leaves an Uncertain prefix, and [Goal recovery](../goals.md#rewind-and-goal-recovery) owns the resume block. Conversation restoration and ordering follow the [Session contract](../session.md#conversation-rewind); the [terminal](../terminal/commands.md#rewind) and [serve](../serve.md#rewind) own controls.

Linux and macOS behave alike. ASCII case-alias refusal applies on both, and case-insensitive APFS also refuses filesystem aliases. There is no F_FULLFSYNC durability claim on macOS. On WSL2, drvfs or /mnt/c executable-bit changes can appear as drift.
