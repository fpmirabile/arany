# Run execution

## Scope and related contracts

This contract owns bounded Run coordination, delegation, accepted outcomes and history-capacity rejection. The [Goals contract](./goals.md) owns durable task lifecycle, Goal budgets, plan contracts and recovery; every accepted task links its Runs to one Goal. [Tools](./tools.md) owns grants and effect continuations; [terminal](./terminal.md) owns attached controls and agent inspection. Session lifecycle and Provider admission stay in the [Session](./session.md) and [Provider](./provider.md) contracts.

Editing constraints: [security rules](../../agents/security.md).

## Committed Event stream

`Journal::append` feeds clients, telemetry and diagnostics only after Event commit. Each subscriber receives committed envelopes through a 256-envelope broadcast ring. Lag produces `Resync { missed }`; the subscriber recovers from the committed view without blocking execution. Subscriber failure or lag cannot change a Run outcome or grant authority. Provisional Provider previews remain separate from this stream.

## Collaboration

Each accepted task is durably linked to a Goal before its first `MessageAccepted`. Each Run has one accountable primary AgentRun and an ordered, bounded collection of direct researcher and EditOnly children. Children cannot create nested teams; only EditOnly children may mutate their private assignment views. In a Run with a Tool runtime each researcher is read-only: its spawn pins the `read_only` grant, while each EditOnly child works under its pinned private assignment grant. A researcher may alternate calls with Workspace List/Read/Search, admitted Skill reads and MCP catalog listing, within the Goal plan contract, before returning its bounded report. Before any plan contract a researcher may read any admitted Workspace path, as the primary prelude may; MCP catalog listing starts the admitted stdio server under the Guard. Without a Tool runtime a child makes one reasoning call. A researcher failure, including one out-of-grant MCP call, fails the Run and drains every sibling. An editor failure remains local as specified below. The primary obtains file evidence, performs authorized effects and owns the final answer. Goal completion and Run completion are separate receipts as defined by the [Goal lifecycle](./goals.md#lifecycle-budgets-and-recovery).

Pin one policy before the Run: `single` admits no children; default `auto` allows up to three total direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The persisted `max_active_children` field limits total direct assignment attempts across the Run, including researchers, failed captures, replacements and later waves. Policy, process safety and remaining call, token, byte and time budgets bound team size; the pinned primary and child Provider concurrency ceilings separately bound simultaneous calls while admitted children wait in order. A ceiling is permission, not a required team size.

Auto guidance asks the primary to keep routine edits and simple inspection local, delegate substantial independent work only when its benefit justifies extra calls, and choose the smallest useful team. Typed policy and budgets enforce capacity; guidance does not guarantee every model's judgment. Agent inspection distinguishes the current or last Run from historical agents rather than presenting accumulated history as simultaneous activity.

Child authority is the intersection of global policy, parent effective authority and the explicit task grant. Children cannot self-approve or alter sibling authority, and missing configuration never restores a capability.

Child identities and assignments retain ordinal order even when calls finish out of order. Synthesis receives committed reports in assignment order; background coordination includes explicit pending identities without provisional child text. Researcher failure drains siblings before primary failure. Cancellation reaches every admitted child and preserves already observed calls and terminal facts.

A delegation abort preserves its original failure when sibling draining also fails; the drain failure is diagnostic only.

## Researcher children

One delegation active-time segment covers child calls and child Tools, including their shared Guard capacity waits. Pause also takes effect before each child step.

Read-only research steps of child AgentRuns keep Child Tool facts in the child's own agent view; the primary's run view and its plan rules are unchanged.

| Bound | Value | Overflow |
|---|---|---|
| Children per delegation | existing policy, ≤ 8 | invalid delegation |
| Child objective / report | 2 KiB objective; 16 KiB result, 2 KiB summary | invalid response, child Failed |
| Child Tool calls | `min(16, ((remaining calls − children − 1) / 2) / children)`, 16 if calls are unlimited; replay cap 16 | catalog `tool_calls_remaining: 0`, only Finish offered; a further Tool is an invalid response |
| Child Tool result | `min([Tool result ceiling](tools.md#limits-and-failure-behavior), (context limit − context − intent − 512) / 6)`; Tools offered only while at least 4.6 KiB fits | only Finish offered; safety net stops the child |
| Delegation time | one active segment, at most 20 min and at most the remaining Goal active time | calls time out, child Failed, Run fails |
| Child Tool time | runtime at most half of (deadline − preparation − cleanup − Store overhead); the Guard capacity wait ends at `expires_at_ms` = start + runtime (Guard returns `Limit` before dispatch, Linux and macOS) | runtime 0: the child stops before `ToolStarted` |
| Events per delegation | child Events at most 928 (8 × (7 × 16 + 4)), admitted with an 8-Event tail plus configured route-switch bounds before the first spawn | Store admission refusal before `AgentSpawned` |
| Concurrency | Provider concurrency for calls; child Tools one at a time per Run | queued |

## Agent definitions

**Recorded owner decisions — 2026-10-18:** use only exact Workspace `.claude/agents/*.md` and the admitted private StateRoot `agents/*.md`, with private names winning; accept one strict Claude-format subset. No home, plugin, recursive or alternative-format discovery is admitted. The project directory must lie wholly inside the parent read grant. Missing directories are empty; unsafe present entries (symlinks, links, non-owned or oversized files, bad names) refuse the whole registry before any Provider call.

**Recorded owner decision, revisitable — invalid definitions are skipped, not fatal (peer behavior: Claude Code skips an invalid agent file and reports it):** a file whose content is invalid (bad frontmatter or field value, YAML anchor/alias/tag, size bounds, duplicate name within a source) is skipped with a bounded diagnostic naming the file and field, journaled in the parse receipt and shown in the Goal report evidence. Unsupported frontmatter fields (for example `color`, `hooks`, `mcpServers`) and unsupported tool names are ignored with a diagnostic; ignoring can only narrow authority. A `model` other than `inherit` that is not the exact admitted initial child model is treated as `inherit` with a diagnostic. The registry lists at most 8 KiB of base entries in name order; later definitions are dropped with a diagnostic. Foreground editor metadata adds its normalized digest and turn ceiling at Engine admission; if the complete agent catalog then exceeds 8 KiB, initialization fails before Provider disclosure. Selecting a skipped, dropped or absent name is an invalid delegation that fails the Run before any child spawn. Discovery is an immutable raw-byte snapshot during input preparation. [Parser admission](./tools.md#agent-definition-parser-admission) owns filesystem and Guard enforcement.

The envelope is Markdown with YAML frontmatter. `name` and `description` are required strings; the only optional fields are `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `isolation` and `background`. Duplicate or explicit-null fields, and wrongly typed or out-of-range values, make the file invalid (skipped). Names use lowercase ASCII letters, digits, `_` and `-`, at most 64 bytes. Description is nonempty and at most 2 KiB; body is at most 32 KiB. The body is labelled untrusted assignment guidance in the child's user input, never a system role. The primary receives bounded names and descriptions, without unselected bodies.

Tool lists accept comma-separated strings or string arrays, at most 32 names of 128 bytes each. `Read`, `Glob`, `Grep`, `Edit`, `Write` and `Skill` map to `read`, `list`, `search`, `edit`, `write` and `skill`; exact names for those operations plus `mkdir` and `mcp_list` are accepted. Unknown names, patterns, Bash, Agent, Git and MCP invocation are ignored with a diagnostic and grant nothing. Missing `tools` inherits the admitted catalog for the assignment kind; `disallowedTools` subtracts. An empty effective edit capability supplies no write authority.

**Recorded owner decision — model and mode overrides:** omitted model or `inherit` retains the complete parent-admitted child chain. Definition model metadata cannot override an assignment-selected profile. A literal model equal to its initial admitted child's exact model is kept; any other value cannot select a route, account, alias or credential lookup and is treated as `inherit`. The five [permission-mode spellings](./tools.md#modes-and-approval-decisions) can only narrow parent settings and live terminal restrictions, using Deny > Ask > Allow. File text never grants a capability or resolves an approval.

The primary's Delegate may select one registry name through `agent` for that group of researcher objectives; null or omission selects the existing default researcher. Selection is validated before any child spawn or call and pinned by the required nullable `AgentSpawned.definition`. A selected definition narrows the read-only catalog and can reduce child inference turns to 1–17 (`maxTurns`, default 17); Tool reviews do not consume inference turns. The existing maximum 16 model Tool requests and Goal headroom still apply. The last available turn offers Finish only. An extra Tool, unknown name or unsupported editor selection is an invalid delegation/child response and fails the C1 Run, without granting or dispatching the requested effect.

**Recorded owner decision — isolation:** `isolation: worktree` requests a disposable Guard view without `.git`, diverging from Claude Code's actual Git worktree because of Arany's hostile-Git and per-effect isolation guarantees. An editor definition requests this isolation; omitted `background` is `false`. A definition with `background: true` requires background assignment mode; a foreground default may be explicitly scheduled in either mode. A researcher group cannot select an editor through its group-level `agent` field.

`RunStarted.config.agent_definitions` is required nullable data: null for an empty/unavailable registry, otherwise the ordered source/filename/raw-digest pins and their SHA-256. Internal parser intents follow the primary spawn, in that exact order, before the first Provider reservation. A matching successful Guard observation fixes each closed normalized-v1 result, either a definition with notes or a skipped-file diagnostic. Private precedence applies after all documents are classified. Strict replay verifies these facts and model admission, requires every parser observation before Provider reservation, rejects late refresh or duplicate parsing, and never reruns a parser. Internal preparation is excluded from model Tool counts, history and compaction bodies; compaction `covered_tool_count` indexes the Run's Tool Events, with the leading parse steps counting as already covered. Interrupted parsing supplies no authority; a new Run requires fresh snapshots and Guard admission.

| Definition bound | Limit / overflow |
|---|---|
| Discovery | 256 scanned entries per source; 64 candidate Markdown files per source; 1 MiB aggregate raw bytes; whole refusal |
| File and normalized registry | 64 KiB per raw file; 1 MiB aggregate normalized records; existing Tool observation, Guard task, catalog and request ceilings may reject sooner; no truncation |
| YAML | 4096 nodes, depth 32; no aliases, anchors, tags or duplicate keys; an unterminated quote at a line end is refused; the file is skipped |
| Catalog | 8 KiB of agent entries; later names dropped with a diagnostic |

A Delegate decision admits one wave of mixed researchers and editors. Each proposal is validated in full before any child disclosure: malformed definitions, paths, overlapping leases, wave numbers or total-attempt overflow refuse the proposal. There are at most eight total attempts under explicit team policy and three under default auto. A replacement requires an explicit new Delegate decision, fresh ID, grant, base and lease; `supersedes` may name a terminal, released child of this Run. There is no automatic retry. Historical ID resume remains unavailable pending [slice 6](../../NEXT_STEPS.md#pursue-in-order).

The Engine pins worker concurrency at four by default, configurable only through Engine settings to 1–8, then narrows it by policy size and admitted Provider concurrency. A finite-token Goal serializes all Provider calls, including background primary coordination. Only available slots admit queued assignments and reserve calls; later assignments never spend calls while queued. Every pending assignment, completion and report collection is bounded by eight; one Tool remains pending per Run. Overflow refuses admission without dropping a member.

A worker retains at most 64 MiB of base plus current image, including conservative metadata allowance; the aggregate is at most 256 MiB. Above concurrency four the per-worker limit narrows to 256 MiB divided by the pinned concurrency, so oversized bases or edits fail before dispatch. The reducer checks the same limit. No native storage/profile limit is raised.

The coordinator consumes Provider completions in observed completion order, captures and commits each eligible handover and settles that queue head before polling the next completion. The committed handover sequence determines integration order, including conflict/discard; there is no ordinal or wall-clock sort. Reports retain assignment order independently. An ordinary editor failure, invalid outcome, private Tool failure or positively contained private uncertainty discards that actor's work and releases its lease while healthy siblings continue. A researcher failure remains fatal; unknown Workspace publication or unknown containment stops the entire Run.

Foreground children block primary coordination until their terminal settlement. Background children are children of this exact Run, never detached jobs: they permit primary RootSynthesis inspection and lease-disjoint typed edits while pending. While workers are active the primary is called once when coordination opens and again after each of its own Tool steps; after an answer it is called again only once a new worker has settled, never to poll. A primary Finish or text answer is deferred: the call is journaled as an invalid response, the Run continues, and the primary answers again after the workers settle with their results. A primary Delegate, or an edit overlapping a live lease, is refused the same way: no Tool intent is journaled, the Run does not fail and healthy workers continue, and the primary's next request carries a `last_answer_refused` note. Primary commands and MCP processes are held until every lease is released. A budget, cancel or pause stop during background coordination records one WorkerStopObserved, schedules no further work and drains to an honest terminal outcome. A stop is recorded only for Runs with editors; a researcher-only team never records one. Run closure cancels/drains all modes. Only committed child reports and pending IDs enter coordination context. Primary Finish and the next Delegate require all current assignments terminal, handovers settled and leases released, plus fresh passing verification for integrated/no-change assignments. Every successor wave captures the then-integrated Workspace; no DAG, restart or cross-Run lease is introduced.

## Worker journal protocol

Every EditOnly AgentRun uses the same `execute_step` and `before_dispatch` as the primary and researchers. A write-capable parent with admitted definitions pins a worker policy; Implementation and a committed Goal plan are required before a primary Delegate can select an editor. The Engine journals base capture before the spawn that acquires its lease, every private mutation and data seal before continuation, and guarded cumulative capture after observed Finish. Finish, handover eligibility, primary ApplyChangeset, integration disposition and lease release are separate committed facts. Worker private edits leave the Workspace unchanged until the primary's eligible integration. A no-change handover is discarded/released without publication and still requires fresh primary verification.

Before producing data, admission narrows the assignment's finite allowance to remaining serialized Store/Event headroom. Each later call, private Tool, capture and integration reserves its complete bounded action plus terminal tail. A known capacity refusal stops before dispatch; a failed append or acknowledgment stops advancement. The action bound is `N + 12 + (4*A + 6) + switches`, conservatively reserving all eight possible outstanding assignments (`A=8`), admitted chunk count `N`, and the configured review, child and primary switch slots. A whole candidate that cannot fit is refused, never split or partially published.

Private failure, denied approval, unavailable approval channel or a positively contained lost private receipt ends that actor, records its typed disposition and cleanup, discards unpublished work and releases the lease. The primary receives the local failure and may report the task's unresolved criterion. Goal budget, cancellation or pause is committed as WorkerStopObserved before further team decisions; no subsequent effect or handover eligibility is admitted. Conflict or a denied integration records a whole-batch prepublication refusal and discard/release; the primary then synthesizes with an honest local worker-failure report (nothing was published), and the lease counts as settled without verification, as in replay. An unknown Workspace publication records Uncertain and stops the entire Run, without release, retry or successful completion. Successful primary Finish requires fresh passing worker verification as well as the Goal criterion.

`RunStarted.config.worker_policy` is required nullable data. A non-null pin declares admitted parent read/write roots, the closed file/research Tool subset, Skill/server names, permission restriction, concurrency (1–8), turns (1–17), model Tools (0–16) and finite serialized data allowance (at most 48 MiB). Runtime pins the effective concurrency described above, 17 turns, 16 Tools and a 48 MiB maximum data allowance; policy total-attempt limits are unchanged. These are authenticated admission facts, never authority supplied by a definition, model, receipt or replay.

`ProviderCallRecorded.delegation` is required nullable: a nonempty, at-most-eight list exactly for Delegated, null otherwise. Its closed assignments distinguish researcher objective/nullable definition/nullable profile from editor definition/digest, mission, direction, sorted lease roots, typed criterion, foreground/background mode, turn ceiling, wave, and explicit nullable resumes/supersedes IDs. Researcher and editor wire requests normalize into this list; [Provider](./provider.md#scope-and-related-contracts) owns the offered envelope. Every spawn must match its exact proposal and ordinal. Total attempts, including later waves, cannot exceed the pinned policy limit. The reducer validates successor-wave and background-coordination ordering independently of runtime scheduling.

`AgentSpawned.assignment` is required nullable, null for primary and researchers and present exactly with `ChildGrant::EditOnly`. Its pins add the effective grant, parent policy/permission digests, exact committed base-manifest reference and remaining data allowance. Spawn acquires the fixed lease atomically. Editor admission requires Implementation, a valid committed Goal plan, a write-capable parent, a parsed matching definition and bounded prior base capture. Read/write/Tool/Skill/server restrictions intersect the parent, definition and Goal; permission modes independently narrow. A base manifest must cover leased creation/absence targets and contain only admitted read paths. An absent subtree root pins absence of its descendants as well as the named root. Names, model overrides and definition body retain the restrictions above.

Writable leases name 1–64 sorted relative files/subtrees of at most 512 ASCII bytes and depth 16. Backslashes, traversal, protected components, controls and non-ASCII writable paths reject. Ancestor/descendant and ASCII case-folded aliases conflict, including within one proposal. Reads retain Unicode-safe admission. Primary typed writes cannot overlap live leases, and primary commands/MCP processes wait for lease quiescence. Acquisition cannot silently replace another owner; there is no TTL or cross-Run lease.

Every Tool intent has `target: Workspace | WorkerView { assignment_id, base_digest, revision }`, included in its digest. Existing primary and researcher intents target Workspace. A private target must match its actor and current assignment revision. Successful private mutation requires a target-bound Guard receipt and a sealed complete before/after delta; revision advances once only after its matching committed observation. Private reads bind their intent and require the execution site's receipt. Workspace attestations cannot attest private work, and private attestations cannot prove Workspace publication or Goal success. Commands, unguarded commands, Git, MCP invocation and nested delegation cannot become worker capabilities.

Internal `PrepareWorker` admits only base or handover capture with an exact assignment ID, maximum bytes and chunk count. Base capture follows its open proposal before spawn; another capture cannot replace an unspawned preparation. Handover capture follows observed child Finish before AgentFinished. Preparation is excluded from model Tool counts and historical Tool bodies; there is no general blob/script API. One Tool remains pending per Run; only correlated data and seal records can complete its data production. Unsealed interrupted prefixes remain valid history and authorize nothing.

| Worker data bound | Limit | Rejection behavior |
|---|---|---|
| Changeset | 2,048 sorted regular files; 32 MiB decoded before plus after content combined; 1 MiB/file version; 48 MiB canonical serialized JSON | Reject the whole record at the first exceeded bound; no split publication |
| Base manifest metadata | 2,048 entries, 32 MiB declared file content, 3 MiB canonical serialized metadata | Reject unsupported entry kinds, protected paths, invalid digests, ordering or capacity |
| Chunk | 45 KiB raw, canonical base64, hash/length/ordinal, assignment, purpose and producing Tool ID; complete envelope ≤64 KiB | Reject changed, duplicate, oversized, trailing or out-of-order data |
| Transfer | At most 1,093 chunks for 48 MiB, or 69 for 3 MiB, then one seal | Exact ordered committed sequence range, count, length and SHA-256 must match |
| Private image | 2,048 entries/32 MiB content, 1 MiB/file, depth 16, 2,048 scanned entries; each transfer ≤48 MiB; retained base plus overlay content ≤64 MiB/assignment | Whole refusal before materialization; snapshots cannot widen the admitted read grant |
| Assignment metadata | Mission/direction 2 KiB each; criterion ≤8 KiB serialized under existing criterion limits; complete spawn/proposal Event ≤64 KiB including JSON escaping | Refuse rather than truncate |
| Verification | At most eight positive, strictly increasing primary observation sequence references | Reject private, stale, duplicate, unrelated or integration-only evidence |

Chunk and seal Events use SQLite schema 4, the [Session Event cap](#persistence-bounds) and the 256 MiB database limit, and normal Store headroom. The assignment's data allowance counts every sealed record and its pending bytes; nominal caps do not promise available capacity. Private typed changes are preflighted against the remaining allowance before GO. The [Tool contract](./tools.md#private-worker-targets-and-handover-transfer) owns per-action private storage, framing, native enforcement and disposal. Replay validates canonical JSON, closed fields, content hashes, base64 and independent decoded/serialized bounds. It retains bounded manifests, current overlay facts and exact sealed references; superseded mutation facts and incomplete private buffers supply no authority. An identical final cumulative delta may reuse a committed mutation seal through an attested handover capture without a second data charge. Bulk bytes never enter Provider input, progress or telemetry automatically. Command capture keeps its independent [changeset bound](./tools.md#command-changesets).

`AgentFinished.worker` is required nullable and present exactly for editors: ready, no_change, failed, cancelled, lost or private_uncertain, with a matching closed cause and exact nullable cumulative data reference. Ready/no-change require an observed Finish and validated cumulative data against the base and acknowledged overlay. Failure/loss requires a positive cleanup receipt bound to assignment/base/revision, enforcement and last intent before discard/release. Unknown private work stops that actor permanently; it never becomes Workspace uncertainty or authorizes a retry. C1 child failure still forbids successful synthesis; a settled failed editor does not abort healthy siblings in the replay model.

`WorkerStopObserved` records the first cancellation, pause or budget boundary before new team dispatch; duplicates reject. In-flight observations and disposal facts may drain, but no new spawn, call (including a pinned Provider fallback), Tool, eligible handover or integration starts past the marker. `WorkerHandoverRecorded` requires the exact Finished editor, matching sealed cumulative data and base, no stop, unknown private effect, previous handover, settlement or release. Its committed sequence determines the integration queue. Late/duplicate/ineligible publication rejects; historical closed Runs accept no new transitions.

`ApplyChangeset.source` is the closed `CommandReceipt { source_intent_digest, changeset } | WorkerHandover { assignment_id, handover_sequence, data }` union. Command integration preserves its immediately preceding attested command source and complete batch. Worker integration is primary-only, Workspace-targeted and consumes exactly the earliest eligible handover, even without a primary model Tool request. An observed integration must be recorded before another team decision; neither a missing integration Event nor a repeated delivery authorizes a second effect. `WorkerIntegrationRecorded` references its exact primary Tool ID/finished sequence and derives integrated/conflict/denied/uncertain from that observation and receipt. Denied also settles a known non-dispatched failed, limited or cancelled Tool with no attestation; the exact underlying Tool disposition is retained. Workspace publication uncertainty stops the whole Run and cannot release its lease as successful.

`WorkerHandoverDiscarded` and `WorkerLeaseReleased` name the assignment, explicit nullable handover, closed settlement reason and exact causal sequence. Release requires committed successful integration or terminal disposal/discard, never a report alone. No-change settles without an empty ApplyChangeset. After release, `WorkerVerificationRecorded` checks the pinned criterion digest against fresh primary Workspace observations, including intervening invalidations; reports, private receipts and integration alone cannot pass. Later Workspace mutations invalidate earlier worker verification. Successful primary completion requires every worker terminal and settled and every integrated/no-change criterion freshly passed. Goal completion still needs its separate criterion.

The foreground Engine Goal corpus is `crates/arany/tests/engine_run/goals.rs::foreground_worker_goal_refuses_editor_authority_without_a_write_capable_parent`; native publication, verification, budget, approval, capacity, conflict and uncertainty journeys are `crates/arany-cli/tests/guard_runs/worker.rs`. Closed SQLite replay, fresh-process text/JSONL and the Goal/Run receipt must agree.

The [worker reducer corpus](../../crates/arany/src/session/reducer/worker_tests.rs) owns decoded/current-format lifecycle, cold prefixes, parent intersection, overlap, revision/receipt/source rejection, stop, mixed C1/C2 outcomes, data limits, integration order and fresh verification. The [Store corpus](../../crates/arany/src/store/journal/tests.rs) owns file-backed cold reopen and byte-preserving refusal of old versions. Native/runtime evidence remains separate.

## Accepted outcomes

A journaled `stopped` result from a successful `PostToolUse`, `Stop` or `SubagentStop` hook terminates the Run as `stopped_by_hook`, distinct from success, failure and cancellation. The primary AgentRun has the same terminal disposition; a SubagentStop also terminates its child as `stopped_by_hook`, drains other children (they end Cancelled) and prevents synthesis. No further Provider reservation, Tool, spawn or hook may start in that Run; already reserved child calls are drained and recorded. No assistant Message is committed, and completed effects remain. The displayed optional reason is derived from the committed hook result, with the [Hook execution](./tools.md#hook-execution) reason bound; existing terminal/exec/serve outcome adapters escape and display it as user feedback, never model input. Diagnostics and telemetry use the closed stopped-by-hook disposition without the reason. The [Goal](./goals.md#lifecycle-budgets-and-recovery) stays open. Strict replay validates the recorded facts without executing the hook.

Every step produces exactly one phase-allowed semantic Finish, Delegate or enabled Tool proposal. A primary planning or synthesis call may carry the Run's accepted steering notes as user input; child calls and Tool review never do, and a pause takes effect only at the Goal boundaries that [Goals](./goals.md#steering-notes-and-pause) names. There is no fixed per-Run Tool-effect or model-step ceiling; each action still requires bounded Event, Store, request, context and terminal-tail admission, while the Goal's call, Run and active-time budgets bound the complete task. Before its first Goal plan contract, the primary may inspect with bounded Workspace List/Read/Search, typed Git reads, an admitted Skill read, or configured bounded MCP catalog listing in planning or synthesis; any other Tool proposal needs a valid contract before dispatch. A contract can accompany inspection and is still validated before dispatch. After a valid contract is recorded, the primary may continue through sequential Tool observations in planning or synthesis, with each operation still limited by the phase, exact plan scope and admitted Tool grant. Children receive Single policy; a researcher receives only the read-only research catalog, its own observations and Finish. Its MCP calls, writes, commands and plan contracts are invalid before dispatch; its reads outside the plan contract are journaled Denied without dispatch. Unknown operations, invalid arguments, unavailable catalog names and policy-incompatible outcomes reject without repair or an alternate encoding. The [Goal contract](./goals.md#initial-plan-contract-and-success-receipt) defines the exact scope and replay rules.

Tool-enabled OpenAI and ChatGPT primaries use strict native functions with required selection and parallel calls disabled; exactly one complete call is accepted. Final text, unknown, multiple or incomplete calls reject. Read-only requests, advisor children, compaction and Anthropic retain their admitted structured-text encoding. Researcher children use their route's Tool encoding restricted to read-only operations and Finish; it is offline-tested only, and live validation is listed in [next steps](../../NEXT_STEPS.md). Exact custom profiles reject Tool context before HTTP until tool-capable conformance is supported.

Structured-text Responses decoding joins ordered text parts exactly and requires one final structured outcome. Explicit commentary can precede it. The legacy absent or null phase is accepted only for an unambiguous single final. Refusal, malformed content, unknown phases, duplicate or ambiguous finals, late commentary and contradictory error or incomplete markers reject. Missing or invalid fields cannot be repaired by a later valid field.

All adapters reject reported input above the shared input ceiling and output above the exact request cap. Accepted outcomes also fit the exact serialized terminal payload bound, including JSON escaping. Native OpenAI may retain unknown usage; custom and ChatGPT outcomes require positive labeled usage. Native API-key and custom output caps are remote request controls; ChatGPT has a local acceptance cap and cannot guarantee remote generation or plan consumption. A Tool review uses Single policy with no Tools, history, includes or project instructions, its own 256-token cap rather than the ordinary final-answer cap, a 20-second ceiling, and the aggregate 32-call headroom. Uncertainty or failure asks a human and never grants a broader permission.

The selected Provider declares the primary output-token cap and the call deadline; the Run pins the cap in its configuration. Native OpenAI and Anthropic API routes declare 16,384 output tokens, and ChatGPT-plan and exact custom routes 4,096; replay rejects a pinned cap outside 1 to 16,384. Child calls request at most 4,096 tokens. Native OpenAI and Anthropic calls have a 600-second deadline; ChatGPT-plan and custom calls have 120 seconds. Each call also ends at the remaining Goal active time. A Tool review reserves 20 seconds plus Store overhead, compaction keeps its 120-second deadline, and a tool-free delegation reserves one deadline per wave of concurrent children, at most 20 minutes; a researcher delegation reserves 20 minutes. The useful answer ceiling stays at the 32 KiB assistant or result bound: the extra native output headroom is for reasoning tokens, and context budgeting reserves no output tokens.

The ChatGPT route's SSE parsing and item reconstruction rules are owned by the [ChatGPT contract](./chatgpt.md#catalog-checks-and-runs).

Malformed, non-object or duplicate-key MCP arguments, and selected-credential reflections including nested escaped arguments, reject before persistence. Provider failure remains the call's outcome even when an earlier Tool denial could otherwise be continued. Every route has zero same-route automatic retries or encoding fallback; only an explicitly configured, admitted [Provider fallback chain](./provider.md#per-role-selection-and-fallback) can switch destinations after an HTTP 5xx failure at status admission. A lost response can still consume remote usage.

## Admission, persistence and recovery

A `serve --stdio` process opens one Engine shared by all its loaded threads; the [serve contract](./serve.md) owns its client loop.

Persist only SQLite schema 4, compaction compiler version 3 and one current payload version per Event kind. Decision O5 (persistence): roster metadata and the agent-definition pin are required nullable `RunStarted` fields; keep role provenance and cross-validate it with the bounded snapshot. `AgentSpawned` requires the nullable selected definition, resolved profile reference and assignment pins; [worker journal records](#worker-journal-protocol) use one current typed format. No SQL change, migration, dual reader or replay-time configuration lookup.

A crash leaves a lifecycle hook open and unsettled: the next Run interrupts it as it does an open Tool hook, and it blocks Goal resume. ToolFinished requires the nullable [checkpoint outcome](./tools.md#checkpoints-and-rewind); v11 and missing fields reject unchanged. Required fields and nullable fields are explicit, including Goal linkage and budgets, Run configuration and its active deadline, Provider provenance, pinned Tool resource values and the required Tool cache-update outcome. Reading unsupported stored formats or missing fields rejects without conversion, automatic deletion or an optimistic projection. Replay rejects an accepted task without a valid Goal linkage; no unlinked legacy Run path or compatibility projection exists. The additive Run-scoped `GoalSteeringNoteRecorded` Event is part of payload version 6 and is accepted only inside the open primary provider reservation, as [Goals](./goals.md#steering-notes-and-pause) defines. A child Tool without its finished observation is interrupted history and blocks explicit resume. Attached startup offers the [explicit history reset](./terminal.md#setup-and-account-choices); it discards history rather than converting or admitting an unsupported format. Each Provider call record also journals `requested_tools` (one per declared model Tool request) and the cache-read and cache-creation usage beside the input total.

Admit every selected role Provider and configured fallback and the complete bounded request before Workspace disclosure. A task objective is at most 64 KiB of UTF-8; the attached composer and `arany --prompt` still limit a draft to 8 KiB, and steering notes keep their separate 8 KiB per-Run bound. Pin the Workspace, instructions and includes, policy, model, effort and caps for the Run. The `RunStarted` wall-clock timestamp precedes its append acknowledgement; `AgentSpawned` follows that acknowledgement. Commit accepted Message, Run and primary identity before inference; commit each observed call before its terminal AgentRun disposition. A failed call commits failure without an assistant Message. Replay requires an observed delegation before child spawn and an observed successful call before successful Agent completion. Known call usage survives an interrupted journal prefix.

`RunStarted` remains `{config, active_deadline_ms}`. `config.providers`, when present, pins four non-empty chains of complete identities. Its primary initial identity must agree with the existing primary config fields; the effective concurrency may narrow the declared ceiling. Without that field the fixed role defaults inherit the existing pinned primary identity with no default fallback; roster-selected children still use their named snapshot chains. This remains the canonical inherited role representation in the current payload. The Tool policy receipt also requires its nullable permissions digest and nullable unguarded-rules digest; unsupported previous versions reject. `ToolStarted` embeds the `command_unguarded` operation, `ToolFinished` adds the `unguarded` attestation and `ToolPermissionDecided` makes the settings mode nullable and adds the `exact_command_rule` source, all as the [unguarded re-run](./tools.md#unguarded-re-run-after-a-guard-failure) defines. Invalid provenance, inconsistent primary fields, missing role chains, redundant all-inherited chains, unsupported limits and incompatible Tool-role adapter/account chains reject replay.

`AgentSpawned.profile` is required nullable provenance, also retained in the reduced Agent view. Outside roster mode it is null. In roster mode the primary references its default and every child references an eligible profile, with null proposals already resolved. Replay rejects missing or forged references, role-ineligible spawns, a reservation before spawn, cross-profile switches and reported output above the actual selected identity's role cap. Calls, fallback, telemetry and replay derive the chain from actor plus role; review/compaction use their fixed roles. No identity copy or replay-time configuration/account lookup can rebind an actor.

`config.roster` is explicit null outside roster mode. Otherwise it pins the preset name, a domain-separated SHA-256 selection digest, profile-name-sorted named identity chains, four resolved role-default references and the ordered child allowlist. The digest covers normalized route Provider/model/effort/account tuples and membership, excluding expiring capability evidence and unrelated presets. Identities retain their full evidence separately. Replay independently validates names, counts, bounds, digest, references, reachability, duplicate/noncanonical entries, identity validity and exact agreement with `config.providers`, including its compact inherited representation. No Provider or account is contacted. Historical profile alternatives confer no executable authority.

Decision O6 (Engine): reject whole over-bound selections without truncation, filtering or eviction. Effective child-call concurrency is the minimum of every primary and eligible child-chain ceiling, and one for finite-token Goals. Tool-free wave planning uses the maximum eligible child attempt deadline within the existing 20-minute delegation and remaining Goal active time; each attempt keeps its narrower deadline. Existing [researcher-child](#researcher-children), switch, lineage and [persistence](#persistence-bounds) bounds remain unchanged. Existing Run-start and per-action Store headroom cover the bounded snapshot without raising quotas. The [assignment contract](./provider.md#named-roster-presets) owns the bounded object wire and null resolution. Event headroom includes switches from the longest eligible child chain, including an alternative longer than the default. Spawn payloads retain the ordinary Event-byte bound. Worker journal assignments do not select routes.

`ProviderFallbackUsed` is a Run/AgentRun-scoped fact containing role, bounded call index, unavailable disposition and exact `from`/`to` identities. It atomically settles the preceding pre-output failed attempt and reserves the next call, before egress, under the same active action ceiling. The original reservation remains open for the final step record. Every extra attempt increments the Goal's call count and marks failed-call token usage unknown. It adds no fabricated assistant outcome, Tool proposal or usage count. The coordinator alone writes the journal and updates the Goal ledger. Child tasks hold only a Provider, request, cancellation and deadline; they return an eligible-failure marker. The coordinator checks compatibility and budget, commits the switch, then respawns the child attempt. Draining child tasks never retains Store or ledger ownership. A crash after the switch retains the failed attempt and charges the unresolved replacement reservation; strict replay executes neither.

Replay requires the actor, role and call index to fit an open reservation, the identities to be adjacent in the pinned chain, sufficient call budget and no finite-token budget that unknown usage would violate. A primary's current display chunks prohibit a switch. The eventual call phase must fit the switched role, and its reported output must fit that role's cap. Compaction records must name the actual pinned or switched compaction route; between-Run compaction uses its compaction boundary index and never changes a closed Goal's receipt or usage. Switches stay within 64 facts per Run and survive closed-store replay, inspection and the bounded Goal report. They never dispatch a Tool, and an uncertain effect still stops its continuation.

Attached visual streaming has separate primary and call-scoped display observations. The Engine checkpoints bounded safe prefixes in `AssistantDisplayRecorded`; these facts remain outside accepted outcomes, model context and compaction. Cancelled or abruptly interrupted replay recovers only acknowledged text. Complete outcome validation still controls `MessageCommitted`, and an incompatible provisional prefix fails validation and strict replay. The Run's committed Events end at `RunFinished`; the later session-scoped Goal settlement follows as its own committed Events. Event observers see only acknowledged Events; neither Event nor hint observers can authorize, steer or cancel a Run. The [terminal contract](./terminal.md#terminal-continuity-and-provisional-text) owns presentation and detailed bounds.

Before Workspace input, inference or Tool preparation, require logical Event capacity for the Goal lifecycle and the next bounded action, plus conservative database-byte headroom, including the terminal facts needed to close that action and Run. Before each actual Provider or Tool dispatch, Store atomically admits the specific reservation and sufficient Event and byte headroom for its observation and terminal tail. The serialized reducer rejects a racing reservation that no longer fits. Capacity waiting and approval do not charge active Goal time or call usage; queued children are charged only after concurrency capacity is available. The Session and fork ancestors remain locked for the Run. Independent lineages remain concurrent; byte preflight does not reserve physical disk or guarantee against storage faults. Reject capacity exhaustion before disclosure or usage and direct the user to a new Session.

Fork admission validates the resulting lineage's depth and total Event count atomically; a failure leaves no partial target. Replay resolves at most eight lineage links within the [Session Event cap](#persistence-bounds) and verifies exact inherited prefix digests. Compaction has no fixed lifetime attempt count: each attempt must fit the current Goal budget, per-action Store and Event headroom, and request and context bounds before inference or an attempt Event. Failure preserves the last good summary and canonical history. Compaction remains derived context; it does not remove canonical Events or restore Tool permission. The serialized compaction input is at most 252 KiB, derived as (512 KiB request ceiling minus an 8 KiB envelope) / 2, because each adapter embeds that input as an escaped JSON string and quotes and backslashes double; an escape-heavy session over this bound fails closed with `CompactionInputTooLarge` before any Provider call. The automatic compaction threshold is 158,080 bytes: the input bound less room for two turns of the 8 KiB attached draft (each turn reserves its draft, steering context, a 32 KiB assistant answer, separators and image metadata). Automatic compaction therefore fails closed for turns above the attached draft size, such as 64 KiB `exec` objectives, with `CompactionInputTooLarge`. An in-Goal compaction input can carry a pinned Goal objective in its pinned Goal context and again in the Goal's first turn when that turn is in the compacted prefix; a 64 KiB prose objective still compacts within the bound, and an escape-heavy one fails closed.

For each in-Goal compaction and subsequent primary Provider request, bounded context reintroduces the pinned objective, project instructions and includes, approved plan or contract and current typed Goal facts. The projection carries dispatched call count, known tokens plus the unknown-usage flag, settled, reserved and uncertain active time, and the current optional success-criterion state; it contains no historical Tool body. It does not replay old Tool effects, promote historical output to instructions or use provisional display text as accepted context. Compaction checkpoints only an acknowledged prefix of active-Run Tool observations using exact Run identity, covered Tool count, ending sequence and digest proof, then stores a bounded untrusted summary. All observations remain canonical Events; Provider context uses the latest summary and a bounded recent tail. Replay checks the active prefix and summary digest without another Provider call. A failed attempt preserves the prior summary; another attempt requires a later acknowledged Tool prefix and consumes its own Goal call, time and Event budget. The summary grants no authority. This compaction contract does not claim complete per-phase or worker-specific context capsules; that behavior remains with the follow-on Goal-completion slice. Context construction respects the 376 KiB compiled-content ceiling, the selected remaining-byte Tool-history allowance, individual Tool argument and result limits and the 512 KiB encoded-request ceiling. A trusted exact route and model input-window bound may reduce the derived request budget, but bytes are not converted to token counts. Public model cards and display model IDs do not prove the selected saved ChatGPT route's context window; when exact route metadata is unavailable, the conservative local byte bounds stay in force and no expanded-window compatibility claim is made. `MAX_REPORTED_INPUT_TOKENS` validates reported usage only; it is not a model-window estimate.

Tool attempts and results are untrusted historical facts. Replay, resume, fork and compaction never execute old intents or restore permission. A command-generated `ApplyChangeset` is internally correlated to its exact preceding command receipt; if it exceeds the active Goal path scope, Engine records a no-Guard denial, and replay rejects any successful out-of-scope integration. Pre-dispatch Guard failure stops as Failed without effects; once the GO write begins, missing completion is Uncertain. Uncertain or cancelled effects stop without another call, retry or rollback claim. A fresh task may inspect current files and propose a newly authorized edit with fresh preconditions.

Cancellation before Message acceptance creates no Run. After admission it drains in-flight work and commits cancellation without a final answer, preserving prior facts. A terminal commitment already started wins its race with cancellation. Store failure leaves an interrupted prefix rather than manufacturing success or a cancellation receipt.

Run and compaction hold the Session lock and every fork ancestor's operation lock, because strict replay counts ancestor suffixes outside the inherited boundary. Cancellation is a sticky caller signal whose waiter interrupts pre-Engine admission; dropping a waiter does not undo started work.

A CLI process opens one Engine: the attached terminal after its Session starts, `exec` after Provider selection. The Engine's Store thread and its shared history lock live until exit, so another process's history reset reports history in use while an attached terminal is open, even when idle; Session, lineage and Workspace locks stay per Run. A normal exit closes the Engine and reports a failed close; an error exit drops it, which still stops the Store thread. The Engine runs one operation at a time: a submission or compaction while another is open is refused with `Busy` before any admission or Provider call. Each submission brings its own [per-role Provider chains](./provider.md#per-role-selection-and-fallback) and controls (Tool grant, approvals, steering, cancellation, display hints), fixed for every Run of its Goal loop, and its handle follows the Engine's committed Event stream from submission on. Invalid chains are refused at submission; a compaction brings the chains whose compaction route it calls. Each attached submission and compaction re-admits the State path and fails closed when it became unavailable or unsafe or no longer names the directory the Engine holds; a Tool grant loads its configuration at submission.

| Bound | Limit | Overflow |

Canonical state resolves before repository input and lives in a private directory outside the Workspace, with verified owner and permissions or ACL, a fixed aggregate page cap and admission headroom. SQLite integrity is not tamper evidence, and the database is not encrypted at rest. Persisted objectives, summaries, results and errors are untrusted typed data.

The schema is created only in an empty version-zero database; any other existing version rejects before mutable pragmas run. `MessageAccepted` and `GoalStarted` limits derive from the objective and image caps at six escaped bytes per byte. Byte preflight is conservative and is not a lease against independent writers or disk faults.
