# Run execution

## Scope and related contracts

This contract owns bounded Run coordination, delegation, accepted outcomes and history-capacity rejection. The [Goals contract](./goals.md) owns durable task lifecycle, Goal budgets, plan contracts and recovery; every accepted task links its Runs to one Goal. [Tools](./tools.md) owns grants and effect continuations; [terminal](./terminal.md) owns attached controls and agent inspection. Remaining Session lifecycle and account/profile admission stay in the [Session](../../agents/session.md) and [Provider](../../agents/provider.md) contracts. [Engine](../../agents/engine.md), [Store](../../agents/store.md) and [security](../../agents/security.md) rules retain implementation and privilege constraints.

## Collaboration

Each accepted task is durably linked to a Goal before its first `MessageAccepted`. Each Run has one accountable primary AgentRun and an ordered, bounded collection of direct read-only children. Children reason over supplied data and cannot create nested teams, acquire Tools or mutate files. The primary obtains file evidence, performs authorized effects and owns the final answer. Goal completion and Run completion are separate receipts as defined by the [Goal lifecycle](./goals.md#lifecycle-budgets-and-recovery).

Pin one policy before the Run: `single` admits no children; default `auto` allows up to three total direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The persisted `max_active_children` field limits total direct children for the delegation. Policy, process safety and remaining call/token/byte/time budgets bound team size; the Provider concurrency ceiling separately bounds simultaneous calls while admitted children wait in order. A ceiling is permission, not a required team size.

Auto guidance asks the primary to keep routine edits and simple inspection local, delegate substantial independent work only when its benefit justifies extra calls, and choose the smallest useful team. Typed policy and budgets enforce capacity; guidance does not guarantee every model's judgment. Agent inspection distinguishes the current/last Run from historical agents rather than presenting accumulated history as simultaneous activity.

Child identities and assignments retain ordinal order even when calls finish out of order. Synthesis receives results in assignment order after all terminal dispositions. Child failure drains siblings before primary failure. Cancellation reaches every admitted child and preserves already observed calls and terminal facts.

## Accepted outcomes

Every step produces exactly one phase-allowed semantic Finish, Delegate or enabled Tool proposal. There is no fixed per-Run Tool-effect or model-step ceiling; each action still requires bounded Event, Store, request, context and terminal-tail admission, while the Goal's call, Run and active-time budgets bound the complete task. Before its first Goal plan contract, the primary may inspect with bounded Workspace List/Read/Search, an admitted Skill read, or configured bounded MCP catalog listing in planning or synthesis; any other Tool proposal needs a valid contract before dispatch. A contract can accompany inspection and is still validated before dispatch. After a valid contract is recorded, the primary may continue through sequential Tool observations in planning or synthesis, with each operation still limited by the phase, exact plan scope and admitted Tool grant. Children receive Single policy and no Tool context. Unknown operations, invalid arguments, unavailable catalog names and policy-incompatible outcomes reject without repair or an alternate encoding. The [Goal contract](./goals.md#initial-plan-contract-and-success-receipt) defines the exact scope and replay rules.

Tool-enabled OpenAI and ChatGPT primaries use strict native functions with required selection and parallel calls disabled; exactly one complete call is accepted. Final text, unknown/multiple/incomplete calls reject. Read-only requests, children, compaction and Anthropic retain their admitted structured-text encoding. Exact custom profiles reject Tool context before HTTP until tool-capable conformance is supported.

Structured-text Responses decoding joins ordered text parts exactly and requires one final structured outcome. Explicit commentary can precede it. The legacy absent/null phase is accepted only for an unambiguous single final. Refusal, malformed content, unknown phases, duplicate/ambiguous finals, late commentary and contradictory error/incomplete markers reject. Missing or invalid fields cannot be repaired by a later valid field.

All adapters reject reported input above the shared input ceiling and output above the exact request cap. Native OpenAI may retain unknown usage; custom and ChatGPT outcomes require positive labeled usage. Native API-key/custom output caps are remote request controls; ChatGPT has a local acceptance cap and cannot guarantee remote generation or plan consumption. A Tool review uses its own 256-token cap, rather than the ordinary final-answer cap.

The ChatGPT route uses one bounded SSE parser regardless of absent or misleading media labels. Optional event labels must agree with JSON types. A matching created/completed identity plus complete indexed item events may supply empty terminal output; populated terminal output must agree. Deltas never supply accepted results. Missing/incomplete closure, invalid identity/model/usage, contradictory items, encoding errors and overflow publish no partial outcome. Native/catalog media admission remains unchanged; no JSON/HTML fallback is implied.

Malformed/non-object/duplicate-key MCP arguments and selected-credential reflections, including nested escaped arguments, reject before persistence. Provider failure remains the call's outcome even when an earlier Tool denial could otherwise be continued. Every route has zero automatic retries or billing/model/encoding fallback. A lost response can still consume remote usage.

## Admission, persistence and recovery

Persist only the current internal format: SQLite schema 4, Event payload version 4 and compaction compiler version 3. Required fields and nullable fields are explicit, including Goal linkage and budgets, Run configuration, Provider provenance, pinned Tool resource values and the required Tool cache-update outcome. Reading unsupported stored formats or missing fields rejects without conversion, automatic deletion or an optimistic projection. Replay rejects an accepted task without a valid Goal linkage; no unlinked legacy Run path or compatibility projection exists. The additive Run-scoped `GoalSteeringNoteRecorded` Event stays within payload version 4 and is accepted only inside the open primary provider reservation, as [Goals](./goals.md#steering-notes-journal) defines. Attached startup offers the [explicit history reset](./terminal.md#setup-and-account-choices); it discards history rather than converting or admitting an unsupported format.

Admit the selected Provider and complete bounded request before Workspace disclosure. Pin the Workspace, instructions/includes, policy, model/effort and caps for the Run. Commit accepted Message, Run and primary identity before inference; commit each observed call before its terminal AgentRun disposition. Replay requires an observed delegation before child spawn and an observed successful call before successful Agent completion. Known call usage survives an interrupted journal prefix.

Attached visual streaming has separate primary/call-scoped display observations. The Engine checkpoints bounded safe prefixes in `AssistantDisplayRecorded`; these facts remain outside accepted outcomes, model context and compaction. Cancelled or abruptly interrupted replay recovers only acknowledged text. Complete outcome validation still controls `MessageCommitted`, and an incompatible provisional prefix fails validation and strict replay. Run progress ends at the committed `RunFinished` Event; the later session-scoped Goal settlement and receipt are not retroactively added to the Run snapshot. The [terminal contract](./terminal.md#terminal-continuity-and-provisional-text) owns presentation and detailed bounds.

Before Workspace input, inference or Tool preparation, require logical Event capacity for the Goal lifecycle and the next bounded action, plus conservative database-byte headroom, including the terminal facts needed to close that action and Run. Before each actual Provider or Tool dispatch, Store atomically admits the specific reservation and sufficient Event/byte headroom for its observation and terminal tail. The serialized reducer rejects a racing reservation that no longer fits. Capacity waiting and approval do not charge active Goal time or call usage; queued children are charged only after concurrency capacity is available. The Session and fork ancestors remain locked for the Run. Independent lineages remain concurrent; byte preflight does not reserve physical disk or guarantee against storage faults. Reject capacity exhaustion before disclosure or usage and direct the user to a new Session.

Fork admission validates the resulting lineage's depth and total Event count atomically; a failure leaves no partial target. Replay resolves at most eight lineage links and 10,000 Events and verifies exact inherited prefix digests. Compaction has no fixed lifetime attempt count: each attempt must fit the current Goal budget, per-action Store/Event headroom, request and context bounds before inference or an attempt Event. Failure preserves the last good summary and canonical history. Compaction remains derived context; it does not remove canonical Events or restore Tool permission.

For each in-Goal compaction and subsequent primary Provider request, bounded context reintroduces the pinned objective, project instructions/includes, approved plan/contract and current typed Goal facts. The projection carries dispatched call count, known tokens plus the unknown-usage flag, settled/reserved/uncertain active time and the current optional success-criterion state; it contains no historical Tool body. It does not replay old Tool effects, promote historical output to instructions or use provisional display text as accepted context. Compaction checkpoints only an acknowledged prefix of active-Run Tool observations using exact Run identity, covered Tool count, ending sequence and digest proof, then stores a bounded untrusted summary. All observations remain canonical Events; Provider context uses the latest summary and a bounded recent tail. Replay checks the active prefix and summary digest without another Provider call. A failed attempt preserves the prior summary; another attempt requires a later acknowledged Tool prefix and consumes its own Goal call/time/Event budget. The summary grants no authority. This compaction contract does not claim complete per-phase or worker-specific context capsules; that behavior remains with the follow-on Goal-completion slice. Context construction respects the 376 KiB compiled-content ceiling, the selected remaining-byte Tool-history allowance, individual Tool argument/result limits and the 512 KiB encoded-request ceiling. A trusted exact route/model input-window bound may reduce the derived request budget, but bytes are not converted to token counts. Public model cards and display model IDs do not prove the selected saved ChatGPT route's context window; when exact route metadata is unavailable, retain the conservative local byte bounds and make no expanded-window compatibility claim. `MAX_REPORTED_INPUT_TOKENS` validates reported usage only; it is not a model-window estimate.

Tool attempts/results are untrusted historical facts. Replay, resume, fork and compaction never execute old intents or restore permission. A command-generated `ApplyChangeset` is internally correlated to its exact preceding command receipt; if it exceeds the active Goal path scope, Engine records a no-Guard denial and replay rejects any successful out-of-scope integration. Pre-dispatch Guard failure stops as Failed without effects; once the GO write begins, missing completion is Uncertain. Uncertain/cancelled effects stop without another call, retry or rollback claim. A fresh task may inspect current files and propose a newly authorized edit with fresh preconditions.

Cancellation before Message acceptance creates no Run. After admission it drains in-flight work and commits cancellation without a final answer, preserving prior facts. A terminal commitment already started wins its race with cancellation. Store failure leaves an interrupted prefix rather than manufacturing success or a cancellation receipt.
