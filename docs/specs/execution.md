# Run execution

## Scope and related contracts

This contract owns bounded Run coordination, delegation, accepted outcomes and history-capacity rejection. The [Goals contract](./goals.md) owns durable task lifecycle, Goal budgets, plan contracts and recovery; every accepted task links its Runs to one Goal. [Tools](./tools.md) owns grants and effect continuations; [terminal](./terminal.md) owns attached controls and agent inspection. Session lifecycle and Provider admission stay in the [Session](./session.md) and [Provider](./provider.md) contracts. [Next steps](../../NEXT_STEPS.md) owns remaining native and live checks.

Editing constraints: [security rules](../../agents/security.md).

## Committed Event stream

A hook-free single-call Tool step without approval or review commits `GoalProviderCallReserved`, `ProviderCallRecorded`, `ToolStarted` and `ToolFinished`. `ToolStarted` carries the final permission verdict (null only for unconfigured pinned-grant steps). Before a pre-hook, AI review or human approval, a conditional `ToolProposed` commits the complete immutable intent and active-time ceiling; hooks and reviews correlate to it, and the folded start advances the same Tool. A denial still commits a folded start and a not-dispatched finish. A proposal without a start is not an unknown effect: explicit resume may re-propose it when every hook outcome is known and non-stopping. A started Tool without a known outcome, or an unfinished or [Uncertain](#effect-outcomes) hook, blocks continuation.

This follows [Codex's durable function-call records and transient approval messages](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/policy.rs); Arany adds the durable proposal for pending-intent validation, exact review ownership and crash-budget guarantees, within the per-step and Session bounds below.

`Journal::append` feeds clients, telemetry and diagnostics only after commit, through a 256-envelope broadcast ring per subscriber. Lag yields `Resync { missed }`, and the subscriber recovers from the committed view without blocking execution. Subscriber failure or lag cannot change a Run outcome or grant authority. Provisional Provider previews stay outside this stream.

An envelope's `created_at_ms` is Unix wall time in milliseconds, sampled inside the transaction before reducer validation, insertion and commit. Timestamp differences are journal intervals, not monotonic elapsed time. A held or lost result acknowledgement cannot complete a monotonic success sample, and negative wall-clock intervals stay separate from monotonic durations.

A primary or researcher Tool step holds 1 through [`MAX_STEP_TOOL_CALLS`](./limits.md#max_step_tool_calls) calls in model order; editors keep one call per step. The complete proposal, arguments, phase, lease, plan scope and context fit are validated before any intent commits. A multi-call step commits every intent as `ToolProposed` in model order before the first dispatch; each folded `ToolStarted` commits after that call's hooks and approval. Admitted in-process reads dispatch concurrently under the [shared file-operation capacity](./tools.md#in-process-file-operations); other calls wait until every read observation commits, then dispatch one at a time in model order. In a primary step with two or more calls, `ToolActiveTimeReserved` commits the [Goal action ceiling](./goals.md#lifecycle-budgets-and-recovery) before each precommitted intent is processed; it names the intent digest, occurs at most once per intent and grants no authority. Overlapping read reservations and starts cannot lower the recorded recovery ceiling. A single-call step keeps its ceiling on `ToolStarted`. Each call keeps its own verdict, intent and `ToolFinished`, correlated by intent digest. Read finishes commit in completion order; the next Provider request carries observations in model order. Replay accepts observations in any order for the step's pending intents and rejects duplicate or unmatched results. Every observation and hook settles before the next Provider call. Command integration and hook replacements stay attached to their source call. A stop prevents later dispatch: dispatched calls settle and the remaining intents receive non-dispatched observations. A read reaching Limit while a sibling approval is pending withdraws that approval; a late acceptance cannot dispatch it. Concurrent reads keep their own deadlines and share elapsed Goal wall time instead of charging overlap repeatedly. A crash after a partial intent prefix leaves those intents interrupted and never executes them.

Workspace file mutations attest in process with an intent-bound FileReceipt on success; historical Guard observations keep their recorded execution site. [File operations](./tools.md#in-process-file-operations) owns validation, publication, deadline and uncertainty rules.

## Collaboration

Each accepted task is durably linked to a Goal before its first `MessageAccepted`. Each Run has one accountable primary AgentRun and an ordered, bounded set of direct researcher and EditOnly children. Children cannot create nested teams; only EditOnly children mutate the Workspace, within their assignment leases. With a Tool runtime, each researcher spawn pins the `read_only` grant and each EditOnly child its leased assignment grant. A researcher may alternate calls with Workspace List/Read/Search, admitted Skill reads, MCP catalog listing and explicitly granted [web Tools](./tools.md#web-fetch-and-web-search), within the Goal plan contract, before returning its bounded report. Before any plan contract a researcher may read any admitted Workspace path, as the primary prelude may; MCP catalog listing starts the admitted stdio server under the Guard. Without a Tool runtime a child makes one reasoning call. A researcher failure, including one out-of-grant MCP call, fails the Run and drains every sibling; an editor failure stays local as specified below. The primary obtains file evidence, performs authorized effects and owns the final answer. Goal completion and Run completion are separate receipts ([Goal lifecycle](./goals.md#lifecycle-budgets-and-recovery)).

One policy is pinned before the Run: default `single` admits no children; opt-in `auto` (`/agents auto`, `exec --collaboration auto`) allows up to three direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The `single` default diverges from Claude Code and Codex, which offer subagents by default, until delegation is an ordinary Tool rather than an exclusive outcome with a synthesis phase. The persisted `max_active_children` limits total direct assignment attempts across the Run, including researchers, replacements and later waves. Policy, process safety and remaining call, token, byte and time budgets bound team size; the pinned primary and child Provider concurrency ceilings separately bound simultaneous calls while admitted children wait in order. A ceiling is permission, not a required team size.

Auto guidance asks the primary to keep routine edits and simple inspection local, delegate substantial independent work only when the benefit justifies extra calls, and choose the smallest useful team. Typed policy and budgets enforce capacity; guidance does not guarantee a model's judgment. Agent inspection separates the current or last Run from historical agents.

Child authority is the intersection of global policy, parent effective authority and the explicit task grant. Children cannot self-approve or alter sibling authority, and missing configuration never restores a capability.

Child identities and assignments keep ordinal order even when calls finish out of order. Synthesis receives committed reports in assignment order; researcher reports never satisfy the Goal criterion. Background coordination lists pending identities without provisional child text. Researcher failure drains siblings before primary failure. Cancellation reaches every admitted child and preserves observed calls and terminal facts. A delegation abort keeps its original failure when sibling draining also fails; the drain failure is diagnostic only.

A primary outcome-contract failure commits as `ProviderCallRecorded` with `invalid_response` and `outcome_contract` before the [single corrective call](./provider.md#structured-outcomes-and-tool-encoding) reserves and dispatches. Replay permits that same-phase continuation only after the first such failure, with settled Tools and hooks, and rejects a reservation after the second. Reservations and unknown usage stay charged. If correction also fails, the Run records `provider_call` with the final typed parse reason. Later context uses the [committed failure projection](./session.md#context-and-compaction), never an invented causal explanation.

A framed response whose content cannot decode into an offered answer or typed proposal records `invalid_response` with `outcome_decode`. It is distinct from `outcome_contract` (one corrective call) and `response_contract` (identity, usage and provenance after decoding). A decoded outcome refused only by budget or token admission records `invalid_response` with a null reason and its usage.

## Researcher children

One delegation active-time segment covers child calls and child Tools, including shared Guard capacity waits, and charges overlapping Provider, effect, preparation and cleanup work once. A pending child Ask pauses this allowance while idle; sibling activity keeps consuming it. Exhaustion withdraws the Ask before dispatch with its delegation or Goal cause. Pause takes effect before each child step.

Child Tool facts of read-only research steps stay in the child's own agent view; the primary's run view and plan rules are unchanged.

| Child Tool calls | `min(16, ((remaining calls − children − 1) / 2) / children)`, 16 if calls are unlimited; replay cap 16 | catalog `tool_calls_remaining: 0`, only answer offered; a further Tool is an invalid response |

## Agent definitions

Definitions come only from exact Workspace `.claude/agents/*.md` and the admitted private StateRoot `agents/*.md`; private names win. One strict Claude-format subset is accepted. There is no home, plugin, recursive or alternative-format discovery. The project directory must lie wholly inside the parent read grant. Missing directories are empty; unsafe present entries (symlinks, links, non-owned or oversized files, bad names) refuse the whole registry before any Provider call.

Following Claude Code, which skips and reports an invalid agent file, a file with invalid content (bad frontmatter or field value, YAML anchor/alias/tag, size bounds, duplicate name within a source) is skipped with a bounded diagnostic naming the file and field, journaled in the parse receipt and shown in the Goal report evidence. Unsupported frontmatter fields (for example `color`, `hooks`, `mcpServers`) and unsupported tool names are ignored with a diagnostic; ignoring only narrows authority. The registry lists at most 8 KiB<!-- unrelated-bound: agent registry base catalog --> of base entries in name order; later definitions are dropped with a diagnostic. Foreground editor metadata adds its normalized digest and turn ceiling at Engine admission; if the complete catalog then exceeds 8 KiB<!-- unrelated-bound: complete agent registry catalog -->, initialization fails before Provider disclosure. Selecting a skipped, dropped or absent name is an invalid delegation; editor proposals follow the upfront refusal rules below. Discovery is an immutable raw-byte snapshot taken during input preparation. [Parser admission](./tools.md#agent-definition-parser-admission) owns filesystem and Guard enforcement.

The envelope is Markdown with YAML frontmatter. `name` and `description` are required strings; the only optional fields are `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `isolation` and `background`. Duplicate or explicit-null fields and wrongly typed or out-of-range values make the file invalid. Names use lowercase ASCII letters, digits, `_` and `-`, at most 64 bytes. Description is nonempty and at most 2 KiB<!-- unrelated-bound: agent definition description -->; body is at most 32 KiB<!-- unrelated-bound: agent definition body cap -->. The body is untrusted assignment guidance in the child's user input, never a system role. The primary receives bounded names and descriptions, never unselected bodies.

Tool lists accept comma-separated strings or string arrays, at most 32 names of 128 bytes each. `Read`, `Grep`, `Write` and `Skill` map to `read`, `search`, `write` and `skill`; `Edit` maps to `edit`, `multiedit`, `delete` and `move`; `MultiEdit` to `multiedit`; `Glob` to `list` and `glob`. Exact names for those operations plus `mkdir` and `mcp_list` are accepted. `Bash` maps to `command` for editors only, as a narrowing permission, and a denied `Bash(...)` pattern denies every command; exact `command` is also recognized. Unknown names, patterns, Agent, Git and MCP invocation are ignored with a diagnostic and grant nothing. Missing `tools` inherits the admitted catalog for the assignment kind; `disallowedTools` subtracts. An empty effective edit capability supplies no write authority.

Omitted `model` or `inherit` keeps the complete parent-admitted child chain. Definition model metadata cannot override an assignment-selected profile. A literal model equal to its initial admitted child's exact model is kept; any other value selects no route, account, alias or credential and is treated as `inherit` with a diagnostic. The five [permission-mode spellings](./tools.md#modes-and-approval-decisions) only narrow parent settings and live terminal restrictions, using Deny > Ask > Allow. File text never grants a capability or resolves an approval.

The primary's Delegate may select one registry name through `agent` for its group of researcher objectives; null or omission selects the default researcher. Selection is validated before any child spawn or call and pinned by the required nullable `AgentSpawned.definition`. A selected definition narrows the read-only catalog and can reduce child inference turns to 1–17 (`maxTurns`, default 17); Tool reviews do not consume turns. The maximum 16 model Tool requests and Goal headroom still apply, and the last available turn offers only answer. A Tool beyond the child's remaining allowance, an unknown name or an unsupported editor selection is an invalid delegation or child response and fails the Run without granting or dispatching the effect.

`isolation: worktree` identifies an editor definition. Editors work on the shared Workspace under leases, without per-editor worktrees or private images; the field grants no isolation or authority. Omitted `background` is `false`. A definition with `background: true` requires background assignment mode; a foreground default may be scheduled in either mode. A researcher group cannot select an editor through its group-level `agent` field.

`RunStarted.config.agent_definitions` is required nullable: null for an empty or unavailable registry, otherwise the ordered source/filename/raw-digest pins and their SHA-256. Internal parser intents follow the primary spawn, in that order, before the first Provider reservation. A matching successful Guard observation fixes each closed normalized-v1 result: a definition with notes or a skipped-file diagnostic. Private precedence applies after every document is classified. Strict replay verifies these facts and model admission, requires every parser observation before Provider reservation, rejects late refresh or duplicate parsing, and never reruns a parser. Internal preparation is excluded from model Tool counts, history and compaction bodies; compaction `covered_tool_count` indexes the Run's Tool Events, with the leading parse steps counted as covered. Interrupted parsing supplies no authority; a new Run takes fresh snapshots and Guard admission.

| Definition bound | Limit / overflow |
|---|---|
| Discovery | 256 scanned entries per source; 64 candidate Markdown files per source; 1 MiB<!-- unrelated-bound: agent definition discovery bytes --> aggregate raw bytes; whole refusal |
| File and normalized registry | 64 KiB<!-- unrelated-bound: agent definition raw file --> per raw file; 1 MiB<!-- unrelated-bound: normalized agent registry bytes --> aggregate normalized records; existing Tool observation, Guard task, catalog and request ceilings may reject sooner; no truncation |
| YAML | 4096 nodes, depth 32; no aliases, anchors, tags or duplicate keys; an unterminated quote at a line end is refused; the file is skipped |
| Catalog | 8 KiB<!-- unrelated-bound: agent registry catalog --> of agent entries; later names dropped with a diagnostic |

A Delegate decision admits one wave of mixed researchers and editors. Each proposal is validated in full before any child disclosure: malformed definitions, paths, overlapping leases, wave numbers or total-attempt overflow refuse it. There are at most eight total attempts under explicit team policy and three under opt-in auto without a count. A replacement requires an explicit new Delegate decision with fresh ID, grant and lease; `supersedes` may name a terminal, released child of this Run. Nothing is retried automatically. Explicit `resumes` names a terminal or interrupted historical child of the same Session and Goal ([Session identity](./session.md#worker-identity-and-explicit-reassignment) owns admission and historical context); it always creates a fresh assignment, grant and lease, never private-state continuation.

Following Codex CLI and Claude Code's upfront subagent-input validation, the Engine runs the Session reducer's editor-request checks before accepting a Delegate and again before spawn. Invalid editor input records a rejected proposal with an editor [refusal cause](#accepted-outcomes) (phase requirements keep `phase`) and follows the bounded refusal continuation. Reasons contain compiled guidance only, never definition or Provider text. Engine-only liveness, wave, route, lease-overlap and total-attempt gates still apply. An accepted queued assignment that fails revalidation stops with an invariant error before spawn; it is never silently omitted. The refusal survives reopen; strict replay rejects forged accepted invalid assignments without executing them. Failed or unknown refusal appends and cancellation stop continuation before child work.

Worker concurrency defaults to four, configurable only through Engine settings to 1–8, then narrowed by policy size and admitted Provider concurrency. A finite-token Goal serializes all Provider calls, including background primary coordination. Only available slots admit queued assignments and reserve calls; queued assignments never spend calls. Pending assignments, completions and report collections are each bounded by eight; Tool dispatch stays serial per Run, while a primary or researcher step may hold its batch of pending intents. Overflow refuses admission without dropping a member.

Editors admit foreground and background assignments with typed file operations and explicitly admitted commands. Disjoint background editors may work while the primary and researchers read the live Workspace; the primary may write outside their leases. Command names intersect parent, plan and definition before spawn. Definition metadata cannot widen authority.

Foreground children block primary coordination until their terminal answer and causal lease release. A successful primary answer and the next delegation also require fresh passing primary verification for every ready or no-change editor. A known editor failure stays local, keeps landed Workspace effects and releases the lease; a researcher failure stays fatal. An unfinished or [Uncertain](#effect-outcomes) Workspace effect, including an editor's write, stops the Run and blocks Goal continuation, with no rollback claim.

For a wave-primary request, the Engine binds the primary route and cap, admits worker use and reserves the Provider call before final primary-context preparation, and builds the request only once that context is ready. The prepared input, model and output cap are unchanged; a refused reservation or stop dispatches nothing.

## Worker journal protocol

Every EditOnly AgentRun uses the same `execute_step` and `before_dispatch` as the primary and researchers, with `target: Workspace`. The Engine journals the lease-acquiring spawn, each Tool intent and observation, the editor's answer, lease release and primary verification as separate committed facts. There is no base capture, private data, handover, discard, integration or cleanup.

This follows Claude Code and Codex CLI subagents sharing the working tree. Unlike Claude Code, which excludes subagents from checkpoints, Arany checkpoints editor typed mutations because receipted effects and rewind are part of its durability contract. Editors never receive host authority; their capabilities are the intersection of parent, plan, definition and leased assignment, with `unguarded: denied`.

Per-editor worktrees are rejected: they add creation, cleanup and merge cost without strengthening these guarantees. An opt-in worktree shared by all agents of one Goal, publishing one changeset at the end, is outside the current capability; revisit it if parallel editors need overlapping areas or a user asks to keep the working tree untouched until review.

An editor requires a write-capable parent, the Implementation phase, an admitted matching definition and a committed Goal plan. Invalid input is refused before spawn or child disclosure. Foreground and background modes share admission; command lists and criteria must fit the parent, plan and definition grants. No editor can invoke Git, MCP, Skills, network, host commands or nested delegation. Per-Tool, context, turn, call, token, active-time and Store bounds stay in force.

`RunStarted.config.worker_policy` is required nullable; its bounded parent grant, concurrency, turns and model Tool ceiling are admission pins, with no data allowance.

`ProviderCallRecorded.delegation` keeps its required nullable bounded typed assignments and ordinal/wave matching. `AgentSpawned.assignment` is required nullable, present exactly with `ChildGrant::EditOnly`: the request, effective grant, parent policy digest and required nullable permission digest. Spawn atomically acquires the lease and validates lineage, concurrency and overlapping assignments against committed facts.

Writable leases name 1–64 sorted relative files or subtrees of at most 512 ASCII bytes and depth 16. Traversal, backslashes, protected components, controls and non-ASCII writable paths reject. Ancestor/descendant and ASCII case-folded aliases conflict. A typed mutation by any actor overlapping another actor's live lease is refused before intent commit. A lease authorizes only its owning editor, never a sibling or the primary. Primary commands and MCP require lease quiescence. Editor commands use the primary command publication path under the child identity; the whole changeset must fit the owning lease and avoid every sibling lease, and one out-of-lease path refuses the batch without changing the Workspace. Leases have no TTL and never cross Runs.

Editor Tool steps run under the child's identity with its verdicts, delegated hooks, cancellation, delegation deadline and shared accounting. Successful typed file operations have ordinary Workspace receipts. Editor commands use the same platform mechanism and exclusive cache-identity lease as primary commands; busy refuses without waiting. Their generated publication is a separate causal Tool under the same identity, with the whole changeset checkpointed before GO. Write, Edit, MultiEdit, Delete, Move and permitted internal Workspace publications enter the shared checkpoint gate before GO; [checkpoints](./tools.md#checkpoints-and-rewind) and [rewind planning](./session.md#rewind-planning-and-replay) include editor observations. Known non-dispatch carries no checkpoint. Mkdir keeps ordinary directory semantics and cannot be a standalone assignment criterion.

`AgentFinished.worker` is required nullable and present exactly for editors, with closed `disposition` and `cause`. Ready and no-change require an observed answer and current committed Workspace Tool evidence for the criterion; no-change means no successful mutation was recorded. A known Tool failure, invalid answer, hook stop, turn or budget limit, or cancellation keeps its own cause. A known pre-dispatch denial follows the shared permission feedback rules; a model, definition, hook or child report cannot supply approval.

The editor's answer passes the criterion gate before SubagentStop. An unmet criterion keeps the closed `criterion_not_met_in_view` reason and allows at most three bounded corrective continuations within remaining turns, Tools, call, token, time and Event capacity. A continuation is a fresh model decision, never an effect retry. A blocked stop hook keeps the existing feedback, turn and budget precedence.

`WorkerLeaseReleased` contains only the assignment ID and the exact causal `AgentFinished` sequence. Release requires that editor's committed terminal outcome, settled known Tools and no earlier release; it fabricates no integration or disposal. `WorkerVerificationRecorded` follows release and pins the criterion digest plus at most eight increasing primary Workspace observation sequences; replay derives the result independently. Child evidence, the answer and release cannot pass verification, and later Workspace mutations invalidate a passing one. A failed editor requires an explicit replacement decision, never fabricated verification.

`WorkerStopObserved` records the first cancellation, pause or budget boundary before further team dispatch. New spawns, calls, Tools and verification reject after it, while in-flight observations and terminal and release facts drain. Cancellation and pause keep landed edits and their checkpoints. Process death leaves interrupted intents and the last receipted Workspace state. An [Uncertain](#effect-outcomes) Workspace effect stops the whole Run without lease release or continuation.

## Accepted outcomes

A validated `arany_plan` call records disposition `plan_recorded`, zero requested effects, null delegation and no failure or refusal. Only a Tool-enabled primary in RootPlan or RootSynthesis without an existing contract may record it, and the function is offered only to autonomous Goals and explicit `team` policy ([Goals](./goals.md#initial-plan-contract-and-success-receipt)). The next contract Event precedes any new action, and continuation requires that contract to be committed. Plan calls consume the ordinary Goal call and usage budget.

A journaled `stopped` result from any successful [hook event](./tools.md#hook-execution) in an active Run ends the Run and its primary AgentRun as `stopped_by_hook`, distinct from success, failure and cancellation. A hook running with a child's identity (SubagentStop or a delegated Tool hook) also ends that child as `stopped_by_hook`, drains the other children (they end Cancelled) and prevents synthesis. No further Provider reservation, Tool, spawn or hook starts in that Run; already reserved child calls drain and are recorded. No assistant Message commits, and completed effects remain. The displayed optional reason comes from the committed hook result within the [Hook execution](./tools.md#hook-execution) reason bound; terminal, `exec` and `serve` adapters escape it and show it as user feedback, never model input. Diagnostics and telemetry use the closed disposition without the reason. The [Goal](./goals.md#lifecycle-budgets-and-recovery) stays open. Strict replay validates the facts without executing the hook.

Every step produces exactly one phase-allowed text answer, Delegate, optional primary plan or enabled Tool proposal within the [per-step bounds](#committed-event-stream). An accepted answer ends the turn and commits once as `MessageCommitted.text`; earlier text is commentary. `AgentFinished.summary` is the answer's first nonempty line, truncated at a UTF-8 boundary to 2 KiB<!-- unrelated-bound: derived child summary bytes -->, and `AgentFinished.result` keeps the answer; replay rejects a summary that differs from this derivation. A primary planning or synthesis call may carry the Run's accepted steering notes as user input; child calls carry only their own actor-bound notes, Tool review receives none, and pause applies only at the [Goal boundaries](./goals.md#steering-notes-and-pause). There is no fixed per-Run Tool-effect or model-step ceiling: each action requires bounded Event, Store, request, context and terminal-tail admission, and the Goal's call, Run and active-time budgets bound the task. The primary's last call under a finite Provider-call budget offers only an answer, as [Goals](./goals.md#lifecycle-budgets-and-recovery) defines after OpenCode's last-step answer; its committed answer finishes the Run normally.

Primary Tool calls need no plan: Tool schemas carry no per-Tool plan fields, and the plan is a separate primary function. Research and Plan Goal phases keep their prelude-only catalog: Workspace List/Read/Search, typed Git reads, admitted Skill reads and configured bounded MCP catalog listing. Implementation calls stay subject to the pinned grant and effect admission. A recorded [Goal plan](./goals.md#initial-plan-contract-and-success-receipt) further narrows scope and binds success; the Goal contract owns scope and replay rules. Children receive Single policy; a researcher receives only the read-only research catalog, its own observations and answer. Its MCP calls, writes, commands and plan contracts are invalid before dispatch; one read outside the plan contract is journaled Denied without dispatch, while an out-of-scope batch is refused in full before any intent. Unknown operations and malformed wire responses reject without an alternate encoding; decoded primary proposals follow the refusal continuation below.

A decoded primary proposal refused by Engine validation in RootPlan or RootSynthesis records `failure_reason: proposal_refused` with required nullable `refusal { operation, cause }` on the same `ProviderCallRecorded`, paired only with `Rejected`. The operation is the compiled `arany_` function name (including `arany_plan`), `answer` or `delegate`, never arguments. Closed causes are `invalid_arguments`, `invalid_path`, `digest_unknown` ([Engine-filled preconditions](./tools.md#engine-filled-preconditions)), `phase`, `plan_invalid`, `plan_budget_outside_goal`, `plan_budget_spent`, `plan_scope_excludes_call`, `plan_outside_grant`, `argument_bytes`, `lease_overlap`, `not_offered`, `answer_invalid`, `delegate_invalid`, `editor_definition`, `editor_digest`, `editor_commands`, `editor_turns`, `editor_lease`, `editor_criterion`, `editor_resume` and `editor_grant`. The refusal commits before another Provider reservation, and the primary loop continues without a Tool intent, Guard dispatch or receipt. One invalid call refuses the whole batch before any intent, and feedback names its zero-based index. Exceeding the [per-step call cap](#committed-event-stream) or duplicating call IDs refuses with `invalid_arguments`, and feedback names the cap.

This continuation follows Claude Code and Codex, which continue the turn after refused Tool proposals; Arany adds its journal and resource cap. For a refused typed Tool proposal, the next request pairs the original assistant turn and each call ID with one native error result derived from the committed refusal: closed cause, fixed remediation, `dispatched: false` and `effect: none`, at most 2 KiB<!-- unrelated-bound: typed Tool refusal result --> plus framing. Invalid paths get the canonical Workspace-relative path requirements, never an echo of argument text. The error turn counts toward continuation capacity and may enter whole-step compaction; no intent, observation or receipt is fabricated. Other refused primary proposals get one `last_answer_refused` note as trailing user data in the `worker_coordination` channel after Tool steps and stop feedback, keeping the earlier request prefix: operation, closed cause and fixed remediation, never model-authored values. A Tool refusal during a worker wave records `worker_tool_refused` without a cause. Ledger read and editor-grant construction errors are Engine errors, never refusal causes. Explicit Team planning that answers instead of delegating uses this path.

Three consecutive primary refusals with the same `(operation, cause)` end the Run with `refusal_limit`, matching OpenCode's doom-loop threshold; a different pair or a non-refused call breaks the streak. Eight total primary refusals also stop the Run. Each retry reserves and spends a normal Provider call under the Goal budget; cancellation and pause keep their boundaries. A crash after the refusal commit keeps it, and a resumed Session shows it as nothing dispatched within the history bounds.

Before publishing a prepared Tool step, the Engine preflights each candidate read-only against the committed Session through the reducer's validator: the proposal before hooks or approval, and the folded start with its final verdict before dispatch. Phase, plan scope and lease checks have one Session-owned implementation shared with proposal refusal and strict replay. Invalid payloads map to `invalid_arguments`, invalid transitions to `phase`, out-of-plan calls to `plan_scope_excludes_call` and lease conflicts to `lease_overlap`. A rejected candidate is never appended or dispatched; instead `ToolPreflightRefused` commits its intent digest and typed `{cause, reason}` under the same Run and actor, where the reason is one of the validator's fixed sentences (unknown reasons and mismatched pairs reject). A verdict already produced by hooks, review or approval is carried as diagnostic evidence without granting dispatch or remembered authority. At most one refusal is admitted per AgentRun. In a concurrent read step, known completions settle first. The refusal closes the actor's unstarted proposals and prevents another Provider call, hook or Tool start for it; it creates no observation, receipt or effect, and cannot settle a started effect or hook with an unknown outcome. A final-start rejection releases its approval or review active-time reservation. Rejection after an accepted proposal stops the Run with `proposal_refused`. The AgentRun projection, historical output and later failure feedback keep the typed cause. Cancellation, hook-stop, uncertainty and budget precedence is unchanged.

A researcher batch above the [Tool step cap](./limits.md#max_step_tool_calls) commits the same `rejected` / `proposal_refused` record with `InvalidArguments` before continuation, starts no Tool and keeps usage. Its next request has one cap-aware non-dispatched result per call ID. The refusal ceilings apply independently to each researcher AgentRun; a refusal consumes a normal turn and Goal call but no Tool-call allowance. Exhausted refusal, turn, context or time bounds end the child. Other invalid researcher outcomes stay fatal. Editors keep single-call validation without a refusal continuation.

`RunFinished.failure` is required nullable and present exactly with `Failed`: `provider_call`, `proposal_refused`, `budget_exhausted` (the Goal budget refused the next action), `tool_stopped` (a terminal dropped Tool step, a Guard failure after GO or without proof of non-dispatch, or an unusable Command result), `definition_invalid`, `plan_admission`, `tool_context_full`, `workers_unverified`, `criterion_unmet` or `refusal_limit`. A known recoverable primary Tool denial or failure, including a Guard failure whose observation proves nothing was dispatched, is delivered once as its correlated result and does not by itself produce `tool_stopped`; the effect is never retried, and the next call is a fresh model decision; a following Provider failure or refused continuation keeps its own cause. Strict replay rejects missing fields, unknown causes and invalid disposition pairings. [Terminal](./terminal.md#conversation-progress-and-history) owns failure copy and [diagnostics](./diagnostics.md) owns private records.

The primary Run settles once, by one precedence:

1. An [Uncertain](#effect-outcomes) primary Tool observation or hook outcome, or the stopping step's uncertain build-cache publication, journals no terminal Event and is reported unknown. A Run that cannot settle because a reservation, another agent or a primary Tool is still open also journals nothing; the submission returns it as reopened history projects it (`uncertain` only with an open or unknown effect, budget exhaustion when its counts prove it, otherwise interrupted).
2. Cancellation or pause ends the Run `cancelled`, including during a lifecycle hook.
3. A settled hook stop ends it `stopped_by_hook`.
4. Exhausted active time, or a call or token budget that refused the next action, ends it `budget_exhausted` and records the Goal exhausted once its budget is spent; this outranks `tool_context_full`, `tool_stopped` and `plan_admission`.
5. The stopping step's own cause.

An accepted answer that passed its Stop hooks still finishes when active time runs out after it.

The [Provider encoding contract](./provider.md#structured-outcomes-and-tool-encoding) owns automatic Tool selection, plain-text answers and structured compaction and review. Responses text parts join in order without inserted or repaired bytes. Explicit commentary may precede the final answer or Tool proposal; refusal, malformed content, unknown phases, ambiguous finals, late commentary and contradictory error or incomplete markers reject. A missing or null phase is valid only for an unambiguous final message or text preceding a call. The ChatGPT route's SSE parsing and item reconstruction belong to the [ChatGPT contract](./chatgpt.md#catalog-and-runs); only complete matching items reconcile, and failure publishes no partial answer.

All adapters reject reported input above the shared input ceiling. Provider-enforced routes reject reported output above the exact request cap; the ChatGPT route caps visible output, so its recorded total (including reasoning) is bounded only by the 1,000,000-token reporting ceiling, live and in replay ([ChatGPT limits](./chatgpt.md#run-limits)). Accepted outcomes also fit the serialized terminal payload bound, including JSON escaping. Native OpenAI may keep unknown usage; custom and ChatGPT outcomes require positive labeled usage. Native API-key and custom output caps are remote request controls; ChatGPT has a local acceptance cap and cannot guarantee remote generation or plan consumption. A Tool review uses Single policy without Tools, history, includes or project instructions, its own 256-token cap, a 20-second ceiling and the aggregate 32-call headroom ([approvals](./tools.md#folder-trust-and-approvals)); uncertainty or failure asks a human and never grants a broader permission.

### Effect outcomes

Every dispatched effect (Tool, hook, host operation, Provider setup edit or rewind) settles as one of:

- **Limit**: a bound (deadline, capacity, size or budget) stopped it before any effect, or with a known partial result and no publication; for example a command timeout keeps bounded partial output and publishes no changeset.
- **Cancelled**: cancellation stopped it before any effect, or with confirmed teardown.
- **Failed**: it completed with a confirmed failure (nonzero exit, refused request, API, auth or parse failure).
- **Uncertain**: its outcome is unknown after dispatch: a lost acknowledgement or receipt, unconfirmed teardown, interrupted publication, process death after GO or unconfirmed durability.

Uncertain stops its continuation: no further Provider call, Tool or hook starts for that work, the Run journals no terminal outcome and is reported unknown, and Goal resume is blocked until the user acts. Confirmed Limit and Cancelled outcomes keep their recorded meaning and imply no rollback.

No effect is retried automatically. A continuation after a failure is a fresh model decision with fresh intents and preconditions; only Provider calls have bounded same-route retries and fallback, which never redispatch an observed Tool. Tool attempts and results are untrusted historical facts: strict replay, resume, fork, rewind planning, compaction and archiving never execute a historical intent, complete or roll back an effect, or restore a permission. A fresh task may inspect current files and propose a newly authorized edit.

A command-generated `ApplyChangeset` correlates to its exact preceding command receipt; one that exceeds the active Goal path scope records a no-Guard denial, and replay rejects a successful out-of-scope integration. Pre-dispatch Guard failure follows the [Tool failure rules](./tools.md#limits-and-failure-behavior); once the GO write begins, missing completion is Uncertain.

## Admission, persistence and recovery

A `serve --stdio` process opens one Engine shared by its loaded threads; the [serve contract](./serve.md) owns its client loop.

Persist only SQLite schema 11 and compaction compiler version 3. The schema is the one journal format version: every Event kind has exactly one current payload shape, and any payload change, additive or not, advances the schema once, which archives existing history ([incompatible history](#incompatible-history)). Rows carry no per-kind version. Roster metadata and the agent-definition pin are required nullable `RunStarted` fields; role provenance is kept and cross-validated with the bounded snapshot. `AgentSpawned` requires the nullable selected definition, resolved profile reference and assignment pins. There is no dual reader or replay-time configuration lookup; history at any other version never reaches runtime decoders. Event decoding validates current fields strictly, and serialization preserves exact field order, flattening, nullable values and stored bytes. Per-kind payload byte bounds stay with the [persistence bounds](#persistence-bounds).

A CLI process opens one Engine: the attached terminal after its Session starts, `exec` after Provider selection. The Engine's Store thread and shared history lock live until exit, so another process's history reset reports history in use while an attached terminal is open, even idle; Session, lineage and Workspace locks stay per Run. A normal exit closes the Engine and reports a failed close; an error exit drops it, which still stops the Store thread. The Engine runs one operation at a time: a submission or compaction while another is open is refused with `Busy` before any admission or call, and a dropped or finished handle frees it. Each submission brings its own [per-role Provider chains](./provider.md#per-role-selection-and-fallback) and controls (Tool grant, approvals, steering, cancellation, display hints), fixed for every Run of its Goal loop, and its handle follows the committed Event stream from submission on. Invalid chains are refused at submission; a compaction brings the chains whose compaction route it calls. Each attached submission and compaction re-admits the State path and fails closed when it became unavailable or unsafe or names a different directory; a Tool grant loads its configuration at submission.

The [Supervisor adapter](./tools.md#supervisor-adapter) owns decision ordering, replay acceptance and interrupted-prefix recovery. `SupervisorVerdictRecorded` occupies its subject's next sequence with the same Run and actor, is transparent to hook adjacency and Tool correlation, and changes no authority or transition legality. A Run pinned with a Supervisor adds verdict slots to each action's bound, at least the [generated verdict payload bound](./limits.md#max_verdict_bytes) per possible evaluation boundary: one per Provider call, `in-flight + 1` per child step, two per Tool step (a narrowing replacement is a second outcome), 12 per worker action and one per delegated child or child Tool call. `supervisor: null` reserves none.

`AgentSteeringNoteRecorded` is an actor-scoped fact with strict `{goal_id,text}` payload and Run/AgentRun IDs in its envelope. The reducer enforces the [shared steering quota and ChildWork reservation](./goals.md#steering-notes-and-pause); replay rebuilds historical guidance without delivering it.

### Incompatible history

Pre-beta, stored formats are never migrated. Only the current journal schema runs; runtime decoders and the reducer never read another format, and nothing rewrites stored history. Peers keep no per-record versions either: one store version is enough because any mismatch archives the whole journal.

Eligibility is read through a read-only connection, so unsupported history reaches the archive with its database and WAL bytes untouched. History is archived when its schema differs from the current one (older or newer), it holds an unknown or removed Event kind or variant, or any row is replay-invalid. Under the exclusive history and checkpoint locks, `events.sqlite3` and `checkpoints.sqlite` with their `-journal`, `-wal` and `-shm` sidecars are renamed intact into a private `archive/history-<UTC timestamp>/` directory, and a fresh journal opens. A durable `archive/pending.json` first records each file's identity (device, inode, size) or absence, and every rename is fsynced on both sides; a crash resumes the plan, moving only files whose identity matches and never newer files, and any mismatch leaves everything in place with a typed archive conflict. The plan stays until the notice is delivered, then becomes the archive's `manifest.json`. Accounts, settings, folder trust and other StateRoot records stay; nothing is deleted. Attached chat names the archive in its [startup notice](./terminal.md#setup-and-account-choices); headless commands print one `warning: …; started a new history` line on stderr. Damaged SQLite, a busy store, full storage and unsafe or inaccessible files are never archived: attached chat keeps its typed recovery choice with an explicit reset for damaged history, and headless commands exit 1 with a typed `error: …` that, for damaged history, says to run `arany` to reset it.

The same gate covers `checkpoints.sqlite`: a readable checkpoint store at another schema version archives the whole history with it, while a damaged, busy or extra-object store is never archived ([checkpoint store contract](./tools.md#checkpoints-and-rewind)).

### Incompatible records

Private StateRoot JSON records carry no version or schema number; SQLite stores keep their `user_version` above. Each record is one of two classes:

- **Tolerant** preference and cache records, `ui-preferences.json` and `model-preferences.json`: the owner reads known fields, ignores unknown ones, defaults missing ones and drops an entry or value that fails validation; an unreadable record reads as defaults. They are never archived and never refuse startup or a Run; a rewrite may drop fields this binary does not know.
- **Strict** authority records, everything else (`tools.json`, `permissions.json`, `workspace-permissions.json`, `unguarded-commands.json`, `command-environment.json`, `command-tools.json`, `mcp-oauth.json`, `provider-profiles.json`, `provider-roster.json`, `provider-routing.json`, `account-credentials.json`, `chatgpt-accounts.json`, `chatgpt-registration.json`): each kind declares its owner's decoder, which rejects unknown fields, missing required fields, wrong types and failed validation. Peers keep no per-record versions either; a closed decoder is what detects another format.

Before any record owner reads, attached chat, `exec`, `serve` and `acp` run every strict record in the selected State directory and the account root through its decoder. A record the decoder refuses, from an older or newer binary or damaged, is renamed intact, under the account-replacement lock, into one private `archive/records-<UTC timestamp>/` directory (with a `-N` suffix when an interrupted attempt left that name) with fsyncs on both sides; its owner then sees no record and fails closed: the folder asks for trust again, accounts sign in again, rules and routes are re-created. Attached chat adds the archived file names and folder to its startup notice; headless commands print one `warning: …` line on stderr. Unsafe, oversized or unreadable files are never archived or altered: their owner reports them. OS keyring entries are never moved, so a refused keyring entry is refused by its owner, and the ChatGPT and native-account setup resets still cover keyring entries and records that disagree with each other. A crash leaves each record either in place or in the archive, never both; the next start archives what remains.

A change of meaning renames the field. Tolerant records only add optional fields with defaults; any change to a strict record's shape makes an older or newer binary archive it. Guard [capacity](./tools.md#shared-native-capacity-and-settings) and unit-recovery records are strict and unversioned too, but shared live between processes, so they are never archived: a shape this binary refuses fails closed as protection unavailable.

### Workspace rewind Events

`WorkspaceRewindStarted` and `WorkspaceRewindFinished` are Session-scoped facts, each at most the [generated Event payload limit](./limits.md#max_event_bytes) including JSON escaping; larger payloads reject before decoding. Started records a UUIDv7 rewind ID, a Run or rewind checkpoint with its sequence, the head sequence and canonical prefix digest, the effective-plan SHA-256, file count and restored bytes, sorted disjoint kept and overwrite selections, Workspace identity and Tool policy and enforcement digests. Overwrite selections carry the observed digest, byte length and executable bit, or explicit null for absence. Kept and overwritten paths together are capped at 64, each at most 512 bytes<!-- unrelated-bound: rewind selection path bytes -->. Neither selections nor stored bytes grant permission.

Finished records its rewind ID, a closed `restored`, `conflict`, `denied`, `failed`, `cancelled` or `uncertain` outcome, required nullable attestation and checkpoint, and sorted conflict paths (the first 32 plus the exact total, at most 2,048). Restored requires an attestation with plan, Workspace, enforcement and nonzero execution receipt digests; in-process publication binds the intent and its in-process attestation, and historical Guard receipt digests keep their encoding. An attested Uncertain outcome uses the same binding. Exactly those attested outcomes carry checkpoint capture status for overwritten content: captured or skipped if any before state exists, otherwise not_needed. Known refusal or cancellation before publication carries neither capture nor receipt. An unconfirmed outcome without a receipt stays [Uncertain](#effect-outcomes) and does not assert whether publication began. Finished immediately follows its own Started. The [Session contract](./session.md#rewind-planning-and-replay) owns planning, sealing and history projection; [Goals](./goals.md#rewind-and-goal-recovery) owns recovery and evidence invalidation.

Canonical state resolves before repository input and lives in a private directory outside the Workspace, with verified owner and permissions or ACL, a fixed aggregate page cap and admission headroom. SQLite integrity is not tamper evidence, and the database is not encrypted at rest. Persisted objectives, summaries, results and errors are untrusted typed data.

The schema is created only in an empty version-zero database; any other existing version rejects before mutable pragmas run. `MessageAccepted` and `GoalStarted` limits derive from the objective and image caps at six escaped bytes per byte. Goal admission preflights the serialized objective plus admitted include list against the GoalStarted ceiling, so combined escaping can refuse an otherwise individually bounded request before Goal acceptance; large pasted objectives reject before disclosure, usage or a partial fork target, and earlier history and summary stay readable. Byte preflight is conservative and is not a lease against independent writers or disk faults.
