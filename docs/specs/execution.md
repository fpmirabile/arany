# Run execution

## Scope and related contracts

This contract owns bounded Run coordination, delegation, accepted outcomes and history-capacity rejection. The [Goals contract](./goals.md) owns durable task lifecycle, Goal budgets, plan contracts and recovery; every accepted task links its Runs to one Goal. [Tools](./tools.md) owns grants and effect continuations; [terminal](./terminal.md) owns attached controls and agent inspection. Session lifecycle and Provider admission stay in the [Session](./session.md) and [Provider](./provider.md) contracts.

Editing constraints: [security rules](../../agents/security.md).

## Committed Event stream

`Journal::append` feeds progress, telemetry and diagnostics only after Event commit. Each subscriber receives committed envelopes through a 256-envelope broadcast ring. Lag produces `Resync { missed }`; the subscriber recovers from the committed view without blocking execution. Subscriber failure or lag cannot change a Run outcome or grant authority. Provisional Provider previews remain separate from this stream.

## Collaboration

Each accepted task is durably linked to a Goal before its first `MessageAccepted`. Each Run has one accountable primary AgentRun and an ordered, bounded collection of direct read-only children. Children cannot create nested teams or mutate files. In a Run with a Tool runtime each child is a read-only researcher: its spawn pins the `read_only` grant and it may alternate calls with Workspace List/Read/Search, admitted Skill reads and MCP catalog listing, within the Goal plan contract, before returning its bounded report. Before any plan contract a researcher may read any admitted Workspace path, as the primary prelude may; MCP catalog listing starts the admitted stdio server under the Guard. Without a Tool runtime a child makes one reasoning call. A child failure, including one out-of-grant MCP call, still fails the Run. The primary obtains file evidence, performs authorized effects and owns the final answer. Goal completion and Run completion are separate receipts as defined by the [Goal lifecycle](./goals.md#lifecycle-budgets-and-recovery).

Pin one policy before the Run: `single` admits no children; default `auto` allows up to three total direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The persisted `max_active_children` field limits total direct children for the delegation. Policy, process safety and remaining call, token, byte and time budgets bound team size; the pinned primary and child Provider concurrency ceilings separately bound simultaneous calls while admitted children wait in order. A ceiling is permission, not a required team size.

Auto guidance asks the primary to keep routine edits and simple inspection local, delegate substantial independent work only when its benefit justifies extra calls, and choose the smallest useful team. Typed policy and budgets enforce capacity; guidance does not guarantee every model's judgment. Agent inspection distinguishes the current or last Run from historical agents rather than presenting accumulated history as simultaneous activity.

Child authority is the intersection of global policy, parent effective authority and the explicit task grant. Children cannot self-approve or alter sibling authority, and missing configuration never restores a capability.

Child identities and assignments retain ordinal order even when calls finish out of order. Synthesis receives results in assignment order after all terminal dispositions. Child failure drains siblings before primary failure. Cancellation reaches every admitted child and preserves already observed calls and terminal facts.

## Researcher children

One delegation active-time segment covers child calls and child Tools, including their shared Guard capacity waits. Pause also takes effect before each child step.

Read-only research steps of child AgentRuns keep Child Tool facts in the child's own agent view; the primary's run view and its plan rules are unchanged.

| Bound | Value | Overflow |
|---|---|---|
| Children per delegation | existing policy, ≤ 8 | invalid delegation |
| Child objective / report | 2 KiB objective; 16 KiB result, 2 KiB summary | invalid response, child Failed |
| Child Tool calls | `min(16, ((remaining calls − children − 1) / 2) / children)`, 16 if calls are unlimited; replay cap 16 | catalog `tool_calls_remaining: 0`, only Finish offered; a further Tool is an invalid response |
| Child Tool result | `min(16 KiB, (context limit − context − intent − 512) / 6)`; Tools offered only while at least 4.6 KiB fits | only Finish offered; safety net stops the child |
| Delegation time | one active segment, at most 20 min and at most the remaining Goal active time | calls time out, child Failed, Run fails |
| Child Tool time | runtime at most half of (deadline − preparation − cleanup − Store overhead); the Guard capacity wait ends at `expires_at_ms` = start + runtime (Guard returns `Limit` before dispatch, Linux and macOS) | runtime 0: the child stops before `ToolStarted` |
| Events per delegation | child Events at most 928 (8 × (7 × 16 + 4)), admitted with an 8-Event tail plus configured route-switch bounds before the first spawn | Store admission refusal before `AgentSpawned` |
| Concurrency | Provider concurrency for calls; child Tools one at a time per Run | queued |

## Accepted outcomes

Every step produces exactly one phase-allowed semantic Finish, Delegate or enabled Tool proposal. A primary planning or synthesis call may carry the Run's accepted steering notes as user input; child calls and Tool review never do, and a pause takes effect only at the Goal boundaries that [Goals](./goals.md#steering-notes-and-pause) names. There is no fixed per-Run Tool-effect or model-step ceiling; each action still requires bounded Event, Store, request, context and terminal-tail admission, while the Goal's call, Run and active-time budgets bound the complete task. Before its first Goal plan contract, the primary may inspect with bounded Workspace List/Read/Search, typed Git reads, an admitted Skill read, or configured bounded MCP catalog listing in planning or synthesis; any other Tool proposal needs a valid contract before dispatch. A contract can accompany inspection and is still validated before dispatch. After a valid contract is recorded, the primary may continue through sequential Tool observations in planning or synthesis, with each operation still limited by the phase, exact plan scope and admitted Tool grant. Children receive Single policy; a researcher receives only the read-only research catalog, its own observations and Finish. Its MCP calls, writes, commands and plan contracts are invalid before dispatch; its reads outside the plan contract are journaled Denied without dispatch. Unknown operations, invalid arguments, unavailable catalog names and policy-incompatible outcomes reject without repair or an alternate encoding. The [Goal contract](./goals.md#initial-plan-contract-and-success-receipt) defines the exact scope and replay rules.

Tool-enabled OpenAI and ChatGPT primaries use strict native functions with required selection and parallel calls disabled; exactly one complete call is accepted. Final text, unknown, multiple or incomplete calls reject. Read-only requests, advisor children, compaction and Anthropic retain their admitted structured-text encoding. Researcher children use their route's Tool encoding restricted to read-only operations and Finish; it is offline-tested only, and live validation is listed in [next steps](../../NEXT_STEPS.md). Exact custom profiles reject Tool context before HTTP until tool-capable conformance is supported.

Structured-text Responses decoding joins ordered text parts exactly and requires one final structured outcome. Explicit commentary can precede it. The legacy absent or null phase is accepted only for an unambiguous single final. Refusal, malformed content, unknown phases, duplicate or ambiguous finals, late commentary and contradictory error or incomplete markers reject. Missing or invalid fields cannot be repaired by a later valid field.

All adapters reject reported input above the shared input ceiling and output above the exact request cap. Accepted outcomes also fit the exact serialized terminal payload bound, including JSON escaping. Native OpenAI may retain unknown usage; custom and ChatGPT outcomes require positive labeled usage. Native API-key and custom output caps are remote request controls; ChatGPT has a local acceptance cap and cannot guarantee remote generation or plan consumption. A Tool review uses Single policy with no Tools, history, includes or project instructions, its own 256-token cap rather than the ordinary final-answer cap, a 20-second ceiling, and the aggregate 32-call headroom. Uncertainty or failure asks a human and never grants a broader permission.

The selected Provider declares the primary output-token cap and the call deadline; the Run pins the cap in its configuration. Native OpenAI and Anthropic API routes declare 16,384 output tokens, and ChatGPT-plan and exact custom routes 4,096; replay rejects a pinned cap outside 1 to 16,384. Child calls request at most 4,096 tokens. Native OpenAI and Anthropic calls have a 600-second deadline; ChatGPT-plan and custom calls have 120 seconds. Each call also ends at the remaining Goal active time. A Tool review reserves 20 seconds plus Store overhead, compaction keeps its 120-second deadline, and a tool-free delegation reserves one deadline per wave of concurrent children, at most 20 minutes; a researcher delegation reserves 20 minutes. The useful answer ceiling stays at the 32 KiB assistant or result bound: the extra native output headroom is for reasoning tokens, and context budgeting reserves no output tokens.

The ChatGPT route's SSE parsing and item reconstruction rules are owned by the [ChatGPT contract](./chatgpt.md#catalog-checks-and-runs).

Malformed, non-object or duplicate-key MCP arguments, and selected-credential reflections including nested escaped arguments, reject before persistence. Provider failure remains the call's outcome even when an earlier Tool denial could otherwise be continued. Every route has zero same-route automatic retries or encoding fallback; only an explicitly configured, admitted [Provider fallback chain](./provider.md#per-role-selection-and-fallback) can switch destinations after an HTTP 5xx failure at status admission. A lost response can still consume remote usage.

## Admission, persistence and recovery

Persist only the current internal format: SQLite schema 4, one payload version per Event kind (version 6, except version 7 for `RunFinished`, `GoalProviderCallReserved`, `GoalCompactionCallReserved`, `ToolStarted` and `ContextCompacted`, version 8 for `ToolFinished`, version 9 for `RunStarted`, and version 1 for `ProviderFallbackUsed` and `ToolPermissionDecided`) and compaction compiler version 3. Active time is journaled per Run and per action-start ceiling as [Goals](./goals.md#lifecycle-budgets-and-recovery) defines; there are no per-action active-time Events. Required fields and nullable fields are explicit, including Goal linkage and budgets, Run configuration and its active deadline, Provider provenance, pinned Tool resource values and the required Tool cache-update outcome. Reading unsupported stored formats or missing fields rejects without conversion, automatic deletion or an optimistic projection. Replay rejects an accepted task without a valid Goal linkage; no unlinked legacy Run path or compatibility projection exists. The additive Run-scoped `GoalSteeringNoteRecorded` Event is part of payload version 6 and is accepted only inside the open primary provider reservation, as [Goals](./goals.md#steering-notes-and-pause) defines. A child Tool without its finished observation is interrupted history and blocks explicit resume. Attached startup offers the [explicit history reset](./terminal.md#setup-and-account-choices); it discards history rather than converting or admitting an unsupported format. Each Provider call record also journals `requested_tools` (one per declared model Tool request) and the cache-read and cache-creation usage beside the input total.

Admit every selected role Provider and configured fallback and the complete bounded request before Workspace disclosure. A task objective is at most 64 KiB of UTF-8; the attached composer and `arany --prompt` still limit a draft to 8 KiB, and steering notes keep their separate 8 KiB per-Run bound. Pin the Workspace, instructions and includes, policy, model, effort and caps for the Run. The `RunStarted` wall-clock timestamp precedes its append acknowledgement; `AgentSpawned` follows that acknowledgement. Commit accepted Message, Run and primary identity before inference; commit each observed call before its terminal AgentRun disposition. A failed call commits failure without an assistant Message. Replay requires an observed delegation before child spawn and an observed successful call before successful Agent completion. Known call usage survives an interrupted journal prefix.

`RunStarted` remains `{config, active_deadline_ms}`. `config.providers`, when present, pins four non-empty chains of complete identities. Its primary initial identity must agree with the existing primary config fields; the effective concurrency may narrow the declared ceiling. Without that field all roles inherit the existing pinned primary identity and no fallback exists. This is the canonical inherited representation in payload v9. The Tool policy receipt also requires its nullable permissions digest; unsupported previous versions reject. Invalid provenance, inconsistent primary fields, missing role chains, redundant all-inherited chains, unsupported limits and incompatible Tool-role adapter/account chains reject replay.

`ProviderFallbackUsed` is a Run/AgentRun-scoped fact containing role, bounded call index, unavailable disposition and exact `from`/`to` identities. It atomically settles the preceding pre-output failed attempt and reserves the next call, before egress, under the same active action ceiling. The original reservation remains open for the final step record. Every extra attempt increments the Goal's call count and marks failed-call token usage unknown. It adds no fabricated assistant outcome, Tool proposal or usage count. The coordinator alone writes the journal and updates the Goal ledger. Child tasks hold only a Provider, request, cancellation and deadline; they return an eligible-failure marker. The coordinator checks compatibility and budget, commits the switch, then respawns the child attempt. Draining child tasks never retains Store or ledger ownership. A crash after the switch retains the failed attempt and charges the unresolved replacement reservation; strict replay executes neither.

Replay requires the actor, role and call index to fit an open reservation, the identities to be adjacent in the pinned chain, sufficient call budget and no finite-token budget that unknown usage would violate. A primary's current display chunks prohibit a switch. The eventual call phase must fit the switched role, and its reported output must fit that role's cap. Compaction records must name the actual pinned or switched compaction route; between-Run compaction uses its compaction boundary index and never changes a closed Goal's receipt or usage. Switches stay within 64 facts per Run and survive closed-store replay, inspection and the bounded Goal report. They never dispatch a Tool, and an uncertain effect still stops its continuation.

Attached visual streaming has separate primary and call-scoped display observations. A progress observer cannot authorize, steer or cancel. The Engine checkpoints bounded safe prefixes in `AssistantDisplayRecorded`; these facts remain outside accepted outcomes, model context and compaction. Cancelled or abruptly interrupted replay recovers only acknowledged text. Complete outcome validation still controls `MessageCommitted`, and an incompatible provisional prefix fails validation and strict replay. Run progress ends at the committed `RunFinished` Event; the later session-scoped Goal settlement and receipt are not retroactively added to the Run snapshot. Run progress observers see only acknowledged Events and cannot authorize, steer or cancel a Run. The [terminal contract](./terminal.md#terminal-continuity-and-provisional-text) owns presentation and detailed bounds.

Before Workspace input, inference or Tool preparation, require logical Event capacity for the Goal lifecycle and the next bounded action, plus conservative database-byte headroom, including the terminal facts needed to close that action and Run. Before each actual Provider or Tool dispatch, Store atomically admits the specific reservation and sufficient Event and byte headroom for its observation and terminal tail. The serialized reducer rejects a racing reservation that no longer fits. Capacity waiting and approval do not charge active Goal time or call usage; queued children are charged only after concurrency capacity is available. The Session and fork ancestors remain locked for the Run. Independent lineages remain concurrent; byte preflight does not reserve physical disk or guarantee against storage faults. Reject capacity exhaustion before disclosure or usage and direct the user to a new Session.

Fork admission validates the resulting lineage's depth and total Event count atomically; a failure leaves no partial target. Replay resolves at most eight lineage links and 10,000 Events and verifies exact inherited prefix digests. Compaction has no fixed lifetime attempt count: each attempt must fit the current Goal budget, per-action Store and Event headroom, and request and context bounds before inference or an attempt Event. Failure preserves the last good summary and canonical history. Compaction remains derived context; it does not remove canonical Events or restore Tool permission. The serialized compaction input is at most 252 KiB, derived as (512 KiB request ceiling minus an 8 KiB envelope) / 2, because each adapter embeds that input as an escaped JSON string and quotes and backslashes double; an escape-heavy session over this bound fails closed with `CompactionInputTooLarge` before any Provider call. The automatic compaction threshold is 158,080 bytes: the input bound less room for two turns of the 8 KiB attached draft (each turn reserves its draft, steering context, a 32 KiB assistant answer, separators and image metadata). Automatic compaction therefore fails closed for turns above the attached draft size, such as 64 KiB `exec` objectives, with `CompactionInputTooLarge`. An in-Goal compaction input can carry a pinned Goal objective in its pinned Goal context and again in the Goal's first turn when that turn is in the compacted prefix; a 64 KiB prose objective still compacts within the bound, and an escape-heavy one fails closed.

For each in-Goal compaction and subsequent primary Provider request, bounded context reintroduces the pinned objective, project instructions and includes, approved plan or contract and current typed Goal facts. The projection carries dispatched call count, known tokens plus the unknown-usage flag, settled, reserved and uncertain active time, and the current optional success-criterion state; it contains no historical Tool body. It does not replay old Tool effects, promote historical output to instructions or use provisional display text as accepted context. Compaction checkpoints only an acknowledged prefix of active-Run Tool observations using exact Run identity, covered Tool count, ending sequence and digest proof, then stores a bounded untrusted summary. All observations remain canonical Events; Provider context uses the latest summary and a bounded recent tail. Replay checks the active prefix and summary digest without another Provider call. A failed attempt preserves the prior summary; another attempt requires a later acknowledged Tool prefix and consumes its own Goal call, time and Event budget. The summary grants no authority. This compaction contract does not claim complete per-phase or worker-specific context capsules; that behavior remains with the follow-on Goal-completion slice. Context construction respects the 376 KiB compiled-content ceiling, the selected remaining-byte Tool-history allowance, individual Tool argument and result limits and the 512 KiB encoded-request ceiling. A trusted exact route and model input-window bound may reduce the derived request budget, but bytes are not converted to token counts. Public model cards and display model IDs do not prove the selected saved ChatGPT route's context window; when exact route metadata is unavailable, the conservative local byte bounds stay in force and no expanded-window compatibility claim is made. `MAX_REPORTED_INPUT_TOKENS` validates reported usage only; it is not a model-window estimate.

Tool attempts and results are untrusted historical facts. Replay, resume, fork and compaction never execute old intents or restore permission. A command-generated `ApplyChangeset` is internally correlated to its exact preceding command receipt; if it exceeds the active Goal path scope, Engine records a no-Guard denial, and replay rejects any successful out-of-scope integration. Pre-dispatch Guard failure stops as Failed without effects; once the GO write begins, missing completion is Uncertain. Uncertain or cancelled effects stop without another call, retry or rollback claim. A fresh task may inspect current files and propose a newly authorized edit with fresh preconditions.

Cancellation before Message acceptance creates no Run. After admission it drains in-flight work and commits cancellation without a final answer, preserving prior facts. A terminal commitment already started wins its race with cancellation. Store failure leaves an interrupted prefix rather than manufacturing success or a cancellation receipt.

Run and compaction hold the Session lock and every fork ancestor's operation lock, because strict replay counts ancestor suffixes outside the inherited boundary. Cancellation is a sticky caller signal whose waiter interrupts pre-Engine admission; dropping a waiter does not undo started work.

A CLI process opens one Engine: the attached terminal after its Session starts, `exec` after Provider selection. The Engine's Store thread and its shared history lock live until exit, so another process's history reset reports history in use while an attached terminal is open, even when idle; Session, lineage and Workspace locks stay per Run. A normal exit closes the Engine and reports a failed close; an error exit drops it, which still stops the Store thread. The Engine runs one operation at a time: a submission or compaction while another is open is refused with `Busy` before any admission or Provider call. Each submission brings its own [per-role Provider chains](./provider.md#per-role-selection-and-fallback) and controls (Tool grant, approvals, steering, cancellation, progress), fixed for every Run of its Goal loop, and its handle follows the Engine's committed Event stream from submission on. Invalid chains are refused at submission; a compaction brings the chains whose compaction route it calls. Each attached submission and compaction re-admits the State path and fails closed when it became unavailable or unsafe or no longer names the directory the Engine holds; a Tool grant loads its configuration at submission.

### Persistence bounds

| Bound | Limit | Overflow |
|---|---|---|
| Session lock files | 65,536, including pre-commit files stranded by process death; the directory scan stops after that bound plus 32 State files | quota failure before Workspace input or Provider disclosure |
| Workspace writer lock files | bounded and shared across StateRoots; the limit is owned by [Goals](./goals.md#lifecycle-budgets-and-recovery) | new writers refused before disclosure or effects |
| Direct-Session projection cache | 128 MiB of serialized Event payload | not kept; the next append replays strictly |
| Event payload, default | 64 KiB | append refused |
| `MessageAccepted` | 656 KiB, with inline PNG bytes (an empty list for text) | append refused |
| `GoalStarted` | 400 KiB | append refused |
| `ToolFinished` | 144 KiB: twice the 64 KiB Tool result plus the 16 KiB argument bound; admission reserves it only for the `ToolFinished` slots an action may append | append refused |
| Steering note per Run | 8 KiB, including history labels | offer refused; the caller keeps its text |
| Requested Tools per model step | 0, or 1 to 4 for a `ToolRequested` disposition | replay refused |
| Evidence caches | 32 custom Provider rows and 256 native rows; native rows expire after 24 hours | expired rows are removed first; a new row beyond the bound is refused as storage full |
| Session discovery | 65,536 heads | exact-ID resume fallback |
| `provider-profiles.json` and `tools.json` | 64 KiB each, read only through the admitted handle | rejected; never parsed as trusted configuration |

Canonical state resolves before repository input and lives in a private directory outside the Workspace, with verified owner and permissions or ACL, a fixed aggregate page cap and admission headroom. SQLite integrity is not tamper evidence, and the database is not encrypted at rest. Persisted objectives, summaries, results and errors are untrusted typed data.

The schema is created only in an empty version-zero database; any other existing version rejects before mutable pragmas run. `MessageAccepted` and `GoalStarted` limits derive from the objective and image caps at six escaped bytes per byte. Byte preflight is conservative and is not a lease against independent writers or disk faults.
