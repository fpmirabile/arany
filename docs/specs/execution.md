# Run execution

## Scope and related contracts

This contract owns bounded Run coordination, delegation, accepted outcomes and history-capacity rejection. The [Goals contract](./goals.md) owns durable task lifecycle, Goal budgets, plan contracts and recovery; every accepted task links its Runs to one Goal. [Tools](./tools.md) owns grants and effect continuations; [terminal](./terminal.md) owns attached controls and agent inspection. Session lifecycle and Provider admission stay in the [Session](./session.md) and [Provider](./provider.md) contracts.

Editing constraints: [security rules](../../agents/security.md).

## Committed Event stream

`Journal::append` feeds clients, telemetry and diagnostics only after Event commit. Each subscriber receives committed envelopes through a 256-envelope broadcast ring. Lag produces `Resync { missed }`; the subscriber recovers from the committed view without blocking execution. Subscriber failure or lag cannot change a Run outcome or grant authority. Provisional Provider previews remain separate from this stream.

An envelope's `created_at_ms` is Unix wall time in milliseconds sampled inside the transaction before reducer validation, insertion and commit. Persisted timestamp differences are journal intervals, not monotonic elapsed time through commit acknowledgement. The [offline Tool latency corpus](../../crates/arany-cli/tests/guard_runs/latency.md) measures that acknowledgement separately and audits its scoped joins against closed history.

## Collaboration

Each accepted task is durably linked to a Goal before its first `MessageAccepted`. Each Run has one accountable primary AgentRun and an ordered, bounded collection of direct researcher and EditOnly children. Children cannot create nested teams; only EditOnly children may mutate their private assignment views. In a Run with a Tool runtime each researcher is read-only: its spawn pins the `read_only` grant, while each EditOnly child works under its pinned private assignment grant. A researcher may alternate calls with Workspace List/Read/Search, admitted Skill reads and MCP catalog listing, within the Goal plan contract, before returning its bounded report. Before any plan contract a researcher may read any admitted Workspace path, as the primary prelude may; MCP catalog listing starts the admitted stdio server under the Guard. Without a Tool runtime a child makes one reasoning call. A researcher failure, including one out-of-grant MCP call, fails the Run and drains every sibling. An editor failure remains local as specified below. The primary obtains file evidence, performs authorized effects and owns the final answer. Goal completion and Run completion are separate receipts as defined by the [Goal lifecycle](./goals.md#lifecycle-budgets-and-recovery).

Pin one policy before the Run: `single` admits no children; default `auto` allows up to three total direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The persisted `max_active_children` field limits total direct assignment attempts across the Run, including researchers, failed captures, replacements and later waves. Policy, process safety and remaining call, token, byte and time budgets bound team size; the pinned primary and child Provider concurrency ceilings separately bound simultaneous calls while admitted children wait in order. A ceiling is permission, not a required team size.

Auto guidance asks the primary to keep routine edits and simple inspection local, delegate substantial independent work only when its benefit justifies extra calls, and choose the smallest useful team. Typed policy and budgets enforce capacity; guidance does not guarantee every model's judgment. Agent inspection distinguishes the current or last Run from historical agents rather than presenting accumulated history as simultaneous activity.

Child authority is the intersection of global policy, parent effective authority and the explicit task grant. Children cannot self-approve or alter sibling authority, and missing configuration never restores a capability.

Child identities and assignments retain ordinal order even when calls finish out of order. Synthesis receives committed reports in assignment order; background coordination includes explicit pending identities without provisional child text. Researcher failure drains siblings before primary failure. Cancellation reaches every admitted child and preserves already observed calls and terminal facts.

A delegation abort preserves its original failure when sibling draining also fails; the drain failure is diagnostic only.

A primary outcome-contract failure is committed as `ProviderCallRecorded` with `invalid_response` and `outcome_contract` before the [single corrective call](./provider.md#structured-outcomes-and-tool-encoding) can reserve and dispatch. Replay permits that same-phase continuation only after the first such failure, with settled Tools and hooks, and rejects another reservation after the second. Reservations and unknown usage remain charged normally; no effect is replayed. If correction also fails, the Run records `provider_call` and retains the final typed parse reason. Subsequent context uses the [committed failure projection](./session.md#context-and-compaction), never an invented causal explanation.

A framed Provider response whose content cannot decode into an offered answer or typed proposal records `invalid_response` with the closed `outcome_decode` reason. It is distinct from `outcome_contract`, which permits one corrective call, and `response_contract`, which covers identity, usage and provenance after decoding.

## Researcher children

One delegation active-time segment covers child calls and child Tools, including their shared Guard capacity waits. Transition-driven accounting charges overlapping Provider, effect, preparation and cleanup work once. A pending child Ask pauses this allowance while idle; sibling activity continues to consume it. Exhaustion withdraws the Ask before dispatch with its delegation or Goal cause. Pause also takes effect before each child step.

Read-only research steps of child AgentRuns keep Child Tool facts in the child's own agent view; the primary's run view and its plan rules are unchanged.

## Agent definitions

**Recorded owner decisions — 2026-10-18:** use only exact Workspace `.claude/agents/*.md` and the admitted private StateRoot `agents/*.md`, with private names winning; accept one strict Claude-format subset. No home, plugin, recursive or alternative-format discovery is admitted. The project directory must lie wholly inside the parent read grant. Missing directories are empty; unsafe present entries (symlinks, links, non-owned or oversized files, bad names) refuse the whole registry before any Provider call.

**Recorded owner decision, revisitable — invalid definitions are skipped, not fatal (peer behavior: Claude Code skips an invalid agent file and reports it):** a file whose content is invalid (bad frontmatter or field value, YAML anchor/alias/tag, size bounds, duplicate name within a source) is skipped with a bounded diagnostic naming the file and field, journaled in the parse receipt and shown in the Goal report evidence. Unsupported frontmatter fields (for example `color`, `hooks`, `mcpServers`) and unsupported tool names are ignored with a diagnostic; ignoring can only narrow authority. A `model` other than `inherit` that is not the exact admitted initial child model is treated as `inherit` with a diagnostic. The registry lists at most 8 KiB of base entries in name order; later definitions are dropped with a diagnostic. Foreground editor metadata adds its normalized digest and turn ceiling at Engine admission; if the complete agent catalog then exceeds 8 KiB, initialization fails before Provider disclosure. Selecting a skipped, dropped or absent name is an invalid delegation that fails the Run before any child spawn. Discovery is an immutable raw-byte snapshot during input preparation. [Parser admission](./tools.md#agent-definition-parser-admission) owns filesystem and Guard enforcement.

The envelope is Markdown with YAML frontmatter. `name` and `description` are required strings; the only optional fields are `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `isolation` and `background`. Duplicate or explicit-null fields, and wrongly typed or out-of-range values, make the file invalid (skipped). Names use lowercase ASCII letters, digits, `_` and `-`, at most 64 bytes. Description is nonempty and at most 2 KiB; body is at most 32 KiB. The body is labelled untrusted assignment guidance in the child's user input, never a system role. The primary receives bounded names and descriptions, without unselected bodies.

Tool lists accept comma-separated strings or string arrays, at most 32 names of 128 bytes each. `Read`, `Grep`, `Write` and `Skill` map to `read`, `search`, `write` and `skill`, `Edit` maps to `edit`, `multiedit`, `delete` and `move`, and `MultiEdit` maps to `multiedit`, and `Glob` maps to both `list` and `glob`; exact names for those operations plus `mkdir` and `mcp_list` are accepted. `Bash` maps to `command` for editors only, as a narrowing permission, and a denied `Bash(...)` pattern denies every command; exact `command` is also recognized. Unknown names, patterns, Agent, Git and MCP invocation are ignored with a diagnostic and grant nothing. Missing `tools` inherits the admitted catalog for the assignment kind; `disallowedTools` subtracts. An empty effective edit capability supplies no write authority.

**Recorded owner decision — model and mode overrides:** omitted model or `inherit` retains the complete parent-admitted child chain. Definition model metadata cannot override an assignment-selected profile. A literal model equal to its initial admitted child's exact model is kept; any other value cannot select a route, account, alias or credential lookup and is treated as `inherit`. The five [permission-mode spellings](./tools.md#modes-and-approval-decisions) can only narrow parent settings and live terminal restrictions, using Deny > Ask > Allow. File text never grants a capability or resolves an approval.

The primary's Delegate may select one registry name through `agent` for that group of researcher objectives; null or omission selects the existing default researcher. Selection is validated before any child spawn or call and pinned by the required nullable `AgentSpawned.definition`. A selected definition narrows the read-only catalog and can reduce child inference turns to 1–17 (`maxTurns`, default 17); Tool reviews do not consume inference turns. The existing maximum 16 model Tool requests and Goal headroom still apply. The last available turn offers answer only. An extra Tool, unknown name or unsupported editor selection is an invalid delegation/child response and fails the C1 Run, without granting or dispatching the requested effect.

**Recorded owner decision — isolation:** `isolation: worktree` requests a disposable Guard view without `.git`, diverging from Claude Code's actual Git worktree because of Arany's hostile-Git and per-effect isolation guarantees. An editor definition requests this isolation; omitted `background` is `false`. A definition with `background: true` requires background assignment mode; a foreground default may be explicitly scheduled in either mode. A researcher group cannot select an editor through its group-level `agent` field.

`RunStarted.config.agent_definitions` is required nullable data: null for an empty/unavailable registry, otherwise the ordered source/filename/raw-digest pins and their SHA-256. Internal parser intents follow the primary spawn, in that exact order, before the first Provider reservation. A matching successful Guard observation fixes each closed normalized-v1 result, either a definition with notes or a skipped-file diagnostic. Private precedence applies after all documents are classified. Strict replay verifies these facts and model admission, requires every parser observation before Provider reservation, rejects late refresh or duplicate parsing, and never reruns a parser. Internal preparation is excluded from model Tool counts, history and compaction bodies; compaction `covered_tool_count` indexes the Run's Tool Events, with the leading parse steps counting as already covered. Interrupted parsing supplies no authority; a new Run requires fresh snapshots and Guard admission.

| Definition bound | Limit / overflow |
|---|---|
| Discovery | 256 scanned entries per source; 64 candidate Markdown files per source; 1 MiB aggregate raw bytes; whole refusal |
| File and normalized registry | 64 KiB per raw file; 1 MiB aggregate normalized records; existing Tool observation, Guard task, catalog and request ceilings may reject sooner; no truncation |
| YAML | 4096 nodes, depth 32; no aliases, anchors, tags or duplicate keys; an unterminated quote at a line end is refused; the file is skipped |
| Catalog | 8 KiB of agent entries; later names dropped with a diagnostic |

A Delegate decision admits one wave of mixed researchers and editors. Each proposal is validated in full before any child disclosure: malformed definitions, paths, overlapping leases, wave numbers or total-attempt overflow refuse the proposal. There are at most eight total attempts under explicit team policy and three under default auto. A replacement requires an explicit new Delegate decision, fresh ID, grant, base and lease; `supersedes` may name a terminal, released child of this Run. There is no automatic retry. Explicit `resumes` names a terminal or interrupted historical child of the same Session/Goal; [Session identity](./session.md#worker-identity-and-explicit-reassignment) owns admission and bounded historical context. It always creates a fresh assignment, base, grant and lease, never private-state continuation.

The Engine pins worker concurrency at four by default, configurable only through Engine settings to 1–8, then narrows it by policy size and admitted Provider concurrency. A finite-token Goal serializes all Provider calls, including background primary coordination. Only available slots admit queued assignments and reserve calls; later assignments never spend calls while queued. Every pending assignment, completion and report collection is bounded by eight; one Tool remains pending per Run. Overflow refuses admission without dropping a member.

A worker retains at most 64 MiB of base plus current image, including conservative metadata allowance; the aggregate is at most 256 MiB. Above concurrency four the per-worker limit narrows to 256 MiB divided by the pinned concurrency, so oversized bases or edits fail before dispatch. The reducer checks the same limit. No native storage/profile limit is raised.

The coordinator consumes Provider completions in observed completion order, captures and commits each eligible handover and settles that queue head before polling the next completion. The committed handover sequence determines integration order, including conflict/discard; there is no ordinal or wall-clock sort. Reports retain assignment order independently. An ordinary editor failure, invalid outcome, private Tool failure or positively contained private uncertainty discards that actor's work and releases its lease while healthy siblings continue. A researcher failure remains fatal; unknown Workspace publication or unknown containment stops the entire Run.

Foreground children block primary coordination until their terminal settlement. Background children are children of this exact Run, never detached jobs: they permit primary RootSynthesis inspection and lease-disjoint typed edits while pending. While workers are active the primary is called once when coordination opens and again after each of its own Tool steps; after an answer it is called again only once a new worker has settled, never to poll. A primary text answer is deferred: the call is journaled as an invalid response with `worker_answer_deferred`, the Run continues, and the primary answers again after the workers settle with their results. A primary Delegate, or an edit overlapping a live lease, is refused the same way: no Tool intent is journaled, the Run does not fail and healthy workers continue, and the primary's next request carries a `last_answer_refused` note. The committed invalid-response reason is `worker_delegate_refused` or `worker_tool_refused`, so a crash before that next request preserves the refusal. These closed reasons identify a primary RootSynthesis call admitted during unsettled background coordination; workers may settle before its response commits. Primary commands and MCP processes are held until every lease is released. A budget, cancel or pause stop during background coordination records one WorkerStopObserved, schedules no further work and drains to an honest terminal outcome. A stop is recorded only for Runs with editors; a researcher-only team never records one. Run closure cancels/drains all modes. Only committed child reports and pending IDs enter coordination context. Primary answer and the next Delegate require all current assignments terminal, handovers settled and leases released, plus fresh passing verification for integrated/no-change assignments. Every successor wave captures the then-integrated Workspace; no DAG, restart or cross-Run lease is introduced.

For a wave-primary request, the Engine binds the primary route and cap, admits worker use, and reserves the Provider call before final primary-context preparation. It constructs the Provider request only after that context is ready. The prepared input, selected model and output cap are unchanged; a refused reservation or stop dispatches no request.

## Worker journal protocol

Every EditOnly AgentRun uses the same `execute_step` and `before_dispatch` as the primary and researchers. A write-capable parent with admitted definitions pins a worker policy; Implementation and a committed Goal plan are required before a primary Delegate can select an editor. The Engine journals base capture before the spawn that acquires its lease, every private mutation and data seal before continuation, and guarded cumulative capture after observed worker answer. Worker answer, handover eligibility, primary ApplyChangeset, integration disposition and lease release are separate committed facts. Worker private edits leave the Workspace unchanged until the primary's eligible integration. A no-change handover is discarded/released without publication and still requires fresh primary verification.

Before producing data, admission narrows the assignment's finite allowance to remaining serialized Store/Event headroom. Each later call, private Tool, capture and integration reserves its complete bounded action plus terminal tail. A known capacity refusal stops before dispatch; a failed append or acknowledgment stops advancement. The action bound is `N + 12 + (4*A + 6) + switches`, conservatively reserving all eight possible outstanding assignments (`A=8`), admitted chunk count `N`, and the configured review, child and primary switch slots. A whole candidate that cannot fit is refused, never split or partially published.

An invalid worker outcome records InvalidOutcome; a Tool request on its final inference turn records TurnLimit, while an ordinary private Tool failure records ToolFailed. A private command result that fails validation also records InvalidOutcome. A private Tool step stopped by cancellation, pause or another actor's hook stop ends the editor `cancelled` with cause `cancelled`. A private Tool step stopped by active time or the Goal budget records `budget`. An editor's answer that passes the in-view gate runs the same guarded SubagentStop lifecycle as a researcher before capture; blocked feedback may consume only remaining admitted turns. A pre-dispatch permission refusal with an unapproved verdict, or with a `Declined` or `ChannelUnavailable` approval cause, and no approved verdict or effect attestation is a known non-dispatch and follows the [shared denial delivery and continuation rules](./tools.md#permission-modes-rules-and-hooks). Child approval timeout is terminal and cannot authorize another child continuation. A denied Tool without its required verdict is invalid history. An approved or dispatched private Tool that returns Denied is an ordinary private Tool failure and ends the actor with its typed cause; it does not authorize a continuation. A closed approval channel, exhausted actor turn or stopped Run still ends the actor. The [approval lifecycle](./tools.md#folder-trust-and-approvals) owns unavailable replies and cancellation/pause behavior. A positively contained lost private receipt also ends that actor, records its typed disposition and cleanup, discards unpublished work and releases the lease. The primary receives the local failure and may report the task's unresolved criterion. Child reports carry up to eight recent Tool outcome facts for researchers and editors, using compiled denial labels and enforcement diagnostics, neutral denial details only when neither permission nor enforcement causes are available, and typed dispositions without raw hook, rule or output text. Private command facts retain validated exit codes and typed capture rejection causes, including rejected captures with a Succeeded process disposition. Goal budget, cancellation or pause is committed as WorkerStopObserved before further team decisions; no subsequent effect or handover eligibility is admitted. Conflict or a denied integration records a whole-batch prepublication refusal and discard/release; the primary then synthesizes with an honest local worker-failure report (nothing was published), and the lease counts as settled without verification, as in replay. An unknown Workspace publication records Uncertain and stops the entire Run, without release, retry or successful completion. Successful primary answer requires fresh passing worker verification as well as the Goal criterion.

`RunStarted.config.worker_policy` is required nullable data. A non-null pin declares admitted parent read/write roots, the closed file/research/command Tool subset, Skill/server names, sorted parent `commands` (0–8 unique names, at most 64 bytes each), permission restriction, concurrency (1–8), turns (1–17), model Tools (0–16) and finite serialized data allowance (at most 48 MiB). Runtime pins the effective concurrency described above, 17 turns, 16 Tools and a 48 MiB maximum data allowance; policy total-attempt limits are unchanged. These are authenticated admission facts, never authority supplied by a definition, model, receipt or replay.

`ProviderCallRecorded.delegation` is required nullable: a nonempty, at-most-eight list exactly for Delegated, null otherwise. Its closed assignments distinguish researcher objective/nullable definition/nullable profile from editor definition/digest, mission, direction, sorted lease roots, required sorted `commands` (0–8 unique names, at most 64 bytes each), typed criterion, foreground/background mode, turn ceiling, wave, and explicit nullable resumes/supersedes IDs. Researcher and editor wire requests normalize into this list; [Provider](./provider.md#scope-and-related-contracts) owns the offered envelope. Every spawn must match its exact proposal and ordinal. Total attempts, including later waves, cannot exceed the pinned policy limit. The reducer validates successor-wave and background-coordination ordering independently of runtime scheduling.

`AgentSpawned.assignment` is required nullable, null for primary and researchers and present exactly with `ChildGrant::EditOnly`. Its pins add the effective grant, parent policy/permission digests, exact committed base-manifest reference, required nullable `cache_generation` (a nonzero SHA-256 digest, null when no worker cache generation is admitted) and remaining data allowance. The effective grant includes the assignment command names and cannot exceed the parent, plan or definition. Spawn acquires the fixed lease atomically. Editor admission requires Implementation, a valid committed Goal plan, a write-capable parent, a parsed matching definition and bounded prior base capture. Read/write/Tool/Skill/server restrictions intersect the parent, definition and Goal; permission modes independently narrow. A base manifest must cover leased creation/absence targets and contain only admitted read paths. An absent subtree root pins absence of its descendants as well as the named root. Names, model overrides and definition body retain the restrictions above.

Writable leases name 1–64 sorted relative files/subtrees of at most 512 ASCII bytes and depth 16. Backslashes, traversal, protected components, controls and non-ASCII writable paths reject. Ancestor/descendant and ASCII case-folded aliases conflict, including within one proposal. Reads retain Unicode-safe admission. Primary typed writes cannot overlap live leases, and primary commands/MCP processes wait for lease quiescence. Acquisition cannot silently replace another owner; there is no TTL or cross-Run lease.

Every Tool intent has `target: Workspace | WorkerView { assignment_id, base_digest, revision, cache_generation }`, included in its digest. Existing primary and researcher intents target Workspace. A private target must match its actor, current assignment revision and spawn-pinned cache generation. Successful private mutation requires a target-bound Guard receipt and a sealed complete before/after delta; revision advances once only after its matching committed observation. Private reads bind their intent and require the execution site's receipt. Workspace attestations cannot attest private work, and private attestations cannot prove Workspace publication or Goal success. Unguarded commands, Git, MCP invocation and nested delegation cannot become worker capabilities. Editor commands use the shared Tool step, including delegated PreToolUse/PostToolUse hooks, permission verdicts and canonical Supervisor evaluation. Commands are serialized across the Run; Provider calls may still overlap. A command criterion requires that exact command in the effective assignment grant before spawn.

A worker `Command` requires its exact name in the effective grant and one pending Tool at most across the Run. Its `WorkerCommand` attestation binds the Guard receipt to the private intent. The typed JSON observation output is `WorkerCommandResult { exit_code, stdout, stderr, private_capture }`, with required nullable `exit_code` and closed capture variants `none`, `sealed { data }` or `rejected { cause: out_of_lease | overflow | unsupported_entry }`. It has the existing bounded Tool result ceiling; no Workspace changeset is embedded. An attested worker command always records `cache_update: discarded`; worker cache publication and Workspace attestations reject. A known command non-dispatch, nonzero exit or rejected capture may continue only within the existing Tool/turn limits. A Denied command needs its permission verdict to continue; a refusal without a required verdict rejects replay, and a verdict-free refusal under unconfigured permissions ends that actor. Timeout/output overflow has no capture. Private Uncertain or cancellation stops the actor without retry.

Worker command capture references use one current record shape and may resolve before or after their committed observation. The Engine seals the complete private capture first and builds its observation from that committed sequence range; replay also admits an observation followed by its referenced chunks and seal. Both orders bind the exact range, producing Tool and assignment, within the remaining assignment allowance. New calls, Tools, hooks, spawns and handovers remain blocked while the observation or its capture is pending. The revision advances once, only after both the matching attested observation and its seal validate the complete lease-contained delta against the pinned revision. Empty or rejected capture never advances it. Interrupted intent, observation, chunk and seal prefixes are valid history and confer no new image revision until both facts commit; strict replay never executes a command, restores cache or reconstructs native storage. Typed file mutations retain their seal-before-observation order. Supervisor verdicts follow each eligible committed boundary before continuation; the Engine never predicts verdicts to number worker data references.

Internal `PrepareWorker` admits only base or handover capture with an exact assignment ID, maximum bytes and chunk count. Base capture follows its open proposal before spawn; another capture cannot replace an unspawned preparation. Handover capture follows observed child answer before AgentFinished. Preparation is excluded from model Tool counts and historical Tool bodies; there is no general blob/script API. One Tool remains pending per Run; only correlated data and seal records can complete its data production. Unsealed interrupted prefixes remain valid history and authorize nothing.

Chunk and seal Events use the current SQLite schema, the [Session Event cap](#persistence-bounds) and the 256 MiB database limit, and normal Store headroom. The assignment's data allowance counts every sealed record and its pending bytes; nominal caps do not promise available capacity. Private typed changes are preflighted against the remaining allowance before GO. The [Tool contract](./tools.md#private-worker-targets-and-handover-transfer) owns per-action private storage, framing, native enforcement and disposal. Replay validates canonical JSON, closed fields, content hashes, base64 and independent decoded/serialized bounds. It retains bounded manifests, current overlay facts and exact sealed references; superseded mutation facts and incomplete private buffers supply no authority. An identical final cumulative delta may reuse a committed mutation seal through an attested handover capture without a second data charge. Bulk bytes never enter Provider input, progress or telemetry automatically. Command capture keeps its independent [changeset bound](./tools.md#command-changesets).

`AgentFinished.worker` is required nullable and present exactly for editors: ready, no_change, failed, cancelled, lost or private_uncertain, with a matching closed cause (a hook stop by the editor is failed with cause `stopped_by_hook` and agent disposition `stopped_by_hook`) and exact nullable cumulative data reference. A blocked editor SubagentStop that cannot reprompt records `budget` when its delegation deadline, call or token budget prevents continuation, and `turn_limit` only when turns alone prevent it. A hook cut-off keeps its own cause even on the last turn. Context overflow retains `tool_failed`: the closed cause set has no context-limit cause, and neither `turn_limit` nor `invalid_outcome` describes a valid answer whose hook feedback cannot fit. Ready/no-change require an observed answer, validated cumulative data against the base and acknowledged overlay, and current private criterion evidence. File criteria use a private Read or a successful attested mutation/capture proving the digest in the acknowledged final image. A guarded handover capture confirms that image before settlement. A command criterion requires the latest matching successful private Command with exit zero and empty or sealed accepted capture. A later private mutation or command invalidates earlier evidence. Worker evidence never satisfies primary verification or the Goal criterion. Failure/loss requires a positive cleanup receipt bound to assignment/base/revision, enforcement and last intent before discard/release. Unknown private work stops that actor permanently; it never becomes Workspace uncertainty or authorizes a retry. C1 child failure still forbids successful synthesis; a settled failed editor does not abort healthy siblings in the replay model.

`WorkerStopObserved` records the first cancellation, pause or budget boundary before new team dispatch; duplicates reject. In-flight observations and disposal facts may drain, but no new spawn, call (including a pinned Provider fallback), Tool, eligible handover or integration starts past the marker. `WorkerHandoverRecorded` requires the exact Finished editor, matching sealed cumulative data and base, no stop, unknown private effect, previous handover, settlement or release. Its required `criterion_evidence` contains up to eight positive, strictly increasing private observation sequences, exactly the recomputed current evidence; missing, stale, unrelated or Workspace evidence rejects for every editor, including command and file criteria. Its committed sequence determines the integration queue. Late/duplicate/ineligible publication rejects; historical closed Runs accept no new transitions.

Every editor's answer passes the in-view criterion gate before SubagentStop and guarded handover capture. An unmet criterion journals the closed child-work failure reason `criterion_not_met_in_view` as an invalid answer and supplies bounded feedback on the next child request. As with Aider's reflection cap, at most three continuations are allowed, also bounded by remaining turns, Tool calls (a continuation needs at least one remaining Tool call, otherwise the worker fails at once), tokens, active time and Event headroom. The reducer counts subsequent child-call reservations and rejects a fourth continuation. Exhaustion ends the worker as `failed { criterion_unverified }`, discards private work and releases its lease. A continuation is a new model decision; an Uncertain command never continues or retries.

`ApplyChangeset.source` is the closed `CommandReceipt { source_intent_digest, changeset } | WorkerHandover { assignment_id, handover_sequence, data }` union. Command integration preserves its immediately preceding attested command source and complete batch. Worker integration is primary-only, Workspace-targeted and consumes exactly the earliest eligible handover, even without a primary model Tool request. An observed integration must be recorded before another team decision; neither a missing integration Event nor a repeated delivery authorizes a second effect. `WorkerIntegrationRecorded` references its exact primary Tool ID/finished sequence and derives integrated/conflict/denied/uncertain from that observation and receipt. Denied also settles a known non-dispatched failed, limited or cancelled Tool with no attestation; the exact underlying Tool disposition is retained. Workspace publication uncertainty stops the whole Run and cannot release its lease as successful.

## Accepted outcomes

A validated `arany_plan` call records disposition `plan_recorded`, zero requested effects, null delegation and no failure or refusal. Only a Tool-enabled primary in RootPlan or RootSynthesis may record it, with no existing contract. The next contract Event must precede any new action; a continuation requires that contract to be committed. Plan calls consume the ordinary Goal call and usage budget.

A journaled `stopped` result from any successful [hook event](./tools.md#hook-execution) inside an active Run terminates the Run as `stopped_by_hook`, distinct from success, failure and cancellation. The primary AgentRun has the same terminal disposition; a hook running with a child's identity (SubagentStop or a delegated Tool hook) also terminates that child as `stopped_by_hook`, drains other children (they end Cancelled) and prevents synthesis. No further Provider reservation, Tool, spawn or hook may start in that Run; already reserved child calls are drained and recorded. No assistant Message is committed, and completed effects remain. The displayed optional reason is derived from the committed hook result, with the [Hook execution](./tools.md#hook-execution) reason bound; existing terminal/exec/serve outcome adapters escape and display it as user feedback, never model input. Diagnostics and telemetry use the closed stopped-by-hook disposition without the reason. The [Goal](./goals.md#lifecycle-budgets-and-recovery) stays open. Strict replay validates the recorded facts without executing the hook.

Every step produces exactly one phase-allowed semantic text answer, Delegate, optional primary plan or enabled Tool proposal. An accepted answer ends the turn and is committed once as `MessageCommitted.text`; earlier text is commentary. The Engine derives `AgentFinished.summary` from its first nonempty line, truncating at a UTF-8 character boundary to 2 KiB, and preserves the answer as `AgentFinished.result`. Replay rejects an `AgentFinished` whose summary differs from that derivation. A primary planning or synthesis call may carry the Run's accepted steering notes as user input; child calls may carry only their own actor-bound notes and Tool review receives none, and a pause takes effect only at the Goal boundaries that [Goals](./goals.md#steering-notes-and-pause) names. There is no fixed per-Run Tool-effect or model-step ceiling; each action still requires bounded Event, Store, request, context and terminal-tail admission, while the Goal's call, Run and active-time budgets bound the complete task. Primary Tool calls need no plan. Research and Plan Goal phases retain their bounded prelude-only rule: Workspace List/Read/Search, typed Git reads, admitted Skill reads and configured bounded MCP catalog listing. Implementation calls remain subject to the pinned grant and effect-admission path. A recorded [Goal plan](./goals.md#initial-plan-contract-and-success-receipt) further narrows scope and binds success. Children receive Single policy; a researcher receives only the read-only research catalog, its own observations and answer. Its MCP calls, writes, commands and plan contracts are invalid before dispatch; its reads outside the plan contract are journaled Denied without dispatch. Unknown operations and malformed wire responses reject without an alternate encoding; decoded primary proposals follow the refusal continuation below. The [Goal contract](./goals.md#initial-plan-contract-and-success-receipt) defines the exact scope and replay rules.

A decoded primary proposal refused by Engine validation in RootPlan or RootSynthesis records `failure_reason: proposal_refused` with required nullable `refusal { operation, cause }` on the same `ProviderCallRecorded` Event. A refusal is present exactly for that reason, paired only with `Rejected`; operation is the compiled `arany_` function name (including `arany_plan`), `answer` or `delegate`, never arguments. Closed causes are `invalid_arguments`, `invalid_path`, `phase`, `plan_invalid`, `plan_budget_outside_goal`, `plan_budget_spent`, `plan_scope_excludes_call`, `plan_outside_grant`, `argument_bytes`, `lease_overlap`, `not_offered`, `answer_invalid` and `delegate_invalid`. The Engine commits the refusal before reserving another Provider call and continues the primary loop without a Tool intent, Guard dispatch or receipt. For a refused typed Tool proposal, the next request pairs its original bounded assistant turn and call ID with one native error result derived from that committed refusal: closed cause, fixed remediation, `dispatched: false` and `effect: none`, at most 2 KiB plus normal result framing. Invalid paths receive the canonical Workspace-relative path requirements, never an echo of argument text. The error turn and result count toward continuation capacity and may enter whole-step compaction with their acknowledged prefix; no Guard intent, Tool execution observation or effect receipt is fabricated. Other primary proposals use one `last_answer_refused` note as trailing user data in the `worker_coordination` channel after Tool steps and stop feedback, preserving the earlier request prefix: compiled operation, closed cause and fixed remediation text for that cause, never model-authored argument values. A Tool refusal during a worker wave still records `worker_tool_refused` without a cause. Ledger read errors propagate as Engine errors and never become a refusal cause. Explicit Team planning that returns an answer instead of Delegate uses this same path. Three consecutive primary refusals with the identical `(operation, cause)` end the Run with `refusal_limit`, matching OpenCode's doom-loop threshold; a different pair or a non-refused primary call breaks the streak. Eight total primary refusals also stop the Run. Every retry reserves and spends a normal Provider call under the pinned Goal budget; cancellation and pause keep their existing boundaries. A crash after the refusal commit preserves it, and a resumed Session includes the historical refusal as nothing dispatched within the existing history and byte bounds. Post-decode response identity, usage and provenance failures use `response_contract`.

`RunFinished.failure` is required nullable and present exactly with `Failed`: `provider_call` (a failed Provider call), `proposal_refused`, `budget_exhausted` (the Goal budget refused the next action), `tool_stopped` (a terminal dropped or Guard-failed Tool step, or an unusable Command result), `definition_invalid` (agent-definition parsing), `plan_admission`, `tool_context_full`, `workers_unverified`, `criterion_unmet` or `refusal_limit`. A known recoverable primary Tool denial or failure is delivered once as its correlated result and does not by itself produce `tool_stopped`; a following Provider failure or refused continuation retains its own cause. Strict replay rejects missing fields, unknown causes and invalid disposition pairings; terminal facts never re-execute work. [Terminal](./terminal.md#conversation-progress-and-history) owns failure copy and [diagnostics](./diagnostics.md) owns private records.

The primary Run settles once, by one precedence. An Uncertain primary Tool observation or hook outcome, or the stopping step's uncertain build-cache publication, journals no terminal Event and is reported unknown. A Run that cannot settle because a reservation, another agent or a primary Tool is still open also journals nothing; the submission returns it as reopened history projects it (`uncertain` only with an open or unknown effect, budget exhaustion when its counts prove it, otherwise interrupted). Then cancellation or pause ends the Run `cancelled`, including cancellation observed while a lifecycle hook runs; a settled hook stop ends it `stopped_by_hook`, and exhausted active time or a call or token budget that refused the next action ends it `budget_exhausted`, which also records the Goal as exhausted once its budget is spent. Only then does the stopping step's own cause apply, so exhausted active time outranks `tool_context_full`, `tool_stopped` and `plan_admission`. An accepted answer that passed its Stop hooks still finishes when active time runs out after it.

The [Provider encoding contract](./provider.md#structured-outcomes-and-tool-encoding) owns automatic Tool selection, plain text Run answers and structured compaction/review. Responses text parts join in order without inserted or repaired bytes. Explicit commentary may precede the final answer or single call; refusal, malformed content, unknown phases, ambiguous finals, late commentary and contradictory error or incomplete markers reject. A missing/null phase is valid only for an unambiguous final message or text preceding a call.

All adapters reject reported input above the shared input ceiling. Provider-enforced routes reject reported output above the exact request cap; the ChatGPT route applies its cap to visible output, so its recorded total (which includes reasoning) is bounded only by the 1,000,000-token reporting ceiling, live and in replay ([ChatGPT limits](./chatgpt.md#run-limits)). Accepted outcomes also fit the exact serialized terminal payload bound, including JSON escaping. Native OpenAI may retain unknown usage; custom and ChatGPT outcomes require positive labeled usage. Native API-key and custom output caps are remote request controls; ChatGPT has a local acceptance cap and cannot guarantee remote generation or plan consumption. A Tool review uses Single policy with no Tools, history, includes or project instructions, its own 256-token cap rather than the ordinary final-answer cap, a 20-second ceiling, and the aggregate 32-call headroom. Uncertainty or failure asks a human and never grants a broader permission.

The selected Provider declares the primary output-token cap and the call deadline; the Run pins the cap in its configuration. Native OpenAI, Anthropic API and ChatGPT-plan routes declare 32,768 output tokens, and exact custom routes 4,096 (ChatGPT-plan routes count only visible output against it; see [Run limits](./chatgpt.md#run-limits)); replay rejects a pinned cap outside 1 to 32,768. Private editor calls request the same finite 32,768-token ceiling, narrowed by route binding; researcher calls request 4,096. Native OpenAI, Anthropic and ChatGPT-plan calls have a 600-second deadline (ChatGPT also has a [stream-idle deadline](./chatgpt.md#run-limits)); custom calls have 120 seconds. Each call also ends at the remaining Goal active time. A Tool review reserves 20 seconds plus Store overhead, compaction keeps its 120-second deadline, and a tool-free delegation reserves one deadline per wave of concurrent children, at most 20 minutes; a researcher delegation reserves 20 minutes. The useful answer ceiling stays at the 32 KiB assistant or result bound: the extra output headroom covers Tool-call arguments and reasoning tokens, and context budgeting reserves no output tokens.

The ChatGPT route's SSE parsing and item reconstruction rules are owned by the [ChatGPT contract](./chatgpt.md#catalog-checks-and-runs).

Malformed, non-object or duplicate-key MCP arguments, and selected-credential reflections including nested escaped arguments, reject before persistence. Provider failure remains the call's outcome even when an earlier Tool denial could otherwise be continued. Same-route retries follow [Provider reliability](./provider.md#usage-provenance-and-reliability); no route has an encoding fallback, and only an explicitly configured, admitted [Provider fallback chain](./provider.md#per-role-selection-and-fallback) can switch destinations. A lost response can still consume remote usage.

### Standalone Provider checks

All standalone `provider check` variants use a separate CheckId-keyed stream in the selected private StateRoot's `events.sqlite3`; they create no Session, Goal, Run or AgentRun. `CheckJournal` owns the typed lifecycle over the existing Store thread, while a pure `CheckReducer` validates each candidate transition before its immediate transaction commits. The read-only `CheckView` exposes only acknowledged state. The Session event tap stays Session-only; request-local synthetic identifiers remain transport data. The ChatGPT target identifies an account/model/effort tuple; account-bound checks follow the [ChatGPT contract](./chatgpt.md#catalog-checks-and-runs).

The STRICT `provider_check_events` table contains its own integer primary-key sequence, CheckId, 32-byte non-secret target key, kind, payload version, canonical JSON payload and creation time. Indexes cover `(check_id, sequence)` and `(target_key, sequence)`. Custom targets identify the declaration name; native targets identify profile, selected account or environment source, model, effort and optional Anthropic workspace. Credential identity uses the existing keyed fingerprint, never raw secret hashes. Diagnostic records contain no credentials, environment values, prompts, reply bodies, Workspace content or raw remote errors.

Every diagnostic kind has floor/current payload version 1 in a closed format registry, with canonical identity fixtures. `CheckEvent::version()` reads that registry, and the same stored-version migration gate as Session Events rejects a future bump without its step and fixture. The registries remain separate because diagnostic Events decode under CheckId without Session/Run envelopes; `session::events::payload_version` and its test-support wrapper describe only Session Events. Session Event payloads and the compaction compiler are independent. Whole-store opening, strict replay and migration validation reduce these streams; valid Session history cannot conceal a malformed check stream. Check entry validates the whole history once before recovery. Subsequent append/publication and read-only inspection reduce only the selected check, bounded by its Event cap; they do not rescan Session history.

| Event | Required transition |
|---|---|
| `ProviderCheckStarted` | Once per CheckId; pins target, model, source/contract fingerprint, destination identity, cost consent, ordered catalog/probe manifest and deadlines. |
| `ProviderCheckEvidenceCleared` | Once, before calls. Custom/native start and cache invalidation commit with this fact atomically; ChatGPT acknowledges the checked JSON clearing before calls. |

Evidence rows carry CheckId. Readers require the latest attempt for that target to replay successfully, match the exact evidence digest and fingerprint, and pass the [Provider freshness and destination checks](./provider.md#custom-destinations-and-routing). A new attempt suppresses old proof even if a stale cache row remains. Publication revalidates the exact declaration or selected native credential/account snapshot; editing a route does not block, but a changed snapshot refuses publication.

One checked zero-byte `provider-check.lock` per root uses the existing private no-follow, owner and ACL machinery. The check holds it throughout its lifecycle and Store shutdown. A concurrent check refuses busy, without queuing; recovery acquires the same lease before touching abandoned checks. The account replacement lock is never held across requests.

Cancellation stops dispatch. A dispatched request without a confirmed response has unknown outcome and usage. A lost append acknowledgment forbids dispatch and success claims. Read-only replay projects every unfinished prefix as Uncertain without effects. The next writable check, under the lease, appends an unknown result for any pending call and terminal Uncertain for the abandoned stream before admitting a fresh CheckId. Recovery never retries a probe or completes evidence publication. A fresh explicit check is a separate operation.

The complete lifecycle has a 240-second ceiling; requests end at least five seconds before it to reserve local settlement. Existing [Provider stage deadlines](./provider.md#commands) remain narrower. Bounds are 48 Events/check, 4 KiB/payload, 1,024 retained checks/root and one active check/root. ChatGPT usage keeps the admitted reported total, including reasoning, while its local output acceptance stays with the [ChatGPT contract](./chatgpt.md#run-limits). Catalog pages follow the [Provider catalog bound](./provider.md#commands), one journaled call each; inference allowances stay with the Provider contract. Admission reserves the entire worst-case local footprint before calls, sharing the 256 MiB database ceiling and existing storage headroom with Sessions; Session writes preserve that reservation. At the retained-check cap, Start atomically prunes the oldest eligible terminal check, deleting at most one stream (48 Events) before admitting its replacement. Custom/native evidence references protect their streams. Under the check lease, the ChatGPT account owner supplies its bounded retained CheckIds; their streams and the latest attempt for each referenced target are protected, so pruning cannot revive superseded proof. A checker without that account-index snapshot conservatively protects successful ChatGPT streams and their latest target attempts. A refused Start rolls back pruning. Evidence-linked and unfinished checks are never pruned; if none is eligible, admission refuses. Retained sequences may have gaps; replay still requires increasing sequences and valid complete stream prefixes. Native Start clears all prior evidence for the exact target, including older credential fingerprints, so pruning cannot revive superseded proof. Other capacity exhaustion refuses new work without truncation, retries or quota widening. Store channel bounds remain unchanged.

Eligibility is read from a read-only connection, so unsupported history reaches the archive without a journal-mode change. A candidate's `sqlite_schema` must equal the exact expected schema for its version; any extra trigger, view, table or index refuses before any copy or mutation. For a supported candidate, under the exclusive history and checkpoint locks, SQLite finishes recovery and folds any WAL into the main file in DELETE mode; a remaining sidecar refuses as unsafe state. Free space must cover a backup, a staged copy and 4 MiB, or the upgrade stops with `StorageFull` and the original intact. A private marker, `migrations/phase.json`, publishes `Preparing` with the migration ID, source identity (device, inode, size), schema versions and backup name. `VACUUM INTO` writes the private backup `migrations/history-<UTC timestamp>-<migration ID>.sqlite3` and a staged copy.

One staged transaction applies the schema steps and rewrites each older payload as canonical current text. It then re-pins every stored prefix reference: fork `prefix_digest`, `ContextCompacted` and `GoalContextCompacted` `source_digest`, and `WorkspaceRewindStarted` `prefix_digest`, each over the whole Session prefix exactly as replay hashes it. Each recorded digest must first equal the digest that replay computed historically, over each Event's canonical serialization at its stored version; it is then recomputed over the upgraded prefix. A mismatch refuses, so noncanonical or forged history is never repaired into validity. Content digests are never recomputed. The same transaction inserts one row in the `migrations` table: ID, schema versions, rewritten Event count, backup name and time. The staged copy must then open as a current journal and pass strict replay of every Session, lineage and standalone check. Each lineage keeps the [Session Event cap](#persistence-bounds), and the whole validation loads at most 1,048,576 events across Sessions, ancestors included. A refused step, a failed validation or an exceeded bound discards that attempt's files and archives the original intact. After file and directory fsyncs, the marker becomes `Ready` with the source, backup and staged identities and SHA-256 digests. The staged file atomically replaces `events.sqlite3` and the directories are synced. The marker then becomes `Cleaning`, recording the decided outcome. `migrations/` keeps only this migration's backup (older backups are removed), and the marker is removed last.

Recovery runs before admission and, rechecked under the shared lease, before any writable Store open; it holds the exclusive history lock and validates every present artifact before it removes anything. `Preparing` requires the original and then discards the incomplete backup, the staging copy and their rollback journals. `Ready` requires the backup digest and either the matching original, with any staging copy matching its pinned identity and digest, or the matching upgrade (digest and migration ID checked). Only then does it publish `Cleaning` with the outcome, before deleting anything. With the original live, this attempt's backup, staging copy and their rollback journals are discarded, and a retry makes its own. With the upgrade, older backups are removed. `Cleaning` only removes redundant copies, so an interruption at any recovery step restarts cleanly. Any other identity, digest or marker fails closed with a typed migration conflict and leaves every file in place. Recovery never re-executes journaled effects.

The schema guard also enumerates `checkpoints.sqlite`; its floor, identity fixture and archive behavior belong to the [checkpoint store contract](./tools.md#checkpoints-and-rewind). The checkpoint schema currently has no upgrade edge.

### JSON record migration

Private StateRoot JSON records follow the same rule. Each record owner declares a `RecordFormat`: its record kind, version field, floor, current version, `Value -> Value` steps keyed by source version and its current decoder. Floors are the versions current when record migration landed and stay fixed: `ui-preferences.json` 3, `workspace-permissions.json` 2, schema 1 for `account-credentials.json` (whose nested native account is schema 2), `chatgpt-accounts.json` and `chatgpt-registration.json`, and version 1 for `model-preferences.json`, `unguarded-commands.json`, `tools.json`, `provider-profiles.json`, `provider-roster.json` and `provider-routing.json`. Registered steps include `ui-preferences.json` 3 → 4, `provider-profiles.json` 1 → 2 (preserving valid Responses profiles without admitting a new protocol), and `chatgpt-accounts.json` schema 1 → 2. The ChatGPT step validates the complete source index, clears old optional model checks that lack journal proof, and preserves account identities, tokens, selection and consent. Current checks require a non-secret CheckId and use an advanced optional-check fingerprint; account-admission authority and Provider-route formats are unchanged. `permissions.json` follows the Claude Code settings shape, which carries no version, so it has no format.

Owners read these records through the migration. A record whose version is at or above its floor and below current is re-read and upgraded under the account-replacement lock, which a reader already holding it on the same thread reuses; another holder makes the read fail with `AccountBusy`. Parsing is bounded by the record limit and a depth of 32 and refuses duplicate keys. Each step must produce its target version, and the result must fit the record limit and pass the owner's current decoder; it is then published through the record's atomic pending replacement. User-authored records, otherwise read-only to the harness, are replaced only this way. A current, newer, below-floor, malformed or refused record is returned unchanged, and its owner rejects it with its existing recovery; nothing is archived or deleted. A crash before the rename leaves the original and at most one pending file, which the next upgrade overwrites. Errors are typed and carry no record content. A step adds a field only with a value the old record proves, or a default the old record could not choose; it never adds authority, grants, trust or secrets. A test fails when a versioned record kind lacks a format, a format lacks a current identity fixture its decoder accepts, or an edge from its floor lacks a step and fixture; the floor fixture must upgrade to an accepted current record.

### Workspace rewind Events

`WorkspaceRewindStarted` v2 and `WorkspaceRewindFinished` v1 are Session-scoped facts, each at most 64 KiB including JSON escaping; larger payloads reject before decoding. Started records a UUIDv7 rewind ID, a Run or rewind checkpoint with its exact sequence, the current head sequence and canonical prefix digest, canonical effective-plan SHA-256, file count/restored bytes, sorted disjoint kept/overwrite selections, Workspace identity and Tool policy/enforcement digests. Overwrite selections carry the observed digest, byte length and executable bit, or explicit null for absence. Kept and overwritten paths together are capped at 64; paths are at most 512 bytes. Neither selections nor stored bytes grant permission.

Finished records its own rewind ID, closed `restored`, `conflict`, `denied`, `failed`, `cancelled` or `uncertain` outcome, required nullable attestation and checkpoint, and sorted conflict paths (the first 32, plus the exact total, at most 2,048). Restored requires an attestation with plan, Workspace, enforcement and nonzero Guard receipt digests. An attested Uncertain outcome uses the same binding. Exactly those attested outcomes require checkpoint capture status for overwritten content: captured/skipped if any before state exists, otherwise not_needed. Pre-GO known refusal/cancellation carries neither capture nor receipt. An unconfirmed outcome with no receipt stays Uncertain; it does not assert whether GO occurred. Finished must immediately follow its own Started. The [Session contract](./session.md#rewind-planning-and-replay) owns planning, sealing and history projection; [Goals](./goals.md#rewind-and-goal-recovery) owns recovery and evidence invalidation. Runtime restore remains unavailable.

### Persistence bounds

| Bound | Limit | Overflow |
|---|---|---|
| Session lock files | 65,536, including pre-commit files stranded by process death; the directory scan stops after that bound plus 32 State files | quota failure before Workspace input or Provider disclosure |
| Workspace writer lock files | bounded and shared across StateRoots; the limit is owned by [Goals](./goals.md#lifecycle-budgets-and-recovery) | new writers refused before disclosure or effects |
| Direct-Session projection cache | 128 MiB of serialized Event payload | not kept; the next append replays strictly |
| Supervisor verdicts | 2 KiB each; at most 256 per Run; the 256th has `capped: true` | oversized payload rejected; after 256 evaluation continues without another verdict |
| Event payload, default | 64 KiB | append refused |
| `MessageAccepted` | 656 KiB, with inline PNG bytes (an empty list for text) | append refused |
| `GoalStarted` | 400 KiB | pre-admission `GoalInputTooLarge` ("objective plus includes too large"); no Event or Provider call |
| `GoalFinished` | [Goal report bound](./goals.md#lifecycle-budgets-and-recovery) + [budget refusal bound](./goals.md#budget-refusal-feedback) + 512 bytes | append refused |
| `ToolStarted` | 512 KiB: the complete intent, including Write, Edit or MultiEdit arguments at the [Tool argument ceiling](tools.md#limits-and-failure-behavior); admission reserves one observation slot for each intent it admits | append refused |
| `HookFinished` | 528 KiB: twice the [Tool result ceiling](tools.md#limits-and-failure-behavior) plus the 400 KiB [Tool argument ceiling](tools.md#limits-and-failure-behavior); admission reserves an observation slot per matched handler | append refused |
| `ToolFinished` | 528 KiB + 512 bytes of checkpoint metadata: twice the [Tool result ceiling](tools.md#limits-and-failure-behavior) plus the 400 KiB [Tool argument ceiling](tools.md#limits-and-failure-behavior); admission reserves it only for the `ToolFinished` slots an action may append | append refused |
| Steering note per Run | 8 KiB, including history labels | offer refused; the caller keeps its text |
| Requested Tools per model step | 0, or 1 to 4 for a `ToolRequested` disposition | replay refused |
| Evidence caches | 32 custom Provider rows and 256 native rows; native rows expire after 24 hours | expired rows are removed first; a new row beyond the bound is refused as storage full |
| Session discovery | 65,536 heads; a listing page replays at most 262,144 Events | partial page with a continuation cursor; exact-ID resume fallback |
| Events per Session lineage | 10,000, including inherited history | append refused; strict replay fails closed with a Store error |
| `provider-profiles.json` and `tools.json` | 64 KiB each, read only through the admitted handle | rejected; never parsed as trusted configuration |

Canonical state resolves before repository input and lives in a private directory outside the Workspace, with verified owner and permissions or ACL, a fixed aggregate page cap and admission headroom. SQLite integrity is not tamper evidence, and the database is not encrypted at rest. Persisted objectives, summaries, results and errors are untrusted typed data.

The schema is created only in an empty version-zero database; any other existing version rejects before mutable pragmas run. `MessageAccepted` and `GoalStarted` limits derive from the objective and image caps at six escaped bytes per byte. Goal admission preflights the serialized objective plus admitted include list against the unchanged GoalStarted ceiling; combined escaping can refuse an otherwise individually bounded request before Goal acceptance. Byte preflight is conservative and is not a lease against independent writers or disk faults.
