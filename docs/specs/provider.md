# Provider

## Scope and related contracts

This contract owns Provider selection and pinning, native and custom admission, outcome and Tool encoding, egress, usage provenance and provisional display. Accepted outcomes and deadlines belong to the [execution contract](./execution.md#accepted-outcomes), saved-account storage to the [credential contract](./credentials.md), ChatGPT-plan OAuth and its output bound to the [ChatGPT contract](./chatgpt.md), and plan contracts to the [goals contract](./goals.md#initial-plan-contract-and-success-receipt). The ChatGPT-plan trade-off is recorded in [D-18](../research/next-step-decision-register.md#d-18--explicitly-accepted-chatgpt-plan-route-is-beta-scope). Editing constraints: [security rules](../../agents/security.md).

- Each role has an explicitly selected profile, model, reasoning profile, privacy profile, outcome encoding and call limits pinned before Workspace input and `RunStarted`, including every configured fallback. A Session changes its defaults only between Runs. Unconfigured roles inherit the primary route; [role routing](#per-role-selection-and-fallback) defines the bounded chains and journal representation.
- Provider is the substitutable semantic inference interface. Requests and responses carry Arany semantics, never wire objects or a generic parameter bag.
- `ProviderKind` owns native Provider names and the `custom:` profile syntax used by runtime identities and CLI route construction. Centralizing that vocabulary preserves profile strings, admission and validation behavior.
- A primary Goal call may carry a bounded typed `GoalContextFacts` projection. It is context, not a grant or budget override; children never receive it.
- `Provider::compact` is a separate semantic call, not a synthetic AgentRun. It receives bounded accepted outcomes and an optional prior summary, never Workspace instructions or includes. API-key and custom routes enforce the output cap remotely; the ChatGPT-plan route records a local-only cap. The summary is untrusted data, portable only with its provenance.
- Rollout is staged: native OpenAI and Anthropic first; exact custom profiles after data-free conformance; OpenRouter stays deferred behind its route and privacy gate; Z.AI stays unadmitted until an exact profile passes the outcome contract.
- Selection is deterministic from admitted user configuration. There is no model-selected destination, hidden discovery call or preliminary model check inside a Run. Fallback is disabled unless explicitly configured as described below.

The primary Delegate envelope accepts optional nullable `agent`, selecting one admitted researcher definition for its `children` objectives. A child object keeps required `objective` and nullable `profile`; an editor additionally carries the closed `editor` assignment from the [worker protocol](./execution.md#worker-journal-protocol), repeats its mission as `objective`, and requires null `profile`. Its definition/digest come from the admitted catalog. The editor envelope requires `commands`: a sorted array of zero to eight unique admitted command names, each at most 64 bytes; missing, duplicate, unknown or extra names refuse admission. Both native function encodings share this envelope. The schema offers editor assignments whenever an admitted editor definition exists, so it stays constant within a Run; the Engine refuses an editor Delegate before a committed Goal plan, using bounded refusal feedback before any child call. Assignments offer foreground/background mode, bounded wave numbers and nullable current-Run supersession; nullable `resumes` accepts an exact historical child ID under the [fresh-assignment semantics](./session.md#worker-identity-and-explicit-reassignment). Editor calls use a compiled live-Workspace, leased-file prompt, Single policy and the restricted catalog, with text answers and no Delegate. [Execution](./execution.md#agent-definitions) owns its strict selection and authority intersection. Definition bodies stay in labelled untrusted user guidance; no new system role or Provider destination is introduced.

## Per-role selection and fallback

`Providers { primary, child, review, compaction }` binds primary planning/synthesis, researcher or reasoning children, AI Tool review and summary calls. A child receives the same narrowing of instructions, Tools, authority and Goal facts regardless of its Provider. Each route retains its own immutable identity, account or custom conformance provenance, effort, output-token bound and call limits. Pinned role deadlines are positive and at most 20 minutes; compiled routes retain their narrower limits. The role-specific output caps still apply, and concurrent children fit both the primary and every admitted child route's concurrency ceiling.

Peer mapping: [OpenCode's per-agent `model`](https://opencode.ai/docs/agents/#model) supplies model overrides and primary inheritance. [Claude Code, “Fallback model chains”](https://code.claude.com/docs/en/model-config#fallback-model-chains) supplies ordered server-availability fallback, a visible switch, actor-local continuation for this turn and a three-model ceiling. Authentication, billing, rate-limit, request-size and transport errors never switch. Arany admits and pins all destinations before disclosure, journals switches before dispatch, and rejects duplicates, oversized chains and unadmittable entries instead of silently removing them. These durability and exact-admission constraints are the R3-7 divergence. Content refusals never select another model.

Both `exec` and attached Run/compaction admission read only the optional private StateRoot record `provider-routing.json`, at most 16 KiB<!-- unrelated-bound: Provider routing record -->. Version 2 is a closed object with a required `providers` object containing all four role names. Each value is null or an ordered array of one initial route and at most two fallbacks. Each route has exactly `provider`, `model`, `effort` and `account_id`; the nullable fields are explicit. The Provider field is a closed `{kind, custom_name}` record: native kinds require an explicit null custom name, and custom requires its exact validated name. Provider/model names use existing exact selection rules. Native effort resolves through the ordinary model defaults; ChatGPT requires explicit effort and the selected account UUID. Unknown fields or versions, empty or oversized chains, duplicate admitted identities and malformed selections refuse admission. No Workspace file, instruction or model output selects these values.

```json
{
  "version": 2,
  "providers": {
    "primary": null,
    "child": [
      {"provider": {"kind": "anthropic", "custom_name": null}, "model": "claude-sonnet-5", "effort": "high", "account_id": null}
    ],
    "review": null,
    "compaction": null
  }
}
```

Routing and roster version 1 records upgrade through registered bounded, locked atomic migrations before current decoding. Migration preserves ordered tuples, exact custom names, account IDs, inheritance and preset selection; invalid kind/name pairs reject before credential lookup, and interruption follows [record recovery](./execution.md#json-record-migration). This intentionally differs from peers’ string Provider IDs to keep persisted identity closed, as with Run Provider records.

Idle attached `/setup` → Role routing edits this complete record through a user-confirmed typed StateRoot operation. It offers all four roles, explicit tuples and ordered fallback insertion, replacement, removal and movement, with null inheritance for non-primary roles. The first explicit primary tuple comes from the current `/model` selection; it cannot be replaced by an unrelated role choice. Native default effort is resolved before saving, and duplicate resolved tuples refuse. Saving does not retrieve credentials, check a destination or call a Provider; exact custom check status remains informational. All candidates, including unused fallbacks, still pass ordinary next-submission admission. Existing Run pins and fallback predicates remain unchanged.

Save and Clear role routing compare the previously inspected byte snapshot under the private replacement lock. Busy, changed, malformed, oversized or unsafe records refuse without overwriting another editor. Clear removes only this record, so roles return to primary inheritance on the next independent submission; it does not activate a roster preset. Publication is journaled through the [setup edit lifecycle](./execution.md#admission-persistence-and-recovery). An unconfirmed publication stops continuation with an unknown outcome and never retries or compensates. Ordinary/model-accessible record replacement and removal remain read-only.

The primary remains the CLI/Session selection. A non-null primary chain must begin with that exact resolved selection; later entries are its fallbacks. A null role inherits the entire pinned primary chain. An absent record means one primary route and no fallback for every role. Every configured entry is admitted through the existing native credential/account, ChatGPT consent or exact-custom destination/conformance gate before Workspace input, including routes that will not be called. An admission failure names the configured profile/model and refuses the Run; it never selects another entry. Exact-custom primary/child routes remain incompatible with a Tool-enabled Run. Review and compaction receive no Tools or images and retain their ordinary strict-text conformance; custom primary/child routes refuse image-bearing objectives.

Fallback walks the pinned chain only when the HTTP status check rejects a response with 5xx (including 529), before body admission, and only after the call's [same-route retries](#usage-provenance-and-reliability) are spent or cannot fit. Native and custom adapters emit a typed pre-admission server failure at that check; ChatGPT keeps its numeric 5xx status and bounded `Retry-After` in a typed remote server failure. Native/custom call records preserve their existing unavailable disposition and failure-reason bytes. A send-time transport failure, any error after a successful status check (including stream overload, hidden reasoning, Tool-input JSON, pre-answer JSON or a body-read failure), local request rejection, content refusal, semantic/stream validation error, output limit, cancellation or deadline never switches. Visible preview text is an additional guard, not the admission-stage test. Only the attached primary exposes previews.

Before any switch fact or replacement charge, requests carrying Tool steps or opaque assistant turns must retain the same adapter and account. OpenAI API keys and ChatGPT subscriptions are different accounts even though their opaque turns use the same adapter tag. Tool-enabled Run admission refuses any primary or child chain mixing adapters or accounts, before dispatch; role overrides themselves may use different adapters. The replacement retains the entire semantic request and correlated observations without translation or truncation. It neither re-dispatches a Tool nor continues an uncertain effect. A successful fallback remains selected for that actor and role for this Run; each new Run starts at chain[0].

Claude Code excludes compaction fallbacks with smaller context windows. Admitted window metadata comes from authenticated ChatGPT catalog `context_window` checks or fresh native Anthropic Models API `max_input_tokens` evidence; both size the primary [context ceiling](./session.md#context-and-compaction) from the smallest window across the primary chain and never select or filter a route. Arany sends the same complete, bounded compaction source to each configured destination, never truncates it to fit and never launches another compaction to make fallback possible. Anthropic window evidence is bound to the checked model, effort, credential and account fingerprint, expires with the native check, and is available to Run admission only while that evidence remains valid. Missing and out-of-range values remain absent. A schema migration clears older derived evidence rather than inferring a window. A target's request-size rejection ends that call without a switch. This explicit rule diverges from Claude Code's window-based filtering; selecting a compaction chain does not certify equal window sizes.

Each switch fits the existing action deadline and fresh Store/call-budget admission. Per-attempt adapter deadlines and output caps can only narrow it. The [execution contract](./execution.md#admission-persistence-and-recovery) owns switch facts and replay, and [Goals](./goals.md#lifecycle-budgets-and-recovery) owns charging unknown failed-call usage. A Run retains at most 64 switch facts; reaching the bound, or a refused Event or storage admission for the switch, stops fallback and records the call's failure. When the latest Run has explicit role provenance, Session compaction requires its admitted chain to match that Run's pinned compaction identities; it cannot introduce a new destination after the Run. Runs with the canonical inherited representation retain ordinary single-route between-Run compaction selection, and cannot introduce a fallback chain after the Run.

Judge-only adapters and durable per-agent pause/retry/switch remain separate proposed D work; writable workers and leases remain outside this contract.

Decision O2 (product): `--profile PRESET` explicitly selects a private preset in attached mode or `exec`. There is no implicit preset, persistent preset default or activation picker. Supplied Provider, model and effort flags must individually match its normalized primary tuple. A selected roster conflicts with any present `provider-routing.json`; choose one routing source. Without the flag ordinary submission does not open the roster record and ordinary selection remains available.

The user maintains `provider-roster.json` beneath the admitted StateRoot outside the Workspace through idle `/setup` → Roster profiles. Autonomous/model-accessible record replacement and removal remain read-only; only confirmed typed setup writes can publish roster edits. Version 2 is a closed object with required `version`, `profiles` and `presets`. Each profile has exactly `name` and `routes`; routes use the exact four-field [role-route form](#per-role-selection-and-fallback). Each preset has exactly `name`, `providers` and `child_profiles`. Its four required Provider-role fields contain profile names, with explicit null permitted for child, review and compaction to inherit the entire primary chain. Primary is required and non-null. The nonempty, ordered child allowlist must include the resolved child default. Unknown or duplicate object fields, duplicate names/routes/eligibility, missing references, malformed values and unsupported versions reject the whole record. Native efforts normalize before duplicate detection or selection comparison.

The manager creates, edits and removes named route profiles and presets, assigns all four role references with explicit primary inheritance, and edits the ordered eligible-child list. Profile removal refuses while any preset references it, naming those presets. Drafts may be incomplete while editing; Save validates the entire record with the existing bounded parser and normalizes native efforts. Invalid drafts retain their edits for repair; an ineligible child-default error names the preset and resolved profile to add, and an expanded-profile limit error names the preset, limit and reference-removal choices. Preview and Save review show every profile's source/account/model/effort, configured inheritance, and each preset's complete resolved manifest and explicit `arany --profile PRESET` invocation. An unrepresentable complete manifest refuses Save. Browsing and saving do not retrieve credentials, check routes or invoke inference; selected saved-native source inspection remains explicit under the credential contract.

Save publishes the whole roster record atomically through the typed StateRoot publisher under the same [snapshot comparison and refusal rule](#per-role-selection-and-fallback) as role routing. Removing the final preset removes the whole record, including its remaining route profiles, after complete warning review. The [setup edit lifecycle](./execution.md#admission-persistence-and-recovery) journals intent before publication and result before visible success; unknown publication stops continuation without retry or compensation. Editing or saving never activates a preset, changes conversation defaults or rewrites admitted submissions. Role-routing conflicts remain in force; the manager offers the separate confirmed [Clear role routing](#per-role-selection-and-fallback) action and never merges or silently clears routing sources.

## Native models and accounts

- Native credential classification, catalog endpoint/header/paging selection and conformance adapter/protocol selection use `ProviderKind`, parsing exact public profile strings at the boundary. Public names, request bytes and evidence fingerprints retain their existing representation; custom and ChatGPT profiles cannot select API-key native discovery or checks.
- Effort is model-specific, resolved before Workspace input, sent explicitly on every Run and compaction request, and pinned in `RunStarted`. An omitted next-Run choice resolves to the reviewed model default. An unreviewed model needs an explicit closed effort and claims no compatibility. Malformed IDs and unsupported reviewed combinations fail before credential or Workspace input.
- A native credential is one immutable value: Provider, bounded key and optional Anthropic API workspace. Only an environment-backed Anthropic selection reads `ANTHROPIC_WORKSPACE_ID`; other Providers and key-only accounts never inherit it. A `wrkspc_` identifier is validated before requests, sent on every catalog, Run, compaction and conformance request, and bound to native evidence. Neither a workspace header nor catalog visibility grants another destination, capability or plan permission.
- `exec` and explicit native selections use only their named API-key environment variable. Bare attached mode can use one saved API account chosen through `/setup` or `--setup`; with none it stays unconfigured and rejects objectives locally before Workspace input. A Session's saved default pins the account UUID; Run and catalog admission must match that UUID and Provider before the key is released, so a replaced account never becomes an older Session's credential. Native adapters carry the UUID into `RunStarted`; environment-backed and custom adapters carry none.
- ChatGPT-plan OAuth is a separate consented route that never falls back to API-key billing. Anthropic remains API-key only unless Anthropic grants Arany prior approval.
- The OpenAI Responses adapter admits exactly `gpt-5.4`, `gpt-5.6-luna`, `gpt-6-astra`, `gpt-6.1-sol` and `gpt-6-luna` with `OPENAI_API_KEY`, sending the resolved value as `reasoning.effort`. Effort sets come from the model pages for [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) and [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). Astra defaults to `medium`; the others match their pages.
- The Anthropic Messages adapter admits exactly `claude-sonnet-5`, `claude-fable-5-1`, `claude-opus-5-5` and `claude-sonnet-5-5` with `ANTHROPIC_API_KEY`, sending the resolved value as `output_config.effort` per the [effort guide](https://platform.claude.com/docs/en/build-with-claude/effort). This is an economical preference, not a compatibility claim. `/model` selects model and effort atomically; selecting is staging, never credential or compatibility authority.

An explicit unknown effort is admitted without a compatibility claim and runs one call at a time.

## Structured outcomes and Tool encoding

- Run answers are plain assistant text, matching Codex CLI and Claude Code. The native Responses and Anthropic adapters decode ordered lists of Tool calls as described below. Earlier assistant text is progress commentary. Without a function call, the final assistant message is the answer and ends the turn. There is no Finish function or model-authored summary/result split. On every adapter, unknown, unoffered or incomplete calls, malformed text parts, non-object or wrongly typed function fields and wire-byte overflow reject without alternate decoding. An offered call whose fields decode into a bounded typed Tool proposal reaches Engine argument validation, preserving response usage. Invalid paths and other semantic argument failures receive the [committed refusal result](./execution.md#accepted-outcomes) before normal continuation; they are not wire parse failures and do not consume the single outcome correction below. The Engine retains the [refusal and completion rules](./execution.md#accepted-outcomes).
- OpenAI API and ChatGPT requests offer the same constant list of strict native functions for catalog-available operations, the optional primary `arany_plan`, and `arany_delegate` when collaboration permits children. Both restrict allowed functions by phase with `tool_choice: {"type":"allowed_tools","mode":"auto","tools":[{"type":"function","name":"arany_…"}]}`, retaining the full list across planning and synthesis. Local decoding admits only the allowed subset. Read-only routes offer only phase-allowed delegation. Primary and researcher requests send `parallel_tool_calls: true`, following Codex CLI; read-only delegation and editor requests send `false`, and editors retain one call per step. Completed `function_call` items become Tool requests in model order under the [step cap](./limits.md#max_step_tool_calls). Plan and Delegate outcomes each require exactly one call and cannot mix with other calls; duplicate call or function-item IDs reject. Bounded over-cap batches reach the Engine's [proposal refusal](./execution.md#accepted-outcomes) with corrective feedback, preserving usage and one non-dispatched result per call. Response bytes and [streaming framing](#streaming-and-provisional-text) bound decoding; dispatch and replay follow the [execution contract](./execution.md#committed-event-stream).
- Native and custom Anthropic Messages Runs offer non-strict catalog Tools and phase-allowed Delegate, with `tool_choice: {"type":"auto"}` and no `output_config.format`, allowing multiple calls as in Claude Code. A `tool_use` stop carries offered Tool calls in model order up to the [step cap](./limits.md#max_step_tool_calls), with earlier text as commentary; plan and Delegate outcomes each require exactly one call and cannot mix with other calls. Duplicate IDs and malformed calls fail closed. A bounded batch above the cap reaches Engine proposal refusal with `InvalidArguments`, feedback naming the cap and one non-dispatched result per call, under the [identical-pair refusal bound](./execution.md#accepted-outcomes). Decoding remains bounded by 16 content blocks and the response byte ceiling. Dispatch follows the [execution ordering](./execution.md#committed-event-stream). Editor requests retain `disable_parallel_tool_use: true` and one call per step. An `end_turn` stop carries the plain text answer and no call. `max_tokens`, `refusal` and every other stop reason fail closed. A replayed Delegate `tool_use` is followed by a fixed `tool_result` before the child results, as on the OpenAI routes. A request with no offered function omits `tools`, `tool_choice` and `parallel_tool_calls` on every route. Compaction uses the plain-text contract below. Tool review retains strict structured JSON encoding and returns the closed verdict object (`verdict: approve | ask`), decoded as a typed verdict, never as answer text.
- Custom Chat Completions offers the same strict function tools as the Responses route: the catalog-available Workspace Tools plus the phase-allowed Run outcome functions, with `tool_choice: auto` (`none` at zero remaining Tool calls) and `parallel_tool_calls: false` only when a function is offered. All requests use `stream: false` and `max_completion_tokens`; ToolReview uses strict JSON-schema `response_format` for its closed verdict. It sends no `store` or extra headers. ## Prompt caching

- Anthropic follows the peer explicit-breakpoint layout for active Tool loops: `cache_control: {"type":"ephemeral"}` on the last Tool definition, the last system text block, and the final content block of the conversation tail. Single-call requests without Tools and compaction requests mark only the system block; their changing data tails are not reused, so a tail breakpoint would pay the 1.25× cache-write charge without a subsequent read. A spent researcher's final call retains Tool and system markers but omits the tail marker. Markers are added to the outgoing request, never stored in replayed turns or accumulated over previous messages. This uses at most three of Anthropic's [four documented breakpoints](https://platform.claude.com/docs/en/build-with-claude/prompt-caching); the default five-minute TTL applies. No top-level automatic cache marker or extended TTL is requested.
- OpenAI API and ChatGPT Run and compaction calls all send the Session UUID as a stable `prompt_cache_key`, matching Codex CLI's conversation-ID key. The UUIDv7 carries a creation timestamp and lets the Provider link the turns of one Session, as with the peer. It adds no prompt, Workspace or credential text to the key. Calls keep `store: false` and existing encrypted-reasoning replay. The shared prefix remains reusable across phase changes; [Structured outcomes and Tool encoding](#structured-outcomes-and-tool-encoding) owns function selection. No retention override is requested. Exact custom Responses profiles share the API request shape and require current conformance evidence.
- A cache key or breakpoint requests reuse; it guarantees neither a cache hit nor remote retention or live compatibility. Actual cache-read counts flow through the [usage record](#usage-provenance-and-reliability) into the [Goal report](./goals.md#lifecycle-budgets-and-recovery).

Changing the decoder, prompts, request encoding, effort mapping, output cap or validation semantics bumps the native and exact-custom check contract versions in the same change; a package version alone does not.

Native adapters validate attachment count, aggregate bytes and objective or history origin before building a request body or egress.

ChildWork requests may contain only notes recorded for that exact child, rendered as ordinary user data at their actual continuation boundary with the shared `steering_notes` block. ReadOnly, Researcher and Editor work roles admit them; ToolReview and invalid role/phase combinations reject them, including nested Tool-step and stop-feedback notes. Earlier request prefixes remain unchanged on later continuations and route/retry attempts. Primary notes do not enter child requests. Guidance cannot widen the child's grant, catalog, lease, plan or budget; [Goals](./goals.md#steering-notes-and-pause) owns admission and delivery semantics.

## Usage, provenance and reliability

MCP argument validity, selected-credential reflection checks and Guard dispatch
share the strict Tool argument parser: one object, at most 8 KiB<!-- unrelated-bound: strict Tool JSON parser -->, depth 32 and
4,096 nodes, with no duplicate decoded keys. Invalid JSON rejects before
canonical Tool persistence; a parse failure never proves credential absence.
The native OpenAI/Anthropic `decoded_native_outcomes_reject_escaped_key_reflection`
corpora own encoded-key/value, duplicate-key and malformed-input regressions.

- A failure before a decoded outcome retries the same route, in every role including manual, automatic and in-Run compaction, single-route or chained: a send that fails before any response (the request may already have been delivered), HTTP 429, HTTP 5xx at status admission, or a body or stream that ends early (including a ChatGPT stream cut at its [idle window or call ceiling](./chatgpt.md#run-limits)). A semantic call has at most three retries across all its routes, with gaps of 2, 4 and 8 s (exponential from 2 s, at most 10 s each) or a longer delta-seconds `Retry-After` on a 429 or 5xx. Each wait must end before the remaining action deadline, which already lies inside the Goal's active time; a `Retry-After` that cannot fit is never waited out, so the call fails at once (a 5xx can still switch). A send timeout, cancellation, other 4xx, malformed stream or body, contract and content failures, and a primary call with committed display text never use this transport retry mechanism. The [bounded primary outcome correction](#structured-outcomes-and-tool-encoding) is a separate journaled call. A clean end is a cut only after at least one well-formed event. A 429 records the closed `rate_limited` reason. Only a bounded 429 body (at most 16 KiB<!-- unrelated-bound: Provider rate refusal body -->, read only to classify) whose error code or type names an exhausted quota, credit balance, plan, or organization or project spending or usage limit (`insufficient_quota`, `credit_balance_exhausted`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded`, `organization_usage_limit_exceeded`, `usage_limit_reached`, `usage_not_included`) records `usage_limit`; such a call is terminal and never retries. Every adapter, ChatGPT included, keeps the bounded delta-seconds `Retry-After` of a 429 or 5xx. A temporary-usage stream event keeps its unavailable class and never retries. Each retry commits its fact and passes fresh call-budget and Store admission before the wait; it is charged as a call with unknown usage, so a finite token budget refuses it. A pause or cancellation during the wait ends the call before any further reservation or dispatch, and both are checked again just before the re-dispatch. The provisional preview is cleared and the retry is shown as `Reconnecting… n/3`; `show`, `exec` receipts and the Goal report list every retry. Only after same-route retries does a configured fallback chain switch; visible preview text still blocks the switch. Peer mapping: Codex retries 429, 5xx, transport errors and compaction streams (four request and five stream retries), honors `Retry-After`, never retries the same exhausted quota, credit and spending codes (openai/codex 102fc57e), and shows `Reconnecting... n/max`; OpenCode backs off from 2 s capped at 10 s and retries only before output; Pi and Goose default to three. Arany takes the lowest peer count. It also journals and charges every attempt, which no peer does, for durable Goals and strict replay: a send failure after delivery can double remote usage, and that cost is charged, never hidden. A Provider call is not a Workspace effect, so no effect repeats.
- Calls across all roles, retries and explicitly configured fallbacks share the Goal budget and per-action limits. A lost response may already have consumed tokens; unconfigured broker fallback stays disabled.
- Each semantic step commits one bounded `ProviderCallRecorded` fact before its AgentRun terminal Event; a failed attempt that switches is recorded by `ProviderFallbackUsed` before its replacement dispatch. Cache-read and cache-creation counts are subsets of the reported input total. Responses `usage.input_tokens_details.cached_tokens` supplies cache reads and `usage.input_tokens_details.cache_write_tokens` supplies cache creation on native OpenAI, exact custom Responses and the shared ChatGPT decoder. Reads and writes are independently optional; absent counters remain unknown and explicit zero is reported zero. Anthropic `usage.cache_read_input_tokens` and `usage.cache_creation_input_tokens` supply reads and writes beside uncached `input_tokens`, and their checked sum is the input total. Messages may instead report cache writes as `usage.cache_creation` with required `ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`; their checked sum supplies the creation total. If both representations are present, the totals must agree and are counted once. Absent optional cache counters stay unknown. Counters must be unsigned 32-bit integers, the input total must fit the reporting ceiling, and cache subsets cannot exceed it; malformed, overflowing or inconsistent usage rejects without retry. Streaming preserves these counters from the final usage envelope (including Anthropic message-start usage merged with message-delta usage). Phase and local disposition are canonical; the response ID and reported usage appear only when a bounded response arrived. A timed-out or cancelled call reports unknown usage and does not prove absence of remote billing. Responses `completed` with a local `store: false` request and Messages `end_turn` are distinct wire provenance; neither is a remote retention or ZDR guarantee.
- API-key adapters reject exact selected-key reflection in bounded raw bytes and in decoded outcome, response-ID or compaction fields, including JSON-escaped echoes. This is not general secret detection.
- Persist only the bounded adapter, endpoint profile, requested and resolved model, request ID, broker and upstream identity, finish reason, usage provenance, privacy controls and capability-evidence version. Raw response bodies and uncontrolled headers are never persisted.
- A catalog lists availability, not compatibility; only reviewed manifests, adapter fixtures and opt-in live probes support capability claims.

Persist no raw headers, account identifiers, plan/meter names, URLs, bodies or upstream text in these observations. They never enter prompts, compaction input or telemetry content, and inspection adds no request or credential access.

Streaming, subscription, custom, Anthropic and Engine context-exhaustion producers use that owner to submit inert bounded records to the shared diagnostics sink; private storage remains at root without a production Provider dependency or re-export. ## Streaming and provisional text

- A preview is a bounded candidate, never an accepted outcome, reasoning channel, Tool argument or authority. Only public assistant text is extracted. Assistant text streams as the answer candidate (a `final_answer` item followed by a function call is a response-contract failure: the item is announced as the end of the turn and may already be journaled as the answer, so honoring a call after it would contradict a committed outcome, while Codex tolerates it. Journal-first keeps exactly one committed outcome per step); text that may still become commentary (all Anthropic text, ChatGPT text outside an explicit `final_answer` item) is shown but journaled only at the completion boundary, as an Answer chunk if it is the answer and as Commentary if a call follows. If a function call follows in the same response, the candidate is withdrawn and the text becomes commentary at the completion boundary; commentary-phase text is held until then. A candidate above the display limit stops streaming and leaves the committed answer to the Engine, which refuses it as `answer_invalid` like every other route.
- Known selected credentials are checked before text is exposed or recorded. A suffix that could complete a credential is retained, and cancellation never flushes it.
- The one-slot `ResponsePreview` observer holds the latest bounded snapshot; complete response, model, usage and outcome checks still decide acceptance. Only attached primary invocations expose a preview; configured fallback chains also use a bounded private observer as an additional visible-output guard; HTTP status admission decides eligibility.
- Shared framing derives its total bounds from the call's declared output-token cap (within the [admitted cap ceiling](./execution.md#accepted-outcomes)): the event bound is the greater of 8,192 events and two events per output token plus 2,048 fixed events; the byte bound is 512 envelope bytes times that event bound across the stream. Probes and compaction use their own smaller call caps. Individual lines, assembled event data and reconciled completed responses retain the non-streamed body byte ceiling; overflow fails closed as `stream_protocol`, without an outcome or retry, and [development diagnostics](./diagnostics.md) identify the framing limit. Framing requires duplicate-free event JSON within 262,144 nodes and depth 64 (a `response.created` event echoes the request, including the Tool catalog); an opaque assistant turn uses the same node and depth bounds within its own byte cap, requires label and type agreement, and never silently switches media or response encoding. Native and custom streaming use strict SSE media admission; ChatGPT uses its [admitted SSE policy](./chatgpt.md#catalog-checks-and-runs).
- Custom checks prove streaming for the default and each declared effort before Workspace-bearing use. Live streaming compatibility remains open evidence.

Cancellation drops any buffered streaming tail instead of flushing it.

A confirmed Start refusal has no CheckId. Cancellation never retries or claims remote cancellation.

The caller supplies the selected source and existing cost consent. Custom admission remains declaration → admitted destination/DNS → selected environment key. Native catalog access uses only the pinned source. Before publication, custom checks reload the exact declaration and DNS; native checks reload the selected environment credential or exact saved account identity, Provider, workspace and credentials. Any mismatch refuses evidence. The check never falls back to another credential, account or billing source. The existing probe deadline is narrowed by the full lifecycle ceiling; neither storage delay nor catalog pagination extends it. Check fingerprints bind the journaled contract, and readers require linked successful evidence rather than a cache row alone.

- `arany provider check openai|anthropic MODEL --effort LEVEL --accept-cost` is an optional, potentially billable diagnostic, not Run authorization. It uses the named environment source or explicit `--saved-account`, confirms catalog visibility, then makes at most three synthetic streaming direct, delegate and compaction calls. Each is capped at 1,024 remote tokens under one 180-second aggregate deadline, with no retries and no Workspace data. It clears the tuple's prior evidence first and publishes a 24-hour HMAC bound to the exact key, Provider, workspace, source or account, model, effort and versions, only after strict success. Native OpenAI routes carry no window metadata. Anthropic `max_input_tokens` is captured from the selected Models API row and stored with successful checked-model evidence. The check proves neither universal compatibility nor credential authority.
- `arany provider check custom:NAME --state-dir STATE` checks a user-authorized custom route; bare `NAME` also works. The [custom conformance contract](#custom-destinations-and-routing) owns cost, probes, bounds and evidence. Only a successful exact check permits `--provider custom:NAME --model EXACT`; a candidate recipe alone grants nothing.
- `arany provider models PROFILE` reads only the selected native credential and no Workspace data. The default source is the Provider's environment key; `--saved-account` selects the current OS-stored API account and rejects a Provider mismatch. The result is complete or fails closed at 1 MiB<!-- unrelated-bound: model discovery response page --> per page, 16 pages or 4,096 unique models. The response needs one `application/json` media type before body reading and uses no proxy, redirect, retry or decompression. Native rows distinguish reviewed effort metadata from availability-only rows; unknown rows are selectable with an explicit effort and no mandatory probe. A custom profile lists its configured model and declared efforts without reading its credential.
