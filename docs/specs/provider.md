# Provider

## Scope and related contracts

This contract owns Provider selection and pinning, native and custom admission, outcome and Tool encoding, egress, usage provenance and provisional display. Accepted outcomes and deadlines belong to the [execution contract](./execution.md#accepted-outcomes), saved-account storage to the [credential contract](./credentials.md), ChatGPT-plan OAuth and its output bound to the [ChatGPT contract](./chatgpt.md), and plan contracts to the [goals contract](./goals.md#initial-plan-contract-and-success-receipt). [D-18](../research/next-step-decision-register.md#d-18--explicitly-accepted-chatgpt-plan-route-is-beta-scope) records the ChatGPT-plan trade-off. Live support per route needs the owner-run checks in [next steps](../../NEXT_STEPS.md#beta-2-and-broader-release); offline fixtures establish neither live support nor an account-level zero-data-retention claim. Editing constraints: [security rules](../../agents/security.md).

- Each role has an explicitly selected profile, model, reasoning profile, privacy profile, outcome encoding and call limits, pinned with every configured fallback before Workspace input and `RunStarted`. A Session changes its defaults only between Runs. Unconfigured roles inherit the primary route ([role routing](#per-role-selection-and-fallback)).
- Provider is the substitutable semantic inference interface. Requests and responses carry Arany semantics, never wire objects or a generic parameter bag.
- `ProviderKind` owns native Provider names and the `custom:` profile syntax for runtime identities and CLI route construction. Native credential classification and catalog endpoint, header and paging selection use it, parsing exact public profile strings at the boundary. Custom and ChatGPT profiles cannot select API-key native discovery.
- A primary Goal call may carry a bounded typed `GoalContextFacts` projection. It is context, not a grant or budget override; children never receive it.
- `Provider::compact` is a separate semantic call, not a synthetic AgentRun. It receives bounded accepted outcomes and an optional prior summary, never Workspace instructions or includes. API-key and custom routes enforce the output cap remotely; the ChatGPT-plan route records a local-only cap. The summary is untrusted data, portable only with its provenance.
- Rollout is staged: native OpenAI and Anthropic first, then exact custom profiles; OpenRouter is deferred behind its route and privacy gate.
- Selection is deterministic from admitted user configuration. There is no model-selected destination, hidden discovery call or preliminary model check inside a Run. Fallback is off unless explicitly configured.

## Per-role selection and fallback

`Providers { primary, child, review, compaction }` binds primary planning and synthesis, researcher or reasoning children, AI Tool review and summary calls. A child receives the same narrowing of instructions, Tools, authority and Goal facts whatever its Provider. Each route keeps its own immutable identity, account or custom conformance provenance, effort, output-token bound and call limits. Pinned role deadlines are positive and at most 20 minutes; compiled routes keep their narrower limits. Role-specific output caps still apply, and concurrent children fit both the primary and every admitted child route's concurrency ceiling.

Peer mapping: [OpenCode's per-agent `model`](https://opencode.ai/docs/agents/#model) supplies model overrides and primary inheritance. [Claude Code fallback model chains](https://code.claude.com/docs/en/model-config#fallback-model-chains) supply ordered server-availability fallback, a visible switch, actor-local continuation for the turn and a three-model ceiling. Authentication, billing, rate-limit, request-size and transport errors never switch, and content refusals never select another model. Arany diverges for durability and exact admission: it admits and pins all destinations before disclosure, journals switches before dispatch, and rejects duplicates, oversized chains and unadmittable entries instead of silently dropping them.

`exec` and attached Run and compaction admission read only the optional private StateRoot record `provider-routing.json`, at most 16 KiB<!-- unrelated-bound: Provider routing record -->. Version 2 is a closed object with a required `providers` object naming all four roles. Each value is null or an ordered array of one initial route and at most two fallbacks. Each route has exactly `provider`, `model`, `effort` and `account_id`, with nullable fields explicit. The Provider field is a closed `{kind, custom_name}` record: native kinds require a null custom name, and custom requires its exact validated name. Provider and model names use the exact selection rules. Native effort resolves through the ordinary model defaults; ChatGPT requires explicit effort and the selected account UUID. Unknown fields or versions, empty or oversized chains, duplicate admitted identities and malformed selections refuse admission. No Workspace file, instruction or model output selects these values.

```json
{
  "version": 2,
  "providers": {
    "primary": null,
    "child": [
      {"provider": {"kind": "anthropic", "custom_name": null}, "model": "claude-sonnet-5", "effort": "high", "account_id": null}
    ],
    "review": null,
    "compaction": null
  }
}
```

Routing and roster records at another version are [archived intact](./execution.md#incompatible-records), never converted; invalid kind/name pairs reject before credential lookup. Peers use string Provider IDs; Arany keeps persisted identity closed, as in Run Provider records.

Idle attached `/setup` → Role routing edits this whole record through a confirmed typed StateRoot operation: all four roles, explicit tuples and ordered fallback insertion, replacement, removal and movement, with null inheritance for non-primary roles. The first explicit primary tuple comes from the current `/model` selection, and an unrelated role choice cannot replace it. Native default effort is resolved before saving; duplicate resolved tuples refuse. Saving retrieves no credential, checks no destination and calls no Provider; custom check status is informational. Every candidate, including unused fallbacks, still passes ordinary admission at the next submission. Cancellation publishes nothing.

Save and Clear compare the previously inspected byte snapshot under the private replacement lock. Busy, changed, malformed, oversized or unsafe records refuse without overwriting another editor. Clear removes only this record, so roles return to primary inheritance on the next independent submission; it activates no roster preset. Publication is journaled through the [setup edit lifecycle](./execution.md#admission-persistence-and-recovery); an unconfirmed publication is [Uncertain](./execution.md#effect-outcomes) and is never compensated. Model-accessible replacement and removal of the record stay read-only.

The primary remains the CLI or Session selection. A non-null primary chain must begin with that exact resolved selection; later entries are its fallbacks. A null role inherits the whole pinned primary chain. An absent record means one primary route and no fallback for every role. Every configured entry passes the native credential or account, ChatGPT consent or exact-custom destination and conformance gate before Workspace input, including routes that are never called. An admission failure names the configured profile and model and refuses the Run; it never selects another entry. Exact-custom primary and child routes are incompatible with a Tool-enabled Run and refuse image-bearing objectives. Review and compaction receive no Tools or images and keep their strict-text conformance. `RunStarted` carries explicit nullable roster metadata even without a roster; invalid or inconsistent role identities reject replay.

Fallback walks the pinned chain only when the HTTP status check rejects a response with 5xx (including 529), before body admission, and only after the call's [same-route retries](#usage-provenance-and-reliability) are spent or cannot fit. Native and custom adapters emit a typed pre-admission server failure at that check; ChatGPT keeps its numeric 5xx status and bounded `Retry-After` in a typed remote server failure. Native and custom call records keep their unavailable disposition and failure-reason bytes. A send-time transport failure, any error after a successful status check (stream overload, hidden reasoning, Tool-input JSON, pre-answer JSON or a body-read failure), local request rejection, content refusal, semantic or stream validation error, output limit, cancellation or deadline never switches. Visible preview text is an extra guard, not the admission-stage test; only the attached primary exposes previews.

Requests carrying Tool steps or opaque assistant turns must keep the same adapter and account across a switch. OpenAI API keys and ChatGPT subscriptions are different accounts even though their opaque turns share an adapter tag. Tool-enabled Run admission refuses any primary or child chain mixing adapters or accounts before dispatch; different roles may still use different adapters, and replay rejects redundant inherited provenance. The replacement keeps the whole semantic request and correlated observations without translation or truncation. It never re-dispatches a Tool, including during review fallback, and never continues an uncertain effect. A successful fallback stays selected for that actor and role for the Run; each new Run starts at chain[0].

Admitted window metadata comes only from the authenticated ChatGPT catalog `context_window` read at each Run admission. It sizes the primary [context ceiling](./session.md#context-and-compaction) from the smallest window across the primary chain and never selects or filters a route; native and custom routes carry no window metadata and keep the default bounds, like peers that ship static windows. An active Run keeps its pinned window. Missing and out-of-range values stay absent; malformed types reject the catalog. Claude Code excludes compaction fallbacks with smaller windows; Arany instead sends the same complete, bounded compaction source to each configured destination, never truncates it and never launches another compaction to make fallback possible. A target's request-size rejection ends that call without a switch, and selecting a compaction chain does not certify equal windows.

Each switch fits the existing action deadline and fresh Store and call-budget admission; per-attempt deadlines and output caps only narrow it. The [execution contract](./execution.md#admission-persistence-and-recovery) owns switch facts and replay, and [Goals](./goals.md#lifecycle-budgets-and-recovery) owns charging unknown failed-call usage. A Run keeps at most 64 switch facts; reaching the bound, or a refused Event or storage admission for the switch, stops fallback and records the call's failure. When the latest Run has explicit role provenance, Session compaction requires its admitted chain to match that Run's pinned compaction identities, so it cannot introduce a destination after the Run. Runs with the inherited representation keep ordinary single-route between-Run compaction selection and cannot introduce a fallback chain after the Run.

## Named roster presets

Presets cover named route selection and eligible child assignment only. An exhausted chain keeps failed-child, sibling-drain and failed-Run behavior: it fails only its child and starts no later sibling. Judge-only adapters, durable per-agent pause, retry or switch, writable workers and leases are outside this contract.

`--profile PRESET` explicitly selects a private preset in attached mode or `exec`. There is no implicit preset, persistent preset default or activation picker. Supplied Provider, model and effort flags must each match the preset's normalized primary tuple. A selected roster conflicts with any present `provider-routing.json`; one routing source must be chosen. Without the flag, submission does not open the roster record.

The user maintains `provider-roster.json` beneath the admitted StateRoot, outside the Workspace, through idle `/setup` → Roster profiles; only confirmed typed setup writes publish it, and model-accessible replacement and removal stay read-only. Version 2 is a closed object with required `version`, `profiles` and `presets`. Each profile has exactly `name` and `routes`, using the four-field [role-route form](#per-role-selection-and-fallback). Each preset has exactly `name`, `providers` and `child_profiles`. Its four required role fields hold profile names; child, review and compaction may be null to inherit the whole primary chain, and primary is required and non-null. The nonempty ordered child allowlist must include the resolved child default. Unknown or duplicate fields, duplicate names, routes or eligibility, missing references, malformed values and unsupported versions reject the whole record. Native efforts normalize before duplicate detection or selection comparison.

The manager creates, edits and removes route profiles and presets, assigns all four role references with explicit primary inheritance, and edits the ordered eligible-child list. Profile removal refuses while a preset references it, naming those presets. Drafts may be incomplete while editing; Save validates the whole record with the bounded parser and normalizes native efforts. Invalid drafts keep their edits for repair; an ineligible child-default error names the preset and the resolved profile to add, and an expanded-profile limit error names the preset, limit and reference-removal choices. Preview and Save review show every profile's source, account, model and effort, configured inheritance, each preset's resolved manifest and its explicit `arany --profile PRESET` invocation; an unrepresentable manifest refuses Save. Browsing and saving retrieve no credentials, check no routes and call no Provider; saved-native source inspection stays explicit under the credential contract. Cancelling publishes nothing and creates no Session.

Save publishes the whole record atomically through the typed StateRoot publisher under the same [snapshot comparison](#per-role-selection-and-fallback) as role routing. Removing the final preset removes the whole record, including its remaining profiles, after warning review. The [setup edit lifecycle](./execution.md#admission-persistence-and-recovery) journals intent before publication and result before visible success; unknown publication is [Uncertain](./execution.md#effect-outcomes) and never compensated. Editing or saving never activates a preset, changes conversation defaults or rewrites admitted submissions. On a role-routing conflict the manager offers the separate confirmed [Clear role routing](#per-role-selection-and-fallback) action; it never merges or silently clears routing sources.

The primary selects only eligible names in the pinned preset for each direct child assignment. `Delegate.children` holds closed objects with required `objective` and required nullable `profile`; strings, missing fields and extra fields reject. Null selects the pinned child default, which may inherit the primary chain; outside roster mode only null is legal. No raw model, account or endpoint, other preset, fifth role or judge capability is introduced.

```json
{"outcome":{"type":"delegate","children":[{"objective":"Inspect replay invariants","profile":"inspect"},{"objective":"Check output bounds","profile":null}],"agent":null}}
```

`RunInput.assignment_profiles` carries the eligible names for primary planning and synthesis and is empty for children, review and compaction. Structured text and native functions share one assignment schema whose profile enum is the frozen eligible names plus null, so primary function schemas stay fixed through the Run while phase restrictions apply. Compiled guidance explains null and default selection. The whole delegation is validated before its first spawn: an unknown, ineligible, malformed or over-bound assignment dispatches no child. Decoding failures follow the [bounded outcome correction](#structured-outcomes-and-tool-encoding); decoded proposals follow the Engine's [refusal continuation](./execution.md#accepted-outcomes). A profile is never inferred from objective text.

Each child binds its resolved profile through acknowledged `AgentSpawned` before reservation or dispatch. Calls and switches look up role, actor and that immutable reference, even when two profiles share an initial identity and differ only in fallbacks. A successful fallback stays with that actor and role; a sibling starts at index zero. A lost or failed spawn or switch acknowledgment, or a cancellation around either, starts no further call; replay rejects forged profile references and switches. Review and compaction keep their fixed role chains. Assignment cannot alter definitions, instructions, authority, Tools, budgets, privacy requirements or destinations beyond those admitted.

Roster account selection reuses the current selected-account loaders and refuses unsupported unused identities ([credential contract](./credentials.md#account-scope-and-identity)). Roster primary selection uses exact `select_provider` admission; headless native selection without a roster stays environment-only. A manifest supplies neither credential authority nor account or plan consent.

Before loading credentials or Workspace content, Arany shows a complete escaped manifest: preset, four role references, eligible children, every initial and fallback model and effort, and billing class (`native API`, `ChatGPT plan`, or `exact custom; unknown pricing`). ChatGPT rows disclose that the local output cap does not cap remote plan consumption. Headless manifests go only to stderr, including JSONL mode; attached submissions use the safe notices. An unrepresentable manifest rejects instead of hiding routes.

Admission structurally validates the whole bounded record, then resolves only profiles reachable from the selected preset. It admits them in profile-name and chain order, sequentially under one cancellable 120-second<!-- unrelated-bound: roster admission deadline --> deadline; identical normalized selections share admitted adapters. Every eligible alternative and fallback is admitted even when unused. There is no inference, discovery, recheck, retry queue or billing fallback, and the credential, consent and destination checks all apply. Both entry paths finish roster admission before opening writable history or the Engine; attached startup does so after folder consent. Failure names the safe profile and route and refuses before journal creation, Workspace input or a Run; earlier Session or default facts need not be rolled back. Cancellation drops remaining admission and starts no Run; account-write uncertainty stays authoritative.

Every agent candidate, including unused eligible profiles, passes the image and native Tool capability checks of [role routing](#per-role-selection-and-fallback). Eligibility never changes the parent grant, child read-only or Single policy, instructions or the shared Goal ledger. Admission pins one immutable semantic snapshot for all autonomous Runs of a submission, so configuration edits during a team Run cannot change its calls; independent submissions re-read and re-admit, and process selection survives new and clear. Inspecting a past Run needs neither current configuration nor credentials. A conflicting idle selection is refused at next-Run admission with guidance to use the preset tuple or drop the selector.

## Native models and accounts

- Effort is model-specific, resolved before Workspace input, sent explicitly on every Run and compaction request, and pinned in `RunStarted`. An omitted next-Run choice resolves to the reviewed model default. An unreviewed model needs an explicit closed effort, claims no compatibility and runs one call at a time. Malformed IDs and unsupported reviewed combinations fail before credential or Workspace input.
- A native credential is one immutable value: Provider, bounded key and optional Anthropic API workspace. The API workspace is a tenant and billing scope, not Arany's filesystem Workspace. Setup offers key-scoped access or a visible explicit workspace ID. Only an environment-backed Anthropic selection reads `ANTHROPIC_WORKSPACE_ID`; other Providers and key-only accounts never inherit it. A `wrkspc_` identifier is validated before requests, sent on every catalog, Run and compaction request. Neither a workspace header nor catalog visibility grants another destination, header, capability or plan permission.
- `exec` and explicit native selections use only their named API-key environment variable. Bare attached mode can use one saved API account chosen through `/setup` or `--setup`; with none it stays unconfigured and rejects objectives locally before Workspace input. A Session's saved default pins the account UUID; Run and catalog admission must match that UUID and Provider before the key is released, so a replaced account never serves an older Session. Native adapters carry the UUID into `RunStarted`; environment-backed and custom adapters carry none. Replay treats it as provenance, never credential authority.
- ChatGPT-plan OAuth is a separate consented route that never falls back to API-key billing. Anthropic stays API-key only unless Anthropic grants Arany prior approval.
- The OpenAI Responses adapter admits exactly `gpt-5.4`, `gpt-5.6-luna`, `gpt-6-astra`, `gpt-6.1-sol` and `gpt-6-luna` with `OPENAI_API_KEY`, sending the resolved value as `reasoning.effort`. Effort sets come from the model pages for [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) and [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). Astra defaults to `medium`; the others match their pages.
- The Anthropic Messages adapter admits exactly `claude-sonnet-5`, `claude-fable-5-1`, `claude-opus-5-5` and `claude-sonnet-5-5` with `ANTHROPIC_API_KEY`, sending the resolved value as `output_config.effort` per the [effort guide](https://platform.claude.com/docs/en/build-with-claude/effort). Opus 5.5 defaults to `medium`; the others to `high`. Requests use the compiled `/v1/messages` route with `anthropic-version: 2023-06-01`.
- Native choices need no synthetic check; each Run validates credential identity, workspace, bounded model and effort, and the strict actual response. Native setup picks a low-effort default from the account's catalog without model, effort or cost questions: visible `gpt-5.6-luna` for OpenAI, or `claude-sonnet-5-5` then `claude-sonnet-5` for Anthropic, otherwise the first visible row with unknown pricing disclosed. This is an economical preference, not a compatibility claim. `/model` selects model and effort atomically; selection is staging, never credential or compatibility authority.

## Structured outcomes and Tool encoding

- Run answers are plain assistant text, as in Codex CLI and Claude Code. Earlier assistant text is progress commentary. Without a function call, the final assistant message is the answer and ends the turn; there is no Finish function or model-authored summary/result split. On every adapter, unknown, unoffered or incomplete calls, malformed text parts, non-object or wrongly typed function fields and wire-byte overflow reject without alternate decoding. An offered call whose fields decode into a bounded typed Tool proposal reaches Engine argument validation with its usage kept. Invalid paths and other semantic argument failures get the [committed refusal result](./execution.md#accepted-outcomes) before normal continuation; they are not wire parse failures and do not consume the outcome correction below.
- The shared Responses decoder validates all assistant text parts, distinguishes explicit `commentary` from exactly one final answer, and joins ordered final text parts without inserting or repairing bytes. A missing or null phase is a single final message. Without a call or final message, the last commentary is the answer, as in Codex CLI; a blank answer is still the Engine's `answer_invalid` refusal. Commentary may precede or interleave with Tool calls in a step; a final answer beside calls, commentary after the final answer, unknown phases, malformed or refusal blocks, extra finals and non-null error or incomplete markers reject. Output items of an unknown type that is not a call stay in the raw replay and decide no outcome; an unknown `*_call` item rejects.
- OpenAI API and ChatGPT requests offer the same constant list of strict native functions for catalog-available operations, the optional primary `arany_plan` when [Goals](./goals.md#initial-plan-contract-and-success-receipt) offer it, and `arany_delegate` when collaboration permits children. Researcher calls at zero remaining Tool calls and the primary's [final budgeted call](./goals.md#lifecycle-budgets-and-recovery) keep the list and send `tool_choice: "none"` (Messages `{"type":"none"}`). Both restrict functions by phase with `tool_choice: {"type":"allowed_tools","mode":"auto","tools":[{"type":"function","name":"arany_…"}]}`, keeping the full list across planning and synthesis; local decoding admits only the allowed subset. Read-only routes offer only phase-allowed delegation. Primary and researcher requests send `parallel_tool_calls: true`, as Codex CLI does; read-only delegation and editor requests send `false`. Completed `function_call` items are the calls.
- Native and custom Anthropic Messages Runs offer non-strict catalog Tools and phase-allowed Delegate with `tool_choice: {"type":"auto"}` and no `output_config.format`, allowing several calls as in Claude Code; editor requests send `disable_parallel_tool_use: true`. A `tool_use` stop carries the offered calls, with earlier text as commentary, within 16 content blocks and the response byte ceiling. An `end_turn` stop carries the plain text answer and no call; `max_tokens`, `refusal` and every other stop reason fail closed. A replayed Delegate `tool_use` is followed by a fixed `tool_result` before the child results, as on the OpenAI routes.
- On both native Tool routes, calls become Tool requests in model order under the [step cap](./limits.md#max_step_tool_calls), and editors keep one call per step. Plan and Delegate each need exactly one call that mixes with no other; duplicate call or item IDs and malformed calls fail closed. A bounded over-cap batch reaches the Engine's [proposal refusal](./execution.md#accepted-outcomes) with `InvalidArguments` and feedback naming the cap, under the identical-pair refusal bound, keeping usage and one non-dispatched result per call. Response bytes and [streaming framing](#streaming-and-provisional-text) bound decoding; dispatch and replay follow the [execution contract](./execution.md#committed-event-stream).
- Tool review keeps strict structured JSON and returns the closed verdict object (`verdict: approve | ask`), decoded as a typed verdict, never as answer text.
- Custom Chat Completions offers the same strict function tools as Responses: catalog-available Workspace Tools and phase-allowed Run outcome functions, with `tool_choice: auto` (`none` at zero remaining Tool calls or on the final budgeted call) and `parallel_tool_calls: false` only when a function is offered. All requests use `stream: false` and `max_completion_tokens`; ToolReview uses strict JSON-schema `response_format` for its verdict. It sends no `store` or extra headers. A reply needs one choice, exact model, nonempty response ID, `stop` with plain text or `tool_calls` with exactly one offered call, and positive `prompt_tokens`, `completion_tokens` and their exact `total_tokens` within the local output cap. `length`, `content_filter`, missing usage, multiple choices or calls, mixed answer and call, or model drift reject without repair. The Limits system block reads "Tool calls per step: at most 1." on every role, because this route admits one call. Provider turns keep only the bounded assistant message needed for replay.
- A request with no offered function omits `tools`, `tool_choice` and `parallel_tool_calls` on every route.
- Read paging accepts omitted or null `offset` and `limit` with the [Tools defaults](./tools.md#in-process-file-operations). OpenAI strict schemas still require the nullable paging fields; canonical calls serialize omitted fields as null.
- Researchers receive only read-only operations, without planning or delegation. At zero remaining Tool calls every route keeps its Tool list, sends Tool choice `none` and accepts text only; the Engine independently refuses exhausted calls.
- Ordinary non-autonomous turns without a recorded plan omit the `goal` budget block; autonomous Goals and recorded plans carry bounded budget context. Engine enforcement never depends on prompt visibility. A recorded plan stays binding scope and success policy, unlike advisory peer plans; [Goals](./goals.md#initial-plan-contract-and-success-receipt) owns that divergence.
- Typed Run input renders as closed [system blocks](./session.md#context-and-compaction) and labelled untrusted user data. Each Tool step renders as the exact replayed assistant turn followed by correlated results that do not repeat the call. A multi-call step emits one result per call ID in model order: one Anthropic user message of paired `tool_result` blocks, or ordered Responses `function_call_output` items on both OpenAI routes. Step harness facts (`goal_context_facts`, `tool_calls_remaining`) follow the results as labelled data in the Anthropic user message; on both Responses routes they fold into the step's last `function_call_output` as a `harness` object (a non-object result becomes `{result, harness}`), because a user message after function outputs ends the turn and drops its reasoning, matching Codex, which adds nothing between outputs. Step steering stays a user message so user authority keeps its label, and a step without function outputs keeps the facts as user data. Hook replacements and Engine integrations stay result data on the originating call, never another model-requested result. A recoverable primary failure or denial, including a declined or unavailable approval, appears once in its paired result and may continue through ordinary Goal admission; cause labels are compiled, never raw hook, client or permission-rule prose. Cancellation, uncertainty and other terminal stops authorize no continuation. Responses replays raw output items, including encrypted reasoning with `store: false`; the ChatGPT route also drops item IDs. Replayed turns are in memory and never journaled; a lost Run is interrupted, not resumed.
- Generated Tool branches and command, Skill and MCP names are limited to bounded catalog availability. Catalog data never replaces pinned router or Guard authorization.

The primary Delegate envelope takes optional nullable `agent`, selecting one admitted researcher definition for its `children`. Child objects follow the [assignment form](#named-roster-presets); an editor child also carries the closed `editor` assignment from the [worker protocol](./execution.md#worker-journal-protocol), repeats its mission as `objective` and requires null `profile`; its definition and digest come from the admitted catalog. The editor assignment requires `commands`: a sorted array of zero to eight unique admitted command names, each at most 64 bytes; missing, duplicate, unknown or extra names refuse admission. Assignments offer foreground or background mode, bounded wave numbers and nullable current-Run supersession; nullable `resumes` takes an exact historical child ID under [fresh-assignment semantics](./session.md#worker-identity-and-explicit-reassignment). Both native function encodings share this envelope. The schema offers editor assignments whenever an admitted editor definition exists, so it stays constant within a Run; the Engine refuses an editor Delegate before a committed Goal plan with bounded refusal feedback and no child call. Editor calls use the editor working-style prompt with its compiled live-Workspace, leased-file authority block, Single policy and the restricted catalog, with text answers and no Delegate. [Execution](./execution.md#agent-definitions) owns definition selection and authority intersection. Definition bodies stay labelled untrusted user guidance and add no system role or destination.

A settled primary call rejected with `outcome_contract` may get one corrective call per Run, on the same admitted routing and under ordinary Goal call, token, time, context and Store limits. The failed `ProviderCallRecorded` commits before the correction's reservation and dispatch. Only that request appends a compiled trailing harness data block asking for a permitted native function call or plain final assistant text; the system prefix stays byte-stable and the block is gone on later calls. Rejected response text never becomes an answer, instruction or executable proposal. Existing Tool observations stay available without redispatch. A second outcome-contract failure ends the Run with both failure records. Unknown usage under a finite token budget, cancellation, hook stop or uncertainty cannot authorize correction. Transport and framing, output-limit, Tool-review and child failures are outside this path. Codex CLI and Claude Code need no final-answer envelope either; Arany adds this single journaled correction to keep its typed Tool and replay guarantees.

Compaction requests use ordinary assistant text on Responses, ChatGPT, Messages and Chat Completions, following [Codex local compaction](https://github.com/openai/codex/blob/61f34c35af77777db4d77d0ea2aeb8547a6b4523/codex-rs/core/src/compact.rs#L318-L335) and [Pi's ordinary completion](https://github.com/badlogic/pi-mono/blob/3bc6eebacf3a6497eb82a66e02ca8644cfa3dde2/packages/coding-agent/src/core/compaction/compaction.ts#L681-L693). They omit response schemas, `tools`, `tool_choice` and `parallel_tool_calls`, keeping effort, caching and privacy fields. A reply must hold exactly one complete non-whitespace summary within the [generated compaction summary limit](./limits.md#max_compaction_summary_bytes), kept byte for byte. The requested cap follows the [generated compaction token limit](./limits.md#max_compaction_output_tokens), narrowed by the Provider's own cap. Responses joins ordered text parts of one final assistant message; Messages requires one text block after any thinking blocks; Chat Completions requires a non-empty string `message.content` and no tool calls. A tool call, refusal, incomplete or unknown stop, invalid required usage, model drift or selected-credential reflection rejects. JSON-looking prose is ordinary text, never parsed or repaired; headings are optional. Local validation proves framing and bounds, not fidelity or resistance to persuasion. A rejected summary never triggers a corrective call or format switch; only the journaled transport retry and fallback rules apply.

Anthropic thinking blocks are opaque: they replay unchanged within a Run, are never interpreted, and are dropped from kept turns when compaction rewrites history.

An opaque in-memory assistant turn is bounded to eight bytes per requested output token plus 64 KiB<!-- unrelated-bound: opaque assistant turn overhead --> of framing and ciphertext overhead, capped at the 1 MiB<!-- unrelated-bound: Provider HTTP response body --> response ceiling; exceeding it fails the call with `InvalidOutcome`.

Native adapters validate attachment count, aggregate bytes and objective or history origin before building a request body.

ReadOnly, Researcher and Editor ChildWork requests carry only that child's notes, as ordinary user data in the shared `steering_notes` block at their continuation boundary; earlier request prefixes stay unchanged on later continuations, retries and switches. ToolReview requests and invalid role or phase combinations, including nested Tool-step and stop-feedback notes, reject notes. [Goals](./goals.md#steering-notes-and-pause) owns admission, delivery and authority.

## Prompt caching

- Anthropic follows the peer explicit-breakpoint layout for active Tool loops: `cache_control: {"type":"ephemeral"}` on the last Tool definition, the last system text block and the final content block of the conversation tail. Single-call requests without Tools and compaction requests mark only the system block, since their changing tails are never reused and a tail breakpoint would pay the 1.25× write charge for nothing. A spent researcher's final call keeps Tool and system markers but omits the tail marker; changing Tool choice may invalidate the messages cache. Markers are added to the outgoing request, never stored in replayed turns or accumulated. This uses at most three of Anthropic's [four breakpoints](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) with the default five-minute TTL; no top-level automatic marker or extended TTL is requested.
- OpenAI API and ChatGPT Run and compaction calls send the Session UUID as a stable `prompt_cache_key`, matching Codex CLI's conversation-ID key. The UUIDv7 carries a creation timestamp and lets the Provider link one Session's turns, as with the peer; it adds no prompt, Workspace or credential text. Calls keep `store: false` and encrypted-reasoning replay. The shared prefix stays reusable across phase changes. No retention override is requested. Exact custom Responses profiles share this request shape.
- A cache key or breakpoint requests reuse; it guarantees no cache hit, remote retention or live compatibility. Cache-read counts flow through the [usage record](#usage-provenance-and-reliability) into the [Goal report](./goals.md#lifecycle-budgets-and-recovery).

## Configuration and egress

- An explicit CLI profile and model override trusted Session or user-configuration defaults. There is no compiled model default, Workspace-defined profile or implicit discovery. Attached `/model` follows the [terminal contract](./terminal.md#interactive-commands-and-completion).
- A Provider receives only the current objective, selected bounded Session context, instruction and include snapshots, and the Engine-produced child results the phase needs. Only the credentials of configured role routes and fallbacks are read. Credentials never enter CLI arguments, Events, output, fixtures, telemetry or error bodies.
- Every Provider HTTP client requests identity encoding, rejects a non-identity `Content-Encoding` before reading the body, and bounds declared and accumulated non-streamed bodies to 1 MiB<!-- unrelated-bound: Provider HTTP response body --> per response; SSE uses the [framing bounds](#streaming-and-provisional-text). Clients follow no redirects, use no ambient proxy or cookies and disable automatic protocol retries. Each client keeps at most one idle connection per host for 60 seconds.
- HTTPS is required outside numeric loopback, which may use explicit HTTP. Destinations are pinned. Route or model drift, changed addresses, metadata, link-local and multicast destinations, credential reuse across origins and credential reflection reject.
- Operating-system TLS trust uses Reqwest's platform verifier with chain and server-name checks intact. Certificate and revocation connections the OS makes during trust evaluation are not Provider destinations and never carry content, files or credentials.
- Each adapter owns authentication, request encoding, error mapping, usage, privacy and parsing. Endpoint authorization is not content authorization: omitted-input canaries prove withheld data never reaches a payload.
- Receipts use exact support language: `ChatGPT plan`; `custom` for a user-declared route; `broker constrained` after a future OpenRouter gate. A receipt never relabels a service as native OpenAI or Anthropic.

A future network grant must bind the typed operation, audience, method, destination, redirect policy, payload schema, data class and limits. A destination allowlist never authorizes arbitrary upload or proves data-loss prevention.

## Custom destinations and routing

One Messages adapter serves custom Anthropic-compatible routes with an explicit base URL and selected key, following [Pi at its reviewed commit](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/ai/src/api/anthropic-messages.ts#L1104-L1108). Arany adds admission before disclosure, durable custom provenance and strict validation of every response; a vendor compatibility label never replaces them.

- Native endpoints come from compiled, reviewed profiles. A custom profile lives in trusted user configuration outside the Workspace and names a closed protocol family, exact endpoint and base path, exact model, credential reference and outcome encoding. It never accepts arbitrary headers, shell credential commands, repository profiles, raw key arguments, redirects, ambient proxies, automatic model discovery, a generic compatibility plugin or cross-profile credential reuse. A new protocol family needs the same adapter and security review.
- The loader reads only `provider-profiles.json` from the private state root through a bounded no-follow handle as a [versioned record](./execution.md#incompatible-records), validating the whole closed set before returning a profile. The document has at most 32 uniquely named profiles, and each credential reference binds one origin. A Responses entry requires `protocol: openai-responses`, an exact canonical `/responses` `endpoint` and `outcome_encoding: json_schema`, and rejects `base_url` and `auth`. A Messages entry requires `protocol: anthropic-messages`, a canonical `base_url`, `outcome_encoding: native_tools` and `auth: bearer | x-api-key`, and rejects `endpoint` and arbitrary headers. A Chat Completions entry requires `protocol: openai-chat-completions`, a canonical `base_url`, `auth: bearer` and `outcome_encoding: json_schema`. Unknown and duplicate fields refuse.
- Every variant requires an exact bounded model ID, an `ARANY_PROVIDER_*` credential reference, `privacy: user_authorized`, `max_output_tokens: 4096` and a canonically ordered unique `efforts` list from `none|low|medium|high|xhigh|max`. An empty list sends no effort field, not even a native Claude default. Messages efforts map to `output_config.effort` and Chat Completions efforts to `reasoning_effort`. Custom profiles never use the native model resolver.
- For Messages and Chat Completions, the base is validated, at most one terminal slash removed, then `/v1/messages` or `/chat/completions` appended, keeping a nonempty base path. Base and derived URL each have a 512-byte<!-- unrelated-bound: custom endpoint URL bytes --> limit and 256-byte path limit. Bases already ending in their protocol suffix, credentials, queries, fragments, percent encoding, dot segments, doubled path slashes and noncanonical hosts or ports reject. Numeric loopback may use HTTP or HTTPS; domains need HTTPS and admitted public DNS.
- Domain DNS answers admit IPv6 only from reviewed allocated ranges; unallocated, reserved and unknown global-unicast ranges fail closed. The allowlist is refreshed against the [IANA global-unicast allocations](https://www.iana.org/assignments/ipv6-unicast-address-assignments) and the [special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry) when a range is needed.
- Messages requests send exactly the selected Bearer or `x-api-key` credential, `anthropic-version: 2023-06-01`, JSON content type, identity encoding and the compiled `User-Agent: arany/<version>`. Responses and Chat Completions use Bearer authentication and the same honest User-Agent. Native environment or saved keys and Anthropic workspace scope are never read or forwarded. The Messages adapter preserves opaque thinking and signatures and paired delegation results, rejects several calls locally even if a vendor ignores parallel-call suppression, and sends no thinking budget. Images refuse before HTTP.
- Chat Completions uses the `messages` wire family and replays assistant turns in it; compaction is a system and user text exchange. A successful reply needs a `Content-Type` media type of `application/json`, compared case-insensitively with parameters ignored; otherwise it fails as `InvalidOutcome`. It has no preview path. Wire provenance follows the [execution contract](./execution.md#admission-persistence-and-recovery).
- Profile documents keep the [record byte bound](./execution.md#persistence-bounds), 65,536 JSON nodes and depth 32. Names and credential references are at most 64 bytes, model IDs 128 and keys 512. Custom DNS admits at most eight addresses within five seconds; connection time is at most ten seconds and each call 120 seconds<!-- unrelated-bound: custom Provider call deadline -->, including vendor queues. Requests are bounded by [the generated Provider request limit](./limits.md#max_provider_request_bytes); replies follow the [Provider HTTP client bound](#configuration-and-egress), SSE the [framing limits](#streaming-and-provisional-text), and Messages at most 16 content blocks. Custom compaction is limited by its 4,096-token profile cap and [the generated compaction token limit](./limits.md#max_compaction_output_tokens). Overflow or invalid required usage rejects without partial acceptance; absent optional cache counters stay unknown.
- `CustomProvider::admit` re-reads the exact profile, resolves and pins every address for that Run, then reads the selected key. `custom:NAME` Runs use it before Workspace input, and `RunStarted` pins the admitted endpoint and a digest of the exact declaration. Each request connects only to the pinned addresses, follows no redirect and refuses a destination change. The Engine rejects a `custom:` Provider without that provenance before Workspace input; replay treats it as history, never authorization. Custom calls require positive labelled usage within the cap, and their unproven concurrency ceiling is one.
- Arany never sends a paid request the user did not ask for. Claude Code, Codex CLI and OpenCode run no conformance pre-check either; the strict decoder validates every real response. The first failure fails the Run with its closed reason and an actionable notice: `response_contract` when the model, completed message or usage does not match, `outcome_contract` for a malformed outcome or Tool call and `outcome_decode` for a reply that decodes to no complete outcome. It is never retried silently. Every reply, including a Tool call's arguments, must fit the profile's `max_output_tokens`, so a large Write needs smaller Edits. Images remain refused.
- Attached setup writes custom profile declarations only through the typed StateRoot writer against the previously inspected byte snapshot. It validates and bounds the whole record before publication. Uncertain publication is reported unknown and never retried or compensated. The environment reference stays metadata until a Run admits the destination.
- A future built-in OpenRouter profile is a broker: it pins one reviewed upstream endpoint, requires parameter support, disables fallback, denies data collection, requires ZDR, disables response caching, and records broker and upstream provenance.

DeepSeek API, Kimi platform and Code, and GLM Standard candidates follow their [setup recipes](../setup.md#openai-compatible-and-anthropic-custom-routes); a recipe grants nothing and claims no live support. Custom primary and child routes receive the same Workspace Tools, grants, Policy and Guard as native routes.

## Usage, provenance and reliability

MCP argument validity, selected-credential reflection checks and Guard dispatch share the strict Tool argument parser: one object, at most 8 KiB<!-- unrelated-bound: strict Tool JSON parser -->, depth 32 and 4,096 nodes, with no duplicate decoded keys. Invalid JSON rejects before canonical Tool persistence; a parse failure never proves credential absence.

- A failure before a decoded outcome retries the same route, in every role (including manual, automatic and in-Run compaction), single-route or chained: a send that fails before any response (the request may already have been delivered), a non-terminal HTTP 429, HTTP 5xx at status admission, or a body or stream that ends early, including a ChatGPT cut at its [idle window or call ceiling](./chatgpt.md#run-limits). A clean end is a cut only after at least one well-formed event.
- A semantic call has at most three retries across all its routes, with gaps of 2, 4 and 8 s (exponential from 2 s, at most 10 s each) or a longer delta-seconds `Retry-After` on a 429 or 5xx, which every adapter keeps. Each wait must end before the remaining action deadline, which lies inside the Goal's active time; a `Retry-After` that cannot fit is never waited out, so the call fails at once (a 5xx can still switch).
- Never retried: a send timeout, cancellation, other 4xx, a malformed stream or body, contract and content failures, a temporary-usage stream event (kept as unavailable), and a primary call with committed display text. The [primary outcome correction](#structured-outcomes-and-tool-encoding) is a separate journaled call.
- A 429 records the closed `rate_limited` reason. A bounded 429 body (at most 16 KiB<!-- unrelated-bound: Provider rate refusal body -->, read only to classify) whose error code or type names an exhausted quota, credit balance, plan, or spending or usage limit (`insufficient_quota`, `credit_balance_exhausted`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded`, `organization_usage_limit_exceeded`, `usage_limit_reached`, `usage_not_included`) records `usage_limit` and is terminal.
- Each retry commits its fact and passes fresh call-budget and Store admission before the wait. It is charged as a call with unknown usage, so a finite token budget refuses it. A pause or cancellation during the wait, or a lost retry acknowledgment, ends the call before any further reservation or dispatch; both are checked again just before re-dispatch. The preview is cleared and the retry shown as `Reconnecting… n/3`; `show`, `exec` receipts and the Goal report list every retry. Only after same-route retries does a configured fallback chain switch, and visible preview text still blocks the switch.
- Peer mapping: Codex retries 429, 5xx, transport errors and compaction streams (four request and five stream retries), honors `Retry-After`, never retries the exhausted quota, credit and spending codes (openai/codex 102fc57e), and shows `Reconnecting... n/max`; OpenCode backs off from 2 s capped at 10 s and retries only before output; Pi and Goose default to three. Arany takes the lowest peer count and, unlike every peer, journals and charges each attempt for durable Goals and strict replay: a send failure after delivery can double remote usage, and that cost is charged, never hidden. A Provider call is not a Workspace effect, so no effect repeats.
- Calls across all roles, retries and configured fallbacks share the Goal budget and per-action limits. A lost response may already have consumed tokens. Unconfigured broker fallback stays off.
- Each semantic step commits one bounded `ProviderCallRecorded` fact before its AgentRun terminal Event; a failed attempt that switches is recorded by `ProviderFallbackUsed` before its replacement dispatch. Phase and local disposition are canonical; the response ID and reported usage appear only when a bounded response arrived. A timed-out or cancelled call reports unknown usage and does not prove absence of remote billing. Responses `completed` with a local `store: false` request and Messages `end_turn` are distinct wire provenance; neither is a remote retention or ZDR guarantee.
- Cache-read and cache-creation counts are subsets of the reported input total. Responses `usage.input_tokens_details.cached_tokens` supplies reads and `usage.input_tokens_details.cache_write_tokens` creation, on native OpenAI, exact custom Responses and the ChatGPT decoder. Anthropic `usage.cache_read_input_tokens` and `usage.cache_creation_input_tokens` supply reads and writes beside uncached `input_tokens`, and their checked sum is the input total. Messages may instead report writes as `usage.cache_creation` with required `ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`, whose checked sum is the creation total; if both forms are present, the totals must agree and count once. Reads and writes are independently optional: absent counters stay unknown and explicit zero is zero. Counters are unsigned 32-bit integers, the input total fits the reporting ceiling, and cache subsets cannot exceed it; malformed, overflowing or inconsistent usage rejects without retry. Streaming keeps these counters from the final usage envelope, merging Anthropic message-start and message-delta usage.
- API-key adapters reject exact selected-key reflection in bounded raw bytes and in decoded outcome, response-ID or compaction fields, including JSON-escaped echoes. This is not general secret detection.
- Persist only the bounded adapter, endpoint profile, requested and resolved model, request ID, broker and upstream identity, finish reason, usage provenance and privacy controls. Raw response bodies and uncontrolled headers are never persisted.
- A catalog lists availability, not compatibility; only reviewed manifests, adapter fixtures and opt-in live Runs support capability claims.

Provider adapters build their closed diagnostic stages, stream counts, response-shape metadata, Tool argument shapes and stream, failure and context records in the private `provider::diagnostics` module, and submit inert bounded records to the shared diagnostics sink; subscription diagnostics keep received stream counts and closed final-decoding causes without response content. Diagnostics never change Provider acceptance, retry, output or canonical failure reasons; the [diagnostics contract](./diagnostics.md#privacy) owns privacy and retention.

### Passive plan-limit observations

Authorized ChatGPT inference responses may supply optional numeric plan windows. The adapter reads only `x-codex-{primary,secondary}-{used-percent,window-minutes,reset-at}` headers and recognized `codex.rate_limits` events whose `rate_limits.primary/secondary` objects hold `used_percent`, `window_minutes` and `reset_at`. An event's `metered_limit_name` and `limit_name`, when present, must each be exactly `codex`; other meters are ignored and never stored. This follows the [pinned Codex parser](https://github.com/openai/codex/blob/a390571745da105cfdc85443dd1d38bf78e5ea6e/codex-rs/codex-api/src/rate_limits.rs); Arany keeps only the default meter and uses percent used. The [ChatGPT route](./chatgpt.md#catalog-and-runs) does not guarantee these fields.

A caller-owned slot keeps at most two final windows and one closed unavailable reason per attempt, at most 4 KiB<!-- unrelated-bound: passive Provider rate-limit sample --> serialized. Header extraction admits at most 32 recognized values, each at most 128 bytes and 4 KiB<!-- unrelated-bound: passive Provider rate-limit header aggregate --> aggregate. Duplicate names, malformed fields and overflow make the affected sample unavailable; aggregate overflow invalidates both header windows. Percentages must be finite and within 0–100, durations positive `u32` minutes, and reset and observation timestamps Unix seconds from zero to 253,402,300,799. Missing percentage, duration and reset are independently unknown; nothing is clamped or inferred. Each received header or event sample reads the observation clock once; each kept window and unavailable reason keeps that receipt time and its closed source. A valid event replaces its slot's whole header window, never borrowing missing fields; omitted windows keep their own source and receipt time.

Header observations are collected before status and body admission and survive body failure, timeout, cancellation and dropped futures. Selected-token reflection in any response header is a transport rejection (`InvalidOutcome`) before collection and status classification, including on 429 and 5xx; stream reflection, framing and required-usage rejection stay authoritative. Otherwise optional metadata changes no outcome, retry, fallback, cancellation, budget or permission decision. A response without metadata supplies no observation. The slot is consumed only with the attempt's [committed fact](./execution.md#admission-persistence-and-recovery), before continuation. Observations persist no raw headers, account identifiers, plan or meter names, URLs, bodies or upstream text, never enter prompts, compaction input or telemetry content, and inspecting them adds no request or credential access.

Native OpenAI Responses and Anthropic Messages JSON and streaming invocation, including previews, children and review calls, and compaction collect passive API rate facts from authorized calls. Every attempt retains admitted headers through status failures, body loss, stream cuts, cancellation and deadlines; retry and fallback facts attribute them to the outgoing actual route before another dispatch. Native API stream events cannot supply plan observations. Between-Run and in-Run compaction keep role-labelled observations in committed compaction facts, including failed or cancelled calls. Only committed samples enter the report; append failure or lost acknowledgment stops continuation. Cancellation before headers supplies no sample; after headers it retains admitted facts without another dispatch, retry or fallback. OpenAI recognizes only the documented `x-ratelimit-{limit,remaining,reset}-{requests,tokens,project-tokens}` family, independently of `Retry-After`. Counts are unsigned `u64`, including zero; missing limit, remaining and reset are independently unknown. OpenAI resets use ordered, unique `d`, `h`, `m`, `s`, `ms` components, with fractional seconds to millisecond precision and checked arithmetic from one receipt-clock read, rounded up to whole Unix seconds. Signs, exponents, unsupported precision, malformed components and timestamp overflow are unavailable. Counters are provider-reported throughput facts, never percentages or a plan balance.

Anthropic recognizes only the documented [`anthropic-ratelimit-{requests,tokens,input-tokens,output-tokens}-{limit,remaining,reset}` and `anthropic-priority-{input-tokens,output-tokens}-{limit,remaining,reset}` families](https://platform.claude.com/docs/en/api/rate-limits#response-headers). Standard, input, output and priority dimensions stay separate. Generic tokens reflect the most restrictive current limit, never an additive total; token remaining counters may be rounded. Resets require a valid RFC3339 Gregorian date, time and offset with at most 9 fractional digits, rounded up to whole seconds. Leap seconds, invalid calendars and normalized timestamp overflow are unavailable. API workspace IDs and foreign or fast-mode quotas are ignored. Collection admits no polling or priority request policy.

The optional `api` payload has a closed dialect and unique dimension rows, bounded by [the API row ceiling](./limits.md#max_api_limit_rows) and the serialized observation and header bounds above. API and plan payloads cannot coexist. Each row keeps its header source, receipt time, independent numeric fields and a closed unavailable reason; an invalid row carries no numeric fields. Aggregate header overflow invalidates the API sample. The first valid sample pins its family for the attempt; a cross-family sample cannot replace it. API headers produce one whole snapshot, while plan events keep whole-window replacement. An absent `api` payload is omitted, leaving Event bytes and plan fields unchanged. The reflection, failure retention, committed settlement, privacy and passivity rules above apply.

## Streaming and provisional text

- A preview is a bounded candidate, never an accepted outcome, reasoning channel, Tool argument or authority. Only public assistant text is extracted. Assistant text streams as the answer candidate. Text that may still become commentary (all Anthropic text, ChatGPT text outside an explicit `final_answer` item) is shown but journaled only at the completion boundary: as an Answer chunk if it is the answer, as Commentary if a call follows. If a function call follows, the candidate is withdrawn; commentary-phase text is held until the boundary. A candidate above the display limit stops streaming and leaves the committed answer to the Engine, which refuses it as `answer_invalid` like every other route.
- A `final_answer` item followed by a function call is a response-contract failure: the item announced the end of the turn and may already be journaled, so honoring the call would contradict a committed outcome. Codex tolerates it; Arany keeps exactly one committed outcome per step.
- Known selected credentials are checked before text is shown or recorded. A suffix that could complete a credential is held back, and cancellation drops any buffered tail instead of flushing it.
- The one-slot `ResponsePreview` observer holds the latest bounded snapshot; complete response, model, usage and outcome checks still decide acceptance. Only attached primary invocations expose a preview; configured fallback chains also use a bounded private observer as an extra visible-output guard, while HTTP status admission decides eligibility.
- Framing bounds derive from the call's declared output-token cap (within the [admitted cap ceiling](./execution.md#accepted-outcomes)): the event bound is the greater of 8,192 events and two events per output token plus 2,048; the byte bound is 512 envelope bytes times the event bound across the stream. Probes and compaction use their own smaller caps. Individual lines, assembled event data and reconciled completed responses keep the non-streamed body ceiling. Overflow fails closed as `stream_protocol`, without an outcome or retry, and [development diagnostics](./diagnostics.md) name the framing limit. Event JSON must be duplicate-free within 262,144 nodes and depth 64 (a `response.created` event echoes the request, including the Tool catalog); an opaque assistant turn uses the same node and depth bounds within its own byte cap. Labels and types must agree, and media or response encoding never switches silently. Native and custom streaming use strict SSE media admission; ChatGPT uses its [own SSE policy](./chatgpt.md#catalog-and-runs).

## Commands

- `arany provider models PROFILE` reads only the selected native credential and no Workspace data. The default source is the Provider's environment key; `--saved-account` selects the current OS-stored API account and rejects a Provider mismatch. The result is complete or fails closed at 1 MiB<!-- unrelated-bound: model discovery response page --> per page, 16 pages or 4,096 unique models.
