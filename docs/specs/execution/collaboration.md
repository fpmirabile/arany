# Execution: collaboration and agent definitions

## Collaboration

Every accepted task belongs to a Goal. Each Run has one accountable primary AgentRun and an ordered, bounded set of direct researcher and EditOnly children, which cannot nest teams. The primary obtains file evidence, performs authorized effects and owns the final answer; Goal completion and Run completion are separate receipts ([Goal lifecycle](../goals.md#lifecycle-budgets-and-recovery)).

A researcher holds the `read_only` grant. Within the Goal plan contract (before one exists, any admitted Workspace path), it may call Workspace List/Read/Search, admitted Skill reads, MCP catalog listing (which starts the admitted stdio server under the Guard) and explicitly granted [web Tools](../tools/commands-and-cache.md#web-fetch-and-web-search), then returns a bounded report. Without a Tool runtime a child makes one reasoning call. Only EditOnly children change files, in private workspaces integrated within their leases ([Worker journal protocol](./events-and-outcomes.md#worker-journal-protocol)).

One policy is pinned before the Run: default `single` admits no children; opt-in `auto` (`/agents auto`, `exec --collaboration auto`) allows up to three direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The persisted `max_active_children` caps total direct assignment attempts across the Run, including researchers, replacements and later waves. Remaining call, token, byte and time budgets also bound team size, and Provider concurrency ceilings bound simultaneous calls while admitted children wait in order. In `auto`, the primary is guided to keep routine work local and choose the smallest useful team; only typed policy and budgets enforce capacity. Agent inspection separates the current or last Run from historical agents.

Child authority is the intersection of global policy, parent effective authority and the explicit task grant. Children cannot self-approve or alter sibling authority, and missing configuration never restores a capability.

Child identities and assignments keep ordinal order even when calls finish out of order; synthesis receives committed reports in assignment order, and researcher reports never satisfy the Goal criterion. Background coordination lists pending identities without provisional child text. A researcher failure, including one out-of-grant MCP call, drains every sibling and fails the Run, keeping its original failure if draining also fails; an editor failure stays local ([Agent definitions](#agent-definitions)). Cancellation reaches every admitted child and keeps observed calls and terminal facts.

A primary outcome that breaks the outcome contract records `invalid_response` with `outcome_contract` and gets one [corrective call](../provider/encoding-and-streaming.md#structured-outcomes-and-tool-encoding); if that also fails, the Run fails with `provider_call` and the final typed parse reason. Both calls stay charged. A framed response that cannot decode into an offered answer or typed proposal records `invalid_response` with `outcome_decode`, distinct from `response_contract` (identity, usage and provenance after decoding). A decoded outcome refused only by budget or token admission records `invalid_response` with a null reason and its usage. Later context uses the [committed failure projection](../session.md#context-and-compaction).

## Researcher children

One delegation active-time segment covers child calls and Tools, including shared Guard capacity waits, and charges overlapping work once. A pending child Ask pauses it while idle, but sibling activity keeps consuming it; exhaustion withdraws the Ask before dispatch with its delegation or Goal cause. Pause takes effect before each child step. Child Tool facts stay in the child's agent view.

| Bound | Value | Overflow |
|---|---|---|
| Children per delegation | existing policy, ≤ 8 | invalid delegation |
| Child objective / report | 2 KiB<!-- unrelated-bound: child objective bytes --> objective; 16 KiB<!-- unrelated-bound: child result bytes --> result, 2 KiB<!-- unrelated-bound: child summary bytes --> summary | invalid response, child Failed |
| Child Tool calls | `min(16, ((remaining calls − children − 1) / 2) / children)`, 16 if calls are unlimited; replay cap 16 | catalog `tool_calls_remaining: 0`, only answer offered; a further Tool is an invalid response |
| Child Tool result | `min([Tool result ceiling](../tools/limits-and-failures.md#limits-and-failure-behavior), (context limit − context − intent − 512) / 6)`; Tools offered only while at least 4.6 KiB fits | only answer offered; safety net stops the child |
| Delegation time | one active segment, at most 20 min and the remaining Goal active time | pending asks withdraw before dispatch with a delegation or Goal stop; a delegation limit stops the Run without closing the Goal as exhausted |
| Child Tool time | at most half the remaining active allowance after preparation, cleanup and Store overhead; the Guard capacity wait counts against it | insufficient runtime: a non-dispatched `Limit` observation (`Delegation deadline reached`); no hook or Tool executes |

## Agent definitions

Definitions come only from exact Workspace `.claude/agents/*.md` and the admitted private StateRoot `agents/*.md`, with private names winning, in one strict Claude-format subset; there is no home, plugin, recursive or alternative-format discovery. The project directory must lie wholly inside the parent read grant. Missing directories are empty; unsafe present entries (symlinks, links, non-owned or oversized files, bad names) refuse the whole registry before any Provider call. Definitions are snapshotted once per Run during input preparation; [parser admission](../tools/editors.md#agent-definition-parser-admission) owns filesystem and Guard enforcement.

A file with invalid content (bad frontmatter or field value, YAML anchor/alias/tag, size bounds, duplicate name within a source) is skipped with a bounded diagnostic naming the file and field, shown in the Goal report evidence. Unsupported frontmatter fields (for example `color`, `hooks`, `mcpServers`) and tool names are ignored with a diagnostic, which only narrows authority. The registry lists at most 8 KiB<!-- unrelated-bound: agent registry base catalog --> of entries in name order, dropping later definitions with a diagnostic; if editor metadata pushes the complete catalog over 8 KiB<!-- unrelated-bound: complete agent registry catalog -->, the Run fails before Provider disclosure. Selecting a skipped, dropped or absent name is an invalid delegation.

The envelope is Markdown with YAML frontmatter. `name` and `description` are required strings; the only optional fields are `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `isolation` and `background`. Duplicate or explicit-null fields and wrongly typed or out-of-range values make the file invalid. Names use lowercase ASCII letters, digits, `_` and `-`, at most 64 bytes; the description is nonempty and at most 2 KiB<!-- unrelated-bound: agent definition description -->, the body at most 32 KiB<!-- unrelated-bound: agent definition body cap -->. The body is untrusted assignment guidance in the child's user input, never a system role; the primary sees only bounded names and descriptions.

Tool lists accept comma-separated strings or string arrays, at most 32 names of 128 bytes each. `Read`, `Grep`, `Write` and `Skill` map to `read`, `search`, `write` and `skill`; `Edit` to `edit`, `multiedit`, `delete` and `move`; `MultiEdit` to `multiedit`; `Glob` to `list` and `glob`. Exact names for those operations plus `mkdir` and `mcp_list` are accepted. `Bash` (or exact `command`) maps to `command` for editors only, as a narrowing permission, and a denied `Bash(...)` pattern denies every command. Unknown names, patterns, Agent, Git and MCP invocation are ignored with a diagnostic and grant nothing. Missing `tools` inherits the admitted catalog for the assignment kind; `disallowedTools` subtracts. An empty effective edit capability supplies no write authority.

Omitted `model` or `inherit` keeps the parent-admitted child chain, and definition model metadata cannot override an assignment-selected profile. A literal equal to its initial admitted child's exact model is kept; any other value selects no route, account, alias or credential and acts as `inherit` with a diagnostic. The five [permission-mode spellings](../tools/permissions.md#modes-and-approval-decisions) only narrow parent settings and live terminal restrictions, using Deny > Ask > Allow. File text never grants a capability or resolves an approval.

The primary's Delegate may select one registry name through `agent` for its group of researcher objectives; null or omission selects the default researcher, and a researcher group cannot select an editor. Selection is validated before any child spawn and pinned by `AgentSpawned.definition`. A selected definition narrows the read-only catalog and can reduce child inference turns to 1–17 (`maxTurns`, default 17); Tool reviews consume none. The 16 model Tool request maximum and Goal headroom still apply, and the last turn offers only answer. A Tool beyond the child's remaining allowance, an unknown name or an unsupported editor selection fails the Run without granting or dispatching the effect.

`isolation: worktree` identifies an editor definition and grants nothing more, since every editor already works in a private workspace. Omitted `background` is `false`; `background: true` requires background assignment mode, while a foreground default may run in either.

`RunStarted.config.agent_definitions` is required nullable: null for an empty or unavailable registry, otherwise the ordered source/filename/raw-digest pins and their SHA-256. Each Run parses its snapshot once, in the Guard when the Run has a sandbox and in process otherwise, before its first Provider call; replay verifies the recorded results and never rereads or reparses a definition. Parsing is excluded from model Tool counts, history and compaction bodies. Interrupted parsing supplies no authority; a new Run takes a fresh snapshot.

| Definition bound | Limit / overflow |
|---|---|
| Discovery | 256 scanned entries per source; 64 candidate Markdown files per source; 1 MiB<!-- unrelated-bound: agent definition discovery bytes --> aggregate raw bytes; whole refusal |
| File and normalized registry | 64 KiB<!-- unrelated-bound: agent definition raw file --> per raw file; 1 MiB<!-- unrelated-bound: normalized agent registry bytes --> aggregate normalized records; existing Tool observation, Guard task, catalog and request ceilings may reject sooner; no truncation |
| YAML | 4096 nodes, depth 32; no aliases, anchors, tags or duplicate keys; an unterminated quote at a line end is refused; the file is skipped |
| Catalog | 8 KiB<!-- unrelated-bound: agent registry catalog --> of agent entries; later names dropped with a diagnostic |

A Delegate decision admits one wave of mixed researchers and editors, each proposal validated in full before any child disclosure: malformed definitions, paths, overlapping leases, wave numbers or total-attempt overflow refuse it. Total attempts are at most eight under explicit team policy and three under opt-in auto without a count. Nothing is retried automatically: a replacement needs an explicit new Delegate decision with fresh ID, grant and lease, and `supersedes` may name a terminal, released child of this Run. Explicit `resumes` names a terminal or interrupted historical child of the same Session and Goal ([Session identity](../session.md#worker-identity-and-explicit-reassignment)); it always creates a fresh assignment, grant and lease, and adopts its source's kept workspace when one remains.

Invalid editor input, checked when the Delegate is accepted and again before spawn, records a rejected proposal with an editor [refusal cause](./events-and-outcomes.md#accepted-outcomes) (phase requirements keep `phase`) and follows the bounded refusal continuation; reasons contain compiled guidance only, never definition or Provider text. The refusal survives reopen, and replay rejects forged accepted invalid assignments without executing them. An accepted assignment that fails revalidation stops the Run before spawn, never silently omitted.

Worker concurrency defaults to four, configurable only through Engine settings to 1–8, then narrowed by policy size and admitted Provider concurrency; a finite-token Goal serializes all Provider calls. Queued assignments spend no calls. Pending assignments, completions and report collections are each bounded by eight, and overflow refuses admission without dropping a member. Tool dispatch stays serial per Run.

Editors take foreground and background assignments with typed file operations and explicitly admitted commands, whose names intersect parent, plan and definition before spawn; definition metadata cannot widen authority. Disjoint background editors work in their own workspaces while the primary and researchers read the live Workspace; the primary may write outside their leases.

Foreground children block primary coordination until their terminal answer and lease release. A successful primary answer and the next delegation also require fresh passing primary verification for every ready or no-change editor. A known editor failure integrates nothing, keeps the editor's workspace for an explicit resume and releases the lease. An unfinished or [Uncertain](./events-and-outcomes.md#effect-outcomes) effect, including an editor's write in its workspace or its integration, stops the Run and blocks Goal continuation, with no rollback claim.
