# Execution: collaboration and agent definitions

## Collaboration

Each accepted task is durably linked to a Goal before its first `MessageAccepted`. Each Run has one accountable primary AgentRun and an ordered, bounded set of direct researcher and EditOnly children. Children cannot create nested teams; only EditOnly children change files, in private workspaces whose changes integrate within their assignment leases. With a Tool runtime, each researcher spawn pins the `read_only` grant and each EditOnly child its leased assignment grant. A researcher may alternate calls with Workspace List/Read/Search, admitted Skill reads, MCP catalog listing and explicitly granted [web Tools](../tools/commands-and-cache.md#web-fetch-and-web-search), within the Goal plan contract, before returning its bounded report. Before any plan contract a researcher may read any admitted Workspace path, as the primary prelude may; MCP catalog listing starts the admitted stdio server under the Guard. Without a Tool runtime a child makes one reasoning call. A researcher failure, including one out-of-grant MCP call, fails the Run and drains every sibling; an editor failure stays local as specified below. The primary obtains file evidence, performs authorized effects and owns the final answer. Goal completion and Run completion are separate receipts ([Goal lifecycle](../goals.md#lifecycle-budgets-and-recovery)).

One policy is pinned before the Run: default `single` admits no children; opt-in `auto` (`/agents auto`, `exec --collaboration auto`) allows up to three direct children when useful; explicit `team` requires decomposition on the first non-Tool outcome. The default stays `single` until delegation is an ordinary Tool rather than an exclusive outcome with a synthesis phase. The persisted `max_active_children` limits total direct assignment attempts across the Run, including researchers, replacements and later waves. Policy, process safety and remaining call, token, byte and time budgets bound team size; the pinned primary and child Provider concurrency ceilings separately bound simultaneous calls while admitted children wait in order. A ceiling is permission, not a required team size.

Auto guidance asks the primary to keep routine edits and simple inspection local, delegate substantial independent work only when the benefit justifies extra calls, and choose the smallest useful team. Typed policy and budgets enforce capacity; guidance does not guarantee a model's judgment. Agent inspection separates the current or last Run from historical agents.

Child authority is the intersection of global policy, parent effective authority and the explicit task grant. Children cannot self-approve or alter sibling authority, and missing configuration never restores a capability.

Child identities and assignments keep ordinal order even when calls finish out of order. Synthesis receives committed reports in assignment order; researcher reports never satisfy the Goal criterion. Background coordination lists pending identities without provisional child text. Researcher failure drains siblings before primary failure. Cancellation reaches every admitted child and preserves observed calls and terminal facts. A delegation abort keeps its original failure when sibling draining also fails; the drain failure is diagnostic only.

A primary outcome-contract failure commits as `ProviderCallRecorded` with `invalid_response` and `outcome_contract` before the [single corrective call](../provider/encoding-and-streaming.md#structured-outcomes-and-tool-encoding) reserves and dispatches. Replay permits that same-phase continuation only after the first such failure, with settled Tools and hooks, and rejects a reservation after the second. Reservations and unknown usage stay charged. If correction also fails, the Run records `provider_call` with the final typed parse reason. Later context uses the [committed failure projection](../session.md#context-and-compaction), never an invented causal explanation.

A framed response whose content cannot decode into an offered answer or typed proposal records `invalid_response` with `outcome_decode`. It is distinct from `outcome_contract` (one corrective call) and `response_contract` (identity, usage and provenance after decoding). A decoded outcome refused only by budget or token admission records `invalid_response` with a null reason and its usage.

## Researcher children

One delegation active-time segment covers child calls and child Tools, including shared Guard capacity waits, and charges overlapping Provider, effect, preparation and cleanup work once. A pending child Ask pauses this allowance while idle; sibling activity keeps consuming it. Exhaustion withdraws the Ask before dispatch with its delegation or Goal cause. Pause takes effect before each child step.

Child Tool facts of read-only research steps stay in the child's own agent view; the primary's run view and plan rules are unchanged.

## Agent definitions

Definitions come only from exact Workspace `.claude/agents/*.md` and the admitted private StateRoot `agents/*.md`; private names win. One strict Claude-format subset is accepted. There is no home, plugin, recursive or alternative-format discovery. The project directory must lie wholly inside the parent read grant. Missing directories are empty; unsafe present entries (symlinks, links, non-owned or oversized files, bad names) refuse the whole registry before any Provider call.

A file with invalid content (bad frontmatter or field value, YAML anchor/alias/tag, size bounds, duplicate name within a source) is skipped with a bounded diagnostic naming the file and field, journaled in the parse receipt and shown in the Goal report evidence. Unsupported frontmatter fields (for example `color`, `hooks`, `mcpServers`) and unsupported tool names are ignored with a diagnostic; ignoring only narrows authority. The registry lists at most 8 KiB<!-- unrelated-bound: agent registry base catalog --> of base entries in name order; later definitions are dropped with a diagnostic. Foreground editor metadata adds its normalized digest and turn ceiling at Engine admission; if the complete catalog then exceeds 8 KiB<!-- unrelated-bound: complete agent registry catalog -->, initialization fails before Provider disclosure. Selecting a skipped, dropped or absent name is an invalid delegation; editor proposals follow the upfront refusal rules below. Discovery is an immutable raw-byte snapshot taken during input preparation. [Parser admission](../tools/editors.md#agent-definition-parser-admission) owns filesystem and Guard enforcement.

The envelope is Markdown with YAML frontmatter. `name` and `description` are required strings; the only optional fields are `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `isolation` and `background`. Duplicate or explicit-null fields and wrongly typed or out-of-range values make the file invalid. Names use lowercase ASCII letters, digits, `_` and `-`, at most 64 bytes. Description is nonempty and at most 2 KiB<!-- unrelated-bound: agent definition description -->; body is at most 32 KiB<!-- unrelated-bound: agent definition body cap -->. The body is untrusted assignment guidance in the child's user input, never a system role. The primary receives bounded names and descriptions, never unselected bodies.

Tool lists accept comma-separated strings or string arrays, at most 32 names of 128 bytes each. `Read`, `Grep`, `Write` and `Skill` map to `read`, `search`, `write` and `skill`; `Edit` maps to `edit`, `multiedit`, `delete` and `move`; `MultiEdit` to `multiedit`; `Glob` to `list` and `glob`. Exact names for those operations plus `mkdir` and `mcp_list` are accepted. `Bash` maps to `command` for editors only, as a narrowing permission, and a denied `Bash(...)` pattern denies every command; exact `command` is also recognized. Unknown names, patterns, Agent, Git and MCP invocation are ignored with a diagnostic and grant nothing. Missing `tools` inherits the admitted catalog for the assignment kind; `disallowedTools` subtracts. An empty effective edit capability supplies no write authority.

Omitted `model` or `inherit` keeps the complete parent-admitted child chain. Definition model metadata cannot override an assignment-selected profile. A literal model equal to its initial admitted child's exact model is kept; any other value selects no route, account, alias or credential and is treated as `inherit` with a diagnostic. The five [permission-mode spellings](../tools/permissions.md#modes-and-approval-decisions) only narrow parent settings and live terminal restrictions, using Deny > Ask > Allow. File text never grants a capability or resolves an approval.

The primary's Delegate may select one registry name through `agent` for its group of researcher objectives; null or omission selects the default researcher. Selection is validated before any child spawn or call and pinned by the required nullable `AgentSpawned.definition`. A selected definition narrows the read-only catalog and can reduce child inference turns to 1–17 (`maxTurns`, default 17); Tool reviews do not consume turns. The maximum 16 model Tool requests and Goal headroom still apply, and the last available turn offers only answer. A Tool beyond the child's remaining allowance, an unknown name or an unsupported editor selection is an invalid delegation or child response and fails the Run without granting or dispatching the effect.

`isolation: worktree` identifies an editor definition. Every editor works in its own private workspace ([Worker journal protocol](./events-and-outcomes.md#worker-journal-protocol)); the field grants no further isolation or authority. Omitted `background` is `false`. A definition with `background: true` requires background assignment mode; a foreground default may be scheduled in either mode. A researcher group cannot select an editor through its group-level `agent` field.

`RunStarted.config.agent_definitions` is required nullable: null for an empty or unavailable registry, otherwise the ordered source/filename/raw-digest pins and their SHA-256. Internal parser intents follow the primary spawn, in that order, before the first Provider reservation. A matching successful Guard observation fixes each closed normalized-v1 result; when the Run's Guard pin has no sandbox, the same parser and bounds run in process instead and an in-process receipt fixes it, which strict replay refuses in a Run with a sandbox. Each result is a definition with notes or a skipped-file diagnostic. Private precedence applies after every document is classified. Strict replay verifies these facts and model admission, requires every parser observation before Provider reservation, rejects late refresh or duplicate parsing, and never reruns a parser. Internal preparation is excluded from model Tool counts, history and compaction bodies; compaction `covered_tool_count` indexes the Run's Tool Events, with the leading parse steps counted as covered. Interrupted parsing supplies no authority; a new Run takes fresh snapshots and Guard admission.

A Delegate decision admits one wave of mixed researchers and editors. Each proposal is validated in full before any child disclosure: malformed definitions, paths, overlapping leases, wave numbers or total-attempt overflow refuse it. There are at most eight total attempts under explicit team policy and three under opt-in auto without a count. A replacement requires an explicit new Delegate decision with fresh ID, grant and lease; `supersedes` may name a terminal, released child of this Run. Nothing is retried automatically. Explicit `resumes` names a terminal or interrupted historical child of the same Session and Goal ([Session identity](../session.md#worker-identity-and-explicit-reassignment) owns admission and historical context); it always creates a fresh assignment, grant and lease; the new editor adopts its source's kept workspace when one remains.

The Engine runs the Session reducer's editor-request checks before accepting a Delegate and again before spawn. Invalid editor input records a rejected proposal with an editor [refusal cause](./events-and-outcomes.md#accepted-outcomes) (phase requirements keep `phase`) and follows the bounded refusal continuation. Reasons contain compiled guidance only, never definition or Provider text. Engine-only liveness, wave, route, lease-overlap and total-attempt gates still apply. An accepted queued assignment that fails revalidation stops with an invariant error before spawn; it is never silently omitted. The refusal survives reopen; strict replay rejects forged accepted invalid assignments without executing them. Failed or unknown refusal appends and cancellation stop continuation before child work.

Worker concurrency defaults to four, configurable only through Engine settings to 1–8, then narrowed by policy size and admitted Provider concurrency. A finite-token Goal serializes all Provider calls, including background primary coordination. Only available slots admit queued assignments and reserve calls; queued assignments never spend calls. Pending assignments, completions and report collections are each bounded by eight; Tool dispatch stays serial per Run, while a primary or researcher step may hold its batch of pending intents. Overflow refuses admission without dropping a member.

Editors admit foreground and background assignments with typed file operations and explicitly admitted commands. Disjoint background editors work in their own workspaces while the primary and researchers read the live Workspace; the primary may write outside their leases. Command names intersect parent, plan and definition before spawn. Definition metadata cannot widen authority.

Foreground children block primary coordination until their terminal answer and causal lease release. A successful primary answer and the next delegation also require fresh passing primary verification for every ready or no-change editor. A known editor failure stays local, integrates nothing, keeps the editor's workspace for an explicit resume and releases the lease; a researcher failure stays fatal. An unfinished or [Uncertain](./events-and-outcomes.md#effect-outcomes) effect, including an editor's write in its workspace or its integration, stops the Run and blocks Goal continuation, with no rollback claim.

For a wave-primary request, the Engine binds the primary route and cap, admits worker use and reserves the Provider call before final primary-context preparation, and builds the request only once that context is ready. The prepared input, model and output cap are unchanged; a refused reservation or stop dispatches nothing.
