# Execution: admission and recovery

## Admission, persistence and recovery

A `serve --stdio` process opens one Engine shared by its loaded threads; the [serve contract](../serve.md) owns its client loop.

Persist only SQLite schema 15 and compaction compiler version 3. The schema is the one journal format version: every Event kind has exactly one current payload shape, and any payload change, additive or not, advances the schema, which archives existing history ([incompatible history](./persistence.md#incompatible-history)). Before opening the Engine, attached chat, `exec`, `serve` and `acp` validate the whole journal. Decoding is strict, and per-kind payload bounds are in [persistence bounds](./persistence.md#persistence-bounds).

| Event kind | Current payload notes |
|---|---|
| `RunStarted` | `config` pins the model `context_window_tokens` and the resolved [`effective_context_window_tokens`](../session.md#context-and-compaction) (both null or both set), `user_instruction_digest` (raw SHA-256 of the State `AGENTS.md`, or explicit null), ordered `instruction_sources` (`{directory, file, digest}`, root first; `file` is required and nullable), `prompts` (`{file, source, digest}` for `primary`, `team`, `researcher`, `editor` and `compaction` in that order; `source` is `default` or `override` and `digest` the raw SHA-256 of the rendered [working-style text](../session.md#prompt-overrides)) and the Workspace-relative `launch_directory`; custom provenance pins the admitted endpoint and declaration digest |
| `ToolStarted` | Required nullable `verdict`, with the configured or host permission verdict before dispatch |
| `ProviderCallRecorded` | Required nullable `context_bytes` counts a primary planning or synthesis request's content bytes (pinned compiled content plus Tool context) and [calibrates the context ceiling](../session.md#context-and-compaction); the closed failure reasons include `rate_limited` and `outcome_decode`; editor refusal causes follow [Accepted outcomes](./events-and-outcomes.md#accepted-outcomes) |
| `CommandToolProbeStarted`, `CommandToolProbeFinished` | Idle, intent-bound Guard probe and outcome; [Command tools](../tools/hooks.md#hook-execution) owns confirmation and interruption |
| `MessageAccepted` | Required nullable `skill` names the invoked Skill, null for an ordinary turn |
| `GoalFinished` | Required nullable `budget_refusal` follows the [Goal refusal contract](../goals.md#budget-refusal-feedback) |
| `ContextCompacted`, `GoalContextCompacted` | The record pins the compaction `prompt` (`{file, source, digest}`, `file` always `compaction`) |
| `WorkspaceRewindStarted` | No preview expiry |

Fields omitted at their default replay as the default. They include Goal resource settings and `ToolLimits.build_jobs` (a missing value replays as **1**, never as current cores; new Goals record resolved jobs, null meaning Build unavailable), Search's `regex`, `include`, `case_sensitive`, `offset` and `limit`, `CompactionRecord.recent_files` (omitted when empty; at most eight `{path, digest}` entries within 4 KiB<!-- unrelated-bound: compaction recent-file metadata --> serialized), the command `prefix_rule`, the prefix-wrapper `wrap` on Tool intents, the host-prefix policy snapshot, `ToolFinished.spill`, `rate_limits`, Command's `resource_class` and `timeout_ms`, and `ToolCall::GitBranch` `scope`, `base` and `max_count`. Non-default Command limits are immutable call data that replay checks against the recorded plan and Goal settings.

`ProviderCallRecorded` wire provenance is an optional closed enum; `chat_completions_stop_storage_unspecified` records acceptance of a Chat Completions `stop` or `tool_calls` finish and claims nothing about remote retention. Workspace command results require an explicit selection field ([command input selection](../tools/changesets-and-checkpoints.md#command-input-selection)).

`RunStarted.config.provider` is the strict record `{kind, custom_name}` with kinds `openai`, `anthropic`, `chatgpt` and `custom`. Native kinds require an explicit null name; custom requires the exact validated profile name without the `custom:` prefix. Anything else rejects; replay never resolves credentials.

Confirmed account, custom-route, role-routing and roster edits are journaled. `ProviderSetupEditStarted` pins a UUID operation ID, a closed target kind (`NativeAccount`, `ChatGptAccount`, `CustomProfile`, `ModelPreferences`, `RoleRouting` or `Roster`, whose identity is exactly `roster`), a bounded non-secret target identity and a required nullable expected digest. `ProviderSetupEditFinished` follows with the same operation ID, a required nullable resulting digest and `Applied`, `Failed`, `Cancelled` or `Uncertain`. Secret material and record bodies never enter these Events. Known registration, callback, browser and authorization failures settle `Failed`; explicit cancellation settles `Cancelled`. A setup edit runs only while the Session is idle (not during a live submission or between its autonomous Runs), after the Workspace validates and the Store has room for both Events, and the attached Session is materialized only after confirmation. Starting one marks crash-left Runs and Running Goals interrupted. An unfinished edit stays pending after recovery, and `Uncertain` blocks every later Session Event, including resume and fork. Replay never republishes an edit.

Provider-call, retry, fallback, between-Run and in-Run compaction payloads carry optional `rate_limits`; absence means unreported, with no backfill. The [Provider contract](../provider/routing-and-usage.md#passive-plan-limit-observations) owns its closed types and 4 KiB<!-- unrelated-bound: passive Provider rate-limit metadata --> bound; Store reserves an extra 4 KiB<!-- unrelated-bound: passive Provider rate-limit Event reservation --> per Event slot within the Event payload ceiling, and a sample that would exceed it is omitted. Retry and fallback facts describe the failed attempt. Replay never refetches.

Branch discovery's non-default `scope`, `base` and `max_count` are immutable intent data, and its observation keeps the [branch read result](../tools/git.md#branch-discovery) as bounded untrusted data. Range `git_log` and endpoint `git_diff` observations keep the requested endpoint names and the commit OIDs they resolved. Replay restores these facts and never resolves refs, opens config or invokes Git.

Active time is journaled per Run and per action-start ceiling ([Goals](../goals.md#lifecycle-budgets-and-recovery)). Lifecycle hook Events carry required nullable `active_ceiling_ms` and `boundary_active_ms`: `HookStarted` records the ceiling in a Run, and an idle `PreCompact` hook charges time between Runs of an open Goal, clamped to its ceiling. A crash-left lifecycle hook is interrupted like an open Tool hook and blocks Goal resume. `ToolFinished` requires the nullable [checkpoint outcome](../tools/changesets-and-checkpoints.md#checkpoints-and-rewind). Successful Write, Edit and MultiEdit output records required nullable `before` (digest, byte length, executable bit) and the resulting digest, byte length and executable bit, outside model-facing output. Missing required fields reject without conversion. The Run-scoped `GoalSteeringNoteRecorded` (payload version 6) is accepted only inside the open primary Provider reservation ([Goals](../goals.md#steering-notes-and-pause)). An unfinished child Tool is interrupted history and blocks [Goal recovery](../goals.md#worker-accounting-and-verification), like an unfinished primary effect. Each Provider call record journals `requested_tools` (one per declared model Tool request) and cache-read and cache-creation usage beside the input total.

Every selected role Provider, configured fallback and the complete bounded request are admitted before Workspace disclosure. A task objective is bounded by the [generated user-message limit](../limits.md#max_user_message_bytes), shared by every primary draft source; steering notes keep their [per-Run limit](../limits.md#max_steering_note_bytes). The Run pins Workspace, instructions and includes, policy, model, effort and caps. Accepted Message, Run and primary identity commit before inference; each call commits before its AgentRun finishes. A failed call commits failure without an assistant Message. Known call usage survives an interrupted journal.

`RunStarted` is `{config, active_deadline_ms}`. `config.providers`, when present, pins four non-empty chains of complete identities whose primary initial identity matches the primary config fields; without it, role defaults inherit the primary identity with no fallback, while roster-selected children keep their named chains. The Tool policy pins its nullable permissions digest, inactive legacy-rules digest, primary host restriction, denied child restriction and optional live host epoch; child grants deny host execution. Generic host intents carry the optional `EffectIntent.host_command` pin for executable path, identity and digest, Workspace, PATH and environment, and settings. `ToolStarted.verdict.host` records the epoch, session scope, optional earlier human intent reference and optional closed host-prefix record; `session_approval` is valid only for exact eligible reuse within that epoch. Replay refuses primary/child confusion, fabricated references, reuse across resume or fork, privilege tools and Guard receipts for host calls. Host session approvals never survive attach, restart or reconnect. Host dispatch invalidates prior Goal and worker success evidence and is marked possibly non-rewindable before spawn. The [host-command contract](../tools/host-commands.md#primary-host-commands) owns admission and supervision. Invalid provenance, inconsistent primary fields, missing or redundant role chains, unsupported limits and Tool-role chains mixing adapters or accounts reject replay.

Host-prefix verdicts add `host_prefix_rule` provenance. A human remember decision records its proposed `host.rule` as the user's action, not as proof that saving or spawning completed. `ToolPolicyReceipt.host_prefixes` snapshots the admitted current-Workspace host records at Run start; a snapshot too large for `RunStarted` refuses the Run. Rule reuse requires membership in that snapshot with no matching deny or ask record, a primary host intent, a pinned settings digest matching its command pin, default or dontAsk mode, no hook restriction, a matching allow record and no literal state-root target. Replay rejects forged scope, executable, environment, argv, mode or child provenance and never reads settings. Archiving an inactive rule never creates a grant ([Tools](../tools/host-commands.md#primary-host-commands)).

Typed `git_push`, `gh_pr_create`, `gh_pr_list` and `gh_pr_view` use the `host` execution class ([Tools](../tools/git.md#human-approved-host-git)), an explicit exception to Guard isolation separate from generic host commands. Optional `EffectIntent.host` pins write source data or the closed PR-list or PR-view adapter version. Host intents declare the `host` network class; every other Tool keeps `none`. The `Attestation::Host` receipt carries the intent digest, executable digest, PID, nullable exit code and confirmed group-teardown fact. A successful write requires exit zero, confirmed teardown and a primary human Ask verdict. Successful PR-list and PR-view reads accept a primary human Ask verdict or a matching user-owned typed prefix verdict with a pinned settings digest; rule-only, AI-only, child, Guard and unguarded substitutions reject. Confirmed typed-read failures are Failed; host execution without confirmed completion and cleanup is [Uncertain](./events-and-outcomes.md#effect-outcomes). Replay validates verdicts and receipts without reauthorizing; [rewind](../tools/git.md#human-approved-host-git) treats host effects as non-rewindable.

`AgentSpawned.profile` is required nullable provenance, null outside roster mode. In roster mode the primary references its default and every child an eligible profile. Replay rejects missing or forged references, role-ineligible spawns, cross-profile switches and reported output above the selected identity's role cap. Review and compaction use their fixed roles.

`config.roster` is explicit null outside roster mode. Otherwise it pins the preset name, a domain-separated SHA-256 selection digest, profile-name-sorted identity chains, four resolved role-default references and the ordered child allowlist. The digest covers normalized route Provider/model/effort/account tuples and membership, excluding expiring capability evidence and unrelated presets. Replay validates the record and its exact agreement with `config.providers`, including unused Tool-incompatible candidates, without contacting a Provider or account. An explicit same-Goal resume cannot omit or change its pinned selection. Historical profile alternatives confer no authority.

Over-bound selections reject whole, without truncation, filtering or eviction. Effective child-call concurrency is the minimum of every primary and eligible child-chain ceiling, and one for finite-token Goals. Tool-free wave planning uses the longest eligible child attempt deadline within the 20-minute delegation and remaining Goal active time; each attempt keeps its narrower deadline. Run-start and per-action Store headroom cover the snapshot and every possible switch. The [assignment contract](../provider/selection.md#named-roster-presets) owns the object wire and null resolution. Worker assignments do not select routes.

`ProviderFallbackUsed` is a Run/AgentRun-scoped fact with role, bounded call index, unavailable disposition and exact `from` and `to` identities, committed before the replacement call. Every extra attempt increments the Goal's call count and marks the failed call's token usage unknown; no assistant outcome, Tool proposal or usage is fabricated. Only the failed model call is replaced: prior Tool observations are carried once, and a review fallback dispatches the proposed effect at most once. A crash after the switch keeps the failed attempt charged; replay executes neither, and explicit resume starts each role at its first route.

`ProviderRetryScheduled` is a fixed-size Run/AgentRun-scoped fact: role, call index, attempt 1–3, closed cause (`transport`, `rate_limited`, `server_error` or `stream_cut`) and delay in milliseconds, at least the attempt's backoff and at most 20 minutes. Like a switch, it charges the failed attempt as one call with unknown usage and commits before the wait. A lost acknowledgement or cancellation during the wait dispatches nothing further.

Replay requires retries and switches to fit an open reservation, the attempt bound, the role and the call budget (never a finite-token budget, since usage is unknown) and, for the primary, a call with no displayed text. Switch identities must be adjacent in the pinned chain. Journaled retry delays must sum to at most the active time the reservation admitted, or 20 minutes for between-Run compaction outside a running Goal; between-Run compaction never changes a closed Goal's receipt or usage. A crash after either fact charges the open reservation's ceiling. Switches stay within 64 facts per Run, appear in inspection and the Goal report, and never dispatch a Tool.

The Engine records bounded safe prefixes of streamed text in `AssistantDisplayRecorded`, outside accepted outcomes, model context and compaction; cancelled or interrupted replay recovers only acknowledged text. Outcome validation still controls `MessageCommitted`, and an incompatible provisional prefix fails validation and replay. A Run's Events end at `RunFinished`; Goal settlement follows as its own Events. Observers see only committed Events and cannot authorize, steer or cancel a Run. The [terminal contract](../terminal/conversation.md#terminal-continuity-and-provisional-text) owns presentation and bounds.

Before Workspace input and before each Provider or Tool dispatch, the Store must have room for the next bounded action and the facts that close it and the Run; racing children cannot share one final slot. Capacity waits and approval charge no Goal time or calls. Byte preflight does not reserve physical disk. Exhaustion rejects before disclosure or usage and directs the user to a new Session. An editor continuation refused for Store capacity settles known effects and releases its lease; the Run records `tool_stopped` without exhausting the Goal.

A write that finds the history changed by another process after it took the write lock refuses with `HistoryChanged`; every appended transition is validated. The journal is not tamper evidence: corruption can stay undetected until the next full validation.

Fork admission validates the resulting lineage's depth and Event count atomically; failure leaves no partial target, and [Session](../session.md#lifecycle-and-identity) owns lineage replay.

Compaction has no lifetime attempt count: each attempt must fit the Goal budget, Store and Event headroom, and request and context bounds before inference. Compaction removes no canonical Event and restores no permission. The serialized compaction input is bounded by [the generated compaction-input limit](../limits.md#max_compaction_input_bytes), derived from [the Provider request limit](../limits.md#max_provider_request_bytes), [the request envelope limit](../limits.md#compaction_request_envelope_bytes) and [the expansion factor](../limits.md#compaction_input_expansion); an escape-heavy Session over it fails closed with `CompactionInputTooLarge` before any Provider call. The automatic threshold is [the generated history threshold](../limits.md#auto_compaction_history_bytes): the input bound less two turns of the 8 KiB<!-- unrelated-bound: attached draft compaction reserve --> attached draft (each with its draft, steering context, a 32 KiB<!-- unrelated-bound: assistant message cap --> answer and image metadata). A text-paste chip or `exec` objective at the [generated user-message limit](../limits.md#max_user_message_bytes) can exceed that reserve and fail the same way; a prose Goal objective at that limit still compacts.

`ToolResultsCleared {run_id, covered_tool_count, cleared_bytes}` records the [Session clearing policy](../session.md#context-and-compaction) before the next primary Provider call. The count indexes the Run's primary Tool observations, including initialization and Engine integrations; initialization is never cleared. Clearing needs settled primary hooks and observations and no open primary call; background worker observations are outside it. The boundary must advance beyond both the cleared and summarized prefixes, end on a complete step and leave at least three recent results. `cleared_bytes` is the difference between the covered results' original and placeholder projections, including removed hook feedback; replay recomputes it and rejects forged values. Cleared bodies stay cleared after interruption, resume or fork.

For each in-Goal compaction and later primary request, bounded context reintroduces the pinned objective, project instructions and includes, approved plan or contract and current typed Goal facts: dispatched calls, known tokens and the unknown-usage flag, settled, reserved and uncertain active time, and the optional success-criterion state, without historical Tool bodies. Historical output never becomes instructions, and provisional display text is never used. Compaction covers only a committed prefix of active-Run Tool observations, proven by Run identity, covered Tool count, ending sequence and digest, then stores a bounded untrusted summary that grants no authority. Provider context uses the latest summary and a bounded recent tail with the clearing projection. Replay checks the prefix and summary digest without a Provider call. A failed attempt keeps the prior summary; another needs a later prefix and its own Goal call, time and Event budget. Compaction provides no per-phase or worker-specific context capsules.

Context respects the [compiled-content ceiling](../session.md#context-and-compaction), the remaining-byte Tool-history allowance, Tool argument and result limits and the encoded-request ceiling, which is [the generated Provider request limit](../limits.md#max_provider_request_bytes) without trusted route window metadata. A pinned route window sets that route's Run-request ceiling to content plus 256 KiB, at most 1.25 MiB, raising or lowering it; compaction requests keep the generated limit. A larger request is refused before egress; a remote context-length rejection fails the call. Model cards and display IDs do not prove a saved ChatGPT route's window; without exact route metadata the conservative byte bounds apply. `MAX_REPORTED_INPUT_TOKENS` validates reported usage only and is not a window estimate.

Cancellation before Message acceptance creates no Run. After admission it drains in-flight work and commits cancellation without a final answer, keeping prior facts; a terminal commitment already started wins the race. Store failure leaves an interrupted prefix, never manufactured success or cancellation. Cancellation is sticky; abandoning a caller does not undo started work.

A Run or compaction locks its Session and every fork ancestor; independent lineages run concurrently. A CLI process opens one Engine, which holds the shared history lock until exit, so another process's history reset reports history in use while an attached terminal is open, even idle. The Engine runs one operation at a time: a submission or compaction while another is open is refused with `Busy` before any admission or call. Each submission brings its own [per-role Provider chains](../provider/selection.md#per-role-selection-and-fallback) and controls (Tool grant, approvals, steering, cancellation, display hints), fixed for every Run of its Goal loop, and follows the committed Event stream from submission on; invalid chains are refused at submission. Each attached submission and compaction re-admits the State path and fails closed when it became unavailable or unsafe or names a different directory.

The [Supervisor adapter](../tools/hooks.md#supervisor-adapter) owns decision ordering, replay and recovery. `SupervisorVerdictRecorded` shares its subject's Run and actor and changes no authority or transition legality. A Run pinned with a Supervisor reserves Store room for every possible verdict, each at the [generated verdict payload bound](../limits.md#max_verdict_bytes); `supervisor: null` reserves none.

`AgentSteeringNoteRecorded` is an actor-scoped fact with strict `{goal_id,text}` payload and Run/AgentRun IDs in its envelope, within the [shared steering quota](../goals.md#steering-notes-and-pause); replay rebuilds historical guidance without delivering it.
