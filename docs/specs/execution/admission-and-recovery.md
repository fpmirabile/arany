# Execution: admission and recovery

## Admission, persistence and recovery

A `serve --stdio` process opens one Engine shared by its loaded threads; the [serve contract](../serve.md) owns its client loop.

Persist only SQLite schema 15 and compaction compiler version 3. The schema is the one journal format version: every Event kind has exactly one current payload shape, and any payload change, additive or not, advances the schema once, which archives existing history ([incompatible history](./persistence.md#incompatible-history)). Rows carry no per-kind version. Roster metadata and the agent-definition pin are required nullable `RunStarted` fields; role provenance is kept and cross-validated with the bounded snapshot. `AgentSpawned` requires the nullable selected definition, resolved profile reference and assignment pins. There is no dual reader or replay-time configuration lookup; history at any other version never reaches runtime decoders. Event decoding validates current fields strictly, and serialization preserves exact field order, flattening, nullable values and stored bytes. Per-kind payload byte bounds stay with the [persistence bounds](./persistence.md#persistence-bounds).

| Event kind | Current payload notes |
|---|---|
| `RunStarted` | `config` pins the model `context_window_tokens` and the resolved [`effective_context_window_tokens`](../session.md#context-and-compaction) (both null or both set), `user_instruction_digest` (raw SHA-256 of the State `AGENTS.md`, or explicit null), ordered `instruction_sources` (`{directory, file, digest}`, root first; `file` is required and nullable), `prompts` (`{file, source, digest}` for `primary`, `team`, `researcher`, `editor` and `compaction` in that order; `source` is `default` or `override` and `digest` the raw SHA-256 of the rendered [working-style text](../session.md#prompt-overrides)) and the Workspace-relative `launch_directory`; custom provenance pins the admitted endpoint and declaration digest |
| `ToolStarted` | Required nullable `verdict`, with the configured or host permission verdict before dispatch |
| `ProviderCallRecorded` | Required nullable `context_bytes` is the Engine's count of a primary planning or synthesis request's content bytes (pinned compiled content plus Tool context) and [calibrates the context ceiling](../session.md#context-and-compaction); the closed failure reasons include `rate_limited` and `outcome_decode`; editor refusal causes follow [Accepted outcomes](./events-and-outcomes.md#accepted-outcomes) |
| `CommandToolProbeStarted`, `CommandToolProbeFinished` | Idle, intent-bound Guard probe and outcome; [Command tools](../tools/hooks.md#hook-execution) owns confirmation and interruption |
| `MessageAccepted` | Required nullable `skill` names the invoked Skill, null for an ordinary turn |
| `GoalFinished` | Required nullable `budget_refusal` follows the [Goal refusal contract](../goals.md#budget-refusal-feedback) |
| `ContextCompacted`, `GoalContextCompacted` | The record pins the compaction `prompt` (`{file, source, digest}`, `file` always `compaction`) |
| `WorkspaceRewindStarted` | No preview expiry |

Fields omitted at their default keep existing bytes and digests within one schema; the current encoder omits them, and the strict decoder replays an omission as the default. They include Goal resource settings and `ToolLimits.build_jobs` (a missing value replays as **1**, never as current cores; new Goal admission records resolved jobs, with null meaning Build unavailable, and replay reads neither cores nor preferences), Search's `regex`, `include`, `case_sensitive`, `offset` and `limit`, `CompactionRecord.recent_files` (omitted when empty; at most eight `{path, digest}` entries within 4 KiB<!-- unrelated-bound: compaction recent-file metadata --> serialized), the command `prefix_rule`, the prefix-wrapper `wrap` on Tool intents, the host-prefix policy snapshot, `ToolFinished.spill`, `rate_limits` and `ToolCall::GitBranch` `scope`, `base` and `max_count`. Adding such a field still advances the schema.

Command's `resource_class` and `timeout_ms` are omitted when absent or null. Non-default requests are immutable call data; replay resolves them against the recorded plan and Goal-pinned settings and rejects mismatched intent limits or RequestedTime receipts without execution.

`ProviderCallRecorded` wire provenance is an optional closed enum; `chat_completions_stop_storage_unspecified` records acceptance of a Chat Completions `stop` or `tool_calls` finish with the local non-streaming request and claims nothing about remote retention. Current Workspace command results require an explicit selection field ([command input selection](../tools/changesets-and-checkpoints.md#command-input-selection)).

`RunStarted.config.provider` is the strict record `{kind, custom_name}` with kinds `openai`, `anthropic`, `chatgpt` and `custom`. Native kinds require an explicit null name; custom requires the exact validated profile name without the `custom:` prefix. Unknown kinds, missing fields, invalid names and inconsistent pairs reject; replay never reads legacy strings or resolves credentials. A strict record instead of a string keeps persisted Run identity closed and explicit.

Confirmed account, custom-route, role-routing and roster edits admit both Event slots and their Store storage before appending `ProviderSetupEditStarted`; insufficient capacity refuses before intent or publication. Started pins a UUID operation ID, a closed target kind (`NativeAccount`, `ChatGptAccount`, `CustomProfile`, `ModelPreferences`, `RoleRouting` or `Roster`, whose identity is exactly `roster`), a bounded non-secret target identity and a nullable expected digest. `ProviderSetupEditFinished` follows the effect with the same operation ID, nullable resulting digest and `Applied`, `Failed`, `Cancelled` or `Uncertain`. Both digest fields are required, with explicit null when absent. Secret material and record bodies never enter these Events. Setup materializes the attached Session only after confirmation. Known registration, callback, browser and authorization failures settle `Failed`; explicit cancellation settles `Cancelled`. Setup admission holds the Session lock, refuses during a live submission including the gaps between its autonomous Runs, and validates the Workspace before Started. The submission keeps the lock until its loop returns or its future drops; standalone compaction keeps its own lock. Started seals crash-left Runs and Running Goals as interrupted, keeping unknown outcomes and resumability checks. The reducer admits one edit only while idle after that recovery and accepts only its matching Finished next; an open Started stays pending after recovery, and `Uncertain` blocks every later Session Event, including resume and fork. Strict replay never republishes an edit.

Provider-call, retry, fallback, between-Run and in-Run compaction payloads carry optional `rate_limits`; absence means unreported, with no backfill. The [Provider contract](../provider/routing-and-usage.md#passive-plan-limit-observations) owns its closed types and 4 KiB<!-- unrelated-bound: passive Provider rate-limit metadata --> bound. Store admission reserves an extra 4 KiB<!-- unrelated-bound: passive Provider rate-limit Event reservation --> per Event slot before dispatch, within the unchanged Event payload ceiling. A sample that would exceed the Provider-call payload ceiling is omitted before append. Every role and both compaction loops settle the observation in their existing fact, including failure and cancellation. Retry and fallback facts describe the failed source attempt, commit before the wait or replacement dispatch, and consume that attempt's slot so a cancelled wait cannot duplicate it. Append failure stops continuation; a crash before commit leaves no sample. Replay reads no clock and never refetches.

Branch discovery's non-default `scope`, `base` and `max_count` are immutable intent data; model-facing calls still include every nullable schema field. The observation carries the captured ref OIDs, resolved comparison base and OID, upstream status, disclosure markers, counts, capped-count and name flags, history completeness and deadline or truncation markers ([branch read contract](../tools/git.md#branch-discovery)), as bounded untrusted data. Range `git_log` and endpoint `git_diff` observations keep the requested endpoint names and the commit OIDs resolved before dependent reads. Replay restores these facts and never resolves refs, opens config or invokes Git.

Active time is journaled per Run and per action-start ceiling ([Goals](../goals.md#lifecycle-budgets-and-recovery)). Lifecycle hook Events carry required nullable `active_ceiling_ms` and `boundary_active_ms`: `HookStarted` records the ceiling in a Run, and an idle `PreCompact` hook reserves and settles time between Runs of an open Goal, clamped to its ceiling. A crash-left lifecycle hook is interrupted by the next Run like an open Tool hook and blocks Goal resume. `ToolFinished` requires the nullable [checkpoint outcome](../tools/changesets-and-checkpoints.md#checkpoints-and-rewind). Successful Write, Edit and MultiEdit output records required nullable `before` (digest, byte length, executable bit) and the resulting digest, byte length and executable bit, outside model-facing output. Required and nullable fields are explicit, including Goal linkage and budgets, Run configuration and active deadline, Provider provenance, pinned Tool resource values and the Tool cache-update outcome; unsupported formats or missing fields reject without conversion, deletion or optimistic projection. Replay rejects an accepted task without valid Goal linkage. The Run-scoped `GoalSteeringNoteRecorded` (payload version 6) is accepted only inside the open primary Provider reservation ([Goals](../goals.md#steering-notes-and-pause)). An unfinished child Tool is interrupted history and blocks [Goal recovery](../goals.md#worker-accounting-and-verification), like an unfinished primary effect. Each Provider call record journals `requested_tools` (one per declared model Tool request) and cache-read and cache-creation usage beside the input total.

Before opening the Engine, attached chat, `exec`, `serve` and `acp` validate the whole journal under the shared history lock; unsupported history is [archived](./persistence.md#incompatible-history).

Every selected role Provider, configured fallback and the complete bounded request are admitted before Workspace disclosure. A task objective is bounded by the [generated user-message limit](../limits.md#max_user_message_bytes); primary typed, startup, restored and framed or clipboard drafts share that cap, while steering notes keep their [per-Run limit](../limits.md#max_steering_note_bytes). The Run pins Workspace, instructions and includes, policy, model, effort and caps. The `RunStarted` timestamp precedes its append acknowledgement, and `AgentSpawned` follows it. Accepted Message, Run and primary identity commit before inference; each observed call commits before its terminal AgentRun disposition. A failed call commits failure without an assistant Message. Replay requires an observed delegation before child spawn and an observed successful call before successful Agent completion. Known call usage survives an interrupted journal prefix.

`RunStarted` is `{config, active_deadline_ms}`. `config.providers`, when present, pins four non-empty chains of complete identities; its primary initial identity must agree with the primary config fields, and effective concurrency may narrow the declared ceiling. Without it, the fixed role defaults inherit the pinned primary identity with no default fallback; roster-selected children still use their named chains. The Tool policy pins its nullable permissions digest, inactive legacy-rules digest, primary host restriction, denied child restriction and optional live host epoch; child grants deny host execution. Generic host intents use the optional `EffectIntent.host_command` pin for executable path, identity and digest, Workspace, PATH and environment, and settings. `ToolStarted.verdict.host` records the epoch, session scope, optional earlier human intent reference and optional closed host-prefix record; `session_approval` is valid only for exact eligible reuse within that epoch. Replay refuses primary/child confusion, fabricated references, reuse across resume or fork, privilege tools and Guard receipts for host calls. Epoch freshness across attach, restart and reconnect and live terminal mode restrictions are Engine-enforced; there is no binding Event or terminal-mode history. Host dispatch invalidates prior Goal and worker success evidence and marks possible non-rewindable effects before spawn. The [host-command contract](../tools/host-commands.md#primary-host-commands) owns admission and supervision. Invalid provenance, inconsistent primary fields, missing role chains, redundant all-inherited chains, unsupported limits and incompatible Tool-role adapter or account chains reject replay.

Host-prefix verdicts add `host_prefix_rule` provenance. A human remember decision carries its proposed `host.rule` before the atomic settings save; it records the user action, not that saving or spawning completed. `ToolPolicyReceipt.host_prefixes` snapshots the admitted current-Workspace host records at Run start. Rule reuse requires membership in that snapshot with no matching deny or ask record, a primary host intent, a non-null pinned settings digest agreeing with its command pin, default or dontAsk mode, no hook restriction, no session or reference substitution, a matching allow record and no literal state-root target. Replay rejects forged scope, executable, environment, argv, mode or child provenance and never reads settings. A snapshot exceeding the `RunStarted` payload ceiling refuses Run admission. Inactive exact-rule archival keeps private source bytes and never creates a grant ([Tools](../tools/host-commands.md#primary-host-commands)).

Typed `git_push`, `gh_pr_create`, `gh_pr_list` and `gh_pr_view` use the `host` execution class ([Tools](../tools/git.md#human-approved-host-git)), a second explicit exception to Guard isolation separate from generic host commands. Optional `EffectIntent.host` pins write source data or the closed PR-list or PR-view adapter version. Host intents declare the `host` network class; every other Tool keeps `none`. The `Attestation::Host` receipt carries the intent digest, executable digest, PID, nullable exit code and confirmed group-teardown fact. A successful write requires exit zero, confirmed teardown and a committed primary human Ask verdict. Successful PR-list and PR-view reads accept a committed primary human Ask verdict or a matching user-owned typed prefix verdict with a pinned settings digest; rule-only, AI-only, child, Guard and unguarded substitutions reject. Confirmed typed-read failures are Failed; host execution without confirmed completion and cleanup is [Uncertain](./events-and-outcomes.md#effect-outcomes). Replay validates committed verdicts and receipts without reauthorizing. Host effects with a receipt, an Uncertain result or a committed approval without an outcome are non-rewindable.

`AgentSpawned.profile` is required nullable provenance, kept in the reduced Agent view and null outside roster mode. In roster mode the primary references its default and every child an eligible profile, with null proposals already resolved. Replay rejects missing or forged references, role-ineligible spawns, a reservation before spawn, cross-profile switches and reported output above the selected identity's role cap. Calls, fallback, telemetry and replay derive the chain from actor and role; review and compaction use their fixed roles. No identity copy or replay-time lookup can rebind an actor.

`config.roster` is explicit null outside roster mode. Otherwise it pins the preset name, a domain-separated SHA-256 selection digest, profile-name-sorted identity chains, four resolved role-default references and the ordered child allowlist. The digest covers normalized route Provider/model/effort/account tuples and membership, excluding expiring capability evidence and unrelated presets. Replay validates names, counts, bounds, digest, references, reachability, duplicate or noncanonical entries, identity validity and exact agreement with `config.providers`, including unused Tool-incompatible candidates, without contacting a Provider or account. An explicit same-Goal resume cannot omit or change its pinned selection. Historical profile alternatives confer no authority.

Over-bound selections reject whole, without truncation, filtering or eviction. Effective child-call concurrency is the minimum of every primary and eligible child-chain ceiling, and one for finite-token Goals. Tool-free wave planning uses the maximum eligible child attempt deadline within the 20-minute delegation and remaining Goal active time; each attempt keeps its narrower deadline. [Researcher-child](./collaboration.md#researcher-children), switch, lineage and [persistence](./persistence.md#persistence-bounds) bounds are unchanged, and Run-start and per-action Store headroom cover the snapshot. The [assignment contract](../provider/selection.md#named-roster-presets) owns the object wire and null resolution. Event headroom includes switches from the longest eligible child chain. Worker assignments do not select routes.

`ProviderFallbackUsed` is a Run/AgentRun-scoped fact with role, bounded call index, unavailable disposition and exact `from` and `to` identities. It atomically settles the failed pre-output attempt and reserves the next call before egress, under the same action ceiling; the original reservation stays open for the final step record. Every extra attempt increments the Goal's call count and marks the failed call's token usage unknown; no assistant outcome, Tool proposal or usage count is fabricated. Only the failed model call is replaced: prior Tool observations are carried once, and a review fallback dispatches the proposed effect at most once. The coordinator alone writes the journal and Goal ledger; child tasks hold only a Provider, request, cancellation and deadline and return an eligible-failure marker, and the coordinator checks compatibility and budget, commits the switch and respawns the attempt. A crash after the switch keeps the failed attempt and charges the open replacement ceiling; replay executes neither, and explicit resume starts each role at its first route.

`ProviderRetryScheduled` is a fixed-size Run/AgentRun-scoped fact: role, call index (compaction numbers its calls as a switch does), attempt 1–3, closed cause (`transport`, `rate_limited`, `server_error` or `stream_cut`) and delay in milliseconds, at least the attempt's backoff and at most 20 minutes. Like a switch, it settles the failed attempt as one charged call with unknown usage and keeps the reservation open; it commits under fresh call-budget and Store admission before the wait and re-dispatch. A lost acknowledgement or cancellation during the wait dispatches nothing further.

Replay of retries and switches requires the actor, role and call index to fit an open reservation, consecutive attempts within the bound, an actor fitting the role, sufficient call budget, no finite-token budget that unknown usage would violate and, for the primary, no display chunk of the call. Switch identities must be adjacent in the pinned chain, and the eventual call phase and reported output must fit the switched role. Journaled retry delays must sum to at most the active time the reservation admitted, or 20 minutes when uncharged; only between-Run compaction outside a running Goal is uncharged. Compaction records name the pinned or switched compaction route; between-Run compaction uses its boundary index and never changes a closed Goal's receipt or usage. A crash after either fact keeps the reservation open and charges its ceiling. Switches stay within 64 facts per Run, survive closed-store replay, inspection and the Goal report, and never dispatch a Tool. Action Event headroom covers every possible switch and three retry facts per call.

Attached visual streaming has separate primary and call-scoped display observations. The Engine checkpoints bounded safe prefixes in `AssistantDisplayRecorded`, outside accepted outcomes, model context and compaction. Cancelled or interrupted replay recovers only acknowledged text. Outcome validation still controls `MessageCommitted`, and an incompatible provisional prefix fails validation and replay. A Run's Events end at `RunFinished`; Session-scoped Goal settlement follows as its own Events. Observers see only acknowledged Events and cannot authorize, steer or cancel a Run. The [terminal contract](../terminal/conversation.md#terminal-continuity-and-provisional-text) owns presentation and bounds.

Before Workspace input, inference or Tool preparation, Store requires logical Event capacity for the Goal lifecycle and next bounded action, plus conservative byte headroom, including the terminal facts that close that action and Run. Before each Provider or Tool dispatch, Store atomically admits the reservation and the headroom for its observation and terminal tail; the serialized reducer rejects a racing reservation that no longer fits, so racing children cannot consume one final slot. Capacity waits and approval charge no active Goal time or calls; queued children are charged only once concurrency admits them. The Session and fork ancestors stay locked for the Run; independent lineages run concurrently. Byte preflight does not reserve physical disk. Capacity exhaustion rejects before disclosure or usage and directs the user to a new Session. An editor continuation refused for Store capacity records the stop, settles known effects and releases its lease before returning the Store error; the Run records `tool_stopped` without exhausting the Goal.

Write admission, including fork preparation, trusts the bounded hot Session cache while SQLite's data version and the global Event sequence match. Cold or invalidated writes validate the whole history before their transaction, rejecting unrelated malformed Events; a version change after the write lock refuses with `HistoryChanged`. Every appended transition still passes reducer validation. Corruption outside an unchanged cached view can stay undetected until invalidation; the journal is not tamper evidence.

Fork admission validates the resulting lineage's depth and Event count atomically; failure leaves no partial target. Replay resolves at most eight lineage links within the [Session Event cap](./persistence.md#persistence-bounds) and verifies inherited prefix digests. Compaction has no lifetime attempt count: each attempt must fit the Goal budget, per-action Store and Event headroom, and request and context bounds before inference or an attempt Event. Failure keeps the last good summary and canonical history; compaction removes no canonical Event and restores no permission. The serialized compaction input is bounded by [the generated compaction-input limit](../limits.md#max_compaction_input_bytes), derived from [the Provider request limit](../limits.md#max_provider_request_bytes), [the request envelope limit](../limits.md#compaction_request_envelope_bytes) and [the expansion factor](../limits.md#compaction_input_expansion), because adapters embed the input as an escaped JSON string; an escape-heavy Session over it fails closed with `CompactionInputTooLarge` before any Provider call. The automatic threshold is [the generated history threshold](../limits.md#auto_compaction_history_bytes): the input bound less two turns of the 8 KiB<!-- unrelated-bound: attached draft compaction reserve --> attached draft (each reserving its draft, steering context, a 32 KiB<!-- unrelated-bound: assistant message cap --> answer, separators and image metadata). A text-paste chip or `exec` objective at the [generated user-message limit](../limits.md#max_user_message_bytes) can exceed that reserve and fail closed with `CompactionInputTooLarge`. A prose Goal objective at that limit, carried in the pinned Goal context and again in a compacted first turn, still compacts; an escape-heavy one fails closed.

`ToolResultsCleared {run_id, covered_tool_count, cleared_bytes}` commits the [Session clearing policy](../session.md#context-and-compaction) before the next primary Provider reservation. The count indexes the Run's primary Tool observations, including initialization and Engine integrations; initialization is never cleared. Replay requires an active Run, primary AgentRun and Goal, settled hooks and primary observations, no open primary Provider or compaction reservation and no pending primary Tool requests; background worker calls may stay active and their observations are outside the projection. Worker preparation records keep their indices but add no visible result or savings. The boundary must advance beyond both the cleared and summarized prefixes, end on a complete step and leave at least three recent results. `cleared_bytes` is the difference between the covered results' original and placeholder projections, including removed hook feedback; replay recomputes it and rejects forged counts, totals, scopes and versions. Rendering derives cleared bodies only from the committed boundary, including after interruption, resume or fork.

For each in-Goal compaction and later primary request, bounded context reintroduces the pinned objective, project instructions and includes, approved plan or contract and current typed Goal facts: dispatched calls, known tokens and the unknown-usage flag, settled, reserved and uncertain active time, and the optional success-criterion state, without historical Tool bodies. It never promotes historical output to instructions or uses provisional display text. Compaction checkpoints only an acknowledged prefix of active-Run Tool observations, proven by Run identity, covered Tool count, ending sequence and digest, then stores a bounded untrusted summary. Observations stay canonical Events; Provider context uses the latest summary and a bounded recent tail with the clearing projection. Replay checks the prefix and summary digest without a Provider call. A failed attempt keeps the prior summary; another attempt needs a later acknowledged prefix and its own Goal call, time and Event budget. The summary grants no authority. Compaction does not provide per-phase or worker-specific context capsules. Context respects the [compiled-content ceiling](../session.md#context-and-compaction), the remaining-byte Tool-history allowance, Tool argument and result limits and the encoded-request ceiling, which is [the generated Provider request limit](../limits.md#max_provider_request_bytes) without trusted route window metadata. A pinned route window sets that adapter's Run-request ceiling to content plus 256 KiB, at most 1.25 MiB, raising or lowering it; compaction requests keep the generated limit. A larger request is refused before egress; a remote context-length rejection fails the call. Public model cards and display IDs do not prove a saved ChatGPT route's window; without exact route metadata the conservative byte bounds apply. `MAX_REPORTED_INPUT_TOKENS` validates reported usage only and is not a window estimate.

Cancellation before Message acceptance creates no Run. After admission it drains in-flight work and commits cancellation without a final answer, keeping prior facts. A terminal commitment already started wins its race with cancellation. Store failure leaves an interrupted prefix, never manufactured success or cancellation.

Run and compaction hold the Session lock and every fork ancestor's operation lock, because strict replay counts ancestor suffixes outside the inherited boundary. Cancellation is a sticky caller signal whose waiter interrupts pre-Engine admission; dropping a waiter does not undo started work.

A CLI process opens one Engine: the attached terminal after its Session starts, `exec` after Provider selection. The Engine's Store thread and shared history lock live until exit, so another process's history reset reports history in use while an attached terminal is open, even idle; Session, lineage and Workspace locks stay per Run. A normal exit closes the Engine and reports a failed close; an error exit drops it, which still stops the Store thread. The Engine runs one operation at a time: a submission or compaction while another is open is refused with `Busy` before any admission or call, and a dropped or finished handle frees it. Each submission brings its own [per-role Provider chains](../provider/selection.md#per-role-selection-and-fallback) and controls (Tool grant, approvals, steering, cancellation, display hints), fixed for every Run of its Goal loop, and its handle follows the committed Event stream from submission on. Invalid chains are refused at submission; a compaction brings the chains whose compaction route it calls. Each attached submission and compaction re-admits the State path and fails closed when it became unavailable or unsafe or names a different directory; a Tool grant loads its configuration at submission.

The [Supervisor adapter](../tools/hooks.md#supervisor-adapter) owns decision ordering, replay acceptance and interrupted-prefix recovery. `SupervisorVerdictRecorded` occupies its subject's next sequence with the same Run and actor, is transparent to hook adjacency and Tool correlation, and changes no authority or transition legality. A Run pinned with a Supervisor adds verdict slots to each action's bound, at least the [generated verdict payload bound](../limits.md#max_verdict_bytes) per possible evaluation boundary: one per Provider call, `in-flight + 1` per child step, two per Tool step (a narrowing replacement is a second outcome), 12 per worker action and one per delegated child or child Tool call. `supervisor: null` reserves none.

`AgentSteeringNoteRecorded` is an actor-scoped fact with strict `{goal_id,text}` payload and Run/AgentRun IDs in its envelope. The reducer enforces the [shared steering quota and ChildWork reservation](../goals.md#steering-notes-and-pause); replay rebuilds historical guidance without delivering it.
