# Execution: incompatible state and persistence bounds

### Incompatible history

Pre-beta, stored formats are never migrated. Only the current journal schema runs; runtime decoders and the reducer never read another format, and nothing rewrites stored history. Peers keep no per-record versions either: one store version is enough because any mismatch archives the whole journal.

Eligibility is read through a read-only connection, so unsupported history reaches the archive with its database and WAL bytes untouched. History is archived when its schema differs from the current one (older or newer), it holds an unknown or removed Event kind or variant, or any row is replay-invalid. Under the exclusive history and checkpoint locks, `events.sqlite3` and `checkpoints.sqlite` with their `-journal`, `-wal` and `-shm` sidecars are renamed intact into a private `archive/history-<UTC timestamp>/` directory, and a fresh journal opens. A durable `archive/pending.json` first records each file's identity (device, inode, size) or absence, and every rename is fsynced on both sides; a crash resumes the plan, moving only files whose identity matches and never newer files, and any mismatch leaves everything in place with a typed archive conflict. The plan stays until the notice is delivered, then becomes the archive's `manifest.json`. Accounts, settings, folder trust and other StateRoot records stay; nothing is deleted. Attached chat names the archive in its [startup notice](../terminal/setup-and-accounts.md#setup-and-account-choices); headless commands print one `warning: …; started a new history` line on stderr. Damaged SQLite, a busy store, full storage and unsafe or inaccessible files are never archived: attached chat keeps its typed recovery choice with an explicit reset for damaged history, and headless commands exit 1 with a typed `error: …` that, for damaged history, says to run `arany` to reset it.

The same gate covers `checkpoints.sqlite`: a readable checkpoint store at another schema version archives the whole history with it, while a damaged, busy or extra-object store is never archived ([checkpoint store contract](../tools/changesets-and-checkpoints.md#checkpoints-and-rewind)).

### Incompatible records

Private StateRoot JSON records carry no version or schema number; SQLite stores keep their `user_version` above. Each record is one of two classes:

- **Tolerant** preference and cache records, `ui-preferences.json` and `model-preferences.json`: the owner reads known fields, ignores unknown ones, defaults missing ones and drops an entry or value that fails validation; an unreadable record reads as defaults. They are never archived and never refuse startup or a Run; a rewrite may drop fields this binary does not know.
- **Strict** authority records, everything else (`tools.json`, `permissions.json`, `workspace-permissions.json`, `unguarded-commands.json`, `command-environment.json`, `command-tools.json`, `mcp-oauth.json`, `provider-profiles.json`, `provider-roster.json`, `provider-routing.json`, `account-credentials.json`, `chatgpt-accounts.json`, `chatgpt-registration.json`): each kind declares its owner's decoder, which rejects unknown fields, missing required fields, wrong types and failed validation. Peers keep no per-record versions either; a closed decoder is what detects another format.

Before any record owner reads, attached chat, `exec`, `serve` and `acp` run every strict record in the selected State directory and the account root through its decoder. A record the decoder refuses, from an older or newer binary or damaged, is renamed intact, under the account-replacement lock, into one private `archive/records-<UTC timestamp>/` directory (with a `-N` suffix when an interrupted attempt left that name) with fsyncs on both sides; its owner then sees no record and fails closed: the folder asks for trust again, accounts sign in again, rules and routes are re-created. Attached chat adds the archived file names and folder to its startup notice; headless commands print one `warning: …` line on stderr. Unsafe, oversized or unreadable files are never archived or altered: their owner reports them. OS keyring entries are never moved, so a refused keyring entry is refused by its owner, and the ChatGPT and native-account setup resets still cover keyring entries and records that disagree with each other. A crash leaves each record either in place or in the archive, never both; the next start archives what remains.

A change of meaning renames the field. Tolerant records only add optional fields with defaults; any change to a strict record's shape makes an older or newer binary archive it. Guard [capacity](../tools/native-guard.md#shared-native-capacity-and-settings) and unit-recovery records are strict and unversioned too, but shared live between processes, so they are never archived: a shape this binary refuses fails closed as protection unavailable.

### Workspace rewind Events

`WorkspaceRewindStarted` and `WorkspaceRewindFinished` are Session-scoped facts, each at most the [generated Event payload limit](../limits.md#max_event_bytes) including JSON escaping; larger payloads reject before decoding. Started records a UUIDv7 rewind ID, a Run or rewind checkpoint with its sequence, the head sequence and canonical prefix digest, the effective-plan SHA-256, file count and restored bytes, sorted disjoint kept and overwrite selections, Workspace identity and Tool policy and enforcement digests. Overwrite selections carry the observed digest, byte length and executable bit, or explicit null for absence. Kept and overwritten paths together are capped at 64, each at most 512 bytes<!-- unrelated-bound: rewind selection path bytes -->. Neither selections nor stored bytes grant permission.

Finished records its rewind ID, a closed `restored`, `conflict`, `denied`, `failed`, `cancelled` or `uncertain` outcome, required nullable attestation and checkpoint, and sorted conflict paths (the first 32 plus the exact total, at most 2,048). Restored requires an attestation with plan, Workspace, enforcement and nonzero execution receipt digests; in-process publication binds the intent and its in-process attestation, and historical Guard receipt digests keep their encoding. An attested Uncertain outcome uses the same binding. Exactly those attested outcomes carry checkpoint capture status for overwritten content: captured or skipped if any before state exists, otherwise not_needed. Known refusal or cancellation before publication carries neither capture nor receipt. An unconfirmed outcome without a receipt stays [Uncertain](./events-and-outcomes.md#effect-outcomes) and does not assert whether publication began. Finished immediately follows its own Started. The [Session contract](../session.md#rewind-planning-and-replay) owns planning, sealing and history projection; [Goals](../goals.md#rewind-and-goal-recovery) owns recovery and evidence invalidation.

| Workspace writer lock files | [generated writer-lock quota](../limits.md#max_workspace_lock_files), shared across StateRoots and owned by [Goals](../goals.md#lifecycle-budgets-and-recovery) | new writers refused before disclosure or effects |
| Direct-Session projection cache | [generated hot Session cache bound](../limits.md#max_hot_session_payload_bytes) of serialized Event payload | not kept; the next append replays strictly |
| Supervisor verdicts | [generated verdict size](../limits.md#max_verdict_bytes); at most [the generated per-Run verdict count](../limits.md#max_verdicts); the verdict reaching that limit has `capped: true` | oversized payload rejected; after the limit evaluation continues without another verdict |
| Event payload, default | [generated Event payload bound](../limits.md#max_event_bytes) | append refused |
| `ContextCompacted` and `GoalContextCompacted` | [generated compaction Event bound](../limits.md#max_compaction_event_bytes), including JSON escaping; admits a summary at the [generated summary bound](../limits.md#max_compaction_summary_bytes) containing worst-case escaped bytes; compaction admission reserves this additional Event headroom | append refused |
| `MessageAccepted` | [generated message payload bound](../limits.md#max_message_accepted_bytes), with inline PNG bytes (an empty list for text) | append refused |
| `GoalStarted` | [generated Goal start bound](../limits.md#max_goal_started_bytes) | pre-admission `GoalInputTooLarge` ("objective plus includes too large"); no Event or Provider call |
| `GoalFinished` | [generated Goal finish bound](../limits.md#max_goal_finished_bytes) | append refused |
| `ToolProposed`, `ToolStarted` | [generated Tool start bound](../limits.md#max_tool_started_bytes): the complete intent, including Write, Edit or MultiEdit arguments at the [Tool argument ceiling](../tools/limits-and-failures.md#limits-and-failure-behavior); admission reserves one observation slot per possible intent record (proposal and start), in addition to the Tool observation | append refused |

| `ToolFinished` | Optional `spill: {ref, bytes, truncated}` binds the intent digest and [retained-output bounds](../tools/limits-and-failures.md#limits-and-failure-behavior); only metadata is journaled and strict replay never opens a spill. | Steering note per Run | [generated steering note bound](../limits.md#max_steering_note_bytes), including history labels | offer refused; the caller keeps its text |
| Requested Tools per model step | 0, or 1 to the [generated per-step Tool-call limit](../limits.md#max_step_tool_calls) for a `ToolRequested` disposition | replay refused |
| Session discovery | At most [the generated Session count](../limits.md#max_discovered_sessions) heads; a listing page scans at most [the generated Event count](../limits.md#max_list_scan_events) | partial page with a continuation cursor; exact-ID resume fallback |
| Events per Session lineage | [generated Session Event limit](../limits.md#max_session_events), including inherited history | append refused; strict replay fails closed with a Store error |
| `provider-profiles.json` and `tools.json` | 64 KiB<!-- unrelated-bound: private Provider and Tool records --> each, read only through the admitted handle | rejected; never parsed as trusted configuration |

Canonical state resolves before repository input and lives in a private directory outside the Workspace, with verified owner and permissions or ACL, a fixed aggregate page cap and admission headroom. SQLite integrity is not tamper evidence, and the database is not encrypted at rest. Persisted objectives, summaries, results and errors are untrusted typed data.

The schema is created only in an empty version-zero database; any other existing version rejects before mutable pragmas run. `MessageAccepted` and `GoalStarted` limits derive from the objective and image caps at six escaped bytes per byte. Goal admission preflights the serialized objective plus admitted include list against the GoalStarted ceiling, so combined escaping can refuse an otherwise individually bounded request before Goal acceptance; large pasted objectives reject before disclosure, usage or a partial fork target, and earlier history and summary stay readable. Byte preflight is conservative and is not a lease against independent writers or disk faults.
