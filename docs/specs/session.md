# Sessions

## Scope and related contracts

This contract owns the durable conversation: Session identity, lineage, defaults, context compilation, compaction and the persisted facts that replay rebuilds. A Session is one durable ordered conversation across process exits. A Run is one bounded execution caused by one accepted Message. An AgentRun is one primary or child execution inside a Run.

[Goals](./goals.md) owns task lifecycle, budgets and steering; [Execution](./execution.md) owns Run coordination, accepted outcomes and persistence bounds; [Provider](./provider.md) and [ChatGPT](./chatgpt.md) own Provider admission and account records; [Terminal](./terminal.md) owns attached commands and presentation; [Credentials](./credentials.md) owns saved accounts.

Editing constraints: [security rules](../../agents/security.md).

## Lifecycle and identity

- Every accepted task belongs to a durable Goal, and each Run is linked to it before its accepted Message. Replay rejects missing linkage and projects unfinished Goals as interrupted without retrying calls or effects. Goal state is task lifecycle; the Session remains the conversation identity.
- Resume preserves Session identity. Retrying interrupted work creates a new Run ID. Historical agents stay inspectable; no in-memory child is fabricated or restarted.
- Fork creates a new Session from an exact committed Run boundary. Its first Event is `SessionForked`, recording the immutable source Session, Run, sequence and prefix digest. Replay resolves at most eight lineage links within the [Session Event cap](./execution.md#persistence-bounds), verifies each canonical Event-prefix digest and includes only inherited committed Runs through the boundary. A missing or changed source fails replay before context compilation. A [journal migration](./execution.md#journal-migration) that rewrites a prefix first checks the recorded digest against the stored bytes, then recomputes it and strict-replays the result before the swap.
- A pre-`RunStarted` interrupted objective has no pinned Workspace identity. Later completed Runs may be forked or compacted in their admitted Workspace; compaction carries the old objective as unanswered data, and a fork inherits only committed terminal Runs.
- A new Session's start Event pins its admitted Workspace identity before the first Run. Every later Run and fork must agree with it.
- `--continue` selects the matching Session with the greatest committed Event sequence and revalidates it through exact-ID resume. Discovery reads canonical Events, never directory names or a mutable index; malformed history fails rather than selecting an older Session.
- The `/resume` picker lists only canonical heads bound to the admitted Workspace, newest committed activity first, at one Event watermark across all internal listing pages. Choosing a row runs exact-ID resume and does not switch if replay or Workspace revalidation fails.
- Paged Engine discovery requires a positive limit; zero returns `InvalidRequest` before Workspace admission or Store access.
- Titles: `SessionView.title` keeps the canonical creation or rename text; the readable name is a projection needing no rename Event. Replay keeps explicit-title provenance, including deliberate placeholder-looking names. Discovery uses the first accepted user objective as its bounded generated title unless creation or an explicit rename supplies a non-placeholder name; an empty conversation has the empty placeholder. A fork retains its inherited title until its first local objective. Times come from canonical Event timestamps; titles add no Provider call or canonical rename.
- Attached resume keeps configured defaults. Without an explicit selection it recovers the latest Run's tuple, then the current user default; an account-only selection restores only its same-account tuple. Inheritance is persisted before switching, and collaboration policy is preserved. Replay and preferences never authorize a replaced account or a billing fallback.

A fork lookup is a hint only. Its parent is loaded and strictly replayed before any Event is disclosed.

## Session commands

- Bare `arany` opens a local unsaved conversation. Attached startup, `/new` and `/clear` create its durable Session only at the first task submission after local selection validates. Local commands, setup, rename, model changes and draft edits keep it unsaved; exit or resume discards it without Events or a resumable ID.
- Explicit Engine creation and forks are durable, and existing empty Sessions remain readable. `--continue` resumes the latest Session in the admitted Workspace, `--resume` resumes an exact Session or opens the picker, and `--fork` creates a Session at a committed boundary.
- Interactive commands are `/resume [SESSION_ID]`, `/new` (alias `/clear`), `/fork`, `/rename` and `/compact`. `/new` copies the current next-Run defaults into a fresh unsaved conversation, not startup preferences or prior title and history. It keeps the account identity without loading credentials or renewing evidence; Run admission still revalidates. The first submission persists the explicit title and defaults before Run admission. A failed admission after submission may leave a retained Session, with no rollback or guaranteed Message acceptance.
- Sessions are never resumed implicitly from the current directory. A draft or active Run must be handled explicitly before switching.
- Provider, model, effort, profile, permission grants and collaboration defaults change only between Runs. Attached dispatch approval mode may narrow the same pinned grant between effects without rewriting defaults or an outstanding intent. `RunStarted` persists the resolved values with explicit nullable fields; missing fields reject.
- A saved native API account is selected by UUID in Session defaults, never by replayed credential bytes. The CLI resolves the UUID and exact Provider against the current protected account before any Run or catalog access, so replacing the account makes an older saved-key selection unavailable rather than switching billing identity. `RunStarted` pins the saved-account UUID as explicit nullable provenance; replay requires a native Provider and a UUIDv7 when present.
- ChatGPT defaults pin the account UUID without a token. Each Run and compaction records the account UUID, opaque admission fingerprint, closed admission category and local-only output bound. Strict replay validates that combination but cannot turn history into current account authority.
- `exec` creates one Run and exits by default. Appending to an existing Session requires an explicit Session ID.

## Collaboration policy

Each Run pins one collaboration policy before it starts. `SessionDefaultChanged` records a complete validated next-Run selection only while idle, and every Run re-admits its selected Provider before Workspace input. Children, capacity, cancellation and the `single`, `auto` and `team` meanings are owned by [execution collaboration](./execution.md#collaboration).

## Workspace admission and authority

A Workspace is hostile before admission. Trusted user/process configuration and private State admission precede repository input. Admission pins an opened directory identity and immutable input digests, never a path string or worktree metadata alone. It executes no repository or Git configuration, hooks, filters, fsmonitor, plugins, package managers, test discovery, startup commands or repository code.

Like Codex CLI, instruction files load from the Workspace root down to the launch directory, at most one per directory, in precedence order: `AGENTS.override.md`, `AGENTS.md`, then `CLAUDE.md`. Like Codex and Claude Code, each name is opened as given, so a case-insensitive volume may serve `agents.md` for `AGENTS.md`; Arany checks no spelling because the repository author controls every candidate name equally, so a case alias grants nothing beyond writing `AGENTS.md` directly, and no peer checks spelling. The launch directory is the process working directory of `exec` and attached chat when its resolved path lies inside the Workspace; otherwise, and for `serve` and `acp`, only the root is read. Codex starts at the nearest `.git` ancestor, reads configured fallback names and follows links. Arany starts at the admitted root, never reads above it, and opens every directory and file from the root handle without following links, because only the admitted root is disclosed and a link could reach outside it; `CLAUDE.md` is its one fixed fallback, since no trusted setting names others. A linked, hard-linked or non-regular instruction file, or a link swapped into the path, rejects the turn; a directory removed after resolution ends the walk. The walk covers at most 32 directories, the root included, and all files share one 64 KiB budget (Codex: 32 KiB). A deeper launch directory, a total over the budget, or source pins that would push `RunStarted` past the [default Event payload bound](./execution.md#persistence-bounds) (long paths at many levels) rejects the turn with `InputTooLarge` before any Provider call or Event. Codex truncates overflow silently with only a `tracing` warning, which can cut a followed rule such as "never do X" without the user knowing; rejecting keeps the pinned digests equal to the bytes the model follows. Instructions and explicit includes are bounded immutable no-follow snapshots. The files reach the primary and every child as the first user-role message, one text block per file and root first, so deeper files read last: `# AGENTS.md instructions for PATH`, a blank line, then the text between `<INSTRUCTIONS>` and `</INSTRUCTIONS>` lines. PATH is the Workspace-relative file path kept on one inert line: control characters and Unicode line and paragraph separators appear as their Rust escapes (`\n`, `\u{1b}`) and tag-like `<` as `&lt;`. The text cannot fake the wrapper either: every `<` that begins an opening or closing `instructions` tag, in any case and with any whitespace, is sent as `&lt;`, and a line starting with a `# AGENTS.md instructions` heading of any case gets a leading `\`. The model follows each file as behavior rules for work in its directory tree; a deeper file wins over a shallower one, and direct user and system instructions take precedence. `RunStarted` pins each file's directory, name and raw SHA-256 in that order, plus the launch directory (a source migrated from before nesting has an unknown name); no instruction text is journaled, and replay never rereads the files. Agent definitions, worker assignments, explicit includes, other repository content, Skills, prompts, model output, Tool or MCP output, Memory and replayed Events are labelled data. None of this text, instructions included, is authority: instruction text never changes Policy; any future restrict-only instruction policy may only narrow. It never selects or widens trust, permission, approval, sandbox, Provider or update modes, roots, endpoints, credentials, executables, budgets or capabilities. Authenticated user or administrator configuration fixes authority before untrusted input; models and classifiers may only raise risk or narrow it. [Tools](./tools.md#folder-trust-and-approvals) owns path and scope admission; [Credentials](./credentials.md#account-scope-and-identity) owns private directory admission.

Like Codex's `CODEX_HOME/AGENTS.md`, the selected State directory's `AGENTS.md` carries the user's defaults for every Workspace using that State; `--state-dir` and `ARANY_STATE_DIR` select it, so no other home or `~/.config` location is searched, and there is no global override or `CLAUDE.md` name. It is read as a private State record under the [credential spec's admission](./credentials.md): at most 64 KiB, a regular single-link file with a private mode, no-follow, and read-only to the harness. Its cap is separate from the project budget, as in Codex. Absence alone is allowed. An unsafe or oversized file, a link, a read failure or non-UTF-8 text rejects the turn with the State error (or `InputNotUtf8`) before any Provider call, with no truncation, repair or fallback. It is rendered first, labelled `user AGENTS.md` (no host path), and project files follow, so the model is told repository files win over it and the user file wins over nothing but defaults; direct system and user instructions still rank highest. Together the blocks must fit the compiled-content ceiling or the turn is rejected with `ContextTooLarge`. `RunStarted` pins the raw SHA-256 as `user_instruction_digest` (null when absent); each new Run, including after resume or fork, snapshots the file again, while replay, show and historical compaction never reread it. The block survives child work and in-Goal compaction as the first `project_instructions` entry. Like project files, it is behavior text and never authority.

## Worker identity and explicit reassignment

An explicit editor assignment may name an exact historical child AgentRun ID in `resumes`. The source must be a terminal or interrupted child of this Session's same Goal, with its lease released or its Run closed. Unknown, primary, active and other-Goal IDs reject before child disclosure. An active ID remains inspectable; it cannot acquire a second runner. `supersedes` retains the explicit replacement relationship. Both are lineage data, never permission or a retry instruction.

Every accepted reassignment receives a new UUIDv7 AgentRun ID and current definition admission, grant, base capture and Run-scoped lease. The selected source contributes its objective, summary and at most 2 KiB of report (each bounded by its journaled limit, about 7 KiB in total) plus bounded typed disposition, publication, verification and lineage facts, labelled untrusted task data. No historical Tool steps, private bytes, permission, approval or lease resume. This is the owner-accepted divergence from Claude Code's retained-worker continuation.

## Worker replay

Strict replay reduces committed assignment, target/revision, sealed data, handover, integration, discard, release and verification facts without executing a Provider, parser, Tool, cleanup or publication. It never rereads definitions or fetches data by path/URL. Unsupported versions, missing required nulls, duplicate/unknown fields, changed references and illegal transitions reject without modifying stored bytes.

An interrupted prefix retains observed usage and unknown private outcomes. Unpublished private work, including unspawned preparations, is projected as discarded at the Run boundary; native disposal is confirmed only by its own evidence. Pending transfer buffers are dropped and no private view or lease becomes live in another Run. A successful attested primary publication remains confirmed even when WorkerIntegrationRecorded or lease release is missing. Replay fabricates neither Event; the result requires fresh primary verification. An unfinished or uncertain Workspace publication blocks Goal continuation. [Goal recovery](./goals.md#worker-accounting-and-verification) owns the narrow private-only exception and native containment admission.

Historical projections identify each assignment and its resumes/supersedes lineage, disposition/cause, unknown private outcome, cleanup confirmation, publication certainty, lease release and verification. `show` retains the complete qualified Events and adds readable derived worker dispositions; JSONL remains the exact canonical Event stream. Goal reports prioritize these worker facts before optional positive evidence. Forks inherit the same qualified history, never authority or executable private views. Context and compaction carry bounded untrusted worker reports and dispositions, excluding raw worker data and internal capture Tool bodies. Compiler v3 and the canonical summary format remain unchanged.

## Rewind planning and replay

The pure rewind planner consumes only strictly replayed lineage facts. A checkpoint is the exact RunStarted or WorkspaceRewindStarted position. For each path published from that checkpoint through the head, the plan restores the first publication's before state and expects the last publication's after state, including byte length and executable bit or absence. It omits net no-ops, marks mismatched intermediate states as history drift, and marks a skipped or [pruned](./tools.md#checkpoints-and-rewind) first pre-image unavailable. It covers typed edits, integrated command changesets, integrated worker handovers and restored rewinds; inherited prefixes participate, while parent suffixes outside the fork do not. A restored rewind reverses its effective plan into a new publication, allowing a later plan to undo it.

The planner enforces the [rewind file, version, content and encoded-transfer bounds](./tools.md#checkpoints-and-rewind); selections are checked again after replacing observed preconditions. Scratch follows the 10,000-publication lineage bound (at most 2,048 path facts per publication) and three non-rewindable facts per Tool, materializing one publication at a time. Net no-ops are removed before the effective file/byte limits are checked. Overflow rejects the whole plan. Kept/overwrite selections must be sorted, distinct, disjoint subsets of the plan; unavailable paths can only be kept. Selected history-drift paths require an explicit observed overwrite precondition. Open or Uncertain Workspace publications and open/Uncertain rewinds between checkpoint and head block code restore. Unguarded commands, MCP calls, cache publication/uncertainty and created directories are listed as non-rewindable effects. No Workspace, checkpoint-store, clock, Provider or Git read occurs.

Started recomputes and selects the canonical plan, requiring exact head/prefix/plan digests, Workspace identity, counts and bytes, no blocker and a nonempty effective plan. Like an idle rename, it seals a crash-left unfinished predecessor Run and pauses its Goal; this is no authority to interrupt a live Engine operation. Duplicate IDs and an open preceding rewind reject. Finished must immediately match its Started and the [attestation/capture rules](./execution.md#workspace-rewind-events). EOF projects an unfinished rewind as Uncertain. Any later fact seals it as Uncertain and forbids a delayed Finished, without inventing an Event or a receipt. A later Run checkpoint does not cross an older uncertainty. Replay never republishes, reads stored pre-images or reruns a fork.

Bounded untrusted history adds the newest eight count/target/outcome rewind lines (at most eight JSON-escaped paths and 4 KiB per line) and an explicit omission marker to subsequent context, compaction and Goal reports. They grant no authority. A rewind advances the between-Run compaction boundary (retaining the last Run identity), so its exact prefix digest covers the new facts; stale pre-rewind snapshot boundaries reject. Existing histories without rewind facts compile byte-identically with compiler v3. Forks inherit rewind history through their exact committed boundary, never Goals or permissions. Guarded runtime code restore follows [Tools](./tools.md#checkpoints-and-rewind). The [terminal](./terminal.md#rewind) and [serve](./serve.md#rewind) own user-facing rewind controls.

### Conversation rewind

`Engine::fork_session_at` accepts an exact earlier committed RunFinished sequence in the source's replayed lineage. It refuses a non-boundary target before writing. The Store selects the ancestor that owns that Run, pins its Session/Run/sequence and canonical prefix digest, and revalidates the pin in the fork transaction. Parent suffixes are excluded; later parent appends do not change the pinned prefix, while prefix drift or a missing ancestor fails closed. The unchanged SessionForked format and strict replay validate the prefix without executing either rewind step.

`Engine::rewind_conversation` selects the Run whose prompt is to be restored and forks at the committed boundary ending its predecessor. The source Session remains intact and resumable. Selecting the first prompt instead returns an unsaved conversation with the current next-Run defaults and no durable ID or Event, following [new-conversation semantics](#session-commands). The result carries prompt text up to 8 KiB; a longer objective is omitted, and images are never restored. The caller surfaces a notice for omitted text or images. A durable rewind fork also returns the source's current next-Run defaults for the client to retain. Inherited Runs and valid compactions follow the selected prefix; Goals, their budgets and permissions never become resumable fork state.

Ancestor-owner selection avoids adding unnecessary lineage links. A fork that would exceed the [lineage bound](#lifecycle-and-identity) is explicitly refused before any Event, with guidance to start a new Session; code-only restore remains available. Selecting the first prompt needs no lineage link. The Engine operation slot and Session/ancestor locks cover selection through completion, with fresh Workspace identity admission and no inherited authority. A client confirmation can pin the source head sequence and prefix digest; a changed pin rejects under those locks before any fork.

`Engine::rewind_both` consumes the same confirmed code preview, preflights the fork and reserves code/fork Event headroom before Started, then restores code first. Only an acknowledged committed WorkspaceRewindFinished with outcome restored permits conversation restoration. A code refusal, failure, cancellation, Uncertain result or lost completion never forks. The result retains the exact code outcome and an unchanged conversation status. If the fork subsequently fails, it retains the restored code receipt and reports conversation failure: “Code restored; conversation unchanged; restore conversation separately.” Cancellation after restored code leaves the conversation unchanged. A crash between Finished and the fork leaves only restored code; reopen never completes or retries the conversation step. A fork transaction commits wholly or leaves no fork.

Owner decision D6 intentionally diverges from Claude Code's transcript branch, Codex thread/rollback marker and OpenCode's in-place revert: Arany creates a new Session ID per conversation rewind. This preserves the append-only source and existing replay, compaction and Goal semantics. The cost is a new ID and the eight-link lineage cap; an in-session marker is deferred unless dogfooding reaches that cap.

## Context and compaction

- Explicit include data carries an escaped relative path, the SHA-256 of the raw bytes and untrusted snapshot text. The full envelope counts toward the context budget; the raw file digest stays pinned separately. Historical Tool context identifies its previous-Run scope and never forbids fresh inspection.
- Recorded steering enters later-Run history and compaction through the same user-text projection, with actor-labelled child notes and byte-identical historical text when no child note exists. The [Goal steering contract](./goals.md#steering-notes-and-pause) owns quotas and non-redelivery.
- Context compilation is deterministic over committed local Messages, Events, instruction snapshots, exact budgets and the selected Provider capability snapshot. Provider-hosted conversation IDs, prompt-cache keys and opaque compaction items are accelerators, never canonical history.
- With Tools enabled, optional history and summary selection leave room for the catalog, the largest bounded primary-route turn, one full Tool result and step feedback. Explicit inputs retain the existing admission ceiling; when they prevent that reserve, only the actual continuation capacity is available. Every new Run recompiles this selection, including after `ToolContextFull`, so a failed Run cannot permanently consume the next message's continuation allowance. Selected Run IDs and excluded counts remain pinned in `RunStarted`; canonical history stays intact.
- Past Tool attempts and results, including those of failed and incomplete Runs, enter history and compaction only as bounded untrusted facts. An unfinished intent is reported as uncertain and is never replayed, retried or reused as approval. Active-Goal compaction covers only an acknowledged Tool prefix of its exact Run, preserves all canonical observations and leaves the completed-Run `ContextCompacted` proof unchanged. Images contribute metadata, not pixels.
- Failed, cancelled, interrupted and hook-stopped Runs without model Tools also enter recent history as `previous_run (historical, untrusted)`: the objective and a typed unanswered status derived only from committed Events, with the last primary call's disposition and closed failure reason when recorded. An absent reason stays unknown; history never infers a refused operation or cause that was not journaled. These turns share the existing history-Run and context-byte budgets. A refused primary proposal is reported as nothing dispatched.
- The immediately previous Run's failure also enters the next Run as compiled harness context derived solely from committed Run/Goal and primary Provider-call facts: the closed Run failure (including projected budget exhaustion), last non-review call disposition, nullable Provider failure reason and nullable proposal-refusal cause. This fixed-size projection is independent of optional history selection and compaction, including after Tools were used. Missing details remain unknown; no Tool output, error prose, objective, private path or model-authored explanation enters the trusted notice. It grants no authority to repeat effects. Together with the [outcome correction notice](./provider.md#structured-outcomes-and-tool-encoding), it is bounded to 1 KiB, reserved explicitly in context admission before optional history selection. The correction notice may extend the compiled system blocks once in a Run; previous-Run feedback stays pinned for that Run.
- Before reserving the next primary Provider call, the Engine projects Tool context with the next bounded Provider turn, Tool arguments and one full [per-call result budget](./tools.md#limits-and-failure-behavior). When the worst-case next-turn reserve alone exceeds the Tool allowance, the maintenance heuristic uses half that allowance instead; actual Tool admission still enforces the complete effect receipt or remaining pageable-read capacity. If the projection would exceed the allowance, or reaches the existing two-thirds pressure threshold, it first clears older results on whole-step boundaries, retaining at least the three most recent results. This follows Claude Code's clear-before-summary policy and three-result retention; Arany additionally commits the rewrite boundary for journal-first replay ([Event contract](./execution.md#admission-persistence-and-recovery)). Clearing costs no Provider call. If it frees less than one result budget, the Engine attempts the existing charged summary compaction. Compaction first selects a whole-step prefix whose replacement also leaves this next-turn reserve; if the pinned prefix makes that impossible, it may still summarize against the actual allowance. If maintenance cannot free the full reserve, a request whose actual context fits still proceeds: the model may answer, and a later Read, List, Search, Glob, Skill or typed Git read receives the remaining rendered result capacity, capped at 64 KiB and pinned in its intent before dispatch. Effectful calls retain the full 64 KiB result allowance and refuse with `ToolContextFull` before dispatch when it cannot fit, preserving publication receipts and their rewind preimages. The internal changeset publication keeps its fixed 128-byte allowance for its bounded applied-count result. Read results page or truncate with their existing markers; Skill text uses the marker specified in the Tool contract. Clearing and charged Tool compaction run only at a settled boundary before the next primary call; a newly recorded Tool request that cannot fit refuses before dispatch without inserting maintenance into the pending step. An already attempted compaction prefix is not retried. A recorded plan reaches the same maintenance boundary before any capacity refusal. Only an actual request or Tool envelope that still cannot fit stops with `ToolContextFull`. Canonical observations and committed Events are never discarded to make room.
- The compiled-content ceiling is 376 KiB unless every primary route carries trusted window metadata: a ChatGPT catalog `context_window` saved by the account's current `provider check chatgpt` ([Provider](./provider.md#per-role-selection-and-fallback)). Then it is `min(1 MiB, 0.9 × window × 3 bytes)` for the smallest window in the chain, and `RunStarted.config.context_window_tokens` pins that window. Native OpenAI and Anthropic routes and custom routes carry none. A window outside 32,768–2,000,000 tokens is absent. A primary call reporting input tokens at or above 90% of the pinned window runs the clear-then-summarize maintenance above before the next call, once per report, even below the two-thirds threshold. Peers: Codex decodes `context_window` from its `models` reply and compacts at 90%; Claude Code and OpenCode compact near the window. Arany assumes no window for unknown routes (OpenCode assumes 200,000 tokens), uses 3 bytes per token instead of Codex's 4, and replay rejects a budget or Tool receipt above the ceiling the pinned window allows. The window comes only from authenticated catalog evidence, never from Workspace content or model text, and only resizes budgets within the hard ceilings.
- A cleared result is untrusted data shaped as `{operation, call, disposition, effect, cleared: true}`: `operation` is the fixed placeholder `Result cleared to save context; call the Tool again for current content`. The call, disposition and effect facts remain, including private-target facts and `uncertain; never replay` for uncertainty. The result body and its hook feedback cannot reappear in subsequent requests, history or summary input except through a fresh Tool call. Clearing never changes the invoked Skill, plan, Goal facts or pinned prefix. Canonical Events remain intact; clearing is not deletion or redaction.
- Compaction never deletes or replaces canonical history. It creates a digest-bound derived snapshot over an exact Session prefix, with author, Provider, model and local semantic-schema provenance.
- A manual compaction summarizes accepted Run outcomes after the latest valid summary, including unanswered failed, cancelled or interrupted objectives as data. `ContextCompacted` records provider-neutral model-authored text or a typed failure; replay checks the source and content digests and the version before any later Run selects it. A failed attempt preserves the last good summary.
- The accepted summary is complete non-whitespace plain text within 8 KiB, preserved byte for byte and rendered as untrusted model-authored data. Neither JSON-looking text nor summary claims change typed approvals, uncertainty, Tool receipts, budgets or Goal completion. The [Provider contract](./provider.md#structured-outcomes-and-tool-encoding) owns framing and rejection. Compaction record versions `(prompt_version, schema_version, compiler_version) = (1, 1, 3)` identify the local summarization task, semantic summary schema and source projection, not an HTTP output schema or remote enforcement. Summary strings, digests, wire/account provenance and output-bound categories retain their existing persisted meaning.
- Capacity is checked under the lineage locks before inference. Manual and automatic compaction have no lifetime attempt quota; Goal compaction is charged to the Goal's Provider-call budget. A rejected attempt makes no Provider call and appends no attempt.
- `/compact` runs only while idle and shows its Provider usage. `RunStarted` records the selected context-content bytes, compactable history bytes, the policy-adjusted budget and the nullable `context_window_tokens` that sized it. After a successful attached Run, automatic maintenance triggers at 80% context pressure with at least 10% compactable history, 24 of 32 selectable history Runs, or compactable bytes approaching the compaction-input cap. The source-pressure guard reserves two maximal canonical turns, derived from the shared Message and image-metadata limits; a cap is never raised to make maintenance pass. A visible warning precedes one attempt per exact committed boundary, and Workspace input alone never triggers a call. Automatic maintenance accepts only the expected Run ID under the Session lock and skips a boundary that already has an attempt, so a stale warning cannot become a Provider call.
- A failed boundary is not retried automatically; manual `/compact` remains available. Unmaintained or failure-heavy prefixes that exceed the source bound reject before Provider egress. `exec` makes no hidden post-Run Provider call.
- A snapshot mismatch, a fork outside its covered prefix, an incompatible Provider item, a deleted source or a non-current compiler version invalidates the snapshot and fails closed.
- Cross-Session Memory is a different product: Session history never silently becomes durable Memory. Future retrieval requires explicit project or tenant scope, caller authentication and authorization before retrieval and prompt assembly; it cannot widen the authority fixed at [Workspace admission](#workspace-admission-and-authority).
- A step declares its model Tool requests on its `ToolRequested` record. `ToolStarted` needs a declared request not yet started, a continuation needs every declared request observed, and a compaction prefix ends on a whole step, counting model Tools only.

Context compilation is a pure function of its inputs. It reads no clock, randomness or Provider-hosted state.

Only the Provider renderer turns a typed request into the conversation: it alone decides what is `system` (a closed set), what is user input and what is labelled untrusted data. Base system prompt text is loaded byte-for-byte from `prompts/` files. Everything before a Run's loop is byte-stable for that Run; each later request is the previous one plus appended blocks, and clearing and compaction are the only rewrites.

## Roster recovery and compaction

Decision O7 (product/security): resuming a roster-bound interrupted Goal requires explicit `--profile` with the same normalized selection digest, plus fresh credential/consent/evidence admission. An omitted selector or drift refuses before Workspace content or inference, with guidance to restore the preset or start a new Goal. Compare selection metadata, never expiring evidence fingerprints. New Goals may choose another preset. Reopen reduces interrupted work without dispatch; explicit resume creates fresh Run/AgentRun IDs with chains starting at index zero. A trailing accepted Message without RunStarted does not erase the last pinned selection. No historical actor is hot-rebound and replay grants no consent.

The [Provider roster contract](./provider.md#named-roster-presets) owns the submission snapshot and selector; no Session preset-default record exists. Automatic and manual compaction of a roster Run re-admit its exact pinned compaction role and provenance through current authorization/evidence rules, including when all role chains use the inherited representation. They never reread a changed roster to choose a destination or admit unrelated profiles. Ordinary inherited-mode compaction retains its existing selection behavior. Failure or cancellation preserves canonical history and the last good summary; exec adds no hidden maintenance call. The [routing corpus](../../crates/arany/tests/engine_run/routing.rs), [custom journey](../../crates/arany-cli/tests/session_run/custom.rs) and [automatic compaction journey](../../crates/arany-cli/tests/session_run/auto_compaction.rs) own snapshot tampering, explicit recovery and immutable selection evidence.

## Persistence facts

- Every canonical Event carries `session_id`; Run and AgentRun scopes are optional where an Event is Session-only. Session lists may use rebuildable indexes, never as a second source of truth.
- Replay labels an unfinished final Run `Interrupted`. A later `MessageAccepted`, an idle `SessionRenamed` or an idle `SessionDefaultChanged` also seals that predecessor, keeping observed calls, terminal agents and committed Messages, and rejects later facts for the abandoned Run ID. Only one Run is active per Engine. Session operations are exclusive under the per-Session lock; busy operations fail before Workspace content or Provider disclosure.
- Tool transitions require the pinned policy, Workspace and primary identity, one preceding Tool-requested call, one matched intent and result, and aggregate bounds. Missing receipts, widened limits, duplicate results and continued or successful work after an uncertain or cancelled effect reject. The Tool grant and native enforcement profile are pinned before Workspace content. `ToolStarted` is committed before approval or dispatch, and `ToolFinished` before continuation. Each accepted AI review is pinned to its pending Tool.
- Command changeset integration requires the immediately preceding attested command observation, its exact intent digest and an identical validated changeset. It consumes effect capacity without inventing a model Tool request. Replay rejects changed or missing sources and duplicate integration, keeps both stages as historical facts and never re-executes either.
- `ProviderCallRecorded` is an AgentRun fact. Primary planning precedes children, child work is a sequence of child calls each following the child's previous read-only Tool observation, and primary synthesis follows finished children. A child spawn requires an observed Delegated call; a successful Agent completion requires an observed Finished call. The record stores the bounded observed outcome, response ID, provider-reported usage, optional accepted wire provenance and an optional closed failure reason. The reason must match a rejected or unavailable call and is never upstream text or account authority. Raw error strings, statuses and stream codes are not persisted. Absent usage is unknown, not zero. Nullable provenance is explicit, and omitted fields reject. A rejected or timed-out call has unknown provenance, which the Engine never infers from a Provider name. Provenance reports a local request control and an accepted wire completion, never a Provider privacy guarantee.
- A plan-less Tool request opens a plan wait. While it is open, only the plan record, prelude Tool events, explicit resume and Failed or Cancelled `AgentFinished` or `RunFinished` are accepted; `RunFinished` clears the wait.
- `AgentSteeringNoteRecorded` retains exact child identity in the envelope and joins the Run's actor-labelled history and compaction input. An interrupted child note stays historical; resume starts fresh without active child notes. Replay never offers a note or dispatches a Provider call.
- `GoalSteeringNoteRecorded` is accepted only while the latest Active Run's primary AgentRun holds an open planning or synthesis reservation. Replay rejects it elsewhere, enforces the per-Run note bound and never re-delivers a note. Its contract is in [Goals](./goals.md#steering-notes-and-pause).
- Persist Session creation, default, rename, fork and compaction facts, and Run and AgentRun lifecycle facts. Terminal focus, panel state, hover, picker selection and native scroll position are never persisted.
- `AssistantDisplayRecorded` is a display-only, primary or call-scoped Event. Replay enforces sequential byte offsets, legal active call phases and the terminal contract's per-Run bytes, items and chunk bounds, including at most one compiled detail-limit cue. It never supplies `MessageCommitted`, Agent results, Provider context or compaction items. An accepted primary result must match every checkpoint of its final call; delegation and Tool calls cannot accept answer checkpoints. Only primary planning and synthesis calls receive the coalescing preview, and its 64 display Event slots are reserved before disclosure. Cancellation flushes only credential-safe text; invalid, rejected or over-limit candidates are withdrawn. Cancelled or interrupted replay exposes these facts as incomplete, and a failed validation hides the candidate. Explicit JSONL export retains the qualified facts.
- History, titles, fork lineage and snapshots are sensitive derived state. Resume never promotes them to authority, and Provider state cannot be the only recovery path.
- `RunStarted.user_instruction_digest` is the raw SHA-256 of the State `AGENTS.md` snapshot or null; neither its text nor the State path is journaled.
- Attached draft preflight reads Workspace input locally before Session materialization, with no Events, disclosure or Tool authority; it does not replace fresh Run admission.

SQLite opens with no-follow and defensive settings, `trusted_schema` off, rollback journaling, `synchronous=EXTRA`, the [listing read and writer busy bounds](./serve.md#methods) and the declared page cap. Read-only inspection creates no file, directory or journal. One owner thread serves a bounded channel of 64 requests; a closed channel is a store failure, never a successful append. Provider evidence tables are derived caches, never Events: malformed or future-dated rows are unavailable.
