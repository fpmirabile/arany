# Sessions

## Scope and related contracts

This contract owns the durable conversation: Session identity, lineage, defaults, context compilation, compaction and the persisted facts that replay rebuilds. A Session is one durable ordered conversation across process exits; a Run is one bounded execution caused by one accepted Message; an AgentRun is one primary or child execution inside a Run.

[Goals](./goals.md) owns task lifecycle, budgets and steering; [Execution](./execution/README.md) owns Run coordination, accepted outcomes, [effect outcomes](./execution/events-and-outcomes.md#effect-outcomes) and persistence bounds; [Provider](./provider/README.md) and [ChatGPT](./chatgpt.md) own Provider admission and account records; [Terminal](./terminal/README.md) owns attached commands and presentation; [Credentials](./credentials.md) owns saved accounts. Editing constraints: [security rules](../../agents/security.md). Native and live evidence gaps: [NEXT_STEPS](../../NEXT_STEPS.md#beta-2-and-broader-release).

## Lifecycle and identity

Live host session approval lasts only for the running Engine's Session ([Execution](./execution/admission-and-recovery.md#admission-persistence-and-recovery)); resume, restart, reconnect and fork never revive earlier grants, and historical approvals are evidence only. Host command effects, including a dispatch with no confirmed outcome, appear as non-rewindable in rewind previews and restored conversations; restoring conversation or code does not undo them. [Tools](./tools/host-commands.md#primary-host-commands) owns command authority.

- Every accepted task belongs to a durable Goal. Replay rejects missing linkage and projects unfinished Goals as interrupted, re-executing nothing.
- Resume preserves Session identity; retrying interrupted work creates a new Run ID. Historical agents stay inspectable; no child is fabricated or restarted.
- Fork creates a new Session from an exact committed Run boundary. Its first Event, `SessionForked`, records the immutable source Session, Run, sequence and prefix digest. Replay follows at most eight lineage links within the [Session Event cap](./execution/persistence.md#persistence-bounds) and verifies each prefix; a missing or changed source fails replay before any context is built or Event disclosed.
- An objective interrupted before `RunStarted` has no pinned Workspace identity; later completed Runs may still be forked or compacted, compaction carries the old objective as unanswered data, and a fork inherits only committed terminal Runs.
- A new Session pins its admitted Workspace identity before the first Run; every later Run and fork must match it.
- `--continue` resumes the Workspace's Session with the latest committed activity. Discovery reads committed history only; malformed history fails rather than selecting an older Session.
- The `/resume` picker lists only Sessions of the admitted Workspace, newest committed activity first, consistently across pages. Choosing a row does not switch if replay or Workspace revalidation fails.
- Paged discovery requires a positive limit; zero returns `InvalidRequest`.
- A Session's title is its creation or rename text, kept even when it looks like a placeholder. Without one, discovery uses the first accepted user objective, bounded; an empty conversation shows the empty placeholder, and a fork keeps its inherited title until its first local objective. Times are committed Event timestamps. Titles cost no Provider call or Event.
- Attached resume keeps configured defaults. Without an explicit selection it recovers the latest Run's tuple, then the current user default; an account-only selection restores only its same-account tuple. Collaboration policy is preserved. Replay and preferences never authorize a replaced account or a billing fallback.

## Session commands

- Bare `arany` opens a local unsaved conversation. Attached startup, `/new` and `/clear` create the durable Session only at the first task submission; local commands, setup, rename, model changes and draft edits keep it unsaved, and exit or resume discards it without Events or a resumable ID.
- Explicit Engine creation and forks are durable; empty Sessions stay readable. `--resume` opens an exact Session or the picker, and `--fork` creates a Session at a committed boundary.
- Interactive commands are `/resume [SESSION_ID]`, `/new` (alias `/clear`), `/fork`, `/rename`, `/compact`, `/status` and `/usage`. `/new` copies the current next-Run defaults, not startup preferences, title or history, and keeps the account identity without loading credentials; Run admission still revalidates. A failed admission after the first submission may leave a retained Session, with no rollback and no guaranteed Message acceptance.
- Sessions are never resumed implicitly from the current directory. A draft or active Run must be handled explicitly before switching.
- Provider, model, effort, profile, permission grants and collaboration defaults change only between Runs; attached approval mode may narrow the same grant between effects. `RunStarted` persists the resolved values with explicit nullable fields; missing fields reject.
- A saved native API account is selected by UUID, never by stored credential bytes, and [resolved at use](./credentials.md#account-scope-and-identity). `RunStarted` pins the saved-account UUID as nullable provenance; when present, replay requires a native Provider and a UUIDv7.
- ChatGPT defaults pin the account UUID without a token. Each Run and compaction records the account UUID, opaque admission fingerprint, closed admission category and local-only output bound; replay validates them but never turns history into account authority.
- `exec` creates one Run and exits by default; appending to an existing Session requires an explicit Session ID.

## Collaboration policy

Each Run pins one collaboration policy. `SessionDefaultChanged` records a complete validated next-Run selection only while idle, and every Run re-admits its selected Provider before Workspace input. [Execution collaboration](./execution/collaboration.md#collaboration) owns the meanings of `single`, `auto` and `team`.

## Workspace admission and authority

A Workspace is hostile before admission. Trusted user configuration and private State admission precede repository input. Admission pins the opened directory identity and immutable input digests, and executes no repository or Git configuration, hooks, filters, fsmonitor, plugins, package managers, test discovery, startup commands or repository code.

Instruction files load from the Workspace root down to the launch directory, at most one per directory, preferring `AGENTS.override.md`, then `AGENTS.md`, then `CLAUDE.md`; a case-insensitive volume may serve `agents.md`, which grants nothing because the repository author controls every name. The launch directory is the working directory of `exec` and attached chat when inside the Workspace; otherwise, and for `serve` and `acp`, only the root is read. Arany never reads above the root or follows links; a linked, hard-linked or non-regular instruction file rejects the turn. The walk covers at most 32 directories<!-- unrelated-bound: instruction walk depth -->, and all files share one 64 KiB<!-- unrelated-bound: project instruction file budget --> budget. A deeper launch directory, an over-budget total, or source pins pushing `RunStarted` past the [default Event payload bound](./execution/persistence.md#persistence-bounds) reject the turn with `InputTooLarge` before any Provider call or Event, never truncating, so the model follows exactly the pinned bytes.

Instruction files reach the primary and every child as the first user-role message, one block per file, root first: `# AGENTS.md instructions for PATH`, a blank line, then the text between `<INSTRUCTIONS>` and `</INSTRUCTIONS>` lines. PATH is the escaped Workspace-relative path on one line (`\n`, `\u{1b}`, `<` as `&lt;`); in the text, a `<` opening an `instructions` tag becomes `&lt;`, and a line starting with a `# AGENTS.md instructions` heading gets a leading `\`. Deeper files win over shallower ones, and direct user and system instructions win over both. `RunStarted` pins each file's [source and raw SHA-256](./execution/admission-and-recovery.md#admission-persistence-and-recovery) and the launch directory, never the text; replay never rereads the files.

Agent definitions, worker assignments, explicit includes, other repository content, Skills, prompts, model output, Tool or MCP output, Memory and replayed Events are labelled data. None of it, instructions included, is authority: it never changes Policy or selects or widens trust, permission, approval, sandbox, Provider or update modes, roots, endpoints, credentials, executables, budgets or capabilities. Authenticated user configuration fixes authority before untrusted input; models and classifiers may only raise risk or narrow. [Tools](./tools/trust-and-approvals.md#folder-trust-and-approvals) owns path and scope admission; [Credentials](./credentials.md#account-scope-and-identity) owns private directory admission.

The selected State directory's `AGENTS.md` holds the user's defaults for every Workspace using that State. `--state-dir` and `ARANY_STATE_DIR` select it; no other home or `~/.config` location is searched, and there is no global override or `CLAUDE.md` name. It is a private State record under [credential admission](./credentials.md), at most 64 KiB<!-- unrelated-bound: user instruction file cap -->, separate from the project budget; absence is allowed. An unsafe or oversized file, a link, a read failure or non-UTF-8 text rejects the turn with the State error (or `InputNotUtf8`) before any Provider call, with no truncation or fallback. It renders first as `user AGENTS.md`, without a host path; project files win over it, and it wins only over defaults. All instruction blocks together must fit the context ceiling or the turn rejects with `ContextTooLarge`. `RunStarted.user_instruction_digest` pins only its SHA-256 (null when absent). Each new Run reads it again; replay, show and historical compaction never do. It survives child work and in-Goal compaction as the first `project_instructions` entry, and is behavior text, never authority.

### Prompt overrides

The selected State directory's private `prompts/` directory may hold `primary.md`, `team.md`, `researcher.md`, `editor.md` and `compaction.md`. Each replaces only its role's default working-style text; the compiled authority-and-trust text, which carries the safe AI cage guarantee, always [renders beside it](#context-and-compaction) and cannot be removed, so an override never widens Tools, grants, approvals or trust labels. Tool review and the read-only prompt are not overridable, other names are ignored, and no Workspace, repository, client or flag supplies overrides. The directory must be owner-private (`0700`, not a link) and each file a private State record under [credential admission](./credentials.md), nonempty UTF-8 within [the override limit](./limits.md#max_prompt_override_bytes), or [the smaller compaction override limit](./limits.md#max_compaction_prompt_override_bytes). Absence means the default. An unsafe, oversized, empty or non-UTF-8 file, or a read failure, refuses Run admission with `PromptOverride` naming the file, before any Event or Provider call. `RunStarted.config.prompts` pins each file's source (`default` or `override`) and the SHA-256 of the rendered text; Session compaction records its own `prompt` fields. Each new Run or compaction reads the directory again; replay and show never do.

## Worker identity and explicit reassignment

An explicit editor assignment may name an earlier child AgentRun ID in `resumes`: a terminal or interrupted child of the same Goal in this Session whose lease is released. Unknown, primary, active and other-Goal IDs reject before disclosure. `supersedes` records an explicit replacement. Both are lineage data, never permission or a retry instruction.

Each reassignment gets a new UUIDv7 AgentRun ID, fresh definition admission, grant and lease. The source contributes its objective, summary, at most 2 KiB<!-- unrelated-bound: selected child report excerpt --> of report (about 7 KiB in total) and its typed disposition, publication, verification, lineage and changed-path facts (under their [report bound](#worker-replay)), as untrusted task data. No Tool steps, private bytes, permission, approval or lease carry over.

## Worker replay

Replay rebuilds worker assignments, Workspace effects, editor outcomes, lease release and verification from committed Events without running a Provider, Tool, cleanup or publication. [Incompatible history](./execution/persistence.md#incompatible-history) is archived before replay; malformed or forged worker facts reject without modifying history.

An interrupted editor keeps landed Workspace receipts and checkpoints; its unfinished or [Uncertain](./execution/events-and-outcomes.md#effect-outcomes) writes block Goal continuation exactly like primary writes. Reassignment grants fresh authority instead of retrying a historical effect. [Goal recovery](./goals.md#worker-accounting-and-verification) owns continuation.

Historical worker views show identities, lineage, disposition and cause, publication certainty, lease release, verification and bounded report text. Editor reports list changed paths and latest after-digests from successful committed Workspace publications, command changesets included; a deletion has a null after-digest. The list is bounded by [MAX_EDITOR_CHANGE_REPORT_BYTES](./limits.md#max_editor_change_report_bytes), ends with an omission notice on overflow, is labelled untrusted, and accompanies the answer in context, compaction and inspection, also after cancellation, pause or interruption. Model text never supplies these facts or any authority. `show` keeps child Tool Events under their AgentRun; JSONL stays the canonical Event stream.

## Rewind planning and replay

A rewind checkpoint is a `RunStarted` or `WorkspaceRewindStarted` position. The plan restores, for each path published since the checkpoint, the before state of its first publication, expecting the after state of its last (content, length, executable bit or absence). Net no-ops are omitted, mismatched intermediate states are marked history drift, and a skipped or [pruned](./tools/changesets-and-checkpoints.md#checkpoints-and-rewind) first pre-image is unavailable. It covers typed edits, integrated command changesets, editor mutations and earlier restored rewinds, which a later plan can undo; inherited fork prefixes participate.

The plan follows the [rewind bounds](./tools/changesets-and-checkpoints.md#checkpoints-and-rewind); overflow rejects the whole plan. Unavailable paths can only be kept, and a history-drift path is overwritten only with an explicit observed precondition. Open or Uncertain publications or rewinds since the checkpoint block code restore. Git writes, host Git, unguarded commands, MCP calls, cache publication and created directories are listed as non-rewindable; [presentation](./tools/changesets-and-checkpoints.md#checkpoints-and-rewind) collapses Git and host ones into one line. Planning reads no Workspace, clock, Provider or Git.

A rewind starts only on the exact previewed head and plan, with no blocker and a nonempty plan; like an idle rename, it seals a crash-left unfinished Run and pauses its Goal. Its completion follows the [attestation and capture rules](./execution/persistence.md#workspace-rewind-events); an unfinished rewind replays as Uncertain and can never complete later. Replay never republishes or reruns a fork.

Later context, compaction and Goal reports get the newest eight rewind lines (count, target, outcome; at most eight JSON-escaped paths and 4 KiB<!-- unrelated-bound: rewind context line --> per line) and an omission marker, as untrusted history. A rewind starts a new compaction boundary. Histories without rewind facts compile unchanged. Forks inherit rewind history through their boundary, never Goals or permissions. The [terminal](./terminal/commands.md#rewind) and [serve](./serve.md#rewind) own user-facing controls.

### Conversation rewind

Conversation rewind forks the Session at the committed boundary before the Run whose prompt is restored; the source Session stays intact and resumable, and later source appends do not affect the fork. Selecting the first prompt instead returns an unsaved conversation with the current next-Run defaults and no durable ID or Event, as for [new conversations](#session-commands). The result carries the complete prompt, up to the [generated user-message limit](./limits.md#max_user_message_bytes), and that Run's images; the attached terminal restores both to its draft without submitting ([Terminal](./terminal/drafts-and-paste.md#paste-and-attachments)), and serve signals `images_omitted`. A durable fork keeps the source's current next-Run defaults. Goals, budgets and permissions never carry over.

A fork past the [lineage bound](#lifecycle-and-identity) is refused before any Event, with guidance to start a new Session; code-only restore stays available. A confirmation pins the source head; a changed head rejects before any fork.

Restoring both restores code first; only an acknowledged committed `WorkspaceRewindFinished` with outcome restored permits the conversation fork. Any other code outcome never forks and leaves the conversation unchanged. If the fork then fails, the result keeps the restored code receipt and reports “Code restored; conversation unchanged; restore conversation separately.” A crash between the two leaves only restored code; reopen never completes the conversation step. A fork commits wholly or not at all.

Each conversation rewind creates a new Session ID, keeping the source append-only, at the cost of the eight-link lineage cap; an in-session marker waits until dogfooding reaches that cap.

## Context and compaction

Context is a deterministic function of committed Messages, Events, instruction snapshots, budgets and the selected Provider capabilities; Provider-hosted conversation IDs, prompt-cache keys and opaque compaction items are accelerators, never history.

Only the Provider renderer decides what is `system` (a closed set), user input or untrusted data. System text renders in this order: the role's working-style prompt (default or pinned [override](#prompt-overrides)), the role's compiled authority-and-trust text, the pinned collaboration policy, then, only when the primary may delegate, the team working-style prompt and team authority text, and last any previous-Run failure feedback. Single mode carries no team text. Each request in a Run extends the previous one; clearing and compaction are the only rewrites.

- An explicit include carries an escaped relative path, SHA-256 and untrusted snapshot text. Size never refuses a message: a file within 128 KiB<!-- unrelated-bound: explicit include file cap --> and the remaining budget is attached whole. A larger file, with at least 1 KiB<!-- unrelated-bound: minimum include head budget --> of budget left, attaches its leading whole lines with a `Truncated: lines 1-N of a B-byte file; Read from line N+1 for the rest` line and the whole-file SHA-256 within [the snapshot bound](./limits.md#max_snapshot_bytes), and a later edit's [precondition](./tools/file-operations.md#engine-filled-preconditions) can fill from it. Otherwise the include is a path and size reference telling the model to Read it, which fills no precondition. The composer shows one notice line (`terminal.rs (212.0 KB) attached partially; the model reads the rest`) instead of an error. More than 16 includes per message is refused, naming the count. A directory include, with at least 1 KiB<!-- unrelated-bound: minimum include head budget --> of budget left (otherwise a reference), lists its immediate entries, sorted and labelled `Directory`, with JSON-quoted names and a trailing `/` on directories, never file bodies or recursive contents; protected, linked, cross-device and special entries are omitted, and protected path components reject. The listing scans at most 8,192 entries, keeps at most 64 names and fits 16 KiB<!-- unrelated-bound: directory include listing cap --> or the remaining budget, ending with `[truncated]` on overflow. Files and directories share the 16-include and 256 KiB<!-- unrelated-bound: aggregate include content budget --> aggregate budget, in mention order.
- Recorded steering enters later-Run history and compaction as user text, child notes labelled by actor; an interrupted child note stays historical. The [Goal steering contract](./goals.md#steering-notes-and-pause) owns quotas and non-redelivery.
- With Tools enabled, history and summary selection leave room for the Tool catalog, one full Tool result and step feedback. Every new Run recompiles the selection, so a failed Run never consumes the next message's allowance. `RunStarted` pins the selected Run IDs and excluded counts; canonical history stays intact.
- Past Tool attempts and results, also from failed and incomplete Runs, enter history and compaction only as bounded untrusted facts. A proposal without an observation projects as `not dispatched; proposal only` and a started Tool as `uncertain; never replay`. Historical Tool facts never execute or renew approval. Compaction inside a Goal keeps all canonical observations; children continue under their [Goal reservations](./goals.md#lifecycle-budgets-and-recovery). Images contribute metadata, not pixels.
- Failed, cancelled, interrupted and hook-stopped Runs without model Tools enter recent history as `previous_run (historical, untrusted)`: the objective and an unanswered status from committed Events, with the last call's disposition and closed failure reason when recorded, never an inferred cause. A refused primary proposal is reported as nothing dispatched.
- The next Run gets a fixed-size trusted notice of the previous Run's stop (failure, budget exhaustion with its dimension, cancellation, pause, hook stop, interruption or uncertainty), the last call's disposition and the closed Provider failure or refusal cause; a successful autonomous continuation gets none. It contains no Tool output, error prose, objective, private path or model text. With the [outcome correction notice](./provider/encoding-and-streaming.md#structured-outcomes-and-tool-encoding) it is bounded to 1 KiB<!-- unrelated-bound: Provider correction notice reserve -->, reserved before history selection. Neither notice authorizes repeating an effect ([Effect outcomes](./execution/events-and-outcomes.md#effect-outcomes)).
- Before the next primary call, Tool context is maintained on observed pressure. With a known window, the latest primary report at or above 70% of it clears old results and at or above 90% summarizes, at most once per report. Until a calibrated report exists, and always without a window, Tool context at two-thirds of its byte allowance also triggers maintenance; once calibrated, the window thresholds govern and only Tool context at 90% of the calibrated allowance still triggers it. Clearing keeps at least the three most recent results on whole-step boundaries, costs no Provider call, and runs only when it frees at least the larger of one [generated per-call result budget](./limits.md#max_tool_result_bytes) and 10% of the allowance. If Tool context still cannot fit the next turn and one result, a charged summary compaction follows; a prefix already attempted is not retried. The rewrite boundary is committed before use ([Event contract](./execution/admission-and-recovery.md#admission-persistence-and-recovery)).
- Byte budgets assume 3 bytes per token. Calibration compares the latest primary call's counted bytes (`ProviderCallRecorded.context_bytes`) with its reported input tokens and raises the Run's ceiling to 95% of the effective window at that ratio, capped at 4 bytes per token and the hard ceiling; the Tool allowance grows by the same amount. It never lowers either, each new Run starts from the baseline, and replay uses only recorded values.
- When maintenance cannot free the full reserve, a request that fits still proceeds, and later Read, List, Search, Glob, Skill or typed Git reads get the remaining capacity, capped at the [generated Tool result limit](./limits.md#max_tool_result_bytes). Effectful calls need the full [generated Tool result allowance](./limits.md#max_tool_result_bytes) and otherwise refuse with `ToolContextFull` before dispatch. Only a request or Tool result that still cannot fit stops with `ToolContextFull`. Canonical observations and committed Events are never discarded to make room.
- The context ceiling is [the generated default](./limits.md#max_context_content_bytes) unless every primary route has trusted window metadata: a ChatGPT or native Anthropic catalog window from the [startup catalog cache](./provider/selection.md#per-role-selection-and-fallback). OpenAI API and custom routes have none, and a window outside 32,768–2,000,000 tokens counts as absent. The saved [context window setting](./terminal/commands.md#interactive-commands-and-completion) applies to the chain's smallest window, as a percentage or a token count, never below 32,768 tokens; the default is the full window. `RunStarted.config` pins `context_window_tokens` and `effective_context_window_tokens`, both null without metadata, when the setting has no effect. The ceiling is then the smaller of [the generated hard ceiling](./limits.md#max_window_content_bytes) and `0.9 × effective window × 3 bytes`, and a windowed request admits at most [the generated window request ceiling](./limits.md#max_window_request_bytes); every admitted window, up to 2,000,000 tokens, is usable in full. The window comes only from the authenticated catalog and the user's setting, never Workspace content or model text. An in-flight primary request can hold tens of MB in memory at the hard ceiling. Compaction requests keep [the windowless request ceiling](./limits.md#max_provider_request_bytes), so in-Run compaction covers a prefix within [the compaction input bound](./limits.md#max_compaction_input_bytes).
- A cleared result is untrusted data shaped as `{operation, call, disposition, effect, cleared: true}`, where `operation` is `Result cleared to save context; call the Tool again for current content`. Call, disposition and effect facts remain, including `uncertain; never replay`; the body returns only through a fresh Tool call, also after reopen. Clearing is not deletion or redaction of canonical Events.
- Compaction never deletes or replaces canonical history. It creates a digest-bound derived snapshot over an exact Session prefix, with author, Provider and model provenance.
- A manual compaction summarizes Run outcomes after the latest valid summary, unanswered failed, cancelled or interrupted objectives included. `ContextCompacted` records model-authored text or a typed failure; a failed attempt keeps the last good summary.
- The accepted summary is non-whitespace plain text within the [generated summary bound](./limits.md#max_compaction_summary_bytes), requested with the [generated output token bound](./limits.md#max_compaction_output_tokens). It is kept byte for byte and rendered as untrusted model-authored data, never system content; summary claims never change approvals, uncertainty, Tool receipts, budgets or Goal completion. The [Provider contract](./provider/encoding-and-streaming.md#structured-outcomes-and-tool-encoding) owns framing and rejection.
- The compaction record's `compiler_version` 5 identifies the source projection. Summaries from older compilers stay as provenance but are not selected; context is rebuilt from canonical Runs. An older Tool summary over denial text that needs redaction is omitted with a notice.
- A compaction record may list recent Workspace files, newest first, with SHA-256 digests derived from successful committed Write, Edit, MultiEdit and ApplyChangeset observations; replay rejects a list that differs from those facts. The next Run receives them under `Files changed before compaction; Read them for current content` as untrusted data, never reading files implicitly, using only spare capacity after summary and history.
- Compaction admission follows [Execution](./execution/admission-and-recovery.md#admission-persistence-and-recovery); Goal compaction is charged to the Goal's Provider-call budget, and a rejected attempt makes no Provider call.
- `/compact` runs only while idle and shows its Provider usage. After a successful attached Run, automatic compaction triggers at 80% context pressure with at least 10% compactable history, at 24 of [the generated history Run limit](./limits.md#max_history_runs) selectable Runs, or when history approaches [the generated compaction input limit](./limits.md#max_compaction_input_bytes). A visible warning precedes one attempt per committed boundary, and Workspace input alone never triggers a call or a stale retry.
- A failed boundary is not retried automatically; manual `/compact` stays available. History that exceeds the source bound rejects before Provider egress. `exec` makes no hidden post-Run Provider call.
- A snapshot mismatch, a fork outside its covered prefix, an incompatible Provider item or a deleted source invalidates the snapshot and fails closed, leaving canonical history available.
- Cross-Session Memory is a different product: Session history never silently becomes durable Memory. Future retrieval requires explicit project or tenant scope, caller authentication and authorization before retrieval and prompt assembly, and cannot widen the authority fixed at [Workspace admission](#workspace-admission-and-authority).

## Roster recovery and compaction

Resuming a roster-bound interrupted Goal requires an explicit `--profile` with the same normalized selection, plus fresh credential, consent and destination admission; an omitted selector or drift refuses before Workspace content or inference, with guidance to restore the preset or start a new Goal. New Goals may choose another preset. Explicit resume creates fresh Run and AgentRun IDs; no historical actor is rebound, and replay grants no consent.

The [Provider roster contract](./provider/selection.md#named-roster-presets) owns the submission snapshot and selector; there is no Session preset default. Compaction of a roster Run re-admits its exact pinned compaction role under current authorization, never rereading a changed roster. Failure or cancellation preserves canonical history and the last good summary.

## Persistence facts

- Every canonical Event carries `session_id`; Run and AgentRun scopes are optional for Session-only Events. Session lists may use rebuildable indexes, never as a second source of truth.
- Session creation, default, rename, fork and compaction facts and Run and AgentRun lifecycle facts are persisted; terminal focus, panel state, hover, picker selection and scroll position never are.
- Replay labels an unfinished final Run `Interrupted`; a later `MessageAccepted`, idle `SessionRenamed` or idle `SessionDefaultChanged` seals it, keeping its committed facts. Only one Run is active per Engine, and busy Session operations fail before Workspace content or Provider disclosure.
- Replay rejects Tool histories with missing receipts, widened limits, duplicate results or work continuing after an uncertain or cancelled effect. The [execution contract](./execution/events-and-outcomes.md#committed-event-stream) owns Tool ordering.
- `ProviderCallRecorded` stores the bounded outcome, response ID, provider-reported usage, optional accepted wire provenance and an optional closed failure reason, never upstream text, raw statuses or account authority. Absent usage is unknown, not zero; a rejected or timed-out call has unknown provenance. Provenance reports a local request control and an accepted wire completion, never a Provider privacy guarantee.
- Usage totals count each Provider call, failed attempt and compaction once, across roles, as known input, output, cache-read and cache-creation sums plus unreported counts, attributed to the route actually used. A failed attempt stays unreported, and open reservations keep totals incomplete after interruption. Totals stay within the [generated Session Event limit](./limits.md#max_session_events); forks keep inherited usage separate. Inspecting usage creates no Event, reads no credential and dispatches nothing.
- Plan-window observations are kept per account selection, Provider/model and Run, within the [generated Session Event cap](./limits.md#max_session_events), never summed, the newest receipt winning; an invalid later sample keeps the previous one, qualified. Reopening never fetches limits. [Terminal](./terminal/conversation.md#reported-usage) owns their labels.
- API rate observations are separate from plan windows and token sums, grouped by Session, Run, actor and role; environment-key observations never aggregate across Runs. The [Provider](./provider/routing-and-usage.md#passive-plan-limit-observations) owns rows and parsing. The newest valid receipt wins, and reopen reads no clock, credentials or network.
- `AssistantDisplayRecorded` is display-only: it never supplies `MessageCommitted`, Agent results, Provider context or compaction input, and an accepted answer must match its display checkpoints. Only primary planning and synthesis show the preview, with 64 display Event slots reserved. Cancellation keeps only credential-safe text; cancelled or interrupted replay shows it as incomplete, and failed validation hides it. JSONL export keeps it qualified.
- History, titles, fork lineage and snapshots are sensitive derived state, never authority; Provider state is never the only recovery path.
- Attached draft preflight reads Workspace input locally before the Session exists, with no Events, disclosure or Tool authority, and does not replace Run admission.

The Session store is SQLite opened with no-follow and defensive settings, `trusted_schema` off and `synchronous=EXTRA`, within the [listing read and writer busy bounds](./serve.md#methods). Read-only inspection creates no file. A closed store channel is a store failure, never a successful append. Provider evidence tables are derived caches, never Events.
