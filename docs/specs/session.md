# Sessions

## Scope and related contracts

This contract owns the durable conversation: Session identity, lineage, defaults, context compilation, compaction and the persisted facts that replay rebuilds. A Session is one durable ordered conversation across process exits. A Run is one bounded execution caused by one accepted Message. An AgentRun is one primary or child execution inside a Run.

[Goals](./goals.md) owns task lifecycle, budgets and steering; [Execution](./execution.md) owns Run coordination, accepted outcomes, [effect outcomes](./execution.md#effect-outcomes) and persistence bounds; [Provider](./provider.md) and [ChatGPT](./chatgpt.md) own Provider admission and account records; [Terminal](./terminal.md) owns attached commands and presentation; [Credentials](./credentials.md) owns saved accounts. Editing constraints: [security rules](../../agents/security.md). Native and live evidence gaps: [NEXT_STEPS](../../NEXT_STEPS.md#beta-2-and-broader-release).

## Lifecycle and identity

Live host session approval is scoped to the Engine's Session epoch ([Execution](./execution.md#admission-persistence-and-recovery)); resume, restart, reconnect and fork never revive earlier grants, and historical approvals are evidence only. Host command effects, including a dispatch with no confirmed outcome, appear as non-rewindable in rewind previews and restored conversations; restoring conversation or code does not undo them. [Tools](./tools.md#primary-host-commands) owns command authority.

- Every accepted task belongs to a durable Goal, and each Run is linked to it before its accepted Message. Replay rejects missing linkage and projects unfinished Goals as interrupted, re-executing nothing ([Effect outcomes](./execution.md#effect-outcomes)).
- Resume preserves Session identity; retrying interrupted work creates a new Run ID. Historical agents stay inspectable; no in-memory child is fabricated or restarted.
- Fork creates a new Session from an exact committed Run boundary. Its first Event, `SessionForked`, records the immutable source Session, Run, sequence and prefix digest. Replay resolves at most eight lineage links within the [Session Event cap](./execution.md#persistence-bounds), verifies each canonical Event-prefix digest and includes only inherited committed Runs through the boundary. A missing or changed source fails replay before context compilation. A fork lookup is a hint: the parent is strictly replayed before any Event is disclosed.
- An objective interrupted before `RunStarted` has no pinned Workspace identity. Later completed Runs may still be forked or compacted in their admitted Workspace; compaction carries the old objective as unanswered data, and a fork inherits only committed terminal Runs.
- A new Session's start Event pins its admitted Workspace identity before the first Run; every later Run and fork must match it.
- `--continue` selects the Workspace's Session with the greatest committed Event sequence through exact-ID resume. Discovery reads canonical Events, never directory names or a mutable index; malformed history fails rather than selecting an older Session.
- The `/resume` picker lists only canonical heads bound to the admitted Workspace, newest committed activity first, at one Event watermark across all pages. Choosing a row runs exact-ID resume and does not switch if replay or Workspace revalidation fails.
- Paged Engine discovery requires a positive limit; zero returns `InvalidRequest` before Workspace admission or Store access.
- `SessionView.title` keeps the canonical creation or rename text; the readable name is a projection needing no rename Event. Replay keeps explicit-title provenance, even for placeholder-looking names. Without a non-placeholder created or renamed name, discovery titles a Session by its first accepted user objective, bounded; an empty conversation shows the empty placeholder. A fork keeps its inherited title until its first local objective. Times come from canonical Event timestamps. Titles cost no Provider call or rename Event.
- Attached resume keeps configured defaults. Without an explicit selection it recovers the latest Run's tuple, then the current user default; an account-only selection restores only its same-account tuple. Inheritance is persisted before switching, and collaboration policy is preserved. Replay and preferences never authorize a replaced account or a billing fallback.

## Session commands

- Bare `arany` opens a local unsaved conversation. Attached startup, `/new` and `/clear` create the durable Session only at the first task submission after local selection validates. Local commands, setup, rename, model changes and draft edits keep it unsaved; exit or resume discards it without Events or a resumable ID.
- Explicit Engine creation and forks are durable; existing empty Sessions stay readable. `--resume` opens an exact Session or the picker, and `--fork` creates a Session at a committed boundary.
- Interactive commands are `/resume [SESSION_ID]`, `/new` (alias `/clear`), `/fork`, `/rename`, `/compact`, `/status` and `/usage`. `/new` copies the current next-Run defaults, not startup preferences, title or history, and keeps the account identity without loading credentials or renewing evidence; Run admission still revalidates. The first submission persists the explicit title and defaults before Run admission. A failed admission after submission may leave a retained Session, with no rollback and no guaranteed Message acceptance.
- Sessions are never resumed implicitly from the current directory. A draft or active Run must be handled explicitly before switching.
- Provider, model, effort, profile, permission grants and collaboration defaults change only between Runs. Attached dispatch approval mode may narrow the same pinned grant between effects without rewriting defaults or an outstanding intent. `RunStarted` persists the resolved values with explicit nullable fields; missing fields reject.
- A saved native API account is selected by UUID in Session defaults, never by replayed credential bytes. The CLI resolves the UUID and exact Provider against the current protected account before any Run or catalog access, so a replaced account makes an older selection unavailable instead of switching billing identity. `RunStarted` pins the saved-account UUID as explicit nullable provenance; when present, replay requires a native Provider and a UUIDv7.
- ChatGPT defaults pin the account UUID without a token. Each Run and compaction records the account UUID, opaque admission fingerprint, closed admission category and local-only output bound. Strict replay validates that combination but never turns history into current account authority.
- `exec` creates one Run and exits by default; appending to an existing Session requires an explicit Session ID.

## Collaboration policy

Each Run pins one collaboration policy before it starts. `SessionDefaultChanged` records a complete validated next-Run selection only while idle, and every Run re-admits its selected Provider before Workspace input. [Execution collaboration](./execution.md#collaboration) owns children, capacity, cancellation and the meanings of `single`, `auto` and `team`.

## Workspace admission and authority

A Workspace is hostile before admission. Trusted user and process configuration and private State admission precede repository input. Admission pins an opened directory identity and immutable input digests, never a path string or worktree metadata alone. It executes no repository or Git configuration, hooks, filters, fsmonitor, plugins, package managers, test discovery, startup commands or repository code.

Instruction files load from the Workspace root down to the launch directory, at most one per directory, preferring `AGENTS.override.md`, then `AGENTS.md`, then `CLAUDE.md`, as in Codex CLI. As in Codex and Claude Code, names are opened as given; a case-insensitive volume may serve `agents.md`, which grants nothing because the repository author controls every candidate name. The launch directory is the working directory of `exec` and attached chat when it resolves inside the Workspace; otherwise, and for `serve` and `acp`, only the root is read. Codex starts at the nearest `.git` ancestor, reads configured fallbacks and follows links; Arany never reads above the admitted root, opens every path from the root handle without following links and has only the `CLAUDE.md` fallback, because only the root is disclosed and no trusted setting names others. A linked, hard-linked or non-regular instruction file, or a link swapped into the path, rejects the turn; a directory removed after resolution ends the walk. The walk covers at most 32 directories, root included, and all files share one 64 KiB<!-- unrelated-bound: project instruction file budget --> budget (Codex: 32 KiB<!-- unrelated-bound: Codex project instruction budget -->). A deeper launch directory, an over-budget total, or source pins pushing `RunStarted` past the [default Event payload bound](./execution.md#persistence-bounds) reject the turn with `InputTooLarge` before any Provider call or Event. Codex silently truncates instead, which can cut a rule unseen; rejecting keeps pinned digests equal to the bytes the model follows.

Instructions and explicit includes are bounded immutable no-follow snapshots. Instruction files reach the primary and every child as the first user-role message, one block per file, root first: `# AGENTS.md instructions for PATH`, a blank line, then the text between `<INSTRUCTIONS>` and `</INSTRUCTIONS>` lines. PATH is the Workspace-relative path on one inert line, with control characters and Unicode line and paragraph separators as Rust escapes (`\n`, `\u{1b}`) and tag-like `<` as `&lt;`. In the text, a `<` beginning an opening or closing `instructions` tag (any case, any whitespace) becomes `&lt;`, and a line starting with a `# AGENTS.md instructions` heading (any case) gets a leading `\`. Each file is behavior rules for its directory tree; deeper files win over shallower ones, and direct user and system instructions win over both. `RunStarted` pins each file's [source and raw SHA-256](./execution.md#admission-persistence-and-recovery) and the launch directory, never instruction text; replay never rereads the files.

Agent definitions, worker assignments, explicit includes, other repository content, Skills, prompts, model output, Tool or MCP output, Memory and replayed Events are labelled data. None of it, instructions included, is authority: it never changes Policy or selects or widens trust, permission, approval, sandbox, Provider or update modes, roots, endpoints, credentials, executables, budgets or capabilities. A future restrict-only instruction policy may only narrow. Authenticated user or administrator configuration fixes authority before untrusted input; models and classifiers may only raise risk or narrow. [Tools](./tools.md#folder-trust-and-approvals) owns path and scope admission; [Credentials](./credentials.md#account-scope-and-identity) owns private directory admission.

The selected State directory's `AGENTS.md` holds the user's defaults for every Workspace using that State, like Codex's `CODEX_HOME/AGENTS.md`. `--state-dir` and `ARANY_STATE_DIR` select it; no other home or `~/.config` location is searched, and there is no global override or `CLAUDE.md` name. It is a private State record under [credential admission](./credentials.md): at most 64 KiB<!-- unrelated-bound: user instruction file cap -->, regular, single-link and private-mode, opened no-follow and read-only. Its cap is separate from the project budget, as in Codex. Absence is allowed. An unsafe or oversized file, a link, a read failure or non-UTF-8 text rejects the turn with the State error (or `InputNotUtf8`) before any Provider call, with no truncation, repair or fallback. It renders first as `user AGENTS.md`, without a host path; project files follow, and the model is told they win over it while it wins only over defaults, below direct system and user instructions. All instruction blocks together must fit the compiled-content ceiling or the turn rejects with `ContextTooLarge`. `RunStarted.user_instruction_digest` pins only its raw SHA-256, never its text or the State path; it is null when the file is absent or the Run predates the field, and migration never reads the file. Each new Run, including after resume or fork, snapshots it again; replay, show and historical compaction never reread it. It survives child work and in-Goal compaction as the first `project_instructions` entry, and is behavior text, never authority.

## Worker identity and explicit reassignment

An explicit editor assignment may name an exact historical child AgentRun ID in `resumes`. The source must be a terminal or interrupted child of the same Goal in this Session, with its lease released or its Run closed. Unknown, primary, active and other-Goal IDs reject before child disclosure; an active ID stays inspectable but cannot gain a second runner. `supersedes` records an explicit replacement. Both are lineage data, never permission or a retry instruction.

Each accepted reassignment gets a new UUIDv7 AgentRun ID, current definition admission, grant and Run-scoped lease. The source contributes its objective, summary and at most 2 KiB<!-- unrelated-bound: selected child report excerpt --> of report (each within its journaled limit, about 7 KiB in total), plus bounded typed disposition, publication, verification, lineage and observation-derived changed-path facts, as untrusted task data. The changed-path list has its own [report bound](#worker-replay). No historical Tool steps, private bytes, permission, approval or lease carry over. This is an owner-accepted divergence from Claude Code's retained-worker continuation.

## Worker replay

Strict replay reduces committed assignment, Workspace Tool intents and observations, editor outcomes, causal lease release and primary verification without running a Provider, parser, Tool, cleanup or publication. It never rereads definitions or loads private worker bytes. [Journal migration](./execution.md#journal-migration) rejects retired transport and handover vocabulary before replay. Unsupported versions, missing required nulls, duplicate or unknown fields, forged private transitions and changed causal references reject without modifying history.

An interrupted editor keeps landed Workspace receipts and checkpoints. Its unfinished or [Uncertain](./execution.md#effect-outcomes) writes block Goal continuation exactly like primary writes. No lease or runner crosses the Run boundary; reassignment grants fresh authority instead of retrying a historical effect. [Goal recovery](./goals.md#worker-accounting-and-verification) owns continuation.

Historical projections contain Run and assignment identities, resumes/supersedes lineage, disposition and cause, Workspace publication certainty, lease release, verification and bounded report text, never private integration, discard or cleanup fields. Editor reports also list changed paths and latest after-digests, derived only from successful, attested committed Workspace publications, including command changesets; a deletion has a null after-digest. The list is bounded by [MAX_EDITOR_CHANGE_REPORT_BYTES](./limits.md#max_editor_change_report_bytes), emits complete JSON rows with an explicit omission notice on overflow, and is labelled untrusted. It accompanies the bounded answer in primary context, historical context, compaction and inspection, including after cancellation, pause or interruption. Model text never supplies these facts or any authority. `show` keeps qualified child Tool Events under their AgentRun; JSONL stays the canonical Event stream.

## Rewind planning and replay

The pure rewind planner uses only strictly replayed lineage facts. A checkpoint is the exact `RunStarted` or `WorkspaceRewindStarted` position. For each path published from the checkpoint through the head, the plan restores the first publication's before state and expects the last publication's after state, including byte length and executable bit or absence. It omits net no-ops, marks mismatched intermediate states as history drift, and marks a skipped or [pruned](./tools.md#checkpoints-and-rewind) first pre-image unavailable. It covers typed edits, integrated command changesets, editor Workspace mutations and restored rewinds; inherited prefixes participate, parent suffixes outside the fork do not. A restored rewind publishes its reversed effective plan, so a later plan can undo it.

The planner enforces the [rewind file, version, content and encoded-transfer bounds](./tools.md#checkpoints-and-rewind) and rechecks selections after replacing observed preconditions. Scratch follows the 10,000-publication lineage bound (at most 2,048 path facts per publication) and three non-rewindable facts per Tool, materializing one publication at a time. Net no-ops are removed before effective file and byte limits apply; overflow rejects the whole plan. Kept and overwrite selections must be sorted, distinct, disjoint subsets of the plan; unavailable paths can only be kept. A selected history-drift path requires an explicit observed overwrite precondition. Open or Uncertain Workspace publications or rewinds between checkpoint and head block code restore. Unguarded commands, MCP calls, cache publication or uncertainty and created directories are listed as non-rewindable. Planning reads no Workspace, checkpoint store, clock, Provider or Git.

Started recomputes and selects the canonical plan, requiring exact head, prefix and plan digests, Workspace identity, counts and bytes, no blocker and a nonempty effective plan. Like an idle rename, it seals a crash-left unfinished predecessor Run and pauses its Goal; this grants no authority to interrupt a live Engine operation. Duplicate IDs and an open earlier rewind reject. Finished must immediately match its Started and the [attestation and capture rules](./execution.md#workspace-rewind-events). At EOF an unfinished rewind projects as Uncertain; any later fact seals it as Uncertain and forbids a delayed Finished, inventing no Event or receipt. A later Run checkpoint does not cross an older uncertainty. Replay never republishes, reads stored pre-images or reruns a fork.

Later context, compaction and Goal reports get the newest eight rewind lines (count, target, outcome; at most eight JSON-escaped paths and 4 KiB<!-- unrelated-bound: rewind context line --> per line) and an explicit omission marker, as untrusted history with no authority. A rewind advances the between-Run compaction boundary (keeping the last Run identity), so the exact prefix digest covers the new facts; stale pre-rewind snapshot boundaries reject. Histories without rewind facts compile byte-identically. Forks inherit rewind history through their committed boundary, never Goals or permissions. Runtime code restore follows [Tools](./tools.md#checkpoints-and-rewind); the [terminal](./terminal.md#rewind) and [serve](./serve.md#rewind) own user-facing controls.

### Conversation rewind

`Engine::fork_session_at` accepts an exact earlier committed `RunFinished` sequence in the source's replayed lineage and refuses a non-boundary target before writing. The Store selects the ancestor owning that Run, pins its Session, Run, sequence and canonical prefix digest, and revalidates the pin in the fork transaction. Parent suffixes are excluded: later parent appends leave the pin unchanged, while prefix drift or a missing ancestor fails closed. Strict replay validates the prefix through the unchanged `SessionForked` format, executing neither rewind step.

`Engine::rewind_conversation` forks at the committed boundary ending the predecessor of the Run whose prompt is restored; the source Session stays intact and resumable. Selecting the first prompt instead returns an unsaved conversation with the current next-Run defaults and no durable ID or Event, as for [new conversations](#session-commands). The result carries the complete canonical prompt, up to the [generated user-message limit](./limits.md#max_user_message_bytes), and that Run's validated image attachments. The attached terminal restores both to its editable draft without submitting ([Terminal](./terminal.md#paste-and-attachments)); serve signals `images_omitted` because its wire result carries no image bytes. A durable rewind fork also returns the source's current next-Run defaults for the client to keep. Inherited Runs and valid compactions follow the selected prefix; Goals, their budgets and permissions never become resumable fork state.

Ancestor-owner selection avoids unnecessary lineage links. A fork past the [lineage bound](#lifecycle-and-identity) is refused before any Event, with guidance to start a new Session; code-only restore stays available. The first prompt needs no lineage link. The Engine operation slot and the Session and ancestor locks cover selection through completion, with fresh Workspace identity admission and no inherited authority. A client confirmation can pin the source head sequence and prefix digest; a changed pin rejects under those locks before any fork.

`Engine::rewind_both` consumes the same confirmed code preview, preflights the fork and reserves code and fork Event headroom before Started, then restores code first. Only an acknowledged committed `WorkspaceRewindFinished` with outcome restored permits conversation restoration. A code refusal, failure, cancellation, Uncertain result or lost completion never forks; the result keeps the exact code outcome and an unchanged conversation status. If the fork then fails, the result keeps the restored code receipt and reports “Code restored; conversation unchanged; restore conversation separately.” Cancellation after restored code leaves the conversation unchanged. A crash between Finished and the fork leaves only restored code; reopen never completes or retries the conversation step. A fork transaction commits wholly or leaves no fork.

Claude Code branches the transcript, Codex writes a rollback marker and OpenCode reverts in place; Arany creates a new Session ID per conversation rewind to keep the source append-only and replay, compaction and Goal semantics unchanged. The cost is a new ID and the eight-link lineage cap; an in-session marker waits until dogfooding reaches that cap.

## Context and compaction

Context compilation is a pure, deterministic function of committed local Messages, Events, instruction snapshots, exact budgets and the selected Provider capability snapshot; it reads no clock, randomness or Provider-hosted state. Provider-hosted conversation IDs, prompt-cache keys and opaque compaction items are accelerators, never canonical history.

Only the Provider renderer turns a typed request into the conversation: it alone decides what is `system` (a closed set), what is user input and what is labelled untrusted data. Base system prompt text is loaded byte-for-byte from `prompts/` files. Everything before a Run's loop is byte-stable for that Run; each later request is the previous one plus appended blocks, and clearing and compaction are the only rewrites.

- Explicit include data carries an escaped relative path, SHA-256 and untrusted snapshot text. A file keeps its raw-byte digest and 128 KiB<!-- unrelated-bound: explicit include file cap --> ceiling. A directory, with or without a trailing slash, opens from the pinned Workspace handle without following links or crossing devices; protected path components reject before disclosure. It contributes a sorted immediate-entry listing labelled `Directory`, with JSON-quoted names and a trailing `/` on directory entries, never file bodies or recursive contents. Protected, linked, cross-device and special entries are omitted. The listing scans at most 8,192 entries, keeps at most 64 names and fits in 16 KiB<!-- unrelated-bound: directory include listing cap -->, including an explicit `[truncated]` line on overflow. Its digest pins the exact listing bytes, so changing only a child's contents leaves it unchanged. File and directory snapshots share the 16-include and 256 KiB aggregate content ceilings. The full envelope counts toward the context budget; replay never rereads a listing. Historical Tool context names its previous-Run scope and never forbids fresh inspection.
- Recorded steering enters later-Run history and compaction through the same user-text projection, with actor-labelled child notes; text without a child note stays byte-identical. The [Goal steering contract](./goals.md#steering-notes-and-pause) owns quotas and non-redelivery.
- With Tools enabled, optional history and summary selection leave room for the catalog, the largest bounded primary-route turn, one full Tool result and step feedback. Explicit inputs keep the existing admission ceiling; when they prevent that reserve, only the actual continuation capacity is available. Every new Run recompiles the selection, including after `ToolContextFull`, so a failed Run never permanently consumes the next message's allowance. Selected Run IDs and excluded counts stay pinned in `RunStarted`; canonical history stays intact.
- Past Tool attempts and results, including those of failed and incomplete Runs, enter history and compaction only as bounded untrusted facts. Without an observation, a proposal-only Tool projects as `not dispatched; proposal only` and a started Tool as `uncertain; never replay`. Historical Tool facts never execute or renew approval ([Effect outcomes](./execution.md#effect-outcomes)). Active-Goal compaction covers only an acknowledged primary Tool prefix of its exact Run, preserves all canonical observations and leaves the completed-Run `ContextCompacted` proof unchanged. Children continue under their [Goal reservations](./goals.md#lifecycle-budgets-and-recovery); the compaction reservation blocks the primary's next call. Images contribute metadata, not pixels.
- Failed, cancelled, interrupted and hook-stopped Runs without model Tools also enter recent history as `previous_run (historical, untrusted)`: the objective and a typed unanswered status derived only from committed Events, with the last primary call's disposition and closed failure reason when recorded. An absent reason stays unknown; history never infers an unjournaled refused operation or cause. These turns share the existing history-Run and context-byte budgets. A refused primary proposal is reported as nothing dispatched.
- The previous Run's failure enters the next Run as a fixed-size trusted harness notice derived only from committed Run, Goal and primary Provider-call facts: the closed Run stop (failure, projected budget exhaustion with its dimension, cancellation, pause, hook stop, interruption or uncertainty), the last non-review call disposition, and the nullable Provider failure reason and proposal-refusal cause. A successful Run continuing a running autonomous Goal gets no notice. The notice is independent of optional history selection and compaction, including after Tool use. Missing details stay unknown; no Tool output, error prose, objective, private path or model-authored explanation enters it. With the [outcome correction notice](./provider.md#structured-outcomes-and-tool-encoding) it is bounded to 1 KiB<!-- unrelated-bound: Provider correction notice reserve -->, reserved in context admission before optional history selection. The correction notice trails the single corrective request, so the system prefix stays byte-stable; previous-Run feedback stays pinned for that Run. Neither notice authorizes repeating an effect ([Effect outcomes](./execution.md#effect-outcomes)).
- Before reserving the next primary call, the Engine projects Tool context plus the next bounded Provider turn, Tool arguments and one full [generated per-call result budget](./limits.md#max_tool_result_bytes). If that next-turn reserve alone exceeds the Tool allowance, the projection uses half the allowance; actual Tool admission still enforces the full effect receipt or remaining pageable-read capacity. When the projection exceeds the allowance or reaches two-thirds pressure, the Engine first clears older results on whole-step boundaries, keeping at least the three most recent; clearing costs no Provider call. This follows Claude Code's clear-before-summary policy and three-result retention; Arany also commits the rewrite boundary for journal-first replay ([Event contract](./execution.md#admission-persistence-and-recovery)). If clearing frees less than one result budget, the Engine attempts charged summary compaction over a whole-step prefix whose replacement leaves the next-turn reserve or, when the pinned prefix prevents that, against the actual allowance. A compaction prefix already attempted is not retried.
- If maintenance cannot free the full reserve, a request whose actual context fits still proceeds: the model may answer, and a later Read, List, Search, Glob, Skill or typed Git read gets the remaining rendered capacity, capped at the [generated Tool result limit](./limits.md#max_tool_result_bytes) and pinned in its intent before dispatch. Effectful calls need the full [generated Tool result allowance](./limits.md#max_tool_result_bytes) and otherwise refuse with `ToolContextFull` before dispatch, preserving publication receipts and their rewind pre-images. Internal changeset publication keeps a fixed 128-byte allowance for its applied-count result. Read results page or truncate with their markers; Skill text uses the Tool contract's marker. Clearing and charged compaction run only at a settled boundary before the next primary call; a new Tool request that cannot fit refuses before dispatch without inserting maintenance into the pending step, and a recorded plan reaches that boundary before any capacity refusal. Only an actual request or Tool envelope that still cannot fit stops with `ToolContextFull`. Canonical observations and committed Events are never discarded to make room.
- The compiled-content ceiling is [the generated default](./limits.md#max_context_content_bytes) unless every primary route has trusted window metadata: a ChatGPT catalog `context_window` selected during [account admission](./chatgpt.md#catalog-checks-and-runs), or fresh Anthropic `max_input_tokens` from a checked Models API row ([Provider](./provider.md#per-role-selection-and-fallback)). Then it is the smaller of [the generated hard ceiling](./limits.md#max_window_content_bytes) and `0.9 × window × 3 bytes` for the chain's smallest window, which `RunStarted.config.context_window_tokens` pins. Native OpenAI and custom routes have none; a window outside 32,768–2,000,000 tokens counts as absent. A primary call reporting input tokens at or above 90% of the pinned window triggers the maintenance above before the next call, once per report, even below two-thirds pressure. Replay rejects a budget or Tool receipt above the ceiling the pinned window allows. The window comes only from authenticated catalog evidence, never Workspace content or model text, and only resizes budgets within the hard ceilings. Like Codex (catalog `context_window`, compaction at 90%), Claude Code and OpenCode, Arany compacts near the window, but assumes none for unknown routes (OpenCode assumes 200,000 tokens) and counts 3 bytes per token, not Codex's 4.
- A cleared result is untrusted data shaped as `{operation, call, disposition, effect, cleared: true}`, where `operation` is the fixed placeholder `Result cleared to save context; call the Tool again for current content`. Call, disposition and effect facts remain, including private-target facts and `uncertain; never replay` for uncertainty. The result body and its hook feedback return to requests, history or summary input only through a fresh Tool call, also after reopen. Clearing never changes the invoked Skill, plan, Goal facts or pinned prefix. Canonical Events stay intact; clearing is not deletion or redaction.
- Compaction never deletes or replaces canonical history. It creates a digest-bound derived snapshot over an exact Session prefix, with author, Provider, model and local semantic-schema provenance.
- A manual compaction summarizes accepted Run outcomes after the latest valid summary, including unanswered failed, cancelled or interrupted objectives as data. `ContextCompacted` records provider-neutral model-authored text or a typed failure; replay checks the source and content digests and the version before a later Run selects it. A failed attempt keeps the last good summary.
- The accepted summary is complete non-whitespace plain text within the [generated summary bound](./limits.md#max_compaction_summary_bytes), requested with the [generated output token bound](./limits.md#max_compaction_output_tokens) and further limited by the selected Provider. It is kept byte for byte and rendered as untrusted model-authored data; Session and Tool-history summaries sit in one JSON object with a fixed untrusted scope and add no system content. Neither JSON-looking text nor summary claims change typed approvals, uncertainty, Tool receipts, budgets or Goal completion. The [Provider contract](./provider.md#structured-outcomes-and-tool-encoding) owns framing and rejection.
- Compaction record versions `(prompt_version, schema_version, compiler_version) = (1, 1, 5)` identify the local summarization task, semantic summary schema and source projection, not an HTTP output schema or remote enforcement. The current source compiler excludes raw permission-denial prose. Records from older compilers stay canonical provenance, but their Session summaries are not selected; the current compiler rebuilds context from canonical Runs. A sanitized decline does not invalidate a current summary. An older Tool summary covering denial text that needs redaction is omitted with a notice; its canonical observations stay inspectable. Summary strings, digests, wire and account provenance and output-bound categories keep their persisted meaning.
- A compaction record may carry bounded recent Workspace files, newest first and de-duplicated by path, under the [compaction record persistence contract](./execution.md#admission-persistence-and-recovery). The Engine derives their SHA-256 digests from successful committed Workspace observations of Write, Edit, MultiEdit and ApplyChangeset by the primary and editors within the covered prefix. Replay rejects a nonempty list that differs from those derived facts; records omitting the optional field stay valid. The next Run receives the paths and digests under `Files changed before compaction; Read them for current content` as untrusted data; files are never read implicitly, and a mismatch with current content does not block the hint. The newest uncovered Run with in-Run compaction hints also offers its paths and digests, even with no Session compaction selected. File hints use spare capacity after summary and recent history selection; omitting a hint never drops the selected summary or history.
- Compaction admission follows [Execution](./execution.md#admission-persistence-and-recovery); Goal compaction is charged to the Goal's Provider-call budget, and a rejected attempt makes no Provider call and appends no attempt.
- `/compact` runs only while idle and shows its Provider usage. `RunStarted` records the selected context-content bytes, compactable history bytes, the policy-adjusted budget and the nullable `context_window_tokens` that sized it. After a successful attached Run, automatic maintenance triggers at 80% context pressure with at least 10% compactable history, at 24 of [the generated history Run limit](./limits.md#max_history_runs) selectable history Runs, or when compactable bytes approach [the generated compaction input limit](./limits.md#max_compaction_input_bytes). The source-pressure guard reserves two maximal canonical turns, derived from the shared Message and image-metadata limits; no cap is raised to make maintenance pass. A visible warning precedes one attempt per exact committed boundary, and Workspace input alone never triggers a call. Automatic maintenance accepts only the expected Run ID under the Session lock and skips a boundary that already has an attempt, so a stale warning cannot become a Provider call.
- A failed boundary is not retried automatically; manual `/compact` stays available. Unmaintained or failure-heavy prefixes that exceed the source bound reject before Provider egress. `exec` makes no hidden post-Run Provider call.
- A snapshot mismatch, a fork outside its covered prefix, an incompatible Provider item or a deleted source invalidates the snapshot and fails closed. A non-current source compiler invalidates only summary selection; canonical history stays available for the current bounded projection.
- Cross-Session Memory is a different product: Session history never silently becomes durable Memory. Future retrieval requires explicit project or tenant scope, caller authentication and authorization before retrieval and prompt assembly, and cannot widen the authority fixed at [Workspace admission](#workspace-admission-and-authority).
- A step declares its model Tool requests on its `ToolRequested` record. `ToolStarted` needs a declared request not yet started, a continuation needs every declared request observed, and a compaction prefix ends on a whole step, counting model Tools only.

## Roster recovery and compaction

Resuming a roster-bound interrupted Goal requires an explicit `--profile` with the same normalized selection digest, plus fresh credential, consent and evidence admission. An omitted selector or drift refuses before Workspace content or inference, with guidance to restore the preset or start a new Goal. Selection metadata is compared, never expiring evidence fingerprints. New Goals may choose another preset. Reopen reduces interrupted work without dispatch; explicit resume creates fresh Run and AgentRun IDs with chains starting at index zero. A trailing accepted Message without `RunStarted` does not erase the last pinned selection. No historical actor is hot-rebound, and replay grants no consent.

The [Provider roster contract](./provider.md#named-roster-presets) owns the submission snapshot and selector; there is no Session preset-default record. Automatic and manual compaction of a roster Run re-admit its exact pinned compaction role and provenance under current authorization and evidence rules, including when all role chains use the inherited representation. They never reread a changed roster to choose a destination or admit unrelated profiles. Ordinary inherited-mode compaction keeps its existing selection. Failure or cancellation preserves canonical history and the last good summary; `exec` adds no hidden maintenance call.

## Persistence facts

- Every canonical Event carries `session_id`; Run and AgentRun scopes are optional for Session-only Events. Session lists may use rebuildable indexes, never as a second source of truth.
- Session creation, default, rename, fork and compaction facts and Run and AgentRun lifecycle facts are persisted. Terminal focus, panel state, hover, picker selection and native scroll position never are.
- Replay labels an unfinished final Run `Interrupted`. A later `MessageAccepted`, idle `SessionRenamed` or idle `SessionDefaultChanged` also seals that predecessor, keeping observed calls, terminal agents and committed Messages, and rejects later facts for the abandoned Run ID. Only one Run is active per Engine. Session operations are exclusive under the per-Session lock; busy operations fail before Workspace content or Provider disclosure.
- Tool transitions require the pinned policy, Workspace and primary identity, one preceding Tool-requested call, one matched intent per started Tool, one matched result per finished Tool, and aggregate bounds. Missing receipts, widened limits, duplicate results and continued or successful work after an uncertain or cancelled effect reject. The Tool grant and native enforcement profile are pinned before Workspace content. The [execution contract](./execution.md#committed-event-stream) owns proposal, approval, review and dispatch ordering, including proposals without a start or result. Each accepted AI review is pinned to its pending Tool.
- Command changeset integration requires the immediately preceding attested command observation, its exact intent digest and an identical validated changeset. It consumes effect capacity without inventing a model Tool request. Replay rejects changed or missing sources and duplicate integration and keeps both stages as history.
- `ProviderCallRecorded` is an AgentRun fact. Primary planning precedes children, each child call follows the child's previous read-only Tool observation, and primary synthesis follows finished children. A child spawn requires an observed Delegated call, and a successful Agent completion an observed Finished call. The record stores the bounded observed outcome, response ID, provider-reported usage, optional accepted wire provenance and an optional closed failure reason, which must match a rejected or unavailable call and is never upstream text or account authority. Raw error strings, statuses and stream codes are not persisted. Absent usage is unknown, not zero. Nullable provenance is explicit, and omitted fields reject. A rejected or timed-out call has unknown provenance, never inferred from a Provider name. Provenance reports a local request control and an accepted wire completion, never a Provider privacy guarantee.
- The usage projection folds each canonical Provider call, failed retry or fallback attempt and between-Run or in-Run compaction once, across primary, child and review roles, into independent known input, output, cache-read and cache-creation sums plus unreported counts, with checked `u64` arithmetic. Attribution follows the pinned role or assigned profile and the committed fallback at the attempt, never current defaults. A failed retry or fallback attempt stays unreported even if a later attempt succeeds. Open reservations keep totals incomplete after interruption, failure, cancellation or resume: ending a Run does not establish whether an unobserved attempt consumed tokens, and a later call never settles an abandoned attempt. Goal reports and context summaries add no consumption. Groups and unresolved reservations stay within the [generated Session Event limit](./limits.md#max_session_events). Resume continues local totals; forks keep inherited usage separate from new Session consumption, which includes local compaction over inherited history. Inspecting this derived state creates no Event, reads no credential and dispatches nothing.
- Plan-window projections keep at most one pair of observations per pinned account selection, Provider/model and local Run, within the [generated Session Event cap](./limits.md#max_session_events). Identity comes only from existing call and compaction provenance; the numeric snapshot adds no account identifier. Percentages are never summed across calls, actors, models, Runs or Sessions. The newest receipt time wins per slot, with committed sequence breaking ties, so a slower older response never overwrites a newer observation. An omitted or invalid later sample keeps the previous valid windows, qualified as unreported or unavailable. Changed selections get separate Run and route labels. Forks keep inherited observations separately, resume keeps the original facts, and reopening never replaces observation times or fetches limits. [Terminal](./terminal.md#reported-usage) owns historical, age and reset labels.
- API rate projections are separate from plan windows and token sums. They group actual attempt identities by Session, Run, actor and role, including pinned saved-account or custom evidence provenance; environment-key observations never aggregate across Runs. Retry facts use the selected attempt and fallback facts use `from`; replay rejects API/plan mixing or a native dialect inconsistent with its route. The [Provider](./provider.md#passive-plan-limit-observations) owns bounded rows and parsing. The newest valid receipt wins per dimension, with sequence breaking ties; omitted or invalid metadata keeps prior valid rows with a latest-report qualification. Groups share the Session Event ceiling, inherited observations stay separate, and reopen reads no clock, credentials or network.
- A plan-less Tool request opens a plan wait. While it is open, only the plan record, prelude Tool events, explicit resume and Failed or Cancelled `AgentFinished` or `RunFinished` are accepted; `RunFinished` clears the wait.
- Steering notes keep their actor identity in history and compaction input; an interrupted child note stays historical, resume starts without active child notes, and replay never re-delivers a note ([Goals](./goals.md#steering-notes-and-pause) owns scope and quotas).
- `AssistantDisplayRecorded` is a display-only Event, primary or call-scoped. Replay enforces sequential byte offsets, legal active call phases and the terminal contract's per-Run byte, item and chunk bounds, including at most one compiled detail-limit cue. It never supplies `MessageCommitted`, Agent results, Provider context or compaction items. An accepted primary result must match every checkpoint of its final call; delegation and Tool calls cannot accept answer checkpoints. Only primary planning and synthesis calls get the coalescing preview, and its 64 display Event slots are reserved before disclosure. Cancellation flushes only credential-safe text; invalid, rejected or over-limit candidates are withdrawn. Cancelled or interrupted replay shows these facts as incomplete, and a failed validation hides the candidate. Explicit JSONL export keeps the qualified facts.
- History, titles, fork lineage and snapshots are sensitive derived state, never authority; Provider state is never the only recovery path.
- Attached draft preflight reads Workspace input locally before Session materialization, with no Events, disclosure or Tool authority; it does not replace fresh Run admission.

SQLite opens with no-follow and defensive settings, `trusted_schema` off, rollback journaling, `synchronous=EXTRA`, the [listing read and writer busy bounds](./serve.md#methods) and the declared page cap. Read-only inspection creates no file, directory or journal. One owner thread serves a bounded channel of 64 requests; a closed channel is a store failure, never a successful append. Provider evidence tables are derived caches, never Events: malformed or future-dated rows are unavailable.
