# Terminal and output contract

## Scope and related contracts

This contract covers attached chat, local controls, presentation, accessibility and deterministic process channels. It does not certify live accounts, every terminal or native platforms; [Next steps](../../NEXT_STEPS.md) owns open defects and unperformed native, assistive-technology and fault-timing checks.

[Session](./session.md) owns lifecycle and compaction. [Credentials](./credentials.md) own saved-account scope, storage and authorization. [Provider](./provider.md) and [ChatGPT](./chatgpt.md) own model, consent and billing admission. [Architecture](../architecture/system-overview.md#8-terminal-presentation) owns physical responsibilities.

Editing constraints: [security rules](../../agents/security.md).

## Entry, modes and channels

| Entry | Observable contract |
|---|---|
| `arany [PROMPT]` | Requires terminal stdin and stderr. Without a prompt, opens a composer held locally until the first task submission; a prompt starts the first Run only after admission and leaves chat open. Fullscreen, the default, draws on stderr in the alternate screen; Classic uses the primary screen. Redirected or same-terminal output follows [terminal continuity](#terminal-continuity-and-provisional-text). |
| `--continue`, `--resume`, `--fork` | Explicit Session entry; Workspace or TTY matching never resumes work. A missing conversation, or a fork source without a completed Run, fails before the prompt with a message naming `arany --resume` or `/resume` and `--state-dir`. An unsafe State still reports the unsafe-state error. |
| `--profile PRESET` | Explicit private roster selection for attached mode or exec; supplies the primary tuple. Any supplied Provider/model/effort field must match, and a present role-routing record conflicts. No preset is selected or read by default. |
| `--setup` | Resolves folder access before setup or Session creation. Cancellation before account save creates no Session. Idle `/setup` works inside the current conversation. |
| `exec --output text` | Noninteractive; no terminal modes. Stdout holds only the sanitized, indented committed answer; stderr holds the stable Session/Run/status receipt. A failed Run exits unsuccessfully without an invented answer. A hook-stopped Run reports `Status: stopped_by_hook` and `error: Run stopped by hook[: REASON]`. An interrupted or hook-stopped Run whose Goal stays open adds `Goal paused; resume with arany exec --session-id SESSION --resume-goal GOAL` to stderr and exits unsuccessfully. An autonomous Goal that stops after a committed Run keeps that answer on stdout, appends `error: Goal stopped after a committed Run: REASON` to stderr and exits unsuccessfully. |
| `exec --output jsonl` | Stdout holds the latest Run's committed Events, its matching Goal's lifecycle and final report, and the new Session fact, if any ([Goal selection](./goals.md#current-format-replay-and-exec)). Successful non-roster JSONL leaves stderr empty; roster mode first writes its complete route manifest there. An interrupted Run keeps its committed Events and adds the same pause line to stderr. |
| `acp` | [ACP spec](./acp.md) owns the editor subprocess, capabilities and core text turns. |
| `serve --stdio`, `generate-schema [--out DIR]` | [Serve spec](./serve.md) owns protocol framing, schema export and the accepted server surface. |
| `storage [--workspace PATH] [--state-dir PATH]` | Local bounded text inventory without a Provider/account, terminal acquisition or Session. [Storage report](#storage-report) owns channels and availability. |
| `show --output text\|jsonl SESSION_OR_RUN_ID` | Deterministic read-only replay without terminal modes. Validates the UUID before State access, opens only existing State read-only, reads no credential and closes the Store before rendering. Session selection exposes direct canonical Events and the fork reference; Run selection exposes only that Run after strict parent validation. Invalid or conflicting ownership fails without output. Valid history renders byte-identically. If strict replay rejects a selected Session with `InvalidHistory` or `InvalidSnapshot`, inspection scans the whole journal within [the generated Event scan limit](./limits.md#max_list_scan_events); the rejecting fault may lie in another Session. Output then holds the selected Session's direct valid prefix, the typed rejecting sequence and cause, and a per-Event lenient tail with a fixed marker for undecodable payloads; a notice says the projection is read-only and not resumable, and the command exits unsuccessfully. JSONL puts a `notice` object before one object per tail Event. Exceeded scan or replay bounds and Store infrastructure errors fail without output. |
| `show --output supervisor-corpus SESSION_ID` | Session-only calibration JSONL to stdout, without terminal initialization. The [Supervisor adapter](./tools.md#supervisor-adapter) owns format, privacy, replay, locking and overflow. Refusal exits unsuccessfully with empty stdout and a fixed diagnostic (plus safe overflow counts) on stderr. |

Headless `exec` text and JSONL deterministically project reopened committed history; Server notifications never become output lines.

Headless `exec --tools` follows the [host policy](./tools.md#primary-host-commands): eligible admitted host prefixes may run in default/dontAsk, and every unresolved host ask refuses immediately. It cannot create rules or reuse a previous process epoch. Text, JSONL, show and Goal receipts keep the unguarded and non-rewindable effect markers.

The command chooses the contract. An ineligible bare invocation fails before Engine entry and directs the caller to `exec`. Headless objective prefixes such as `/`, `@` and `!` are literal data, except that `exec --tools` and `--prompt` treat `/name [task]` as an invocation when `name` is an admitted Skill and not a compiled command (`serve` has no slash form).

An unavailable stderr sink never turns error reporting or cleanup into a panic, never blocks restoration of surviving terminal settings and never changes the intended exit class. Diagnostics never fall back to stdout. Output failure does not prove delivery of an error, receipt or mode-reset sequence.

`--screen-reader` or `ARANY_SCREEN_READER=1` selects labeled append-only output with canonical input, without raw mode, cursor rewriting, boxes or animation. `TERM=dumb`, fewer than eight rows or unavailable geometry selects that fallback before acquisition. Resizing never switches presentation; only an explicit idle `/settings` chat-view change switches Classic or Fullscreen ownership.

`--no-color` and `NO_COLOR` remove color, including after reacquisition; text labels, selection markers, focus and bracketed hints keep their meaning. Action and consent alternatives occupy separate vertical rows; horizontal button groups are not admitted. Message bodies are unstyled except recognized leading slash tokens and the assistant Markdown projection below. Inline role headings are emphasized `› You:` and `● Arany:`. A two-cell rail groups nonempty user-body rows, assistant bodies keep plain indentation, and existing spacing separates messages without extra indexed rows. Restored user previews use `› You:`; attached committed answers use `Arany · Answer:` and headless `exec` keeps `Answer:`. Linear mode keeps plain role labels without decorative rules. The terminal background stays user-owned.

Human output escapes or rejects ANSI/ECMA-48 controls, OSC sequences, C0/C1 controls, carriage return, backspace, bidirectional controls and forged line prefixes. JSONL comes only from a serializer, one object per line. Inline chat reserves one blank row above the transcript when at least five history rows fit, so a sticky command header cannot cover the first speaker label; with fewer rows, content wins. Linear and deterministic output is unstyled and contains no CSI, OSC or carriage-return rewriting.

Roster selection displays the complete escaped [manifest](./provider.md#named-roster-presets), with native API / ChatGPT plan / exact custom unknown-pricing labels and every fallback, before credential access or Workspace-content loading: on stderr when headless, and again as a notice for each independent attached submission. The selector is the selection action, with no extra picker or confirmation flag; account/plan consent is still required. `/new` and `/clear` keep the process selection. Conflicting `/model` or `/setup` defaults cannot substitute a roster route at next-Run admission; restore the preset tuple or start without `--profile`. Roster-Goal resume requires the matching selector as [Sessions](./session.md#roster-recovery-and-compaction) defines.

## Human-readable measures

Human-facing sizes use one shared formatter across attached, linear, plain and accessible output: below 1 KB, exact bytes (`500 B`); otherwise one decimal KB/MB/GB/TB with a 1024 base (`38.3 KB`), promoting to the next unit when the rounded value reaches 1024.0. This follows Claude Code and Codex. Draft and text counts use characters or lines where those are the defined measure; byte limits keep their meaning and display in these units. JSON/JSON-RPC (`serve`, ACP), JSONL exports including `exec`, journals/Events, schema fixtures and diagnostics keep exact machine units, including integer bytes and milliseconds.

Durations use `h`, `min` and `s`, omitting zero components except `0 s`; fractional seconds keep millisecond precision without trailing zeros: `0.001 s`, `1.5 s`, `2 min`, `1 h 30 min`. Time limits use the same format without rounding away their bounds. Large counts use digit grouping (`12,340 lines`) or explicitly approximate values.

## Conversation, progress and history

Answer headings carry any unguarded and host effect counts.

Attached assistant text (Fullscreen, its pager, Classic and selected agent results) renders a bounded Markdown projection following Codex CLI:

- ATX headings are bold with hidden delimiters; setext headings are bold with the underline hidden.
- Paragraphs, setext headings and table cells decode escapes and entities and style emphasis, strong emphasis and inline code with hidden delimiters. A soft break keeps its source row break and a hard break adds a row. Prose wraps at spaces; long words break at graphemes. An entity decoding to several graphemes is one atomic source group.
- Fenced and indented code, including code nested in lists and quotes, keeps whitespace and line boundaries with plain reverse styling and grapheme wrapping. Fence delimiters are hidden; info strings decode escapes and entities into bold sanitized labels with per-fragment source origins. No lexer is loaded.
- Top-level pipe tables use fitted columns with bold headers and wrapped cells, or header/value records when narrow. Cells decode escaped pipes and entities and style inline emphasis and code; generated labels, separators and padding carry source anchors.
- Inline, reference, collapsed and shortcut links render as underlined `label (destination)`, even when both are equal; autolinks show their URL once. Destinations decode entities and escapes before sanitization and wrap at word/grapheme boundaries; titles and reference definitions are hidden. Links are inert escaped text, with no fetch, open, path resolution or OSC 8.
- Lists and quotes use generated source-anchored markers: `• ` bullets, ordered items counting from the list's start number, and `│ ` quote rails. Wrapped and continued rows keep hanging indents and rails, including nested, empty and code-first items; indentation follows CommonMark tab columns.
- HTML, images, strikethrough, task-list markers, thematic breaks and footnote references stay literal inert source. Messages with lone carriage returns stay literal under control escaping.

Provisional and incomplete answers use the same projection with their qualified headings. Formatting is disposable; canonical Markdown is unchanged. Counting, drawing, find and resize share one layout. Repeated destinations keep distinct selection, reading and find anchors through reflow; a literal match in a definition selects its first rendered use, and stepping visits uses in row order. Code, ATX headings and literal lines keep source line boundaries, wrap at graphemes and use safe replacement at tiny widths. Monochrome keeps heading weight and block structure. Linear/screen-reader output, `exec`, `show`, JSONL, serve and ACP keep source with existing escaping.

The renderer checks [source bytes](./limits.md#max_markdown_parse_bytes) before parser construction, then bounds [event containers](./limits.md#max_markdown_depth), [events](./limits.md#max_markdown_events), [escaped output including decoration](./limits.md#max_markdown_output_bytes) and [rows](./limits.md#max_markdown_rows). Overflow selects whole-message escaped literal fallback plus one formatting-limit cue outside copied source, without truncating the answer or changing its Run. Parser construction precedes event limits and has no hard RSS/deadline guarantee; no AST or cross-Session cache is retained. Tables bound [columns](./limits.md#max_markdown_table_columns) and [data rows](./limits.md#max_markdown_table_rows) before growing the matrix; the parser's upstream empty-cell padding cap applies independently. Emitted fragments, including fence labels, are sanitized after decoding.

Compact Tool rows follow Claude Code's `⏺ Operation(arg)` and indented `⎿ result` shape, without a `Tool ·` prefix or success word. A Fetch row names its URL, a Web search row its query, and a Search row its query and path plus any non-default option, such as `Search(fn \w+, src, regex, include **/*.rs, ignore case, offset 100, limit 10)`. Results give:

- bounded entry or line counts and readable sizes, including truncation;
- command exit status and total lines (`exit 0 · 12,340 lines (truncated)`), then only nonzero selection counters (ignored entries with `(N pruned roots)`, oversized inputs, discarded outputs);
- `applied` for file changes;
- otherwise the disposition and sanitized failure text: `Error: ...` for a failed call, `denied`, `uncertain` and other dispositions by name.

Consecutive successful reads by the same actor collapse into one row worded like Claude Code (`Read 2 files`, `Listed 2 directories`, `Searched for 2 patterns, read 2 files, listed 2 directories`) with combined counts; Git queries, Skills and MCP lists keep their own nouns, and details keep each call. A Command or unguarded command row shows a multi-line script as its first non-blank line plus ` …` when more follow, escaped and bounded, never an escaped line break. Pending, failed, denied, cancelled, conflicting, limited and uncertain calls stay distinct. Failed command rows append at most 80 cells of escaped stderr. Trust-bearing rows never collapse: unguarded, uncertainty, enforcement-cause, checkpoint, denial-source, cache-problem and hook markers stay visible. Cache markers show only rejected, failed and uncertain updates. Limit rows follow the committed closed cause: `timed out after DURATION` (the effective timeout, bounded by the operation cap, with `; /settings raises it` only for Commands), `output passed 1.0 GB; stopped`, `no room left in this Run's context`, `too many reads at once; nothing was read`, `asked for more time than the pinned maximum` or `resource limit reached`. Truncation labels derive from typed totals or limit causes, never from stdout or stderr text. Presentation never changes the [Tool guarantees](./tools.md). Classic and linear output append a read group once its boundary or the Run's end is known. Linear and screen-reader output use the same words, with an operation line and `Result:` instead of glyphs and no rewriting.

An active-Run notice names the unavailable action and an alternative, for example `/model changes are unavailable while a Run is active; Ctrl+C cancels`. View-only commands keep current-value inspection; empty submission says `Run is active; Ctrl+C cancels`. Notices never imply that another action ran.

Failed Run feedback distinguishes an Engine-refused proposal from a Provider-call failure. A committed preflight refusal shows its typed cause (arguments, phase, plan, budget, scope, grant, byte limit, lease, unavailable operation, answer or Delegate) and fixed reason, then `The refused action was not dispatched.`; it is never attributed to the Provider, and JSONL and text `show` keep the canonical refusal Event. A Goal-budget stop uses the [deterministic numeric Goal feedback](./goals.md#budget-refusal-feedback), labelled `Arany status`, including recent bounded Tool failures and preserved-answer wording. Attached, `exec` stderr and text `show` use the same committed facts; `exec` admission-refusal reload uses the shared refusal-record lookup with its looser budget-stop fallback. Receipts render the exact Run reported, even within a multi-Run Goal. Invalid agent definitions, stopped Tool steps, plan admission, unavailable Tool context, unverified workers, unmet criteria and refusal-limit failures each have distinct copy. A failed Run without a committed answer says so; earlier completed actions remain and uncertainty keeps its warning. [Execution](./execution.md#accepted-outcomes) owns the closed causes and journal pairings.

Agent inspection and text `show` use the [Session worker projection](./session.md#worker-replay). Inspection qualifies an unknown Workspace publication and shows the bounded untrusted [observation-derived path/digest report](./session.md#worker-replay), keeping landed edits after completion, cancellation and pause, without appending Events or calling a Provider. JSONL keeps canonical Events, including qualified lineage and refusal reasons; derived interruption facts add no Events or terminal view.

Agent inspection shows only the selected actor's committed Supervisor verdicts; transcript details show every actor's verdicts in the Run. Each verdict is one dim labelled line, wrapping at the cell width without losing words: `Supervisor (shadow): possible loop; no action taken`. Multiple signals share the line; the capped verdict adds `verdict limit reached`. The terminal uses a fixed reduced vocabulary without canonical features or evidence; [serve](./serve.md#notifications-and-items) forwards the canonical privacy-reduced verdict. Linear and screen-reader inspection and `/transcript` use the same words without styling. Nothing displays before commitment, the collection follows the [verdict cap](./execution.md#persistence-bounds) with no notices fabricated past it, transcript details keep their Run and byte limits and overflow cue, compact chat and answers are unchanged, and these lines never enter model input.

A Tool waiting for shared Guard capacity shows `queued · waiting for capacity` in every mode. The hint follows only the current committed pending intent, clears when waiting or the Run ends, never enters Events, history, replay or Provider context, grants nothing and does not survive restart; draft editing and Ctrl+C stay available.

Classic uses native scrollback above a bounded viewport. On its first draw for a Session it projects the newest whole-Run suffix, stopping before a Run that would exceed 16 Runs<!-- unrelated-bound: Classic viewport Run count -->, 64 KiB<!-- unrelated-bound: Classic escaped history buffer --> of escaped rendered row text (including trusted headings, rails and indents) or 4,096 rendered rows. Every native-visible objective, Tool summary and answer is counted before rows are materialized. A width-safe cue points to `arany show`. Omitted Runs stay in the journal, find and export and are not backfilled on redraw. Fullscreen uses an alternate screen with managed history and a bottom composer; Classic never borrows the alternate screen.

OSC 52 is written only on an explicit user copy gesture (Fullscreen selection release, Ctrl+C or Ctrl+Shift+C with a selection, or `/copy`), never because of model, Tool, MCP, Skill, hook or repository content, following Claude Code and Codex. It is output-only: Arany never emits the `?` query and discards inbound OSC 52. Each gesture writes one sequence: the escaped copy payload with C0/C1 controls other than LF and TAB removed, base64-encoded under the fixed `c` selection and terminated by BEL, within the [clipboard copy limit](#public-limits-and-compatibility), written by the terminal owner on stderr and never in linear mode. No mode enables focus reporting or title OSC.

### Terminal continuity and provisional text

The saved `/settings` chat view selects the initial presentation, Fullscreen by default; `--classic` selects Classic for one process without saving. Saving a different view in idle `/settings` switches presentation within the Session, keeping draft, caret and reading anchors; a running task locks mode changes. Following Claude Code's binding, `Ctrl+O` or `/transcript` appends bounded detail text to native scrollback in Classic and opens the [transcript pager](#transcript-pager) in Fullscreen; Ctrl+T does not. Unlike Claude Code's complete dump, both stay bounded with an explicit cue: Classic by the [detail limit](#transcript-detail-limit), the pager's `[` by its whole-Run bound. Details stay available during work without cancelling it or granting authority.

Geometry is bounded to 4,096 columns and 262,144 cells; zero or excessive geometry fails with a typed presentation error. Classic keeps raw ownership while inserting output above its content-sized viewport (at most the screen height) in batches of at most 64 native rows. Cursor queries go only through the stderr backend and the sole raw reader with a one-second deadline; an unavailable reply selects linear fallback before work, unsolicited replies are discarded, and query bytes never enter drafts, stdout or history. Cleanup uses the stored owned area, never queries a stopped reader and never clears settled primary-screen transcript.

Fullscreen follows new content only at the live tail; PageUp/PageDown and find keep older source anchors through generation, completion and resize, and returning live resumes following.

Classic delegates scrollback, selection and copy to the emulator. Like Codex's inline viewport, every Classic surface (idle and streaming composer, completion menus, Tool approval, folder trust, setup, selectors, pickers and rewind) takes min(screen height, content height) with no floor. Selector lists show at most 10 rows, the linear page size, and scroll inside (Codex caps at 8). Growing scrolls the rows above into native scrollback. A height change clears only from the lower of the old and new viewport tops, repaints and flushes pending native history in the same frame. Shrinking keeps the top while history remains above it, so the composer sits under the latest history with no blank rows; rows below stay empty until new output, and a viewport that filled the screen returns to the bottom row. History is never redrawn inside the viewport, so scrollback holds each row once. A dialog taller than the screen pages with Up, Down, PageUp and PageDown, and accepting stays blocked until its last page has been shown. PageUp/PageDown are ignored; Ctrl+F shows `Use your terminal's find; Ctrl+O writes details to scrollback`. A complete 200-line answer stays readable without duplicate final lines or intermediate frames.

Replies stream as source-backed provisional Markdown in one replaceable active location. Following Codex CLI, each changed snapshot or width re-renders atomically with the committed formatting and limits; unfinished syntax uses the parser's current interpretation without invented closing bytes, and growing tables can reflow earlier rows. Only the latest pending snapshot is kept; identical snapshots cause no parse or redraw. Strictly accepted completion replaces the candidate with the confirmed answer, inserted once into Classic scrollback. Compact presentation shows replies and Tool summaries; details add bounded inert operation and result facts and explicitly public model commentary. Reasoning, raw prompts, transport JSON and uncontrolled upstream errors stay excluded. Tool details neither renew approval nor execute anything; details and `show` list `spill:<digest>`, retained bytes and truncation, never implicit file contents.

Display checkpoints retain at most 32 KiB<!-- unrelated-bound: Session display text cap --> of final-result candidate and 32 KiB<!-- unrelated-bound: Session display text cap --> of public commentary per Run, at most 32 commentary items and 64 Events of at most 2 KiB<!-- unrelated-bound: display checkpoint Event payload --> each, including at most one compiled detail-limit cue. Excess commentary shows a cue; answer overflow remains a failed call. Checkpoints use bounded byte chunks, not one Event per token. After cancellation or abrupt interruption only acknowledged checkpoints reopen: `Answer` text formatted under an incomplete heading, `Commentary` as public commentary. Incomplete text is never an accepted Message, Provider history or compaction input. Validation-rejected candidates are withdrawn from presentation in both attached modes and stay qualified in the journal.

Classic exit removes transient input and panels and keeps the final conversation once. Fullscreen restores the previous shell screen with a brief receipt; text that the pager's `[` wrote stays in shell scrollback. Redirected stdout receives confirmed answers after each task in either mode, after read-only outcome confirmation. Exec publishes no display checkpoints; show JSONL includes display-only Events. Linear `/settings` can save the chat view without changing linear presentation. <a id="transcript-detail-limit"></a>`/transcript` shows safe detail text for at most 16 recent Runs and 64 KiB<!-- unrelated-bound: transcript command output cap --> per invocation, with a limit cue; JSONL export covers the complete journal.

Empty chat shows a short width-aware welcome and `/help`; without a selected Provider, welcome, input hint and status point to `/setup`. Hints never become draft bytes.

History shows committed objectives and terminal answers, labeled display-only incomplete text and public commentary, with bounded local notices interleaved. Notices never enter Events, Provider context, replay or `show`; they survive redraw and reacquisition and clear on Session change. Important errors have a textual heading. Confirmed failed or cancelled Runs show safe compiled guidance without invented answers, raw error bodies or automatic retries. Progress, panel-closure and copy-success cues are transient; a copy cue names its destination, and an OSC 52 copy reads `sent to terminal (OSC 52); it may be ignored`, because delivery cannot be confirmed. A failed copy shows `Copy unavailable: REASON` and an oversized one `Copy exceeds 97.7 KB; use arany show`; neither retries. Retained-draft cues stay separate from history notices; a notice uses status fallback if no row fits.

Failure feedback follows the terminal cause. A recoverable primary Tool denial shows in its Tool row with a compiled cause label and reaches the model once as the correlated result, without terminal failure guidance while continuation is admitted. If the next Provider call fails, the view shows that Provider failure, never denial or expired-approval guidance. An attested filesystem denial is not user denial. Optional AI-review failure followed by human denial keeps the human-approval guidance; completed effects are never described as rolled back. Unavailable approval-channel guidance asks for a new request from an interactive channel. Hook and permission-rule text never appear in denial feedback.

In Fullscreen, PageUp/PageDown navigate; Ctrl+F opens local literal find with grapheme Backspace, visible query and Enter and Escape hints; Ctrl+L returns to live. New content and resize keep an older source anchor and show a textual new-content cue. `arany show` is the canonical export; emulator scrollback is not complete history.

<a id="transcript-pager"></a>The transcript pager follows Claude Code's Ctrl+O transcript. It is modal: detailed History fills every row above one width-bounded key footer, the hidden composer keeps its draft, unowned keys do nothing, and pastes and clipboard results are discarded. It takes input during compaction too. Keys:

- `/` or Ctrl+F opens find from the newest match; `n` and `N` step to the next older and newer match.
- `j`/`k` or Down/Up move one row, Ctrl+U/Ctrl+D half a screen, PageUp/PageDown a screen, `g`/`G` or Home/End to the top and live end. Wheel, selection and copy work as in chat.
- `q`, Ctrl+O or Escape closes; Escape first closes find, then clears a selection. Ctrl+C keeps its chat meaning and cancels a Run.
- `[` releases mouse capture and the alternate screen and writes each Run's objective, details and committed answer to the primary screen, escaped like all human output. It keeps the newest whole Runs, at most 16 and 64 KiB<!-- unrelated-bound: conversation export text cap --> counting line endings and cues, starts with `Earlier Runs omitted; arany show prints the whole conversation` when older Runs are left out (or `The newest Run exceeds the transcript limit; arany show prints the whole conversation` when none fits) and ends with `Enter returns to Arany`. Streaming text shows as provisional. The Run continues without redrawing; Enter, Ctrl+C, a Tool approval or SIGCONT reacquires the screen and capture and returns to the pager. Exit, suspension, signals, errors and unwinding during the dump restore the terminal without clearing that text.

Fullscreen selection follows Claude Code fullscreen and Codex. With [mouse capture](#selectors) the wheel scrolls History three rows. Click-drag selects History text, a double click a word (a whole URL inside `scheme://`) and a triple click a line. Selection shows in inverse video and stays anchored to source text through streaming, appends and resize; dragging past the top or bottom scrolls one row per motion event. Copied text is the escaped display text without role headings, rails, indents or Tool markers (`⏺`, `⎿`), with wrapped rows joined and messages divided by a blank line; its plain length is checked against the [clipboard copy limit](#public-limits-and-compatibility) before any Tool result is joined. With Copy on select (default), release copies and a successful copy clears the highlight, so the next Ctrl+C cancels as usual. Ctrl+Shift+C also copies, as does Ctrl+C with a selection while chat is idle; during a Run or compaction Ctrl+C always cancels. Escape clears a selection; a failed copy keeps it. The first copy in a process names the emulator's own selection gesture from `TERM_PROGRAM`: Fn-drag in Terminal.app, Option-drag in iTerm2, otherwise Shift-drag, with the whole list over SSH or in tmux, where it adds that wheel scrolling needs `set -g mouse on`. A selection grants nothing and never reaches Events, Provider context or diagnostics.

Fullscreen inline text panels (`/usage`, `/settings`, `/help`, quick actions) also support click-drag selection while mouse capture is on, highlighted in inverse video and underline so it differs from a focused row. Release copies under Copy on select, and Ctrl+Shift+C copies an existing selection. Copy uses the rendered escaped panel text with rows joined by line breaks, under the same size limit. A bounded cue shows success or failure while the panel stays open; failed copies keep the selection. Moving or resizing the panel clears its selection before the next frame. Escape clears a selection, then a later Escape closes the panel. Picker rows keep their mouse behavior.

### Reported usage

`/usage` takes no arguments and opens a read-only paged token report while idle or running, including for an unsaved conversation without account access. It covers the current/latest Run, this Session's totals and separately labelled inherited history excluded from them; the [Session projection](./session.md#persistence-facts) owns accounting and pending-reservation uncertainty. Each scope groups the actual pinned Provider/profile and model. Tokens use grouped decimal counts. Cache reads/writes say `included in input` and are never added again; output includes reasoning where reported. A partial counter reads `12,340 known; some calls unreported`, no report reads `unknown (not reported)` and no calls reads `no calls yet`. Failed retry/fallback attempts count as unreported even after a later success. Pending reservations mark totals incomplete after a Run ends. No plan allowance, context capacity, billing cost or balance is inferred.

ChatGPT observations appear apart from token totals with local Run/route labels and `Account-level observation; not this Session's share`. A weekly row always appears, unknown when absent. Reported duration selects the label: 300 minutes is `5-hour`, 10,080 is `weekly`, others show their minute count and absent duration is unknown; slot names do not imply duration. `% used` rounds to at most one decimal; percentage and reset are unknown independently, and no allowance is inferred. Native OpenAI JSON invocation adds separate `API rate limits` rows with Run/route, role, Provider/model and header dialect; each dimension shows its known limit, remaining and reset independently, grouped counts including zero, and header receipt/source. Counters are never converted to plan bars or summed. Missing facts read `unknown (not reported)`, including for streaming/preview invocation, compaction and routes without collected facts.

Each window and API row is `Last reported` with its stored absolute UTC receipt time and source. The terminal supplies the current time on inspection or committed update; the renderer reads no clock. Ages and relative resets use at most two nonzero units of seconds, minutes, hours and days (zero is `0 s`); a relative reset includes its UTC timestamp, and a missing reset reads `Reset unknown`. A future receipt or backward clock reads `Observation age unknown`, never fresh. Following Codex, a sample older than 15 minutes is stale, and after its reset passes reads `Stale; reset time passed, current usage unknown`; neither zeroes usage or advances a window. Reopened and prior-Run observations are historical; `show` keeps only stored timestamps. A later omission says `Latest call did not report limits`; invalid optional metadata adds a closed unavailable reason and receipt time while keeping earlier valid rows; a partial omission names unreported dimensions. Inspection never requests or refreshes limits, and age cannot rule out another client's consumption.

Both visual modes use the detail-dialog input barrier and keep draft, caret and history anchor on Escape; Ctrl+K's Usage action can inspect over a draft. Up/Down, Home/End and PageUp/PageDown scroll; Left/Right change pages. A page holds at most 16 route groups and 8 KiB<!-- unrelated-bound: MCP route status page --> of escaped text, showing its range when paged; narrow layouts wrap complete labelled fields vertically. Ctrl+C still cancels work. Linear/screen-reader mode writes every page as complete labelled text with no truncation, boxes, controls, color dependency or rewrites. The renderer reads only committed projections; report state never enters the journal or model input.

## Draft editing and submission

Inline edits operate on whole graphemes and keep the caret on a grapheme boundary. Insertion, deletion and wrapping preserve accepted bytes except explicit editing and paste newline normalization. After a deletion the draft is resegmented, because removed separators can merge graphemes or regroup regional indicators; the caret snaps to the first surviving boundary at or after the deletion point. Long drafts wrap into at most four visible rows around the caret, and the heading identifies a clipped window. Growth clips activity before input and status.

| Input | Effect |
|---|---|
| Left/Right, Backspace/Delete | Whole-grapheme movement or deletion |
| Up/Down | Logical-line movement at a preserved grapheme column |
| Ctrl+Left/Right | Previous or next Unicode-whitespace-delimited chunk; punctuation in paths and model IDs stays in the chunk |
| Alt+Left/Right | On an empty draft, switch [agent chats](#agent-chats); otherwise inert |
| Ctrl+W | Delete the same preceding chunk range |
| Typed backslash immediately followed by Enter | Replace that backslash with LF at the caret before completion or dispatch |
| Decoded Shift+Enter, selected Alt/Ctrl+Enter, or Ctrl+J | Insert newline without consuming a preceding backslash or submitting |
| Enter while idle | Submit through local validation, or complete an open slash-name menu |
| Enter during admission or catalog loading | Retain a task draft; never queue another Run |
| Enter during an admitted Run | Offer the draft as a steering note, or retain it as a task draft; never queue another Run |
| Enter during compaction | Retain all text, including slash commands; execute nothing |

Backslash continuation follows Claude Code's portable newline gesture. Only a successfully typed backslash arms it, at that caret, for the next ordinary Enter; a second typed backslash arms the latest one, so two backslashes then Enter keep one literal backslash and add LF. Movement, another key, deletion, paste (including rejection), recall, focus/owner changes and draft replacement disarm it; resize, redraw and incoming output do not. Pasted or restored trailing backslashes stay literal. Replacement adds no bytes and succeeds at capacity. Primary idle, admission/catalog waits, active steering, compaction and editable child drafts consume continuation before submission, and newline edits in busy states never queue an objective or steering offer; editing a waiting note keeps its withdrawal semantics. Dialogs, approvals, search and read-only child views never use chat continuation.

Following Codex, each visual acquisition queries kitty keyboard flags and then device attributes through the sole input reader, within one 250 ms probe budget. A valid flags reply enables a scoped push of disambiguation only; device attributes without flags, or an absent or malformed reply, keep legacy input and the portable fallback. Late replies never enable a mode. Replies bypass saturated input queues without stealing or reordering keys or framed paste; protocol-looking paste stays data. The keyboard mode is popped before leaving its screen on release, suspension, view changes, scrollback output, failure or unwind, and probed afresh on reacquisition. Canonical and screen-reader input emit no keyboard query or enhancement controls. No modifyOtherKeys mode, subprocess or host terminal configuration is enabled automatically. Linux and macOS share negotiation, decoding and restoration.

The preferred modified shortcut is recommended after successful negotiation or receipt of that distinct chord; backslash then Enter stays visible as the fallback. Visual newline settings report whether enhanced keys were negotiated. Received CSI-u and modifyOtherKeys chords work regardless of negotiation. Konsole's default keytab sends `ESC O M` for Shift+Enter; since Arany never enables application keypad mode (DECKPAM), it decodes that as Shift+Enter and inserts LF, matching Claude Code's Enter/Shift+Enter split. Plain CR always means Enter, because an emulator or multiplexer can lose any modifier. The newline setting describes manual CSI-u mappings (CSI `13 ; 2 u` for Shift, `3` for Alt, `5` for Ctrl) and tmux's extended-key requirement, without inferring delivery from a terminal name.

Linear/screen-reader chat submits with Enter. A newly received physical segment ending in backslash loses exactly that backslash and gains LF, keeping the draft; this is segment-local and never examines an assembled draft or clipboard payload. Ctrl+D after nonempty input continues without adding LF; empty Ctrl+D exits on an empty draft and gives Enter and Ctrl+C guidance on a retained one. Overflow or invalid physical input rejects the whole segment without submitting a prefix or erasing accepted text. Linear entry and settings say `Modified newline shortcuts apply only to visual sessions; use backslash then Enter here`. Unframed emulator paste has no provenance: a pasted line ending in backslash continues and later lines can submit; guidance says so and recommends `/paste` for multiline clipboard text.

Before consuming an idle inline draft, unknown slash syntax, invalid local arguments, an oversized rename, a capacity rejection or an incomplete objective selection leaves text and caret correctable, with no credential, State, Workspace or Provider I/O. Failure after State access or an attempted effect does not restore a consumed command, promise rollback or authorize resubmission. Linear text starts a fresh line after rejection.

During an admitted Run, valid slash controls give read-only inspection, a locked notice or `/goal pause`. Next-Run defaults and Session mutations stay locked; `/exit` explains Ctrl+C cancellation first until the Run's outcome is committed.

Enter during an admitted Run offers the composer text as a steering note; with attached images it reports `Steering notes are text only; draft retained`. The composer keeps the note until the Engine records it for the Run's next primary call; the notice then reads `Steering note sent to the agent`, and the composer clears only if it still holds the offered text. While waiting it shows `Steering note waits for the agent's next step; editing withdraws it`; in Classic a second Enter repeats that. Any edit withdraws an untaken offer with `Steering note withdrawn; draft retained`. When the Run's notes, including history labels and the waiting note, would exceed [8 KiB](./limits.md#max_steering_note_bytes), it reports `No room for more steering notes this Run` and keeps the draft; a single note over [8 KiB](./limits.md#max_steering_note_bytes) reports `Steering note exceeds 8.0 KB; draft retained`. Feedback never repeats note text. An undelivered note returns as a retained draft at Run end, keeping editable text and inert paste boundaries.

In linear mode, Enter hands the note off and clears the line; a further text line while it waits merges into it after a blank line, so one note is delivered. `/status` and `/goal pause` run normally. A draft kept by a refusal (including images) is held aside for the Run; further bounded text stays in the composer with `Both drafts retained; wait for the Run to finish`. At Run end the held draft returns ahead of newer text if both fit; otherwise both survive in the [draft recovery slots](#paste-and-attachments): submit or clear the current draft, then use Up. A Ctrl+D segment counts as a further text line while a draft is held; empty Ctrl+D gives the retained-draft guidance.

`/goal pause` asks the Run to pause at its next step: the notice reads `Pausing at the next step; Ctrl+C cancels now`, and the status row shows `Pausing at the next step... Ctrl+C cancels now` until the Run ends. The Goal pauses under its [pause boundaries](./goals.md#steering-notes-and-pause). A repeat reports that it is already pausing; idle `/goal pause` reports that no Goal is running; `/goal pause` followed by other text during a Run is refused as a locked Goal change.

Manual and automatic compaction preserve draft, caret and history through success, failure, interruption, resize and suspension. Ctrl+K is locked; Ctrl+C interrupts maintenance without clearing the draft. Completion reloads canonical facts and returns to explicit idle submission. Automatic maintenance follows a confirmed Run receipt with a visible warning; its usage excludes model-authored summary text. Interruption does not guarantee rollback of a queued append or remote usage.

Draft feedback counts graphemes, including accepted whitespace; combined emoji and combining accents count as one. Storage and physical-line admission keep their UTF-8 bounds, so no fixed character maximum is promised. Capacity errors ask the user to shorten input or paste a smaller section.

The sole raw reader keeps reads nonblocking through shutdown, so signal-flushed input cannot strand its join. Its 32-event channel applies backpressure at 256 backlogged events; a pending [cursor query](#terminal-continuity-and-provisional-text) permits read-ahead up to 4,352 events, past which input closes with an explicit error rather than dropping keys. A lone Escape waits at most one poll interval. Key repeats and releases, focus events and mouse events other than the wheel and the left button's press, drag and release are ignored. A left press on the previous press's cell within 500 ms counts as a double, then triple, click. An SGR mouse record (`ESC [ <`) is read whole through its `M` or `m` terminator, storing at most 32 bytes; a malformed, out-of-range or oversized record, or one unterminated at the ten-second record deadline, is discarded whole, so none of its bytes reach the draft, a dialog or an approval.

Unknown commands give local suggestions without Provider input. No-argument controls accept trailing whitespace and reject extra arguments in every Run state. Selected children use the [agent-chat input surface](#agent-chats) instead.

Typing `/` at the draft-end caret opens a completion list below the input, even for one match. For a bare `/`, Commands and Skills are separate tabs by default, and the saved Combined preference shows both. Once text follows `/`, one prefix-filtered list holds built-in commands in registry order, then admitted user-invocable Skills alphabetically, regardless of tab or preference, following [Claude Code's unified menu](https://code.claude.com/docs/en/interactive-mode#commands). An empty tab activates nothing; an unmatched prefix goes through ordinary unknown-command validation. Exact names, arguments, multiline or mid-draft editing take precedence. Outside the menu, Tab completes a unique registry name or value, or an admitted cached model; ambiguous arguments leave the draft unchanged. Hints distinguish Tab from Enter. Placeholders never enter the draft, submission or Events.

Completion performs no catalog or credential I/O on a keystroke. Provider or account changes invalidate catalog and effort candidates; a same-source redraw or model-only change keeps them. Offered effort levels follow Provider admission; displayed availability is not compatibility evidence.

With supported native Tools and remembered folder trust, or explicit private Tool configuration, `/` also lists admitted project and runtime Skills, at most [64 Skill](./limits.md#max_skills) names under the same geometry and truncation bounds. Automatic discovery uses only `.agents/skills`; other harness and global folders are ignored. Exact folder trust admits project guidance; private selected-root grants cannot expand through discovery. A Skill colliding with a compiled command is omitted, so a Skill named `help` cannot replace `/help`; this deliberately differs from [Claude Code's local override](https://code.claude.com/docs/en/skills#resolve-skills-that-share-a-name) because untrusted Skill metadata must not redefine built-in controls. `/name [task]` then Enter submits a turn with the Skill attached separately and the whole draft as objective. The slash token, spacing and newlines stay in the accepted message, echo, resumed transcript and copy text; the CLI never strips the token or rebuilds the message, and the admitted name alone selects the pinned attachment. Tab completes `/name ` without submitting; filtering and completion execute no Skill content. Linear input accepts the same `/name [task]` without a menu. During a Run, `/name` is rejected because it starts a new turn. The [Portable Skills contract](./tools.md#portable-skills) owns attachment and loading; invocation grants no authority. Invalid or unavailable configuration gives visible recovery and no Skill candidates. At startup, a root regular `skills-lock.json` without `.agents/skills` gives an `npx --yes skills@1.7.0 experimental_install` notice without reading the lock or running an installer; an existing, even empty, directory does not. `/permissions` refreshes candidates after a trust change.

An exact leading `/name` resolving to a command or admitted Skill shows accent plus bold in the composer; partial and unknown names stay plain. Command recognition uses the parser's literal-space separator and trailing-whitespace trimming; Skills accept general whitespace. Echoed user bodies highlight only an accepted Skill invocation, so `//help` and `/goal /help` stay plain. Styling covers only the leading token across wrapped rows, never edits bytes, and uses cached admitted names while composing and the accepted identity in history, without discovery on redraw. Colorless output keeps bold; completion rows and hints name the command or Skill, and committed Skill headings say `You (skill):` in every mode. These labels sit outside the verbatim body and signal recognition, not execution, success or authority. Child chat keeps literal text-only semantics.

Linear mode prints `Choice N: NAME: VALUE` rows with one accepted-input hint each (newline values `shift+enter`, `alt+enter`, `ctrl+enter`), then accepts one `NUMBER VALUE` per line, like `/model`. Settings is locked during admission, Runs and maintenance.

- Typing searches project names and relative paths case-insensitively, including nested paths, ranking exact names and prefixes first; an empty query shows the folder's immediate entries.
- Up/Down selects. Tab or Enter inserts a quoted file mention without sending; Enter inserts a trailing-slash directory reference and Tab enters the directory. Escape keeps the draft.

It revalidates Workspace identity, scope and permission generation, uses the same no-follow ignore-control admission and Read restrictions, never opens file bodies and keeps the shared discovery and ignore-parsing bounds. Overflow rejects the whole index.
- The terminal never waits synchronously. One build slot per binary and one latest query belong to the composer; edits refine the index in process with at most 2,048 comparisons and a 50 ms deadline, and a timeout discards that update. At most 64 deterministic candidates display. A superseded build keeps its resources until cleanup and cannot publish a stale generation.

There is no watcher, persistent cache or stale fallback; explicit folder narrowing starts a fresh index.

Mention failures name the escaped path and distinguish symbolic links, filesystem boundaries and non-directory components; an unfinished quoted mention reports `unterminated quoted path`.

The model catalog is bounded and scoped to Provider and account; cached metadata and keystrokes grant no credential or Run authority.

## Storage report

`arany storage` uses the existing Workspace and selected/default StateRoot conventions and the fixed account root. It runs without a Provider or account, writes its bounded text report to stdout and fixed failures to stderr. A complete report succeeds, including explicitly absent roots. A partial or refused report exits unsuccessfully with any known subtotal labelled; cancellation emits no complete report. [Tools](./tools.md#local-storage-inventory) owns coverage, byte semantics, exclusions, bounds and cleanup non-effects, including the [cache recovery contract](./tools.md#persistent-workspace-build-cache).

Idle `/storage` takes no arguments and shows the same report without creating a Run, history or context; it is locked during a Run. Classic and Fullscreen use a read-only pager with Up/Down, PageUp/PageDown and Home/End; Escape, Enter or Ctrl+C closes it and restores the composer. Linear/screen-reader mode appends the complete text to stderr. During collection, Escape or Ctrl+C cancels and shutdown is preserved; filesystem work stays off the terminal reactor, is joined after cancellation and cannot publish a late report. Reports are never journalled, exported through telemetry/MCP or disclosed to the model; model guidance may suggest `/storage` without obtaining the result.

## Rewind

Idle `/rewind` opens the checkpoint panel. Esc Esc within two seconds on an empty idle composer opens the same panel; on a nonempty draft it saves and clears the draft, which Up recalls (one local draft, text under the draft byte bound and attachments under the image bounds, replaced by the next cleared draft). A focused menu or panel consumes Escape first, and the first idle Escape announces the second action. Rewind is locked during a Run, admission or maintenance. Attached images or another retained draft must be submitted or cleared before switching conversations. Rewind is never automatic and not available in headless `exec`.

Rows follow conversation order with the newest focused: `Run N · objective excerpt · time · K files changed since` (`file` for one), or `no code changes since`, plus `Before rewind` rows. Times come from committed Events (inherited ones labeled inherited); excerpts are at most 80 characters. Later autonomous Runs read `Goal run k` under their Goal objective; steering notes create no checkpoints. Enter opens Restore code and conversation / Restore conversation / Restore code / Never mind, in that order. Code choices appear only for a nonempty plan. Unknown or open publications disable code actions with their Event sequence and an inspect-files reason, and read-only access disables them with a grant reason; conversation restoration stays available. A Before rewind row offers code restoration only.

Code choices open a paged preview listing each path's state (restore, delete, recreate, drifted, history drift, unavailable, unsafe, outside grant or kept), `+added -removed` counts over one replacement region after trimming equal leading and trailing lines (unknown for binary or unavailable content), and the non-rewindable effects. Cancel / Compare / Restore are vertical rows with Cancel focused. Restore needs every page traversed in order; resize or suspension restarts review. Compare opens a numbered per-file picker and bounded text-diff pages, minus for current Workspace content and plus for checkpoint content, each escaped page at most 64 KiB<!-- unrelated-bound: escaped rewind diff page -->; binary or unadmitted comparisons say unavailable. Compare grants no file access and opens no paths outside Engine admission. A confirmation that reports a change needs a new preview; [Tools](./tools.md#checkpoints-and-rewind) owns confirmation validity.

Drift refuses the whole batch and lists affected files. Resolve offers Cancel, `Restore the others, keep these files` and `Overwrite changed files (their current content is saved first)`. Keep requires review and Restore on a new preview. Overwrite applies only to drift and history drift and needs a separate Cancel / Overwrite confirmation with Cancel focused, then review and Restore on the new preview. Unavailable, unsafe and outside-grant paths can only be kept. Empty effective plans refuse. These copy Cline/Roo's three restore choices and per-file Compare, and Claude Code's `/rewind`, Esc Esc and prompt restoration; the drift refusal is stricter, as [Tools](./tools.md#checkpoints-and-rewind) defines with its capture guarantees.

Receipts keep the committed outcome: `Restored K files to before Run N`, `Rewind refused: M files changed outside Arany`, or `Rewind outcome unknown: inspect files before continuing` for an [Uncertain](./execution.md#effect-outcomes) outcome, with listed conflicts and checkpoint/pruning notices. If conversation restore fails or is cancelled after code restore, the receipt reads `Code restored; conversation unchanged; use /rewind → Restore conversation`. The [Session contract](./session.md#conversation-rewind) owns fork ordering, source preservation, budgets and lineage limits. Conversation restore switches to the fork (or an unsaved conversation for the first prompt), keeps next-Run defaults and places the selected prompt and images in the composer unsent with text editing focused, with a leading slash escaped as a literal objective. Images return as [attachments](#paste-and-attachments); unsupported control characters produce an omission notice, and an image that cannot be reattached stops the rest with `image restoration failed: REASON`. Restored text follows the [primary text draft limit](#public-limits-and-compatibility). Linear mode announces the complete restored draft as not sent.

Unavailable checkpoint storage offers Retry / Reset checkpoint storage / Cancel. Reset needs complete warning review and a separate Cancel / Reset confirmation with Cancel focused; healthy, busy, unsafe or concurrently changed storage refuses. [Tools](./tools.md#checkpoints-and-rewind) owns deletion scope and private-state admission.

All modes share these states and words. Linear output lists numbered rows and accepts numbers or complete visible choice names; empty Enter, q, Ctrl+C or EOF cancels. It prints full inert paths, previews and comparison pages without truncation or rewriting. At 80+ columns the panel keeps full hints; 50–79 keeps choose, review and cancel; below 50 it keeps arrows, Enter/PgDn and Escape with details on sequential pages. Below 16 columns<!-- unrelated-bound: rewind minimum viewport width --> or eight rows actions require resizing. Paths, excerpts and diff bytes are untrusted data escaped before layout or output. `show` text renders rewind Events and the checkpoint field inertly; JSONL keeps canonical Events.

## Selectors

Ctrl+K, `/settings`, `/model`, `/resume`, `/help`, `/agents`, `/usage` and `/status` open inline in the bottom area, like [Claude Code's dialogs](https://code.claude.com/docs/en/interactive-mode), with no centered box. In Fullscreen, live history fills the rectangle above and keeps following a running task, as above Tool approval; in Classic the selector draws in the grown viewport. Rows read `N. label`; the focused row is marked `›` in inverse video. A `/settings` row too wide for one line puts its value on the next line. The composer is hidden while a selector owns input and returns with its draft and caret. Every selector uses the [Tool approval admission barrier](#interactive-commands-and-completion): unarmed first (dim rows, no focus or key hint; linear rows without the prompt), then armed. Keys typed before the armed frame, including digits sent with Ctrl+K, are discarded; Ctrl+C, signals, suspension and resize keep their meaning. A selector opened from Ctrl+K arms again. Digits act only in fixed short lists (Ctrl+K actions and `/settings` rows); typed text filters `/model` and [searches `/agents`](#agent-picker), where digits are search text.

Idle Ctrl+K offers Models, Agents, Resume, Setup and Usage, numbered 1-5, without consuming the draft; with no Provider, Setup has initial focus. A digit activates; Up/Down selects; Enter activates; Escape or Ctrl+C restores draft and caret. All five fit at 16×8. Session switching requires an empty draft with no outstanding images. Opening performs no catalog or credential I/O. It is locked during a Run; linear mode uses slash commands.

Bare `/model` opens an idle numbered catalog above the retained composer. Up/Down focuses models, Left/Right sets that row's tentative effort, and filtering keeps per-row choices. Enter saves model and effort atomically; Escape changes nothing; an empty filter result activates nothing. The panel overlays the transcript without moving the history anchor; its local ASCII filter (at most 64 characters) never enters Session, context or scrollback. Below 16 columns<!-- unrelated-bound: model selector minimum viewport width --> or eight rows only resize and close work. Linear mode uses numbered pages and `NUMBER [EFFORT|default]`.

Metadata marks reviewed, listed or exact choices. Unknown native models need explicit effort and stay unproven until a strict response succeeds; ChatGPT choices need explicit levels; custom tuples use their declaration. A changed native or ChatGPT model starts at low effort, the same model keeps its effort, and a Provider change clears both. Selection loads no token and starts no inference; Run admission revalidates account, consent and custom evidence.

Cached choices open immediately while one cancellable refresh stays input-owned. Refresh failure keeps old rows visibly stale; replacement keeps filter, model identity and admissible effort. Linear numbers stay bound to the opened snapshot. Completion or cancellation during loading keeps draft text without submitting it; queued typeahead is not guaranteed. Custom declarations load locally.

Saved-account tuples and catalog IDs survive restart. A new bare Session restores the last acknowledged tuple for the same Provider and account UUID and seeds cached rows without loading a credential or calling the network; OS-store authorization is a separate phase. Explicit flags and resumed defaults win; a different or replaced account inherits neither tuple nor catalog. `/model` refreshes restored rows through the same flow. A remembering failure is visible without undoing the selection. The cache holds at most eight sources, 4,096 IDs per source and 1 MiB<!-- unrelated-bound: terminal model catalog cache --> in aggregate, evicting the oldest unselected source first. A separate optional Provider and account pointer remembers explicit setup, model and resume choices; refresh never changes it, and token-free preferences without it stay readable. Stored availability never authorizes an account, model, effort, custom destination or inference, and malformed or over-limit preferences grant nothing. With no saved preference, startup may copy only the matching model and effort from the latest valid Session in the same Workspace into a new empty Session.

A selection rejected by another Session operation's lock gives labeled feedback without saving or retrying. An unavailable ChatGPT account or invalid custom choice keeps the selection and starts no sign-in, fallback or inference. Catalog failure changes no defaults; published account work is not rolled back. State, replay and terminal-owner failures keep their fatal boundary.

<a id="agent-picker"></a>`/agents` inspects primary-first agents from the 16 most recent Runs, newest first, with bounded inert identity, state, objective, summary and result previews. A Tool row that failed before dispatch shows its typed Guard stage and check. The header separates current or last Run counts from historical totals; each choice reads `Run N: <agent>; <status> · <objective>`. Its argument form changes only next-Run collaboration. As in Claude Code's agent panel and Codex's agent picker, Enter opens the focused child's [agent chat](#agent-chats), even from an older Run, or the primary chat on a primary row.

- **Search.** Typed text, digits included, searches each row's label and objective locally, ignoring ASCII case. The line reads `Type to search N agents`, `Search: TEXT · M of N agents` or `Search: TEXT · no matching agents`; a character past the limit or outside printable ASCII leaves the search unchanged with `Search takes up to 64 ASCII characters`.
- **Idle collapse.** Running, failed, cancelled, interrupted and stopped rows always show. The first idle rows up to the [inspection limit](#public-limits-and-compatibility) show and the rest collapse into a final `N idle agents` row; Enter on it expands every row in place, focuses the first revealed one and arms again. Rows collapse or expand only through committed status changes or that Enter, never on a timer, and the focused row never collapses.
- **Focus.** Focus belongs to the row's Run and AgentRun identity: committed changes move rows but never the focus; a vanished focus leaves nothing focused (`No agent focused; Up or Down focuses one`), and with no match nothing is focused, so Enter does nothing.
- **Inline keys.** A window of numbered rows follows focus; arrows focus, Home/End jump, PageUp/PageDown scroll the focused row's details, Backspace edits the search and Escape closes to the primary.
- **Linear.** Prints the header and search line, `Choices A-B of M:`, numbered rows with ` (focused)` after the focused one, its details, and `Agent choice: n next, p previous, number select, o open, /TEXT search, q close:`. Numbers bind to the printed rows and focus a row or expand the idle group; `n`/`p` move focus, `/TEXT` searches and `/` clears, `o` opens the focused row (`No agent focused; choose a number first` otherwise), and other input prints `Notice: invalid agent selection`. Committed changes print nothing; each reprint follows a choice and arms again, and incomplete input is discarded if work ends.

`show` exposes complete older history.

<a id="agent-chats"></a>Agent chats follow Codex's subagent navigation. With an empty composer (no text or images) and no completion menu, selector, pager, approval or clipboard read, Alt+Left and Alt+Right cycle through the current, else the latest, Run's agents: the primary, then children in committed spawn order, wrapping at both ends. On macOS, `ESC b` and `ESC f` (Option+Left/Right without enhanced keys) do the same; elsewhere they stay inert. A draft or popup keeps the keys, and plain or Ctrl+Left/Right keep their editing meaning. Without children the notice reads `No child agents in this Run`; with children the empty composer's border names `Alt+Left/Right agents`.

A child view is a committed transcript drawn by the ordinary escaped History: the child's assignment under `Assignment:`, its newest whole safe Tool rows, its result or summary under `Agent result:`, and its status with its qualification (`Error: child N failed: REASON`, cancelled, interrupted, `private outcome unknown`); a working child reads `child N is working; its committed activity appears here`. Reasoning, prompts, provisional and uncommitted text never appear. <a id="live-agent-chat"></a>Like Codex's and Claude Code's agent views, it follows the child's committed Events: after each [burst](#conversation-progress-and-history) that changes a shown fact, Fullscreen redraws once, Classic appends only the new whole records, and linear mode prints them under `New activity from child N:`. A working child's read group appears once its boundary is known, and a changed status appears once. Sibling or primary Events, same-fact reloads and the primary's provisional text or waiting hint draw nothing and never change the selection; no timer redraws a quiet view. A sequence gap or journal resync reloads the validated Session view and rebuilds the selection by Run and AgentRun identity; a child that no longer resolves returns to the primary with `That agent is no longer in this Run; back to primary`. Unreadable history ends the Run view with `Run history unavailable; check Session history` and shows no unvalidated text.

The bottom panel shows `viewing child N (message)`, with a separate text-only composer, for an eligible latest Active Run's Active child in a Running Goal; other children show `viewing child N (read-only)`. The primary composer, images, caret and History anchor stay separate. Enter offers literal guidance to the exact Session/Run/AgentRun target, never to the primary, siblings or review, and never invokes a command or Skill, even for slash-looking text. Text paste uses the 8 KiB<!-- unrelated-bound: child message draft cap --> draft limit; images and command/Skill completion are disabled. `Note waiting for child N's next step` acknowledges only the local offer; `Steering note recorded for child N` appears only after its committed Event, which does not prove remote receipt. Editing withdraws only that target's waiting offer; an unsuccessful withdrawal leaves the outcome unknown until history confirms it. Each committed note appears once in the child transcript as `Steering note (sent during the child's work):` plus escaped text after the Tool rows (the journal records no step position for notes), within the transcript budget. A child that finishes without another authorized boundary, or Run settlement, pause or failure, keeps unacknowledged text with non-delivery or unknown-outcome feedback.

Child drafts follow the [public bounds](#public-limits-and-compatibility): nonempty drafts are never evicted or retargeted, and a full draft table refuses another editable target. A finished child's retained draft stays visible but cannot submit; Backspace or Delete (or linear `/clear`) clears it locally and also drops an unknown-outcome offer of a child that can no longer take notes, freeing its slot. Alt navigation needs an empty child draft and no clipboard owner. Escape returns to the primary with the draft kept and cancels nothing; Ctrl+C keeps its Run cancellation meaning and leaves the view open. A Tool approval, even an unrelated primary one, keeps waiting offers and drafts (as Claude Code keeps queued teammate messages), closes the view and arms on its own; the Engine takes a waiting note at that child's next boundary after the approval settles. The end of a Run leaves the chosen view readable.

Fullscreen draws the child in place of History, where PageUp/PageDown, Home/End and the wheel scroll it and new records are followed only at the live tail; primary History, draft and anchor are untouched. Classic appends a `Viewing child N (message)` or `Viewing child N (read-only)` boundary and the transcript to native scrollback, holds primary rows until return, then appends `Back to primary` without repainting settled rows. Every switch, return, resize and resumption draws unarmed, discards earlier input and then draws armed. Inline, `/transcript agents` opens the first child; `/transcript agents N` opens agent N (1 is the primary) in every mode. Linear and screen-reader mode print `Agent chats in this Run:`, numbered `N. label · status · objective` rows and `Agent chat: number opens, n next, p previous, q returns to primary:`; numbers bind to that list, `n`/`p` wrap, `q` prints `Back to primary`, and other input reports `Invalid agent choice; type a number, n, p or q`. In an eligible child, `/message TEXT` offers literal text under the 8 KiB<!-- unrelated-bound: child message draft cap --> bound and `/clear` clears the retained draft. Controls keep their 16 ASCII byte bound. Empty or oversized messages leave selection and drafts unchanged; a different message cannot overwrite a retained draft until it is cleared. Selection alone calls no Provider, changes no Run, Goal or grant and writes no Event; it is local and starts at the primary in each process.

`/goal` alone shows the current or last Goal read-only: short ID, status, phase, mode (autonomous or single-Run), Runs, provider calls, known tokens with any unknown-usage flag and active time, each against its pinned budget. A paused (Interrupted) Goal ends with `Use /goal resume to continue`, or `out of budget` when no next Run is admitted; such a Goal is not offered for resume, and `/goal resume` closes it as Failed with its report. If the paused Goal is not the one shown, a second line reads `Paused Goal SHORT can be resumed with /goal resume` or `Paused Goal SHORT is out of budget`. Unknown recorded include paths replace those hints with the `GoalIncludesUnavailable` guidance below. With no Goal, a short notice appears.

`/goal resume` continues the most recent paused Goal at once with its pinned objective and phase, even after newer Goals finished; older paused Goals are history, and with none paused it reports an error. A migrated Goal with unknown admitted include paths refuses its next Run with `GoalIncludesUnavailable` ("Goal include paths are unknown; start a new Goal with explicit inputs"), without an Event or Provider call, under the [recorded-include rule](./goals.md#budget-continuation). `/goal continue` starts a new Goal from the most recent budget-exhausted Goal under the [continuation rule](./goals.md#budget-continuation), with the current saved budget and resource settings, or reports `No exhausted Goal is available to continue`. Only the exact words `resume` and `continue` (ignoring ASCII case and surrounding spaces) are commands; other text, such as `resume now`, is an objective. `/goal OBJECTIVE` starts an autonomous Goal with the default budget that keeps starting Runs until its criterion is met or it stops; if a later admission fails after a committed Run, that answer appears, then `Error: Goal stopped after this Run: REASON` and the resume hint. Plain messages are one-Run Goals. A paused Goal leaves the Session usable: a plain message or `/goal OBJECTIVE` starts a new Goal.

During a Run, `/goal` shows status and Goal changes are locked. A new message becomes a retained draft; during an autonomous Goal it reads `Draft retained; press Enter after this Goal to submit`. Ctrl+C cancels the Run and further iterations. A cancelled Goal stays Interrupted for `/goal resume`, without a terminal receipt, with `Goal paused; use /goal resume to continue.` or, when no next Run is admitted, `Goal paused and out of budget; /goal resume will close it.` The hint, the notice and `/goal resume` share one admission rule: an unaccepted trailing link is not a Run, and an unsettled active-time reservation counts as spent. `/resume-goal` is an unknown command.

`/resume` opens the Workspace picker; `/resume SESSION_ID` selects exactly. Numbered rows show titles, not IDs. Generic titles use the first objective (at most 128 UTF-8 bytes, whitespace normalized) or `Empty conversation`; answers never supply a title. Non-placeholder creation titles and `/rename`, even placeholder-looking, win. Projection makes no Provider call and rewrites no Event or context; a fork derives inherited title and model only through its recorded prefix, pinning a bounded inherited title to its verified source prefix. `arany --resume SESSION_ID --resume-goal GOAL_ID` resumes that paused Goal at startup, with PROMPT as resume text. Every startup objective, including a Goal resume without PROMPT, shows `New conversation · /help for commands` or `Session SESSION_ID · /help for commands` unless a setup notice takes precedence. See [Goal recovery](./goals.md#lifecycle-budgets-and-recovery).

In the interactive Session, State directory and history reload failures are notices, not exits: conversation, composer and draft stay. This covers `/resume`, `/fork`, `/rename`, `/model`, `/provider PROFILE`, `/agents POLICY`, `/compact`, and history reload after any Run or compaction; unknown submission acceptance instead uses the [submission recovery dialog](#paste-and-attachments). Notices:

- `Error: state directory unavailable or unsafe` when State cannot be admitted before a change.
- `Error: Forked Session ID, but it could not be opened: REASON` and `Error: Renamed Session, but it could not be reloaded: REASON` after `/fork` or `/rename` saved.
- `Error: Settings saved, but the conversation could not be reloaded: REASON` after `/model`, `/provider PROFILE` or `/agents POLICY` saved; `/model` still remembers the selection for new conversations and appends any remembering error.
- A reload failure after a Run or compaction appends `; Error: history could not be reloaded: REASON; use /resume to reload it`; after a Run, the visual modes append `; Error: history could not be reloaded: REASON; the committed answer was not shown; use /resume to reload it`.

Linear `/resume` and `/transcript` show only headers or incomplete text, so linear mode also writes an untruncated stderr line `Committed answer not shown; read it with: arany show --output text RUN_ID`, or `Committed answer not shown; read it with: arany show --state-dir 'DIR' --output text RUN_ID` after an explicit `--state-dir DIR` (single-quoted, embedded quotes escaped; `ARANY_STATE_DIR` and the default store need no argument). Linear notices truncate to 240 cells, so the linear hint is `; Error: history could not be reloaded: REASON; the committed answer was not shown; see the command above`. Linear and non-TTY Fullscreen print neither answer nor receipt until reload succeeds. A failed reload keeps the displayed history and persists as history; a later successful reload after automatic compaction drops the earlier error and prints the answer and receipt. A failed post-compaction reload reports once with the same guidance, and an interrupted submission before admission persists its reload failure the same way. A Run whose committed record contradicts its outcome is an integrity failure. Fatal failures end the Session and restore the terminal: `/setup`, terminal rendering, input or cleanup, signals, shutdown, Workspace, append, replay and integrity failures, and first-Session materialization.

Focused picker details show creation, last committed activity in UTC, access route and model; an uncommitted conversation fabricates no activity. Narrow widths shorten dates. Keyboard and mouse keep selection; only list rows activate. Linear choices announce full dates without UUID labels.

Credentials and the saved-source preference belong to the OS user. A configured conversation keeps its selection. Without one, resume recovers its latest pinned Run tuple, else the current selection or saved preference; account-only defaults can recover the same account's remembered tuple. Inheritance, including collaboration policy, is persisted before switching. Missing or replaced pinned credentials never select another account or billing route; Run admission still validates credentials and consent. In chat, an empty list gives guidance and an unavailable list an error; before Session entry either fails. Rendering, input and cleanup errors propagate to restoration and exit.

Classic never enables mouse reporting or alternate scroll. Following Claude Code fullscreen, Fullscreen enables button, drag and SGR reporting (`?1000`, `?1002`, `?1006`, never `?1015`) while it owns the terminal, and selectors share that capture: Session-picker and agent-inspector rows take clicks and the wheel, off-list input is inert, and every action has a keyboard equivalent. Any-motion (`?1003`) is added only after a graphics protocol is detected and while capture is on. `ARANY_DISABLE_MOUSE` set to anything but `0` disables mouse reporting and enables alternate scroll (`?1007`) instead, like Codex; Up/Down then scroll History one row only while the composer is empty and no menu, picker or draft recall is pending. Close, suspension, cancellation, failure, a chat-view switch, linear fallback and loss of ownership disable every pointer mode before control returns.

## Setup and account choices

Attached startup orders its checks: [folder consent](./tools.md#folder-trust-and-approvals), then [local history](#history-recovery), then account choice and [selected-item authorization](./credentials.md#selected-item-authorization), then Provider catalog work and chat input.

A new bare start with no account, or with incompatible or damaged saved access, still opens editable chat that names `/setup`; an unconfigured task starts no Run. A saved explicit access or model preference is reused on bare startup with its Provider and account identity; disconnected ChatGPT access is not restored as connected. Without a remembered selection, mixed saved API and ChatGPT access requires an explicit billing-route choice with Cancel focused; empty Enter cancels and creates no Session, and invalid chosen access never falls back to another route.

Idle `/setup` keeps the draft and defaults on cancellation before save. Materializing an unsaved conversation for a confirmed setup edit keeps its explicit title and current defaults; saving a declaration and returning with Back keeps that configuration. Native and ChatGPT setup return from selected-account catalog discovery with a low-effort model, without a questionnaire or synthetic inference; Provider and account contracts own preferred-model selection, and catalog visibility does not prove compatibility. Incompatible or damaged saved setup gives actionable feedback and leaves the composer available; `/setup` offers the [checked local reset](./credentials.md#storage-replacement-and-recovery), with Back focused and its deletion scope disclosed first; the reset keeps history and other routes' accounts. Reset is a separate effect that later setup cancellation does not undo. Recoverable initial `--setup` errors return to chat; terminal failure and shutdown still exit.

The Provider manager separates API account management, custom routes, Role routing and Roster profiles.

- **Custom routes.** Declarations list without reading their referenced environment variables; inspection shows the protocol family, exact derived check destination and credential reference, and waits for acknowledgment. The add/edit form offers `1. OpenAI Responses`, `2. Anthropic Messages` and `3. OpenAI Chat Completions`, keeps the saved protocol when editing and labels the protocol-specific destination. Changing the protocol clears the destination and requires a new value. The Chat Completions prompt names the canonical base URL and appended `/chat/completions` path, with Bearer authentication and no authentication picker. Add, edit and remove use one previously inspected snapshot; a stale snapshot refuses rather than overwriting a concurrent editor. Check shows its destination, maximum synthetic call count and aggregate deadline before explicit cost consent, then keeps the result visible until Enter or Escape. Escape, Ctrl+C, end-of-input and shutdown cancel active probes and wait for journal settlement; an [Uncertain](./execution.md#effect-outcomes) check leaves the manager before any dependent selection.
- **Accounts.** Removal confirms the chosen identity against its pre-confirmation snapshot; cancellation does not switch the active ChatGPT account. ChatGPT removal lists every validated saved identity, including disconnected and pending ones, so a fresh setup can retry uncertain cleanup without changing another account's selection or defaults. Use saved offers only usable alternatives. Native inspection shows escaped Provider, model, effort and storage metadata with the credential hidden. Selecting a saved native account shows the private-file warning when applicable, then loads only that account and its catalog; cancellation keeps current defaults and selects no other route.
- **Role routing** offers Inspect resolved routes, editing for Primary/Child/Review/Compaction, Save and a separately confirmed Clear role routing. Inspection and Save review show every resolved source/model/effort, inherited primary chains and ordered fallbacks, with exact custom destinations, credential references and diagnostic status. Model fields are bounded by the routing validator. Sources distinguish environment credentials, explicitly inspected saved native access, the selected ChatGPT account and exact custom declarations; only declared custom efforts and admissible native efforts are offered, and choosing a source runs no check. The primary's first tuple changes through `/model`; its chain editor can copy that tuple while keeping fallbacks. Edits stay in the manager's draft until Save publishes the complete record, which next-submission admission uses. Escape discards the current chain edit and Back the unpublished draft. A confirmed Save or Clear stays committed when the manager closes; stale concurrent edits refuse without overwrite. The [Provider contract](./provider.md#per-role-selection-and-fallback) owns admission, inheritance and the conflict with roster selection.
- **Roster profiles** offer Route profiles, Named presets, Preview complete roster, Save roster, Clear role routing when a routing record exists, and Back. Route profiles have ordered initial/fallback chains with role-routing source/model/effort choices, independent of `/model`. Presets assign Primary/Child/Review/Compaction by named profile, with Inherit primary for non-primary roles, and toggle an ordered eligible-child list. Escape discards the current edit and Back the unpublished roster draft. Errors keep the draft for repair and name affected presets. Preview and Save show the complete configured and resolved roster and `arany --profile PRESET` launch guidance; a present role-routing record is called out before Save. A recoverable Clear failure keeps the roster draft; uncertainty and terminal failures stop the manager. The [Provider roster contract](./provider.md#named-roster-presets) owns validation, limits, publication, activation, admission and routing-source conflicts.

Save, Clear and final-preset removal start confirmation on Back and need complete paged intent review, restarted after resize or suspension, in every mode; linear and screen-reader modes expose the same actions and full pages. Returning from the manager restores the draft, caret and history anchor. Admissions, Runs and maintenance keep setup locked.

Setup failures are recoverable, presentation, uncertain or shutdown. Recoverable failures keep their message and setup recovery path; presentation failures keep terminal-specific handling; [Uncertain](./execution.md#effect-outcomes) effects stop setup without retry or rollback claims and block continuation after reopening; shutdown is cancellation. Each flow owns its journal disposition and settlement.

Successful setup returns to the selected chat presentation with a usable composer and notice. Setup never changes inherited output flags, even when terminal input and output share an open-file description.

A confirmed account, custom-route, role-routing or roster mutation materializes the attached Session before its first durable effect and records the edit lifecycle under the [Execution contract](./execution.md#admission-persistence-and-recovery); the first task then uses that Session. Back or cancellation before confirmation, local commands and model changes write no Session Events. An incomplete or uncertain edit blocks resuming that Session; start a new one after inspecting saved state.

[Selected-item authorization](./credentials.md#selected-item-authorization) shows a waiting frame naming the OS password store; already granted access can stay quiet. Escape or Ctrl+C exits without a Run, restoring terminal ownership and cleaning up the helper. Denial, missing or invalid credentials, a changed selection or timeout gives safe feedback and never submits an initial or resumed objective. The credential contract owns scope, deadlines and permission persistence.

The ChatGPT menu offers Use saved, Reconnect, Connect new and Inspect. Inspect works for any saved account, including disconnected, plan-disabled and unavailable ones, without selecting it. It shows the full account UUID, storage backend, ChatGPT-plan billing class and saved connected/unavailable state with its reason; metadata proves neither credential validity nor plan entitlement. Inspection never retrieves or refreshes tokens, opens the password store, loads catalogs or contacts Providers, changes no selection or defaults, and returns to the manager after acknowledgment. Multiple saved accounts show full IDs and the current marker. Cancelling the picker changes nothing; reusing the current account avoids browser sign-in. A switch, new connection or reconnect can keep account-only defaults if later catalog work fails or cancels, without rolling back published account work. Reconnect repeats backend-specific consent and clears old diagnostic evidence. Failed catalog discovery shows a retry notice without retrying.

On Linux, replacing the executable during an open conversation must not stop the running image from launching its credential helper or look like a store failure. Store failures say the desktop password store could not be accessed and direct the user to unlock it and retry. Missing saved sign-in directs to Reconnect; generic authorization failure gives setup or retry guidance without asserting a cause. Reconnect keeps a pinned store; when it is unavailable, guidance names Connect new's separately consented private-file option, which warns that sign-in credentials will be stored unencrypted, keeps Cancel focused and opens no browser before consent.

Non-secret inline setup uses centered borderless focused rows with arrows, Tab, Enter and Escape; typed characters do not select rows. Linear choices show bounded numbered tokens and accept the token or an exact visible name within the input limit, so long or non-ASCII labels stay selectable. Long lists page the complete instructions and choices before a bounded prompt. Each prompt announces what empty Enter selects. Unrecognized linear confirmation input shows a correction notice and prompts again. Reopening a choice announces it again; identical redraws stay quiet. Labels and actions stay readable at 16 columns<!-- unrelated-bound: inline setup readability viewport --> without color. Optional fields keep or clear existing values on empty input.

API-key input disables echo and shows only a character count; printable ASCII admission makes its 512-character limit exact. Echo is restored after cancellation, signals and suspension. Non-secret input keeps echo. ChatGPT consent shows the complete backend-specific warning before Back or Accept, with Back focused; empty Enter declines. Resize or resume discards queued confirmation input and restarts review. Insufficient inline geometry rejects before sign-in. Private-file storage has a separate plaintext warning and explicit selection with Cancel focused, empty Enter declining; it never silently replaces a pinned keyring.

Rejected linear setup or key characters form a correction-only suffix: Backspace removes them first, and later characters count as no choice or key bytes until corrected. Linear rejection starts a new line without enabling echo during hidden-key entry. Anthropic's optional Console workspace ID is visible, locally validated text, not a secret or ambient scope. The OS store may show its own unlock prompt; Arany makes no OS-store encryption guarantee.

### History recovery

Attached startup checks local history in the [order above](#setup-and-account-choices). Incompatible history ([archive rule](./execution.md#admission-persistence-and-recovery)) is archived intact automatically; the new unsaved conversation names the archive, and an initial objective is not submitted. Accounts, preferences and folder trust stay. Damaged or unsafe history, or a failure blocking the archive, opens a recovery choice in the current UI explaining the typed cause, with Retry (focused), Reset history when the history is damaged, and Exit. Retry, Exit and cancellation leave stored data unchanged.

Reset history needs complete warning review and explicit Back or Accept, with Back focused; resize or resume restarts review. The warning says that all conversations in this StateRoot and their derived Provider evidence are discarded, while accounts, model choices and folder trust remain. A confirmed reset opens a new unsaved conversation with no resumed ID and no automatic objective; a supplied initial objective is reported as not submitted.

Reset needs checked private regular files and exclusive ownership against other current Arany Store users; concurrent change, active use or unsafe files refuse deletion with retry guidance. It validates the database and its three fixed SQLite sidecars before any SQLite access, snapshots their identities, sizes and modification times under the lease and rejects any change before removing a file. It clears only those four files, recreates a checked empty database and leaves Session lock files. A storage failure after deletion may leave an incomplete reset; that is reported and recovery stays available. Unsupported history is never interpreted or converted; read-only inspection such as `show` rejects it unchanged.

## Paste and attachments

Primary framed and explicit clipboard text are bounded before normalization and across the expanded draft by the [public paste limits](#public-limits-and-compatibility). After CRLF/CR-to-LF normalization, a paste of more than 1,000 Unicode scalar characters becomes an atomic `[Pasted Content N chars]` chip. A shorter paste is ordinary typed text: it joins command and mention discovery and shares the [64 KiB](./limits.md#max_user_message_bytes) primary draft cap. Chips count only against the expanded-draft cap; linear text beside chips uses the remaining capacity under both caps, and a physical segment exceeding either is rejected whole. Draft merges count their newline separator in both limits. Equal-size pastes append ` #2`, ` #3` outside the bracket from the highest remaining suffix plus one, reusing the base label when none remain. There is no chip count quota. Typed spans and payloads keep insertion order; marker-looking literal text is ordinary text, never a lookup key. Collapse changes presentation only, not model input or token usage.

Child-message pastes always stay editable text without chips, under the [child-message draft limit](#public-limits-and-compatibility); an oversized insertion rejects whole.

Left/Right traverses a chip atomically. At its start, Tab opens its full escaped inert text; Up/Down, PageUp/PageDown and Home/End scroll, and Escape or Enter closes with the original caret. Delete/Backspace removes the whole chip. Command and file completion are disabled while the draft holds a text chip; editable mentions are still admitted on submission. Detail accepts no paste and invokes nothing; Ctrl+C cancels as usual. Narrow and no-color layouts keep the label and keyboard selection. Linear mode prints labeled compact and expanded inert content.

Only explicit editable input participates in command and `@` discovery. Mention scanning accepts at most 64 KiB<!-- unrelated-bound: mention scanner input cap -->, so chip separators do not consume the objective's [64 KiB](./limits.md#max_user_message_bytes) allowance. A command mixed with text chips refuses locally with the draft intact; slash, Skill, file-path and mention syntax inside chips is data. Submission expands exact normalized text into the ordinary objective before Engine admission. `/goal continue` uses the original Goal's recorded includes and never reparses stored text, as [Goals](./goals.md#budget-continuation) defines. Accepted text survives reopen, fork and replay through canonical Messages without clipboard or cache access. Unsubmitted text and chip boundaries are process-local; local recall keeps them, with no crash-recovery promise.

Admission cancellation and definite pre-acceptance failure restore complete text, chip metadata and images. If acknowledgment reconciliation fails, a modal recovery dialog holds the submitted draft outside the composer. Check history repeats only the read: confirmed non-acceptance restores the draft, confirmed acceptance removes it, and another failure keeps it held. Enter cannot resubmit while acceptance is unknown; Exit discards the process-local draft and closes the Session. No submission retries automatically. During work a large paste stays a draft and cannot bypass the [steering bound](./limits.md#max_steering_note_bytes). Refused held/newer merges keep drafts for explicit submit/clear and Up recovery, blocking conflicting insertion until recovered; ordinary recall is one replaceable slot. The active, held, recalled and pending draft slots each keep at most one message's text and images (256 KiB text and 768 KiB raw images total, plus bounded render/encoding copies). Linear steering offers additionally keep up to [8 KiB](./limits.md#max_steering_note_bytes) text and one provenance record per admitted note until Run end. No payload appears in notices, diagnostics or telemetry before submission.

Canonical input rejects an unexpected bracketed frame and drains through its end marker across reads, including interior Enter, slash and protocol-looking lines. Delimiter state is fixed-size; an incomplete frame or split delimiter closes input under the [framed-paste deadline](#framed-paste-deadline) without submitting a prefix. Admission or focus changes never release a frame's interior as actions. Linear mode adds no raw mode or keyboard query.

<a id="framed-paste-deadline"></a>

Framed Unix inline paste atomically inserts one bounded valid block into the editable draft, also during admission, work, maintenance and catalog waits. CR and CRLF become LF; tabs stay bytes with four-space visual expansion. Overflow or invalid UTF-8 rejects the whole record. Paste never submits, completes a command or activates a selector; modal pickers ignore it. An unterminated framed record fails terminal ownership closed after ten seconds. Secret and Workspace fields keep separate bounds and explicit Enter. Linear canonical input does not claim safe unframed multiline paste.

Ctrl+V, decoded Ctrl+Shift+V or `/paste` requests one bounded OS clipboard read. Unsupported transport, hostile payload or process failure gives local feedback without changing the draft. Clipboard data stays transient untrusted input until submission and supplies no key event, file authority or Run. Enter while loading retains rather than submits. Picker or find entry, release, suspension and ownership changes discard late results; Ctrl+C still cancels a Run. Linear mode shows a complete inert `Draft (not sent)` preview, also during work, and renews its idle prompt afterwards.

Linux reads admitted text and PNG through standard Wayland or local X11 clients. macOS uses a bounded supervised AppKit pasteboard read that prefers PNG over UTF-8 text and rejects other image formats, changed generations and excess bytes; AppKit has no size check before `dataForType`, so the bound applies to the parent's read and the child may materialize the full payload.

Clipboard transports come only from checked local OS metadata: Wayland or local X11 clients on Linux, the checked `osascript` bridge for paste and `pbcopy` for copy on macOS, and a checked tmux socket for copy; never from `PATH`, an external host, an arbitrary command or Provider content. The child gets a cleared environment with only the selected display or runtime variables (plus `LANG` for `pbcopy`), never credentials, network settings or the home directory as configuration. Support checks never read the clipboard.

Clipboard clients run in owned process groups, owned before any fallible pipe setup, under a shared two-second read or copy deadline. Every exit attempts group termination and reaping under a separate one-second cleanup deadline, except a Linux serving copy client (`wl-copy` or `xclip`): as in Claude Code and Codex, its descendant keeps serving the selection until another owner takes it, even after Arany exits. Arany reaps the foreground process and leaves the descendant in its own group with only the payload and cleared environment; a failure or deadline terminates the whole group. Cancellation discards a late payload without blocking the terminal reactor. One clipboard worker runs at a time; another read is refused until it finishes. A cleanup error or deadline returns `clipboard cleanup unconfirmed`, never a payload or a reaping claim; the worker keeps observing the child, and later reads report the unconfirmed cleanup until restart, even when cancellation discarded the result. Teardown signals an outstanding worker and waits at most one second; a miss reports unconfirmed cleanup to stderr. No read retries automatically.

The composer shows attachments as ordered `[Image #N]` chips. Workspace admission captures the root's device and inode before Session creation; every pasted path read requires that identity, also in fresh conversations, and opens the root and each component without following links. Clipboard PNGs and pasted `.png` paths share the admission limits; candidates follow the [PNG path bound](#pasted-png-path-limit). Text containing `://` or control characters is ordinary text even when it ends in `.png`; URLs are never fetched. Absolute paths are accepted only lexically beneath the canonical Workspace root. Reads require a same-filesystem regular file with one link and snapshot at most the PNG byte limit before validation. Linux rejects mount crossings, including same-device bind mounts, and fails closed without kernel enforcement; macOS uses no-follow component opens and rejects device changes. A path confirmed absent beneath the pinned root falls back to the pasted text. Workspace failures, identity changes, escaping, forbidden, linked, cross-filesystem, oversized and malformed inputs leave the draft unchanged.

When the chips do not fit the composer header, it shows the selected chip or, with none selected, the image count, keeping the clipped draft position when both fit. Left/Right selects adjacent image chips at the text boundary or among chips; Delete/Backspace removes the selected image and the rest renumber in order. Successful text edits, including paste, clear image selection; ignored keys, pointer motion and resize keep it. At most four PNGs totaling 192 KiB raw bytes are admitted, including image-only submission with empty user text. Human history shows metadata only; canonical history, forks and JSONL export keep bytes. Compaction uses image metadata and prior assistant interpretation, not pixels. Overflow rejects a whole image or historical turn, never a truncated prefix or silently lost attachment. Custom routes stay text-only.

Admitted PNG bytes stay unchanged, metadata included. Admission checks structure, chunk CRCs and dimensions without decompressing; animated PNG and unknown critical chunks reject, and dimensions prove neither decoding nor vision support. Filenames, URLs and terminal image escapes are never admitted.

<a id="image-hover-preview"></a>

Image hover preview is an Arany addition; Claude Code and Codex CLI have none. It runs only in Fullscreen with mouse capture, outside tmux and the screen-reader path, sharing the keyboard probe deadline. Detection prefers an exact Kitty graphics `OK` reply before DA1, then DA1 attribute `4` (the first DA1 parameter identifies the terminal) with a known cell pixel size for Sixel, then the iTerm2-compatible environment (`TERM_PROGRAM` exactly `iTerm.app` or `WezTerm`, or `LC_TERMINAL` exactly `iTerm2`). Sixel cell pixels come from `tcgetwinsize`, else from an exact `CSI 6;height;width t` reply before DA1 to a `CSI 16 t` sent first. Missing, zero, oversized or malformed cell sizes disable Sixel but still permit an eligible iTerm2 fallback. Detection and rendering never change terminal or tmux configuration. [Xterm's control sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) own DA1 and cell-size replies; [DEC's Sixel](https://vt100.net/docs/vt3xx-gp/chapter14.html) owns raster and palette encoding.

Hovering a visible chip draws a bordered balloon above the composer header, anchored at the chip, clamped to the screen and titled with the image description; the image keeps its aspect ratio. Hidden compact chips have no hit area, and the balloon is omitted when fewer than four inner rows fit. Kitty and iTerm2 receive the unchanged base64 PNG and decode it themselves; their decoders are outside Arany's security boundary. Sixel alone decodes locally in `spawn_blocking`, scales by nearest neighbour and quantizes to a fixed 6×7×6 RGB palette (252 colors); fully transparent pixels leave the background, other alpha uses the pixel's RGB. The decoder uses the PNG byte limit as its best-effort allocation limit, ignores text/profile metadata, and checks frame pixels (before decoding) and output pixels against `PREVIEW_MAX_PIXELS` under the [preview limits](#public-limits-and-compatibility); a started job completes under those bounds without a hard RSS or preemption guarantee. Decode errors and overflow suppress graphics without changing the attachment or reaching a Provider, journal, diagnostics or telemetry.

One Sixel decode runs per binary with one latest request kept; a superseded job keeps its slot until done, generation changes (leave, reentry, chip or geometry change) prevent late publication, and a busy slot suppresses the preview for that hover. Mode replacement keeps the outstanding job's ownership. Results arrive as a terminal event. Motion within a chip neither redraws nor retransmits. Leaving deletes the Kitty placement or repaints iTerm2 and Sixel cells. Resize, chip change, opening a picker, dialog, pager or detail view, mode switch, scrollback dump, suspension, release and exit clear the hover. Without a detected protocol, and in Classic, linear, screen-reader, disabled-mouse or tmux sessions, no preview or fallback graphics are drawn. A graphics write error propagates through ordinary restoration.

Idle `/copy` copies the latest committed answer's source Markdown with control escaping; it is locked during a Run. Fullscreen selection maps visible graphemes to contiguous source ranges, including heading, code, table and inline syntax envelopes and intervening source; reference destinations include their use and definition envelopes, so an aliased endpoint can widen the copy. A double click keeps plain source words in ATX headings, code bodies and plain table text, and otherwise selects the visible word with its source envelope; selecting the whole body returns its original Markdown. Classic emulator selection copies rendered cells.

A copy goes to the first destination that works, each tried at most once:

1. A native client when local (no `SSH_CONNECTION`, `SSH_CLIENT` or `SSH_TTY`): `wl-copy` (Wayland) or `xclip` (X11) on Linux, `pbcopy` with `LANG=en_US.UTF-8` on macOS. `xsel` is not used, because its daemon calls `setsid()` and leaves the owned process group.
2. Inside tmux, `tmux -S SOCKET load-buffer -w -` (tmux 3.2 or later). `$TMUX`'s socket must be absolute, a socket, owned by the user and in a private canonical directory whose every ancestor is owned by root or the user and not group- or world-writable unless sticky; its device and inode are rechecked before and after the client runs, and a change fails this destination.
3. OSC 52.

Copy clients come from the same admitted root-owned directories as paste clients (so Homebrew tmux on macOS is never used) and read only the payload on stdin. Copied text is never journaled, sent to a Provider or recorded in diagnostics. OSC 52 depends on the emulator: Terminal.app and VTE ignore it; iTerm2 requires "Applications in terminal may access clipboard"; Kitty, foot, WezTerm, Ghostty and Alacritty support it. Over SSH, Terminal.app users need Fn-drag or Classic; inside Homebrew tmux on macOS, OSC 52 needs `set -g set-clipboard on`.

## Interruption, suspension and restoration

Primary Tool approval prompts stay answerable without a wall-clock deadline while terminal I/O and the Run are live, including suspension or a live tmux/screen PTY. Explicit No records a human decline and stops the Run without dispatching; Escape and Ctrl+C cancel the whole Run. EOF, SIGHUP/shutdown and lost terminal I/O withdraw the request, closing its dialog and restoring the composer without a verdict. A child approval stays pending through idle waits, then withdraws when shared delegation or Goal active time is exhausted, with that cause named apart from human denial. Earlier completed effects remain.

| State/action | Required outcome |
|---|---|
| Ctrl+C on folder consent | Exit and restore the terminal without selecting read-only or saving trust |
| Idle Ctrl+C with a draft | Clear the draft |
| Idle Ctrl+C on empty input | Explain copying (in Fullscreen with mouse selection, `Select text with the mouse to copy; GESTURE for terminal selection` with the emulator's selection gesture; otherwise the emulator's Ctrl+Shift+C); a second press within two seconds exits |
| Ctrl+C during selected-Provider admission | Return to chat with the new draft retained and no Run receipt or retry; delegated account work may still complete |
| `/goal pause` during a Run | Pause at the next step; the in-flight call completes and a dispatched action is not aborted; Ctrl+C afterwards cancels now |
| First Ctrl+C during a Run | Request graceful whole-Run cancellation, even while a Fullscreen selection is shown |
| Second Ctrl+C during cancellation | Bounded local shutdown; report only the strongest durably confirmed terminal state |
| Escape | Closes the focused panel first; otherwise cancels a pending clipboard read, then clears a Fullscreen selection, then closes the completion menu. With nothing focused during a Run, cancels the Run like Ctrl+C: the Goal stays paused and resumable and the draft is kept; a second Escape during cancellation is ignored. Linear input cannot send Escape; Ctrl+C cancels there |
| Unix SIGTSTP / inline Ctrl+Z | Release input and modes before stopping, never stop after restoration fails; SIGCONT reacquires the chosen presentation and keeps draft, caret, history and pinned work |
| Unix SIGTERM/SIGHUP | Exit through the input-owning state; an active Run requests cancellation before bounded outcome confirmation |

`q`, Ctrl+D, `/goal pause` and other slash controls do not cancel work. An empty-draft Ctrl+D or `/exit` after the Run's outcome is shown, while the Run is still finishing, exits once it returns; `/exit` also abandons a held linear draft or undelivered steering note. Cancellation and shutdown grace is at most three seconds, and expiry never fabricates a cancelled receipt or answer. Run cancellation is distinct from pre-Run admission interruption and from compaction interruption; replay can instead expose an interrupted prefix. Interrupted compaction promises no Run cancellation or remote billing stop.

Raw mode, cursor, wrapping, echo and every enabled mode, including mouse reporting and alternate scroll, are restored on normal exit, error, cancellation, signal, render failure, partial acquisition, unwind and suspension; Fullscreen exit shows the cursor last and leaves the alternate screen. Receipt and answer output follow restoration and read-only confirmation. Renderer failure after Run admission may expose only committed sanitized linear facts or a typed presentation failure. Secret bytes never reach drawing, notices, Events or output during cleanup.

Classic cursor-query timeout fallback stops and joins the key reader, releases raw mode and then starts the linear reader; a raw-mode release failure prevents restart. Partial acquisition unwinds in reverse order. Cleanup attempts every remaining reset in order and returns the first error; a failed guard reset stays armed for its best-effort Drop retry. Failed reacquisition leaves the prior owner released. The [Transcript owner](../architecture/system-overview.md#8-terminal-presentation) keeps distinct histories and native emission tracking across replacement; linear Tool rows already written stay suppressed.
