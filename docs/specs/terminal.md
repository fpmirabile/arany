# Terminal and output contract

## Scope and related contracts

This contract covers attached chat, local controls, presentation, accessibility and deterministic process channels. It does not certify live accounts or every terminal and native platform. [Next steps](../../NEXT_STEPS.md) owns open defects and unperformed checks.

[Session](./session.md) owns lifecycle and compaction. [Credentials](./credentials.md) own saved-account scope, storage and authorization. [Provider](./provider.md) and [ChatGPT](./chatgpt.md) own model, consent and billing admission. [Architecture](../architecture/system-overview.md#8-terminal-presentation) owns physical responsibilities.

Editing constraints: [security rules](../../agents/security.md).

## Entry, modes and channels

| Entry | Observable contract |
|---|---|
| `arany [PROMPT]` | Requires terminal stdin and stderr. Without a prompt, opens a composer held locally until the first task submission; a prompt starts the first Run only after admission and leaves chat open. Fullscreen, the default, draws on stderr in the alternate screen; Classic uses the primary screen. Redirected or same-terminal output follows [terminal continuity](#terminal-continuity-and-provisional-text). |
| `--continue`, `--resume`, `--fork` | Explicit Session entry; Workspace or TTY matching never resumes work. A missing conversation, or a fork source without a completed Run, fails before the prompt with a message naming `arany --resume` or `/resume` and `--state-dir`. An unsafe State still reports the unsafe-state error. |
| `--profile PRESET` | Explicit private roster selection for attached mode or exec; supplies the primary tuple. Any supplied Provider/model/effort field must match. A present role-routing record conflicts. No preset is selected or read by default. |
| `--setup` | Resolves folder access before setup or Session creation. Cancellation before account save creates no Session. Idle `/setup` works inside the current conversation. |
| `exec --output text` | Noninteractive; no terminal modes. Stdout holds only the sanitized, indented committed answer; stderr holds the stable Session/Run/status receipt. A failed Run exits unsuccessfully without an invented answer. A Run stopped by a hook reports `Status: stopped_by_hook` and `error: Run stopped by hook[: REASON]`. An interrupted or hook-stopped Run whose Goal stays open adds `Goal paused; resume with arany exec --session-id SESSION --resume-goal GOAL` to stderr and exits unsuccessfully. An autonomous Goal that stops after a committed Run keeps that answer on stdout, appends `error: Goal stopped after a committed Run: REASON` to stderr and exits unsuccessfully. |
| `exec --output jsonl` | Stdout holds the latest Run's committed Events, its matching Goal's lifecycle and final report, and the new Session fact, if any ([Goal selection](./goals.md#current-format-replay-and-exec)). Successful non-roster JSONL leaves stderr empty; roster mode first writes its complete route manifest there. An interrupted Run keeps its committed Events and adds the same pause line to stderr. |
| `acp` | [ACP spec](./acp.md) owns the editor subprocess, capabilities and core text turns. |
| `serve --stdio` (reserved), `generate-schema [--out DIR]` | [Serve spec](./serve.md) owns protocol framing, schema export and the accepted server surface. |
| `show --output text\|jsonl SESSION_OR_RUN_ID` | Deterministic read-only replay without terminal modes. Session selection exposes direct canonical Events and the fork reference; Run selection exposes only that Run after strict parent validation. Invalid or conflicting ownership fails without output. It validates the Session-or-Run UUID before State access, opens only existing State read-only, never reads a credential and closes the Store before rendering. |
| `show --output supervisor-corpus SESSION_ID` | Session-only calibration JSONL to stdout, with no terminal initialization. The [Supervisor adapter](./tools.md#supervisor-adapter) owns format, privacy, replay, locking and overflow. Refusal exits unsuccessfully with empty stdout and a fixed diagnostic (plus safe overflow counts) on stderr. |

The command chooses the contract. An ineligible bare invocation fails before Engine entry and directs the caller to `exec`. Headless objective prefixes such as `/`, `@` and `!` are literal data, except that `exec --tools` and `--prompt` treat `/name [task]` as an invocation when `name` is an admitted Skill and not a compiled command (`serve` has no slash form).

An unavailable stderr sink never turns error reporting or cleanup into a panic, never blocks restoration of surviving terminal settings and never changes the intended exit class. Diagnostics never fall back to stdout. Output failure does not prove delivery of an error or receipt.

`--screen-reader` or `ARANY_SCREEN_READER=1` selects labeled append-only output with canonical input, without raw mode, cursor rewriting, boxes or animation. `TERM=dumb`, fewer than eight rows or unavailable geometry selects that fallback before acquisition. Resizing never switches presentation; only an explicit idle `/settings` chat-view change switches classic or fullscreen ownership.

`--no-color` and `NO_COLOR` remove color, including after reacquisition. Text labels, selection markers, focus and bracketed hints keep their meaning. Action and consent alternatives occupy separate vertical rows; horizontal button groups are not admitted. Slash-menu filters use Commands/Skills tabs with Left/Right navigation. Message bodies are unstyled. Inline role headings use `› You:` and `● Arany:` with emphasis; a two-cell rail groups nonempty user-body rows, assistant bodies keep plain indentation, and existing spacing separates messages without extra indexed rows; restored user previews use `› You:`; attached committed answers use `Arany · Answer:` and headless `exec` keeps `Answer:`. Linear mode keeps plain role labels without decorative rules. The terminal background stays user-owned.

Human output escapes or rejects ANSI/ECMA-48 controls, OSC sequences, C0/C1 controls, carriage return, backspace, bidirectional controls and forged line prefixes. JSONL comes only from a serializer, one object per line. Inline chat reserves one blank row above the transcript when at least five history rows fit, so a sticky command header cannot cover the first speaker label; with four or fewer history rows, content takes priority. Linear and deterministic output is unstyled and contains no CSI, OSC or carriage-return rewriting.

Roster selection displays the complete escaped [manifest](./provider.md#named-roster-presets) before credential access or Workspace-content loading, with native API / ChatGPT plan / exact custom unknown-pricing labels and every fallback. Headless output uses stderr and preserves stdout/JSONL. Attached independent submissions re-display the selected manifest using existing notices. The selector is the selection action; existing account/plan consent remains required. `/new` and `/clear` preserve process selection. Conflicting `/model` or `/setup` defaults cannot substitute a roster route at next-Run admission; restore the preset tuple or start a later invocation without `--profile`. No extra picker or confirmation flag is introduced. Roster-Goal resume requires the explicit matching selector as [Sessions](./session.md#roster-recovery-and-compaction) defines.

## Conversation, progress and history

Compact Tool rows follow Claude Code's `⏺ Operation(arg)` and indented `⎿ result` shape, without a `Tool ·` prefix or a success-state word. A Search row names its query and path plus any non-default option, such as `Search(fn \w+, src, regex, include **/*.rs, ignore case, offset 100, limit 10)`. Results give bounded entry, line or byte counts (including truncation), command exit status and total lines (for example `exit 0 · 12,340 lines (truncated)`), `applied` for file changes, or the disposition and sanitized failure text (`Error: ...` for a failed call, `denied`, `uncertain` and other dispositions by name). Consecutive successful reads by the same actor collapse into one row worded like Claude Code, such as `Read 2 files`, `Listed 2 directories` or `Searched for 2 patterns, read 2 files, listed 2 directories`, with combined counts (Git queries, Skills and MCP lists keep their own nouns); details retain each call. Pending, failed, denied, cancelled, conflicting, limited and uncertain calls remain distinct. Trust-bearing rows never collapse: unguarded, uncertainty, enforcement-cause, checkpoint, denial-source, cache-problem and hook markers stay visible. Cache markers show only rejected, failed and uncertain updates. Limit rows follow the committed closed cause: `timed out after N s` (the effective timeout, bounded by the operation cap, with `; /settings raises it` only for Commands), `output passed 1 GiB; stopped`, `no room left in this Run's context`, `too many reads at once; nothing was read`, `asked for more time than the pinned maximum` or `resource limit reached`. Command truncation labels derive from typed totals or limit causes, never from stdout or stderr marker text. This presentation does not change the [Tool guarantees](./tools.md). Classic and linear output append a read group once its boundary or the Run's end is known. Linear and screen-reader output use the same operation and result words, replacing the decorative glyphs with an operation line and `Result:`, without rewriting earlier output.

An active-Run notice names the unavailable action and a supported alternative, for example `/model changes are unavailable while a Run is active; Ctrl+C cancels`. View-only commands retain their current-value inspection; empty submission says `Run is active; Ctrl+C cancels`. Command notices respond to input and never imply that another action ran.

Failed Run feedback distinguishes an Engine-refused proposal from a Provider-call failure. It names the closed refusal cause (arguments, phase, plan, budget, scope, grant, byte limit, lease, unavailable operation, answer or Delegate), says the proposed action did not run where applicable, and never attributes an Engine refusal to the Provider. A Goal-budget stop and an invalid agent definition have their own copy; a stopped Tool step keeps its Tool-specific copy. Plan admission, unavailable Tool context, unverified workers, unmet criteria and refusal-limit failures have distinct copy. No answer is committed; earlier completed actions remain, and uncertainty keeps its existing warning. [Execution](./execution.md#accepted-outcomes) owns the closed causes and journal pairings.

Existing agent inspection and text `show` include historical worker identity/lineage, disposal and publication certainty, lease and verification facts from the [Session projection](./session.md#worker-replay). JSONL preserves canonical Events, including qualified lineage and refusal reasons; derived interruption facts add no fabricated Events or new terminal view.

Agent inspection shows only the selected actor's committed Supervisor verdicts; transcript details show every actor's verdicts in the Run. Each verdict is one dim labelled line, wrapping at the existing cell width: `Supervisor (shadow): possible loop; no action taken`. Multiple signals share that line; the capped verdict adds `verdict limit reached`. Wrapping preserves the full `no action taken` and cap wording, including at 80 and 120 columns. Terminal presentation uses a further-reduced fixed vocabulary without canonical features or evidence; [serve](./serve.md#notifications-and-items) forwards the canonical, privacy-reduced verdict. Linear and screen-reader inspection and `/transcript` use the same words without styling or controls. No verdict is displayed before commitment. The replay-derived collection follows the [verdict cap](./execution.md#persistence-bounds); no additional notices are fabricated after it. Transcript details retain their existing Run and byte limits and explicit overflow cue. Compact chat and accepted answers are unchanged; these lines never enter model input.

A Tool waiting for shared Guard capacity shows `queued · waiting for capacity` in classic, fullscreen and linear mode. The one-slot hint follows the current committed pending intent, clears when waiting or the Run ends, and never enters Events, history, replay or Provider context. It grants no authority and does not resume after restart; draft editing and Ctrl+C stay available.

Classic mode uses native scrollback above a bounded viewport. On its first draw for a Session it projects the newest whole-Run suffix, stopping before a Run that would exceed 16 Runs, 64 KiB of escaped rendered row text (including trusted headings, rails and indents) or 4,096 rendered rows. Every native-visible objective, Tool summary and available answer is counted before rows are materialized. A width-safe cue points to `arany show` for the complete history. Omitted Runs stay in the journal and full-history find and export; they are not backfilled on redraw. Fullscreen uses an alternate screen with managed history and a bottom composer. Classic never borrows the alternate screen. OSC 52 is written only on an explicit user copy gesture (a Fullscreen selection release, Ctrl+C or Ctrl+Shift+C with a selection, or `/copy`), never because of model, Tool, MCP, Skill, hook or repository content, following Claude Code and Codex. It is output-only: Arany never emits the `?` query and discards inbound OSC 52. The payload is the copy payload (the selected History display text, or for `/copy` the latest committed answer's display text), already escaped, with C0/C1 controls other than LF and TAB removed, base64-encoded under the fixed `c` selection and terminated by BEL, within the [clipboard copy limit](#public-limits-and-compatibility), written by the terminal owner on stderr and never in linear mode. No mode enables focus reporting or title OSC.

### Terminal continuity and provisional text

The saved `/settings` chat view selects the initial presentation, defaulting to fullscreen; `--classic` selects classic for that process without saving it. Saving a different chat view in idle `/settings` switches presentation within the same Session, keeping draft, caret and reading anchors. A running task locks mode changes. `Ctrl+T`, `Ctrl+O` or `/transcript` appends bounded detailed text to native scrollback in Classic and opens the detailed History in the Fullscreen [transcript pager](#transcript-pager), following Claude Code's Ctrl+O and Codex's Ctrl+T. Both dumps stay bounded with an explicit cue rather than Claude Code's complete dump: Classic follows the [detail limit](#transcript-detail-limit) and the pager's `[` its [whole-Run bound](#transcript-pager). Details stay available during work without cancelling it or granting authority.

Geometry is bounded to 4,096 columns and 262,144 cells; zero or excessive geometry fails with a typed presentation error. Classic keeps raw ownership while inserting output above its viewport sized to its content, at most the screen height, in batches of at most 64 native rows. Inline cursor observation targets stderr through the sole input reader under a one-second deadline; unavailable replies select linear fallback before work. Cursor queries travel only through the stderr backend and the sole raw reader; unsolicited replies are discarded and query bytes never enter drafts, stdout or history. Cleanup uses the stored owned area, never queries a stopped reader and never clears settled primary-screen transcript.

Fullscreen follows new content only at the live tail. PageUp/PageDown and find keep older source anchors through generation, completion and resize; returning live resumes following. Classic delegates scrollback, selection and copy to the emulator. Like Codex's inline viewport ([`tui.rs`](https://github.com/openai/codex/blob/af91f6ef/codex-rs/tui/src/tui.rs) at af91f6ef), every Classic surface takes min(screen height, its content height), with no floor: the idle and streaming composer, completion menus, Tool approval, folder trust, setup, selectors, pickers and rewind. Selector lists show at most 10 rows, the linear page size, and scroll inside, where Codex caps at 8. Growing scrolls the rows above into native scrollback rather than overwriting them. A height change clears only from the lower of the old and new viewport tops, repaints, and flushes pending native history in the same frame. Shrinking keeps the viewport top while history remains visible above it, so the composer stays under the latest history with no blank rows between. Rows below it stay empty until new output. A viewport that had filled the screen returns to the bottom row. History is never redrawn inside the viewport, so scrollback holds each row once. A dialog taller than the screen pages with Up, Down, PageUp and PageDown in both directions; accepting stays blocked until its last page has been shown. Native scrolling can move the composer out of view; typing returns through the emulator's scroll-on-input (the default in Terminal.app, iTerm2 and VTE). In tmux, leaving copy-mode on a key follows the user's tmux configuration. PageUp/PageDown are ignored in Classic; Ctrl+F shows `Use your terminal's find; Ctrl+T writes details to scrollback`. A complete 200-line answer stays readable without duplicate final lines or intermediate frames.

Replies stream as decoded provisional text in one active location. Strictly accepted completion replaces the candidate with the confirmed answer, inserted once into classic scrollback. Compact presentation shows replies and Tool summaries; details add bounded inert operation and result facts and explicitly public model commentary. Reasoning, raw prompts, transport JSON and uncontrolled upstream errors stay excluded. Tool details neither renew approval nor execute anything.

Display checkpoints retain at most 32 KiB of final-result candidate and 32 KiB of public commentary per Run, at most 32 commentary items and 64 Events of at most 2 KiB each, including at most one compiled detail-limit cue. Excess commentary shows a visible cue; answer overflow remains a failed call. Checkpoints use bounded byte chunks, not one Event per token. Cancelled or abruptly interrupted text is labeled incomplete on reopen; only acknowledged checkpoints survive a crash. Incomplete text is never an accepted Message, Provider history or compaction input. Validation-rejected candidates are withdrawn from presentation and stay qualified in the journal.

Classic exit removes transient input and panels and keeps the final conversation once. Fullscreen restores the previous shell screen with a brief receipt; text that the pager's `[` wrote there stays in the shell's scrollback. Redirected stdout receives confirmed answers after each task in either mode, after read-only outcome confirmation. Exec publishes no display checkpoints; show JSONL includes display-only Events. Linear `/settings` can save the chat view without changing the linear presentation. <a id="transcript-detail-limit"></a>`/transcript` exposes safe detail text for at most 16 recent Runs and 64 KiB per invocation, with an explicit limit cue; JSONL export covers the complete journal.

Empty chat shows a short width-aware welcome and `/help`; without a selected Provider, welcome, input hint and status point to `/setup`. Hints never become draft bytes.

History exposes committed objectives and terminal answers, labeled display-only incomplete text and public commentary, with bounded local notices interleaved. Notices never enter Events, Provider context, replay or `show`; they survive redraw and reacquisition and clear on Session change. Important errors have a textual heading, independent of color. Confirmed failed or cancelled Runs show safe compiled guidance without invented answers, raw error bodies or automatic retries. Progress, panel-closure and successful clipboard cues are transient; a copy cue names its destination, and an OSC 52 copy reads `sent to terminal (OSC 52); it may be ignored`, because Arany cannot confirm delivery. A failed copy gives `Copy unavailable: REASON` and an oversized one `Copy exceeds 100 KB; use arany show`; neither is retried. Retained-draft cues stay separate from history notices; a notice uses status fallback if no row fits.

Failure feedback follows the terminal cause: a recoverable Tool denial followed by a failed Provider call shows the Provider failure, not an approval-expiry notice. An attested filesystem denial is not evidence of user denial. Optional AI-review failure followed by human denial keeps the human approval guidance; completed effects are never described as rolled back.

In Fullscreen, PageUp/PageDown navigate; Ctrl+F opens local literal find, with grapheme Backspace and visible query, Enter and Escape hints; Ctrl+L returns to live. New content and resize preserve an older source-text anchor and show a textual new-content cue. `arany show` is the canonical export; emulator scrollback is not the complete history.

<a id="transcript-pager"></a>The transcript pager follows Claude Code's Ctrl+O transcript. It is modal: detailed History takes every row above one footer of keys, the composer is hidden and keeps its draft, keys it does not own do nothing, and pastes and clipboard results are discarded. It also takes input during compaction. `/` or Ctrl+F opens find, which starts at the newest match; `n` and `N` step to the next older and newer match. `j`/`k` or Down/Up move one row, Ctrl+U/Ctrl+D half a screen, PageUp/PageDown a screen, and `g`/`G` or Home/End jump to the top and the live end. The wheel, selection and copy work as in chat. `q`, Ctrl+O, Ctrl+T or Escape closes it; Escape first closes find, then clears a selection. Ctrl+C keeps its chat meaning, so it cancels a Run. `[` releases mouse capture and the alternate screen and writes the conversation to the primary screen like chat: each Run's objective, its details and its committed answer. It keeps the newest whole Runs, at most 16 and 64 KiB counting line endings and cues, escapes every line like all human output, starts with `Earlier Runs omitted; arany show prints the whole conversation` when older Runs are left out, or `The newest Run exceeds the transcript limit; arany show prints the whole conversation` when no Run fits, and ends with `Enter returns to Arany`. A Run still streaming shows its text as provisional. The Run keeps going without redrawing; Enter, Ctrl+C or a Tool approval reacquires the screen and capture and returns to the pager. Exit, suspension, signals, errors and unwinding during the dump restore the terminal without clearing that text.

Fullscreen selection follows Claude Code fullscreen and Codex. With [mouse capture](#selectors) the wheel scrolls History three rows. Click-drag selects History text, a double click selects a word (a whole URL inside `scheme://`) and a triple click a line. The selection shows in inverse video, so it does not depend on color, and stays anchored to source text through streaming, appended content and resize. Dragging past the top or bottom of History scrolls one row per motion event. Copied text is the escaped display text without role headings, rails, indents or Tool markers (`⏺`, `⎿`), with wrapped rows joined and separate messages divided by a blank line; its plain length is measured against the [clipboard copy limit](#public-limits-and-compatibility) before any Tool result is joined into it. With Copy on select (the default), releasing the button copies, and a successful copy clears the highlight, so the next Ctrl+C cancels as usual. Ctrl+Shift+C also copies, and so does Ctrl+C with a selection shown while chat is idle; during a Run or compaction Ctrl+C always reaches cancellation. Escape clears a selection; a failed copy keeps it. The first copy in a process names the emulator's own selection gesture from `TERM_PROGRAM`: Fn-drag in Terminal.app, Option-drag in iTerm2, otherwise Shift-drag, with the whole list over SSH or inside tmux, where it adds that wheel scrolling needs `set -g mouse on`. A selection grants nothing and never reaches Events, Provider context or diagnostics.

| Work state | Activity |
|---|---|
| Idle | No empty agent dashboard |
| Selected-Provider admission | Local preparing row and next-Run model; no prior Run or context shown as current |
| Single active primary | One primary row |
| Team or attention | At most three stable primary-first, spawn-ordered agent rows, with `+N more` for overflow |

Preparing is transient admission feedback, not an Event or proof of inference; linear mode announces it once. Current committed Events replace it. Every agent state and wait has a textual label, and completed or failed children stay visible while their Run is active. A queued or awaiting child never claims that a Provider call was dispatched. The attached view reduces every committed Event in order and redraws once per burst of ready Events (at most 64); provisional answer observation is separate and never shows reasoning. Redraw occurs only for committed Events, user actions or resize: no spinners, animations, idle refreshes or ticking clocks.

Status prioritizes interaction state and model, adds Provider from 50 columns, and shows a recognizable title when space permits. Terminal outcomes return to ready. Request-size metrics appear only in explicitly requested `/status` details. Older-history navigation may take priority at narrow widths; actionable notices can occupy the row. Active `/status` explains its rounded local request-size percentage, counts agents with a singular or plural label, points to `/agents`, and includes chat, instructions, files and images. It measures the pinned Arany content budget, including encoded images; it is not a Provider context-window percentage. Model tokens show only recorded Provider usage, with unknown values labeled unknown. Agent details identify input and output tokens of the last recorded call. Clipped printable ASCII model IDs keep both ends. The composer, `/status`, resume feedback, human export headings and discovery share one generated title, with explicit-title precedence; canonical title Events stay unchanged. Resume feedback names the conversation, not its UUID.

History rows derive only from the caller's loaded committed `SessionView`; indexing, search and drawing never read State, Workspace, credentials or Providers. During an active Run, `/status`, `/provider` and `/model` report only facts committed before its submission boundary.

## Draft editing and submission

Inline edits operate on whole graphemes and keep the caret on a grapheme boundary. Insertion, deletion and wrapping preserve accepted bytes except explicit editing and paste newline normalization. Long drafts wrap into at most four visible rows around the caret; the heading identifies a clipped window. Growth clips activity before input and status.

| Input | Effect |
|---|---|
| Left/Right, Backspace/Delete | Whole-grapheme movement or deletion |
| Up/Down | Explicit logical-line movement at a preserved grapheme column |
| Ctrl+Left/Right | Previous or next Unicode-whitespace-delimited chunk; punctuation in paths and model IDs stays in the chunk |
| Alt+Left/Right | On an empty draft, switch [agent chats](#agent-chats); otherwise inert |
| Ctrl+W | Delete the same preceding chunk range |
| Ctrl+J or decoded Shift+Enter | Insert newline without submission |
| Enter while idle | Submit through local validation, or complete an open slash-name menu |
| Enter during admission or catalog loading | Retain a task draft; never queue another Run |
| Enter during an admitted Run | Offer the draft as a steering note, or retain it as a task draft; never queue another Run |
| Enter during compaction | Retain all text, including slash commands; execute nothing |

Shift+Enter works only when the emulator distinguishes it; Arany enables no keyboard-enhancement mode. Linear input uses Enter to submit and Ctrl+D after nonempty input to continue a logical draft. On an empty draft Ctrl+D exits; on a retained draft it gives Enter and Ctrl+C guidance. Overflow or invalid physical input rejects that segment without submitting a prefix or erasing earlier accepted text.

Before consuming an idle inline draft, unknown slash syntax, invalid local arguments, an oversized rename or an incomplete objective selection leaves text and caret correctable, with no credential, State, Workspace or Provider I/O. Failure after State access or an attempted effect does not restore a consumed command, promise rollback or authorize resubmission. Linear submitted text starts a fresh physical line after rejection.

During an admitted Run, valid slash controls give read-only inspection, a locked notice or `/goal pause`. Next-Run defaults and Session mutations stay locked; `/exit` explains Ctrl+C cancellation first until the Run's outcome is committed.

Enter during an admitted Run offers the composer text as a steering note, unless it has attached images ("Steering notes are text only; draft retained"). The composer keeps the note until the Engine records it for the Run's next primary call; the notice then reads "Steering note sent to the agent", and the composer clears only if it still holds the offered text. While the note waits, "Steering note waits for the agent's next step; editing withdraws it" is shown. Any edit withdraws an untaken offer, with "Steering note withdrawn; draft retained". In Classic mode a second Enter while the note waits repeats that it waits; to add text, edit the composer, which withdraws the offer. A Run whose notes, each with its history label and the waiting note included, would exceed 8 KiB reports "No room for more steering notes this Run" and keeps the draft. A note over 8 KiB reports "Steering note exceeds 8 KiB; draft retained". Feedback never repeats note text. An undelivered note returns as a retained draft when the Run ends.

In linear mode, Enter hands the note off and clears the line. A further text line while it waits merges into the waiting note, separated by a blank line, so the Engine delivers one note. `/status` and `/goal pause` run normally. A draft kept by a refusal (including images) is held aside for the Run: a further text line reports "A draft is already retained; line not kept" and is not kept, and the held draft returns when the Run ends, ahead of any newer text. If both do not fit, the newer text stays with a notice that the retained draft was not restored. A Ctrl+D segment counts as a further text line while a draft is held; an empty Ctrl+D gives the retained-draft guidance.

`/goal pause` asks the Run to pause at its next step: the notice reads "Pausing at the next step; Ctrl+C cancels now", and the status row shows "Pausing at the next step... Ctrl+C cancels now" until the Run ends. The Goal pauses under its [pause boundaries](./goals.md#steering-notes-and-pause). A repeated `/goal pause` reports that it is already pausing. Idle `/goal pause` reports that no Goal is running. During a Run, `/goal pause` followed by other text is refused as a locked Goal change.

Manual and automatic compaction preserve draft, caret and history through success, failure, interruption, resize and suspension. Ctrl+K is locked; Ctrl+C interrupts maintenance without clearing the draft. Completion reloads canonical facts and returns to explicit idle submission. Automatic maintenance follows a confirmed Run receipt and shows a visible warning; its usage excludes model-authored summary text. An interruption does not guarantee rollback of a queued append or remote usage.

Draft feedback counts graphemes, including accepted whitespace; combined emoji and combining accents count as one. Storage and physical-line admission keep their UTF-8 bounds, so the UI promises no fixed Unicode-character maximum. Capacity errors ask the user to shorten input or paste a smaller section. Human attachment sizes use rounded decimal KB; canonical data and machine exports keep exact bytes.

The sole raw reader keeps reads nonblocking through shutdown, so signal-flushed input cannot strand its join. Its 32-event delivery channel applies backpressure at 256 backlogged events; a pending [cursor query](#terminal-continuity-and-provisional-text) permits read-ahead up to a hard cap of 4,352 backlogged events. Exceeding that cap closes input with an explicit error rather than dropping keys or growing without bound. A lone Escape waits at most one poll interval. Key repeats and releases, focus events and mouse events other than the wheel and the left button's press, drag and release are ignored. A left press on the cell of the previous press within 500 ms counts as a double, then triple, click. An SGR mouse record (`ESC [ <`) is read whole through its `M` or `m` terminator, storing at most 32 bytes; a malformed, out-of-range or oversized record, or one still unterminated at the ten-second record deadline, is discarded entirely, so no byte inside it reaches the draft, a dialog or an approval.

## Interactive commands and completion

The [compiled registry](../../crates/arany-cli/src/terminal/commands.rs) owns exact command names, aliases, argument syntax and availability. Workspace, Provider, Skill or persisted text cannot register or redefine commands. Only an exact lowercase name after a single column-zero slash is command syntax. `//text` submits `/text`; unknown commands give local suggestions without Provider input. No-argument controls accept trailing whitespace and reject extra arguments in every Run state.

Typing `/` at the draft-end caret opens a completion list below the input, even for one remaining prefix match. It shows at most 20 entry rows and a header, clipped to geometry while preserving input and status; the 21-command registry is longer than 20 rows, so its header shows the visible range. Commands and Skills occupy separate tabs by default. The active tab has an inverted background, bold text and a bracketed label; the inactive tab is subdued. Selection stays explicit without color. Left/Right switches tabs without editing. An empty tab or filtered list activates nothing, except that Enter on a Commands tab with no match invokes a Skill only when exactly one matches, so a unique Skill prefix behaves as in the combined list. Up/Down focuses; Tab fills the name and argument space; Enter invokes the selected command or Skill through normal admission. Escape closes without editing. For example, `/resum` followed by Enter opens the resume picker without an ID. Exact names, arguments, multiline or mid-draft editing take precedence. Outside that menu, Tab completes a unique registry name or value, or an admitted cached model; ambiguous arguments leave the draft unchanged. Hints distinguish Tab completion from Enter submission. Placeholders never enter the draft, submission or Events.

Completion performs no catalog or credential I/O on a keystroke. Provider or account changes invalidate catalog and effort candidates; a same-source redraw or model-only change keeps them. ## Rewind

Idle `/rewind` opens the checkpoint panel. Esc Esc within two seconds on an empty idle composer opens the same panel; with text it saves and clears the draft, with Up to recall that one local draft (text follows the draft byte bound and attachments follow the image bounds, replaced by the next cleared draft). A focused menu or panel consumes Escape first. The first idle Escape announces the second action. Rewind is locked during a Run, admission or maintenance. Attached images or another retained draft must be submitted or cleared before switching conversations. No rewind is automatic or available through headless `exec`.

Rows follow conversation order with the newest focused: `Run N · objective excerpt · time · K files changed since`, or `no code changes since`, plus `Before rewind` rows. Rewind file counts use `file` for one and `files` otherwise. Times come from committed Events (inherited timestamps are labeled inherited); excerpts are bounded to 80 characters. Later autonomous Runs are labeled `Goal run k` under their Goal objective; steering notes do not create checkpoints. Enter opens Restore code and conversation / Restore conversation / Restore code / Never mind, in that order. Code choices appear only for a nonempty plan. Unknown or open publications disable code actions with their Event sequence and an inspect-files reason; read-only access disables code actions with a grant reason. Conversation restoration remains available. A Before rewind row offers code restoration only.

Code choices open a paged preview with each path's restore, delete, recreate, drifted, history drift, unavailable, unsafe, outside grant or kept state, `+added -removed` line counts, and the non-rewindable effects list. Counts describe one replacement region after trimming equal leading and trailing lines; binary or unavailable content uses unknown counts. Cancel / Compare / Restore occupy vertical rows, initially Cancel. Every explanation page must be traversed in order before Restore; resize or suspension restarts review. Compare opens a numbered per-file picker and bounded text-diff pages: minus is current Workspace content, plus is checkpoint content. Each escaped diff page is at most 64 KiB; further pages are explicit, and binary or unadmitted comparisons say unavailable. Compare grants no file access and opens no Workspace paths independently of Engine admission.

Drift refuses the whole batch and lists affected files. Resolve listed files offers Cancel, `Restore the others, keep these files`, and `Overwrite changed files (their current content is saved first)`. Keep requires review and Restore on a new preview. Overwrite applies only to drift/history-drift, requires a separate Cancel / Overwrite after saving confirmation with Cancel focused, then review and Restore on the new preview. Unavailable, unsafe and outside-grant paths can only be kept. Empty effective plans refuse. These copy Cline/Roo's three restore choices and per-file Compare, and Claude Code's `/rewind`, Esc Esc and prompt restoration. Arany's drift refusal is stricter; [Tools](./tools.md#checkpoints-and-rewind) owns that policy and capture guarantees.

Receipts preserve the committed outcome: `Restored K files to before Run N`, `Rewind refused: M files changed outside Arany`, or `Rewind outcome unknown: inspect files before continuing`, with listed conflicts and checkpoint/pruning notices. Unknown outcomes never retry. Both mode preserves a successful code receipt if conversation restore fails or is cancelled: `Code restored; conversation unchanged; use /rewind → Restore conversation`. The [Session contract](./session.md#conversation-rewind) owns fork ordering, source preservation, budgets and lineage limits. On conversation restore the terminal switches to the fork, or an unsaved conversation for the first prompt, retains next-Run defaults and places the selected prompt in the composer without submitting it. A leading slash is escaped as a literal objective so restored history cannot execute a local command. Images, objectives over 8 KiB (including any literal escape), or unsupported control characters produce an omission notice. Linear mode announces the complete restored draft as not sent.

Unavailable checkpoint storage offers Retry / Reset checkpoint storage / Cancel. Reset requires complete warning review and a separate Cancel / Reset confirmation with Cancel focused; healthy, busy, unsafe or concurrently changed storage refuses. [Tools](./tools.md#checkpoints-and-rewind) owns deletion scope and private-state admission.

Classic, Fullscreen, linear and screen-reader modes share these states and words. Linear output lists numbered rows and accepts numbers or complete visible choice names; empty Enter, q, Ctrl+C or EOF cancels. It prints full inert paths, preview text and comparison pages without truncation or terminal rewriting. At 80+ columns the panel keeps full action hints; 50–79 keeps choose, review and cancel; below 50 it keeps arrows, Enter/PgDn and Escape, with full details on sequential pages. Below 16 columns or eight rows actions require resizing. Paths, excerpts and diff bytes are untrusted data, neutralized through the ordinary terminal-control escaping before layout or linear output. `show` text renders both rewind Events and the checkpoint field inertly; JSONL preserves canonical serialized Events.

## Selectors

A `/settings` row too wide for one line puts its value on the next line, so a changed value stays visible. The composer is hidden while a selector owns input and returns with its draft and caret. Each selector uses the Tool approval admission barrier: it first draws unarmed, with dim rows, no focus and no key hint (linear mode prints the rows without the prompt); the reader then discards earlier input, and the selector redraws armed with focus, key hint or prompt. Keys typed before the armed frame, including digits sent with Ctrl+K, are discarded; Ctrl+C, signals, suspension and resize keep their meaning. Typed text filters `/model` and [searches `/agents`](#agent-picker), so a digit there is search text.

Idle Ctrl+K offers Models, Agents, Resume and Setup, numbered 1-4, without consuming the draft; with no Provider, Setup has initial focus. The panel overlays the transcript without moving the history anchor; its local ASCII filter (at most 64 characters) never enters Session, context or scrollback. Metadata marks reviewed, listed or exact choices. Unknown native models require explicit effort and stay unproven until a strict response succeeds; ChatGPT choices need explicit levels; custom tuples use their declaration. A changed typed native or ChatGPT model starts at low; the same model keeps its effort; a Provider change clears model and effort. Selection loads no token and starts no inference; Run admission revalidates account, consent and custom evidence.

Cached choices open immediately while one cancellable refresh stays input-owned. Refresh failure keeps old rows visibly stale; replacement preserves filter, model identity and admissible effort. Linear numbers remain the opened snapshot, so refresh cannot retarget an edited choice. Completion or cancellation during loading preserves draft text without automatic submission; queued typeahead is not guaranteed. Custom declarations load locally.

Saved-account tuples and catalog IDs survive restart. A new bare Session restores the last acknowledged tuple for the same Provider and account UUID and seeds cached rows with no credential load or network request; OS-store authorization is a separate phase. Explicit flags and resumed defaults win; a different or replaced account inherits neither tuple nor catalog. `/model` refreshes restored rows through the same input-owned flow. Remembering failure is visible without undoing the selection. The cache holds at most eight sources, 4,096 IDs per source and 1 MiB in aggregate, evicting the oldest unselected source first. A separate optional Provider and account pointer remembers explicit setup, model and resume choices; refresh never changes it. Token-free preferences without that pointer stay readable. Stored availability never authorizes an account, model, effort, custom destination or inference. With no saved preference, startup may copy only the matching model and effort from the latest valid Session in the same Workspace, into a new empty Session.

Selection rejected by another Session operation's lock gives labeled feedback without saving or retrying. A typed unavailable ChatGPT account or invalid custom choice preserves the selection and starts no sign-in, fallback or inference. Catalog failure changes no defaults; published account work is not rolled back. State, replay and terminal-owner failures keep their fatal boundary under CLI rules.

## Setup and account choices

After folder consent, attached startup checks local history before account setup, catalog use or Session entry. Incompatible history ([archive rule](./execution.md#admission-persistence-and-recovery)) is archived automatically: the new unsaved conversation opens with a notice naming the archive, and, as after a reset, an initial objective is not submitted. Damaged history, or a failure that blocks the archive, opens a recovery choice in the current UI, without a special flag or restart. It explains the failure and offers Retry, Reset history when the history is damaged, and Exit. Retry is initially focused; cancellation leaves stored data unchanged. Reset history requires complete warning review and explicit Back or Accept, with Back initially focused. Resize or resume restarts that review. The warning says that all conversations in this StateRoot and their derived Provider evidence are discarded, while accounts, model choices and folder trust remain. A confirmed reset opens a new unsaved conversation with no resumed ID and no automatic objective; if an initial objective was supplied, the UI says it was not submitted and must be entered again.

Reset requires checked private regular files and exclusive ownership against other current Arany Store users. Concurrent change, active use or unsafe files refuse deletion with visible retry guidance. A storage failure after deletion may leave an incomplete reset; report that and keep recovery available. Unsupported history is never interpreted or converted; read-only inspection such as `show` rejects it unchanged.

A new bare start with no account still opens chat and names `/setup`; an unconfigured task starts no Run. A saved explicit access or model preference is reused on bare startup, keeping its Provider and account identity. Disconnected ChatGPT access is not restored as connected. Without a remembered selection, mixed saved API and ChatGPT access requires an explicit billing-route choice, with Cancel initially focused. Empty Enter cancels and creates no Session; invalid chosen access never falls back to another billing route.

Idle `/setup` preserves the draft and defaults on pre-save cancellation. Native and ChatGPT setup return from selected-account catalog discovery with a low-effort model, without a questionnaire or synthetic inference. Provider and account contracts own preferred-model selection and admission; catalog visibility alone does not prove compatibility. Incompatible or damaged saved setup gives actionable feedback and leaves the composer available; `/setup` offers the [checked local reset](./credentials.md#storage-replacement-and-recovery), with Back focused and its deletion scope disclosed before confirmation. Reset is a separate effect; cancelling later setup does not restore deleted records. Recoverable initial `--setup` errors return to chat; terminal failure and shutdown still exit.

Successful setup returns to the selected chat presentation with a usable composer and notice. Setup never changes inherited output flags, including when terminal input and output share an open-file description, in inline and linear modes.

Attached startup presents [selected-item authorization](./credentials.md#selected-item-authorization) after folder consent and account choice, before Provider catalog work and chat input. Its waiting frame names the OS password store; already granted access can stay quiet. Escape or Ctrl+C exits without a Run, restoring terminal ownership and cleaning up the helper. Denial, missing or invalid credentials, a changed selection or timeout gives safe feedback and never submits an initial or resumed objective. Credential scope, deadlines and permission persistence belong to the credential contract.

Saved ChatGPT choices are Use saved, Reconnect and Connect new; multiple saved accounts show short IDs and the current marker. Cancelling the account picker changes nothing; reusing the current account avoids browser sign-in. An explicit switch, new connection or reconnect can keep account-only defaults if later catalog work fails or cancels, without rolling back published account work. Reconnect repeats backend-specific consent and clears old diagnostic evidence. Failed catalog discovery shows a retry notice without retrying itself.

On Linux, replacing the executable during an open conversation must not stop the running image from launching its credential helper or look like a credential-store failure. Store failures say the desktop password store could not be accessed and direct the user to unlock it and retry. Missing saved sign-in directs to Reconnect; generic authorization failure gives setup or retry guidance without asserting a cause. Reconnect preserves a pinned store; when unavailable, guidance names Connect new's separately consented private-file option. That option warns that sign-in credentials will be stored without encryption, keeps Cancel focused, and opens no browser before explicit consent.

Non-secret inline setup uses centered borderless focused rows with arrows, Tab, Enter and Escape; typed characters do not select rows. Linear choices accept visible names, not numeric codes, and announce the option empty Enter chooses. Reopening a choice announces it again; identical redraws stay quiet. Labels and actions stay readable at 16 columns without color.

API-key input disables echo and shows only a character count, never key content; printable ASCII admission makes its 512-character limit exact. Non-secret input keeps echo. ChatGPT consent shows the complete backend-specific warning before Back or Accept; Back starts focused and empty Enter declines. Resize or resume restarts review. Insufficient inline geometry rejects before sign-in. Private-file storage has a separate plaintext warning and explicit selection, with Cancel initially focused; it never silently replaces a pinned keyring.

Rejected linear setup or key characters form a correction-only suffix: Backspace removes them before earlier valid input, and later characters become no choice or key bytes until corrected. Anthropic's optional Console workspace ID is visible text with local validation, not a secret or ambient scope. Linear rejection restores echo and starts a new physical line. The OS store may show its own unlock prompt; Arany makes no OS-store encryption guarantee.

Local history reset validates the database and its three fixed SQLite sidecars before any SQLite access. It snapshots their identities, sizes and modification times under the lease, and rejects any change before removing a file. It clears only those four files, recreates a checked empty database and leaves Session lock files in place.

## Paste and attachments

Framed Unix inline text paste atomically inserts one bounded valid block into the editable draft, including during admission, work, maintenance and catalog waits. CR and CRLF become LF; tabs stay bytes with four-space visual expansion. Overflow or invalid UTF-8 rejects the entire record. Paste never submits, completes a command or activates a selector; modal pickers ignore it. An unterminated framed record fails terminal ownership closed after the ten-second deadline. Secret and Workspace fields keep separate bounds and explicit Enter. Linear canonical input does not claim safe unframed emulator multiline paste.

Explicit Ctrl+V, decoded Ctrl+Shift+V or `/paste` requests one bounded OS clipboard read. Unsupported transport, hostile payload or process failure gives local feedback without altering the draft. Clipboard data stays transient untrusted input until submission and supplies no key event, file authority or automatic Run. Enter while loading retains rather than submits. Picker or find entry, release, suspension and ownership changes discard late results. During a Run, Ctrl+C still cancels it. Linear mode shows a complete inert `Draft (not sent)` preview, including during work, and renews its idle prompt after success or failure.

Linux supports admitted text and PNG through standard Wayland or local X11 clients; compiled routing is not proof of native desktop interoperability. macOS uses a bounded, supervised AppKit pasteboard read, preferring PNG over UTF-8 text and rejecting other advertised image formats, changed generations and excess bytes. AppKit exposes no size check before `dataForType`, so the bound applies to the parent's read of the child's output, and the child may materialize the full payload.

Clipboard clients run in owned process groups under a shared two-second read or copy deadline. Every client exit attempts group termination and positive child reaping under a separate one-second cleanup deadline, except a Linux serving copy client (`wl-copy` or `xclip`): as in Claude Code and Codex, its descendant keeps serving the selection after the foreground process exits, until another owner takes it, even after Arany exits. Arany waits for that foreground exit, reaps it and leaves the descendant in its own process group with only the payload and the cleared environment; a failure or deadline terminates the whole group. Cancellation discards the late payload without waiting on the terminal reactor; the process owns at most one clipboard worker and refuses another read until it finishes. A cleanup error or deadline returns `clipboard cleanup unconfirmed`, never a successful payload or a claim of reaping. The worker retains the child for nonblocking reap observation, and further clipboard reads report the unconfirmed cleanup until Arany restarts, including when cancellation discarded the original result. Terminal teardown signals the outstanding worker and waits at most one second for shutdown; a missed deadline reports unconfirmed cleanup to stderr even when cancellation discarded the original result. No read is retried automatically.

The image contract admits at most four PNGs totaling 192 KiB raw bytes, including image-only submission. An image-only Message has empty user text. Human history shows metadata only; canonical history, forks and explicit JSONL export retain bytes. Compaction is metadata-only: it uses image metadata and prior assistant interpretation, not covered pixels. Overflow rejects a whole image or whole historical turn, never a truncated prefix or a silently lost attachment. Custom routes remain text-only.

Clipboard transports come only from checked local OS metadata: standard Wayland or local X11 clients on Linux, the checked `osascript` bridge for paste and `pbcopy` for copy on macOS, and a checked tmux socket for copy. A transport is never selected from `PATH`, an external host, an arbitrary command or Provider content. The child receives a cleared environment with only the selected display or runtime variables (plus `LANG` for `pbcopy`), never account credentials, network settings or the home directory as configuration. Its process group is owned before any fallible pipe setup; cleanup follows the deadline and uncertainty rules above. Support checks never read the user's clipboard.

Idle `/copy` copies the latest committed answer's escaped display text; it is locked during a Run. The copy goes to the first destination that works, trying each at most once: a native client when the session is local (no `SSH_CONNECTION`, `SSH_CLIENT` or `SSH_TTY`), which is `wl-copy` (Wayland) or `xclip` (X11) on Linux and `pbcopy` with `LANG=en_US.UTF-8` on macOS; then, inside tmux, `tmux -S SOCKET load-buffer -w -` (tmux 3.2 or later) after `$TMUX`'s socket is checked to be absolute, a socket and owned by the user in a private canonical directory whose every ancestor is owned by root or the user and is not group- or world-writable unless sticky; its device and inode are checked again before and after the client runs, and a change fails that destination; then OSC 52. `xsel` is not used, because its daemon calls `setsid()` and leaves the owned process group. Copy clients come from the same admitted root-owned directories as paste clients, so Homebrew tmux on macOS is never used, and they read only the payload on stdin. Copied text is never journaled, sent to a Provider or recorded in diagnostics.

OSC 52 depends on the emulator: Terminal.app and VTE do not write the clipboard through it; iTerm2 requires "Applications in terminal may access clipboard". Over SSH, Terminal.app users need Fn-drag or Classic. Inside Homebrew tmux on macOS, OSC 52 needs `set -g set-clipboard on`. Kitty, foot, WezTerm, Ghostty and Alacritty provide OSC 52 destinations; interoperability still requires the [owner-run checks](../../NEXT_STEPS.md#terminal).

Admitted PNG bytes are kept unchanged, including metadata, without local decompression. Admission checks structure, chunk CRCs and dimensions. Animated PNG and unknown critical chunks reject. Dimension admission is not raster decoding or proof of vision support. Filenames, URLs and terminal image escapes are never admitted.

## Interruption, suspension and restoration

| State/action | Required outcome |
|---|---|
| Ctrl+C on folder consent | Exit Arany and restore the terminal without selecting read-only or saving trust |
| Idle Ctrl+C with a draft | Clear the draft |
| Idle Ctrl+C on empty input | Explain copying (in Fullscreen with mouse selection, `Select text with the mouse to copy; GESTURE for terminal selection`, where GESTURE is the emulator's own selection gesture; otherwise the emulator's Ctrl+Shift+C); a second press within two seconds exits |
| Ctrl+C during selected-Provider admission | Return to chat with the new draft retained and no Run receipt or retry; delegated account work may still complete |
| `/goal pause` during a Run | Request a pause at the next step; the in-flight call completes and a dispatched action is not aborted; Ctrl+C after it cancels now |
| First Ctrl+C during a Run | Request graceful whole-Run cancellation, even while a Fullscreen selection is shown |
| Second Ctrl+C during cancellation | Bounded local shutdown; report only the strongest durably confirmed terminal state |
| Escape | Close the focused panel first; a pending clipboard read is cancelled first, then a Fullscreen selection is cleared, then the completion menu closes. With nothing focused during a Run, it cancels the Run like Ctrl+C: the Goal stays paused and resumable and the draft is kept; a second Escape during cancellation is ignored. Linear (canonical line) input cannot send Escape; Ctrl+C is the cancel key there |
| Unix SIGTSTP / inline Ctrl+Z | Release input and modes before stopping, and never stop after restoration fails; SIGCONT reacquires the chosen presentation and preserves draft, caret, history and pinned work |
| Unix SIGTERM/SIGHUP | Exit through the input-owning state; an active Run requests cancellation before bounded outcome confirmation |

`q`, Ctrl+D, `/goal pause` and other slash controls do not cancel active work. An empty-draft Ctrl+D or `/exit` after the Run's outcome is shown, while Arany still finishes that Run, exits once it returns; `/exit` also abandons a held linear draft or an undelivered steering note. The cancellation and shutdown grace is at most three seconds; expiry must not fabricate a cancelled receipt or answer. Run cancellation stays distinct from pre-Run admission interruption and from compaction interruption. Replay can instead expose an interrupted prefix. An interrupted compaction makes no Run-cancellation or remote-billing-stop promise.

Restore raw mode, cursor, wrapping, echo and every enabled mode, including mouse reporting and alternate scroll, on normal exit, error, cancellation, signal, render failure, partial acquisition, unwind and suspension. Receipt and answer output follows restoration and read-only confirmation. Renderer failure after Run admission may expose only committed sanitized linear facts or a typed presentation failure. Secret bytes stay absent from drawing, notices, Events and output throughout cleanup.

Width layouts distinguish at least 80 columns, 50–79 and narrower terminals. At 20–39 columns picker hints keep editing, navigation, Enter and Escape; at 16–19 they keep distinguishing identity and essential actions. Unperformed native, assistive-technology and fault-timing checks are listed in [next steps](../../NEXT_STEPS.md#beta-1-final-user-owned-checks). Chain-of-thought, raw prompts, reasoning items, raw wire token streams and uncontrolled upstream errors are never conversation sources. Explicit action approval alone exposes the bounded sanitized immutable action for a user decision.
