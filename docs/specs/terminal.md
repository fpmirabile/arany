# Terminal and output contract

## Scope and related contracts

This contract covers attached chat, local controls, presentation, accessibility and deterministic process channels. It does not certify live accounts or every terminal and native platform. [Next steps](../../NEXT_STEPS.md) owns open defects and unperformed checks.

[Session](./session.md) owns lifecycle and compaction. [Credentials](./credentials.md) own saved-account scope, storage and authorization. [Provider](./provider.md) and [ChatGPT](./chatgpt.md) own model, consent and billing admission. [Architecture](../architecture/system-overview.md#8-terminal-presentation) owns physical responsibilities.

Editing constraints: [security rules](../../agents/security.md).

## Entry, modes and channels

| Entry | Observable contract |
|---|---|
| `arany [PROMPT]` | Requires terminal stdin and stderr. Without a prompt, opens a composer held locally until the first task submission; a prompt starts the first Run only after admission and leaves chat open. Fullscreen, the default, draws on stderr in the alternate screen; Classic uses the primary screen. Redirected or same-terminal output follows [terminal continuity](#terminal-continuity-and-provisional-text). |
| `--continue`, `--resume`, `--fork` | Explicit Session entry; Workspace or TTY matching never resumes work. A missing conversation, or a fork source without a completed Run, fails before the prompt with a message naming `arany --resume` or `/resume` and `--state-dir`. An unsafe State still reports the unsafe-state error. |
| `--profile PRESET` | Explicit private roster selection for attached mode or exec; supplies the primary tuple. Any supplied Provider/model/effort field must match. A present role-routing record conflicts. No preset is selected or read by default. |
| `--setup` | Resolves folder access before setup or Session creation. Cancellation before account save creates no Session. Idle `/setup` works inside the current conversation. |
| `exec --output text` | Noninteractive; no terminal modes. Stdout holds only the sanitized, indented committed answer; stderr holds the stable Session/Run/status receipt. A failed Run exits unsuccessfully without an invented answer. A Run stopped by a hook reports `Status: stopped_by_hook` and `error: Run stopped by hook[: REASON]`. An interrupted or hook-stopped Run whose Goal stays open adds `Goal paused; resume with arany exec --session-id SESSION --resume-goal GOAL` to stderr and exits unsuccessfully. An autonomous Goal that stops after a committed Run keeps that answer on stdout, appends `error: Goal stopped after a committed Run: REASON` to stderr and exits unsuccessfully. |
| `exec --output jsonl` | Stdout holds the latest Run's committed Events, its matching Goal's lifecycle and final report, and the new Session fact, if any ([Goal selection](./goals.md#current-format-replay-and-exec)). Successful non-roster JSONL leaves stderr empty; roster mode first writes its complete route manifest there. An interrupted Run keeps its committed Events and adds the same pause line to stderr. |
| `acp` | [ACP spec](./acp.md) owns the editor subprocess, capabilities and core text turns. |
| `serve --stdio`, `generate-schema [--out DIR]` | [Serve spec](./serve.md) owns protocol framing, schema export and the accepted server surface. |
| `storage [--workspace PATH] [--state-dir PATH]` | Local bounded text inventory without a Provider/account, terminal acquisition or Session. [Storage report](#storage-report) owns channels and availability. |
| `show --output text\|jsonl SESSION_OR_RUN_ID` | Deterministic read-only replay without terminal modes. Session selection exposes direct canonical Events and the fork reference; Run selection exposes only that Run after strict parent validation. Invalid or conflicting ownership fails without output. If strict replay rejects a directly selected Session with `InvalidHistory` or `InvalidSnapshot`, inspection scans the whole journal within [the generated Event scan limit](./limits.md#max_list_scan_events). A fault in another Session can trigger this fallback and supply its rejecting sequence and cause; output includes only the selected Session's direct Events. It renders the valid prefix, the typed rejecting sequence and cause, then a per-Event lenient tail; undecodable payloads are a fixed marker. Exceeded scan or replay bounds and Store infrastructure errors fail without output. The notice says the projection is read-only and not resumable, and the command exits unsuccessfully. JSONL uses a `notice` object followed by one object per tail Event. Valid-history output stays byte-identical. It validates the Session-or-Run UUID before State access, opens only existing State read-only, never reads a credential and closes the Store before rendering. |
| `show --output supervisor-corpus SESSION_ID` | Session-only calibration JSONL to stdout, with no terminal initialization. The [Supervisor adapter](./tools.md#supervisor-adapter) owns format, privacy, replay, locking and overflow. Refusal exits unsuccessfully with empty stdout and a fixed diagnostic (plus safe overflow counts) on stderr. |

Headless `exec` text and JSONL deterministically project reopened committed history; Server notifications never become output lines. The [Serve contract](./serve.md#scope-and-related-contracts) owns its in-process connection behavior.

Headless `exec --tools` follows [H1 host policy](./tools.md#primary-host-commands): eligible admitted host prefixes may run in default/dontAsk; every unresolved host ask refuses immediately. It cannot create rules or reuse a previous process epoch. Text, JSONL, show and Goal receipts retain the existing unguarded and non-rewindable effect markers.

The command chooses the contract. An ineligible bare invocation fails before Engine entry and directs the caller to `exec`. Headless objective prefixes such as `/`, `@` and `!` are literal data, except that `exec --tools` and `--prompt` treat `/name [task]` as an invocation when `name` is an admitted Skill and not a compiled command (`serve` has no slash form).

An unavailable stderr sink never turns error reporting or cleanup into a panic, never blocks restoration of surviving terminal settings and never changes the intended exit class. Diagnostics never fall back to stdout. Output failure does not prove delivery of an error or receipt.

`--screen-reader` or `ARANY_SCREEN_READER=1` selects labeled append-only output with canonical input, without raw mode, cursor rewriting, boxes or animation. `TERM=dumb`, fewer than eight rows or unavailable geometry selects that fallback before acquisition. Resizing never switches presentation; only an explicit idle `/settings` chat-view change switches classic or fullscreen ownership.

`--no-color` and `NO_COLOR` remove color, including after reacquisition. Text labels, selection markers, focus and bracketed hints keep their meaning. Action and consent alternatives occupy separate vertical rows; horizontal button groups are not admitted. Slash menus follow the [completion contract](#interactive-commands-and-completion). Message bodies are unstyled except recognized leading slash tokens and the assistant Markdown projection below. Inline role headings use `› You:` and `● Arany:` with emphasis; a two-cell rail groups nonempty user-body rows, assistant bodies keep plain indentation, and existing spacing separates messages without extra indexed rows; restored user previews use `› You:`; attached committed answers use `Arany · Answer:` and headless `exec` keeps `Answer:`. Linear mode keeps plain role labels without decorative rules. The terminal background stays user-owned.

Human output escapes or rejects ANSI/ECMA-48 controls, OSC sequences, C0/C1 controls, carriage return, backspace, bidirectional controls and forged line prefixes. JSONL comes only from a serializer, one object per line. Inline chat reserves one blank row above the transcript when at least five history rows fit, so a sticky command header cannot cover the first speaker label; with four or fewer history rows, content takes priority. Linear and deterministic output is unstyled and contains no CSI, OSC or carriage-return rewriting.

Roster selection displays the complete escaped [manifest](./provider.md#named-roster-presets) before credential access or Workspace-content loading, with native API / ChatGPT plan / exact custom unknown-pricing labels and every fallback. Headless output uses stderr and preserves stdout/JSONL. Attached independent submissions re-display the selected manifest using existing notices. The selector is the selection action; existing account/plan consent remains required. `/new` and `/clear` preserve process selection. Conflicting `/model` or `/setup` defaults cannot substitute a roster route at next-Run admission; restore the preset tuple or start a later invocation without `--profile`. No extra picker or confirmation flag is introduced. Roster-Goal resume requires the explicit matching selector as [Sessions](./session.md#roster-recovery-and-compaction) defines.

## Human-readable measures

Human-facing sizes use the shared size formatter across attached, linear, plain and accessible output: below 1 KB, exact B (for example `512 B`); otherwise one decimal KB/MB/GB/TB with a 1024 base (for example `38.3 KB`), promoting to the next unit when the rounded value reaches 1024.0. This follows Claude Code and Codex's readable units and line/entry summaries. Draft and text counts prefer characters or lines where those are the defined measure; byte limits retain their actual meaning and display in these size units. JSON/JSON-RPC (`serve`, ACP), JSONL exports including `exec`, journals/Events, schema fixtures and diagnostics retain exact machine units, including integer bytes and milliseconds.

Durations use the shared duration formatter with `h`, `min` and `s`, omitting zero components except `0 s`. Fractional seconds preserve millisecond precision without trailing zeros: `0.001 s`, `1.5 s`, `2 min`, `1 h 30 min`. Time limits use the same format without rounding away their bounds. Large counts use digit grouping (for example `12,340 lines`) or explicitly approximate rounded values.

## Conversation, progress and history

Answer headings carry any unguarded and host effect counts. Fullscreen, its pager, Classic and selected agent results format top-level ATX assistant headings with bold weight and hidden heading delimiters, following Codex CLI. Fenced and indented code, including code nested in lists and quotes, preserve whitespace and line boundaries with plain reverse styling and grapheme wrapping; fence delimiters are hidden and info strings decode parser escapes and entities into bold, sanitized labels with per-fragment source origins and grapheme wrapping, without loading lexers. Top-level pipe tables use fitted columns with bold headers and wrapped cells, or header/value records when narrow, following Codex CLI. Table cells decode escaped pipes/entities and style emphasis, strong emphasis and inline code; generated labels, separators and padding carry source anchors. In paragraphs, setext headings and table cells, inline, reference, collapsed and shortcut links render as underlined `label (destination)`, including when label and destination are equal, following Codex CLI's no-hyperlink path; autolinks show their URL once. Destinations wrap at word/grapheme boundaries, titles are hidden, and links are escaped inert text without fetching, opening, path resolution or OSC 8. Destinations decode entities and escapes before sanitization; reference definitions are hidden. HTML and images remain inert literal source. Paragraphs and setext headings decode escapes and entities and style emphasis, strong emphasis and inline code with hidden delimiters, following Codex CLI: a soft break keeps its source row break, a hard break adds a row, prose wraps at spaces and long words break at graphemes, and setext headings are bold with the underline hidden. An entity decoding to several graphemes is one atomic source group. Ordered and unordered lists and block quotes use generated source-anchored markers and rails: bullets show `• `, ordered items count from the list's starting number and quotes show `│ `. Following Codex CLI, wrapped and continued rows retain hanging indents and quote rails, including nested, empty and code-first items; indentation follows CommonMark tab columns. Strikethrough, task-list markers, thematic breaks and footnote references remain literal source. Messages with lone carriage returns stay literal under the control-escaping contract. Provisional and incomplete answers use the same bounded projection, retaining their qualified headings. Formatting is a disposable projection; canonical Markdown remains unchanged. Counting, drawing, find and resize share layout. Repeated destinations keep distinct selection, reading and find anchors through reflow; a literal match in a definition selects its first rendered use, and stepping visits uses in row order. Code, ATX headings and literal lines retain source line boundaries and wrap at grapheme boundaries, with safe replacement at tiny widths; monochrome retains heading weight and block structure. Linear/screen-reader output, `exec`, `show`, JSONL, serve and ACP preserve source and existing escaping.

The renderer checks [source bytes](./limits.md#max_markdown_parse_bytes) before parser construction, then bounds [event containers](./limits.md#max_markdown_depth), [events](./limits.md#max_markdown_events), [escaped output including decoration](./limits.md#max_markdown_output_bytes) and [rows](./limits.md#max_markdown_rows). Overflow selects whole-message escaped literal fallback plus one formatting-limit cue outside copied source, without truncating the answer or changing its Run. Parser construction precedes event limits and has no hard RSS/deadline guarantee; no retained AST or cross-Session cache exists. Tables bound [columns](./limits.md#max_markdown_table_columns) and [data rows](./limits.md#max_markdown_table_rows) before growing the matrix; parser construction retains its upstream empty-cell padding cap independently of renderer limits. Emitted fragments, including fence labels, are sanitized after decoding.

Compact Tool rows follow Claude Code's `⏺ Operation(arg)` and indented `⎿ result` shape, without a `Tool ·` prefix or a success-state word. A Fetch row names its URL and a Web search row its query. A Search row names its query and path plus any non-default option, such as `Search(fn \w+, src, regex, include **/*.rs, ignore case, offset 100, limit 10)`. Results give bounded entry or line counts and readable sizes (including truncation), command exit status and total lines (for example `exit 0 · 12,340 lines (truncated)`) followed by only the nonzero selection counters (ignored entries with `(N pruned roots)`, oversized inputs, discarded outputs), none when all are zero, `applied` for file changes, or the disposition and sanitized failure text (`Error: ...` for a failed call, `denied`, `uncertain` and other dispositions by name). Consecutive successful reads by the same actor collapse into one row worded like Claude Code, such as `Read 2 files`, `Listed 2 directories` or `Searched for 2 patterns, read 2 files, listed 2 directories`, with combined counts (Git queries, Skills and MCP lists keep their own nouns); details retain each call. A Command or unguarded command row shows a multi-line script argument as its first non-blank line followed by ` …` when more non-blank lines follow, never an escaped line break, in every mode; the shown line stays escaped and bounded. Pending, failed, denied, cancelled, conflicting, limited and uncertain calls remain distinct. Failed command rows append at most 80 cells of escaped stderr beside the exit and selection counts. Trust-bearing rows never collapse: unguarded, uncertainty, enforcement-cause, checkpoint, denial-source, cache-problem and hook markers stay visible. Cache markers show only rejected, failed and uncertain updates. Limit rows follow the committed closed cause: `timed out after DURATION` (the effective timeout, bounded by the operation cap, with `; /settings raises it` only for Commands), `output passed 1.0 GB; stopped`, `no room left in this Run's context`, `too many reads at once; nothing was read`, `asked for more time than the pinned maximum` or `resource limit reached`. Command truncation labels derive from typed totals or limit causes, never from stdout or stderr marker text. Compact summaries and approval actions dispatch through the closed Tool family and execution-site classifications; family ownership changes do not change operation labels, order, receipts, host warnings, escaping or inert output. This presentation does not change the [Tool guarantees](./tools.md). Classic and linear output append a read group once its boundary or the Run's end is known. Linear and screen-reader output use the same operation and result words, replacing the decorative glyphs with an operation line and `Result:`, without rewriting earlier output.

An active-Run notice names the unavailable action and a supported alternative, for example `/model changes are unavailable while a Run is active; Ctrl+C cancels`. View-only commands retain their current-value inspection; empty submission says `Run is active; Ctrl+C cancels`. Command notices respond to input and never imply that another action ran.

Failed Run feedback distinguishes an Engine-refused proposal from a Provider-call failure. A committed preflight refusal shows its exact typed cause and fixed reason, followed by `The refused action was not dispatched.`; JSONL and text `show` retain the canonical refusal Event. It names the closed refusal cause (arguments, phase, plan, budget, scope, grant, byte limit, lease, unavailable operation, answer or Delegate), says the proposed action did not run where applicable, and never attributes an Engine refusal to the Provider. A Goal-budget stop uses the [deterministic numeric Goal feedback](./goals.md#budget-refusal-feedback), labelled `Arany status`, including recent bounded Tool failures and preserved-answer wording. Attached, `exec` stderr and text `show` use the same committed facts; JSONL remains canonical Events. `exec` admission-refusal reload uses the shared refusal-record lookup and retains its looser budget-stop fallback. Committed receipts render the exact Run being reported, even when a Goal contains multiple Runs. An invalid agent definition has its own copy; a stopped Tool step keeps its Tool-specific copy. Plan admission, unavailable Tool context, unverified workers, unmet criteria and refusal-limit failures have distinct copy. For a failed Run without a committed answer, feedback says no answer was committed; earlier completed actions remain, and uncertainty keeps its existing warning. [Execution](./execution.md#accepted-outcomes) owns the closed causes and journal pairings.

Existing agent inspection and text `show` use the [Session worker projection](./session.md#worker-replay). Inspection qualifies an unknown Workspace publication explicitly and also shows the bounded untrusted [observation-derived path/digest report](./session.md#worker-replay), retaining landed edits after completion, cancellation and pause. JSONL preserves canonical Events, including qualified lineage and refusal reasons; derived interruption facts add no fabricated Events or new terminal view.

Agent inspection shows only the selected actor's committed Supervisor verdicts; transcript details show every actor's verdicts in the Run. Each verdict is one dim labelled line, wrapping at the existing cell width: `Supervisor (shadow): possible loop; no action taken`. Multiple signals share that line; the capped verdict adds `verdict limit reached`. Wrapping preserves the full `no action taken` and cap wording, including at 80 and 120 columns. Terminal presentation uses a further-reduced fixed vocabulary without canonical features or evidence; [serve](./serve.md#notifications-and-items) forwards the canonical, privacy-reduced verdict. Linear and screen-reader inspection and `/transcript` use the same words without styling or controls. No verdict is displayed before commitment. The replay-derived collection follows the [verdict cap](./execution.md#persistence-bounds); no additional notices are fabricated after it. Transcript details retain their existing Run and byte limits and explicit overflow cue. Compact chat and accepted answers are unchanged; these lines never enter model input.

A Tool waiting for shared Guard capacity shows `queued · waiting for capacity` in classic, fullscreen and linear mode. The one-slot hint follows the current committed pending intent, clears when waiting or the Run ends, and never enters Events, history, replay or Provider context. It grants no authority and does not resume after restart; draft editing and Ctrl+C stay available.

Classic mode uses native scrollback above a bounded viewport. On its first draw for a Session it projects the newest whole-Run suffix, stopping before a Run that would exceed 16 Runs<!-- unrelated-bound: Classic viewport Run count -->, 64 KiB<!-- unrelated-bound: Classic escaped history buffer --> of escaped rendered row text (including trusted headings, rails and indents) or 4,096 rendered rows. Every native-visible objective, Tool summary and available answer is counted before rows are materialized. A width-safe cue points to `arany show` for the complete history. Omitted Runs stay in the journal and full-history find and export; they are not backfilled on redraw. Fullscreen uses an alternate screen with managed history and a bottom composer. Classic never borrows the alternate screen. OSC 52 is written only on an explicit user copy gesture (a Fullscreen selection release, Ctrl+C or Ctrl+Shift+C with a selection, or `/copy`), never because of model, Tool, MCP, Skill, hook or repository content, following Claude Code and Codex. It is output-only: Arany never emits the `?` query and discards inbound OSC 52. The payload is the copy payload (the selected History display text, or for `/copy` the latest committed answer's display text), already escaped, with C0/C1 controls other than LF and TAB removed, base64-encoded under the fixed `c` selection and terminated by BEL, within the [clipboard copy limit](#public-limits-and-compatibility), written by the terminal owner on stderr and never in linear mode. No mode enables focus reporting or title OSC.

### Terminal continuity and provisional text

The saved `/settings` chat view selects the initial presentation, defaulting to fullscreen; `--classic` selects classic for that process without saving it. Saving a different chat view in idle `/settings` switches presentation within the same Session, keeping draft, caret and reading anchors. A running task locks mode changes. `Ctrl+O` or `/transcript` appends bounded detailed text to native scrollback in Classic and opens the detailed History in the Fullscreen [transcript pager](#transcript-pager), following Claude Code's Ctrl+O binding. Ctrl+T does not open transcript details. Both dumps stay bounded with an explicit cue rather than Claude Code's complete dump: Classic follows the [detail limit](#transcript-detail-limit) and the pager's `[` its [whole-Run bound](#transcript-pager). Details stay available during work without cancelling it or granting authority.

Geometry is bounded to 4,096 columns and 262,144 cells; zero or excessive geometry fails with a typed presentation error. Classic keeps raw ownership while inserting output above its viewport sized to its content, at most the screen height, in batches of at most 64 native rows. Inline cursor observation targets stderr through the sole input reader under a one-second deadline; unavailable replies select linear fallback before work. Cursor queries travel only through the stderr backend and the sole raw reader; unsolicited replies are discarded and query bytes never enter drafts, stdout or history. Cleanup uses the stored owned area, never queries a stopped reader and never clears settled primary-screen transcript.

Fullscreen follows new content only at the live tail. PageUp/PageDown and find keep older source anchors through generation, completion and resize; returning live resumes following. Classic delegates scrollback, selection and copy to the emulator. Like Codex's inline viewport ([`tui.rs`](https://github.com/openai/codex/blob/af91f6ef/codex-rs/tui/src/tui.rs) at af91f6ef), every Classic surface takes min(screen height, its content height), with no floor: the idle and streaming composer, completion menus, Tool approval, folder trust, setup, selectors, pickers and rewind. Selector lists show at most 10 rows, the linear page size, and scroll inside, where Codex caps at 8. Growing scrolls the rows above into native scrollback rather than overwriting them. A height change clears only from the lower of the old and new viewport tops, repaints, and flushes pending native history in the same frame. Shrinking keeps the viewport top while history remains visible above it, so the composer stays under the latest history with no blank rows between. Rows below it stay empty until new output. A viewport that had filled the screen returns to the bottom row. History is never redrawn inside the viewport, so scrollback holds each row once. A dialog taller than the screen pages with Up, Down, PageUp and PageDown in both directions; accepting stays blocked until its last page has been shown. Native scrolling can move the composer out of view; typing returns through the emulator's scroll-on-input (the default in Terminal.app, iTerm2 and VTE). In tmux, leaving copy-mode on a key follows the user's tmux configuration. PageUp/PageDown are ignored in Classic; Ctrl+F shows `Use your terminal's find; Ctrl+O writes details to scrollback`. A complete 200-line answer stays readable without duplicate final lines or intermediate frames.

Replies stream as source-backed provisional Markdown in one replaceable active location. Following Codex CLI, each changed accumulated snapshot or width re-renders atomically with the same formatting and limits as committed answers; unfinished syntax uses the parser’s current interpretation without invented closing bytes, and growing tables can reflow earlier rows. Only the latest pending snapshot is retained; identical snapshots cause no extra parse or redraw. Strictly accepted completion replaces the candidate with the confirmed answer, inserted once into classic scrollback. Compact presentation shows replies and Tool summaries; details add bounded inert operation and result facts and explicitly public model commentary. Reasoning, raw prompts, transport JSON and uncontrolled upstream errors stay excluded. Tool details neither renew approval nor execute anything. Tool details and `show` list `spill:<digest>`, retained bytes and truncation, never implicit file contents.

Display checkpoints retain at most 32 KiB<!-- unrelated-bound: Session display text cap --> of final-result candidate and 32 KiB<!-- unrelated-bound: Session display text cap --> of public commentary per Run, at most 32 commentary items and 64 Events of at most 2 KiB<!-- unrelated-bound: display checkpoint Event payload --> each, including at most one compiled detail-limit cue. Excess commentary shows a visible cue; answer overflow remains a failed call. Checkpoints use bounded byte chunks, not one Event per token. After cancellation or abrupt interruption, only acknowledged checkpoints reopen: `Answer` text is formatted under an incomplete heading, while `Commentary` keeps its public-commentary presentation. Incomplete text is never an accepted Message, Provider history or compaction input. Validation-rejected candidates are withdrawn from presentation and stay qualified in the journal.

Classic exit removes transient input and panels and keeps the final conversation once. Fullscreen restores the previous shell screen with a brief receipt; text that the pager's `[` wrote there stays in the shell's scrollback. Redirected stdout receives confirmed answers after each task in either mode, after read-only outcome confirmation. Exec publishes no display checkpoints; show JSONL includes display-only Events. Linear `/settings` can save the chat view without changing the linear presentation. <a id="transcript-detail-limit"></a>`/transcript` exposes safe detail text for at most 16 recent Runs and 64 KiB<!-- unrelated-bound: transcript command output cap --> per invocation, with an explicit limit cue; JSONL export covers the complete journal.

Empty chat shows a short width-aware welcome and `/help`; without a selected Provider, welcome, input hint and status point to `/setup`. Hints never become draft bytes.

History exposes committed objectives and terminal answers, labeled display-only incomplete text and public commentary, with bounded local notices interleaved. Notices never enter Events, Provider context, replay or `show`; they survive redraw and reacquisition and clear on Session change. Important errors have a textual heading, independent of color. Confirmed failed or cancelled Runs show safe compiled guidance without invented answers, raw error bodies or automatic retries. Progress, panel-closure and successful clipboard cues are transient; a copy cue names its destination, and an OSC 52 copy reads `sent to terminal (OSC 52); it may be ignored`, because Arany cannot confirm delivery. A failed copy gives `Copy unavailable: REASON` and an oversized one `Copy exceeds 97.7 KB; use arany show`; neither is retried. Retained-draft cues stay separate from history notices; a notice uses status fallback if no row fits.

Failure feedback follows the terminal cause: a recoverable primary Tool denial is shown in its Tool row with a compiled cause label and reaches the model once as the correlated result; it does not show terminal failure guidance while continuation is admitted. If the following Provider call fails, the terminal view shows the Provider failure, not approval-denial guidance. An attested filesystem denial is not evidence of user denial. Optional AI-review failure followed by human denial keeps the human approval guidance; completed effects are never described as rolled back. Unavailable approval-channel guidance asks for a new request from an interactive approval channel. Hook reason text and permission-rule text are never included in denial feedback.

In Fullscreen, PageUp/PageDown navigate; Ctrl+F opens local literal find, with grapheme Backspace and visible query, Enter and Escape hints; Ctrl+L returns to live. New content and resize preserve an older source-text anchor and show a textual new-content cue. `arany show` is the canonical export; emulator scrollback is not the complete history.

<a id="transcript-pager"></a>The transcript pager follows Claude Code's Ctrl+O transcript. It is modal: detailed History takes every row above one footer of keys, the composer is hidden and keeps its draft, keys it does not own do nothing, and pastes and clipboard results are discarded. It also takes input during compaction. `/` or Ctrl+F opens find, which starts at the newest match; `n` and `N` step to the next older and newer match. `j`/`k` or Down/Up move one row, Ctrl+U/Ctrl+D half a screen, PageUp/PageDown a screen, and `g`/`G` or Home/End jump to the top and the live end. The wheel, selection and copy work as in chat. `q`, Ctrl+O or Escape closes it; Escape first closes find, then clears a selection. Ctrl+C keeps its chat meaning, so it cancels a Run. `[` releases mouse capture and the alternate screen and writes the conversation to the primary screen like chat: each Run's objective, its details and its committed answer. It keeps the newest whole Runs, at most 16 and 64 KiB<!-- unrelated-bound: conversation export text cap --> counting line endings and cues, escapes every line like all human output, starts with `Earlier Runs omitted; arany show prints the whole conversation` when older Runs are left out, or `The newest Run exceeds the transcript limit; arany show prints the whole conversation` when no Run fits, and ends with `Enter returns to Arany`. A Run still streaming shows its text as provisional. The Run keeps going without redrawing; Enter, Ctrl+C or a Tool approval reacquires the screen and capture and returns to the pager. Exit, suspension, signals, errors and unwinding during the dump restore the terminal without clearing that text.

Fullscreen selection follows Claude Code fullscreen and Codex. With [mouse capture](#selectors) the wheel scrolls History three rows. Click-drag selects History text, a double click selects a word (a whole URL inside `scheme://`) and a triple click a line. The selection shows in inverse video, so it does not depend on color, and stays anchored to source text through streaming, appended content and resize. Dragging past the top or bottom of History scrolls one row per motion event. Copied text is the escaped display text without role headings, rails, indents or Tool markers (`⏺`, `⎿`), with wrapped rows joined and separate messages divided by a blank line; its plain length is measured against the [clipboard copy limit](#public-limits-and-compatibility) before any Tool result is joined into it. With Copy on select (the default), releasing the button copies, and a successful copy clears the highlight, so the next Ctrl+C cancels as usual. Ctrl+Shift+C also copies, and so does Ctrl+C with a selection shown while chat is idle; during a Run or compaction Ctrl+C always reaches cancellation. Escape clears a selection; a failed copy keeps it. The first copy in a process names the emulator's own selection gesture from `TERM_PROGRAM`: Fn-drag in Terminal.app, Option-drag in iTerm2, otherwise Shift-drag, with the whole list over SSH or inside tmux, where it adds that wheel scrolling needs `set -g mouse on`. A selection grants nothing and never reaches Events, Provider context or diagnostics.

Fullscreen inline text panels, including `/usage`, `/settings`, `/help` and quick actions, also support click-drag selection while mouse capture is enabled. The visible panel text highlights in inverse video and underline, so selection stays distinct from a focused row; release copies when Copy on select is enabled, and Ctrl+Shift+C copies an existing selection. Copy uses the rendered, escaped panel text, joins selected rows with line breaks and obeys the same clipboard size limit. A bounded success or failure cue appears in the panel while it remains open; failed copies retain the selection. Moving or resizing the panel clears its selection before the next frame. Escape clears a selection; a later Escape closes the panel. Interactive picker rows keep their existing mouse behavior.

Clipped printable ASCII model IDs keep both ends. ### Reported usage

`/usage` takes no arguments and opens a read-only token report while idle or running, including an unsaved conversation without account access. A partial counter reads `12,340 known; some calls unreported`; no report is `unknown (not reported)`, while no calls is `no calls yet`. Unreported counters include failed retry/fallback attempts even after a later success. Pending reservations qualify totals as incomplete after a Run ends; the [Session projection](./session.md#persistence-facts) owns this uncertainty. No plan allowance, model context capacity, billing cost or balance is inferred.

Primary/secondary slot names do not imply duration. Display `% used` rounded to at most one decimal place, never infer an allowance, and show percentage and reset unknown independently. Other routes show API rate limits as `unknown (not reported)`.

## Draft editing and submission

Inline edits operate on whole graphemes and keep the caret on a grapheme boundary. Insertion, deletion and wrapping preserve accepted bytes except explicit editing and paste newline normalization. Long drafts wrap into at most four visible rows around the caret; the heading identifies a clipped window. Growth clips activity before input and status.

| Input | Effect |
|---|---|
| Left/Right, Backspace/Delete | Whole-grapheme movement or deletion |
| Up/Down | Explicit logical-line movement at a preserved grapheme column |
| Ctrl+Left/Right | Previous or next Unicode-whitespace-delimited chunk; punctuation in paths and model IDs stays in the chunk |
| Alt+Left/Right | On an empty draft, switch [agent chats](#agent-chats); otherwise inert |
| Ctrl+W | Delete the same preceding chunk range |
| Typed backslash immediately followed by Enter | Replace that backslash with LF at the caret before completion or dispatch |
| Decoded Shift+Enter, selected Alt/Ctrl+Enter, or Ctrl+J | Insert newline without consuming a preceding backslash or submitting |
| Enter while idle | Submit through local validation, or complete an open slash-name menu |
| Enter during admission or catalog loading | Retain a task draft; never queue another Run |
| Enter during an admitted Run | Offer the draft as a steering note, or retain it as a task draft; never queue another Run |
| Enter during compaction | Retain all text, including slash commands; execute nothing |

Backslash continuation follows Claude Code's portable newline gesture. Only a successfully typed backslash arms it, at that caret, for the next ordinary Enter. A second typed backslash arms the latest one, so two backslashes then Enter keep one literal backslash and add LF. Movement, another key, deletion, paste (including rejection), recall, focus/owner changes and draft replacement disarm it; resize, redraw and incoming output do not. Pasted or restored trailing backslashes stay literal. Replacement has no byte growth and succeeds at capacity. Primary idle, admission/catalog waits, active steering, compaction and editable child drafts consume continuation before submission; editing a waiting note keeps its withdrawal semantics. Dialogs, approvals, search and read-only child views never use chat continuation.

Following Codex's capability-dependent guidance, each visual acquisition uses the sole input reader to query kitty keyboard flags followed by device attributes, with one 250 ms probe budget. A valid flags reply enables a scoped push of disambiguation only; a device-attribute reply without flags, an absent or malformed response leaves legacy input and the portable fallback. Late replies never enable a mode. Replies bypass saturated input queues without stealing or reordering keys or framed paste; protocol-looking paste stays data.

Pop the keyboard mode before leaving its screen on release, suspension, view changes, scrollback output, failure or unwind; probe afresh on reacquisition. Canonical and screen-reader input emits no keyboard query or enhancement controls. No modifyOtherKeys mode, subprocess or host terminal configuration is enabled automatically.

The preferred modified shortcut is recommended after successful negotiation or receipt of that distinct chord; backslash then Enter stays visible as the fallback. Visual newline settings report whether enhanced keys were negotiated or remain unavailable. Received CSI-u and modifyOtherKeys chords work independently of negotiation. Konsole's default keytab sends `ESC O M` for Shift+Enter; Arany never enables application keypad mode (DECKPAM), where the same bytes mean numeric-keypad Enter, so it decodes the chord as Shift+Enter and inserts LF. This follows Claude Code's separate Enter submission and Shift+Enter newline behavior.

Plain CR always means Enter: an emulator or multiplexer can lose/intercept any modifier. The newline setting describes manual CSI-u mappings (`ESC [ 13 ; 2 u` for Shift, `3` for Alt, `5` for Ctrl) and tmux's extended-key requirement, without inferring delivery from a terminal name.

Linux and macOS use identical keyboard negotiation, decoding and restoration behavior. The [decoder tests](../../crates/arany-cli/src/terminal/input/raw.rs) and [shared PTY evidence owner](../../crates/arany-cli/tests/session_run/active_terminal/keyboard.rs) cover wire identity, probe fallback, input retention, keypad-mode exclusion and scoped restoration.

Linear/screen-reader chat uses Enter to submit. A newly received physical segment ending in backslash removes exactly its final backslash and appends LF, retaining the draft; repeated continued lines work. This is segment-local and never examines an assembled draft or explicit clipboard payload. Ctrl+D after nonempty input still continues without adding LF. Empty Ctrl+D exits on an empty draft; on a retained draft it gives Enter and Ctrl+C guidance. Overflow or invalid physical input rejects the whole segment without submitting a prefix or erasing earlier accepted text. Linear entry and settings say `Modified newline shortcuts apply only to visual sessions; use backslash then Enter here`. Unframed emulator paste has no distinguishable provenance: a line ending in backslash loses that backslash and continues; later lines can submit. Guidance discloses this and recommends `/paste` for safe multiline clipboard insertion.

Before consuming an idle inline draft, unknown slash syntax, invalid local arguments, an oversized rename or an incomplete objective selection leaves text and caret correctable, with no credential, State, Workspace or Provider I/O. Failure after State access or an attempted effect does not restore a consumed command, promise rollback or authorize resubmission. Linear submitted text starts a fresh physical line after rejection.

During an admitted Run, valid slash controls give read-only inspection, a locked notice or `/goal pause`. Next-Run defaults and Session mutations stay locked; `/exit` explains Ctrl+C cancellation first until the Run's outcome is committed.

Enter during an admitted Run offers the composer text as a steering note, unless it has attached images ("Steering notes are text only; draft retained"). The composer keeps the note until the Engine records it for the Run's next primary call; the notice then reads "Steering note sent to the agent", and the composer clears only if it still holds the offered text. While the note waits, "Steering note waits for the agent's next step; editing withdraws it" is shown. Any edit withdraws an untaken offer, with "Steering note withdrawn; draft retained". In Classic mode a second Enter while the note waits repeats that it waits; to add text, edit the composer, which withdraws the offer. A Run whose notes, each with its history label and the waiting note included, would exceed [8 KiB](./limits.md#max_steering_note_bytes) reports "No room for more steering notes this Run" and keeps the draft. A note over [8 KiB](./limits.md#max_steering_note_bytes) reports "Steering note exceeds 8.0 KB; draft retained". Feedback never repeats note text. An undelivered note returns as a retained draft when the Run ends, preserving editable text and inert paste boundaries.

In linear mode, Enter hands the note off and clears the line. A further text line while it waits merges into the waiting note, separated by a blank line, so the Engine delivers one note. `/status` and `/goal pause` run normally. A draft kept by a refusal (including images) is held aside for the Run. Further bounded text stays in the composer and reports "Both drafts retained; wait for the Run to finish". When the Run ends, the held draft returns ahead of newer text if they fit. Otherwise both survive in the [draft recovery slots](#paste-and-attachments): submit or clear the current draft, then use Up to recover waiting drafts. A Ctrl+D segment counts as a further text line while a draft is held; an empty Ctrl+D gives the retained-draft guidance. The [attached Run draft owner](../../crates/arany-cli/src/cli/attached/run.rs), [focused driver tests](../../crates/arany-cli/src/cli/attached/run/tests.rs) and [steering journeys](../../crates/arany-cli/tests/session_run/active_terminal/steering.rs) cover delivery, return order and overflow recovery.

The [focused Run corpus](../../crates/arany-cli/src/cli/attached/run/tests.rs) covers Goal-budget refusal, Escape cancellation routing, retained-draft feedback and current-Run-only settlement for end-of-input and `/exit`.

`/goal pause` asks the Run to pause at its next step: the notice reads "Pausing at the next step; Ctrl+C cancels now", and the status row shows "Pausing at the next step... Ctrl+C cancels now" until the Run ends. The Goal pauses under its [pause boundaries](./goals.md#steering-notes-and-pause). A repeated `/goal pause` reports that it is already pausing. Idle `/goal pause` reports that no Goal is running. During a Run, `/goal pause` followed by other text is refused as a locked Goal change.

Manual and automatic compaction preserve draft, caret and history through success, failure, interruption, resize and suspension. Ctrl+K is locked; Ctrl+C interrupts maintenance without clearing the draft. Completion reloads canonical facts and returns to explicit idle submission. Automatic maintenance follows a confirmed Run receipt and shows a visible warning; its usage excludes model-authored summary text. An interruption does not guarantee rollback of a queued append or remote usage.

Draft feedback counts graphemes, including accepted whitespace; combined emoji and combining accents count as one. Storage and physical-line admission keep their UTF-8 bounds, so the UI promises no fixed Unicode-character maximum. Capacity errors ask the user to shorten input or paste a smaller section.

The sole raw reader keeps reads nonblocking through shutdown, so signal-flushed input cannot strand its join. Its 32-event delivery channel applies backpressure at 256 backlogged events; a pending [cursor query](#terminal-continuity-and-provisional-text) permits read-ahead up to a hard cap of 4,352 backlogged events. Exceeding that cap closes input with an explicit error rather than dropping keys or growing without bound. A lone Escape waits at most one poll interval. Key repeats and releases, focus events and mouse events other than the wheel and the left button's press, drag and release are ignored. A left press on the cell of the previous press within 500 ms counts as a double, then triple, click. An SGR mouse record (`ESC [ <`) is read whole through its `M` or `m` terminator, storing at most 32 bytes; a malformed, out-of-range or oversized record, or one still unterminated at the ten-second record deadline, is discarded entirely, so no byte inside it reaches the draft, a dialog or an approval.

The dialog first draws unarmed: dim choices with no focus marker, and in linear mode the action and numbered rows without the `Select` prompt. The input reader then handles an admission barrier in its own loop: it flushes unread OS input in every mode, resets partial decoded records and partial lines, and starts a new admission epoch. Only bytes the reader reads after that barrier can act on the dialog; earlier queued events and backlog cannot. After the acknowledgment the dialog redraws armed (focus marker, or the linear `Select` prompt). Keys typed while the dialog is unarmed may be dropped and the dialog stays open, so the arming cue tells the user when input counts. The reader handles this barrier even when its event queue is full. Queued cancellation is preserved. Admission failure or a one-second acknowledgment timeout closes input without an approval verdict. These page and typeahead gates diverge from peers to bind the user's verdict to the complete immutable intent and prevent hostile text or a steering Enter from authorizing an unseen effect. Linear mode prints the same action and numbered rows followed by `Select 1-N, yes or no; empty Enter denies:` with the actual maximum number. Numbers select by choice identity, `yes` selects one-use Yes and `no` or empty Enter denies, case-insensitively; other replies are rejected. Empty Enter denies because linear mode has no visible focus. Unguarded summaries retain their markings. Escape from initial folder consent closes the dialog without saving trust; chat stays read-only unless explicit `--tools` supplies a supported private configuration.

Inline `@` at a whitespace boundary opens bounded local file and directory suggestions, following [Claude Code's file and directory references](https://code.claude.com/docs/en/common-workflows#reference-files-and-directories) and [Codex CLI's file search](https://github.com/openai/codex/blob/rust-v0.117.0/codex-rs/tui/src/file_search.rs#L52-L73). These are user-initiated UI completion reads owned by the binary, outside journal-first Tool execution: they are not model-proposed Tool intents and create no Session, Run, permission-verdict or observation Events. Candidate names stay local; only a user-selected or manually typed path enters the normal submitted Message/include admission path. Unquoted paths and JSON-quoted paths with spaces work with or without a trailing slash; a completed closing quote is decoded before discovery, never treated as part of a directory name. Directory candidates carry a trailing `/`. Typing searches project names and relative paths case-insensitively, including nested paths; exact names and prefixes rank first. Empty queries show the selected folder's immediate entries. Up/Down selects; Tab or Enter inserts a quoted file mention without sending. Enter inserts a trailing-slash directory reference; Tab enters that directory. Escape retains the draft. Discovery uses the [typed discovery selector](./tools.md#typed-read-discovery): ignored, protected and permission-hidden names are excluded before ranking or presentation. One asynchronous local blocking read captures an immutable names-only index for the admitted root, at most 2,048 names and 48 KiB serialized. It revalidates Workspace identity, configured or trusted scope and permission generation, uses the same no-follow ignore-control admission and Read restrictions, and never opens candidate file bodies. Each build retains the shared discovery scan, depth, matcher-call and selection-time bounds; ignore parsing retains its shared byte, rule and expansion bounds. Overflow rejects the whole index. The terminal never waits synchronously for a build. One build slot per binary and one latest query belong to the composer; query edits refine that index in process, with at most 2,048 comparisons and a 50 ms wall deadline. At most 64 deterministic candidates display. A refinement timeout discards that update. A superseded build keeps its resource ownership until cancellation/cleanup and cannot publish a stale generation.

The index expires after 30 seconds<!-- unrelated-bound: mention index lifetime --> and is dropped when the popup closes or the search root, Workspace identity, permission or grant generation changes. Old candidates clear before rebuilding; authority changes invalidate before the next selection. Filesystem and ignore edits appear in a new snapshot, with no watcher, persistent cache or stale-results fallback. Explicit folder narrowing starts a fresh index. Full local build capacity or the 100 ms admission wait expiry shows suggestions unavailable/busy, preserving the draft; only a new query/session may try again, without background retries. Explicit safe file and directory mentions become [bounded include snapshots](./session.md#context-and-compaction) at Run admission, at most 16 distinct paths, with no permission grant. A directory contributes only its immediate-entry listing, never recursive file bodies. Failed suggestions report a sanitized unavailable/busy cause; they preserve the draft and never substitute a file read. Submitted mention failures identify the escaped offending path and distinguish symbolic links, filesystem boundaries and non-directory components; an unfinished quoted mention reports `unterminated quoted path`.

After a deletion, the draft is resegmented: removing separators can merge graphemes or regroup regional indicators, so the caret snaps to the first surviving boundary at or after the deletion point. The Composer's model catalog is bounded and scoped to Provider and account; cached metadata and keystrokes grant no credential or Run authority.

## Storage report

`arany storage` uses the existing Workspace and selected/default StateRoot
conventions and the fixed account root. It runs without a Provider/account and
writes its bounded text report to stdout; stderr carries fixed failures. A
complete report succeeds, including explicitly absent roots. A partial/refused
report exits unsuccessfully with any known subtotal clearly labelled; cancellation
emits no complete report. Coverage, byte semantics, exclusions, bounds and cleanup
non-effects belong to [Tools](./tools.md#local-storage-inventory), including the [cache recovery contract](./tools.md#persistent-workspace-build-cache).

Idle `/storage` has no arguments and displays the same local report without
creating a Run or inserting it into context. It is locked during a Run. Classic
and Fullscreen use a read-only pager with Up/Down, PageUp/PageDown and Home/End;
Escape, Enter or Ctrl+C closes it and restores the composer. Linear/screen-reader
mode appends the complete bounded text to stderr without rewriting or controls.
During collection, Escape or Ctrl+C cancels; shutdown is preserved. Filesystem
work stays off the terminal reactor, is joined after cancellation, and cannot
publish a late completed report. Reports are never journalled, exported through
telemetry/MCP or automatically disclosed to the model. Model guidance may suggest
`/storage` without obtaining the result.

## Rewind

Idle `/rewind` opens the checkpoint panel. Esc Esc within two seconds on an empty idle composer opens the same panel; with text it saves and clears the draft, with Up to recall that one local draft (text follows the draft byte bound and attachments follow the image bounds, replaced by the next cleared draft). A focused menu or panel consumes Escape first. The first idle Escape announces the second action. Rewind is locked during a Run, admission or maintenance. Attached images or another retained draft must be submitted or cleared before switching conversations. No rewind is automatic or available through headless `exec`.

Rows follow conversation order with the newest focused: `Run N · objective excerpt · time · K files changed since`, or `no code changes since`, plus `Before rewind` rows. Rewind file counts use `file` for one and `files` otherwise. Times come from committed Events (inherited timestamps are labeled inherited); excerpts are bounded to 80 characters. Later autonomous Runs are labeled `Goal run k` under their Goal objective; steering notes do not create checkpoints. Enter opens Restore code and conversation / Restore conversation / Restore code / Never mind, in that order. Code choices appear only for a nonempty plan. Unknown or open publications disable code actions with their Event sequence and an inspect-files reason; read-only access disables code actions with a grant reason. Conversation restoration remains available. A Before rewind row offers code restoration only.

Code choices open a paged preview with each path's restore, delete, recreate, drifted, history drift, unavailable, unsafe, outside grant or kept state, `+added -removed` line counts, and the non-rewindable effects list. Counts describe one replacement region after trimming equal leading and trailing lines; binary or unavailable content uses unknown counts. Cancel / Compare / Restore occupy vertical rows, initially Cancel. Every explanation page must be traversed in order before Restore; resize or suspension restarts review. Compare opens a numbered per-file picker and bounded text-diff pages: minus is current Workspace content, plus is checkpoint content. Each escaped diff page is at most 64 KiB<!-- unrelated-bound: escaped rewind diff page -->; further pages are explicit, and binary or unadmitted comparisons say unavailable. Compare grants no file access and opens no Workspace paths independently of Engine admission.

Request a new preview when confirmation reports a change; [Tools](./tools.md#checkpoints-and-rewind) owns confirmation validity.

Drift refuses the whole batch and lists affected files. Resolve listed files offers Cancel, `Restore the others, keep these files`, and `Overwrite changed files (their current content is saved first)`. Keep requires review and Restore on a new preview. Overwrite applies only to drift/history-drift, requires a separate Cancel / Overwrite after saving confirmation with Cancel focused, then review and Restore on the new preview. Unavailable, unsafe and outside-grant paths can only be kept. Empty effective plans refuse. These copy Cline/Roo's three restore choices and per-file Compare, and Claude Code's `/rewind`, Esc Esc and prompt restoration. Arany's drift refusal is stricter; [Tools](./tools.md#checkpoints-and-rewind) owns that policy and capture guarantees.

Receipts preserve the committed outcome: `Restored K files to before Run N`, `Rewind refused: M files changed outside Arany`, or `Rewind outcome unknown: inspect files before continuing`, with listed conflicts and checkpoint/pruning notices. Unknown outcomes never retry. Both mode preserves a successful code receipt if conversation restore fails or is cancelled: `Code restored; conversation unchanged; use /rewind → Restore conversation`. The [Session contract](./session.md#conversation-rewind) owns fork ordering, source preservation, budgets and lineage limits. On conversation restore the terminal switches to the fork, or an unsaved conversation for the first prompt, retains next-Run defaults and places the selected prompt in the composer without submitting it. A leading slash is escaped as a literal objective so restored history cannot execute a local command. Images return as attachments under [Paste and attachments](#paste-and-attachments); unsupported control characters produce an omission notice, and an image that cannot be reattached stops the remaining images with `image restoration failed: REASON`; restored text follows the [primary text draft limit](#public-limits-and-compatibility). Linear mode announces the complete restored draft as not sent.

Unavailable checkpoint storage offers Retry / Reset checkpoint storage / Cancel. Reset requires complete warning review and a separate Cancel / Reset confirmation with Cancel focused; healthy, busy, unsafe or concurrently changed storage refuses. [Tools](./tools.md#checkpoints-and-rewind) owns deletion scope and private-state admission.

Classic, Fullscreen, linear and screen-reader modes share these states and words. Linear output lists numbered rows and accepts numbers or complete visible choice names; empty Enter, q, Ctrl+C or EOF cancels. It prints full inert paths, preview text and comparison pages without truncation or terminal rewriting. At 80+ columns the panel keeps full action hints; 50–79 keeps choose, review and cancel; below 50 it keeps arrows, Enter/PgDn and Escape, with full details on sequential pages. Below 16 columns<!-- unrelated-bound: rewind minimum viewport width --> or eight rows actions require resizing. Paths, excerpts and diff bytes are untrusted data, neutralized through the ordinary terminal-control escaping before layout or linear output. `show` text renders both rewind Events and the checkpoint field inertly; JSONL preserves canonical serialized Events.

## Selectors

Catalog failure changes no defaults; published account work is not rolled back. State, replay and terminal-owner failures keep their fatal boundary under CLI rules.

## Paste and attachments

Primary framed and explicit clipboard text are bounded before normalization and across the expanded draft by the [public paste limits](#public-limits-and-compatibility). After CRLF/CR-to-LF normalization, a pasted block of strictly more than 1,000 Unicode scalar characters becomes an atomic `[Pasted Content N chars]` chip. A sub-threshold paste is ordinary typed text: it participates in command and mention discovery and shares the [64 KiB](./limits.md#max_user_message_bytes) primary draft cap defined there. Chips count only against the expanded-draft cap. Linear text beside chips uses the remaining capacity under both caps; a physical segment exceeding either is rejected whole. Draft merges include their newline separator in both limits. Equal-size pastes append a space followed by `#2`, `#3` outside the bracket using the highest remaining suffix plus one; when none remain the base label is reused. There is no independent text-chip count quota. Typed spans and payloads keep insertion order; literal marker-looking text is ordinary text, never a lookup key. Collapse changes presentation only, not model input or token usage.

Child-message pastes always remain editable text without chips, including above the primary collapse threshold. They share the [child-message draft limit](#public-limits-and-compatibility); an oversized insertion rejects whole.

Left/Right traverses a chip atomically. At its start, Tab opens full escaped, inert text detail; Up/Down, PageUp/PageDown and Home/End scroll, and Escape or Enter closes with the original caret. Delete/Backspace removes the complete chip. Command and file completion remain disabled while the draft contains a text chip; editable mentions are still admitted on submission. Detail does not accept paste or invoke commands; Ctrl+C retains the normal cancellation behavior. Narrow and no-color layouts retain the label and keyboard selection. Linear mode prints labeled compact and expanded inert content without cursor rewriting.

Only explicit editable input participates in local command and `@` discovery. Mention scanning accepts at most 64 KiB<!-- unrelated-bound: mention scanner input cap --> so inert chip separators do not consume the primary objective's [64 KiB](./limits.md#max_user_message_bytes) allowance. A command mixed with text attachments refuses locally with the draft intact; hidden slash, Skill, file-path and mention syntax is data. Submission expands exact normalized text into the ordinary objective before Engine admission. `/goal continue` uses the original Goal's recorded admitted includes and never reparses stored text, as [Goals](./goals.md#budget-continuation) defines. Accepted text survives reopen, fork and replay through canonical Messages without clipboard or cache access. Unsubmitted text and chip boundaries are process-local; local recall preserves them, with no crash-recovery promise.

Admission cancellation and definite pre-acceptance failure restore complete text, chip metadata and images. Failed acknowledgment reconciliation holds the submitted draft outside the composer in a modal recovery dialog. Check history repeats only the read: confirmed non-acceptance restores the complete draft, confirmed acceptance removes it, and another read failure keeps it held. Enter cannot resubmit while acceptance is unknown; Exit discards the process-local draft and closes the Session. No submission is retried automatically. During work a large paste stays a draft and cannot bypass the [steering bound](./limits.md#max_steering_note_bytes). Refused held/newer merges preserve drafts for explicit submit/clear and Up recovery, blocking conflicting insertion until recovered; ordinary local recall remains one replaceable slot. The active, held, recalled and pending draft slots each retain at most one message's text/images (256 KiB text and 768 KiB raw images total, plus bounded render/encoding copies). Linear steering offers additionally retain up to [8 KiB](./limits.md#max_steering_note_bytes) text and one provenance record per admitted note until Run end. No payload appears in notices, diagnostics or telemetry before submission.

Canonical input rejects an unexpected bracketed frame and drains through its end marker across physical reads, including its interior Enter, slash and protocol-looking lines. Delimiter state is fixed-size; an incomplete frame or split delimiter closes input under the [framed-paste deadline](#framed-paste-deadline), with no prefix submission. Admission/focus changes never release a frame's interior as input actions. No raw mode or keyboard query is introduced in linear mode.

<a id="framed-paste-deadline"></a>

Framed Unix inline text paste atomically inserts one bounded valid block into the editable draft, including during admission, work, maintenance and catalog waits. CR and CRLF become LF; tabs stay bytes with four-space visual expansion. Overflow or invalid UTF-8 rejects the entire record. Paste never submits, completes a command or activates a selector; modal pickers ignore it. An unterminated framed record fails terminal ownership closed after a ten-second deadline. Secret and Workspace fields keep separate bounds and explicit Enter. Linear canonical input does not claim safe unframed emulator multiline paste.

Explicit Ctrl+V, decoded Ctrl+Shift+V or `/paste` requests one bounded OS clipboard read. Unsupported transport, hostile payload or process failure gives local feedback without altering the draft. Clipboard data stays transient untrusted input until submission and supplies no key event, file authority or automatic Run. Enter while loading retains rather than submits. Picker or find entry, release, suspension and ownership changes discard late results. During a Run, Ctrl+C still cancels it. Linear mode shows a complete inert `Draft (not sent)` preview, including during work, and renews its idle prompt after success or failure.

Linux supports admitted text and PNG through standard Wayland or local X11 clients; compiled routing is not proof of native desktop interoperability. macOS uses a bounded, supervised AppKit pasteboard read, preferring PNG over UTF-8 text and rejecting other advertised image formats, changed generations and excess bytes. AppKit exposes no size check before `dataForType`, so the bound applies to the parent's read of the child's output, and the child may materialize the full payload.

Clipboard clients run in owned process groups under a shared two-second read or copy deadline. Every client exit attempts group termination and positive child reaping under a separate one-second cleanup deadline, except a Linux serving copy client (`wl-copy` or `xclip`): as in Claude Code and Codex, its descendant keeps serving the selection after the foreground process exits, until another owner takes it, even after Arany exits. Arany waits for that foreground exit, reaps it and leaves the descendant in its own process group with only the payload and the cleared environment; a failure or deadline terminates the whole group. Cancellation discards the late payload without waiting on the terminal reactor; the process owns at most one clipboard worker and refuses another read until it finishes. A cleanup error or deadline returns `clipboard cleanup unconfirmed`, never a successful payload or a claim of reaping. The worker retains the child for nonblocking reap observation, and further clipboard reads report the unconfirmed cleanup until Arany restarts, including when cancellation discarded the original result. Terminal teardown signals the outstanding worker and waits at most one second for shutdown; a missed deadline reports unconfirmed cleanup to stderr even when cancellation discarded the original result. No read is retried automatically.

The composer displays attachments as ordered `[Image #N]` chips. CLI Workspace admission captures the root's device and inode before Session creation; every pasted path read requires that identity, including in fresh conversations, and opens the root and each path component without following links. Clipboard PNGs and pasted `.png` paths inside the admitted Workspace use the same admission limits. Pasted path candidates follow the [PNG path bound](#pasted-png-path-limit). Text containing `://` or embedded control characters uses ordinary text-paste admission even when it ends in `.png`; URLs are never fetched. Absolute paths are accepted only when their lexical path is beneath the canonical Workspace root; path reads require a same-filesystem regular file with one link and snapshot at most the PNG byte limit before validation. Linux resolution rejects mount crossings, including same-device bind mounts, and fails closed when kernel enforcement is unavailable. macOS uses no-follow component opens and rejects device changes. A candidate path confirmed absent beneath the pinned root falls back to the original pasted text. Workspace failures, identity changes, escaping, forbidden, linked, cross-filesystem, oversized and malformed inputs leave the draft unchanged. When all chips cannot fit in the composer header, it shows the selected chip there, or the total image count when none is selected, and retains the clipped draft position when both fit. Left/Right selects adjacent image chips at the text boundary or among selected chips; Delete/Backspace removes the selected image, and remaining labels renumber in order. Successful text edits, including paste, clear image selection. Ignored keys, pointer motion and resize preserve image selection. The image contract admits at most four PNGs totaling 192 KiB raw bytes, including image-only submission. An image-only Message has empty user text. Human history shows metadata only; canonical history, forks and explicit JSONL export retain bytes. Conversation rewind restores the selected checkpoint's prompt and image bytes to the local draft with text editing focused; it does not submit them. Compaction is metadata-only: it uses image metadata and prior assistant interpretation, not covered pixels. Overflow rejects a whole image or whole historical turn, never a truncated prefix or a silently lost attachment. Custom routes remain text-only.

<a id="image-hover-preview"></a>

In Fullscreen with mouse capture, image preview detection prefers an exact Kitty graphics `OK` reply before DA1, then DA1 attribute `4` with a known cell pixel size for Sixel, then the iTerm2-compatible environment (`TERM_PROGRAM` exactly `iTerm.app` or `WezTerm`, or `LC_TERMINAL` exactly `iTerm2`). DA1's first parameter identifies the terminal and is not an attribute. The queries share the existing keyboard probe deadline and run only in Fullscreen, outside tmux, with mouse capture enabled and the screen-reader path inactive. Sixel takes cell pixels from `tcgetwinsize` when available; otherwise `CSI 16 t` precedes the capability queries, and an exact `CSI 6;height;width t` reply before DA1 supplies the size. Missing, zero, oversized or malformed cell dimensions do not enable Sixel. Neither detection nor rendering changes terminal or tmux configuration. [Xterm's control-sequence contract](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) owns DA1 and cell-size replies; [DEC's Sixel contract](https://vt100.net/docs/vt3xx-gp/chapter14.html) owns raster and palette encoding. Claude Code and Codex CLI have no image-chip hover preview; this is an Arany addition.

Hovering a visible chip draws a bordered balloon above the composer header, anchored at the chip and clamped to the screen, with the existing image description as its title. The image preserves its aspect ratio within the balloon. A hidden compact chip has no hit area. A balloon is omitted when fewer than four inner rows fit above the composer. Kitty and iTerm2 receive the unchanged base64 PNG and decode and scale it in the terminal. Sixel alone decodes locally in `spawn_blocking`, scales by nearest neighbour into the available pixel rectangle and quantizes to a fixed 6×7×6 RGB palette (252 colors). Fully transparent pixels leave the background unchanged; other alpha values use the pixel's RGB color. Decode errors and bound overflow suppress graphics without changing the attachment or sending error details to a Provider, journal, diagnostics or telemetry.

At most one Sixel decode runs per binary, with one latest request retained. A superseded job retains its slot until completion; leave, reentry, chip identity or geometry changes invalidate its generation, and late results cannot publish. Mode replacement retains the outstanding job's ownership. A busy slot suppresses a new owner's preview for that hover. Completed bytes arrive as a terminal event. Motion within a chip does not redraw or retransmit. Leaving deletes the Kitty placement or repaints iTerm2 and Sixel image cells. Resize, chip change, opening a picker, dialog, pager or detail view, mode switch, scrollback dump, suspension, release and exit clear the hover and placement. No preview, fallback rendering or graphics output occurs without a detected protocol or in Classic, linear, screen-reader, disabled-mouse or tmux sessions. A terminal graphics write error propagates through ordinary terminal restoration.

Sixel's decoder uses the admitted PNG byte limit for its internal best-effort allocation limit and ignores text/profile metadata. Frame allocation is separately checked against `PREVIEW_MAX_PIXELS` before decoding; output pixel allocation has the same cap. The [public preview limits](#public-limits-and-compatibility) bound both. This is finite in-process work, without a hard RSS or preemptive cancellation guarantee; a started blocking job completes under its bounds. Kitty and iTerm2's terminal PNG decoders remain outside Arany's security boundary.

Clipboard transports come only from checked local OS metadata: standard Wayland or local X11 clients on Linux, the checked `osascript` bridge for paste and `pbcopy` for copy on macOS, and a checked tmux socket for copy. A transport is never selected from `PATH`, an external host, an arbitrary command or Provider content. The child receives a cleared environment with only the selected display or runtime variables (plus `LANG` for `pbcopy`), never account credentials, network settings or the home directory as configuration. Its process group is owned before any fallible pipe setup; cleanup follows the deadline and uncertainty rules above. Support checks never read the user's clipboard.

Idle `/copy` copies the latest committed answer's source Markdown with existing control escaping; it is locked during a Run. Fullscreen selection maps visible graphemes to contiguous source ranges, including heading/code/table/inline syntax envelopes and intervening source. Reference destinations include their use and definition envelopes, so an aliased endpoint can widen the contiguous copy. A double-click keeps plain source words in ATX headings, code bodies and ordinary table text, and otherwise selects the visible word with its source envelope; selecting the whole body returns its original Markdown. Classic emulator selection copies rendered cells. The copy goes to the first destination that works, trying each at most once: a native client when the session is local (no `SSH_CONNECTION`, `SSH_CLIENT` or `SSH_TTY`), which is `wl-copy` (Wayland) or `xclip` (X11) on Linux and `pbcopy` with `LANG=en_US.UTF-8` on macOS; then, inside tmux, `tmux -S SOCKET load-buffer -w -` (tmux 3.2 or later) after `$TMUX`'s socket is checked to be absolute, a socket and owned by the user in a private canonical directory whose every ancestor is owned by root or the user and is not group- or world-writable unless sticky; its device and inode are checked again before and after the client runs, and a change fails that destination; then OSC 52. `xsel` is not used, because its daemon calls `setsid()` and leaves the owned process group. Copy clients come from the same admitted root-owned directories as paste clients, so Homebrew tmux on macOS is never used, and they read only the payload on stdin. Copied text is never journaled, sent to a Provider or recorded in diagnostics.

OSC 52 depends on the emulator: Terminal.app and VTE do not write the clipboard through it; iTerm2 requires "Applications in terminal may access clipboard". Over SSH, Terminal.app users need Fn-drag or Classic. Inside Homebrew tmux on macOS, OSC 52 needs `set -g set-clipboard on`. Kitty, foot, WezTerm, Ghostty and Alacritty provide OSC 52 destinations; interoperability still requires native evidence.

Admitted PNG bytes are kept unchanged, including metadata. Admission does not decompress them; only the local Sixel hover projection decodes a separate copy under the [preview bounds](#image-hover-preview). Admission checks structure, chunk CRCs and dimensions. Animated PNG and unknown critical chunks reject. Dimension admission is not raster decoding or proof of vision support. Filenames, URLs and terminal image escapes are never admitted.

## Interruption, suspension and restoration

Primary Tool approval prompts remain answerable without a wall-clock deadline while terminal input/output and the Run remain live, including suspension or a live tmux/screen PTY. Explicit No records a human decline and stops the Run without dispatching the proposal; Escape and Ctrl+C cancel the whole Run. EOF, SIGHUP/shutdown and lost terminal input/output withdraw the request. An abandoned approval closes its dialog and restores composer input without sending a verdict. A child approval remains pending through idle waits, then withdraws when shared delegation or Goal active time is exhausted; terminal output names that cause separately from human denial. Earlier completed effects remain.

| State/action | Required outcome |
|---|---|
| Ctrl+C on folder consent | Exit Arany and restore the terminal without selecting read-only or saving trust |
| Idle Ctrl+C with a draft | Clear the draft |
| Idle Ctrl+C on empty input | Explain copying (in Fullscreen with mouse selection, `Select text with the mouse to copy; GESTURE for terminal selection`, where GESTURE is the emulator's own selection gesture; otherwise the emulator's Ctrl+Shift+C); a second press within two seconds exits |
| Ctrl+C during selected-Provider admission | Return to chat with the new draft retained and no Run receipt or retry; delegated account work may still complete |
| `/goal pause` during a Run | Request a pause at the next step; the in-flight call completes and a dispatched action is not aborted; Ctrl+C after it cancels now |
| First Ctrl+C during a Run | Request graceful whole-Run cancellation, even while a Fullscreen selection is shown |
| Second Ctrl+C during cancellation | Bounded local shutdown; report only the strongest durably confirmed terminal state |
| Escape | Close the focused panel first; a pending clipboard read is cancelled first, then a Fullscreen selection is cleared, then the completion menu closes. With nothing focused during a Run, it cancels the Run like Ctrl+C: the Goal stays paused and resumable and the draft is kept; a second Escape during cancellation is ignored. Linear (canonical line) input cannot send Escape; Ctrl+C is the cancel key there |
| Unix SIGTSTP / inline Ctrl+Z | Release input and modes before stopping, and never stop after restoration fails; SIGCONT reacquires the chosen presentation and preserves draft, caret, history and pinned work |
| Unix SIGTERM/SIGHUP | Exit through the input-owning state; an active Run requests cancellation before bounded outcome confirmation |

`q`, Ctrl+D, `/goal pause` and other slash controls do not cancel active work. An empty-draft Ctrl+D or `/exit` after the Run's outcome is shown, while Arany still finishes that Run, exits once it returns; `/exit` also abandons a held linear draft or an undelivered steering note. The cancellation and shutdown grace is at most three seconds; expiry must not fabricate a cancelled receipt or answer. Run cancellation stays distinct from pre-Run admission interruption and from compaction interruption. Replay can instead expose an interrupted prefix. An interrupted compaction makes no Run-cancellation or remote-billing-stop promise.

Restore raw mode, cursor, wrapping, echo and every enabled mode, including mouse reporting and alternate scroll, on normal exit, error, cancellation, signal, render failure, partial acquisition, unwind and suspension. Receipt and answer output follows restoration and read-only confirmation. Renderer failure after Run admission may expose only committed sanitized linear facts or a typed presentation failure. Secret bytes stay absent from drawing, notices, Events and output throughout cleanup.

Classic cursor-query timeout fallback stops and joins the key reader, releases raw mode, then starts the linear reader; a raw-mode release failure prevents restart. Partial acquisition unwinds resources in reverse acquisition order. Cleanup attempts every remaining reset in order and returns the first error; a failed guard reset remains armed for its best-effort Drop retry. Failed reacquisition leaves the prior owner released. The [Transcript owner](../architecture/system-overview.md#8-terminal-presentation) preserves distinct histories and native emission tracking across replacement; linear Tool rows already written stay suppressed. [Lifecycle and preview cleanup faults](../../crates/arany-cli/src/terminal.rs) and [released-state continuity](../../crates/arany-cli/src/terminal/clipboard.rs) own this recovery evidence alongside the history, frame and pager journeys below.
