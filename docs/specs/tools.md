# Local coding tools

This contract owns Tool grants, guarded effects, runtime Skills and local MCP. [Terminal](./terminal.md) owns completion, settings and consent presentation; [execution](./execution.md) owns Run coordination, capacity admission and [effect outcomes](./execution.md#effect-outcomes). Editing constraints: [security rules](../../agents/security.md).

A primary AgentRun can use file operations, commands, portable Skills and local stdio MCP tools. This is an explicit, offline local foundation, not unrestricted host shell access. [Folder trust](#folder-trust-and-approvals) gates Tools on attached startup; without explicit private Tool configuration, untrusted folders stay read-only. Explicit process selections and headless Runs opt into reviewed configuration with `--tools`, which adds no paid compatibility check.

Folder consent and native Tool capability are independent. Without an implemented enforcer, attached chat runs without Tools even after trust is remembered; `/permissions` offers the same consent choices, Shift+Tab reports the native restriction without enabling authority, and explicit `--tools` rejects. Trust never supplies missing OS protection: only approved [primary host commands](#primary-host-commands) and [typed host](#human-approved-host-git) operations run outside the Guard, and [in-process file operations](#in-process-file-operations) run only once native protection admits Tools.

Supported operating systems provide equivalent file operations, commands, Skills and local MCP with the same permission, isolation, cancellation and durable-result contract. Typed Git reads follow their [per-platform availability](#typed-git-reads); resource guarantees differ by native profile as defined below. [Next steps](../../NEXT_STEPS.md#beta-2-and-broader-release) records the native, platform, live and human checks still required before claiming support.

Native adapters use [automatic Tool selection and plain text answers](./provider.md#structured-outcomes-and-tool-encoding), translating one semantic proposal at a time. Exact custom profiles reject `--tools` because their data-free conformance covers only read-only turns.

The generated function and outcome schemas offer file reads and search plus only catalog-enabled mutations, commands, Skills, MCP operations, typed Git reads and, with `write`, [typed Git writes](#typed-git-writes). Command, Skill and MCP-server identifiers are constrained to configured names. An unparsable or oversized catalog offers only read-only file operations and the primary's optional plan function. Catalog text guides generation but supplies no authority; the pinned router and Guard admit every proposal independently.

The optional `arany_plan` function records Engine-owned Goal state, separate from effect Tools; [Goals](./goals.md#initial-plan-contract-and-success-receipt) owns its admission, scope, success and replay.

## Authority and effect admission

`ToolGrant`, owned by Tools, is the access a caller supplies for one submission: none, the admitted private `tools.json` configuration, or the trusted Workspace grant. The Engine consumes it when admitting a submission.

Each mutation, process, Skill script and MCP call requires typed effects, deterministic restrict-only Policy and effective-capability attestation. Programs run in the separate Guard. [In-process file operations](#in-process-file-operations) publish under the same admitted directory capability with their own execution-site attestation. Hooks, prompts, command regexes, classifiers and approval UI are not enforcement boundaries.

An effect is normalized once into an immutable typed intent naming actor, Run, Tool, resources, operations, destinations, descendant behavior, use count and finite action limits. Policy, approval, journal and Guard share its digest; names, prefixes, hostnames, remembered approvals and summaries never define authority. Primary and child Tool effects pass one deterministic Policy route. [Provider egress](./provider.md#configuration-and-egress) has its own admission; [execution](./execution.md#collaboration) owns child grants.

Tool intent preflight and replay share one Session-owned reducer validator; [execution](./execution.md#accepted-outcomes) owns its refusal causes and feedback. Preflight is read-only and grants no authority. The Engine keeps live catalog, grant, liveness and budget admission; final permission provenance, hooks and host requirements still apply at the folded start.

Effective capabilities must equal or narrow the authorized set. Unsupported enforcement dimensions, missing capabilities, failed attestation, and authentication, authorization, signature, policy or schema failures reject. Descendants keep or lose authority; there is no automatic unsandboxed fallback. Privileged code never follows or executes a filesystem object created by a less-privileged agent or sandbox without fresh no-follow, handle-relative validation. A process starts from a trusted executable identity without ambient PATH search, with validated arguments, a pinned working directory, an allowlisted cleared environment and closed inherited descriptors and sockets. Scripts need an admitted interpreter policy. Process-tree supervision, cancellation, reaping and release of permits, transactions and temporary resources follow the native profiles and the [failure contract](#limits-and-failure-behavior).

## Folder trust and approvals

Every attached startup asks whether to trust the opened folder, including when no account is configured, unless that exact folder has remembered trust. Consent precedes saved-account lookup, catalog or credential access and Session discovery or creation, for new, resumed and forked entry. The flow is the same on every OS and independent of Provider flags or `--tools`; `/permissions` revisits it.

The consent screen shows the full folder path and vertical Read only / Trust choices, Read only focused. With explicit `--tools`, the first choice reads Use explicit config and keeps that private configuration when trust is skipped; neither choice expands roots or capabilities. The screen proposes metadata-only runtime and cache selections; toggling one switches to Trust. Discovery runs for initial consent or when `/permissions` opens, and a discovery failure shows a notice without aborting startup. Remembered startup revalidates only saved pins, so an unrelated over-limit manager cannot block prompt-free chat. Enter confirms, Escape dismisses without a decision and Ctrl+C exits without saving. `/permissions` first asks whether to manage folder trust or [typed Git rules](#typed-prefix-rules); folder trust rediscovers candidates, keeps exact pins and permits explicit changes. Checking a toolchain unchecks other selections of its runtime kind; linear `trust` with two of one kind asks again, and `trust N` and `use config` also work. A selection that cannot be saved reports an error and keeps the previous permissions, so startup continues read only. Consent warns that prior versions of files changed by Arany are saved unencrypted in private StateRoot storage.

Choosing read only, using explicit configuration without trust, or dismissing remembers nothing. Unavailable, malformed or unsafe trust metadata stops startup before account or Session access with a message naming the record and the failed check. An unsupported-version or malformed `workspace-permissions.json` offers Retry, Reset folder trust or Exit, like [history recovery](./terminal.md#setup-and-account-choices); a reset deletes only that record after explicit confirmation and refuses if the record changed meanwhile. A non-private record or state directory is reported and never reset or modified. Trust is user-owned, shared by conversations, and pinned to the exact absolute path, device and inode in private OS-user state, never in Session facts; a replaced directory needs trust again, and replay never supplies authority. Remembered grants apply only to native Providers on platforms that admit Tools; custom Providers stay read-only. Explicit private `--tools` configuration takes precedence over remembered trust and keeps its narrower roots and capabilities.

The private `workspace-permissions.json` in the fixed OS-user account root holds at most 128 entries and 64 KiB<!-- unrelated-bound: workspace trust record cap --> and is replaced atomically, owner-only. Versions below its [migration floor](./execution.md#json-record-migration) reject without changing the record; only the consented reset removes it. Trust generates a Tool grant for `workspace_paths: ["."]`, typed writes, discovered project Skills and a pinned resolved system `sh`, plus a pinned system Git for [typed Git reads](#typed-git-reads) when available. Optional runtime selections bind exact path, profile kind and directory device/inode to the folder entry. MCP needs explicit private configuration. Standard secret, link and mount exclusions and finite snapshots apply; `target`, `node_modules`, `.venv` and `venv` are omitted from root discovery and snapshots. Commands use the offline Guard, never the host terminal, the whole home directory, package-manager configuration or credentials.

Discovery reads bounded directory entries and executable metadata under `~/.rustup/toolchains`, the per-version Node roots of nvm, fnm, Volta and asdf, and `~/.pyenv/versions`. It never executes a candidate or reads manager or project configuration. It reads the existing command environment without creating or changing State: an absent record uses an in-memory preview, while invalid or unsafe existing state reports discovery failure. Candidates need a numeric `major.minor.patch` directory label; aliases such as `stable` and `nightly` are excluded, and the label is the manager's directory name, not a verified binary version. Python candidates need a version-specific regular executable, or a `python`/`python3` alias to one in the same `bin`; other symlinks reject. Without an exact saved pin, consent proposes the newest numeric Rust, Node and Python, breaking ties by display order; saved pins, even stale ones, win. A saved toolchain grant for a recreated root is a new candidate.

User program directories are proposed, metadata only, from that environment's `PATH` entries under the home directory or a Homebrew/`/usr/local` prefix, never under the Workspace. Version-manager shim directories come from a closed table with their manager root and home variable. Both keep environment order regardless of display grouping; saved selections keep their saved order. A Homebrew-prefix `PATH` directory stays its own search entry while the whole prefix mounts read-only for its libraries; the Homebrew proxy directory is pinned at its physical Cellar location. A selected subtree of a fixed system mount such as `/usr/local` is pinned and added to `PATH` without a second mount. Discovery refuses, rather than truncates, a `PATH` over 16 KiB<!-- unrelated-bound: user program discovery PATH cap --> or more than 32 in-scope entries. A manager root is pinned by path and device/inode with its shim directory and rechecked with it; a replaced or missing root rejects. Contents are not reviewed: a selected directory runs whatever it holds, and a user-writable Homebrew prefix is granted whole. Both kinds are offered only where the Guard enforces their grants; unlike toolchain kinds, several may be selected, deduplicated by path and device/inode.

Selected roots mount read-only. Their `bin` joins `PATH`, followed by selected user program and shim directories in pinned environment order, before the fixed system path; a selected manager root sets only its manager's home variable. Label, path and device/inode bind policy and candidate tokens; Run/Guard admission and Ready/GO recheck them and reject drift before dispatch. A saved root that no longer verifies stays pinned: commands and MCP reject with `ChangedInput`, while file and Skill Tools keep working. A runtime, user-program or cache grant overlapping the Workspace, the StateRoot or a fixed Guard runtime root rejects. Profile numbers use kind order (Rust, Node, Python, Cargo archive/source/index caches, npm cache, pip HTTP/wheel caches, Apple compiler, Apple SDK), then descending lexicographic version label, then ascending absolute path and token. Saved selections match by token, never by display position.

On macOS, Rust also proposes the Command Line Tools compiler and the newest numeric physical SDK, keeping exact saved pins. The compiler profile is the fixed physical `/Library/Developer/CommandLineTools/usr` root. Admission requires root-owned, non-group/world-writable directories, a root-owned `cc` link to `clang`, and root-owned, single-link, executable, non-set-ID, non-group/world-writable `clang` and `ld`. The native signature check must show both executables are unentitled; an unknown result is not checked at discovery, and the Guard refuses the grant at bootstrap with `ProtectionUnavailable`. Only `cc`, `clang` and `ld` receive process-exec permission. SDK profiles are exact physical `MacOSX<version>.sdk` directories under `/Library/Developer/CommandLineTools/SDKs`; versions have two or three canonical numeric components, each in the range 0–65535 with a nonzero major component, and a total length at most 32 bytes. The SDK directory and its required contents must be root-owned and not group/world-writable. Compiler and SDK grants bind kind, manager, exact path and directory device/inode; the SDK also binds its version. Each is deselectable and counts toward the [selected runtime grant ceiling](#limits-and-failure-behavior).

Optional host caches are separate read-only grants: Cargo's exact `registry/cache`, `registry/src` and `registry/index`; npm's exact `_cacache`; pip's exact `http-v2` or `wheels` under `~/.cache/pip` (Linux) or `~/Library/Caches/pip` (macOS). Existing caches are proposed only with their runtime, only human Trust saves them, and no parent cache mounts. Consent warns that caches may disclose private package names, source, registry metadata or credential URLs, which commands and MCP can emit into journaled output that later Provider requests carry; Arany never auto-loads them. Configuration, credential files, environment values and parent directories stay unavailable. A selected read-only host subtree takes precedence for that Run: Arany neither archives it nor restores private bytes over it, and keeps earlier Arany-owned entries at that subtree when publishing other cache changes. Disabling the opt-in restores the private writable view and those entries. Cache data supplies no authority.

Shift+Tab cycles **Auto edits → Request approvals → Auto approval → Auto edits**, keeping the draft and caret. The mode shows beside the composer and follows the selected Provider's native capability; selecting a supported native Provider after trusting an unconfigured conversation restores the remembered mode. Auto edits allows typed edits and asks for commands, MCP calls and Git writes; Request approvals asks for every effect. Reads and Skill or catalog discovery need the pinned grant but no per-action question. Auto approval has the selected AI review the exact action against the current user request and resolve an Ask within the pinned grant, which can add model usage. Uncertainty, invalid output, failure, an exhausted review budget, or switching out of Auto during review asks the user.

A human approval shows the exact proposed action; [terminal approval](./terminal.md#interactive-commands-and-completion) owns layout, focus, labels and linear replies. All pages must be reviewed before accepting. Approval is one-use and never expands the grant. Primary ordinary, hook Ask and unguarded prompts have no wall-clock expiry while their human channel and Run are live, following [Claude Code ordinary permission waits](https://code.claude.com/docs/en/remote-control#limitations) and [Codex one-shot approval waits](https://github.com/openai/codex/blob/61f34c35af77777db4d77d0ea2aeb8547a6b4523/codex-rs/core/src/session/mod.rs#L2988-L3119). Escape and Ctrl+C cancel the Run; explicit No declines the proposal. Pause, cancellation and channel or turn shutdown withdraw pending work. Losing a delegated Ask's local approval inbox or reply sender cancels the Run; an explicitly delivered unavailable reply from a live channel differs from channel shutdown. A missing, invalid or undelivered reply while the Run is live records unavailable approval, never human decline. A late allow still revalidates the admitted directory, any explicit file-content precondition, executable bytes, grant/enforcement digests and worker revision before dispatch; no pin is refreshed. Ordinary reads pin no file content. Permission settings stay the Run snapshot: editing the rules file during a wait affects later admission, not the pending decision.

A child Ask stays pending while its human channel and Run are live. Its shared delegation and finite Goal active-time allowance pause during an idle human wait and keep running during overlapping sibling Provider, effect, preparation and cleanup work. Exhaustion withdraws the ask before dispatch with the delegation or Goal cause, never as human decline; cancellation and pause win over an accept, and dispatch rechecks the allowance. The non-dispatched observation stores `approval_cause` as `cancelled`, `paused`, `channel_unavailable`, `declined` or, on older observations only, `child_timeout`; active-time withdrawal uses the typed limit and Run stop causes instead, and other observations carry `null`. Presentation and replay use typed causes, never output text, and replay never restores a live request. The shared [denial delivery rules](#permission-modes-rules-and-hooks) apply. Cancellation, pause, hook stop, [Uncertain](./execution.md#effect-outcomes) effects and exhausted or unavailable continuation still stop; completed effects are not rolled back.

AI reviews have a 20-second ceiling, a 256-token output cap, no Tools, project instructions, history or includes, and canonical Provider-call usage. They share the primary call budget while preserving final continuation; review text never becomes an assistant answer. Each accepted review is pinned to its pending Tool in the projection; ownership is never inferred from adjacent review calls, so an approval-mode change cannot duplicate an integration review. Headless `--tools` uses its explicit private upfront grant without an interactive approval channel.

Workspace input resolves one component at a time beneath the pinned directory handle with no-follow semantics. Symlinks, special files, absolute paths, empty components, `.` and `..` reject. Candidates open nonblocking before the regular-file check, and the validated handle is used instead of reopening by path.

## Permission modes, rules and hooks

The shared Engine `before_dispatch` evaluates permission settings for primary and researcher Tool steps. Optional `permissions.json` is an authenticated user settings record beside `tools.json` in the admitted StateRoot, outside the Workspace, admitted like `provider-routing.json` (private regular file, ownership, no-follow, bounded read). Malformed JSON, unknown fields, group/world-readable or symlinked files and oversized settings reject Tool admission with a Configuration error before Provider usage or any Tool intent. Missing settings keep the existing interactive and headless approval behavior. Repository, Skill, model and hook text never select trust. Parsed settings are immutable data, not executable configuration or a grant; hook commands run only as [Hook execution](#hook-execution) defines.

Tool admission snapshots the settings once and pins the SHA-256 of their bytes in `RunStarted.tool_policy.permissions_digest` (`null` when absent); editing the file never changes an admitted Run. Present settings select the mode and approval path below, also headless: a required human approval without a channel denies, and AI review may use the admitted review Provider. Without settings, the terminal mode cycle is unchanged.

Every configured step commits its permission verdict in `ToolStarted`, after preparation and approval and before dispatch or its denied observation. `verdict` is required and nullable; only unconfigured pinned-grant steps carry null. A pre-hook, AI review or human approval first commits `ToolProposed` with the immutable intent and crash-charge ceiling; a hook-free single-call step needing none commits no proposal. [Execution](./execution.md#committed-event-stream) owns multi-call proposal ordering. The proposal advances in place at `ToolStarted`, keeping its hook and review evidence. The verdict binds the exact intent digest, effective decision, pinned settings mode, rule/mode/grant basis, final approval, approval source (`rule`, `mode`, `pinned_grant`, `human`, `ai_review`, `unavailable_approval`, `session_approval`, `hook`, `typed_prefix_rule` or `host_prefix_rule`), the narrowest `hook_restriction` (`null` when none) and the number of `hooks` that ran. The reducer rejects missing, duplicate, wrong-intent or post-observation verdicts and any effect after a denied verdict. An AI preapproval requires a recorded review of that pending Tool. Strict replay consumes these facts without reading settings, rerunning a review or dispatching. [Execution](./execution.md#admission-persistence-and-recovery) owns payload versions.

Only a primary [host command](#primary-host-commands), primary [typed Git write](#typed-git-writes) or primary [`gh_pr_list` / `gh_pr_view` read](#host-pull-request-listing) in a Run without settings commits a verdict with `mode: null`; the reducer rejects an omitted mode elsewhere, including for children. Unconfigured host commands and typed Git writes use basis `mode` or `pinned_grant` and source `mode`, `pinned_grant`, `human`, `ai_review` or `unavailable_approval`; the reducer rejects hook restrictions, rule, hook, session, typed or host-prefix sources, and an unconfigured host or typed-write start without a verdict. An unconfigured `gh_pr_list` or `gh_pr_view` approval requires decision `ask` and source `human`, and an `unavailable_approval` denial stays valid; `mode`, `pinned_grant` and `ai_review` approvals reject, and `typed_prefix_rule` requires pinned settings.

The same settings restrict children; a child cannot select its own settings or expand its read-only spawn grant. Explicit asks go to the human adapter. Auto reviews of researcher MCP discovery use the admitted review Provider with the child's exact intent and the Goal objective, within the [shared delegation active-time allowance](#folder-trust-and-approvals) and budget. Tool steps after primary synthesis keep their non-review path: required approval goes to a human or denies without a channel, preserving the delegation's reserved synthesis and continuation headroom. Rules never bypass the Goal plan, deterministic Policy, pinned grant or Guard. Denials use compiled labels such as `permission_rule_denied`, `permission_mode_denied`, `hook_denied`, `user_declined` or `channel_unavailable`, never hook prose, rule text or undisclosed paths. A committed denial reaches its requesting actor once as a correlated Tool result; continuation stays under that actor's limits. Every new proposal gets a fresh permission check; a refusal never retries the effect.

### Modes and approval decisions

The [serve approval transport](./serve.md#server-requests) is another human client of the same channel, with negotiated live-session scope for eligible primary host commands. The [ACP adapter](./acp.md#tool-updates-and-permissions) permits ordinary one-use client verdicts, including user-configured client policy. ACP v1 cannot attest a human gesture, so its channel disables human-only requests: unresolved host-command asks and hook Asks dispatch nothing, send no permission request and journal `unavailable_approval`. Host-prefix preapproval follows [Remembered host prefixes](#remembered-host-prefixes); client policy and `allow_always` supply no host authority. AI review, mode changes and client capabilities cannot resolve those requests.

The peer contract is [Claude Code permission modes](https://code.claude.com/docs/en/permissions#permission-modes). The five spellings are case-sensitive; aliases and bypass modes reject. An omitted `defaultMode` parses as `default` and does not change Arany's interactive default.

| Mode | Peer behavior | Arany mapping and narrowing |
|---|---|---|
| `default` | Prompt on first Tool use. | `Request`: absent a matching allow, a fresh one-use human approval for each effect needing approval. Remembered Tool use cannot renew an immutable intent. |
| `acceptEdits` | Accept file edits and common filesystem commands in working directories. | `AutoEdits`: typed mutations, including changeset integration; commands, MCP calls and Git writes still ask because process behavior is not a typed edit. |
| `plan` | Explore without source edits; read-only shell commands are available. | Deny mutations and command/MCP processes, even with allow rules. Permit admitted typed reads, Skill reads and typed Git reads; arbitrary argv and MCP metadata cannot prove a read-only effect. |
| `auto` | Classify actions without routine prompts; broad execution allows are dropped. | `Auto` AI review for approval-needing calls, plus typed Git processes and MCP discovery; every `spawns_process` call and MCP operation needs review and matching allows never skip it. Budgets, uncertainty-to-human fallback and cancellation stay mandatory. |
| `dontAsk` | Deny actions that would prompt; pre-approved actions remain available. | An unresolved `Ask`, including a hook `ask`, becomes `Deny` (the hook `ask` is still recorded); otherwise admitted no-question calls and matching allows proceed. An explicit ask rule denies. |

Settings and the live terminal mode are independent restrictions: a call asks if either asks, human Request takes precedence over AI review or edit preapproval, and neither widens a settings Ask or Deny. [Claude Code treats `defaultMode` as a starting mode that Shift+Tab overrides](https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in); Arany combines both to keep its only-narrow guarantee.

`decision(call)` returns `Allow`, `Deny` or `Ask`: approval dispositions within the pinned grant, never authority. Invalid or oversized calls deny. An explicit ask rule selects human `Request` even under `auto` or `acceptEdits`; only an otherwise unresolved `auto` decision selects AI review. The caller still journals the exact intent and verdict and needs deterministic Policy admission before dispatch; guarded calls also need Guard attestation, and executed host commands record an `UnguardedReceipt` ([Primary host commands](#primary-host-commands)). Independent restrictions combine as `Deny > Ask > Allow`; an allow from a hook or review cannot erase an earlier denial or question. A hook's `allow` is ignored because it is runtime program output, unlike a static user rule; only a human or the Auto review resolves an Ask. Children keep the intersection with parent authority. There is no bypass or implicit unguarded execution: `command_unguarded` is never pre-approved by an ordinary allow rule, a mode or AI review, only by its separate [session or host-prefix authority](#primary-host-commands), and `plan` denies it.

**Owner-accepted peer behavior (2026-10-17):** in `default`, a matching allow rule pre-approves commands and MCP calls without a human prompt or AI review, subject to live terminal restrictions, as in [Claude Code permissions](https://code.claude.com/docs/en/permissions#permission-rule-syntax). It is a user-configured approval, not a bypass of the Guard, Policy or pinned grant; deny and ask keep precedence. `acceptEdits` keeps human approval for commands and MCP calls even with an allow rule.

[Claude Code drops broad execution allows on entering auto mode](https://code.claude.com/docs/en/permission-modes#how-auto-mode-evaluates-actions). Arany is stricter during decision evaluation: `auto` ignores allow rules for processes, MCP operations and calls that already need approval, including bare `Bash`/`command`, `Bash(*)`, `Bash(python*)`, `Bash(python *)`, `:*` equivalents, bare `mcp_call` and whole-server MCP rules. AI review of commands, MCP calls and typed mutations stays mandatory; with settings present, typed Git processes and MCP discovery are reviewed too, while terminal Auto without settings keeps its narrower scope. Explicit ask rules still select a human and deny rules still block.

**Typed Git prefix rules.** A matching typed `allow` rule skips the prompt in Request approvals and Auto edits, as Claude Code allow rules do; the verdict records `typed_prefix_rule`. Settings `default` and `dontAsk` honor it; `acceptEdits` and `auto` ignore local-write allows and ask, live Auto approval keeps its AI review, and `plan` denies writes. Deny and ask rules in either list always win over any allow, and a typed rule never overrides an ordinary Read, Edit, path or tool-name restriction. Rules are user-owned; repository content never adds or widens one. See [Typed prefix rules](#typed-prefix-rules).

### Permission rules

The envelope copies [Claude Code settings](https://code.claude.com/docs/en/settings) and [rule syntax](https://code.claude.com/docs/en/permissions#permission-rule-syntax):

```json
{
  "permissions": {
    "defaultMode": "default",
    "allow": ["Bash(git diff *)", "Read(./crates/arany/src/**)"],
    "deny": ["Read(./private/**)"],
    "ask": ["Edit(./crates/arany/src/**)"]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{"type": "command", "command": "/reviewed/check", "timeout": 30}]
      }
    ]
  }
}
```

Every envelope and permissions field shown is optional, defaulting to empty lists/maps. Unknown or duplicate fields, wrong types, unsupported names and malformed rules reject the whole document; no invalid rule is skipped. A rule is a bare Tool or `Tool(specifier)`; inner parentheses are literal. Lists evaluate in deny, ask, allow order regardless of specificity or input order, and no exception within a list undoes a match.

| Peer Tool | Typed Arany operations |
|---|---|
| `Bash` | `command`; the subject is its admitted logical program identifier and argv, not an inferred executable basename. |
| `Read` | `list`, `read`, `search`, `glob`; deny and ask also cover `git_status`, `git_diff` and `git_log` paths, Skill files inside the Workspace, and [Git writes](#typed-git-writes): commit paths and potentially covered descendants, plus every staged or whole-repository commit and every switch, whose paths are unknown before dispatch. A deny also covers typed mutations and changeset paths, so a read denial cannot be written through. |
| `Edit` | `mkdir`, `write`, `edit`, `multiedit`, `delete`, `move`, `apply_changeset`; deny and ask also cover the same [Git writes](#typed-git-writes) as `Read`. |
| `MultiEdit` | `multiedit`, with the same Edit-family path rules and read-denial protection. |
| `Write`, `Glob` | Bare `write`, and bare `list` and `glob`; path specifiers reject in favor of `Edit` and `Read`. |
| `Grep`, `Skill` | `search` path and admitted `skill` name. Skill wildcards match names, not authority or resource discovery. |
| `mcp__<server>__<tool>` | `mcp_call`, matched against separate server and tool fields; the Tool segment supports `*`. `mcp__<server>` also covers that server's catalog listing and all calls; `mcp__*` covers all servers for deny/ask. |
| `Network(domain:x)` | Not a call matcher: a host pattern that extends or restricts a configured [network grant](#network-grants-and-egress-proxy). Allow adds the domain; deny and ask remove it. The domain uses the grant grammar; `Network` alone, other specifiers and invalid patterns reject. |
| Exact Arany catalog name | That operation only, including `git_status`, `git_diff`, `git_log`, `mcp_list` and `mcp_call`. Native MCP operation names accept bare rules only. |

Bare Tool-name `*` globs are supported for deny and ask against peer and native operation names; a non-MCP glob matching no known operation rejects. MCP allow rules require a literal server; generic allow name-globs reject. Server patterns are at most 64 bytes of lowercase ASCII letters, digits, `_`, `-` and `*`; Tool patterns are at most 128 bytes within the complete-rule ceiling. MCP allows compare parsed server and Tool fields separately. Deny/ask also test the complete peer-name glob against the call or catalog subject, including `__` descendants, so a rule can restrict a whole server; ambiguous server names containing `__` or ending in `_` may be over-restricted but never pre-approved. Tool names supply no authority and matching discovers no servers. A changeset allow requires every path to match the same rule; deny/ask requires any path. Separate allows cannot assemble authority for an otherwise unmatched batch.

Bash patterns follow the peer's [wildcard examples](https://code.claude.com/docs/en/permissions#wildcard-patterns): `*` spans spaces and exact patterns stay exact. A sole trailing ` *` also matches the bare command but keeps its word boundary; trailing `:*` is equivalent; `Bash(*)` equals bare `Bash`. Other characters are literal.

Only unambiguous argv words of ASCII letters/digits and `_./:@+=,%~-` are joined with spaces for specifier matching. Empty, quoted, whitespace-bearing or shell/control-bearing arguments are opaque: an opaque command never matches a specifier allow and matches every applicable specifier deny/ask, while a bare Tool rule still covers it. Deny/ask also check every word-boundary suffix of the joined argv, so `timeout 30 rm x`, `nice rm x`, `xargs rm x` and `env FOO=1 rm x` cannot hide an `rm *` restriction, even when the word is ordinary data. Allows match only the complete argv projection. Unlike the peer, Arany does not split shell strings, expand variables or infer commands from scripts, so shell parsing never becomes an authority boundary; execution stays under the pinned command grant and Guard. Text matching proves nothing about an executable's effects, disclosure or read-only behavior.

File patterns use the peer's [Read/Edit matching depths](https://code.claude.com/docs/en/permissions#read-and-edit) and [gitignore wildcards](https://git-scm.com/docs/gitignore#_pattern_format): `*` and `?` stay within a segment; whole-segment `**` crosses zero or more directories; alphanumeric classes/ranges, class negation and backslash-escaped literals are supported. Bare filenames match at any depth. `/path`, `./path` and multi-segment relative patterns anchor at the admitted Workspace; Claude Code anchors `/path` at the settings source, but Arany uses its admitted directory capability so settings placement cannot change path authority. Unanchored `crates/arany/src/**` matches only root `src` for allow and a `src` directory at any depth for deny/ask; an explicit `**/src/**` matches at any depth for every list. Deny/ask patterns compile case-insensitively; allow patterns stay case-sensitive. Deny/ask reject non-ASCII pattern literals, and any non-ASCII subject path, including changeset and Git paths, matches an applicable restrictive path rule; this closes NFC/NFD and Unicode case aliases without normalization and deliberately over-restricts. Allow literals keep exact Unicode spelling and cannot normalize into a wider match. The matcher does no filesystem access or symlink following; filesystem aliases stay under the separate no-follow grant and Guard.

The path vocabulary is Workspace-relative. `//` absolute and `~/` home anchors, traversal, empty components, trailing directory-only slashes, non-segment `**`, unsupported classes, dangling escapes, leading comments and gitignore `!` exceptions reject; restrict-only sources cannot remove prior restrictions. No-follow admission and exclusions still apply. Rules match proposed typed paths and filter results.

A commit path can publish its whole subtree, so Read/Edit deny and ask rules also apply when a commit path overlaps the rule's literal directory prefix in either direction. The prefix ends before the first segment with a wildcard, class or escape; patterns that can start at any depth have an empty prefix and restrict every commit path. Staged and whole-repository commits match every applicable restrictive path rule.

Result filtering follows the peer's [best-effort application of `Read` rules to Grep and Glob](https://code.claude.com/docs/en/permissions#read-and-edit) and its listings that omit matched names. `list`, `search` and `glob` results, `git_status` and `git_diff` rows and patch sections, and `git_log` commits omit every path for which the same operation would match a deny or ask rule that the call itself did not match. A rule that matched the call either denied it or was approved for it, so an approved `search` of an asked directory shows its rows while a broader call hides them; an approver never sees paths the call did not name. The matcher is unchanged, so while any restrictive path rule applies, a broader call drops every non-ASCII path. A covered directory covers its subtree: Workspace walks prune it before opening it and Search never opens a covered file. Filtering precedes ordering, row and byte fitting, `limit`, `offset`, `next_offset` and `truncated`, so pages count only visible rows. The Engine sends the restrictive patterns to the Guard, which filters Git output before fitting. Every patch section starts hidden; only a `diff --git a/P b/P` or combined `diff --cc P` header, or a staged `* Unmerged path P` line, naming a visible unquoted path reveals it, so conflict sections, unrecognized or quoted headers and a line cut by the capture limit fail closed. A collapsed untracked directory row such as `dir/` names only that directory and is hidden when a rule covers it. The view sets `core.quotePath=false`, so only names with control characters, `"` or `\` are quoted, and those stay hidden. A filtered `git_log` reads changed paths (`--name-only` without rename detection, so a move reports both sides; merges against their first parent) for at most 1,000 commits, keeps commits changing a visible path, then applies `max_count`; a commit without path evidence is dropped and an exhausted scan sets `truncated`. Subjects of kept commits show even when they also change covered paths. Git failures follow the [typed Git disclosure policy](#typed-git-reads). Git's [capture bound](#limits-and-failure-behavior) still counts covered output, so a capture overflow keeps `truncated` true. A Workspace Skill file is also a file read: a `skill` call takes the stricter of its own decision and a `read` of that path, and a Skill whose `SKILL.md` is covered is omitted from the catalog, so its description is never previewed. The verdict is journaled before dispatch, so a denied Skill file is never opened and no Guard task starts; the read path checks the pinned grant and file digests. Rules do not filter explicit includes, interpreter I/O or subprocess filesystem access; that stays bounded by the grant and Guard, and this config API is not an OS path filter.

### Hook execution

The envelope and nested groups copy the [Claude Code hooks reference](https://code.claude.com/docs/en/hooks#configuration) and [command fields](https://code.claude.com/docs/en/hooks#command-hook-fields). Accepted events are exactly `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop` and `PreCompact`. Groups contain a `hooks` array of command handlers, an optional matcher, and nothing else. Handlers accept `type: "command"`, a nonempty `command`, optional `args` and an optional integer `timeout` in seconds. Omitted `args` means shell form; a present array, including `[]`, means exec form. Nothing is interpolated or resolved.

An absent, empty or `*` matcher selects every occurrence. The peer's exact-name and `|`/`,` alternatives are copied; other patterns are unanchored regexes in bounded finite-automaton syntax, so lookaround, backreferences and oversized compiled patterns reject. Tool events match through `matches_tool`, so invalid or ambiguous calls cannot evade a hook; other events match their event-specific subject. Tool subjects use the canonical peer names above, including `mcp__<server>__<tool>` calls and `mcp__<server>` catalog subjects; `SubagentStop` matches agent type and `PreCompact` the trigger (`manual`/`auto`). `Stop` accepts only match-all: a filtering matcher rejects instead of the peer's silent ignore. An MCP server name containing `__` produces a blocking Tool-subject error. A present `null` is invalid. Empty handler groups, other events or types, async handlers and extra execution options reject.

**Recorded owner decision (2026-10-17):** hook commands run inside the Guard like every process, under pinned interpreter/executable identities, an explicit environment and typed grants. Arany copies Claude Code's hook protocol (events, matchers, JSON on stdin, event-specific exit-2 blocking, `permissionDecision` `allow|deny|ask`, timeouts) but not its execution authority: [Claude Code command hooks run with full user permissions](https://code.claude.com/docs/en/hooks#security-considerations), while Arany's [Per-effect isolation guarantee](../../AGENTS.md#non-negotiable-guarantees) requires the Guard. Descendants gain no authority, and repository or hook output cannot select trust.

| Claude Code behavior | Arany behavior | Reason |
|---|---|---|
| Hooks run with full user permissions and real working-directory paths. | Guarded, offline, pinned shell/program, explicit environment; stdin `cwd` is `/workspace`; hook changes are discarded. | Per-effect isolation; untrusted output cannot select trust. |
| `allow` can skip prompts. | Journal `allow_is_no_op`; never resolve Ask or erase Deny. A hook Ask needs the human even in Auto mode. | Hooks only narrow. |
| `updatedInput` replaces input. | Only the provable narrowing below, under a new intent, for primary Tools; a delegated `updatedInput` denies (Claude Code rewrites subagent input). | Immutable intent and pinned authority. |
| Matching hooks run in parallel. | Sequential configuration order, bounded matches, stop at a terminal restriction. | Journal-first ordering, finite Guard capacity, deterministic replay. |
| Nonzero errors and timeouts are normally non-blocking. | Other exits add no restriction. Timeout and output overflow fail closed: PreToolUse denies, PostToolUse adds limit feedback, lifecycle hooks block. | A model-steered timeout must not disable a restrictor. |
| PostToolUse can replace some Tool output. | Bounded feedback only; attested observations and completed effects stay. | Hook text cannot forge effect evidence. |
| `continue: false` stops the actor; `stopReason` is user-only. | All five events journal `stopped`; in an active Run they take the [terminal outcome](./execution.md#accepted-outcomes) before the pending Tool or compaction. An idle PreCompact stops only that compaction. | Typed honest outcomes. |
| Stop blocks send feedback to the model. | Bounded user-data continuations under Goal admission, a per-actor cap and the child deadline. | Durable budgets, bounded context. |
| PreCompact accepts custom instructions. | `custom_instructions` is empty; digest-only occurrence subjects. | No fresh authority or host-path disclosure. |
| JavaScript regexes and ignored Stop matchers are accepted. | Bounded finite automata; filtering Stop matchers and ambiguous MCP subjects reject. | Resource bounds, fail-closed matching. |
| Transcript paths, interpolation, async and non-command handlers exist. | Closed stdin fields and command handlers only; unsupported configuration rejects, unknown output fields are ignored. | Bounded disclosure and authority. |
| Settings can be re-read during execution. | Pinned per Run; replay validates recorded results without reading settings or executing hooks. | Journal-first durability, strict replay. |

**Common rules.** Each handler is a journaled `Command` effect with the Guard's offline, private-Workspace-view, explicit-environment grant of a model command. `HookStarted` commits the immutable hook intent, the exact-stdin digest and the pending proposal's digest; `HookFinished` commits the Guard observation (with receipt) and the parsed result. Shell form runs the pinned `sh` as `sh -c <command>`; exec form runs `command` as a pinned program name with `args`. Every recorded result must equal the deterministic parse of its Guard observation for its event, and can only narrow. Exit 0 with empty, non-JSON or non-UTF-8 stdout adds nothing; unknown fields are ignored, and stdout is never instructions. Reasons and feedback are control-stripped and bounded; model and history projections show `hook_denied` and never the reason text, including for older observations and compaction summaries. A hook cannot see host files, and its Workspace changes are discarded. A hook whose observation is [Uncertain](./execution.md#effect-outcomes), cancelled or unattested is recorded and blocks continuation and resume like an uncertain Tool. A Guarded Command that is not a hook reads an empty stdin (immediate EOF), like the unguarded executor. Internal Engine preparation calls over snapshot-pinned input, such as agent definition parsing, are never model Tools: no hook sees or narrows them, and they widen nothing.

An ignored hook failure stays `Ignored` with bounded diagnostic feedback. It never creates a host-command offer or an escape-only Stop/PreCompact continuation; the primary may separately request a fresh [host command](#primary-host-commands), whose result never replaces the recorded hook verdict.

**Delegated Tools.** As in Claude Code, researcher and editor Tool calls trigger the same PreToolUse and PostToolUse hooks as primary Tools. Hook intents and Events keep the child's `agent_run_id`; admission reserves their bounded tail, and execution stays within the shared delegation active-time allowance. Denial and feedback apply to that child's Tool. Delegated calls are never rewritten. Completed Workspace publication stays recorded if a post hook stops the Run.

**`PreToolUse`.** After the permission decision and live terminal restriction, and only while the decision is not `Deny`, matched handlers run one at a time in configuration order, then the verdict follows. An unpinned program, a matcher error or more matched handlers than the limit denies the Tool before any hook starts, with reason `hook program is not pinned`, `hook configuration blocks this Tool` or `hook limit`. Handlers after a denial do not run. Stdin is one JSON object with a closed field set: `session_id`, `cwd` (always `/workspace`, never a host path), `permission_mode`, `hook_event_name`, `tool_name` (peer name), `tool_input` (the typed call) and `tool_use_id`. Exit 0 with a JSON object may carry `hookSpecificOutput` (`hookEventName` must be `PreToolUse`) with `permissionDecision` and `permissionDecisionReason`, the legacy top-level `decision: "block"` with `reason`, or `continue: false` with `stopReason`, which stops the Run before dispatch and takes precedence over `decision: "block"`. Exit 2 denies with stderr as the reason; any other exit is a non-blocking failure. Decisions combine `deny > ask > allow`.

The verdict records `hook_restriction` (`null`, `ask` or `deny`) and `hooks` (handlers that ran). The reducer requires every started hook to finish before the verdict, `hooks` to equal the journaled count, `null` only when no hook restricted or stopped, `ask` only for an `Ask` fold, and `deny` only for a `Deny` fold, a stopped hook or a denial before any hook ran. A hook `Deny` has basis and source `hook`; a hook `Ask` over an `Allow` has basis `hook` and is resolved by the human, never AI review (a forged AI review of it rejects on replay).

**Hook limits.** Configuration holds at most 64 groups and 128 handlers across events. Matchers and match subjects are at most 1024 bytes<!-- unrelated-bound: hook matcher subject bytes --> and control-free; subject overflow, controls or an invalid Tool call return an error that blocks the pending action instead of a non-match. Commands are at most 4096 bytes<!-- unrelated-bound: hook command text -->; tab and newline are inert, other controls reject. Exec form has at most 64 arguments of 4096 bytes<!-- unrelated-bound: hook exec argument --> each, without NUL, within the document limit. Timeout is 1–600 seconds<!-- unrelated-bound: hook handler timeout -->, default 600; the finite maximum is an Arany narrowing. Each regex has a 128 KiB<!-- unrelated-bound: hook regex compiled size --> compiled-size ceiling, a 32 KiB<!-- unrelated-bound: regex DFA cache --> DFA cache and 32 nesting levels. Configuration overflow rejects with no truncation, partial config, retry or fallback; errors name the list/index or constraint without echoing command or rule text.

At most 8 matched handlers run per occurrence. Stdin is at most 32 KiB<!-- unrelated-bound: hook input cap -->, including the complete `tool_input`: a matched `PreToolUse` or `PostToolUse` set that cannot receive the whole call, such as a Write, Edit or MultiEdit carrying more than about 32 KiB<!-- unrelated-bound: hook input cap --> of content, denies the Tool before any handler or effect (`hook input exceeds its limit`, zero handlers); `tool_input` is never truncated or hashed and the hook is never bypassed. Every matched handler's Guard task must encode within the Guard task ceiling before any hook starts, else the Tool is denied (`hook input exceeds the Guard task limit`) with no `HookStarted`. A result is at most 32 KiB<!-- unrelated-bound: hook result cap -->, with each stdout/stderr capture capped at 16 KiB<!-- unrelated-bound: hook stream capture cap --> minus 128 bytes; overflow fails closed and cannot turn an exit-2 hook into a non-blocking one. Runtime is at most the handler `timeout` and the remaining Goal active time, never less than 1 s; the Goal ledger refuses a start that does not fit, and the Guard reaps descendants on timeout. Reasons are truncated at a UTF-8 boundary to at most 1 KiB<!-- unrelated-bound: hook reason bytes -->. Tool step admission reserves two Events and one observation per matched handler, and the Tool's authorization lifetime and active-time ceiling grow by the handlers' worst case, clamped to the remaining Goal active time (unbounded Goals keep the full worst case). Hook time is Goal active time.

**`PostToolUse`.** After a primary or delegated Tool commits a `Succeeded` observation, its matched handlers run one at a time with the `PreToolUse` grant, bounds and `HookStarted`/`HookFinished` pair. `HookStarted` requires that observation and the Tool's digest and directly follows the Tool's latest step: a Command's hooks run after its changeset integration commits and see the published tree (a worker command's hook runs after its private seal and sees the host Workspace), and no Provider call, compaction or other Tool may intervene. In a concurrent in-process read step, sibling read and admission Events may intervene: read post-hooks run serially in observation completion order after the step's admissions and reads settle, before any non-read call or Provider reservation, and successful reads still run them after a sibling `Limit`. Each source has one contiguous set of distinct handlers in configuration order, and each deferred hook binds its source digest in the current step. Failed, denied, uncertain, limited and internal calls run no `PostToolUse` hook. The hook cannot undo the effect. Stdin adds `tool_response`, the observation's model-facing projection, replaced by `{"truncated": true, "text": <prefix>}` when it would exceed the stdin limit, with the prefix halved (down to empty) until every matched Guard task fits, so on macOS a hook can receive less than 32 KiB<!-- unrelated-bound: hook input cap -->. Exit 2 (stderr), `decision: "block"` with `reason`, and `hookSpecificOutput` (`hookEventName` must be `PostToolUse`) with `additionalContext` become feedback; other exits are non-blocking failures; a timeout or output overflow becomes the feedback `hook limit reached`. On exit 0, `continue: false` takes precedence over feedback, records `stopped` with optional `stopReason` and skips remaining handlers; [Run outcomes](./execution.md#accepted-outcomes) own the terminal behavior. `updatedToolOutput` and other fields are ignored. An Uncertain, cancelled or unattested hook stops the Run after the effect; the observation stays committed and the next Provider call does not start, while the typed pre-dispatch bootstrap exception stays `Ignored`.

Feedback is stored only in the journaled `HookFinished` result (a `feedback` result with a `lines` list). The model-facing Tool result gains a `hook_feedback` list of `hook feedback: <text>` lines (at most 4 KiB<!-- unrelated-bound: PostToolUse feedback aggregate --> in total, later lines dropped), rebuilt from the journaled results after resume, so prompts are byte-identical. A step matching either Tool hook set reserves twice that room in the context budget, and `PostToolUse` time extends the active-time ceiling but not the authorization lifetime. Because a post hook cannot be refused after the effect, a Tool whose `PostToolUse` handlers are unpinned, over the matched-handler limit, or unable to encode their Guard task or stdin even with an empty truncated response is denied before dispatch with the `PreToolUse` reasons and no `HookStarted`.

**`updatedInput` narrowing.** `updatedInput` must be a complete, valid Tool call of the `tool_input` shape; anything else denies. A replacement narrows only when it is:

- a `read` of the same path whose offset and end lie inside the original window;
- a `glob` with the same normalized pattern, an equal or lower limit and an equal or subtree path;
- a `list`, `git_status`, `git_diff` or `git_log` whose path equals the original or lies beneath it by whole segments (a root original admits any path), with Git reads keeping every other field;
- a `search` keeping its query, `regex`, `include` and `case_sensitive` after default normalization, whose page lies inside the original row window (`offset` through `offset + limit`) for the same path, or whose path lies beneath the original's with no include, both offsets zero and a limit no larger.

Parent paths, `..`, case or symlink variants, larger windows or glob limits, changed queries, patterns, matching modes, includes or case, and every `command`, MCP, Skill, `write`, `edit`, `multiedit`, `mkdir`, `apply_changeset` or internal call never narrow; the model must propose those as new calls. The replacement must also be at least as restrictive under the pinned rules and within the pinned grant. `HookFinished` journals every valid-shaped update outside an `ask` decision as a `narrowed` result, but only the verdict's `narrowed` flag records acceptance. An update identical to the current call is a no-op, so idempotent clamping hooks work. An update refused by narrowing, rules, grant or the per-step limit denies with the matching reason and a false flag. `ask` with `updatedInput` keeps the ask on the original input. On an accepted narrowing the original Tool is `Denied` with basis `hook`, the flag set and the line `Hook narrowed this Tool to: <tool_name>`; the next Tool of that step must be exactly the replacement (a new `ToolStarted` intent), and `PreToolUse` hooks run again for it. At most one narrowing per step; a second denies (`hook narrowing limit`). The model receives one Tool result built from the replacement's observation, and the original's denial line arrives as a separate `hook_narrowing` data block. Internal Engine calls and delegated research are never narrowed. Step admission reserves the replacement's Events and observations.

**`Stop` and `SubagentStop`.** A primary answer runs `Stop` before `AgentFinished`; a researcher or editor answer runs `SubagentStop`, matched against its definition name (or the role fallback `researcher` / `editor`), before the child's `AgentFinished`. Both receive `stop_hook_active` and `last_assistant_message`, truncated at a UTF-8 boundary to fit the stdin and Guard task ceilings. Exit 2 or `decision: "block"` records `blocked` with a bounded reason. On exit 0, `continue: false` takes precedence over `decision: "block"`, journals `stopped` with optional `stopReason` and skips remaining handlers; [Run outcomes](./execution.md#accepted-outcomes) own settlement. On a block, the accepted assistant turn and a user-data block labelled `stop_hook_feedback` are appended to the next request, which uses ordinary Goal Provider-call admission; exhaustion ends the turn with the budget outcome. A child re-prompt stays inside its delegation deadline and turn ceiling; a stopped editor keeps its landed Workspace effects and releases its lease through the [editor lifecycle](#editor-tool-steps). At most eight blocked continuations are admitted per actor in a Run, counting every blocked Stop regardless of intervening Tool calls (which never reset the cap or `stop_hook_active`), so feedback stays within 8 KiB<!-- unrelated-bound: Stop hook feedback aggregate -->; after the cap a valid answer completes without another Stop invocation.

**`PreCompact`.** Before an active-Run compaction reservation or an idle Session compaction, matching handlers receive `trigger` (`manual` or `auto`) and empty `custom_instructions`. Passing hooks are journaled before the reservation. A block skips the compaction without a reservation, and the Run continues while retained context fits; otherwise the context failure applies. `continue: false` stops an active Run before the reservation, or only the compaction when idle. Cancellation during an active-Run hook with a known outcome cancels the Run before any reservation; an unknown outcome leaves the Run interrupted with an uncertain stop under [Run outcome precedence](./execution.md#accepted-outcomes). A manual `/compact` blocked by a hook fails with `CompactionBlockedByHook`, distinct from an empty input. Each trigger/call-index occurrence runs once; a retry at the same call count reuses the recorded outcome and never reruns the hook. Idle compaction re-admits the current private configured or remembered folder grant only if its digest and the permissions digest match the Run's pins; otherwise it fails closed. Between Runs of an open Goal, hook start reserves a durable active-time ceiling and completion settles elapsed time; outside an open Goal the handler keeps its finite timeout and Guard limits.

**Lifecycle hooks** use the same pinned programs, Guard, sequential execution, limits, fail-closed Limit and uncertainty handling as Tool hooks. An invalid program records the offending handler's call as a denied, never-dispatched intent; matched-handler overflow uses the event's first configured handler, and stdin that cannot fit the Guard task uses the first matched handler. That call carries the reason as output and the result is `Blocked`, before any process runs. A SubagentStop shares its delegation, so admission reserves the child's settlement tail; a cut-off or cancelled SubagentStop ends that child (cancelled when the user cancelled, otherwise failed under the child's fatal or local failure policy) without exhausting the Goal budget, and the editor's closed failure cause follows the [worker outcome contract](./execution.md#worker-journal-protocol). An unknown outcome stops the Run as Uncertain. Replay binds Stop subjects to `(agent_run_id, provider call index)` and PreCompact subjects to `(trigger, provider call count)`. A Stop occurrence immediately follows its accepted Finished call; a blocked Stop forbids successful Agent completion until a new call is recorded. Each continuation re-renders the answer turn, which counts toward Tool context and its compaction trigger; a context without room refuses with `ContextTooLarge` before any hook journals. Open or Uncertain hooks block continuation and resume; strict replay consumes recorded facts and rejects forged outcomes, miscounts and unknown payload versions without executing hooks.

### Supervisor adapter

The Engine owns bounded Supervisor evaluation state and calls one pure, deterministic evaluator over committed reducer facts. The RunLoop journals a verdict or continues without one; the reducer only validates recorded verdicts' shape and placement. Tool-enabled Runs pin the required `config.supervisor = {evaluator: 1, window: 32, floors, candidates, digest}` in `RunStarted`; Runs without Tools pin null. The SHA-256 digest binds the domain `arany.supervisor.policy.v1`, evaluator, window and both closed threshold structs. There is no configuration file, model call, clock, I/O, network, Guard task or journal subscriber, and repository text, model output and hooks cannot select thresholds. Shadow mode is always on and never changes permissions, catalogs, approvals, continuation, integration, Run outcomes or model input.

A boundary follows every model `ToolFinished`, including editor Workspace effects and known denials or failures. A primary command with a nonempty validated changeset uses `command_capture`; invalid or deferred Provider results and blocked Stop/SubagentStop use `stall`. Internal definition parsing and changeset integration are excluded. The site vocabulary is closed to `tool_outcome`, `command_capture` and `stall`; other subjects reject.

Each actor (at most nine per Run) has an independent window of its last 32 boundaries; the oldest step is evicted whole on the 33rd, and a new Run starts empty. Feature counts saturate at 65,535; ratios use saturating integer arithmetic, floor division and a denominator of at least one. Keys are SHA-256 over domain `arany.supervisor.call.v1` and canonical typed calls, with Write/Edit content replaced by its SHA-256; intent, actor and Run IDs, expiry and target revision are excluded. Outcome equality binds disposition, closed enforcement cause, exit class (zero/nonzero/unknown) and SHA-256 of the model-facing result without its call or target. No prose is parsed. Policy/plan/grant/lease/permission/hook denials count as refusals; closed `filesystem_denied` counts as a path-admission rejection; ordinary nonzero exits are not probing.

| Signal | Features | Notice floor | Would-narrow candidate |
|---|---|---|---|
| Loop | Identical `(call, outcome)` suffix; same-call non-success suffix; greatest whole suffix cycle repetitions for lengths 2, 3 and 4 (shortest length wins ties); maximum per-path returns to a prior after-digest following a different digest; stall boundaries since the last succeeded observation | identical 3; failing 2; cycle 3; oscillation 1; stalled 2 | identical 4; failing 3; length-2 cycle 3, other cycles 5; oscillation 2; stalled 3 |
| Probing | Refusal suffix; refusals in window; distinct refused call keys; closed path-admission rejections | streak 2 or alias 1 | streak 3, or distinct 3 with window 4, or alias 2 |
| Disproportion | Files, deleted files, ceil(decoded before+after bytes / 1024), declared roots (minimum 1), nullable base KiB (currently null), files/root, deleted/files permille, nullable changed/base permille (currently null) | files 16, or deletion 250 permille with files/root 4 | files/root 8 with files 32; deletion 500 permille with deleted 8; growth 4000 permille with changed 64 KiB<!-- unrelated-bound: change profile growth bytes --> |

Loop and probing are evaluated at all three sites and journaled only when the subject is in the signal's evidence, so one crossing yields one verdict; disproportion is evaluated at every capture. A candidate hit has level `would_narrow`, otherwise a floor hit has level `notice`; both are journaled. Candidate responses are loop `pause`, probing `revoke`, disproportion `require_approval`; notices have null response. These are calibration candidates only. Disproportion uses validated changeset facts and declared lease/plan roots; base/growth features are null without a base. Live editors supply no private capture or handover boundaries. Each signal keeps at most eight increasing subject sequences as evidence. Edit equality keeps only hashed path/after-digest pairs, at most the [capture bound](./limits.md#max_snapshot_files) per step and 589,824 pairs per Run (36 MiB of pair data), never contents; eviction removes a step and its pairs together. Per-boundary work is bounded by the window and those capture bounds and never grows with Session history. The evaluator has no fallible external operation; a panic fails the coordinator through its failure boundary.

The RunLoop commits a nonempty `SupervisorVerdictRecorded` as its own decision immediately after its subject, before hooks, integration, stop facts or other continuation. A failed or unknown append stops continuation; an uncommitted verdict is never treated as recorded. The closed payload carries `subject_sequence`, `site`, `evaluator: 1`, `mode: shadow`, one to three signal entries (`signal`, `level`, nullable `would_response`, fixed feature struct, evidence) and `capped`, and holds only integers, booleans, enums and sequences. [Execution](./execution.md#persistence-bounds) owns the [2 KiB](./limits.md#max_verdict_bytes) payload and 256-verdict Run cap; evaluation continues after the cap without journaling. No verdict enters compiled context, compaction input, Provider input or diagnostics. [Serve](./serve.md#notifications-and-items) forwards the canonical verdict (counts, sequences and closed enums, never paths or content); [terminal](./terminal.md#conversation-progress-and-history) and [telemetry](./telemetry.md#spans) own further-reduced projections.

Replay accepts recorded decisions without reevaluating the Supervisor, executing any historical action or reading configuration. It validates the closed payload, supported evaluator, pinned Supervisor, Run and actor scope, adjacent subject and site, evidence shape, cap and cap marker; malformed, duplicate or misplaced verdicts reject. A well-formed, correctly placed forged verdict is accepted even when the evaluator would differ, and replay never infers a missing verdict. An interrupted prefix ending right after a subject stays valid; recovery starts fresh windows in a new Run. A changed feature definition needs a new evaluator version; threshold changes stay pinned data. Replay does not prove evaluator provenance, and the journal is not tamper evidence. No verdict grants authority.

`arany show --output supervisor-corpus SESSION_ID` exports a local calibration corpus after strict read-only replay. It takes the Session lock nonblockingly for the whole read, refuses an active operation or an absent or unsafe lock, and creates no lock files or journal changes. It opens no Workspace, reads no credentials or runtime configuration, and makes no Provider, Tool, hook or Guard call. Fork references and inherited history get the same strict validation; records describe the selected Session's own boundaries. Interrupted closed prefixes are valid; invalid history emits no corpus.

Stdout is JSONL: one header, then one record for every evaluation boundary, including negatives and boundaries after the verdict cap. The header has `format: "arany.supervisor.corpus.v1"`, `evaluator: 1`, `session_ordinal: 1`, `runs` and `goals`. Each Run entry has a one-based `run_ordinal`, closed `outcome` (`completed|failed|cancelled|stopped_by_hook|interrupted`, unfinished prefixes `interrupted`) and nullable `policy` with its pinned evaluator, window, floors and candidates, without the digest. Goal entries have a one-based `goal_ordinal`, `run_ordinals` and `outcome: completed|failed|interrupted|budget_exhausted`.

Each record has `run_ordinal`, the journal's zero-based `actor_ordinal`, closed `role`, `site`, nullable catalog `operation`, nullable `disposition_class` and closed enforcement `cause_class`, `features: {loop, probing, disproportion}`, nullable `journaled_level`, `salted_call_key`, `salted_outcome_key`, one-based `relative_step` and `labels`. Features are recomputed over the same actor window; disproportion is null outside capture sites, and operation, disposition and cause are null outside Tool observations. `relative_step` counts all boundaries of the Run in journal order. `journaled_level` is the greatest level in the matching committed verdict, or null when none was committed. Labels are booleans `pause_or_cancel`, `steering` and `goal_failed`, set when the committed cancellation, steering note or failed Goal follows within three subsequent boundaries of the same Run (including immediately after the subject). The journal cannot distinguish a user pause from Ctrl+C, so the combined label makes no such inference; crash interruption is not a cancellation label.

Corpus privacy is an allowlist: only the fields above are serialized, with no objectives, paths, argv, file content, model text, UUIDs, timestamps, account data, raw hashes or policy digests. Call and outcome keys are HMAC-SHA-256 of the evaluator's normalized keys, with separate corpus domains and a fresh random 32-byte secret salt per export that is never exported or persisted. Keys are equal within one export and unlinkable across exports; ordering, ordinals and feature patterns stay observable, so the corpus is privacy-reduced, not anonymous. Nothing is uploaded; owner labels are added offline to a copy, and threshold sweeps use the feature columns without re-execution.

An export holds at most 10,000 records and 8 MiB<!-- unrelated-bound: repetition corpus export cap -->, including header and newlines, and the [lineage replay cap](./execution.md#persistence-bounds) applies first. Record or byte overflow refuses the whole export with record and byte counts, never truncating or emitting partial stdout; replay-limit refusal uses the history-limit error. Buffers and label tracking are bounded by those limits, the fixed schema and a four-boundary label window. Random-source failure fails closed. The corpus grants no enforcement authority.

Peers: [OpenHands](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/stuck_detector.py) supplies ID-free action/observation equality, four identical steps, failure streaks and alternating cycles; [Gemini CLI](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/loopDetectionService.ts) hashed calls and short cycles; [Goose](https://github.com/aaif-goose/goose/blob/main/crates/goose/src/agents/agent.rs) the pre-dispatch inspector seam; [Claude Code hooks](https://code.claude.com/docs/en/hooks) the restrict-only adapter shape. Arany journals shadow candidates before any enforcement, uses bounded per-actor windows and excludes LLM judges. Enforcement, durable pause/revoke and human-only overrides need later calibrated owner approval; this adapter applies none.

### Permission limits

[Hook execution](#hook-execution) owns hook bounds. The whole settings document is at most [64 KiB](./limits.md#max_config_bytes), with the JSON ceiling of 4096 nodes and 32 levels<!-- unrelated-bound: permission JSON nesting depth -->. There are at most 128 permission rules across the allow, deny and ask lists and `typedPrefixes`, each complete ordinary rule at most 1024 UTF-8 bytes; controls reject. Tool calls keep the serialized argument ceiling of [Tool context](#limits-and-failure-behavior), checked before typed validation without allocating in proportion to oversized input. Hostile rule text parses or errors deterministically, never panicking. Overflow rejects without partial configuration, retry or fallback, and errors name the constraint without echoing rule text.

## Private grants

Put an owner-only `tools.json` beside the admitted Session database, outside the Workspace. Its directory must be private (`0700`); the file must be regular, single-link, no-follow, current-user-owned and `0600`. `--state-dir` selects this Session and configuration root, not your saved account. Permissions are not encryption and do not protect against another process of the same user.

A minimal file-only configuration is:

```json
{
  "version": 1,
  "workspace_paths": ["src", "Cargo.toml", "Cargo.lock"],
  "write": true,
  "commands": [],
  "skills": [],
  "mcp": []
}
```

Use exact, nonoverlapping relative files or directories. The singleton `["."]` selects the whole project under the same exclusions and bounds; mixing `"."` with other roots rejects. List, search and command working directories accept `"."` or an empty path for the root; mutations require a named relative path. Absolute paths, traversal, links, mount crossings and special files are refused. StateRoot and the fixed account root must not overlap the Workspace or configured runtime resources. `.git`, `.env`/`.env.*`, `.aws`, `.ssh`, `.gnupg`, `.npmrc` and `.pypirc` path components are excluded. Repository history is reachable only through [typed Git reads](#typed-git-reads). This is not a secret detector: review the files you select. Tool observations can reach the selected Provider and the private, unencrypted journal.

The Linux profile exposes the system `/usr` tree read-only as its runtime. Workspace, StateRoot and account roots must not overlap it, because a private file inside a runtime mount stays visible to a same-user payload. No home or unselected cache is mounted.

Without a [network grant](#network-grants-and-egress-proxy), offline profiles deny network, named Unix socket creation, connect, bind, listen and destination-bearing sends; a network namespace alone would leave pathname sockets reachable. Anonymous pipes and socket pairs stay usable, but Linux pairs cannot reach named destinations and macOS denies pair writes. `sendmsg`/`sendmmsg` descriptor passing is unsupported.

The JSON schema is closed and versioned. All six listed top-level fields are required. Optional fields: `network` is the [egress grant](#network-grants-and-egress-proxy); an `mcp` entry may be a Linux-only [remote server](#remote-mcp-and-oauth); `web_search` `{endpoint, key}` declares the [search backend](#web-fetch-and-web-search); `git` pins [typed Git reads](#typed-git-reads); `git_identity` `{name, email}` is the [commit identity](#typed-git-writes); `child_unguarded` accepts only `denied`, and children never receive [host authority](#primary-host-commands). Unknown and duplicate fields reject. There is no interpolation, automatic installation or hidden executable lookup. Project Skill discovery stays within the selected Workspace roots. Folder trust pins the resolved system shell rather than searching PATH. Configuration is pinned for a Run; editing it does not cancel an admitted Run. Changed pinned executable or resource contents reject dispatch.

## Enforcement failure causes

`ToolFinished` and `HookFinished` record an optional closed `enforcement_cause`, separate from the disposition and untrusted output:

- `filesystem_denied`: the typed file boundary or command snapshot capture rejected a protected path component or set-ID entry metadata, including in ignored outputs. It requires an execution attestation and a `denied` disposition.
- `guard_bootstrap`: the trusted controller observed a typed Guard bootstrap error at the NamespaceEntry, RuntimeMounts, Capabilities or Handshake stage before GO. It requires `failed`, no execution attestation and a Guard-site intent. A Linux or macOS mount-topology refusal before Ready and GO is this cause.

A `guard_bootstrap` failure is known pre-dispatch, so the next model request may receive it; this grants no authority and retries nothing. Once GO begins, a missing completion stays [Uncertain](./execution.md#effect-outcomes) and cannot use this exception. Ordinary errno, diagnostics and program output cannot set either cause. Resource limits, cancellation, uncertainty and successes cannot claim one. Unsupported Git layouts, path validation, non-regular or multiply linked files, changeset type conversions and opaque filesystem errors stay unclassified. Classification changes no grant or approval.

The cause carries no path, filename, contents or native diagnostic text, and its size is fixed by the enum. When a cause exists, the model result and Tool summary add one diagnostic: `Guard enforcement: protected path or set-ID entry refused`, or `Guard enforcement: bootstrap failed before dispatch`. Other results keep their projection. JSONL and strict replay keep the typed field under the [current payload versions](./execution.md#admission-persistence-and-recovery).

Only snapshot-capture refusals and typed bootstrap failures are attributed. Linux Bubblewrap startup failures, namespace-hidden paths, read-only mounts and seccomp errno (`EPERM`, `ENOSYS` for `clone3`) have no trusted denial channel, and no Landlock or audit channel is used. macOS Seatbelt violations have no trusted invocation-correlated channel. Errno, stderr, exit status, signals, blocked sockets and system sandbox reports never establish Guard causation. `null` means no attributable cause, not proof that enforcement was uninvolved; no network or process cause is claimed. This applies to commands, Skill scripts and local MCP servers, whose `isError`, cause fields and text stay program data. In-process File effects have no pre-GO stage, so `guard_bootstrap` is invalid for them.

This mirrors Claude Code's [sandbox runtime](https://github.com/anthropic-experimental/sandbox-runtime/blob/main/src/sandbox/sandbox-manager.ts) diagnostic and Codex CLI's [`SandboxErr::Denied`](https://github.com/openai/codex/blob/main/codex-rs/core/src/exec.rs), but not Codex's `is_likely_sandbox_denied` output heuristic, because hostile output must never attest enforcement.

## Primary host commands

`command` stays guarded. The primary may request `command_unguarded` with a bounded justification at any time, including after a Guard failure. This follows Codex's explicit `require_escalated` request, but keeps human authorization, journal-first execution and primary-only authority. Host execution is never an automatic fallback from the Guard and is never retried. Host requests need no Guard image and stay available when missing protection removes guarded commands from the catalog; each guarded dispatch rechecks availability before spawning. Children, workers and hook outputs never receive host authority or inherit host approvals. A failed hook stays Ignored and produces no host proposal or escape-only Stop/PreCompact continuation.

Repository content, model text, hooks, AI review, Tool output, MCP metadata or output, Skill text, child reports and ACP client policy never authorize host execution. Only a human approval or an admitted user-owned rule does. Approval does not make the process trustworthy or isolated.

**Admission.** Program, explicit argv and Workspace-relative cwd form a fresh immutable intent. Absolute targets belong in argv; cwd opens beneath the Workspace without following links. Programs resolve only through absolute PATH entries outside the Workspace, and an absolute program must canonicalize to the same executable as that lookup. The absolute executable, filesystem identity, digest, Workspace, environment policy and permission snapshot are pinned before approval and rechecked before dispatch. Native executables have the [32 MiB](./limits.md#max_snapshot_bytes) program bound. Scripts require an explicitly pinned interpreter. The closed interpreter-name set is `awk`, `gawk`, `mawk`, `nawk`, `sed`, `sh`, `bash`, `dash`, `zsh`, `ksh`, `mksh`, `fish`, `csh`, `tcsh`, `python`, `python2`, `python3`, `pypy`, `pypy3`, `node`, `nodejs`, `deno`, `bun`, `perl`, `ruby`, `php`, `lua`, `luajit`, `tclsh`, `wish`, `pwsh` and `powershell`, plus the BusyBox and ToyBox launchers. A requested or resolved interpreter needs a matching `tools.json` command marked `interpreter: true`; otherwise admission refuses with a distinct interpreter error. Wrapper arguments that name or resolve to an interpreter need their own matching pin; a wrapper pin cannot admit a nested interpreter. These checks repeat before dispatch. Versioned interpreters are identified only by explicit declarations, not a numeric-suffix heuristic. Guard-only paths and variables are refused. Model text cannot select actor, trust or approval provenance.

**Privilege tools.** The closed first-token policy prohibits `sudo`, `sudoedit`, `doas`, `su`, `pkexec`, `run0`, `runuser`, `chroot`, `systemd-run`, `machinectl`, `pfexec`, `ksu`, `dzdo` and `authopen`, by requested and resolved basename. `osascript` is refused when any argument contains “with administrator privileges” (ASCII case-insensitive). The closed wrapper/launcher set is `env`, `xargs`, `find`, `nice`, `ionice`, `timeout`, `nohup`, `setsid`, `time`, `busybox`, `toybox`, `stdbuf`, `chrt`, `taskset`, `flock`, `command`, `exec`, `strace`, `ltrace`, `nsenter`, `unshare`, `setpriv`, `script`, `watch`, `eatmydata`, `runcon`, `capsh`, `firejail` and `bwrap`. Wrapper argv naming a privilege tool refuses, including nested launchers. `env -S` and `--split-string` refuse outright. During live admission and dispatch, path-like wrapper arguments and attached option values are canonicalized against the cwd and refused if they name a privilege tool or match the identity of one found through admitted PATH; replay does not repeat these filesystem checks. Shell, interpreter and wrapper argv is tokenized conservatively on whitespace, quotes and shell metacharacters (`;`, `&`, `|`, parentheses, backticks, `$`, redirection and `=`); any privilege-tool token refuses. Inline options (`-c`, `-e`, `-Command`, `--eval`, `--execute` and similar) trigger this scan for any executable. The scan reads literal strings without evaluation, including nested inline commands and quoted data; false positives are deliberate. It is not a security boundary: inline programs beyond this check, file scripts, obfuscation and configuration stay uninspected.

Refusal precedes any approval offer and is rechecked before dispatch. No mode, reply, rule or cached grant overrides it, so privilege-escalation commands cannot be approved. The durable result says “Arany cannot run privilege-escalation commands. Please run this command by hand:” with the exact argv and Workspace-relative cwd as bounded JSON-quoted data. The primary must explicitly ask the user to run it and must never evade refusal through wrappers, shells or children.

**Authority.** Attached human choices are `Yes` (once), `Yes, for this session` (the identical command in this live Session), `Yes, and allow this host prefix in this folder from the next Run` (an eligible proposal) and `No`. Each Run pins an opaque Engine-generated epoch. A session grant is journaled with the approving human verdict; reuse commits a new verdict referencing that earlier human intent in the same epoch. Reuse requires the same executable path, identity and digest, argv, cwd and Workspace, environment policy and settings, with no greater limits. At most 128 grants are reusable per epoch; `Yes` stays available when full. Session approval is offered only where reuse is eligible: rule-based asks, hook restrictions and literal StateRoot/account-root targets offer once only. Resume, restart, reconnect, fork, opening rewind and `/permissions` end reuse. Failed permission readmission denies host authority until a successful explicit readmission; the attached session shows a recoverable notice and keeps an already saved folder-trust change.

The Engine creates a fresh epoch on attachment, restart and reconnection and journals it in Runs and verdicts. The reducer validates epoch changes, resume/fork boundaries and prior-human references, but cannot detect a restart that wrongly reused an epoch. Live terminal mode is an Engine restriction; replay validates only the recorded settings mode and verdict.

Explicit ask/deny and hooks only narrow. Generic host commands count as mutating and are refused in plan mode. `default` and `dontAsk` may reuse eligible session grants. `auto` and `acceptEdits` always require a fresh human approval, never AI review. Exec and ACP use only [remembered host prefixes](#remembered-host-prefixes). Without a human channel, a generic host command runs only under an eligible remembered rule; any other request refuses immediately with a durable explanation. This follows [Codex headless policy](https://github.com/openai/codex/blob/61f34c35af77777db4d77d0ea2aeb8547a6b4523/codex-rs/exec/src/lib.rs#L586-L601) and [Claude preapproval](https://code.claude.com/docs/en/headless#auto-approve-tools). No human-attestation protocol or bypass mode exists. Serve offers once and negotiated exact-session scope only; unsupported scopes refuse rather than downgrade to once. These surfaces cannot create rules. Typed push and PR create always need a fresh human; typed PR reads keep their own [typed-rule authority](#human-approved-host-git). An approved generic host command can still perform Git and remote effects; typed-operation guarantees cover only typed operations.

**Legacy rules file.** An inactive `unguarded-commands.json` is archived byte-for-byte to `archive/inactive-host-commands/unguarded-commands.json`, with a bounded notice naming the archive and requiring fresh authority. Private-file admission and size bounds apply even to malformed contents. The archive is durable before its pending marker is published and the source moves; the marker is removed last. An unconfirmed archive stays blocked across reopen, without retry or automatic completion. A recreated source beside an archive is a conflict and is never overwritten or deleted. Unconfirmed and conflicting archives have distinct admission errors naming the directory. Recovery is manual: stop Arany, keep source and archive intact, and restore a verified backup or get operator help; never remove a pending marker or overwrite a conflicting copy. No entry becomes authority, and no exact-rule reader or writer takes part in dispatch.

**Review and disclosure.** Review shows the pinned program, every argument, the real cwd and the model justification as escaped data. The prompt says that inline programs are opaque beyond the lexical privilege-tool check, file scripts and obfuscation are uninspected, and children have no controlling terminal for privilege prompts. It warns that the process runs as the user with file and network access, can execute repository configuration, modify Arany permissions, Store and journal, and disclose private data to the Provider. Lexical `.env`/`.env.*`, `.ssh`, `.aws`, `.gnupg`, StateRoot and account-root paths add a warning. Rule-matched or cached non-human dispatch refuses argv that lexically names the StateRoot or account root, including embedded absolute paths and relative tokens normalized against cwd; this check misses computed paths and aliases and is not an isolation boundary.

Live permission settings are compared with the admitted digest before any approval offer and before dispatch. Out-of-band changes refuse with a settings-change explanation until human readmission through `/permissions`; drift during an approval still refuses dispatch. Saving a human-approved typed Git rule advances the settings pin only to the exact bytes written from the expected prior digest and never clears an existing settings-change lockout; later host requests in that Run refuse before offering approval. Executables are invoked by path after digest and identity validation, spawn re-resolves cwd after its check, and wrapper target checks race replacement before the wrapper opens the path; same-user replacement in these windows is not prevented. Pins are admission evidence, not execution isolation. Arany refuses to treat host writes as approvals, but same-user tampering with its state or journal is neither prevented nor reliably detectable.

**Execution.** Intent, verdict, scope and dispatch authority commit before spawn. The Store tail, Goal action-time reservation and Workspace writer lease apply. The supervisor uses explicit argv, empty stdin and a cleared allowlisted environment: the pinned command environment record's `PATH` and selected names (a core set by default; names matching `*KEY*`, `*SECRET*` or `*TOKEN*` are never selectable), real HOME and TMPDIR, NO_COLOR, ARANY_TOOL_WORKSPACE and ARANY_UNGUARDED. The command starts in a new OS session with no controlling terminal or terminal-scoped privilege ticket; launcher failure runs no payload. The finite command timeout, rendered output bound and 1 GiB<!-- unrelated-bound: command output kill ceiling --> per-stream kill ceiling apply. Timeout or output overflow with confirmed teardown is Limit, confirmed cancellation is Cancelled, and a known nonzero exit is Failed. Lost acknowledgement or unconfirmed leader/group termination is [Uncertain](./execution.md#effect-outcomes). Process-group supervision does not contain deliberately detached descendants or confine host filesystem, network, CPU or memory.

**Login-shell capture.** The command environment record comes from the process environment or, on an explicit `/permissions` Capture from login shell or Re-capture action, from the user's login shell. Each capture needs fresh human approval of the pinned executable and home directory. The shell comes from `getpwuid_r`, never `$SHELL`, and must be `zsh`, `bash` or `sh`. It runs once on the host as `-lc 'env -0'` with cwd `$HOME`, the pinned record as initial environment, the [capture runtime bound](./limits.md#login_shell_capture_timeout_ms) and a [capture output cap](./limits.md#login_shell_capture_output_bytes) on combined output. Codex and Claude Code run login shells per command or session; Arany never runs one inside the Guard or from model text. Only selected non-secret names and PATH replace the private record; shell identity and source are shown with values hidden. Requests, verdicts, digests and outcomes are journaled as host operations; captured values never enter Events. Non-zero exit, confirmed timeout or overflow, malformed output and pin drift leave the record unchanged. An unknown process or save outcome is [Uncertain](./execution.md#effect-outcomes); an interrupted capture is reported unknown after reopen. The captured digest commits before replacement, and replacement refuses concurrent editor drift. Re-capture is a new human action, never recovery. Startup reports when process PATH differs from the record. Login files run with the user's authority.

**Receipts and recovery.** Host commands produce only an UnguardedReceipt, never a Guard receipt, changeset or cache publication. They are excluded from automatic rewind. Approval without a terminal outcome is a possible non-rewindable effect, and recovery never redispatches it. Host dispatch invalidates earlier file-success and worker-verification evidence. Every projection marks host effects, keeps partial output and claims no complete inventory, rollback or rewind. Replay validates committed authority, references and bounds without reading settings or executing anything. [Execution](./execution.md#admission-persistence-and-recovery) owns migrations and [Session](./session.md#rewind-planning-and-replay) owns rewind.

### Remembered host prefixes

The optional `command_unguarded.prefix_rule` is a literal argv token prefix including the executable spelling. A model proposal needs at least two tokens and must prefix the actual request; absent or null means none. Only attached human approval and idle `/permissions` create rules; serve, ACP, exec, children and hooks cannot. The prompt shows the complete escaped token sequence and warns that every eligible suffix becomes authorized host behavior, not confinement. Saving approves the pending action once; the rule applies from the next Run.

Private `permissions.hostPrefixes` is separate from `typedPrefixes`. Each closed version-1 record binds the literal prefix, an allow/ask/deny decision, the exact relative cwd, Workspace path/device/inode, resolved executable path/device/inode/digest and PATH/environment-policy identity. It keeps the admitted state-root scope and carries no live settings-digest authority. The list is empty by default and shares the [permission settings bounds](#typed-prefix-rules). Inserting a rule also caps the compact JSON host-prefix array at 32 KiB<!-- unrelated-bound: host prefix array cap -->, reserving half the Event payload budget for other Run facts; overflow returns Invalid without replacing settings or dispatching the pending command. Larger existing lists stay readable, editable and removable, and Run admission still checks the complete payload. Unknown versions, malformed or duplicate records and overflow reject the list as a whole. Settings without this list keep their bytes; legacy exact rules are archived, never converted.

Cannot be remembered: every privilege tool, wrapper/launcher and interpreter from the policy above, and generic `git`, `gh` and `rm`, by requested and resolved basename. A declared interpreter or typed Git/gh pin also excludes matching resolved paths, identities or digests, including renamed or versioned copies. Interpreter/script forms, inline program options, heredocs, here-strings and tokens with shell control syntax cannot be remembered. These checks run at creation, settings admission and dispatch. A saved rule that conflicts with a declared pin refuses Tool admission with an error naming its one-based entry and pointing to `/permissions` → Host command rules; the settings stay editable without admitting it. This closed policy is not executable classification or confinement: unknown programs may run other programs. Privilege tools stay prohibited under every scope.

Matching is exact literal argv-prefix matching, with no globbing, shell splitting, substitution, alias matching or wrapper stripping. Deny/ask rules, host rules, hooks, grants, budgets, cancellation and plan restrictions still narrow. Remembered prefixes apply only in `default`/`dontAsk` and in eligible exec: there, with live Request approvals or no human channel, an eligible allow records `host_prefix_rule` and dispatches without a prompt. Serve and ACP may reuse admitted rules under the same restrictions. `auto` and `acceptEdits`, including live terminal modes, require a fresh human and ignore prefix and session allows. A rule never applies to a child or a typed Git operation. Non-human dispatch refuses lexical StateRoot/account-root targets; a fresh human may approve an otherwise eligible action. Settings drift refuses until readmission.

The editor reuses the account replacement lock, expected whole-file digest, Workspace identity check, complete validation and atomic replacement. A missing file may be created with default mode, with a warning that this activates policy for other Tools too. The human save verdict, including the proposed record, commits before saving. A failed save dispatches nothing; an unconfirmed replacement is [Uncertain](./execution.md#effect-outcomes). The Run snapshot stays immutable: the confirmed self-save digest stays admitted for the rest of the Run, and the new rule gives no current-Run authority. Revocation applies from the next Run; cancellation withdraws pending authority at once. Run admission pins scoped host records beside the settings digest; replay requires membership in that snapshot and no matching deny/ask record, and never reads current settings.

`/permissions` lists, changes and removes host decisions. It can derive a prefix from a recent eligible command in the conversation after revalidating its executable and Workspace pins. Only this editor may choose a single executable token, with a warning that every eligible argument is covered. There is no user-wide host scope.

## Commands

Native Tool decoding strips leading `./` segments and one trailing `/` from directory arguments (`list`, `search`, `glob` and command `cwd`), matching Claude Code and Codex. File arguments keep a trailing `/` and fail validation. This lexical step precedes validation, permission subjects, intent hashing and Guard pins, with no filesystem lookup, traversal collapse or home expansion; absolute `/` stays absolute. The result must be canonical and Workspace-relative: at most 512 UTF-8 bytes, normal components separated by single `/`, and no absolute path, traversal, `.` component, trailing separator, backslash, control character or excluded private component. Directory arguments also accept `.` or the empty string for the root. A doubled trailing separator stays invalid. Command argv has at most 64 NUL-free strings of at most 4,096 bytes<!-- unrelated-bound: command argv element --> each, within the aggregate [argument ceiling](#limits-and-failure-behavior). Refusals use [correlated argument feedback](./execution.md#accepted-outcomes), so a spelling error grants nothing and can be corrected within the Goal budget.

Command project copies exclude `.git`, and the command description points to typed Git reads when cataloged. When `git_status`, `git_diff` and `git_log` are available, a nonzero exit whose kept stderr contains `not a git repository` gets a fixed `hint` in the model result, unless it would push the result above the [per-call result ceiling](#limits-and-failure-behavior).

Each `commands` entry declares a reviewed executable, its SHA-256, whether it is an interpreter and any extra pinned input files:

```json
{
  "name": "bash",
  "executable": "/usr/bin/bash",
  "sha256": "REPLACE_WITH_THE_64_CHARACTER_LOWERCASE_SHA256",
  "interpreter": true,
  "inputs": []
}
```

The placeholder is deliberately invalid; compute the real path and digest yourself (`readlink -f`, `sha256sum` or `shasum -a 256`). The executable must be a no-follow, regular, single-link native binary (ELF on Linux, Mach-O on macOS); replace a symlink with its resolved path. The optional `git` pin differs: it must lie under `/usr`, be root-owned, non-set-ID and not group- or world-writable, may have several hard links (distributions hard-link `git-core`), and runs in place from the read-only `/usr` mount because its shared libraries load from `/usr`. Updating an executable requires changing its pin.

Extra inputs use `{"path":"/absolute/reviewed/file","destination":"relative/name","sha256":"<digest>"}` and appear read-only under `/inputs/PROGRAM_ID/relative/name`. Executables are copied to `/programs/PROGRAM_ID`, except checked immutable macOS system programs, which keep their paths. Paths and digests are rechecked for each invocation. Allowing a shell or interpreter authorizes its behavior, including descendants using the admitted runtime, inside the same OS-enforced boundary; the `interpreter` flag proves nothing about arguments or scripts.
## Persistent Workspace build cache

Commands receive an explicit argument array, a relative working directory, a cleared environment, private `HOME`, temporary and Cargo directories, no terminal input and bounded lossy UTF-8 output. The model-facing contract states this environment: `PATH` is the selected toolchain `bin` directories followed by `/usr/bin:/bin`, the pinned shell accepts only `-c SCRIPT`, and user-installed tools outside the Guard are reachable only through a primary host command. Locale names from the pinned command environment record are the only host values carried. Project selection runs inside the command's own timeout, as Codex CLI and Claude Code bound a command only by its tool timeout; control-file caps still apply. With the build cache enabled, `CARGO_HOME`, `CARGO_TARGET_DIR`, `npm_config_cache` and `PIP_CACHE_DIR` point into the admitted cache view (`/cache` on Linux, the cache volume on macOS); otherwise into private scratch. Toolchain subtrees are executable throughout; selected `bin` paths extend `PATH` in grant order, and a selected host cache replaces only its nested cache path. Each snapshot is a fresh writable copy of the selected paths, including prior edits and integrated changes; empty directories and executable bits survive, set-ID bits do not.

Selected Rust commands receive `CARGO_ENCODED_RUSTFLAGS=--cfg\x1farany_guard` (separator byte `0x1f`), which replaces lower-precedence Rust flags and enables only inventoried conditional ignores, never `arany_ci`. Build also receives `CARGO_NET_OFFLINE=true` and `CARGO_BUILD_JOBS` from the digest-bound `intent.limits.build_jobs` ([Goal admission](./goals.md#lifecycle-budgets-and-recovery) owns its bounds); jobs cap neither test threads nor CPU. The payload can override these within its limits; they prove no isolation. The [decision register](../research/next-step-decision-register.md#d-27--selected-rust-and-honest-guard-only-test-omissions) owns the peer choice.

An offline registry-backed build needs each archive, source and index subtree selected, plus the compiler and SDK on macOS. Missing inputs and unselected tools are ordinary command failures, with no discovery, installation, extra mount, network retry or host rerun. Repository toolchain files and configuration are computation inputs only. Guarded Cargo output keeps actual passed, failed and ignored counts. IPC-dependent tests use `cfg_attr(arany_guard, ignore = "requires local test IPC")`; forcing them keeps socket denial. A compile-only command can publish a cache but is not executed-test evidence.

Each Workspace has one cache identity keyed by canonical path, device and inode; at most 128 identities are retained. A nonblocking exclusive identity lease covers primary and editor command restore, collection, publication and clear; competing operations return busy rather than wait. No shared-read lease or pinned generation exists; editor command admission follows [Editor Tool steps](#editor-tool-steps). Store accepts only allowlisted cache roots and rejects symlinks, special files, set-ID inputs, malformed paths, identity drift and unknown archive data. Only success, or a Guard-attested primary or editor Build timeout with an empty Workspace changeset, may publish; other failures, cancellation, resource or output limits and uncertain cleanup keep the prior cache.

**Linux directory cache.** Primary and editor Commands in both `default` and `build` classes use one directory-backed cache overlay under the identity lease. The supervisor receives only the pinned cache-directory identity, clones it read-only and mounts a sized, inode-bounded tmpfs upper at `/cache`; payload Tasks never carry a `StateRoot` path or handle. A durable cache record pins the Guard reservation before launch; admission and clear first recover that exact abandoned reservation, and unconfirmed teardown keeps record and reservation and refuses lower mutation. A live controller stays busy. Read-only host-cache subtrees mounted in the view are excluded from publication. Lower bytes and bounded upper and publication headroom are admitted before GO; insufficient reservation or an over-limit lower refuses dispatch. Application waits for supervisor exit, reap, output EOF and positive unit cleanup; missing handoff or cleanup evidence after GO is [Uncertain](./execution.md#effect-outcomes).

Capture reuses the overlay whiteout and `opaque=y` classifier under the cache root, entry, path and streaming byte bounds. Safe output outside the cache roots, such as Cargo lock files and npm logs, is validated and discarded. Safe regular-file hard links copy as independent files; links, set-ID, unsupported private metadata and special objects refuse capture. Quota rejection precedes lower mutation. Before in-place application, Store durably marks the cache unavailable; only synchronized content, ancestors and directory publication readmit it. An interrupted apply, failed sync or uncertain publication leaves it unavailable until `/cache clear`; archive rollback does not repair a mutated directory. Changes apply in place through pinned directory handles, without archive candidates, staging or generation transfer. Switching between default and Build reuses the directory under the newly pinned allowance. An old archive or stamped generation is converted under the lease: restore the validated archive, sync the directory, then remove the archive and stamp before reuse; interruption leaves it unavailable until clear.

**macOS archive cache.** macOS restores archives as fresh single-link regular files with executable bits into a separate quota-backed view and never creates links. Archives store regular files by content regardless of link count, so Cargo hard links restore as independent files. After positive cleanup, the Guard streams a bounded candidate to Store, which commits it beside the previous archive with a rollback intent; the synced commit marker is the commit point, and earlier failure rolls back. A failed marker write or sync keeps both archives and blocks cache admission until recovery succeeds or `/cache clear`. Recovery keeps a valid committed archive and otherwise restores a valid previous one. Malformed or unsafe records fail closed and stay for diagnosis.

**Outcome.** The controller records a typed `cache_update` beside the observation, command result and Guard receipt:

| Value | Meaning |
|---|---|
| `published` | Candidate committed |
| `rejected` | Known size or quota rejection kept the prior cache |
| `failed` | Validation, staging, write, sync, reopen or known publication failure kept the prior cache |
| `uncertain` | Outcome unconfirmed; [Uncertain](./execution.md#effect-outcomes) stops the Run |
| `not_attempted` | Guard error after dispatch, or a failed command that did not publish |
| `not_applicable` | No private cache, including a synthetic Limit without a Guard report |

Published, rejected and failed require the eligibility above; success cannot commit `not_attempted`. The update keeps the disposition and cause, including `Limit(timeout)`; a later explicit command may reuse a validated timeout cache. Cache data is never executable authority or automatic Provider context; output that discloses it is ordinary bounded observation. Background jobs do not survive a call. This finite profile does not establish support for every large Rust, Node or Python build.

The cache result is separate from command success. Text receipts surface rejected, failed and uncertain updates; JSONL and replay keep the full observation. The class, user settings and checked headroom set each invocation's view limit. The [8 GiB](./limits.md#max_build_cache_bytes) setting is a requested maximum, not usable capacity: committed directories and archives, metadata, reservations, uppers, candidates and staging all count toward the [8 GiB](./limits.md#aggregate_bytes) StateRoot aggregate, and candidate and view are capped by remaining headroom. Nothing is evicted automatically. Raising the setting raises no other bound.

`/cache clear` removes the current Workspace cache, including unavailable directory data, and shows `Cleared this Workspace's private build cache`; `/cache clear all` reclaims all committed caches and shows `Cleared all private build caches`. A busy clear shows `Build cache is in use; retry after its command finishes` and keeps the cache. Malformed input shows `Error: Usage: /cache clear [all]`; other failures show `Error: private build cache could not be cleared`.

## Network grants and egress proxy

A reviewed `tools.json` may carry `"network": {"allow": [...]}`. A pattern is an exact lowercase ASCII host with at least two labels, one leading `*.` label matching subdomains only (the apex stays unlisted and at least two labels must follow), or a numeric loopback address. Other IP literals, ports, schemes, uppercase, trailing dots, bare TLDs, unknown or duplicate fields, duplicate patterns and more than [`MAX_NETWORK_PATTERNS`](limits.md#max_network_patterns) patterns reject. Absent means no grant.

The effective domain set is the grant plus `Network(domain:x)` [allow rules](#permission-rules) in `permissions.json`; deny and ask rules remove matching hosts, because a running command cannot pause for approval. A rule never creates a grant, and each rule list carries at most [`MAX_NETWORK_PATTERNS`](limits.md#max_network_patterns) domain rules. The effective set joins the pinned configuration digest in `RunStarted`. `/permissions` > Network domains lists these rules, adds one from a host refused earlier in the conversation, and changes or removes them; edits apply from the next Run and rewrite only `Network(domain:…)` strings.

Only a primary guarded Command with a grant, a primary [remote MCP](#remote-mcp-and-oauth) call and admitted primary or researcher [`web_fetch` and `web_search`](#web-fetch-and-web-search) carry `limits.network = proxy`. Every other Tool, including child Commands, editors, local MCP, Skill scripts and interactive or background jobs, keeps `none`; the intent validator rejects `proxy` elsewhere, and the reducer rejects a child intent carrying a grant. The enforcement digest binds the proxy contract, its bounds and the routed seccomp program, so the Guard refuses a mismatched profile.

On Linux the parent starts one proxy per command on a `0600` Unix socket in the user's runtime directory, bind-mounted read-only as `/arany-egress.sock`. The payload keeps its empty network namespace. Before seccomp is installed, the Guard helper starts a bridge from the same pinned executable on `127.0.0.1:3128` inside that namespace, relaying to the socket. The payload gets `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, their lowercase forms and empty `NO_PROXY`. The routed filter admits `connect` and only `AF_INET`/`AF_INET6` sockets, with no datagram `socketpair`, so the bridge is the only route out. Failure to start proxy or bridge refuses before GO. The bridge shares the payload's PID namespace and cgroup, is not seccomp-filtered and can be killed by the payload, which costs availability, not authority; socket and bridge use one task and one file slot of the command's limits.

On macOS the controller binds one `127.0.0.1` listener on an ephemeral port per command and passes the port only in the Task, never in a journaled field. The routed Seatbelt profile adds `(allow system-socket (socket-domain AF_INET))` and `(allow network-outbound (remote ip "localhost:PORT"))`; `bind`, `listen` and descriptor delegation stay denied. The payload gets the same proxy variables. The helper attests the route with two connects the profile must refuse (the neighbouring loopback port and a documentation address) and refuses before GO if either succeeds. Any local process can reach the listener, which grants only the effective set under the same bounds. Proxy and connections close after the coalition is empty.

The proxy accepts HTTP/1.1 `CONNECT host:port` and absolute-form `GET`/`POST http://…`; other methods and forms refuse. Plain HTTP is admitted only for a listed numeric loopback host and is sent upstream in origin form with `Connection: close`. The host must be in the effective set and the port must be 443, except numeric loopback hosts, which may use any port. Destinations resolve through the [Provider destination policy](./provider.md#configuration-and-egress): public addresses for names, loopback only for numeric loopback, a bounded address set per connection and no ambient proxies. TLS is never terminated or inspected. Redirects are new payload requests, checked again. A command may open at most [`MAX_NETWORK_CONNECTIONS`](limits.md#max_network_connections) connections and move at most [`MAX_NETWORK_BYTES`](limits.md#max_network_bytes) each way; a connection idle for [`NETWORK_IDLE_MS`](limits.md#network_idle_ms) without a read or completed write closes, including one stalled on a non-reading peer. Overflow closes the connection with a `limit` row. Connection tasks are capped at twice the connection limit, including tasks awaiting reaping; an arrival at capacity, or a bridge relay overflow, is refused before any header with a `limit` row and empty host. Refusal replies are bounded.

Refusals are typed rows, never prompts. The command result gains `network_refusals`, omitted when empty: a few `{host, reason, count}` rows with reason `unlisted`, `unsupported` (other method or form, disallowed port, or plain HTTP to a domain), `destination` (resolution or address admission failed), `limit` or `proxy_unavailable`. Only hostname characters survive in `host`, others become `?`; rows are untrusted data. The result budget, including the overlay merge, reserves space for them; a result that cannot hold them fails the call rather than dropping rows. A proxy that stops mid-command yields connection failures and a `proxy_unavailable` row; the disposition still follows the exit. The model catalog gains a `network` entry with the domains and one contract sentence only when a grant exists. The effect settles only after the proxy and every connection close. Replay never contacts the network.

Non-claims: allowed hosts remain exfiltration channels, TLS content is invisible to the proxy, tools that ignore proxy variables cannot connect (no transparent redirection), and Build commands keep Cargo offline.

### Web fetch and web search

`web_fetch {url}` and `web_search {query}` run in the Guard helper with `limits.network = proxy`, an empty network namespace and the routed seccomp program. Linux offers them to the primary; `web_search` only when configured. `child_web: true` in `tools.json` offers them to read-only researchers under the pinned Tool policy: a researcher fetch must match the parent's effective domain set with deny precedence and cannot ask to widen it, and researcher search reaches only the configured backend. Agent definitions can narrow further. Editors and macOS never get them; a configured grant fails closed there. Neither is a Goal success call or plan prelude; a plan contract admits them without a path or command binding. A call cancelled with confirmed teardown is `Cancelled`; any other error after dispatch, or unconfirmed teardown, is [Uncertain](./execution.md#effect-outcomes).

`web_fetch` follows Claude Code's per-domain WebFetch prompt. The URL is at most [`MAX_URL_BYTES`](limits.md#max_url_bytes), HTTPS on the default port (numeric loopback may use HTTP and any port), with no credentials or fragment. A host in the [effective domain set](#network-grants-and-egress-proxy) runs without a prompt. Any other host asks on every call unless an explicit `WebFetch` allow rule skips the prompt; `dontAsk` denies it, and a deny-listed host refuses in every mode. An approved host joins only that call's proxy grant, with deny precedence. The Guard sends one GET with no redirects (a 3xx is a typed error), no compression and the proxy's address admission. It trusts the host CA bundle (`SSL_CERT_FILE`, then the usual distribution paths) bound read-only as `/arany-ca.pem`; a missing bundle fails an HTTPS fetch before any request. The body is read up to [`WEB_DOWNLOAD_BYTES`](limits.md#web_download_bytes). `text/html` and `application/xhtml+xml` reduce to text with a bounded extractor that drops head, script, style and comments, breaks lines at block tags, decodes entities and collapses whitespace; nothing executes. Other `text/*` and `application/json` pass as UTF-8 with invalid bytes replaced; other types are errors. Text is cut at [`WEB_FETCH_CHARS`](limits.md#web_fetch_chars) characters and again to the result budget, each cut ending with `[web_fetch truncated]` and `truncated: true`. The result is `{url, status, content_type, truncated, text}`; an error is `{error}` with `Failed`. A cut result carries `output_total` and, within [Output spill](#limits-and-failure-behavior) bounds, a spill reference to the full text, readable with `Read` as `spill:<ref>`. The excerpt is the committed observation; replay renders it without network access.

`web_search` needs `web_search: {endpoint, key}`: an HTTPS endpoint (numeric loopback may use HTTP) speaking the Brave Search API, and `key` naming an `ARANY_WEB_SEARCH_*` environment variable. The parent reads it when launching the Guard and passes it only over the private task pipe; it never enters an intent, Event, digest or Provider request. A missing or malformed value refuses the call. The search proxy grant is exactly the endpoint host, independent of `network`. A response repeating the key is refused with a generic error. Each call makes one backend request with a query of at most [`MAX_QUERY_BYTES`](limits.md#max_query_bytes) and returns up to [`WEB_SEARCH_RESULTS`](limits.md#web_search_results) `{title, url, description}` rows, each field cut at [`MAX_SEARCH_FIELD_CHARS`](limits.md#max_search_field_chars) characters, dropping rows from the end to fit the budget. At most [`MAX_SESSION_SEARCHES`](limits.md#max_session_searches) `web_search` proposals commit per Session, counting primary and researcher records across Runs; the next is refused as not offered and replay rejects a record past the limit, so the allowance survives resume and is spent before any request.

Permission rules name `WebFetch`/`web_fetch` and `WebSearch`/`web_search`. `WebFetch(domain:x)` (Claude Code syntax; exact host or one leading `*.` label) allows, asks or denies fetches by host with deny precedence. Default modes allow them like other Guard reads. Results are untrusted data. Non-claims: an allowed host or the backend receives whatever URL or query the model writes, and TLS content is visible only to the Guard process.
## Command input selection

Linux primary guarded commands read each admitted directory through a private Workspace overlay; exact file grants are read-only binds. Reads include gitignored files, dependency directories and inputs above [1 MiB](./limits.md#max_file_bytes) within directory grants; ignore rules do not limit Linux overlay reads. Changes, deletions, deduplication and candidate limits follow [Linux overlay publication](#linux-overlay-publication). macOS uses the disposable-copy selection below.

### Linux overlay visibility

The supervisor inventories each read-only lower clone without dependency or ignore pruning and without following links. Protected names present at launch are masked at any depth. A protected name created or renamed into the live lower tree during execution may be visible but is never publishable; Codex and Claude Code share this limit because bubblewrap masks paths collected at launch. Masks are empty or inert and read-only. A protected symlink masks its bounded canonical target and enclosing directory; unresolved, cyclic, outside-view or unpinnable targets mask the enclosing directory. Special and set-ID entries are masked. A regular-file hard link to a protected inode found by the walk refuses launch. Ordinary symlinks and hard links stay visible; symlinks resolve only within admitted mounts.

Discovery shares the command entry, path-metadata, depth and preparation-time bounds. Unreadable or over-depth directories are masked whole. Exhausted entry, path or mask-argument space masks the enclosing subtree, up to the root, so no unscanned branch stays visible. A deadline or report/mountinfo bound that prevents installing and attesting masks refuses before GO. Masks reveal names and existence. No coherent snapshot of concurrent external lower mutation is promised. Hard-link aliases outside the grant, or to protected content in an unwalked or masked subtree, are not detected; no alias confidentiality is claimed.

The whole-root `["."]` grant uses one overlay. Narrow grants expose only their directory overlays and single-link read-only file mounts (hard-linked file grants refuse) under empty parents at `/workspace`; no ancestor or sibling tree is mounted. The parent tmpfs is read-only after setup, with a byte ceiling from the [command path-metadata allowance](./limits.md#command_path_metadata_bytes) and an inode ceiling of grant count times [command depth](./limits.md#command_snapshot_depth) plus its root. Both namespace owners attest every grant, mask and parent mount and reject unexpected submounts. Directory uppers share one pinned project tmpfs allowance, and scan, selection and candidate budgets are aggregate across grants. The mask argument envelope ([`MASK_ARGUMENT_BYTES`](../../crates/arany/src/tools/guard/linux/overlay/masks.rs)) is bounded by grant count and path length. Root identities and no-follow admission are rechecked before GO and capture, so replacement refuses. Only ignore controls inside admitted directory grants apply. For a `src` grant, a root `.gitignore` rule `src/gen/` does not discard `src/gen/` outputs; put `/gen/` in `src/.gitignore` instead. Unlike [disposable-copy selection](#disposable-copy-selection), Linux narrow grants need no ancestor controls.

### Linux overlay publication

The launch inventory records each visible path's device, inode, size, modification and change times, type and executable bits. Complete directories establish absence for unlisted names; masked or incomplete ones never do. Frozen launch controls and fixed dependency rules select publication independently of read visibility. Nested controls in excluded directories are skipped and cannot re-include them. In the selection counts, `ignored_entries` counts inventoried ignored and dependency entries, `pruned_directories` and `oversized_inputs` are zero, and `discarded_outputs` counts safe upper entries discarded by the frozen rules, including changes to existing ignored paths. Masks and identical copy-ups count as neither.

After bwrap exit, pidfd wait and reap, the capability-free supervisor validates the whole upper through no-follow handles before reading content. It may restore owner read/search bits on mode-000 entries, never executable bits. Touched paths and their parents must match launch lower identities or recorded absence; lower metadata is checked around bounded reads, and that lower object supplies the digest-bound `before` bytes. Any mismatch rejects the whole candidate. The in-process publisher rechecks these preconditions before writing.

Safe ignored and dependency creates, edits and deletions are discarded unread, including character-device 0/0 whiteouts and `opaque=y` under ignored directories. Links, other devices, set-ID, protected paths and unsupported metadata reject even under ignored paths. Only bounded kernel `origin`, `impure`, `uuid` and directory `opaque=y` attributes are accepted; redirects, metacopy, unknown private attributes, xattr whiteouts and `opaque=x` refuse (a supported-format limit, not a claim that kernels never produce them). Other attributes, such as SELinux, POSIX ACL and user attributes, are ignored and never published. A 0/0 whiteout over a baseline regular file is a deletion with the same lower identity and digest checks as an edit. Directory whiteouts and `opaque=y` remove hidden baseline regular files and keep recreated upper files as edits or creates; an affected baseline entry that is neither a regular file nor a directory refuses with `Path`, even when ignored. Capture compares every affected baseline entry and complete directory with the current lower before and after building the candidate; new, removed or changed entries, masked descendants and incomplete inventories conflict instead of becoming deletions. Frozen ignored files stay unpublished, and inferred ignored deletions count as discarded. Empty directories produce no change; file/directory type conversions refuse.

Before retained-file, content or changeset caps apply, copy-ups with identical content and executable bit are dropped. Comparison checks lower identity around reads and shares an aggregate allowance of the project upper allowance times [`COMMAND_COMPARE_BYTES_PER_UPPER_BYTE`](./limits.md#command_compare_bytes_per_upper_byte); exceeding it refuses the candidate. Changed files, including executable-only changes and deletions, count toward the candidate caps. Entry and path-metadata budgets charge each upper entry and baseline subtree descendant once, including ignored ones. Opened lower directories must match the baseline; unknown entries, open failure or drift conflict. Subtree deletions share the changeset caps.

Storage exhaustion preserves the command's exit and output. After positive cleanup, bounded valid partial writes may publish even after ENOSPC; unsafe or over-limit candidates, conflicts, timeout and cancellation publish nothing.

During capture, after positive descendant absence, the cgroup memory ceiling is the smaller of the payload allowance and [512 MiB](./limits.md#memory_bytes) plus its verified retained `shmem` charge. Capture cannot grow those tmpfs files; other unit memory stays within [512 MiB](./limits.md#memory_bytes), and CPU and process limits return to the selection envelope. Malformed or out-of-bound accounting fails closed.

### Disposable-copy selection

macOS primary commands select disposable-copy inputs by pattern. Root and nested `.gitignore` files apply in directory order with ordered negation, case-sensitive matching and parent pruning; a descendant rule cannot reopen an excluded parent. Selection is pattern-only, includes tracked-but-ignored files and never reads the Git index. Fixed protected names, dependency-directory exclusions and the command grant dominate; negations never disclose protected names such as environment, Git and credential paths. There is no `.ignore`, `.rgignore`, parent or global ignore, Git configuration or `.git/info/exclude` discovery. An ignored control still supplies rules when its directory is reached, without becoming payload-visible.

Controls are bounded UTF-8 regular single-link files admitted through no-follow, no-mount-crossing directory handles, and must lie inside the command grant and depth. The matcher uses pinned `ignore = "=0.4.33"` (`GitignoreBuilder::new`, `add_line`, `build`, `matched`) and never walks the filesystem or reads global, parent or repository configuration. Missing controls mean no rules. Unsafe, inaccessible, oversized, non-UTF-8 or malformed required controls, replacement and resource exhaustion refuse preparation before copying; invalid data reports `Path` and exceeded bounds report `Limit`. The invocation freezes control bytes and selection; replay never loads controls. Entries are classified through their admitted parent without following links, and exclusions apply before opening. Excluded symlinks, special files and hard links are omitted; unexcluded ones refuse preparation. Output validation stays mandatory for ignored paths. Safe inputs above [1 MiB](./limits.md#max_file_bytes) are omitted unread; exactly [1 MiB](./limits.md#max_file_bytes) is admitted, and growth during a bounded read rejects rather than truncates. An omitted input is never a deletion; a replacement at an omitted path rejects capture, and publication separately checks absent-file preconditions and safe parents.

Parsing and walking run inside the native unit with a [512 MiB](./limits.md#memory_bytes) phase envelope, even for Build. macOS supervises the whole coalition during preparation and capture, keeps control data outside the payload's Seatbelt grants and captures before detaching images. Selection limits apply only in the SELECT and capture phases; other phases use the intent limits, and the inner supervisor owns payload resource outcomes. Capture CPU is not charged to the payload: after descendant absence the supervisor's CPU counter is pinned, its 15-second CPU bound counts only later work, a regressed counter is rejected, and no credit transfers to another process.

Selection and payload share one command runtime; the payload gets what remains. macOS starts it when disposable volumes are ready; earlier setup stays inside the action deadlines. Deadlines are monotonic expiries capped by the action deadline; delivery and GO never restart them. Cancellation stops an in-flight compile or match wait and keeps ownership until cleanup. The selection summary records elapsed milliseconds, or null when unavailable. Capture stays inside the completion deadline and maximum command timeout and keeps a one-second report window, shortening its work deadline as needed; insufficient time refuses capture. Capacity waiting, including recovery and the ticket lifetime, is at most 30 seconds<!-- unrelated-bound: native capacity waiting deadline -->. SELECT preserves changed-input, configuration, operation, missing-path and grant-denial errors. Resource, expansion or call overflow is `Limit(resource)`; elapsed selection time is `Limit(timeout)`. There is no unguarded fallback or retry.

Unlike the real-path mounts of Codex CLI and Claude Code, Linux overlays keep private bounded writes and launch masks, and macOS keeps disposable copies. Ignore rules select copy inputs only. Host changes still need validated changesets.

## Local storage inventory

`arany storage` and idle `/storage` show a user-local metadata report. The [terminal contract](./terminal.md#storage-report) owns invocation and channels; [credentials](./credentials.md#metadata-only-storage-inspection) owns account-root admission. It is not a model Tool or a private-file read grant. It creates no Session, Run, Event, directory, database, lock, cache or log, and invokes no Provider, credential helper, recovery, cleanup or telemetry export.

Coverage is the selected Session StateRoot, the default StateRoot and the fixed OS-user account root; `--state-dir` and `ARANY_STATE_DIR` select Session storage only. Each existing root is authenticated by private no-follow component admission, independently of payload validity; missing roots are reported absent and never created. Paths appear only for admitted owned locations; individual private file and directory names are suppressed. The Workspace is excluded by opened identity, even inside a root; a root inside the Workspace is unavailable. Nested roots and file identities count once. Build-cache and Output spill totals are separate rows, not added twice. Each admitted `spill` subtree has an `Output spill` row covering directories, output files and writer-lock metadata. The report reads no payloads, checks no journal references, takes no writer locks, changes no retention and grants no Read authority.

It aggregates file and directory counts, logical lengths and allocated bytes (`blocks × 512`, overflow-checked) through metadata-only descriptors. Private ownership, permissions and ACL admission are required. Unexpected multi-link files, symlinks, special objects, foreign owners and unowned mount crossings are excluded and make coverage partial; linked targets are never followed. Unsupported enforcement fails closed. A denied metadata open (possible for mode-000 records on macOS) excludes that record and marks its category partial, without reading content or changing permissions.

Build-cache inventory reuses the owner's record-name classification. It counts directory caches, generation, ownership and unavailable records, archives, candidates, staging, locks and reservation or transaction records without parsing them, taking leases or recovering. Pending, candidate and reservation records mark the category busy or retained and the report partial. Promised reservation capacity is not allocated usage. An unknown or unsafe cache object is excluded as partial. Complete metadata does not prove inactivity or safe reclamation.

Each category is complete, partial, absent, busy or unavailable. Metadata or root identity changes during collection make it partial. Only attributed observations enter the known subtotal. Allocated bytes do not promise reclaimable space (sparse files, compression, clones, snapshots). The result is point-in-time, not an atomic host total.

One inventory runs at a time, with no queue, retry or refresh. A shared 30-second<!-- unrelated-bound: storage inventory deadline --> cooperative deadline, 16,384 scanned entries, depth 32, 4 KiB<!-- unrelated-bound: storage inventory path --> paths, an 8 MiB<!-- unrelated-bound: storage inventory identity and path index cap --> identity/path index and the [cache-identity limit](#persistent-workspace-build-cache) bound work before allocation. Exhaustion or overflow stops that scan and marks a partial known subtotal, never an exact zero. Cancellation publishes no complete report, closes handles and cleans nothing; blocking work stays owned until it stops, and a deadline cannot interrupt a stalled syscall. Output is at most 64 KiB<!-- unrelated-bound: local storage inventory output --> with at most 128 detail rows, reserving space for summaries and an overflow marker.

Not covered: Guard backing storage and scratch, worktrees (no owned worktree registry exists; this is not a zero-size claim), unregistered StateRoots, developer checkouts, shared Cargo/npm caches, installed binaries and OS-keyring allocation. No ambient host search or prefix-based attribution occurs.

Cleanup guidance names `/cache clear` (current Workspace) and `/cache clear all` (selected StateRoot), including busy behavior, and the [historical Guard maintenance procedure](../tools.md#historical-linux-seed-maintenance). It never generates deletion or detach commands or recommends removing history, credentials or live or uncertain Guard storage.

## Command changesets

After completion and positive descendant termination, the Guard compares the private view with its input and returns a sorted changeset of created, modified and deleted regular files with digest-bound before and after bytes and executable bits; binary content is canonical base64. A nonzero exit may still return changes. A failed capture, timeout, cancellation or unconfirmed cleanup publishes nothing. Commands publish to the primary Workspace; [Editor Tool steps](#editor-tool-steps) owns the editor capability, and live editor histories reject worker-image transfer fields.

The whole output tree, including ignored directories, is structurally validated before content is read. For disposable copies, baseline membership wins over frozen ignore rules; Linux overlays also discard changes to existing ignored paths. Payload edits to controls affect only the next invocation. Ignored outputs are discarded unread. Oversized changed outputs or enlarged baseline files reject capture. The command result has a required `selection` field: `{ignored_entries, pruned_directories, oversized_inputs, discarded_outputs}`, or `null` when counts were not observed, shown as `selection counts unavailable`, never zero. Counts cover observed entries, inferred deletions and pruned roots, never uninventoried descendants, and carry no paths or content. Links (including hard links), special files other than supported Linux whiteouts, set-ID bits, protected, out-of-grant or invalid paths, mount crossings, type conversions and overflow reject the whole changeset. Directories are created only as parents of created files; empty-directory changes are not integrated. The ceiling is 64 files, 32 KiB<!-- unrelated-bound: command changeset decoded content cap --> decoded before and after content and 48 KiB canonical changeset JSON. Engine-generated integration has a [64 KiB](./limits.md#max_command_integration_argument_bytes) argument allowance; model Tool arguments stay at [16 KiB](./limits.md#max_ordinary_tool_argument_bytes). The Build class raises none of these.

The Engine records the observation, then creates a separate one-use integration intent bound to that receipt; models cannot request integration. Goal path scope and the write grant are checked first. An out-of-scope integration is journaled as `Denied` with no receipt or dispatch. In-scope integration goes through the in-process file publisher and never adopts subprocess-created host paths. A later command's snapshot includes integrated creates, modifications, deletions, executable bits and binary content. Approval cannot widen the grant: Auto edits accepts in-grant integration after command approval, Request approvals shows the sanitized changes and asks separately, and Auto approval reviews the integration and asks a human when uncertain. Headless Runs use their upfront grant. Plan revision cannot widen the Tool grant.

The publisher validates the whole batch, Workspace identity, every before digest, executable bit or absence precondition, and parent types through no-follow handles; conflict, denial or overflow changes nothing. It writes fresh regular inodes and syncs directories. A deletion first renames the leaf, no-replace and handle-relative, into an owner-only sibling directory, then rechecks inode, digest, executable bit and parent before unlinking. Drift restored without overwriting is Conflict if no earlier member published. An occupied restore destination is never overwritten; the entry stays under `.arany-remove-<id>/entry` for inspection. The batch is not atomic: unconfirmed restoration, deletion or sync, and failure or drift after a partial publication, are [Uncertain](./execution.md#effect-outcomes). Cancellation during approval changes nothing; during publication it may leave uncertain effects. Only a successful integration receipt proves publication.

Before dispatch, a command reserves Store and Event headroom for its observation, integration and terminal Run and Goal receipts, and context for the full integration argument and rendering; either shortfall prevents dispatch. Integration shares the Goal's active time and needs fresh authorization. The system-executable catalogue travels only through the trusted controller channel, never Workspace or payload input, and is never persisted as authority.

## Checkpoints and rewind

Store captures private pre-images for primary and editor Write, Edit, MultiEdit, Delete, Move and both ApplyChangeset sources after approval, through the Engine checkpoint gate before publication. A checkpoint is the position before a Run's first effect (prompts, Goal start or resume, autonomous Runs); steering notes create none. A file is saved on its first successful or Uncertain publication in a Run, and again when its before digest differs from its last successful after digest in that Run. Creates and gap-free repeats need no bytes; deletions save their before bytes. A failed publication never advances the chain.

Typed edits read pre-images through the admitted directory handle under the usual file bounds and verify the expected SHA-256; command and rewind integration use their validated before bytes. Capture commits before publication, and the publisher still rechecks the batch. A digest mismatch skips capture and leaves the publisher's conflict check in force. Not covered: Mkdir, MCP, commands themselves (integrated changes are covered), cache publication, scratch, host commands and external effects.

`StateRoot/checkpoints.sqlite` is a Store-owned derived store outside the Workspace and separate from the journal. It holds content-addressed `blobs(digest, bytes, len)` and `refs(session_id, goal_id, run_id, rewind_id, tool_sequence, path, digest, len, captured_at_ms)`. The sequence names the ToolStarted or WorkspaceRewindStarted; exactly one of run_id and rewind_id is set, and rewinds use the Session quota bucket. Blobs are deduplicated and SHA-256-verified on read. Refs never choose a restore destination: plans come from journal facts and look up blobs by journal digest. Strict replay never opens this store, reads the Workspace or re-executes a publication.

Storage uses private-file admission. SQLite runs defensive, with trusted_schema=OFF, synchronous=EXTRA and a page ceiling from the physical quota. Values and rows are capped at 1 MiB<!-- unrelated-bound: checkpoint SQLite value limit --> + 4 KiB<!-- unrelated-bound: checkpoint SQLite row overhead --> and SQL at 64 KiB<!-- unrelated-bound: checkpoint SQL statement limit -->; overflow makes storage unavailable. The migration floor and `user_version` are both 1; later steps follow the [journal migration protocol](./execution.md#journal-migration) under the history and checkpoint locks, preserving digests and refs. At startup, a nonempty file below the floor, including a foreign SQLite database, is archived intact with the journal; a file SQLite cannot read stays as malformed storage. A hot `-journal` is recovered by SQLite under both exclusive locks before eligibility is re-read; a sidecar surviving recovery refuses as unsafe with every file untouched. Missing or empty storage initializes lazily. Newer or malformed schemas refuse before mutable pragmas or eviction; busy or unsafe storage is never archived. Capture failures keep storage and do not block the effect. An explicitly confirmed reset removes only a private malformed or unsupported store and its sidecars, under its exclusive lock, refusing if a file changed since the snapshot; busy, non-private or unsafe storage cannot be reset. The [terminal rewind panel](./terminal.md#rewind) offers this recovery; there is no clear command or toggle.

| Bound | Limit | Overflow |
|---|---|---|
| Pre-image | 1 MiB<!-- unrelated-bound: checkpoint preimage cap --> | skip the whole publication with `too_large` |
| Path per owning Session | 32 versions and 32 MiB<!-- unrelated-bound: checkpoint path retention bytes --> logical bytes | evict oldest versions first |
| Goal | 256 MiB logical referenced bytes | evict oldest checkpoint refs, excluding the current Run |
| Session | 100 checkpoints with refs and 512 MiB<!-- unrelated-bound: checkpoint Session retention bytes --> logical bytes | evict the oldest checkpoint's refs, excluding the current Run |
| Store | 2 GiB SQLite pages including free pages, blobs and refs; 262,144 refs; remaining filesystem headroom | evict the least recently captured Session's oldest refs, excluding this publication; otherwise skip whole with `quota` |
| Retention | 30 days after the Session's latest capture; future-dated Sessions are eligible | sweep on Engine open and before capture |
| Publication capture | typed edit 1 MiB<!-- unrelated-bound: checkpoint typed edit capture -->; [command changeset limits](#command-changesets); editor edits use the primary bounds | skip whole; no partial capture |
| Contention | 2 seconds shared by checkpoint-lock and SQLite contention | skip with `store_unavailable` |

Eviction is transactional: expired Sessions, then per-path, per-Goal, per-Session and total quotas, each in one ordered pass removing whole checkpoints; the physical-size pass targets twice the shortfall. Retention expiry commits separately, so it progresses even when capture is skipped. Unreferenced blobs are removed and pages reclaimed; a failed batch rolls back. The headroom check after eviction keeps 4 MiB free plus the incoming bytes and file growth. The Engine waits at most 3 seconds, and at least 1 second before the publication deadline; a later result is discarded as `skipped` with `store_unavailable`. Orphans from a crash before publication expire with the Session's refs. A removed ref whose digest survives through deduplication emits no notice. The first eviction per Run that loses a blob of this Session names its newest affected checkpoint: `Older checkpoints pruned; code restore unavailable before Run ID`. Other Sessions' prunes are never named here; a startup sweep's prune is reported at the Session's next capture.

[ToolFinished](./execution.md#admission-persistence-and-recovery) has a required nullable `checkpoint`: null for non-publications and known non-dispatch, otherwise `{status: captured|not_needed|skipped, reason: null|quota|too_large|store_unavailable|digest_mismatch, pruned_before_run: null|RunId}`. `captured` requires an overwrite and a successful or Uncertain publication. `not_needed` covers creates, gap-free repeats and dispatched publications that changed nothing (failed, conflicted or denied), which never produce a rewind notice. A skipped capture still permits publication. Summaries and `show` show the reason (quota: `This change cannot be rewound (checkpoint storage full)`); JSONL keeps the field, and Goal reports keep it as a priority unresolved fact. Checkpoint bytes never enter model context, telemetry or diagnostics automatically.

Capture runs no Git and leaves `.git` untouched. Prior file contents are unencrypted private state, like the journal. [D-21](../research/next-step-decision-register.md#d-21--checkpoint-storage) owns the peer comparison.

**Preview.** Engine::rewind_preview admits an idle Session under the operation slot, Session and ancestor locks and the Workspace writer lock. It checks the Workspace identity and reloads the current write grant or folder consent, never historical permission; current denies also exclude a path, and confirmation supplies any required human approval. It computes live digests and executable bits through the admitted directory capability and verifies needed blobs. Read-only or excluded paths are outside_grant; links, special files, mounts and case aliases are unsafe; missing, pruned or tampered blobs are unavailable. A preview carries no executable text or authority from restored bytes. Comparison data reuses the before/after versions up to 64 MiB<!-- unrelated-bound: rewind comparison decoded content --> of decoded content; beyond that it is marked unavailable without changing admission. Unsafe, outside-grant and unavailable paths disclose no content. Checkpoint-storage errors stay distinct from a missing blob so the terminal can offer recovery.

Live drift, history drift, an unavailable blob, an unsafe path or a grant exclusion refuses the whole batch by default and lists the paths. Two explicit selections produce a new preview: keep listed files and restore the rest, or overwrite drifted paths using their observed digest or absence as the new precondition. Unavailable, unsafe and outside-grant paths can only be kept; a live file above the 1 MiB<!-- unrelated-bound: checkpoint file version cap --> version bound is unsafe. Preview applies the publisher's path admission (ASCII, at most 16 components, whole-batch scan bound), so it never promises a restore the publisher refuses. Kept and overwrite selections are sorted, distinct, disjoint sets of at most 64 paths of at most 512 UTF-8 bytes each. An empty plan cannot restore. Open or Uncertain publications block code restore under the [Session contract](./session.md#rewind-planning-and-replay).

**Restore.** Engine::rewind consumes one opaque, non-cloneable preview as confirmation of that plan. It reacquires the locks and rechecks head and prefix, live state, blobs, grant and enforcement, refusing a changed preview before Started. A live, unchanged preview stays confirmable but cannot be renewed or reused. Before Started the Engine reserves two maximal Session Events; a capacity refusal changes nothing. The plan is capped at 32 MiB<!-- unrelated-bound: rewind restored content cap --> restored and 32 MiB<!-- unrelated-bound: rewind overwritten content cap --> overwritten content; file count, version size and transfer use the [changeset bounds](./execution.md#worker-journal-protocol). Overflow refuses the action. Workspace contention returns WorkspaceBusy; an active Engine returns Busy.

Restoration is an internal Rewind publication source holding the plan digest and transfer length and digest, never a model Tool or ToolStarted source. Bytes are decoded and validated in process under the transfer bounds. After Started, the Engine tries to capture overwritten content under the rewind ID as the Before rewind checkpoint; Finished records the actual status, and a skipped capture still permits ordinary restoration. An explicit drift overwrite refuses before publication if its content could not be saved. Hooks never run. The publisher checks the whole batch before its first write and follows the capacity, deadline and uncertainty rules of [in-process file operations](#in-process-file-operations), with no Guard unit. Cancellation before Started changes nothing; after Started it records cancelled when non-publication is known. A conflict lists only the paths whose live state, re-read after refusal, differs from the preview. An unconfirmed write or lost completion is [Uncertain](./execution.md#effect-outcomes). Finished binds the intent and its in-process attestation digest to plan, Workspace and enforcement; historical Guard receipt digests keep their encoding. A missing Finished leaves an Uncertain prefix, and [Goal recovery](./goals.md#rewind-and-goal-recovery) owns the resume block. Conversation restoration and ordering follow the [Session contract](./session.md#conversation-rewind); the [terminal](./terminal.md#rewind) and [serve](./serve.md#rewind) own controls.

Linux and macOS share one implementation. ASCII case-alias refusal applies on both, and case-insensitive APFS also refuses filesystem aliases. SQLite keeps the macOS durability settings with no F_FULLFSYNC claim. On WSL2, drvfs or /mnt/c executable-bit changes can appear as drift.

## Portable Skills

Each `skills` entry contains a name, reviewed discovery description, absolute directory, exact relative file-to-SHA-256 map and an optional `disable_model_invocation` flag (default false):

```json
{
  "name": "review",
  "description": "Review the selected project code",
  "directory": "/absolute/reviewed/skills/review",
  "disable_model_invocation": false,
  "files": {"SKILL.md": "<digest>", "references/checklist.md": "<digest>"}
}
```

Project Skills come only from `.agents/skills/NAME/SKILL.md`, admitted by remembered whole-folder trust or by an explicit grant whose roots contain `.agents/skills`; other directories and home Skills are not sources. Private entries win over duplicate project names. At most 64 names are admitted. Names, resources and digests are bounded and pinned anew at Run admission; links, special files and excessive discovery reject. Startup and `/permissions` refresh names; installation changes during a pinned Run never renew grants. Untrusted folder contents grant no Skill access.

The model sees admitted names and bounded previews (literal frontmatter excerpts, descriptions truncated to 96 characters). A Skill flagged `disable_model_invocation` is hidden from the model and refused as not offered if it proposes it; explicit user invocation still works, as in Claude Code. A project Skill sets the flag only through literal `disable-model-invocation: true` frontmatter in its pinned `SKILL.md`; a private entry carries the reviewed flag. Resources load lazily.

`SKILL.md` is bounded UTF-8 text. The host never evaluates YAML; frontmatter is returned as inert guidance. Identity and authority come only from the admitted name, directory and digest. `allowed-tools`, hooks, shell directives, forks and installation text are guidance, never grants, and no Skill body is a system instruction. Requesting a Skill executes nothing; its scripts need an ordinary approved command.

The [terminal completion contract](./terminal.md#interactive-commands-and-completion) owns slash invocation. Before the first Provider call, an explicit invocation commits one ordinary `Skill { name, resource: null }` intent and its observation through the admitted Skill path; replay admits this Engine origin only for the accepted Skill, after definition parsing, once per Run. The observation enters that turn as `invoked_skill (untrusted)` data under the [64 KiB](./limits.md#max_tool_result_bytes) Tool result ceiling, context accounting and the credential-reflection check. Later Runs never replay the body; the accepted message records the Skill name separately from the verbatim objective. A failed read ends the Run with `tool_stopped` before Provider egress.

A root `skills-lock.json` without a `.agents/skills` directory produces a notice to run `npx --yes skills@1.7.0 experimental_install` (the [Skills 1.7.0 installer](https://github.com/vercel-labs/skills/blob/v1.7.0/src/install.ts)). Arany checks only whether the directory exists, never reads the lock and never runs the installer.

Skill text uses the in-process read path on Linux and macOS. Admission holds at most [64 Skill](./limits.md#max_skills) directory handles; a directory that cannot be opened fails only its own reads for that Run and is never reopened. Each read revalidates the directory identity, opens only a listed resource through no-follow checked handles, rejects set-ID files and checks the pinned digest. Text over the intent's result allowance is shortened at a UTF-8 boundary with the shared `…[N bytes, L lines omitted; B bytes, T lines total]…` marker. `Succeeded` means verified, bounded text, not complete text; the marker is untrusted, since Skill content can contain it. Skill scripts run as approved commands in the Guard; Linux exposes admitted Skills read-only under `/skills/SKILL_ID`. A Goal plan names Skill resources exactly (`resource: null` means `SKILL.md`) and only narrows admitted files. A matching successful Skill receipt may satisfy a Goal success criterion.

Guard failures before dispatch report the closed failure stage and check, say when the cause is unknown, and give a recovery step: namespace-bootstrap failures point to user-namespace and Bubblewrap support, native-manager failures to the user service manager, and only native-protection and startup failures to the Guard executable and prerequisites. Project-selection timeouts, vanished inputs and conflicts are named at the selection boundary; the same errors from payload startup, capture or typed mutation keep their own stage. `/agents` renders the stage from a typed fact. Recovery text asks the user to resend the message and assumes no resumable Goal. Only development builds mention `development.log`. No raw native error text, path or secret is shown, and nothing retries automatically.

## Agent definition parser admission

[Execution](./execution.md#agent-definitions) owns discovery, format, precedence and selection. Snapshot capture uses opened directory capabilities, no-follow same-device resolution, current ownership, regular single-link non-set-ID files and bounded reads. Protected names reject before opening, and replacement during capture rejects; later replacement cannot change pinned bytes. Private StateRoot agent files also need private permissions and ACL admission against the held StateRoot identity. No repository Git, shell, configuration script or agent body executes.

YAML parsing runs only in the killable native Guard, after an internal `parse_agent_definition` ToolStarted and the one-use Ready/GO exchange. Its intent names an ordered snapshot index and exact raw digest, not a model path. The task carries only that raw snapshot as canonical base64 within the Guard task bound (1 MiB<!-- unrelated-bound: Guard task frame payload --> plus room for one base64 definition file, so the full pinned config always fits); native admission checks length and digest before Ready. The bounded YAML visitor refuses anchor, alias and tag tokens (quote literal token punctuation in scalar guidance). The normalized-v1 record returns through ordinary bounded ToolFinished and attestation. Model schemas and generic script APIs cannot invoke the parser, and there is no host YAML fallback.

A selected definition's mode can require a verdict even without a parent permission-settings file. `ToolStarted.verdict.mode` names the parent settings mode when present, otherwise the definition mode; replay checks the definition restriction independently. A definition Ask needs a human or recorded AI review and cannot approve itself.

Parsing uses ordinary primary Tool admission, capacity, approval-wait accounting, deadline, cancellation, cleanup and terminal-tail reservation, one pending Tool at a time, and spends no model request. An invalid definition file is a successful parse with a skip diagnostic. Guard failure, malformed normalization, unsupported enforcement, overflow or a missing observation blocks Provider continuation like any primary Tool step; an unknown parse outcome is [Uncertain](./execution.md#effect-outcomes), and Store failure stops advancement. Cancellation preserves acknowledged receipts. Strict replay never re-parses or recovers old authority.

## Editor Tool steps

Editors (foreground or disjoint background) use the primary's typed Workspace file path under their own journal identity and leased subset grant. Their catalog is List, Read, Search, Glob, Mkdir, Write, Edit, MultiEdit, Delete, Move and Command, narrowed by parent, plan and definition; Git, Skill, MCP, network, nested delegation and host execution are unavailable.

Reads see the live Workspace through ordinary admitted capabilities and bounds. Typed mutations keep expected-digest/create preconditions, exact path-case checks, full-batch validation, fresh-inode publication and intent-bound receipts. Scope and both lease directions are checked before an intent commits: an editor cannot escape its lease and no other actor can write into it. Hooks and permission modes are evaluated under the child's identity and only narrow authority.

Editor mutations change the Workspace immediately; the editor's answer neither publishes bytes nor authorizes integration. Its terminal outcome releases the lease, and successful completion still needs fresh primary Workspace evidence. Landed changes stay on cancellation or pause. Write, Edit, MultiEdit, Delete and Move follow the [checkpoint and rewind rules](#checkpoints-and-rewind); Mkdir is neither captured nor rewound. An unknown editor effect is an [Uncertain](./execution.md#effect-outcomes) Workspace effect that stops the entire Run; process death never reschedules it. [Execution](./execution.md#worker-journal-protocol) owns the journal lifecycle and format boundary.

Editor commands reuse the primary [command input selection](#command-input-selection), capture and publication. The whole changeset is validated against the child lease and other live leases before a publication intent commits; any out-of-lease change publishes nothing. The lease bounds publication, not command output or disclosure. Publications keep the child's identity, permissions, deadline, checkpoints and accounting. Commands take the ordinary exclusive [cache lease](#persistent-workspace-build-cache); `cache_update` settles independently, as for primary commands.

Linux and macOS share the in-process admitted-capability file publisher, checkpoint Store and pure rewind planner; discovery and commands use each platform's Guard mechanism.

## Local MCP

Each `mcp` entry pins a server executable, immutable input files, fixed startup arguments and allowed tool names:

```json
{
  "name": "local",
  "program": {
    "name": "python-mcp",
    "executable": "/absolute/resolved/python-executable",
    "sha256": "<digest>",
    "interpreter": true,
    "inputs": [{"path":"/absolute/reviewed/server.py","destination":"server.py","sha256":"<digest>"}]
  },
  "args": ["/inputs/python-mcp/server.py"],
  "tools": ["echo"]
}
```

The server gets the offline snapshot, runtime and descendant restrictions of commands and no Provider or account credentials. Servers needing external APIs, credentials, writable host state or package installation are unsupported.

Arany implements the **2025-11-25 tools profile** over stdio and, for [remote servers](#remote-mcp-and-oauth), streamable HTTP: `initialize`, exact version and capability negotiation, `notifications/initialized`, bounded `tools/list` pagination, schema validation, one `tools/call`, then disconnect. It is not the newer 2026-07-28 stateless profile. Server-to-client ping works; sampling, roots and elicitation get method-not-found. Notifications cannot trigger discovery, refresh permission or extend deadlines.

Discovery returns a digest of each admitted complete tool definition. A later call lists again and requires the selected digest; drift rejects before the call. Arguments must be an object encoded as a JSON string that satisfies the admitted input schema. Schemas use the supported Draft 2020-12 or Draft 7 subset, bounded linear regexes and offline compilation; references, `$id`, remote retrieval and unsupported dialects reject. Calls never retry. Output admits bounded text, inert resource links (never fetched) and legacy object `structuredContent`; a declared output schema is enforced for successful results. Embedded resources, images and audio reject. `isError` is recorded as an observed failure, not success.

### Remote MCP and OAuth

An `mcp` entry with `url` instead of `program` is a remote server: `{"name": "docs", "url": "https://mcp.example.com/mcp", "auth": "oauth", "tools": ["search"]}`. Exactly one of `program` and `url` is present, and a remote entry has no `args`. The URL follows the [`web_fetch`](#web-fetch-and-web-search) rules (HTTPS on the default port, no credentials or fragment; numeric loopback may use HTTP and any port). `auth` is absent (no credential) or `oauth`. Remote servers are Linux-only (configuration fails closed elsewhere) and primary-only: researchers neither see nor can call them (a guessed name is denied before any approval), and the parent reads no saved token for a call without the proxy class. The catalog row names the streamable HTTPS transport and the `arany mcp login` action.

A remote call runs in the Guard like `web_fetch` (`limits.network = proxy`, empty network namespace, routed seccomp program), with a proxy grant for the server's host alone, independent of the `network` grant; the enforcement digest binds the proxy class. Framing is the stdio profile's bounded JSON-RPC over streamable HTTP: one `POST` per message with `Accept: application/json, text/event-stream` and `MCP-Protocol-Version`, the `Mcp-Session-Id` from `initialize` echoed, `202` for acknowledged notifications and replies, and responses as a JSON frame or an event stream of `data:` frames serviced as they arrive (a server may await its `ping` answer before the result). A response is at most [`MAX_MCP_RESPONSE_BYTES`](limits.md#max_mcp_response_bytes) and 16 frames, each within the stdio frame bound; compressed, redirected and other content types fail the call. A frame whose decoded text contains the bearer token fails the call before capture, so the token never reaches Events, spills or the Provider. Once `tools/call` is sent, the outcome is [Uncertain](./execution.md#effect-outcomes) (transport error, refused reply to a server `ping`, timeout, oversized, invalid or unrelated frame) unless the server refused with `401`/`403` or returned a well-formed JSON-RPC 2.0 response with the call's request ID. Local catalog, schema, digest and result bounds apply, and output stays untrusted. Server requests other than `ping` get method-not-found. There is no GET stream, resumption or session `DELETE`.

`arany mcp login <server>` authorizes an `auth: "oauth"` server; `arany mcp logout <server>` revokes and removes it. Login resolves protected-resource metadata (RFC 9728), then authorization server metadata (RFC 8414), falling back to the server origin. It requires an `issuer` equal to the discovered address, HTTPS (or numeric loopback) endpoints and PKCE `S256`. It registers a public client dynamically (RFC 7591; no registration endpoint is unsupported), prints the authorization URL, accepts one code on a one-shot `127.0.0.1` callback (exact `Host`, path and `state`; at most eight connections and 180 seconds) and exchanges it with the PKCE verifier and the server URL as `resource` (RFC 8707). Every login request uses the [Provider destination policy](./provider.md#configuration-and-egress), follows no redirect and reads at most [`MAX_METADATA_BYTES`](limits.md#max_metadata_bytes). Login requests are never made for a model call.

The parent reads the saved token before the Guard launches and passes it over the private task pipe, like the search key; it never enters an intent, Event, digest or observation. A token within a minute of expiry renews through the saved refresh token:

- The renewal belongs to the triggering MCP effect: that intent commits first, and the renewal runs inside the action deadline.
- Under the account lock the grant moves from `ready` to `renewing` (a uniquely identified claim) before the request; the result publishes only if that claim is still current, so a logout or new login in between wins.
- A new token or rotated refresh token replaces the grant; a definite client refusal (4xx other than 408/429) marks it `rejected`; anything else (lost reply, timeout, 5xx, invalid reply, failed publication, cancellation, crash) leaves it `renewing`, so a refresh token is never submitted twice and only a new login clears it.
- The renewal counts as dispatched once the claim is written. An unconfirmed renewal makes the call [Uncertain](./execution.md#effect-outcomes); later calls see the blocked grant and record `unauthorized` without a request.

A token is never sent to a URL other than the one its record names. A missing, expired-without-refresh, failed-to-renew or `401`/`403`-rejected token ends the call with ``{"server", "error": "unauthorized", "action": "run `arany mcp login <server>` …"}`` and observation `Failed`; `mcp_list` and `mcp_call` never retry. A token is at most [`MAX_ACCESS_TOKEN_BYTES`](limits.md#max_access_token_bytes); the credentials contract owns its [storage](./credentials.md#remote-mcp-tokens). Logout sends one revocation request when advertised, removes the local token either way and warns when revocation is unconfirmed. Replay never contacts the network. Non-claims: an allowed server receives whatever the model sends, the proxy cannot see TLS content, and no scopes are requested.

## Extension and transport admission

The MCP profiles are [local stdio](#local-mcp) and [remote streamable HTTP](#remote-mcp-and-oauth) as a client behind the egress proxy; no generic listener or runtime self-update is admitted. The only other listeners are the per-command [egress proxy](#network-grants-and-egress-proxy) and, on Linux, its in-namespace loopback bridge. A new listener needs a named feature and a reviewed protocol. A stdio server and network-capable extensions are deferred.

Any future HTTP or MCP listener must validate exact `Host` and `Origin`, authenticate and authorize each session, admit exact content types, bound bodies and sessions, reject DNS-rebinding, CSRF and cross-site requests, and encrypt traffic leaving loopback. Loopback routing is not authentication. The only listener exceptions are the one-shot [ChatGPT OAuth callback](./chatgpt.md#authorization-transaction) and the one-shot [MCP login callback](#remote-mcp-and-oauth). PTY, update, package-install, approval and other high-authority operations require a narrow authenticated protocol and explicit capability, not a generic listener.

MCP servers, plugins, Skills and updates require reviewed provenance and an immutable version or digest; no update endpoint may select arbitrary packages or installation/lifecycle scripts. MCP credentials bind server, issuer endpoints and audience (the server URL as `resource`), never Provider or ambient credentials; authorization is per server, Tool, resource and operation. Manifests and results stay untrusted. Network grants keep the [Provider destination and disclosure constraints](./provider.md#configuration-and-egress).

## Typed Git reads

On macOS, Git reads need the Command Line Tools.

1. **Availability.** Folder trust pins the platform Git (path and SHA-256 per Run) when it resolves under the platform root to a root-owned, non-set-ID, non-writable executable of the platform format: `/usr/bin/git` (ELF) on Linux, `/Library/Developer/CommandLineTools/usr/bin/git` (Mach-O) on macOS. Explicit configuration uses the `git` field (`name` `git`, executable under the platform root, SHA-256, `interpreter: false`, no inputs) and requires `workspace_paths: ["."]`. Without a pin the catalog reports `unavailable`, no Git operation is offered, and Git is never emulated. Git outside the platform root (Nix, Homebrew, Guix, Xcode.app, the macOS `/usr/bin/git` xcrun shim) is unavailable by design.
2. **Operations.** `git_status {path}`, `git_diff {path, base, head, staged}` and `git_log {path, revision, max_count}`. `path` is a Workspace-relative literal pathspec (`.` is the whole repository). `git_diff` compares the working tree with the index, the staged index with `base` (HEAD when null), the working tree with `base`, or two endpoint trees with Git's two-dot semantics; `head` requires `base` and excludes `staged`. A revision is `HEAD`, a ref name or a hex commit name with at most four `~N`/`^N` steps, at most 128 bytes. `git_log.revision` also accepts one `base..head` range of two nonempty, independently valid revisions (whole range at most 258 bytes). Open endpoints, three-dot ranges, revision sets, `:`, `@{` and options reject. A revision matching ambiguous refs fails before dependent reads. `max_count` is 1 through 50. Endpoints resolve once to commit OIDs; at most four invocations share the action deadline. Results are JSON: `git_status` returns `{"branch":{"oid","head"},"entries":[{"path","state"}],"truncated"}`, `git_diff` returns `{"files":[{"path","added","deleted"}],"patch","truncated"}` and `git_log` returns `{"commits":[{"oid","parents","author","time","subject"}],"truncated"}`; endpoint diffs and ranges add `comparison` with both original endpoint names and captured OIDs. A failure returns `{"failed"}`; diagnostics follow the disclosure policy below.
3. **Exclusions and fidelity.** The components `.git`, `.aws`, `.ssh`, `.gnupg`, `.env`, `.env.*`, `.npmrc` and `.pypirc` are excluded ASCII-case-insensitively, including from history, through `:(icase)` pathspecs and row and stderr filters. Renames are not detected, submodules are ignored and `.git/info/exclude` is not applied. Git uses default settings, not the repository's `core.filemode`, `core.autocrlf`, `core.eol`, `core.ignorecase`, `core.symlinks`, `core.excludesFile`, sparse checkout or `branch.*`; results can therefore show mode-only (WSL2 `/mnt/c`), line-ending or, on APFS, deleted-plus-untracked case/Unicode differences that your own `git status` hides. A `HEAD` or repository config that is a directory, hard link or FIFO is an unsupported layout before any private view is created, never an enforcement denial. These fail without running Git: a repository rooted in a parent directory, a linked worktree, a submodule checkout or other `.git` file, a symlinked `.git`, a missing `HEAD`, `objects` or `refs`, and `[extensions]`. A split index fails when Git runs.
4. **Neutralization.** Git never receives the repository's configuration, hooks or attribute-selected drivers; Arany reads repository config only to detect `[extensions]` and extract the inert upstream metadata below. Git runs against a private view on scratch tmpfs (Linux) or the bounded unit volume (macOS): a fixed config, copied `HEAD` and `index`, and linked `objects`, `refs`, `packed-refs` and `shallow`. The index is read without following links, with its mtime from the same open file; a linked or hard-linked index is unsupported, and one over [32 MiB](./limits.md#max_snapshot_bytes) refuses with Limit. Git gets a closed 13-variable environment, fixed argv (`--no-optional-locks`, `--no-ext-diff`, `--no-textconv`, `--no-pager`, `--end-of-options`, `--`), read-only Workspace access, no network, the rechecked pinned executable and the default resource profile. Linux stops namespace descendants before the receipt; macOS empties the unit coalition at teardown. Inert vectors include `core.fsmonitor`, hooks, `diff.external`, textconv, filter drivers, `include.path`, pagers, signing programs, credential helpers and lazy fetch.
5. **Policy and disclosure.** Git reads need the pinned grant and no approval in any mode. They are in the Goal prelude with plan-contract `path` scope, are never success criteria and are never offered to children. Bounds follow [limits](#limits-and-failure-behavior) (the `git_log` limit counts returned rows; macOS uses the supervised default profile); [branch comparison](#branch-discovery) has a separate ancestry scan bound. A nonzero exit is Failed and the Run may continue. Stderr is suppressed, because arbitrary diagnostics cannot be filtered by path. History and changes reach the Provider and journal as untrusted data. Residual risk: secret-path exclusions are filters, not sandbox enforcement.
6. **Ignore selection.** Returned paths also pass the shared bounded Git-ignore selector, after Git capture, within the shorter of the two-second discovery window and the action deadline. It reads root and nested `.gitignore` controls under the shared [ignore-control admission](#command-input-selection) and [discovery limits](#typed-read-discovery). A missing control means no rules at that level; a malformed, unsafe, unavailable or over-budget control fails the whole read. Ignored paths stay hidden even when tracked or named explicitly. Filtering precedes result fitting: rows are omitted, a diff section stays only when its recognized path is visible (unrecognized or quoted headers stay hidden), and a log commit needs visible changed-path evidence. A subject visible through another path is untrusted data, not a redaction guarantee. Expiry returns `Limit(timeout)`, an over-budget control `Limit(resource)`, and invalid or unsafe controls (`Path`, `FilesystemDenied`) `Denied`. Strict replay never loads current ignore controls or reruns Git.

Accepted macOS trade-offs:

- The private view lives in one fixed-capacity native volume of [`SCRATCH_BYTES`](./limits.md#scratch_bytes), verified (no-follow, owner-only, `nosuid`, writable, exact capacity) before Git starts; the profile grants writes only beneath it, and failure to prepare it refuses. Filling it gives `ENOSPC` and fails the read or write without publication; teardown detaches the volume.
- The pinned Git's only check is a SHA-256 pin of a root-owned file (no code-signature or entitlement verdict; the kernel enforces the platform signature). A TOCTOU window exists between pin verification and spawn-by-path, exploitable only with root write access to the Command Line Tools tree; Linux executes the pinned file in place. On both platforms only the executable leaf is checked, not its ancestors.
- A Command Line Tools update changes the digest, so Git reads fail with `ChangedInput` until folder trust is renewed. The read-only Workspace bind includes `.env`, so a Git memory-corruption bug triggered by a hostile pack could emit Workspace bytes through the bounded output, the only exit.

### Branch discovery

`git_branch {name:null, start_point:null, scope, base, max_count}` reads local and remote-tracking tips through the same primary-only Git grant on Linux and macOS, including plan mode. `scope` is `local` (default when null), `remote` or `all`. `max_count` is 1–256 (256 when null). A null `base` omits comparison; an explicit base uses the read revision grammar and must resolve to a commit. Invalid inputs reject before execution. Creation follows the [write contract](#typed-git-writes) and requires these three fields null.

The JSON result has `branches`, nullable `comparison_base: {revision, oid}`, `history_complete`, `truncated` and `timed_out`. Rows are sorted by full ref name; invalid UTF-8 becomes U+FFFD and `name` is capped at 1 KiB<!-- unrelated-bound: displayed Git ref name --> on a UTF-8 boundary, with `name_truncated` marking clipped or lossy names (clipped or lossy names also set `truncated:true`). A displayed name is never an exact ref identity; a lossy local name reports `upstream_status:unsupported`. Rows carry `kind: local|remote|non-commit`, tip `oid`, `current`, nullable `symbolic_target` (same cap, with `symbolic_target_truncated`), nullable `subject`, `subject_withheld`, nullable `upstream`, `upstream_status`, nullable `ahead`/`behind`, `counts_withheld` and `counts_capped`. Non-commit refs, including annotated tags in branch namespaces, stay rows with their object OID, null subject and withheld counts. Remote symbolic aliases keep their target but have no subject or counts. Detached or unborn HEAD does not prevent enumeration; an empty repository without a base succeeds with no rows.

The base resolves once to a commit OID. Each comparison runs fixed `rev-list --left-right --max-count=1001 base_oid...tip_oid` against the captured tip: left is `behind`, right is `ahead`. Up to 1,000 commits give exact counts; a lookahead commit withholds both with `counts_capped:true`, never a partial count. Subject and count work share a one-second per-row deadline, since the output cap does not bound merge-base traversal; reaching it leaves unobserved fields null and withheld, marks requested counts capped and moves on. Any cap sets `truncated:true`. Counts describe whole-history ancestry, not permitted-file changes. Null counts mean no comparison was requested, an alias or non-commit row, or `counts_withheld`.

Tip subjects are at most 256 characters and need visible-path evidence from that exact commit. Mandatory secret-path exclusions always filter evidence and diagnostics but do not disable enrichment; unresolved restrictive user Read path rules suppress subject and count enrichment and mark those fields withheld. A protected-only tip, or a parentless tip in a shallow view, has a null subject with `subject_withheld:true`. Filters run before persistence and model continuation.

Remote-tracking refs are local, possibly stale observations; nothing is fetched. Shallow repositories return `history_complete:false`. Missing objects or an unresolved base fail explicitly. Captured OIDs do not change with concurrent ref updates, but the result is not an atomic snapshot. One sorted `for-each-ref` enumerates the selected namespaces within the [shared read limits](#limits-and-failure-behavior); rows are enriched sequentially, with at most one subject and one comparison invocation each plus one base resolution per action. All invocations share the action ceiling, with one second reserved for teardown and delivery. Reaching the work deadline returns completed rows with `truncated:true` and `timed_out:true`; a deadline during enumeration or base resolution returns an empty truncated listing, with `comparison_base` null if unresolved. A timeout is never an empty successful inspection. Only complete rows fit the result budget: overflow sets `truncated:true`, never partial rows or invented counts. Only confirmed cleanup permits another row or a partial result; a failed or expired child reap stops the action, and a missing receipt is [Uncertain](./execution.md#effect-outcomes). Replay uses committed rows, flags and OIDs without running Git or rereading configuration.

Upstream associations use only direct `branch.<name>.remote`, `branch.<name>.merge` and the matching `remote.<name>.fetch`, parsed as inert metadata from the no-follow, at-most-64-KiB<!-- unrelated-bound: Git configuration inspection cap --> config inspection (Git-written quoted subsections and plain or quoted scalars in the admitted ref alphabet). Remote `.` names a local ref; another remote needs one unambiguous positive literal or single-wildcard fetch mapping, optionally prefixed with `+`. Targets go through the shared no-follow ref reader (1 KiB<!-- unrelated-bound: Git loose ref cap --> loose refs, at most [32 MiB](./limits.md#max_snapshot_bytes) packed refs, read once per action; loose refs win). No URL, helper or executable setting is loaded or passed to Git. `upstream_status` is:

- `present`: the direct association resolves to a present target ref;
- `gone`: the supported target ref is missing, with its name retained;
- `unavailable`: direct metadata is missing; no claim is made about user-global configuration;
- `unsupported`: duplicate or ambiguous keys, unsupported syntax or mappings, escapes, continuations, any include/includeIf declaration, or an unsupported or over-bound target ref; `upstream` is null;
- `not_applicable`: a remote row has no branch upstream.

Includes are never read; their presence prevents claiming a complete direct association. [Decision D-25](../research/next-step-decision-register.md#d-25--branch-reads-use-git-semantics-with-inert-tracking-metadata) records the peer behavior and neutralization rationale.

### Range history and endpoint diff

A `base..head` log lists commits reachable from head and not from base. An endpoint diff compares the two trees directly (two-dot), so it includes tree changes a three-dot diff would omit. Identical endpoints give an empty successful result. Ambiguous branch/tag names and missing endpoints fail before dependent reads. Both results pin the resolved OIDs and apply the ordinary exclusions, Read rules and replay rules.

### Typed prefix rules

`permissions.json` may carry `permissions.typedPrefixes`, an optional list (default empty) of `{"prefix": [...], "decision": "allow"|"ask"|"deny", "workspace": null | {"path","device","inode"}}`; every field is required and unknown or duplicate fields reject. `prefix` is exactly one of `["git","commit"]`, `["git","branch"]`, `["git","switch"]`, `["git","push"]`, `["gh","pr","create"]`, `["gh","pr","list"]` or `["gh","pr","view"]`; partial verbs, extra tokens, flags, globs, shell strings, aliases, wrappers and executable paths reject. Matching uses the validated typed operation, never argv: `git_commit`, `git_branch` with a `name` and `git_switch` map to their verbs, and branch listing is a read that matches none. `push` and `pr create` match `git_push` and `gh_pr_create`, which stay human-only in every permitted mode even with an `allow` rule; `/permissions` labels them `host; human approval required`. `pr list` and `pr view` match `gh_pr_list` and `gh_pr_view` under the [host-read exception](#human-approved-host-git). `workspace: null` is user-wide within this state directory; an object binds the folder's exact absolute path, device and inode, so a moved or replaced folder inherits nothing. Paths are at most 4096 bytes<!-- unrelated-bound: host approval Workspace path -->, canonical, control-free, with a nonzero inode.

Typed rules and [host-prefix records](#remembered-host-prefixes) share the 128-rule and [64 KiB](./limits.md#max_config_bytes) limits with ordinary rules and the single `deny > ask > allow` order, so a typed allow never overrides an ordinary deny or ask. The folder filter applies once at Run admission; the pinned digest still covers the whole file, and settings never reload during a Run. A configuration read without a Workspace identity ignores folder-scoped allows but still applies folder-scoped deny and ask rules. Replay admits typed-rule verdicts only for the primary with pinned settings in `default` and `dontAsk`, plus the first-use `mode: null` human verdict.

The only writers are the `/permissions` typed settings edit (only while no Run is active) and the remember choice below. Under the account replacement lock the writer rereads and validates the whole file, compares the SHA-256 the user saw (absence included), revalidates the folder identity captured at load or Run admission, applies one insert, decision change or removal, validates and atomically replaces the private file; other settings keep their values. A stale view, busy lock, replaced folder or overflow refuses with a fresh-load notice, without retry or truncation. A failure after the replacement may already have taken effect and reports `save not confirmed`. `/permissions` may create a missing file with `defaultMode: "default"`, warning that this activates default policy for other Tools; the remember choice never creates the file.

When a human approves a primary local Git write that no rule or hook decided, the dialog offers `Yes, and allow git commit in this folder from the next Run` (or `git branch` or `git switch`). The human verdict (source `human`) commits before the rule is appended. A failed save denies the pending call. A save whose final directory sync fails after the rename may be in effect, so it is an [Uncertain](./execution.md#effect-outcomes) `rule save not confirmed` outcome that dispatches nothing. The [host-prefix save](#remembered-host-prefixes) uses the same writer. The Run keeps its pinned rules, so another matching call in the same Run still asks; the rule applies from the next admission. Replay never saves. The choice is offered only when `permissions.json` already pinned the Run, and never for children, branch listing, hook asks, explicit ask rules, serve or ACP clients, or an `exec` Run without a human.

## Human-approved host Git

The primary may request `git_push {remote, branch}`, `gh_pr_create {repository, base, head, title, body, draft}`, `gh_pr_list {repository, state, base, head, limit}` or `gh_pr_view {repository, number}`. These run outside the Guard under the owner-approved exception in [AGENTS.md](../../AGENTS.md). They reuse the typed Git catalog, immutable intent, permission verdict, action reservation and committed observation.

Authority is closed:

- `git_push` and `gh_pr_create` need a fresh one-use human approval for every call in every mode; no rule, mode or AI review replaces it.
- `gh_pr_list` and `gh_pr_view` ask a human in every mode that asks. Only a matching user-owned [typed prefix](#typed-prefix-rules) allow rule may pre-approve them. Without a human channel or such a rule they are refused before dispatch.
- Repository content, ordinary rules, hooks, AI review, upfront grants and child authority never authorize any of them. Children neither receive these operations nor inherit their approvals.
- Every host Git process runs with inert Git configuration on a neutralized private view, as below.
- All four are journaled as the separate `host` execution class, are never Guard-attested, and terminal, transcript, exec/show, Provider observations and Goal reports mark them `host`.

Writes keep the whole-Workspace Git/write grant and writer lock. PR operations need an explicit native `gh` Program pin in the user-owned `commands` list; neither PATH nor repository files choose it. The catalog offers push only when the admission snapshot has user Git configuration or an SSH-agent socket, and PR operations only with a captured gh authentication record; the snapshot shows availability, not authorization. Using the user's existing Git and gh credentials follows peers.

### Host pull request inspection

`gh_pr_view {repository, number}` is a primary-only read of one PR in an explicit admitted `host/owner/repository` (the [PR-listing repository bounds](#host-pull-request-listing) apply; number 1–2,147,483,647; the gh authentication host must match). It runs fixed `gh pr view NUMBER --repo HOST/OWNER/REPO --json ...` scalar fields, then one fixed `gh api graphql --hostname HOST --method POST --input -` with adapter-generated variables. The returned URL and number must match: scheme, host, route and number exactly, owner and repository ASCII-case-insensitively, as [GitHub documents for repository identity](https://docs.github.com/en/rest/repos/repos#get-a-repository). It fetches the latest 50 issue comments and 50 reviews and at most 100 check/status contexts on the head, and never paginates, accepts a caller query, follows a returned URL or mutates a PR.

Approval follows `gh_pr_list`, with the `gh pr view` rule. Both subprocesses share one deadline narrowed by the Goal allowance and the [PR-listing runtime and capture bounds](#host-pull-request-listing). The query body is capped at 8 KiB<!-- unrelated-bound: PR inspection query body cap -->, and at most 200 discussion/check rows are kept. Body, comment and review text are clipped to 8 KiB<!-- unrelated-bound: PR inspection text field cap --> each; other strings follow the [PR-listing text bounds](#host-pull-request-listing). Truncation is explicit, and the pinned result budget wins: trimming keeps the newest comments and reviews and the first checks. If the fixed PR fields still do not fit, the result is a local budget failure with no PR data and the exit-zero host receipt, not a malformed response. GraphQL errors fail even when gh exits successfully. Null or missing status stays unknown; empty checks means none reported. A head OID that changed between the two observations sets `stale: true` and keeps both heads, so old description and current checks never pose as one snapshot. Failure text is inspection-specific. The result is data, not instruction or authority. Confirmed auth/API/parse failures are Failed; a dispatched process without confirmed completion and cleanup is [Uncertain](./execution.md#effect-outcomes). Replay uses only the committed observation.

### Host pull request listing

`gh_pr_list` is a primary-only remote read: `gh pr list` for the explicit admitted `host/owner/repository` with a fixed JSON field set, state `open` (default), `closed`, `merged` or `all`, optional exact base/head names and a limit of 1–50 (default 30). The repository is at most 256 bytes and base/head at most 128 bytes, control-free and validated before argv construction. The user-owned gh authentication host must match the repository host. No local repository discovery, arbitrary API request, browser, pagination, mutation or URL following is available.

A matching typed allow rule may pre-approve the read in any mode, including Plan, Auto and headless/ACP, subordinate to deny and ask. The approval names host execution, the exact repository and filters, and private PR disclosure to the current Provider. Saving a rule that allows this read, including changing an ask or deny rule, repeats that disclosure and requires explicit confirmation.

The command runs through the pinned private gh copy and the host supervisor. Stdout is capped at 256 KiB, stderr at 4 KiB<!-- unrelated-bound: host PR listing stderr capture --> and runtime at 20 seconds, narrowed by the Goal allowance. At most 50 rows are kept; title is clipped to 256 bytes and other strings to 2 KiB<!-- unrelated-bound: host PR string projection -->, with truncation fields. A result at the limit reports `possibly_more: true`; no total is inferred. Empty output is a successful empty list. Invalid or oversized JSON and confirmed API/auth failures are Failed. An interrupted dispatch without captured completion is [Uncertain](./execution.md#effect-outcomes) even after confirmed local cleanup, which does not establish the remote outcome. Replay uses the committed result without a process, network request or credential read.

**Intent and approval.** Failure to pin host source data refuses before approval or dispatch with `Host source data is unavailable; no operation was dispatched`; hook denials keep precedence. Push accepts one literal credential-free `https://host/path` or `ssh://git@host/path` URL and an existing local branch; remote aliases, userinfo, ports, query strings, fragments, local/file/ext transports, symlinked or ambiguous ref routing refuse. Its intent pins the local source object ID and `OID:refs/heads/branch` refspec; there is no force, deletion, follow-tags or recursive submodule push. PR creation pins `host/owner/repository`, base, head, title, body and draft. Its local head OID detects local drift before dispatch but does not bind the remote PR commit: the approval says the PR uses the remote head branch at creation and never shows the local OID as its source. Push and PR creation need separate one-use approvals showing the whole normalized destination and payload; PR body lines are escaped and indented beneath `Body:` so they cannot impersonate approval fields. Rule precedence stays deny > ask > allow, but default, acceptEdits and Auto ask a human, and plan and dontAsk deny. Missing, dropped, denied or cancelled approval dispatches nothing. ACP's channel without human-only attestation refuses; a human-capable serve channel may approve. Write prompts offer once/deny only. A committed `ToolStarted` verdict with source `human` precedes launch; replay rejects rule-only or AI-only host write approval and any Guard or unguarded receipt for that intent.

**Execution and credentials.** Authentication inputs are captured at Run admission from the launching user's configuration and environment, before repository Skill discovery. Credential values never appear in intents, catalog, Provider context, journal, diagnostics or result text.

- HTTPS snapshots the user-owned XDG Git config, then `~/.gitconfig` (64 KiB<!-- unrelated-bound: user Git config file --> each). The pinned Git reads every credential entry in file order with `config --file … --no-includes --null --get-regexp`; any include/includeIf refuses, since an omitted file could reset credentials. Entries pass in order through `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n`, never argv, so Git itself applies matching sections, helper resets and chains, username and useHttpPath. The query has a five-second deadline, 128 KiB<!-- unrelated-bound: Git credential query stdout --> stdout, 256 entries and 4 KiB<!-- unrelated-bound: Git credential query stderr capture --> stderr, with an explicit private GIT_DIR. Missing or malformed credential configuration refuses; an intentional reset stays effective. Repository helper settings never apply.
- Helpers are searched after the private pinned Git directory only in admitted root- or user-owned, non-group/other-writable `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` and `/bin`; unsafe directories are skipped, none admitted refuses specifically, and ambient PATH never applies.
- SSH requires the launching `SSH_AUTH_SOCK` and uses fixed `/usr/bin/ssh` with no SSH config, batch mode, no identity files or forwarding and strict host-key checking. Missing helpers or agents refuse; no login or prompt starts.
- gh uses the user's bounded `hosts.yml` record, copied into an exclusive 0600 file in a 0700 temporary configuration directory that is also its home. The host is github.com unless a literal `host:` in the user's gh config selects another. User config must be an admitted regular file owned by the current user and not group/other-writable.
- Host scratch is an owner-only, non-symlink `host-scratch` directory under the admitted State root (never `TMPDIR`) with 64 slots; exhaustion refuses before dispatch. Each slot's private lease file is locked before its directory is created and held through removal; startup removes stale directories only under their leases.
- Program verification and the private gh copy have a separate 256 MiB executable limit. gh is streamed once through a 64 KiB<!-- unrelated-bound: gh executable copy buffer --> buffer into an exclusive 0500 file while hashing; a mismatch or copy failure unlinks it. Only the verified copy executes.

**Neutralized view.** Every host write runs from a disposable neutralized repository view holding only the approved branch ref, HEAD and a fixed private config. Push links the admitted object store read-only by convention (not an OS mount), never copying or counting objects; PR creation gets an empty object directory. PR listing and inspection use an empty private Git directory and an explicit repository and never inspect the Workspace repository. No host Git process sees live repository config, and no incidental tracking-ref update reaches it. Unsupported layouts and object alternates refuse writes. Host write admission keeps the HEAD 256-byte and repository config 64 KiB<!-- unrelated-bound: repository Git config cap --> bounds but never reads the index (the [32 MiB](./limits.md#max_snapshot_bytes) index bound is for local views); packed refs and shallow metadata are bounded to 32 MiB<!-- unrelated-bound: host private Git metadata --> each, and a preparation refusal names the bound. After a dispatched push, Arany rechecks the Git directory and object-store identities and the absence of alternates; a mismatch records Uncertain. A replacement restored before that check, or a brief alternate during execution, is not reliably detected. Repository includes, sshCommand, insteadOf, pushurl, hooks, filters, signing, aliases, pagers, editors and extensions supply no authority. The environment is cleared; Git system/global config, interactive auth and HTTPS redirects are disabled. gh receives fixed arguments and an explicit repository, so it cannot implicitly push, fork, paginate or select another repository. User credential helpers are user-authorized host code. Only the primary Git and gh binaries are hash-pinned: `/usr/bin/ssh`, `git-remote-https`, their libraries and user-selected helpers are trusted host components.

**Bounds and outcomes.** The Host Git row in [Limits and failure behavior](#limits-and-failure-behavior) defines payload and runtime bounds; stdout and stderr use the Typed Git reads capture caps there, and overflow terminates the process group. Malformed or control-bearing write data refuses (body newlines are allowed). One Git write is in flight per Workspace. After approval, one monotonic deadline covers scratch acquisition, preparation, credential setup and execution; a preparation timeout refuses before dispatch, and the cleanup allowance is separate. Human waiting follows the [shared approval contract](#folder-trust-and-approvals), consumes neither Goal active time nor the host runtime allowance, and cannot invalidate the approved intent. Cancellation and the deadline are rechecked immediately before spawn. Raw process output is always discarded, to prevent credential disclosure. Outcomes:

- A confirmed zero exit with confirmed group teardown records a host receipt and fixed completion text.
- A confirmed exit 1 with exactly one Git porcelain rejection for the pinned refspec, `(non-fast-forward)` or `(fetch first)`, is Failed with fixed “remote reported no ref update” text. This does not mean nothing was uploaded: HTTPS can upload a pack before rejection.
- For PR listing or inspection, a confirmed nonzero exit, invalid JSON or capture overflow is Failed with fixed bounded text.
- Timeout, cancellation after launch, lost acknowledgement or unconfirmed teardown is [Uncertain](./execution.md#effect-outcomes). So are write authentication errors and gh's PR-already-exists diagnostics, which do not prove the absence of a remote effect.
- A crash after the committed approval without an outcome stays unresolved on replay.

Rewind marks host effects with a receipt, an Uncertain outcome or an approval without outcome as non-rewindable; nothing undoes, completes or rolls back a push or PR.

Host execution has no Guard filesystem, network, CPU, memory or process-count isolation, remote transfer or storage bound, DNS isolation, or containment of descendants escaping the process group; human approval and time/output bounds are its controls.

## Typed Git writes

Typed Git writes let the primary commit, create branches and switch like [Claude Code](https://code.claude.com/docs/en/permissions#bash) and Codex CLI agents running `git`, while keeping per-effect isolation: Git runs inside the Guard on a neutralized private view, and only Arany's code publishes the validated result into the real repository. [Human-approved host Git](#human-approved-host-git) owns push and PR creation; [typed prefix rules](#typed-prefix-rules) remember approval for the three local verbs.

1. **Availability.** Writes need the [typed Git read](#typed-git-reads) pin and whole-Workspace grant, `write: true`, and either Linux Landlock ABI 3 or later or the macOS executor and publisher profiles. Otherwise only reads are listed, with a `git_branch` schema fixing `name` and `start_point` to null, so plan mode can still list branches. **On macOS each local verb uses two Guard units** ([item 4](#typed-git-writes)), because Seatbelt cannot further restrict a child of a sandboxed unit. Writes are primary-only, never offered to researchers or editors, never Goal success criteria, and admitted by a plan contract only with `.` scope. Unsupported layouts fail as for reads.
2. **Operations.** `git_commit {message, paths, staged}` commits to the current local branch either distinct literal Workspace-relative `paths` (`.` for every change), whose working-tree contents, including new and deleted files, are committed with Git's `--only` semantics while protected components stay uncommitted; or, with `staged: true` and empty `paths`, the index exactly as staged. Other staged entries stay staged. The message is non-blank UTF-8 with no controls except newline and tab; Git's default whitespace cleanup applies. `git_branch` with `name: null` is the [branch discovery read](#branch-discovery); creation requires `scope`, `base` and `max_count` null and creates `name` at `start_point` (a read revision, HEAD when null) without switching or tracking; an existing name fails. A start point that is a symbolic ref other than HEAD (any `ref:` content), such as `origin/HEAD` or a bare remote name, refuses, as does creation while HEAD points outside `refs/heads`. Names use the read ref-name grammar without ancestry steps, are never `HEAD`, and may not differ only by ASCII case from an existing ref or ref directory. `git_switch {branch}` moves HEAD to an existing local branch; the current branch returns `switched: false` and publishes nothing. There is no amend, signing, force, delete, detach, merge, remote or raw-argument escape.
3. **Results and receipts.** A commit returns `{"commit","branch","publication"}`, a creation `{"branch","oid","publication"}` and a switch `{"branch","switched","files","publication"}`. `publication` is `{"objects","files"}` plus, as applicable, `"ref": {"name","before","after"}` (`before` null for a new branch), `"index": {"before","after"}` (SHA-256 of the real index, `before` null when absent) and `"head": {"before","after"}`. Receipts carry object and branch names, never file paths. Failures return `{"failed"}` with filtered diagnostics and publish nothing; under Read-rule filtering a failure keeps only its message, and a switch refusal never names a hidden path.
4. **Neutralized mutable view.** A fresh view in Guard scratch holds the read configuration plus `logAllRefUpdates`, `commit.gpgSign`, `gc.auto` and `maintenance.auto` off; copies of HEAD, the index with its mtime, `packed-refs`, `shallow` and the `refs` tree (skipping another Git's `*.lock`); and a private object directory borrowing the real store as an alternate, so new objects stay private until publication. On Linux each Git child is spawned from a thread confined by a Landlock domain (ABI 3 or later) denying every write, truncation, link, rename and node creation outside scratch and `/dev/null`, and by seccomp filters denying mode, owner, time, extended-attribute and `file_setattr` changes, every `ioctl` (`ENOTTY`) and every syscall newer than the policy knows (`ENOSYS`). Git can read the Workspace and real `.git` but never change them; the Guard keeps access for publication. A missing facility fails closed before Git runs. Repository configuration, includes, hooks, aliases, `core.sshCommand`, filter, diff and merge drivers, signing programs and fsmonitor never apply. The environment gains only `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME` and `GIT_COMMITTER_EMAIL`; commits use `--no-verify` and `--no-gpg-sign`, timestamps are UTC, and no reflog is written.

   **macOS** reserves an executor and a publisher unit together in one admission, so the publisher is never starved after Git ran; a reservation above the shared capacity fails `Limit` at once. The executor profile reads the Workspace and `.git`, writes only its view volume, runs only the pinned Git, has no network, and denies the `F_MAKECOMPRESSED` and `F_TRANSFEREXTENTS` fcntls (as Codex CLI's Seatbelt policy does); its helper closes inherited descriptors above standard error first. It plans as on Linux and streams one hashed frame of at most [`WRITE_FRAME_BYTES`](./limits.md#write_frame_bytes) to the controller, which relays it chunk by chunk, verifying length and SHA-256, to the publisher. The executor's helper stays alive, bounded, until the relay is acknowledged. The controller relays only while the executor's helper is alone in its coalition, then tears the executor down and waits for an empty coalition before sending GO, so no executor process exists while the publisher holds locks; the publisher takes none before GO. The publisher profile allows Workspace read and write (never `.git/config` or `.git/hooks`), no process execution and no network; it re-validates the frame, repository identity, locks and drift (item 8) and copies new loose objects opaquely. A truncated, oversized or mismatched transfer, or cancellation before GO, publishes nothing. Claude Code and Codex CLI run Git in one sandbox with protected paths or a read-only `.git`; Arany splits executor and publisher for journal-first receipts and neutralized configuration. Residual risk: a compromised Git could emit a malformed object that a later read rejects but never executes.
5. **Identity.** Private `tools.json` may set `git_identity` (`name` and `email`, without controls, `<` or `>`, no whitespace in the email). Otherwise folder trust reads only `user.name` and `user.email`, as data, from `$XDG_CONFIG_HOME/git/config` (default `~/.config/git/config`) and then `~/.gitconfig`, the later winning per key; includes, escapes and environment overrides are ignored. Without both values commits use `Arany <arany@localhost.invalid>`. Repository configuration never supplies the identity.
6. **Commit and branch rules.** A commit needs HEAD on a local branch. A switch refuses from a detached HEAD, whose commits no reflog would keep reachable; creating a branch from a detached HEAD is allowed. `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `BISECT_LOG`, `rebase-merge`, `rebase-apply` or `sequencer` refuses commits and switches. Git itself refuses empty commits and unmerged entries. An unborn branch can receive its first commit.
7. **Switch rules.** After a private index refresh, a switch refuses when a path changed between HEAD and the target is modified in the index or working tree; an untracked or ignored entry occupies an added path; an entry is a symbolic link or submodule; a path is protected, invalid or too deep; or two planned paths or their parents differ only by ASCII case, or alias an existing Workspace name by case. The failure lists the first conflicts. A file-to-directory or directory-to-file transition refuses with a message to switch in your own terminal, even from a clean tree. Each preimage is captured only while its bytes and executable bit equal HEAD's blob, so a racing edit refuses instead of being overwritten. The switch writes raw blobs without end-of-line or attribute conversion, creates files `0600` (`0700` when executable), removes deleted files and leaves emptied directories. The new index comes from Git's two-tree `read-tree -m`, keeping unrelated staged entries. On macOS the frame carries replacement bytes, executable bits and preimage digests, and the publisher checks every live preimage under the locks before replacing any file.
8. **Publication.** Before the first effect the Guard takes Git-compatible exclusive locks on every target it replaces or read: the branch ref, `index`, HEAD (even when unchanged), a switch's source and target refs, a new branch's start ref (HEAD's referent by default) and `packed-refs`. Ref path components are admitted with exact case; a directory created for a lock is synced and removed again unless the lock commits. Under the locks, HEAD, `packed-refs`, every loose ref and the index digest must equal the view's snapshot. A held lock, any drift or a replaced `.git` returns `Failed` with nothing published; locks only held are removed afterwards. Publication then writes switched files through the [changeset publisher](#command-changesets) (digest-checked, no-follow, fresh inodes) and new loose objects (`0444`, renamed without replacement; existing objects kept), and renames the ref, index and HEAD locks, syncing each directory. This is not a transaction: any failure after the first effect is [Uncertain](./execution.md#effect-outcomes), and reopen and replay neither complete nor roll it back. [Rewind](#checkpoints-and-rewind) does not undo Git writes.

   **Stale locks.** Before its first lock the Guard writes `.git/arany-locks-<intent>.json`, recording each lock's path, device, inode and SHA-256; the record goes with the locks. If the Guard dies, nothing moves or deletes its locks. After the Guard unit is confirmed stopped, the controller (and Goal resume, after private recovery) reports every recorded lock still at the recorded inode with the recorded bytes as the typed `StaleGitLocks` error, naming the paths and saying to remove them once no git process runs; other inodes or bytes are not reported, and a record with no remaining lock is removed. The report leads the write's Uncertain observation, so `show`, `exec` and serve carry it whole; the terminal wraps it, escaped, over at most eight continuation rows plus a remainder count. Record paths admit only the ref-name alphabet. Goal resume returns the report before refusing to resume past the unsettled write.
9. **Policy.** Writes ask like commands: Request and Auto edits ask a human, Auto approval reviews them and `plan` denies them. A matching ordinary (`git_commit`, `git_branch`, `git_switch`) or typed allow rule pre-approves them in `default` and is required in `dontAsk`; `acceptEdits` and `auto` ignore it, and the [typed-allow mode mapping](#modes-and-approval-decisions) owns the rest. Commit paths, including `.` and ancestors, cannot bypass restrictive rules on their descendants. Rules and hooks only narrow; the Guard and pinned grant still apply. The [limits table](#limits-and-failure-behavior) owns every bound; a result budget below its minimum records `Limit` before any effect.
10. **Platforms and non-claims.** Git still reads the whole Workspace under the Guard. Linked worktrees, submodules and signing are unsupported. On macOS, cancellation before publisher dispatch records Cancelled without attestation. The publisher counts as dispatched before any GO byte is sent, so cancellation after a partial or complete GO is Uncertain unless a completed receipt settles it. Each intent has one start and one terminal observation. Executor timeout, view exhaustion and repository replacement publish nothing. Publisher death after the first effect is Uncertain, even if only Workspace files changed, and surviving locks are reported as in item 8. Both capacity reservations stay held until unit cleanup and view-volume detach complete.

## In-process file operations

Exact Read, exact-file Search and Skill text reads run in the Engine process, as peers do for explicit files. List, directory Search and Glob run in the Guard because their ignore parser consumes hostile repository data. Write, Edit, MultiEdit, Mkdir, Delete, Move and primary ApplyChangeset publication run in process on Linux and macOS, following Claude Code's exact replacement and Codex CLI's in-process patch application; editors use the same path under their child identity and lease. Typed Git reads, commands, Skill loading, Skill scripts and MCP stay in the Guard. In-process operations run with the Engine's privileges, bounded only by the handle-relative checks below; they never spawn, use the network or widen disclosure beyond the admitted grant.

Tool admission still requires native protection. The Engine opens the Workspace directory handle once at admission and resolves paths beneath it with no-follow, link, mount, special-file and protected-name checks within `workspace_paths`. Dispatch checks the intent, policy digest and directory identity; a replaced Workspace records Failed at `pinned input` without attestation. A failed discovery never starts an exact read. Missing or unsafe exact paths record attested Failed or Denied observations that permit continuation; content comes only from an admitted regular file.

In a primary or researcher multi-call step, exact Read, exact-file Search and Skill text calls run concurrently under the [file-operation capacity](#limits-and-failure-behavior), each with its own bounds; full capacity records Limit without reading. [Execution](./execution.md#committed-event-stream) owns step ordering. A path that stops being an exact file never falls back to Guard discovery. Read completions commit while a sibling waits for hooks, review or approval. Cancellation, Uncertain, Limit or a hook stop ends dispatch: a pending sibling approval is withdrawn, dispatched reads drain, and each remaining intent gets a `not_dispatched` observation. Started hooks and reviews settle under their bounds; nothing new is admitted or escalated, and a late approval cannot dispatch the withdrawn call. This follows [Claude Code](https://code.claude.com/docs/en/agent-sdk/agent-loop#parallel-tool-execution) and [Codex CLI](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/parallel.rs) parallel read-only dispatch.

Results fit the intent's rendered (model-facing serialized) result budget: List and Glob drop trailing rows and set `may_be_truncated`, Search pages as [below](#limits-and-failure-behavior), and a budget too small for any content is Limit. Read follows Claude Code's 1-based line paging: nullable `offset` defaults to 1 and nullable `limit` defaults to and caps at [`MAX_READ_PAGE_LINES`](./limits.md#max_read_page_lines). Lines are cut at [`MAX_READ_LINE_CHARS`](./limits.md#max_read_line_chars) characters with `… [line truncated to <MAX_READ_LINE_CHARS> chars]`. Read streams the file with its whole-file SHA-256 and returns numbered `N\t` lines as `{sha256, total_lines, start_line, end_line, next_line, truncated, text}`. CRLF is one line ending; invalid UTF-8 fails. A page ends at the line limit or the budget; `next_line` is the next unread line or null at EOF, and `truncated` marks more pages or a cut line. An empty file or an offset past EOF returns empty text, `total_lines`, `end_line: start_line - 1` and null `next_line`. Each page is the committed observation; replay never rereads. Repeating a Read of an unchanged file with the same arguments returns the same page. A crash before `ToolFinished` replays the read as Interrupted with its active-time reservation still charged. Timeout is Limit and cancellation Cancelled, neither attested. A read takes no Guard capacity and reserves its Goal action with zero preparation overhead; its runtime is clamped to the remaining active time, and exhausted time refuses it.

`Read { path: "spill:<digest>", offset, limit }` pages a spill file through a separate private-directory capability. The digest must be 64 lowercase hex characters; other `spill:` shapes reject before opening. Only references committed in this Session's own Runs authorize access; guesses, other Sessions and inherited fork history grant nothing. Workspace and plan scopes do not apply, but Read permission rules do. Unknown references record attested `Failed` with `no spill for this Run`. No-follow, owner, private-mode, single-link, regular-file and same-device checks apply. The Guard never receives StateRoot paths or handles.

A valid, in-scope, non-protected missing path (including one under a regular-file ancestor) records attested `Failed` with `File or directory not found; List the parent directory to check the path`, like OpenCode but without suggestions. Links, mounts and special files stay `Denied` with `File path is unavailable or outside the admitted regular-file boundary`; protected and out-of-scope paths keep their grant denial.

Each observation carries an `attestation`: `in_process` (policy digest, Workspace device and inode) or `guard` (Guard receipt). Validation and replay reject in-process attestations for List and Glob, and Guard receipts or bootstrap causes for Skill reads and in-process mutations; live Guard dispatch refuses exact Read and Skill text. Successful mutations carry `FileReceipt { intent_digest, before, after, executable }` in the attestation, binding intent and result: Move keeps the digest, Delete has no after digest, and Mkdir and batch ApplyChangeset have no single-file digests. Historical Guard mutation intents keep their own enforcement digest and labels and replay unchanged. Worker discovery wraps its profile-identifying Guard receipt in `worker_read`.

"Guarded Edit" means this in-process Edit with its FileReceipt and checkpoint; there is no Guard Edit path, as in Claude Code and Codex CLI.

Writes use digest or create preconditions, no-follow handles and a fresh inode with atomic replacement, never in-place truncation. Parents must exist: a missing Write or Mkdir parent records attested `Failed` with `Parent directory not found; create it with Mkdir first`; a missing Edit or MultiEdit target gets the not-found result. Symlinks, hard links, special files and stale preconditions reject. This is not a transaction against concurrent host edits, a rollback guarantee or protection from a hostile same-user or root process.

ToolStarted commits before any mutation byte, and checkpoint capture precedes dispatch. A blocking task keeps its capacity slot until it exits. Cancellation is checked before temporary creation and before publication; once publication begins it completes and records success, then the Run stops Cancelled. A deadline before publication is Limit; after publication begins it is [Uncertain](./execution.md#effect-outcomes), as is a failed parent-directory sync. Failed temporary writes or pre-publication renames leave the target unchanged. Death between publication and ToolFinished leaves an Interrupted intent that resume never retries. There is no Guard preparation or pre-GO stage.

### Typed read discovery

List, directory Search, Glob and [file suggestions](./terminal.md#interactive-commands-and-completion) apply the shared [ignore-control admission](#command-input-selection) before opening payloads. Only admitted root and nested `.gitignore` files supply rules, also outside Git repositories, with the same precedence, escapes, negation and ancestor pruning as command selection; tracked files are not exempt. Naming a nested or ignored directory keeps its ancestor rules. Query patterns only narrow candidates. Protected names, generated-directory exclusions, grants and Read restrictions stay dominant, including case variants and descendants. An inaccessible required control rejects generically; confirmed absence is allowed. Unsafe, oversized, malformed or inaccessible controls discard results without raw rule diagnostics.

List and Glob read metadata only. Vanishing descendants and absent scope roots are omitted; an explicitly requested missing base gets the not-found result. A required-control change rejects the whole selection. Directory Search opens only selected regular files, so oversized ignored files cannot fail it. Filtering precedes sorting, pagination and fitting. Exact Read and exact-file Search of an admitted ignored file keep their permission decisions without loading controls; protected names stay refused. Includes, Skills, commands and Git keep their own disclosure contracts. The model cannot override ignores; unlike Claude's default Glob, consistent omission deliberately narrows incidental disclosure.

Selection runs single-threaded in the default native unit, within the [512 MiB](./limits.md#memory_bytes) envelope and shared FIFO capacity. It waits at most 250 ms for capacity, including locks and recovery; full capacity or expiry is busy (`QueueFull`, model `Limit / ReadCapacity`) without dispatch or retry. The [Terminal contract](./terminal.md#interactive-commands-and-completion) owns composer suggestions. Selection is bounded by 1,048,576 matcher calls, including ancestor checks, and two seconds, shortened by the Tool or Goal deadline: count or expansion exhaustion is `Limit(resource)`, elapsed time `Limit(timeout)`. Walks keep the scan, path, content and result bounds and depth 16, including control filenames. Failure discards partial results; cancellation keeps ownership until confirmed cleanup; neither starts an exact Read or host operation. Strict replay projects committed observations without rereading controls or names.

### Glob file discovery

`glob` takes `{pattern, path, limit}` and returns admitted regular files whose path relative to `path` matches `pattern`, copying Claude Code's and OpenCode's call shape and 100-file default. `pattern` is 1–512 UTF-8 bytes; `path` is a Workspace-relative directory; `limit` is 1–100. Strict schemas expose `path` and `limit` as required nullable fields; null, omitted or empty `path` becomes `.` and a missing limit 100 before hashing, so permissions, hooks and replay see one form. Out-of-range limits are refused, not clamped.

The grammar is closed and case-sensitive. The whole relative path must match. `*` matches any run and `?` one character within a component. `**` must be a whole component: `**/` crosses zero or more directories and a terminal `**` matches the rest, so `*.rs` matches only files directly in `path`. One level of `{a,b}` gives literal or wildcard alternatives within a component, at most 16 in total. Bracket classes, backslash escapes, a leading `!`, absolute or `~` prefixes, controls, empty, `.` or `..` components, nested, empty, single or unclosed braces and partial `**` are refused before traversal, never reinterpreted as literals. The translated regular expression is at most 8 KiB<!-- unrelated-bound: glob regex translation bytes -->, compiled with a 128 KiB<!-- unrelated-bound: discovery regex compiled size --> size, a 32 KiB<!-- unrelated-bound: regex DFA cache --> DFA cache and 32 nesting levels; overflow refuses. Claude Code accepts bracket classes; Arany refuses them to keep the grammar closed. Permission path patterns have their own semantics.

Glob never opens contents, so it reports sizes beyond the [1 MiB](./limits.md#max_file_bytes) content cap and supplies no SHA-256 or edit precondition. It walks like List: protected components (`.env`, `.env.*`, `.git` and the rest), symbolic links, hard-linked and special files, other mounts and non-UTF-8 names are skipped, and a whole-project grant also skips `target`, `node_modules`, `.venv` and `venv`. Other hidden names match normally. A pattern without `**` does not descend past its component count. The walk inspects at most 8,192 directory entries, keeps at most 2,048 matches, depth 16 and paths of 512 bytes<!-- unrelated-bound: Glob discovery path bytes -->; exceeding any bound is Limit, never partial success.

The result is `{entries: [{path, bytes}], limit, may_be_truncated}`: Workspace-relative paths, deduplicated across roots and sorted by UTF-8 bytes before the first `limit` are kept. `may_be_truncated` is true only when another match exists or trailing entries were dropped to fit, so exactly `limit` matches is complete; if nothing fits, Limit. There is no paging. Claude Code orders by modification time; Arany uses path order so the observation does not depend on mutable timestamps. A `path` naming a file records Failed, a missing path not-found, and a link, mount or special file Denied. Editors use the same guarded Glob within their read grant; a missing leased creation root records not-found.

## Typed delete and move

`delete {path, expected_digest}` removes one existing regular file. `move {source, destination, expected_digest}` moves one existing regular file to an absent destination, creating missing destination parents, and preserves its bytes and executable status. The digest is the source's lowercase SHA-256 from Read or a file include. Neither removes directories or overwrites; identical and ASCII case-only moves reject. Missing sources fail; stale digests and occupied destinations conflict. Protected names, unsafe ancestors, links (including hard links), special and set-ID files, mount crossings and filesystem aliases refuse. File-version, argument, result, action and checkpoint bounds apply; overflow publishes nothing.

Both are Edit-family mutations under the write grant, modes, hooks and Goal scope. Move needs both paths within the grant, plan and any editor lease: one allow rule must cover both, while a deny or ask, or a Read denial, on either applies. Hooks see `Edit` with the complete typed call; unsupported rewrites deny. Summaries and approvals name every path inertly. Researchers cannot call them; editors need the `delete` or `move` capability and use the [editor mutation path](#editor-tool-steps). Primary effects refuse overlap with an active editor lease on either path.

One call is one journaled intent and result, published by the [in-process publisher](#in-process-file-operations) after validating source bytes, digest, executable status, the absent destination and parent identities. Move writes a fresh destination inode, then deletes the source with changeset integration's checked deletion and directory sync; it is not an atomic multi-file transaction. Failure or drift after any publication, lost completion or unconfirmed durability is [Uncertain](./execution.md#effect-outcomes), with no rollback claim; cancellation before publication changes nothing. Results keep the removed file's digest, length and executable status. Checkpoints save the source first; rewind restores it and removes the destination. Strict replay validates receipts without touching files.

Codex CLI's [apply-patch](https://github.com/openai/codex/blob/main/codex-rs/apply-patch/src/lib.rs) supplies the delete and move semantics, and [Claude Code](https://code.claude.com/docs/en/tools-reference) uses Bash for filesystem commands; Arany offers closed typed operations because generic command changes must pass changeset publication.

## Atomic single-file MultiEdit

`multiedit` takes `{file_path, expected_digest, edits: [{old_string, new_string, replace_all}]}` and edits one existing regular UTF-8 file under Edit's path and SHA-256 precondition rules. Unknown fields reject at both levels. `replace_all` defaults to false (strict schemas: required nullable, null meaning false); intents store the effective boolean.

It applies 1–64 literal replacements in order, each to the previous result. False needs exactly one non-overlapping match; true replaces all and needs at least one. Empty searches, identical old and new strings and an unchanged final result reject. Text stays literal: no quote normalization, newline removal or token expansion. Dependent edits (A → B, then B → C) work. Any missing or ambiguous match leaves the file unchanged.

[Limits](#limits-and-failure-behavior) owns the replacement, input, file-size and argument ceilings. The original, each intermediate result and the final content stay within the file-size ceiling, checked before allocation; overflow refuses the batch. At most 64 passes run, without recursion or retry.

The change publishes once through Edit's fresh-inode replacement with before and after digests, lengths and executable bits, so readers see either version. Stale digests, invalid UTF-8, unsafe paths and match or bound failures publish nothing; so does cancellation before publication. Interrupted publication or unconfirmed durability is [Uncertain](./execution.md#effect-outcomes). One batch is one intent, permission decision, action and outcome; replay uses its receipt without touching the file.

MultiEdit is in the Edit permission family, including `acceptEdits`, path restrictions and read-denial protection. Hooks see `MultiEdit` with the whole batch under the hook-input ceiling; unsupported rewrites deny. Researchers cannot call it; editors need the `multiedit` capability within the parent grant and lease. Model results omit checkpoint metadata. The terminal shows one `MultiEdit(path, N edits)` outcome, and approval shows every replacement in order.

Field names, defaults, match checks, no-op rejection and the permission family follow Claude Code 1.0.128 ([evidence](../research/claude-code-multiedit-evidence.md)); ordered intermediate results follow [OpenCode v1.1.13](https://github.com/anomalyco/opencode/blob/v1.1.13/packages/opencode/src/tool/multiedit.ts#L21-L35) by owner choice. Existing-file scope and the 64-edit limit are owner decisions; peers' implicit creation, fuzzy matching and partial writes are not copied.

## macOS enforcement and compatibility

Primary Workspace mutations allocate no Guard unit or image. Discovery, Skill loading and definition parsing use the non-spawning profile, which never grants Workspace writes. Typed Git reads use a third profile that may spawn only the pinned Command Line Tools Git, with no command catalogue, runtime grants, network or Mach lookup. Commands and MCP run native binaries with ordinary child launches, including `posix_spawn`; a fork/exec-only profile is insufficient.

Dispatch requires an available Background launchd user domain, a distinct kernel resource coalition, a trusted bounded supervisor and a separate attested Seatbelt worker. The private control directory lies outside the Workspace; overlap rejects. Without the Apple compiler and SDK profiles, a guarded command cannot read or execute the Command Line Tools or an SDK, even where the host baseline allows it. A stale executable pin rejects before any Provider request and keeps the committed history prefix. The supervisor's launchd PID and authenticated peer must be one process. Completion is accepted only after the coalition is empty and the one-use job is removed or reported absent; job retirement is not descendant cleanup. There is no unsandboxed fallback. The launcher runs in its own process group so descendants cannot hang up the supervisor; a PID or process group is not containment, the coalition is.

Before Tools are offered, admission validates the immutable `launchctl`, `env` and `hdiutil` through no-follow OS-program admission, then coalition observation and the launchd domain with a data-free probe (three-second deadline, one second for kill and reap). Availability is not attestation: unit authentication, coalition ownership, storage preparation and installed enforcement are checked before GO. Deadlines and native-manager failures name their stage without native diagnostics; cleanup failures keep their own stage and block acceptance.

Teardown (supervisor stop, launcher reap, stderr EOF and storage-cleanup retries) shares one ten-second bound; MCP server reap and stderr drain share a second, equal bound in the worker. Member enumeration failing during exit is retried within it. Storage cleanup makes at most eight attempts with pauses growing by 250 ms while time remains, so a transiently unlistable inventory is retried; a path-less entry rejects. A device that leaves the inventory before its detach re-check is never detached; only a later fresh inventory and mount check can accept. Disk-image commands keep their own bounds, so teardown can outlast the shared bound; the completion deadline then makes the call [Uncertain](./execution.md#effect-outcomes). Only observed termination and detachment accept.

Failed teardown names a closed stage (process cleanup, launcher reap, output EOF or storage cleanup) as the Guard stage; no worker text reaches the model. The failed storage check (inspection, listing unavailable, device unlisted before detach, detach failed, image still listed, mount still present) and post-dispatch execution check (worker closed before report, worker panicked, malformed, unattested or unterminated report, cancelled, controller thread failed) go only to the debug development log; the model-facing stage stays execution. Supervisor stdout and stderr go to one owner-only file in the unit root, deleted with it; it holds only panic text, capped at 4 KiB<!-- unrelated-bound: macOS supervisor panic output -->, and fixed fatal-abort lines. On early worker close the controller reads at most the last 4 KiB<!-- unrelated-bound: macOS supervisor diagnostic tail --> to classify a panic, keeping the printable tail for the debug log and test recorder. Privileged OS mutation stays outside the current-user boundary.

Supervision uses kernel process identity, membership from bounded kernel metadata (never arguments or environments) and cumulative CPU across exec. Reaped or replaced members retire after identity revalidation, even if sampling fails during exit; an unobserved live member rejects. Signals target exact incarnations, never a reused PID. Memory is aggregate physical footprint plus thread count; a missing observation fails closed. Cleanup needs an exact-target `bootout` that succeeds or reports absence, then positive emptiness.

Default and Build profiles kill the whole unit when a threshold is exceeded or the observer fails. Thresholds are supervised, not kernel ceilings: delays and work between samples can exceed them, and no swap prohibition or group OOM is claimed. CPU is per process, so tree CPU and instantaneous rate are unbounded; Build's threshold follows its wall timeout, the default keeps 15 seconds per process. Since processes can ignore `SIGXCPU`, `RLIMIT_CPU` alone is insufficient: non-spawning profiles reset and unblock it, install hard CPU expiry and forbid handler, mask, signal-wait and limit changes before Seatbelt locks them, while commands and MCP use external CPU supervision. Wall time, output, storage, offline isolation and complete descendant termination are always enforced.

Each unit gets separate owner-only native filesystems sized from the intent: scratch [64 MiB](./limits.md#scratch_bytes), project [64 MiB](./limits.md#scratch_bytes) by default or up to [1 GiB](./limits.md#max_build_project_bytes) for Build, and the cache view with its checked capacity; none enlarges a Workspace bound. Admission reserves the exact sizes against shared capacity before GO. Volumes are fixed-size, case-sensitive images attached kernel-only. The unit root is `/private/tmp/arany-u-<uuid>`, locked by `unit.lock` created in one exclusive open and released by the kernel when the controller exits. The controller durably records root device, inode and boot identity before launching its job; the supervisor durably records process and coalition identity before any task, payload or attachment.

Cleanup empties the coalition before detaching any image, including during preparation unwinds. Image inodes are pinned and the unfinished-attachment marker written just before attachment. Unexpected mount targets reject unfollowed. Unfinished attachment or failed cleanup keeps the root and rejects completion rather than deleting through a live or uncertain mount. Deletion needs positive ownership and device or mount evidence, never a filename prefix.

Before creating a unit, admission scans at most 4096 directory entries and recovers at most eight unlocked roots owned by the effective uid within one 30-second<!-- unrelated-bound: macOS native recovery deadline --> deadline, taking an exclusive lock and validating no-follow records and root identity. Within the recorded boot it removes the exact job and empties the coalition by current audit-token identities; after reboot it signals nothing and leaves later-boot jobs alone. Storage cleanup needs the pinned image inode, the OS disk-image inventory and exact device and mount correspondence; nested or unexpected targets reject, and an attached unmounted owned image is detached. The attachment marker clears only after positive absence following detachment, or proof its boot ended; an empty inventory alone cannot settle a current-boot attachment. Recovery records positive observation before detaching, and root deletion requires no mounts beneath. Roots without valid records, including older ones, stay untouched and count toward capacity like live, recovering and pre-lock roots; valid records are tried first. Unreadable or over-limit listings and deadline expiry reject as unavailable protection without removal advice. Cancellation or failure leaves records recoverable and never retries an old intent.

Commands and MCP get a fresh checked Workspace snapshot, including prior typed edits, and a read-only tree of pinned runtime resources. Writable mounts prohibit set-ID. System executables must be immutable, root-owned, non-set-ID and unentitled. Selected user program directories, Homebrew prefixes and manager roots are a separate user-owned class with read, map-executable and exec permission and without those checks; privileged process, credential and coalition changes stay denied. With commands or MCP enabled, admission checks the bounded executable catalogue once per Run and binds it into each intent and receipt. Workers revalidate each entry through no-follow handles relative to pinned `/bin` and `/usr/bin` (ownership, mode, device, inode, size, timestamps) before Ready; changed or oversized catalogues reject without retry. Signature verdicts are reused only for an identical path and stamp, never persisted; an undetermined one excludes the program for that admission. File and Skill workers carry no catalogue. The runtime excludes account and Session roots, network and Mach services. Root or mismatched real and effective identities reject. Unprivileged `fork`, `exec` and `posix_spawn` stay available.

Seatbelt metadata grants name only required roots and exact ancestors; ancestors such as `/private/tmp` and the unit root grant metadata, never listings, through search-only descriptors, and only the selected final directory opens readably. Admitted runtime directories stay readable; other host paths get no metadata. The command profile also reads `/` itself because the native loader opens it, exposing only top-level names. Commands and MCP may read `/private/etc/ssl` (TLS configuration and CA bundle), because the system LibreSSL behind `/usr/lib/libcurl.4.dylib`, loaded by clients such as rustup proxies, exits when `openssl.cnf` is denied; no other `/private/etc` path is granted, whereas Codex CLI and Claude Code leave system configuration readable. Canonicalized selected roots reject descendant mount targets in `getfsstat` before Seatbelt and Ready/GO, a point-in-time check only.

macOS uses private physical paths, not a mount namespace. The working directory is in the project snapshot. Standalone argv paths under `/workspace`, `/scratch`, `/cache`, `/inputs`, `/skills` or `/programs` map into private storage, and copied-program aliases apply to copied executables. Shell strings are not rewritten; scripts use `ARANY_TOOL_WORKSPACE`, `ARANY_TOOL_INPUTS`, `ARANY_TOOL_SKILLS` or relative paths. On both platforms the pinned `/bin/sh` accepts only argv starting with `-c` followed by a script that does not begin with `-` or `+`; anything else is refused before the shell starts. Unlike Codex CLI and Claude Code, Arany never starts a login shell or sources profiles, preserving per-effect isolation; a script may source a file it names. The Guard prepends one fixed prefix exporting the quote-escaped page-size helper path, never rewriting options into script text. `HOME` and `TMPDIR` point to scratch. System binaries run at their original paths.

The environment is cleared; `SDKROOT` is set only for the exact Apple SDK profile. The embedded universal (arm64, arm64e, x86_64) page-size dylib is staged privately, read no-follow under a 128 KiB<!-- unrelated-bound: embedded compatibility dylib cap --> cap and compared with the embedded bytes, which the enforcement digest binds. It answers only `sysconf(_SC_PAGESIZE)` and `getpagesize()` from `vm_page_size`; sysctl stays denied without exception. Host CPU discovery stays denied; selected-Rust Build commands get the Goal-pinned jobs default. Because SIP can strip `DYLD_INSERT_LIBRARIES`, the `-c` prefix re-exports it; nested SIP-protected shells get no page-size compatibility claim.

The profile denies sysctl, named socket creation, network operations and descriptor-bearing messages, attested before GO so no payload runs under a partial profile. Inherited bootstrap ports are cleared before exec; `NOSUID` does not strip signed entitlements.

Debug builds with an explicit account root and `ARANY_TEST_GUARD_TRACE` may snapshot Guard stages for fixtures: one record per compiled stage, at most 128 bytes each and 8 KiB<!-- unrelated-bound: debug Guard trace aggregate --> total, each `active`, `complete` or `interrupted`. Capture failures never change outcomes, and records never reach Events, context, telemetry or the development log.

## Shared native capacity and settings

Linux and macOS coordinate Guard capacity across processes and Session roots through the effective user's fixed account root. The owner-only file `guard/limits.json` is created on first native admission with:

```json
{"version":1,"units":8,"queued":32}
```

Edit it to change capacity, keeping mode `0600` and the private directory. The account root is `~/Library/Application Support/dev.Arany.arany` on macOS and `~/.local/state/arany` on Linux, from the effective user's account, not Session storage. `units` accepts 1–64 and `queued` 1–1024; unknown fields or versions, unsafe files and invalid ranges reject. Every admission rereads it. Lowering a limit kills no admitted unit or waiter; no new admission exceeds it.

Every Guard unit, file-only included, reserves one slot before launch; live, recovering and retained units count. macOS also reserves the intent's backing-volume sizes, so a per-Goal maximum does not promise concurrent units at that size. Excess roots from an earlier implementation are kept and block admission. A Linux slot owns its host seed until checked deletion. Each seed holds at most [128 MiB](./limits.md#command_snapshot_bytes) of Workspace data and [96 MiB](./limits.md#max_runtime_bytes) of runtime data, so new retained payload is at most `units × 224 MiB` (1.75 GiB by default): a logical bound, not a filesystem quota.

When capacity is full, the approved Tool stays pending; each Run has at most one. Up to `queued` Tools wait in one shared FIFO under the namespace lock; newcomers cannot overtake. Cancellation, the capacity deadline and process death remove a waiter. The deadline starts at post-approval queue entry, is bounded by the pinned runtime allowance and is a capacity refusal, not a human rejection. Native preparation and GO then have their own deadlines, so a short command timeout is not refused because preparation outlasts it; Linux reaches GO within five seconds of preparation and macOS within its worker bound. Overflow rejects before effects. Waiting renews no intent, approval or budget, is not durable, and restart resumes no permission. The [terminal contract](./terminal.md#conversation-progress-and-history) owns the queued indication. Native recovery's 30-second<!-- unrelated-bound: macOS native recovery deadline --> deadline runs within the capacity window; filesystem bounds are cooperative, not hard real time.

Coordination records are no-follow, owner-, mode- and ACL-checked, single-link and bounded. Coordination writes no database records or Events; wait hints use the existing callback. `Drop` reaping respects the attempt and deadline budget. Preparation without a committed identity may only remove an empty directory. macOS control roots count against capacity independently of reservations, deduplicated by UUID.

### Linux host seed ownership

Every host seed keeps its reservation from creation until checked deletion; normal completion leaves neither. After controller death, the next admission recovers owned storage before releasing capacity, without replaying the effect. Failed deletion, identity uncertainty and ambiguous launch keep the charge. A new boot settles processes, not file deletion. Recovery resets a positively identified failed unit before retiring it; a missing or unloaded unit cannot settle an interrupted launch, so its reservation can hold capacity until native evidence or a later boot allows recovery. A locked lease owns one seed record and at most one publication temporary. The planned location is committed before exclusive creation and the directory identity before copying. Launch-requested precedes the launcher, and positive termination precedes recursive deletion. Deletion rejects links, mounts, foreign ownership, unsafe permissions and replacements; incomplete cleanup keeps the slot and blocks completion. Normal admission never migrates or deletes unsupported records. Unrecorded historical roots need the [one-time maintenance procedure](../tools.md#historical-linux-seed-maintenance): Arany stopped, positive native inactivity and authorization of exact inventoried objects, with reboot as the fallback for uncertain inactivity. A name prefix never authorizes removal.

## Linux enforcement and compatibility

Primary Workspace mutations allocate no Guard unit or Workspace mount; typed Git and discovery keep direct Workspace mounts. The non-spawning seccomp filter is used only for non-process rewind handover. [Command input selection](#command-input-selection) covers overlay and copy views.

The enforcer requires non-set-ID, root-owned `/usr/bin/bwrap`, `/usr/bin/systemd-run`, `/usr/bin/systemctl` and `/usr/bin/env`, unprivileged user namespaces, a systemd user manager and cgroup v2 with effective memory, swap, PID and CPU limits and owned termination. `systemd-run` must support `--expand-environment=no`. A selected toolchain whose host path overlaps a fixed Guard mount target rejects with Configuration before seed creation. Other init systems need their own enforcing adapter; unsupported architectures or missing enforcement fail closed. No desktop environment is required.

The supervisor executable must be a regular file without set-ID or group/other write bits (a group-writable umask build may need `chmod go-w target/debug/arany`); unsafe modes fail as `ChangedInput` even with unchanged bytes. The controller opens it once, pins device, inode and SHA-256 and holds the handle through teardown. The supervisor runs that object via the controller's `/proc/<pid>/fd/<fd>` with fixed argv, root working directory and cleared environment, and checks itself against the pin. After clearing capabilities it passes only `/proc/self/exe` to bwrap's [read-only data import](https://github.com/containers/bubblewrap/blob/v0.9.0/bubblewrap.c), which copies it to a private owner-executable `/arany` and closes the source before payload execution; the helper re-verifies the digest and attests a unique private read-only nosuid/nodev tmpfs. The image's byte ceiling equals the default Tool memory allowance, debug symbols included. Binding `/proc/self/exe` after namespace entry is invalid, since it keeps the original mount. Path replacement cannot select new code; unsupported proc-fd execution, import or identity checks fail closed without repinning or path fallback. The supervisor `unshare(2)`s user and mount namespaces itself, maps only the invoking UID/GID with setgroups denied and makes propagation recursively private; no external launcher exists. The AppArmor prerequisite below stays required, with no wildcard or proc-path profile.

For primary Commands the supervisor first mounts fresh nosuid/nodev tmpfs outside the input tree, bytes bounded by the project allowance and inodes by the scan bound plus finite per-grant overhead, and probes `user.arany_probe` xattr set, read and remove. Missing namespace authorization reports `NamespaceEntry` and failed mounts, topology or xattrs `RuntimeMounts`, each `ProtectionUnavailable` before GO. Tmpfs user xattrs need Linux 6.6 or a backport, verified by operation. Each admitted lower is pinned, cloned non-recursively with `open_tree`/`move_mount`, remounted read-only and overlaid with `userxattr,redirect_dir=nofollow,metacopy=off` on private tmpfs upper and work directories. Only merged trees and masks reach bwrap as binds, exact files via `--ro-bind`, with narrow parents read-only. Probe objects must survive overlay create, edit, unlink and recreate before GO. Any cloning, overlay or topology failure refuses with no copy or host fallback.

A granted root containing any host submount (a tmpfs `target/`, a bind-mounted vendor tree, a nested devcontainer volume) refuses as `ProtectionUnavailable` before setup; narrowing the grant avoids it, and a root that is itself a mount is a different case. The bounded mount inventory must be complete, even where the kernel would clone locked children.

User program directories, Homebrew prefixes and manager roots bind read-only and executable at their host paths, parents first; only another selected root may be a descendant mount.

Before forking bwrap or parsing output, the supervisor clears all five capability sets, sets no-new-privileges and verifies the six status fields. It binds a pidfd to the exact bwrap child and reaps it before releasing the namespace. The controller owns bounded reports, READY/GO, cgroup teardown and positive descendant absence before capture. Helper or report death after GO is [Uncertain](./execution.md#effect-outcomes) and publishes nothing. After bwrap exits, the capability-free supervisor runs the bounded capture phase within the selection envelope and deadline, validating the upper and launch baseline and emitting an intent- and namespace-bound candidate or a known refusal; anything else is Uncertain. The enforcement digest binds overlay, mask, probe, capability and pidfd enforcement separately from copy selection, including both cache classes and handle handoff.

Both namespace owners parse bounded namespace-local `/proc/self/mountinfo`. The supervisor attests the private tmpfs identity, flags, limits and lack of descendant mounts before building views; overlay attestation checks each read-only lower, the layers and every mask before READY and again before GO. Before Ready and after GO the helper rejects ambiguous roots, stacked or missing runtime mounts, propagation metadata and descendant mounts under a runtime mount, and attests the project tmpfs (copy) or every merged bind, read-only file, mask, narrow-grant parent tmpfs and absence of unexpected submounts (overlay). Later host mounts cannot propagate in. Read-only binds import source submounts recursively, so sources are checked accordingly.

Before releasing a one-use intent the Guard verifies isolated mount, network, PID, user, IPC and UTS namespaces, dropped capabilities, no-new-privileges, inherited syscall filters and effective limits. It owns the exact transient unit, invocation and retained cgroup, including double-fork and setsid descendants, and verifies termination before accepting completion. The seccomp deny profile is defense in depth, not an allowlist. The ARM64 profile builds from source; no ARM64 support is claimed.

Snapshot byte and entry bounds do not guarantee a finite response from stalled storage or an uninterruptible kernel call; deadlines bound ordinary payloads, not kernel failures. File preconditions are not a multi-file transaction and do not exclude hostile host mutation.

### Ubuntu namespace-entry diagnosis

Creating a user namespace does not grant permission to map IDs or mount in it. On Ubuntu 24.04 [AppArmor lets unconfined executables create user namespaces but denies capabilities inside them](https://documentation.ubuntu.com/release-notes/24.04/#unprivileged-user-namespace-restrictions), giving `ProtectionUnavailable` even with the kernel facilities present. A denial alone does not identify AppArmor: compare the stage, profile labels and capability sets. Namespace authorization and tmpfs user-xattr support are separate prerequisites.

Ubuntu 24.04 ships `bwrap-userns-restrict` as an [extra profile](https://gitlab.com/apparmor/apparmor/-/raw/master/profiles/apparmor/profiles/extras/bwrap-userns-restrict), enabled by default since [25.04](https://documentation.ubuntu.com/release-notes/25.04/#apparmor-profile-for-bwrap). [Codex](https://learn.chatgpt.com/docs/sandboxing#prerequisites) installs it from `apparmor-profiles`, with the sysctl as fallback; Arany also needs its pinned supervisor authorized. [CI](../../.github/workflows/ci.yml) disables the restriction for Linux native lanes, so they do not prove stock-policy compatibility.

When the namespace is denied, guarded commands fail closed as `ProtectionUnavailable` before GO with this diagnosis and the remedy below, rendering the admitted supervisor path as an escaped literal, never a model- or repository-supplied path or a wildcard.

**Preferred one-time administrator step.** Add executable-specific `userns` exceptions for `/usr/bin/bwrap` and the exact installed supervisor path; replace the example `/opt/arany/bin/arany` with the resolved admitted path. Never use a symlink, version wildcard, directory or terminal/shell profile. Review local profiles first and do not overwrite policy or create conflicting attachments. If `aa-status` already lists a profile attached to `/usr/bin/bwrap`, omit `arany_bwrap`; that profile's compatibility with Arany's bwrap invocation is not assumed. [AppArmor denies exec when it cannot choose between attachments](https://manpages.ubuntu.com/manpages/noble/man5/apparmor.d.5.html).

The administrator runs these by hand; Arany never makes policy changes or executes privilege tools, even with a host-command approval.

```sh
sudo tee /etc/apparmor.d/arany-userns >/dev/null <<'PROFILE'
abi <abi/4.0>,

profile arany_bwrap /usr/bin/bwrap flags=(unconfined) {
  userns,
}

profile arany_supervisor /opt/arany/bin/arany flags=(unconfined) {
  userns,
}
PROFILE
sudo chmod 0644 /etc/apparmor.d/arany-userns
sudo apparmor_parser -r /etc/apparmor.d/arany-userns
```

Loading applies without a reboot and persists in `/etc/apparmor.d`. Keep `kernel.apparmor_restrict_unprivileged_userns=1`. Restart Arany from the profiled executable, then retry explicitly. Verify the loaded labels and namespace operations; the profile alone does not establish mount, xattr, overlay or full Guard support. These `flags=(unconfined)` profiles only authorize namespaces for the named executables; Arany still enforces zero payload capabilities, no-new-privileges, seccomp and its grants, and they authorize no host command or wider access.

[Attachments](https://manpages.ubuntu.com/manpages/noble/man5/apparmor.d.5.html) match paths, not digests. If `cargo install`, an upgrade or relocation moves the executable, the new path has no exception until the administrator updates it, and namespace entry fails closed meanwhile. A replacement at the same path keeps the exception, so trust what is installed there. Arany's digest pin rejects a changed binary for an already pinned invocation; restart and readmit before retrying. Do not broaden the attachment to future versions.

**Last resort.** If targeted profiles are unavailable or insufficient, an administrator may by hand choose this temporary system-wide change:

```sh
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

It lifts the restriction for every unconfined application, widening their kernel attack surface, supplies no other missing enforcement and is not profile-enabled evidence. Restore it with `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=1`; it normally resets at reboot unless persisted.

To diagnose from the checkout, in a disposable unprivileged account on stock Ubuntu 24.04, run:

```sh
cargo run --locked --offline -p arany --example namespace_entry_probe
```

The [probe](../../crates/arany/examples/namespace_entry/probe.rs) runs no command payload. It records kernel, package and profile provenance, labels, UID/GID maps, capability sets and positive teardown; on success it also observes a bounded tmpfs mount, write, read and unmount, capability removal and no-new-privileges across exec. A missing entry snapshot is a startup failure. Timed-out children are killed and reaped; cleanup errors or leftover host mountpoints stop the comparison. The probe has its own path and is not covered by the Arany attachment. Neither a probe nor a sysctl-disabled run shows that the profiled supervisor works under the stock restriction or beside an existing `bwrap-userns-restrict` attachment.
