# Terminal: interactive commands

## Interactive commands and completion

In the primary composer, the [compiled registry](../../../crates/arany-cli/src/terminal/commands.rs) owns command names, aliases, argument syntax and availability. Workspace, Provider, Skill or persisted text cannot register or redefine commands. Only an exact lowercase name after a single column-zero slash is command syntax; `//text` submits `/text`. Unknown commands give local suggestions without Provider input. No-argument controls accept trailing whitespace and reject extra arguments in every Run state. Selected children use the [agent-chat input surface](./selectors.md#agent-chats) instead.

Typing `/` at the draft-end caret opens a completion list below the input, even for one match. It shows a header and at most 20 entry rows, clipped to geometry while preserving input and status; the header shows the visible range when the registry is longer. For a bare `/`, Commands and Skills are separate tabs by default, and the saved Combined preference shows both. The active tab has an inverted background, bold text and a bracketed label; the inactive tab is subdued. Left/Right switches tabs only for a bare `/`. Once text follows `/`, one prefix-filtered list holds built-in commands in registry order, then admitted user-invocable Skills alphabetically, regardless of tab or preference. Skill rows carry a literal `(skill)` label before their description, also in monochrome and narrow views. Returning to bare `/` restores the tab. An empty tab activates nothing; an unmatched prefix goes through ordinary unknown-command validation. Up/Down focuses, Tab fills the name and argument space, Enter invokes the selection through normal admission (`/resum` then Enter opens the resume picker), and Escape closes without editing. Exact names, arguments, multiline or mid-draft editing take precedence. Outside the menu, Tab completes a unique registry name or value, or an admitted cached model; ambiguous arguments leave the draft unchanged. Hints distinguish Tab from Enter. Placeholders never enter the draft, submission or Events.

Completion performs no catalog or credential I/O on a keystroke. Provider or account changes invalidate catalog and effort candidates; a same-source redraw or model-only change keeps them. Offered effort levels follow Provider admission; displayed availability is not compatibility evidence.

With supported native Tools and remembered folder trust, or explicit private Tool configuration, `/` also lists admitted project and runtime Skills, at most [64 Skill](../limits.md#max_skills) names under the same geometry and truncation bounds. Automatic discovery uses only `.agents/skills`; other harness and global folders are ignored. Exact folder trust admits project guidance; private selected-root grants cannot expand through discovery. A Skill colliding with a compiled command is omitted, so a Skill named `help` cannot replace `/help`, because untrusted Skill metadata must not redefine built-in controls. `/name [task]` then Enter submits a turn with the Skill attached separately and the whole draft as objective. The slash token, spacing and newlines stay in the accepted message, echo, resumed transcript and copy text; the CLI never strips the token or rebuilds the message, and the admitted name alone selects the pinned attachment. Tab completes `/name ` without submitting; filtering and completion execute no Skill content. Linear input accepts the same `/name [task]` without a menu. During a Run, `/name` is rejected because it starts a new turn. The [Portable Skills contract](../tools/skills-and-mcp.md#portable-skills) owns attachment and loading; invocation grants no authority. Invalid or unavailable configuration gives visible recovery and no Skill candidates. At startup, a root regular `skills-lock.json` without `.agents/skills` gives an `npx --yes skills@1.7.0 experimental_install` notice without reading the lock or running an installer; an existing, even empty, directory does not. `/permissions` refreshes candidates after a trust change.

An exact leading `/name` resolving to a command or admitted Skill shows accent plus bold in the composer; partial and unknown names stay plain. Command recognition uses the parser's literal-space separator and trailing-whitespace trimming; Skills accept general whitespace. Echoed user bodies highlight only an accepted Skill invocation, so `//help` and `/goal /help` stay plain. Styling covers only the leading token across wrapped rows, never edits bytes, and uses cached admitted names while composing and the accepted identity in history, without discovery on redraw. Colorless output keeps bold; completion rows and hints name the command or Skill, and committed Skill headings say `You (skill):` in every mode. These labels sit outside the verbatim body and signal recognition, not execution, success or authority. Child chat keeps literal text-only semantics.

Idle `/settings` and `/limits` take no arguments and edit one private `ui-preferences.json` record, limited to 1 KiB<!-- unrelated-bound: UI preferences record cap -->, through the same panel: numbered `NAME: VALUE` rows in an inline [selector](./selectors.md#selectors), titled `Settings` or `Limits`. `/settings` covers Slash menu (Tabs or Combined), Chat view (Fullscreen or Classic), Copy on select (on or off), Newline shortcut (Shift+Enter by default, Alt+Enter or Ctrl+Enter) and [Guard](../tools/host-commands.md#guard-mode-and-extra-reads) (auto by default, required or off, saved to the account root's `guard.json` instead of `ui-preferences.json`), then `Guard folders ›`, which lists the saved extra read folders and removes the selected one at once (Enter, or `NUMBER` in linear mode), and a seventh row `Limits ›` (linear `Choice 7: Limits: opens /limits`) that opens `/limits` with Enter or `7`; closing `/limits` returns to `/settings` with its edits kept in the draft, and saving `/settings` saves both. `/limits` covers:

- Provider calls, tokens and active time per task (the Goal budget keys), `unlimited` by default, with the default first in each cycle and finite choices after it;
- default and maximum command timeout (2 min and 10 min initially);
- Build memory (4.0 GB), [256 processes or threads](../limits.md#max_build_processes_or_threads), 1.0 GB writable project storage and a Build cache size, `unlimited` by default or a size (`0 B` disables), whose row also shows the private build caches' current total (`Build cache: unlimited (default) · 3.2 GB used`), as [Tools](../tools/commands-and-cache.md#persistent-workspace-build-cache) defines;
- Build jobs and Build CPU cores, each automatic by default or 1–cores; both ranges derive from the controller core count, explicit counts above it are rejected, effective jobs narrow to the process limit, and CPU cores set the Linux quota only ([macOS keeps supervised CPU thresholds](../tools/limits-and-failures.md#limits-and-failure-behavior)).
- Context window, `100%` of the model's window by default, or a percentage from 10% to 100% (`80%`), or a token count from 32,768 to 2,000,000 (`500k`, `1m`, `500000`); `exec` and `serve` Runs read the same saved value, and [Session context](../session.md#context-and-compaction) owns how a Run resolves it;
- Editor changes: files and Editor changes: size, the bounds of one [editor integration](../execution/events-and-outcomes.md#worker-journal-protocol): a count from 1 to [`MAX_EDITOR_CHANGE_FILES`](../limits.md#max_editor_change_files) and a whole-MiB size up to [`MAX_EDITOR_CHANGE_BYTES`](../limits.md#max_editor_change_bytes), defaulting to [`DEFAULT_EDITOR_CHANGE_FILES`](../limits.md#default_editor_change_files) and [`DEFAULT_EDITOR_CHANGE_BYTES`](../limits.md#default_editor_change_bytes), with no `unlimited`.

These are configured policy bounds, not measured platform support or a disk-space guarantee; the shared [Goal defaults](../goals.md#lifecycle-budgets-and-recovery) keep [`MAX_GOAL_RUNS`](../limits.md#max_goal_runs) and durable accounting without an aggregate dollar-spend guarantee. A row that follows the default shows its value with ` (default)`. Digits 1-9 or Up/Down select a row, Left/Right choose a bounded value, Backspace or Delete returns the row to its default and Enter saves; Escape or Ctrl+C closes without changing preferences, draft or history. Rows that take a typed value (limits, timeouts, Build sizes and counts, Context window) open an inline value field on Enter instead, with the row's accepted-input hint; it uses the linear parser, Enter applies a valid value and returns to the list, an invalid value keeps the field with a notice, empty Enter saves and Escape returns to the list. Context window presets cycle `100%`, `75%`, `50%`, `1m`, `500k`, `256k`, `128k`, skipping token presets above the model window of the last Run on the selected model.

Linear mode prints `Choice N: NAME: VALUE` rows with one accepted-input hint each (newline values `shift+enter`, `alt+enter`, `ctrl+enter`), then accepts one `NUMBER VALUE` per line, like `/model`; `NUMBER default` returns that row to its default. Durations and Build sizes use the [human-readable formats](./entry-and-modes.md#human-readable-measures), expanding precision so re-entering a displayed value keeps the exact stored limit. Durations need `s`, `m`/`min` or `h` (`30s`, `5m`, `0.5h`, compound descending `1 min 30s`); sizes need `B`, `KB`, `MB`, `GB` or `TB` (`512MB`, `8GB`), and Build cache also takes `unlimited`. Units are case-insensitive with optional spaces, and decimals must resolve exactly to whole milliseconds or bytes. Provider calls and tokens per task take a number or `unlimited`, active time per task a duration or `unlimited`, process/thread counts an integer, Build cores and jobs `automatic` or a positive integer up to current cores, and Context window a percentage or a token count with an optional `k` or `m` suffix. Bare numbers for durations or sizes, overflow and out-of-bounds values are rejected. Rows reprint after each accepted change. Empty Enter saves (from `/limits` opened by `/settings`, it returns there) and `q` cancels; an unknown row or missing or invalid value reports `Type NUMBER VALUE from the list; q cancels` and leaves the draft unchanged. Under `--classic`, the chat-view notice and hint say the saved view applies to sessions without the flag.

Display preferences stay presentation-local. Execution budgets are snapshotted into a new Goal before Workspace disclosure, Provider inference or effect admission; they constrain that Goal, are reused on explicit resume and never widen Tool grants. The record stores only keys that differ from the binary defaults, so every unchanged row follows the running binary's default; the record is [tolerant](../execution/persistence.md#incompatible-records): unknown keys, malformed JSON and values that fail validation keep their defaults and are never archived or rewritten by reading. Unsafe or oversized files give visible recovery without conversion or overwrite. A failed or busy save keeps the current display, reports failure and never claims rollback of an uncertain write. The newline choice applies only after an acknowledged save and restores on startup; cancelled, busy, failed or [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) saves keep the effective shortcut and draft/caret without retrying. Changing it removes only the previous Alt/Ctrl alias; the [fixed newline bindings](./drafts-and-paste.md#draft-editing-and-submission) remain. The shortcut row lists the complete fallback first, then a direction to widen for manual setup, then the modifier-loss warning; narrow views keep the value, fallback and navigation keys. Settings and limits are locked during admission, Runs and maintenance.

Inline `/help` opens a scrollable registry-backed numbered [selector](./selectors.md#selectors): arrows, PageUp/PageDown and Home/End navigate; Enter or Escape restores composer and history. It works during Runs; Ctrl+C keeps its cancellation meaning. Linear help appends the full registry. Help marks optional arguments, including the current-conversation `/fork` form, and performs no State, credential, catalog or Provider I/O.

`/clear` aliases `/new` and deletes no history. `/compact` creates derived context. `/model` owns model and effort; `/effort` and `/models` are unknown commands, and `/models` suggests `/model` without submitting an objective.

`/permissions` offers Folder trust, Typed Git rules, Host command rules, Command environment, Command tools, Network domains and [Git hooks](../tools/git.md#git-hooks) while idle and is inspection-only during a Run. Dialogs keep the existing paging, cancellation and input barriers; changes apply next Run. Remembered consent never supplies missing native Tool protection. The [Tool contract](../tools/trust-and-approvals.md#folder-trust-and-approvals) owns folder identity and trust, the approval modes, AI review and Guard limits.

- **Typed Git rules** list saved verb, decision and folder or user-wide scope; add from fixed verb/decision/scope choices; change or remove a rule. The `git push` and `gh pr create` rows say they are unavailable. [Tools](../tools/git.md#typed-prefix-rules) owns typed rules.
- **Network domains** list saved `Network(domain:…)` rules with their decision, add one from an unlisted host recorded in a command result of the current conversation, and change or remove a rule; [Tools](../tools/commands-and-cache.md#network-grants-and-egress-proxy) owns their effect.
- **Host command rules** list escaped literal token prefixes, decision, folder and exact cwd, and change or remove rules through the private atomic writer. Add picks a recent eligible host command, showing argv and nonempty cwd as escaped JSON with distinct labels, then the prefix length and decision. A one-token prefix warns that every eligible argument to the pinned executable is authorized. Before the first save the editor explains that saving activates default policy for other Tools; cancelling leaves settings absent. Leaving distinguishes no edits from confirmed saves and keeps the latest save failure with notice of earlier confirmed edits. An [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) save ends editing with a reopen-to-verify notice. [Tools](../tools/host-commands.md#remembered-host-prefixes) owns exclusions, identity checks and mode restrictions.
- **Command environment** lists the private record's source, PATH entries and selected names with values hidden until revealed; it adds a non-secret name from the Arany process environment or removes one. A missing record is created from the process environment on first open. Capture from login shell and Re-capture need fresh human approval through the paged host approval under [host capture](../tools/host-commands.md#primary-host-commands). An unconfirmed creation or save ends the editor with a reopen-to-verify notice, and Tool admission refuses while a creation stays unconfirmed.
- **Command tools** selects a Rewrite hook or Prefix wrapper from granted executables with literal fixed arguments; Import from Claude Code settings proposes user-level Bash hooks through the same selection and probe flow. Selecting or re-pinning disables it until a probe; the probe runs in the Guard and Escape cancels it. An unfinished probe is recorded as unknown and never retried; only human acceptance after a successful probe enables it. [Tools](../tools/hooks.md#hook-execution) owns the record, pins and probe rules.

Folder consent fills the chat area (the Fullscreen alternate screen or the Classic viewport) with no centered box: the question, the full sanitized folder path, a brief explanation, the runtime profile list with newest numeric defaults and associated caches or exact saved pins (each deselectable before Trust), and two vertical choices. Rows wrap at spaces; only a token wider than the row breaks, and a profile row continues indented under its label. Paths under home show `~`; linear mode prints the full absolute path. Profile controls and Trust stay unavailable until every explanation page has been traversed in order; Tab cannot skip pages, and resize or resume restarts review. [Tools](../tools/trust-and-approvals.md#folder-trust-and-approvals) owns when consent appears, its choices, keys, outcomes and recovery of unreadable trust records. Escape dismissal continues with ephemeral read-only chat unless explicit `--tools` supplies private configuration. A remembered path still revalidates the pinned directory identity before project input. No unsandboxed fallback exists.

The optional runtime explanation presents the selected Rust environment, offline Cargo prerequisites and Build defaults from the [Tool contract](../tools/commands-and-cache.md#persistent-workspace-build-cache), with the cache-disclosure warning. Command results keep Cargo's own pass/fail/ignore output; ignored IPC fixtures are never shown as passed.

Inline Shift+Tab cycles Auto edits, Request approvals and Auto approval for trusted or enabled Tools without changing the draft, caret or a pending immutable intent; the composer names the mode.

A pending effect replaces the composer with an inline bottom block under trusted `Tool approval` chrome, below history in Fullscreen and in the grown Classic viewport; history cannot draw there. It shows the operation title, the complete sanitized action, `↓ N more lines · PgDn` while rows remain, `Do you want to proceed?` and numbered vertical choices: `1. Yes`, any eligible scoped approvals, and `No` last. No follows the [approval interruption rules](./entry-and-modes.md#interruption-suspension-and-restoration) and collects no model feedback. Guarded approval opens with Yes focused; a [primary host command](../tools/host-commands.md#primary-host-commands) opens with No focused; paging keeps focus. Scoped choices:

- Switch to Auto edits for `file edits`, only when Request approvals alone caused the Ask; it uses the mode cycle and a one-use AllowOnce reply.
- For an eligible primary host request, approval of the identical command in this live Session, plus `Yes, and allow this host prefix in this folder from the next Run` for an eligible literal prefix: the model's proposal, or else the command's first two argv tokens, except when the program is a [shell, interpreter or wrapper](../tools/host-commands.md#remembered-host-prefixes), which offers only the exact command. Its paged warning shows the complete JSON token sequence, says every eligible suffix is authorized and explains settings creation, Provider disclosure and non-rewindable effects. Auto/acceptEdits offer no session choice; an Auto edits host prompt without the session choice adds the dim hint `Shift+Tab to Request offers session approval for later eligible commands` (plain text in linear mode), which changes neither the intent nor its choices.
- A guarded command asking for new [extra read directories](../tools/host-commands.md#guard-mode-and-extra-reads) offers `Yes, and always allow these folders in every trusted folder`, which also saves them to the user's Guard list; its action lists each directory and the model's reason.
- In Auto approval, a push to a destination other than the folder's pinned repository offers `Yes, and treat this destination as this folder's repository`, which also pins it for the [same-repository order](../tools/git.md#human-approved-host-git) from the next Run.
- A primary local Git write matched by no rule offers `Yes, and allow git commit in this folder from the next Run` (or `git branch`, `git switch`): one-use approval that also saves a typed prefix rule.

Guarded commands and local MCP calls ask only for extra read directories or under a user ask rule. When the Run's Guard mode has no sandbox, every host approval starts with `sandbox off: commands run on your machine`, and the status line shows the same words after the Run state while the latest Run was admitted that way. Host warnings name host authority, Provider disclosure, non-rewindable effects and same-user State/journal limitations. A lexically sensitive path puts the sensitive-path warning first in the action, above program and arguments, in the warning color, or as plain text under no-color and linear output. Host PR-list approval shows the exact repository and filters and discloses private data to the current Provider. Superseded exact project approvals are archived intact, with a notice naming the archive and requiring fresh approval. Privilege tools get a durable exact-command manual handoff with no approval offer.

Digits select and confirm only while approval owns input; arrows and Tab move focus and Enter confirms. Yes and remember choices stay unavailable until every action page has been shown in order; an early approving digit shows `Review the whole action first (PgDn)` and records nothing. Enter or PgDn advances, Up/PgUp goes back, and resize or suspend/resume restarts review. A screen too small for the action and controls asks for resize and permits only denial.

The dialog first draws unarmed: dim choices with no focus marker, or in linear mode the action and rows without the `Select` prompt. The reader then handles an admission barrier in its own loop, even with a full event queue: it flushes unread OS input, resets partial records and lines, and starts a new admission epoch. Only bytes read after the barrier can act on the dialog; queued cancellation is preserved. The dialog then redraws armed (focus marker or `Select` prompt); keys typed while unarmed may be dropped. Barrier failure or a one-second acknowledgment timeout closes input without a verdict. These page and typeahead gates bind the verdict to the complete immutable intent, so hostile text or a steering Enter cannot authorize an unseen effect. Linear mode prints the action and rows, then `Select 1-N, yes or no; empty Enter denies:` with the real maximum. Numbers select by choice identity, `yes` selects one-use Yes, and `no` or empty Enter denies (linear mode has no visible focus), case-insensitively; other replies are rejected. Unguarded summaries keep their markings.

Inline `@` at a whitespace boundary opens bounded local file and directory suggestions. These are user-initiated UI reads owned by the binary, not model-proposed Tool intents, and create no Session, Run, verdict or observation Events. Candidate names stay local; only a selected or typed path enters normal Message/include admission.

- Unquoted paths and JSON-quoted paths with spaces work with or without a trailing slash; a completed closing quote is decoded before discovery. Directory candidates end in `/`.
- Typing searches project names and relative paths case-insensitively, including nested paths, ranking exact names and prefixes first; an empty query shows the folder's immediate entries.
- Up/Down selects. Tab or Enter inserts a quoted file mention without sending; Enter inserts a trailing-slash directory reference and Tab enters the directory. Escape keeps the draft.
- Discovery uses the [typed discovery selector](../tools/file-operations.md#typed-read-discovery): ignored, protected and permission-hidden names are excluded before ranking.
- One asynchronous blocking read builds an immutable names-only index for the admitted root, at most 2,048 names and 48 KiB serialized. It revalidates Workspace identity, scope and permission generation, uses the same no-follow ignore-control admission and Read restrictions, never opens file bodies and keeps the shared discovery and ignore-parsing bounds. Overflow rejects the whole index.
- The terminal never waits synchronously. One build slot per binary and one latest query belong to the composer; edits refine the index in process with at most 2,048 comparisons and a 50 ms deadline, and a timeout discards that update. At most 64 deterministic candidates display. A superseded build keeps its resources until cleanup and cannot publish a stale generation.
- The index expires after 30 seconds<!-- unrelated-bound: mention index lifetime --> and drops when the popup closes or the root, Workspace identity, permission or grant generation changes; old candidates clear before rebuilding and authority changes invalidate before the next selection. There is no watcher, persistent cache or stale fallback; explicit folder narrowing starts a fresh index.
- Full build capacity or expiry of the 100 ms admission wait shows suggestions busy, keeping the draft; only a new query or session retries. Failed suggestions report a sanitized unavailable/busy cause, never imply an empty directory and never substitute a file read.

At Run admission, explicit safe mentions become [bounded include snapshots](../session.md#context-and-compaction), at most 16 distinct paths and no permission grant; a directory contributes only its immediate-entry listing. Mention failures name the escaped path and distinguish symbolic links, filesystem boundaries and non-directory components; an unfinished quoted mention reports `unterminated quoted path`.

The model catalog is bounded and scoped to Provider and account; cached metadata and keystrokes grant no credential or Run authority.

## Storage report

`arany storage` uses the existing Workspace and selected/default StateRoot conventions and the fixed account root. It runs without a Provider or account, writes its bounded text report to stdout and fixed failures to stderr. A complete report succeeds, including explicitly absent roots. A partial or refused report exits unsuccessfully with any known subtotal labelled; cancellation emits no complete report. [Tools](../tools/commands-and-cache.md#local-storage-inventory) owns coverage, byte semantics, exclusions, bounds and cleanup non-effects, including the [cache recovery contract](../tools/commands-and-cache.md#persistent-workspace-build-cache).

Idle `/storage` takes no arguments and shows the same report without creating a Run, history or context; it is locked during a Run. Classic and Fullscreen use a read-only pager with Up/Down, PageUp/PageDown and Home/End; Escape, Enter or Ctrl+C closes it and restores the composer. Linear/screen-reader mode appends the complete text to stderr. During collection, Escape or Ctrl+C cancels and shutdown is preserved; filesystem work stays off the terminal reactor, is joined after cancellation and cannot publish a late report. Reports are never journalled, exported through telemetry/MCP or disclosed to the model; model guidance may suggest `/storage` without obtaining the result.

## Rewind

Idle `/rewind` opens the checkpoint panel. Esc Esc within two seconds on an empty idle composer opens the same panel; on a nonempty draft it saves and clears the draft, which Up recalls (one local draft, text under the draft byte bound and attachments under the image bounds, replaced by the next cleared draft). A focused menu or panel consumes Escape first, and the first idle Escape announces the second action. Rewind is locked during a Run, admission or maintenance. Attached images or another retained draft must be submitted or cleared before switching conversations. Rewind is never automatic and not available in headless `exec`.

Rows follow conversation order with the newest focused: `Run N · objective excerpt · time · K files changed since` (`file` for one), or `no code changes since`, plus `Before rewind` rows. Times come from committed Events (inherited ones labeled inherited); excerpts are at most 80 characters. Later autonomous Runs read `Goal run k` under their Goal objective; steering notes create no checkpoints. Enter opens Restore code and conversation / Restore conversation / Restore code / Never mind, in that order. Code choices appear only for a nonempty plan. Unknown or open publications disable code actions with their Event sequence and an inspect-files reason, and read-only access disables them with a grant reason; conversation restoration stays available. A Before rewind row offers code restoration only.

Code choices open a paged preview listing each path's state (restore, delete, recreate, drifted, history drift, unavailable, unsafe, outside grant or kept), `+added -removed` counts over one replacement region after trimming equal leading and trailing lines (unknown for binary or unavailable content), and the non-rewindable effects, with Git and host effects shown as the single line `Git and host command changes are not undone`. Cancel / Compare / Restore are vertical rows with Cancel focused. Restore needs every page traversed in order; resize or suspension restarts review. Compare opens a numbered per-file picker and bounded text-diff pages, minus for current Workspace content and plus for checkpoint content, each escaped page at most 64 KiB<!-- unrelated-bound: escaped rewind diff page -->; binary or unadmitted comparisons say unavailable. Compare grants no file access and opens no paths outside Engine admission. A confirmation that reports a change needs a new preview; [Tools](../tools/changesets-and-checkpoints.md#checkpoints-and-rewind) owns confirmation validity.

Drift refuses the whole batch and lists affected files. Resolve offers Cancel, `Restore the others, keep these files` and `Overwrite changed files (their current content is saved first)`. Keep requires review and Restore on a new preview. Overwrite applies only to drift and history drift and needs a separate Cancel / Overwrite confirmation with Cancel focused, then review and Restore on the new preview. Unavailable, unsafe and outside-grant paths can only be kept. Empty effective plans refuse. [Tools](../tools/changesets-and-checkpoints.md#checkpoints-and-rewind) defines the drift refusal with its capture guarantees.

Receipts keep the committed outcome: `Restored K files to before Run N`, `Rewind refused: M files changed outside Arany`, or `Rewind outcome unknown: inspect files before continuing` for an [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) outcome, with listed conflicts and checkpoint/pruning notices. If conversation restore fails or is cancelled after code restore, the receipt reads `Code restored; conversation unchanged; use /rewind → Restore conversation`. The [Session contract](../session.md#conversation-rewind) owns fork ordering, source preservation, budgets and lineage limits. Conversation restore switches to the fork (or an unsaved conversation for the first prompt), keeps next-Run defaults and places the selected prompt and images in the composer unsent with text editing focused, with a leading slash escaped as a literal objective. Images return as [attachments](./drafts-and-paste.md#paste-and-attachments); unsupported control characters produce an omission notice, and an image that cannot be reattached stops the rest with `image restoration failed: REASON`. Restored text follows the [primary text draft limit](./entry-and-modes.md#public-limits-and-compatibility). Linear mode announces the complete restored draft as not sent.

Unavailable checkpoint storage offers Retry / Reset checkpoint storage / Cancel. Reset needs complete warning review and a separate Cancel / Reset confirmation with Cancel focused; healthy, busy, unsafe or concurrently changed storage refuses. [Tools](../tools/changesets-and-checkpoints.md#checkpoints-and-rewind) owns deletion scope and private-state admission.

All modes share these states and words. Linear output lists numbered rows and accepts numbers or complete visible choice names; empty Enter, q, Ctrl+C or EOF cancels. It prints full inert paths, previews and comparison pages without truncation or rewriting. At 80+ columns the panel keeps full hints; 50–79 keeps choose, review and cancel; below 50 it keeps arrows, Enter/PgDn and Escape with details on sequential pages. Below 16 columns<!-- unrelated-bound: rewind minimum viewport width --> or eight rows actions require resizing. Paths, excerpts and diff bytes are untrusted data escaped before layout or output. `show` text renders rewind Events and the checkpoint field inertly; JSONL keeps canonical Events.
