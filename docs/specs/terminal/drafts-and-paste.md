# Terminal: drafts, paste and attachments

## Draft editing and submission

Inline edits operate on whole graphemes and keep the caret on a grapheme boundary. Insertion, deletion and wrapping preserve accepted bytes except explicit editing and paste newline normalization. After a deletion the draft is resegmented, because removed separators can merge graphemes or regroup regional indicators; the caret snaps to the first surviving boundary at or after the deletion point. Long drafts wrap into at most four visible rows around the caret, and the heading identifies a clipped window. Growth clips activity before input and status.

| Input | Effect |
|---|---|
| Left/Right, Backspace/Delete | Whole-grapheme movement or deletion |
| Up/Down | Logical-line movement at a preserved grapheme column |
| Ctrl+Left/Right | Previous or next Unicode-whitespace-delimited chunk; punctuation in paths and model IDs stays in the chunk |
| Alt+Left/Right | On an empty draft, switch [agent chats](./selectors.md#agent-chats); otherwise inert |
| Ctrl+W | Delete the same preceding chunk range |
| Typed backslash immediately followed by Enter | Replace that backslash with LF at the caret before completion or dispatch |
| Decoded Shift+Enter, selected Alt/Ctrl+Enter, or Ctrl+J | Insert newline without consuming a preceding backslash or submitting |
| Enter while idle | Submit through local validation, or complete an open slash-name menu |
| Enter during admission or catalog loading | Retain a task draft; never queue another Run |
| Enter during an admitted Run | Offer the draft as a steering note, or retain it as a task draft; never queue another Run |
| Enter during compaction | Retain all text, including slash commands; execute nothing |

Backslash continuation is a portable newline gesture. Only a successfully typed backslash arms it, at that caret, for the next ordinary Enter; a second typed backslash arms the latest one, so two backslashes then Enter keep one literal backslash and add LF. Movement, another key, deletion, paste (including rejection), recall, focus/owner changes and draft replacement disarm it; resize, redraw and incoming output do not. Pasted or restored trailing backslashes stay literal. Replacement adds no bytes and succeeds at capacity. Primary idle, admission/catalog waits, active steering, compaction and editable child drafts consume continuation before submission, and newline edits in busy states never queue an objective or steering offer; editing a waiting note keeps its withdrawal semantics. Dialogs, approvals, search and read-only child views never use chat continuation.

Each visual acquisition queries kitty keyboard flags and then device attributes through the sole input reader, within one 250 ms probe budget. A valid flags reply enables a scoped push of disambiguation only; device attributes without flags, or an absent or malformed reply, keep legacy input and the portable fallback. Late replies never enable a mode. Replies bypass saturated input queues without stealing or reordering keys or framed paste; protocol-looking paste stays data. The keyboard mode is popped before leaving its screen on release, suspension, view changes, scrollback output, failure or unwind, and probed afresh on reacquisition. Canonical and screen-reader input emit no keyboard query or enhancement controls. No modifyOtherKeys mode, subprocess or host terminal configuration is enabled automatically. Linux and macOS share negotiation, decoding and restoration.

The preferred modified shortcut is recommended after successful negotiation or receipt of that distinct chord; backslash then Enter stays visible as the fallback. Visual newline settings report whether enhanced keys were negotiated. Received CSI-u and modifyOtherKeys chords work regardless of negotiation. Konsole's default keytab sends `ESC O M` for Shift+Enter; since Arany never enables application keypad mode (DECKPAM), it decodes that as Shift+Enter and inserts LF. Plain CR always means Enter, because an emulator or multiplexer can lose any modifier. The newline setting describes manual CSI-u mappings (CSI `13 ; 2 u` for Shift, `3` for Alt, `5` for Ctrl) and tmux's extended-key requirement, without inferring delivery from a terminal name.

Linear/screen-reader chat submits with Enter. A newly received physical segment ending in backslash loses exactly that backslash and gains LF, keeping the draft; this is segment-local and never examines an assembled draft or clipboard payload. Ctrl+D after nonempty input continues without adding LF; empty Ctrl+D exits on an empty draft and gives Enter and Ctrl+C guidance on a retained one. Overflow or invalid physical input rejects the whole segment without submitting a prefix or erasing accepted text. Linear entry and settings say `Modified newline shortcuts apply only to visual sessions; use backslash then Enter here`. Unframed emulator paste has no provenance: a pasted line ending in backslash continues and later lines can submit; guidance says so and recommends `/paste` for multiline clipboard text.

Before consuming an idle inline draft, unknown slash syntax, invalid local arguments, an oversized rename, a capacity rejection or an incomplete objective selection leaves text and caret correctable, with no credential, State, Workspace or Provider I/O. Failure after State access or an attempted effect does not restore a consumed command, promise rollback or authorize resubmission. Linear text starts a fresh line after rejection.

During an admitted Run, valid slash controls give read-only inspection, a locked notice or `/goal pause`. Next-Run defaults and Session mutations stay locked; `/exit` explains Ctrl+C cancellation first until the Run's outcome is committed.

Enter during an admitted Run offers the composer text as a steering note; with attached images it reports `Steering notes are text only; draft retained`. The composer keeps the note until the Engine records it for the Run's next primary call; the notice then reads `Steering note sent to the agent`, and the composer clears only if it still holds the offered text. While waiting it shows `Steering note waits for the agent's next step; editing withdraws it`; in Classic a second Enter repeats that. Any edit withdraws an untaken offer with `Steering note withdrawn; draft retained`. When the Run's notes, including history labels and the waiting note, would exceed [8 KiB](../limits.md#max_steering_note_bytes), it reports `No room for more steering notes this Run` and keeps the draft; a single note over [8 KiB](../limits.md#max_steering_note_bytes) reports `Steering note exceeds 8.0 KB; draft retained`. Feedback never repeats note text. An undelivered note returns as a retained draft at Run end, keeping editable text and inert paste boundaries.

In linear mode, Enter hands the note off and clears the line; a further text line while it waits merges into it after a blank line, so one note is delivered. `/status` and `/goal pause` run normally. A draft kept by a refusal (including images) is held aside for the Run; further bounded text stays in the composer with `Both drafts retained; wait for the Run to finish`. At Run end the held draft returns ahead of newer text if both fit; otherwise both survive in the [draft recovery slots](#paste-and-attachments): submit or clear the current draft, then use Up. A Ctrl+D segment counts as a further text line while a draft is held; empty Ctrl+D gives the retained-draft guidance.

`/goal pause` asks the Run to pause at its next step: the notice reads `Pausing at the next step; Ctrl+C cancels now`, and the status row shows `Pausing at the next step... Ctrl+C cancels now` until the Run ends. The Goal pauses under its [pause boundaries](../goals.md#steering-notes-and-pause). A repeat reports that it is already pausing; idle `/goal pause` reports that no Goal is running; `/goal pause` followed by other text during a Run is refused as a locked Goal change.

Manual and automatic compaction preserve draft, caret and history through success, failure, interruption, resize and suspension. Ctrl+K is locked; Ctrl+C interrupts maintenance without clearing the draft. Completion reloads canonical facts and returns to explicit idle submission. Automatic maintenance follows a confirmed Run receipt with a visible warning; its usage excludes model-authored summary text. Interruption does not guarantee rollback of a queued append or remote usage.

Draft feedback counts graphemes, including accepted whitespace; combined emoji and combining accents count as one. Storage and physical-line admission keep their UTF-8 bounds, so no fixed character maximum is promised. Capacity errors ask the user to shorten input or paste a smaller section.

The sole raw reader keeps reads nonblocking through shutdown, so signal-flushed input cannot strand its join. Its 32-event channel applies backpressure at 256 backlogged events; a pending [cursor query](./conversation.md#terminal-continuity-and-provisional-text) permits read-ahead up to 4,352 events, past which input closes with an explicit error rather than dropping keys. A lone Escape waits at most one poll interval. Key repeats and releases, focus events and mouse events other than the wheel and the left button's press, drag and release are ignored. A left press on the previous press's cell within 500 ms counts as a double, then triple, click. An SGR mouse record (`ESC [ <`) is read whole through its `M` or `m` terminator, storing at most 32 bytes; a malformed, out-of-range or oversized record, or one unterminated at the ten-second record deadline, is discarded whole, so none of its bytes reach the draft, a dialog or an approval.

## Paste and attachments

Primary framed and explicit clipboard text are bounded before normalization and across the expanded draft by the [public paste limits](./entry-and-modes.md#public-limits-and-compatibility). After CRLF/CR-to-LF normalization, a paste of more than 1,000 Unicode scalar characters becomes an atomic `[Pasted Content N chars]` chip. A shorter paste is ordinary typed text: it joins command and mention discovery and shares the [64 KiB](../limits.md#max_user_message_bytes) primary draft cap. Chips count only against the expanded-draft cap; linear text beside chips uses the remaining capacity under both caps, and a physical segment exceeding either is rejected whole. Draft merges count their newline separator in both limits. Equal-size pastes append ` #2`, ` #3` outside the bracket from the highest remaining suffix plus one, reusing the base label when none remain. There is no chip count quota. Typed spans and payloads keep insertion order; marker-looking literal text is ordinary text, never a lookup key. Collapse changes presentation only, not model input or token usage.

Child-message pastes always stay editable text without chips, under the [child-message draft limit](./entry-and-modes.md#public-limits-and-compatibility); an oversized insertion rejects whole.

Left/Right traverses a chip atomically. At its start, Tab opens its full escaped inert text; Up/Down, PageUp/PageDown and Home/End scroll, and Escape or Enter closes with the original caret. Delete/Backspace removes the whole chip. Command and file completion are disabled while the draft holds a text chip; editable mentions are still admitted on submission. Detail accepts no paste and invokes nothing; Ctrl+C cancels as usual. Narrow and no-color layouts keep the label and keyboard selection. Linear mode prints labeled compact and expanded inert content.

Only explicit editable input participates in command and `@` discovery. Mention scanning accepts at most 64 KiB<!-- unrelated-bound: mention scanner input cap -->, so chip separators do not consume the objective's [64 KiB](../limits.md#max_user_message_bytes) allowance. A command mixed with text chips refuses locally with the draft intact; slash, Skill, file-path and mention syntax inside chips is data. Submission expands exact normalized text into the ordinary objective before Engine admission. `/goal continue` uses the original Goal's recorded includes and never reparses stored text, as [Goals](../goals.md#budget-continuation) defines. Accepted text survives reopen, fork and replay through canonical Messages without clipboard or cache access. Unsubmitted text and chip boundaries are process-local; local recall keeps them, with no crash-recovery promise.

Admission cancellation and definite pre-acceptance failure restore complete text, chip metadata and images. If acknowledgment reconciliation fails, a modal recovery dialog holds the submitted draft outside the composer. Check history repeats only the read: confirmed non-acceptance restores the draft, confirmed acceptance removes it, and another failure keeps it held. Enter cannot resubmit while acceptance is unknown; Exit discards the process-local draft and closes the Session. No submission retries automatically. During work a large paste stays a draft and cannot bypass the [steering bound](../limits.md#max_steering_note_bytes). Refused held/newer merges keep drafts for explicit submit/clear and Up recovery, blocking conflicting insertion until recovered; ordinary recall is one replaceable slot. The active, held, recalled and pending draft slots each keep at most one message's text and images (256 KiB text and 768 KiB raw images total, plus bounded render/encoding copies). Linear steering offers additionally keep up to [8 KiB](../limits.md#max_steering_note_bytes) text and one provenance record per admitted note until Run end. No payload appears in notices, diagnostics or telemetry before submission.

Canonical input rejects an unexpected bracketed frame and drains through its end marker across reads, including interior Enter, slash and protocol-looking lines. Delimiter state is fixed-size; an incomplete frame or split delimiter closes input under the [framed-paste deadline](#framed-paste-deadline) without submitting a prefix. Admission or focus changes never release a frame's interior as actions. Linear mode adds no raw mode or keyboard query.

<a id="framed-paste-deadline"></a>

Framed Unix inline paste atomically inserts one bounded valid block into the editable draft, also during admission, work, maintenance and catalog waits. CR and CRLF become LF; tabs stay bytes with four-space visual expansion. Overflow or invalid UTF-8 rejects the whole record. Paste never submits, completes a command or activates a selector; modal pickers ignore it. An unterminated framed record fails terminal ownership closed after ten seconds. Secret and Workspace fields keep separate bounds and explicit Enter. Linear canonical input does not claim safe unframed multiline paste.

Ctrl+V, decoded Ctrl+Shift+V or `/paste` requests one bounded OS clipboard read. Unsupported transport, hostile payload or process failure gives local feedback without changing the draft. Clipboard data stays transient untrusted input until submission and supplies no key event, file authority or Run. Enter while loading retains rather than submits. Picker or find entry, release, suspension and ownership changes discard late results; Ctrl+C still cancels a Run. Linear mode shows a complete inert `Draft (not sent)` preview, also during work, and renews its idle prompt afterwards.

Linux reads admitted text and PNG through standard Wayland or local X11 clients. macOS uses a bounded supervised AppKit pasteboard read that prefers PNG over UTF-8 text and rejects other image formats, changed generations and excess bytes; AppKit has no size check before `dataForType`, so the bound applies to the parent's read and the child may materialize the full payload.

Clipboard transports come only from checked local OS metadata: Wayland or local X11 clients on Linux, the checked `osascript` bridge for paste and `pbcopy` for copy on macOS, and a checked tmux socket for copy; never from `PATH`, an external host, an arbitrary command or Provider content. The child gets a cleared environment with only the selected display or runtime variables (plus `LANG` for `pbcopy`), never credentials, network settings or the home directory as configuration. Support checks never read the clipboard.

Clipboard clients run in owned process groups, owned before any fallible pipe setup, under a shared two-second read or copy deadline. Every exit attempts group termination and reaping under a separate one-second cleanup deadline, except a Linux serving copy client (`wl-copy` or `xclip`): its descendant keeps serving the selection until another owner takes it, even after Arany exits. Arany reaps the foreground process and leaves the descendant in its own group with only the payload and cleared environment; a failure or deadline terminates the whole group. Cancellation discards a late payload without blocking the terminal reactor. One clipboard worker runs at a time; another read is refused until it finishes. A cleanup error or deadline returns `clipboard cleanup unconfirmed`, never a payload or a reaping claim; the worker keeps observing the child, and later reads report the unconfirmed cleanup until restart, even when cancellation discarded the result. Teardown signals an outstanding worker and waits at most one second; a miss reports unconfirmed cleanup to stderr. No read retries automatically.

The composer shows attachments as ordered `[Image #N]` chips. Workspace admission captures the root's device and inode before Session creation; every pasted path read requires that identity, also in fresh conversations, and opens the root and each component without following links. Clipboard PNGs and pasted `.png` paths share the admission limits; candidates follow the [PNG path bound](./entry-and-modes.md#pasted-png-path-limit). Text containing `://` or control characters is ordinary text even when it ends in `.png`; URLs are never fetched. Absolute paths are accepted only lexically beneath the canonical Workspace root. Reads require a same-filesystem regular file with one link and snapshot at most the PNG byte limit before validation. Linux rejects mount crossings, including same-device bind mounts, and fails closed without kernel enforcement; macOS uses no-follow component opens and rejects device changes. A path confirmed absent beneath the pinned root falls back to the pasted text. Workspace failures, identity changes, escaping, forbidden, linked, cross-filesystem, oversized and malformed inputs leave the draft unchanged.

When the chips do not fit the composer header, it shows the selected chip or, with none selected, the image count, keeping the clipped draft position when both fit. Left/Right selects adjacent image chips at the text boundary or among chips; Delete/Backspace removes the selected image and the rest renumber in order. Successful text edits, including paste, clear image selection; ignored keys, pointer motion and resize keep it. At most four PNGs totaling 192 KiB raw bytes are admitted, including image-only submission with empty user text. Human history shows metadata only; canonical history, forks and JSONL export keep bytes. Compaction uses image metadata and prior assistant interpretation, not pixels. Overflow rejects a whole image or historical turn, never a truncated prefix or silently lost attachment. Custom routes stay text-only.

Admitted PNG bytes stay unchanged, metadata included. Admission checks structure, chunk CRCs and dimensions without decompressing; animated PNG and unknown critical chunks reject, and dimensions prove neither decoding nor vision support. Filenames, URLs and terminal image escapes are never admitted.

<a id="image-hover-preview"></a>

Image hover preview runs only in Fullscreen with mouse capture, outside tmux and the screen-reader path, sharing the keyboard probe deadline. Detection prefers an exact Kitty graphics `OK` reply before DA1, then DA1 attribute `4` (the first DA1 parameter identifies the terminal) with a known cell pixel size for Sixel, then the iTerm2-compatible environment (`TERM_PROGRAM` exactly `iTerm.app` or `WezTerm`, or `LC_TERMINAL` exactly `iTerm2`). Sixel cell pixels come from `tcgetwinsize`, else from an exact `CSI 6;height;width t` reply before DA1 to a `CSI 16 t` sent first. Missing, zero, oversized or malformed cell sizes disable Sixel but still permit an eligible iTerm2 fallback. Detection and rendering never change terminal or tmux configuration. [Xterm's control sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) own DA1 and cell-size replies; [DEC's Sixel](https://vt100.net/docs/vt3xx-gp/chapter14.html) owns raster and palette encoding.

Hovering a visible chip draws a bordered balloon above the composer header, anchored at the chip, clamped to the screen and titled with the image description; the image keeps its aspect ratio. Hidden compact chips have no hit area, and the balloon is omitted when fewer than four inner rows fit. Kitty and iTerm2 receive the unchanged base64 PNG and decode it themselves; their decoders are outside Arany's security boundary. Sixel alone decodes locally in `spawn_blocking`, scales by nearest neighbour and quantizes to a fixed 6×7×6 RGB palette (252 colors); fully transparent pixels leave the background, other alpha uses the pixel's RGB. The decoder uses the PNG byte limit as its best-effort allocation limit, ignores text/profile metadata, and checks frame pixels (before decoding) and output pixels against `PREVIEW_MAX_PIXELS` under the [preview limits](./entry-and-modes.md#public-limits-and-compatibility); a started job completes under those bounds without a hard RSS or preemption guarantee. Decode errors and overflow suppress graphics without changing the attachment or reaching a Provider, journal, diagnostics or telemetry.

One Sixel decode runs per binary with one latest request kept; a superseded job keeps its slot until done, generation changes (leave, reentry, chip or geometry change) prevent late publication, and a busy slot suppresses the preview for that hover. Mode replacement keeps the outstanding job's ownership. Results arrive as a terminal event. Motion within a chip neither redraws nor retransmits. Leaving deletes the Kitty placement or repaints iTerm2 and Sixel cells. Resize, chip change, opening a picker, dialog, pager or detail view, mode switch, scrollback dump, suspension, release and exit clear the hover. Without a detected protocol, and in Classic, linear, screen-reader, disabled-mouse or tmux sessions, no preview or fallback graphics are drawn. A graphics write error propagates through ordinary restoration.

Idle `/copy` copies the latest committed answer's source Markdown with control escaping; it is locked during a Run. Fullscreen selection maps visible graphemes to contiguous source ranges, including heading, code, table and inline syntax envelopes and intervening source; reference destinations include their use and definition envelopes, so an aliased endpoint can widen the copy. A double click keeps plain source words in ATX headings, code bodies and plain table text, and otherwise selects the visible word with its source envelope; selecting the whole body returns its original Markdown. Classic emulator selection copies rendered cells.

A copy goes to the first destination that works, each tried at most once:

1. A native client when local (no `SSH_CONNECTION`, `SSH_CLIENT` or `SSH_TTY`): `wl-copy` (Wayland) or `xclip` (X11) on Linux, `pbcopy` with `LANG=en_US.UTF-8` on macOS. `xsel` is not used, because its daemon calls `setsid()` and leaves the owned process group.
2. Inside tmux, `tmux -S SOCKET load-buffer -w -` (tmux 3.2 or later). `$TMUX`'s socket must be absolute, a socket, owned by the user and in a private canonical directory whose every ancestor is owned by root or the user and not group- or world-writable unless sticky; its device and inode are rechecked before and after the client runs, and a change fails this destination.
3. OSC 52.

Copy clients come from the same admitted root-owned directories as paste clients (so Homebrew tmux on macOS is never used) and read only the payload on stdin. Copied text is never journaled, sent to a Provider or recorded in diagnostics. OSC 52 depends on the emulator: Terminal.app and VTE ignore it; iTerm2 requires "Applications in terminal may access clipboard"; Kitty, foot, WezTerm, Ghostty and Alacritty support it. Over SSH, Terminal.app users need Fn-drag or Classic; inside Homebrew tmux on macOS, OSC 52 needs `set -g set-clipboard on`.
