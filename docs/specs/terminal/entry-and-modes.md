# Terminal: entry, modes and restoration

## Entry, modes and channels

| Entry | Observable contract |
|---|---|
| `arany [PROMPT]` | Requires terminal stdin and stderr. Without a prompt, opens a composer held locally until the first task submission; a prompt starts the first Run only after admission and leaves chat open. Fullscreen, the default, draws on stderr in the alternate screen; Classic uses the primary screen. Redirected or same-terminal output follows [terminal continuity](./conversation.md#terminal-continuity-and-provisional-text). |
| `--continue`, `--resume`, `--fork` | Explicit Session entry; Workspace or TTY matching never resumes work. A missing conversation, or a fork source without a completed Run, fails before the prompt with a message naming `arany --resume` or `/resume` and `--state-dir`. An unsafe State still reports the unsafe-state error. |
| `--profile PRESET` | Explicit private roster selection for attached mode or exec; supplies the primary tuple. Any supplied Provider/model/effort field must match, and a present role-routing record conflicts. No preset is selected or read by default. |
| `--setup` | Resolves folder access before setup or Session creation. Cancellation before account save creates no Session. Idle `/setup` works inside the current conversation. |
| `exec --output text` | Noninteractive; no terminal modes. Without `--provider` and `--profile`, `exec` uses the saved attached-mode selection; with none saved it names the missing `--provider`/`--model` or `/model` choice. A missing `--effort` uses the effort saved for that Provider and model. Stdout holds only the sanitized, indented committed answer; stderr holds the stable Session/Run/status receipt. A failed Run exits unsuccessfully without an invented answer. A hook-stopped Run reports `Status: stopped_by_hook` and `error: Run stopped by hook[: REASON]`. An interrupted or hook-stopped Run whose Goal stays open adds `Goal paused; resume with arany exec --session-id SESSION --resume-goal GOAL` to stderr and exits unsuccessfully. An autonomous Goal that stops after a committed Run keeps that answer on stdout, appends `error: Goal stopped after a committed Run: REASON` to stderr and exits unsuccessfully. |
| `exec --output jsonl` | Stdout holds the latest Run's committed Events, its matching Goal's lifecycle and final report, and the new Session fact, if any ([Goal selection](../goals.md#current-format-replay-and-exec)). Successful non-roster JSONL leaves stderr empty; roster mode first writes its complete route manifest there. An interrupted Run keeps its committed Events and adds the same pause line to stderr. |
| `acp` | [ACP spec](../acp.md) owns the editor subprocess, capabilities and core text turns. |
| `serve --stdio`, `generate-schema [--out DIR]` | [Serve spec](../serve.md) owns protocol framing, schema export and the accepted server surface. |
| `storage [--workspace PATH] [--state-dir PATH]` | Local bounded text inventory without a Provider/account, terminal acquisition or Session. [Storage report](./commands.md#storage-report) owns channels and availability. |
| `show --output text\|jsonl SESSION_OR_RUN_ID` | Deterministic read-only replay without terminal modes. Validates the UUID before State access, opens only existing State read-only, reads no credential and closes the Store before rendering. Session selection exposes direct canonical Events and the fork reference; Run selection exposes only that Run after strict parent validation. Invalid or conflicting ownership fails without output. Valid history renders byte-identically. If strict replay rejects a selected Session with `InvalidHistory` or `InvalidSnapshot`, inspection scans the whole journal within [the generated Event scan limit](../limits.md#max_list_scan_events); the rejecting fault may lie in another Session. Output then holds the selected Session's direct valid prefix, the typed rejecting sequence and cause, and a per-Event lenient tail with a fixed marker for undecodable payloads; a notice says the projection is read-only and not resumable, and the command exits unsuccessfully. JSONL puts a `notice` object before one object per tail Event. Exceeded scan or replay bounds and Store infrastructure errors fail without output. |
| `show --output supervisor-corpus SESSION_ID` | Session-only calibration JSONL to stdout, without terminal initialization. The [Supervisor adapter](../tools/hooks.md#supervisor-adapter) owns format, privacy, replay, locking and overflow. Refusal exits unsuccessfully with empty stdout and a fixed diagnostic (plus safe overflow counts) on stderr. |

Headless `exec` text and JSONL deterministically project reopened committed history; Server notifications never become output lines.

Headless `exec --tools` follows the [host policy](../tools/host-commands.md#primary-host-commands): eligible admitted host prefixes may run in default/dontAsk, and every unresolved host ask refuses immediately. It cannot create rules or reuse a previous process epoch. Text, JSONL, show and Goal receipts keep the unguarded and non-rewindable effect markers.

The command chooses the contract. An ineligible bare invocation fails before Engine entry and directs the caller to `exec`. Headless objective prefixes such as `/`, `@` and `!` are literal data, except that `exec --tools` and `--prompt` treat `/name [task]` as an invocation when `name` is an admitted Skill and not a compiled command (`serve` has no slash form).

An unavailable stderr sink never turns error reporting or cleanup into a panic, never blocks restoration of surviving terminal settings and never changes the intended exit class. Diagnostics never fall back to stdout. Output failure does not prove delivery of an error, receipt or mode-reset sequence.

`--screen-reader` or `ARANY_SCREEN_READER=1` selects labeled append-only output with canonical input, without raw mode, cursor rewriting, boxes or animation. `TERM=dumb`, fewer than eight rows or unavailable geometry selects that fallback before acquisition. Resizing never switches presentation; only an explicit idle `/settings` chat-view change switches Classic or Fullscreen ownership.

`--no-color` and `NO_COLOR` remove color, including after reacquisition; text labels, selection markers, focus and bracketed hints keep their meaning. Action and consent alternatives occupy separate vertical rows; horizontal button groups are not admitted. Message bodies are unstyled except recognized leading slash tokens and the assistant Markdown projection below. Inline role headings are emphasized `› You:` and `● Arany:`. A two-cell rail groups nonempty user-body rows, assistant bodies keep plain indentation, and existing spacing separates messages without extra indexed rows. Restored user previews use `› You:`; attached committed answers use `Arany · Answer:` and headless `exec` keeps `Answer:`. Linear mode keeps plain role labels without decorative rules. The terminal background stays user-owned.

Human output escapes or rejects ANSI/ECMA-48 controls, OSC sequences, C0/C1 controls, carriage return, backspace, bidirectional controls and forged line prefixes. JSONL comes only from a serializer, one object per line. Inline chat reserves one blank row above the transcript when at least five history rows fit, so a sticky command header cannot cover the first speaker label; with fewer rows, content wins. Linear and deterministic output is unstyled and contains no CSI, OSC or carriage-return rewriting.

Roster selection displays the complete escaped [manifest](../provider/selection.md#named-roster-presets), with native API / ChatGPT plan / exact custom unknown-pricing labels and every fallback, before credential access or Workspace-content loading: on stderr when headless, and again as a notice for each independent attached submission. The selector is the selection action, with no extra picker or confirmation flag; account/plan consent is still required. `/new` and `/clear` keep the process selection. Conflicting `/model` or `/setup` defaults cannot substitute a roster route at next-Run admission; restore the preset tuple or start without `--profile`. Roster-Goal resume requires the matching selector as [Sessions](../session.md#roster-recovery-and-compaction) defines.

## Human-readable measures

Human-facing sizes use one shared formatter across attached, linear, plain and accessible output: below 1 KB, exact bytes (`500 B`); otherwise one decimal KB/MB/GB/TB with a 1024 base (`38.3 KB`), promoting to the next unit when the rounded value reaches 1024.0. Draft and text counts use characters or lines where those are the defined measure; byte limits keep their meaning and display in these units. JSON/JSON-RPC (`serve`, ACP), JSONL exports including `exec`, journals/Events, schema fixtures and diagnostics keep exact machine units, including integer bytes and milliseconds.

Durations use `h`, `min` and `s`, omitting zero components except `0 s`; fractional seconds keep millisecond precision without trailing zeros: `0.001 s`, `1.5 s`, `2 min`, `1 h 30 min`. Time limits use the same format without rounding away their bounds. Large counts use digit grouping (`12,340 lines`) or explicitly approximate values.

## Interruption, suspension and restoration

Primary Tool approval prompts stay answerable without a wall-clock deadline while terminal I/O and the Run are live, including suspension or a live tmux/screen PTY. Explicit No records a human decline and stops the Run without dispatching; Escape and Ctrl+C cancel the whole Run. EOF, SIGHUP/shutdown and lost terminal I/O withdraw the request, closing its dialog and restoring the composer without a verdict. A child approval stays pending through idle waits, then withdraws when shared delegation or Goal active time is exhausted, with that cause named apart from human denial. Earlier completed effects remain.

| State/action | Required outcome |
|---|---|
| Ctrl+C on folder consent | Exit and restore the terminal without selecting read-only or saving trust |
| Idle Ctrl+C with a draft | Clear the draft |
| Idle Ctrl+C on empty input | Explain copying (in Fullscreen with mouse selection, `Select text with the mouse to copy; GESTURE for terminal selection` with the emulator's selection gesture; otherwise the emulator's Ctrl+Shift+C); a second press within two seconds exits |
| Ctrl+C during selected-Provider admission | Return to chat with the new draft retained and no Run receipt or retry; delegated account work may still complete |
| `/goal pause` during a Run | Pause at the next step; the in-flight call completes and a dispatched action is not aborted; Ctrl+C afterwards cancels now |
| First Ctrl+C during a Run | Request graceful whole-Run cancellation, even while a Fullscreen selection is shown |
| Second Ctrl+C during cancellation | Bounded local shutdown; report only the strongest durably confirmed terminal state |
| Escape | Closes the focused panel first; otherwise cancels a pending clipboard read, then clears a Fullscreen selection, then closes the completion menu. With nothing focused during a Run, cancels the Run like Ctrl+C: the Goal stays paused and resumable and the draft is kept; a second Escape during cancellation is ignored. Linear input cannot send Escape; Ctrl+C cancels there |
| Unix SIGTSTP / inline Ctrl+Z | Release input and modes before stopping, never stop after restoration fails; SIGCONT reacquires the chosen presentation and keeps draft, caret, history and pinned work |
| Unix SIGTERM/SIGHUP | Exit through the input-owning state; an active Run requests cancellation before bounded outcome confirmation |

`q`, Ctrl+D, `/goal pause` and other slash controls do not cancel work. An empty-draft Ctrl+D or `/exit` after the Run's outcome is shown, while the Run is still finishing, exits once it returns; `/exit` also abandons a held linear draft or undelivered steering note. Cancellation and shutdown grace is at most three seconds, and expiry never fabricates a cancelled receipt or answer. Run cancellation is distinct from pre-Run admission interruption and from compaction interruption; replay can instead expose an interrupted prefix. Interrupted compaction promises no Run cancellation or remote billing stop.

Raw mode, cursor, wrapping, echo and every enabled mode, including mouse reporting and alternate scroll, are restored on normal exit, error, cancellation, signal, render failure, partial acquisition, unwind and suspension; Fullscreen exit shows the cursor last and leaves the alternate screen. Receipt and answer output follow restoration and read-only confirmation. Renderer failure after Run admission may expose only committed sanitized linear facts or a typed presentation failure. Secret bytes never reach drawing, notices, Events or output during cleanup.

Classic cursor-query timeout fallback stops and joins the key reader, releases raw mode and then starts the linear reader; a raw-mode release failure prevents restart. Partial acquisition unwinds in reverse order. Cleanup attempts every remaining reset in order and returns the first error; a failed guard reset stays armed for its best-effort Drop retry. Failed reacquisition leaves the prior owner released. The [Transcript owner](../../architecture/system-overview.md#8-terminal-presentation) keeps distinct histories and native emission tracking across replacement; linear Tool rows already written stay suppressed.

Keyboard text selection (Shift+arrows) and external-editor transcript export are unsupported; use `/copy` for the latest answer, or Classic native selection, the transcript dump or `arany show`. Disabling alternate scroll on release can also disable an emulator default such as xterm's `alternateScroll`.

Markdown, HTML, SVG, files, links and model output are inert by default, restricted to admitted formats and isolated from privileged APIs. A future browser Client needs CSP, safe templating, origin isolation and a new threat model before privileged operations; browser Clients stay [deferred](../../architecture/system-overview.md#14-explicitly-deferred).

Width layouts distinguish at least 80 columns, 50–79 and narrower. At 20–39 columns picker hints keep editing, navigation, Enter and Escape; at 16–19 they keep identity and essential actions. Chain-of-thought, raw prompts, reasoning items, raw wire token streams and uncontrolled upstream errors are never conversation sources. Only explicit action approval exposes the bounded sanitized immutable action for a user decision.
