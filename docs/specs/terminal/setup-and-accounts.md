# Terminal: setup and accounts

## Setup and account choices

Attached startup checks, in order: [folder consent](../tools/trust-and-approvals.md#folder-trust-and-approvals), [local history](#history-recovery), account choice and [selected-item authorization](../credentials.md#selected-item-authorization), then the Provider catalog and chat.

Without a usable account, chat still opens and names `/setup`; a task without one starts no Run. [Credentials](../credentials.md#backend-selection-and-startup) own bare-start reuse and the mixed API/ChatGPT billing-route choice, which the terminal shows with Cancel focused; empty Enter cancels.

Idle `/setup` keeps the draft and defaults if cancelled before saving. Native and ChatGPT setup end by picking a low-effort model from the account's catalog, without a questionnaire or test inference; catalog listing does not prove compatibility. Incompatible or damaged saved setup shows actionable feedback and leaves the composer usable; `/setup` then offers the [local reset](../credentials.md#storage-replacement-and-recovery), with Back focused and its deletion scope shown first. The reset keeps history and other routes' accounts, and cancelling setup afterwards does not undo it. Recoverable `--setup` errors return to chat.

The Provider manager separates API accounts, custom routes, Role routing and Roster profiles.

- **Custom routes.** The list never reads the referenced environment variables; Inspect shows the protocol, exact destination and credential reference. A route offers Inspect, Select, Edit, Remove and Back; nothing is tested, and the next Run admits the selected route. The form offers `1. OpenAI Responses`, `2. Anthropic Messages` and `3. OpenAI Chat Completions`; changing the protocol clears the destination. The Chat Completions prompt asks for the base URL, to which `/chat/completions` is appended, with Bearer authentication. Edits made against a stale view are refused rather than overwriting another editor.
- **Accounts.** Removal confirms the exact account; cancelling does not switch the active ChatGPT account. ChatGPT removal lists every saved account, including disconnected and pending ones, so failed cleanup can be retried. Use saved offers only usable accounts. Native inspection shows Provider, model, effort and storage with the credential hidden. Selecting a saved native account shows the private-file warning when applicable, then loads only that account; cancelling keeps the current defaults.
- **Role routing** offers Inspect resolved routes, editing for Primary/Child/Review/Compaction, Save and a separately confirmed Clear role routing. Inspection and Save review show every resolved source, model, effort, inherited chain and fallback, with custom destinations and credential references. Sources are environment credentials, inspected saved native accounts, the selected ChatGPT account and custom routes; only admissible efforts are offered. The primary's first choice changes through `/model`, and its chain editor can copy it. Edits stay a draft until Save; Escape discards the current chain edit and Back the draft. A confirmed Save or Clear stays; stale concurrent edits are refused. The [Provider contract](../provider/selection.md#per-role-selection-and-fallback) owns admission, inheritance and the conflict with rosters.
- **Roster profiles** offer Route profiles, Named presets, Preview complete roster, Save roster, Clear role routing when routing exists, and Back. Route profiles hold ordered model chains, independent of `/model`. Presets assign Primary/Child/Review/Compaction by profile, with Inherit primary for non-primary roles, and an ordered list of eligible children. Escape discards the current edit and Back the draft; errors keep the draft and name affected presets. Preview and Save show the full roster and `arany --profile PRESET` launch guidance, warning first about existing role routing. The [Provider roster contract](../provider/selection.md#named-roster-presets) owns validation, limits and activation.

Save, Clear and removing the last preset need the full change reviewed page by page, restarting after resize or suspension, in every mode. Leaving the manager restores draft, caret and position. Setup is locked during admission, Runs and compaction.

Setup failures are recoverable, presentation, uncertain or shutdown. Recoverable ones keep their message and recovery path; [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) ones stop setup without retry or rollback claims and block continuing after reopening; shutdown counts as cancellation.

Successful setup returns to chat with a usable composer and a notice.

A confirmed account, route, routing or roster change creates the attached Session before its first effect and records the edit ([Execution contract](../execution/admission-and-recovery.md#admission-persistence-and-recovery)); the first task then uses that Session. Cancelling before confirmation, local commands and model changes record nothing. An incomplete or uncertain edit blocks resuming that Session; start a new one after checking saved state.

[Selected-item authorization](../credentials.md#selected-item-authorization) shows a waiting frame naming the OS password store. Escape or Ctrl+C exits without a Run. Denial, missing or invalid credentials, a changed selection or timeout gives feedback and never submits the initial or resumed objective.

<a id="chatgpt-account-choices"></a>

The ChatGPT menu offers Use saved, Reconnect, Connect new and Inspect. Inspect works on any saved account, including disconnected, plan-disabled and unavailable ones, without selecting it: it shows the account UUID, storage backend, plan billing class and saved state with its reason, which proves neither valid credentials nor plan entitlement. Inspecting never touches tokens, the password store, catalogs, Providers, selection or defaults. Multiple accounts show full IDs and the current marker. Reusing the current account skips browser sign-in. After a switch, new connection or reconnect, a failed or cancelled catalog step keeps the account change and shows a retry notice. Reconnect repeats consent.

Replacing the executable on Linux during a conversation does not break credential access. Store failures say the desktop password store could not be accessed and ask the user to unlock it and retry. A missing sign-in points to Reconnect. When the pinned store is unavailable, guidance names Connect new's private-file option, which warns that sign-in credentials will be stored unencrypted, keeps Cancel focused and opens no browser before consent.

Inline setup uses focused rows with arrows, Tab, Enter and Escape; typing never selects a row. Linear choices accept a number or an exact visible name, and each prompt says what empty Enter selects; invalid input shows a correction and asks again. Long lists page in full before the prompt. Labels stay readable at 16 columns<!-- unrelated-bound: inline setup readability viewport --> without color. Optional fields keep or clear their value on empty input.

API-key input hides the key and shows only a character count, with a 512-character printable ASCII limit; echo is restored after cancellation, signals and suspension. ChatGPT consent shows the full warning before Back or Accept, with Back focused; empty Enter declines, and resize or resume restarts the review. Private-file storage needs its own plaintext warning and explicit choice with Cancel focused, and never silently replaces a pinned keyring. In linear mode, rejected characters must be deleted before input continues. Anthropic's optional Console workspace ID is visible, validated text, not a secret. The OS store may show its own unlock prompt; Arany makes no OS-store encryption guarantee.

### History recovery

Startup checks local history in the [order above](#setup-and-account-choices). Incompatible history ([archive rule](../execution/admission-and-recovery.md#admission-persistence-and-recovery)) is archived intact automatically; the new unsaved conversation names the archive, and an initial objective is not submitted. Accounts, preferences and folder trust stay, except [strict records the current version refuses](../execution/persistence.md#incompatible-records), which are archived and named in the startup notice. Damaged or unsafe history, or a failed archive, opens a recovery choice explaining the cause: Retry (focused), Reset history when the history is damaged, and Exit. Retry, Exit and cancellation change nothing.

Reset history needs the full warning read and explicit Back or Accept, with Back focused; resize or resume restarts the review. The warning says every conversation in this StateRoot and its derived Provider evidence is discarded, while accounts, model choices and folder trust remain. A confirmed reset opens a new unsaved conversation; a supplied initial objective is reported as not submitted.

Reset refuses, with retry guidance, while another Arany process uses the store or when its files are unsafe or change during the reset. It deletes only the history database and its SQLite sidecar files and recreates an empty one. A failure partway is reported and recovery stays available. Unsupported history is never interpreted or converted; `show` rejects it unchanged.
