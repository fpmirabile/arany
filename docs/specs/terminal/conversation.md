# Terminal: conversation, progress and history

## Conversation, progress and history

Answer headings carry any unguarded and host effect counts.

Attached assistant text (Fullscreen, its pager, Classic and selected agent results) renders a bounded Markdown projection:

- ATX headings are bold with hidden delimiters; setext headings are bold with the underline hidden.
- Paragraphs, setext headings and table cells decode escapes and entities and style emphasis, strong emphasis and inline code with hidden delimiters. A soft break keeps its source row break and a hard break adds a row. Prose wraps at spaces; long words break at graphemes. An entity decoding to several graphemes is one atomic source group.
- Fenced and indented code, including code nested in lists and quotes, keeps whitespace and line boundaries with plain reverse styling and grapheme wrapping. Fence delimiters are hidden; info strings decode escapes and entities into bold sanitized labels with per-fragment source origins. No lexer is loaded.
- Top-level pipe tables use fitted columns with bold headers and wrapped cells, or header/value records when narrow. Cells decode escaped pipes and entities and style inline emphasis and code; generated labels, separators and padding carry source anchors.
- Inline, reference, collapsed and shortcut links render as underlined `label (destination)`, even when both are equal; autolinks show their URL once. Destinations decode entities and escapes before sanitization and wrap at word/grapheme boundaries; titles and reference definitions are hidden. Links are inert escaped text, with no fetch, open, path resolution or OSC 8.
- Lists and quotes use generated source-anchored markers: `• ` bullets, ordered items counting from the list's start number, and `│ ` quote rails. Wrapped and continued rows keep hanging indents and rails, including nested, empty and code-first items; indentation follows CommonMark tab columns.
- HTML, images, strikethrough, task-list markers, thematic breaks and footnote references stay literal inert source. Messages with lone carriage returns stay literal under control escaping.

Provisional and incomplete answers use the same projection with their qualified headings. Formatting is disposable; canonical Markdown is unchanged. Counting, drawing, find and resize share one layout. Repeated destinations keep distinct selection, reading and find anchors through reflow; a literal match in a definition selects its first rendered use, and stepping visits uses in row order. Code, ATX headings and literal lines keep source line boundaries, wrap at graphemes and use safe replacement at tiny widths. Monochrome keeps heading weight and block structure. Linear/screen-reader output, `exec`, `show`, JSONL, serve and ACP keep source with existing escaping.

The renderer checks [source bytes](../limits.md#max_markdown_parse_bytes) before parser construction, then bounds [event containers](../limits.md#max_markdown_depth), [events](../limits.md#max_markdown_events), [escaped output including decoration](../limits.md#max_markdown_output_bytes) and [rows](../limits.md#max_markdown_rows). Overflow selects whole-message escaped literal fallback plus one formatting-limit cue outside copied source, without truncating the answer or changing its Run. Parser construction precedes event limits and has no hard RSS/deadline guarantee; no AST or cross-Session cache is retained. Tables bound [columns](../limits.md#max_markdown_table_columns) and [data rows](../limits.md#max_markdown_table_rows) before growing the matrix; the parser's upstream empty-cell padding cap applies independently. Emitted fragments, including fence labels, are sanitized after decoding.

Compact Tool rows use the `⏺ Operation(arg)` and indented `⎿ result` shape, without a `Tool ·` prefix or success word. A Fetch row names its URL, a Web search row its query, and a Search row its query and path plus any non-default option, such as `Search(fn \w+, src, regex, include **/*.rs, ignore case, offset 100, limit 10)`. Results give:

- bounded entry or line counts and readable sizes, including truncation;
- command exit status and total lines (`exit 0 · 12,340 lines (truncated)`), then only nonzero selection counters (ignored entries with `(N pruned roots)`, oversized inputs, discarded outputs);
- `applied` for file changes;
- otherwise the disposition and sanitized failure text: `Error: ...` for a failed call, `denied`, `uncertain` and other dispositions by name.

Consecutive successful reads by the same actor collapse into one row (`Read 2 files`, `Listed 2 directories`, `Searched for 2 patterns, read 2 files, listed 2 directories`) with combined counts; Git queries, Skills and MCP lists keep their own nouns, and details keep each call. A Command or unguarded command row shows a multi-line script as its first non-blank line plus ` …` when more follow, escaped and bounded, never an escaped line break. Pending, failed, denied, cancelled, conflicting, limited and uncertain calls stay distinct. Failed command rows append at most 80 cells of escaped stderr. Trust-bearing rows never collapse: unguarded, uncertainty, enforcement-cause, checkpoint, denial-source, cache-problem and hook markers stay visible. Cache markers show only rejected, failed and uncertain updates. Limit rows follow the committed closed cause: `timed out after DURATION` (the effective timeout, bounded by the operation cap, with `; /settings raises it` only for Commands), `output passed 1.0 GB; stopped`, `no room left in this Run's context`, `too many reads at once; nothing was read`, `asked for more time than the pinned maximum` or `resource limit reached`. Truncation labels derive from typed totals or limit causes, never from stdout or stderr text. Presentation never changes the [Tool guarantees](../tools/README.md). Classic and linear output append a read group once its boundary or the Run's end is known. Linear and screen-reader output use the same words, with an operation line and `Result:` instead of glyphs and no rewriting.

An active-Run notice names the unavailable action and an alternative, for example `/model changes are unavailable while a Run is active; Ctrl+C cancels`. View-only commands keep current-value inspection; empty submission says `Run is active; Ctrl+C cancels`. Notices never imply that another action ran.

Failed Run feedback distinguishes an Engine-refused proposal from a Provider-call failure. A committed preflight refusal shows its typed cause (arguments, phase, plan, budget, scope, grant, byte limit, lease, unavailable operation, answer or Delegate) and fixed reason, then `The refused action was not dispatched.`; it is never attributed to the Provider, and JSONL and text `show` keep the canonical refusal Event. A Goal-budget stop uses the [deterministic numeric Goal feedback](../goals.md#budget-refusal-feedback), labelled `Arany status`, including recent bounded Tool failures and preserved-answer wording. Attached, `exec` stderr and text `show` use the same committed facts; `exec` admission-refusal reload uses the shared refusal-record lookup with its looser budget-stop fallback. Receipts render the exact Run reported, even within a multi-Run Goal. Invalid agent definitions, stopped Tool steps, plan admission, unavailable Tool context, unverified workers, unmet criteria and refusal-limit failures each have distinct copy. A failed Run without a committed answer says so; earlier completed actions remain and uncertainty keeps its warning. [Execution](../execution/events-and-outcomes.md#accepted-outcomes) owns the closed causes and journal pairings.

Agent inspection and text `show` use the [Session worker projection](../session.md#worker-replay). Inspection qualifies an unknown Workspace publication and shows the bounded untrusted [observation-derived path/digest report](../session.md#worker-replay), keeping landed edits after completion, cancellation and pause, without appending Events or calling a Provider. JSONL keeps canonical Events, including qualified lineage and refusal reasons; derived interruption facts add no Events or terminal view.

Agent inspection shows only the selected actor's committed Supervisor verdicts; transcript details show every actor's verdicts in the Run. Each verdict is one dim labelled line, wrapping at the cell width without losing words: `Supervisor (shadow): possible loop; no action taken`. Multiple signals share the line; the capped verdict adds `verdict limit reached`. The terminal uses a fixed reduced vocabulary without canonical features or evidence; [serve](../serve.md#notifications-and-items) forwards the canonical privacy-reduced verdict. Linear and screen-reader inspection and `/transcript` use the same words without styling. Nothing displays before commitment, the collection follows the [verdict cap](../execution/persistence.md#persistence-bounds) with no notices fabricated past it, transcript details keep their Run and byte limits and overflow cue, compact chat and answers are unchanged, and these lines never enter model input.

A Tool waiting for shared Guard capacity shows `queued · waiting for capacity` in every mode. The hint follows only the current committed pending intent, clears when waiting or the Run ends, never enters Events, history, replay or Provider context, grants nothing and does not survive restart; draft editing and Ctrl+C stay available.

Classic uses native scrollback above a bounded viewport. On its first draw for a Session it projects the newest whole-Run suffix, stopping before a Run that would exceed 16 Runs<!-- unrelated-bound: Classic viewport Run count -->, 64 KiB<!-- unrelated-bound: Classic escaped history buffer --> of escaped rendered row text (including trusted headings, rails and indents) or 4,096 rendered rows. Every native-visible objective, Tool summary and answer is counted before rows are materialized. A width-safe cue points to `arany show`. Omitted Runs stay in the journal, find and export and are not backfilled on redraw. Fullscreen uses an alternate screen with managed history and a bottom composer; Classic never borrows the alternate screen.

OSC 52 is written only on an explicit user copy gesture (Fullscreen selection release, Ctrl+C or Ctrl+Shift+C with a selection, or `/copy`), never because of model, Tool, MCP, Skill, hook or repository content. It is output-only: Arany never emits the `?` query and discards inbound OSC 52. Each gesture writes one sequence: the escaped copy payload with C0/C1 controls other than LF and TAB removed, base64-encoded under the fixed `c` selection and terminated by BEL, within the [clipboard copy limit](./entry-and-modes.md#public-limits-and-compatibility), written by the terminal owner on stderr and never in linear mode. No mode enables focus reporting or title OSC.

### Terminal continuity and provisional text

The saved `/settings` chat view selects the initial presentation, Fullscreen by default; `--classic` selects Classic for one process without saving. Saving a different view in idle `/settings` switches presentation within the Session, keeping draft, caret and reading anchors; a running task locks mode changes. `Ctrl+O` or `/transcript` appends bounded detail text to native scrollback in Classic and opens the [transcript pager](#transcript-pager) in Fullscreen; Ctrl+T does not. Both stay bounded with an explicit cue: Classic by the [detail limit](#transcript-detail-limit), the pager's `[` by its whole-Run bound. Details stay available during work without cancelling it or granting authority.

Geometry is bounded to 4,096 columns and 262,144 cells; zero or excessive geometry fails with a typed presentation error. Classic keeps raw ownership while inserting output above its content-sized viewport (at most the screen height) in batches of at most 64 native rows. Cursor queries go only through the stderr backend and the sole raw reader with a one-second deadline; an unavailable reply selects linear fallback before work, unsolicited replies are discarded, and query bytes never enter drafts, stdout or history. Cleanup uses the stored owned area, never queries a stopped reader and never clears settled primary-screen transcript.

Fullscreen follows new content only at the live tail; PageUp/PageDown and find keep older source anchors through generation, completion and resize, and returning live resumes following.

Classic delegates scrollback, selection and copy to the emulator. Every Classic surface (idle and streaming composer, completion menus, Tool approval, folder trust, setup, selectors, pickers and rewind) takes min(screen height, content height) with no floor. Selector lists show at most 10 rows, the linear page size, and scroll inside. Growing scrolls the rows above into native scrollback. A height change clears only from the lower of the old and new viewport tops, repaints and flushes pending native history in the same frame. Shrinking keeps the top while history remains above it, so the composer sits under the latest history with no blank rows; rows below stay empty until new output, and a viewport that filled the screen returns to the bottom row. History is never redrawn inside the viewport, so scrollback holds each row once. A dialog taller than the screen pages with Up, Down, PageUp and PageDown, and accepting stays blocked until its last page has been shown. PageUp/PageDown are ignored; Ctrl+F shows `Use your terminal's find; Ctrl+O writes details to scrollback`. A complete 200-line answer stays readable without duplicate final lines or intermediate frames.

Replies stream as source-backed provisional Markdown in one replaceable active location. Each changed snapshot or width re-renders atomically with the committed formatting and limits; unfinished syntax uses the parser's current interpretation without invented closing bytes, and growing tables can reflow earlier rows. Only the latest pending snapshot is kept; identical snapshots cause no parse or redraw. Strictly accepted completion replaces the candidate with the confirmed answer, inserted once into Classic scrollback. Compact presentation shows replies and Tool summaries; details add bounded inert operation and result facts and explicitly public model commentary. Reasoning, raw prompts, transport JSON and uncontrolled upstream errors stay excluded. Tool details neither renew approval nor execute anything; details and `show` list `spill:<digest>`, retained bytes and truncation, never implicit file contents.

Display checkpoints retain at most 32 KiB<!-- unrelated-bound: Session display text cap --> of final-result candidate and 32 KiB<!-- unrelated-bound: Session display text cap --> of public commentary per Run, at most 32 commentary items and 64 Events of at most 2 KiB<!-- unrelated-bound: display checkpoint Event payload --> each, including at most one compiled detail-limit cue. Excess commentary shows a cue; answer overflow remains a failed call. Checkpoints use bounded byte chunks, not one Event per token. After cancellation or abrupt interruption only acknowledged checkpoints reopen: `Answer` text formatted under an incomplete heading, `Commentary` as public commentary. Incomplete text is never an accepted Message, Provider history or compaction input. Validation-rejected candidates are withdrawn from presentation in both attached modes and stay qualified in the journal.

Classic exit removes transient input and panels and keeps the final conversation once. Fullscreen restores the previous shell screen with a brief receipt; text that the pager's `[` wrote stays in shell scrollback. Redirected stdout receives confirmed answers after each task in either mode, after read-only outcome confirmation. Exec publishes no display checkpoints; show JSONL includes display-only Events. Linear `/settings` can save the chat view without changing linear presentation. <a id="transcript-detail-limit"></a>`/transcript` shows safe detail text for at most 16 recent Runs and 64 KiB<!-- unrelated-bound: transcript command output cap --> per invocation, with a limit cue; JSONL export covers the complete journal.

Empty chat shows a short width-aware welcome and `/help`; without a selected Provider, welcome, input hint and status point to `/setup`. Hints never become draft bytes.

History shows committed objectives and terminal answers, labeled display-only incomplete text and public commentary, with bounded local notices interleaved. Notices never enter Events, Provider context, replay or `show`; they survive redraw and reacquisition and clear on Session change. Important errors have a textual heading. Confirmed failed or cancelled Runs show safe compiled guidance without invented answers, raw error bodies or automatic retries. Progress, panel-closure and copy-success cues are transient; a copy cue names its destination, and an OSC 52 copy reads `sent to terminal (OSC 52); it may be ignored`, because delivery cannot be confirmed. A failed copy shows `Copy unavailable: REASON` and an oversized one `Copy exceeds 97.7 KB; use arany show`; neither retries. Retained-draft cues stay separate from history notices; a notice uses status fallback if no row fits.

Failure feedback follows the terminal cause. A recoverable primary Tool denial shows in its Tool row with a compiled cause label and reaches the model once as the correlated result, without terminal failure guidance while continuation is admitted. If the next Provider call fails, the view shows that Provider failure, never denial or expired-approval guidance. An attested filesystem denial is not user denial. Optional AI-review failure followed by human denial keeps the human-approval guidance; completed effects are never described as rolled back. Unavailable approval-channel guidance asks for a new request from an interactive channel. Hook and permission-rule text never appear in denial feedback.

In Fullscreen, PageUp/PageDown navigate; Ctrl+F opens local literal find with grapheme Backspace, visible query and Enter and Escape hints; Ctrl+L returns to live. New content and resize keep an older source anchor and show a textual new-content cue. `arany show` is the canonical export; emulator scrollback is not complete history.

<a id="transcript-pager"></a>The transcript pager is modal: detailed History fills every row above one width-bounded key footer, the hidden composer keeps its draft, unowned keys do nothing, and pastes and clipboard results are discarded. It takes input during compaction too. Keys:

- `/` or Ctrl+F opens find from the newest match; `n` and `N` step to the next older and newer match.
- `j`/`k` or Down/Up move one row, Ctrl+U/Ctrl+D half a screen, PageUp/PageDown a screen, `g`/`G` or Home/End to the top and live end. Wheel, selection and copy work as in chat.
- `q`, Ctrl+O or Escape closes; Escape first closes find, then clears a selection. Ctrl+C keeps its chat meaning and cancels a Run.
- `[` releases mouse capture and the alternate screen and writes each Run's objective, details and committed answer to the primary screen, escaped like all human output. It keeps the newest whole Runs, at most 16 and 64 KiB<!-- unrelated-bound: conversation export text cap --> counting line endings and cues, starts with `Earlier Runs omitted; arany show prints the whole conversation` when older Runs are left out (or `The newest Run exceeds the transcript limit; arany show prints the whole conversation` when none fits) and ends with `Enter returns to Arany`. Streaming text shows as provisional. The Run continues without redrawing; Enter, Ctrl+C, a Tool approval or SIGCONT reacquires the screen and capture and returns to the pager. Exit, suspension, signals, errors and unwinding during the dump restore the terminal without clearing that text.

In Fullscreen, with [mouse capture](./selectors.md#selectors) the wheel scrolls History three rows. Click-drag selects History text, a double click a word (a whole URL inside `scheme://`) and a triple click a line. Selection shows in inverse video and stays anchored to source text through streaming, appends and resize; dragging past the top or bottom scrolls one row per motion event. Copied text is the escaped display text without role headings, rails, indents or Tool markers (`⏺`, `⎿`), with wrapped rows joined and messages divided by a blank line; its plain length is checked against the [clipboard copy limit](./entry-and-modes.md#public-limits-and-compatibility) before any Tool result is joined. With Copy on select (default), release copies and a successful copy clears the highlight, so the next Ctrl+C cancels as usual. Ctrl+Shift+C also copies, as does Ctrl+C with a selection while chat is idle; during a Run or compaction Ctrl+C always cancels. Escape clears a selection; a failed copy keeps it. The first copy in a process names the emulator's own selection gesture from `TERM_PROGRAM`: Fn-drag in Terminal.app, Option-drag in iTerm2, otherwise Shift-drag, with the whole list over SSH or in tmux, where it adds that wheel scrolling needs `set -g mouse on`. A selection grants nothing and never reaches Events, Provider context or diagnostics.

Fullscreen inline text panels (`/usage`, `/settings`, `/help`, quick actions) also support click-drag selection while mouse capture is on, highlighted in inverse video and underline so it differs from a focused row. Release copies under Copy on select, and Ctrl+Shift+C copies an existing selection. Copy uses the rendered escaped panel text with rows joined by line breaks, under the same size limit. A bounded cue shows success or failure while the panel stays open; failed copies keep the selection. Moving or resizing the panel clears its selection before the next frame. Escape clears a selection, then a later Escape closes the panel. Picker rows keep their mouse behavior.

|---|---|
| Idle | No empty agent dashboard |
| Selected-Provider admission | Local preparing row and next-Run model; no prior Run or context shown as current |
| Single active primary | One primary row |
| Team or attention | At most three stable primary-first, spawn-ordered agent rows, with `+N more` for overflow |

Preparing is transient admission feedback, not an Event or proof of inference; linear mode announces it once, and committed Events replace it. Every agent state and wait has a textual label, and completed or failed children stay visible while their Run is active. A queued or awaiting child never claims a dispatched Provider call. The attached view reduces committed Events in order and redraws once per burst of ready Events (at most 64); provisional answer observation is separate and never shows reasoning. Redraw happens only for committed Events, user actions or resize: no spinners, animations, idle refreshes or ticking clocks.

The status row shows interaction state and model, adds Provider from 50 columns and a title when space permits, and returns to ready after terminal outcomes; older-history navigation or actionable notices may take the row at narrow widths. `/status` opens a one-screen summary of the current or latest model, recorded latest-Run input and output tokens, remaining bytes in the pinned Arany request budget at Run admission, and the newest remaining plan windows for that Run's pinned ChatGPT account. Plan observations are chosen by account provenance and receipt time, never from another account or Provider; a newer one from a prior Run or route is labeled, and retained valid windows keep the [qualification](#reported-usage) of a later omission or rejected metadata. The byte budget is labeled an admission-time Arany request budget, never current or model context capacity. Missing windows and stale observations stay unknown; in-flight or interrupted reservations are marked pending. Model tokens show only recorded Provider usage, unknown values labeled unknown. Agent details give the last recorded call's input and output tokens. For a compacted Run, the inspector lists its bounded recent-file paths and digests on separate rows, matching the canonical `arany show` payload. Clipped printable ASCII model IDs keep both ends. The composer, `/status`, resume feedback, human export headings and discovery share one generated title, with explicit-title precedence; canonical title Events stay unchanged. Resume feedback names the conversation, not its UUID.

History rows derive only from the caller's loaded committed `SessionView`; indexing, search and drawing never read State, Workspace, credentials or Providers. During a Run, `/provider` and `/model` keep their submission-boundary selection. `/status` and `/usage` include usage through the committed Event watermark, label in-flight or interrupted usage pending and rebuild on committed changes or explicit inspection, never on a timer.

### Reported usage

`/usage` takes no arguments and opens a read-only paged token report while idle or running, including for an unsaved conversation without account access. It covers the current/latest Run, this Session's totals and separately labelled inherited history excluded from them; the [Session projection](../session.md#persistence-facts) owns accounting and pending-reservation uncertainty. Each scope groups the actual pinned Provider/profile and model. Tokens use grouped decimal counts. Cache reads/writes say `included in input` and are never added again; output includes reasoning where reported. A partial counter reads `12,340 known; some calls unreported`, no report reads `unknown (not reported)` and no calls reads `no calls yet`. Failed retry/fallback attempts count as unreported even after a later success. Pending reservations mark totals incomplete after a Run ends. No plan allowance, context capacity, billing cost or balance is inferred.

ChatGPT observations appear apart from token totals with local Run/route labels and `Account-level observation; not this Session's share`. A weekly row always appears, unknown when absent. Reported duration selects the label: 300 minutes is `5-hour`, 10,080 is `weekly`, others show their minute count and absent duration is unknown; slot names do not imply duration. `% used` rounds to at most one decimal; percentage and reset are unknown independently, and no allowance is inferred. Native OpenAI and Anthropic JSON and streaming invocation, including previews and role-routed calls, and both compaction paths add separate `API rate limits` rows with Run/route, role, Provider/model and header dialect. Compaction rows stay separate from invocation rows even with the same model; each dimension shows its known limit, remaining and reset independently, grouped counts including zero, and header receipt/source. Anthropic generic tokens say `Tokens (most restrictive limit)`; input, output and priority rows keep their own labels, with a notice that token counters may be rounded and dimensions are not additive. Counters are never converted to plan bars or summed. Missing facts read `unknown (not reported)` for routes without collected facts. Retries and fallbacks keep each attempt's actual route and identity, including an outgoing failed stream.

Each window and API row is `Last reported` with its stored absolute UTC receipt time and source. The terminal supplies the current time on inspection or committed update; the renderer reads no clock. Ages and relative resets use at most two nonzero units of seconds, minutes, hours and days (zero is `0 s`); a relative reset includes its UTC timestamp, and a missing reset reads `Reset unknown`. A future receipt or backward clock reads `Observation age unknown`, never fresh. A sample older than 15 minutes is stale, and after its reset passes reads `Stale; reset time passed, current usage unknown`; neither zeroes usage or advances a window. Reopened and prior-Run observations are historical; `show` keeps only stored timestamps. A later omission says `Latest call did not report limits`; invalid optional metadata adds a closed unavailable reason and receipt time while keeping earlier valid rows; a partial omission names unreported dimensions. Inspection never requests or refreshes limits, and age cannot rule out another client's consumption.

Both visual modes use the detail-dialog input barrier and keep draft, caret and history anchor on Escape; Ctrl+K's Usage action can inspect over a draft. Up/Down, Home/End and PageUp/PageDown scroll; Left/Right change pages. A page holds at most 16 route groups and 8 KiB<!-- unrelated-bound: MCP route status page --> of escaped text, showing its range when paged; narrow layouts wrap complete labelled fields vertically. Ctrl+C still cancels work. Linear/screen-reader mode writes every page as complete labelled text with no truncation, boxes, controls, color dependency or rewrites. The renderer reads only committed projections; report state never enters the journal or model input.
