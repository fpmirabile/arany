# Terminal: conversation, progress and history

## Conversation, progress and history

Answer headings carry any unguarded and host effect counts.

Attached assistant text (Fullscreen, its pager, Classic and agent results) renders Markdown: bold headings, emphasis, inline code and fenced or indented code in reverse style, pipe tables (header/value records when narrow), `• ` bullets, numbered lists, `│ ` quote rails, and links as underlined `label (destination)` (autolinks once). Links are inert text: nothing is fetched, opened or resolved, and no OSC 8 is emitted. HTML, images, strikethrough, task-list markers, thematic breaks and footnote references stay literal. Provisional and incomplete answers render the same way under their qualified headings. Formatting is display-only; copy, `show`, JSONL, linear output, `exec`, serve and ACP keep the source Markdown.

Rendering is bounded by [source bytes](../limits.md#max_markdown_parse_bytes), [nesting](../limits.md#max_markdown_depth), [events](../limits.md#max_markdown_events), [output](../limits.md#max_markdown_output_bytes), [rows](../limits.md#max_markdown_rows), [table columns](../limits.md#max_markdown_table_columns) and [table rows](../limits.md#max_markdown_table_rows). Past any bound the whole message shows as escaped literal text with one formatting-limit cue; the answer and its Run are unchanged.

Compact Tool rows read `⏺ Operation(arg)` with an indented `⎿ result`, without a `Tool ·` prefix or success word. A Fetch row names its URL, a Web search row its query, and a Search row its query, path and non-default options, such as `Search(fn \w+, src, regex, include **/*.rs, ignore case, offset 100, limit 10)`. Results give:

- bounded entry or line counts and readable sizes, including truncation;
- command exit status and total lines (`exit 0 · 12,340 lines (truncated)`), then nonzero selection counters (ignored entries with `(N pruned roots)`, oversized inputs, discarded outputs);
- `applied` for file changes;
- otherwise the disposition: `Error: ...` for a failed call, `denied`, `uncertain` and others by name.

Consecutive successful reads by one actor collapse into one row (`Read 2 files`, `Listed 2 directories`, `Searched for 2 patterns, read 2 files, listed 2 directories`); Git queries, Skills and MCP lists keep their own nouns, and details list each call. A multi-line command shows its first non-blank line plus ` …`. Pending, failed, denied, cancelled, conflicting, limited and uncertain calls stay distinct; failed commands append at most 80 cells of stderr. Rows carrying trust markers (unguarded, uncertainty, enforcement cause, checkpoint, denial source, cache problem, hook) never collapse; cache markers appear only for rejected, failed and uncertain updates. Limit rows name the cause: `timed out after DURATION` (with `; /settings raises it` only for Commands), `output passed 1.0 GB; stopped`, `no room left in this Run's context`, `too many reads at once; nothing was read`, `asked for more time than the pinned maximum` or `resource limit reached`. Truncation labels come from recorded totals, never from command output text. Presentation never changes the [Tool guarantees](../tools/README.md). Linear and screen-reader output use the same words, with an operation line and `Result:` instead of glyphs.

An active-Run notice names the unavailable action and an alternative, such as `/model changes are unavailable while a Run is active; Ctrl+C cancels`; empty submission says `Run is active; Ctrl+C cancels`. View-only commands still inspect.

Failed Run feedback separates an Engine-refused proposal from a Provider failure. A refusal shows its typed cause (arguments, phase, plan, budget, scope, grant, byte limit, lease, unavailable operation, answer or Delegate) and reason, then `The refused action was not dispatched.`, and is never blamed on the Provider. A Goal-budget stop shows the [numeric Goal feedback](../goals.md#budget-refusal-feedback), labelled `Arany status`. Attached chat, `exec` stderr and text `show` show the same committed facts, for the exact Run reported. Invalid agent definitions, stopped Tool steps, plan admission, unavailable Tool context, unverified workers, unmet criteria and refusal-limit failures each have distinct copy. A failed Run without an answer says so; earlier completed actions remain and uncertainty keeps its warning. [Execution](../execution/events-and-outcomes.md#accepted-outcomes) owns the causes.

Agent inspection and text `show` use the [Session worker projection](../session.md#worker-replay): an unknown Workspace publication is qualified and shows its untrusted path/digest report, and landed edits stay listed after completion, cancellation and pause. Inspection appends no Events and calls no Provider.

Committed Supervisor verdicts show as one dim line each, such as `Supervisor (shadow): possible loop; no action taken`, for the selected actor in agent inspection and for every actor in transcript details; the capped verdict adds `verdict limit reached`. [Serve](../serve.md#notifications-and-items) forwards the canonical verdict instead. Verdicts follow the [verdict cap](../execution/persistence.md#persistence-bounds), never appear in compact chat or answers and never enter model input.

A Tool waiting for shared Guard capacity shows `queued · waiting for capacity`. The hint is display-only, grants nothing and clears when waiting or the Run ends; editing and Ctrl+C stay available.

Classic writes history into native scrollback above a bounded viewport. On first draw it shows the newest whole Runs, at most 16 Runs<!-- unrelated-bound: Classic viewport Run count -->, 64 KiB<!-- unrelated-bound: Classic escaped history buffer --> of text or 4,096 rendered rows, with a cue pointing to `arany show`. Fullscreen uses the alternate screen with managed history and a bottom composer.

OSC 52 is written only on an explicit user copy (Fullscreen selection release, Ctrl+C or Ctrl+Shift+C with a selection, or `/copy`), never because of model, Tool, MCP, Skill, hook or repository content, and never in linear mode. Arany never queries the clipboard through OSC 52 and ignores inbound OSC 52. The payload is escaped, within the [clipboard copy limit](./entry-and-modes.md#public-limits-and-compatibility). No mode enables focus reporting or title changes.

### Terminal continuity and provisional text

The saved `/settings` chat view picks the presentation, Fullscreen by default; `--classic` selects Classic for one process without saving. Saving a different view in idle `/settings` switches it in place, keeping draft, caret and position; a running task locks the change. Linear `/settings` can save the chat view without changing linear output. `Ctrl+O` or `/transcript` appends bounded details to scrollback in Classic and opens the [transcript pager](#transcript-pager) in Fullscreen; Ctrl+T does not. Both work during a Run without cancelling it.

Geometry above 4,096 columns or 262,144 cells, or zero, fails with a typed presentation error.

Classic leaves scrollback, selection, copy and find to the emulator. Its surfaces (composer, menus, Tool approval, folder trust, setup, selectors, pickers and rewind) grow only as tall as their content, up to the screen; lists show at most 10 rows and scroll inside. The composer sits right under the latest history, and scrollback holds each row once. A dialog taller than the screen pages with Up, Down, PageUp and PageDown, and accepting stays blocked until its last page has been shown; otherwise PageUp/PageDown are ignored. Ctrl+F shows `Use your terminal's find; Ctrl+O writes details to scrollback`.

Replies stream as provisional Markdown in one place that updates until the answer is accepted; the confirmed answer then replaces it, appearing once in Classic scrollback. Compact view shows replies and Tool summaries; details add bounded operation and result facts and public model commentary, never reasoning, raw prompts, transport JSON or raw upstream errors. Tool details renew no approval; details and `show` list `spill:<digest>`, retained bytes and truncation, never file contents.

Display checkpoints keep, per Run, at most 32 KiB<!-- unrelated-bound: Session display text cap --> of answer candidate and 32 KiB<!-- unrelated-bound: Session display text cap --> of public commentary in at most 32 items, recorded as at most 64 Events of at most 2 KiB<!-- unrelated-bound: display checkpoint Event payload --> each; excess commentary shows a cue. After cancellation or a crash only acknowledged checkpoints reopen: `Answer` text under an incomplete heading and `Commentary` as public commentary. Incomplete text is never an accepted Message, Provider history or compaction input. A candidate rejected by validation disappears from the view. `exec` publishes no display checkpoints; `show` JSONL includes display-only Events.

Classic exit keeps the final conversation once. Fullscreen restores the previous shell screen with a brief receipt; text the pager's `[` wrote stays in shell scrollback. Redirected stdout receives each confirmed answer after its task. <a id="transcript-detail-limit"></a>`/transcript` shows details for at most 16 recent Runs and 64 KiB<!-- unrelated-bound: transcript command output cap --> per invocation, with a limit cue; JSONL export covers everything.

Empty chat shows a short welcome and `/help`; without a selected Provider, welcome, input hint and status point to `/setup`. Hints never become draft text.

History shows committed objectives and answers, labeled incomplete text and public commentary, with bounded local notices interleaved. Notices are display-only: never in Events, Provider context, replay or `show`; they survive redraw and clear on Session change. Important errors have a textual heading. Failed or cancelled Runs show compiled guidance without invented answers, raw error bodies or automatic retries. Progress and copy cues are transient; a copy cue names its destination, and an OSC 52 copy reads `sent to terminal (OSC 52); it may be ignored`, because delivery cannot be confirmed. A failed copy shows `Copy unavailable: REASON` and an oversized one `Copy exceeds 97.7 KB; use arany show`; neither retries.

Failure feedback follows the actual cause. A recoverable primary Tool denial shows in its Tool row and reaches the model once as the result, without failure guidance while the Run continues. If the next Provider call fails, the view shows that failure, not the denial. A filesystem denial is not a user denial. AI-review failure followed by human denial keeps the human-approval guidance; completed effects are never described as rolled back. With no approval channel, guidance asks for a new request from an interactive one. Hook and permission-rule text never appear in denial feedback.

Fullscreen follows new content only at the live end. PageUp/PageDown navigate; Ctrl+F opens local literal find with Backspace, visible query and Enter and Escape hints; Ctrl+L returns to live. While reading older history, new content shows a textual cue instead of moving the view. `arany show` is the canonical export; emulator scrollback is not complete history.

<a id="transcript-pager"></a>The transcript pager is modal: detailed History fills the screen above one key footer, the hidden composer keeps its draft, other keys do nothing, and pastes are discarded. It works during compaction too. Keys:

- `/` or Ctrl+F finds from the newest match; `n` and `N` step to the next older and newer match.
- `j`/`k` or Down/Up move one row, Ctrl+U/Ctrl+D half a screen, PageUp/PageDown a screen, `g`/`G` or Home/End to the top and live end. Wheel, selection and copy work as in chat.
- `q`, Ctrl+O or Escape closes; Escape first closes find, then clears a selection. Ctrl+C cancels a Run as in chat.
- `[` leaves the alternate screen and prints each Run's objective, details and answer to the shell screen: the newest whole Runs, at most 16 and 64 KiB<!-- unrelated-bound: conversation export text cap -->, starting with `Earlier Runs omitted; arany show prints the whole conversation` when older Runs are left out (or `The newest Run exceeds the transcript limit; arany show prints the whole conversation` when none fits) and ending with `Enter returns to Arany`. The Run continues meanwhile; Enter, Ctrl+C, a Tool approval or SIGCONT returns to the pager. Exiting or failing during the dump leaves that text in place.

In Fullscreen with [mouse capture](./selectors.md#selectors), the wheel scrolls History three rows. Click-drag selects text, a double click a word (a whole URL inside `scheme://`) and a triple click a line; dragging past an edge scrolls. Selection shows in inverse video and stays on its text through streaming and resize. Copied text is the display text without role headings, rails, indents or Tool markers (`⏺`, `⎿`), messages divided by a blank line, within the [clipboard copy limit](./entry-and-modes.md#public-limits-and-compatibility). With Copy on select (default), release copies and a successful copy clears the highlight, so the next Ctrl+C cancels as usual. Ctrl+Shift+C also copies, as does Ctrl+C with a selection while idle; during a Run or compaction Ctrl+C always cancels. Escape clears a selection; a failed copy keeps it. The first copy in a process names the emulator's own selection gesture from `TERM_PROGRAM`: Fn-drag in Terminal.app, Option-drag in iTerm2, otherwise Shift-drag, listing all of them over SSH or in tmux, where it adds that wheel scrolling needs `set -g mouse on`. A selection grants nothing and never reaches Events, Provider context or diagnostics.

Fullscreen inline panels (`/usage`, `/settings`, `/help`, quick actions) allow the same click-drag selection, shown in inverse video and underline to differ from a focused row; release (under Copy on select) or Ctrl+Shift+C copies the panel text within the same limit, with a success or failure cue. Moving or resizing the panel clears the selection. Escape clears a selection, then closes the panel.

| Work state | Activity |
|---|---|
| Idle | No empty agent dashboard |
| Selected-Provider admission | Local preparing row and next-Run model; no prior Run or context shown as current |
| Single active primary | One primary row |
| Team or attention | At most three stable primary-first, spawn-ordered agent rows, with `+N more` for overflow |

Preparing is transient feedback, not proof of inference; linear mode announces it once. Every agent state and wait has a textual label; finished children stay visible while their Run is active; a queued child never claims a Provider call. The view redraws only for committed Events, user actions or resize: no spinners, animations, idle refreshes or ticking clocks.

The status row shows interaction state and model, adds Provider from 50 columns and a title when space allows, and returns to ready after the outcome. `/status` opens a one-screen summary: current or latest model, latest-Run input and output tokens, remaining bytes of the Arany request budget as of Run admission (not context capacity), and the newest remaining plan windows for that Run's ChatGPT account, never another account's; observations from a prior Run or route are labeled and keep the [qualification](#reported-usage) of later omissions. Missing windows and stale observations show unknown; in-flight or interrupted usage shows pending. Tokens show only Provider-reported usage, else unknown; agent details give the last call's tokens. A compacted Run lists its recent-file paths and digests, as `arany show` does. Long model IDs are clipped in the middle. The composer, `/status`, resume feedback and exports share one generated title unless an explicit title exists; resume feedback names the conversation, not its UUID.

History rendering reads only committed Session history, never State, Workspace, credentials or Providers. During a Run, `/provider` and `/model` keep the Run's selection. `/status` and `/usage` refresh on committed changes or explicit inspection, never on a timer.

### Reported usage

`/usage` takes no arguments and opens a read-only paged token report, idle or running, also for an unsaved conversation without account access. It covers the current/latest Run, this Session's totals, and separately labelled inherited history excluded from them, grouped by pinned Provider/profile and model; the [Session projection](../session.md#persistence-facts) owns the accounting. Cache reads/writes say `included in input` and are never added again; output includes reasoning where reported. A partial counter reads `12,340 known; some calls unreported`, no report `unknown (not reported)` and no calls `no calls yet`. Failed retry/fallback attempts count as unreported. Pending reservations mark totals incomplete. No plan allowance, context capacity, cost or balance is inferred.

ChatGPT plan windows appear apart from token totals, labelled `Account-level observation; not this Session's share`. A weekly row always appears, unknown when absent. Reported duration picks the label: 300 minutes is `5-hour`, 10,080 is `weekly`, others show minutes. `% used` has at most one decimal; percentage and reset can each be unknown. Native OpenAI and Anthropic calls, including role-routed and compaction calls, add separate `API rate limits` rows per Run/route, role, Provider/model and header dialect, each dimension with its known limit, remaining and reset. Anthropic generic tokens read `Tokens (most restrictive limit)`, with a notice that counters may be rounded and dimensions are not additive; counters are never summed or shown as plan bars. Routes without facts read `unknown (not reported)`. Retries and fallbacks keep each attempt's actual route.

Each window and API row is `Last reported` with its UTC receipt time and source. Ages and relative resets use at most two units (seconds to days); a relative reset includes its UTC time, a missing one reads `Reset unknown`, and a future receipt reads `Observation age unknown`. A sample older than 15 minutes is stale, and after its reset passes reads `Stale; reset time passed, current usage unknown`; usage is never zeroed. Reopened and prior-Run observations are historical. A later call without limits adds `Latest call did not report limits`; invalid metadata adds an unavailable reason while keeping earlier valid rows; a partial omission names the missing dimensions. Inspection never requests limits, and age cannot rule out other clients' use.

The report keeps draft, caret and position on Escape; Ctrl+K's Usage action opens it over a draft. Up/Down, Home/End and PageUp/PageDown scroll; Left/Right change pages of at most 16 route groups and 8 KiB<!-- unrelated-bound: MCP route status page -->. Ctrl+C still cancels work. Linear mode prints every page in full as labelled text. Report state never enters the journal or model input.
