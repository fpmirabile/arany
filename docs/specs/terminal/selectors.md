# Terminal: selectors

## Selectors

Ctrl+K, `/settings`, `/model`, `/resume`, `/help`, `/agents`, `/usage` and `/status` open inline at the bottom; in Fullscreen, live history stays visible above. Rows read `N. label`, the focused row marked `›` in inverse video. The composer is hidden while a selector is open and returns with its draft and caret. Like [Tool approval](./commands.md#interactive-commands-and-completion), a selector discards keys typed before it is ready, including digits sent with Ctrl+K; Ctrl+C, signals, suspension and resize keep their meaning. Digits act only in short fixed lists (Ctrl+K actions and `/settings` rows); typed text filters `/model` and [searches `/agents`](#agent-picker).

Idle Ctrl+K offers Models, Agents, Resume, Setup and Usage, numbered 1-5, keeping the draft; with no Provider, Setup is focused. A digit or Enter activates; Escape or Ctrl+C closes. Switching Sessions needs an empty draft without images. It is locked during a Run; linear mode uses slash commands.

Bare `/model` opens a numbered model list for the current Provider and account. Up/Down focuses, Left/Right sets that row's effort, typing filters (at most 64 ASCII characters), Enter saves model and effort together and Escape changes nothing. Below 16 columns<!-- unrelated-bound: model selector minimum viewport width --> or eight rows it only closes. Linear mode uses numbered pages and `NUMBER [EFFORT|default]`.

Rows mark reviewed, listed or exact models. Unknown native models need an explicit effort and stay unproven until a response succeeds; ChatGPT choices need explicit levels; custom routes use their declaration. A changed native or ChatGPT model starts at low effort, the same model keeps its effort, and a Provider change clears both. Choosing loads no credential and starts no inference; the next Run revalidates account, consent and custom routes.

`/model` shows the cached list without reading the catalog, except for a catalog never read before, which loads first and can be cancelled. Ctrl+R (shown in the footer) and linear `/model refresh` re-read the catalog; the result reads `Model list refreshed` or the failure reason, and on failure the old rows stay, marked stale. [Startup](../provider/selection.md#per-role-selection-and-fallback) owns catalog refresh by age. Cancelling a load keeps the draft unsent.

The chosen model and effort, and the cached catalog, survive restart per Provider and account: a new Session restores them without loading a credential or calling the network, and a different or replaced account inherits neither. Explicit flags and resumed conversations win. A failure to remember is shown without undoing the choice. The cache holds at most eight sources of up to 4,096 models each, within 1 MiB<!-- unrelated-bound: terminal model catalog cache -->, dropping the oldest unselected source first. Cached entries never authorize an account, model, effort, route or inference, and the cache is [tolerant](../execution/persistence.md#incompatible-records): invalid content is dropped. With nothing saved, a new Session may reuse the model and effort of the latest Session in the same Workspace.

A selection blocked by another Session operation shows feedback without saving or retrying. An unavailable ChatGPT account or invalid custom choice keeps the selection and starts no sign-in, fallback or inference. Catalog failure changes no defaults.

<a id="agent-picker"></a>`/agents` lists agents of the 16 most recent Runs, newest first, primary first, with identity, state, objective, summary and result previews; `show` has older history. A Tool that failed before dispatch shows its Guard stage and check. The header separates current-Run counts from totals; each row reads `Run N: <agent>; <status> · <objective>`. Its argument form sets next-Run collaboration: new conversations default to `single`, and `/agents auto` enables delegation. Enter opens the focused [agent chat](#agent-chats), even from an older Run.

- **Search.** Typed text, digits included, searches labels and objectives, ignoring case. The line reads `Type to search N agents`, `Search: TEXT · M of N agents` or `Search: TEXT · no matching agents`; text past the limit or outside printable ASCII is refused with `Search takes up to 64 ASCII characters`.
- **Idle collapse.** Running, failed, cancelled, interrupted and stopped rows always show. Idle rows past the [inspection limit](./entry-and-modes.md#public-limits-and-compatibility) collapse into an `N idle agents` row; Enter on it expands them. Rows never collapse on a timer, and the focused row never collapses.
- **Focus.** Focus stays on the same agent as rows move; if that agent disappears nothing is focused (`No agent focused; Up or Down focuses one`) and Enter does nothing.
- **Inline keys.** Arrows focus, Home/End jump, PageUp/PageDown scroll the focused row's details, Backspace edits the search and Escape returns to the primary.
- **Linear.** Prints the header and search line, `Choices A-B of M:`, numbered rows with ` (focused)` after the focused one, its details, and `Agent choice: n next, p previous, number select, o open, /TEXT search, q close:`. Numbers focus a row or expand the idle group; `n`/`p` move focus, `/TEXT` searches and `/` clears, `o` opens the focused row (`No agent focused; choose a number first` otherwise), and other input prints `Notice: invalid agent selection`.

<a id="agent-chats"></a>With an empty composer and nothing else open, Alt+Left and Alt+Right cycle through the current (else latest) Run's agents: the primary, then children in spawn order, wrapping around. On macOS `ESC b` and `ESC f` (Option+Left/Right) do the same. Without children the notice reads `No child agents in this Run`; with children the composer border shows `Alt+Left/Right agents`.

A child view shows the child's committed transcript: its assignment under `Assignment:`, its recent Tool rows, its result under `Agent result:` and its status (`Error: child N failed: REASON`, cancelled, interrupted, `private outcome unknown`); a working child reads `child N is working; its committed activity appears here`. Reasoning, prompts and uncommitted text never appear. <a id="live-agent-chat"></a>The view updates as the child's committed Events arrive, like the [main view](./conversation.md#conversation-progress-and-history); linear mode prints new records under `New activity from child N:`. Other agents' Events never change it. After a journal gap the view reloads; a child that no longer exists returns to the primary with `That agent is no longer in this Run; back to primary`, and unreadable history shows `Run history unavailable; check Session history`.

The panel shows `viewing child N (message)` with a separate text-only composer when the child can take guidance (an Active child of the latest Active Run in a Running Goal); otherwise `viewing child N (read-only)`. The primary draft stays separate. Enter sends literal guidance to that exact child only, never invoking a command or Skill. Child drafts are limited to 8 KiB<!-- unrelated-bound: child message draft cap -->, without images or completion. `Note waiting for child N's next step` acknowledges only the local offer; `Steering note recorded for child N` appears once recorded, which does not prove the child read it. Editing withdraws the waiting offer; if the withdrawal fails, the outcome stays unknown until history confirms it. Each recorded note appears once in the child transcript as `Steering note (sent during the child's work):` after the Tool rows. If the child finishes, or the Run ends, pauses or fails, before taking the note, the text is kept with non-delivery or unknown-outcome feedback.

Child drafts follow the [public bounds](./entry-and-modes.md#public-limits-and-compatibility); nonempty drafts are never retargeted. A finished child's draft stays visible but cannot be sent; Backspace or Delete (or linear `/clear`) clears it and frees its slot. Escape returns to the primary keeping the draft and cancelling nothing; Ctrl+C still cancels the Run. A Tool approval closes the view but keeps drafts and waiting notes. The view stays readable after the Run ends.

Fullscreen draws the child in place of History, scrolling with PageUp/PageDown, Home/End and the wheel. Classic appends `Viewing child N (message)` or `Viewing child N (read-only)` and the transcript to scrollback, then `Back to primary` on return. Inline, `/transcript agents` opens the first child and `/transcript agents N` agent N (1 is the primary) in every mode. Linear and screen-reader mode print `Agent chats in this Run:`, numbered `N. label · status · objective` rows and `Agent chat: number opens, n next, p previous, q returns to primary:`; `q` prints `Back to primary`, and other input reports `Invalid agent choice; type a number, n, p or q`. In a child that can take guidance, `/message TEXT` sends text and `/clear` clears the draft; controls are at most 16 ASCII bytes. A new message cannot overwrite a retained draft until it is cleared. Viewing a child calls no Provider, changes nothing and records nothing; each process starts at the primary.

`/goal` alone shows the current or last Goal: short ID, status, phase, mode (autonomous or single-Run), Runs, provider calls, known tokens (flagging unknown usage) and active time, each against its budget. A paused (Interrupted) Goal ends with `Use /goal resume to continue`, or `out of budget` when no further Run fits; `/goal resume` then closes it as Failed with its report. If the paused Goal is not the one shown, a second line reads `Paused Goal SHORT can be resumed with /goal resume` or `Paused Goal SHORT is out of budget`. Unknown recorded include paths replace those hints with the `GoalIncludesUnavailable` guidance below. With no Goal, a short notice appears.

`/goal resume` continues the most recent paused Goal with its pinned objective and phase, even after newer Goals finished; older paused Goals are history, and with none paused it reports an error. A Goal with unknown include paths refuses to continue with `GoalIncludesUnavailable` ("Goal include paths are unknown; start a new Goal with explicit inputs") under the [recorded-include rule](../goals.md#budget-continuation). `/goal continue` starts a new Goal from the most recent budget-exhausted one with the current budgets ([continuation rule](../goals.md#budget-continuation)), or reports `No exhausted Goal is available to continue`. Only the exact words `resume` and `continue` (ignoring case and surrounding spaces) are commands; `resume now` is an objective. `/goal OBJECTIVE` starts an autonomous Goal with the default budget that keeps starting Runs until its criterion is met or it stops; if a later Run cannot start, the last answer appears, then `Error: Goal stopped after this Run: REASON` and the resume hint. Plain messages are one-Run Goals. A paused Goal leaves the Session usable: a plain message or `/goal OBJECTIVE` starts a new Goal.

During a Run, `/goal` shows status and Goal changes are locked. A new message becomes a retained draft; during an autonomous Goal it reads `Draft retained; press Enter after this Goal to submit`. Ctrl+C cancels the Run and further iterations; the Goal stays Interrupted for `/goal resume`. A Goal started with `/goal` then notes `Goal paused; use /goal resume to continue.` or, with no budget left, `Goal paused and out of budget; /goal resume will close it.`; a plain message's Goal notes `Interrupted. Send a message to continue.` A plain Goal's budget stop reads `Stopped after N Provider calls (limit set in /settings). Send a message to continue.` (tokens or active time likewise), preceded by `The model requested another Tool, but no Provider call remained to read its result.` when that is why it stopped; the `Committed refused reservation detail is unavailable.` sentence appears only in `show`. The hint, the notice and `/goal resume` agree on whether another Run fits. `/resume-goal` is an unknown command.

`/resume` opens the Workspace's conversation picker; `/resume SESSION_ID` selects one directly. Rows show titles, not IDs. Untitled conversations use their first objective (at most 128 UTF-8 bytes) or `Empty conversation`; answers never supply a title, and `/rename` always wins. A fork inherits the title and model of its source. `arany --resume SESSION_ID --resume-goal GOAL_ID` resumes that paused Goal at startup, with PROMPT as resume text. Startup shows `New conversation · /help for commands` or `Session SESSION_ID · /help for commands` unless a setup notice takes precedence. See [Goal recovery](../goals.md#lifecycle-budgets-and-recovery).

State directory and history reload failures in an interactive Session are notices, not exits: conversation, composer and draft stay. This covers `/resume`, `/fork`, `/rename`, `/model`, `/provider PROFILE`, `/agents POLICY`, `/compact`, and reloading after a Run or compaction; unknown submission acceptance uses the [recovery dialog](./drafts-and-paste.md#paste-and-attachments) instead. Notices:

- `Error: state directory unavailable or unsafe` when State is unusable before a change.
- `Error: Forked Session ID, but it could not be opened: REASON` and `Error: Renamed Session, but it could not be reloaded: REASON` after `/fork` or `/rename` saved.
- `Error: Settings saved, but the conversation could not be reloaded: REASON` after `/model`, `/provider PROFILE` or `/agents POLICY` saved; `/model` still remembers the choice for new conversations.
- After a Run or compaction, `; Error: history could not be reloaded: REASON; use /resume to reload it`; after a Run in visual modes, `; Error: history could not be reloaded: REASON; the committed answer was not shown; use /resume to reload it`.

Linear mode also writes `Committed answer not shown; read it with: arany show --output text RUN_ID` to stderr, or `Committed answer not shown; read it with: arany show --state-dir 'DIR' --output text RUN_ID` after an explicit `--state-dir DIR` (quoted for the shell; `ARANY_STATE_DIR` and the default need no argument), and its notice ends `; Error: history could not be reloaded: REASON; the committed answer was not shown; see the command above`. Linear and non-TTY Fullscreen print no answer or receipt until a reload succeeds; a later successful reload prints them. A Run whose record contradicts its outcome is an integrity failure. These failures end the Session and restore the terminal: `/setup`, rendering, input or cleanup failures, signals, shutdown, Workspace, append, replay and integrity failures, and failing to create the first Session.

Picker details show creation and last activity in UTC, access route and model; narrow widths shorten dates. Keyboard and mouse both select; only list rows activate. Linear choices give full dates without UUIDs.

Credentials and the saved source preference belong to the OS user. Resuming a conversation keeps its selection, else uses its latest Run's model, else the current or saved choice. Missing or replaced credentials never switch to another account or billing route; the next Run still checks credentials and consent. In chat an empty list gives guidance and an unavailable one an error; before a Session exists either fails.

Classic never captures the mouse. Fullscreen captures clicks, drags and the wheel while it owns the terminal, and selectors share it: picker and agent rows take clicks and the wheel, and every action also has a key. Setting `ARANY_DISABLE_MOUSE` to anything but `0` turns capture off and lets the terminal turn the wheel into Up/Down, which scroll History one row while the composer is empty and no menu, picker or recall is open. Closing, suspending, failing, switching chat view or falling back to linear mode releases the mouse before anything else.
