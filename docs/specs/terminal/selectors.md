# Terminal: selectors

## Selectors

Ctrl+K, `/settings`, `/model`, `/resume`, `/help`, `/agents`, `/usage` and `/status` open inline in the bottom area, with no centered box. In Fullscreen, live history fills the rectangle above and keeps following a running task, as above Tool approval; in Classic the selector draws in the grown viewport. Rows read `N. label`; the focused row is marked `›` in inverse video. A `/settings` row too wide for one line puts its value on the next line. The composer is hidden while a selector owns input and returns with its draft and caret. Every selector uses the [Tool approval admission barrier](./commands.md#interactive-commands-and-completion): unarmed first (dim rows, no focus or key hint; linear rows without the prompt), then armed. Keys typed before the armed frame, including digits sent with Ctrl+K, are discarded; Ctrl+C, signals, suspension and resize keep their meaning. A selector opened from Ctrl+K arms again. Digits act only in fixed short lists (Ctrl+K actions and `/settings` rows); typed text filters `/model` and [searches `/agents`](#agent-picker), where digits are search text.

Idle Ctrl+K offers Models, Agents, Resume, Setup and Usage, numbered 1-5, without consuming the draft; with no Provider, Setup has initial focus. A digit activates; Up/Down selects; Enter activates; Escape or Ctrl+C restores draft and caret. All five fit at 16×8. Session switching requires an empty draft with no outstanding images. Opening performs no catalog or credential I/O. It is locked during a Run; linear mode uses slash commands.

Bare `/model` opens an idle numbered catalog above the retained composer. Up/Down focuses models, Left/Right sets that row's tentative effort, and filtering keeps per-row choices. Enter saves model and effort atomically; Escape changes nothing; an empty filter result activates nothing. The panel overlays the transcript without moving the history anchor; its local ASCII filter (at most 64 characters) never enters Session, context or scrollback. Below 16 columns<!-- unrelated-bound: model selector minimum viewport width --> or eight rows only resize and close work. Linear mode uses numbered pages and `NUMBER [EFFORT|default]`.

Metadata marks reviewed, listed or exact choices. Unknown native models need explicit effort and stay unproven until a strict response succeeds; ChatGPT choices need explicit levels; custom tuples use their declaration. A changed native or ChatGPT model starts at low effort, the same model keeps its effort, and a Provider change clears both. Selection loads no token and starts no inference; Run admission revalidates account, consent and custom evidence.

`/model` opens on the cached rows of the shown Provider and account without a catalog read; only one whose catalog was never read loads it first, cancellably and input-owned, and catalog age is left to the [startup read](../provider/selection.md#per-role-selection-and-fallback). Ctrl+R, shown in the picker footer and never filter text, and `/model refresh`, for linear input, always re-read the shown Provider's catalog whatever its age and update the cache and rows; a read in flight is joined, not repeated, and never blocks selection. The result reads `Model list refreshed` or the failure reason. Refresh failure keeps old rows visibly stale; replacement keeps filter, model identity and admissible effort. Linear numbers stay bound to the opened snapshot. Completion or cancellation during loading keeps draft text without submitting it; queued typeahead is not guaranteed. Custom declarations load locally.

Saved-account tuples and catalog IDs survive restart. A new bare Session restores the last acknowledged tuple for the same Provider and account UUID and seeds cached rows without loading a credential or calling the network; OS-store authorization is a separate phase. Explicit flags and resumed defaults win; a different or replaced account inherits neither tuple nor catalog. Restored rows change only through the startup read, Ctrl+R or `/model refresh`. A remembering failure is visible without undoing the selection. The cache holds at most eight sources, each with its last catalog read time and up to 4,096 IDs with their optional context windows, within 1 MiB<!-- unrelated-bound: terminal model catalog cache --> in aggregate, evicting the oldest unselected source first; a missing read time means never read and a missing window means default bounds. A separate optional Provider and account pointer remembers explicit setup, model and resume choices; refresh never changes it, and token-free preferences without it stay readable. Stored availability never authorizes an account, model, effort, custom destination or inference, and the record is [tolerant](../execution/persistence.md#incompatible-records): an invalid source or dangling pointer is dropped, and a malformed or over-limit record reads as empty and grants nothing. With no saved preference, startup may copy only the matching model and effort from the latest valid Session in the same Workspace into a new empty Session.

A selection rejected by another Session operation's lock gives labeled feedback without saving or retrying. An unavailable ChatGPT account or invalid custom choice keeps the selection and starts no sign-in, fallback or inference. Catalog failure changes no defaults; published account work is not rolled back. State, replay and terminal-owner failures keep their fatal boundary.

<a id="agent-picker"></a>`/agents` inspects primary-first agents from the 16 most recent Runs, newest first, with bounded inert identity, state, objective, summary and result previews. A Tool row that failed before dispatch shows its typed Guard stage and check. The header separates current or last Run counts from historical totals; each choice reads `Run N: <agent>; <status> · <objective>`. Its argument form changes only next-Run collaboration; new conversations default to `single`, and `/agents auto` opts into delegation. Enter opens the focused child's [agent chat](#agent-chats), even from an older Run, or the primary chat on a primary row.

- **Search.** Typed text, digits included, searches each row's label and objective locally, ignoring ASCII case. The line reads `Type to search N agents`, `Search: TEXT · M of N agents` or `Search: TEXT · no matching agents`; a character past the limit or outside printable ASCII leaves the search unchanged with `Search takes up to 64 ASCII characters`.
- **Idle collapse.** Running, failed, cancelled, interrupted and stopped rows always show. The first idle rows up to the [inspection limit](./entry-and-modes.md#public-limits-and-compatibility) show and the rest collapse into a final `N idle agents` row; Enter on it expands every row in place, focuses the first revealed one and arms again. Rows collapse or expand only through committed status changes or that Enter, never on a timer, and the focused row never collapses.
- **Focus.** Focus belongs to the row's Run and AgentRun identity: committed changes move rows but never the focus; a vanished focus leaves nothing focused (`No agent focused; Up or Down focuses one`), and with no match nothing is focused, so Enter does nothing.
- **Inline keys.** A window of numbered rows follows focus; arrows focus, Home/End jump, PageUp/PageDown scroll the focused row's details, Backspace edits the search and Escape closes to the primary.
- **Linear.** Prints the header and search line, `Choices A-B of M:`, numbered rows with ` (focused)` after the focused one, its details, and `Agent choice: n next, p previous, number select, o open, /TEXT search, q close:`. Numbers bind to the printed rows and focus a row or expand the idle group; `n`/`p` move focus, `/TEXT` searches and `/` clears, `o` opens the focused row (`No agent focused; choose a number first` otherwise), and other input prints `Notice: invalid agent selection`. Committed changes print nothing; each reprint follows a choice and arms again, and incomplete input is discarded if work ends.

`show` exposes complete older history.

<a id="agent-chats"></a>With an empty composer (no text or images) and no completion menu, selector, pager, approval or clipboard read, Alt+Left and Alt+Right cycle through the current, else the latest, Run's agents: the primary, then children in committed spawn order, wrapping at both ends. On macOS, `ESC b` and `ESC f` (Option+Left/Right without enhanced keys) do the same; elsewhere they stay inert. A draft or popup keeps the keys, and plain or Ctrl+Left/Right keep their editing meaning. Without children the notice reads `No child agents in this Run`; with children the empty composer's border names `Alt+Left/Right agents`.

A child view is a committed transcript drawn by the ordinary escaped History: the child's assignment under `Assignment:`, its newest whole safe Tool rows, its result or summary under `Agent result:`, and its status with its qualification (`Error: child N failed: REASON`, cancelled, interrupted, `private outcome unknown`); a working child reads `child N is working; its committed activity appears here`. Reasoning, prompts, provisional and uncommitted text never appear. <a id="live-agent-chat"></a>It follows the child's committed Events: after each [burst](./conversation.md#conversation-progress-and-history) that changes a shown fact, Fullscreen redraws once, Classic appends only the new whole records, and linear mode prints them under `New activity from child N:`. A working child's read group appears once its boundary is known, and a changed status appears once. Sibling or primary Events, same-fact reloads and the primary's provisional text or waiting hint draw nothing and never change the selection; no timer redraws a quiet view. A sequence gap or journal resync reloads the validated Session view and rebuilds the selection by Run and AgentRun identity; a child that no longer resolves returns to the primary with `That agent is no longer in this Run; back to primary`. Unreadable history ends the Run view with `Run history unavailable; check Session history` and shows no unvalidated text.

The bottom panel shows `viewing child N (message)`, with a separate text-only composer, for an eligible latest Active Run's Active child in a Running Goal; other children show `viewing child N (read-only)`. The primary composer, images, caret and History anchor stay separate. Enter offers literal guidance to the exact Session/Run/AgentRun target, never to the primary, siblings or review, and never invokes a command or Skill, even for slash-looking text. Text paste uses the 8 KiB<!-- unrelated-bound: child message draft cap --> draft limit; images and command/Skill completion are disabled. `Note waiting for child N's next step` acknowledges only the local offer; `Steering note recorded for child N` appears only after its committed Event, which does not prove remote receipt. Editing withdraws only that target's waiting offer; an unsuccessful withdrawal leaves the outcome unknown until history confirms it. Each committed note appears once in the child transcript as `Steering note (sent during the child's work):` plus escaped text after the Tool rows (the journal records no step position for notes), within the transcript budget. A child that finishes without another authorized boundary, or Run settlement, pause or failure, keeps unacknowledged text with non-delivery or unknown-outcome feedback.

Child drafts follow the [public bounds](./entry-and-modes.md#public-limits-and-compatibility): nonempty drafts are never evicted or retargeted, and a full draft table refuses another editable target. A finished child's retained draft stays visible but cannot submit; Backspace or Delete (or linear `/clear`) clears it locally and also drops an unknown-outcome offer of a child that can no longer take notes, freeing its slot. Alt navigation needs an empty child draft and no clipboard owner. Escape returns to the primary with the draft kept and cancels nothing; Ctrl+C keeps its Run cancellation meaning and leaves the view open. A Tool approval, even an unrelated primary one, keeps waiting offers and drafts, closes the view and arms on its own; the Engine takes a waiting note at that child's next boundary after the approval settles. The end of a Run leaves the chosen view readable.

Fullscreen draws the child in place of History, where PageUp/PageDown, Home/End and the wheel scroll it and new records are followed only at the live tail; primary History, draft and anchor are untouched. Classic appends a `Viewing child N (message)` or `Viewing child N (read-only)` boundary and the transcript to native scrollback, holds primary rows until return, then appends `Back to primary` without repainting settled rows. Every switch, return, resize and resumption draws unarmed, discards earlier input and then draws armed. Inline, `/transcript agents` opens the first child; `/transcript agents N` opens agent N (1 is the primary) in every mode. Linear and screen-reader mode print `Agent chats in this Run:`, numbered `N. label · status · objective` rows and `Agent chat: number opens, n next, p previous, q returns to primary:`; numbers bind to that list, `n`/`p` wrap, `q` prints `Back to primary`, and other input reports `Invalid agent choice; type a number, n, p or q`. In an eligible child, `/message TEXT` offers literal text under the 8 KiB<!-- unrelated-bound: child message draft cap --> bound and `/clear` clears the retained draft. Controls keep their 16 ASCII byte bound. Empty or oversized messages leave selection and drafts unchanged; a different message cannot overwrite a retained draft until it is cleared. Selection alone calls no Provider, changes no Run, Goal or grant and writes no Event; it is local and starts at the primary in each process.

`/goal` alone shows the current or last Goal read-only: short ID, status, phase, mode (autonomous or single-Run), Runs, provider calls, known tokens with any unknown-usage flag and active time, each against its pinned budget. A paused (Interrupted) Goal ends with `Use /goal resume to continue`, or `out of budget` when no next Run is admitted; such a Goal is not offered for resume, and `/goal resume` closes it as Failed with its report. If the paused Goal is not the one shown, a second line reads `Paused Goal SHORT can be resumed with /goal resume` or `Paused Goal SHORT is out of budget`. Unknown recorded include paths replace those hints with the `GoalIncludesUnavailable` guidance below. With no Goal, a short notice appears.

`/goal resume` continues the most recent paused Goal at once with its pinned objective and phase, even after newer Goals finished; older paused Goals are history, and with none paused it reports an error. A Goal with unknown (null) admitted include paths refuses its next Run with `GoalIncludesUnavailable` ("Goal include paths are unknown; start a new Goal with explicit inputs"), without an Event or Provider call, under the [recorded-include rule](../goals.md#budget-continuation). `/goal continue` starts a new Goal from the most recent budget-exhausted Goal under the [continuation rule](../goals.md#budget-continuation), with the current saved budget and resource settings, or reports `No exhausted Goal is available to continue`. Only the exact words `resume` and `continue` (ignoring ASCII case and surrounding spaces) are commands; other text, such as `resume now`, is an objective. `/goal OBJECTIVE` starts an autonomous Goal with the default budget that keeps starting Runs until its criterion is met or it stops; if a later admission fails after a committed Run, that answer appears, then `Error: Goal stopped after this Run: REASON` and the resume hint. Plain messages are one-Run Goals. A paused Goal leaves the Session usable: a plain message or `/goal OBJECTIVE` starts a new Goal.

During a Run, `/goal` shows status and Goal changes are locked. A new message becomes a retained draft; during an autonomous Goal it reads `Draft retained; press Enter after this Goal to submit`. Ctrl+C cancels the Run and further iterations. A cancelled Goal stays Interrupted for `/goal resume`, without a terminal receipt. A Goal started with `/goal` notes `Goal paused; use /goal resume to continue.` or, when no next Run is admitted, `Goal paused and out of budget; /goal resume will close it.`; a plain message's Goal notes `Interrupted. Send a message to continue.` A plain Goal's budget stop reads `Stopped after N Provider calls (limit set in /settings). Send a message to continue.` (tokens or active time likewise), preceded by `The model requested another Tool, but no Provider call remained to read its result.` when its last primary call was a decoded proposal refused only by budget admission; interactive output omits the `Committed refused reservation detail is unavailable.` sentence that `show` keeps. The hint, the notice and `/goal resume` share one admission rule: an unaccepted trailing link is not a Run, and an unsettled active-time reservation counts as spent. `/resume-goal` is an unknown command.

`/resume` opens the Workspace picker; `/resume SESSION_ID` selects exactly. Numbered rows show titles, not IDs. Generic titles use the first objective (at most 128 UTF-8 bytes, whitespace normalized) or `Empty conversation`; answers never supply a title. Non-placeholder creation titles and `/rename`, even placeholder-looking, win. Projection makes no Provider call and rewrites no Event or context; a fork derives inherited title and model only through its recorded prefix, pinning a bounded inherited title to its verified source prefix. `arany --resume SESSION_ID --resume-goal GOAL_ID` resumes that paused Goal at startup, with PROMPT as resume text. Every startup objective, including a Goal resume without PROMPT, shows `New conversation · /help for commands` or `Session SESSION_ID · /help for commands` unless a setup notice takes precedence. See [Goal recovery](../goals.md#lifecycle-budgets-and-recovery).

In the interactive Session, State directory and history reload failures are notices, not exits: conversation, composer and draft stay. This covers `/resume`, `/fork`, `/rename`, `/model`, `/provider PROFILE`, `/agents POLICY`, `/compact`, and history reload after any Run or compaction; unknown submission acceptance instead uses the [submission recovery dialog](./drafts-and-paste.md#paste-and-attachments). Notices:

- `Error: state directory unavailable or unsafe` when State cannot be admitted before a change.
- `Error: Forked Session ID, but it could not be opened: REASON` and `Error: Renamed Session, but it could not be reloaded: REASON` after `/fork` or `/rename` saved.
- `Error: Settings saved, but the conversation could not be reloaded: REASON` after `/model`, `/provider PROFILE` or `/agents POLICY` saved; `/model` still remembers the selection for new conversations and appends any remembering error.
- A reload failure after a Run or compaction appends `; Error: history could not be reloaded: REASON; use /resume to reload it`; after a Run, the visual modes append `; Error: history could not be reloaded: REASON; the committed answer was not shown; use /resume to reload it`.

Linear `/resume` and `/transcript` show only headers or incomplete text, so linear mode also writes an untruncated stderr line `Committed answer not shown; read it with: arany show --output text RUN_ID`, or `Committed answer not shown; read it with: arany show --state-dir 'DIR' --output text RUN_ID` after an explicit `--state-dir DIR` (single-quoted, embedded quotes escaped; `ARANY_STATE_DIR` and the default store need no argument). Linear notices truncate to 240 cells, so the linear hint is `; Error: history could not be reloaded: REASON; the committed answer was not shown; see the command above`. Linear and non-TTY Fullscreen print neither answer nor receipt until reload succeeds. A failed reload keeps the displayed history and persists as history; a later successful reload after automatic compaction drops the earlier error and prints the answer and receipt. A failed post-compaction reload reports once with the same guidance, and an interrupted submission before admission persists its reload failure the same way. A Run whose committed record contradicts its outcome is an integrity failure. Fatal failures end the Session and restore the terminal: `/setup`, terminal rendering, input or cleanup, signals, shutdown, Workspace, append, replay and integrity failures, and first-Session materialization.

Focused picker details show creation, last committed activity in UTC, access route and model; an uncommitted conversation fabricates no activity. Narrow widths shorten dates. Keyboard and mouse keep selection; only list rows activate. Linear choices announce full dates without UUID labels.

Credentials and the saved-source preference belong to the OS user. A configured conversation keeps its selection. Without one, resume recovers its latest pinned Run tuple, else the current selection or saved preference; account-only defaults can recover the same account's remembered tuple. Inheritance, including collaboration policy, is persisted before switching. Missing or replaced pinned credentials never select another account or billing route; Run admission still validates credentials and consent. In chat, an empty list gives guidance and an unavailable list an error; before Session entry either fails. Rendering, input and cleanup errors propagate to restoration and exit.

Classic never enables mouse reporting or alternate scroll. Fullscreen enables button, drag and SGR reporting (`?1000`, `?1002`, `?1006`, never `?1015`) while it owns the terminal, and selectors share that capture: Session-picker and agent-inspector rows take clicks and the wheel, off-list input is inert, and every action has a keyboard equivalent. Any-motion (`?1003`) is added only after a graphics protocol is detected and while capture is on. `ARANY_DISABLE_MOUSE` set to anything but `0` disables mouse reporting and enables alternate scroll (`?1007`) instead; Up/Down then scroll History one row only while the composer is empty and no menu, picker or draft recall is pending. Close, suspension, cancellation, failure, a chat-view switch, linear fallback and loss of ownership disable every pointer mode before control returns.
