# Provider: outcome encoding, caching and streaming

## Structured outcomes and Tool encoding

- Run answers are plain assistant text; earlier text is commentary, and there is no Finish function or model-authored summary/result split. On every adapter, unknown, unoffered or incomplete calls, malformed text parts, non-object or wrongly typed function fields and wire-byte overflow reject without alternate decoding. An offered call that decodes into a bounded typed Tool proposal reaches Engine argument validation with its usage kept; invalid paths and other semantic argument failures get the [committed refusal result](../execution/events-and-outcomes.md#accepted-outcomes), are not wire parse failures and consume no outcome correction.
- Responses (native and ChatGPT): explicit `commentary` text may precede or interleave with calls; without a call, exactly one final message is the answer, its ordered text parts joined without inserted or repaired bytes, and a missing or null phase counts as final. Without a call or final message, the last commentary is the answer; a blank answer is the Engine's `answer_invalid` refusal. A final answer beside calls, commentary after it, unknown phases, malformed or refusal blocks, extra finals and non-null error or incomplete markers reject. An unknown non-call output item stays in the raw replay and decides nothing; an unknown `*_call` item rejects.
- OpenAI API and ChatGPT requests offer one constant list of strict native functions: catalog-available operations, primary `arany_plan` when [Goals](../goals.md#initial-plan-contract-and-success-receipt) offer it and `arany_delegate` when collaboration permits children. Phases restrict it with `tool_choice: {"type":"allowed_tools","mode":"auto","tools":[{"type":"function","name":"arany_…"}]}` and decoding admits only that subset; read-only routes offer only phase-allowed delegation. Primary and researcher requests send `parallel_tool_calls: true`; read-only delegation and editor requests send `false`. Completed `function_call` items are the calls.
- Researchers receive only read-only operations, without planning or delegation. At zero remaining Tool calls and on the primary's [final budgeted call](../goals.md#lifecycle-budgets-and-recovery), every route keeps its Tool list, sends `tool_choice: "none"` (Messages `{"type":"none"}`) and accepts text only; the Engine independently refuses exhausted calls.
- Native and custom Anthropic Messages Runs offer non-strict catalog Tools and phase-allowed Delegate with `tool_choice: {"type":"auto"}` and no `output_config.format`, allowing several calls; editor requests send `disable_parallel_tool_use: true`. A `tool_use` stop carries the offered calls, earlier text being commentary, within 16 content blocks and the response byte ceiling. An `end_turn` stop carries the plain text answer and no call; `max_tokens`, `refusal` and every other stop reason fail closed. A replayed Delegate `tool_use` is followed by a fixed `tool_result` before the child results, as on the OpenAI routes.
- Calls become Tool requests in model order under the [step cap](../limits.md#max_step_tool_calls); editors keep one call per step. Plan and Delegate each need exactly one call mixed with no other; duplicate call or item IDs and malformed calls fail closed. A bounded over-cap batch reaches the Engine's [proposal refusal](../execution/events-and-outcomes.md#accepted-outcomes) with `InvalidArguments` and feedback naming the cap, keeping usage and one non-dispatched result per call. Response bytes and [streaming framing](#streaming-and-provisional-text) bound decoding; dispatch and replay follow the [execution contract](../execution/events-and-outcomes.md#committed-event-stream).
- Tool review uses strict structured JSON and returns the closed verdict object (`verdict: approve | ask`), never answer text. Its one untrusted data block carries only the Session's user prompts and the action ([review input](../tools/trust-and-approvals.md#folder-trust-and-approvals)), with no Goal budget, plan, Goal facts, steering or catalog.
- Custom Chat Completions offers the same strict function tools as Responses with `tool_choice: auto` (`none` as above) and `parallel_tool_calls: false` only when a function is offered. All requests use `stream: false` and `max_completion_tokens`; ToolReview uses strict JSON-schema `response_format`. It sends no `store` or extra headers. A reply needs one choice, exact model, nonempty response ID, `stop` with plain text or `tool_calls` with exactly one offered call, and positive `prompt_tokens`, `completion_tokens` and their exact `total_tokens` within the local output cap; `length`, `content_filter`, missing usage, several choices or calls, mixed answer and call, or model drift reject without repair. Its Limits system block reads "Tool calls per step: at most 1." on every role.
- A request with no offered function omits `tools`, `tool_choice` and `parallel_tool_calls` on every route.
- Read paging accepts omitted or null `offset` and `limit` with the [Tools defaults](../tools/file-operations.md#in-process-file-operations); OpenAI strict schemas still require them, and canonical calls serialize omitted fields as null.
- Ordinary non-autonomous turns without a recorded plan omit the `goal` budget block; autonomous Goals and recorded plans carry bounded budget context. Enforcement never depends on prompt visibility; [Goals](../goals.md#initial-plan-contract-and-success-receipt) owns a recorded plan's scope and success policy.
- Typed Run input renders as closed [system blocks](../session.md#context-and-compaction) and labelled untrusted user data. Each Tool step replays the exact assistant turn followed by one result per call ID in model order, without repeating the call: one Anthropic user message of paired `tool_result` blocks, or ordered `function_call_output` items on both OpenAI routes. Step harness facts (`goal_context_facts`, `tool_calls_remaining`) follow as labelled data in the Anthropic user message; on Responses routes they fold into the step's last `function_call_output` as a `harness` object (a non-object result becomes `{result, harness}`), keeping the turn's reasoning. Step steering stays a user message, and a step without function outputs keeps the facts as user data. Hook replacements and Engine integrations stay result data on the originating call. A recoverable primary failure or denial, including a declined or unavailable approval, appears once in its paired result with a compiled cause label, never raw hook, client or permission-rule prose, and may continue under ordinary Goal admission; cancellation, uncertainty and other terminal stops authorize no continuation. Responses replays raw output items, including encrypted reasoning with `store: false`; the ChatGPT route drops item IDs. Replayed turns are never journaled; a lost Run is interrupted, not resumed.
- Tool branches and command, Skill and MCP names offered are limited to bounded catalog availability; catalog data never replaces pinned router or Guard authorization.

The primary Delegate envelope takes optional nullable `agent`, selecting one admitted researcher definition for its `children`. Child objects follow the [assignment form](./selection.md#named-roster-presets); an editor child also carries the closed `editor` assignment from the [worker protocol](../execution/events-and-outcomes.md#worker-journal-protocol), repeats its mission as `objective`, requires null `profile` and takes its definition and digest from the admitted catalog. The editor assignment requires `commands`: a sorted array of zero to eight unique admitted command names, each at most 64 bytes; missing, duplicate, unknown or extra names refuse admission. Assignments offer foreground or background mode, bounded wave numbers and nullable current-Run supersession; nullable `resumes` takes an exact historical child ID under [fresh-assignment semantics](../session.md#worker-identity-and-explicit-reassignment). Both native function encodings share this envelope, which offers editor assignments whenever an admitted editor definition exists; an editor Delegate before a committed Goal plan is refused with bounded feedback and no child call. Editor calls use the editor prompt with its live-Workspace and leased-file authority block, Single policy and the restricted catalog, with text answers and no Delegate. [Execution](../execution/collaboration.md#agent-definitions) owns definition selection and authority; definition bodies stay labelled untrusted user guidance.

A settled primary call rejected with `outcome_contract` may get one corrective call per Run, on the same routing and under ordinary Goal call, token, time, context and Store limits, after its failed `ProviderCallRecorded` commits. Only that request appends a trailing harness data block asking for a permitted function call or plain final text; the system prefix stays byte-stable. Rejected response text never becomes an answer, instruction or proposal, and Tool observations stay available without redispatch. A second outcome-contract failure ends the Run with both failure records. Unknown usage under a finite token budget, cancellation, hook stop or uncertainty prevents correction; transport, framing, output-limit, Tool-review and child failures are outside this path.

Compaction requests use plain assistant text on every route, omitting response schemas, `tools`, `tool_choice` and `parallel_tool_calls` but keeping effort, caching and privacy fields. A reply must hold exactly one complete non-whitespace summary within the [generated compaction summary limit](../limits.md#max_compaction_summary_bytes), kept byte for byte; the requested cap follows the [generated compaction token limit](../limits.md#max_compaction_output_tokens), narrowed by the Provider's cap. Responses joins the ordered text parts of one final message; Messages requires one text block after any thinking blocks; Chat Completions requires a non-empty string `message.content` and no tool calls. A tool call, refusal, incomplete or unknown stop, invalid required usage, model drift or selected-credential reflection rejects. JSON-looking prose is plain text, never parsed or repaired. Validation proves framing and bounds, not fidelity or resistance to persuasion. A rejected summary gets no corrective call or format switch, only the journaled retry and fallback rules.

Anthropic thinking blocks are opaque: replayed unchanged within a Run, never interpreted, and dropped from kept turns when compaction rewrites history. An opaque in-memory assistant turn is bounded to eight bytes per requested output token plus 64 KiB<!-- unrelated-bound: opaque assistant turn overhead --> of overhead, capped at the 1 MiB<!-- unrelated-bound: Provider HTTP response body --> response ceiling; exceeding it fails the call with `InvalidOutcome`. Image count, aggregate bytes and origin are validated before any request is sent.

ReadOnly, Researcher and Editor ChildWork requests carry only that child's notes, as user data in the shared `steering_notes` block at their continuation boundary; earlier request prefixes stay unchanged across continuations, retries and switches. ToolReview requests and invalid role or phase combinations, including nested Tool-step and stop-feedback notes, reject notes. [Goals](../goals.md#steering-notes-and-pause) owns admission, delivery and authority.

## Prompt caching

- Anthropic active Tool loops put `cache_control: {"type":"ephemeral"}` on the last Tool definition, the last system text block and the final content block of the conversation tail; single-call requests without Tools and compaction mark only the system block. A spent researcher's final call omits the tail marker, and changing Tool choice may invalidate the messages cache. Markers go only on the outgoing request, at most three of Anthropic's [four breakpoints](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), with the default five-minute TTL and no top-level automatic marker or extended TTL.
- OpenAI API, ChatGPT and exact custom Responses Run and compaction calls send the Session UUID as a stable `prompt_cache_key`, which links one Session's turns and reveals its creation time but carries no prompt, Workspace or credential text. Calls keep `store: false` and encrypted-reasoning replay and request no retention override.
- A cache key or breakpoint guarantees no cache hit, remote retention or live compatibility. Cache-read counts flow through the [usage record](./routing-and-usage.md#usage-provenance-and-reliability) into the [Goal report](../goals.md#lifecycle-budgets-and-recovery).

## Streaming and provisional text

- A preview is a bounded candidate of public assistant text only, never an accepted outcome, reasoning, Tool argument or authority, and only attached primary calls show one; complete response, model, usage and outcome checks still decide acceptance. Text that may still become commentary (all Anthropic text, ChatGPT text outside an explicit `final_answer` item) is shown but journaled only at the completion boundary: as an Answer chunk if it is the answer, or as Commentary, withdrawing the candidate, if a call follows. Explicit commentary is held until the boundary. A candidate above the display limit stops streaming, and the Engine refuses the answer as `answer_invalid`.
- A `final_answer` item followed by a function call is a response-contract failure, since the announced answer may already be journaled.
- Known selected credentials are checked before text is shown or recorded; a suffix that could complete a credential is held back, and cancellation drops any buffered tail.
- Framing bounds derive from the call's declared output-token cap (within the [admitted cap ceiling](../execution/events-and-outcomes.md#accepted-outcomes)): the greater of 8,192 events and two events per output token plus 2,048, and 512 envelope bytes per allowed event across the stream; probes and compaction use smaller caps. Lines, assembled event data and reconciled completed responses keep the non-streamed body ceiling. Overflow fails closed as `stream_protocol`, without an outcome or retry. Event JSON must be duplicate-free within 262,144 nodes and depth 64; an opaque assistant turn uses the same node and depth bounds within its own byte cap. Labels and types must agree, and media or response encoding never switches silently. Native and custom streaming use strict SSE media admission; ChatGPT uses its [own SSE policy](../chatgpt.md#catalog-and-runs).
