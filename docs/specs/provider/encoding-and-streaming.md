# Provider: outcome encoding, caching and streaming

## Structured outcomes and Tool encoding

- Run answers are plain assistant text. Earlier assistant text is progress commentary. Without a function call, the final assistant message is the answer and ends the turn; there is no Finish function or model-authored summary/result split. On every adapter, unknown, unoffered or incomplete calls, malformed text parts, non-object or wrongly typed function fields and wire-byte overflow reject without alternate decoding. An offered call whose fields decode into a bounded typed Tool proposal reaches Engine argument validation with its usage kept. Invalid paths and other semantic argument failures get the [committed refusal result](../execution/events-and-outcomes.md#accepted-outcomes) before normal continuation; they are not wire parse failures and do not consume the outcome correction below.
- The shared Responses decoder validates all assistant text parts, distinguishes explicit `commentary` from exactly one final answer, and joins ordered final text parts without inserting or repairing bytes. A missing or null phase is a single final message. Without a call or final message, the last commentary is the answer; a blank answer is still the Engine's `answer_invalid` refusal. Commentary may precede or interleave with Tool calls in a step; a final answer beside calls, commentary after the final answer, unknown phases, malformed or refusal blocks, extra finals and non-null error or incomplete markers reject. Output items of an unknown type that is not a call stay in the raw replay and decide no outcome; an unknown `*_call` item rejects.
- OpenAI API and ChatGPT requests offer the same constant list of strict native functions for catalog-available operations, the optional primary `arany_plan` when [Goals](../goals.md#initial-plan-contract-and-success-receipt) offer it, and `arany_delegate` when collaboration permits children. Researcher calls at zero remaining Tool calls and the primary's [final budgeted call](../goals.md#lifecycle-budgets-and-recovery) keep the list and send `tool_choice: "none"` (Messages `{"type":"none"}`). Both restrict functions by phase with `tool_choice: {"type":"allowed_tools","mode":"auto","tools":[{"type":"function","name":"arany_…"}]}`, keeping the full list across planning and synthesis; local decoding admits only the allowed subset. Read-only routes offer only phase-allowed delegation. Primary and researcher requests send `parallel_tool_calls: true`; read-only delegation and editor requests send `false`. Completed `function_call` items are the calls.
- Native and custom Anthropic Messages Runs offer non-strict catalog Tools and phase-allowed Delegate with `tool_choice: {"type":"auto"}` and no `output_config.format`, allowing several calls; editor requests send `disable_parallel_tool_use: true`. A `tool_use` stop carries the offered calls, with earlier text as commentary, within 16 content blocks and the response byte ceiling. An `end_turn` stop carries the plain text answer and no call; `max_tokens`, `refusal` and every other stop reason fail closed. A replayed Delegate `tool_use` is followed by a fixed `tool_result` before the child results, as on the OpenAI routes.
- On both native Tool routes, calls become Tool requests in model order under the [step cap](../limits.md#max_step_tool_calls), and editors keep one call per step. Plan and Delegate each need exactly one call that mixes with no other; duplicate call or item IDs and malformed calls fail closed. A bounded over-cap batch reaches the Engine's [proposal refusal](../execution/events-and-outcomes.md#accepted-outcomes) with `InvalidArguments` and feedback naming the cap, under the identical-pair refusal bound, keeping usage and one non-dispatched result per call. Response bytes and [streaming framing](#streaming-and-provisional-text) bound decoding; dispatch and replay follow the [execution contract](../execution/events-and-outcomes.md#committed-event-stream).
- Tool review keeps strict structured JSON and returns the closed verdict object (`verdict: approve | ask`), decoded as a typed verdict, never as answer text. Its one untrusted data block carries only the Session's user prompts and the action ([review input](../tools/trust-and-approvals.md#folder-trust-and-approvals)); it has no Goal budget, plan, Goal facts, steering or catalog block.
- Custom Chat Completions offers the same strict function tools as Responses: catalog-available Workspace Tools and phase-allowed Run outcome functions, with `tool_choice: auto` (`none` at zero remaining Tool calls or on the final budgeted call) and `parallel_tool_calls: false` only when a function is offered. All requests use `stream: false` and `max_completion_tokens`; ToolReview uses strict JSON-schema `response_format` for its verdict. It sends no `store` or extra headers. A reply needs one choice, exact model, nonempty response ID, `stop` with plain text or `tool_calls` with exactly one offered call, and positive `prompt_tokens`, `completion_tokens` and their exact `total_tokens` within the local output cap. `length`, `content_filter`, missing usage, multiple choices or calls, mixed answer and call, or model drift reject without repair. The Limits system block reads "Tool calls per step: at most 1." on every role, because this route admits one call. Provider turns keep only the bounded assistant message needed for replay.
- A request with no offered function omits `tools`, `tool_choice` and `parallel_tool_calls` on every route.
- Read paging accepts omitted or null `offset` and `limit` with the [Tools defaults](../tools/file-operations.md#in-process-file-operations). OpenAI strict schemas still require the nullable paging fields; canonical calls serialize omitted fields as null.
- Researchers receive only read-only operations, without planning or delegation. At zero remaining Tool calls every route keeps its Tool list, sends Tool choice `none` and accepts text only; the Engine independently refuses exhausted calls.
- Ordinary non-autonomous turns without a recorded plan omit the `goal` budget block; autonomous Goals and recorded plans carry bounded budget context. Engine enforcement never depends on prompt visibility. A recorded plan stays binding scope and success policy; [Goals](../goals.md#initial-plan-contract-and-success-receipt) owns that rule.
- Typed Run input renders as closed [system blocks](../session.md#context-and-compaction) and labelled untrusted user data. Each Tool step renders as the exact replayed assistant turn followed by correlated results that do not repeat the call. A multi-call step emits one result per call ID in model order: one Anthropic user message of paired `tool_result` blocks, or ordered Responses `function_call_output` items on both OpenAI routes. Step harness facts (`goal_context_facts`, `tool_calls_remaining`) follow the results as labelled data in the Anthropic user message; on both Responses routes they fold into the step's last `function_call_output` as a `harness` object (a non-object result becomes `{result, harness}`), because a user message after function outputs ends the turn and drops its reasoning. Step steering stays a user message so user authority keeps its label, and a step without function outputs keeps the facts as user data. Hook replacements and Engine integrations stay result data on the originating call, never another model-requested result. A recoverable primary failure or denial, including a declined or unavailable approval, appears once in its paired result and may continue through ordinary Goal admission; cause labels are compiled, never raw hook, client or permission-rule prose. Cancellation, uncertainty and other terminal stops authorize no continuation. Responses replays raw output items, including encrypted reasoning with `store: false`; the ChatGPT route also drops item IDs. Replayed turns are in memory and never journaled; a lost Run is interrupted, not resumed.
- Generated Tool branches and command, Skill and MCP names are limited to bounded catalog availability. Catalog data never replaces pinned router or Guard authorization.

The primary Delegate envelope takes optional nullable `agent`, selecting one admitted researcher definition for its `children`. Child objects follow the [assignment form](./selection.md#named-roster-presets); an editor child also carries the closed `editor` assignment from the [worker protocol](../execution/events-and-outcomes.md#worker-journal-protocol), repeats its mission as `objective` and requires null `profile`; its definition and digest come from the admitted catalog. The editor assignment requires `commands`: a sorted array of zero to eight unique admitted command names, each at most 64 bytes; missing, duplicate, unknown or extra names refuse admission. Assignments offer foreground or background mode, bounded wave numbers and nullable current-Run supersession; nullable `resumes` takes an exact historical child ID under [fresh-assignment semantics](../session.md#worker-identity-and-explicit-reassignment). Both native function encodings share this envelope. The schema offers editor assignments whenever an admitted editor definition exists, so it stays constant within a Run; the Engine refuses an editor Delegate before a committed Goal plan with bounded refusal feedback and no child call. Editor calls use the editor working-style prompt with its compiled live-Workspace, leased-file authority block, Single policy and the restricted catalog, with text answers and no Delegate. [Execution](../execution/collaboration.md#agent-definitions) owns definition selection and authority intersection. Definition bodies stay labelled untrusted user guidance and add no system role or destination.

A settled primary call rejected with `outcome_contract` may get one corrective call per Run, on the same admitted routing and under ordinary Goal call, token, time, context and Store limits. The failed `ProviderCallRecorded` commits before the correction's reservation and dispatch. Only that request appends a compiled trailing harness data block asking for a permitted native function call or plain final assistant text; the system prefix stays byte-stable and the block is gone on later calls. Rejected response text never becomes an answer, instruction or executable proposal. Existing Tool observations stay available without redispatch. A second outcome-contract failure ends the Run with both failure records. Unknown usage under a finite token budget, cancellation, hook stop or uncertainty cannot authorize correction. Transport and framing, output-limit, Tool-review and child failures are outside this path. Arany needs no final-answer envelope; this single journaled correction to keep its typed Tool and replay guarantees.

Compaction requests use ordinary assistant text on Responses, ChatGPT, Messages and Chat Completions. They omit response schemas, `tools`, `tool_choice` and `parallel_tool_calls`, keeping effort, caching and privacy fields. A reply must hold exactly one complete non-whitespace summary within the [generated compaction summary limit](../limits.md#max_compaction_summary_bytes), kept byte for byte. The requested cap follows the [generated compaction token limit](../limits.md#max_compaction_output_tokens), narrowed by the Provider's own cap. Responses joins ordered text parts of one final assistant message; Messages requires one text block after any thinking blocks; Chat Completions requires a non-empty string `message.content` and no tool calls. A tool call, refusal, incomplete or unknown stop, invalid required usage, model drift or selected-credential reflection rejects. JSON-looking prose is ordinary text, never parsed or repaired; headings are optional. Local validation proves framing and bounds, not fidelity or resistance to persuasion. A rejected summary never triggers a corrective call or format switch; only the journaled transport retry and fallback rules apply.

Anthropic thinking blocks are opaque: they replay unchanged within a Run, are never interpreted, and are dropped from kept turns when compaction rewrites history.

An opaque in-memory assistant turn is bounded to eight bytes per requested output token plus 64 KiB<!-- unrelated-bound: opaque assistant turn overhead --> of framing and ciphertext overhead, capped at the 1 MiB<!-- unrelated-bound: Provider HTTP response body --> response ceiling; exceeding it fails the call with `InvalidOutcome`.

Native adapters validate attachment count, aggregate bytes and objective or history origin before building a request body.

ReadOnly, Researcher and Editor ChildWork requests carry only that child's notes, as ordinary user data in the shared `steering_notes` block at their continuation boundary; earlier request prefixes stay unchanged on later continuations, retries and switches. ToolReview requests and invalid role or phase combinations, including nested Tool-step and stop-feedback notes, reject notes. [Goals](../goals.md#steering-notes-and-pause) owns admission, delivery and authority.

## Prompt caching

- Anthropic uses the explicit-breakpoint layout for active Tool loops: `cache_control: {"type":"ephemeral"}` on the last Tool definition, the last system text block and the final content block of the conversation tail. Single-call requests without Tools and compaction requests mark only the system block, since their changing tails are never reused and a tail breakpoint would pay the 1.25× write charge for nothing. A spent researcher's final call keeps Tool and system markers but omits the tail marker; changing Tool choice may invalidate the messages cache. Markers are added to the outgoing request, never stored in replayed turns or accumulated. This uses at most three of Anthropic's [four breakpoints](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) with the default five-minute TTL; no top-level automatic marker or extended TTL is requested.
- OpenAI API and ChatGPT Run and compaction calls send the Session UUID as a stable `prompt_cache_key`. The UUIDv7 carries a creation timestamp and lets the Provider link one Session's turns; it adds no prompt, Workspace or credential text. Calls keep `store: false` and encrypted-reasoning replay. The shared prefix stays reusable across phase changes. No retention override is requested. Exact custom Responses profiles share this request shape.
- A cache key or breakpoint requests reuse; it guarantees no cache hit, remote retention or live compatibility. Cache-read counts flow through the [usage record](./routing-and-usage.md#usage-provenance-and-reliability) into the [Goal report](../goals.md#lifecycle-budgets-and-recovery).

## Streaming and provisional text

- A preview is a bounded candidate, never an accepted outcome, reasoning channel, Tool argument or authority. Only public assistant text is extracted. Assistant text streams as the answer candidate. Text that may still become commentary (all Anthropic text, ChatGPT text outside an explicit `final_answer` item) is shown but journaled only at the completion boundary: as an Answer chunk if it is the answer, as Commentary if a call follows. If a function call follows, the candidate is withdrawn; commentary-phase text is held until the boundary. A candidate above the display limit stops streaming and leaves the committed answer to the Engine, which refuses it as `answer_invalid` like every other route.
- A `final_answer` item followed by a function call is a response-contract failure: the item announced the end of the turn and may already be journaled, so honoring the call would contradict a committed outcome. Arany keeps exactly one committed outcome per step.
- Known selected credentials are checked before text is shown or recorded. A suffix that could complete a credential is held back, and cancellation drops any buffered tail instead of flushing it.
- The one-slot `ResponsePreview` observer holds the latest bounded snapshot; complete response, model, usage and outcome checks still decide acceptance. Only attached primary invocations expose a preview; configured fallback chains also use a bounded private observer as an extra visible-output guard, while HTTP status admission decides eligibility.
- Framing bounds derive from the call's declared output-token cap (within the [admitted cap ceiling](../execution/events-and-outcomes.md#accepted-outcomes)): the event bound is the greater of 8,192 events and two events per output token plus 2,048; the byte bound is 512 envelope bytes times the event bound across the stream. Probes and compaction use their own smaller caps. Individual lines, assembled event data and reconciled completed responses keep the non-streamed body ceiling. Overflow fails closed as `stream_protocol`, without an outcome or retry, and [development diagnostics](../diagnostics.md) name the framing limit. Event JSON must be duplicate-free within 262,144 nodes and depth 64 (a `response.created` event echoes the request, including the Tool catalog); an opaque assistant turn uses the same node and depth bounds within its own byte cap. Labels and types must agree, and media or response encoding never switches silently. Native and custom streaming use strict SSE media admission; ChatGPT uses its [own SSE policy](../chatgpt.md#catalog-and-runs).
