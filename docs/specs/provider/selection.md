## Per-role selection and fallback

Four roles bind calls: `primary` (planning and synthesis), `child` (researcher or reasoning children), `review` (AI Tool review) and `compaction` (summaries). A child gets the same narrowing of instructions, Tools, authority and Goal facts whatever its Provider. Each route keeps its own immutable identity, account or custom provenance, effort, output-token bound and call limits. Role deadlines are positive and at most 20 minutes, compiled routes keep narrower limits, role output caps apply, and concurrent children fit every admitted route's concurrency ceiling. Per-agent model overrides inherit from the primary.

`exec` and attached Run and compaction admission read only the optional private StateRoot record `provider-routing.json`, at most 16 KiB<!-- unrelated-bound: Provider routing record -->: a closed [strict record](../execution/persistence.md#incompatible-records) whose required `providers` object names all four roles. Each value is null or an ordered array of one initial route and at most two fallbacks; each route has exactly `provider`, `model`, `effort` and `account_id`, with nullable fields explicit. `provider` is the closed `{kind, custom_name}` record: native kinds require a null custom name, custom its exact validated name, and invalid pairs reject before credential lookup. Native effort resolves through the model defaults; ChatGPT requires explicit effort and the selected account UUID. Unknown fields, empty or oversized chains, duplicate admitted identities and malformed or unadmittable selections refuse admission; nothing is silently dropped. No Workspace file, instruction or model output selects these values.

```json
{
  "providers": {
    "primary": null,
    "child": [
      {"provider": {"kind": "anthropic", "custom_name": null}, "model": "claude-sonnet-5", "effort": "high", "account_id": null}
    ],
    "review": null,
    "compaction": null
  }
}
```

Idle attached `/setup` → Role routing ([setup UI](../terminal/setup-and-accounts.md#setup-and-account-choices)) edits the whole record as one confirmed operation, including null inheritance for non-primary roles; the primary tuple comes from `/model`, and no other role choice replaces it. Native default effort resolves before saving; duplicate resolved tuples refuse. Saving reads no credential, checks no destination and calls no Provider; every candidate passes ordinary admission at the next submission. Cancellation publishes nothing.

Save and Clear compare the inspected bytes under the private replacement lock; busy, changed, malformed, oversized or unsafe records refuse without overwriting another editor. Clear removes only this record, so roles inherit the primary from the next independent submission, and activates no roster preset. Publication follows the [setup edit lifecycle](../execution/admission-and-recovery.md#admission-persistence-and-recovery); an unconfirmed publication is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) and never compensated. The model can never replace or remove the record.

The primary stays the CLI or Session selection: a non-null primary chain begins with it, a null role inherits the whole pinned primary chain, and an absent record means one primary route and no fallback for every role. Every configured entry, including routes never called, passes the native credential or account, ChatGPT consent or exact-custom destination gate before Workspace input; a failure names the profile and model and refuses the Run, never selecting another entry. Exact-custom primary and child routes refuse image-bearing objectives. Review and compaction receive no Tools or images. `RunStarted` carries explicit nullable roster metadata even without a roster; invalid or inconsistent role identities reject replay.

A chain switches, journaled and visible before dispatch, only when a call is rejected with HTTP 5xx (including 529) at status admission, before its body is read, after its [same-route retries](./routing-and-usage.md#usage-provenance-and-reliability) are spent or cannot fit, and before any preview text was shown. Nothing else switches: not authentication, billing, rate-limit, request-size or send-time transport failures, any error after a successful status check (stream overload, hidden reasoning, Tool-input or pre-answer JSON, body-read failure), local rejection, content refusal, semantic or stream validation, output limit, cancellation or deadline.

Tool-enabled Runs refuse any primary or child chain mixing adapters or accounts, because Tool steps and opaque assistant turns must keep both across a switch; OpenAI API keys and ChatGPT subscriptions are different accounts. Different roles may use different adapters; replay rejects redundant inherited provenance. The replacement keeps the whole semantic request and correlated observations without translation or truncation, never re-dispatches a Tool (review fallback included) and never continues an uncertain effect. A successful fallback stays selected for that actor and role for the Run; each new Run starts at the first route.

Context windows come only from authenticated catalogs: ChatGPT's `context_window` and Anthropic's `max_input_tokens`; OpenAI's model list reports none, and environment-key and custom routes keep the default bounds. Each attached, `exec`, `serve` (saved selection) and `acp` process reads the selected Provider's free model catalog once at startup in the background, unless that saved account's catalog is under one day old or its secret is in the OS credential store, where a read could prompt again; setup and `/model` reads refresh it. Windows are kept beside each model ID in the saved-account [model catalog cache](../terminal/selectors.md#selectors); Run admission reads only that cache, and a missing entry or failed refresh keeps the default bounds without blocking a Run. The smallest window across the primary chain sizes the primary [context ceiling](../session.md#context-and-compaction) and never selects or filters a route; an active Run keeps its pinned window. Missing and out-of-range values stay absent; malformed types reject the catalog. Every compaction destination gets the same complete bounded source, never truncated, and no extra compaction runs to enable fallback; a request-size rejection ends that call without a switch.

Each switch fits the existing action deadline and fresh Store and call-budget admission; the [execution contract](../execution/admission-and-recovery.md#admission-persistence-and-recovery) owns switch facts and replay, and [Goals](../goals.md#lifecycle-budgets-and-recovery) owns charging unknown failed-call usage. A Run keeps at most 64 switch facts; reaching that bound, or a refused admission for the switch, stops fallback and records the call's failure. When the latest Run has explicit role provenance, Session compaction must use that Run's pinned compaction chain, so it cannot add a destination afterwards; Runs with inherited provenance keep single-route between-Run compaction.

## Named roster presets

Presets cover named route selection and eligible child assignment only; judge-only adapters, durable per-agent pause, retry or switch, writable workers and leases are out of scope. An exhausted chain fails only its child and starts no later sibling.

`--profile PRESET` explicitly selects a private preset in attached mode or `exec` ([flag](../terminal/entry-and-modes.md#entry-modes-and-channels)); there is no implicit preset, persistent default or activation picker, and without the flag the roster record is never opened. Supplied Provider, model and effort flags must match the preset's normalized primary tuple, and a present `provider-routing.json` conflicts.

The user maintains `provider-roster.json` beneath the admitted StateRoot, outside the Workspace, only through confirmed idle `/setup` → Roster profiles edits; the model can never replace or remove it. It is a closed [strict record](../execution/persistence.md#incompatible-records) with required `profiles` and `presets`. A profile has exactly `name` and `routes` in the four-field [role-route form](#per-role-selection-and-fallback). A preset has exactly `name`, `providers` and `child_profiles`: its four role fields hold profile names (primary non-null; child, review and compaction null to inherit the whole primary chain), and the nonempty ordered child allowlist must include the resolved child default. Unknown or duplicate fields, duplicate names, routes or eligibility, missing references, malformed values and unsupported versions reject the whole record. Native efforts normalize before duplicate detection or comparison.

The [roster manager](../terminal/setup-and-accounts.md#setup-and-account-choices) refuses to remove a profile a preset references, naming those presets. Save validates the whole record and keeps invalid drafts for repair: an ineligible child default names the preset and the profile to add, and an expanded-profile limit names the preset, limit and references to remove. Review shows each preset's resolved manifest and `arany --profile PRESET` invocation; an unrepresentable manifest refuses Save. Browsing and saving read no credentials, check no routes and call no Provider; inspecting a saved native source stays an explicit action. Cancelling publishes nothing and creates no Session.

Save publishes the whole record atomically under role routing's [snapshot comparison](#per-role-selection-and-fallback). Removing the final preset removes the whole record, remaining profiles included, after a warning. Publication follows the [setup edit lifecycle](../execution/admission-and-recovery.md#admission-persistence-and-recovery); unknown publication is [Uncertain](../execution/events-and-outcomes.md#effect-outcomes) and never compensated. Editing never activates a preset, changes conversation defaults or rewrites admitted submissions. On a role-routing conflict the manager offers the separate confirmed [Clear role routing](#per-role-selection-and-fallback) action; it never merges or silently clears routing sources.

For each direct child assignment the primary selects only eligible names in the pinned preset. `Delegate.children` holds closed objects with required `objective` and required nullable `profile`; strings, missing fields and extra fields reject. Null selects the pinned child default, which may inherit the primary chain; outside roster mode only null is legal. No raw model, account or endpoint, other preset, fifth role or judge capability is introduced.

```json
{"outcome":{"type":"delegate","children":[{"objective":"Inspect replay invariants","profile":"inspect"},{"objective":"Check output bounds","profile":null}],"agent":null}}
```

Only primary planning and synthesis are offered profile names. Structured text and native functions share one assignment schema whose `profile` enum is the eligible names plus null, fixed for the Run. The whole delegation is validated before its first spawn: an unknown, ineligible, malformed or over-bound assignment dispatches no child. Decoding failures follow the [bounded outcome correction](./encoding-and-streaming.md#structured-outcomes-and-tool-encoding); decoded proposals follow the Engine's [refusal continuation](../execution/events-and-outcomes.md#accepted-outcomes). A profile is never inferred from objective text.

Each child's resolved profile is pinned in acknowledged `AgentSpawned` before any call, and its calls and switches use it even when two profiles differ only in fallbacks. A successful fallback stays with that actor and role; a sibling starts at index zero. A lost or failed spawn or switch acknowledgment, or a cancellation around either, starts no further call; replay rejects forged profile references and switches. Review and compaction keep their fixed role chains.

Roster accounts use the selected-account loaders and refuse unsupported identities, even unused ones ([credential contract](../credentials.md#account-scope-and-identity)); headless native selection without a roster stays environment-only. A manifest grants no credential authority or account or plan consent; ChatGPT consent follows the [account contract](../chatgpt.md#catalog-and-runs).

The escaped manifest, [shown](../terminal/entry-and-modes.md#entry-modes-and-channels) before credentials or Workspace content load (headless: stderr only, JSONL mode included), lists the preset, four role references, eligible children, every initial and fallback model and effort, and billing class (`native API`, `ChatGPT plan`, or `exact custom; unknown pricing`); ChatGPT rows disclose that the local output cap does not cap remote plan consumption. An unrepresentable manifest rejects instead of hiding routes.

Admission validates the whole record, then admits every profile reachable from the selected preset, eligible alternatives and fallbacks included even when unused, under all credential, consent and destination checks and one cancellable 120-second<!-- unrelated-bound: roster admission deadline --> deadline, with no inference, discovery, recheck, retry or billing fallback. It finishes before writable history or the Engine opens (attached: after folder consent). Failure names the safe profile and route and refuses before journal creation, Workspace input or a Run; earlier Session or default facts need not roll back. Cancellation starts no Run; account-write uncertainty stays authoritative.

Every agent candidate, unused eligible profiles included, passes the image and Tool chain checks of [role routing](#per-role-selection-and-fallback). Eligibility and assignment never change the parent grant, child read-only or Single policy, definitions, instructions, authority, Tools, budgets, privacy requirements, admitted destinations or the shared Goal ledger. One immutable snapshot serves all autonomous Runs of a submission, so configuration edits during a team Run cannot change its calls; independent submissions re-read and re-admit, and process selection survives new and clear. Inspecting a past Run needs neither current configuration nor credentials. A conflicting idle selection is refused at next-Run admission with guidance to use the preset tuple or drop the selector. [Session](../session.md#roster-recovery-and-compaction) owns drift, recovery and pinned compaction.

| Surface | Bound / overflow |
|---|---|
| Private record | 64 KiB<!-- unrelated-bound: custom Provider profile record --> before decoding; JSON nesting at most 16; 1–32 profiles and 1–16 presets; reject whole input |
| Names | 1–64 ASCII bytes, first lowercase letter, then lowercase letters/digits/hyphens; case-sensitive; no paths or aliases |
| Expanded selection | At most eight distinct profiles across defaults and eligibility, eight eligible names, three routes per profile / 24 route slots; reject excess |
| Snapshot / manifest | Each at most 16 KiB<!-- unrelated-bound: custom Provider manifest serialization --> serialized/rendered; complete RunStarted retains the [generated Event payload ceiling](../limits.md#max_event_bytes); no truncation or quota increase |
| Admission | Sequential, at most 24 slots and 120 seconds<!-- unrelated-bound: credential admission deadline --> total, narrowing existing helper deadlines; cancellation or timeout refuses |
| Delegation | Count and objective bounds follow [researcher children](../execution/collaboration.md#researcher-children); objective nonblank; profile follows the name bound; complete encoded delegation at most 24 KiB; whole rejection before spawns |

## Native models and accounts

- Effort is model-specific, resolved before Workspace input, sent explicitly on every Run and compaction request and pinned in `RunStarted`; an omitted choice resolves to the reviewed model default. An unreviewed model needs an explicit closed effort, claims no compatibility and runs one call at a time. Malformed IDs and unsupported reviewed combinations fail before credential or Workspace input.
- A native credential is one immutable value: Provider, bounded key and optional Anthropic API workspace (a tenant and billing scope, not Arany's Workspace). Setup offers key-scoped access or a visible explicit workspace ID; only an environment-backed Anthropic selection reads `ANTHROPIC_WORKSPACE_ID`. A `wrkspc_` identifier is validated and sent on every catalog, Run and compaction request; neither the header nor catalog visibility grants another destination, header, capability or plan permission.
- `exec` and explicit native selections use only their named API-key environment variable. Bare attached mode can use one saved API account chosen through `/setup` or `--setup`; with none it stays unconfigured and rejects objectives before Workspace input. A Session's saved default pins the account UUID, and Run and catalog admission must match that UUID and Provider before the key is released, so a replaced account never serves an older Session. `RunStarted` records the native account UUID as provenance only; environment-backed and custom routes record none.
- ChatGPT-plan OAuth uses the separate consented [Codex backend route](../chatgpt.md#catalog-and-runs) and never falls back to API-key billing. Anthropic stays API-key only unless Anthropic grants Arany prior approval.
- The OpenAI Responses adapter admits exactly `gpt-5.4`, `gpt-5.6-luna`, `gpt-6-astra`, `gpt-6.1-sol` and `gpt-6-luna` with `OPENAI_API_KEY`, sending the effort as `reasoning.effort` with the effort sets of the model pages for [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) and [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). Astra defaults to `medium`; the others match their pages.
- The Anthropic Messages adapter admits exactly `claude-sonnet-5`, `claude-fable-5-1`, `claude-opus-5-5` and `claude-sonnet-5-5` with `ANTHROPIC_API_KEY`, sending the effort as `output_config.effort` per the [effort guide](https://platform.claude.com/docs/en/build-with-claude/effort); Opus 5.5 defaults to `medium`, the others to `high`. Requests use `/v1/messages` with `anthropic-version: 2023-06-01`.
- Native choices need no synthetic check; each Run validates credential identity, workspace, model, effort and the actual response. Native setup picks a low-effort default from the account's catalog without questions or compatibility claim: visible `gpt-5.6-luna` for OpenAI, or `claude-sonnet-5-5` then `claude-sonnet-5` for Anthropic, otherwise the first visible row with unknown pricing disclosed. `/model` selects model and effort atomically; selection is staging, never credential or compatibility authority.

## Commands

- `arany provider models PROFILE` reads only the selected native credential and no Workspace data: the Provider's environment key by default, or with `--saved-account` the current OS-stored API account, rejecting a Provider mismatch. The result is complete or fails closed at 1 MiB<!-- unrelated-bound: model discovery response page --> per page, 16 pages or 4,096 unique models. The response needs one `application/json` media type and uses no proxy, redirect, retry or decompression. Rows distinguish reviewed effort metadata from availability-only rows, which are selectable with an explicit effort. A custom profile lists its configured model and declared efforts without reading its credential.
