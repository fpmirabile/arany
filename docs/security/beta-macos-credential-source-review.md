# macOS credential backend source review

Status: **selected source path traced; native release gate open**. Reviewed the locked, locally cached sources on 2026-09-30. This is not a macOS build, Keychain behavior test, transitive FFI audit, at-rest encryption attestation, or release clearance.

## Selected path

The [manifest](../../Cargo.toml) pins `keyring 4.2.0` with default features disabled and only `v1`. The locked macOS feature tree selects `apple-native-keyring-store 1.0.2` with `keychain` and `security-framework`, not `protected`. Both macOS target graphs select that same package identity. In pinned source, `keyring/src/v1.rs` initializes `apple_native_keyring_store::keychain::Store::new()` once as its platform default. `apple-native-keyring-store/src/keychain.rs` chooses `MacKeychainDomain::User`, maps Arany's fixed service and account slot to a generic-password item, and calls `SecKeychain::default_for_domain(User)`. Its set/get/delete operations call `security-framework`'s generic-password wrappers, which cross `security-framework-sys` into Apple's Security framework. No product credential subprocess or alternate protected-data backend is selected by this path.

Arany's [credential owner](../../src/cli/credentials.rs) uses one fixed service and default native-account slot. It serializes a versioned, at-most-1,024-byte record containing the selected Provider, model, effort, account UUID, and API key, then calls `Entry::set_password` on a blocking worker. Loads parse and validate the entire record before returning a selected key. Arany maps store errors to generic `Unavailable` or `InvalidAccount` diagnostics and does not print third-party error payloads. `keyring-core`'s UTF-8 decode error can carry raw bytes internally, so preserving that redaction boundary is necessary. The selected source stores one password value under the pair; this review does not establish atomic replacement or recovery after a failed native write.

The pinned `apple-native-keyring-store` source says its Keychain backend is intended for unsigned command-line applications; its separate Protected Data backend needs app entitlements for its richer controls. The Keychain backend maps item-not-found to `NoEntry` and storage-denial or unavailable Keychain codes to store errors. Its `set_generic_password` wrapper attempts an add after any lookup error, not only item-not-found; whether a locked or denied Keychain can then produce an unexpected duplicate/failure requires native behavior evidence. Arany treats any resulting save failure as unavailable and must not claim the selected account changed successfully.

## Native release gate

Use a dedicated macOS test account or otherwise isolated native Keychain, never the developer's production default slot. On both `x86_64-apple-darwin` and `aarch64-apple-darwin`, build the guarded release artifact and exercise the shipped first-run/save/reuse flow, a wrong-account selection, replacement identity invalidation, locked/unavailable Keychain, failed-write recovery, secret-free terminal output, and clean terminal restoration. Reopen State and confirm Session defaults pin only the account UUID. Inspect the resulting Keychain item and access prompts with the intended unsigned CLI distribution. Then review the selected Security Framework FFI and any platform ACL/backup behavior against those observations. A Linux PTY, macOS target graph, or source trace cannot substitute for this gate.

No dependency, feature, credential behavior, or public interface changed in this review. The fixed-slot test-isolation rule is in [testing](../../agents/testing.md); the broader dependency and advisory gates remain in the [inventory](./beta-dependency-inventory.md).
