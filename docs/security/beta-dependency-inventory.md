# Beta dependency supply-chain inventory

Status: **inventory and scoped offline policy checks; release gate open**. Captured on 2026-09-30 for `x86_64-unknown-linux-gnu`, `x86_64-apple-darwin`, and `aarch64-apple-darwin` from the current [manifest](../../Cargo.toml), [lockfile](../../Cargo.lock), and locally cached crate manifests. This is not advisory clearance, license-compliance advice, source-code clearance, native-platform evidence, or artifact-provenance clearance.

The manifest declares six development dependencies, three of which overlap its normal dependencies. These counts include the protected credential-store addition and direct use of already-selected `base64`, `getrandom 0.3.4`, `aws-lc-rs`, and `url` for the staged OAuth transaction and signed identity verification.

Both macOS normal-plus-build trees select the same 201 package identities: Arany, 26 direct third-party dependencies, and 174 transitive third-party dependencies. Adding development dependencies selects `tempfile` and `fastrand`, for 203 packages. Each macOS-filtered metadata result contains 220 packages; 17 third-party packages in that result are not selected even with development dependencies. Relative to Linux, the macOS trees select five unique packages: `apple-native-keyring-store 1.0.2`, `core-foundation 0.10.1`, `core-foundation-sys 0.8.7`, `security-framework 3.7.0`, and `security-framework-sys 2.17.0`. These are locked target selections, not macOS compile or runtime evidence.

Reproduce the graph and feature observations without refreshing the lockfile:

```sh
cargo metadata --locked --offline --filter-platform x86_64-unknown-linux-gnu --format-version 1
cargo tree --locked --offline --target x86_64-unknown-linux-gnu --edges normal,build --prefix none --format '{p}'
cargo tree --locked --offline --target x86_64-unknown-linux-gnu --edges normal,build --duplicates
cargo tree --locked --offline --target x86_64-unknown-linux-gnu --edges features --invert reqwest
cargo metadata --locked --offline --filter-platform x86_64-apple-darwin --format-version 1
cargo metadata --locked --offline --filter-platform aarch64-apple-darwin --format-version 1
cargo tree --locked --offline --target x86_64-apple-darwin --edges normal,build --prefix none --format '{p}'
cargo tree --locked --offline --target aarch64-apple-darwin --edges normal,build --prefix none --format '{p}'
cargo tree --locked --offline --target x86_64-apple-darwin --edges normal,build,dev --prefix none --format '{p}'
cargo tree --locked --offline --target aarch64-apple-darwin --edges normal,build,dev --prefix none --format '{p}'
```

Package counts above deduplicate `cargo tree`'s `(*)` repeats, then intersect its selected package identities with full filtered `cargo metadata` for target kinds and license fields. Unfiltered locked offline metadata now resolves all 354 packages, including `crossterm_winapi 0.9.1`, which was missing from an earlier local cache. Resolution does **not** mean the 353 registry entries across all targets have received the same source, license, or build-script review. The [toolchain pin](../../rust-toolchain.toml) is Rust 1.98.1; the package's declared minimum is 1.88.

## Build-time and native authority

In the selected Linux normal-plus-build tree, 34 third-party packages declare a Cargo custom-build target and 23 declare a procedural-macro target. Both are compiler-host code-execution surfaces, not just runtime libraries. Three active packages declare native `links`: `aws-lc-rs 1.18.1`, `aws-lc-sys 0.45.0`, and `libsqlite3-sys 0.38.2`. The [manifest](../../Cargo.toml) enables `rusqlite/bundled`, which normally selects the SQLite amalgamation C source in `libsqlite3-sys`; `reqwest/rustls` selects Rustls → AWS-LC and the native build in `aws-lc-sys`. The [SQLite](./findings/sqlite-build-environment-override.md) and [AWS-LC](./findings/aws-lc-system-autodetection.md) build-environment findings record how ambient state can override these expected native inputs; feature selection alone is not artifact provenance. The [AWS-LC pinned-source note](./beta-aws-lc-build-provenance-research.md) maps its target-specific source and build controls without clearing the artifacts. The selected ICU4X data crates have a distinct [external-Rust-source override](./findings/icu4x-external-data-source.md) under `ICU4X_DATA_DIR`; the current Linux build output does not activate it. Local crate manifests and build files confirm these paths. The Linux metadata lists 37 build-script packages, but three (`quinn`, `quinn-udp`, `ring`) are **not** in the selected normal/build tree. Do not treat their metadata presence as evidence that they ship in this Linux binary.

Each macOS selection has 31 custom-build packages, 17 procedural-macro packages, and the same three Cargo `links` declarations. The five macOS-only packages have no custom-build target or Cargo `links` field, but `core-foundation-sys` links Apple's `CoreFoundation` framework and `security-framework-sys` links its `Security` framework through `extern "C"` bindings. `security-framework` enters through both `rustls-platform-verifier` and `apple-native-keyring-store`. These FFI, key-store, and platform-trust-store paths add macOS-specific review and native behavior requirements; an offline graph does not validate their runtime behavior.

The [macOS TLS platform-fetch finding](./findings/macos-tls-platform-network-fetch.md) records a selected verifier path that does not disable Security Framework's default missing-intermediate network fetch. It is a source-supported possible secondary egress, not a native traffic observation or evidence of Workspace-byte disclosure.

The [macOS credential source review](./beta-macos-credential-source-review.md) traces the selected `keyring/v1` → User Keychain → Security Framework path and its fixed-slot/redaction boundary. It does not clear native Keychain behavior, Security Framework FFI, ACLs, prompts, or artifact provenance.

The application's [library](../../src/lib.rs) and [binary](../../src/main.rs) forbid `unsafe_code`. That does not cover transitive Rust `unsafe`, FFI, build scripts, procedural macros, or native C. Pinned entrypoint source review now covers all 34 Linux-selected build scripts and 23 Linux-selected macros, including the new Secret Service graph; it does not clear transitive behavior, macro expansions, native inputs, or artifacts. Review priority includes those deeper surfaces and the low-level OS/network crates (`rustix` 0.38/1.1, `libc`, `mio`, `reqwest`/Rustls). This is a review queue, not a finding that those crates are unsafe to use.

The [procedural-macro source review](./beta-proc-macro-source-review.md) covers all 23 Linux-selected and 17 macOS-selected entrypoints, including the six Linux-only credential-store additions. The Zbus-family macros reach locked `proc-macro-crate`, which reads Cargo manifests and may run the `CARGO`-selected executable during expansion. `enumflags2_derive` adds a generated `unsafe impl` requiring expanded-code invariant review. Neither observation is a demonstrated exploit or release clearance.

The [build-script source review](./beta-build-script-source-review.md) classifies all 34 Linux-selected and 31 macOS-selected entrypoints. The three additional Linux scripts use compiler probes or packaged target tables, with no new direct external-source override found. The distinct [libc fixed-name executable finding](./findings/libc-build-path-executable.md) tracks an `emcc` PATH lookup that the current guard does not reject. The [guarded native release script](../../scripts/release-build.sh) rejects the three known AWS-LC, SQLite, and ICU4X override families and verified one fresh Linux build's selected records and linkage. It does not pin compiler, `CARGO`, SDK, PATH, or all transitive source inputs, and it has not run on either macOS host.

Feature unification matters here: OTLP's `reqwest-blocking-client` enables `reqwest/blocking` in the shared package even though the direct Provider declaration requests `rustls` only. The local `opentelemetry-otlp 0.33.0` manifest's `http-proto` feature also activates its `metrics` feature despite Arany's trace-only intent. `rusqlite/bundled` selects bundled SQLite and bindings. Direct `base64` requests only `alloc`, but `reqwest`/`hyper-util` already activate its default `std` and `simd-unsafe` features in the unified graph; adding the direct dependency did not remove that existing `unsafe` review surface. Direct `getrandom 0.3.4` was already selected on both targets; its native Linux/macOS source uses OS entropy under the reviewed target configuration, while compiler cfg provenance remains a release-host gate. The first ChatGPT-plan code redemption now directly uses the already selected `aws-lc-rs 1.18.1` RSA verifier and `url 2.5.8` form serializer with default features disabled; it adds no selected package, but makes the locked native crypto/source and JWT-validation review directly relevant to account admission. The private callback transport enables `tokio/io-util` in the normal manifest; rerunning all six target/edge trees leaves the package counts above unchanged. Development builds additionally enable SDK testing/logging, Tokio test utilities, and Rustix pipe/PTY features; do not project those onto the normal/build tree. The Linux normal/build duplicate-version review now has seven names: `getrandom`, `hashbrown`, `io-lifetimes`, `linux-raw-sys`, `rustix`, `syn`, and `unicode-width`; the macOS selections omit `hashbrown` and `linux-raw-sys`. Their coexistence needs review for build size and audit coverage, not an automatic removal.

## License and advisory status

All 261 Linux-selected third-party packages declare a nonempty Cargo `license` field; they use 21 distinct raw strings. Six selected packages use legacy slash forms instead of an unambiguous SPDX `OR` expression: `cassowary`, `fallible-iterator`, `fallible-streaming-iterator`, `ident_case`, `vcpkg`, and `signal-hook`. `option-ext 0.2.0` declares `MPL-2.0`; `aws-lc-sys` and `aws-lc-rs` declare compound expressions; Unicode-related packages include `Unicode-3.0`. These declarations are **not** proof that the chosen license branch, bundled native notices, or redistributed artifacts meet policy. A complete license/notice assessment must include all release targets and bundled upstream code.

All 200 selected macOS third-party packages also declare nonempty license fields, with the same 21 raw strings and the same six slash-form packages. The five macOS-only packages each declare `MIT OR Apache-2.0`; that does not by itself clear Apple-framework or redistributed-notice obligations.

`cargo-audit 0.22.2` and `cargo-deny 0.20.2` are installed. An offline `cargo audit --no-fetch --stale` against the locally cached RustSec database found three warnings: `paste 1.0.15` unmaintained (`RUSTSEC-2024-0436`) and `lru 0.12.5` unsound (`RUSTSEC-2026-0002`, `RUSTSEC-2026-0253`). Its default exit status was zero despite those warnings, so it is not a strict release gate by itself. The approved [cargo-deny policy](../../deny.toml) scopes the three selected release targets, denies unknown registries and Git sources, and fails on unmaintained and unsound advisories. Its offline locked check fails on those three advisories and on `option-ext 0.2.0`'s unapproved `MPL-2.0`; source and duplicate-version checks pass at their configured severities. This is a deliberately red gate, not evidence of an exploitable Arany call path or a legal judgment about MPL. The local database was present on 2026-09-30, but its upstream freshness was not independently verified by this offline run. The [pinned native license/notice source research](./beta-native-license-notice-research.md) identifies relevant AWS-LC and SQLite files but does not clear redistribution obligations. No notice audit or cross-platform source/license clearance exists from this inventory. A successful offline compile or lockfile checksum is not evidence of those claims.

## Release checks still required

1. Verify advisory-feed freshness, then rerun the strict `cargo-deny` policy and a lockfile-wide `cargo-audit` scan; resolve the `lru` and `paste` findings without suppressing them merely to pass. An unavailable feed must fail visibly.
2. Resolve the `option-ext` `MPL-2.0` distribution decision and six slash expressions, review compound/native expressions, and verify bundled SQLite/AWS-LC notices and the distributed `LICENSE`/`NOTICE` contents. Rerun the license/source policy on all three release targets.
3. Extend the selected-entrypoint reviews through transitive build/macro behavior, exact expansions, native source/FFI, enabled features, duplicate versions, and transitive `unsafe` against the locked versions. Include the Linux Secret Service graph and macOS CoreFoundation/Security framework bindings, then verify platform behavior on a native macOS runner. All-target metadata resolution is available offline, but it is not source or artifact review.
4. Build release artifacts through the [guarded entry point](../../scripts/release-build.sh) from the reviewed lockfile and pinned toolchain in a controlled environment, close the [SQLite](./findings/sqlite-build-environment-override.md), [AWS-LC](./findings/aws-lc-system-autodetection.md), [ICU4X](./findings/icu4x-external-data-source.md), and [libc fixed-name executable](./findings/libc-build-path-executable.md) findings on each native target, then verify remaining compiler/PATH/SDK provenance and publish artifact checksums/signatures. Re-run the inventory after every dependency, feature, target, or lockfile change.
