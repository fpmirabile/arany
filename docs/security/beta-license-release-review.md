## `option-ext` release path

Mozilla's [MPL 2.0, sections 3.1-3.4](https://www.mozilla.org/en-US/MPL/2.0/) requires that covered executable code's source form be available, that recipients be told how to obtain it, and that source-form license notices be preserved. Mozilla's [FAQ, questions 8, 11, and 22](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) specifically discusses compiling unchanged MPL code into a larger executable, file-level copyleft, and the placement of source notices. This does not require relicensing Arany's separate source files under MPL, but it does require a release-specific source and notice path for the MPL component.

The candidate bundle includes the exact published [`option-ext 0.2.0` source archive](https://static.crates.io/crates/option-ext/option-ext-0.2.0.crate) beside the binary, checks its locked SHA-256 `04744f49eae99ab78e0d5c0b603ab218f515ea8cfe5a456d7629ad883a3b6e7d`, identifies its MPL-2.0 source and packaged `LICENSE.txt` in the notice, and ships the license text separately for readability. Arany does not modify that source. This addresses the specific source-availability packaging path without resolving all release attributions. The user-approved `deny.toml` exception accepts only this crate and version for metadata checks. A green metadata check cannot certify the binary or satisfy source and notice obligations; full distribution review remains separate.
