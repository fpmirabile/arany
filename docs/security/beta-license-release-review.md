## `option-ext` release path

Mozilla's [MPL 2.0, sections 3.1-3.4](https://www.mozilla.org/en-US/MPL/2.0/) requires that covered executable code's source form be available, that recipients be told how to obtain it, and that source-form license notices be preserved. Mozilla's [FAQ, questions 8, 11, and 22](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) specifically discusses compiling unchanged MPL code into a larger executable, file-level copyleft, and the placement of source notices. This does not require relicensing Arany's separate source files under MPL, but it does require a release-specific source and notice path for the MPL component.

The bundle script copies the exact published [`option-ext 0.2.0` source archive](https://static.crates.io/crates/option-ext/option-ext-0.2.0.crate) beside the binary and checks its locked SHA-256 `04744f49eae99ab78e0d5c0b603ab218f515ea8cfe5a456d7629ad883a3b6e7d`. Its generated `THIRD-PARTY-NOTICES.txt` directs recipients to unpack `sources/option-ext-0.2.0.crate` and identifies the packaged MPL-2.0 `LICENSE.txt`; Arany does not modify that source. The current bundle has not been rebuilt to verify this path in an artifact, and this instruction is not a legal-sufficiency or release-approval claim. The user-approved `deny.toml` exception accepts only this crate and version for metadata checks.
