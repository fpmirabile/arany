The [Tool contract](../specs/tools.md) uses Guard-only YAML parsing, offline MCP JSON Schema validation and a fixed Linux syscall filter, following [MCP/Skill research](../research/mcp-and-runtime-skills-2026-10.md) and [Guard research](../research/effect-guard-platform-base-2026-10.md). ## Native macOS dependency selection

The locked `nix` dependency is selected on Unix: production enables user lookup; tests also enable safe FIFO and PTY wrappers. Its cached published manifest declares MIT, a Rust minimum below Arany's and the existing `cfg_aliases` build dependency. The full build script emits fixed platform aliases without process execution, network access or generated source.

The selected safe `User::from_uid` wrapper calls `getpwuid_r`, sizes its initial buffer from the OS with a fixed fallback and caps retry growth at 1 MiB; lookup failure or an absent user propagates to account-path rejection. The safe `mkfifo` wrapper is confined to synthetic private-state rejection fixtures. The test-only safe `openpty` wrapper initializes both descriptors, checks the native return code and transfers successful handles into owned descriptors; the macOS attached fixture passes no custom termios or size and owns its directly spawned test process through bounded capture and kill/reap cleanup. It uses no `forkpty`. Its only test-side unsafe is one `pre_exec` hook ([`own_terminal`](../../tests/session_run/active_terminal_macos.rs)) that calls `setsid` and `TIOCSCTTY` on the inherited PTY descriptor 0 so the child owns the terminal. Between fork and exec it allocates nothing, takes no locks and calls only those two async-signal-safe syscalls, returning the OS error on failure. Product code contains no such hook. The other wrappers contain dependency FFI/unsafe, not application unsafe. This scoped review and the [native account/process owners](../../tests/session_run.rs) in `macOS Tests (debug)` do not establish transitive soundness or release provenance. Fresh advisory and dependency-policy evidence belongs to `Fresh dependency policy` in the [release-policy workflow](../../.github/workflows/release-policy.yml), required for the release lockfile.

`core-foundation =0.10.1` (with `link`) and `security-framework =3.7.0` are direct macOS dependencies at the exact versions already selected transitively by `apple-native-keyring-store` and `rustls-platform-verifier`, so they add no graph identity. Both and their `-sys` crates are `MIT OR Apache-2.0`, have no build script and declare no Cargo `links`. The `link` feature links the OS-owned CoreFoundation framework. Direct use is limited to typed binary-plist serialization of the Guard job dictionary and code-signing metadata reads in the [Guard adapter](../../src/tools/guard/macos/ffi.rs), plus generic-password Keychain item calls in the [credential helper](../../src/cli/credentials/keyring_helper/macos.rs). The release provenance and advisory gates above still apply.

## Effective enforcement and evidence

The native Linux owner `tools::resource_quotas_apply_to_payload_descendants_and_oom_is_uncertain` verifies memory, swap, process and CPU controls before payload release. `OOMPolicy=kill` is the selected service-manager setting; the Guard independently verifies `memory.oom.group=1`, not merely a requested property. The [kernel's group-OOM contract](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory) prevents partial workload continuation; the installed `systemd.service(5)` documents that `OOMPolicy=kill` sets this control. A real memory-exhaustion payload terminates the owned group and becomes an uncertain, non-retried Run. Native enforcement is not protection from privileged or hostile same-user host actors.

The Guard excludes Workspace/state/account roots from the broad read-only `/usr` runtime mount and denies socket creation, connect/bind/listen and destination-bearing sends. Anonymous socket-pair IPC remains usable but cannot reconnect or send to named host transports; message/descriptor passing is unsupported. `tools::command_descendants_cannot_reach_host_canaries_or_guard_memory` checks both permitted anonymous IPC and denied socket/destination operations. `tools::guard_failure_corpus_does_not_widen_paths_or_lose_effect_facts` verifies that successful receipts stay within the minimum 128-byte result grant even for long paths, with the resource retained in its correlated intent.

`decoded_native_outcomes_reject_escaped_key_reflection` in both [`openai.rs`](../../src/provider/openai.rs) and [`anthropic.rs`](../../src/provider/anthropic.rs) owns encoded MCP argument values, arrays and keys. Reflection inspects bounded argument JSON's semantic keys/values before disclosure or persistence, as well as decoded Tool fields. This detects the selected credential in known encodings; it is not universal declassification, taint tracking or detection of arbitrary transformations.

The native owners above live in [`tests/session_run/tools.rs`](../../tests/session_run/tools.rs). That file also maps coding/Skills/compaction/closed replay to `guarded_coding_skill_and_mcp_journey_survives_closed_journal_replay`, hostile MCP protocol/schema/content to `mcp_stdio_corpus_rejects_unnegotiated_authority_and_hostile_results`, shared budgets/read-only children to `tool_loop_exhaustion_and_team_children_do_not_widen_authority`, and cancellation/descendants to `cancellation_owns_the_actual_descendant_unit_and_never_retries_it`. These explicitly ignored Linux gates require activation under [testing rules](../../agents/testing.md); an old pass does not establish current native support. Default wire/configuration/reducer and reflection evidence runs in `Linux Tests (debug)` and `Linux Tests (release)` in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml). Current scenario owners and compatibility boundaries remain in the [Tool contract](../specs/tools.md#acceptance-scenarios-and-evidence-owners).
