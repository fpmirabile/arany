# Beta procedural-macro source review

Status: **source review of the 23 Linux-selected entrypoints and 17 macOS-selected entrypoints; release gate open**. The [locked normal-plus-build target inventory](./beta-dependency-inventory.md) excludes dev-only and metadata-only packages. Versions are fixed by [Cargo.lock](../../Cargo.lock); the linked upstream source revisions are those recorded in each cached published package's `.cargo_vcs_info.json`, not substitutes for the lockfile's registry checksums. Cargo's [Rust Reference](https://doc.rust-lang.org/reference/procedural-macros.html) explains why these macros execute with compiler-host file and I/O access during compilation.

## Build-host authority observed

Only `paste` and `rustversion` among these 23 declare custom-build targets in their published manifests; none of the six Linux-only additions has a `build.rs`. [`paste/build.rs`](https://github.com/dtolnay/paste/blob/a2c7e27875277450ed28147623ba5218dd23e732/build.rs#L1-L42) reads Cargo's `RUSTC`, runs it with `--version`, and emits version-dependent `cfg` lines. [`rustversion/build/build.rs`](https://github.com/dtolnay/rustversion/blob/3a7c76605450b9a7299c6502a421909de9126a59/build/build.rs#L19-L107) reads `RUSTC`, `RUSTC_WRAPPER`, `OUT_DIR`, and `HOST`; runs the compiler or wrapper with `--version`; writes `version.expr` under `OUT_DIR`; and emits `cfg` lines. The latter makes compiler/wrapper provenance and the generated version expression part of the build input. Cargo documents build scripts as host executables whose stdout can [control compilation](https://doc.rust-lang.org/cargo/reference/build-scripts.html#outputs-of-the-build-script).

Four macro crates read the build environment directly. [`clap_derive`](https://github.com/clap-rs/clap/blob/13f2db5072d600c11d8d6298e4e9ba53ffc6c1ab/clap_derive/src/item.rs#L1269-L1306) reads `CARGO_PKG_DESCRIPTION`, `CARGO_PKG_AUTHORS`, and `CARGO_PKG_VERSION` when those derive attributes are requested; its [`Parser` derive](https://github.com/clap-rs/clap/blob/13f2db5072d600c11d8d6298e4e9ba53ffc6c1ab/clap_derive/src/derives/parser.rs#L27-L42) also reads `CARGO_PKG_NAME`. [`paste`'s `env!("NAME")` segment](https://github.com/dtolnay/paste/blob/a2c7e27875277450ed28147623ba5218dd23e732/src/segment.rs#L150-L171) can read the named environment variable and insert its value into a generated identifier. In Arany's selected graph `paste` enters through Ratatui, whose [observed invocations](https://github.com/ratatui/ratatui/blob/28732176e1adb4cddba45c2d6b2b27abf7a46f79/src/style/stylize.rs#L118-L168) use color/modifier segments rather than `env!`; this is a scoped source observation, not proof about every expansion. [`strum_macros`](https://github.com/Peternator7/strum/blob/7ab74c8cd97bc5d607c72ffdecd09f25f368acdf/strum_macros/src/lib.rs#L19-L34) reads `STRUM_DEBUG` and can print generated tokens into build output. [`rustversion`](https://github.com/dtolnay/rustversion/blob/3a7c76605450b9a7299c6502a421909de9126a59/src/time.rs#L15-L34) also reads `CARGO_PKG_NAME` and wall-clock time; the observed callers use the date in [parse diagnostics](https://github.com/dtolnay/rustversion/blob/3a7c76605450b9a7299c6502a421909de9126a59/src/bound.rs#L27-L29), not in emitted code.

The two Zbus-family macro crates call [`proc-macro-crate::crate_name`](https://github.com/z-galaxy/zbus/blob/7518d73db4dbf830ec1c9c43865bf8aeae9a8ffd/zbus_macros/src/utils.rs#L17-L26) to choose generated crate paths; [`zvariant_derive` does likewise](https://github.com/z-galaxy/zbus/blob/0f4db6980bc1566278618a46c9ffa7f5f025c18a/zvariant_derive/src/utils.rs#L8-L25). The locked [`proc-macro-crate 3.5.0` helper](https://github.com/bkchr/proc-macro-crate/blob/8f3d8b04539f732e09c07907f138a248c8d0eed9/src/lib.rs#L173-L216) reads `CARGO_MANIFEST_DIR/Cargo.toml` and potentially the workspace manifest; when `CARGO` is set, it [launches that environment-selected executable](https://github.com/bkchr/proc-macro-crate/blob/8f3d8b04539f732e09c07907f138a248c8d0eed9/src/lib.rs#L241-L257) with `locate-project --workspace --message-format=plain` while expanding a macro. It also reads [`CARGO_TARGET_TMPDIR`](https://github.com/bkchr/proc-macro-crate/blob/8f3d8b04539f732e09c07907f138a248c8d0eed9/src/lib.rs#L343-L355) when resolving the generated crate path. This is compiler-host file/process authority in a transitive helper, not runtime D-Bus communication. A controlled release build must fix and verify the effective `CARGO` executable, PATH resolution, and manifest inputs; a source review or lockfile checksum alone cannot establish them.

The six additional direct macro sources showed no explicit network client, dynamic-library loader, or arbitrary file read/write call beyond static documentation includes; the two build scripts have the `OUT_DIR` write described above. This is **not** a claim that compiler-host execution is sandboxed or that all transitive macro dependencies are inert. Source review also found generated `unsafe` in [`enumflags2_derive`](https://github.com/meithecatte/enumflags2/blob/332c37f47577e5f6b7104419da7e761963032086/enumflags_derive/src/lib.rs#L334-L350), [`futures-macro`](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-macro/src/join.rs#L41), [`yoke-derive`](https://github.com/unicode-org/icu4x/blob/a59ab860d4bda548e94dfbf992d87fe1f761bc55/utils/yoke/derive/src/lib.rs#L218-L240), and [`zerovec-derive`](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/utils/zerovec/derive/src/ule.rs#L58-L65). The [`RawBitFlags` safety contract](https://github.com/meithecatte/enumflags2/blob/332c37f47577e5f6b7104419da7e761963032086/src/lib.rs#L304-L325) requires accurate bit representations and single-bit enum values. These are generated-code invariant review targets, not evidence of build-host I/O or a demonstrated exploit.

## Decision and limits

No independent exploit was established among these 23 reviewed entrypoints, so this pass does not create a new finding. Keep the supply-chain release gate open: source-only inspection cannot attest the compiler/wrapper/`CARGO` executable identities, ambient build environment, manifest inputs, exact macro invocations and expanded code, transitive dependency behavior, binary artifacts, or native macOS behavior. The GitHub revisions were not fetched separately; the inspected bytes were the locally cached published crate sources. A controlled release build must pin and inspect compiler-host executables and build output, then review the expanded `unsafe` paths, generated tracing fields, and artifact provenance for the selected targets. Re-run this review after a lockfile, feature, or target change.
