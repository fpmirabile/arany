# Beta build-script source review

Status: **current selected-entrypoint source review; release gate open**. The prior locked normal-plus-build trees selected 32 third-party custom-build packages on Linux and 29 on each macOS target. The Linux-only direct `nix 0.29.0/user` dependency now selects an additional build script and its `cfg_aliases 0.2.2` build dependency; the Linux entrypoint count is 33, and macOS is unchanged. The earlier Ratatui/Crossterm comparison remains the prior baseline, not a claim that this new Linux entrypoint was already selected. Reproduce the comparison with `cargo tree --locked --offline --target <triple> --edges normal,build --prefix none --format '{p}'` and `cargo metadata --locked --offline --filter-platform <triple> --format-version 1`; [Cargo.lock](../../Cargo.lock) fixes registry versions/checksums. The linked upstream revisions below came from the cached published packages' `.cargo_vcs_info.json`; inspection used those local published sources, not a separately fetched checkout. Cargo [executes build scripts on the build host](https://doc.rust-lang.org/cargo/reference/build-scripts.html) and uses their stdout to set compiler configuration and linkage.

## Candidate finding and verification boundary

The 2026-10-01 guarded Linux build that produced the candidate executable with SHA-256 `2ad36bdfee8287e1917fa85196ba90eac3a6c2e383540dc86ddfdbec2bce7c80` left 37 build-script `output` records; some packages have distinct host and target units. Those records emit exactly two `rustc-link-lib` directives, for static AWS-LC crypto and SQLite, and two `rustc-link-search` directives, both beneath that build's private target directory. They emit no `rustc-env` or `rustc-flags` directives. Six generated `.rs` files exist under script output directories; `libsqlite3-sys`'s generated `bindgen.rs` has SHA-256 `5b5a37a74dc728fb0bcd041867eb577c03c95e2fe46285262c589a3b1cd4bbac`, identical to `sqlite3/bindgen_bundled_version.rs` extracted from the checksum-matched `libsqlite3-sys 0.38.2` archive. AWS-LC emitted two assembler warnings about `.note.GNU-stack`; `readelf -W -l` reports the final candidate's `GNU_STACK` as `RW`, without execute permission. This is current Linux output and artifact evidence, not proof of compiler/wrapper identity, every native object input, absence of build-host tampering, or macOS behavior.

The `libc` fixed-name command path remains an open [release finding](./findings/libc-build-path-executable.md) for unguarded builds, native macOS verification, and full host provenance. The guarded entry point now rejects an executable `emcc` on `PATH` and ambient `LIBC_CI` before Cargo; a planted-executable test and fresh Linux release build pass. The risk requires host-build-environment influence, not malicious Workspace input; no affected Arany artifact or binary-level native ABI change is demonstrated by this source review. A controlled release environment must still constrain compiler/wrapper/SDK identities and the remaining `PATH` inputs, record build-script outputs, and repeat the guarded build on native macOS.

Across the remaining 24 scripts in the current 29-entry macOS selection and the four additional Linux scripts, direct entrypoint/source inspection found no HTTP client, download command, or additional arbitrary host-file path that substitutes external code for locked crate content. That observation does **not** clear transitive build dependencies, compiler/wrapper/`cc`/CMake subprocesses, locally unpacked registry-source integrity, generated Rust output, or final artifacts. In particular, packaged probe files, `zerocopy`'s manifest, and `rustix`'s architecture-file presence still require immutable source bytes; the earlier Linux output snapshot predates the Nix selection and is not a complete validation of every emitted `cfg`, generated source, or native object, and macOS has no equivalent snapshot. Source-only inspection cannot prove native macOS build or runtime behavior. Re-run this classification whenever the lockfile, features, targets, toolchain, or release environment changes.
