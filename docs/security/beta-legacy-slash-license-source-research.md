## Evidence and provisional MIT branch

Cargo documents `OR` as the SPDX choice operator, and the [Rust Style Guide](https://doc.rust-lang.org/stable/style-guide/cargo.html#package-metadata) permits the historical `/` spelling in place of `OR`. These five package declarations therefore support one MIT alternative, rather than simultaneous MIT and Apache-2.0 compliance. This establishes an available branch, not legal approval of a release bundle. [Cargo manifest reference](https://doc.rust-lang.org/cargo/reference/manifest.html#the-license-and-license-file-fields), [SPDX expression grammar](https://spdx.github.io/spdx-spec/v2.3/SPDX-license-expressions/#d42-disjunctive-or-operator).

## Remaining release judgment

The table gives the conservative package-by-package inputs if Arany uses `NOTICE` to carry third-party license text. MIT requires retention of its copyright and permission notices in copies or substantial portions; it does **not** require a file specifically named `NOTICE`. Using that layout and deciding whether each package's code enters an actual distributed artifact remain release-review judgments, not facts established by Cargo metadata.

The two unusual attributions have a traceable **textual lineage, not verified copyright provenance**:

- Steven Fackler added `LICENSE-MIT` to [`rust-openssl-verify` on 2016-04-30](https://github.com/sfackler/rust-openssl-verify/commit/ddc0a3707e9224283be8078354096d7af8b022e6), then added a byte-identical file to [`fallible-iterator` on 2016-05-06](https://github.com/sfackler/rust-fallible-iterator/commit/42067d38f425ffdf5d7422ad23ae70359b2e683e). The [`v0.3.0` tag](https://github.com/sfackler/rust-fallible-iterator/blob/v0.3.0/LICENSE-MIT) and [published crate](https://docs.rs/crate/fallible-iterator/0.3.0/source/LICENSE-MIT) retain that file and its `rust-openssl-verify Developers` line.
- Michal Vaner added `LICENSE-MIT` to [`tokio-jsonrpc` on 2017-02-07](https://github.com/vorner/tokio-jsonrpc/commit/0dcc1c464d00b23b8aae35e4c74ba32ba0299eec), then added a byte-identical file to [`signal-hook` on 2018-06-22](https://github.com/vorner/signal-hook/commit/429e738466eee60248de739f9c83ec0b8a26ed80). The [`v0.3.18` tag](https://github.com/vorner/signal-hook/blob/v0.3.18/LICENSE-MIT) and [published crate](https://docs.rs/crate/signal-hook/0.3.18/source/LICENSE-MIT) retain that file and its `tokio-jsonrpc developers` line.

The shared authors, chronology, and identical Git blobs are consistent with reusing license-file templates; they do **not** establish that either named group wrote or owns the later crate's code. Preserve the published lines rather than substituting manifest authors. If a release reviewer requires ownership provenance, seek maintainer clarification; this check alone cannot clear the notices.

This is evidence for a defensible branch and a proposed packaging layout, **not a legal conclusion** that the notice bundle is complete. A release reviewer still needs to record the MIT choice, approve the actual third-party text, and compare the Linux/macOS artifacts with it. Arany's current [NOTICE](../../NOTICE) contains only its own attribution; the independent [native-code](./beta-native-license-notice-research.md) and [`option-ext` MPL-2.0](./beta-dependency-inventory.md#license-and-advisory-status) branches remain open. A passing `cargo-deny` policy check would not itself approve redistribution.
