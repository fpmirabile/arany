# Locked `yoke-derive` generated-unsafe review

Status: **source and feature-selection review for the Linux normal/build graph and both macOS target selections; release gate open**. [Cargo.lock](../../Cargo.lock) pins `yoke-derive 0.8.4` with registry checksum `ec8ebde2db3681e8c9980cc27822030e68752690ddfa9473e739aeb4dbde6d71`. Its cached published source records ICU4X revision `a59ab860d4bda548e94dfbf992d87fe1f761bc55` in `.cargo_vcs_info.json`; the revision identifies the cited source, not the built artifact. `cargo tree --locked --offline --target <target> -e normal,build -i yoke-derive` selects it through `yoke 0.8.3` on `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`, and `x86_64-apple-darwin`, ultimately through Arany's `url`/`idna` dependency path. On all three, `yoke/derive` and `zerotrie/yoke` are enabled, `icu_properties` has only `compiled_data`, and `icu_provider` has only `baked` among their named features. [Yoke's reexport](https://github.com/unicode-org/icu4x/blob/a954ec29392c0225453404cb1f6a77f0ded27089/utils/yoke/src/lib.rs#L58-L63) makes the derive available; feature selection alone does not invoke it.

A bounded search of `src/` in the six selected crates with visible `Yokeable` derives identifies **16 active source derives** on each target. The two lifetime-free inputs are [`CodePointTrieHeader`](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/collections/src/codepointtrie/cptrie.rs#L171-L180) and [`ZeroTrie<Store>`](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/utils/zerotrie/src/zerotrie.rs#L65-L70), the latter selected by `zerotrie/yoke`. Twelve single-lifetime inputs take the ordinary covariance branch: three other [`icu_collections` types](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/collections/src/codepointtrie/cptrie.rs#L129-L154) ([inversion list](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/collections/src/codepointinvlist/cpinvlist.rs#L30-L44), [list and strings](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/collections/src/codepointinvliststringlist/mod.rs#L25-L47)), four [`icu_normalizer` provider types](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/normalizer/src/provider.rs#L121-L207), four [`icu_properties` provider types](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/properties/src/provider.rs#L904-L1180), and [`PropertyValueNameToEnumMap`](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/properties/src/provider/names.rs#L326-L336). The two manual-covariance inputs are [`PropertyEnumToValueNameLinearMap` and `PropertyScriptToIcuScriptMap`](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/properties/src/provider/names.rs#L375-L410), whose fields are `VarZeroVec<'data, str>` and `ZeroVec<'data, NichedOption<Script, 4>>`. The adjacent [`PropertyEnumToValueNameSparseMap`](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/properties/src/provider/names.rs#L349-L361) needs `icu_properties/alloc`, which is absent. The [`icu_provider` derives](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/provider/core/src/lib.rs#L98-L105) occur under `alloc`, `export`, or [`cfg(test)`](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/provider/core/src/data_provider.rs#L465-L479); all five manual-covariance [`zerovec` derive examples](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/yoke_impls.rs#L298-L501) are inside `#[cfg(test)] mod test`. Those features/tests are outside this normal/build selection. This count covers visible derives in selected source, not macros another expander might synthesize. The same [`zerovec` module has hand-written `unsafe impl Yokeable` code](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/yoke_impls.rs#L25-L299) outside its test module; that is a separate transitive-unsafe review surface, not generated by this derive.

The pinned generator emits [`unsafe impl Yokeable` even for lifetime-free inputs](https://github.com/unicode-org/icu4x/blob/a59ab860d4bda548e94dfbf992d87fe1f761bc55/utils/yoke/derive/src/lib.rs#L213-L245); there `Output = Self`, type parameters gain `'static` bounds, and the methods are identity operations. For ordinary single-lifetime inputs it emits an [`unsafe impl`, a lifetime-erasing `transmute` in `make`, and a mutable pointer cast in `transform_mut`](https://github.com/unicode-org/icu4x/blob/a59ab860d4bda548e94dfbf992d87fe1f761bc55/utils/yoke/derive/src/lib.rs#L269-L329). Its `transform` body must compile with a raw-reference coercion check, intended to establish covariance. The manual branch adds [per-field `Yokeable`/`'static` checks](https://github.com/unicode-org/icu4x/blob/a59ab860d4bda548e94dfbf992d87fe1f761bc55/utils/yoke/derive/src/lib.rs#L394-L469), then emits [transmutes for borrowed and owned transforms, `make`, and a mutable pointer cast](https://github.com/unicode-org/icu4x/blob/a59ab860d4bda548e94dfbf992d87fe1f761bc55/utils/yoke/derive/src/lib.rs#L478-L543). The `#[yoke(prove_covariance_manually)]` attribute selects those checks; it is not, by itself, proof of covariance.

For single-lifetime types, the exact safety obligation is [`Yokeable<'a> for T<'static>` with `Output = T<'a>` and covariance in `'a`](https://github.com/unicode-org/icu4x/blob/a954ec29392c0225453404cb1f6a77f0ded27089/utils/yoke/src/yokeable.rs#L11-L45). The lifetime-only conversions must preserve the same value/layout; the `transform_mut` closure's `'static` and higher-ranked bounds must prevent insertion of shorter-lived references; and a value returned by `make` must be dropped before its borrowed backing data ([method contract](https://github.com/unicode-org/icu4x/blob/a954ec29392c0225453404cb1f6a77f0ded27089/utils/yoke/src/yokeable.rs#L87-L119), [mutable method contract](https://github.com/unicode-org/icu4x/blob/a954ec29392c0225453404cb1f6a77f0ded27089/utils/yoke/src/yokeable.rs#L121-L239)). The selected manual branch also depends on the soundness of the nested `zerovec` `Yokeable` implementations; this note does not independently prove them.
