# Locked `zerovec` handwritten-unsafe review: selected Yoke and two-field ULE paths

Status: **bounded source review; release gate open**. [Cargo.lock](../../Cargo.lock) pins `zerovec 0.11.8` with checksum `bb0464e17806c1d976d5cba29399c7f08e516e279e2ba493f63123b5fca67dd8`; the cached published source records ICU4X revision `c56bbb5a7b47409759113903764c456f13b418e5`. Offline `cargo tree --locked --target <target> -e normal,build` and feature-tree checks select `zerovec` through Arany's `url`/IDNA chain on `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`, and `x86_64-apple-darwin`. All three select `zerovec/yoke` and `zerovec/derive`, **not** `zerovec/alloc`; the latter excludes the [handwritten `ZeroMap` Yokeable implementations](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/yoke_impls.rs#L109-L295). Target resolution on Linux is not a native macOS build.

Threshold set before inspection: a credible safe-API-reachable invalid lifetime, alias, alignment, bounds, or byte-representation cast in these selected paths is release-blocking. Missing whole-crate or artifact proof keeps the release gate open but is not labeled an exploit. The asset is process memory safety while ICU data is handled; the relevant inputs are borrowed/baked Unicode data and, at the outer dependency boundary, URL/IDNA input. Source selection does not establish that every selected type is invoked by Arany at runtime.

## Yoke lifetime conversions

The two selected `#[yoke(prove_covariance_manually)]` inputs are [`PropertyEnumToValueNameLinearMap` (`VarZeroVec<'data, str>`) and `PropertyScriptToIcuScriptMap` (`ZeroVec<'data, NichedOption<Script, 4>>`)](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/properties/src/provider/names.rs#L375-L410). Their nested handwritten [`Yokeable` implementations](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/yoke_impls.rs#L25-L79) use safe `self` coercions for `transform`/`transform_owned`, `ManuallyDrop` plus a same-type-family pointer read for `make`, and a mutable-reference transmute for `transform_mut`. `ZeroVec` has a lifetime-covariant [`PhantomData<&'a T::ULE>` marker](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/zerovec/mod.rs#L92-L102); without `alloc`, `VarZeroVec` contains only a [borrowed `&'a VarZeroSlice` variant](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/varzerovec/vec.rs#L143-L149). The safe coercions support covariance for these fixed `T` inputs; the pointer reads still require lifetime-only layout identity, single ownership/drop, and backing data surviving the erased value. [`Yokeable::make` assigns that drop-order obligation to its unsafe caller](https://github.com/unicode-org/icu4x/blob/a954ec29392c0225453404cb1f6a77f0ded27089/utils/yoke/src/yokeable.rs#L109-L119); its [`F: 'static + for<'b> FnOnce(&'b mut Output)` bound](https://github.com/unicode-org/icu4x/blob/a954ec29392c0225453404cb1f6a77f0ded27089/utils/yoke/src/yokeable.rs#L121-L239) prevents safe mutable callers from inserting a newly short-lived borrow. The nested `ZeroVec` storage and `VarZeroVec` parsing implementations themselves were not audited here.

## Two-field byte layout and typed access

The selected [`CodePointInversionListAndStringList`](https://github.com/unicode-org/icu4x/blob/a14f2dad852be26bad277ae704abf27a15cbfed1/components/collections/src/codepointinvliststringlist/mod.rs#L28-L46) invokes the `make_varule` two-field branch: `CodePointInversionListULE` and `VarZeroSlice<str>` are represented by `MultiFieldsULE<2, Index16>`. The pinned generator calculates both lengths, creates the buffer, and writes fixed slots `0` and `1` with [`set_field_at`](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/utils/zerovec/derive/src/make_varule.rs#L577-L618); its validator first parses the structure and then [validates each slot as its declared `VarULE` type](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/utils/zerovec/derive/src/make_varule.rs#L644-L690). The generated outer [`VarULE::validate_bytes` calls that validator](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/utils/zerovec/derive/src/varule.rs#L83-L125) before safe parsed access.

The handwritten [`MultiFieldsULE`](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/ule/multi.rs#L12-L111) is transparent over a byte-aligned lengthless slice. Its safe partial constructor writes index metadata into an already initialized `&mut [u8]` and returns structural bytes; the unsafe setters must fill the typed slots before typed getters are used. The [writer](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/varzerovec/components.rs#L721-L792) checks the exact output length and index range; the [parser](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/varzerovec/components.rs#L266-L306) checks index-table extent and [monotone in-range slices](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/varzerovec/components.rs#L435-L483). For `LEN = 2`, those checks support the `get_bytes_at_mut`, `validate_field`, and `get_field` preconditions of in-range slots; each nested `VarULE` must still reject invalid field bytes. The [`VarULE` trait contract](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/ule/mod.rs#L259-L343) additionally requires byte alignment, complete validation, and a reference to those same bytes. This review did not independently prove the generated unsized-tail pointer metadata cast or the nested `CodePointInversionListULE`/`VarZeroSlice<str>` codecs.

No threshold-crossing issue was identified in these exact source paths. This is not a whole-`zerovec` unsafe audit, exact macro expansion, Miri proof, native macOS test, or release-artifact attestation. Before release, inspect feature-faithful dependency expansions and nested codec/storage invariants, exercise the selected parse/encode and Yoke lifetime paths under targeted verification, and rerun the review if the lockfile or features change.
