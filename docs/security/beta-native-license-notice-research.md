Its [published source listing](https://docs.rs/crate/aws-lc-rs/1.18.1/source/) includes `LICENSE` but no `NOTICE`; its [license file](https://github.com/aws/aws-lc-rs/blob/22e629d5c46276497a24ee3e575be4315940e7cb/aws-lc-rs/LICENSE) reproduces Apache-2.0 and ISC terms. The upstream repository's [current root `NOTICE`](https://github.com/aws/aws-lc-rs/blob/main/NOTICE) credits Amazon and Brian Smith for ring-derived work. That moving-branch file is a lead for the artifact review, **not** proof that the same text was part of the pinned crate distribution.
- [`aws-lc-sys 0.45.0` declares a compound license expression](https://docs.rs/crate/aws-lc-sys/0.45.0/source/Cargo.toml) containing ISC, Apache-2.0, MIT, BSD-3-Clause, and alternative branches for imported code. Its [pinned `LICENSE`](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/LICENSE) identifies BoringSSL- and OpenSSL-derived code, mlkem-native and mldsa-native, and the compiled third-party Fiat Cryptography, s2n-bignum, and Jitter Entropy code. It states that Amazon elects BSD-3-Clause, not GPL-2.0, for its Jitter Entropy distribution. The [crate inclusion list](https://docs.rs/crate/aws-lc-sys/0.45.0/source/Cargo.toml) selects third-party source files and Fiat's nested `LICENSE`; the cached published package has no separate s2n-bignum or Jitter Entropy `LICENSE` file, although the top-level `LICENSE` includes their license and attribution descriptions. This merits a file-by-file release-artifact check, not an inference that the package is or is not compliant.
- [`libsqlite3-sys 0.38.2` declares MIT](https://docs.rs/crate/libsqlite3-sys/0.38.2/source/Cargo.toml), and its [license file](https://docs.rs/crate/libsqlite3-sys/0.38.2/source/LICENSE) carries the rusqlite developers' copyright and MIT permission notice. Arany enables [`rusqlite`'s `bundled` feature](../../Cargo.toml), for which the [crate's README](https://docs.rs/crate/libsqlite3-sys/0.38.2/source/README.md) says it compiles embedded SQLite 3.53.2. [SQLite's own copyright statement](https://www.sqlite.org/copyright.html) says its deliverable code and documentation are dedicated to the public domain; that statement does **not** make the Rust binding crate public domain. The cached amalgamation identifies itself as SQLite 3.53.2 in its [source header](https://docs.rs/crate/libsqlite3-sys/0.38.2/source/sqlite3/sqlite3.c).

## NOTICE rule and unresolved decision

[Apache-2.0 §4](https://www.apache.org/licenses/LICENSE-2.0) describes redistribution conditions: supply the license; mark modified files; retain pertinent source-form notices; and, **if the Work includes a `NOTICE` text file as part of its distribution**, carry its pertinent attribution notices in a permitted readable location. The condition is not a universal instruction that every Apache-licensed dependency has a `NOTICE` file. The same source says a `NOTICE` is informational and does not modify the license. Whether the upstream repository-level AWS notice, package-level files, and any source-file notices must appear in Arany's particular binary/source distributions requires a review of the actual selected files and release artifacts; Cargo license fields and the present Arany `NOTICE` alone cannot resolve that question. [Apache-2.0 §4](https://www.apache.org/licenses/LICENSE-2.0), [AWS repository `NOTICE`](https://github.com/aws/aws-lc-rs/blob/main/NOTICE), [AWS crate source listing](https://docs.rs/crate/aws-lc-rs/1.18.1/source/).
