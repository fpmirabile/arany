Status: **source and feature-selection review for Linux normal/build and both macOS targets; release gate open**. [Cargo.lock](../../Cargo.lock) pins `zerovec-derive 0.11.6` with registry checksum `34df6fc39dbd26ddc9c10e6a2984476e13acce22e64e4487636ef494369225da`. Its cached published source records ICU4X revision `898d79c69f37da7b45a15a5714663c9b59b3d928` in `.cargo_vcs_info.json`; the revision identifies cited source, not an artifact. `cargo tree --locked --offline --target <target> -e normal,build -i zerovec-derive` selects it through `zerovec 0.11.8` on `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`, and `x86_64-apple-darwin`. On each selection `zerovec/derive` is enabled; `icu_collections` has no features, `icu_properties` has `compiled_data`, and `icu_provider` has `baked`. Both `make_varule` inputs invoke the same [generated `unsafe impl VarULE`](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/utils/zerovec/derive/src/varule.rs#L90-L128). Its `from_bytes_unchecked` recovers the tail's fat-pointer metadata, then casts a pointer to the original bytes to the generated struct; it relies on the expected unsized-tail layout and prior whole-buffer validation. The [`ULE` contract](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/ule/mod.rs#L42-L89) requires byte alignment, no padding or uninitialized bytes, and rejection of invalid or incomplete input. The [`VarULE` contract](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/ule/mod.rs#L255-L356) additionally requires `from_bytes_unchecked` to reference those same validated bytes; [`EncodeAsVarULE`](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/ule/encode.rs#L43-L70) must report the exact encoded length and write a valid complete representation. For the two-field case, [the helper's unsafe methods](https://github.com/unicode-org/icu4x/blob/c56bbb5a7b47409759113903764c456f13b418e5/utils/zerovec/src/ule/multi.rs#L60-L104) require indices in range and types matching each encoded slot; generator iteration supplies fixed indices `0` and `1` and validates both slots. The selected source structurally supports these obligations, but this is not an independent proof of the tail-metadata cast or of nested `ULE`/`VarULE` implementations.

No direct source invocation of `#[derive(VarULE)]` or the `make_ule` struct branch was identified in the selected crates; `make_varule` calls the `VarULE` generator internally, while the selected `make_ule` enum branch emits its own impl. This review covers visible selected invocations and generated `unsafe` only. The selected handwritten `MultiFieldsULE<2, Index16>` path has a separate [bounded source review](./beta-zerovec-handwritten-unsafe-review.md); nested codecs and the rest of `zerovec` are outside that review. No exact expansion was captured: a feature-faithful check would need the selected dependency compiler invocations, while a standalone package build can change feature unification. The macOS graphs were resolved offline on Linux, not built natively. Compiler/proc-macro identity, expanded tokens, native behavior, and release-artifact provenance remain unverified.
