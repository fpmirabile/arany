# Locked `futures-macro` generated-unsafe review

Status: **source-level conclusion for the selected Linux normal/build graph; release gate open**. [Cargo.lock](../../Cargo.lock) fixes `futures-macro 0.3.34` and its registry checksum. The locally cached published source records futures-rs revision `705e6b5c0f06535b1aac1cb1989a172b3d45be8c` in `futures-macro-0.3.34/.cargo_vcs_info.json`; that revision is a source citation, not an artifact attestation. `cargo tree --locked --offline --target x86_64-unknown-linux-gnu -e normal,build -i futures-macro` selects it through [`futures-util 0.3.34`](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-util/Cargo.toml#L38-L63), whose `async-await-macro` feature is enabled in this graph. That feature compiles and reexports the macro entrypoints; it does not itself invoke them. [The reexport wrappers](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-util/src/async_await/join_mod.rs#L82-L110) forward tokens only when a caller uses the public macro.

The pinned macro emits explicit `unsafe` in two places: [`join!` and `try_join!` share `bind_futures`](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-macro/src/join.rs#L30-L44), which creates `Pin::new_unchecked(&mut local_maybe_done)` for each input; [`select!` and `select_biased!` share `select_inner`](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-macro/src/select.rs#L121-L130), which creates `Pin::new_unchecked(&mut future)` inside each poll closure ([source lines 151–210](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-macro/src/select.rs#L151-L210)). The other pinned entrypoint implementations, `stream_select` and `test`, contain no explicit generated `unsafe` (`futures-macro-0.3.34/src/stream_select.rs` and `src/executor.rs`). The relevant [Rust `Pin::new_unchecked` contract](https://doc.rust-lang.org/std/pin/struct.Pin.html#method.new_unchecked) requires the pointee to remain in place and valid until drop.

The source supports a narrow structural invariant for those constructors: `join` binds each input to a local `MaybeDone`, then shadows the local with a pinned mutable reference used through the awaited `poll_fn` ([source lines 35–84](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-macro/src/join.rs#L35-L84)). `select` demands `Unpin` and `FusedFuture` for an existing path, while a non-path expression is bound to a local inside the select expression before polling ([source lines 151–210](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-macro/src/select.rs#L151-L210); [assertion definitions](https://github.com/rust-lang/futures-rs/blob/705e6b5c0f06535b1aac1cb1989a172b3d45be8c/futures-util/src/async_await/mod.rs#L50-L57)). Thus its intended pinning argument is visible in source. This is not an independent proof that every expansion or caller upholds the contract.

Searching `src/` in `futures-util` and its seven direct selected dependents (`futures-executor`, `hyper-util`, `reqwest`, `opentelemetry_sdk`, `secret-service`, `tower`, `tower-http`) found **one** source invocation of these public macros: [`opentelemetry_sdk` imports and calls `select!`](https://docs.rs/crate/opentelemetry_sdk/0.33.0/source/src/trace/span_processor_with_async_runtime.rs#L9-L14) ([call at line 347](https://docs.rs/crate/opentelemetry_sdk/0.33.0/source/src/trace/span_processor_with_async_runtime.rs#L346-L365)). Its module is gated by [`experimental_trace_batch_span_processor_with_async_runtime`](https://docs.rs/crate/opentelemetry_sdk/0.33.0/source/src/trace/mod.rs#L19-L21), which `cargo tree --locked --offline --target x86_64-unknown-linux-gnu -e features -i opentelemetry_sdk` does not show; [Arany's manifest](../../Cargo.toml) requests `trace` for normal builds and `trace, testing` for dev builds, and the pinned SDK's [`testing` feature](https://docs.rs/crate/opentelemetry_sdk/0.33.0/source/Cargo.toml#L105-L112) does not enable that experimental feature. The remaining selected `select!` calls in Arany use `tokio::select!` ([example](../../src/engine/run_loop.rs)), a different macro. Therefore the selected Linux normal/build source graph has **no identified active invocation** of `futures-macro`'s two unsafe generators. This is a graph/source inference, not a compiler expansion observation.
