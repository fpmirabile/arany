# Finding: interactive PTY loss can strand Arany's input reader

Status: **repaired and Linux-tested; native macOS availability and distribution gates remain open**. Severity: **high for local availability**. This is not a claim of remote code execution or credential disclosure.

## Evidence and boundary

The published `crossterm 0.29.0` Unix Mio event backend ignored a zero-byte read and non-`WouldBlock`, non-`Interrupted` errors. After a PTY master closed, Arany's sole interactive reader in [`src/terminal/input.rs`](../../../src/terminal/input.rs) could stay inside `event::poll` instead of reporting the loss and joining. [Upstream issue #1110](https://github.com/crossterm-rs/crossterm/issues/1110) independently identifies the ignored-error busy loop. Arany now selects a [local, checksum-matched source copy](../../../vendor/README.md) through its relative Cargo patch; that one TTY loop returns `UnexpectedEof` for zero bytes and propagates permanent errors, while retaining the existing `WouldBlock` and `Interrupted` branches. The `use-dev-tty` feature remains absent.

The Linux product-process regression in [`tests/session_run/active_terminal/acquisition.rs`](../../../tests/session_run/active_terminal/acquisition.rs) opens a real inline setup PTY, observes the live prompt, closes only its test-owned master, and requires the product to exit within five seconds. It failed with the original registry source; its matching screen-reader case already passed. A second case in [`tests/session_run/active_terminal.rs`](../../../tests/session_run/active_terminal.rs) waits for an active synthetic Provider request before closing the PTY; the original backend left that request's socket open past a separate three-second deadline. With the selected local patch, all three default-feature Linux cases pass in 0.37 seconds, including cancellation of the active Run without an answer. An earlier abandoned product process had stdin/stdout/stderr linked to a deleted `/dev/pts/4`; its named terminal thread was runnable and accounted for about 85% lifetime CPU while its main thread slept. This process observation supports the original failure mode but does not identify how every older orphan was created.

A read-only host inventory on 2026-10-01 found 45 older `arany` processes with the same parent, all with deleted `/dev/pts/*` stdin and deleted executable images from prior build locations. All 45 accumulated CPU time during a 10.219-second interval, totaling 164 CPU seconds while host load was about 50 on 16 visible CPUs. Their exact invocation histories were not reconstructed, so this does not attribute every process to one test; it does establish a material local resource burden. None was terminated while user authorization was pending. After a host reboot later that day, `ps -C arany` returned no processes; no cleanup signal was needed or sent.

The current PTY-loss tests separately guard their discovered product PID. A focused regression exposed that the guard's literal `/proc/PID/exe` comparison rejected the expected binary path after Linux marked a replaced image ` (deleted)`. The guard now recognizes only the exact expected path or that exact path with the kernel suffix, and still requires its private State argument before signaling. The matcher test failed before the change and passed afterward; all three PTY-loss cases passed with the temporary alternate backend. This hardens future test cleanup but does not fix the default Crossterm spin or establish the origins of the older processes. The 45 existing processes were not terminated.

Loss of an SSH, tmux, IDE, or test-owned PTY is outside the Provider and Workspace trust boundaries but should not keep the attached process consuming CPU. The pre-fix active test proved that the product did not promptly cancel its local Provider socket after PTY loss; it did not prove how long a remote Provider would continue generating or billing. The patched Linux test proves prompt local cancellation, not remote billing cessation. No credential or omitted Workspace input was observed in the terminal transcript. No pre-existing orphan was signaled; the host reboot removed them.

## Integrated repair, alternatives, and remaining verification

The temporary `crossterm/use-dev-tty` alternate backend made Linux PTY-loss tests pass, but was not selected. It would add `filedescriptor 0.8.3` and its native FFI to runtime; its `tty.rs` source maps both EOF and `WouldBlock` to `Ok(0)`, so a readable-EOF macOS PTY could still spin. The selected Mio patch handles those cases separately without adding that dependency. Linux success is not native macOS evidence.

The pinned published crate archive's SHA-256 matched the original registry checksum in `Cargo.lock` before extraction. A full source-tree comparison found only the patched `mio.rs` differs from the cached published source, apart from the cache-only `.cargo-ok` marker; the original MIT license remains. The relative `[patch.crates-io]` and regenerated lockfile select that local source. The three default-feature Linux PTY-loss cases and complete default-feature offline suite pass. An unrelated warning from unmodified Crossterm source remains visible when Cargo builds the local copy.

The [source-archive entry point](../../../scripts/source-archive.sh) creates a separate top-level archive containing the original Arany package files, current root manifest and lockfile, and the patched Crossterm source and provenance README. It extracts that archive at a fresh path, compares the TTY repair byte-for-byte, verifies `cargo tree --offline --locked` selects the extracted local crate, and performs a fresh-target offline check. The final Linux archive run passed after the patch hunk's line endings were normalized to match the published source; its local SHA-256 was `67e15296e02f04003bdf6bcd226e5fa4211ad5dbcb1b266b7f0ba0bd633eab56`. This identifies the inspected local archive, not a published release artifact or binary/source pair.

The local patch enlarges the reviewed source and release-distribution surface. [Cargo packaging](https://doc.rust-lang.org/cargo/commands/cargo-package.html) removes `[patch]` and ignores a dependency's local `path` in the published manifest. The ordinary verified Arany `.crate` therefore builds against the unpatched registry source and is **not** a fixed install path. [Source replacement](https://doc.rust-lang.org/cargo/reference/source-replacement.html) requires identical source; [Cargo vendor](https://doc.rust-lang.org/cargo/commands/cargo-vendor.html) directs modified crates to `[patch]` or a local path dependency. A beta release must ship the separately verified top-level source archive with the binaries and identify it as their build input, or replace this arrangement with a reviewed published fork.

The earlier disposable archive rehearsal established feasibility before adoption; the current checked-in source-archive script now owns that reproducible procedure. Neither rehearsal nor the integrated Linux check proves native macOS behavior or complete binary-artifact provenance.

An application-level Mio observer was also tried and removed. Its stop path detached Crossterm's still-spinning reader after hangup, violating Arany's joined-reader invariant. Product exit would have hidden rather than repaired the dependency loop.

The integrated patch passed a fresh guarded Linux release build, default-feature offline suite, formatting, strict Clippy, source-archive extraction, and ordinary package verification with the stated limitation. Before closing this finding for beta, run the default-feature idle and active PTY-loss gates on both supported native macOS architectures, verify the source archive and guarded binary build on each host, and inspect the actual distributed source/binary pairing. Preserve the joined-reader invariant; lost terminal input must never become a submitted Message.
