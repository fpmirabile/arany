## Selected package and source paths

For `x86_64-unknown-linux-gnu`, `x86_64-apple-darwin`, and `aarch64-apple-darwin`, `cargo tree --locked --offline --target TARGET --invert aws-lc-sys --edges features` selects `reqwest/rustls` → Rustls/AWS-LC → `aws-lc-rs 1.18.1` → `aws-lc-sys 0.45.0`. `aws-lc-rs` enables `aws-lc-sys` and `prebuilt-nasm`; the latter reaches `aws-lc-sys/prebuilt-nasm` but its [build-script condition](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/main.rs#L1186-L1199) applies only to Windows x86-64, not these release targets. The selected feature trees do **not** enable `fips`, `bindgen`, `ssl`, or `all-bindings`; the [sys package manifest](https://docs.rs/crate/aws-lc-sys/0.45.0/source/Cargo.toml) declares `builder/main.rs` as its build script, bundled `aws-lc` C/assembly source, and `cc`, `cmake`, and Unix `pkg-config` build dependencies. Absent binding overrides, the [build script](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/main.rs#L893-L966) selects universal pregenerated Rust bindings for Linux and universal-prefixed bindings for Apple. If a source build selects the [CC builder](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/cc_builder.rs#L49-L88), it combines universal native sources with Linux x86-64, Apple x86-64, or Apple aarch64 source lists. These are conditional source-code paths, not a claim that all three were compiled. The [rs build script](https://github.com/aws/aws-lc-rs/blob/22e629d5c46276497a24ee3e575be4315940e7cb/aws-lc-rs/build.rs) forwards selected sys build metadata to its dependent crate.

## Build-environment control points

The [sys build-script selection](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/main.rs#L725-L813) checks `AWS_LC_SYS_SYSTEM_DIR` first. If it is absent, an unset `AWS_LC_SYS_USE_SYSTEM` **still auto-detects** a usable system AWS-LC through target-specific or bare `OPENSSL_DIR`, `OPENSSL_INCLUDE_DIR`/`OPENSSL_LIB_DIR`, then Unix pkg-config modules (`openssl`, `aws-lc`, `libcrypto`, `libcrypto-awslc`). `AWS_LC_SYS_USE_SYSTEM=0` disables auto-detection but conflicts with an explicit `AWS_LC_SYS_SYSTEM_DIR` and fails; `USE_SYSTEM=1` requires a discovered install. A candidate needs AWS-LC headers, a compatible version, library, and bindings, but that validation does **not** pin it to the bundled crate source or checksum. `AWS_LC_SYS_SYSTEM_BINDINGS` and `AWS_LC_SYS_SYSTEM_SKIP_VERSION_CHECK` further alter the system path; `AWS_LC_SYS_STATIC` can select static or dynamic linking. Sources: [pinned detection code](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/system_detect.rs), [pinned system-library code](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/system_library.rs), and [published package README](https://docs.rs/crate/aws-lc-sys/0.45.0/source/README.md).

Even on the bundled-source path, the same [builder](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/main.rs#L864-L890) accepts crate/target-specific controls. `AWS_LC_SYS_CMAKE_BUILDER` selects CMake versus CC; `NO_PREGENERATED_SRC`, `NO_ASM`, `SANITIZER`, and binding/prefix controls can change the path or fail it; `STATIC`, `SMALL`, `NO_JITTER_ENTROPY`, and `INCLUDES` can change linkage, compiled implementation, or headers. The [CC builder](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/cc_builder.rs#L373-L411) and [CMake builder](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/cmake_builder.rs#L202-L317) accept target/host/compiler/CFLAGS and CMake/toolchain inputs; ordinary `cc`/CMake environment and selected compiler/SDK therefore remain release inputs. On Apple targets, the [CoreServices header probe](https://github.com/aws/aws-lc-rs/blob/7943223c99d909bc399bdf1b856821bb04f1f3c5/aws-lc-sys/builder/main.rs#L1096-L1148) can automatically disable jitter entropy if unavailable. A locked Cargo graph alone cannot prove compiler flags, source list, dynamic dependencies, or equivalent native behavior across macOS hosts.

## Current artifact observation and remaining proof

The existing `target/release/build/aws-lc-sys-1d9e5338ba067fb0/output` records `Building with: CC`, `Symbol Prefix: Some("aws_lc_0_45_0")`, target `x86_64-unknown-linux-gnu`, `cargo:rustc-link-lib=static=aws_lc_0_45_0_crypto`, `link_kind=static`, and `libcrypto_path` inside that build's `OUT_DIR`. That archive exists. `readelf -d target/release/arany` lists no dynamic AWS-LC library. This supports **only that local Linux artifact's recorded path**; it does not authenticate the compiler invocation or all source bytes, prove a future clean release build, or prove either macOS target.

Before release, build each target in a controlled environment from the reviewed locked crate archive; reject ambient system-library selection and unreviewed native compiler/linker flags; capture verbose build-script and compiler evidence; inspect `libcrypto_path`, its source/build input provenance, final binary dependencies, and target-specific linkage. Run native macOS artifact and TLS/provider checks on both architectures, and reopen the supply-chain review whenever the lockfile, features, build environment, or toolchain changes.
