# Credential-store stalls in other harnesses

Retrieved: 2026-10-06  
Status: primary-source comparison and isolated synthetic diagnosis; no real account lookup, credential access, native-store mutation or model inference

## Finding

Other harnesses do not share one solution. Claude Code, Pi and OpenCode avoid the Linux Secret Service dependency by using credential files. Codex exposes an explicit backend choice and an automatic fallback mode. Gemini CLI addresses a non-responsive native store directly with a functional probe and a short observation deadline. These patterns do not establish the cause of Arany's recorded timeout, or prove that a timed-out write was rolled back.

## Why availability does not prove writability

Secret Service separates session establishment, collection lookup/creation, unlocking and item creation. A service can accept a session and return no matching items while having no default collection or no unlocked writable collection. Creation/unlocking can require a service-owned prompt whose completion depends on user interaction. A headless process may therefore reach a usable D-Bus service but stall later waiting for a prompt. This is a possible mechanism, not proof that Arany's observed stall took this path. [Service methods and collection aliases](https://specifications.freedesktop.org/secret-service/latest/org.freedesktop.Secret.Service.html), [collection/item creation](https://specifications.freedesktop.org/secret-service/latest/ch03.html).

Prompts belong to the client's D-Bus connection and become invalid on disconnect. The specification also describes a race between dismissal and completion. Consequently, killing a helper closes its connection and bounds the application's wait, but cannot prove an already accepted write or deletion never happened. [Prompt lifecycle and dismissal](https://specifications.freedesktop.org/secret-service/latest/prompts.html).

## Arany's recorded parent-deadline miss

The [Unicode editing closeout](../../planning/arany-beta/README.md#implemented-preserve-grapheme-boundaries-after-deletion) recorded one generic parent-deadline failure while other build work was running. It did not identify which stage exceeded the deadline. The original failure transcript was not located in the available local diagnostic logs. A later passing run cannot establish that the historical miss was caused by load, account locking, terminal input, or the credential helper.

The existing Linux owner, `setup::stalled_credential_bus_does_not_strand_unconfigured_start` in [setup.rs](../../tests/session_run/setup.rs), deliberately accepts a Unix socket connection and never answers D-Bus authentication. It exercises four credential waits: first startup and three resumed/preparation cases, including an unlinked running executable. Its total duration is therefore approximately twenty seconds; that is not one twenty-second credential operation. The first phase has a seven-second outer guard, and the shared process observer has a ten-second exit/output-EOF deadline per capture. These bounds have different owners from the helper's five-second operation deadline.

The focused owner passed exactly one test in 20.56 seconds with:

```sh
rtk proxy cargo test --locked --offline --test session_run setup::stalled_credential_bus_does_not_strand_unconfigured_start -- --exact --nocapture
```

A separate bounded observer of the same debug test process measured four helper lifetimes of 4.974, 4.991, 4.991 and 4.978 seconds; the entire owner passed in 20.574 seconds. Observation used only test-owned descendant process identity, state, wait channel and timestamps, without reading process environments or credential payloads. No helper exceeded its deadline in this run. These are observations on this host, not timing assertions or a load-independent guarantee.

Two further isolated comparisons narrowed the current behavior:

| Comparison | Observed result | What it establishes |
|---|---|---|
| Invoke the optimized internal helper directly against a silent synthetic peer; then change only the peer to close the connection | The silent peer received `AUTH EXTERNAL`; the diagnostic killed/reaped the direct helper after one second. Closing the peer made the helper exit with failure in 0.002 seconds. | This fixture stalls during D-Bus authentication, before Secret Service collection or item operations. Direct internal invocation omits the production parent supervisor; its continued wait is not a failure of that supervisor. |
| Run optimized attached startup with null stdin, then piped interactive stdin, then interactive stdin with GNU `timeout --foreground` | All three cases reached the composer in 5.009–5.018 seconds and exited successfully in 5.038–5.128 seconds. Interactive cases explicitly submitted `/quit`. | Neither stdin EOF nor the timeout process-group variation reproduced the historical miss in these isolated cases. |

The direct-helper probe and PTY comparisons used private homes, synthetic slots, test-owned Unix sockets, bounded captures and parent kill/reap cleanup. They did not contact the user's Secret Service. The pinned [zbus authentication handshake](https://github.com/dbus2/zbus/blob/zbus-5.19.0/zbus/src/connection/handshake/client.rs) waits for the authentication reply before method calls; its [method-call timeout](https://docs.rs/zbus/5.19.0/zbus/connection/struct.Builder.html#method.method_timeout) does not bound that phase. This explains why the synthetic peer needs Arany's external supervisor, not why the historical observer missed its deadline.

The historical parent-deadline miss remains unresolved. On recurrence, the existing owner needs bounded stage metadata distinguishing peer acceptance, helper start/reap, composer readiness, process exit and channel EOF, together with contemporaneous load metadata. Keep that follow-up in [NEXT_STEPS.md](../../NEXT_STEPS.md#beta-2-and-broader-release); do not increase deadlines or retry automatically. No product fix is justified by the currently passing observations alone.

## Application to Arany

Keep the existing [supervised credential boundary](../../agents/credentials.md): a bounded same-binary helper with kill/reap on deadline is stronger lifecycle evidence than a promise race or an in-process synchronous keyring call. Do not replace it with the latter patterns or increase its timeout as a substitute for diagnosis.

The separate native-store release gate requires a fresh private bus, isolated synthetic store and independent synthetic client. Record only operation-stage metadata: service activation, session establishment, default alias, collection count/locked state, creation versus unlock prompt, and prompt completion. Compare Arany's helper with an independent client on the same isolated service before attributing failure to either side. The deliberately silent authentication peer cannot prove those later native stages. Never inspect the user's real wallet or credential payloads.

For user recovery, retain explicit informed file-backend selection before a backend is pinned. A pinned native-store timeout must preserve the pin and report read failure separately from uncertain write/delete completion. Automatically saving the same credential to a file after an uncertain native write could create two copies and weaken the existing contract. The comparison supplies implementation options; it does not authorize changing Arany's backend-consent behavior.

## Scope and limits

Public source was downloaded and inspected at the listed commit hashes; branches can move. Claude evidence is documentation-only. No upstream binaries were executed, native stores unlocked or queried, real credentials read, or provider calls made. This research changes no product behavior or acceptance contract. Current synthetic supervision passes; Arany's historical observer miss still requires failure-stage evidence to identify its cause.
