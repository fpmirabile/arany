# Subscription Provider routes: October 2026 recheck

Retrieved: 2026-10-02  
Status: current official-source evidence, not live account conformance or legal approval

This is a short update to [the detailed subscription research](./consumer-subscription-authentication-for-provider-adapters.md). It distinguishes a documented third-party authorization from a first-party client that happens to accept a subscription. Neither route was exercised with a paid account for this report.

| Route | Current official position | Arany implication |
| --- | --- | --- |
| ChatGPT Plus/Pro in a local open-source app | OpenAI explicitly offers Sign in with ChatGPT plan usage to eligible users of open-source/local apps, with a dynamically issued client ID and a user-consented OAuth grant. | A native Arany account route is eligible to implement; login alone is not inference or model-conformance evidence. |
| Claude Pro/Max in Arany's native Anthropic adapter | Anthropic directs third-party product developers, including Agent SDK products, to API keys or a supported cloud provider. Without prior approval they may not offer Claude.ai login, intermediate Claude.ai credentials, or route plan credentials for their users. | Do not offer native Claude subscription login or import Claude Code tokens. Seek explicit Anthropic approval for that product path; retain the API-key adapter independently. |
| Unmodified Claude Code binary used by an end user | Anthropic describes a narrower permitted case under its commercial/product conditions: the end user signs in to the unmodified binary with their own account. | This is another agent runtime, not a drop-in credential source for Arany's Provider seam; it requires a separate architecture and security decision if considered. |

## ChatGPT plan: supported route and remaining proof

- OpenAI's [open-source overview](https://developers.openai.com/siwc/token-sharing-open-source) and [registration guide](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) describe a stable host ID, first-time `dynamic_agent_client` registration, an issued client ID bound to the user/workspace, loopback Authorization Code with PKCE, fresh `state` and nonce, ID-token verification, and distinct `chatgpt.tokens.use.direct` consent. Neither a client secret nor an OpenAI API key is needed for this path. Keep registration and credentials separate per verified account; a shared machine-wide account is not implied.
- OpenAI's [account guidance](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) requires protected local token storage, separate account registrations, serialized rotating-token refresh, and revocation on sign-out. Its [token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference) currently gives one-hour access tokens and rotating 30-day refresh tokens. Access, refresh, and retained ID tokens must stay out of browser storage, URLs, logs, analytics, and source control. Those requirements do not prove that a particular Linux keyring backend isolates an unlocked item from every other same-user process.
- The account's [public model catalog](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) is `GET https://api.openai.com/v1/models` with the same OAuth bearer token; visible rows use `visibility: "list"`, `display_name`, and `slug`. A visible model is a selection candidate, not proof that Arany's strict `Delegate | Finish`, effort, or compaction contract works for that exact model. A synthetic, explicitly consented conformance check remains necessary before Workspace disclosure.
- Plan inference uses the [public Responses endpoint](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), not ChatGPT `backend-api`; requests set `store: false` and `stream: true`. Only terminal `response.completed` is success. The [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) reject `max_output_tokens` and `max_tool_calls` and require the caller to send needed history in each HTTP input. Arany can enforce finite local time/bytes/call count and stop reading on overflow, but cannot promise a provider-enforced remote output-token or plan-usage ceiling on this route. The user must see and affirm that weaker bound before account activation, and errors must not silently fall back to a metered API key.

## Claude plan: policy boundary, not an API entitlement

- Anthropic's current [Claude Code legal and compliance guide](https://code.claude.com/docs/en/legal-and-compliance), [Agent SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart), and [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview) say third-party developers need prior approval to offer Claude.ai login or plan rate limits in their products, even when built with the Agent SDK. The legal guide forbids collecting, storing, or intermediating Claude.ai credentials or session tokens. Its exception for an end user signing into an unmodified Claude Code binary does not authorize token extraction for a separate native Provider.
- The [Claude login guidance](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account) says Anthropic may allow certain paid-subscriber third-party uses at its discretion and may charge usage credits instead of subscription limits. A [June 2026 Agent SDK billing notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) says a proposed credit change was paused and some third-party SDK usage still counts against subscription limits. **Inference:** these describe possible approved/accounting cases, not a blanket authorization for Arany. The explicit developer restriction above remains the controlling public guidance; an approval or revised official integration contract is needed before promising Claude subscription support.
- Anthropic's [subscription/API distinction](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console) says Pro/Max does not include Console/API access. Its [API authentication guide](https://platform.claude.com/docs/en/manage-claude/authentication) documents API keys, workload identity federation, and App Attest, not a general consumer-plan grant for direct Messages API calls. The existing API-key path remains separately billable and can still list/check models under its own contract.
- Anthropic also documents [`ant auth login`](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/authentication): a browser OAuth login **to Claude Console** for Anthropic's `ant` CLI, issuing a workspace-scoped API token for local development and scripting. **Inference:** this is not Claude.ai Pro/Max login, a subscription billing entitlement, or a published grant for Arany to reuse the CLI's credential; the [third-party developer restriction](https://code.claude.com/docs/en/legal-and-compliance) still applies. Its existence does not change the approval gate for a native Claude-plan Provider.

## Decision boundary for beta 1

Prioritize completing Arany's ChatGPT-plan account, consent, model-specific conformance, and first real Engine Run on Linux. Preserve the explicit remote-output-limit non-claim and do not treat a model catalog or synthetic fixture as a successful live turn. Keep Anthropic subscription as a high-priority request that needs Anthropic's written approval or a changed published policy; do not emulate Claude Code or copy its credentials while waiting. All commercial, billing, availability, and preview facts above require rechecking before public distribution because the providers can change them.
