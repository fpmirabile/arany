# Pi's Anthropic subscription route: October 2026 check

Retrieved: 2026-10-02  
Status: primary-source code and policy review; no account login, inference call, billing observation, or Anthropic approval

## What Pi implements

Pi registers a separate OAuth choice named `Anthropic (Claude Pro/Max)` alongside API-key authentication in its [Anthropic provider](https://github.com/earendil-works/pi/blob/main/packages/ai/src/providers/anthropic.ts). The provider points to `https://api.anthropic.com`, uses Pi's Anthropic Messages implementation, and supplies a bundled model table. Pi's [provider guide](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/providers.md) describes `/login`, a private `auth.json` holding the resulting credential, and `/logout`; the [Pi AI README](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md#oauth-providers) describes automatic refresh under a credential-store lock. The bundled model table is not evidence that each model is enabled for an account or compatible with Arany's strict outcome contract.

Pi's [OAuth implementation](https://github.com/earendil-works/pi/blob/main/packages/ai/src/auth/oauth/anthropic.ts) starts a browser or copy-code authorization-code flow with PKCE, state, and a local callback option. It uses an embedded client identifier, requests a `user:inference` scope among others, exchanges the code for access and refresh credentials, refreshes near expiry, and passes the access credential to the provider. This is not an independently published third-party integration grant. Pi's [Messages transport](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/anthropic-messages.ts) recognizes an OAuth token and sends a bearer-authenticated Messages request through the Anthropic SDK. For that branch it identifies itself with a `claude-cli/...` user agent, `x-app: cli`, Claude Code/OAuth beta flags, Claude Code tool names, and a system instruction identifying the assistant as Claude Code. Pi's source calls the tool-name mapping a stealth mode. Pi is **not** merely launching the unmodified Claude Code binary for this native provider path.

The existence of Pi's route proves technical implementation, not subscription-plan billing, continuing availability, or authorization for Arany. In April 2026, [Pi's own release note](https://pi.dev/news/releases/0.70.3) documented an optional extra-usage billing warning, and a [Pi issue](https://github.com/earendil-works/pi/issues/3372) recorded a successful login followed by a third-party-usage billing rejection. Neither historical observation establishes what a particular account would be charged now. Extensions that imitate Claude Code more closely are separate community software, not Pi's native route or an Anthropic authorization.

## Current Anthropic boundary

Anthropic's current [Claude Code legal and compliance guide](https://code.claude.com/docs/en/legal-and-compliance) says OAuth plan credentials are for ordinary use of its native applications, while third-party product developers should use API keys or supported cloud providers. It explicitly disallows offering Claude.ai login or routing Free/Pro/Max credentials on behalf of users, and collecting, storing, or intermediating Claude.ai tokens. Its [Agent SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart) makes prior approval the exception, including for products built on that SDK. The [Claude login guide](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account) also prohibits third-party tools that misrepresent their identity or steer traffic against subscription limits. The legal guide's narrower unmodified-Claude-Code-binary exception is not permission to import its tokens into Arany or to present Arany as Claude Code. The same guide directs questions about permitted authentication methods to [Anthropic sales](https://www.anthropic.com/contact-sales). **Inference:** limiting Arany to one local user, warning about risk, or obtaining that user's consent does not itself grant the developer approval Anthropic requires.

The same [Claude login guide](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account) says Anthropic may allow *certain* third-party tools for paid users with usage credits, at its discretion, and may charge those credits instead of subscription limits. This leaves a possible provider-approved route, not a published permission for Arany to reuse Pi's client identity or OAuth credential flow. Pi's current [Messages source](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/anthropic-messages.ts) still sends a `claude-cli/...` user agent, `x-app: cli`, Claude Code beta flags, and a system instruction identifying itself as Claude Code on its OAuth branch; these are concrete identity claims Arany must not copy without authorization.

Anthropic's [June 2026 Agent SDK billing notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) says a proposed change was paused and that Agent SDK, `claude -p`, and third-party app usage still drew from subscription limits at that time. Its mention of third-party apps can look like permission, but it describes **accounting**, whereas the current legal guide and SDK quickstart explicitly constrain which developers may offer plan login. It does not establish Pi's approval, Arany's approval, or a stable plan-price guarantee. Anthropic separately states that [a paid Claude plan does not include Console/API access](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console).

## Arany decision

Do not copy Pi's native Anthropic OAuth transport, Claude Code identity shaping, or credential import into Arany. The blocker is **provider authorization, not Rust or OAuth feasibility**; Arany's native Messages API-key adapter is a separate, potentially metered route. Treat Claude subscription as a high-priority **authorization gate**, requiring Anthropic's written approval for Arany or a new published third-party route before implementation. A user-owned, unmodified Claude Code binary is a distinct product/runtime integration, not a Provider credential shortcut; it needs its own architecture, effects, and security decision if pursued. Recheck Anthropic's current policy and billing terms before any public beta claim.
