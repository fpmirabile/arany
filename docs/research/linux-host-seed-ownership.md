# Linux host seed ownership after controller death

Research date: 2026-10-12. Code inspected at `5b3c21e`. Scope: the rationale for [Linux host seed ownership](../specs/tools.md#linux-host-seed-ownership). This is design evidence, not native Linux execution evidence.

## Failure mechanism at the inspected baseline

At the inspected baseline, `execute_inner` acquired shared admission, created a host snapshot, then started `systemd-run --user --pipe` and Bubblewrap. The seed and its resource directories were host-path read-only mounts. `Snapshot::create` and `Drop` created `/tmp/arany-tools-<uuid>`, copied selected Workspace/runtime data, and attempted deletion only in the controller destructor. `Reservation`, `Permit`, and `reserved` persisted admission ownership but did not record the seed; Linux could discard an unlocked previous-boot reservation without inspecting its files.

The operating system cannot run a Rust destructor after `SIGKILL`: Linux does not allow catching, blocking or ignoring that signal, and Rust explicitly does not guarantee destructors after process termination without unwinding. Signal handling or another destructor is therefore not a repair. [Linux signal semantics](https://man7.org/linux/man-pages/man7/signal.7.html), [Rust destructors](https://doc.rust-lang.org/reference/destructors.html).

## Options

| Design | Fit and limitation | Disposition |
| --- | --- | --- |
| Extend existing durable admission ownership with checked seed identity and publication phase | Preserves the current launch, mounts, quota and recovery owners. Requires explicit checked cleanup before capacity release, including prelaunch death and previous boots. | Selected. |
| Move storage to a systemd `RuntimeDirectory` | Manager removes its directory when the unit stops, but current seed creation happens before the unit exists. Eliminating that window requires moving copy into a supervised bootstrap or adding a preparation unit/handshake. | Reject as the immediate repair; reconsider only if a supervised preparation lifecycle is independently needed. |
| Anonymous descriptors or seed construction entirely in the mount namespace | Removes named host seed storage, but a `memfd` is one regular file, not a directory tree. Requires new transfer/bootstrap behavior, descriptor accounting and cancellation/attestation evidence. | Reject for this bounded fix. |

Systemd creates configured directories when executing the unit; `RuntimeDirectoryPreserve=no` removes them on stop. User units place these directories beneath `$XDG_RUNTIME_DIR`, unlike system units' `/run`. Merely changing the pathname or adding the property cannot transfer ownership of data already copied before launch. That last conclusion is an inference from Arany's ordering and systemd's documented lifecycle. [Systemd directory lifecycle](https://github.com/systemd/systemd/blob/main/man/systemd.exec.xml).

`memfd_create` releases anonymous storage after its last reference disappears. Bubblewrap's `--ro-bind-data FD DEST` copies a descriptor into a single read-only bind-mounted file; `--ro-bind SRC DEST` consumes a host path. Arany currently requires multiple directories and executables. [Linux memfd semantics](https://man7.org/linux/man-pages/man2/memfd_create.2.html), [Bubblewrap options](https://github.com/containers/bubblewrap/blob/main/bwrap.xml).

`systemd-run --pipe` connects standard input/output/error to the service, whose process is spawned by the manager. Its implementation explicitly sends those three descriptors. Clearing `CLOEXEC` in the controller alone does not forward arbitrary descriptors through that launch. A descriptor-based design would need an explicit supported transfer mechanism or a bootstrap stream using the existing task channel; no such mechanism has been validated for this change. [Systemd-run documentation](https://github.com/systemd/systemd/blob/main/man/systemd-run.xml), [Systemd-run descriptor publication](https://github.com/systemd/systemd/blob/main/src/run/run.c).

## Required properties of the recommended repair

1. Record ownership before private payload copying. Tie a bounded generated seed name to the reserved unit, publish its checked directory identity before copying, and represent the creation/publication gap explicitly. An unrecorded empty-directory gap must not become a payload gap. Unsupported or inconsistent records fail closed.
2. Keep liveness locking independent from replaceable metadata. Linux `flock` locks an open file description; `rename` leaves open descriptors referring to the original object. Replacing the currently leased `.unit` file would let a reaper lock the replacement while the controller still holds the old inode. Use a stable lease inode with checked metadata publication, or an equally explicit immutable publication design; do not reuse `replace_record` on a leased file. [Linux flock](https://man7.org/linux/man-pages/man2/flock.2.html), [Linux rename](https://man7.org/linux/man-pages/man2/rename.2.html).
3. Recover only after acquiring the dead owner's lease and proving the owned native unit empty. Delete through a pinned admitted parent with no-follow identity checks. Release the reservation only after checked seed absence; incomplete deletion, ambiguous identity or failed unit cleanup retains the charge. Reuse current limits and error owners instead of adding a daemon or generic cleanup framework.
4. Treat a changed boot ID as evidence that old processes ended, not that files vanished. FHS recommends clearing `/tmp` on boot but expressly does not require it. Recovery must still prove seed absence or perform checked deletion. [FHS `/tmp`](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/ch03s18.html).
5. Separate recoverable residue from an untracked leak. Normal completion and recovered controller death must leave no seed and no stale reservation. During disk faults, unavailable managers or identity conflicts, preserve bounded tracked ownership and fail closed; do not claim immediate deletion. Recovery needs a later live Arany invocation unless another existing owner is explicitly assigned the work. Deletion is not secure erasure of storage media.
6. Do not delete existing unrecorded `/tmp/arany-tools-*` roots by prefix. Their names alone cannot establish ownership or original inode identity; no new recovery format retroactively supplies that proof. Manual removal requires checked current-object identities, explicit user authority over those objects and established native inactivity, not automatic legacy deletion or migration. The [maintenance procedure](../tools.md#historical-linux-seed-maintenance) selects exact current objects; it does not manufacture missing historical provenance.

## Evidence required before closure

Exercise the existing Guard/admission interface with real Linux controller `SIGKILL` at empty creation, identity publication, partial copy, launch, execution and cleanup boundaries. Cover normal success, cancellation, copy failure, manager failure, retained charge after failed deletion, identity replacement/symlink rejection, concurrent controllers/reapers, and previous-boot records with present directories. Assert seed absence and capacity recovery together; assert unrelated canaries survive every rejection. Preserve macOS admission behavior with its existing tests. Current research establishes the design constraints only; it does not establish platform support or a successful implementation.
