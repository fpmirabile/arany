# Arany account setup

The chat input stays above the bottom status row. Long text wraps visually into up to four visible rows without adding newlines to your message. When some rows are hidden, the heading shows the visible visual-row range, or the caret row and total at narrow widths. `Ctrl+O` inserts an explicit newline; Left/Right edit across wrapped rows, while Up/Down move between explicit lines. Enter submits when idle and retains your task draft while a Run is active; the lower rule names that action and shows Ctrl+O where space permits, including without color. Closing a selector or resizing keeps the same editable text and caret.

In the inline chat, press `Ctrl+K` and choose Setup to configure an account while keeping your draft. When no Provider is selected, Setup is already focused. `/setup` opens the same wizard. A task rejected before account or model selection remains editable; errors and important notices appear in the chat, while closing a selector returns to the same text and caret. This local feedback is not saved in Session Events or sent to a Provider. The [next steps](../NEXT_STEPS.md) checklist separates final manual/live beta 1 checks from beta 2 and broader release work.

To change reasoning effort while idle, use `/effort`, or `Ctrl+K` → Effort to keep a draft in place. The picker focuses the current value; use Up/Down or Tab and Enter, or type a visible choice name in screen-reader mode. Escape or Ctrl+C closes it without changing your selection or draft. Reviewed native models show their supported levels and provider default; custom profiles show their declared levels and provider default. ChatGPT and unreviewed native models require an explicit checked level. Opening the picker makes no inference call. If the selected tuple lacks current compatibility evidence, it offers a complete Provider/model/effort/account-source review, then a separate cost choice focused on Back. Only `Accept cost` starts synthetic calls; a checked tuple needs no new inference. Declining, interrupting or failing leaves the previous effort unchanged, reports the outcome in chat, and preserves your draft and caret. A failed or interrupted started check may still consume usage. `/effort LEVEL` and `/effort default` retain their non-inference argument forms; ChatGPT has no implicit default. During a Run, `/effort` reports the pinned value instead of opening a selector.

After a failed or cancelled Run is confirmed from saved Events, the inline chat explains that no answer was committed. When a failed AgentRun has a recorded cause, the chat and `/agents` distinguish an unavailable Provider, rejected request, incompatible response, output limit, timeout, or internal task failure. These are safe outcome categories, not an exact upstream HTTP error or billing diagnosis. Your in-flight draft and caret remain editable, with a separate retained-draft status cue. Arany does not retry automatically or display the upstream error body. The screen-reader presentation keeps its labeled receipt and append-only notices.

Use `arany show --output text SESSION_ID` to inspect a Session's saved Events, or replace the ID with a receipt's `RUN_ID` to inspect only that Run. `--output jsonl` exports the same selected facts as one JSON object per line. Run inspection validates the complete parent history first, also works for failed or interrupted work, and neither starts a Provider call nor changes saved State. A missing or ambiguous ID fails without output.

On Linux, Arany uses the cross-desktop Secret Service interface, not the GNOME desktop. Any compatible implementation may provide the credential store; for a new unpinned account, an unavailable store leads to a separately confirmed private-file choice.

Keyring calls run in a short-lived same-binary helper with bounded private pipes. Arany terminates and reaps it after five seconds if the OS store does not respond. A timeout during a write does not prove the store rejected the request; the keyring backend remains pinned and Arany reports an uncertain failure rather than claiming rollback.

Run `arany` in a terminal to open a new attached Session. If both an API account and a ChatGPT account are saved, Arany asks which billing route to use on every new start before loading either credential; cancelling creates no Session, and an unavailable chosen account never falls back to the other route. With only one saved access method, Arany uses it. When neither exists, it still opens the normal chat input and immediately shows `/setup` guidance; submitting a task shows `Use /setup to choose an account` and starts no Run. Type `/setup` to choose an access method inside that Session. Native API-key setup includes Provider, model, and reasoning effort; ChatGPT setup selects or connects an account, lists its visible models, asks for an effort, and offers a separate plan-consuming compatibility check. Use `arany --setup` to open the same wizard before creating a new Session. Escape or Ctrl+C before saving an account closes `/setup` without changing Session defaults and cancels `--setup` without creating a Session. After a ChatGPT account is saved, cancelling model selection keeps that account selected but leaves model and effort unset. Inline choices use Up/Down or Tab and Enter, while linear/screen-reader choices accept their visible names. Only the API-key field hides typed input.

A positional task such as `arany "Your task"` requires a selected Provider and model at startup. Without a configured selection, Arany exits with local setup guidance before creating a Session. Open `arany`, choose `/setup`, model and effort, then submit your task in chat. A fork starts with unselected defaults rather than inheriting the source's billing route; starting it with a positional task requires explicit Provider/model flags. Resume and continue retain their saved-default behavior.

If a connected ChatGPT account is already selected, choosing `ChatGPT plan` in `/setup` or `--setup` offers `Use saved`, `Reconnect`, and `Connect new`. `Use saved` skips browser login; when several accounts are saved, it shows their short IDs with `*` marking the current one. Choosing another validates its consented credential and changes the selected OS-user account before loading its model catalog. Cancelling that account picker changes nothing; cancelling later leaves a switched account selected with no runnable model or effort until an exact check succeeds. `Reconnect` signs in again to the currently selected account, useful after expired consent, an unusable refresh token, or uncertain credential storage. It repeats the warning and typed consent, then opens the official browser account selector without placing an old token in its URL; choose the same account. A different signed identity is rejected, and the original account UUID, storage backend, and selected client must still match when the new token is saved. `Connect new` starts a separate sign-in. Cancelling or declining before a successful model check when reusing the current account leaves existing Session defaults unchanged; cancelling after a newly connected or reconnected account keeps that account selected without a runnable model. A malformed saved account index fails closed instead of being treated as a missing account.

Run `arany provider logout chatgpt` to disconnect the selected OS-user ChatGPT account. Arany blocks new account use before attempting refresh-token revocation, then removes its local token and model checks while retaining its registration for `Reconnect`. A successful remote revocation is reported only when confirmed; otherwise the command exits with a warning to disconnect the app in ChatGPT Settings. If the OS credential store cannot confirm deletion, Arany keeps the account blocked and warns that a token may remain there. Logout does not erase filesystem backups or cancel a Provider request already in flight. After logout, bare `arany` opens an unconfigured Session when no other access method is available; `/setup` offers `Reconnect` or `Connect new`, plus another saved account when one is connected. The command neither reads an API key nor switches billing routes.

If a refresh response identifies an unusable refresh token, Arany disconnects that account and removes its local token and model checks; use `/setup` or `arany --setup` to reconnect. A temporary network or server failure instead preserves the saved credential for a later retry. If keyring deletion cannot be confirmed, account use stays blocked and Arany tells you to retry `arany provider logout chatgpt` after checking the OS credential store. Neither file replacement nor keyring deletion guarantees secure erasure of backups.

The API key is entered with terminal echo disabled. Arany prefers the operating system's credential store: Keychain Services on macOS or Secret Service on Linux. If no keyring backend is pinned and that store is unavailable, setup asks you to accept a private-file fallback before you enter the key. The file is plaintext under a user-owned `0700` State directory with a `0600` account file; these permissions restrict ordinary other-user access but do not encrypt the key or protect it from another process using your OS account, an administrator, or a device backup. If the keyring is locked or already pinned for the saved account, Arany reports an error instead of silently switching to the file. A file-backed account remains on that backend even if the keyring later becomes available; migration is not automatic. Arany does not write the key to its SQLite Session history, shell arguments, process environment, or telemetry. On Linux, only a single local Unix D-Bus session address is accepted for keyring access; executable and remote transports are rejected. Separate Session history is not encrypted, and a Linux Secret Service backend may allow another same-user client to read an unlocked item. The [Linux client-isolation finding](./security/findings/linux-secret-service-client-isolation.md) remains open.

On Linux, account replacement holds a private, empty lock under the effective OS user's passwd home at `.local/state/arany`, independent of Session `--state-dir`, `HOME`, and `XDG_STATE_HOME`. The account root contains a versioned backend marker without a key for keyring-backed accounts, or the bounded private record for a file-backed account. An older record under an environment-selected StateRoot is validated and moved to this stable root before account use; if both roots contain different accounts, Arany reports a conflict and changes neither. The old record is replaced with a marker after a durable copy, not securely erased from the underlying disk. Another Arany process using the stable root reports a busy error instead of writing concurrently. This does not coordinate older Arany versions or prevent same-user processes from accessing an unlocked keyring item or file. The lock contains no key or token; a failed or interrupted keyring write can still have an uncertain outcome and must not be described as rolled back. A synthetic native two-process replacement check has passed; full isolated product setup and cross-user proof remain pending. macOS continues to use its default account root until its later native review.

The setup picker lists every model visible to the selected API account. Reviewed models offer their supported efforts. For another visible model, choose an explicit effort, then separately accept a potentially billable synthetic check: up to three inference calls with at most 3,072 remote output tokens in total, plus bounded input and catalog usage. The check uses no Workspace content. Declining returns to the same model row; cancelling or failing the check saves no key or selected defaults. A canceled request may already have incurred Provider usage. A successful check is bound to the new saved-account UUID and expires within 24 hours; an expired or failed check cannot authorize a later Run. An empty private StateRoot may remain after a failed or canceled check.

In an attached Session, `/models` lists every visible model and can set an unreviewed model ID for the next Run; it cannot make that model runnable by itself. In the inline browser, type to filter model IDs, use Backspace to edit, navigate with arrow keys, and press Enter to select; Escape closes it. Linear/screen-reader mode keeps numbered pages. Use bare `/effort` to choose a level and, when required, review and accept its compatibility check inside chat. The separate `arany provider check` command remains available for an environment-backed `exec` Run or a saved-account Run; after checking there, typed `/effort LEVEL` selects the checked level without inference. `/model MODEL` is also available if you know the ID. One default native API account can be saved at a time; replacing it changes its account ID, so older Sessions pinned to the previous account will not silently use the new key. Start a new Session or select an explicit environment-backed Provider for those Sessions.

For headless `exec` with native API-key Providers, custom profiles, or attached native use with explicit Provider flags, set the selected credential in its named environment variable (`OPENAI_API_KEY` or `ANTHROPIC_API_KEY`) and pass a Provider and model. For example:

```sh
arany exec --provider openai --model gpt-5.4 --output text "Your task"
```

`exec` never prompts or reads the saved default native API account. Explicit `--provider chatgpt` instead reads only the selected, checked OS-user ChatGPT account; it never falls back to `OPENAI_API_KEY`. `arany provider models openai` uses the explicit environment key; add `--saved-account` to list the current saved API account instead. `/models` inside a Session uses that Session's pinned account when present. After consenting to and connecting a ChatGPT account, run `arany provider models chatgpt` to list every model visible to the selected OS-user account. It may refresh a near-expiry token; it does not read `OPENAI_API_KEY` or any Workspace content. Its display names are escaped for terminal safety. A listed model still requires an explicit check before a Run.

To check one ChatGPT model and effort, first review its name in that catalog, then run:

```sh
arany provider check chatgpt MODEL --effort high --accept-cost
```

This uses only the selected ChatGPT account, makes up to three synthetic, plan-consuming inference calls, and sends no Workspace content. Each call accepts at most 1,024 reported output tokens locally, under a 180-second aggregate probe deadline; OpenAI does not accept a remote output-token cap on this route, so actual generation or plan usage is not bounded by that local number. A failed or cancelled check cannot guarantee no usage already occurred. Successful exact account/model/effort evidence lasts at most 24 hours and is rechecked with the pinned account before a Run reads Workspace input. There is no API-key fallback, `--state-dir`, or `--saved-account` for ChatGPT checks; no paid check has been run during development.

For a checked headless Run, select the same model and effort explicitly:

```sh
arany exec --provider chatgpt --model MODEL --effort high "Your task"
```

If you completed the model check inside ChatGPT setup, its model and effort are selected for the attached Session. If you skipped or cancelled it, use `/models` or `/model MODEL`, then bare `/effort` to choose a level and accept the separate check inside chat. Alternatively, use the explicit check command above, then typed `/effort high`. Both cost choices default to Back; accepting starts up to three synthetic plan-consuming calls with no remote output-token cap. Escape after the account has been saved preserves an account-only Session, not a checked model. Opening a Session with the selected ChatGPT account reads its local account ID but does not refresh a token or contact the keyring; listing models, checking compatibility, and starting a Run still require a valid consent-matched token. Attached paths reject a changed selected account before loading or renewing its token, and check publication revalidates the identity. ChatGPT Run and compaction receipts identify the plan route and warn that output is capped only on local acceptance. The account UUID and opaque evidence fingerprint are recorded for replay; neither tokens nor the consent text enter Session history. A real account login, paid check, and live Run remain unverified.

With the explicitly accepted private-file ChatGPT fallback, the bounded account index may contain several accounts' tokens in one plaintext file. Opening that index parses the whole protected record inside Arany, even though only the selected account may be used for a catalog, check, or Run. The mixed-access startup choice avoids reading the separate API-key record when ChatGPT is chosen, or the ChatGPT index when API is chosen; it does not isolate private-file tokens within the chosen index from Arany's own process memory.

For a model outside the reviewed table, use the same selected environment key for the explicit check and subsequent `exec` Run:

```sh
arany provider check openai MODEL --effort high --accept-cost
arany exec --provider openai --model MODEL --effort high "Your task"
```

After explicit cost consent and selection validation, the check creates a private StateRoot if needed and confirms that the model appears in the selected account's catalog. It can incur up to three inference calls with a total remote output cap of 3,072 tokens, plus bounded catalog and input usage; pricing varies by model. It sends only synthetic text and no Workspace content. Successful evidence lasts at most 24 hours and is tied to the exact Provider, model, effort, API key, and credential source. Listing a model does not check or authorize it. A failed or expired check cannot authorize a Run; a saved account cannot reuse evidence created with an environment key, even if the key text matches. Paid live Provider conformance remains a beta release gate.

To check the current saved API account instead, run `arany provider check openai MODEL --effort high --saved-account --accept-cost`. This creates evidence bound to that account's UUID. In its attached Session, select `/model MODEL` and `/effort high` before submitting work. Arany rechecks the exact account, key, model, effort, and evidence before reading Workspace input. A replacement account needs its own check, even if its key text is unchanged. No paid native check has been run in the beta environment yet; live support remains unverified.

The selected saved API account's UUID is recorded with each Run and can be inspected in JSONL history; the API key is never recorded there. Replacing the saved account leaves older Sessions unable to use their previous account selection.

For a new or reconnected ChatGPT account, setup signs in through the official browser OAuth flow. Before opening a loopback listener or browser, Arany shows the complete warning that local time/read limits cannot guarantee a remote output-token or plan-usage cap. It also warns about the selected storage backend: an unlocked Linux Secret Service item may be readable by another app running as your OS user, while a private fallback file is not encrypted. Read every page and type exactly `I ACCEPT` to proceed; resizing the inline terminal restarts the warning. Arany prefers the OS keyring for a new account and offers the file only after an explicit choice when that backend is unavailable; reconnect keeps the saved backend and never silently migrates it. A locked keyring must be unlocked rather than silently treated as absent. A verified account is saved in the OS-user account root, separately from API-key accounts and SQLite Sessions. Setup then offers model/effort selection and an explicit synthetic check; a successful check creates or updates a Session with the checked tuple. Cancelling or declining after a new, switched, or reconnected account leaves it selected without a runnable tuple. A catalog or check error has the same account-only result and reports a retry path. A failed reuse of the current account instead leaves existing Session defaults unchanged. Reusing an account does not reauthorize a broken login; use `Reconnect` for reauthorization. No route falls back to API-key billing. A ChatGPT inference request rejected with HTTP 4xx reports a rejected Provider call; HTTP 5xx reports unavailable. Arany does not display the upstream error body or retry automatically. A live login, complete keyring lifecycle, paid subscription conformance, and a real Run remain unverified. Anthropic consumer subscriptions are not supported.

When you are ready to run the separate live ChatGPT beta gate on Linux, first connect an account with `cargo run --release -- --setup`. Decline setup's optional cost check to avoid up to three additional inference calls. Inspect visible models with `cargo run --release -- provider models chatgpt`, then replace `MODEL_FROM_CATALOG` and `EFFORT` below with the exact model and reasoning effort you want to test:

```sh
ARANY_LIVE_CONFORMANCE=1 ARANY_LIVE_CHATGPT=1 ARANY_LIVE_CHATGPT_MODEL=MODEL_FROM_CATALOG ARANY_LIVE_CHATGPT_EFFORT=EFFORT cargo test --release --offline --locked --test session_run live::chatgpt_plan_direct_turn_replays_exact_events -- --ignored --exact
```

This explicit gate uses the selected OS-user ChatGPT account, makes one synthetic compatibility check of up to three calls and one direct Engine Run, and strictly replays its temporary Session. It can refresh the saved token and consume plan usage; the local read/time limits do not cap remote generation or usage under the [current ChatGPT-plan preview rules](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). It does not read an API key or require a token in the command. Do not run it until you accept that usage and have selected the intended account; it has not been run against a real account here.
