# Large draft text attachments

## Metadata

- Status: `Draft`
- Owner: Fernando Mirabile
- Last updated: `2026-10-22`

## Outcome and scope

Users can compose, inspect and submit large text as collapsed attachments without losing its content at submission, interruption or Session resume. This is the input half of [Daily use first item 5](../../NEXT_STEPS.md#daily-use-first) (`NEXT_STEPS.md:22`); [attached-turn Goal defaults](../attached-turn-defaults/README.md) is independently shippable and is not a dependency. The split follows [PLANNING.md:8](../PLANNING.md).

Here, **text attachment means a composer representation backed by text that is committed and sent inline**, as in the reviewed peers. It does not mean a file upload, a generated Workspace file, a lazy Tool Read, or a new persistent artifact service. Proposed maximum expanded text is the Engine's existing 64 KiB per message. Unsubmitted draft recovery across process exit is not added; submitted content survives through canonical Session history.

Inference: all three peers separate compact composer presentation from full inline model content. Reusing Arany's canonical text is sufficient; a file cache would add retention, path admission and missing-content failures without increasing the existing model-input allowance. Arany intentionally rejects an incomplete attachment instead of reproducing Claude's missing-cache omission behavior, because accepted content and strict replay must agree.

## Contract and scenarios

- Owning specs: [Terminal](../../docs/specs/terminal.md#paste-and-attachments) owns collapse/edit/preview, bounds, clipboard and busy drafts; [Execution](../../docs/specs/execution.md#admission-persistence-and-recovery) owns acceptance ordering and the existing 64-KiB message ceiling; [Session](../../docs/specs/session.md#context-and-compaction) owns history, rewind and context/compaction. Update these owners only when their slice lands. Provider wire format and image limits stay with their existing contracts.
- Success: paste 9 KiB with surrounding typed text, inspect its complete inert content, submit once, and observe the complete normalized text in committed `MessageAccepted` and the Provider request. Resume/fork after process exit uses those committed bytes, even with clipboard access unavailable. A literal string resembling a placeholder never resolves to another payload. Multi-paste order is preserved.
- Rejection: expanded text at 65,537 bytes, a seventeenth attachment, invalid UTF-8/controls, context/request overflow or full Store rejects without partial insertion or disclosure. A rejected submit retains the entire local draft. Selection, command parsing and file mentions cannot activate syntax contained inside an attachment. An attachment-only draft is a text objective, never an empty task or local command.
- Interruption/recovery: late clipboard results are discarded after ownership changes; paste during work never starts another Run. Large drafts cannot bypass the separate 8-KiB primary/child steering quotas and remain retained when refused. Cancellation before acceptance retains the draft; a lost acceptance acknowledgment reports uncertainty and must not auto-resubmit. After committed acceptance, reopen/replay reconstructs content without reading a cache/clipboard/Workspace or executing effects. Unsent drafts stay process-local, including through resize/suspend within that process.
- Evidence owners: [composer](../../crates/arany-cli/src/terminal/composer.rs), [raw decoder](../../crates/arany-cli/src/terminal/input/raw.rs), [clipboard](../../crates/arany-cli/src/terminal/clipboard.rs), [frames](../../crates/arany-cli/src/terminal/view/tests.rs), [active terminal](../../crates/arany-cli/tests/session_run/active_terminal.rs), [macOS terminal](../../crates/arany-cli/tests/session_run/active_terminal_macos.rs), [rewind journeys](../../crates/arany-cli/tests/session_run/rewind.rs), [Engine journeys](../../crates/arany/tests/engine_run.rs) and [Goal compaction](../../crates/arany/tests/engine_run/goals.rs). Existing [native terminal/clipboard checks](../../NEXT_STEPS.md#terminal) retain the real emulator, clipboard and assistive-technology evidence.

## Chosen direction

- Simplest sufficient solution after Ponytail: retain ordered text spans and attachment payloads inside the existing composer; derive atomic labels from local metadata. Use Codex's **strictly more than 1,000 Unicode scalar characters** threshold for pasted blocks, with Arany's byte cap checked independently. A restored or accumulated draft above the existing 8-KiB editable allowance becomes one attachment; small ordinary typed text stays editable. This gives a precise source-backed collapse rule without conflating UTF-8 bytes, graphemes, JavaScript units or model tokens. Existing visible character counts remain grapheme-based.
- At submit, expand once in order into the ordinary `RunRequest.objective`. Labels are presentation only and are never the canonical payload. Preserve existing CRLF/CR-to-LF normalization, tabs and all admitted text; do not silently trim, sanitize away unsupported content or truncate. Preview is scrollable, inert and fully keyboard-accessible; Backspace/Delete removes an attachment atomically. Provide local expand/edit/collapse without changing byte order, and preserve the payload while it is expanded. A normal text-only command can still run; mixed attachment/local-command submissions reject locally. Parse explicit `@file`/Skill/local command syntax only from editable user syntax, never from collapsed payload contents.
- Persist complete expanded content using existing `GoalStarted.objective` and `MessageAccepted.text`. **Their acknowledged commits, then Run/Agent identity and the Provider-call reservation, precede Provider dispatch.** No separate attachment file, digest reference, upload, retention sweep or new Event version is necessary. Original paste grouping/IDs are transient: history can display or rehydrate the complete long objective as one attachment. Submitted text survives resume, while exact original chip boundaries are not promised. This is the explicit tradeoff for avoiding a new durable format.
- Use existing context/history compilation and its full-byte admission. Text attachments cost input tokens and can be summarized by ordinary compaction; collapsing the UI saves no model context. Canonical bytes remain intact. If this design requires a stored-format change during implementation, stop at the RPI gate and revise the plan with its migration step and fixture before editing that format.
- Linux/macOS impact: same composer and model text. Raise the framed/explicit clipboard text admission to the chosen 64-KiB maximum through the existing Linux clients and macOS bridge, preserving bounded cleanup and generation checks. Physical canonical-line caps remain 4,094/1,023 bytes; explicit clipboard paste and bounded accumulated draft input provide the large-input path in linear mode. Do not claim safe unframed multiline paste. Native clipboard/PTY evidence is required on both OSes before claiming interoperability; no new native dependency or `unsafe` is proposed.
- Ownership/interface: CLI owns transient span IDs, editor state and preview; Engine owns semantic message admission and durable order; Store/reducer own accepted bytes; Provider rendering owns inline wire conversion. The existing in-process `RunRequest` boundary carries text/images, not UI types or paths. Preview/edit is bounded linear work over at most 64 KiB and 16 segments. No new trait, crate, daemon or remote seam is justified. The rewind response may return the existing full admitted objective rather than dropping it at 8 KiB; caller tests own its faithful reconstruction.

## Security and resource model

Security pass triggers: changed untrusted rendering and prompt assembly, larger clipboard ingress and Session recovery behavior ([agents/security.md:32–47](../../agents/security.md#security-pass-triggers)).

Assets are private pasted text, canonical history, credentials, Workspace authority and paid input usage. Clipboard/emulator text and replayed history are attacker-controlled data. User submission authorizes disclosure to the already-admitted Provider; attachment labels/content cannot choose a path, credential, command, Skill, Tool grant or role. Local IDs are typed metadata, never parsed from attacker-authored placeholder strings. Keep all child grants intersected with the parent; there is no new child execution path. Attached payloads must not trigger `@file` discovery or widen disclosure. Use synthetic secret canaries to verify that pre-submission payloads stay out of diagnostics, telemetry and errors.

| Resource | Proposed bound and overflow behavior |
|---|---|
| Expanded primary draft and submitted objective | 64 KiB UTF-8 total, including editable text and payloads; reject the entire insertion/submission before allocation-heavy expansion or egress. Pre-normalized incoming text also has a 64-KiB cap. |
| Attachment segments | At most 16, each within the aggregate text cap; seventeenth insertion refuses without modifying the draft. |
| Transient text owners | One active draft, one held draft, one recalled draft and one pending clipboard/framed record, each at most 64 KiB: at most 256 KiB retained payload across these slots, plus bounded rendering/normalization copies. Merge overflow retains held and newer drafts separately for explicit recovery; never silently discards either. |
| Editable rendering / preview | Existing four-row composer viewport; one scrollable preview over the bounded payload; existing terminal geometry, row escaping and input backlog limits. No whole-payload log/notice. |
| Child drafts / steering / images | Existing eight child drafts × 8 KiB, per-Run 8-KiB steering quotas, and four PNGs / 192 KiB per image collection; none is enlarged by a text chip. |
| Clipboard/input lifecycle | Existing one clipboard worker, two-second read and one-second cleanup deadlines; framed-record ten-second deadline and whole-record drain on overflow. No automatic retry or extra process. |
| Canonical and model storage | Existing 400-KiB GoalStarted, 656-KiB MessageAccepted, 10,000-Event lineage and aggregate Store admission; unchanged context/encoded request/compaction bounds. Whole-message rejection, not omitted attachment bytes. No independent disk cache or orphan artifact quota. |

Startup ordering, private-State admission and Provider consent stay unchanged. Reopening cannot reread local clipboard or activate pasted instructions. Strict replay is data-only. An unknown effect or acceptance outcome remains unknown, with no automatic retry. There is no encryption-at-rest claim, no protection against terminal loss before bytes reach Arany, and no claim that a collapsed text block has lower cost. These limits and non-claims belong in the implementation PR security notes with the adversarial evidence.

## Risks and mitigations

- A pretty placeholder hides oversized, missing or reordered content → expand under the aggregate bound and compare exact canonical/model bytes; reject missing IDs and malformed spans.
- Hidden command/mention text causes disclosure → parse local controls only from explicit editable syntax; attachment-only submission is always ordinary text. Add hostile slash, `@`, fake marker and terminal-control cases.
- New input cap bypasses other owners → test clipboard/framed input, busy/held/recall state, startup prompt, rewind, steering and child input individually through their real boundaries.
- A 64-KiB message still exceeds encoded context or compaction capacity → preserve current whole-request rejection with retained draft; do not raise ceilings or truncate to make a test pass.
- Original chip identity is lost after restart → document that canonical content, not paste grouping, is durable; deterministic whole-objective reconstruction avoids a second storage authority.

## Exit criteria

- **Research gate:** current input limits, rejection rather than truncation, durable order, recovery gaps and all three peers have file:line/URL evidence. Unknown peer guarantees and native interoperability are explicitly bounded, not assumptions.
- **Plan gate:** resolve both owner questions before implementation; this plan remains Draft until the chosen bounds and persistence contract are accepted. A requirement for stable durable chip identity, larger canonical messages or unsent crash recovery reopens Research and changes the design.
- **Implement gate per slice:** exact-byte success and meaningful overflow, hostile-input, cancellation, Store-failure, replay/resume and platform adapter tests pass; security review includes assets/authority/egress/limits. Any contradiction reopens the prior RPI phase. Full required CI must pass for code handoff; unavailable native/live/assistive checks are recorded once under the existing NEXT_STEPS evidence owner.
- The owning specs contain accepted behavior and recovery after their slices land; no speculative contract changes are made by this task. Close the completed plan and index row under the [planning lifecycle](../README.md#lifecycle).
