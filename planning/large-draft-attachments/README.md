# Large draft attachments

## Metadata

- Status: `In progress`
- Owner: Fernando Mirabile
- Last updated: `2026-10-22`

## Outcome and scope

Users can compose, inspect, remove and submit text and image attachments as compact draft chips, with complete accepted content available on Session resume. This is one draft-attachment capability delivered in text and image vertical slices; existing image transport/persistence is reused. It delivers [Daily use first item 3](../../NEXT_STEPS.md#daily-use-first). Shared [Goal defaults](../../docs/specs/goals.md#lifecycle-budgets-and-recovery) already apply independently.

Text chips expand inline into the ordinary objective; image chips refer to the existing typed PNG payload. No upload service, Workspace artifact or paste cache is needed. The recorded continuation decision below requires a minimal Goal payload migration. Submitted content is durable; unsubmitted drafts remain process-local, as in the selected Codex behavior.

Only actual paste ingress uses the collapse threshold; typing and restored canonical text do not acquire an arbitrary 8-KiB chip transition.

The shared behavior is compact presentation backed by full model content, removable image chips and recoverable submitted messages. The peers disagree on text thresholds and cache strategy: choose Codex's complete threshold/label rule and submitted-content persistence, not a new hybrid. No further peer tie-breaker is needed. Arany's canonical journal replaces peer temporary-file/cache storage; accepted bytes must survive independently of a path or cache, and missing content cannot be silently omitted under journal-first durability and strict replay.

## Contract and scenarios

- Owners: [Terminal](../../docs/specs/terminal.md#paste-and-attachments) owns chips, input, keyboard access, bounds and busy drafts; [Execution](../../docs/specs/execution.md#admission-persistence-and-recovery) owns acceptance ordering and journal bounds; [Session](../../docs/specs/session.md#context-and-compaction) owns recall, rewind and context. [Provider](../../docs/specs/provider.md) retains its current image wire/capability admission. Update each contract when its slice lands.
- Text success: paste 9 KiB between typed spans, inspect full inert content, submit once, and observe exact normalized bytes in `MessageAccepted` and the Provider request. Multiple pastes retain order; literal marker-looking text never resolves to a payload. Resume/fork works without clipboard/cache access.
- Image success: clipboard PNG or a pasted/dragged admitted PNG path creates `[Image #N]`; keyboard selection/removal renumbers remaining chips. Mixed and image-only submission preserve image bytes/order in canonical history and Provider input. Delete the source file after acceptance: resume, fork and conversation rewind still recover the canonical images. Human history remains metadata-only.
- Rejection: 65,537 expanded text bytes, a fifth image, image byte/dimension overflow, unsupported image format, invalid controls/UTF-8, unsafe path, context/request overflow or full Store rejects atomically. Retain complete local drafts; never send a truncated text, missing image or chip label as its payload. Custom routes and child drafts retain existing image refusal.
- Lifecycle: paste during work never submits; loading blocks Enter; stale clipboard/path-read results are discarded after ownership change. Large text cannot bypass 8-KiB steering/child limits. Refused held/newer merges preserve both drafts. Cancellation before acceptance retains input; lost acceptance acknowledgment reports uncertainty and never auto-resubmits. Strict replay reads canonical bytes and performs no clipboard, attachment-source file, Provider or effect call.
- Evidence owners: [composer](../../crates/arany-cli/src/terminal/composer.rs), [raw decoder](../../crates/arany-cli/src/terminal/input/raw.rs), [clipboard](../../crates/arany-cli/src/terminal/clipboard.rs), [frames](../../crates/arany-cli/src/terminal/view/tests.rs), [active terminal](../../crates/arany-cli/tests/session_run/active_terminal.rs), [macOS terminal](../../crates/arany-cli/tests/session_run/active_terminal_macos.rs), [rewind journeys](../../crates/arany-cli/tests/session_run/rewind.rs), [Workspace input races](../../crates/arany/src/session/input/race_tests.rs), [image validation](../../crates/arany/src/provider/image.rs), [Engine journeys](../../crates/arany/tests/engine_run.rs) and [Goal compaction](../../crates/arany/tests/engine_run/goals.rs). ## Chosen direction

- **Decided 2026-10-22 (lead; Claude/Codex history parity):** `/goal continue` must never reparse stored objectives for `@` mentions. Reuse the original admitted include list. Existing GoalStarted records and plan contracts do not contain it, so slice 1 records required nullable `include_paths` in GoalStarted v8 with a v7 migration and canonical fixture. Migration records unknown, never guessed paths; unknown refuses continuation with explicit new-submission guidance. Ordinary existing-Goal Runs also reuse the recorded list rather than replacement request paths. This supersedes the initial no-stored-format-change assumption. Rationale lives in [D-24](../../docs/research/next-step-decision-register.md#d-24--pasted-text-and-continuation-inputs); behavior lives in Goals/Terminal/Execution.

- **Decided 2026-10-22 (peer parity: Codex threshold and labels above):** pasted blocks collapse at **strictly more than 1,000 Unicode scalar characters**, after CRLF/CR-to-LF normalization, into `[Pasted Content N chars]`; same-size duplicates append ` #2`, ` #3` outside the bracket using the current highest suffix plus one. Reuse the base when no same-size paste remains. Claude's >800-character OR >3-line rule and `[Pasted text #N +M lines]` are recorded alternatives, not additional triggers. No line-based Arany threshold.
- **Decided 2026-10-22 (owner; peer parity with Codex):** remove the invented 16-text-attachment quota. There is no separate count setting; nonempty payloads and all editable text share the existing 65,536-byte objective cap. Remove empty elements and coalesce adjacent editable spans, so finite bytes also bound metadata. Codex accepts up to 1,048,576 characters; Arany's smaller cap is required by existing journal/context admission, not a new product limit ([Execution persistence bounds](../../docs/specs/execution.md#persistence-bounds), [Session context](../../docs/specs/session.md#context-and-compaction)).
- **Decided 2026-10-22 (peer parity: Codex history, backtrack and portable media above):** persist expanded text and PNG bytes through existing `GoalStarted.objective` and `MessageAccepted` before dispatch. Unsent drafts and original text-chip boundaries stay process-local; canonical text imports remain editable regardless of length, while conversation rewind restores images as numbered chips. Local recall may retain original chip metadata. Reuse Session history rather than copying Claude's expiring paste cache. No unsent crash recovery, stable cross-session paste IDs or legacy-record preservation work.
- **Decided 2026-10-22 (owner; peer parity: Claude/Codex image chips above):** image attachments are the third vertical slice of this same composer feature. Reuse `ImageAttachment`, clipboard transport, provider encoding and journal storage. Add atomic `[Image #N]` chips at insertion positions, keyboard selection/removal and image restoration on conversation rewind. Keep canonical text plus ordered image payloads; chip positions are transient UI metadata, not a new wire format.
- **Decided 2026-10-22 (Arany guarantee constraint):** keep four PNGs/192 KiB, current PNG dimensions and text-only custom routes. Unlike broader peer image loading and Codex's 32-MiB transport allowance, the existing validated PNG type and Event/context bounds provide bounded admission without a new decoder or raster allocation. Unsupported formats fail visibly; no conversion dependency is introduced. Image inspection uses existing inert metadata, not an unbounded raster preview.
- Simplest sufficient solution after Ponytail: extend the existing composer with ordered text elements and local attachment metadata. Expand text once into `RunRequest.objective`; pass existing `RunRequest.images`. Labels are never parsed as payload identities. Reuse keyboard navigation and scrollable detail presentation for text inspection; Delete/Backspace removes whole elements. Claude and Codex offer external prompt editing ([Claude controls](https://code.claude.com/docs/en/interactive-mode#general-controls), [Codex edit expansion](https://github.com/openai/codex/blob/342ed69a174c206c1de52a59491b131e0753cfa5/codex-rs/tui/src/bottom_pane/chat_composer.rs#L1478-L1491)); Arany uses its inert in-process detail surface because an external editor would need a separately admitted Guard process under per-effect isolation. Do not add a second editor or expand/edit/collapse mode. Closing detail restores draft focus/caret; linear mode prints labeled inert content without cursor rewriting, and no-color/narrow layouts retain chip identity and selection. A normal editable command works as today; mixed local-command/attachment input rejects locally, and hidden payload syntax never invokes commands, Skills or `@file` discovery.
- File ingress: recognize an explicit pasted/dragged single image path using peer-style quoted/escaped path parsing, with no shell evaluation. Resolve only within the already-admitted Workspace root using its pinned directory identity and no-follow/single-link regular-file checks; accept an absolute spelling only when it maps into that root. Snapshot and validate bytes once before publishing the chip. Paths outside the admitted root fail with guidance to use explicit clipboard image input; peer ambient-path loading would violate per-effect directory isolation. Payload text, restored history and model output never trigger path reads. One bounded, cancellable read uses the existing input owner; no generic loader framework or new grant.
- Ownership/interface: CLI owns cursor, chips, generation checks and draft retention; the existing Workspace input owner admits image byte snapshots; Engine admits semantic text/images and commits them; Store/reducer owns durable bytes; Provider adapters own existing wire conversion. Conversation rewind returns the existing complete admitted text/images instead of omitting them. These are in-process boundaries, with no terminal or filesystem-path types entering Engine policy.
- Linux/macOS: same semantics. Raise framed/clipboard/startup text admission to 64 KiB through existing adapters. Canonical physical-line bounds stay 4,094/1,023 bytes; safe unframed multiline paste is not claimed. Clipboard and path operations retain cleanup/cancellation and platform admission checks. No new OS dependency or `unsafe`; native interoperability requires native evidence.

## Security and resource model

The [security pass](../../agents/security.md#security-pass-triggers) covers larger clipboard ingress, untrusted rendering, file input, prompt assembly and recovery. Assets are private text/images, canonical history, Workspace authority, credentials and paid usage. Clipboard, terminal input, image bytes/paths and replayed history are untrusted. Explicit input selects data under an existing directory capability; it cannot widen roots, grants, roles or Provider destinations. Submission authorizes disclosure only to the admitted Provider. File bytes are immutable snapshots, not later path dereferences. Startup State/Provider admission stays ahead of Workspace reads; descendant grants remain restricted.

| Resource | Bound and overflow |
|---|---|
| Primary text | 64 KiB UTF-8 total across editable text and payloads; same finite bound before normalization. Reject whole insertion/submission. Encoded context/request admission may reject less. |
| Text element metadata | No independent attachment-count quota. Every retained payload is nonempty, hence at most 65,536 payload elements under the byte cap; prune empty elements/coalesce editable spans. Bound preview/expansion work by the admitted bytes and elements. |
| Draft slots | One active, held, recalled and pending input, each within message text/image limits. At most 256 KiB text and 768 KiB raw image payload across those four slots, plus bounded base64/rendering copies; share immutable images where possible. Refused merges retain both drafts in existing slots and reject further conflicting input. |
| Images | Four PNGs, 192 KiB aggregate raw bytes per collection, each side ≤4,096 and area ≤4,194,304 pixels, as in the existing validator. Whole-image/whole-turn refusal; unchanged Provider aggregate history limits. |
| Rendering | Existing four-row editor viewport and bounded scrollable text detail; image metadata only. No full payload in notices, diagnostics or telemetry. |
| Input lifecycle | One pending clipboard or path read; reuse two-second read and one-second cleanup bounds and generation checks. Framed input keeps ten-second termination deadline and whole-record overflow drain. No automatic retry. |
| Steering/child input | Existing 8-KiB per-Run steering and eight child drafts ×8 KiB; child input stays text-only. |
| Canonical/model storage | Existing 400-KiB GoalStarted, 656-KiB MessageAccepted, 10,000-Event lineage, aggregate Store, context/request and compaction bounds. No separate disk cache or retention sweep; the continuation decision adds only the admitted-path list. |

Journal acknowledgment, Run identity and Provider reservation precede dispatch. A missing payload or uncertain acceptance stops continuation; replay performs no effects. Compaction may summarize text and image metadata/previous interpretation; canonical bytes remain intact and UI collapse saves no input tokens. No encryption-at-rest, unsent-crash-recovery or universal desktop-support claim. Synthetic canaries must prove pre-submission bytes stay out of diagnostics/errors/telemetry; hostile controls, fake chips and image paths cannot create authority.

## Risks and mitigations

- Hidden missing/reordered content → compare exact canonical/model text and image bytes/order; reject malformed elements without changing the draft.
- Attachment text activates local syntax or file discovery → parse only explicit editable input; hostile slash, `@`, fake marker and nested path cases stay inert.
- Path replacement or stale worker result changes disclosure → pinned no-follow snapshot and generation ownership; race/admission failures publish no chip.
- A valid individual message exceeds history/context/Store capacity → whole-request rejection with retained draft, never larger limits or omission.
- Persistent grouping confused with durable content → document transient text grouping and deterministic image numbering; test resumed content independently of original files/clipboard.
