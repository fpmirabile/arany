# Arany-owned storage report

## Metadata

- Status: `Ready` — Research and Plan gates passed; no material open question remains.
- Owner: Arany maintainer.
- Last updated: 2026-10-22.
- Delivery: Research → Plan → Implement; two vertical slices, independently implementable.

## Outcome and scope

Add `arany storage` and idle `/storage` to report disk usage attributable to Arany's known storage owners, excluding the selected main Workspace. Show aggregated sizes, counts and paths of owned locations, coverage, unavailable/partial categories and safe cleanup guidance. This serves local operational visibility; the report is shown to the user and never automatically disclosed to the model.

The report covers selected/default StateRoot, fixed account-root storage, private build caches and recorded Guard backing storage/scratch. Its worktree category explicitly reports the current absence of a product-owned registry, established below. It does not search the host for the word “arany.” Unregistered state roots, developer checkouts, externally created worktrees, shared Cargo/npm caches, installed binaries and OS-keyring storage cannot be attributed by name alone; coverage names those limitations. No deletion command, background scanner, new model Tool or general host `du`/`find` is included.

## Research

Arany baseline: `cb87fa2cdd97fbfc2af06f91ebdfcec321f90bf0`. The inspected [Codex CLI command inventory](https://github.com/openai/codex/blob/61f34c35af77777db4d77d0ea2aeb8547a6b4523/codex-rs/cli/src/main.rs#L149-L250) contains no general disk-usage report. [OpenCode's known-path uninstall preview](https://github.com/anomalyco/opencode/blob/b42c31613fdcbd220e859bea357fea48260a6c7a/packages/cli/src/commands/handlers/uninstall.ts#L23) demonstrates explicit coverage and separation of inspection from deletion; its [stats command](https://github.com/anomalyco/opencode/blob/b42c31613fdcbd220e859bea357fea48260a6c7a/packages/cli/src/commands/handlers/stats.ts#L95) reports session/token/cost statistics, not disk sizes. These bounded findings establish no shared disk-report command or schema. Arany's report uses its existing storage owners and local rendering conventions.

| Existing owner | Finding and consequence |
|---|---|
| [StateRoot](../../crates/arany/src/store/state.rs) and [credential contract](../../docs/specs/credentials.md#account-scope-and-identity) | Session storage is configurable; account storage is fixed from the effective user's OS home, independently of `HOME`/XDG and `--state-dir`. They can coincide and must be deduplicated. `StateRoot::open_existing` also validates database files, so it is not a generic “inspect storage even if history is damaged” API. Reuse private-directory admission without opening history or credentials. |
| [Private build cache](../../crates/arany/src/store/state/build_cache.rs) and [cache contract](../../docs/specs/tools.md#persistent-workspace-build-cache) | Owns committed, previous, candidate/staging and reservation/transaction records under `build-cache`; 128 identities and an 8 GiB aggregate. Pending bytes are real storage too. Existing `/cache clear [all]` uses checked ownership and busy semantics; the report must not trigger recovery or clear anything. |
| [Guard admission](../../crates/arany/src/tools/guard/admission.rs) | Owns capacity leases, Linux seed records and identity evidence. A prefix is insufficient ownership proof. Read-only inventory must not call admission/recovery, which can mutate storage. |
| [macOS storage](../../crates/arany/src/tools/guard/macos/storage.rs) and [native contract](../../docs/specs/tools.md#macos-enforcement-and-compatibility) | Workspace, scratch and cache volumes use backing images beneath `/private/tmp/arany-u-<uuid>`. Count backing images once; do not descend mounted views and count their contents again. `storage.pending`, image/root identity and boot-bound ownership records already describe uncertainty. |
| [Linux seed contract](../../docs/specs/tools.md#linux-host-seed-ownership) | `arany-tools-<uuid>` seeds belong to recorded leases. Runtime tmpfs is memory-backed and is not ordinary persistent disk allocation. Historical unrecorded candidates stay unowned; the existing [maintenance procedure](../../docs/tools.md#historical-linux-seed-maintenance) requires independent inactivity/ownership evidence. |
| [Worker architecture](../../docs/architecture/system-overview.md#2-runtime-architecture) and [worker implementation](../../crates/arany/src/tools/worker.rs) | Current worker views are private disposable images, not a persistent product-owned Git-worktree registry. `isolation: worktree` in definitions does not prove a host worktree was created. Report “no owned-worktree registry in this version,” not “all worktrees use zero bytes.” Do not invent a new registry or scan Git to populate one. |
| [Terminal contract](../../docs/specs/terminal.md#entry-modes-and-channels) | Existing local controls and deterministic noninteractive output provide the presentation pattern. [Architecture](../../docs/architecture/system-overview.md#2-runtime-architecture) keeps platform/storage mechanics in their library owners and CLI composition at the edge. |

For size semantics, [Rust 1.88.0's Unix metadata contract](https://github.com/rust-lang/rust/blob/1.88.0/library/std/src/os/unix/fs.rs) defines logical size in bytes and allocated blocks in 512-byte units. Compute allocated bytes with checked `blocks × 512`, not the filesystem I/O block size. This uses existing platform metadata support and adds no dependency.

## Contract and scenarios

[Tools](../../docs/specs/tools.md) will own storage inventory scope, attribution, bounds and cleanup non-effects; [Terminal](../../docs/specs/terminal.md) will own command/output behavior; [Credentials](../../docs/specs/credentials.md) will delimit metadata-only account-root admission. No generic read grant or exception for arbitrary StateRoot content is added.

| Scenario | Required observation | Evidence owner to extend |
|---|---|---|
| Known storage, main Workspace excluded | Report category, safe owned-location path, aggregated counts, allocated bytes, logical bytes and completeness; default/selected/account roots and nested categories are counted once. Workspace source/build contents are excluded. | Store/private-fs fixtures and [session CLI journeys](../../crates/arany-cli/tests/session_run.rs) |
| Missing state or malformed database | Report absence or independently measurable metadata without creating directories, locks, database, Session or account selection. Damaged history does not prevent safe size inspection. | Store/private-fs and fresh-process CLI fixtures |
| Live cache/Guard activity, pending attachment or stale lease | Report busy/changing/retained/unknown as applicable; never recover, detach, signal, delete, wait indefinitely or assert safe reclamation. | Build-cache and Guard admission/storage fixtures |
| Secret files, hostile names, symlink, hard link, nested mount or foreign owner | Never open payloads or credentials. Reject unsafe attribution, escape rendered paths, suppress sensitive names, and count no linked target. Aggregate owned private-file metadata without exposing individual secret names or file contents. | private-fs/Guard tests and bounded cross-output canary assertions |
| Scan or output budget exhausted | Emit a partial report with known subtotal and reason, never a complete zero or exact machine total. Cancellation emits no complete report and closes handles without cleanup mutation. | CLI observation and inventory-owner boundary tests |
| User runs `/storage` while idle | Same report and coverage as CLI, accessible in Fullscreen, Classic and linear modes, with no Provider call or insertion into model context. | Terminal/presentation tests and CLI journey |

## Chosen direction and decisions

- **Decided 2026-10-22 (owner scope):** keep storage reporting as an independent feature. No old-default compatibility work and no cleanup implementation.
- **Decided 2026-10-22 (lead default, S1):** show the user aggregated private-storage metadata only: sizes, counts and paths of Arany-owned locations, never file contents. Include secret-containing regular files only in aggregate category totals, without listing their individual names. Never automatically disclose the report to the model, journal, telemetry or MCP. A model-facing variant requires an explicit later decision. This is a lead default, not an owner approval or a generic Tool read grant.
- **Decided 2026-10-22 (peer research):** use an explicit local command and existing storage owners, following the known-path inspection precedent cited in Research. No shared peer inventory wire format was established, so do not invent a new public protocol or JSON schema. Initial output is text.
- **Decided 2026-10-22 (existing architecture):** reuse `private_fs`, StateRoot path resolution, build-cache metadata and Guard ownership parsers behind one bounded library report operation. CLI and the idle slash adapter call it; no Provider, shell, Store database open, generic model filesystem capability, new dependency, daemon, crate or pluggable inventory framework. Linux/macOS native ownership collectors justify their existing platform boundary.
- **Decided 2026-10-22 (existing ownership guarantees):** no recursive ambient search. Include only the selected Session root, default Session root and fixed account root, deduplicated by admitted identity, plus exact storage targets authenticated by existing Guard records. An explicit `--state-dir` selects another Session root; it does not silently move the account root. Do not discover other roots from conversation contents or arbitrary paths stored in untrusted files. Validate every record-derived target against its owner's compiled location and identity rules.
- **Decided 2026-10-22 (honest uncertainty):** display allocated and logical bytes separately using filesystem metadata; allocated blocks are not guaranteed reclaimable bytes, particularly for compression, sparse files, clones and snapshots. Totals are point-in-time observations, not an atomic machine snapshot. Count backing storage, not its mounted contents, and do not include capacity reservations as allocated bytes. Label Linux tmpfs separately as memory-backed, with disk allocation not applicable. Known subtotals plus unknown categories remain partial.
- **Decided 2026-10-22 (safe cleanup contract):** hints name existing `/cache clear` and `/cache clear all`, explain their Workspace/all-cache scope and busy behavior, and link the existing Guard maintenance procedure. Never generate `rm`, detach commands, secret-store deletion, recursive cleanup from prefixes, or a promise that reported bytes can be reclaimed. StateRoot history/credentials and live/uncertain Guard units receive no automatic-removal hint.
- **Decided 2026-10-22 (local-control pattern):** `arany storage` uses existing Workspace/StateRoot selection conventions and works without a Provider/account. Stdout is the bounded report; stderr carries failures; complete reports exit successfully, partial/refused reports unsuccessfully with their measured subtotal clearly labeled. `/storage` is idle-only, has no arguments and displays the same local result without creating a Run. Model guidance may suggest `/storage` but never obtain its report automatically.

The simplest solution is metadata summation under already owned directories, with typed per-category results (`complete`, `partial`, `absent`, `busy`, `unavailable`). The library owns deduplication and coverage; the CLI does not infer ownership from a filename. The report operation takes trusted resolved locations and cancellation, and returns domain values, not raw platform handles or native diagnostics. Bound traversal before allocation; checks occur between metadata operations. Blocking filesystem work stays off the terminal reactor, remains owned until it stops, and cannot publish after cancellation. As with current filesystem traversal, deadlines are cooperative and do not claim to interrupt a stalled kernel syscall.

## Security and resource model

This triggers [filesystem, disclosure and private-state security review](../../agents/security.md#security-pass-triggers). Assets are credentials, private history, ownership records, host paths and the integrity of running Guard units. File contents and names, supplied paths and storage records are untrusted until admitted. An explicit local user command authorizes only the fixed report; model/repository text cannot invoke a privileged report or choose its roots.

Open directories through existing no-follow private admission; read only bounded, nonsecret ownership records needed for attribution, never expose their contents in the report. Do not parse account records, call keyrings, read history payloads, inspect process environments or follow mount targets. Stat secret-containing regular files only for aggregate private-record sizes/counts; omit their individual names and values. Show only paths of admitted Arany-owned locations. Authenticate each root before traversing it. The selected main Workspace and nested storage overlap reject/skip before traversal, even if a user passes it as `--state-dir`.

**Decided 2026-10-22 (reuse existing resource bounds):** one inventory at a time; no queue, retry or background refresh. A 30-second aggregate cooperative deadline reuses the native inventory/recovery ceiling without invoking recovery. Root discovery keeps the current 4,096-entry native-parent cap and 64-unit/128-cache-identity caps; report traversal shares 16,384 entries, depth 32, 4 KiB paths and an 8 MiB identity/path-index cap from the build-cache owner. Native records retain their existing individual byte/schema caps. Output shares the 64 KiB Tool-result ceiling, with at most 128 detail rows; category summaries and a partial/overflow marker have reserved room. These are finite reused ceilings, not a claim that every installation fits. On any exhausted cap, stop that scan and mark the aggregate partial; do not silently select a complete-looking subset. Checked arithmetic detects byte-count overflow.

Deduplicate roots and regular-file identities within those bounds; an unexpected multiple-link private file is an unsafe record, not permission to open another path. Do not follow symlinks, cross unowned mounts or traverse the macOS mounted volumes. Metadata changes during collection make the affected category changing/partial; errors name safe categories rather than leaking native paths. Only rows attributable to known ownership enter the owned subtotal. Prefix-only candidates may produce a fixed “unattributed storage not inventoried” notice, without traversing or recommending removal.

No new Run, Tool intent or filesystem effect occurs: this is a user-local metadata view, like existing read-only inspection controls. It writes no inventory, lock, log or cache and sends nothing to a Provider or telemetry. It must not call a constructor that performs admission recovery or creates state. A model-facing variant requires an explicit later decision and its own journaled Tool disclosure design.

## Risks and mitigations

- “Everything belonging to Arany” overstates attribution → print the exact roots/categories covered and exclusions; never claim an exhaustive host scan.
- Disk images, nested categories or hard links inflate totals → count each backing object once and show category hierarchy without adding parent and child totals together.
- A read command repairs or cleans state as a side effect → use metadata-only owner entry points, and assert no changed fixture bytes/directory entries after success, failure and cancellation.
- Metadata itself exposes private history or account details → category aggregation, fixed secret bucket, no payload reads and user-local delivery under the recorded S1 lead default.

## Vertical slices

1. **Known StateRoot and cache disk report.** `arany storage` and `/storage` → metadata-only owner operation → identity deduplication/size accounting → local text report with coverage and existing cache-clear hints. Include missing/corrupt state, secrets, overlaps, sparse/hard-linked data, bounded scans, cancellation and no-mutation/no-Provider scenarios. Update Tools/Terminal/Credentials contracts in this PR. Guard storage is explicitly “not yet included” until slice 2; no machine-total claim.
2. **Recorded native Guard storage.** Extend the same report through existing Linux seed and macOS image ownership records → backing-byte accounting → live/retained/unknown labels and existing maintenance guidance. Include mounted-image non-traversal, unrecorded prefixes, stale boot, replaced roots, busy/changing records and aggregate overflow in native fixtures. Report the current absence of an owned-worktree registry explicitly; do not introduce worktree management. This PR completes the feature's declared coverage.

## Exit criteria

- Implement both vertical slices under the recorded metadata-only lead default; no owner-only decision remains.
- CLI and slash report known owned disk usage while excluding the main Workspace, with exact coverage and honest partial results; no credential/content access, Provider call, mutation, cleanup or double counting occurs.
- Existing owner fixtures plus fresh-process/terminal observations prove success and meaningful failure/cancellation paths. Native Linux/macOS evidence covers metadata allocation and image/mount accounting; document unavailable native/live dogfood checks in `NEXT_STEPS.md` during implementation, without claiming support from synthetic evidence.
