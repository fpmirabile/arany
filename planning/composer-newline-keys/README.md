## Outcome and scope

One feature: predictable, configurable newline entry in the attached composer. By default, typing `\` immediately followed by Enter replaces that backslash with a newline; distinguishable Shift+Enter inserts a newline; ordinary Enter retains its submission meaning. Existing newline bindings remain functional but leave recommended help and hints. `/settings` saves the preferred newline shortcut.

This serves the harness's input and presentation responsibility across primary and editable child drafts, Classic, Fullscreen, and canonical linear/screen-reader input. It includes terminal capability detection, truthful fallback guidance, paste containment and terminal restoration. It adds no general keymap editor, external configuration writer, new dependency, Engine policy or journal event. [Large draft attachments](../large-draft-attachments/README.md) remains a separate feature, with the composition contract below.

## Chosen direction

1. **Decided 2026-10-22: default gestures and immediate semantics (owner; [Claude parity][claude-terminal]).** Implement the requested typed `\` then ordinary Enter independent of enhanced-key support. A successful typed backslash arms one continuation at that caret; the next editing/key action must be ordinary Enter. Replace exactly that last backslash with LF, atomically, before completion or submission. Cursor movement, another non-backslash key, deletion, paste, recall, focus/owner change or draft replacement disarms it; redraw, resize and incoming output do not. A second typed backslash arms the latest one, so two backslashes followed by Enter retain one literal backslash and add LF. A pasted/restored trailing backslash does not arm it. Mid-draft typing works at the caret. Shift+Enter inserts LF without consuming a preceding backslash. This specifies the owner's immediacy requirement; it is not a claim about undocumented Claude internals.
2. **Decided 2026-10-22: a bounded saved shortcut, not a new keymap subsystem (owner; [peer action configuration][claude-keys], [Codex][codex-config], [OpenCode choices][opencode-keys]).** Add `Newline shortcut` to `/settings`, cycling `Shift+Enter` (default), `Alt+Enter`, `Ctrl+Enter`; linear values are `shift+enter`, `alt+enter`, `ctrl+enter`. The selected key is the preferred shortcut and an additional alias; Shift+Enter, backslash-Enter and existing Ctrl+J remain available. Changing the selection removes only the previous additional alias. Plain Enter cannot be rebound here. Accept only these typed enum values, apply after acknowledged save, restore on startup, and retain existing cancel, busy, malformed-record and uncertain-save behavior. No compatibility design for previously saved defaults/records is part of this plan (owner: no users yet). The three-choice UI is Arany's scoped use of peer action remapping, not a claim that peers use this picker.
3. **Decided 2026-10-22: negotiate only what the terminal path proves (peer parity: [Codex probe][codex-probe], [budget][codex-budget], [modes][codex-modes]; guarantee constraint: per-effect isolation).** In visual modes, use the existing single input reader for kitty query/device-attribute replies and a 250ms total keyboard-probe budget per acquisition, without stealing or reordering unrelated keys/paste. A valid response permits a scoped push of the [protocol's disambiguation flag][kitty]. Codex requests additional flags for broader shortcuts/event handling; this feature needs no alternate-key, all-key, associated-text or event-type reporting, keeping the untrusted input surface within the existing decoder's contract. Missing/malformed responses retain legacy input and the fallback. Continue decoding received CSI-u and modifyOtherKeys records even when negotiation failed; a manual mapping can work independently. Do not enable modifyOtherKeys blindly or spawn `tmux` to inspect configuration. [Codex's tmux configuration-query subprocess][codex-tmux] would require a separately admitted process here; use negotiated CSI-u or the portable fallback. Pop before leaving the relevant screen on release/suspend/mode switch, then probe afresh on reacquisition. No host terminal configuration is written automatically.
4. **Decided 2026-10-22: guidance follows capability and selection (owner; [Codex footer parity][codex-footer], [Claude setup guidance][claude-terminal]).** Recommend the selected shortcut when enhanced reporting or a distinct received chord establishes it, and always expose `\` then Enter as fallback. Before negotiation lands in slice 2, and whenever capability is unknown, the usable default follows [Claude multiline input][claude-terminal]: Enter submits, backslash-Enter is enabled without setup and is the recommended newline gesture; the saved shortcut defaults to Shift+Enter and works whenever distinctly decoded. `/settings` warns for all three choices—Shift+Enter, Alt+Enter and Ctrl+Enter—that a terminal or multiplexer can discard/intercept modifiers; if the received bytes are plain CR, Arany sees Enter and can submit. [Legacy protocol encoding][kitty] normally gives Alt+Enter an ESC prefix, unlike Shift/Ctrl+Enter, so this is an end-to-end delivery warning, not a claim that every legacy terminal encodes all three identically. Help/settings describe manual emulator setup and tmux extended-key requirements, using standard CSI-u examples, without claiming a successful configuration from a terminal name. De-emphasize the verified bindings: [Ctrl+J newline](../../crates/arany-cli/src/terminal/input.rs) and [Ctrl+D canonical continuation](../../crates/arany-cli/src/terminal/linear.rs) remain functional but are no longer recommended in hints/help. Cancellation/EOF help stays accurate. Keep labels readable at narrow widths and without color.
5. **Decided 2026-10-22: preserve canonical accessibility (owner; [Arany mode contract](../../docs/specs/terminal.md#entry-modes-and-channels), honest uncertainty and accessibility constraints).** Linear/screen-reader input gets trailing-backslash physical-line continuation: remove the final backslash, append LF and retain the logical draft instead of Submit, including for repeated lines. Apply this only to the newly received canonical segment, never to the assembled draft or explicit clipboard payload. Recognized paste bypasses continuation: `/paste` preserves trailing backslashes literally, and bracketed frames follow decision 6. The kernel has already performed editing; unframed emulator paste has no distinguishable provenance. Accepted non-claim: a line from such a paste ending in backslash is treated like a typed continuation and loses that final backslash; later pasted lines can submit. This exception to raw-key provenance is disclosed in linear guidance with `/paste` as the safe multiline ingress; no timing heuristic attempts to infer origin. Keep Ctrl+D continuation/EOF semantics and physical-line limits. No raw mode or keyboard query is introduced there. The saved modified shortcut applies to visual sessions; at linear entry and in `/settings`, print `Modified newline shortcuts apply only to visual sessions; use backslash then Enter here` and recommend backslash-Enter for typed continuation. An overflow rejects the whole segment, leaving earlier accepted text intact. This is a mode-specific Arany adaptation, not asserted peer canonical-input parity.
6. **Decided 2026-10-22: paste cannot become input actions (peer parity: [Codex paste][codex-paste]; Arany safe-input guarantee).** Bracketed and explicit clipboard payloads never arm backslash continuation, submit, complete commands or activate selectors. Preserve raw atomic paste insertion and its deadline. In canonical mode, reject an unexpected bracketed frame as a whole and drain through its end marker across physical reads; never release interior lines as Submit. Use bounded delimiter state and the existing ten-second incomplete-record deadline; timeout closes terminal input, with no prefix submission. Offer the existing explicit `/paste` path for safe multiline clipboard insertion. Do not claim safe unframed emulator multiline paste or introduce timing-based intent detection.
7. **Decided 2026-10-22: compose with existing draft admission (owner; [large-draft plan](../large-draft-attachments/README.md), journal-first durability).** Neither slice raises draft, note or storage limits or changes attachment persistence. Newlines remain ordinary text edits under the currently effective limit; backslash replacement has zero byte growth and can succeed at capacity. If attachments land first, operate on editable text beside atomic chips, never inside their labels/payloads; paste provenance and draft replacement clear continuation state. Newlines do not expand a chip or trigger its collapse. Enter still uses the attachment plan's single expansion/admission path. This plan can land independently; the second change to land extends the shared composition scenarios, rather than changing the other plan.

The simplest sufficient implementation extends the existing composer, typed terminal input, settings rows and terminal mode guard. Keep the continuation state bounded to one caret/generation marker per composer. Do not route dialog answers, approvals, searches or read-only child views through chat continuation. Preserve modifier identity until the active input owner resolves it; a configured chat shortcut cannot confirm a hidden dialog. The same composer-level decision must precede primary idle/active/compaction and editable child dispatch, rather than duplicating backslash logic at each Submit branch.

Ownership remains in-process: the terminal owns byte decoding, capability replies and mode lifetime; the composer owns draft/caret/continuation; attached controls own acknowledged saved preference application; rendering consumes the effective shortcut/capability. Engine, reducer and Store keep existing semantic submission and acceptance ordering. No terminal-library types cross into Engine policy. Newline edits produce no Run, steering offer, approval verdict or Provider call; explicit subsequent submission follows the existing durable path. Editing a waiting note retains the existing withdrawal semantics.

## Security and resource model

The [security pass](../../agents/security.md#security-pass-triggers) is triggered by terminal input/rendering, capability handling and a saved preference field. Assets are private draft bytes, saved choices, terminal ownership and authority to submit/approve. Terminal bytes, paste, protocol replies and stored records are untrusted; only the active human input owner can dispatch submission or confirm a preference. Capability evidence changes decoding/presentation only, never trust, grants or approval authority. Repository/model text cannot set the binding, select a probe command or emit setup instructions as executable configuration.

Keep the existing 1-KiB preference record, draft/note caps, 64-byte key-sequence bound, finite input queue/backlog and paste deadline. Add only fixed-size capability/continuation state and a bounded reply path within the existing reader; replies must not deadlock behind a saturated input queue. Overflow or malformed records never become a submit-capable suffix. A save preserves the existing private-root admission, lock and atomic replacement semantics; uncertainty stays unknown and never retries. Probe cancellation and shutdown join the existing terminal owner. No new filesystem roots, credentials, network, subprocesses, descendants, dependencies or `unsafe` are introduced. No draft or raw capability payload is logged. Unframed paste safety and physical-key identity when bytes are identical are explicit non-claims.

## Risks and mitigations

- A legacy terminal sends the same CR for Enter and Shift+Enter → capability-aware hints and always-available backslash fallback; no heuristic can recover the lost modifier.
- A newline reaches one of several Submit branches → resolve it once at the chat editing boundary and exercise primary, busy and child flows.
- Enhanced modes leak into the shell or a different screen → scoped mode ownership and native fault/restoration scenarios, including partial acquisition.
- Canonical paste rejection releases later lines → keep frame-drain state across reads and close input on an incomplete record deadline.
- Concurrent attachment work changes draft representation → use the composition contract and current admission limit; never parse a chip label or hidden payload as key state.
