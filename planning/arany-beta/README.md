## Goal

Ship the CLI-only Arany beta defined in [the canonical architecture](../../docs/architecture/system-overview.md): durable Sessions and Runs, bounded direct children, deterministic replay and output, safe Workspace inputs, supported Providers, an accessible inline terminal, and opt-in trace export.

## Ownership and seams

| Responsibility | Owner | Interface and ordering | Seam |
|---|---|---|---|
| CLI grammar and mode selection | `main.rs` | Validated command to Engine; exit after durable result | In-process |
| Run coordination and budgets | `engine.rs` behind `lib.rs` | One committed transition before any observation; bounded cancellation | In-process |
| Resume, fork, compaction, context | `session.rs` and private `session/` files | Typed committed Session facts and bounded context | In-process |
| Provider invocation | `provider.rs` | Semantic `Finish` or `Delegate`; selected profile fixed per Run | Local-substitutable: scripted, OpenAI, Anthropic, verified custom |
| SQLite Events | `store.rs` | Bounded append/replay requests, one owner thread, transaction acknowledgement | In-process ownership isolation |
| Semantic and terminal output | `presentation.rs`, `terminal.rs` | Pure projections; terminal alone owns modes and input | In-process |
| Opt-in trace export | `telemetry.rs` | Bounded, lossy, safe facts after commit | In-process output isolation |

The Engine owns every state transition. No vendor wire type, SQLite handle, path-open capability, or terminal type crosses its public interface. Unknown Event kinds and illegal transitions fail replay.

## Interface and resource contract

Implement the command grammar, Event schema, lifecycle, provider outcomes, and limits in the canonical architecture and decision register. The Event journal is canonical; views and compaction snapshots are derived. Each Run pins provider/model, Workspace snapshot facts, collaboration policy, and one aggregate budget before `RunStarted`. Calls and children consume that budget without retries or fallback. Accepted Events commit before the reducer or presentation sees them. A process crash leaves an interrupted prefix.

The fixed beta limits include an 8 KiB user objective, 64 KiB Event payload, 256 MiB SQLite cap with 4 MiB admission headroom, 64 store requests, at most 32 queued updates, at most eight direct children, 4,096 output tokens per call, and 120/300-second call/Run deadlines. Durable limits reject or backpressure visibly; content is never silently truncated. The attached progress observer uses one latest-snapshot slot within that update ceiling and explicitly coalesces superseded display states, never canonical Events.

## Security model

The protected assets are credentials, Workspace input, Session history, canonical Events, and terminal integrity. CLI selections and trusted user configuration establish authority before any Workspace content is read. The Workspace, provider output, replayed text, and custom endpoint responses are attacker-controlled data. Immutable Run settings are the normalized authorization decision; the effective beta capabilities are bounded read-only Workspace input and one selected Provider egress. Children receive narrower assignment capsules. There is no sandbox or Tool execution claim.

State is private, owner-checked, no-follow, and outside the admitted Workspace. Inputs are handle-relative, no-follow, bounded snapshots. Only the selected Provider credential is loaded. Native origins are compiled; custom endpoints require exact current data-free conformance. Human output neutralizes controls and bidi; JSONL is serialized. Secrets and raw content do not enter diagnostics or telemetry. An unavailable capability, malformed state, missing evidence, limit breach, or cancellation fails closed with a safe typed result. Every dependency, native/build script, procedural macro, and application `unsafe` is reviewed before release.
