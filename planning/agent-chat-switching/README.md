# Switch between agent chats

## Metadata

- Status: `In progress`; next slice: live committed child transcript (slice 2)
- Owner: `fpmirabile` (terminal and Engine)
- Last updated: `2026-10-21`

## Outcome and scope

Deliver one feature: **switch between agent chats** within the attached Session. A user can inspect a child's journaled assignment, public Tool activity and result, return to the primary, and eventually follow committed child activity and find agents in a large history. This serves Arany's responsibility to make autonomous team execution inspectable without changing which agent owns execution or authority.

The four PRs below progressively deliver that capability. Slices 1-3 are read-only; slice 4 adds messaging a child, which the owner approved on 2026-10-21 to match Codex and Claude Code. No Provider call, Run, Goal, grant, fork or Session switch is caused by viewing a chat. Private reasoning, raw prompts and uncommitted child text are not conversation sources.

## Chosen direction

- **Simplest sufficient solution after Ponytail:** extend existing history projection, input routing and `/agents` surfaces. Keep one selected `(RunId, AgentRunId)` and one saved primary reading position; materialize only the selected bounded display. Reuse the existing committed Session view, safe Tool formatting and history anchors. No new crate, daemon, dependency, persistent selection, Event format or transcript database is needed.
- **Linux/macOS impact:** common navigation semantics in Classic and Fullscreen; no native Windows scope. Option+Left/Right on macOS can arrive as `ESC b` / `ESC f`. Adopt Codex's macOS-only fallback only when enhanced keys are unsupported, the composer is empty and no popup owns input. Never globally rebind word movement or treat standalone Escape as the start of an unbounded wait. Verify decoded Alt arrows, fallback bytes, ordinary Escape and nonempty drafts synthetically; record native terminal/emulator checks separately. The explicit text route below remains usable when terminal key mappings differ.
- **Accessible entry in slice 1:** extend the local `/transcript` command with `/transcript agents [N]`. Without `N`, print a bounded numbered list for the current/last Run; `n`/`p` cycle with wrap, a number opens that target, and `q` returns primary. This is proposed syntax, not an existing command. It enters an armed view with the composer retained and disabled; arbitrary input is navigation feedback, never a Goal note. Slice 3 also routes `/agents` to the same transcript selection.
- **Ownership and interface:** Engine/Session retain execution, canonical IDs, ordering, reducer validation and journal ownership. Pure presentation maps the selected actor's admitted facts to inert rows; the terminal owns selection, focus, input admission, drafts and anchors. The attached loop consumes the existing in-process committed stream; no geometry, key or database-row type enters Engine. Crossing data is limited to domain IDs and committed views/Events, translated into display rows at the presentation edge. Lookup failure preserves the primary context; cancelling a view cancels no Engine work. Reuse the existing seam rather than introducing a forwarding trait or remote adapter. Replay and PTY scenarios above exercise that seam through its current interface.

## Security and resource model

Rendering user/model/Tool content triggers the [security pass](../../agents/security.md#security-pass-triggers). Assets are admitted Session history, the primary draft, terminal ownership and existing execution authority. The trust boundary is committed domain data → inert human display → local input selection; names, assignments, paths, results, search text and imported history remain attacker-controlled data.

Authority comes only from the already admitted Session and parent/child grants. Startup State/Workspace admission precedes projection. The normalized selection is the exact Session/Run/AgentRun tuple, validated against that Session; a label, ordinal, search match or collapsed-row index grants nothing. No repository path, child-private file, credential, network route or Provider request is opened for viewing. New input stays local; it cannot become a command embedded in history, a steering note, approval or renewed grant. Existing Guard enforcement and descendant authority remain unchanged; source review of this UI is not a new sandbox or secret-isolation claim.

Use the ordinary terminal-control escaping before layout and append-only output. Exclude credentials, raw requests, private prompts/reasoning and transport errors, even if a journal metadata field could expose them. Keep selected-actor Tool ownership and uncertainty markers intact; never imply that merely reading a child's transcript authorizes its operations. Test hostile controls, forged headings, cross-Session IDs, hidden drafts and typeahead as explicit rejection cases.

Proposed bounds and backpressure, to become terminal-spec limits in their implementing slice:

| Resource | Bound and overflow/failure behavior |
|---|---|
| Targets | Current/last Run for shortcut cycling and text entry; picker retains the existing 16 recent Runs × nine agents ceiling (144 targets). Preserve current/last counts separately from historical totals. Older targets use `arany show`; this feature raises no child budget. |
| Display | One selected transcript, at most 64 KiB escaped text and 4,096 rendered rows; existing geometry and per-row bounds still apply. Stop before allocating beyond the bound, retain whole safe records and show a truncation/export cue. No copied full transcript per agent. |
| Live work | Reuse the existing 64-Event drain burst and 256-slot journal tap ([journal.rs:10](../../crates/arany/src/journal.rs#L10)); yield to input between bursts. A lag or sequence gap reloads the admitted view rather than dropping history silently. One selected projection, no per-child queue or watcher; zero new LLM calls or durable storage. |
| Search and window | At most 64 ASCII filter characters, local-only; reject excess input with feedback. At most 10 visible selector rows, further clipped by geometry; filter only bounded target metadata, never allocate transcript bodies to search. |
| Idle groups | Keep up to three settled idle rows expanded, then one `N idle agents` row that Enter expands into the same window. Running, failed, uncertain or attention-needed rows remain visible. Collapse/expand only on committed changes or user action, with no age timer or auto-hide. |
| Navigation state | One selected identity and one saved primary draft/caret/anchor under existing draft/image bounds. Linear choice input is bounded to 16 ASCII bytes; malformed/overflow choices leave selection unchanged. Refresh preserves identities; linear numbers bind to the displayed snapshot and re-arm before a changed mapping is accepted. |

A read/replay failure shows no unvalidated child content, preserves the primary draft and follows the existing terminal/history failure classification. No self-retry, effect replay or change to Goal cost/storage budgets is introduced. Live catch-up and terminal teardown retain their existing cancellation and restoration owners.

## Risks and mitigations

- Escape normally cancels an active Run → give child-view return higher precedence, consume that key once, and verify zero cancellation Events from return; Ctrl+C keeps explicit Run cancellation.
- Classic scrollback cannot erase an older agent's rows → append an unmistakable agent/read-only boundary on switch, keep the viewport label visible and never repaint settled native history. Fullscreen replaces only its managed view. Test switching back without duplicate confirmed answers or lost primary position.
- Completion, approval or refresh races with selection → key state by canonical identity, keep completed transcripts readable, preempt for approval with a fresh barrier and freeze linear numbering until re-armed.
- Peer behavior drifts or requires more authority → use pinned research, preserve Arany's guarantees and resolve deviations in the owning spec; no inference about unverified peer limits or native key behavior.

## Vertical slices

1. **Read-only switching and return — landed.** The [agent chat contract](../../docs/specs/terminal.md#agent-chats) owns the shipped behavior.
2. **Live committed child transcript — one PR, after slice 1.** Ship a selected running child's transcript that updates from committed child Events and remains readable at completion. End to end: Engine journal commit → existing subscription/reducer and gap/resync reload → selected actor projection → one bounded redraw burst in both visual modes or new labeled append-only lines in linear mode. Update terminal live/limits/scenarios; preserve execution's commit-before-observation contract. Extend the active agent journey with gated child steps and out-of-order sibling completion; prove no provisional text, no idle redraw, bounded bursts, responsive return/cancel, stable scrolled anchors, resync recovery and honest read-failure feedback. Snapshot switching remains usable if a child has already finished.
3. **Searchable `/agents` switch picker — one PR, after slice 2.** Ship Enter-to-open transcripts with local search, windowing and expandable collapsed idle rows, following Claude Code's panel pattern without timer-based hiding. End to end: `/agents`/existing Agents action admission → bounded committed roster and stable ID selection → shared transcript lookup/live path → armed picker/view/return in Classic, Fullscreen, linear and screen-reader forms. Preserve `/agents` policy arguments and primary/current/last/historical distinctions. Update selectors/agent inspection, limits and acceptance scenarios; extend the same inspector/frame/linear owners for search overflow, zero matches, more than one window, group expansion, hidden-row nonactivation, refresh races, stale numbers and return with the retained draft. The two earlier navigation paths continue working independently of search.
4. **Message the selected child — one PR, after slice 2.** Typing in a selected running child's view sends a steering note to that child, as in Codex (live agents accept input) and Claude Code (teammate messaging). End to end: the composer → the existing steering-note admission, extended to child Runs → a committed note Event bound to that AgentRun → delivery at the child's next Provider boundary → a visible notice in its transcript. This changes the [Goals steering contract](../../docs/specs/goals.md#steering-notes-and-pause) ("child calls never receive notes"). The note only adds guidance: it never widens the child's grant, and a finished child stays read-only. Tests: note delivery and ordering, a finished or cancelled child refusing the note, replay, and the linear form.
