# Context budgets: compaction summaries, recent files and output spill

## Metadata

- Status: `Ready`
- Owner: harness maintainers
- Last updated: 2026-10-25

## Outcome and scope

One capability: a day-long Session keeps working after compaction without re-reading everything and without losing command output. Concretely: (a) a compaction summary large enough to carry a working day; (b) a bounded list of recently changed files recorded with each compaction so the model knows what to re-read; (c) full command and MCP output kept in a private per-Run spill file that `Read` can page when the inline excerpt is cut. The harness responsibility served is context management ([priority 1](../../AGENTS.md#product-and-implementation-priorities)); every bound stays finite ([global rule 4](../../AGENTS.md#global-rules)).

This plan resolves the `NEXT_STEPS` "Full-output spill (owner decision)" item: the owner approved the spill on 2026-10-25; the item is deleted from `NEXT_STEPS.md` in the same change that adds this plan. Excluded: window-relative context budgets beyond the evidence that already exists (`Provider::context_window_tokens_for_run`, #426), cross-Session memory, retrieval.

## Contract and scenarios

- Owning specs: [session.md Context and compaction](../../docs/specs/session.md#context-and-compaction) (summary bounds, compiler version, what the next Run receives), [tools.md Limits](../../docs/specs/tools.md#limits-and-failure-behavior) and [In-process reads](../../docs/specs/tools.md#in-process-reads) (output row, Read grammar), [execution.md Persistence bounds](../../docs/specs/execution.md#persistence-bounds) (observation field), [goals.md](../../docs/specs/goals.md#lifecycle-budgets-and-recovery) (compaction call accounting), [terminal.md storage report](../../docs/specs/terminal.md#storage-report) (spill storage inventory).
- Proposed contract, summary: `MAX_COMPACTION_OUTPUT_TOKENS = 8192`, `MAX_COMPACTION_SUMMARY_BYTES = 64 KiB`; the compiler version bumps to 5 and the recorded floor stays 3 (older summaries remain valid input). The summary still enters context as untrusted derived data; the input cap and request ceiling are unchanged, so the compaction call fits as today (64 KiB output under a 512 KiB request).
- Proposed contract, recent files: the compaction record gains `recent_files: Vec<{path, digest}>`, at most 8 entries and 4 KiB serialized, derived deterministically by the Engine from the covered prefix's committed Write/Edit/MultiEdit/ApplyChangeset observations (newest first, de-duplicated by path), never from model text; omitted when empty (additive-field rule, no payload version bump). The next Run's compiled context renders the list as untrusted data under a fixed heading ("Files changed before compaction; Read them for current content"); no file content is re-read implicitly, so no Tool authority or replay change.
- Proposed contract, spill: when a Command or MCP result's raw stdout+stderr exceeds the inline excerpt, the Engine writes the complete captured bytes (bounded by a new `MAX_SPILL_RESULT_BYTES = 8 MiB` per result and `MAX_SPILL_RUN_BYTES = 64 MiB` per Run; beyond that the file is cut with a trailing marker and `truncated: true`) to `<StateRoot>/spill/<run-id>/<intent-digest-hex>.txt` with mode 0600, before `ToolFinished` commits. The observation gains an additive optional `spill: {ref, bytes, truncated}` where `ref` is the intent digest. `Read { path: "spill:<digest>" }` pages that file with the ordinary Read grammar (offset, limit, 2,000-char lines, result budget) through a second in-process directory capability admitted on the StateRoot spill directory for the current Session's Runs only; any other path shape under `spill:` is refused before opening. Spill files are untrusted data like any observation, never enter changesets, checkpoints, rewind, hooks' `tool_input`, Provider context (except through an explicit Read) or replay; `show` lists `spill` facts without content; files are removed with the Session's State. The storage report counts spill bytes.
- Successful path: a failing `cargo test` whose 3 MiB output is excerpted inline; the model reads `spill:<digest>` page 3 to find the failing assertion; after compaction the summary and the recent-files list name the edited test file; the next Run reads it and continues.
- Rejection/failure/recovery: a 9 MiB result is cut at 8 MiB with `truncated: true`; a 65th MiB in one Run yields no spill and `spill: null` with the inline excerpt unchanged; `Read spill:<unknown digest>` records attested `Failed` with "no spill for this Run"; a spill write failure before `ToolFinished` keeps the observation (excerpt only, no `spill`) and records a development diagnostic, never an Uncertain outcome (the effect itself succeeded); a crash between the file write and the commit leaves an orphan file that the next open removes; a summary over 64 KiB rejects as today and never retries; a digest-mismatched recent file is still listed (it is a hint, not a precondition).
- Evidence owners: `crates/arany-cli/tests/session_run/auto_compaction.rs` (summary bound, record fields, next-Run rendering), `crates/arany/src/session/reducer/tests.rs` (record validation), `crates/arany-cli/tests/session_run/tools/native_exec.rs` and `tools.rs` (spill write, Read paging, bounds), `tests/session_run/storage.rs` (inventory), `crates/arany/tests/engine_run/workspace_security.rs` (spill never enters changesets or hooks).

## Chosen direction

- Simplest sufficient solution: three constants change value; one additive field on the compaction record; one additive field on the observation; one new read root with a closed `spill:` prefix reusing `read_page`; no new Event kind, no new Tool, no index. The spill directory is per Run so cleanup is a directory removal.
- OS impact: none beyond a private file under the admitted StateRoot (same permissions as the journal) on Linux and macOS.
- Ownership: the Engine writes spill files (it owns the observation); the Store owns the directory under StateRoot admission; Tools owns the `spill:` Read grammar and the second capability. Not a module boundary change.

## Security and resource model

New persistent surface: spill files hold untrusted command output under the private StateRoot with mode 0600, outside the Workspace and never handed to the Guard. The Read capability is a cap-std directory handle opened on `<StateRoot>/spill/<run-id>` at Run admission; path components are a fixed 64-hex digest, so traversal is impossible by construction and verified by the existing no-follow open. Bounds: 8 MiB per result, 64 MiB per Run, counted in the storage report; writes are bounded by the Guard's existing drain cap. Replay never reads spill files; forged or missing files cannot alter a committed observation. The security pass for a new persistent format and read surface ([security triggers](../../agents/security.md#security-pass-triggers)) runs in slice 3 and its evidence is `workspace_security.rs`.

## Risks and mitigations

- A larger summary costs more per compaction → the compaction reservation already charges output tokens; the Goal report shows it; 8,192 is the Codex order of magnitude, below Claude Code's skill re-injection alone.
- Models may treat the recent-files list as content → the heading says to Read; the list carries digests, not bytes; `auto_compaction.rs` pins the rendering.
- Spill files outlive their usefulness → removed with Session State; counted in the storage report; no automatic growth beyond 64 MiB per Run.
