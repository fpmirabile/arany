# Assistant Markdown rendering

## Metadata

- Status: `Ready`; the repository owner approved the `pulldown-cmark =0.10.3` dependency (Codex's parser and pin) on 2026-10-26
- Owner: harness maintainers; dependency approval belongs to the repository owner
- Last updated: 2026-10-26
- Request: owner-requested assistant text formatting, received 2026-10-26; normal/medium priority, after the existing priority plans

## Outcome and scope

Make assistant Markdown readable in the existing Fullscreen and Classic transcript, including the Fullscreen transcript pager and selected agent results. This serves the harness's terminal presentation responsibility. Preserve the original Markdown as the source of history, copy and export; formatting is a disposable terminal projection.

Include committed answers, provisional answer snapshots and reopened incomplete answers. User objectives, assignments, steering, public commentary, Tool output, approvals, notices and errors retain their existing presentation. Screen-reader/linear output, deterministic `exec`/`show`, JSONL, `/serve` (`serve --stdio`) and ACP text remain unchanged. This plan adds no terminal view, command, setting, protocol item or journal format.

## Research

### Arany contracts and current flow

- The [terminal contract](../../docs/specs/terminal.md#entry-modes-and-channels) currently says message bodies are unstyled, except recognized leading slash tokens. Its [history and provisional-text rules](../../docs/specs/terminal.md#terminal-continuity-and-provisional-text) require source anchors, a single provisional location, confirmed Classic insertion once, explicit incomplete labels and bounded history. Its [public compatibility rule](../../docs/specs/terminal.md#public-limits-and-compatibility) requires inert Markdown, HTML, SVG, links and model output. Styling changes the first rule; it must preserve the others.
- [Binary practice](../../agents/arany-cli.md), [terminal design](../../agents/skills/arany-terminal-design/SKILL.md), [untrusted-rendering security](../../agents/security.md) and [testing](../../agents/testing.md) apply. [Architecture §8](../../docs/architecture/system-overview.md#8-terminal-presentation) assigns geometry and transient history to the terminal, outside the Engine and canonical state. The dependency/layout choice follows Ponytail: reuse Ratatui, escaping, Unicode segmentation/width and existing history; add only the missing Markdown parser. Rust clean-code and architecture review retain this dependency direction.
- [Attached notifications](../../crates/arany-cli/src/cli/attached/run.rs), in `RunProgress::on_server_message`'s `turn/display` handling, forward raw `PreviewText.answer` to `AttachedTerminal::set_preview`. [History](../../crates/arany-cli/src/terminal/history.rs) reads `RunView.assistant_message` or display checkpoints through `message_text`; `message_rows` escapes graphemes and wraps strings, and `HistoryRow` has no Markdown spans. [Drawing](../../crates/arany-cli/src/terminal/view.rs), in `draw_history_rows` and `native_line`, styles headings/chrome but draws body strings plainly. [Classic insertion](../../crates/arany-cli/src/terminal.rs), in `insert_native` and its callers, shares `history::display_rows`; this is an additional consumer, not a second parser owner.
- History currently counts rows separately in `message_row_count`/`run_row_counts` and Classic bytes/rows in `classic_run_cost`. Formatting must use the same layout decisions for counting, drawing, selection and source-anchor recovery; changing drawing alone would break scrolling and history admission. `History::point_at`, `selected_cells`, find and resize also depend on source-byte mappings.
- [`CopyRequest::latest_answer`](../../crates/arany-cli/src/terminal/clipboard.rs) already copies the original assistant message through bounded `display_text`, retaining Markdown while escaping hostile controls. `History::selection_text` copies source ranges, excluding trusted chrome and wrap breaks. Classic mouse copy belongs to the emulator and captures rendered text; that cannot provide a raw-source guarantee. `/copy`, canonical `show`/JSONL export and Fullscreen source selection remain the source-preserving paths. [Linear output](../../crates/arany-cli/src/terminal/linear.rs) and [deterministic presentation](../../crates/arany-cli/src/presentation.rs) are separate consumers and must bypass formatting.
- Existing accepted assistant and preview text caps are both 32 KiB ([Session constants](../../crates/arany/src/session.rs), [display records](../../crates/arany/src/session/events/records.rs)); this does not itself bound Markdown expansion. Current CLI dependencies provide terminal layout and Unicode handling, but no Markdown parser ([CLI manifest](../../crates/arany-cli/Cargo.toml), [workspace manifest](../../Cargo.toml), [lockfile](../../Cargo.lock)).

## Chosen direction

- Put one private concrete renderer in `terminal/markdown.rs`, consumed by History and both existing drawing paths. It takes borrowed source plus width and returns bounded rows containing safe styled fragments and source ranges. Translate parser events at this edge; no parser or Ratatui types enter Engine, journal, Provider, protocol or shared semantic presentation. No new workspace crate, trait, plugin, theme system, setting, persistent render cache or background task.
- Keep the loaded Session/checkpoints as the source owner. History owns row counts, selection and scroll anchors; it uses the renderer's same layout in count-only and visible-row modes, rather than keeping a second full transcript. `HistoryRow` carries terminal style/source information; `draw_history_rows` and `native_line` apply it. Classic preflight counts the actual transformed bytes/rows including decoration before materialization and retains its existing whole-Run suffix limits. User-owned terminal themes and the existing no-color palette still apply.
- Source mapping covers every visible grapheme, decoded entity/escape and generated marker. Generated bullets/padding anchor to their construct; hidden delimiters anchor to the nearest visible construct for find/resize. Fullscreen selection copies the contiguous original source range between mapped endpoints, including intervening Markdown delimiters and link destinations; selecting a whole construct includes its syntax envelope, and selecting the whole body returns its original Markdown. Partial selections can therefore include syntax absent from the selected cells. Existing control escaping and clipboard limits still apply. Literal find continues to search source Markdown. Classic emulator selection necessarily copies displayed text; `/copy` provides source there. Text exports retain original Markdown with their existing escaping/serialization rules.

| Construct | Terminal projection |
|---|---|
| Headings, emphasis, strong emphasis, inline code | Heading weight/spacing, italic/bold/reverse or existing supported modifiers; no semantic reliance on color. Hide syntax delimiters; preserve source ranges. |
| Fenced and indented code | Preserve whitespace and line boundaries, show a sanitized fence-language label when present, use plain code styling, hard-wrap long code lines at grapheme boundaries; continuation decoration is generated and excluded from copy. Never execute or load a lexer named by content. |
| Ordered/unordered lists and block quotes | Visible numbers/bullets and quote rails; continuation rows use hanging indentation, clamped at narrow widths to leave content space. |
| Pipe tables | Bounded cell layout fitted to available width, with header emphasis and wrapped cells; below fitting width use header/value records per source row, following Codex. No horizontal overflow or column truncation that loses content. |
| Links/autolinks | Visible label plus destination, such as `label (https://example.test)`; show a destination once if label equals URL. No OSC 8, opening, fetching, path lookup or clickable action. |
| HTML, images and unsupported extensions | Literal source text, escaped like other output; no HTML interpretation, image decoding/loading, math, Mermaid, footnotes or executable extensions. Entity decoding in ordinary Markdown is sanitized before display. |

Wrapping is by terminal cells after reserving speaker chrome, body indentation and list/quote prefixes. Reuse existing Unicode segmentation/width and word-wrap behavior: prose breaks at spaces; overlong words, URLs and code break on graphemes, with the existing safe replacement when a grapheme cannot fit. Preserve explicit hard breaks and code whitespace; soft prose breaks become spaces. Zero/tiny widths use existing geometry/fallback handling. Screen-reader, `TERM=dumb` and other linear fallbacks keep plain labeled source text and never invoke this renderer; `--no-color` retains structure without color.

Streaming follows Codex's source-backed re-render principle using Arany's existing replaceable preview, rather than copying its scrollback stable-prefix machinery. Each source/width change atomically re-renders the latest complete accumulated snapshot in the active location. Unclosed fences render their available body as code; unfinished delimiters/links render according to the parser's current interpretation, without invented closing bytes. A later token can legitimately change that construct's earlier layout. Unchanged snapshots cause no extra parse/redraw; only the latest pending snapshot is retained. Mutable tables remain in that replaceable location. Accepted completion replaces the preview and inserts Classic history once; rejected candidates withdraw, and cancellation/reopen retain current incomplete labels. No timer, per-token Event, durable styled text or preview-to-answer promotion.

**Syntax highlighting is a later slice, excluded from this plan.** Both peers highlight code, but Codex's syntax/theme/native-regex closure is substantially beyond the minimal parser and Arany has no installed lexer. Keep plain code blocks usable now. A separate researched proposal, capped at 400 changed lines for its first usable language set, is triggered by owner demand for code coloring; it must justify its own dependency/size/security cost. There is no unresolved highlighting choice in the slices below.

Linux and macOS use the same pure-Rust renderer and terminal-cell rules, with no new OS facility or enforcement adapter. Existing native terminal restoration/copy owners remain authoritative; source inspection and this plan do not establish native support.

## Security and resource model

Triggers: rendering attacker-controlled model content and adding a parsing dependency ([security pass](../../agents/security.md#security-pass-triggers)). Assets are terminal integrity, readable trust labels, raw history/copy fidelity and input responsiveness. The boundary is raw assistant source → parser-decoded data → escaped fragments → trusted Ratatui styles. Model text, fence languages, URLs, HTML and apparent roles supply no authority. Startup admission, immutable Tool intents, Policy, Guard enforcement, descendant grants and journal ordering remain outside this path; formatting makes no authorization decision and adds no effects, credentials, file/network access or child process.

Sanitize every emitted parser string **after decoding**, including link destinations and language labels, using existing `escape_terminal`; pre-sanitizing raw Markdown alone is insufficient because the parser [unescapes destinations](https://docs.rs/crate/pulldown-cmark/0.10.3/source/src/parse.rs#L864). Keep forged prefixes within existing assistant chrome. No content-provided CSI/OSC/C0/C1, carriage return, backspace or bidi controls reach the backend as controls. Trusted terminal styling and the existing explicit clipboard OSC 52 mechanism remain separate compiled operations; content cannot create their sequences. Preserve raw canonical source but apply existing sanitization at human copy/export boundaries. Do not log source, parsed fragments, private paths or URLs to diagnostics/telemetry.

Proposed renderer constants live once beside `terminal/markdown.rs`; implementation spec bounds link their generated owners under the [limits workflow](../../docs/specs/README.md#generated-bounds-and-disambiguation), without parallel numeric restatements:

| Bound | Proposed value and overflow behavior |
|---|---|
| `MAX_MARKDOWN_PARSE_BYTES` | 32 KiB UTF-8 per message, checked before constructing a parser; excess skips parsing entirely. This is a renderer admission bound independent of the Session's message cap. |
| `MAX_MARKDOWN_DEPTH` | 32 active parser-event containers; check before pushing any renderer stack. This bounds renderer nesting, not parser-internal depth. |
| `MAX_MARKDOWN_EVENTS` | 65,536 events per message; stop consuming at overflow. No unbounded event vector or recursive renderer. |
| `MAX_MARKDOWN_OUTPUT_BYTES` | Derive as 16 × parse-byte cap, counting generated text, safe escapes and padding before allocation. |
| `MAX_MARKDOWN_ROWS` | Reuse `history::MAX_CLASSIC_HISTORY_ROWS` as a per-message formatting-row ceiling. Existing history/agent/clipboard bounds still apply independently. |
| `MAX_MARKDOWN_TABLE_COLUMNS`, `MAX_MARKDOWN_TABLE_ROWS` | 16 columns and 128 source data rows per table; check before building the table matrix. |

Any formatting limit aborts that message's derived layout and selects the existing escaped literal renderer for the **whole** message, with one compiled formatting-limit cue outside copied source. Never truncate the accepted answer, fail its Run, retry inference or retain a partially formatted prefix. Counting and drawing choose the same fallback. Malformed/incomplete Markdown is ordinary parser input, not a Run failure. Output/write errors retain existing propagation/restoration behavior.

Parser allocation has a separate, explicit limitation: the [constructor runs its first pass before events](https://docs.rs/crate/pulldown-cmark/0.10.3/source/src/parse.rs#L215), with [heap-backed nodes/spine](https://docs.rs/crate/pulldown-cmark/0.10.3/source/src/tree.rs#L53) and no public general depth setting. Its [table padding cap](https://docs.rs/crate/pulldown-cmark/0.10.3/source/src/firstpass.rs#L303) permits up to 262,144 synthesized empty cells. The pre-construction byte cap and this upstream cap bound admitted parser expansion; renderer event/depth/table limits act afterward and do not promise a hard RSS or deadline bound on parser construction. S1 checks maximal nesting, and S3 checks adversarial table padding through the adapter before enabling tables. If dependency inspection or those checks contradict this bounded-work model, stop and revise the Research/Plan gates rather than weaken limits. Render one message at a time with bounded transient output, no cross-Session cache, retained AST, parser queue, retry or new storage budget.

## Risks and mitigations

- Formatted rows drift from counters/source anchors → one layout owner for drawing, count-only use, find and selection; exercise resize, hidden syntax, entities and mixed-width graphemes in existing History tests.
- Partial grammar changes earlier rows or tables → replace a whole preview snapshot, preserve source anchors, append only accepted Classic answers; tests split every relevant delimiter/fence/link/table boundary.
- Hostile controls reappear after entity/URL decoding → sanitize every output fragment and test both direct and encoded payloads through both terminal consumers.
- Parser expansion or dependency drift → explicit parser-versus-renderer bounds above, finite fallback, pinned minimal closure and supply-chain review; no executable-size/performance claim from archive sizes.
- Scope exceeds review budget → split by observable syntax family or risk while keeping all consumers/spec/tests together; never move tests or spec updates to another PR to meet the ceiling.
