# Editors on the shared Workspace

## Metadata

- Status: `Ready` (implementation gated as listed under Gates)
- Owner: harness maintainers
- Last updated: 2026-10-25

## Outcome and scope

One capability: an EditOnly child edits the real Workspace the way the primary does, through typed, receipted, checkpointed in-process mutations and overlay commands under its path lease, while researchers and QA read the live tree; the primary verifies before answering and `/rewind` covers mistakes. The private base/overlay image, the 45 KiB `WorkerDataChunk` transfer, sealed handovers and primary integration of worker bytes are retired. Owner decision 5, 2026-10-25, exactly as the brief recommended (option d). The harness responsibility served is the team on top of the guarantees ([priority 1](../../AGENTS.md#product-and-implementation-priorities)); no guarantee sentence changes: an editor's edit is a typed effect with intent, receipt and observation ([journal-first](../../AGENTS.md#non-negotiable-guarantees)), its grant is a leased subset of the parent's grant (children never widen), and the Workspace still changes only through validated typed effects (per-effect isolation after [in-process file operations](../../docs/specs/tools.md#in-process-file-operations) and [the command overlay](../command-workspace-overlay/README.md)).

**Non-goal, recorded with its trigger:** an opt-in "one worktree per Goal where all agents work, one changeset at the end" (brief option c) is deliberately not built now. Trigger to revisit: dogfooding shows parallel editors needing overlapping areas, or a user asks to keep the working tree untouched until review. Per-editor worktrees are rejected (maximum creation, cleanup and merge cost for no guarantee gain).

## Research

- Protocol to retire: "The Engine journals base capture before the spawn that acquires its lease, every private mutation and data seal before continuation, and guarded cumulative capture after observed worker answer. Worker answer, handover eligibility, primary ApplyChangeset, integration disposition and lease release are separate committed facts. Worker private edits leave the Workspace unchanged until the primary's eligible integration." ([execution.md Worker journal protocol](../../docs/specs/execution.md#worker-journal-protocol)); every Tool intent carries `target: Workspace | WorkerView { assignment_id, base_digest, revision, cache_generation }`; data bound `N + 12 + (4*A + 6) + switches`; 48 MiB allowance, 64 MiB per worker image, 256 MiB aggregate. Event kinds: `WorkerDataChunk`, `WorkerDataSealed`, `WorkerHandoverRecorded` (v2), `WorkerIntegrationRecorded`, `WorkerHandoverDiscarded`, `WorkerLeaseReleased`, `WorkerVerificationRecorded`, `WorkerStopObserved` ([events.rs:419-458](../../crates/arany/src/session/events.rs); floors at [migrate.rs:352-359](../../crates/arany/src/store/migrate.rs)). `AgentSpawned.assignment` pins the base-manifest reference, `cache_generation` and remaining data allowance; `RunStarted.config.worker_policy` pins the 48 MiB allowance. Tool-side: `ToolCall::{PrepareWorker, WorkerCommand, WorkerRead, WorkerMutation, WorkerData}` ([types.rs:998-1020](../../crates/arany/src/tools/types.rs)), `tools/worker.rs` (3,121 lines), `session/worker.rs` types (`WorkerDataRef`, `WorkerDataChunk`, `WorkerDataSealed`, `WorkerHandover`, `WorkerIntegration`, `ChangesetSource::WorkerHandover`), Engine `run_loop/worker.rs` (1,996 lines: `capture_handover`, `integrate_worker`, `finish_worker_integration`, `settle_worker_integration`, `release_worker`, `verify_workers`), reducer `reducer/worker.rs` + `worker/{apply,before}.rs` (2,245 lines), `reducer/worker_tests.rs` (5,492), `test_support/worker_teams.rs` (2,441), native private targets in `guard/linux.rs` (fresh 64 MiB project tmpfs, file-worker seccomp layer) and `guard/macos` (worker volumes) plus the worker cache shared-read generation lease ([tools.md Private worker targets](../../docs/specs/tools.md#private-worker-targets-and-handover-transfer), [Persistent Workspace build cache](../../docs/specs/tools.md#persistent-workspace-build-cache)).
- What stays and already does the job: leases ("Writable leases name 1–64 sorted relative files/subtrees … Ancestor/descendant and ASCII case-folded aliases conflict … Primary typed writes cannot overlap live leases, and primary commands/MCP processes wait for lease quiescence. Acquisition cannot silently replace another owner; there is no TTL or cross-Run lease", execution.md); the shared `execute_step` with delegated hooks and permission verdicts under the child identity; `WorkerVerificationRecorded` ("the primary obtains fresh Workspace Tool evidence for the assignment's criterion", [goals.md Worker accounting and verification](../../docs/specs/goals.md#worker-accounting-and-verification)); `WorkerStopObserved`, `WorkerLeaseReleased`; explicit `resumes`/`supersedes` lineage ([session.md Worker identity](../../docs/specs/session.md#worker-identity-and-explicit-reassignment)); upfront editor validation through the reducer (G5, #441).
- Checkpoints today exclude editor work by design: "Mkdir, MCP, commands themselves, private worker edits, cache publication and scratch have no checkpoint capture. Integrated command and worker changes are covered because they are Workspace publications" ([tools.md Checkpoints and rewind](../../docs/specs/tools.md#checkpoints-and-rewind)); capture happens in the Engine before GO from committed before-versions ([step/checkpoint.rs](../../crates/arany/src/engine/run_loop/step/checkpoint.rs)), so extending it to editor effects is a site change, not a new mechanism.
- Uncertainty today: "a positively contained private unknown is a local worker disposition, while an unknown Workspace publication remains a fatal continuation/recovery block" (goals.md). On the shared tree an editor's Uncertain write is an unknown Workspace effect; the Run stops like a primary Uncertain write (honest uncertainty; this is the one semantic the shared tree makes stricter, see Risks).
- Peers: Claude Code subagents share the working tree by default ("Checkpoints do not cover subagent edits"), `isolation: worktree` is opt-in ([subagents](https://code.claude.com/docs/en/sub-agents)); Codex subagents inherit the parent's sandbox and approval policy on the same tree ([subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)); OpenCode Task subagents and Goose `delegate` share the tree ([OpenCode agents](https://opencode.ai/docs/agents/), [Goose subagents](https://block.github.io/goose/docs/guides/context-engineering/subagents)). None streams file bytes through a transcript or journal.

## Chosen direction

- Simplest sufficient solution: editors reuse the primary's Tool path unchanged (`target: Workspace`), the lease check becomes symmetric at intent admission, checkpoint capture drops its "primary only" condition, and the whole private-target protocol is deleted. Nothing is added except a derived changed-paths list in the report.
- Linux/macOS: no native difference beyond what 4B/3B already document; both platforms lose their private worker tmpfs/volume targets and the worker cache lease.
- Ownership: the reducer keeps leases, dispositions, lineage and verification; the Engine keeps scheduling, waves and settlement; Tools loses the worker transfer phase. Not a new seam.

## Security and resource model

Trust: editor authority is unchanged (lease ∩ parent grant ∩ plan ∩ definition; `unguarded: denied`; no Git, MCP, Skill, network or nested delegation); every editor effect passes the same permission verdicts and delegated hooks under the child identity, now against the live tree, so permission modes that gate primary edits gate editor edits identically (acceptEdits/plan/dontAsk semantics apply per effect, prompts labelled with the child). What changes: an editor's mistake is visible in the Workspace before the primary verifies; covered by checkpoints, `/rewind`, the automatic failure rewind and the primary's mandatory verification. Bounds: per-effect bounds unchanged; the 48 MiB data allowance, chunk reservations and 64/256 MiB image limits disappear with their machinery; lease count and depth unchanged. The security pass ([triggers](../../agents/security.md#security-pass-triggers): Tools, processes, untrusted content) runs in slice 1 against `workspace_security.rs` and `engine_run/permissions.rs` (editor prompts cannot be answered by model or child text).

## Risks and mitigations

- Editor Uncertain now stops the whole Run instead of one actor → honest and rare (parent-sync failure); documented in goals.md; the Goal receipt names the editor and path.
- Two editors racing on build outputs through commands → overlay changesets are lease-validated; build caches are shared and discard-only as for the primary; conflicts surface as refused out-of-lease changes, never merges.
- Retired types referenced across presentation, ACP, telemetry and serve → exhaustive `Event` matches and the schema snapshot fail to compile or differ; the slice lists consumers by `grep -rn 'WorkerData\|WorkerHandover\|WorkerIntegration\|WorkerView'` at open.
