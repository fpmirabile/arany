# Editors on the shared Workspace

## Metadata

- Status: `Ready` (owner decisions D1/D2 recorded; implementation gates below)
- Owner: harness maintainers
- Last updated: 2026-10-26

## Outcome and scope

One capability: an EditOnly child edits the real Workspace the way the primary does, through typed, receipted, checkpointed in-process mutations and guarded commands through the primary publication owner under its path lease, while researchers and QA read the live tree; the primary verifies before answering and `/rewind` covers mistakes. The private base/overlay image, the 45 KiB `WorkerDataChunk` transfer, sealed handovers and primary integration of worker bytes are retired. Owner decision 5, 2026-10-25, exactly as the brief recommended (option d). The harness responsibility served is the team on top of the guarantees ([priority 1](../../AGENTS.md#product-and-implementation-priorities)); no guarantee sentence changes: an editor's edit is a typed effect with intent, receipt and observation ([journal-first](../../AGENTS.md#non-negotiable-guarantees)), its grant is a leased subset of the parent's grant (children never widen), and the Workspace still changes only through validated typed effects (per-effect isolation after [in-process file operations](../../docs/specs/tools.md#in-process-file-operations), with commands sharing the admitted primary [publication path](../../docs/specs/tools.md#command-input-selection)).

**Non-goal, recorded with its trigger:** an opt-in "one worktree per Goal where all agents work, one changeset at the end" (brief option c) is deliberately not built now. Trigger to revisit: dogfooding shows parallel editors needing overlapping areas, or a user asks to keep the working tree untouched until review. Per-editor worktrees are rejected (maximum creation, cleanup and merge cost for no guarantee gain).

## Chosen direction

- Simplest sufficient solution: editors reuse the primary's Tool path unchanged (`target: Workspace`), the lease check becomes symmetric at intent admission, editor dispatch enters the existing Workspace checkpoint gate, and the whole private-target protocol is deleted. Reuse the existing admission, journal migration and archive machinery; the changed stored shapes and derived report are explicit additions.
- Linux/macOS: typed editor behavior is common to both platforms; commands share the primary native adapters and their overlay rollout. Both eventually lose private worker targets; S1b2 selects the primary exclusive cache-identity lease for editor commands, replacing assignment-time discard-only shared-read leases.
- Ownership: the reducer keeps leases, dispositions, lineage and verification; the Engine keeps scheduling, waves and settlement; Tools loses the worker transfer phase. Not a new seam.

## Security and resource model

Trust: editor authority is unchanged (lease ∩ parent grant ∩ plan ∩ definition; `unguarded: denied`; no Git, MCP, Skill, network or nested delegation); every editor effect passes the same permission verdicts and delegated hooks under the child identity, now against the live tree, so permission modes that gate primary edits gate editor edits identically (acceptEdits/plan/dontAsk semantics apply per effect, prompts labelled with the child). What changes: an editor's mistake is visible in the Workspace before the primary verifies; covered by checkpoints, `/rewind`, the automatic failure rewind and the primary's mandatory verification. Bounds: per-effect bounds unchanged; the 48 MiB data allowance, chunk reservations and 64/256 MiB image limits disappear with their machinery; lease count and depth unchanged. The security pass ([triggers](../../agents/security.md#security-pass-triggers): Tools, processes, untrusted content) runs in every affected S1 slice against `crates/arany/tests/engine_run/{workspace_security,permissions}.rs` (editor prompts cannot be answered by model or child text).

## Risks and mitigations

- Editor Uncertain now stops the whole Run instead of one actor → honest and rare (parent-sync failure); documented in goals.md; the Goal receipt names the editor and path.
- Two editors racing on build outputs through commands → snapshot changesets are lease-validated and the primary exclusive cache-identity lease serializes primary/editor commands sharing a cache. Today primary commands publish under that exclusive lease; worker commands use an assignment-pinned discard-only shared-read lease, which S1 retires for editors. Busy acquisition refuses without waiting or retry. An out-of-lease changeset publishes nothing; disjoint Workspace leases do not authorize concurrent cache writers.
- Retired types referenced across presentation, ACP, telemetry and serve → exhaustive `Event` matches and the schema snapshot fail to compile or differ; the slice lists consumers by `grep -rn 'WorkerData\|WorkerHandover\|WorkerIntegration\|WorkerView'` at open.
