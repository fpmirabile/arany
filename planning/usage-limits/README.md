## Outcome and scope

One capability: inspect the rate-limit facts actually reported by the selected Provider route, separately from Arany's token accounting. Preserve ChatGPT account-window reporting, confirm whether the admitted public route emits any Codex plan family, and extend the same passive observation → committed attempt → reduced view → `/usage` path to native API keys and admitted custom routes. This serves the harness's usage transparency responsibility; observations never control execution or grant authority.

The two [Terminal follow-ups](../../NEXT_STEPS.md#terminal-follow-ups) are one reporting feature. This plan does not admit another OAuth integration, private usage endpoint, subscription credential, polling loop, paid diagnostic probe, billing switch, quota estimate or automatic wait/resume policy. Existing `/status` plan summaries and `/usage` token totals retain their meanings.

This is a planning change only; no implementation is authorized in this task. The owner decisions below grant a scoped exception to the [freeze](../../NEXT_STEPS.md#frozen-areas) for `UL1` only. `UL2a`–`UL5` add rows to the existing `/usage` pager and touch no subscription route or new terminal view; they need no freeze lift. All other frozen work remains frozen.

## Chosen direction

Ponytail choice: extend the existing caller-owned observation slot and committed attempt records. Reuse native/custom transports, the reducer and report paging. No new crate, service, cache, registry, transport, command or dependency is needed. Provider remains the existing in-process semantic interface with concrete OpenAI, Anthropic, ChatGPT and custom adapters; wire/header/date parsing stays at the Provider edge. Engine owns ordering and settlement, Session owns derived state, presentation owns escaped text and consumes explicit time. HTTP types and raw metadata never cross into Engine policy.

1. Keep ChatGPT `PlanWindow`, strict default-meter selection, exact duration-derived 5-hour/weekly labels and account binding. `UL1` records one bounded debug diagnostics line per authorized ChatGPT response naming only the compiled categories `plan_headers={none|default|other|invalid}` and `plan_events={none|default|other|invalid}` plus bounded counts, gathered at the existing `limits::headers`/`limits::event` boundary. Aggregate response-local counts; never log per stream event or add settlement tracing. Classify invalid recognized metadata before valid default metadata, then other recognized plan families, then none; untrusted meter/header text is never retained. Optimized builds remain diagnostically silent. `/usage` appends `; the admitted route reports no plan windows` to `ChatGPT weekly: unknown (not reported)` once a matching Run on that route has settled with no sample. Use committed Run/route/account facts and no pending attempt; retain invalid-sample reasons and earlier valid windows. The existing `has_unreported_plan_window` checks account-level empty groups only, so additionally scope by Session/Run/model and settlement rather than treating that helper alone as proof. This wording describes the settled report, never guarantees future wire absence. No Event or observation-slot change is needed; D3 owns live incident disposition.
2. Add an optional API sample to `RateLimits`, omitted when absent, leaving existing plan fields and their serialized order/meaning intact. The new `api: Option<ApiLimits>` field uses `#[serde(default, skip_serializing_if = "Option::is_none")]`, unlike the present-or-null plan fields, so existing bytes deserialize unchanged and a default sample serializes to the existing bytes; `valid()` rejects `api` together with `primary`/`secondary`. Existing `deny_unknown_fields` makes an older binary reject a non-default API value, as Execution requires. Use closed dialect and dimension types: requests, tokens, project tokens, input tokens, output tokens, priority input tokens and priority output tokens; name the single row ceiling `MAX_API_LIMIT_ROWS = 7` beside `MAX_RATE_LIMIT_BYTES` in `provider/limits.rs` and derive every use from it. Each row carries independently optional unsigned `u64` limit/remaining counts, normalized reset, receipt time and header source. Keep a closed unavailable reason. No arbitrary labels, maps, header bags, quota strings or invented percentages. API and plan payloads cannot coexist.
3. OpenAI recognizes only its documented header family; Anthropic recognizes only its documented families. Native ChatGPT admits only plan samples. Native API routes admit only their dialect. Custom Responses/Chat Completions parse the OpenAI dialect and custom Messages parses the Anthropic dialect. A custom label remains custom: its OpenAI observed path calls only the `x-ratelimit-*` extractor and never `openai::limits::headers`; the reducer rejects any `primary`/`secondary` plan sample without a ChatGPT route and account provenance, preserving [the current provenance gate](../../crates/arany/src/session/reducer/usage.rs) (lines 186–229), and `UL5` pins both collection and forged-journal rejection. Unrecognized vendor/fast-mode quotas stay `unknown (not reported)`; no fast-mode or priority request policy is added.
4. Parse OpenAI reset durations with checked integer arithmetic: ordered unique `d`, `h`, `m`, `s`, `ms` components, fractional seconds to millisecond precision, no signs/exponents; malformed/unsupported forms are unavailable. Normalize relative resets from the single receipt-clock read. Anthropic accepts validated RFC3339 calendar/time/offset values with bounded fractional seconds; reject invalid dates, leap-second values and out-of-range normalized timestamps. Normalize fractional resets upward to the next whole second and label reset precision as seconds. Reuse [timestamp.rs](../../crates/arany/src/timestamp.rs) calendar ownership; add only the narrow checked conversion required, without libc/timezone dependence. Remaining counters are provider-reported, potentially rounded; do not subtract them from limit or require an inferred utilization.
5. Override `invoke_observed` and `compact_observed` in API/custom adapters; keep plain invocation delegating with a fresh disposable slot. Collect once after destination/secret-header admission and before status/body checks. Native JSON, native SSE and custom streaming/non-streaming paths share their family extractor. The owned slot survives dropped futures; cancellation and retry scheduling keep existing deadlines and facts. The existing bounded retry classifier alone interprets `Retry-After`; report collection cannot schedule a request.
6. Add a separate derived API-limit projection beside plan groups, reusing the reducer's actual route resolution. Key it by Session, Run, role/assignment route identity and model, including pinned saved-account UUID or custom endpoint/evidence provenance where available. Environment-key routes remain scoped to that Run/role; never manufacture a key fingerprint or aggregate API accounts across Runs. Fallback observations belong to `from`; retry observations belong to that attempt's selected identity. Group updates retain earlier valid rows on omission/invalid samples, with explicit latest-report qualification. Replay validates native dialect/route consistency and custom provenance without reading today's profile or credentials.
7. `/usage` adds `API rate limits` rows with reported dimension, limit, remaining, reset and `Last reported` receipt/source; unknown fields remain independent. Retain token groups and separate historical/inherited labels. Apply existing stale/reset/clock-anomaly rules, wrapping/paging and linear completeness. Do not reuse ChatGPT percentage/weekly helpers for counters. `/status` keeps its current short token/ChatGPT summary; the detailed report owns API dimensions.
8. Preserve old Event bytes with the omitted additive field under [Execution's additive-field rule](../../docs/specs/execution.md#admission-persistence-and-recovery), verified for all five enclosing families: `ProviderCallRecorded`, `ProviderRetryScheduled`, `ProviderFallbackUsed`, `ContextCompacted`, `GoalContextCompacted`. No SQLite/Event version change is planned. If implementation cannot preserve those bytes/meanings, stop and revise the plan to include version advances, registered migration steps, source canonicalizers and fixtures in the same slice. Never introduce a runtime old-format reader. Superseded hard-coded API unknown branches are replaced where real facts exist, with unknown retained as the fallback.

Linux and macOS use the same header parsers, UTC arithmetic, Engine/reducer and renderer. No new OS capability, shell, account-root access or native adapter is required. Synthetic CI on both platforms proves common behavior; this plan makes no native terminal, keyring or live quota support claim. Native/live checks remain in NEXT_STEPS.

## Risks and mitigations

- Codex's richer account source can mask the actual direct-route limitation → diagnostic-first ChatGPT gate; retain unknown without an authorized reported value.
- A common model could collapse distinct vendor semantics → closed labelled dimensions, independent fields and dialect-specific edge parsing; no counter-to-plan conversion.
- Old persisted bytes or fallback attribution could change silently → byte-preservation fixtures for every enclosing family plus reopened actual-route/retry/compaction evidence.
- Near-ceiling API slices or growing owner functions → apply the explicit `UL2a`/`UL2b`, `UL4` and `UL5` split rules below before delivery, targeting at most 1,200 changed lines per PR and retaining each flow's own evidence/docs. Use family children at the repository's growth signals. Any changed slice IDs require a plan amendment and matching closing checklist; no ceiling exception is requested.
