## Outcome and scope

One capability: inspect the rate-limit facts actually reported by the selected Provider route, separately from Arany's token accounting. Move ChatGPT-plan inference from `https://api.openai.com/v1/responses` to `https://chatgpt.com/backend-api/codex/responses`, matching Codex CLI and Pi under OWNER DECISION D2 (2026-10-27). Carry that backend's account-window observations through committed attempts and the reduced view into `/usage`, then extend the same passive path to native API keys and admitted custom routes. This serves the harness's usage transparency responsibility; observations never control execution or grant authority.

The two [Terminal follow-ups](../../NEXT_STEPS.md#terminal-follow-ups) are one reporting feature. The backend switch includes request shape, account/session headers, bounded SSE, errors/limits, selected-account renewal and admission fingerprints for Runs, children, compaction and explicit checks. It does not add `/wham/usage`, `/api/codex/usage`, polling, WebSockets, imported harness tokens, a paid diagnostic probe, API-key fallback, quota estimates or automatic wait/resume. Existing `/status` plan summaries and `/usage` token totals retain their meanings. A backend-compatible credential is required; D2 does not establish that existing SIWC grants can be reused or silently authorize a different OAuth client.

This is a planning change only; no implementation is authorized in this task. The owner decisions below extend the scoped [freeze](../../NEXT_STEPS.md#frozen-areas) exception to the proposed `UL1a` backend flow and `UL1b` passive-window reporting, including their contracts and evidence. `UL2a`–`UL5` add rows to the existing `/usage` pager and touch no subscription route or new terminal view; they need no freeze lift. All other frozen work remains frozen.
