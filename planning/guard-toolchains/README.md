# Guard toolchains for daily development

## Metadata

- Status: `Ready` (research and design complete; native support claims require the evidence below)
- Owner: harness maintainers; priority: daily use, macOS first
- Last updated: 2026-10-26

## Outcome and scope

One capability: ordinary folder trust enables the existing installed runtime and read-only package-cache profiles, after showing their exact paths and disclosure, so a guarded primary can run this repository's offline Rust tests on macOS without six independent opt-ins. The owner's observed failure was **macOS**, not Linux. The first deliverable must cover macOS Rust, CLT compiler, physical SDK, Cargo registry and existing compatibility/environment handling together. It must not wait for Linux work.

Change the defaults and consent of the existing feature; do not build a second toolchain feature. Keep Read only initially focused and retain individual profile deselection. Persist the same exact `RuntimeGrant` selections through the same trust record. One library owner computes runtime visibility; one translator per OS enforces it. This serves the harness's existing Tool execution responsibility. Success is executed tests with actual passed/failed/ignored counts, not merely finding Cargo or compiling a fixture.

The [Workspace overlay plan](../command-workspace-overlay/README.md) decides Workspace visibility, Linux overlay/changesets, build-cache storage and CPU/jobs. This plan decides **system/toolchain/cache visibility**, independently of whether the Workspace is copied or overlaid. The [NEXT_STEPS test-IPC item](../../NEXT_STEPS.md#daily-use-first) owns socket-dependent tests; the [network plan](../network-proxy/README.md) owns guarded fetch access. Keep those boundaries. No installer, rustup proxy state, daemon, host fallback, new manager discovery, general host-home read grant, system-Rust profile or custom project-version parser is added.

### Peers, inspected 2026-10-26

- **Codex Linux:** [`create_filesystem_args`](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/linux-sandbox/src/bwrap.rs#L392-L585) starts full-read policies with `--ro-bind / /`, adds minimal `/dev`, rebinds writable roots with `--bind`, then reapplies read-only protected subpaths and unreadable masks. Thus read-only filesystem protection prevents writes; it does not hide private host files. Restricted-read policies already have an alternative: start with `--tmpfs /` and bind only approved readable roots. Its optional system defaults include `/bin`, `/sbin`, `/usr`, `/etc`, `/lib`, `/lib64`, `/nix/store` and `/run/current-system/sw`; they do not implicitly expose home directories. [`BwrapNetworkMode`](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/linux-sandbox/src/bwrap.rs#L105-L125) distinguishes full access, isolated and proxy-only; the latter two unshare networking. The filesystem root bind alone says nothing about network access. This is direct source evidence, rather than a claim that every Codex configuration has identical permissions.
- **Codex protected metadata:** [`permissions.rs`](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/protocol/src/permissions.rs#L40-L52) identifies `.git`, `.agents`, `.codex`, and `.aws` as protected names. Its [default protected subpaths](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/protocol/src/permissions.rs#L2359-L2405) include a Git worktree pointer's resolved gitdir, existing `.agents` and `.aws`, and `.codex` even before creation at the workspace root. These protections are principally write restrictions, not universal secrecy rules.
- **Codex macOS:** the [Seatbelt base](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/sandboxing/src/seatbelt_base_policy.sbpl#L1-L15) begins with `(deny default)` and permits descendant execution under inherited policy. The [policy builder](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/sandboxing/src/seatbelt.rs#L980-L1030) then emits `(allow file-read*)` for full disk read with no unreadable roots. With deny paths it builds an excluded-root read policy; restricted-read policies allow only specified roots and scratch reads. Therefore “Seatbelt denies by default” does not establish that Codex hides home files: the generated read policy determines disclosure.
- **Claude Code defaults:** official [sandbox documentation](https://code.claude.com/docs/en/sandboxing#filesystem-isolation) says sandboxed commands normally read most of the computer, including credentials, while writing cwd, added working directories and a per-user temporary directory. Filesystem deny lists and credential settings restrict those defaults. Its [protected paths](https://code.claude.com/docs/en/sandboxing#protected-paths) deny writes to executable configuration such as Claude settings/skills/hooks, shell startup files, editor directories, and Git hooks/config even within writable roots. This is not a default read barrier for SSH or cloud credentials. The sandbox wraps shell commands; file tools, hooks and MCP have separate execution/permission behavior.
- **Claude source:** the public runtime at revision `98a4016d27609ed34dd1fb43d23ed6efb6eeeb77` [documents](https://github.com/anthropic-experimental/sandbox-runtime/blob/98a4016d27609ed34dd1fb43d23ed6efb6eeeb77/README.md#dual-isolation-model) reads as broad by default and writes as explicit allows. [`FilesystemConfigSchema`](https://github.com/anthropic-experimental/sandbox-runtime/blob/98a4016d27609ed34dd1fb43d23ed6efb6eeeb77/src/sandbox/sandbox-config.ts#L956-L989) exposes `denyRead`, narrower `allowRead`, `allowWrite`, and overriding `denyWrite`. [`generateReadRules`](https://github.com/anthropic-experimental/sandbox-runtime/blob/98a4016d27609ed34dd1fb43d23ed6efb6eeeb77/src/sandbox/macos-sandbox-utils.ts#L860-L929) emits a broad `file-read*` allow then denied regions, narrower exceptions and the denies those exceptions would otherwise erase. [`sandbox-utils.ts`](https://github.com/anthropic-experimental/sandbox-runtime/blob/98a4016d27609ed34dd1fb43d23ed6efb6eeeb77/src/sandbox/sandbox-utils.ts#L17-L50) owns the shell/Git/editor/MCP configuration write-protection names. The public runtime is source evidence for the mechanism, not proof of an unpublished Claude Code embedding revision.

## Chosen direction

### Existing profiles become the reviewed default

Keep the same **Read only / Trust** flow. The library proposes a complete selection from the current detected `Candidate` values; the existing chooser displays those checked defaults, exact paths, versions and package-disclosure warning before the human confirms Trust. Read only remains initially focused, so proposed checks are not authority. Preserve individual deselection and the existing linear selection syntax. Do not add a third Trust-with-tools mode, a bundle flag, a new grant file or a second discovery pass.

Retain a valid saved version when editing existing trust. Otherwise propose a runtime automatically only when its existing kind has one unambiguous detected candidate; multiple Rust/SDK versions use the existing one-version chooser. Rust on macOS proposes its existing AppleCompiler, one physical AppleSdk and the three existing Cargo cache kinds together. A missing prerequisite is reported, never replaced by a parent directory or an alias. Node/Python use their existing runtime kinds and npm/pip cache kinds, with the same rule and no extra manager search. A human can keep an intentionally incomplete/narrow selection; the UI must not label it build-ready. For this repository the compiler to choose is its current 1.98.1 pin; discovery remains metadata-only and does not parse `rust-toolchain.toml` or implement rustup selection. After consent the selected physical compiler is the computation input; repository text cannot add or switch a grant.

This is a default-selection change over the existing runtime feature. It removes six independent macOS opt-ins in the unambiguous installed case, while retaining explicit human consent to all disclosed roots. Provisioned means tools, SDK and complete offline package data already exist and meet current admission; it does not promise installing software on a cold machine.

### One policy compiler, one translator per OS

The common owner takes the admitted existing runtime grants, the compiled platform runtime table, protected-root capabilities, validated native executable facts and the **already admitted Workspace-view descriptor**. It alone computes positive read/exec roots, source/destination relationships, traversal-only ancestors, masks, cache precedence, selected-bin `PATH` and Rust/SDK environment decisions. Platform-specific facts remain necessary, but both platforms' path/operation/default tables are declared in this owner; neither adapter has its own allowlist or RuntimeKind switch.

Compute this normalized value **once for each immutable admitted execution scope** (process or its narrower non-spawning/Git scope), before its intent can execute. Retain it through the existing `ProcessPolicy`/ToolRuntime/Guard Task path: selected grants keep their existing config digest, and the derived plan binds into the existing enforcement digest. A per-effect private path slot refers to the prepared Workspace/scratch/cache/resources; resolving that slot to its attested Linux or macOS path is mechanical placement, not recomputing authority. Reuse the admitted plan for Ready/GO, cache exclusions, environment and receipts. Guard bootstrap validates its bounded shape, digest and host pins; it does not rerun discovery, default selection or authorization. Effect/child subsets are narrowed by the common owner at their admission, never by native guesswork. Replay consumes committed facts without reconstructing a current host plan.

Do not introduce broad `/etc`, `/opt`, Nix-store, Homebrew or Developer-tree grants to fix missing inputs. Any required new root must be supported by the same profile model, added once in the common owner's bounded table, named for its consumer, consented and verified natively on its OS; unsupported layouts stay unsupported. Linux's current `/usr` includes `/usr/local`; this plan does not call it hidden or independently granted, nor add a second prefix policy. Required StateRoot/credential overlap checks still dominate that existing root. Package caches remain explicitly consented potentially private data, not automatically secret-free input.

**Completion invariant:** no runtime read/exec/cache/PATH/mask policy decision remains in `guard.rs`, `linux.rs`, `macos.rs`, macOS storage, presentation or a second config layer. Remove readable-root literals from `PROFILE`, `COMMAND_PROFILE`, `GIT_PROFILE`, and root-selection branches from both adapters; their remaining native process/network/signal restrictions and attestation checks may only enforce/refuse the authorized plan. Different effect categories retain narrower plans and process constraints, but use the **same read-policy translator per OS**. There is never a legacy-vs-new switch, fallback backend or copied policy table. G1/G2/G3 migrate complete flows sequentially; do not claim this final invariant before G3's owner audit closes.

## Security and resource model

**Named security pass: shared runtime visibility and macOS profile consent.** Triggers: changed consent/default authorization, filesystem/exec visibility and native profile construction ([requirements](../../agents/security.md#security-pass-triggers)). Assets: source, packages, state/journal, credentials and host integrity. Boundaries: user-owned trust → shared runtime compiler → committed Engine intent/verdict → authenticated native Guard → bounded result/validated changeset. Attacker inputs: manager entries, repository/config/build scripts, aliases/mounts, cache bytes and Tool output. Only human folder consent to displayed exact roots creates authority; repository text, AI, hooks and native detection output cannot add grants. Child effects compile only from their existing narrower grants and never receive host authority.

Keep current no-follow root identity and executable/signature verification, pin source/destination/operations/masks/environment in the plan digest and revalidate before Ready/GO. Pinning directory device/inode does not freeze contents or establish supply-chain trust. Native validation can refuse unsupported protections but cannot add roots or reclassify reads as authority. Linux private propagation/read-only mounts and macOS physical positive Seatbelt rules keep their existing native differences, including macOS mount checks being point-in-time rather than lifetime isolation. No socket/Mach/sysctl or network widening. Existing helper bytes, entitlement constraints, cleanup, failed-command publication rules and Uncertain handling stay intact.

Keep discovery bounds (64 candidates, 128 entries per manager directory, 11 selected runtime/cache roots), trust-record count/bytes, Task size and system-program catalogue limits at their [current owners](../../crates/arany/src/tools/toolchains.rs). The derived value is bounded by the selected grants plus the fixed common system table and existing checked executable catalogue, deduplicated and rejected on overflow under existing caps; no unbounded closure walk. Reuse copies/arrays already carried by admission instead of duplicating a second catalogue inside Task. No cache scan/copy, subprocess, package fetch or config read during consent. Existing Tool/Goal memory, storage, processes, time, output and aggregate cache budgets are unchanged; every native change keeps meaningful limit/cancel/cleanup evidence.

Defaults do not modify saved selections or schema: **no trust-record migration or journal payload bump is required**. Derived access policy is transient and bound into existing digest fields; remove superseded internal rule construction with its replacement. Changing this design to add stored authority would require a separately justified migration and fixture. Consent still precedes credential/catalog and Session access; discovery failure continues read-only startup with a notice. StateRoot/account/credential paths and inherited auth sockets never become visible through a runtime grant. Selected cache data may disclose through permitted bounded output; existing same-user host-state and non-tamper-evidence limitations remain unchanged.

## Risks and mitigations

- Trust appears to enable builds but omits CLT, SDK or registry data → G1 proposes the existing complete macOS dependency set and tests actual repository execution; missing or ambiguous candidates are explicit.
- Policy consolidation leaves an adapter-local read exception → compare compiled entries with native mounts/rules, remove old lists per flow, and close G3 only after an owner audit finds no residual root/default/RuntimeKind decisions outside `toolchains.rs`.
- Native path aliases, SDK/compiler changes or cache replacement expose siblings → reuse existing identity/mount/signature owners, deny overlapping roots before GO and run sensitive canaries against the emitted policy; never refresh a pending pin.
- Private Workspace copies or native builds exceed existing limits → attribute the exact input/storage failure to that owner; do not add host execution, change copy visibility or enlarge budgets here. A fixture pass cannot substitute for G1 repository evidence.
- Bundled defaults hide data disclosure → keep Read only initially focused, show all paths and cache warning, permit deselection, and never upgrade remembered folders automatically.
