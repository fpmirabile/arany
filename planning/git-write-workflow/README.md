## Outcome and scope

One feature: **commit, branch, push and open PRs from Arany like peers**. The harness owns the complete coding handoff, from a local change to a reviewable PR, with durable approvals, honest outcomes and non-executing replay. Each of the three slices is one PR and delivers a usable increment; none requires a Guard network proxy first.

Version 1 supports ordinary repositories in the layout admitted by [typed Git reads](../../docs/specs/tools.md#typed-git-reads), local commits, branch creation and safe switching, non-force push, and explicit GitHub PR creation. Linked worktrees, submodules, signing, branch deletion, history rewriting, force-push, arbitrary Git/gh flags and automatic retries of writes are outside this feature. This worktree's layout is not evidence that the product supports linked worktrees.

Owner decisions, recorded **2026-10-21**:

- Git writes work like peers. The owner wants the workflow working first; additional protections are separate work, not prerequisites invented by this plan.
- **Approved:** add the second per-effect-isolation exception quoted below for typed `git_push` and `gh pr create`. They run on the host with inert Git configuration, always require a human even in Auto, refuse when no human channel is available, and have their own journaled execution class marked `host`.
- Lead defaults: rules come only from user-owned configuration, never repository files; no commit signing in v1 because `gpg.program` is an execution vector; user rules may pre-approve commits because commits run inside the Guard.

These decisions supersede the conflicting proposals in [agentic teams E6](../agentic-teams/README.md#e-goal-lifecycle-and-terminal): host execution of local writes, repository rules authorizing commits, and later opt-ins for disruptive writes. That plan is not edited by this task. Convention guidance from repository text remains untrusted data and supplies no authorization.

## Chosen direction

Use the existing typed Git, permission, shared step, Guard, changeset and reducer paths. Add closed operation variants and publication data; no new crate, daemon, plugin framework or generic executor trait. Engine owns policy, ordering and Goal accounting; Tools owns normalized schema, pinned executable/view and receipts; Guard owns local execution and validated publication; the reducer owns canonical state; Store owns persistence/migration. The CLI translates user settings and human replies at the edge and projects committed results. Git/gh process output and API shapes never become Engine policy types or authority.

Local schemas are `git_commit {message, paths, staged}`, `git_branch {name, start_point}` and `git_switch {branch}`. A commit selects exactly one of nonempty literal `paths` or `staged: true`; selected paths commit their captured working contents and leave unrelated index entries intact, while staged mode commits the captured index. Branch creates only; switch selects an existing local branch and refuses any overwrite conflict. Revision/path syntax follows the admitted Git-read grammar and path exclusions; no raw argv, shell, amend, delete, detach, force, signing or caller-supplied `-c` escape exists. Commit identity is admitted name/email data from user-owned configuration, never repository config; missing identity refuses with a settings action.

For local writes, use a fresh Guard-private mutable Git view with fixed configuration, `commit.gpgSign=false` and copied metadata. Existing objects may be read-only backing data; newly written objects, refs and index must stay private until publication. Never make the current read-view links writable. Capture switch's Workspace delta too. A bounded publication manifest pins before/after digests for the real `.git` and affected Workspace files. Publish new objects first, then validated ref/HEAD/index and file changes through the Guard's receipted publication path, using Git locks, the Workspace writer permit and fresh handle-relative validation. No Git process runs against live repository configuration. Multiple filesystem updates are not promised atomic: an interrupted publication is classified from durable phase/receipt evidence or remains Uncertain, without automatic completion or rollback of unknown effects.

Host schemas are `git_push {remote, branch}` (one explicit local branch to an explicit remote branch, no deletion/force) and `gh_pr_create {repository, base, head, title, body, draft}`. The latter is the typed representation of `gh pr create`. Generate fixed argv with explicit `--repo`, `--base`, `--head`, `--title` and `--body`; no editor, browser, automatic fork or implicit push. Pin repository/base/head and payload before approval. Push and PR creation are separate effects with separate human approvals.

Linux local Git is pinned `/usr/bin/git`. macOS uses the admitted Command Line Tools Git, not the `/usr/bin/git` xcrun shim, following the [platform pin contract](../../docs/specs/tools.md#typed-git-reads). Both use fixed argv/config, `hooksPath=/dev/null`, a closed environment and offline Guard execution for local writes. Host operations need equivalent executable and configuration admission on both systems; `gh` must be explicitly pinned, never selected by PATH or project files. Existing unsupported Git layouts remain unsupported. Native filesystem locks, process teardown and signing/keychain interactions require Linux/macOS evidence before support claims; this documentation task establishes none.

## Security and resource model

The security pass is triggered by new mutation/publication, permission and durable-record behavior in S1/S2, and network, credential and host-process behavior in S3. Assets are repository objects/refs/index and files, user approval records, GitHub identity/tokens, remote repositories and journal integrity. Attacker-controlled inputs include repository config/attributes/objects/ref names, model arguments, PR text and process/network responses. None supplies authority. Admit user-owned settings, directory/executable identities and bounded schemas before project input can influence execution; revalidate pins before dispatch/publication. Hooks/reviews may narrow only. Version 1 offers these Git writes only to the primary; children neither receive these operations nor inherit prefix/remembered approvals.

**Exact AGENTS.md amendment, approved by the owner on 2026-10-21; land only in S3.** In the Per-effect isolation bullet, replace the final two sentences beginning “The only exception:” with:

> The exceptions are: a per-command run outside the Guard that the user approves after a sandbox-caused failure, never automatic, journaled and marked unguarded; and typed `git_push` and `gh pr create` operations on the host with inert Git configuration, always human-approved, including in Auto, refused when no human approval channel is available, journaled as a separate execution class and marked host. Other guarantees still apply.

The rest of that bullet and the other guarantees remain in force. Host Git and Git subprocesses invoked by gh still use a neutralized private view; this preserves “Git runs only on a neutralized private view” in the Safe AI cage bullet. The exception does not enable a generic host shell, convert approval rules into grants, or require a prior sandbox failure for the two new typed operations. It does not label host execution as Guard-attested.

**Inert configuration and disclosure.** For both sites, clear the environment and disable system/global Git configuration; generate the entire private config from admitted data. Host Git additionally receives `-c core.hooksPath=/dev/null`. Merely adding `-c` to a live-repository run is insufficient: never honor repository `include`/`includeIf`, `core.sshCommand`, `url.*.insteadOf`, `remote.*.pushurl`, credential helpers, executable filters, aliases, pagers or signing programs. Use read-only object/ref backing for push and prevent incidental updates to real repository metadata; Git/gh must not discover the live `.git/config`. Do not load user-global Git configuration wholesale either: import only admitted identity, destination and, once decided, authentication fields as data.

Remotes come from user-owned config or a fresh explicit approval displaying the exact normalized URL, never from repository config as authority. Reject credential-bearing URLs, local/file/ext transports and ambiguous routing; any selected HTTPS/SSH transport must have an admitted authentication path. Bind the URL, repository and refspec into the immutable intent and approval; a changed URL or head requires a new intent. Do not promise hostname/DNS network isolation on the host. No ambient credential/proxy environment, interactive credential prompt or credential bytes enter Provider input, journal, diagnostics or output. User-approved credential/auth adapter choices remain S3 questions below; a missing adapter refuses, never falls back to arbitrary helpers or `gh auth login`.

**Rules and modes.** Store typed prefix rules in the private user-owned permissions surface, with directory identity binding for folder-specific entries. Match exact token prefixes of the canonical semantic command (`git commit`, `git branch`, `git switch`, `git push`, `gh pr create`) only after validating the closed schema; adapter-inserted security flags are fixed, not matchable escape hatches. Require a complete verb prefix; no glob, shell splitting, wrapper stripping, arbitrary flag or `sh -c` interpretation. Deny > ask > allow; grants, schema validation and execution class remain independent restrictions. “Always allow” for local writes saves the displayed typed prefix for the next Run. Generic unguarded approvals remain exact and failure-gated; old raw-command rules are not automatically promoted into typed authority. Display and edit/remove typed rules in `/permissions`, including scope and human-only host status, with atomic saves and pinned Run digests.

| Effective mode/channel | Local guarded writes | Typed push / PR creation |
|---|---|---|
| `default` | User allow can pre-approve; otherwise human Ask. | Human Ask even when a rule allows. |
| `acceptEdits` | Treat these process mutations as commands: human Ask. | Human Ask. |
| `auto` | Existing process-review semantics apply; allow does not skip review; uncertainty asks a human. | Human Ask; never AI review in place of a human. |
| `plan` / `dontAsk` | Plan denies writes; dontAsk permits only an otherwise pre-approved local action. | Denied. |
| Headless without human channel | Proceed only with a pinned grant and resolved local approval; unresolved Ask denies. | Refused, including with allow rules or upfront grants. |

An explicit deny always denies; an explicit ask always requires a human. A human-capable serve adapter can carry a one-use host approval; a channel unable to attest a human, including the current [ACP human-only restriction](../../docs/specs/tools.md#modes-and-approval-decisions), refuses it. Cancellation, expiry, dropped replies and failed rule saves dispatch nothing. Saving a rule cannot approve the current action implicitly. Host prompts offer once/deny, never “always allow host execution.”

**Declared v1 bounds.** Retain the existing Guard/Goal/storage ceilings without raising them for this feature. Limit local input/publication to 2,048 files, 1 MiB per Workspace file and 32 MiB aggregate captured content; cap new Git objects plus metadata at a separate 32 MiB per effect, including a 32 MiB index maximum. Reject excess before publication, never truncate a changeset. Commit message, PR title and PR body caps are 8 KiB, 256 bytes and 8 KiB; at most 128 paths, 128-byte revision/branch names and a 2 KiB remote URL; reject controls and malformed data. Typed rules share a 128-rule total and 64 KiB settings ceiling; reject oversized or unknown schema fields atomically. Source anchors for existing local ceilings: [types.rs:24](../../crates/arany/src/tools/types.rs#L24); the additional field/object limits here are proposed v1 choices.

At most one Git write/publication per Workspace is in flight; use existing bounded scheduling, not another queue. Local runtime is at most 20 seconds and host runtime at most 600 seconds, narrowed by the pinned action/Goal budget. Keep at most 256 KiB stdout and 4 KiB stderr, fit model observations to the existing result budget, and terminate on overflow. Reserve bounded journal/storage headroom before starting, including manifest, private objects and receipt. Zero automatic write retries. Host process supervision owns timeout, cancellation, pipe draining and group kill/reap; unknown remote outcome or unconfirmed termination is Uncertain. The host exception does not enforce Guard filesystem/network/CPU/memory/process-count isolation, bound remote storage/transfer volume, or guarantee containment of descendants escaping the process group; time/output limits and human approval are the v1 controls. Further hardening requires its own scope, not a proxy prerequisite for S3.

## Risks and mitigations

- Private-view links could turn a local write into a live mutation → separate mutable metadata/new-object storage from read-only backing, then validate and receipt publication. Switch includes Workspace files, not only `.git`.
- Partial publication or a lost network reply could look like success or invite a retry → journal before each effect/publication phase, acknowledge receipts before continuation, and stop with Uncertain whenever the result cannot be proved. Never claim transactional rollback across Git and Workspace files.
- A prefix could authorize dangerous flags or a repository could redirect credentials → match only validated closed-schema tokens; inert private configuration and explicit URL/repository approval are mandatory v1 behavior.
- A new Event shape could discard dogfood history → S1 depends on #233's `store::migrate` framework and ships the migration and fixture required by [AGENTS.md rule 5](../../AGENTS.md#global-rules). Rebase version numbers on the implementation base; do not add compatibility readers or rely on archive-only handling for a migratable bump.
- Existing E6 text can mislead a future implementer → this plan explicitly supersedes its conflicting Git proposals; implementation contracts in tools.md/execution.md become authoritative as each slice lands.
