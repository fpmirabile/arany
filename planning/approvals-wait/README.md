# Approvals wait for the human

## Metadata

- Status: `Ready`
- Owner: Fernando Mirabile
- Last updated: `2026-10-22`
- Next action: implement non-host A1 now, then A2; host A3 follows A1 once [Git S3, PR #279](https://github.com/fpmirabile/arany/pull/279) merges.

## Outcome and scope

A pending human approval remains answerable for as long as its live human channel and operation remain valid. Reading a prompt slowly must not deny the operation. This covers terminal, serve/ACP, primary/child Tools and host approvals. [Rewind confirmation](../rewind-confirmation/README.md) is a separate feature and plan. Execution, capacity admission and cleanup remain bounded; cancellation and loss of the channel still stop work. [Failure feedback](../failure-feedback/README.md) separately delivers explanations and model continuation after denial.

### Peer behavior

| Source | Verified behavior and implication |
|---|---|
| [Claude Code Remote Control limitations][claude-wait] | Permission prompts and AskUserQuestion stay open until answered. The five-minute timeout in the same documentation applies to other forwarded dialogs. The local process must remain running; tmux/screen can preserve it across SSH disconnect. This supports indefinite ordinary human approval waits, not durable approval after process death. |
| [Claude interactive controls][claude-keys] | Ctrl+C interrupts the current operation. Cancellation is not a negative approval that silently authorizes a replacement operation. |
| [Codex command and patch approval wait][codex-wait], commit `61f34c35af77777db4d77d0ea2aeb8547a6b4523` | Both register a one-shot reply and await it without a wall-clock timeout; a dropped reply becomes Abort. [Approval overlay][codex-interrupt] handles Ctrl+C by cancelling and clearing queued requests; its [Escape handler][codex-escape] invokes the same cancellation path before decline shortcuts. |
| [Codex stdio shutdown][codex-stdio] and [connection removal][codex-detach] | Closing stdio exits the server loop. Daemon/WebSocket disconnection has different semantics: connection bookkeeping is removed, and [pending requests can be listed][codex-pending] for reconnection. Arany has a live terminal/stdio boundary, not that daemon lifecycle; do not copy reconnect persistence without its owner. |

Claude's closed-source implementation is not available for a universal timeout claim. Its [special critical-path removal confirmation](https://code.claude.com/docs/en/permission-modes#time-limits-and-denials-in-auto-and-bypasspermissions-modes) has a two-minute countdown in auto/bypass modes, cancelled by any keypress; explicit ask rules do not time out. Arany has no equivalent bypass path, and its owner explicitly requests no wall-clock expiry while a human is attached. The common ordinary-prompt behavior above is sufficient; no secondary harness or new dependency is needed to choose it.

## Chosen direction

All decisions below were made **2026-10-22**.

| Decision | Basis |
|---|---|
| **A-D1:** Human approval has no wall-clock expiry, including host confirmation; rewind is owned by its separate plan. No TTL setting, keepalive, periodic renewal, maximum-date sentinel or automatic approval. | Owner; ordinary-prompt peer parity [Claude][claude-wait], [Codex][codex-wait]. |
| **A-D2:** A live tmux/screen PTY or suspended process keeps its pending request; actual EOF, SIGHUP/shutdown, lost terminal input/output, turn cancellation or connection close withdraws it. Ctrl+C and Escape in an approval prompt cancel the Run; explicit No/Decline rejects only the proposal. Never restore live authority on restart/replay. | [Peer controls][codex-interrupt] and [Escape handler][codex-escape], [Claude process lifetime][claude-wait]; Arany [execution/recovery](../../docs/specs/execution.md#admission-persistence-and-recovery). Loss-of-channel refusal deliberately differs from Codex daemon reconnection because Arany has no durable human-channel ownership/reconnection contract. |
| **A-D3:** Commit intent, then the correlated approval disposition, then validate dispatch admission. Late, duplicate, unsent, cancelled or foreign replies cannot act. Revalidate the original pins and preconditions immediately before dispatch/GO; changed facts refuse, never silently refresh or broaden what the human saw. | [Journal-first and per-effect isolation](../../AGENTS.md#non-negotiable-guarantees), [Tools admission](../../docs/specs/tools.md#authority-and-effect-admission). Removing time invalidation cannot remove drift detection. |
| **A-D4:** Use finite operational queue/preparation/execution windows independently of the immutable intent's lifetime. Approval wait alone consumes no active budget. For delegation, replace issue-time deadline consumption with remaining active allowance: idle human wait pauses it; sibling Provider/effect work still consumes it and may cause a real budget/delegation stop while the ask is pending. Re-evaluate accounting on every sibling start/settlement, not from a sampled entry/exit boolean; the detailed rule below owns withdrawal. | [Goals accounting](../../docs/specs/goals.md#worker-accounting-and-verification), [researcher bounds](../../docs/specs/execution.md#researcher-children). Guarantee-driven retention of resource bounds, not a hidden prompt TTL. |
| **A-D5:** No human channel means immediate refusal of an Ask; no infinite headless wait. `exec` keeps explicit grants, serve needs its owning connected client, and ACP retains restricted human-only capability. | [Serve human channel](../../docs/specs/serve.md#server-requests), [ACP permissions](../../docs/specs/acp.md#tool-updates-and-permissions), [Tools modes](../../docs/specs/tools.md#modes-and-approval-decisions); owner requirement. |
| **A-D6:** Use one current intent/protocol shape, without saved-default conversion or compatibility readers. Apply the repository's required payload-version/migration fixture discipline for changed stored shapes; migration cannot create a live approval. | Owner: no users or legacy-default preservation; [format discipline](../../AGENTS.md#global-rules), [journal migration](../../docs/specs/execution.md#journal-migration). |

Engine owns request lifecycle, budget/cancellation arbitration and journal ordering; the reducer validates terminal dispositions and one-use effects. Tools/Guard own pinned resource validation and operational deadlines. Terminal, serve and ACP translate replies and withdrawals at their existing edges; wire/terminal types do not enter policy. Keep these in-process seams and the existing separate Guard/host boundaries; no new crate, service or dependency. Errors distinguish decline, cancellation, channel unavailable/disconnected, stale pins and capacity timeout. [Tool continuation](../failure-feedback/README.md) owns their detailed user/model projection.

Linux and macOS share policy. Both native Guard queues and signal/terminal adapters need implementation evidence; this research makes no new native support claim.

### Delegated pending-ask lifecycle (A2)

**Decided 2026-10-22 (Goals accounting):** the current [step.rs:1805](../../crates/arany/src/engine/run_loop/step.rs) samples `providers_idle()` once; [ledger.rs:601–610](../../crates/arany/src/engine/ledger.rs) checks again when excluding the whole elapsed interval. Both miss an idle → active → idle sibling interval. Replace that approximation with transition-driven interval accounting under the existing Engine coordinator. Recompute on every Provider reservation/settlement and active effect/preparation/cleanup transition; count overlapping active work once, exclude only genuinely idle approval intervals. Use bounded state-change notification plus a timer for the *remaining active delegation/Goal allowance while work is active*. No periodic polling or heartbeat is added. Process suspension without active work spends no allowance.

When sibling work consumes the shared delegation allowance or finite Goal allowance while a child waits, the coordinator withdraws that ask immediately, journals a non-dispatched observation with the delegation/Goal cause, and records the existing worker/Run stop facts as applicable before any dependent work. It is not `PermissionSource::Human` denial. Cancellation/pause and budget exhaustion win over an accept observed before dispatch; every accept rechecks live allowance. A child deadline remains a delegation limit, not automatically `GoalFinished.exhausted`; only Goal arithmetic can close the Goal as exhausted.

**Scenario:** gate a child ask while idle, start a sibling, settle it, then accept: only its active interval is charged. Repeat with a sibling consuming the remaining allowance before the human responds: the child request is withdrawn without a human reply, no child effect dispatches, the late allow changes nothing, and terminal/serve/ACP/reopened facts name delegation or Goal exhaustion correctly. Exercise idle → active → idle, active → idle → active, overlapping siblings and an accept/exhaustion race through [worker journeys](../../crates/arany-cli/tests/guard_runs/worker.rs), [ledger tests](../../crates/arany/src/engine/ledger/tests.rs) and protocol corpora.

## Security and resource model

The security pass is triggered by approval, capability, transport and stored-shape changes. Assets are Workspace/remote effects, approval identities, private journal integrity and paid usage. Model calls, repository bytes, client replies and displayed text remain untrusted; only the admitted human channel resolves an Ask. Startup directory/grant admission still precedes disclosure. Children keep the parent intersection; no new credential or network path is introduced, and diagnostics must not reveal credentials, raw commands or undisclosed paths.

**Held while waiting:** Session and lineage locks remain held for the live Run, as do the admitted Workspace writer lock for write-capable Goals and editor leases across waves ([Goals lifecycle](../../docs/specs/goals.md#lifecycle-budgets-and-recovery), [worker accounting](../../docs/specs/goals.md#worker-accounting-and-verification)). The coordinator retains bounded worker base/overlay/handover data and the one pending ask. Under the [current architecture](../../docs/architecture/system-overview.md#2-runtime-architecture), native worker filesystems/processes are disposable per effect, not assignment-long sandboxes: the pending Tool starts no private process/sandbox and takes **no Guard FIFO position or execution capacity until after its committed approval verdict**. Already active siblings retain only their own bounded process/sandbox until cleanup; their activity continues to count. Waiting adds neither a native worker nor a heartbeat. Cancel/pause settles work and releases Run locks normally; the indefinite lock lifetime while a human waits is intentional, never bypassed by another writer.

**Unsent is not declined:** if a full outbound queue keeps a request unsent, keep bounded pending state while the channel remains live. If delivery becomes impossible or that unsent request is withdrawn, record `channel_unavailable` delivery status, not human Decline; preserve a stronger cancellation/Goal/delegation stop cause separately. A transport enqueue is not proof of human receipt. Only an explicit correlated decline response can be attributed to the user; no response, invalid/error reply, oversized unsent request and output closure cannot. Withdrawal and journal completion stay independent of output capacity.

One pending Tool per Run, the one-slot approval inbox, one pending protocol permission, existing bounded queues/lines, Event/Store headroom and finite action bounds remain. Waiting holds bounded state and emits no periodic Events. Overflow refuses without evicting or approving another request. Backpressure never holds cancellation behind output. Time-independent approval supplies neither perpetual authority nor stale-pin permission; dispatch requires the same live Run, unused verdict and validated capability. Unknown outcomes stop continuation without retry. Do not claim human gesture attestation from ACP, network isolation for host operations or support from a source review alone.

## Risks and mitigations

- Removing only a UI timeout leaves hidden dispatch expiry → the inventory is the implementation removal checklist, including PR #279 and rewind.
- Delegation wait accounting grants free sibling work → explicit overlapping-work tests and a shared active allowance, not blanket deadline extension.
- Long-lived request accepts stale authorization → lifecycle-bound one-use reply plus immediate pin/precondition revalidation; no automatic refresh.
