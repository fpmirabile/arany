# Portable compaction

## Metadata

- Status: `Ready`
- Owner: Arany maintainer
- Last updated: `2026-10-22`

## Outcome and scope

Admit an otherwise conforming custom Provider without requiring provider-enforced JSON-schema summaries. Use one bounded plain-text compaction format through the existing Responses, ChatGPT and Messages adapters, preserving durable context, exact destination admission and non-executing replay.

This removes the compaction blocker for DeepSeek API and GLM Standard API Messages routes; it does not certify their live compatibility. Custom primary/child use remains read-only, without Workspace Tools or images. Strict Tool-review verdicts, subscription authorization, budgets and routing retain their separate contracts. No Chat Completions adapter, vendor-specific adapter, new dependency or remote compaction service is included.

## Research

Checked 2026-10-22 against checkout `5b6b071b60500e9379316578d8e419ca97bdb014`, official documentation and the immutable peer revisions below. Documentation establishes capabilities, not successful paid calls. No live Provider or native-platform checks were run.

### Why Arany requires schemas today

The answer to the owner's question is **no: these Providers do not support only JSON**. Their JSON/SSE transport envelopes can contain ordinary assistant text. JSON mode, schema-constrained output, tool selection and strict tool arguments are different capabilities.

- The [original D-04, 2026-09-29](https://github.com/fpmirabile/arany/blob/63719315ea3a00ac17e39061d38c25232990270d/docs/research/next-step-decision-register.md#d-04--provider-seam-and-profiles) explicitly preferred provider-enforced JSON Schema, allowed synthetic outcome tools only with strict arguments and forced selection, and rejected prompt-only substitutes. It was an adopted output-conformance policy, not an API limitation. The record does not establish that implementation convenience was the motivation.
- Current [D-02/D-04/D-05](../../docs/research/next-step-decision-register.md#d-02--durable-session-model) require derived compaction, semantic Provider boundaries, exact conformance and canonical Events. [PR #189](https://github.com/fpmirabile/arany/pull/189) already moved ordinary agent answers to text and automatic tool choice; [Provider encoding](../../docs/specs/provider.md#structured-outcomes-and-tool-encoding) retains schema output for compaction and review.
- [PR #251](https://github.com/fpmirabile/arany/pull/251) reused Messages for custom routes while retaining strict compaction. Its [nonce fix](https://github.com/fpmirabile/arany/commit/e2c350553c16545702588d2902163f338a56a75b) distinguished schema enforcement from plausible prompt-generated JSON: a fresh nonce appears only in the schema and must be returned exactly. The [current gate](../../docs/specs/provider.md#custom-destinations-and-routing) applies before *any* custom-role admission, including primary/child.
- None of the [five guarantees](../../AGENTS.md#non-negotiable-guarantees) requires a model-authored summary to be JSON. They require committed transitions, bounded untrusted data, preserved uncertainty, authority isolation, budget accounting and replay without execution. A schema constrains shape; neither a schema nor its nonce probe proves summary truth, completeness or injection resistance. The current spec's attribution of schema enforcement to the guarantees is broader than necessary and must be corrected when implementing this plan.

The implementation already separates narrative from authority: [wire decoders](../../crates/arany/src/provider/anthropic/wire.rs) extract `SummaryEnvelope.summary`; [Engine classification](../../crates/arany/src/engine/compaction.rs) checks bounds/usage and computes the content digest; [Session compaction](../../crates/arany/src/session/compaction.rs) validates exact source coverage and references. Stored summaries are strings, not saved provider JSON. [Rendering](../../crates/arany/src/provider/render.rs) labels them untrusted. Manual/automatic boundary compaction and [in-Run Tool compaction](../../crates/arany/src/engine/run_loop/tool_compaction.rs) share these semantic results, but have distinct source projections; preserve both.

| What the schema bought | Replacement or retained protection |
|---|---|
| Closed-shape parsing: `SummaryEnvelope` denies unknown fields; the [Responses wire corpus](../../crates/arany/src/provider/openai/wire/tests.rs) rejects an extra field and the [Messages decoder](../../crates/arany/src/provider/anthropic/wire.rs) parses the same closed shape. Byte limits were separate local checks. | One complete summary text block, valid completion/stop, no tool call or refusal, and the 8 KiB local cap. Preserve adapter framing: Responses text parts form one final assistant message; Messages uses `single_text`. |
| Exact route proof: the [schema-only nonce](../../docs/specs/provider.md#custom-destinations-and-routing) detects a route ignoring the requested schema. | The text-compaction probe below verifies the selected route's replacement contract, not schema enforcement. Current [D-04](../../docs/research/next-step-decision-register.md#d-04--provider-seam-and-profiles) demands exact data-free conformance, not a particular schema. |
| Injection resistance | The schema never provided it. [Rendering](../../crates/arany/src/provider/render.rs) retains `session_summary (untrusted, model-authored)` inside a JSON `data_block`; authoritative facts remain typed. |

## Chosen direction

| Alternative | Assessment |
|---|---|
| Require strict conformance only for compaction-role routes | Can unblock primary/child with a separately admitted compactor. Review still needs its own verdict contract. Adds role-scoped capability evidence and admission logic, requires a second conforming route for these vendors, and leaves single-route defaults unusable. Valid containment option, but unnecessary when summaries already have a text semantic type. |
| Forced summary tool, locally validated | Adds a wire branch and model/mode exceptions; not the documented common denominator. Local validation remains necessary. Reject. |
| One plain-text summary format | Matches Codex's portable path and Pi/OpenCode's ordinary text mechanism; reuses existing adapters and stored strings. **Recommended.** |

Omit response-schema and tool-selection fields for this operation, retaining unrelated effort/cache/privacy fields. Keep summary guidance about decisions, results, unresolved objectives and uncertainty; headings are optional prose, not a new parser grammar. No selectable format, JSON fallback or provider-native opaque snapshot.
2. **Decided 2026-10-22 (peer parity: ordinary completion above; guarantee constraint: D-04 exact admission):** retain `provider check`, replacing only its strict-schema summary probes with real text-compaction probes for the default and every declared effort, as specified below. Advance check-contract fingerprints; earlier check-contract evidence is simply refused, never converted into new capability evidence ([current admission rule](../../docs/specs/provider.md#custom-destinations-and-routing)). Also bump ChatGPT's separate account-admission contract for the request/decoder change, as its [contract requires](../../docs/specs/chatgpt.md#authorization-transaction). Do not turn native optional diagnostics into mandatory admission.
3. **Decided 2026-10-22 (peer parity: Codex/Pi completion checks; guarantee constraint: bounded accepted outcomes):** accept only complete, non-whitespace summary text within existing limits. Preserve the accepted text bytes; whitespace detection does not trim them. Reject unexpected tool calls, refusal blocks/stops, incomplete/unknown stops, invalid required usage, model drift, reflection and oversized output. Reuse `CompactionFailure::InvalidOutcome` and existing Provider-error mappings; malformed completed output must not become a retryable transport failure. Reasoning blocks retain existing adapter handling and never become the summary. JSON-looking prose is ordinary text, never parsed or repaired. A fluent but inaccurate summary cannot be identified reliably by syntax checks.
4. **Decided 2026-10-22 (owner: retain all five guarantees):** reuse reservations, typed failures, summary Events/digests and strict replay. A rejected completed summary gets no corrective call, format switch or implicit destination change. Keep existing explicitly configured, bounded and journaled transport retry/fallback predicates; they are not summary repair. Never retry an uncertain Workspace effect or resume inference during replay. Preserve the last good snapshot and canonical history on failure.
5. **Decided 2026-10-22 (peer parity: shared Messages integration; scope constraint: existing Provider contract):** use existing exact custom routes, with no vendor special case. 6. **Decided 2026-10-22 (owner: no legacy-default preservation; implementation choice grounded in the record validator):** retain `CompactionRecord.prompt_version = 1`, `schema_version = 1` and `compiler_version = 3`. They continue to identify the local summarization task, semantic summary schema and source projection; none is a copy of the HTTP schema or proof of remote enforcement. The saved summary string, source/content digests, wire-provenance enums, account provenance and output-bound meaning remain unchanged. `ContextCompacted` payload version 7 and `GoalContextCompacted` payload version 6 also remain unchanged. The [record validator](../../crates/arany/src/session/events/records.rs) still accepts these values and rejects other versions. The existing [subscription_compaction_pins_account_and_weaker_bound](../../crates/arany/src/session/events/tests.rs) validates the `(1, 1, 3)` record; extend its table to pin all three version fields explicitly, and retain [subscription_account_and_local_bound_survive_run_and_compaction_replay](../../crates/arany/tests/engine_run.rs) for persisted provenance. Clarify this local-schema meaning in the Session contract when implementing. No stored format changes, so no migration is required here. The owner's instruction removes speculative legacy-default work; it does **not** waive [AGENTS.md rule 5](../../AGENTS.md#global-rules). Any implementation change to a stored format/version must ship its registered migration step and fixture before proceeding; no relabelling old provenance or compatibility reader.

### Text-compaction probe

Use the existing synthetic conversation and production `compact` encoder/decoder, with no Workspace data, credentials in prompts, retry, extra call or alternate encoding. For the default and each declared effort, require a completed response (`completed`/`end_turn` as appropriate), one non-whitespace summary, no tool call/refusal, exact model match, valid required usage within the route's cap, no raw or decoded selected-credential reflection, and at most 8 KiB of summary text. Retain response-ID checks, transport/body limits, aggregate deadline and clear-before-check/publish-only-after-all-success evidence handling. Synthetic-server fixtures must inspect the request and assert that response-schema fields, `tools`, `tool_choice` and `parallel_tool_calls` are absent; effort/cache/privacy fields remain allowed.

**Decided 2026-10-22 (same D-04 conformance scope): no fixed-token echo liveness check.** A complete bounded response to the actual summarization request already demonstrates response liveness. An echo tests a different instruction, can be satisfied by a canned response, and establishes neither summary quality nor schema enforcement. Keep the real summary probe; deterministic fixture responses may be fixed, but live admission must not require an exact summary string.

Ponytail choice: remove the redundant summary JSON envelope in the existing encoders/decoders; keep `Provider::compact -> CompactionResponse` and the Engine classifier. No new seam, trait, crate or configuration field. Linux/macOS use identical code and policy; this introduces no OS facility or native-support claim.

## Security and resource model

The [security pass](../../agents/security.md#security-pass-triggers) is triggered by changed prompts, Provider output admission and replay-to-context behavior. Assets are Session content, credentials, paid usage, journal space and effect authority. Model output, old summaries and HTTP bodies are hostile data. Only admitted user/process configuration chooses credentials, endpoint, model and role before Workspace input; normalized route/request bounds remain pinned. No extra disclosure, Tool authority or descendant grant is introduced.

Ownership stays at the existing in-process Provider seam: real Responses, subscription and Messages adapters translate wire data; Engine owns admission, calls, budgets and acceptance; Journal/Store own acknowledged facts; reducer owns replay validation; presentation escapes text. Source coverage and summary digests are computed locally, never supplied by the model. PreCompact hooks retain their existing Guard/grant path. Summary text cannot update approvals, budgets, effect disposition or authoritative task completion.

Retain the [current resource bounds](../../docs/specs/execution.md#admission-persistence-and-recovery): 252 KiB serialized source, 256 compaction items, 512 KiB request, 1 MiB reply and existing SSE/JSON limits, 8 KiB accepted summary, 1,024 requested compaction output tokens and 120-second compaction deadline. ChatGPT keeps its route-specific local-only output accounting and the prompt instruction for **at most 6,144 UTF-8 bytes**, including the note that a non-ASCII character can take four bytes ([ChatGPT limits](../../docs/specs/chatgpt.md#run-limits)); preserve that assertion in the subscription request corpus. Never describe this instruction as a remote generation cap. Existing concurrency, Goal budgets, lineage/Store capacity, probe maximum of 15 calls/180 seconds and retry accounting stay in force. No new queue or extra formatting retry. Overflow refuses; it does not crop input/output or raise a bound.

Journal-first means the reservation is committed before dispatch and the validated success/failure fact before continuation. Lost acknowledgement cannot publish a summary. Honest uncertainty means missing responses/usage remain unknown and unfinished effects stay uncertain. Strict replay validates persisted bytes, provenance and digests without calling a model. These properties do not depend on schema-constrained generation.

## Risks and mitigations

- Lossy or injected prose → retain canonical history, untrusted labels and independently projected typed facts. Schema compliance never supplied semantic truth; make no stronger fidelity claim now.
- Accidental permissive fallback → one text contract, exact wire termination checks, typed refusal and no JSON/heading repair. Unlike Codex's overflow cropping or OpenCode's formatting nudge, Arany preserves the admitted exact source and stops invalid outcomes; this retains bounded, journal-first transitions. Goose's parse fallback is unnecessary because no JSON summary is requested.
- Optional capabilities mistaken for admission → exact check still required for custom routes; schema support is no longer its purpose. Review, Tool, image and entitlement limits remain explicit.
- Checker/runtime mismatch → change probes, encoders, decoders and fixtures in the same vertical slice; assert absent schema/tools fields and test an endpoint that rejects them.

## Vertical slices

1. **One PR: an exact custom text-capable route passes admission and completes durable compaction through ordinary use.** Cross private profile/check → existing wire adapters → Engine validation/reservation → committed summary → attached/exec/show observations → reopened replay. Change all compaction encodings and probes together, including native diagnostics and ChatGPT, so no intermediate release attests a different format from the one it sends. Update the owning contracts/setup once and exercise the scenario table through existing evidence owners. The feature is usable with one admitted vendor or the existing explicit per-role routing; there is no separate horizontal “types” or “tests” slice.
