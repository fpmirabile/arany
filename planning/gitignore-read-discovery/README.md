# Gitignore-aware read discovery

## Metadata

- Status: `Draft`; depends on shared parser dependency approval in [Real-scale command snapshot](../real-scale-command-snapshot/README.md#open-questions-and-gates).
- Owner: Arany maintainer.
- Last updated: 2026-10-22.
- Delivery: Research → Plan → Implement; two vertical slices. No implementation in this documentation change.

## Outcome and scope

Routine typed discovery avoids opening or exposing gitignored files, which can contain credentials. List, Search, Glob, Git result disclosure and `@` suggestions share one interpretation. An exact Read or exact-file Search remains possible under the existing grant and permission decision; ignore patterns are selection data, not authorization.

This is a separate observable feature from command snapshot capacity under [PLANNING.md](../PLANNING.md). It depends on that plan's selector, not its larger snapshots or changesets. Explicit includes, Skill discovery, Git writes and subprocess access retain their owning contracts; this feature does not claim that ignore patterns prevent every secret read.

## Research

### Existing Arany behavior

- [Permission rules](../../docs/specs/tools.md#permission-rules) already implement #245: Read deny/ask restrictions hide List/Search/Glob rows and Git paths, patches and log entries. Restrictive directories are pruned before opening; filtering precedes sorting, pagination and fitting. Approval of an asked call does not approve other hidden paths. Reuse [permissions::hidden_paths](../../crates/arany/src/tools/permissions.rs) and its [evidence owner](../../crates/arany/src/tools/permissions/tests.rs), rather than creating a second permission system.
- [Filesystem inspection](../../crates/arany/src/tools/fs.rs) dispatches explicit Read directly through admitted no-follow file access. List has both a metadata branch and a restricted-grant branch that currently collects content for lengths; Search collects selected file content. Ignore exclusion must precede opening in every branch, not just filter the final JSON.
- [Glob](../../crates/arany/src/tools/glob.rs) has its own metadata walk. [Workers](../../crates/arany/src/tools/worker.rs) implement Read/List/Search/Glob over an immutable private image. Fixed directory-name exclusions exist, but no `.gitignore` interpreter exists.
- [Attached file discovery](../../crates/arany-cli/src/cli/attached/permissions.rs) calls `tools::workspace_entries` → `fs::workspace_entries`, currently with no Read-result filter. #245 did not cover this helper. Suggestions need both the new selection and the applicable existing restrictions; choosing or manually typing an explicit include still uses its separate admission contract.
- [Git](../../crates/arany/src/tools/git.rs) owns the neutralized view and conservative result parsing. Keep permission filtering, unknown/quoted patch-header hiding, rename-side treatment, bounded log path evidence and filtered-stderr suppression there.
- The [shared dependency/module review](../real-scale-command-snapshot/README.md#ignore-semantics-existing-dependencies-and-the-module) inventories the lockfile and evaluates alternatives. Do not implement a second matcher here. `tools.rs` currently admits 16 in-process reads; those slots do not establish an aggregate matcher-memory bound.

## Contract and scenarios

Owner: [Tools permission rules and file tools](../../docs/specs/tools.md#permission-rules); [Terminal file mentions](../../docs/specs/terminal.md) owns suggestions, while [Session explicit inputs](../../docs/specs/session.md) continues to own includes.

**Decided 2026-10-22:** adopt the following surface policy from the peer evidence above, the owner's request to avoid incidental ignored-file reads, and Arany's disclosure guarantees:

| Arany surface | Planned behavior |
|---|---|
| Exact `read(path)` | Preserve current admission, limits, deny/ask/allow and explicit Read behavior even for an ignored path. Do not load ignore controls or add an approval merely because of `.gitignore`. No fallback from failed discovery to Read happens automatically. |
| Exact-file `search(path)` | Like Claude Grep and ripgrep, an explicitly named admitted regular file may be searched even when ignored. Resolve its type through existing safe admission, apply all Read restrictions, and retain Search limits. A glob or a named directory is not an exact-file request. |
| Directory `search`, `glob`, `list` | Exclude ignored names and prune ignored directories before payload access, including restricted grants and worker images. Naming an ignored directory as a discovery root does not reset its ancestor rules. Query patterns narrow visible candidates; they never re-include an ignored path. |
| `@` suggestions | Exclude ignored and permission-hidden names before ranking, truncation and presentation. Use the pinned Workspace and available user-owned restrictions, without prompting or creating authority. The explicit include loader is unchanged. |
| `git_status`, `git_diff`, `git_log` | Apply the same frozen path selection in the existing neutralized Git result adapter, in addition to permission filtering. Hide ignored paths even when tracked; do not use Git's tracked-file exception as disclosure authority. An explicit Git path argument does not bypass it. Preserve existing conservative handling of renames, quoted/unknown headers and commits without visible path evidence. |

**Protected names dominate discovery:** the existing [`forbidden` / `valid_relative` checks](../../crates/arany/src/tools/types.rs) exclude `.git`, `.aws`, `.ssh`, `.gnupg`, `.env`, `.env.*`, `.npmrc` and `.pypirc` at every path component, case-insensitively. Apply them before ignore matching, opening, ranking or output in List, directory Search, Glob and `@`. Neither `!.env`, `!.git/`, a query pattern nor an exact-file request can undo hard protection; explicit Read/Search exceptions apply only to otherwise admitted non-protected files. Preserve these checks independently of grants, Read permissions and ignore negation.

The exact Read and exact-file Search exceptions follow peers. Stricter discovery across Glob/List/Git and refusal of query-driven re-inclusion are deliberate narrowing: Claude's default Glob and peer listing can expose ignored names, and ripgrep override globs can search ignored content; Arany instead implements the owner's requested omission consistently through its existing per-effect disclosure filter. No source/model query can undo a permission denial. There is no new model-controlled `include_ignored` switch. The existing [catalog](../../crates/arany/src/tools/catalog.rs) supports Search of a file or directory; preserve that distinction rather than treating every path argument as discovery.

Success and failure scenarios:

1. An ignored synthetic credential canary is absent from List/Glob/Git rows, `@` suggestions and directory-Search content. Directory Search never opens its payload; a nonignored sibling remains discoverable. Exercise both full and restricted grants.
2. Authorized exact Read and exact-file Search of that ignored fixture succeed; an explicit Read deny still rejects both. A broad query's `Read` ask restrictions remain hidden unless the queried path itself was approved. These tests must not use real credentials.
3. Root/nested precedence, escapes, negation, directory pruning and tracked-but-ignored files match the shared selector. A direct nested search still applies root rules; a hidden parent cannot be reopened by a query glob or child negation.
4. Malformed/oversized/unsafe or unavailable required controls fail the operation without partial results, secret-bearing errors or automatic fallback. Ordinary control-file absence is allowed. Cancellation retains resource ownership until evaluation exits.
5. Ignored and Read-hidden paths do not affect visible pagination. Git's independent raw capture bound can still report truncation, as its existing contract requires; filtering is not a promise to erase all cardinality side channels.
6. The worker's admitted image supplies controls and names; it never opens host paths to fill missing data. A required inaccessible ancestor control rejects discovery rather than guessing visible. Explicit Read can only read data present in that image.
7. A Git rename across the visibility boundary cannot leak the hidden side's name or patch: hide the whole section unless every named path is visible. Log inclusion uses visible changed-path evidence; retained commit subjects keep their existing contract and are not a secret-redaction guarantee.
8. A synthetic protected-name corpus includes case variants and descendants plus `!.env`, `!.env.*`, `!.git/`, `!.aws/`, `!.ssh/`, `!.gnupg/`, `!.npmrc` and `!.pypirc` negations. No name/content canary appears in List/Search/Glob/`@`, observations or diagnostics; no protected payload is opened. An ordinary ignored fixture remains available through authorized exact Read/Search, proving the tests distinguish hard protection from ignore selection.
9. Strict replay projects the committed observation without reading today's `.gitignore`, invoking Git or rerunning discovery. No snapshot matcher, repository config or cached result becomes authority on resume.

## Chosen direction

Use the shared private Tools module and its [shared selector admission](../real-scale-command-snapshot/README.md#shared-selector-admission). Keep ignore exclusion and `HiddenPaths` separate inputs composed by intersection. Existing query and permission matchers keep their grammars; a whitelist match in ignore data only removes that ignore exclusion.

The selector's interface is data-only and deterministic: admitted directory-relative controls in, bounded visible/excluded decisions or typed failure out. The caller owns capability access; the selector owns interpretation; Engine owns authorization/journal order; Git owns output framing. No filesystem walker from the dependency, global mutable cache, durable matcher store or new public configuration is required. Per-operation control snapshots allow changes to take effect on the next call without reinterpreting committed results.

The [chosen matcher placement](../real-scale-command-snapshot/README.md#matcher-placement-and-interactive-latency) is owned once in the snapshot plan. Under that decision, discovery that constructs a matcher uses the existing Guard capacity and resource envelope; exact Read and exact-file Search can retain their current in-process paths without constructing ignore matchers. Do not leave the compiler in an unbounded controller merely because a payload later enters a Guard. Keep each complete walk/selection in one owned operation; no per-file IPC or duplicated Engine-side parser.

Linux and macOS use identical selection and case-sensitive ignore matching. Existing case/Unicode, hard-link, no-follow, mount and replacement checks remain stricter than peer walkers. Native resource enforcement differences and unavailable evidence remain explicit; this documentation makes no native support claim.

## Interactive admission and latency

Current `refresh_files` is synchronous on query change; moving it unchanged into a Guard would block input and repeatedly pay native admission. [Codex's pinned manager](https://github.com/openai/codex/blob/rust-v0.117.0/codex-rs/tui/src/file_search.rs#L52-L73) instead owns one search session and calls `session.update_query(&query)`. Adopt session reuse, with narrower bounded data and no new daemon. A restricted custom in-process ignore matcher was rejected in the shared placement review: its apparent speed would replace the mature grammar or introduce a second one, while preflight plus RSS measurements alone cannot enforce aggregate memory.

- A suggestion session captures one immutable, fully filtered name index for the admitted search root: **2,048 names / 48 KiB serialized total**, at most **64 displayed candidates**. Include directories and names only, never file contents or compiled matchers. Keep the complete response inside the existing 64 KiB result envelope; overflow reports Limit rather than passing an incomplete index off as complete. Folder narrowing is explicit.
- Build that index asynchronously in one resource-owned operation; the terminal event loop must never wait synchronously. Query updates only rank/filter those names in-process, with the existing bounded query grammar. This replaces per-keystroke traversal; it does not add a second ignore parser. One active build and one latest-query value per attached composer; superseded requests/results cannot accumulate or overwrite a newer session generation. An active build's permit stays held until cancellation and cleanup finish.
- Freeze selection for the suggestion session, expire it after **30 seconds**, and drop it on popup closure, search-root/Workspace identity change or permission/grant generation change. Clear old candidates before rebuilding. Authority changes invalidate immediately; filesystem/ignore changes become visible on a new snapshot, so this is not a live filesystem view. No watcher, persistent cache or stale-results fallback is required.
- Use the [shared unit-wait, work and memory limits](../real-scale-command-snapshot/README.md#matcher-placement-and-interactive-latency): **100 ms wait for suggestions, 250 ms for typed discovery**. Full queue/expiry returns typed busy (`QueueFull`, model `Limit / ReadCapacity`); UI shows suggestions unavailable/busy, not an empty successful search. A new user query/session may try again; do not schedule background retries. Exact Read and exact-file Search keep the existing 16-slot in-process path.
- Match-call/time limits live in [shared selector admission](../real-scale-command-snapshot/README.md#shared-selector-admission). A timeout clears/discards the whole result, emits typed Timeout and never exposes a path as a fallback. Query refinement has a separate **50 ms wall deadline** and at most 2,048 candidate comparisons per update; timeout discards that update without touching the accepted immutable index.

**Implementation evidence gate:** extend the attached journey with explicit gates proving that typing/cancellation remains responsive while a build is queued, that many keystrokes start only one Guard walk per snapshot, and that stale generations never publish names. Use paused-time tests for queue expiry, work timeout and cancellation; reuse existing Guard saturation/failure owners. Record named-host Linux/macOS measurements for cold index construction (within the 2-second selection deadline) and **warm-query p95 ≤ 50 ms** on the maximum admitted index. Couple this with the shared adversarial RSS fixture; neither latency nor RSS has been measured in this plan update. Keep timing experiments outside the deterministic default suite. A failed measurement returns the affected design to Research, not to an automatic authority/memory expansion.

## Security and resource model

Assets: file names/content, credentials, private State, bounded memory/CPU and truthful journal results. Attacker inputs: path names, control-file bytes, query globs, churn and Git output. Startup admits the root/grant and user-owned permissions before repository data. Ignore files only narrow selection; no config, hook, executable or outbound connection is discovered through them. Children inherit the same or narrower authority.

The [shared selector admission](../real-scale-command-snapshot/README.md#shared-selector-admission) is the sole owner of accepted/denied ignore sources, no-follow single-link regular control files, pre-parse expansion, match-call/time budgets and typed overflow. Discovery retains its **depth-16** path bound, including control filenames (root controls plus at most 15 nested directory levels); command depth 32 does not apply here. A needed control exceeding that depth rejects the operation, rather than permitting unfiltered results. Preserve existing per-surface scan, path, file and result limits. Budget failure discards partial results and never changes an exclusion into visibility. Errors stay typed and sanitized; no upstream pattern text, automatic retry or widened scope.

Git is a disclosure filter over its neutralized private view, not a claim that ignored data is absent from historical Git objects/indexes. Do not read ignored working-file content solely for discovery or copy it into a new view; where the existing Git substrate must inspect opaque admitted objects, preserve its bounds and filter before model/journal output. If an operation cannot construct truthful output without exposing an omitted path, refuse or hide that section rather than inventing a deletion. Exact Read, explicit includes and allowed commands retain their separate authority, so `.gitignore` is not a secret vault.

## Vertical slices

1. **Ignore-aware typed discovery and suggestions.** After snapshot slice 1 supplies the shared selector, take List/Search/Glob and `@` from intent or UI request → capability/permission admission → resource-owned selection → visible output → canonical observation/presentation. Include worker-image discovery, restricted-grant listing, protected-name dominance, the bounded asynchronous suggestion session, and the exact Read/exact-file Search exceptions in this slice. Update Tools/Terminal contracts and extend their existing permission/discovery/attached journey owners with canaries, pagination, parser failure and cancellation. It ships a usable discovery feature independent of larger commands.
2. **Ignore-aware typed Git disclosure.** Carry frozen selection into the neutralized Git operation → path/patch/log filtering → bounded observation → journal/presentation/replay. Update the Tools Git contract and extend the existing Git/permission corpus and Guard journey with tracked ignored paths, renames, log evidence, malformed headers, capture limits and replay. No typed Git write behavior changes.
