## Outcome and scope

One capability: on Linux a guarded primary `Command` sees each admitted directory root through a private overlay, including dependency directories, ignored inputs and large files, except for the launch masks below. Writes stay in bounded private uppers and reach the Workspace only through validated changesets with receipts. Granted single files are read-only mounts; narrow `workspace_paths` expose no sibling tree. The build cache becomes a per-Workspace cache overlay with a sized tmpfs upper and Build CPU quota follows the peers. macOS keeps disposable-copy semantics as a documented platform difference. This serves [Tool execution for real projects](../../AGENTS.md#product-and-implementation-priorities); no `AGENTS.md` guarantee changes.

Owner decision **O1, 2026-10-26**, approves **B+C+E**: B, a same-binary namespace supervisor with bounded, inspectable tmpfs uppers; C, one overlay per granted directory and read-only granted files; E, launch-time protected-name masks with the explicit live-lower/alias limitations below. The supervisor mounts overlays itself and passes merged directories to bwrap with `--bind`. This refines decision 3B and replaces the original S1 with the bounded slices below; it does not depend on bwrap's overlay options.

This plan owns Workspace visibility, build-cache storage and Build CPU quota. Toolchain, SDK and package-cache visibility and the Cargo jobs default belong to the [guard-toolchains plan](../guard-toolchains/README.md).

Owner decisions **D5 and D2, 2026-10-26**: S1a2a refuses any granted root containing a host submount before GO; masking submount positions is outside this increment. Guard-toolchains G1' owns the Cargo jobs default on both platforms; overlay S3 owns only Build `cpu.max` and the `/settings` CPU range. Socket-dependent test ignores/local IPC and the opt-in network proxy remain in `NEXT_STEPS`. Excluded: worker private targets (shared-editor plan), MCP and Skill snapshots (still 32 MiB), and macOS real-path execution.

Owner decision **D6(a), 2026-10-26**: the StateRoot per-Workspace cache directory is a read-only lower, with upper/work in a sized tmpfs under the pinned cache allowance. Reuse S1 capture and apply validated changes in place after positive cleanup under the exclusive cache lease. A live writable host-directory bind is rejected: post-command measurement cannot bound in-flight writes. S2a remains after the deletion slices.

Owner decision **D7, 2026-10-26**: guarded commands must work on stock Ubuntu 24.04 without a root-installed AppArmor profile or sysctl change. Choose in-process `unshare(2)` or exec through distro-profiled `/usr/bin/unshare --keep-caps` from S1a0 native evidence, before S1a1 design freezes; clear capabilities before forking bwrap. Neither route is yet claimed supported. Failed probes stop before GO, never select a copy or host fallback.

## Research

Code and upstream sources were rechecked on 2026-10-26 at worktree head `e9a053aa`; earlier review revisions are not evidence of the current code. These are design constraints, not implemented or native-support claims.

- **Existing owners.** [`guard/linux.rs`](../../crates/arany/src/tools/guard/linux.rs) `BWRAP_BOOTSTRAP` currently execs `unshare` directly into bwrap, deliberately without retained capabilities. `profile_arguments` owns Workspace binds and sized tmpfs mounts. `parse_mountinfo` currently discards filesystem/options/source identity; retaining only targets and propagation is insufficient for overlay attestation. [`fs/command.rs`](../../crates/arany/src/tools/fs/command.rs) owns selected copies, frozen controls, `same_file` metadata comparison and capture. [`fs.rs`](../../crates/arany/src/tools/fs.rs) owns `CommandScanBudget`; [`types.rs`](../../crates/arany/src/tools/types.rs) sets `COMMAND_SCAN_ENTRIES = 131_072`, depth and metadata caps. [`config.rs`](../../crates/arany/src/tools/config.rs) caps nonoverlapping grants at 32. [`validate::forbidden`](../../crates/arany/src/validate.rs) owns case-insensitive protected components, including `.git` and `.env.*`; reuse it.
- **Bwrap facts and supervisor entry.** Overlay options first shipped in [v0.11.0, 2024-10-30](https://github.com/containers/bubblewrap/releases/tag/v0.11.0), not 0.8.0, and are unavailable in that release's setuid mode. The [main source](https://github.com/containers/bubblewrap/blob/main/bubblewrap.c) and [manual](https://github.com/containers/bubblewrap/blob/main/bwrap.xml) show lower/upper/work opened by `openat_in_root("/oldroot", …)`, `/proc/self/fd/N` option strings and unconditional `,userxattr`; main now refuses setuid entirely. A bwrap `--tmpfs` cannot create these earlier source paths, and `--tmp-overlay` hides the upper. Mounting in the retained supervisor avoids these ordering issues and the bwrap ≥0.11 overlay-option floor. Existing bwrap feature/security probes remain mandatory; this is no endorsement of an obsolete packaged binary.
- **Identity by construction and host submount refusal.** Overlay mountinfo records names, not authenticated layer identities ([`ovl_show_options`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/params.c)). Private non-recursive clones bind pinned lower handles. In [Linux v6.6 `fs/namespace.c`](https://github.com/torvalds/linux/blob/v6.6/fs/namespace.c), `copy_mnt_ns`/`lock_mnt_tree` lock inherited mounts when changing owning user namespace; `open_tree` reaches `__do_loopback`, whose non-recursive path rejects `has_locked_children` with `EINVAL`. Thus the old scenario promising to walk beneath a host submount is unreachable on this path. D5 refuses any descendant host mount even if a kernel would permit its clone; it is not a subtree-mask fallback. A grant root that is itself a mount is distinct from one containing submounts. The [overlayfs contract](https://github.com/torvalds/linux/blob/master/Documentation/filesystems/overlayfs.rst) keeps lower changes outside coherent snapshot semantics; do not replace clone failure with recursive cloning or a host-path walk.
- **Kernel metadata.** The [overlayfs contract](https://github.com/torvalds/linux/blob/master/Documentation/filesystems/overlayfs.rst) requires suitable upper/work storage on the same filesystem; read-write open alone can cause copy-up, including existing xattrs. [`params.c`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/params.c) forces `redirect_dir=nofollow` and `metacopy=off` with `userxattr`; lower/merged directory rename therefore returns `EXDEV` (a user program may implement its own copy/delete). [`ovl_mknod`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/dir.c) refuses 0/0 character devices through the merged view; [`xattrs.c`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/xattrs.c) filters private overlay xattrs. Arany's [`profile.rs::metadata_program`](../../crates/arany/src/tools/guard/profile.rs) additionally denies setxattr/removexattr/chmod families. With raw uppers inaccessible, the payload cannot forge whiteouts, opaque markers or private xattrs. Still validate capture as untrusted data.
- **Capability-free capture.** [`chmod(2)`](https://man7.org/linux/man-pages/man2/chmod.2.html) permits an owner to restore read permission without `CAP_FOWNER`; mode-000 does not require privileged capture. The supervisor owns the private tmpfs files under the same mapped UID, and can restore readability through validated no-follow handles after positive teardown. [`profile.rs::metadata_program`](../../crates/arany/src/tools/guard/profile.rs) denies the payload's chmod/xattr syscalls; creation with mode 000 remains possible, so S1a2b must prove that case without changing payload policy. Whiteout classification reads metadata, not device content.
- **Linux floor and actual probe.** Upstream [`v6.5 shmem.c`](https://github.com/torvalds/linux/blob/v6.5/mm/shmem.c) lacks the user-xattr handler present in [`v6.6`](https://github.com/torvalds/linux/blob/v6.6/mm/shmem.c): Linux 6.6 is the upstream tmpfs-user-xattr floor, with equivalent backports admitted by probes. Overlay mount success is insufficient: `super.c` warns and sets `noxattr` when its xattr test fails. Directly set, read back and remove a small `user.arany_probe` xattr on a newly created file in the fresh tmpfs. S1a1 owns this tmpfs-only probe; S1a2a exercises overlay create/edit/unlink/recreate on disposable probe objects before GO, where the first overlay mount exists. Probe failure is `ProtectionUnavailable`, with no copy fallback on an overlay-selected invocation.

## Contract and scenarios

- **B — bootstrap and least privilege.** Launch the same-binary supervisor under the existing unit from a pinned executable identity/digest, or execute its admitted fd. Linux currently binds the binary by path; macOS Task's `guard_executable` is only a precedent, not a Linux field. S1a0 prefers in-process entry if it passes the stock-host probes, otherwise requires the exec route to pass. It chooses either in-process user/mount namespace setup and invoking UID/GID maps, or exec through `/usr/bin/unshare --user --map-current-user --mount --propagation private --keep-caps --` into that pinned supervisor. Attest the executable and any external launcher, bounded environment and exact argv; model/repository text cannot choose them. The supervisor mounts private tmpfs outside lower roots, sized from the existing project allowance with finite `nr_inodes` derived from `COMMAND_SCAN_ENTRIES` and per-grant upper/work/probe overhead. Setup completes before payload-controlled code. Clear effective, permitted, inheritable, ambient and regainable bounding capabilities and set no-new-privileges before forking bwrap, before READY and before upper parsing. Retain the supervisor; bwrap starts cap-free and uses its existing nested user namespace. Payload caps remain zero with current seccomp, Landlock and descriptor isolation; raw lower/upper/work and control handles never enter the payload.
- **Syscalls and unsafe review.** S1a1/S1a2a introduce `unshare`, UID/GID-map writes, `mount`, `open_tree`, `move_mount`, read-only mount attributes (`mount_setattr` or equivalent bind/remount), `capset`, bounding/ambient capability `prctl`, `PR_SET_NO_NEW_PRIVS`, and `pidfd_open`/`waitid`. Enable the existing rustix `mount`/`thread` features only where consumed; retain existing `process` support. Isolate unavoidable unsafe wrappers behind a safe, single-purpose Linux interface under global rule 7, with dedicated review and native failure tests. Prefer clearing capabilities in the single-threaded supervisor before fork, requiring no new `pre_exec`; if unavoidable, use one audited child-side `pre_exec` site beside the seccomp installer, with no allocation, locks or unwinding. S1a1's security pass owns feature/launcher/capability changes; S1a2a owns mount wrappers and inherited-descriptor/topology checks. No new crate or speculative abstraction.
- **Ubuntu failure disclosure and hand-run remedy.** S1a1's tools.md Linux-enforcement edit must distinguish `ProtectionUnavailable` caused by AppArmor denying user-namespace mount capability from missing kernel/xattr enforcement, and include the exact hand-run S1a0 probe invocation and how to retry with the evidence-selected admitted entry. Ubuntu's optional administrator remedies (an executable-specific `/etc/apparmor.d` profile with `userns,`, or the hand-run `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`) are external policy changes, never executed by Arany and never a D7 prerequisite or success criterion. If neither stock entry passes, retain Draft and raise the evidence to the owner; do not freeze S1a1 around an unverified route.

- **Identity and attestation.** For each grant, call `open_tree(pinned_fd, "", OPEN_TREE_CLONE | OPEN_TREE_CLOEXEC | AT_EMPTY_PATH)`, without `AT_RECURSIVE`, and attach the detached clone under the supervisor's private runtime. Make lower clones read-only; walk those clones, never host pathname substitutes. Before walking a grant clone or mounting its overlay, reject any host submount beneath that grant root as `ProtectionUnavailable` (D5); bound and attest the descendant-mount inventory, and fail closed if it is incomplete. Locked children make the non-recursive clone fail with `EINVAL`; a successful clone is not permission to ignore the explicit D5 check. No payload or lower walk/overlay setup follows this refusal; the supervisor may already have mounted its private tmpfs. Otherwise the private clone excludes later host-mount propagation; unsupported cloning/attachment is `ProtectionUnavailable`. Create upper/work from retained tmpfs handles and mount overlay from these private paths with explicit `userxattr,redirect_dir=nofollow,metacopy=off`. Only merged paths go to bwrap `--bind`. Thus pinned handles and private construction bind identities. The supervisor's mountinfo attests, before READY and again before GO, each lower clone (read-only, private propagation, no submounts), the sized and inode-bounded tmpfs and each overlay mount (`overlay`, `userxattr`, private upper/work). The helper inside bwrap attests the merged bind at `/workspace`, every mask, the read-only parent and the absence of unexpected submounts, as `verify_runtime_mounts` does today. `parse_mountinfo` retains filesystem type, mount/root/source fields, mount options and super options under its existing bounds for both; option strings are not identity proof. S1a1 supplies the bounded parser and copy-path checks; S1a2a supplies overlay/mask checks. Both reports bind to the same intent and namespace/process identities and gate READY/GO. GO still follows committed intent/verdict.
- **Cleanup before capture.** Retain the supervisor outside bwrap's PID namespace. Pin bwrap with a pidfd; wait for its exit and reap, retaining the existing positive descendant-cleanup evidence, before walking upper metadata. [`pid_namespaces(7)`](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html) supplies the namespace-init-death/descendant-kill guarantee; an inner helper report alone does not prove teardown. Do not wait for the whole outer cgroup to empty while its supervisor is alive. The capability-free supervisor emits the bounded candidate, then the controller proves final unit cleanup. Helper death, missing cleanup proof or lost capture after GO is `Uncertain`, stops continuation and never retries; confirmed cancellation/timeout remains `Cancelled`/`Limit`, without publication.
- **C — bounded mount scope.** `["."]` uses one overlay. Otherwise `/workspace` is a separate sized, inode-bounded tmpfs containing only empty parents and grant mounts, at most the existing 32 entries; grant files use `--ro-bind`. Derive its byte bound from `COMMAND_PATH_METADATA_BYTES` and its inode bound from grant count × `COMMAND_SNAPSHOT_DEPTH` plus the root. After installing grants and masks, `--remount-ro /workspace` makes only the parent tmpfs read-only, leaving directory overlays writable; attest this topology. No convenient ancestor or alternate raw lower path discloses a sibling. Root admission still rejects symlink grants and replacement; allowing lower-entry links does not relax grant-root identity checks.
- **E — bounded launch discovery.** Pre-walk the exact cloned lowers without ignore/dependency pruning or following ordinary links. Reuse `validate::forbidden`, `CommandScanBudget` entry/path-metadata bounds, depth and the admitted preparation deadline; baseline records, protected inode sets and masks share these bounds, not parallel unlimited maps. Protect names at every depth reached: directory masks are empty/read-only, file masks inert/read-only. Lower symlinks and hard links remain visible and resolve only against the sandbox's mounted view. Record protected inodes, including canonical targets of protected symlinks, for the alias check. Refuse launch for a lower hard link whose `(dev, ino)` equals a protected inode found by this walk; ordinary lower hard links do not refuse. Continue to deny special/set-ID exposure by masking the affected entry/subtree. Upper links, including hard links, remain invalid output. D5 refuses a grant root containing any host submount before GO, rather than using an E enclosing mask. This prevents overlay commands with a `target/` on tmpfs, a bind-mounted vendor directory or a nested devcontainer volume inside a granted root; narrowing the grant to exclude that mount can avoid the refusal. Masking submount positions in the merged view is a later option, not S1a2a.
- **Unwalkable subtrees.** An unreadable directory or exhausted entry/path/depth budget masks the whole affected subtree as an empty read-only directory, rather than refusing an otherwise enforceable command. Reserve bounded ancestor/root mask slots before descending. If traversal has no budget left to enumerate remaining siblings, replace their nearest already-known enclosing subtree (up to the grant root) with one mask, discard its partial baseline, and stop descending. Never leave an unscanned branch visible or return a truncated mask list. A deadline or argument/mountinfo/report bound that prevents installing and attesting even that enclosing mask refuses before GO. Baseline absence is inferable only under completely inventoried visible directories; masked/unwalked paths are never capture candidates. Masks' existence and names can be inferred from empty entries and mountinfo; no name-existence secrecy is claimed.
- **Protected symlinks.** For `.env -> x`, record the link spelling and its bounded canonical target in the admitted view, as Codex does. Mask the canonical target and make the link's enclosing directory read-only/empty if its spelling cannot safely receive a mask; never read target content to discover it. An unresolved, cyclic, out-of-view or unpinnable target requires an enclosing subtree mask (or `ProtectionUnavailable` if exact enforcement is impossible). A plain mask over a symlink spelling is insufficient. Revalidate the launch target/mask construction before GO.
- **Launch baseline and conflicts.** The E walk records each visible path's `(dev, ino, size, mtime_ns, ctime_ns)` and type/exec bit under the same scan budget, with complete-directory records establishing absence for unlisted names. At capture, every touched path must still match its launch lower identity or recorded absence. A path absent from the baseline but present now conflicts; lack of a record inside a masked/incomplete directory never means absence. Recheck lower metadata around bounded content reads, then create the existing digest/absence `before` precondition from that same lower object. Any mismatch refuses the whole candidate with nothing published; publication checks `before` again as today. Whiteout and opaque/subtree deletions enumerate only baseline regular-file entries; any new/currently changed entry in the affected subtree conflicts instead of being swept into deletion. Do not discover new deletion targets from a capture-time host walk.
- **Capture and output selection.** Validate the complete upper with no-follow handles, xattr name/value accounting within `COMMAND_PATH_METADATA_BYTES` and existing scan/depth/deadline bounds. From S1c1, first drop byte-identical copy-ups (same content and exec bit) before retained-file/content/changeset caps; stream comparison with aggregate compared bytes capped by `COMMAND_COMPARE_BYTES` (derived once as twice the pinned upper allowance beside the capture owner), without an unbounded allocation. Until S1c1, S1a2b/S1b count copy-ups under ordinary candidate caps and may refuse capture when those caps are exceeded; they never silently omit a candidate. Frozen-at-launch ignore controls and fixed dependency-directory rules determine publication selection, independently of lower read visibility. Discard safe ignored/dependency changes, including new outputs and edits/deletions of existing ignored lower files; baseline inventory alone does not make an ignored file publishable. Changing `.gitignore` during the command cannot reclassify that invocation. Ordinary selected lower files yield edits/deletions even if the command adds an ignore rule for them. Existing oversized lower inputs are visible, but changed selected files must still meet existing publication content caps. Validate unsafe output before discarding it; links, special files other than recognized whiteouts, set-ID, protected/out-of-grant paths and unsupported metadata reject the whole candidate.
- **Whiteouts and xattrs.** S1a2b/S1b refuse any whiteout, opaque marker or recreated directory on a publishable path. Beneath a directory frozen as ignored or dependency at launch, kernel-produced 0/0 whiteouts and `opaque=y` markers are classified from metadata only and discarded as safe output without content reads; any other special file, link or set-ID entry there still rejects the whole candidate. S1a2a is the earlier empty-upper-only increment: any payload upper entry refuses, with no publication. S1c1 adds plain kernel-produced character-device 0/0 whiteouts over baseline regular files and identical-copy-up dropping. S1c2 adds opaque `y`, bounded subtree removal and recreation. Accept only supported kernel-produced private `origin`, `impure`, `uuid` and `opaque=y` metadata with bounded form checks (on ignored paths, only validated kernel whiteouts/opaque markers are discarded); reject redirects, metacopy, unknown private forms, `opaque=x` and xattr-whiteout files. Kernel documentation also permits xattr-whiteout files and `opaque=x`; this plan deliberately rejects those forms, including beneath ignored paths, rather than claiming that overlayfs cannot produce them. Unsupported forms fail closed until an explicitly reviewed extension. Ignore bounded non-overlay xattrs such as `security.selinux`, `system.posix_acl_*` and ordinary `user.*` during content capture; copy-up must not reject normal SELinux/ACL hosts. Publish content and the exec bit only, never xattrs. Preserve empty-directory behavior, binary/executable content, valid selected changes after nonzero exit, receipt correlation, checkpoints and unknown-publication semantics. Neither masks nor upper metadata authorize publication. No Workspace Event or record format changes in S1; S2a owns any private cache-record migration and fixture required by D6.
- **Live-lower and alias non-claims.** Kernel documentation calls external lower-tree mutation undefined overlay behavior. The baseline protects publication against lost updates; it promises neither coherent concurrent reads nor visibility of a new path. Launch masks cannot cover protected names first created/renamed into a visible lower subtree during execution. Hard links to content outside the grant, or to protected content in an unwalked/masked tree, cannot be identified from the bounded in-grant walk; no outside-grant inode-alias confidentiality is claimed. Ordinary symlinks may resolve to other already-admitted runtime mounts; no extra host tree is mounted for them. Protected publication remains forbidden. This disclosure scope must be explicit in tools.md, without changing `AGENTS.md`.

State mask name/existence leakage, outside-grant hard-link non-claims and the exact E sentence: “Protected names present at launch are masked at any depth; a protected name created or renamed into the live lower tree during execution may be visible to the command but is never publishable, matching Codex and Claude Code's Linux sandbox limitation because bubblewrap masks concrete paths collected at launch.” Update changesets/limits rows for S1a2b create/edit capture, discarded existing ignored edits, baseline conflicts and unchanged candidate caps; S1c1 owns identical-copy-up dropping/plain deletions and S1c2 owns subtree/recreation semantics. Update Linux enforcement with the supervisor-mounted mechanism, upstream Linux 6.6/equivalent-backport tmpfs-user-xattr floor and actual probes, with no bwrap overlay-option minimum. - **Selection result.** From S1a2b, Linux overlay commands return `selection: Some(CommandSelectionSummary)` through S1c2 and afterwards. `ignored_entries` counts launch inventory entries classified ignored/dependency, `pruned_directories = 0` (ignore rules do not prune Linux reads), `oversized_inputs = 0` (no size-based input omission), and `discarded_outputs` counts safe upper changes/deletions discarded by frozen rules, including existing ignored paths. S2a owns descriptor lifetime/teardown evidence, this recovery contract and any private-record migration/fixture; do not imply archive-swap rollback for directory mutation. Existing failed-command non-publication and macOS archive recovery stay intact. ## Chosen direction and security model

Reuse the binary, unit supervision, admitted handles, scan budget, mount builder, changeset types and publication path. A retained namespace owner is necessary for capture isolation; add no daemon, crate, dependency, generic adapter or host fallback. Supervisor mounting is the smallest complete identity solution: its added mount call replaces bwrap overlay-argument construction and layer-string attestation, avoids the 0.11 floor, and permits direct setup probes before privilege removal. Use standard Linux namespace/mount APIs behind the existing Guard boundary. New supervisor/mount code goes into a phase child under `tools/guard/linux/`, with overlay capture kept under the existing `tools/fs/command` owner, following the repository's growth rule instead of expanding the parent orchestration file. Each slice updates the enforcement digest for its actual profile.

Assets are Workspace bytes, protected data, StateRoot/account data and capture metadata. User grants supply authority; repository content, payload output and upper metadata do not. Only a capability-free parser consumes payload-controlled upper data after positive teardown. StateRoot/account/home and raw upper/work stay absent from payload mounts; only the isolated cache merged view appears at `/cache`. The cache publisher alone retains its narrow private-directory handle. READY/GO, deterministic Policy, committed intent/verdict and typed publication retain their owners. E states accepted disclosure limits, never publication exceptions. One project tmpfs bounds project uppers/workdirs together; D6 adds a separately sized cache tmpfs under its pinned allowance; the narrow-parent tmpfs has its separate derived bound. Existing preparation/capture CPU, memory, deadline, output and report envelopes remain finite. Overflow masks only where E explicitly defines a complete enclosing mask; candidate overflow refuses the whole candidate. Every slice receives the [security pass](../../agents/security.md#security-pass-triggers) for its actual mount, capability, filesystem or capture change.

## Risks and mitigations

- Missing tmpfs user xattrs, usable user namespaces or LSM permissions → direct probes and attestation refuse before GO; no kernel-version-only or overlay-mount-only success claim.
- Large real trees (including hard-linked Cargo artifacts and pnpm packages) exceed discovery bounds → retain ordinary lower links and mask an enclosing subtree completely; no extra metadata budget or secret-content reads.
- Host submounts beneath a grant root → D5 refuses before GO, including tmpfs build targets, bind-mounted vendors and nested devcontainer volumes; no claim that all devcontainers or a root mount itself are refused.
- External lower mutation or aliasing can disclose data within E's non-claims → frozen masks and bounded baseline checks protect publication, while tools.md states the disclosure widening honestly.
- Privileged capture or premature walks → clear all capabilities and set NNP before READY, pin/wait/reap bwrap, retain positive descendant cleanup, and parse only afterward; unknown outcomes stop continuation.
- Whiteout/opaque mistakes lose files → S1a2a accepts only empty uppers; S1a2b discards safe ignored deletions and refuses publishable deletion forms; S1c1 handles plain baseline whiteouts/dedup, S1c2 handles bounded baseline subtree deletion, with strict private-metadata tables and existing digest preconditions.
- Slice growth → the estimates below include code, tests, documentation and deletions; re-inventory and split by observable risk before implementation if the ceiling cannot hold. Do not drop evidence or security work to fit.
