## Outcome and scope

One capability: on Linux a guarded primary `Command` sees each admitted directory root through a private overlay, including dependency directories, ignored inputs and large files, except for the launch masks below. Writes stay in bounded private uppers and reach the Workspace only through validated changesets with receipts. Granted single files are read-only mounts; narrow `workspace_paths` expose no sibling tree. The build cache becomes a per-Workspace directory bind and Build CPU/jobs defaults follow the peers. macOS keeps disposable-copy semantics as a documented platform difference. This serves [Tool execution for real projects](../../AGENTS.md#product-and-implementation-priorities); no `AGENTS.md` guarantee changes.

Owner decision **O1, 2026-10-26**, approves **B+C+E**: B, a same-binary namespace supervisor with bounded, inspectable tmpfs uppers; C, one overlay per granted directory and read-only granted files; E, launch-time protected-name masks with the explicit live-lower/alias limitations below. The supervisor mounts overlays itself and passes merged directories to bwrap with `--bind`. This refines decision 3B and replaces the original S1 with S1a1/S1a2/S1b/S1c; it does not depend on bwrap's overlay options.

This plan absorbs the toolchain/cache visibility and Build jobs/CPU parts of the `NEXT_STEPS` “Daily use first” items “`cargo test` here inside the Guard” and “Development command environment”. Their socket-dependent test ignores/local IPC and opt-in network allowlist proxy remain there. Excluded: worker private targets (shared-editor plan), MCP and Skill snapshots (still 32 MiB), and macOS real-path execution.

## Research

Code and upstream sources were rechecked on 2026-10-26 at the current worktree head (`3f794d16`, including the earlier merges of `origin/main`), rather than treating the prior review as authority. These are design constraints, not implemented or native-support claims.

- **Existing owners.** [`guard/linux.rs`](../../crates/arany/src/tools/guard/linux.rs) `BWRAP_BOOTSTRAP` currently execs `unshare` directly into bwrap, deliberately without retained capabilities. `profile_arguments` owns Workspace binds and sized tmpfs mounts. `parse_mountinfo` currently discards filesystem/options/source identity; retaining only targets and propagation is insufficient for overlay attestation. [`fs/command.rs`](../../crates/arany/src/tools/fs/command.rs) owns selected copies, frozen controls, `same_file` metadata comparison and capture. [`fs.rs`](../../crates/arany/src/tools/fs.rs) owns `CommandScanBudget`; [`types.rs`](../../crates/arany/src/tools/types.rs) sets `COMMAND_SCAN_ENTRIES = 131_072`, depth and metadata caps. [`config.rs`](../../crates/arany/src/tools/config.rs) caps nonoverlapping grants at 32. [`validate::forbidden`](../../crates/arany/src/validate.rs) owns case-insensitive protected components, including `.git` and `.env.*`; reuse it.
- **Bwrap facts and rejected bootstrap.** Overlay options first shipped in [v0.11.0, 2024-10-30](https://github.com/containers/bubblewrap/releases/tag/v0.11.0), not 0.8.0, and are unavailable in that release's setuid mode. The [main source](https://github.com/containers/bubblewrap/blob/main/bubblewrap.c) and [manual](https://github.com/containers/bubblewrap/blob/main/bwrap.xml) show lower/upper/work opened by `openat_in_root("/oldroot", …)`, `/proc/self/fd/N` option strings and unconditional `,userxattr`; main now refuses setuid entirely. A bwrap `--tmpfs` cannot create these earlier source paths, and `--tmp-overlay` hides the upper. Mounting in the retained supervisor avoids these ordering issues and the bwrap ≥0.11 overlay-option floor. Existing bwrap feature/security probes remain mandatory; this is no endorsement of an obsolete packaged binary.
- **Identity by construction.** [Overlayfs `super.c`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/super.c) stores lower option names for [`ovl_show_options` in `params.c`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/params.c); mountinfo echoes names, not authenticated lower/upper/work identities. Use [non-recursive `open_tree`](https://man7.org/linux/man-pages/man2/open_tree.2.html) clones of pinned dirfds, attach them privately, and mount the overlay there. Walk that exact lowerdir object: overlay layers do not import host submount trees. Inspecting the host pathname instead could miss an underlying protected entry hidden by a host mount.
- **Kernel metadata.** The [overlayfs contract](https://github.com/torvalds/linux/blob/master/Documentation/filesystems/overlayfs.rst) requires suitable upper/work storage on the same filesystem; read-write open alone can cause copy-up, including existing xattrs. [`params.c`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/params.c) forces `redirect_dir=nofollow` and `metacopy=off` with `userxattr`; lower/merged directory rename therefore returns `EXDEV` (a user program may implement its own copy/delete). [`ovl_mknod`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/dir.c) refuses 0/0 character devices through the merged view; [`xattrs.c`](https://github.com/torvalds/linux/blob/master/fs/overlayfs/xattrs.c) filters private overlay xattrs. Arany's [`profile.rs::metadata_program`](../../crates/arany/src/tools/guard/profile.rs) additionally denies setxattr/removexattr/chmod families. With raw uppers inaccessible, the payload cannot forge whiteouts, opaque markers or private xattrs. Still validate capture as untrusted data.
- **Linux floor and actual probe.** Upstream [`v6.5 shmem.c`](https://github.com/torvalds/linux/blob/v6.5/mm/shmem.c) lacks the user-xattr handler present in [`v6.6`](https://github.com/torvalds/linux/blob/v6.6/mm/shmem.c): Linux 6.6 is the upstream tmpfs-user-xattr floor, with equivalent backports admitted by probes. Overlay mount success is insufficient: `super.c` warns and sets `noxattr` when its xattr test fails. Directly set, read back and remove a small `user.arany_probe` xattr on a newly created file in the fresh tmpfs, then exercise overlay create/edit/unlink/recreate on disposable probe objects before GO. Probe failure is `ProtectionUnavailable`, with no copy fallback on an overlay-selected invocation.

## Contract and scenarios

- **B — bootstrap and least privilege.** Launch the same-binary supervisor under the existing unit, with `guard_executable` admission extended to pin executable identity/digest (or execute its admitted fd with `fexecve`); a pathname alone is insufficient. In its single-threaded setup, call [`unshare(2)`](https://man7.org/linux/man-pages/man2/unshare.2.html) in process, establish the invoking UID/GID maps, and create a private mount namespace. This retains namespace-local mount capability without carrying ambient caps across an exec. The supervisor mounts a private tmpfs outside lower roots, sized to the existing aggregate project allowance (256 MiB primary / 1 GiB Build), with finite `nr_inodes` derived from `COMMAND_SCAN_ENTRIES` plus per-grant upper/work/probe overhead. Set up pinned lower clones, upper/work and merged mounts before running payload-controlled code. Fork the bwrap child, then both branches clear effective, permitted, inheritable and ambient capability sets and the regainable bounding set and set no-new-privileges; the supervisor does this immediately after setup, before READY and before any upper capture parsing. Bwrap starts cap-free (otherwise non-root startup says “Unexpected capabilities”), then uses its existing `--unshare-user` setup. Do not exec the supervisor away. Payload caps remain zero with existing seccomp, Landlock and descriptor isolation; raw lower/upper/work handles and report descriptors never enter the payload.
- **Identity and attestation.** For each grant, call `open_tree(pinned_fd, "", OPEN_TREE_CLONE | OPEN_TREE_CLOEXEC | AT_EMPTY_PATH)`, without `AT_RECURSIVE`, and attach the detached clone under the supervisor's private runtime. Make lower clones read-only; walk those clones, never host pathname substitutes. This selects the lowerdir object without importing host submounts, including later host mounts; unsupported cloning/attachment is `ProtectionUnavailable`. Create upper/work from retained tmpfs handles and mount overlay from these private paths with explicit `userxattr,redirect_dir=nofollow,metacopy=off`. Only merged paths go to bwrap `--bind`. Thus pinned handles and private construction bind identities. Mountinfo attests destination, filesystem `overlay`, `userxattr`, read-only grants/masks, private propagation, sized/inode-bounded tmpfs and absence of unexpected submounts before READY and again before GO; option strings are not identity proof. GO still follows committed intent/verdict.
- **Cleanup before capture.** Retain the supervisor outside bwrap's PID namespace. Pin bwrap with a pidfd; wait for its exit and reap, retaining the existing positive descendant-cleanup evidence, before walking upper metadata. [`pid_namespaces(7)`](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html) supplies the namespace-init-death/descendant-kill guarantee; an inner helper report alone does not prove teardown. Do not wait for the whole outer cgroup to empty while its supervisor is alive. The capability-free supervisor emits the bounded candidate, then the controller proves final unit cleanup. Helper death, missing cleanup proof or lost capture after GO is `Uncertain`, stops continuation and never retries; confirmed cancellation/timeout remains `Cancelled`/`Limit`, without publication.
- **C — bounded mount scope.** `["."]` uses one overlay. Otherwise `/workspace` is a separate sized, inode-bounded tmpfs containing only empty parents and grant mounts, at most the existing 32 entries; grant files use `--ro-bind`. Derive its byte bound from `COMMAND_PATH_METADATA_BYTES` and its inode bound from grant count × `COMMAND_SNAPSHOT_DEPTH` plus the root. After installing grants and masks, `--remount-ro /workspace` makes only the parent tmpfs read-only, leaving directory overlays writable; attest this topology. No convenient ancestor or alternate raw lower path discloses a sibling. Root admission still rejects symlink grants and replacement; allowing lower-entry links does not relax grant-root identity checks.
- **E — bounded launch discovery.** Pre-walk the exact cloned lowers without ignore/dependency pruning or following ordinary links. Reuse `validate::forbidden`, `CommandScanBudget` entry/path-metadata bounds, depth and the admitted preparation deadline; baseline records, protected inode sets and masks share these bounds, not parallel unlimited maps. Protect names at every depth reached: directory masks are empty/read-only, file masks inert/read-only. Lower symlinks and hard links remain visible and resolve only against the sandbox's mounted view. Record protected inodes, including canonical targets of protected symlinks, for the alias check. Refuse launch for a lower hard link whose `(dev, ino)` equals a protected inode found by this walk; ordinary lower hard links do not refuse. Continue to deny special/set-ID exposure by masking the affected entry/subtree. Upper links, including hard links, remain invalid output.
- **Unwalkable subtrees.** An unreadable directory or exhausted entry/path/depth budget masks the whole affected subtree as an empty read-only directory, rather than refusing an otherwise enforceable command. Reserve bounded ancestor/root mask slots before descending. If traversal has no budget left to enumerate remaining siblings, replace their nearest already-known enclosing subtree (up to the grant root) with one mask, discard its partial baseline, and stop descending. Never leave an unscanned branch visible or return a truncated mask list. A deadline or argument/mountinfo/report bound that prevents installing and attesting even that enclosing mask refuses before GO. Baseline absence is inferable only under completely inventoried visible directories; masked/unwalked paths are never capture candidates. Masks' existence and names can be inferred from empty entries and mountinfo; no name-existence secrecy is claimed.
- **Protected symlinks.** For `.env -> x`, record the link spelling and its bounded canonical target in the admitted view, as Codex does. Mask the canonical target and make the link's enclosing directory read-only/empty if its spelling cannot safely receive a mask; never read target content to discover it. An unresolved, cyclic, out-of-view or unpinnable target requires an enclosing subtree mask (or `ProtectionUnavailable` if exact enforcement is impossible). A plain mask over a symlink spelling is insufficient. Revalidate the launch target/mask construction before GO.
- **Launch baseline and conflicts.** The E walk records each visible path's `(dev, ino, size, mtime_ns, ctime_ns)` and type/exec bit under the same scan budget, with complete-directory records establishing absence for unlisted names. At capture, every touched path must still match its launch lower identity or recorded absence. A path absent from the baseline but present now conflicts; lack of a record inside a masked/incomplete directory never means absence. Recheck lower metadata around bounded content reads, then create the existing digest/absence `before` precondition from that same lower object. Any mismatch refuses the whole candidate with nothing published; publication checks `before` again as today. Whiteout and opaque/subtree deletions enumerate only baseline regular-file entries; any new/currently changed entry in the affected subtree conflicts instead of being swept into deletion. Do not discover new deletion targets from a capture-time host walk.
- **Capture and output selection.** Validate the complete upper with no-follow handles, xattr name/value accounting within `COMMAND_PATH_METADATA_BYTES` and existing scan/depth/deadline bounds. First drop byte-identical copy-ups (same content and exec bit) before retained-file/content/changeset caps; stream comparison with aggregate compared bytes capped by `COMMAND_COMPARE_BYTES` (derived once as twice the pinned upper allowance beside the capture owner), without an unbounded allocation. Frozen-at-launch ignore controls and fixed dependency-directory rules determine publication selection, independently of lower read visibility. Discard safe ignored/dependency changes, including new outputs and edits/deletions of existing ignored lower files; baseline inventory alone does not make an ignored file publishable. Changing `.gitignore` during the command cannot reclassify that invocation. Ordinary selected lower files yield edits/deletions even if the command adds an ignore rule for them. Existing oversized lower inputs are visible, but changed selected files must still meet existing publication content caps. Validate unsafe output before discarding it; links, special files other than recognized whiteouts, set-ID, protected/out-of-grant paths and unsupported metadata reject the whole candidate.
- **Whiteouts and xattrs.** S1a2 supports plain kernel-produced character-device 0/0 whiteouts over baseline regular files. S1c adds opaque `y`, bounded subtree removal and recreation. Accept only supported kernel-produced private `origin`, `impure`, `uuid` and `opaque=y` metadata with bounded form checks; reject redirects, metacopy, unknown private forms, `opaque=x` and xattr-whiteout files. The kernel contract's alternative xattr whiteouts are never created by overlayfs; they are not an expected payload output. Ignore bounded non-overlay xattrs such as `security.selinux`, `system.posix_acl_*` and ordinary `user.*` during content capture; copy-up must not reject normal SELinux/ACL hosts. Publish content and the exec bit only, never xattrs. Preserve empty-directory behavior, binary/executable content, valid selected changes after nonzero exit, receipt correlation, checkpoints and unknown-publication semantics. Neither masks nor upper metadata authorize publication. No Event or stored-format change is planned.
- **Live-lower and alias non-claims.** Kernel documentation calls external lower-tree mutation undefined overlay behavior. The baseline protects publication against lost updates; it promises neither coherent concurrent reads nor visibility of a new path. Launch masks cannot cover protected names first created/renamed into a visible lower subtree during execution. Hard links to content outside the grant, or to protected content in an unwalked/masked tree, cannot be identified from the bounded in-grant walk; no outside-grant inode-alias confidentiality is claimed. Ordinary symlinks may resolve to other already-admitted runtime mounts; no extra host tree is mounted for them. Protected publication remains forbidden. This disclosure scope must be explicit in tools.md, without changing `AGENTS.md`.
- **Same-PR tools edits (S1a2, extended by S1b/S1c).** Replace the copy-only “Command input selection” opening and “Ignore preferences never grant access” comparison with an explicit Linux-overlay/macOS-copy distinction: Linux overlay reads include gitignored files, dependency directories and inputs above 1 MiB within directory grants, subject to E masks; ignore rules select publication, not Linux read access. State mask name/existence leakage, outside-grant hard-link non-claims and the exact E sentence: “Protected names present at launch are masked at any depth; a protected name created or renamed into the live lower tree during execution may be visible to the command but is never publishable, matching Codex and Claude Code's Linux sandbox limitation because bubblewrap masks concrete paths collected at launch.” Update changesets/limits rows for identical-copy-up dropping, discarded existing ignored edits, baseline conflicts and unchanged candidate caps. Update Linux enforcement with the supervisor-mounted mechanism, upstream Linux 6.6/equivalent-backport tmpfs-user-xattr floor and actual probes, with no bwrap overlay-option minimum. Other Tool families retain their protections.
- **Selection result.** Linux overlay commands return `selection: Some(CommandSelectionSummary)` through S1c and afterwards. `ignored_entries` counts launch inventory entries classified ignored/dependency, `pruned_directories = 0` (ignore rules do not prune Linux reads), `oversized_inputs = 0` (no size-based input omission), and `discarded_outputs` counts safe upper changes/deletions discarded by frozen rules, including existing ignored paths. Identical copy-ups count neither as discarded nor as changes. Whole-subtree protection masks are not fabricated ignore counts; document them in enforcement/disclosure semantics, retaining the existing result schema and bounded counters. macOS retains its current copy-selection meanings.
- **Storage exhaustion.** Bound tmpfs bytes and inodes, but do not infer atomic command success from ENOSPC or a zero exit. ENOSPC follows existing nonzero-exit semantics: after positive cleanup, valid bounded selected partial changes may publish with their actual output/exit result. Unsafe/over-cap candidates and baseline/publication conflicts publish nothing. There is no unsupported promise that storage exhaustion rolls back or automatically suppresses every partial write.
- **S2/S3 and macOS.** S2 binds an owner-only per-Workspace StateRoot cache at `/cache`, enforces its existing storage policy, and reports/clears it with existing commands; Linux archive/candidate/staging/generation transport retires and `cache_update` uses existing `NotApplicable`. S3 uses all controller cores for Build, leaves Cargo jobs unset by default and lets `/settings` lower them; default-class CPU/memory/PID/time bounds stay unchanged. macOS retains selected copies, fixed storage and archive caches. Each implementing tools.md enforcement/limits row names its platform difference; no native parity claim follows from this plan.

## Chosen direction and security model

Reuse the binary, unit supervision, admitted handles, scan budget, mount builder, changeset types and publication path. A retained namespace owner is necessary for capture isolation; add no daemon, crate, dependency, generic adapter or host fallback. Supervisor mounting is the smallest complete identity solution: its added mount call replaces bwrap overlay-argument construction and layer-string attestation, avoids the 0.11 floor, and permits direct setup probes before privilege removal. Use standard Linux namespace/mount APIs behind the existing Guard boundary. Each slice updates the enforcement digest for its actual profile.

Assets are Workspace bytes, protected data, StateRoot/account data and capture metadata. User grants supply authority; repository content, payload output and upper metadata do not. Only a capability-free parser consumes payload-controlled upper data after positive teardown. StateRoot/account/home and raw upper/work stay absent from payload mounts. READY/GO, deterministic Policy, committed intent/verdict and typed publication retain their owners. E states accepted disclosure limits, never publication exceptions. One tmpfs bounds all uppers/workdirs together; the narrow-parent tmpfs has its separate derived bound. Existing preparation/capture CPU, memory, deadline, output and report envelopes remain finite. Overflow masks only where E explicitly defines a complete enclosing mask; candidate overflow refuses the whole candidate. Every slice receives the [security pass](../../agents/security.md#security-pass-triggers) for its actual mount, capability, filesystem or capture change.

## Risks and mitigations

- Missing tmpfs user xattrs, usable user namespaces or LSM permissions → direct probes and attestation refuse before GO; no kernel-version-only or overlay-mount-only success claim.
- Large real trees (including hard-linked Cargo artifacts and pnpm packages) exceed discovery bounds → retain ordinary lower links and mask an enclosing subtree completely; no extra metadata budget or secret-content reads.
- External lower mutation or aliasing can disclose data within E's non-claims → frozen masks and bounded baseline checks protect publication, while tools.md states the disclosure widening honestly.
- Privileged capture or premature walks → clear all capabilities and set NNP before READY, pin/wait/reap bwrap, retain positive descendant cleanup, and parse only afterward; unknown outcomes stop continuation.
- Whiteout/opaque mistakes lose files → S1a2 ordinary deletion first, S1c bounded baseline subtree deletion, strict private-metadata table and existing digest preconditions.
- Slice growth → the estimates below include code, tests, documentation and deletions; re-inventory and split by observable risk before implementation if the ceiling cannot hold. Do not drop evidence or security work to fit.
