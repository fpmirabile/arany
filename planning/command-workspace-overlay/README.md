## Outcome and scope

One capability: on Linux a guarded primary `Command` sees the admitted directory roots as read-only lower layers of private overlays, including dependency directories, build outputs and large files. Writes stay in bounded private uppers and reach the Workspace only through validated changesets with receipts. Granted single files are read-only mounts; narrow `workspace_paths` never disclose siblings. The build cache becomes a per-Workspace directory bind and Build CPU/jobs defaults follow the peers. macOS keeps disposable-copy semantics as a documented platform difference. This serves [Tool execution for real projects](../../AGENTS.md#product-and-implementation-priorities); no `AGENTS.md` guarantee changes.

Owner decision **O1, 2026-10-26**, approves **B+C+E** from the overlay review: B, a same-binary namespace helper with bounded, inspectable tmpfs uppers; C, one overlay per granted directory and read-only granted files; E, masks for protected names present at launch at any depth, with the accepted live-lower limitation below. This refines owner decision 3B of 2026-10-25; the original single S1 becomes S1a/S1b/S1c.

This plan absorbs the toolchain/cache visibility and Build jobs/CPU parts of the `NEXT_STEPS` “Daily use first” items “`cargo test` here inside the Guard” and “Development command environment”. Their socket-dependent test ignores/local IPC and opt-in network allowlist proxy remain there. Excluded: worker private targets (shared-editor plan), MCP and Skill snapshots (still 32 MiB), and macOS real-path execution.

## Research

Claims from the uncommitted `wt/cwo-s1` plan section “S1 research corrections and open questions” and the local architecture review's `#overlay` section were checked against current code at `d66e18a8` and upstream sources on 2026-10-26. They are research inputs, not authority. O1 resolves the bootstrap, narrow-grant and disclosure choices as follows.

- **Current path and ownership.** [`guard/linux.rs`](../../crates/arany/src/tools/guard/linux.rs) `BWRAP_BOOTSTRAP` executes `unshare` directly into bwrap, with no intervening tmpfs setup. `profile_arguments` has the writable/read-only `/workspace` bind branches and a bounded tmpfs branch. `verify_runtime_mounts` currently retains only target paths and propagation fields: it needs overlay filesystem/options/identity checks, not merely another target. [`fs/command.rs::prepare_command`](../../crates/arany/src/tools/fs/command.rs) iterates only `config.workspace_paths`. [`config.rs::validate`](../../crates/arany/src/tools/config.rs) caps them at 32 and rejects duplicate/overlapping roots. [`validate.rs::forbidden`](../../crates/arany/src/validate.rs) owns protected components, case-insensitively, including `.git` and `.env.*`; do not invent a separate mask deny list.
- **Bootstrap correction (B).** Bubblewrap opens overlay sources and upper/work through `/oldroot` during `setup_newroot`; a sandbox `--tmpfs` cannot supply these earlier source paths. `--tmp-overlay` deliberately hides its upper from host and child. The [source](https://github.com/containers/bubblewrap/blob/main/bubblewrap.c) and [manual](https://github.com/containers/bubblewrap/blob/main/bwrap.xml) confirm the need for an outer namespace-owned tmpfs. Overlay options arrived in [bubblewrap 0.11.0](https://github.com/containers/bubblewrap/releases/tag/v0.11.0), not 0.8.0 as the old plan claimed; probe the actual executable/features and fail closed. A process that execs bwrap cannot later perform capture: retain a same-binary supervisor in the outer namespace; its child execs bwrap. Do not wait for an empty whole cgroup while that supervisor is still alive.
- **Overlay metadata and capability.** The [kernel overlayfs contract](https://docs.kernel.org/filesystems/overlayfs.html) requires upper/work on the same suitable filesystem; whiteouts may be device 0/0 or zero-length regular files with the overlay whiteout xattr. Opaque directories and whiteout containers have distinct `opaque=y`/`opaque=x` meanings. `userxattr` selects `user.overlay.*`; the bwrap source requests it. [tmpfs source](https://github.com/torvalds/linux/blob/master/mm/shmem.c) implements user xattrs, but a version number alone cannot establish support. Probe mounting and the create/delete/recreate semantics on the actual tmpfs before GO. Recognize only supported kernel metadata; reject unsupported redirect/metacopy/type forms rather than publishing a guessed diff.
- **Disclosure correction (C+E).** A Workspace-root overlay would disclose ungranted siblings. Mount directory grants separately over an otherwise empty `/workspace`, and bind granted files read-only. Launch masks need a bounded metadata pre-walk of every granted subtree, including `node_modules`, `target` and nested `.git`, without ignore pruning. The old selection/copy walker cannot simply retain its dependency exclusions. Masks cannot cover protected names first created or renamed into the live lower tree during execution; O1 accepts possible visibility, while publication still rejects every protected component.
- **Peer behavior and reason for divergence.** [Codex's Linux source](https://github.com/openai/codex/blob/main/codex-rs/linux-sandbox/src/bwrap.rs) expands unreadable globs to existing matches before constructing mounts. [Claude Code's sandbox runtime](https://github.com/anthropics/sandbox-runtime#filesystem-configuration) explicitly documents the same Linux read-glob limitation. O1 adopts this launch-time limitation. Arany retains private uppers and receipted publication because the peers' live writable mounts do not meet its publication guarantee. Neither peer supplies the combined bounded-upper/capture mechanism.
- **Existing success and failure flow.** [`process.rs`](../../crates/arany/src/tools/process.rs) stops descendants before `CAPTURE_READY` and snapshot comparison; [`guard.rs`](../../crates/arany/src/tools/guard.rs) owns READY/GO, bounded report transfer, cleanup and cache transport. The Engine's [`step.rs`](../../crates/arany/src/engine/run_loop/step.rs) owns the correlated `ApplyChangeset` publication. Preserve those boundaries. The cache remains archive-backed through S1c; Linux currently pins `CARGO_BUILD_JOBS=1` and default/Build quotas of 25%/one core. S2/S3 change those separately.
- **Owning contracts.** [tools.md](../../docs/specs/tools.md) owns folder trust, command selection/changesets, persistent cache, Linux/macOS enforcement and limits. [Overview §2/§6](../../docs/architecture/system-overview.md#2-runtime-architecture) owns Guard view/cache ownership. [Goals](../../docs/specs/goals.md#lifecycle-budgets-and-recovery) and [terminal](../../docs/specs/terminal.md#storage-report) own Build settings and storage presentation. Change each only with its implementing slice; this planning change does not assert implemented overlay support.

## Contract and scenarios

- **B — preparation, execution and capture.** Insert the same binary between `unshare` and bwrap inside the admitted Guard unit. Its supervisor mounts a private tmpfs at an owned runtime mountpoint outside the lower roots, sized by the existing aggregate project allowance (256 MiB primary / 1 GiB Build), creates upper/work pairs there, and retains their handles and the namespace in its supervisor. The setup child execs the pinned bwrap with `--overlay-src <admitted-root> --overlay <upper> <work> <destination>`. Retain only namespace-scoped setup capabilities for mounting; clear them before bwrap execution (the current bootstrap deliberately avoids passing retained capabilities to non-root bwrap). The payload retains zero capabilities/no-new-privileges/seccomp and cannot reach raw upper/work, the supervisor or its report descriptors. Inner mountinfo attestation binds every overlay, lower/upper/work identity, tmpfs bound, read-only file mount and mask to the immutable admitted task before READY and again before GO. GO still follows the committed intent/verdict. After positive payload-descendant cleanup, the retained supervisor walks the upper through no-follow handles and sends the bounded candidate on the existing report path; the controller then observes final unit cleanup. Helper death, missing cleanup proof or lost capture after GO is `Uncertain`, stops continuation and never retries; confirmed cancellation/timeout remains `Cancelled`/`Limit`, with no publication.
- **C — mount scope.** `/workspace` exposes only empty parent directories plus mounts for admitted roots; `["."]` is the single-overlay case. Each granted directory has a separate upper/work pair sharing one storage allowance, at most the existing 32 grant entries. Granted regular files use `--ro-bind`: commands can read but cannot modify them; typed mutations retain their existing authority. No sibling is mounted as a convenient ancestor or hidden alternate lower path. Revalidate identities and reject links/mount crossings or changes that prevent exact grant enforcement.
- **E — protected names and bounds.** Before launching the payload, the Guard pre-walks granted roots without following links or crossing unadmitted mounts, including dependencies and nested repositories, and masks each protected component at any depth. Directories use empty read-only masks; files use a read-only inert file. Reuse `validate::forbidden` and existing `CommandScanBudget` entry/path-metadata bounds (`COMMAND_SCAN_ENTRIES`, `COMMAND_PATH_METADATA_BYTES`), `COMMAND_SNAPSHOT_DEPTH` and the admitted preparation deadline; count masks against the existing mountinfo/argument/report bounds. Exceeding a bound is `Limit` before GO; inability to complete the protection walk or attest exact masks fails closed. No skipped subtree or truncated mask list is accepted. Retain existing rejection of unprotected links (including hard links), special files and set-ID inputs; masks must not leave an alias to protected content. Do not read secret content during discovery.
- **Same-PR tools sentence (S1a).** Scope the owning `tools.md` command-selection/protected-name sentence explicitly to Linux overlay commands: “Protected names present at launch are masked at any depth; a protected name created or renamed into the live lower tree during execution may be visible to the command but is never publishable, matching Codex and Claude Code's Linux sandbox limitation because bubblewrap masks concrete paths collected at launch.” Keep other Tool families' protection unchanged and make no `AGENTS.md` guarantee edit. Complete the protection walk and mask attestation before GO; make no continuous-filter or frozen-lower claim.
- **Changeset publication.** After cleanup, upper regular files yield created/modified entries; supported whiteouts and opaque directories yield explicit deletions, enumerating affected lower subtrees under the same caps. Read `before` through the admitted lower capability and `after` through upper handles. Only recognized overlay bookkeeping xattrs are accepted; links (including hard links), special files other than recognized whiteouts, set-ID bits, other xattrs, protected/out-of-grant paths, unsupported types and overflow reject the whole candidate. Preserve existing empty-directory behavior, binary/executable content, valid changes after nonzero exit, receipt correlation and `ApplyChangeset` preconditions/checkpoints. Neither upper walks nor masks authorize publication. No Event or stored-format change is planned.
- **Live lower is not a snapshot.** Kernel documentation warns that external changes to mounted lower trees have undefined overlay behavior; do not promise coherent concurrent reads or guaranteed visibility of a newly introduced path. E permits visibility and never publication of a protected path. Revalidate candidate preconditions at publication; conflicts reject before writes as today, and unknown publication retains existing `Uncertain` semantics.
- **S2/S3 final contract.** The cache becomes an owner-only per-Workspace StateRoot directory bound at `/cache`, counted by storage and cleared by existing commands; Linux archive/candidate/staging/generation-transfer machinery retires and `cache_update` uses existing `NotApplicable`. Build uses all controller cores, with Cargo jobs unset by default and `/settings` able to lower them; default-class CPU, memory, PID and time bounds remain unchanged. S2/S3 own their spec edits below.
- **macOS.** Retain selected copies, fixed-size storage and archive caches. Same-PR `tools.md` enforcement/limit rows explain dependency exclusions, the file cap and CPU/jobs differences as each Linux slice changes them. Existing macOS evidence remains authoritative; no new native parity claim.

## Chosen direction and security model

Use the existing binary, unit supervision, admitted directory handles, mount builder, scan budget, changeset type and typed publication path. The helper is required by mount-namespace lifetime and capture isolation; add no daemon, crate, generic adapter, dependency or host-execution fallback. Linux alone changes mechanism; macOS keeps its current copy path. Each slice updates the enforcement digest for its actual profile; do not preselect a stale next version number.

Assets are Workspace bytes, protected metadata/credentials, StateRoot/account data and private capture metadata. The user-owned grant supplies authority; repository content, payload output and upper metadata do not. Payload-controlled bytes cross into a bounded no-follow capture parser only after positive cleanup. StateRoot/account/home stay absent from payload mounts. Descendants inherit only the Guard grant and cannot access the retained supervisor/raw uppers. The normalized intent and READY/GO protocol remain the authority and ordering boundary. E is the explicit disclosure non-claim, never a publication exception. No host lower writes, widened grants or automatic retries are introduced.

One tmpfs bounds all uppers/workdirs together, not one full allowance per grant. Scan, mask count, path bytes, mountinfo, candidate content/entry/serialization, output, memory, PIDs, deadline and final cleanup retain finite limits with whole-operation refusal on overflow. S2 must enforce the existing cache/StateRoot storage policy on its directory bind, not merely count bytes afterwards. S3 changes Build CPU/jobs only. Every implementing slice receives the [Guard/security pass](../../agents/security.md#security-pass-triggers) for its changed authority, filesystem or capture boundary and meaningful refusal/recovery paths.

## Risks and mitigations

- Missing unprivileged overlayfs, tmpfs user xattrs or bwrap overlay support → an actual namespace probe fails closed before GO; version checks alone do not suffice.
- A supervisor that execs away, captures before descendant absence or waits for its own cgroup to empty loses the upper or deadlocks → retain the namespace owner, prove payload cleanup before capture and final unit cleanup afterwards; after-GO unknowns are `Uncertain`.
- Protected-name discovery now visits dependencies and can exceed its finite metadata/depth/mask bounds → refuse before GO and report the bound; never skip nested `.git` or widen a narrow grant.
- External lower changes can affect reads; E accepts new protected-name visibility → document the limitation with peer names in S1a, retain exact grant mounts and protected publication validation in every slice.
- Whiteout/opaque errors could publish wrong deletions → recognized-form tables and native delete/recreate journey, bounded subtree enumeration and digest preconditions on every publication.
- Cache growth and all-core builds → S2 enforces existing storage bounds/clear behavior; S3 retains default-class quota and user-lowered Build settings.
