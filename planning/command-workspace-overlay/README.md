# Commands on a Workspace overlay

## Metadata

- Status: `Ready`
- Owner: harness maintainers
- Last updated: 2026-10-25

## Outcome and scope

One capability: on Linux a guarded primary `Command` sees the whole admitted Workspace (dependency directories, build outputs, large files included) as the read-only lower layer of an overlay mount, writes only into a private upper layer, and that upper layer is the changeset candidate the Guard validates and the primary publishes; the build cache is a bind mount of a per-Workspace directory instead of an archive; CPU and job defaults follow the peers. macOS keeps today's disposable-copy semantics as a documented platform difference. The harness responsibility served is Tool execution for real projects ([priority 1](../../AGENTS.md#product-and-implementation-priorities)); the [per-effect isolation](../../AGENTS.md#non-negotiable-guarantees) guarantee is kept verbatim (the payload never writes the Workspace; publication stays through validated changesets with receipts). Owner decision 3, Option B, 2026-10-25: "keep Arany's security philosophy but relax this situation".

This plan absorbs the overlapping parts of two `NEXT_STEPS` "Daily use first" items: from "`cargo test` here inside the Guard" the toolchain/cache visibility and the Build jobs/CPU profile (the socket-dependent test ignores and the local test IPC capability remain there); from "Development command environment" the all-cores default (the opt-in network allowlist proxy remains there). Both items link here instead of restating. Excluded: worker (editor) private targets (decision 5), MCP and Skill snapshots (they keep the 32 MiB project snapshot), macOS real-path execution (a separate decision; see Platform below).

- bubblewrap overlay options: `--overlay-src SRC` (one or more lower layers), `--overlay RWSRC WORKDIR DEST` (persistent upper), `--tmp-overlay DEST` (tmpfs upper), `--ro-overlay DEST` ([bwrap(1)](https://github.com/containers/bubblewrap/blob/main/bwrap.xml), since 0.8.0). Unprivileged overlayfs inside a user namespace is available from Linux 5.11; whiteouts appear in the upper layer as character devices 0/0 and opaque directories as the `trusted.overlay.opaque`/`user.overlay.opaque` xattr (unprivileged mounts use the `user.` namespace, kernel ≥ 5.11 with `userxattr`).
- Peers: Codex runs commands in the real working directory under bubblewrap (default) or Landlock plus seccomp with `writable_roots`, `.git`/`.codex`/`.agents` read-only ([approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security), [codex-rs/sandboxing](https://github.com/openai/codex/tree/main/codex-rs/sandboxing)); no CPU cap, all cores. Claude Code: bubblewrap with writes limited to cwd and `--add-dir`, a host-side proxy for allow-listed domains, no CPU cap ([sandboxing](https://code.claude.com/docs/en/sandboxing)); Bash default timeout 2 minutes, ceiling 10 ([tools reference](https://code.claude.com/docs/en/tools-reference)). Neither copies the project or archives a build cache.

## Contract and scenarios

- Owning contracts: `tools.md` sections above, `execution.md` [Committed Event stream](../../docs/specs/execution.md#committed-event-stream) (unchanged Events), `goals.md` [Lifecycle, budgets and recovery](../../docs/specs/goals.md#lifecycle-budgets-and-recovery) (Build settings), `terminal.md` [storage report](../../docs/specs/terminal.md#storage-report) and `/settings` Build rows, overview §2/§6.
- Proposed Linux contract: the payload's `/workspace` is `--overlay-src <admitted Workspace> --overlay <upper> <work> /workspace` where `upper` and `work` are fresh directories in the unit's private tmpfs (bounded by the existing writable project storage: 256 MiB primary, 1 GiB Build, in the tmpfs `--size`); `.git`, `.arany`, `.env*` and the other protected names are masked with `--tmpfs`/`--ro-bind /dev/null` over their paths exactly as the selection excluded them (so Git neutralization is unchanged); dependency directories are no longer excluded (they are visible read-only and writable through the upper layer). Selection, the 1 MiB per-file omission, the 128 MiB snapshot and the `SELECTION_READY` preparation process do not run on Linux. After positive descendant termination the Guard walks the upper layer under the existing changeset caps: regular files → created/modified entries with `before` from the lower tree (digest read through the admitted capability, no-follow) and `after` from the upper file; whiteouts and opaque directories → deleted entries (whole-subtree deletions enumerate the lower tree under the same entry cap); anything else in the upper layer (links, special files, set-ID bits, xattrs) rejects the whole candidate as today's "unexcluded links reject preparation". The receipt, `ApplyChangeset` intent, precondition validation and publication are unchanged. The build cache becomes `--bind <StateRoot cache>/<workspace identity> /cache` (owner-only directory, created on first use, counted by the storage report, cleared by `/cache clear [all]`); the archive, candidate, staging, generation lease and `cache_update` publication states are retired and `cache_update` records `NotApplicable` (the value exists). Defaults: Build CPU quota = all controller cores (`cpu.max max 100000`), Build jobs unset (Cargo's default) unless the user lowers them in `/settings` (range 1–controller cores), default class keeps 25% of one core for non-build commands; memory, PID and time bounds unchanged.
- macOS contract: unchanged mechanism (selected copy, fixed-size volume, archive cache); `tools.md` §macOS gains one paragraph stating the difference and the user-visible effects (dependency directories excluded, 1 MiB file cap, one-core builds), and §Limits splits the affected rows into Linux and macOS columns. Parity evidence that remains: the macOS `session_run/tools_macos.rs` corpus for the copy path; no macOS claim changes.
- Successful path: `cargo test -p arany --lib` on this repository inside the Guard on Linux reuses `target/` through `/cache`, runs on all cores, returns the test receipt and an empty changeset; `npm test` in a project with `node_modules` sees them; a command that edits three files and deletes one returns a four-entry changeset published through `ApplyChangeset`.
- Rejection/failure/recovery: kernel without unprivileged overlayfs → `ProtectionUnavailable` before GO, no fallback to copy (fail closed, Linux only); an upper layer containing a symlink or set-ID file → candidate rejected, nothing published, command disposition unchanged; upper layer over the storage bound → the unit's tmpfs refuses writes and the command fails with `ENOSPC` output, nothing published; a changeset over the entry cap → whole record refused before publication as today; cancellation or timeout → `Limit`/`Cancelled`, no publication; capture failure after GO → `Uncertain`, Run stops; a concurrent host edit between the command and `ApplyChangeset` → digest precondition fails at publication as today.
- Evidence owners: `crates/arany-cli/tests/session_run/tools/native_exec.rs` (overlay command journeys, cache reuse, `guarded_offline_cargo_tests_use_selected_runtime_and_registry` adjusted to the mount), `crates/arany/src/tools/fs.rs` tests (upper-layer walk and whiteout classification tables), `crates/arany/src/tools/guard/linux.rs` tests (mountinfo attestation of the overlay and masked paths), `tests/session_run/storage.rs` (cache directory inventory), `guard_runs/latency.rs` (new no-op command row), `tests/engine_run/workspace_security.rs` (protected names masked; `.git` never visible), macOS corpus unchanged.

## Chosen direction

- Simplest sufficient solution: extend the existing `/workspace` bind branch with the overlay arguments; replace the snapshot diff with an upper-layer walk feeding the existing `CommandChangeset` type; replace the cache archive with a bind of a directory; delete the Linux preparation/selection process and the `build_cache.rs` archive machinery. No new daemon, format or configuration surface; `/settings` Build rows keep their names with new ranges.
- Linux/macOS impact: Linux changes; macOS keeps copy semantics. The parity rule ("Document unavoidable differences in the owning contract") applies; the owner accepted the difference. A separate macOS decision (Seatbelt writable Workspace with a before/after digest changeset, Codex's model) would need its own brief because it weakens the publication clause on that platform.
- Interface change: `CommandSnapshot`/`command_changeset` gain a Linux upper-layer source; `BuildCacheSession`/`BuildCacheTransfer` are deleted; the enforcement digest string changes (new `arany-guard-v17` prefix). Not a module boundary change.

## Security and resource model

Disclosure widens by design: the payload reads every unprotected Workspace file instead of a selection; this is the peers' model and the Workspace is the user's trusted folder. Protected names stay masked; `.git` is never visible (Git neutralization unchanged); the StateRoot, account root and host home are not mounted (unchanged). The payload cannot write the lower layer (overlayfs semantics plus `--ro-bind` of the source); the upper layer is private tmpfs under the unit's storage bound; publication validates every precondition against the live Workspace through the mutation path (now in process per decision 4). New attack surface: upper-layer content is attacker-controlled (the payload wrote it); the walk treats it as untrusted bytes with the same type/link/set-ID/xattr rejections the snapshot capture applies, and never follows anything. Cache directory: owner-only, outside the Workspace, writable by the payload (as the tmpfs view is today); a poisoned cache can only affect subsequent guarded builds, which is also today's property. Bounds: writable storage 256 MiB / 1 GiB, changeset caps unchanged, cache directory counted against the 8 GiB StateRoot aggregate with the existing clear commands, CPU all cores (bounded by cgroup `cpu.max`), memory and PIDs unchanged. The security pass for a changed Guard profile ([triggers](../../agents/security.md#security-pass-triggers)) runs in slice 1.

## Risks and mitigations

- Kernels or distributions without unprivileged overlayfs (older than 5.11, or `user.max_user_namespaces=0`) → fail closed with a named enforcement cause; `arany storage`/`/settings` surfaces the capability; no silent copy fallback (one Linux contract, not two).
- Whiteout and opaque-directory handling errors publish wrong deletions → the walk is table-tested per case in `fs.rs`; whole-subtree deletions are capped and listed entry by entry; the mutation path still validates every `before` digest before deleting.
- Large `target/` directories in the cache bind push the StateRoot aggregate → counted in the storage report with the existing `/cache clear`; the 8 GiB aggregate and the Build setting still bound it.
- All-cores builds starve the terminal → the default class keeps its quota; only the Build class uses all cores, under `cpu.max`, and `/settings` can lower it.

## Exit criteria

- Linux CI: a guarded command on this repository sees `target/` and `Cargo.lock`, publishes a validated changeset from the upper layer, reuses the cache directory across two commands, runs on more than one core (asserted through `nproc` output inside the unit), and `cargo test -p arany --lib` completes inside the Guard with its ignored-count receipt.
- Failure observations: overlay unavailable → fail closed before GO; link/set-ID in the upper layer → candidate refused; storage bound → command failure without publication; capture failure → Uncertain.
- macOS CI: the copy-path corpus unchanged; `tools.md` names the difference.
- `grep -rn 'SELECTION_READY\|BuildCacheTransfer' crates/arany/src/tools/guard/linux.rs crates/arany/src/tools/guard.rs` returns only macOS-gated code; contract updates as listed; NEXT_STEPS items rewritten as described. Delete this folder when slice 3 lands.
