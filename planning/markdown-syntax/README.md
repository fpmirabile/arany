# Remaining Markdown syntax

## Metadata

- Status: `Draft` (owner decisions D1–D3 below; each carries a recommendation that makes the plan `Ready` once accepted)
- Owner: harness maintainers
- Last updated: 2026-10-27

## Outcome and scope

One capability: assistant Markdown prose, links, decoded fence labels, lists and quotes render readably in Fullscreen, its pager, Classic and selected agent results, with the original Markdown unchanged as the source of copy, find and export. This continues the delivered heading, code-block, table and provisional/recovered projection ([terminal contract](../../docs/specs/terminal.md#conversation-progress-and-history)) and serves the harness's terminal presentation responsibility.

It delivers the five slice IDs preserved in [NEXT_STEPS](../../NEXT_STEPS.md#terminal-follow-ups): S1b paragraphs and inline styles, S1c direct inert links with the projection coordinate, S1d decoded and reference links, S2b decoded fence labels, S2c lists, quotes and nested code. Excluded: syntax highlighting (no lexer is loaded; a separate proposal on owner demand), HTML/image interpretation, strikethrough, task-list markers, thematic breaks and footnotes (stay literal source, D3), linear/screen-reader, `exec`, `show`, JSONL, serve and ACP text, and any new view, setting, protocol item or journal format.

## Research

### Current code (verified 2026-10-27)

- Parser: `pulldown-cmark =0.10.3` with default features off, already a workspace dependency ([Cargo.toml:14](../../Cargo.toml)), used only by `arany-cli`; runtime options are `ENABLE_TABLES` alone ([blocks.rs:41](../../crates/arany-cli/src/terminal/markdown/blocks.rs)). No dependency change is needed, so the supply-chain review is the existing one.
- Layout is per source line. `blocks::project` returns one `BlockLine` per `\n`-split line carrying `original/envelope/content` ranges, `padding`, a `Modifier`, `hidden` and an optional `Table` ([blocks.rs:5-14](../../crates/arany-cli/src/terminal/markdown/blocks.rs)); `markdown::layout` walks those lines and `layout_line` wraps by grapheme with a prefix and `source_range` envelope mapping ([markdown.rs:30-129](../../crates/arany-cli/src/terminal/markdown.rs)). Only top-level ATX headings are styled; a multi-line heading (setext) returns early ([blocks.rs:113](../../crates/arany-cli/src/terminal/markdown/blocks.rs)), and code nested in a container is not projected (`depth == 0` guards at [blocks.rs:56-64](../../crates/arany-cli/src/terminal/markdown/blocks.rs)). Fence info strings are taken from the raw opening line, so they are literal, not decoded ([blocks.rs:132-153](../../crates/arany-cli/src/terminal/markdown/blocks.rs)).
- The decoded-text machinery already exists, but only for tables: `Table::inline` keeps a style stack for emphasis/strong/inline code, `append` maps each decoded grapheme to a source range by `find`, and `envelope` widens first/last cell to the construct's source range ([tables.rs:63-182](../../crates/arany-cli/src/terminal/markdown/tables.rs)). Links and images inside a cell are emitted as literal source ([tables.rs:85-93](../../crates/arany-cli/src/terminal/markdown/tables.rs)). S1b extracts this into a shared inline flow instead of writing a second decoder.
- `tables::append` locates each decoded grapheme with `source[cursor..end].find(text)` ([tables.rs:144-170](../../crates/arany-cli/src/terminal/markdown/tables.rs)). pulldown-cmark 0.10.3 normalizes a multiline inline code span (backtick, `a`, newline, `b`, backtick) to the text `a b`; the joining space does not exist in the source, so `find` fails for it, the cell falls back to the whole construct range, and the following `b` is mapped from that fallback. Parser event offsets identify only the whole span. `word_at` scans raw source lines ([history.rs:798-820](../../crates/arany-cli/src/terminal/history.rs)), so a visible word spanning the normalized join is not selectable as one word either.
- Each emitted `Cell { byte, source, text, style }` already carries a source range and sanitized text ([markdown.rs:19-24](../../crates/arany-cli/src/terminal/markdown.rs)); `History` rows hold `cells: Option<Vec<Cell>>` and a `source_byte` ([history.rs:80-82](../../crates/arany-cli/src/terminal/history.rs)). Consumers: `message_rows` (drawing, selection, find) and `markdown_cost` (nonretaining counts, Classic budget) call the one `markdown::project` ([history.rs:1770-1790,1876-1886](../../crates/arany-cli/src/terminal/history.rs)); `word_at` uses `markdown::content_at` ([history.rs:798-820](../../crates/arany-cli/src/terminal/history.rs)). `formats_markdown` selects Assistant, AgentResult, Preview and Incomplete ([history.rs:1626](../../crates/arany-cli/src/terminal/history.rs)), so provisional and recovered text already share every change.
- The anchor model is the S1c/S1d risk. `row_of_byte` finds a row by cell source containment, else by monotonic `source_byte` `partition_point`; `row_span` and `selected_cells` derive a row's source span from the next row's `source_byte` ([history.rs:1665-1760](../../crates/arany-cli/src/terminal/history.rs)). That relies on rows following source order and a row never aliases a distant range. An autolink shown twice (S1c), reference-link and repeated destinations (S1d) and decoded entities violate both, so S1c replaces the span derivation with a width-independent projection coordinate separate from copy provenance.
- Bounds are one owner: parse bytes, depth, events, output bytes, rows and table limits in `markdown.rs` ([markdown.rs:10-17](../../crates/arany-cli/src/terminal/markdown.rs)), mirrored in the [generated limits](../../docs/specs/limits.md#max_markdown_parse_bytes). Overflow selects whole-message escaped literal fallback plus one cue ([terminal.md](../../docs/specs/terminal.md#conversation-progress-and-history)).
- Evidence owners: [Markdown corpus](../../crates/arany-cli/src/terminal/history/markdown_tests.rs) (747 lines, ten tests, shared consumers/counts/copy/find/resize/limits), [History](../../crates/arany-cli/src/terminal/history.rs), [frame corpus](../../crates/arany-cli/src/terminal/view/tests.rs), the Classic insertion corpus in [terminal.rs](../../crates/arany-cli/src/terminal.rs), [agent inspector journey](../../crates/arany-cli/tests/session_run/agent_inspector.rs), [clipboard](../../crates/arany-cli/src/terminal/clipboard.rs). The scenario rows are "Older history" and "Terminal continuity" in terminal.md; native readability stays in the [NEXT_STEPS terminal row](../../NEXT_STEPS.md#beta-2-and-broader-release).
- History: slices S1a, S2a, S3 and S4 of the closed rendering plan are merged (#521, #531, #538, #541); its text, including the S1b–S2c scopes, is in git history at `dd2a7da2^:planning/markdown-rendering/README.md`.

### Peer behavior (read from source)

- Codex CLI at the commit the closed plan pinned (`970111f6`), [`markdown_render.rs`](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/tui/src/markdown_render.rs): one `pulldown-cmark 0.10.3` event writer. Soft break pushes a new line (`soft_break`, L998-1015, so source line boundaries are kept); hard break pushes a line (L984); prose is word-wrapped with `textwrap` using initial/subsequent indents, and code lines are not wrapped (L2335-2360). Web links render the label followed by ` (destination)` styled as a link, even when the label equals the destination (`push_link`/`pop_link`, L2187-2230; `should_render_link_destination` L455); local-path-like links show the target instead, an OS/path lookup Arany excludes as non-inert. Images emit no tag (`Tag::Image` falls through, L728), so only alt text shows. Lists/items keep hanging indents through initial/subsequent indent stacks (`start_list` L1017, `start_item` L1038); strikethrough, task lists, rules and footnote references have handlers Arany does not adopt (D3).
- Claude Code: its [accessibility](https://code.claude.com/docs/en/accessibility) and [interactive-mode](https://code.claude.com/docs/en/interactive-mode#side-questions-with-btw) docs describe formatted terminal output with raw Markdown on `/copy` (hard-wrapped mouse copy differs from source). It documents no parser or link rule beyond that, and its hyperlink escape sequences are excluded here by the inert-rendering guarantee. Codex is therefore the direct source-level precedent.

## Contract and scenarios

- Owning spec: [terminal.md](../../docs/specs/terminal.md#conversation-progress-and-history). Every slice rewrites the paragraph that now says "Other inline syntax, lists and block quotes remain escaped literal source" and "Code inside lists/quotes and decoded info strings remain outside this projection" for the syntax it ships, and extends the "Older history" row (terminal.md Acceptance scenarios) and, in S1d, the selection sentence under idle `/copy`. Bounds stay links to [generated limits](../../docs/specs/limits.md#max_markdown_parse_bytes); a new bound is declared beside `markdown.rs` and linked, never restated.
- Successful path per slice: committed text, provisional snapshots and reopened incomplete text render through both attached modes, pager and agent results at 16, 40, 50, 80 and 120 columns; counting agrees with drawing and Classic costs; `/copy` and whole-body selection return the original Markdown; partial, whole-construct and word selection map to contiguous source; literal find steps through source matches in rows, including across reflow; resize and append keep the reading anchor.
- Failure and recovery: hostile controls, bidi and C0/C1 sequences in raw and entity/escape-decoded text, link destinations and fence labels reach the backend only escaped; HTML, images, titles and unsupported extensions stay literal; depth at/over [the limit](../../docs/specs/limits.md#max_markdown_depth), events, output bytes and rows fall back for the whole message with the one cue and no change to the answer or Run; rejected, cancelled and reopened provisional text behave as delivered by S4.
- Deferred checks: native emulator readability, real screen-reader use and Linux/macOS visual parity stay in the existing NEXT_STEPS terminal/accessibility row. TestBackend frames establish none of them.

## Chosen direction

- Simplest sufficient solution after Ponytail: reuse the pinned parser, the existing `Cell`/source-range model, `escape_terminal`, `unicode-segmentation`/`unicode-width` and the shared `project`/`layout` entry. S1b generalizes the table inline decoder into `markdown/inline.rs` (a pure move plus paragraph use) and word-wraps its cells in `layout`; the remaining slices add event handlers for the remaining constructs behind the same `BlockLine`-level projection. No new crate, trait, setting, cache, retained AST or lexer.
- Behavior choices (peer parity, D1–D2): soft breaks keep the source line boundary (row break), hard breaks add a row, prose wraps at spaces and long words/URLs break at graphemes with the existing safe replacement; a link renders `label (destination)` exactly as Codex does, including when the label equals the destination.
- Placement per [binary practice](../../agents/arany-cli.md#growth): new flows go in family children under `terminal/markdown/` (`inline.rs`, `links.rs`, `lists.rs`), so `markdown.rs` and `blocks.rs` do not grow past the file-size signal; tests go in a new sibling of `markdown_tests.rs` per slice rather than extending it past 1,000 lines.
- Linux/macOS impact: none. The renderer is pure Rust terminal-cell logic with no OS facility; native terminal evidence stays deferred as above.
- Hard-to-reverse decision: the anchor model (S1c, extended by S1d) moving from row-order source bytes to a width-independent projection coordinate separate from copy provenance. Alternative considered: keep monotonic `source_byte` and forbid aliasing by rendering reference destinations as literal source; rejected because it leaves the bullet's repeated/decoded destinations undone and makes find results land on the wrong row.

## Security and resource model

Security pass triggers: untrusted rendering of attacker-controlled model text and parsed URLs ([security pass](../../agents/security.md#security-pass-triggers)); no Tool, effect, credential, file, network or process is added. The boundary stays raw assistant source → parser-decoded data → escaped fragments → trusted styles. Rules every slice must hold and test:

- Sanitize every emitted string after decoding (entities, backslash escapes, destinations, labels) with the existing escaping, because the parser unescapes destinations; test direct and encoded payloads (`&#27;`, `\x1b`, bidi overrides, carriage returns) through both consumers. Link titles are never shown. Links are never fetched, opened, path-resolved or emitted as OSC 8; the clipboard OSC 52 mechanism is unchanged and content cannot create it.
- Amplification: a reference definition used many times, or a long destination, multiplies generated bytes. Count generated destination and marker bytes under [the output bound](../../docs/specs/limits.md#max_markdown_output_bytes) and [row bound](../../docs/specs/limits.md#max_markdown_rows) before materializing (S1d test at the limit and one over); overflow is whole-message fallback.
- Aliased source ranges (reference definitions far from the use) widen a selection's contiguous source copy; the existing clipboard limit and control escaping bound the copy, and S1d tests an aliased endpoint selection.
- Nesting: list/quote nesting counts against [the depth bound](../../docs/specs/limits.md#max_markdown_depth) with the same pre-push check; no recursive renderer.
- Parser construction keeps the stated no-RSS/deadline-guarantee caveat; none of these slices change it, and no diagnostics or telemetry log source, URLs or fragments.

## Risks and mitigations

- Counters, drawing and anchors drift when paragraphs span source lines → one layout owner stays; every slice asserts count-only rows equal drawn rows and Classic costs at the five widths.
- Word wrap at tiny widths loses content → keep the grapheme fallback and `…`/empty replacement already in `overflow_replacement`; test widths 1–3.
- Decoded text maps to the wrong source range → S1b replaces the `find`-based origin with normalization-aware parser-offset mapping (Research, multiline inline code) and pins it with entity, escape and multiline-code regressions; this is decided here, not left to implementation.
- The S1c anchor rewrite regresses table/code/heading selection → the existing "Older history" tests run unchanged and gain aliasing cases.
- Slice grows past its estimate → split by observable syntax within the same ID family before editing, never move tests or spec to another PR.

## Vertical slices

Estimates count added plus deleted lines (code, tests, spec, limits). Each slice is one PR on the previous merged one, is usable alone, and carries its consumers, [terminal.md](../../docs/specs/terminal.md) edit and evidence together. The ceiling is the repository's 1,500 lines ([slice delivery](../PLANNING.md#slice-delivery)); D2 below records why this plan does not keep the earlier 600-line figure.

1. **S1b — Paragraphs and inline styles (est. 1,050).** Paragraph and setext-heading source → shared inline flow extracted from `tables.rs` (move) → word-wrapped rows with source-line-preserving soft breaks, hard breaks, decoded text, bold/italic/inline code with hidden delimiters → drawing, counts and Classic cost through History, pager and agent results → source copy envelopes, visible-word selection and find. Same PR: terminal.md prose and "Older history" scenario row, tests in a new sibling of `markdown_tests.rs`. Origin mapping is normalization-aware: graphemes of a text/code event map to successive source graphemes by a forward cursor over the event's range; a grapheme with no source counterpart (the joined newline-to-space in multiline code, a decoded entity's extra bytes) takes the range of the source bytes it replaces (the line break and its indentation, or the whole entity), and the next grapheme resumes after that range, so no later grapheme inherits a construct-wide fallback. `word_at` (and `content_at`) select by the visible cells of the row/paragraph, not by raw source lines, so a word across the join is one word. Required regressions: multiline inline code, entity and backslash-escape origins, word selection across the join, partial and whole copy. Links and images stay literal inside the flow.
2. **S1c — Direct inert links and the projection coordinate (est. 950).** Inline `[label](dest)` and `<autolink>` → `label (destination)` with link styling and no effect (the destination is appended even when it equals the label, as in Codex), wrapping at word/grapheme boundaries. Because an autolink displays its URL twice from the same source bytes, this slice introduces the width-independent projection coordinate and repairs its consumers: each `Cell` gains a projection coordinate `(use-site byte, fragment, grapheme offset)` that is strictly increasing in render order and independent of width, separate from `Cell.source` (copy provenance, which may alias the same or a distant range). Saved reading anchor (`top`/`anchor` triple), `matched_source`/`matched_row`, `TextPoint` and `Selection` endpoints and ordering, and the selection-range consumers (`selected_cells`, `row_span`, `word_at`/`content_at`, `row_of_byte`) key on the coordinate; copy unions the `source` ranges of selected cells plus the construct envelope; find matches source text and resolves a match inside a construct to its first rendered copy, stepping in row order. Required regressions: a wrapped autolink with resize while reading and while a match is current on the appended (second) copy (stays there, never jumps to the label copy), partial selection starting in a continuation row of the second copy, and highlight not aliasing both copies. Same PR: spec sentence replacing "Links … remain inert literal source" with the inert projection while keeping HTML and images literal; counts, both consumers, whole/partial source selection, find and reflow; hostile destination tests.
3. **S1d — Decoded and reference links (est. 600).** Reference/shortcut/collapsed links and decoded destinations → cells whose `source` aliases a definition elsewhere, on the S1c coordinate (fragment/grapheme offset runs through the whole expanded destination, so a six-byte `[x][r]` use displaying hundreds of graphemes keeps distinct endpoints in every wrapped row). A match inside a definition resolves deterministically to its first rendered use; stepping visits uses in row order. Required scenarios: the same reference used twice, with resize while reading and while a match is current on the second use, and partial selection and resize starting from a continuation row of the second repeated destination (anchor stays in that row's use, copy returns that use's envelope); plus repeated-destination amplification and expansion fallback. Same PR: spec selection/find sentences and the amplification bound test.
4. **S2b — Decoded fence labels (est. 380).** Fence info strings parsed and decoded by the parser → sanitized label with per-fragment source origins → counts, both consumers, partial/word selection, narrow-width find/reflow, hostile labels. Same PR: spec replacement of "decoded info strings remain outside".
5. **S2c — Lists, quotes and nested code, plus closeout (est. 1,000).** Ordered/unordered lists, block quotes and code nested in them, including empty and code-first items → markers and rails as generated anchored cells, hanging indents, CommonMark tab columns, continuation lines, depth-at/over-limit fallback → both consumers and counts. Same PR: spec sentence for lists/quotes, closing checklist under [slice delivery](../PLANNING.md#slice-delivery) (one line per ID naming its merged PR, one per exit criterion), unmet checks moved to NEXT_STEPS, removal of this plan, its index row and its NEXT_STEPS pointer per the [lifecycle](../README.md#lifecycle). If S2c measures above 1,300 lines, split lists from quotes/nested code as S2c1/S2c2 in a plan-scope PR before editing.

## Open questions

- **D1 — Soft breaks.** Codex keeps a source line break as a row break and the current contract says text "retains source line boundaries"; the closed plan proposed joining soft breaks into spaces. Recommendation: Codex parity (row break, word wrap within each line). It needs no spec reversal and keeps anchors simple. Owner decides.
- **D2 — Slice ceiling.** NEXT_STEPS retained a 600-line ceiling per ID while [PLANNING](../PLANNING.md#slice-delivery) allows 1,500 and larger slices are accepted; recommendation: use 1,500 with the estimates above, so S1b, S1d and S2c stay whole instead of splitting by layer. Link text follows Codex exactly (the destination is appended even when it equals the label), so it needs no decision. Owner decides the ceiling.
- **D3 — Extra syntax.** Strikethrough, task-list markers, thematic breaks and footnote references are rendered by Codex but are not in the NEXT_STEPS bullet. Recommendation: leave them literal in this plan and open a separate item if wanted (each needs a parser option and its own inert projection). Owner decides.

## Exit criteria

- For each syntax family, committed, provisional and reopened text matches its terminal.md rows at 16, 40, 50, 80 and 120 columns in Fullscreen, pager, Classic and agent results (Markdown corpus, frame corpus, Classic corpus and agent inspector journey), with counts equal to drawn rows.
- Hostile decoded controls, amplification at limit and one over, depth at/over limit and formatting-overflow fallback pass through both consumers; source copy, linear/`exec`/`show`/JSONL/serve/ACP text are byte-identical to before (existing external corpora unchanged and green).
- terminal.md describes the final projection with no stale "remain literal" statement for shipped syntax; generated bounds pass `scripts/spec-bounds.py`; typos, link/anchor check and `git diff --check` are clean.
- Unavailable here: native emulator, screen-reader and macOS visual evidence stay in the NEXT_STEPS terminal/accessibility row; the closing PR confirms that row still covers the new syntax and moves any gap there.
- Closeout: S2c removes this plan, its [planning index](../README.md#active-plans) row and the NEXT_STEPS pointer in the same change.
