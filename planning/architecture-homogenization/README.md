## Outcome and scope

When the last slice lands the repository satisfies the [exit criteria](#exit-criteria): refactor corpora pass unchanged, and the eight decision follow-ups prove their named behavior and format contracts. The harness responsibility served is [priority 3](../../AGENTS.md#product-and-implementation-priorities): a homogeneous codebase that the daily feature merge train (team roles, host commands, setup UI) can extend without re-learning each vertical's local conventions.

In scope, in priority order:

1. **Homogeneity.** Every vertical applies the same idioms ([house idioms](#house-idioms)); each slice names the idiom it applies and reviewers use the [checklist](#reviewer-checklist).
2. **One owner per rule** where today two copies can drift: Goal dimension order, hook-output parsing, budget-refusal reload, stop text and signals, in-memory account-index mutation.
3. **Finish the cuts** left as pure moves: `step.rs` into `permission/ask/intent/skills`, `cli/attached/run.rs` into approval/input flows (large platform tests stay in place), the reducer `tool.rs` and `worker.rs` arm sets, the remaining 250-line binary functions.
4. **Closed values over flags and names** where a closed value already exists: `ChildWork.editor: bool`, the ChatGPT-by-provenance check in the Run loop, `custom:` prefix strips in the binary, `ToolCall::is_*` via `matches!` beside the facts table.
5. **Decided ownership and persistence.** Cached admission (D2), an intent record at the journal boundary (J1–J2), Engine-owned Supervisor decisions (V1–V3), and tagged persisted Provider identity with migrations (K1–K2).

Out of scope, with the reason:

- Changes to model-facing bytes, `tests/fixtures/serve/schema.json` or `tools/snapshots/*.json`; journal/record format changes beyond K1–K2. Typed `ToolObservation` results, session-owned records beyond `EffectIntent`, and unifying the four journaled worker enums remain out of scope. J1–J2 preserve bytes; only K1–K2 may change their owned migration fixtures and digests.
- Behavior corrections found on the way: the Engine's `valid_editor_delegation` ([worker.rs:239](../../crates/arany/src/engine/run_loop/worker.rs)) and the reducer's `validate_request` ([reducer/worker.rs:457](../../crates/arany/src/session/reducer/worker.rs)) check different predicates (liveness, wave and settled state in the Engine; digest, turns, commands, lease and criterion in the reducer); making the Engine call the reducer's function would turn a would-be `InvalidHistory` into an earlier refusal, which is a behavior fix, not a refactor. Recorded in `NEXT_STEPS.md` at closeout, not sliced.
- `StoreError` cause collapse (`ReplayError` → `InvalidHistory` at [store.rs:210](../../crates/arany/src/store.rs); oversized payload → `StorageFull`): changing the returned variant changes the user-visible failure text and the serve `Reason` vocabulary.
- Host Git spawning from the Engine process ([git/host.rs:869](../../crates/arany/src/tools/git/host.rs)) versus the `setsid` launcher ([unguarded.rs:42](../../crates/arany/src/tools/unguarded.rs)): a supervision change under the per-effect isolation guarantee, owned by the Tool spec and a security pass.
- `engine/report.rs` prose and `goal_report_call_label` ([report.rs:833](../../crates/arany/src/engine/report.rs)) as a fourth Tool formatter: the report is journaled in `GoalFinished.report`.
- The network refresh under the account lock ([account.rs:1329](../../crates/arany-cli/src/accounts/chatgpt/account.rs) `refresh_selected_with`): changing lock scope is behavior.
- `expect` density, `.clone()` density, `RunConfig`/`GoalView` field counts: no demonstrated consequence.

## House idioms

Every vertical converges on these; each slice names the idiom it applies, and a reviewer checks the diff against the list.

1. **At Engine boundaries, routine admission/refusal uses a typed decision rather than `EngineError`.** A pure decision over facts may return a closed enum or a closed decision aggregate. Enum canon: `decide_host_reuse` returns `HostReuse` ([step.rs:170](../../crates/arany/src/engine/run_loop/step.rs)); aggregate canon: `DispatchDecision` ([dispatch.rs:183](../../crates/arany/src/engine/run_loop/step/dispatch.rs)) contains `Result<Dispatch, Refusal>` plus `Decision` and `PermissionSource`. Preserve that representation; check the closed alternatives exhaustively where they select behavior. No enum-for-struct or helper-for-one-line churn to satisfy the idiom. One-arm-per-variant tables (`not_dispatched`, `tool_summary`, `goal_report_call_label`) may exceed 80 lines with a review justification.
2. **`EngineError` distinguishes infrastructure/invariant failure from ordinary Engine refusal.** Canonical: `Admission<T> { Reserved(T), Exhausted }` ([ledger.rs:17](../../crates/arany/src/engine/ledger.rs)) and `From<AdmissionRefusal> for StopCause` ([step.rs:2070](../../crates/arany/src/engine/run_loop/step.rs)). This is not a ban on `Result` or `Err` elsewhere: `DispatchDecision.outcome` carries a typed refusal, and T1's parser `Err(HookResult)` short-circuits with an already classified hook result. Keep those representations and their existing meaning. Names such as `<Subject>Admission`, `<Subject>Refusal` and `<Subject>Completion` distinguish roles without requiring renames.
3. **Per-variant facts come from the facts table, never from `matches!`.** Canonical: `ToolCall::is_process` ([types.rs:450](../../crates/arany/src/tools/types.rs)) reads `self.facts().spawns_process`; `ToolCall::site()` ([catalog.rs:268](../../crates/arany/src/tools/catalog.rs)). A new predicate over `ToolCall` either reads `facts()` or is an exhaustive match.
4. **A limit is named once beside its owner and derived everywhere else, including text.** Canonical: `ADMISSION_HEADROOM_BYTES` ([store/journal.rs:17](../../crates/arany/src/store/journal.rs)); `validate::MAX_PATH_BYTES`; `Action::max_events` ([ledger.rs:44](../../crates/arany/src/engine/ledger.rs)) as the Event-headroom owner. Two limits sharing a value are not merged; a shared limit is never restated.
5. **A flow is `x.rs` plus `x/{phase}.rs`: the parent keeps the entry point and the shared types, each child owns one phase and its tests, visibility is `pub(super)` or narrower.** Canonical: `run_loop/step.rs` with `step/{checkpoint,dispatch,review,hooks}.rs` ([step.rs:22–25](../../crates/arany/src/engine/run_loop/step.rs)); `reducer/agent.rs` with `agent/{call,finish,route_change,spawn}.rs`; `serve/server.rs` with `server/serve_loop.rs`. Move focused tests with their code when that improves ownership and fits the slice budget; existing cross-flow/platform corpora may retain their current paths and self-spawned filter names (B3). Count all moved tests in the review budget.
6. **The binary consumes library closed enums and maps them to text at the edge.** Canonical: `ProviderKind::parse(&route.provider)` matched to billing labels ([roster.rs:314–319](../../crates/arany-cli/src/cli/provider/roster.rs)); `profile_label` ([select.rs:23](../../crates/arany-cli/src/cli/provider/select.rs)). The binary never compares a library identity as a string literal and never re-parses JSON the library already typed.
7. **One projection owner per user-visible fact.** Canonical: `presentation::session_run_feedback` ([presentation.rs:328](../../crates/arany-cli/src/presentation.rs)) is called by exec, serve and attached rather than copied. A sentence shown by two drivers is one `pub(crate) const` or one function in `presentation/`.
8. **Shared fixtures are always-present functions whose bodies are gated.** Canonical: `fault::LatencyReceipt::default()` at the children's attempt sites ([children.rs:1248](../../crates/arany/src/engine/run_loop/children.rs)). No `#[cfg]` inside a production function body.
9. **Lifecycle ownership hides acquisition, stop and cleanup behind one interface.** Present canon: `TerminalReader` ([terminal/input.rs:126](../../crates/arany-cli/src/terminal/input.rs)), with `start`, `stop`, mode-specific readers and their cleanup. A matching field count or common `take()` sites alone do not prove a new owner; B4 must establish full success/error/unwind ordering before proposing an equivalent boundary.
10. **Names say the subject and the side.** Model-facing proposals such as `ToolRequest` are distinct from journaled facts such as `WorkerSettlement`; in-memory authority uses `Grant`/kind enums. Preserve established public names unless a concrete ownership benefit warrants their caller churn; `ChildAssignment` is unchanged. A rename that changes serde output is a behavior change.

### Reviewer checklist

- At an EngineError boundary, does ordinary admission/refusal use the existing typed enum or decision aggregate, with closed alternatives handled where they select behavior? (idiom 1)
- Does a routine Engine refusal leak into `EngineError`? Typed `Result` decisions and parser short-circuits such as `Err(HookResult)` are valid; no representation change is required solely by this check. (idiom 2)
- Does any new `matches!` over `ToolCall` duplicate a facts column? (idiom 3)
- Is any number, duration or ratio written twice, including inside a string? (idiom 4)
- Does a moved item keep narrow visibility, with its existing evidence either moved within budget or deliberately kept at its stable cross-flow test path? (idiom 5)
- Does the binary compare a library identity as a string or re-parse typed JSON? (idiom 6)
- Is a user-visible sentence now defined in two places? (idiom 7)
- Did a `#[cfg]` enter a function body? (idiom 8)
- Did a function the slice changed (not moved) end above 80 lines, nesting 4 or 5 parameters without a one-line justification? Pure moves and substitution-only edits are exempt.
- Byte owners untouched: `schema.json`, `tools/snapshots/`; migration fixtures and prefix digests change only in their explicitly owned K1–K2 formats. J1 reads fixtures for equality evidence without rewriting them.

## Security and resource model

Refactors change no trust boundary, authority, secret, bound or overflow behavior; terminal lifecycle guards stay in place while B4 is research. D2 retains cache invalidation and transition checks but delays corruption detection on cache hits. V1–V3 retain journal-first continuation and bounded shadow verdicts while accepting recorded decisions without proving their evaluator provenance on replay; same-user journal tampering remains outside the guarantee. No repository, model or verdict text grants execution authority.

The [security pass](../../agents/security.md#security-pass-triggers) applies to the replay contract and persisted-format work. Its assets are journal integrity and exact Provider/account binding; inputs are stored Events and private account/route records. K1–K2 validate closed kind/name combinations before credential selection, retain current account-root admission and consent, and use the existing bounded, crash-safe migration owners. No credential, new disclosure, descendant authority, I/O path or retry is added. Existing per-action, payload, window, verdict and storage bounds and fail-closed overflow behavior remain. Refactor slices that need another check-order change stop and record the finding.

## Risks and mitigations

- A pure move widens visibility or reorders a side effect → every moved item keeps the narrowest visibility that compiles; `before_dispatch`'s call order is pinned by `engine_run::{permissions,hooks}` and `guard_runs::permissions`; Clippy `-D warnings` on every slice.
- Merge conflicts with in-flight work on the same files → the [parallelism map](#parallelism-map) gates each slice on the worktree that holds uncommitted edits to its files; slices on hot files open and merge the same day.
- A shared helper hides a predicate difference (exec's budget reload, the two editor validators) → the slice keeps the differing site as is and records the difference in `NEXT_STEPS.md`; the helper serves identical copies only.
- A rename reaches serde output → every renamed type is checked for `#[serde(tag)]`/`rename` usage in the PR body; J1–J2 prove byte equality, while K1–K2 explicitly version and migrate their changed formats.
- Splitting a 150-line decision changes its result on an untested input → refactor functions are split beside existing tables, extended only for newly reachable inputs; V2 separately rewrites the decided replay cases.
- The step-file cuts leave `step.rs` a shell with cross-file `use super::*` → each child file imports named items; `step.rs` keeps `Grant`, `execute_step`, `before_dispatch`, `dispatch_primary`, `dispatch_guard` and the shared result types (`Answer`, `ActiveTime`, `IntentResult`, `BoxedStep`).
