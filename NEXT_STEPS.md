# Arany next steps

The current milestone is personal beta 1 on Linux. Manual testing and real Provider calls belong to the final user handoff; they do not block implementation. Synthetic checks do not establish live account compatibility or a verified release. See the [implementation plan](./planning/arany-beta/README.md) for the requirement and evidence register, and the [setup guide](./docs/setup.md) for account warnings and the separately opted-in live gate.

## Local beta 1 handoff

Run the current checkout with `cargo run --release`, or launch the built executable with `./target/release/arany`. Use `/setup` or idle `Ctrl+K` → Setup to select an account; no account is required merely to open and edit the chat.

A positional task without a selected Provider/model now fails with local setup guidance instead of panicking or creating an empty Session. The unconfigured Linux PTY owner covers new and fork startup, exact error output and terminal restoration, while retaining its ordinary chat, setup cancellation and Run-free replay checks. Fork startup still requires an explicit billing selection for a positional task; resume and continue keep their existing defaults.

The [requirement audit](./planning/arany-beta/README.md#requirement-by-requirement-audit) records the automated scope and the local executable is ready for the checklist below. Confirmed unsuccessful outcomes stay in chat; recorded failure categories and recovery advice are also available in `/agents`, without raw upstream diagnostics. Long input now wraps visually into up to four rows instead of panning horizontally; wrapping never adds message bytes, and Enter/Ctrl+O hints stay beside input. Retained draft/caret, mid-draft selector return, narrow resize and reading anchors pass automated Linux checks. The joined Engine journey proves resume, Provider change, ordered teams, fork, failed compaction and drained cancellation. `show` supports Session or Run IDs with strict read-only replay. Both complete offline profiles, strict lint, formatting, cached dependency checks, optimized build and explicit tmux gates pass. After the input change, the optimized networkless ChatGPT setup/check/direct/team/logout journey and the independent API private-file setup/reuse/direct-turn journey also pass with the updated executable.

This handoff does not finish the full goal: native Anthropic subscription access is still missing. Real account use, complete native keyring lifecycle, human UX/accessibility, macOS and redistributable-release support remain unverified in their separately assigned scopes below. No commits were made.

Idle `/effort` opens named choices with the current value focused; `Ctrl+K` → Effort preserves a draft while opening the same picker. An unchecked native/ChatGPT tuple now offers its complete Provider/model/effort/account-source terms and a separate cost choice focused on Back, all inside chat. Checked choices need no extra inference. Declining, interrupting or failing preserves effort; recoverable errors return to chat. Typed arguments remain non-inference controls, and custom profiles retain their exact-profile checker. Existing Linux PTYs prove named selection, invalid-input recovery, cancellation without default changes, focused reopening, and mid-draft caret return at 16–40 columns. Networkless optimized product journeys prove declined and accepted in-chat native/ChatGPT checks, exact source/account binding, recoverable synthetic failure, no extra calls for checked effort, and checked Engine turns. ChatGPT account drift is rejected both during cost consent and on later admission before renewing an expired synthetic replacement token. ## Beta 1: final user-owned checks

1. **ChatGPT account and first real turn.** Complete sign-in, inspect the account-visible catalog, choose a model and effort, and explicitly accept its synthetic compatibility check. Submit a small direct task, then inspect its committed Session with `arany show`. Confirm the selected billing route and local-only output bound. A real follow-up/resume and team journey require their own deliberate plan-usage choices; do not treat offline evidence as those live results.
2. **Credential lifecycle.** Verify setup, restart/reuse, replacement, reconnect, refresh, and logout with the intended Linux credential backend. Arany targets the standard Secret Service interface, not a particular desktop. Full isolated keyring-backed product setup remains unverified; synthetic helper and private-file journeys are distinct evidence. Review the same-user access warning and any uncertain storage/deletion result instead of assuming exclusive token access or secure erasure.
3. **Actual-use chat and accessibility.** Review ordinary text, wrapped long drafts and their row-position cue, explicit multiline editing, Enter's task/command action hints, slash completion/placeholders, `/models`, `/effort` and `Ctrl+K` → Effort, chat errors, cancellation, and return from selectors to the same draft and caret. Confirm current effort focus, full check-term pagination and Back as the default cost choice; accepting a check deliberately consumes usage, while declining should retain effort. Check closing, resizing and returning from that review with a retained draft, including narrow/monochrome mode; its new pager has frame and linear process evidence, not full native keyboard/fault or human accessibility proof. Ctrl+O inserts a newline; Up/Down navigate explicit lines rather than visual wraps. Read older history while a Run completes, resize the terminal, and check the selected theme, `--no-color`, and `--screen-reader`. Automated narrow/monochrome frames and Linux PTYs passed within their recorded scope; theme contrast and assistive-technology usability still need human review.
4. **Native API-key routes.** When explicitly authorized, run the separate OpenAI and Anthropic live compatibility/direct/team gates with their selected keys and models. These are potentially billable and are not covered by a ChatGPT-plan test. Fix observed failures before claiming those live routes are verified.

## Next functional priority

- **Setup lifecycle recovery.** The source audit found that idle setup converts shutdown and terminal failures into the same chat notice as a recoverable account error. Complete typed failure propagation and its isolated automated signal/restoration checks. Account errors should preserve chat and defaults; termination or lost terminal ownership must exit. This remains implementation work, not a manual-test prerequisite.
- **Anthropic consumer subscriptions.** The native Anthropic API-key route exists; Claude subscription access does not. The documented third-party authorization/route gate remains unresolved. Admit a route only after its authorization, credential lifecycle, strict outcomes, and request bounds are established. Pi's technical implementation is not by itself that authorization, and Arany must not import another harness's credentials or present API billing as plan access. This remains high priority without blocking the first personal ChatGPT Engine trial.
- **Use-driven fixes.** Feed failures from the beta 1 checklist into a focused correction pass. Preserve durable Session/Run semantics, explicit model/effort admission, billing-route isolation, and draft/history continuity.

## Beta 2 and broader release

- **Native macOS.** On a macOS machine, verify account/Keychain scope and lifecycle, private filesystem and SQLite behavior, standard system TLS validation, processes/signals, terminal restoration, and VoiceOver. No native macOS result is claimed by this Linux build.
- **Broader terminal evidence.** Complete remaining terminal/history fault and theme/assistive-technology checks, and refine the UI from real usage. The fixed-bottom input uses Arany's navigable primary-screen history; emulator scrollback is not the complete Session history. `arany show` remains the complete export.
- **Performance.** Finish the remaining named-host history/input latency, resource, and telemetry-overhead gates after the main functional routes. Existing measurements are workload-specific, not a universal responsiveness claim.
- **Distribution.** Verify linked-code notices and license/source bundles, source/binary pairing, compiler/native-build provenance, Rust 1.88 compatibility, and fresh advisory data before redistribution. The local executable is not portable-release approval. Keep both `cargo-audit` and `cargo-deny`: vulnerability review and the license/source/bans policy are complementary.
- **Crossterm.** Replace the temporary pinned local patch only when an official published version contains the EOF fix and passes Arany's terminal regressions. Do not remove the working repair merely because an upstream PR exists.
- **Effectful tools and Skills.** Model-driven writes, commands, MCP, and executable Skills remain outside this read-only beta. Introduce typed effects, deterministic Policy, a separate Guard, and adversarial enforcement evidence before enabling them.

For every OS-dependent feature, prefer a general kernel or standard OS capability that satisfies the contract; keep necessary platform integrations narrow. Linux backend tests do not make a desktop a product prerequisite or prove support on every Linux installation.
